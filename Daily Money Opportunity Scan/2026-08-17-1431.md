## 1. Nhu cầu được phát hiện

Các team đang chạy Azure Functions bằng .NET in-process phải chuyển sang isolated worker model trước **10/11/2026** nếu muốn tiếp tục nhận đầy đủ security updates, bug fixes và platform support. Microsoft hiện ghi rõ đây là deadline chính thức, không còn là một roadmap mơ hồ.

Vấn đề thực tế không phải chỉ đổi một setting từ `dotnet` sang `dotnet-isolated`. Migration thường yêu cầu đồng thời:

- thay đổi `.csproj` và package references;
- thêm `Program.cs` và startup model mới;
- đổi `[FunctionName]` sang `[Function]`;
- chuyển các binding packages sang `Microsoft.Azure.Functions.Worker.Extensions.*`;
- sửa logging, DI, middleware và HTTP request/response model;
- cập nhật `FUNCTIONS_WORKER_RUNTIME`;
- kiểm thử lại triggers, bindings và Application Insights;
- xử lý khác biệt riêng của Durable Functions;
- deploy an toàn qua staging slot hoặc rollout có kiểm soát.

Microsoft vừa cập nhật tài liệu troubleshooting riêng cho các lỗi migration như app không start, function biến mất khỏi portal, HTTP 500 do serialization, hoặc mismatch giữa runtime setting và code artifact. Điều này cho thấy đây là migration có failure modes đủ phổ biến để cần hướng dẫn vận hành chuyên biệt.

Nguồn chính thức:  
- Microsoft Learn — .NET isolated worker guide: https://learn.microsoft.com/en-us/azure/azure-functions/dotnet-isolated-process-guide  
- Microsoft Learn — Migrate C# apps from in-process to isolated worker: https://learn.microsoft.com/en-ca/azure/azure-functions/migrate-dotnet-to-isolated-model?tabs=net8  
- Microsoft Learn — Troubleshoot runtime/language migration: https://learn.microsoft.com/en-us/troubleshoot/azure/azure-functions/config-mgmt/functions-configuring-updateversion
