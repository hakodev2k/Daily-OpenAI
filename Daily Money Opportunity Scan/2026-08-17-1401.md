## 1. Nhu cầu được phát hiện

Từ ngày 01/06/2026, GitHub Copilot chuyển sang usage-based billing bằng **GitHub AI Credits**. Đồng thời, Copilot Code Review trên private repositories còn tiêu thụ **GitHub Actions minutes** vì review agent chạy trên GitHub Actions infrastructure. Điều đó tạo ra một cấu trúc chi phí mới: một hoạt động code review có thể phát sinh hai loại usage khác nhau, trong khi chi phí được phân bổ theo user, repository, workflow và billing entity khác nhau.

Các engineering manager hoặc billing admin đang phải trả lời những câu hỏi thực tế như:

- repository nào đang tiêu thụ nhiều Actions minutes nhất;
- user nào đang tiêu thụ nhiều AI Credits;
- Copilot Code Review đang chiếm bao nhiêu phần trong Actions usage;
- workflow nào chạy quá thường xuyên hoặc quá lâu;
- budget hiện tại có đủ hay có nguy cơ vượt chi phí;
- nên giữ automatic Copilot review ở repo nào và tắt/giới hạn ở repo nào;
- có thể giảm usage mà không làm giảm chất lượng review hay không.

GitHub cung cấp dashboard, billing reports và REST API để lấy dữ liệu usage, nhưng việc biến các dữ liệu này thành một **cost attribution + recommendation report** vẫn cần phân tích workflow, repository và policy. Đây là pain point phù hợp để bắt đầu bằng một audit service thay vì xây SaaS ngay.

### Work context

Những team này thường đã có CI pipelines và Copilot adoption tăng dần. Khi usage-based billing được áp dụng, billing admin phải phân biệt:

## 4. Giải pháp kiếm tiền đề xuất

### Hình thức phù hợp nhất

**Productized service: “GitHub Copilot + Actions Cost Audit — 7-Day Snapshot”.**

Không xây dashboard SaaS trước.

### Offer

Khách hàng cấp read-only billing/usage access hoặc tự chạy script rồi gửi export. Dịch vụ tạo một report gồm:

1. usage breakdown theo product/repository/user;
2. Copilot Code Review Actions consumption;
3. top workflows/repositories gây cost;
4. budget/guardrail gaps;
5. 5–10 optimization actions có estimated impact direction: high/medium/low, không fabricate savings.

### Core workflow

**Collect usage → attribute cost → find anomalies → map policy → recommend changes → optional implementation.**

### Phần được tự động hóa

- gọi GitHub Billing Usage REST API;
- tổng hợp AI Credit usage;
- nhóm Actions usage theo repository/SKU;
- lọc workflow Copilot review bằng `dynamic/agents/copilot-pull-request-reviewer`;
- tạo CSV/Markdown report.

GitHub Docs nêu rõ Copilot code review usage có thể được lọc trong Billing Usage Report bằng workflow path `dynamic/agents/copilot-pull-request-reviewer`.

Nguồn: https://docs.github.com/en/copilot/reference/copilot-billing/models-and-pricing

### Phần khách hàng giữ quyền kiểm soát

- repository nào cần automatic review;
- budget limits;
- runner lựa chọn;
- workflow nào được thay đổi;
- policy chấp nhận mức quality/cost trade-off nào.

### Main differentiator

Không bán generic “GitHub optimization”. Offer chỉ trả lời một câu hỏi cụ thể:

> “Sau billing changes 2026, team của bạn đang tốn AI Credits + Actions minutes ở đâu và nên thay đổi gì trước?”

### Vì sao một developer làm được

Official REST API đã expose billing usage; phần còn lại chủ yếu là data aggregation, workflow analysis và report generation. MVP có thể là CLI/script + Markdown report, không cần database hay multi-tenant system.

## 6. Đối thủ và giải pháp hiện tại

### GitHub Billing UI + Billing Usage Report

**Làm tốt:** dữ liệu chính thức, có usage/budget controls, không cần third-party platform.  
**Điểm yếu:** vẫn cần người phân tích repository/workflow và chuyển dữ liệu thành hành động.  
**Khác biệt:** service bán interpretation + remediation, không bán dữ liệu.  
**Cạnh tranh trực tiếp?** Không; dùng GitHub native tooling làm nguồn dữ liệu.

### GitHub REST Billing API

**Làm tốt:** automation-friendly, dữ liệu structured.  
**Điểm yếu:** là API, không phải cost optimization recommendation engine.  
**Khác biệt:** cung cấp ready-to-use audit/report cho team không muốn tự viết tooling.

### FinOps / SaaS management platforms

**Làm tốt:** quản lý spend rộng hơn nhiều vendor.  
**Điểm yếu:** có thể quá rộng hoặc quá nặng cho startup chỉ muốn hiểu GitHub/Copilot spend.  
**Khác biệt:** engagement nhỏ, fixed scope, GitHub-specific.  
**Cạnh tranh trực tiếp?** Không nên; target team chưa cần enterprise FinOps suite.
