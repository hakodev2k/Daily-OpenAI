# Daily Developer Tips & Design — 2026-08-18

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `Span<T>` và `Memory<T>` cho xử lý dữ liệu hiệu năng cao

**Mẹo:**
Sử dụng `Span<T>` khi cần xử lý mảng hoặc buffer tạm thời mà không muốn tạo allocation mới.

**Tại sao hữu ích:**
Giảm áp lực Garbage Collector trong các đoạn code xử lý dữ liệu lớn.

**Ví dụ:**
```csharp
Span<int> numbers = stackalloc int[] { 1, 2, 3 };
var first = numbers[0];
```

**Lưu ý:**
Không dùng trong code thông thường nếu chưa có vấn đề performance rõ ràng.

### Tip 2 — Dùng `EF Core` projection thay vì load toàn bộ entity

**Mẹo:**
Chỉ select những field cần thiết bằng `Select()` thay vì lấy toàn bộ entity.

**Tại sao hữu ích:**
Giảm dữ liệu truyền từ database và giảm memory usage.

**Ví dụ:**
```csharp
var users = await db.Users
    .Select(x => new UserDto
    {
        Id = x.Id,
        Name = x.Name
    })
    .ToListAsync();
```

**Lưu ý:**
Không projection nếu cần thay đổi entity sau khi query.

### Tip 3 — Dùng `OpenTelemetry` để chuẩn hóa observability

**Mẹo:**
Thu thập traces, metrics và logs theo chuẩn OpenTelemetry thay vì tự xây format riêng.

**Tại sao hữu ích:**
Dễ theo dõi request flow giữa nhiều service.

**Ví dụ:**
```csharp
builder.Services.AddOpenTelemetry()
    .WithTracing();
```

**Lưu ý:**
Cần kiểm soát sampling để tránh chi phí lưu trữ quá lớn.

### Tip 4 — Dùng `git reflog` để khôi phục commit bị mất

**Mẹo:**
Sử dụng `git reflog` khi lỡ reset hoặc checkout nhầm branch.

**Tại sao hữu ích:**
Git vẫn lưu lịch sử thay đổi reference trong một khoảng thời gian.

**Ví dụ:**
```bash
git reflog
```

**Lưu ý:**
Không nên xem reflog như thay thế cho backup repository.

### Tip 5 — Dùng `Rate Limiting` bảo vệ API

**Mẹo:**
Áp dụng giới hạn request cho các endpoint quan trọng.

**Tại sao hữu ích:**
Ngăn abuse, giảm nguy cơ overload và bảo vệ resource.

**Ví dụ:**
```csharp
builder.Services.AddRateLimiter(options =>
{
    options.AddFixedWindowLimiter("api", config =>
    {
        config.Window = TimeSpan.FromSeconds(10);
        config.PermitLimit = 100;
    });
});
```

**Lưu ý:**
Cần chọn policy phù hợp, tránh chặn nhầm user hợp lệ.

## 🧠 Software Design

### Design 1 — Bounded Context trong Domain-Driven Design

**Khái niệm:**
Bounded Context xác định ranh giới rõ ràng nơi một domain model có ý nghĩa và được quản lý độc lập.

**Vấn đề nó giải quyết:**
Tránh việc một model khổng lồ bị dùng chung cho toàn hệ thống gây coupling.

**Ví dụ thực tế:**
Hệ thống e-commerce có `Order`, `Inventory` và `Customer` là các context khác nhau với rule riêng.

**Trade-off:**
Tăng khả năng mở rộng và bảo trì nhưng cần thêm effort mapping giữa context.

**Middle → Senior insight:**
Middle cần biết tách domain theo trách nhiệm. Senior cần xác định boundary dựa trên business capability, không chỉ theo technical layer.

### Design 2 — Eventual Consistency trong hệ thống phân tán

**Khái niệm:**
Eventual Consistency cho phép dữ liệu giữa các component chưa đồng nhất ngay lập tức nhưng sẽ hội tụ về trạng thái đúng.

**Vấn đề nó giải quyết:**
Giảm coupling và tăng khả năng scale trong distributed system.

**Ví dụ thực tế:**
Sau khi thanh toán thành công, event được gửi để cập nhật notification và reporting system.

**Trade-off:**
Tăng scalability nhưng application phải xử lý trạng thái dữ liệu tạm thời chưa đồng bộ.

**Middle → Senior insight:**
Senior cần hiểu khi nào consistency tuyệt đối quan trọng và khi nào có thể chấp nhận eventual consistency.

### Design 3 — Strategy Pattern thay vì nhiều nhánh `if/else`

**Khái niệm:**
Strategy Pattern đóng gói các thuật toán hoặc business rule có thể thay đổi thành các strategy riêng biệt.

**Vấn đề nó giải quyết:**
Giảm code phức tạp khi logic thay đổi theo nhiều điều kiện.

**Ví dụ thực tế:**
Hệ thống tính phí vận chuyển có nhiều cách tính theo khu vực hoặc loại khách hàng.

**Trade-off:**
Code dễ mở rộng hơn nhưng tăng số lượng class cần quản lý.

**Middle → Senior insight:**
Middle cần nhận biết dấu hiệu của conditional complexity. Senior cần cân nhắc abstraction có thực sự giảm complexity hay chỉ chuyển chỗ phức tạp.
