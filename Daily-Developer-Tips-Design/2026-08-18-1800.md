# Daily Developer Tips & Design — 2026-08-18

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `ValueTask` khi tối ưu hot path trong .NET

**Mẹo:**
Sử dụng `ValueTask<T>` cho các method async có nhiều trường hợp trả về kết quả đồng bộ và được gọi với tần suất rất cao.

**Tại sao hữu ích:**
Giảm allocation của `Task` trong các scenario performance-sensitive.

**Ví dụ:**
```csharp
public ValueTask<User?> GetCacheUserAsync(string id)
{
    if (_cache.TryGetValue(id, out User? user))
        return ValueTask.FromResult(user);

    return new ValueTask<User?>(LoadFromDatabaseAsync(id));
}
```

**Lưu ý:**
Không thay thế toàn bộ `Task` bằng `ValueTask`; chỉ dùng khi có benchmark.

### Tip 2 — Dùng `AsNoTracking` cho query chỉ đọc trong EF Core

**Mẹo:**
Sử dụng `AsNoTracking()` khi lấy dữ liệu chỉ để hiển thị hoặc export.

**Tại sao hữu ích:**
Giảm memory usage và overhead của EF Core change tracker.

**Ví dụ:**
```csharp
var products = await db.Products.AsNoTracking().ToListAsync();
```

**Lưu ý:**
Không dùng nếu entity cần update.

### Tip 3 — Dùng `dotnet-trace` để điều tra performance issue

**Mẹo:**
Thu thập runtime trace khi ứng dụng .NET gặp vấn đề CPU hoặc performance.

**Tại sao hữu ích:**
Phân tích production issue mà không cần attach debugger.

**Ví dụ:**
```bash
dotnet-trace collect --process-id 1234
```

**Lưu ý:**
Giới hạn thời gian collect trong production.

### Tip 4 — Dùng `git worktree` để làm nhiều branch cùng lúc

**Mẹo:**
Tạo nhiều working directory từ một repository.

**Tại sao hữu ích:**
Fix production bug mà không cần checkout qua lại.

**Ví dụ:**
```bash
git worktree add ../hotfix main
```

**Lưu ý:**
Quản lý worktree để tránh nhầm source.

### Tip 5 — Validate configuration khi startup

**Mẹo:**
Dùng Options Pattern validation để phát hiện config sai khi deploy.

**Tại sao hữu ích:**
Tránh lỗi runtime sau khi service nhận traffic.

**Ví dụ:**
```csharp
builder.Services.AddOptions<DatabaseOptions>()
    .BindConfiguration("Database")
    .ValidateOnStart();
```

**Lưu ý:**
Không validate dependency chưa sẵn sàng lúc startup.

## 🧠 Software Design

### Design 1 — Dependency Inversion Principle

**Khái niệm:**
Business logic phụ thuộc abstraction thay vì implementation cụ thể.

**Vấn đề nó giải quyết:**
Giảm coupling giữa domain và infrastructure.

**Ví dụ thực tế:**
Dùng `IEmailSender` thay vì gọi trực tiếp SMTP provider.

**Trade-off:**
Dễ thay đổi hơn nhưng có thể tạo abstraction dư thừa.

**Middle → Senior insight:**
Senior cần biết abstraction nào thực sự bảo vệ business rule khỏi thay đổi.

### Design 2 — Saga Pattern cho distributed transaction

**Khái niệm:**
Chia transaction lớn thành nhiều local transaction kèm compensation.

**Vấn đề nó giải quyết:**
Đảm bảo consistency trong hệ thống nhiều service.

**Ví dụ thực tế:**
Order, Payment và Shipping xử lý qua event workflow.

**Trade-off:**
Tăng resilience nhưng workflow phức tạp hơn.

**Middle → Senior insight:**
Senior cần thiết kế retry, compensation và monitoring rõ ràng.

### Design 3 — Anti-Corruption Layer trong Domain-Driven Design

**Khái niệm:**
Lớp bảo vệ domain model khỏi ảnh hưởng từ hệ thống bên ngoài.

**Vấn đề nó giải quyết:**
Ngăn legacy model làm ảnh hưởng business logic mới.

**Ví dụ thực tế:**
Adapter giữa Order domain và ERP cũ.

**Trade-off:**
Code sạch hơn nhưng thêm mapping layer.

**Middle → Senior insight:**
Senior cần bảo vệ domain boundary trước dependency thay đổi nhanh.
