# Daily Developer Tips & Design — 2026-08-17

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `AsNoTracking` cho read-only query trong EF Core

**Mẹo:**
Sử dụng `AsNoTracking()` khi query dữ liệu chỉ để hiển thị hoặc báo cáo.

**Tại sao hữu ích:**
Giảm memory usage và tăng performance vì EF Core không cần tạo change tracker.

**Ví dụ:**
```csharp
var users = await db.Users
    .AsNoTracking()
    .Where(x => x.IsActive)
    .ToListAsync();
```

**Lưu ý:**
Không dùng khi entity cần được update và gọi `SaveChanges()`.

### Tip 2 — Dùng `dotnet-counters` để kiểm tra runtime performance

**Mẹo:**
Sử dụng công cụ .NET diagnostics để quan sát CPU, GC, thread pool trong production.

**Tại sao hữu ích:**
Giúp tìm bottleneck mà không cần attach debugger vào application.

**Ví dụ:**
```bash
dotnet-counters monitor --process-id 1234
```

**Lưu ý:**
Metrics cần được kết hợp với logging và tracing để có kết luận chính xác.

### Tip 3 — Validate input ở API boundary

**Mẹo:**
Kiểm tra dữ liệu ngay tại Controller hoặc request pipeline trước khi vào business logic.

**Tại sao hữu ích:**
Giảm lỗi lan truyền và giữ domain code sạch hơn.

**Ví dụ:**
```csharp
[ApiController]
public class OrderController : ControllerBase
{
    [HttpPost]
    public IActionResult Create(CreateOrderRequest request)
    {
        if (!ModelState.IsValid) return BadRequest(ModelState);
        return Ok();
    }
}
```

**Lưu ý:**
Không đặt toàn bộ business validation vào API layer nếu rule thuộc domain.

### Tip 4 — Sử dụng `git reflog` khi mất commit

**Mẹo:**
Dùng `git reflog` để tìm lại commit hoặc branch bị reset nhầm.

**Tại sao hữu ích:**
Git vẫn lưu lịch sử reference thay đổi trong một khoảng thời gian.

**Ví dụ:**
```bash
git reflog

git checkout <commit-sha>
```

**Lưu ý:**
Reflog chủ yếu tồn tại local, không thay thế remote backup.

### Tip 5 — Thiết kế health check cho dependency quan trọng

**Mẹo:**
Expose trạng thái database, Redis, external service thông qua health endpoint.

**Tại sao hữu ích:**
Hỗ trợ Kubernetes, monitoring và xử lý incident nhanh hơn.

**Ví dụ:**
```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(connectionString);
```

**Lưu ý:**
Không nên expose thông tin nhạy cảm trong health response public.

## 🧠 Software Design

### Design 1 — Dependency Inversion Principle trong ứng dụng thực tế

**Khái niệm:**
Module cấp cao không nên phụ thuộc trực tiếp vào implementation chi tiết mà phụ thuộc vào abstraction.

**Vấn đề nó giải quyết:**
Giảm coupling giữa business logic và infrastructure.

**Ví dụ thực tế:**
Order service phụ thuộc vào `IPaymentGateway` thay vì trực tiếp gọi Stripe API.

**Trade-off:**
Tăng khả năng test và thay đổi implementation nhưng có thể tạo thêm abstraction không cần thiết.

**Middle → Senior insight:**
Middle cần biết inject dependency đúng cách. Senior cần biết khi nào abstraction tạo giá trị và khi nào chỉ làm code phức tạp hơn.

### Design 2 — Cache Aside Pattern

**Khái niệm:**
Application tự quản lý việc đọc cache trước, nếu thiếu dữ liệu thì lấy từ database rồi cập nhật cache.

**Vấn đề nó giải quyết:**
Giảm database load cho dữ liệu đọc nhiều.

**Ví dụ thực tế:**
Product catalog cache trong Redis với fallback xuống SQL Server.

**Trade-off:**
Tăng performance nhưng phải xử lý cache invalidation và stale data.

**Middle → Senior insight:**
Middle cần biết cách implement cache. Senior cần quyết định dữ liệu nào được cache, TTL bao lâu và consistency yêu cầu ra sao.

### Design 3 — Event-Driven Communication

**Khái niệm:**
Các module giao tiếp thông qua events thay vì gọi trực tiếp nhau.

**Vấn đề nó giải quyết:**
Giảm coupling và hỗ trợ mở rộng hệ thống.

**Ví dụ thực tế:**
Khi EmployeeCreated event phát sinh, các service khác tự xử lý notification, audit và provisioning.

**Trade-off:**
Scalability tốt hơn nhưng debugging và đảm bảo consistency trở nên khó hơn.

**Middle → Senior insight:**
Middle cần hiểu event flow. Senior cần thiết kế event contract, retry strategy, ordering và failure handling.
