# Ý tưởng hôm nay: AI Pull Request Review Companion

## 1. Tóm tắt ý tưởng

Xây dựng một công cụ hỗ trợ developer tự review pull request trước khi gửi cho team bằng cách phân tích diff, kiểm tra các vấn đề phổ biến và tạo checklist review cá nhân. Công cụ phục vụ developer làm việc với GitHub/GitLab, đặc biệt hữu ích cho solo developer hoặc team nhỏ muốn nâng chất lượng code review.

Quy mô: Medium. MVP dự kiến: 2-4 tuần.

## 2. Bài toán thực tế

Developer thường tạo pull request nhưng review chưa đầy đủ vì thiếu thời gian hoặc bỏ sót các vấn đề như:
- Breaking API changes.
- Missing validation.
- Database migration nguy hiểm.
- Thiếu test.
- Performance hoặc security issue.

Hiện tại nhiều người dựa vào kinh nghiệm cá nhân, checklist thủ công hoặc review sau khi merge.

Giả định: developer làm việc nhiều repository cần một bước pre-review trước khi gửi code cho người khác.

## 3. Người dùng mục tiêu

Primary user:
- Senior developer.
- Tech lead.
- Solo builder có nhiều project.

Pain point:
Muốn giảm bug lọt qua pull request nhưng không muốn thiết lập hệ thống review phức tạp.

## 4. Giải pháp đề xuất

Workflow:

Developer chọn branch hoặc pull request.

Input:
- Git diff.
- Changed files.
- Project metadata.
- Coding rules.

Processing:
- Rule engine kiểm tra pattern.
- AI phân tích các phần cần reasoning.

Output:
- Review report.
- Risk level.
- Suggested improvements.
- Checklist trước merge.

Điểm khác biệt: kết hợp deterministic rules và AI reasoning thay vì chỉ hỏi AI đọc toàn bộ code.

## 5. Tại sao ý tưởng này đáng làm

Giá trị:
- Tạo thói quen review trước merge.
- Học cách xây AI coding assistant thực tế.

Phù hợp solo developer vì có thể bắt đầu bằng CLI.

Có thể thất bại nếu output review quá chung chung.

Lý do không nên xây: GitHub Copilot và IDE AI đã có nhiều tính năng tương tự, nên cần tập trung vào workflow riêng và rules cá nhân.

## 6. Phạm vi MVP

### Must have

- CLI nhận git diff.
- Rule check C#/.NET.
- Generate markdown review report.
- Lưu review history.

### Should have

- GitHub PR integration.
- Custom team rules.
- Risk scoring.

### Later

- VS Code extension.
- Multi-agent review.
- Organization knowledge base.

## 7. Luồng hoạt động

User chạy CLI
→ đọc git diff
→ validate repository
→ chạy static rules
→ gửi context phù hợp cho AI
→ tổng hợp kết quả
→ xuất report.

Failure:
- AI unavailable: chỉ chạy rule engine.
- Git error: báo branch/repository issue.
- Large diff: giới hạn phạm vi phân tích.

## 8. Kiến trúc đề xuất

MVP modular monolith:

- CLI: .NET Console.
- Core engine: C# library.
- Database: SQLite local.
- Optional API: ASP.NET Core khi cần cloud.
- Background worker: không cần trong MVP.
- Storage: local files.

Không dùng microservice vì workflow nhỏ.

## 9. Công nghệ đề xuất

- .NET 8/9 Console App: phù hợp backend developer.
- Roslyn Analyzer: phân tích C# code.
- LibGit2Sharp: đọc git history.
- SQLite: đơn giản cho local app.
- OpenAI API/local model: AI reasoning.
- GitHub Actions: test package.

Alternative: Python nếu muốn thử nghiệm AI nhanh hơn.

## 10. Thiết kế dữ liệu ban đầu

ReviewSession:
- Id
- Repository
- CommitHash
- CreatedAt
- ResultFile

ReviewFinding:
- Id
- SessionId
- Category
- Severity
- Description
- Recommendation

Giữ lịch sử để so sánh chất lượng review.

## 11. API và tích hợp

GitHub API:
- Lấy pull request metadata.
- Cần OAuth nếu truy cập private repository.

OpenAI API:
- Phân tích reasoning.
- Có chi phí token.

Fallback:
- Local rules không cần API.

## 12. AI có thực sự cần thiết không?

AI hữu ích nhưng optional.

AI task:
- Giải thích logic phức tạp.
- Phát hiện risk từ context.
- Đề xuất cải thiện.

Validation:
- Developer đánh giá finding.
- So sánh với review thực tế.

Fallback:
- Rule engine.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

Tạo 10 pull request mẫu và kiểm tra công cụ có phát hiện vấn đề hữu ích không.

### Phase 1 — Core MVP

Build CLI, diff parser, rules, markdown output.

### Phase 2 — Reliability

Thêm test, logging, cache, retry API.

### Phase 3 — Useful expansion

GitHub integration, custom rules.

### Phase 4 — Production readiness

Package NuGet/tool, documentation, release automation.

## 14. Các bài toán kỹ thuật đáng học

1. Code analysis với Roslyn.
2. AI context engineering cho code review.
3. Diff processing.
4. Rule engine design.
5. CLI tool architecture.

## 15. Rủi ro và cách xử lý

AI hallucination:
- Bắt buộc review thủ công.

Chi phí API:
- Chỉ gửi phần diff cần thiết.

Scope creep:
- Bắt đầu bằng .NET/C#.

## 16. Kiểm thử

5 scenario:

1. Diff nhỏ được phân tích đúng.
2. Migration nguy hiểm được cảnh báo.
3. AI lỗi vẫn tạo report.
4. Repository lớn không bị treo.
5. Rule không tạo quá nhiều false positive.

## 17. Cách đo dự án có hữu ích hay không

Metrics:
- Số finding hữu ích.
- Thời gian review giảm.
- Số bug phát hiện trước merge.
- Tần suất sử dụng mỗi tuần.

## 18. Khả năng mở rộng

## 19. Mô hình giá trị hoặc kiếm tiền

## 20. Việc cần làm ngay hôm nay

Trong 60-120 phút:

Objective:
Tạo CLI review diff đầu tiên.

Tasks:

```bash
dotnet new console -n PrReviewCompanion
```

Tạo:
- Git diff reader.
- ReviewFinding model.
- Markdown exporter.
- Một rule kiểm tra TODO hoặc missing test pattern.

Kết quả:
Chạy command và nhận được file review-report.md.

Verification:
- Đọc được diff.
- Rule phát hiện issue mẫu.
- Report sinh thành công.

Stop condition:
Chưa thêm GitHub bot hoặc AI agent trước khi CLI workflow hoàn chỉnh.
