## 1. Executive Summary

### 1. Guardian v2 đưa **visual evidence** vào verifier/safety transcript

- **One-sentence summary:** Codex `main` thêm `features.guardianv2.transcript.include_images`, cho phép Guardian v2 nhận ảnh gần đây từ user/assistant messages và configured tool outputs; visual context bị giới hạn ở **4 ảnh gần nhất** và **8 MiB tổng**, đồng thời bỏ `detail` hint trước sampling. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal QA, browser agents, verifier/safety pipelines, evidence collection.
- **Why it matters:** Browser/UI agents có thể ra quyết định từ screenshot; nếu executor thấy ảnh nhưng reviewer/verifier chỉ thấy text thì hệ thống có **asymmetric context** và dễ đưa verdict sai.
- **Practical implication:** Screenshot nên là first-class evidence có provenance, timestamp, hash và redaction metadata; verifier chỉ nhận bounded subset cần thiết.
- **Priority:** **Critical** cho browser/UI agents; **High** cho coding agents có image-bearing tool outputs.
- **Confirmed facts:** Setting opt-in, mặc định `false`; ảnh có thể đến từ user, assistant và tool outputs; tối đa 4 ảnh và 8 MiB tổng; tests cover config parsing và forwarding. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Analysis:** Verification channel nên có access tới cùng evidence classes mà execution channel đã dùng.
- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }` cho QA/browser/review agents.
- **Uncertainty:** Chưa có evidence public rằng stable Codex `0.147.0` đã ship behavior này hoặc Guardian v2 là default path cho hosted Codex.

### 2. Multimodal context cần **budget, recency, deduplication và redaction**

- **One-sentence summary:** Codex bounded visual transcript theo số lượng ảnh và tổng bytes thay vì forward toàn bộ visual history. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Context engineering, browser automation, long-running agents, cost/latency control.
- **Why it matters:** UI automation có thể tạo hàng chục screenshot gần giống nhau; gửi tất cả làm tăng payload mà không bảo đảm tăng correctness.
- **Practical implication:** Nên có `VisualEvidenceBudget`, recency policy, dedupe bằng hash và privacy redaction trước verifier.
- **Priority:** **High**.
- **Confirmed facts:** Implementation dùng bounded queue và loại ảnh cũ khi vượt count/byte budget.
- **Analysis:** Đây là multimodal equivalent của context compaction.
- **Recommendation:** Benchmark `latest-only`, `latest+failure`, `latest+failure+pre-action`; đo verifier accuracy, latency và payload size.
- **Uncertainty:** 4 ảnh/8 MiB là implementation choice, chưa có benchmark chứng minh tối ưu cho mọi workflow.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **Text Context Budget** và **Visual Evidence Budget**

- **Problem:** Agent thường gom text, screenshots và tool artifacts vào cùng một “context bucket”, khó biết surface nào đang gây cost hoặc làm mất evidence quan trọng.
- **Proposed improvement:** Theo dõi riêng `text_tokens`, `skill_catalog_tokens`, `tool_result_tokens`, `image_count`, `image_bytes`, `evidence_priority`.
- **Why it may work:** Codex đang quản lý riêng skill-catalog tokens và Guardian visual transcript bytes/count, cho thấy context surfaces có thể có budget độc lập. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Image transcript](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** QA browser agents, code review agents có screenshots, incident analysis, research agents có diagrams/images.
- **Limitations:** Không có một budget tối ưu chung cho mọi model/provider.
- **Risks:** Cắt evidence quá mạnh có thể giảm correctness.

### B. Skill metadata nên phục vụ **routing**, không chứa full procedure

- **Problem:** Description dài làm catalog phình nhanh và cạnh tranh token với task evidence.
- **Proposed improvement:** Discovery metadata chỉ giữ `name`, `trigger`, `expected outcome`, `exclusions`; full procedure/examples/commands chỉ load sau khi skill được chọn.
- **Why it may work:** Progressive disclosure giảm catalog overhead nhưng vẫn giữ procedural depth.
- **Suitable use cases:** Cursor rules/skills, Codex skills, Claude reusable workflows, QA/research/review role libraries.
- **Limitations:** Metadata quá ngắn có thể gây ambiguous routing.
- **Risks:** Hai skills có trigger gần nhau có thể collision.
- **Recommendation:** Mỗi skill cần 3 positive trigger examples + 3 negative examples và một routing eval set.

### C. Prompt phải phân biệt **Fact / Assumption / Inference / Recommendation**

- **Problem:** Agent planning/research dễ biến assumption thành fact rồi tiếp tục reasoning trên nền sai.
- **Proposed improvement:** Bắt buộc output artifact có bốn lớp: `Confirmed facts`, `Assumptions`, `Inferences`, `Recommendations`, kèm evidence link/hash cho facts.
- **Why it may work:** Giảm propagation của unsupported claims và giúp verifier tập trung vào unresolved assumptions.
- **Suitable use cases:** Architecture planning, RCA, research agents, interview-story verification, code-review reasoning.
- **Limitations:** Tăng output verbosity và cần schema discipline.
- **Risks:** LLM có thể tự gắn nhãn sai nếu không có deterministic evidence checks.

## 4. Agent, Workflow, and Loop Engineering

### A. Thiết kế **Verifier Symmetry** cho multimodal agents

- **Problem:** Executor có thể thấy screenshot nhưng verifier chỉ thấy text summary.
- **Technique:** Mọi evidence class được executor dùng cho quyết định quan trọng phải có đường truyền tương ứng tới verifier hoặc được explicit-marked là unavailable.
- **Expected benefit:** Giảm false pass/false fail do reviewer thiếu context.
- **Failure risks:** Forward ảnh chứa secrets/PII; evidence payload quá lớn; screenshot stale.
- **Suitable use cases:** Playwright QA agents, browser agents, UI regression, incident response.
- **Concrete test:** Chạy cùng 20 UI failures với `text-only verifier` và `text+bounded visual evidence verifier`; đo accuracy, false-pass rate và latency.

### B. Dùng **Plan → Execute → Verify → Decide**, không loop vô hạn `Execute → Retry`

- **Problem:** Agent gặp lỗi cùng signature nhiều lần nhưng tiếp tục sửa nhỏ rồi rerun.
- **Technique:** Sau 2 lần failure cùng signature, tạo `FailureFingerprint`, stop retry và chuyển sang root-cause/re-plan.
- **Expected benefit:** Giảm low-value loops và tool cost.
- **Failure risks:** Fingerprint quá coarse có thể gộp hai lỗi khác nhau.
- **Suitable use cases:** Build/test-fix, Selenium/Playwright, CI troubleshooting, migration scripts.

### C. Approval cache phải phụ thuộc **policy revision**

- **Problem:** Approval cũ có thể không còn hợp lệ sau khi permissions/config thay đổi.
- **Technique:** Cache key gồm `action fingerprint + environment + policy revision/fingerprint + tool version`.
- **Expected benefit:** Tránh stale approval vượt qua boundary mới.
- **Failure risks:** Quá nhiều invalidation gây approval fatigue.
- **Suitable use cases:** Deployment agents, file-write agents, database agents, production tools.
- **Primary evidence:** Codex đã đưa environment-policy fingerprint vào approval cache keys. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### D. Durable state nên nằm ngoài transcript

- **Problem:** Transcript dài vừa khó resume vừa khó audit; compaction có thể mất state quan trọng.
- **Technique:** Lưu `Project`, `Run`, `Checkpoint`, `Evidence`, `Decision`, `Artifact` riêng; transcript chỉ là interaction stream.
- **Expected benefit:** Resume/retry/fork rõ ràng hơn, dễ regression test.
- **Failure risks:** State schema drift hoặc divergence giữa transcript và store.
- **Suitable use cases:** QA campaigns, research pipelines, interview intelligence, code-review automation, knowledge transfer.

## 7. Opportunities and Trends to Watch

### 1. **Multimodal verification** trở thành first-class agent capability

- **What is changing:** Safety/reviewer layers bắt đầu nhận visual evidence thay vì chỉ text transcript. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Why it matters:** Browser/UI/computer-use agents cần reviewer thấy cùng trạng thái mà executor thấy.
- **Opportunity:** Xây reusable evidence gateway cho screenshot/video-frame/tool images với redaction/provenance/budget.
- **Risk:** Privacy leakage, stale screenshots, image cost.
- **Status:** **Growing**.

### 2. **Context budget engineering** thay thế tư duy “càng nhiều context càng tốt”

- **What is changing:** Skill catalog và visual evidence đều được bounded bằng explicit budgets.
- **Why it matters:** Context window lớn không loại bỏ trade-off cost/latency/relevance.
- **Opportunity:** Context-budget telemetry + adaptive allocation + eval harness.
- **Risk:** Over-optimizing token count và bỏ critical evidence.
- **Status:** **Growing**.

### 3. **Runtime-enforced least privilege** thay thế prompt-only permission rules

- **What is changing:** Command policy, approval cache và secret boundaries đang được enforced ở runtime layers. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929) · [Codex #38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Why it matters:** Prompt injection hoặc model error không nên có khả năng vượt policy.
- **Opportunity:** .NET agent runtime có policy engine + approval state + secret sanitizer reusable cho nhiều agents.
- **Risk:** Complexity và approval fatigue.
- **Status:** **Established pattern, growing implementation maturity**.

### 4. **Durable project state** tách khỏi chat transcript

- **What is changing:** Agent platforms đang formalize project/workspace/thread/run lifecycle thay vì lưu mọi thứ trong conversation.
- **Why it matters:** Long-running workflows cần resume/fork/audit/retry độc lập với transcript length.
