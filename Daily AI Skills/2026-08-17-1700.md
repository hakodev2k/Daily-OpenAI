## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách `Policy`, `Procedure`, `Context`, `Task` thành bốn lớp

- **Problem:** Một file rules lớn dễ trộn security constraints, coding conventions, workflow steps và task-specific details; khi conflict xảy ra rất khó biết instruction nào có precedence.
- **Proposed improvement:**
  - `policy/`: deny/allow boundaries, approval requirements, data restrictions.
  - `skills/`: reusable procedures/checklists.
  - `context/`: architecture, repo facts, domain knowledge.
  - `task/`: objective, acceptance criteria, current evidence.
- **Why it may work:** Codex environment-policy change cung cấp evidence cụ thể rằng policy nên được compose theo scope và lower layer chỉ nên restrict. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor Rules/Skills, Claude Code `CLAUDE.md` + skills, Codex skills/instructions, QA/research/review agents.
- **Limitations:** Nhiều file hơn, cần deterministic loading order và conflict rules.
- **Risks:** Duplicate instruction giữa layers nếu không có ownership rõ.
- **Recommendation:** Viết precedence contract ngắn: `Policy > Environment restrictions > Task > Procedure defaults`; context chỉ cung cấp facts, không tự grant permission.

### B. Thêm provenance cho mọi assumption quan trọng

- **Problem:** Agent dễ biến inference thành “fact” sau vài bước, đặc biệt trong architecture review hoặc root-cause analysis dài.
- **Proposed improvement:** Mỗi claim quan trọng có type: `FACT`, `ASSUMPTION`, `INFERENCE`, `RECOMMENDATION`, `UNKNOWN`; fact phải kèm evidence reference.
- **Why it may work:** Nó tạo deterministic checkpoint cho reviewer hoặc verifier agent, giảm lỗi “reasoning drift”.
- **Suitable use cases:** Research agents, code review, incident analysis, interview story verification, architecture planning.
- **Limitations:** Tăng verbosity và token usage.
- **Risks:** Agent có thể gắn nhãn đúng nhưng evidence vẫn yếu.
- **Recommendation:** Chỉ bắt provenance ở decision points, không áp dụng cho mọi câu. Ví dụ:

```text
FACT: API currently times out after 30s. Evidence: log #42.
ASSUMPTION: DOM state is stable after sidebar open.
INFERENCE: Timeout may be caused by stale element/re-render.
RECOMMENDATION: Re-query element immediately before click.
UNKNOWN: Whether React re-renders after animation on every run.
```

### C. Context budgeting phải theo **effective route**, không chỉ model name

- **Problem:** Model limits có thể khác theo provider, auth mode, gateway hoặc harness; hard-code theo model name dễ sai.
- **Proposed improvement:** Capability registry key bằng `model + provider + auth_mode + route + tool_version`.
- **Why it may work:** OpenCode vừa điều chỉnh model limits trong ChatGPT-subscription path, cho thấy effective limits có thể phụ thuộc harness/route thay vì là universal model constant. [OpenCode source context](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Suitable use cases:** Long-context research, codebase review, RAG, agent handoffs.
- **Limitations:** Registry cần được cập nhật và test định kỳ.
- **Risks:** Changelog metadata có thể không phản ánh runtime behavior đầy đủ.
- **Recommendation:** Capability probe + telemetry thực tế; không dùng một `MaxContextTokens` global cho mọi route.

## 4. Agent, Workflow, and Loop Engineering

### A. Thêm explicit stop condition cho research/monitor loops

- **Problem:** Agent tiếp tục search dù nguồn primary không thay đổi, dẫn tới noise, latency và chi phí tăng.
- **Technique:** `Detect → Classify → Verify → Decide` với outcomes: `MATERIAL_UPDATE`, `CORRECTION`, `NO_MATERIAL_DELTA`, `SOURCE_CONFLICT`.
- **Expected benefit:** Giảm repeated work và giữ briefing incremental.
- **Failure risks:** Stop quá sớm nếu source set quá hẹp.
- **Suitable use cases:** Daily briefings, GitHub radar, job radar, release monitoring, market scan.
- **Recommendation:** Chỉ stop khi đã kiểm tra đủ source tiers đã định trước; không stop chỉ vì một repo im lặng.

### B. Policy fingerprint phải đi cùng approval cache

- **Problem:** Cached approval có thể trở nên invalid khi environment restrictions đổi.
- **Technique:** Cache key gồm `command/action fingerprint + policy fingerprint + environment identity + tool version`.
- **Expected benefit:** Approval cũ không vô tình grant permission dưới policy mới.
- **Failure risks:** Cache miss nhiều hơn, tăng user prompts.
- **Suitable use cases:** Shell execution, deploy, file write, DB mutation, cloud operations.
- **Confirmed facts:** Codex main đã đưa environment policy fingerprint vào cached approval keys. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Recommendation:** Với high-risk actions, thêm resource scope vào cache key, ví dụ repo/path/subscription/environment.

### C. `Project → Run → Step → Evidence` tốt hơn “one giant transcript”

- **Problem:** Long-running agent bị phụ thuộc transcript, khó resume/fork/audit.
- **Technique:** Tách stable project state khỏi ephemeral run state; artifacts/evidence lưu ngoài transcript.
- **Expected benefit:** Rerun deterministic hơn, context handoff nhỏ hơn, dễ parallelize verifier agents.
- **Failure risks:** State synchronization và schema migration phức tạp hơn.
- **Suitable use cases:** QA agents, interview intelligence, research pipelines, architecture review, code review agents.
- **Confirmed facts:** Codex experimental Project APIs đang tách project lifecycle và thread assignment. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Recommendation:** Transcript chỉ là một artifact; source of truth nên là structured project/run records.

### D. Secret-boundary test nên là deterministic regression, không phải LLM judge

- **Problem:** Không nên hỏi model “có thấy secret không?” làm security test duy nhất.
- **Technique:** Spawn controlled child process/hook và assert env không chứa denylisted keys; test cả case variants trên Windows.
- **Expected benefit:** Security property có pass/fail deterministic.
- **Failure risks:** Không cover secret nằm trong file, command-line args hoặc inherited credentials ngoài env.
- **Suitable use cases:** .NET agent runner, CI agents, hooks, MCP tools invoking subprocesses.
- **Recommendation:** LLM-as-a-judge chỉ đánh giá semantic output; dùng deterministic validators cho permission/secrets/schema/security invariants.

## 5. Hooks and Integrations

### 1. .NET subprocess execution + secret scrubber

- **What can be integrated:** `ProcessStartInfo`, centralized environment builder, command-policy evaluator, audit logging.
- **Workflow benefit:** Mọi CLI tool/hook dùng cùng security boundary thay vì tự xử lý environment.
- **Security concerns:** Không log secret values; tránh inherited credentials; normalize env var names case-insensitively trên Windows.
- **Difficulty:** **Moderate**.
- **Recommendation:** Thêm integration test chạy dummy child process in ra keys được nhận, rồi assert sensitive keys không xuất hiện.

### 2. GitHub Actions as regression harness for agent workflows

- **What can be integrated:** Prompt/rules fixtures, code-review tasks, QA tasks, version metadata, deterministic validators.
- **Workflow benefit:** Mỗi lần đổi rules/skills có baseline regression thay vì đánh giá cảm tính.
- **Security concerns:** Không expose repository secrets cho untrusted PR workflows; dùng minimum `permissions:` và environment protections.
- **Difficulty:** **Moderate**.
- **Recommendation:** Matrix theo `tool_version/model/provider/auth_route`; lưu result artifact gồm accuracy, latency, cost, tool-call errors.

### 3. MCP tool boundary + policy layer

- **What can be integrated:** MCP server tools, per-tool permissions, environment-specific restrictions, human approval for mutation.
- **Workflow benefit:** Tool contracts reusable giữa Claude/Codex/custom .NET agents.
- **Security concerns:** MCP tool availability không đồng nghĩa agent được quyền gọi; auth/token scope và approval phải enforce ngoài prompt.
- **Difficulty:** **Advanced**.
- **Recommendation:** Tách `ToolDiscovery` khỏi `ToolAuthorization`; một tool có thể discoverable nhưng unavailable for execution trong current environment.

### 4. Teams/Slack notifications cho checkpoint, không cho hidden authority escalation

- **What can be integrated:** Run status, approval requests, failed validations, summary artifacts.
- **Workflow benefit:** Human-in-the-loop không cần ngồi trong IDE/terminal.
- **Security concerns:** Button/message action phải map về server-side approval object có TTL, policy version và action fingerprint; không trust text message alone.
- **Difficulty:** **Advanced**.
- **Recommendation:** Approval payload tối thiểu: `run_id`, `action_hash`, `policy_revision`, `resource_scope`, `expires_at`.

## 7. Opportunities and Trends to Watch

### 1. Permission policy đang dịch từ prompt convention sang runtime-enforced capability model

- **What is changing:** Agent runtimes ngày càng encode permission/approval state ngoài model, với environment-specific restrictions và invalidation logic.
- **Why it matters:** Security không thể dựa vào model tự “nhớ” không làm điều nguy hiểm.
- **Opportunity:** Xây reusable .NET policy engine cho agent tools, CLI, MCP và CI runners.
- **Risk:** Policy model quá phức tạp gây approval fatigue hoặc false denies.
- **Status:** **Growing**.

### 2. Durable project/workspace state đang tách khỏi conversation thread

- **What is changing:** Agent systems hướng tới project-level roots/metadata/state, còn thread/run trở thành execution unit.
- **Why it matters:** Đây là foundation cho long-running, forkable và auditable agents.
- **Opportunity:** Chuẩn hóa project/run/evidence schema dùng chung cho QA, research, review, architecture và interview agents.
- **Risk:** Schema lock-in sớm vào experimental vendor API.
- **Status:** **Growing**.

### 3. Model gateways cần “governance normalization + native protocol fidelity”

- **What is changing:** Gateway vẫn unify routing/telemetry/auth nhưng provider-native request/response paths được giữ khi cần.
- **Why it matters:** Reasoning/tools/streaming không phải lúc nào có feature parity qua compatibility APIs.
- **Opportunity:** .NET abstraction kiểu `CommonAgentContract + ProviderCapabilities + NativeAdapter`.
- **Risk:** Adapter matrix và tests tăng đáng kể.
- **Status:** **Early signal**.

### 4. Agent evaluation sẽ ngày càng version-aware thay vì chỉ model-aware

- **What is changing:** Same model có thể khác behavior qua tool version, auth route, gateway và policy layer.
- **Why it matters:** Benchmark không ghi environment metadata sẽ khó reproducible.
- **Opportunity:** Build lightweight eval harness lưu full execution fingerprint và compare regressions.
- **Risk:** Quá nhiều dimensions làm matrix nổ combinatorially.
- **Status:** **Growing**.

### 5. Deterministic validators sẽ giữ vai trò bắt buộc bên cạnh LLM-as-a-judge

- **What is changing:** Security, permissions, schemas, test outcomes và secret boundaries đều phù hợp với deterministic checks hơn semantic judging.
- **Why it matters:** LLM judge không nên là oracle cho invariants có thể kiểm chứng bằng code.
- **Opportunity:** Thiết kế evaluator chain: `Deterministic checks → semantic judge → human review for ambiguous cases`.
- **Risk:** Teams có thể overfit vào deterministic fixtures và bỏ sót semantic failures.
- **Status:** **Established**.
