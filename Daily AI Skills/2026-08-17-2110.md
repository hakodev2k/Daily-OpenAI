## 1. Executive Summary

### 1. Cost nên trở thành first-class telemetry của agent run
- **One-sentence summary:** Codex app-server có thể emit `codex.turn_cost` qua OTLP cho OpenAI API-key sessions sau completed hoặc aborted turns, kèm estimated USD cost, interruption state, model, speed và reasoning effort. [Codex #39006, 17/08/2026](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Affected skill area:** Agent evaluation, observability, model comparison, cost/latency optimization.
- **Why it matters:** Hai workflows cùng đạt task success nhưng chênh 2–3× cost hoặc latency không có cùng production fitness.
- **Practical implication:** Mỗi run nên log `outcome + latency + estimated cost + model + reasoning effort + retry/interruption` để phát hiện regression và low-value loops.
- **Priority:** **Critical**.
- **Confirmed facts:** Turn-cost worker chỉ chạy khi OTLP exporter bật và provider là OpenAI; theo dõi turn lifecycle, response count, completed/aborted state; query turn-cost endpoint; emit estimated USD cost; preserve organization/project headers; bounded polling/retry; re-probe sau auth changes. [Source](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Analysis:** Cost observability nên là một eval dimension, không phải billing hậu kiểm. Có thể đo `success-per-dollar`, `verification-cost`, `retry-cost` và `cost of low-value loops`.
- **Recommendation:** Với QA/research/code-review/interview agents, thêm telemetry `runId, stepId, model, reasoningEffort, latencyMs, estimatedCostUsd, retryCount, verifierCostUsd, outcome`.
- **Uncertainty:** Turn-cost endpoint trong commit không được xác nhận là public contract; nên lấy pattern observability, không phụ thuộc endpoint cụ thể.

### 2. Async verifier cần explicit committed-progress signal
- **One-sentence summary:** Codex sửa Guardian approval tests để đợi `latest_scored_tool_call` advance thay vì chỉ chờ `SecurityRiskScore` xuất hiện, vì score có thể visible trước khi progress state hoàn tất. [Codex #39007, 17/08/2026](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Affected skill area:** Async verification, deterministic testing, concurrency, multi-agent handoff.
- **Why it matters:** “Output đã tồn tại” không đồng nghĩa “state machine đã hoàn tất”. Consumer đọc quá sớm có thể tạo flaky behavior và false confidence.
- **Practical implication:** Workflow nên phân biệt `Started → OutputProduced → StateCommitted → ReadyForConsumption`.
- **Priority:** **Critical**.
- **Confirmed facts:** Guardian stores `SecurityRiskScore` trước khi advance `latest_scored_tool_call`; test cũ chờ score có thể assert approval quá sớm; test mới chờ progress counter. [Source](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Analysis:** Pattern này áp dụng cho background jobs, browser screenshots, CI artifacts, MCP tasks và multi-agent handoff.
- **Recommendation:** Tests/consumers phải await explicit completion/version markers thay vì polling file/row/message existence.
- **Uncertainty:** Đây là implementation evidence từ Guardian, không phải API guarantee tổng quát của Codex.

### 3. Managed reviewer policy phải thắng local feature preference
- **One-sentence summary:** Codex force-disable Guardian v2 nếu managed `allowed_approvals_reviewers` không cho phép reviewer `user`, kể cả khi local config bật `guardianv2 = true`. [Codex #39005, 17/08/2026](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Affected skill area:** Permission boundaries, human approval, enterprise config, reviewer architecture.
- **Why it matters:** Local preference không được phép re-enable một approval path mà organization policy đã loại bỏ.
- **Practical implication:** Agent platforms nên tách `desiredConfig` và `effectiveConfig`, với policy/requirements là authoritative constraints.
- **Priority:** **Critical**.
- **Confirmed facts:** Disable áp dụng cho local requirements và cloud config bundles; `config/read` phản ánh effective `false`; Guardian v2 vẫn có thể bật khi `user` reviewer còn allowed. [Source](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Analysis:** Đây là concrete evidence cho monotonic policy model, không phải “last config wins”.
- **Recommendation:** Mọi feature liên quan approval/security nên resolve theo `FeatureDesired ∩ OrgPolicy ∩ EnvironmentPolicy ∩ HumanApproval`.
- **Uncertainty:** Không nên suy rộng rằng mọi Codex feature đã dùng cùng precedence model.

### 4. Async verdict cần freshness bound riêng với confidence
- **One-sentence summary:** Guardian v2 bỏ qua approval review nếu risk score chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async reviewers, agent state synchronization, approval systems.
- **Why it matters:** Một score có thể rất confident nhưng đã stale với current action.
- **Practical implication:** Reviewer output nên bind với `subjectVersion`/`toolCallIndex`, evidence hash và reviewer version.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call`; nếu lag vượt config thì approval review trả `None`; default `3`; tests cover boundary và recovery. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** `confidence`, `freshness`, `evidence completeness` là ba dimensions độc lập của verifier correctness.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, evidenceHash, decision, score, createdAt, reviewerVersion }` và reject stale verdict trước execution.
- **Uncertainty:** Default `3` không có bằng chứng tối ưu cho workload khác.

- **Why it matters:** Retry từng phase độc lập dễ phình total attempts hoặc tạo low-value loops.
- **Practical implication:** Mỗi logical step cần `RetryBudget`, error classifier, idempotency check và stop condition.
- **Priority:** **High**.
- **Confirmed facts:** Retry categories gồm timeout/connection/network, retryable/stream errors, overload, HTTP 5xx và `429`; tests cover `503` recovery và stop khi budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)

- **Uncertainty:** `2` retries chỉ là Guardian implementation choice.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Từ “nhét toàn bộ skills vào prompt” sang catalog có budget + router có eval
- **Problem:** Khi số rules/skills tăng, prompt dài hơn, duplicate instruction nhiều hơn và model phải tự “route” trong một blob lớn.
- **Proposed improvement:** Giữ catalog metadata ngắn; chọn candidate skills bằng router; full-load chỉ top candidates; áp budget riêng cho catalog; ghi lại routing decision và downstream outcome. Codex hiện có cả token budget cho skill catalog và experimental hybrid selectors dùng recent-use + routing-card + lexical signals. [Budget #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Routing #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Why it may work:** Retrieval/ranking tách riêng khỏi execution giúp đo được `wrong-skill rate`, `top-k recall` và token overhead; recent-use signal giúp các turn ngắn như “continue” không mất procedural context.
- **Suitable use cases:** Cursor skills/rules, Codex skills, Claude Code reusable commands, QA skill packs, interview/code-review subagents.
- **Limitations:** Recent-use có thể tạo anchoring; lexical exact-match có thể ưu tiên tên giống query nhưng sai intent; metadata kém làm router kém.
- **Risks:** Router sai nhưng confidence cao; candidate set bị truncate; history kéo workflow cũ sang task mới.
- **Recommendation:** Eval tối thiểu trên 30–50 prompts thực tế, so sánh `static-all`, `lexical-only`, `recent-only`, `hybrid`; đo task success và tokens, không chỉ routing accuracy.

### B. Context cần provenance, không chỉ nội dung
- **Problem:** Agent có thể nhận cùng nội dung nhưng từ nguồn khác nhau: user requirement, inferred assumption, repo rule, org policy, tool output, memory, verifier result.
- **Proposed improvement:** Mỗi context item mang `source`, `authority`, `createdAt`, `subjectVersion`, `hash`, `confidence`, `expiry/freshness`.
- **Why it may work:** Policy precedence và stale-verdict fixes hôm nay cho thấy “nội dung đúng” chưa đủ; nguồn và độ mới quyết định nó còn hợp lệ hay không. [Policy #39005](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576) · [Freshness #39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Suitable use cases:** Research agents, architecture decision agents, requirements analysis, code-review evidence, production incident agents.
- **Limitations:** Metadata adds complexity and storage.
- **Risks:** Nếu provenance optional, hệ thống lại rơi về implicit assumptions.
- **Recommendation:** Tách rõ `Fact`, `Assumption`, `Inference`, `Recommendation`, `Policy`, `Evidence`; chỉ `Policy` có authority override behavior; `Inference` không được silently trở thành `Fact`.

### C. Multimodal evidence phải bounded và có lifecycle
- **Problem:** Browser/QA verifier thiếu screenshot dễ bỏ sót visual failure, nhưng gửi toàn bộ ảnh làm context cost tăng và có rủi ro privacy.
- **Proposed improvement:** Dùng bounded image evidence, recent-first, hash/provenance/redaction; Codex Guardian image transcript hiện opt-in với giới hạn 4 ảnh và 8 MiB. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Why it may work:** Verifier nhìn cùng evidence class với executor mà context vẫn có giới hạn.
- **Suitable use cases:** Playwright QA, visual regression triage, browser automation, UI incident review.
- **Limitations:** Ảnh không thay thế DOM/API evidence; visual model có thể miss subtle state.
- **Risks:** Screenshot chứa PII/secrets; duplicate frames tốn context.
- **Recommendation:** `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, subjectVersion }`; dedupe bằng hash và chỉ đưa ảnh liên quan assertion hiện tại.

## 4. Agent, Workflow, and Loop Engineering

### A. `Plan → Execute → Verify → Decide`, nhưng verifier phải version-aware
- **Problem:** Verifier chạy async có thể đánh giá state cũ trong khi executor đã đi tiếp.
- **Technique:** Mỗi execution step increment `subjectVersion`; verifier trả verdict gắn version; orchestrator chỉ consume verdict nếu chưa stale. Guardian giờ track lag giữa latest tool call và latest scored tool call. [Codex #39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Expected benefit:** Giảm false approval/false rejection do race condition.
- **Failure risks:** Quá strict freshness làm verifier liên tục bị discard nếu executor chạy quá nhanh.
- **Suitable use cases:** QA agents, code-review agents, security reviewers, multi-agent planning.

### B. Retry classification + repair + bounded budget
- **Problem:** Blind retry gây loop, cost tăng và có thể lặp side effect.
- **Technique:** `Attempt → ClassifyFailure → RepairState(optional) → RetryWithinBudget → Replan/Fail`; Codex Guardian retries transient transport/server/stream/rate-limit failures, xử lý `401` qua auth recovery và clear stale pooled connections. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Expected benefit:** Recover transient failures mà vẫn có stop condition.
- **Failure risks:** Misclassification; retry action không idempotent; retry storm khi nhiều workers cùng lỗi.
- **Suitable use cases:** MCP calls, Graph/API calls, browser interactions, CI/CD commands, LLM streaming.
- **Recommendation:** Failure taxonomy: `TransientTransport`, `TransientServer`, `RateLimit`, `UnauthorizedRecoverable`, `PermanentRequest`, `Quota`, `PolicyViolation`, `ContextLimit`, `Superseded`, `Unknown`.

### C. Output visibility != completion
- **Problem:** Một artifact có thể xuất hiện trước khi related state commit hoàn tất.
- **Technique:** State machine `Started → OutputProduced → StateCommitted → ReadyForConsumption`; test wait vào completion marker/version, không wait artifact existence. [Codex #39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Expected benefit:** Flaky tests và race conditions giảm mạnh.
- **Failure risks:** Completion event bị mất; consumer chờ vô hạn nếu không timeout.
- **Suitable use cases:** Background jobs, async QA video/screenshot processing, CI artifact generation, agent handoffs.

### D. Cost-aware stop conditions
- **Problem:** Agent có thể vẫn “progressing” nhưng marginal value thấp trong khi cost tiếp tục tăng.
- **Technique:** Mỗi loop ghi cumulative cost, latency, retries, novel evidence count, changed-output hash; stop/replan nếu cost tăng mà evidence/output không đổi đáng kể.
- **Expected benefit:** Phát hiện low-value loops và runaway verifier chains.
- **Failure risks:** Cost threshold quá thấp làm dừng task khó nhưng cần thiết.
- **Suitable use cases:** Deep research, interview graph generation, code review on large diffs, long QA suites.
- **Concrete test:** So sánh baseline với stop rule `same failure signature >=2`, `same output hash >=2`, hoặc `cost +50% without new evidence`; đo task success và median cost.

- **Effort:** **Half a day** cho model + tests; **Several days** nếu migrate toàn artifact pipeline.
- **Concrete test:** Cố ý delay screenshot writer sau khi row artifact được tạo; verifier phải chờ completion marker, không pass sớm.

### 3. Chuẩn hóa retry policy trong .NET agent runner
- **Relevance:** Graph, HTTP, browser, MCP và LLM streaming đều có transient failures nhưng semantics khác nhau.
- **Existing workflow improved:** QA browser actions, Microsoft Graph integrations, research fetchers, CI tooling.
- **What to change/test:** Viết `IRetryClassifier` + `RetryBudget` + `RepairAction`; phân biệt 429/5xx/network/401/quota/policy/validation; side-effecting command bắt buộc idempotency key hoặc no-auto-retry.
- **Expected benefit:** Giảm blind retry, tránh duplicated side effects, telemetry rõ hơn.
- **Effort:** **Half a day** cho core abstraction, **Several days** để rollout.
- **Recommendation:** Sau 2 lần cùng failure signature, chuyển `ReplanRequired` thay vì tăng retry count tự động.

### 4. Refactor Cursor/Codex/Claude reusable instructions thành catalog + routing metadata
- **Relevance:** Khi skill/rule packs tăng, full injection sẽ nhanh chóng trở thành context bottleneck.
- **Existing workflow improved:** Cursor rules/skills, Codex skills, Claude Code commands, knowledge-transfer packs.

### 5. Tách `desiredConfig` và `effectiveConfig` trong agent platform

## 7. Opportunities and Trends to Watch

### 1. Agent observability chuyển từ token counting sang outcome/cost/reasoning telemetry
- **What is changing:** Codex source bắt đầu attach estimated cost, model, speed, reasoning effort và interrupted state vào turn telemetry. [#39006](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Why it matters:** Có thể tối ưu theo production objective thay vì model leaderboard.
- **Opportunity:** Xây eval dashboards cho `quality × latency × cost × retries × verifier overhead`.
- **Risk:** Cost estimate không đồng nhất giữa providers; dễ tối ưu chi phí mà làm giảm correctness.
- **Status:** **Growing**.

### 2. Async verifier correctness trở thành distributed-systems problem
- **What is changing:** Freshness lag, progress counters và race-condition tests xuất hiện trực tiếp trong Guardian reviewer path. [#39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1) · [#39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Why it matters:** Multi-agent không chỉ là prompt orchestration; nó có versioning, consistency, stale reads và concurrency.
- **Opportunity:** Reusable `VersionedVerdict`, `EvidenceManifest`, `CompletionBarrier` libraries cho agent runtimes.
- **Risk:** Overengineering cho workflow đơn giản.
- **Status:** **Growing**.

### 3. Skills đang trở thành retrieval system hơn là prompt feature
- **What is changing:** Token budget + hybrid routing + recent-use memory + shadow evaluation. [#38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Why it matters:** Skill count có thể scale mà không tuyến tính tăng context.
- **Opportunity:** Vendor-neutral skill router/eval harness cho Cursor/Codex/Claude.
- **Risk:** Router complexity lớn hơn lợi ích nếu chỉ có vài skills.
- **Status:** **Growing**.

### 4. Policy engines sẽ tách khỏi prompt/rules layer
- **What is changing:** Managed reviewer requirements và environment command policies có precedence/enforcement ngoài prompt. [#39005](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576) · [#38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Why it matters:** Enterprise agents cần deterministic authority boundaries.
- **Opportunity:** Policy-as-code cho agent actions, approvals, secrets, environments.
- **Risk:** UX kém nếu effective policy khó giải thích.
- **Status:** **Established direction / Growing implementation**.

### 5. Provider-native adapters thay cho lowest-common-denominator abstraction
- **What is changing:** OpenCode `main` giữ native OpenAI Responses và Anthropic Messages path thay vì ép tất cả vào một compat protocol. [OpenCode commit](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Why it matters:** Native reasoning/tool/streaming semantics dễ bị mất nếu normalize quá sớm.
- **Opportunity:** `IModelProvider` + capability negotiation trong .NET agent platforms.
- **Risk:** Adapter maintenance tăng, behavior khác nhau theo provider/auth route.
- **Status:** **Growing**.
