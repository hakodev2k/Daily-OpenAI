## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **Policy**, **Procedure**, **Context**, **Task** thành bốn lớp khác nhau

- **Problem:** Một file `rules.md` lớn dễ trộn security constraints, coding conventions, workflow steps và task-specific details.
- **Proposed improvement:**
  - `policy/`: deny/allow boundaries, approval requirements, data restrictions.
  - `skills/`: reusable procedures và checklists.
  - `context/`: architecture/repo/domain facts.
  - `task/`: objective, acceptance criteria, current evidence.
- **Why it may work:** Codex environment policy change là evidence rõ cho principle “lower-level context chỉ được restrict authority”.
- **Suitable use cases:** Cursor rules, Claude Code `CLAUDE.md`/skills, Codex instructions/skills, QA/research/review agents.
- **Limitations:** Nhiều file hơn, cần precedence rõ và loader deterministic.
- **Risks:** Duplicate/inconsistent instruction giữa layers.
- **Confirmed facts:** Codex source hiện phân biệt environment policy khỏi broader active command policy. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Analysis:** Instruction quality phụ thuộc nhiều vào boundary clarity hơn là tăng số lượng prose.
- **Recommendation:** Mỗi rule nên có `scope`, `priority`, `enforcement`, `owner`, `version`.
- **Uncertainty:** Không có benchmark cho thấy cấu trúc bốn lớp luôn tăng task success; cần A/B eval trên task set thực tế.

### B. Thêm **Facts / Evidence / Assumptions / Inferences / Decisions / Unknowns** vào context handoff

- **Problem:** Long-running agents dễ biến inference thành fact sau nhiều lần summarize/fork.
- **Proposed improvement:** Checkpoint artifact có sáu buckets rõ ràng.
- **Why it may work:** Khi project/thread/run được tách lifecycle, structured handoff giảm phụ thuộc transcript và làm reasoning trace audit-friendly hơn.
- **Suitable use cases:** Architecture planning, incident RCA, interview-agent story verification, QA bug triage, research synthesis.
- **Limitations:** Tăng token/storage overhead.
- **Risks:** Agent có thể mechanically classify sai nếu không có evidence validator.
- **Recommendation:** `Facts` bắt buộc source/evidence pointer; `Assumptions` bắt buộc confidence + verification plan; `Decision` bắt buộc rationale + rejected alternatives.
- **Test method:** Chạy cùng 20 tasks với transcript-only vs structured handoff; đo contradiction rate, repeated-tool-call rate, human correction count.

### C. Capability metadata phải gắn với **route**, không chỉ model name

- **Problem:** Cùng model name nhưng provider/auth/gateway path có thể có effective limits hoặc features khác nhau.
- **Proposed improvement:** Registry key dạng `provider + model + auth_mode + transport + tool_version`.
- **Why it may work:** OpenCode source change hôm nay cho thấy native passthrough và ChatGPT-subscription path có logic riêng.
- **Suitable use cases:** Context budgeting, model routing, cost/latency eval, fallback selection.
- **Limitations:** Registry dễ stale.
- **Risks:** Hard-coded limits trở thành false facts khi provider thay đổi.
- **Recommendation:** Kèm `observed_at`, `source`, `probe_result`; prefer runtime capability probe khi có.

## 4. Agent, Workflow, and Loop Engineering

### A. Dùng `NO_MATERIAL_DELTA` như một **stop condition** hợp lệ

- **Problem:** Research/monitoring agents tiếp tục search vì objective mơ hồ “tìm latest”.
- **Technique:** Sau N primary-source groups không có delta: stop search, emit evidence table, chuyển phase sang `ValidateKnownChanges`.
- **Expected benefit:** Giảm repeated search, latency, cost và news duplication.
- **Failure risks:** Stop quá sớm nếu source coverage hẹp.
- **Suitable use cases:** Daily briefings, dependency monitoring, release radar, security change detection.
- **Recommendation:** Stop only khi đã cover `official release notes + source repo + stable release endpoint + relevant spec/docs`.

### B. Approval cache phải depend on **policy revision**

- **Problem:** Command từng được approve có thể không còn hợp lệ sau policy/environment change.
- **Technique:** Cache key = `action identity + environment + policy fingerprint + risk class`.
- **Expected benefit:** Tránh stale human approvals.
- **Failure risks:** Too-frequent invalidation gây approval fatigue.
- **Suitable use cases:** Deployment agent, database write agent, package installation, infra mutation.
- **Confirmed facts:** Codex main đã đưa environment-policy fingerprint vào cached approval keys. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Recommendation:** Thêm TTL + reason hash; low-risk approvals có thể cache ngắn, high-risk writes luôn re-evaluate.

### C. `Plan → Execute → Verify → Decide`, không dùng `Plan → Execute → Execute → Execute`

- **Problem:** Agent thường retry cùng chiến thuật sau failure mà không classify error.
- **Technique:** Mỗi execution phase phải tạo verifier result; sau 2 failures cùng signature bắt buộc re-plan/root-cause.
- **Expected benefit:** Giảm low-value loops và destructive retries.
- **Failure risks:** Verifier yếu có thể false-pass.
- **Suitable use cases:** QA automation, CI fixing, migrations, browser automation, code review auto-fix.
- **Recommendation:** Error fingerprint gồm exception type, exit code, failing test IDs, affected files và tool-state snapshot.

### D. Separate **Project state** from **Run state**

- **Problem:** Một session fail/restart làm mất work hoặc contaminate new attempt bằng stale assumptions.
- **Technique:** Stable project state immutable/versioned; run state disposable; artifacts/evidence append-only.
- **Expected benefit:** Resume, fork, compare approaches và audit tốt hơn.
- **Failure risks:** State synchronization complexity.
- **Suitable use cases:** Research agents, interview intelligence, multi-repo refactors, QA campaigns.
- **Confirmed facts:** Codex experimental project APIs tách project lifecycle khỏi threads và giữ thread sau project deletion. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

### 3. Native provider adapters quay trở lại sau giai đoạn “OpenAI-compatible everything”

- **What is changing:** OpenCode gateway work giữ native OpenAI/Anthropic paths.
- **Why it matters:** Tool calls, reasoning, streaming và auth semantics không phải lúc nào cũng flatten an toàn.
- **Opportunity:** Multi-provider .NET gateway có common governance + native adapters + contract tests.
- **Risk:** Adapter maintenance cost tăng.
- **Status:** **Growing**.

### 4. Agent evaluation cần thêm **tool/harness version** như một axis bắt buộc

- **What is changing:** Source/main, prerelease, stable CLI, IDE Agent Host và hosted surfaces evolve độc lập.
- **Why it matters:** Benchmark model mà không pin harness version có thể đo nhầm tool behavior thay vì model quality.
- **Opportunity:** Eval harness lưu full environment manifest và reproducible task corpus.
- **Risk:** Matrix explosion.
- **Status:** **Established** về principle, nhưng implementation trong nhiều personal-agent projects còn thiếu.

### 5. MCP ecosystem đang chuyển trọng tâm từ “kết nối tool” sang auth/gateway/interceptor/skills concerns

- **What is changing:** Current MCP 2026-07-28 spec đã có stateless core, extensions, authorization hardening; public events hiện có dedicated auth, gateways, interceptors, server-card và skills-over-MCP groups. [MCP spec](https://blog.modelcontextprotocol.io/posts/2026-07-28/) · [MCP events](https://meet.modelcontextprotocol.io/)
- **Why it matters:** Production MCP không còn chỉ là expose functions; governance và lifecycle trở thành phần chính.
- **Opportunity:** .NET MCP gateway/interceptor package cho auth, audit, rate limit, policy, evidence capture.
- **Risk:** Chasing experimental surfaces quá sớm.
- **Status:** **Early signal / Growing**.
