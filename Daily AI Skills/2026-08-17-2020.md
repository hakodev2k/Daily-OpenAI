## 1. Executive Summary

### 1. Managed reviewer policy phải thắng local feature preference
- **One-sentence summary:** Codex giờ force-disable Guardian v2 nếu policy quản trị `allowed_approvals_reviewers` loại reviewer `user`, kể cả khi local config bật `guardianv2 = true`. [Codex #39005, 17/08/2026](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Affected skill area:** Permission boundaries, reviewer policy, enterprise config, human approval.
- **Why it matters:** Một feature local không được phép vô tình mở lại review path mà tổ chức đã chủ động loại khỏi policy.
- **Practical implication:** Config layering cho agents phải phân biệt **preference** với **requirement/policy**; policy layer nên monotonic và authoritative.
- **Priority:** **Critical**.
- **Confirmed facts:** Commit áp dụng disable khi managed reviewer set không chứa `user`, cho cả local requirements và cloud bundles; khi `user` còn được phép, Guardian v2 vẫn có thể bật; `config/read` trả effective value `false` trong case bị policy override. [Source](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Analysis:** Đây là ví dụ mạnh cho rule `effective capability = feature preference ∩ organizational policy`, không phải “last config wins”.
- **Recommendation:** Trong agent platform tự xây, tách `desiredConfig` và `effectiveConfig`; mọi UI/debug endpoint phải hiển thị effective value cùng lý do bị policy override.
- **Uncertainty:** Commit mô tả Guardian reviewer path cụ thể; không nên suy rộng rằng mọi Codex feature đã dùng cùng precedence model.

### 2. Asynchronous verifier phải có freshness bound
- **One-sentence summary:** Guardian v2 bỏ qua approval review nếu risk score chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async reviewers, approval systems, concurrency, agent state.
- **Why it matters:** Verdict cũ có thể vẫn “đúng” với action cũ nhưng không còn hợp lệ với state mới.
- **Practical implication:** Reviewer output cần `subjectVersion`/`toolCallIndex`, và consumer phải reject stale verdict trước execution.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call`; nếu lag vượt config thì approval review trả `None`; default lag = 3; tests cover boundary, stale state và recovery. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** `confidence` và `freshness` là hai dimensions độc lập.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, evidenceHash, score, decision, createdAt, reviewerVersion }`.
- **Uncertainty:** Default `3` không có bằng chứng tối ưu cho workload khác.

### 3. Retry phải bounded trên toàn logical operation
- **One-sentence summary:** Guardian sampler dùng chung retry budget tối đa 2 lần cho lease connection, request start và stream consumption. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, long-running agents, verifier reliability.
- **Why it matters:** Retry từng phase riêng có thể phình attempt count hoặc tạo low-value loops.
- **Practical implication:** Một logical step nên có shared `RetryBudget`, error classification và stop condition.
- **Priority:** **Critical**.
- **Confirmed facts:** Retryable categories gồm timeout/connection/network, retryable/stream errors, overload, HTTP 5xx và `429`; tests verify `503` recovery và stop khi budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Reliability loop tốt cần cả retry boundedness, freshness và re-plan trigger.
- **Recommendation:** Sau retry budget hết, chuyển state sang `ReplanRequired` thay vì tiếp tục retry cùng strategy.
- **Uncertainty:** `2` retries chỉ là implementation choice của Guardian.

### 4. Skill routing đang tiến tới hybrid retrieval + recent-use memory
- **One-sentence summary:** Codex thêm shadow selectors fuse recently invoked skills với character routing-card matches bằng Reciprocal Rank Fusion; một variant thêm weighted lexical matching. [Codex #38993, 17/08/2026](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Skills, routing, context engineering, multi-turn memory, evals.
- **Why it matters:** Turn như “continue”, “retry”, “fix that” có ít lexical signal nhưng recent-use history là strong prior.
- **Practical implication:** Router nên fuse query relevance, recent skill history, routing metadata và lexical/semantic signals.
- **Priority:** **High**.
- **Confirmed facts:** New selectors dùng RRF `K=10`, cap 50 candidates; tests cover cold start, exact matches, duplicate removal, deterministic ranking và recover prior-turn skill. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Đây là procedural short-term memory rẻ hơn việc inject full transcript.
- **Recommendation:** Shadow-run routing variants và đo top-1/top-k recall, wrong-skill rate, downstream task success, latency và token cost.
- **Uncertainty:** Chưa có evidence các selectors mới đã thành production default.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách `desiredConfig` khỏi `effectiveConfig`
- **Problem:** User/repo config có thể bật capability trong khi policy quản trị yêu cầu tắt.
- **Proposed improvement:** Resolve config theo hai outputs: `desiredConfig` cho preference và `effectiveConfig` sau khi áp policy constraints; expose cả `reason` và `sourceLayer` cho mỗi override.
- **Why it may work:** Codex #39005 thể hiện đúng pattern này: local `guardianv2=true` không thắng managed reviewer requirement, và `config/read` trả effective disabled value.
- **Suitable use cases:** Cursor/Claude/Codex rules, enterprise agent runners, Teams/Slack plugins, deployment agents.
- **Limitations:** Layering càng nhiều càng khó debug nếu không có provenance.
- **Risks:** Nếu UI chỉ hiển thị desired value, người vận hành sẽ hiểu sai capability đang thực sự bật.
- **Recommendation:** Tạo cấu trúc `ResolvedSetting { desired, effective, source, constrainedBy, explanation }`.
- **Uncertainty:** Cần tự định nghĩa policy model nếu tool không expose provenance đầy đủ.

### B. Skill catalog nên dùng two-stage context loading
- **Problem:** Inject full skill instructions gây token pressure và dễ làm loãng context.
- **Proposed improvement:** Stage 1 chỉ inject routing metadata ngắn; stage 2 lazy-load full skill khi router chọn candidate.
- **Why it may work:** Codex vừa giới hạn catalog token budget, vừa đầu tư hybrid selector.
- **Suitable use cases:** Large skill libraries cho QA, research, architecture, interview, code review.
- **Limitations:** Router miss ở stage 1 sẽ không bao giờ load skill tốt ở stage 2.
- **Risks:** Metadata quá ngắn hoặc mơ hồ gây wrong routing.
- **Recommendation:** Mỗi skill có `name`, `purpose`, `triggers`, `anti-triggers`, `requiredTools`, `outputs`, `riskLevel`.
- **Uncertainty:** Không có public evidence cho schema metadata tối ưu.

### C. Reviewer context phải versioned, không chỉ “recent”
- **Problem:** Async reviewer có thể hoàn thành sau khi executor state đã thay đổi.
- **Proposed improvement:** Mỗi review request gắn `subjectVersion`, `evidenceHash` và `stateVersion`; result chỉ valid nếu consumer version vẫn trong allowed lag.
- **Why it may work:** Guardian #39001 đã chuyển từ score-only sang score + tool-call freshness.
- **Suitable use cases:** Browser QA, CI review, migration approval, production ops agents.
- **Limitations:** Versioning không tự giải quyết semantic drift nếu state change nhỏ nhưng quan trọng.
- **Risks:** Lag threshold quá rộng gây stale approval; quá hẹp gây excessive re-review.
- **Recommendation:** Tune lag bằng evals theo domain, không copy default 3 một cách máy móc.

## 4. Agent, Workflow, and Loop Engineering

### A. `Plan → Execute → Verify → Freshness Check → Decide`
- **Problem:** Nhiều workflows dùng verifier nhưng không kiểm tra verdict còn valid với state hiện tại.
- **Technique:** Thêm freshness gate sau verifier và trước action decision.
- **Expected benefit:** Tránh apply verdict cũ cho action/state mới.
- **Failure risks:** Có thể tạo churn nếu executor tiến quá nhanh so với verifier.
- **Suitable use cases:** Parallel QA/verifier agents, code review agents, browser agents, infrastructure automation.
- **Recommendation:** Khi stale, không dùng verdict; enqueue re-review với current version.

### B. Retry budget + re-plan boundary
- **Problem:** Retry loops thường lặp cùng action mà không đổi hypothesis.
- **Technique:** Shared retry budget trên logical operation; khi hết budget, chuyển state sang `ReplanRequired`.
- **Expected benefit:** Giảm low-value loops, làm failure observable hơn.
- **Failure risks:** Re-plan quá sớm với flaky infrastructure.
- **Suitable use cases:** API calls, browser navigation, CI jobs, MCP tools, database operations.
- **Recommendation:** Log `failureSignature`; nếu cùng signature lặp 2 lần, ưu tiên root-cause/re-plan hơn retry thứ ba.

### C. Shadow evaluation cho decision components
- **Problem:** Router/planner/reviewer threshold thay đổi có thể silent-regress.
- **Technique:** Chạy candidate decision logic song song nhưng không điều khiển execution; ghi active choice và shadow choice.
- **Expected benefit:** Có dữ liệu production-like trước rollout.
- **Failure risks:** Telemetry cost và privacy nếu log quá nhiều context.
- **Suitable use cases:** Skill router, model router, verifier threshold, retry classifier, planner variants.
- **Recommendation:** Log decision IDs, features, candidate rank, latency và downstream outcome; tránh lưu raw sensitive prompts nếu không cần.

### D. Managed policy phải là monotonic constraint
- **Problem:** Nested config layers dễ vô tình mở lại quyền ở layer thấp hơn.
- **Technique:** Policy layer chỉ được giữ nguyên hoặc restrict, không expand.
- **Expected benefit:** Dễ reason và audit hơn “last-write-wins”.
- **Failure risks:** Quá restrictive nếu inheritance không minh bạch.
- **Suitable use cases:** Shell permissions, reviewer policy, plugin access, database write tools, deploy tools.
- **Recommendation:** Mỗi capability decision trả `allowed/denied + governingPolicy + policyHash`.

## 7. Opportunities and Trends to Watch

### 1. **Policy-aware effective configuration** — **Growing**
- **What is changing:** Agent runtimes đang phân biệt feature preference với managed requirements/policy.
- **Why it matters:** Enterprise/production agents cần predictable authority và explainable overrides.
- **Opportunity:** Xây vendor-neutral config resolver + policy provenance layer cho multi-agent systems.
- **Risk:** Quá nhiều layers nếu không có diagnostics sẽ tạo configuration opacity.

### 2. **Freshness-aware async verification** — **Early signal**
- **What is changing:** Reviewer output bắt đầu được bound vào execution progress/version thay vì chỉ score threshold.
- **Why it matters:** Parallel agents và long-running workflows sẽ tăng race/stale-state problems.
- **Opportunity:** Generic `VersionedVerdict` middleware cho QA, code review, infra approval.
- **Risk:** Hard-coded lag threshold không phù hợp mọi domain.

### 3. **Skill routing as retrieval system, not prompt enumeration** — **Growing**
- **What is changing:** Token budgets + hybrid routing + shadow evaluation xuất hiện cùng nhau.
- **Why it matters:** Reusable skill catalogs càng lớn càng cần IR-style ranking/evals.
- **Opportunity:** Build local router benchmark harness dùng chung cho Cursor/Claude/Codex/OpenCode skills.
- **Risk:** Overengineering khi catalog chỉ có vài skills.

### 4. **Verifier evidence symmetry** — **Growing**
- **What is changing:** Multimodal evidence đi vào safety/reviewer sampling.
- **Why it matters:** Browser/UI executor và verifier cần nhìn cùng loại evidence.
- **Opportunity:** Evidence packet standard cho screenshots, DOM, logs, tool outputs.
- **Risk:** PII/secrets và context cost.

### 5. **Runtime security replacing prompt-only guardrails** — **Established direction**
- **What is changing:** Monotonic command policy, policy-aware approvals, secret scrubbing.
- **Why it matters:** Production safety cần enforcement outside the model.
- **Opportunity:** Reusable .NET execution sandbox/policy middleware cho agent tools.
- **Risk:** Permission UX kém có thể khiến người dùng disable guardrails để “cho chạy được”.
