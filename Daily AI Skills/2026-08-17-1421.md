## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách “policy” khỏi “procedure” và “task context”

- **Problem:** Một file rules/instructions quá lớn thường trộn security policy, coding conventions, workflow steps, repo knowledge và task-specific requirements. Kết quả là khó review precedence, khó biết rule nào bắt buộc, và context token bị tiêu tốn cho nội dung không liên quan.
- **Proposed improvement:** Chia thành bốn lớp rõ ràng:
  1. `Policy`: điều agent không được vi phạm — permissions, secrets, destructive operations, approval gates.
  2. `Repository guidance`: conventions, architecture boundaries, build/test commands.
  3. `Reusable skill`: procedure có trigger rõ — review PR, investigate bug, write migration, run QA.
  4. `Task context`: acceptance criteria và evidence của run hiện tại.
- **Why it may work:** Codex environment policy change cho thấy enforcement và user/task instructions nên là các concern khác nhau; lower layer không được nới quyền. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor rules/skills, Claude Code commands/agents, Codex Skills/AGENTS, QA/research/code-review agents.
- **Limitations:** Tool-specific instruction resolution khác nhau; cần regression test sau khi refactor.
- **Risks:** Split quá nhỏ tạo nhiều lookup; thiếu deterministic precedence khiến agent vẫn conflict.
- **Recommendation:** Mỗi file nên có `scope`, `priority`, `when_to_apply`, `must_not`, `expected_output` thay vì narrative dài.

### B. Capability registry thay cho model-name assumptions

- **Problem:** Prompt pipeline thường hard-code context size, tool support hoặc reasoning parameters theo model name.
- **Proposed improvement:** Dùng `ModelCapabilityRegistry` với key gồm `provider`, `model`, `access_mode`, `route`, `tool_version`; entry có `context`, `max_input`, `max_output`, `tools`, `reasoning`, `streaming`, `source`, `verified_at`.
- **Why it may work:** OpenCode vừa phải sửa GPT-5.6 limits riêng cho ChatGPT subscription path. [OpenCode #39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Suitable use cases:** Multi-model agent platforms, context compaction, evaluation harness, cost/latency routing.
- **Limitations:** Một số capabilities chỉ có thể probe runtime; API limits có thể thay đổi server-side.
- **Risks:** Registry stale tạo false confidence.
- **Recommendation:** Tất cả capability entries phải có provenance và expiration/revalidation rule.

### C. Handoff nên truyền structured state, không truyền toàn transcript

- **Problem:** Multi-agent workflows dễ copy toàn transcript từ planner sang executor/verifier, gây context pollution và làm verifier bị anchoring vào reasoning trước đó.
- **Proposed improvement:** Handoff artifact gồm `Goal`, `Facts`, `Evidence`, `Assumptions`, `Decisions`, `OpenQuestions`, `Constraints`, `FilesChanged`, `TestsRun`, `Failures`, `NextAction`.
- **Why it may work:** Codex experimental project/thread separation củng cố pattern project state độc lập conversation. [Codex #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Suitable use cases:** QA agents, research agents, interview intelligence, architecture review, long-running coding tasks.
- **Limitations:** Summarization có thể mất nuance; evidence links phải giữ nguyên.
- **Risks:** Agent upstream có thể đưa inference vào `Facts` nếu schema không validate.
- **Recommendation:** Bắt buộc field-level provenance: `FACT`, `ASSUMPTION`, `INFERENCE`, `RECOMMENDATION`, `UNKNOWN`.

## 4. Agent, Workflow, and Loop Engineering

### A. Stop condition chống low-value research loop

- **Problem:** Agent tiếp tục search/re-read khi không có material delta, tạo latency/cost nhưng không tăng information value.
- **Technique:** Sau mỗi research round, tính:
  - `new_primary_sources`
  - `new_material_claims`
  - `claims_changed_since_last_run`
  - `source_diversity`
  - `uncertainty_reduction`

  Stop khi `new_material_claims == 0` sau một số nguồn primary đủ rộng và previous run đủ gần.
- **Expected benefit:** Giảm repeated browsing, tránh briefing giả tạo novelty.
- **Failure risks:** Stop quá sớm có thể bỏ sót source khác; cần source coverage checklist.
- **Suitable use cases:** Daily radars, job scans, market briefs, GitHub release monitors, research agents.
- **Recommendation:** Nếu stop vì no delta, chuyển phase sang `validate/adopt/reject` thay vì kết thúc vô ích.

### B. Approval cache phải phụ thuộc policy revision

- **Problem:** Human từng approve command trước đó nhưng policy/environment đã đổi; reuse approval cũ có thể bypass guardrail mới.
- **Technique:** Cache key nên chứa `command_signature + workspace + environment + policy_hash + tool_version`.
- **Expected benefit:** Policy đổi → approval tự hết hiệu lực.
- **Failure risks:** Too-specific key gây excessive prompts; too-broad key gây privilege leakage.
- **Evidence:** Codex đưa environment policy fingerprint vào cached approval keys. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Deploy agent, DB migration agent, file-system agent, shell-enabled code agent.

### C. Retry phải đổi hypothesis, không chỉ lặp action

- **Problem:** Test-fix-retest loop có thể lặp cùng failure signature nhiều lần.
- **Technique:** Sau 2 lần cùng normalized failure signature:
  1. stop execution;
  2. capture evidence;
  3. generate alternative root-cause hypotheses;
  4. choose discriminating test;
  5. only then resume.
- **Expected benefit:** Giảm “thrashing” và accidental regressions.
- **Failure risks:** Signature normalization kém có thể gom nhầm lỗi khác nhau.
- **Suitable use cases:** Selenium/Playwright flaky flows, CI debugging, integration tests, package/version conflicts.
- **Recommendation:** Log `failure_signature`, `attempt`, `hypothesis`, `evidence`, `next_discriminating_test`.

### D. Verifier nên độc lập khỏi executor khi chất lượng quan trọng

- **Problem:** Executor dễ self-confirm solution của mình.
- **Technique:** Verifier chỉ nhận requirement + diff/artifacts + test evidence, không nhận full internal reasoning của executor.
- **Expected benefit:** Giảm anchoring; tăng khả năng phát hiện missing edge case.
- **Failure risks:** Tăng cost/latency; verifier model vẫn có thể cùng failure mode.
- **Suitable use cases:** Code review agent, QA agent, architecture decision, security-sensitive changes.
- **Test method:** So sánh detection rate của independent verifier với self-review trên một bộ bug/requirements cố định.

## 5. Hooks and Integrations

### 1. .NET child-process sanitizer cho agent hooks

- **Can integrate:** `ProcessStartInfo`, build/test CLI, Git hooks, custom agent command hooks.
- **Workflow benefit:** Agent có thể chạy tooling thực tế mà không tự động truyền control-plane credentials xuống child process.
- **Security/permission concerns:** Phải xử lý Windows case-insensitive env names; scrub sau override; tránh log secret values.
- **Difficulty:** **Moderate**.
- **Evidence:** Codex secret-scrubbing change. [#38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)

### 2. GitHub Actions as deterministic verifier, không phải “AI judge duy nhất”

- **Can integrate:** Agent tạo patch → push branch → deterministic build/tests/lint/security checks → agent chỉ diễn giải failures và đề xuất fix.
- **Workflow benefit:** Tách correctness checks có thể xác định bằng machine khỏi subjective LLM review.
- **Security/permission concerns:** Token scope tối thiểu; fork/PR secrets; untrusted code không được tự nhận deployment credentials.
- **Difficulty:** **Moderate**.
- **Recommendation:** `LLM review` không thay thế `dotnet test`, linters, schema validation, migration dry-run hoặc contract tests.

### 3. MCP gateway với provider/tool allowlists theo environment

- **Can integrate:** MCP tools cho GitHub, DB read-only, browser, files, Teams/Slack/Confluence.
- **Workflow benefit:** Một tool layer thống nhất nhưng permission profile khác nhau theo `dev`, `qa`, `prod`.
- **Security/permission concerns:** Tool discovery không đồng nghĩa tool invocation authority; production write nên explicit approval.
- **Difficulty:** **Advanced**.
- **Recommendation:** Apply same deny-overrides pattern: environment profile có thể disable tool/capability nhưng không tự enable tool bị global policy cấm.

### 4. Native provider adapters sau internal gateway

- **Can integrate:** OpenAI Responses API, Anthropic Messages API, provider-specific reasoning/tool options sau một routing layer nội bộ.
- **Workflow benefit:** Giữ observability/routing chung nhưng không mất native features.
- **Security/permission concerns:** BYOK separation; gateway token và upstream provider keys phải có ownership rõ; không leak credential giữa providers.
- **Difficulty:** **Advanced**.
- **Evidence:** OpenCode Cloudflare AI Gateway implementation. [#42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)

## 7. Opportunities and Trends to Watch

### Trend 1. Permission semantics đang dịch từ prompt rules sang runtime policy composition

- **What is changing:** Agent tools ngày càng formalize execution policies, approval state và environment restrictions thay vì chỉ dựa vào instructions.
- **Why it matters:** Prompt không phải security boundary.
- **Opportunity:** Build reusable .NET permission engine cho local agents/MCP workers với deny-overrides, approval cache và audit trail.
- **Risk:** Overengineering nếu agent chỉ read-only/local; policy UX quá phức tạp có thể làm người dùng tắt guardrails.
- **Status:** **Growing**.
- **Evidence:** Codex environment-specific command policy. [#38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### Trend 2. Agent state đang tách khỏi transcript/chat

- **What is changing:** Project/workspace-level entities, persistent metadata, roots và thread assignments đang được formalize.
- **Why it matters:** Long-running work cần resume/fork/audit mà không phụ thuộc một conversation duy nhất.
- **Opportunity:** Knowledge-transfer system hoặc QA/research platform có first-class `Project`, `Run`, `Evidence`, `Artifact` model.
- **Risk:** Schema complexity; migration/versioning; accidental state leakage giữa runs.
- **Status:** **Experimental → Growing**.
- **Evidence:** Codex experimental project APIs. [#38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

### Trend 3. Provider gateways sẽ cần “common governance, native protocol”

- **What is changing:** Một gateway có thể unify routing/telemetry/BYOK nhưng vẫn giữ native API semantics cho từng provider.
- **Why it matters:** Reasoning/tool behavior ngày càng khó flatten vào một compatibility schema.
- **Opportunity:** .NET AI gateway có common observability + provider-specific capability adapters.
- **Risk:** Adapter maintenance tăng; abstraction surface lớn hơn.
- **Status:** **Growing**.
- **Evidence:** OpenCode native Cloudflare passthrough. [#42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)

### Trend 4. Capability metadata sẽ phải versioned theo access path

- **What is changing:** Context/tool limits có thể khác giữa API, subscription, gateway, wrapper và model family.
- **Why it matters:** Planning/compaction/evaluation sai nếu model metadata stale.
- **Opportunity:** Open-source capability registry + probes + regression suite cho agent harnesses.
- **Risk:** Server-side limits thay đổi nhanh; probe có thể tốn chi phí.
- **Status:** **Growing**.
- **Evidence:** OpenCode GPT-5.6 ChatGPT-subscription limit correction. [#39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)

### Trend 5. “No material update” nên trở thành first-class result của research agents

- **What is changing:** Khi monitoring chạy dày, duplicate detection và stop conditions trở nên quan trọng ngang search quality.
- **Why it matters:** Một agent luôn buộc phải tìm “tin mới” sẽ có incentive tạo novelty giả.
- **Opportunity:** Claim fingerprinting, source-delta detection, confidence decay và `no_change` outputs cho scheduled research systems.
- **Risk:** Threshold quá mạnh có thể bỏ sót subtle update.
- **Status:** **Established engineering need**, nhưng còn ít workflow làm tốt.
