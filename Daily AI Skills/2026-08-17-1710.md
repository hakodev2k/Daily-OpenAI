## 1. Executive Summary

### 1. Codex thêm **configurable skill catalog token budget** — thay đổi trực tiếp cho Context Engineering

- **One-sentence summary:** Codex vừa merge `[skills].max_context_tokens`, cho phép override token budget của available-skills catalog; giá trị phải >0, bị cap ở 10.000 tokens, còn khi unset thì giữ mặc định 2% model context window. [Codex #38978, 17/08/2026](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Affected skill area:** Skills architecture, context budgeting, skill discovery, prompt efficiency.
- **Why it matters:** Một agent có hàng chục/hàng trăm reusable skills có thể tốn context đáng kể chỉ để “quảng cáo” catalog trước khi skill thực sự được chọn; budget riêng biến overhead này thành một parameter có thể đo và kiểm soát.
- **Practical implication:** Với repository lớn hoặc multi-agent platform, có thể benchmark trade-off `catalog recall ↔ prompt cost ↔ latency` thay vì để skill metadata scale ngầm theo context window.
- **Priority:** **Critical** cho hệ thống có nhiều skills; **High** cho coding agent cá nhân.
- **Confirmed facts:** Commit thêm `SkillsConfig.max_context_tokens`, schema yêu cầu minimum 1, config được capped ở 10.000; tests cover parsing, override, cap và rendering dưới configured budget.
- **Analysis:** Đây là evidence rõ rằng “context engineering” không chỉ là viết prompt ngắn hơn; cần **budget từng context surface** như skills catalog, repository context, memory, tool schemas và evidence.
- **Recommendation:** Thiết kế `ContextBudget` riêng cho `System/Policy`, `Skill Catalog`, `Repository Context`, `Task Evidence`, `Conversation`, `Tool Results`; log actual token use per surface.
- **Uncertainty:** Đây là commit trên `main`; stable Codex `0.147.0` chưa được xác nhận có option này.

### 2. Skill catalog nên được đánh giá như một **retrieval system**, không phải danh sách càng dài càng tốt

- **One-sentence summary:** Việc Codex đặt default skill-catalog budget bằng tỷ lệ context window và thêm configurable cap cho thấy skill discovery phải hoạt động dưới bounded context thay vì inject toàn bộ catalog vô hạn. [Codex #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Affected skill area:** Skill selection, context engineering, evaluation.
- **Why it matters:** Nếu catalog quá nhỏ, agent có thể không thấy skill phù hợp; quá lớn thì metadata cạnh tranh token với requirements, code và evidence.
- **Practical implication:** Cần đo `skill discovery recall@k`, false-selection rate, tokens consumed và task success thay vì chỉ đo số skills đã cài.
- **Priority:** **High**.
- **Confirmed facts:** Commit có shared catalog budget và tests rằng catalog rendering phải nằm trong configured token budget.
- **Analysis:** Skill systems nên dùng progressive disclosure: metadata ngắn để discovery → load full skill only khi selected.
- **Recommendation:** Với Cursor/Codex/Claude reusable skills, giữ discovery metadata cực ngắn: `name + trigger + outcome + exclusions`; procedural details để trong skill body.
- **Uncertainty:** Chưa có public benchmark từ commit này về budget tối ưu cho từng số lượng skills hoặc task domain.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Treat **Skill Catalog** như một context surface có ngân sách riêng

- **Problem:** Khi số skills tăng, metadata discovery có thể ăn context trước khi task, code, evidence được đưa vào model.
- **Proposed improvement:** Đặt budget cố định hoặc adaptive cho skill catalog và đo actual usage. Ví dụ conceptual config:

```toml
[skills]
max_context_tokens = 1200
```

- **Why it may work:** Codex commit mới implement chính pattern này và tests ensure rendered catalog nằm trong budget. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Codex skills, Cursor skill libraries, Claude reusable agent instructions, internal agent marketplace.
- **Limitations:** Budget quá thấp có thể làm skill description bị rút gọn hoặc giảm discoverability.
- **Risks:** Teams có thể chọn budget theo cảm tính mà không eval recall.
- **Recommendation:** Benchmark 300/600/1200/2400 token catalog budgets trên cùng 30–50 representative tasks; đo `correct skill selected`, `no skill selected`, `wrong skill selected`, input tokens, latency và task success.
- **Uncertainty:** Không có universal optimal budget.

### B. Tối ưu skill metadata cho **discovery**, không biến metadata thành full procedure

- **Problem:** Description dài giúp giải thích skill nhưng làm catalog phình nhanh.
- **Proposed improvement:** Metadata chỉ chứa:
  - `name`
  - `trigger / when to use`
  - `expected outcome`
  - `important exclusions`

Full workflow, commands, examples và validation rules chỉ load sau khi skill được chọn.
- **Why it may work:** Progressive disclosure giữ discovery cheap nhưng vẫn preserve procedural depth.
- **Suitable use cases:** QA agent skills, research skills, code-review skills, architecture skills, deployment skills.
- **Limitations:** Description quá ngắn/ambiguous sẽ giảm retrieval quality.
- **Risks:** Hai skills có trigger gần nhau có thể collision.
- **Recommendation:** Tạo evaluation set cho skill routing và bắt mỗi skill phải có ít nhất 3 positive + 3 negative trigger examples.

### C. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Giant rules file trộn security, coding convention, domain knowledge và task instruction.
- **Proposed improvement:**
  - `policy/`: hard boundaries
  - `skills/`: reusable procedure
  - `context/`: facts / architecture
  - `task/`: objective / acceptance criteria / evidence
- **Why it may work:** Codex restrictive environment policy cho thấy scoped policy nên được compose rõ và lower layer chỉ tighten authority. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor Rules, Claude Code, Codex skills, .NET architecture/review agents.
- **Limitations:** Cần precedence và loading rules deterministic.
- **Risks:** Duplicate instructions.
- **Recommendation:** Contract: `Policy > Environment Restriction > Task > Procedure Default`; context không grant permission.

### D. Context Budget Ledger

- **Problem:** Teams thường chỉ biết tổng context window, không biết phần nào tiêu token.
- **Proposed improvement:** Mỗi run record:

```text
Policy/System        1,100
Skill Catalog          850
Repo Context          4,600
Task/Evidence         3,200
Tool Schemas          2,000
Conversation          5,300
--------------------------
Total                17,050
```

- **Why it may work:** Cho phép tìm context waste và compare across model/tool versions.
- **Suitable use cases:** long-running research, multi-agent orchestration, architecture reviews, QA agents.
- **Limitations:** Token accounting khác tokenizer/provider.
- **Risks:** Tối ưu token quá mức có thể làm mất evidence quan trọng.
- **Recommendation:** Optimize based on success/cost curve, không chỉ minimize token count.

## 4. Agent, Workflow, and Loop Engineering

### A. Add **Context Budget Checkpoint** trước Execute

- **Problem:** Agent thường execute khi context đã đầy metadata/memory/tool outputs không cần thiết.
- **Technique:**

```text
Plan
→ Select skills
→ Allocate context budgets
→ Load minimal evidence
→ Execute
→ Verify
→ Persist only durable state
```

- **Expected benefit:** Ít context dilution, dễ detect vì sao task degradation khi skill library lớn lên.
- **Failure risks:** Budgeting layer có thể drop critical detail.
- **Suitable use cases:** repo-wide coding agents, architecture analysis, research agents.
- **Recommendation:** Nếu budget overflow, prune theo priority `stale conversation → low-confidence retrieved context → verbose skill descriptions`; không prune acceptance criteria hoặc security policy.

### B. Skill-routing regression loop

- **Problem:** Thêm skill mới có thể làm skill cũ ít được chọn hoặc gây ambiguity.
- **Technique:** Giữ dataset task→expected skill(s); chạy lại sau mỗi thay đổi catalog/description/budget.
- **Expected benefit:** Detect routing regression deterministic hơn cảm nhận thủ công.
- **Failure risks:** Dataset không đại diện real tasks.
- **Suitable use cases:** Cursor/Codex skills, QA automation skill sets, internal multi-role agent kits.
- **Metrics:** `precision`, `recall`, `wrong-skill rate`, `no-skill rate`, input tokens, latency.

### C. Permission loop: `Plan → Policy Check → Approval → Execute → Verify`

- **Problem:** Approval có thể được cache trong khi environment policy thay đổi.
- **Technique:** Bind approval to action + policy revision/fingerprint; policy change invalidates approval.
- **Expected benefit:** Giảm stale approval reuse.
- **Failure risks:** Quá nhiều prompts nếu policy revision thay đổi liên tục.
- **Suitable use cases:** deployment agents, DB migrations, scripts, Git write actions.
- **Evidence:** Codex source áp dụng policy fingerprint vào cached approval key. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### D. Low-value loop detector

- **Problem:** Research/repair agent lặp cùng search hoặc cùng fix khi evidence không thay đổi.
- **Technique:** Tạo signature `action + target + evidence hash + failure class`; nếu lặp 2 lần mà không có new evidence, trigger `REPLAN` hoặc `STOP`.
- **Expected benefit:** Giảm wasted tokens/time và tránh retry storms.
- **Failure risks:** Stop quá sớm với transient failures.
- **Suitable use cases:** Selenium/Playwright repair agents, CI fix agents, research agents.

## 7. Opportunities and Trends to Watch

### 1. **Context budgets become first-class runtime configuration** — **Status: Growing**
- **What is changing:** Context window không còn được coi là một bucket duy nhất; subsystems như skill catalog bắt đầu có explicit budgets.
- **Why it matters:** Agent quality phụ thuộc allocation, không chỉ total context size.
- **Opportunity:** Xây provider/tool-neutral `Context Budget Manager` cho .NET agent frameworks.
- **Risk:** Premature optimization hoặc fixed budgets không adapt theo task.

### 2. **Skill libraries move toward retrieval + progressive disclosure** — **Status: Growing**
- **What is changing:** Large skill catalogs cần metadata routing và selective loading.
- **Why it matters:** “Cài càng nhiều skills càng tốt” có thể làm context/routing tệ hơn.
- **Opportunity:** Skill-router evaluator, skill-lint tool, catalog optimizer.
- **Risk:** Over-engineering với bộ skill nhỏ.

### 3. **Runtime policy composition over prompt-only safety** — **Status: Growing**
- **What is changing:** Permissions được enforce theo environment/action layers và approval state.
- **Why it matters:** Model instruction không phải security boundary.
- **Opportunity:** Reusable policy engine cho AI-assisted .NET automation.
- **Risk:** Complex policies gây friction hoặc hidden denial behavior.

### 4. **Version-aware agent evaluation** — **Status: Established → Growing**
- **What is changing:** Behavior phụ thuộc model + harness + provider route + auth mode + tool version + config.
- **Why it matters:** Benchmark không record runtime metadata rất khó reproduce.
- **Opportunity:** Standard `AgentRunManifest` + regression dashboard.
- **Risk:** Metadata collection phức tạp nếu không chuẩn hóa sớm.

### 5. **Project-scoped durable state thay chat-scoped memory** — **Status: Early signal / Growing**
- **What is changing:** Agent platforms đang tách persistent project/workspace state khỏi thread/run.
- **Why it matters:** Long-running agents cần resume/fork/audit.
