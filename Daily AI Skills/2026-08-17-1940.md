## 1. Executive Summary

### 1. Codex đang gom quyền quyết định apps/plugins về **một effective runtime feature configuration**
- **One-sentence summary:** Codex `main` ngừng fetch ChatGPT workspace setting `enable_plugins`; app/plugin APIs, plugin-provided skills, hooks và experimental feature reporting giờ được gate bởi effective Codex feature configuration. [Codex #38994, 17/08/2026](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)
- **Affected skill area:** Plugin architecture, hooks, skills, config layering, permission boundaries.
- **Why it matters:** Hai control planes cùng gate một capability dễ tạo hidden state: runtime config nói “enabled” nhưng workspace gate nói “disabled”, khiến debug rất khó.
- **Practical implication:** Feature availability nên resolve về một effective config duy nhất; **authorization** và **human approval** vẫn phải là lớp riêng.
- **Priority:** **Critical** cho agent platform có plugins/hooks.
- **Confirmed facts:** Commit loại `workspace_settings::WorkspaceSettingsCache`, bỏ checks `workspace_codex_plugins_enabled`, và để `Feature::Apps` / `Feature::Plugins` cùng effective Codex config quyết định app list/read, plugin operations, plugin-provided skills/hooks và feature reporting. [Source](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)
- **Analysis:** Đây là control-plane simplification, nhưng không nên hiểu là “plugin enabled = plugin được phép làm mọi thứ”. Enablement, policy, credentials, approval và environment support phải là các dimensions khác nhau.
- **Recommendation:** Chuẩn hóa runtime decision thành `FeatureEnabled && PolicyAllowed && CredentialAvailable && UserApproved && EnvironmentSupported`.
- **Uncertainty:** Chưa có public evidence về cách các hosted ChatGPT workspace policies ngoài source path này tương tác với Codex sau thay đổi.

### 2. Skill routing đang đi từ prompt matching sang **hybrid retrieval + recent-use memory**
- **One-sentence summary:** Codex thêm shadow selectors dùng Reciprocal Rank Fusion để kết hợp recently invoked skills với character routing-card matches, và một biến thể thêm weighted lexical matching. [Codex #38993, 17/08/2026](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Skill routing, context engineering, short-term agent memory, multi-turn workflows, evals.
- **Why it matters:** Turn tiếp theo thường ngắn như “continue”, “run again”, “fix that”; current-turn text không đủ nhưng history của skill vừa dùng là signal mạnh.
- **Practical implication:** Router nên fuse ít nhất `query relevance`, `recent skill history`, `structured routing metadata`, và lexical/semantic signals.
- **Priority:** **Critical** cho systems có catalog skills lớn.
- **Confirmed facts:** Hai selector mới `lru_plus_character_routing_v1` và `lru_plus_lexical_character_routing_v1` dùng RRF với `RRF_K = 10`, cap 50 candidates, deduplicate, propagate truncation metadata; tests cover cold start, duplicate removal, exact matches, deterministic ranking và recover skill từ turn trước. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Đây là procedural short-term memory với chi phí nhỏ hơn inject full transcript.
- **Recommendation:** Đánh giá router bằng `top-1 accuracy`, `top-k recall`, `wrong-skill rate`, `task success`, latency và input tokens.
- **Uncertainty:** Đây vẫn là shadow experiment; chưa có evidence selector mới đã thành default.

### 3. **Shadow evaluation** nên là mặc định trước khi đổi decision layer

- **Affected skill area:** Agent evals, safe rollout, model/tool/skill routing, planning.
- **Why it matters:** Routing/planning changes có blast radius lớn và dễ tạo silent regression.
- **Practical implication:** Candidate selector có thể chạy song song, ghi telemetry nhưng không điều khiển execution.
- **Priority:** **High**.
- **Confirmed facts:** Commit thêm nhiều selector variants vào shadow experiment, với deterministic ranking và bounded result size. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Pattern này áp dụng trực tiếp cho model routing, planner variants, verifier thresholds, retry policies và code-review heuristics.
- **Recommendation:** Mỗi decision ghi `active_choice`, `shadow_choices[]`, `evidence`, `latency`, `outcome` và `decision_version`.
- **Uncertainty:** Public source không công bố threshold promote selector.

### 5. Browser/QA verifiers cần **visual evidence symmetry**
- **One-sentence summary:** Guardian v2 có opt-in image transcript từ user/assistant/tool outputs, bounded 4 ảnh gần nhất và 8 MiB tổng. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Browser agents, QA agents, multimodal verification, evidence engineering.
- **Why it matters:** Executor nhìn screenshot nhưng verifier chỉ nhìn text là asymmetric evidence.
- **Practical implication:** Screenshot phải là first-class evidence với provenance, redaction, retention budget và selection policy.
- **Priority:** **Critical** cho browser/UI automation.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **feature enablement** khỏi **authorization**
- **Problem:** Một boolean “plugin enabled” thường bị dùng đồng thời cho visibility, loading, permissions và execution.
- **Proposed improvement:** Resolve riêng `FeatureEnabled`, `PolicyAllowed`, `CredentialsReady`, `HumanApproved`, `EnvironmentSupported`.
- **Why it may work:** Codex #38994 đang đơn giản hóa feature gating, còn #38942 cho thấy permission policy là một subsystem riêng. [#38994](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005) · [#38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** MCP tools, Teams/Slack integrations, database tools, GitHub write tools, deployment agents.
- **Limitations:** Nhiều dimensions hơn làm config model phức tạp hơn.
- **Risks:** Nếu UI chỉ hiển thị một “enabled” trạng thái sẽ che mất lý do execution bị deny.

### B. Skill descriptions nên là **routing metadata**, không phải full procedure
- **Problem:** Catalog descriptions dài làm chiếm context và làm lexical signals noisy.
- **Proposed improvement:** Initial catalog chỉ chứa `name`, `short intent`, `dependencies`, `trigger examples`, `exclusions`; load full skill khi selected.
- **Why it may work:** Codex đang có explicit catalog budget và routing-card/lexical selectors. [#38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor skills, Claude Code skills/commands, Codex skills, QA/research/interview agent catalogs.
- **Limitations:** Metadata quá ngắn có thể làm giảm recall.
- **Risks:** Skill names/descriptions giống nhau gây ambiguity; cần negative examples hoặc exclusions.

### C. Thêm **recent-skill memory** nhưng có decay và scope
- **Problem:** Giữ mọi skill từng dùng sẽ tạo recency bias lâu dài.
- **Proposed improvement:** Lưu last-N skill invocations với `timestamp`, `run/thread`, `success`, `scope`; decay score theo turn/time và reset theo project/domain boundary.
- **Why it may work:** Codex đang thử LRU-style recent skills như routing signal. [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Multi-step QA, research, code review, migrations, interview workflows.
- **Limitations:** History có thể bias sai nếu user đổi topic.
- **Risks:** Wrong-skill loops nếu recent skill luôn được ưu tiên quá mạnh.

### D. Config cần **explainability**
- **Problem:** Global defaults, model defaults, repo rules, environment restrictions và local overrides tạo “config archaeology”.
- **Proposed improvement:** Mỗi effective field lưu `value`, `source`, `sourceVersion`, `overriddenBy`; cung cấp debug output kiểu `config explain`.
- **Why it may work:** Guardian model defaults hiện có explicit local precedence. [#38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Suitable use cases:** Agent platforms, CI runners, enterprise policy, model routing.
- **Limitations:** Cần schema/versioning tốt.
- **Risks:** Debug output có thể leak sensitive config nếu không redact.

## 4. Agent, Workflow, and Loop Engineering

### A. `Observe → Compare → Promote` cho mọi decision layer
- **Problem:** Thay router/planner trực tiếp khiến regression khó phát hiện.
- **Technique:** Shadow-run candidate decision logic; active path vẫn giữ nguyên. Sau execution, gắn outcome vào cả active và shadow decisions.
- **Expected benefit:** So sánh quality mà không ảnh hưởng user-visible behavior.
- **Failure risks:** Shadow logic có thể tăng latency/cost; telemetry thiếu ground truth thì ranking comparison không đủ ý nghĩa.
- **Suitable use cases:** Skill routing, model routing, code-review prioritization, retry policies, planner variants.

### B. Detect **low-value loops** bằng signature, không chỉ retry count
- **Problem:** Agent có thể retry 5 lần nhưng mỗi lần lỗi khác nhau; hoặc chỉ 2 lần nhưng cùng lỗi y hệt.
- **Technique:** Tạo `failure_signature = normalized_error + failing_step + evidence_hash + environment_hash`; nếu cùng signature lặp 2 lần thì stop/re-plan/root-cause.
- **Expected benefit:** Giảm test-fix-retest vô ích.
- **Failure risks:** Signature quá coarse sẽ stop sớm; quá fine sẽ không nhận ra loop.
- **Suitable use cases:** CI fixes, Playwright/Selenium QA, migrations, deployment automation.

### C. `Project → Run → Step → Evidence` thay transcript-centric state
- **Problem:** Transcript không phải durable operational state.
- **Technique:** Project giữ roots/rules; Run giữ objective/config/version; Step giữ tool call; Evidence/Artifact tách riêng; Checkpoint ghi progress + unresolved gaps.
- **Expected benefit:** Resume, fork, audit, retry và handoff rõ hơn.
- **Failure risks:** Over-modeling cho task nhỏ.
- **Suitable use cases:** QA agents, research agents, interview pipelines, long-running architecture reviews.

### D. Verifier phải có **evidence parity** với executor
- **Problem:** Reviewer đánh giá trên evidence nghèo hơn executor.
- **Technique:** Build bounded evidence packet gồm latest screenshot, failure screenshot, relevant DOM/tool output, action intent và provenance.
- **Expected benefit:** Giảm false verdict trong browser/UI workflows.
- **Failure risks:** Screenshot chứa PII/secrets; payload lớn.
- **Suitable use cases:** Browser agents, visual regression, incident triage, UI QA.

- **Change/test:** Merge env → remove denylisted secrets case-insensitively → optional allowlist → spawn; unit test secret absence.
- **Expected benefit:** Giảm credential leakage qua scripts/hooks/build tools.
- **Confirmed fact:** Codex scrub auth token sau environment policy overrides và trước shell/hooks. [#38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Recommendation:** Không log secret values; chỉ log variable names bị scrub.
- **Uncertainty:** Cần inventory secret classes của từng project.

### 5. Chuẩn hóa **QA EvidenceEnvelope** — **Half a day**
- **Relevance:** Trực tiếp cho browser/Playwright/Selenium QA agent.
- **Improve:** Evidence hiện thường rời rạc: screenshot, DOM, logs, video.
- **Change/test:** `type`, `source`, `capturedAt`, `hash`, `redacted`, `artifactRef`, `runId`, `stepId`; verifier nhận bounded evidence packet.
- **Expected benefit:** Better auditability, deduplication, verifier symmetry, giảm screenshot spam.
- **Confirmed fact:** Guardian v2 image transcript dùng bounded image evidence. [#38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Recommendation:** Benchmark `latest-only` vs `latest+failure` vs `pre-action+failure+latest`.
- **Uncertainty:** Optimal evidence retention phụ thuộc task và model.

## 7. Opportunities and Trends to Watch

### 1. **Agent control plane consolidation** — **Growing**
- **What is changing:** Feature availability đang được resolve gần agent runtime thay vì dựa vào nhiều remote/product gates.
- **Why it matters:** Fewer hidden dependencies, easier reproducibility.
- **Opportunity:** Xây reusable config resolver/explainability layer cho internal agent frameworks.
- **Risk:** Central config trở thành single point of misconfiguration; enablement có thể bị nhầm với authorization.
- **Evidence:** Codex #38994. [Source](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)

### 2. **Skill systems trở thành retrieval systems** — **Growing**
- **What is changing:** Explicit token budgets, structured routing metadata, recency signals, lexical matching và rank fusion.
- **Why it matters:** “Dump all skill descriptions into prompt” không scale.
- **Opportunity:** Skill router/eval toolkit cho Cursor/Claude/Codex-style agents.
- **Risk:** Router complexity có thể vượt benefit nếu catalog nhỏ.
- **Evidence:** Codex #38978 + #38993. [#38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)

### 3. **Shadow evaluation for agent decisions** — **Growing**
- **What is changing:** Candidate routing logic được quan sát song song trước khi promote.
- **Why it matters:** Agent systems cần rollout discipline giống search/ranking systems.
- **Opportunity:** Generic shadow-decision framework cho router/planner/verifier/model selection.
- **Risk:** Telemetry cost và false confidence nếu downstream outcome metric kém.
- **Evidence:** Codex #38993. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)

### 4. **Model identity → capability profile** — **Early signal**
- **What is changing:** Model catalog bắt đầu mang review/safety defaults và runtime-relevant metadata.
- **Why it matters:** Agent behavior có thể thay đổi theo model family ngoài prompt.
- **Opportunity:** Provider-neutral capability registry với probes + versioned metadata.
- **Risk:** Stale metadata, provider drift, hidden remote changes.
- **Evidence:** Codex #38990. [Source](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)

### 5. **Multimodal verification** — **Early signal**
- **What is changing:** Visual evidence bắt đầu đi vào review/safety transcript.
- **Why it matters:** Browser agents cần verifier thấy cùng UI evidence.
- **Opportunity:** Evidence budget, redaction, screenshot provenance, multimodal eval harness.
- **Risk:** Privacy leakage, increased latency/cost, visual prompt injection.
- **Evidence:** Codex #38987. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
