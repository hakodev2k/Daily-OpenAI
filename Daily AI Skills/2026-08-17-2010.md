## 1. Executive Summary

### 1. Asynchronous verifier phải có **freshness bound**, không chỉ confidence threshold
- **One-sentence summary:** Guardian v2 giờ bỏ qua approval review nếu risk score hiện tại chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async review agents, approval systems, concurrency, long-running agents, state synchronization.
- **Why it matters:** Một risk score có thể chính xác tại thời điểm được tạo nhưng vẫn không còn phù hợp nếu agent đã thực hiện thêm nhiều tool calls. `confidence` không giải quyết được `staleness`.
- **Practical implication:** Mọi asynchronous reviewer nên gắn verdict với `subject version/index`, và consumer phải kiểm tra freshness trước khi dùng verdict cho approval hoặc execution.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call` per thread; tính lag bằng chênh lệch index; nếu `tool_call_lag > max_tool_call_lag` thì approval review trả `None`; config mặc định `3`, có thể override; tests cover đúng giới hạn, vượt giới hạn và recovery khi scorer bắt kịp. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** Đây là một dạng **temporal consistency contract** giữa executor và verifier. Verdict cần vừa đúng về nội dung vừa đủ mới về thời gian/state version.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, createdAt, score, decision, evidenceHash, reviewerVersion }` và enforce `currentVersion - subjectVersion <= allowedLag` trước khi áp dụng.
- **Uncertainty:** Default `3` chỉ là lựa chọn của Guardian; không có evidence rằng phù hợp cho mọi tốc độ tool execution hay domain risk.

### 2. Bounded retry nên áp dụng cho **logical operation**, không phải từng request riêng lẻ
- **One-sentence summary:** Guardian sampler dùng `MAX_SAMPLING_RETRIES = 2` cho toàn flow: connection lease, request start và response stream. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, retry engineering, verifier reliability, long-running agents.
- **Why it matters:** Nếu mỗi phase có retry độc lập, total attempt count có thể phình ra và khó quan sát; nếu chỉ retry một phase, failure ở phase khác bị bỏ sót.
- **Practical implication:** Một logical step nên có shared retry budget, error classification và stop condition rõ ràng.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex retry connection timeout, stream/retryable errors, overload, transport timeout/connection/network, HTTP 5xx và `429`, tối đa hai retry; tests cover recovery sau prewarm failure, `503` và stop khi budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Khi kết hợp với #39001, reliability của verifier cần hai dimension: **retry boundedness** và **result freshness**.
- **Recommendation:** Thiết kế `RetryBudget` theo operation ID và log `attempt`, `errorCategory`, `idempotency`, `resetTransport`, `outcome`.
- **Uncertainty:** `2` retries chưa được chứng minh optimal cho workload khác.

### 3. Auth recovery cần refresh credential **và** invalidate stale transport state
- **One-sentence summary:** Guardian sampling recover `401` qua auth manager rồi clear idle pooled WebSocket connections trước khi retry. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Authentication, persistent transports, MCP/API clients, long-running agents.
- **Why it matters:** Refresh token nhưng tiếp tục reuse connection cũ có thể giữ stale auth/session state và tạo loop lỗi.
- **Practical implication:** Credential lifecycle và connection/session lifecycle nên được model cùng nhau.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex uses `UnauthorizedRecovery`, advances recovery on `401`, clears idle connections và retries nếu recovery còn khả dụng. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Đây là bài học trực tiếp cho .NET `HttpClient`, WebSocket, Microsoft Graph token refresh và MCP persistent sessions.
- **Recommendation:** Add regression test `401 -> refresh -> stale connection invalidated -> next request succeeds` cho long-lived clients.
- **Uncertainty:** Có cần recreate toàn transport hay chỉ update request headers tùy protocol/auth binding.

- **Why it matters:** Turn như “continue”, “retry”, “fix that” có ít lexical signal nhưng recent skill history là strong prior.
- **Practical implication:** Skill router nên fuse `current-query relevance`, `recent-use history`, `routing metadata/dependencies` và lexical/semantic signals.
- **Priority:** **High**.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Thêm **freshness metadata** vào mọi reusable context artifact
- **Problem:** Facts, assumptions, plans, risk scores, retrieved docs và tool results có thể đúng khi tạo nhưng nhanh chóng stale trong long-running agent.
- **Proposed improvement:** Mỗi artifact nên có `version/index`, `capturedAt`, `source`, `scope`, `evidenceHash`, optional `expiresAfter` hoặc `maxLag`.
- **Why it may work:** Consumer có thể kiểm tra tính mới deterministic thay vì tin vào prompt như “hãy dùng thông tin mới nhất”.
- **Suitable use cases:** QA state, browser DOM/screenshot, research findings, code review diff, incident status, approval verdicts, architecture assumptions.
- **Limitations:** Freshness threshold phụ thuộc domain; version count không phản ánh mức độ semantic change.
- **Risks:** Threshold quá chặt gây recomputation dư thừa; quá rộng khiến stale state vẫn lọt qua.
- **Confirmed facts:** Codex #39001 dùng tool-call lag làm freshness boundary cho Guardian approval review.
- **Recommendation:** Với agent framework riêng, tách `validity` thành `content confidence` và `freshness` thay vì một confidence score duy nhất.

### B. Skill catalog nên có **two-stage context loading**
- **Problem:** Inject full skill definitions làm context phình to và giảm attention cho requirement/code/evidence.
- **Proposed improvement:** Stage 1 chỉ load compact routing metadata; stage 2 load full skill procedure khi selected.
- **Why it may work:** #38978 xác nhận skill catalog có explicit budget; #38993 cho thấy skill retrieval có thể dựa trên recent-use + routing metadata + lexical signal.
- **Suitable use cases:** Cursor skills, Claude Code subagent/command libraries, Codex skills, QA/research/interview agent catalogs.
- **Limitations:** Router miss ở stage 1 sẽ không load đúng skill ở stage 2.
- **Risks:** Routing metadata quá sơ sài làm recall giảm; metadata quá dài lại quay về context bloat.
- **Recommendation:** Đo `top-k skill recall per 1k catalog tokens` và downstream task success.

### C. Tách **policy**, **procedure**, **capability metadata** và **task context**
- **Problem:** Một file rules lớn thường trộn security policy, coding convention, workflow steps, model quirks và task facts.
- **Proposed improvement:** Dùng bốn layer rõ: `Policy`, `Skill/Procedure`, `CapabilityProfile`, `TaskContext`.
- **Why it may work:** Hôm nay Codex cho thấy cả runtime permissions, model-owned Guardian defaults, skill catalog budget và effective feature config đều đang tách thành structured layers.
- **Suitable use cases:** `.cursor/rules`, `CLAUDE.md`, `AGENTS.md`, custom .NET agent frameworks, team knowledge systems.
- **Limitations:** Nhiều layer làm configuration graph phức tạp hơn.
- **Risks:** Không có deterministic precedence sẽ tạo hidden overrides.
- **Recommendation:** Mỗi run log `resolvedConfigHash`, `policyHash`, `capabilityProfileVersion`.

## 4. Agent, Workflow, and Loop Engineering

### A. **Freshness-gated approval loop**
- **Problem:** Reviewer chạy async và verdict về chậm hơn executor state.
- **Technique:** Gắn mỗi review request với `subjectVersion`; trước khi apply decision, compare với current state; nếu lag vượt threshold thì discard/re-review.
- **Expected benefit:** Giảm sai approval do stale risk analysis, stale test evidence hoặc stale diff.
- **Failure risks:** Quá nhiều invalidation có thể tạo starvation nếu executor chạy nhanh hơn reviewer.
- **Suitable use cases:** Browser agents, deployment approvals, code-review agents, destructive tool calls, security reviewers.
- **Concrete test:** Simulate tool calls 1..N, intentionally delay reviewer, measure stale-verdict application rate trước/sau freshness guard.

### B. **Retry-budget + freshness-budget** như hai stop conditions độc lập
- **Problem:** Agent có thể vừa retry quá nhiều vừa dùng result đã stale khi cuối cùng request thành công.
- **Technique:** Một logical step có `retryBudget`; result sau khi nhận phải qua `freshnessCheck` trước khi apply.
- **Expected benefit:** Tránh hai failure mode khác nhau: infinite retry và late-but-obsolete result.
- **Failure risks:** Hệ thống quá conservative làm tăng abort/replan rate.
- **Suitable use cases:** Remote test runners, MCP, research fetchers, background reviewers, external APIs.
- **Recommendation:** Sau `maxRetries` hoặc stale result, chuyển state sang `REPLAN_REQUIRED`, không tự động tiếp tục loop cũ.

### C. **Shadow decisioning** trước khi đổi router/planner
- **Problem:** Routing/planning change có thể tạo silent regression.
- **Technique:** Chạy candidate selector song song nhưng không cho nó điều khiển execution; lưu active vs shadow choice và eventual outcome.
- **Expected benefit:** Có evidence trước rollout.
- **Failure risks:** Telemetry cost và challenge trong việc xác định “ground truth” cho decision quality.
- **Suitable use cases:** Skill routing, model routing, reviewer thresholds, retry classifier, planner strategies.
- **Confirmed facts:** Codex #38993 đưa new skill selectors vào existing shadow-selection experiment.

### D. **Required / Degradable / Deferred startup dependencies**
- **Problem:** Optimization failure làm cả agent service fail startup.
- **Technique:** Phân loại init dependency; prewarm/cache/index prefetch là degradable/deferred nếu correctness không phụ thuộc.
- **Expected benefit:** Higher availability.
- **Failure risks:** Latency spike ở first-use.
- **Suitable use cases:** Browser pool prelaunch, vector index warmup, MCP preconnect, model metadata cache.
- **Confirmed facts:** Guardian sampler now survives failed initial WebSocket prewarm.

## 5. Hooks and Integrations

### 1. .NET `HttpClient` / WebSocket auth recovery — **Moderate**
- **Can integrate:** Token provider + transport lifecycle manager.
- **Workflow benefit:** Khi refresh credential, invalidate sessions/connections có khả năng stale thay vì chỉ đổi token object.
- **Security concerns:** Không log token; invalidate đúng scope để tránh disruption không cần thiết.
- **Recommendation:** Thêm integration test cho `401 -> refresh -> recreated transport -> success`.

### 2. QA/browser evidence pipeline — **Moderate**
- **Can integrate:** Screenshot, DOM snapshot, action intent, console/network logs vào `EvidenceEnvelope`.
- **Workflow benefit:** Executor và verifier nhìn cùng evidence classes; freshness/version giúp tránh review screenshot cũ.
- **Security concerns:** Screenshot có thể chứa PII, cookies, secrets; cần redaction trước forwarding.
- **Recommendation:** Chỉ giữ bounded recent evidence, kèm hash/timestamp/action ID.

### 3. GitHub Actions / Azure DevOps review hooks — **Advanced**
- **Can integrate:** Async AI reviewer chạy song song CI, verdict gắn commit SHA/diff hash.
- **Workflow benefit:** Reviewer result chỉ áp dụng nếu HEAD SHA vẫn đúng; nếu branch đổi thì discard/re-run.
- **Security concerns:** Token scope, fork PR secrets, command execution permissions.
- **Recommendation:** Treat commit SHA như `subjectVersion`; tuyệt đối không approve merge dựa trên verdict của SHA cũ.

### 4. MCP long-lived sessions — **Advanced**
- **Can integrate:** Session state, auth refresh, retry budget, stale result detection.
- **Workflow benefit:** Reliable tool calls qua persistent connection.
- **Security concerns:** Session authority và credentials có thể stale sau policy/account changes.
- **Recommendation:** Khi auth/policy fingerprint đổi, invalidate/re-negotiate session.

### 5. Teams/Slack knowledge-transfer agent — **Moderate**
- **Can integrate:** Skill routing dùng recent-use history cho follow-up commands ngắn như “continue”, “post that”, “summarize again”.
- **Workflow benefit:** Giảm phải inject full transcript chỉ để giữ procedural continuity.
- **Security concerns:** Cross-channel context bleed; cần scope recent-skill memory theo conversation/project.
- **Recommendation:** TTL procedural memory và explicit project/thread key.

## 7. Opportunities and Trends to Watch

### 1. **Verdict freshness** trở thành first-class reliability primitive
- **What is changing:** Async reviewer result không còn được coi là timeless; Codex bắt đầu track lag giữa scored action và current action.
- **Why it matters:** Agent systems ngày càng concurrent và long-running.
- **Opportunity:** Xây generic `VersionedVerdict` / `FreshnessGuard` middleware dùng chung cho QA, code review, approvals, research validation.
- **Risk:** Threshold tuning kém có thể gây excessive recomputation.
- **Status:** **Early signal**.

### 2. Agent reliability đang chuyển từ “retry nhiều hơn” sang **classified, bounded, state-aware recovery**
- **What is changing:** Retry classifier, fixed budget, auth-aware transport reset và stale-result guard xuất hiện cùng một ngày trong Guardian path.
- **Why it matters:** Production agents cần predictable recovery semantics.
- **Opportunity:** Reusable reliability layer cho MCP/API/browser/model calls.
- **Risk:** Retry abstraction quá generic có thể bỏ qua idempotency/domain semantics.
- **Status:** **Growing**.

### 3. Skill systems đang trở thành **retrieval systems**
- **What is changing:** Explicit catalog token budget, hybrid routing, recent-use memory, shadow evaluation.
- **Why it matters:** Khi số skills tăng, prompt-only selection không scale.
- **Opportunity:** Skill router benchmark harness và skill-catalog optimizer.
- **Risk:** Over-engineering cho catalog nhỏ.
- **Status:** **Growing**.

### 4. Review agents tiến tới **model-aware, multimodal, versioned evidence pipelines**
- **What is changing:** Model catalog defaults + image evidence + freshness checks.
- **Why it matters:** Browser/UI/QA tasks phụ thuộc evidence ngoài text và thay đổi nhanh theo state.
- **Opportunity:** Evidence store + verifier framework có provenance, redaction, freshness, bounded context.
- **Risk:** Privacy, storage cost, multimodal latency.
- **Status:** **Growing**.

### 5. Feature enablement và authorization tiếp tục tách rời
- **What is changing:** Effective Codex feature config quyết định apps/plugins, trong khi command execution có separate restrictive policies và approvals.
- **Why it matters:** Một boolean “enabled” không đủ đại diện authority.
- **Opportunity:** Capability matrix rõ ràng cho custom agent platforms.
- **Risk:** Configuration complexity nếu precedence không deterministic.
- **Status:** **Established direction**.
