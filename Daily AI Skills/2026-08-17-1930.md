## 1. Executive Summary

### 1. Codex bỏ workspace-level plugin gate và chuyển sang **runtime-effective feature configuration**

- **One-sentence summary:** Codex `main` ngừng fetch ChatGPT workspace setting `enable_plugins`; app/plugin APIs, plugin-provided skills, hooks và experimental feature reporting giờ dựa vào effective Codex feature configuration. [Codex #38994, 17/08/2026](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)
- **Affected skill area:** Plugin architecture, hooks, skill loading, configuration layering, permission boundaries.
- **Why it matters:** Một agent runtime có thể gặp config từ nhiều domain: product workspace, local user config, repo config, enterprise policy và runtime feature flags. Khi hai control planes cùng gate cùng capability, behavior dễ khó đoán và khó debug.
- **Practical implication:** Nên có **một effective runtime configuration** làm nguồn sự thật cuối cùng cho việc feature/plugin có được load hay không, đồng thời vẫn tách policy/permission enforcement khỏi feature enablement.
- **Priority:** **Critical** cho agent platforms có plugins/hooks; **High** cho personal multi-tool agents.
- **Confirmed facts:** Commit loại `workspace_settings::WorkspaceSettingsCache`, bỏ các checks `workspace_codex_plugins_enabled`, để `Feature::Apps`/`Feature::Plugins` và effective config quyết định app list/read, plugin list/read/install/configure, plugin-provided skills/hooks và feature reporting. [Source](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)
- **Analysis:** Đây là dấu hiệu quan trọng về **control-plane simplification**: feature availability nên được resolve một lần từ effective runtime config thay vì phụ thuộc nhiều remote gates rải rác. Tuy vậy, feature enablement không nên đồng nghĩa với authorization.
- **Recommendation:** Trong framework riêng, tách rõ `FeatureEnabled`, `PolicyAllowed`, `CredentialAvailable`, `UserApproved`, `EnvironmentSupported`. Một tool chỉ chạy khi tất cả điều kiện cần đều true.

### 2. Skill routing đang tiến từ keyword matching sang **hybrid retrieval + recent-use memory**

- **One-sentence summary:** Codex `main` thêm shadow selectors dùng Reciprocal Rank Fusion để kết hợp recently invoked skills với character routing-card matches, và một biến thể thêm weighted lexical matches. [Codex #38993, 17/08/2026](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Skill routing, context engineering, agent memory, multi-turn workflows, evaluation.
- **Why it matters:** Multi-turn tasks thường có những turn ngắn như “tiếp tục”, “fix cái này”, “re-run”, khiến current-turn text không đủ để router chọn đúng skill.
- **Practical implication:** Skill selection nên xem `current query`, `recent skill history`, `structured dependencies/routing metadata` và lexical/semantic relevance là các signals độc lập có thể fuse.
- **Priority:** **Critical** cho systems có nhiều reusable skills; **High** cho personal agent stacks.
- **Confirmed facts:** Hai selector mới `lru_plus_character_routing_v1` và `lru_plus_lexical_character_routing_v1` dùng RRF với `RRF_K = 10`, cap 50 candidates; tests cover cold start, duplicates, exact matches, deterministic ranking, truncation và recover skill từ turn trước. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Đây là một form **procedural short-term memory** hiệu quả hơn việc inject full transcript chỉ để nhớ “skill nào vừa dùng”.
- **Recommendation:** Benchmark router theo `top-1 skill accuracy`, `top-k recall`, `task success`, latency, tokens và wrong-skill rate; chạy shadow trước khi thay production path.
- **Uncertainty:** Commit vẫn là shadow experiment, chưa có evidence selector mới đã được promote thành default.

### 3. **Shadow evaluation** nên trở thành mặc định khi thay routing/planning logic

- **One-sentence summary:** Codex đưa các skill selectors mới vào existing shadow-selection experiment thay vì đổi execution behavior ngay. [Codex #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Agent evals, safe rollout, model/tool/skill routing, regression testing.
- **Why it matters:** Agent routing là decision layer có blast radius lớn; một improvement ở nhóm task A có thể gây silent regression ở nhóm B.
- **Practical implication:** Candidate router/plan selector có thể chạy song song, ghi telemetry nhưng không điều khiển execution cho đến khi metrics đủ tốt.
- **Priority:** **High**.
- **Confirmed facts:** Commit record nhiều selector variants trong shadow experiment và giữ selection deterministic/capped.
- **Analysis:** Pattern `observe → compare → promote` phù hợp không chỉ skill routing mà cả model routing, verifier thresholds, planner variants và retry policies.
- **Recommendation:** Mỗi agent decision quan trọng nên có `decision_id`, `active_choice`, `shadow_choices[]`, `evidence`, `latency`, `outcome`.
- **Uncertainty:** Public source không nêu acceptance threshold để promote selector.

### 5. Guardian v2 bắt đầu nhận **visual evidence** từ transcript và tool outputs

- **Affected skill area:** Browser agents, multimodal QA, verifier pipelines, evidence handling.
- **Why it matters:** Nếu executor thấy screenshot nhưng verifier chỉ thấy text, verifier có asymmetric context.
- **Practical implication:** Screenshot nên là first-class evidence với provenance, redaction và bounded retention.
- **Priority:** **Critical** cho browser/UI agents.

- **Recommendation:** Dùng `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }`.
- **Uncertainty:** Không có benchmark public chứng minh 4 ảnh/8 MiB là optimal cho mọi use case.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **feature enablement** khỏi **authorization**

- **Problem:** Một config `enabled=true` dễ bị hiểu nhầm là “agent được phép dùng”.
- **Proposed improvement:** Resolve 5 dimensions riêng: `featureEnabled`, `policyAllowed`, `credentialAvailable`, `environmentSupported`, `humanApproved`.
- **Why it may work:** Codex #38994 chuyển plugin availability sang effective feature config, trong khi #38942 cho thấy permission vẫn là một lớp riêng. [#38994](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005) · [#38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** MCP tools, GitHub/Slack/Teams plugins, deployment agents, DB agents, browser agents.
- **Limitations:** Nhiều layers làm debug khó nếu không có explainability.
- **Risks:** Nếu merge config bằng OR thay vì intersection ở permission layer, lower-level config có thể vô tình mở quyền.

### B. Skill descriptions nên phục vụ **routing**, full procedure chỉ load sau selection

- **Problem:** Full skill procedure trong catalog làm token cost tăng nhanh.
- **Proposed improvement:** Catalog chỉ chứa `name`, `shortDescription`, `dependencies`, `routingHints`, `examples`; full instructions load khi skill được chọn.
- **Why it may work:** Codex đang vừa giới hạn catalog token budget vừa nâng chất lượng selector. [#38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor skills, Claude skills, Codex skills, role-based agent packs.
- **Limitations:** Routing metadata quá ngắn có thể giảm recall.
- **Risks:** Metadata drift so với actual skill behavior.

### C. Mỗi effective config nên có **provenance**

- **Problem:** Khi model defaults, repo rules, user config, environment restrictions và runtime flags cùng tồn tại, rất khó biết value cuối đến từ đâu.
- **Proposed improvement:** Lưu `{ value, source, sourceVersion, resolvedAt, overriddenBy }` cho từng setting quan trọng.
- **Why it may work:** Guardian v2 model defaults + local overrides và plugin feature config đều đang dựa vào explicit resolution order.
- **Suitable use cases:** Review thresholds, model routing, tool permissions, skill budgets, retry/stop conditions.
- **Limitations:** Telemetry volume tăng.
- **Risks:** Nếu log values nhạy cảm, provenance telemetry có thể leak secrets; log metadata, không log secret values.

### D. Context budget nên chia theo **surface**

- **Problem:** “Model có 400k context” không nói lên skill catalog, tool evidence hay screenshots nên chiếm bao nhiêu.
- **Proposed improvement:** Budget riêng cho `system/policy`, `skill catalog`, `repo guidance`, `tool results`, `conversation`, `visual evidence`, `verifier evidence`.
- **Why it may work:** Codex đang explicit hóa cả skill-token budget và image count/bytes.
- **Suitable use cases:** Long-running coding agents, QA/browser agents, research agents.
- **Limitations:** Budget tuning cần benchmarks thực tế.
- **Risks:** Over-compression có thể loại evidence quan trọng.

## 4. Agent, Workflow, and Loop Engineering

### A. **Shadow decision loop** trước khi đổi production router

- **Problem:** Routing/planning changes dễ regression không nhìn thấy.
- **Technique:** Chạy `active decision` và `shadow decisions` song song; chỉ active path được execute, shadow paths chỉ log candidate/rank/latency.
- **Expected benefit:** Có thể compare candidate algorithms mà không tăng blast radius.
- **Failure risks:** Shadow result không hoàn toàn phản ánh production nếu downstream feedback không được map lại.
- **Suitable use cases:** Skill selection, model routing, tool selection, planner variants, verifier threshold variants.

### B. **Recent procedural memory** thay vì transcript replay

- **Problem:** Agent cần nhớ skill/tool vừa dùng nhưng full transcript quá đắt.
- **Technique:** Duy trì compact state như `recentSkillIds`, `recentToolIds`, `lastSuccessfulPlanType`, decay theo recency.
- **Expected benefit:** Better continuity cho follow-up turns, ít token hơn transcript replay.
- **Failure risks:** Recency bias kéo agent vào skill cũ dù task đã đổi.
- **Suitable use cases:** QA test-fix-retest, code review follow-ups, research deep-dives, interview coaching.

### C. **Config explainability** như một debugging primitive

- **Problem:** Agent có thể “không thấy plugin” hoặc “không được phép chạy command” nhưng lý do nằm trong layer khác.
- **Technique:** Tạo debug output `effective feature`, `policy decision`, `credential state`, `approval state`, `source config`.
- **Expected benefit:** Giảm thời gian debug false-negative capability issues.
- **Failure risks:** Debug output có thể lộ sensitive metadata nếu không redacted.
- **Suitable use cases:** MCP/plugins, GitHub Actions agents, Azure DevOps agents, local CLI agents.

### D. **Verifier symmetry** cho multimodal workflows

- **Problem:** Executor thấy screenshot/DOM nhưng verifier chỉ thấy text summary.
- **Technique:** Xây bounded evidence packet dùng chung giữa executor và verifier.
- **Expected benefit:** Giảm verdict sai do context asymmetry.
- **Failure risks:** Screenshot có PII/secrets; visual evidence tăng latency.
- **Suitable use cases:** Selenium/Playwright QA, browser automation, UI incident diagnosis.

### E. Stop condition cho **low-value research loops**

- **Problem:** Monitoring agent có thể re-query cùng nguồn liên tục khi không có material delta.
- **Technique:** `NO_MATERIAL_DELTA` là valid outcome; chỉ deep-dive khi source hash/release/commit/advisory thay đổi.
- **Expected benefit:** Giảm duplicate output, cost và false novelty.
- **Failure risks:** Hosted/private rollouts có thể không xuất hiện trên public repos.
- **Suitable use cases:** AI news agents, release monitors, dependency/update monitors.

## 7. Opportunities and Trends to Watch

### Trend 1 — Agent platforms đang hội tụ về **single effective runtime config**

- **What is changing:** Codex #38994 loại một remote workspace gate và dựa vào effective feature config; Guardian v2 cũng có explicit default/override resolution.
- **Why it matters:** Nhiều control planes làm agent behavior khó dự đoán.
- **Opportunity:** Xây config resolver có provenance/explainability dùng chung cho tools, models, skills, permissions.
- **Risk:** Oversimplification có thể bỏ qua enterprise governance nếu feature config và policy không tách riêng.
- **Status:** **Growing**.

### Trend 2 — Skill selection trở thành **retrieval/ranking engineering**

- **What is changing:** Token budget, routing cards, lexical matching, recent-use memory và RRF đang xuất hiện trong cùng skill-selection surface.
- **Why it matters:** Số skills tăng khiến static prompt routing không scale.
- **Opportunity:** Skill-router benchmark suites, skill metadata linters, shadow-routing telemetry.
- **Risk:** Router phức tạp hơn nhưng không tăng task success nếu skill definitions chất lượng thấp.
- **Status:** **Growing**.

### Trend 3 — **Short-term procedural memory** tách khỏi conversation memory

- **What is changing:** Recently invoked skills được dùng như signal riêng, không cần replay full transcript.
- **Why it matters:** Memory nên lưu những state có utility cho next decision, không phải mọi token quá khứ.
- **Opportunity:** Compact memory stores cho `recent skills/tools/plans/failures`.
- **Risk:** Recency bias và stale workflow state.
- **Status:** **Early signal**.

### Trend 4 — Safety/review behavior ngày càng **model-aware và evidence-aware**

- **What is changing:** Guardian v2 lấy defaults từ model catalog và bắt đầu nhận image evidence.
- **Why it matters:** Review reliability phụ thuộc cả model capability lẫn evidence available.
- **Opportunity:** Capability profiles + multimodal verifier benchmarks.
- **Risk:** Dynamic model metadata gây reproducibility drift nếu không version/persist resolved config.
- **Status:** **Growing**.

### Trend 5 — Runtime security đang rời khỏi prompt layer

- **What is changing:** Command restrictions, approval fingerprints, secret scrubbing và hook isolation được enforce trong code/runtime.
- **Why it matters:** Prompt-based “đừng làm X” không phải security boundary.
- **Opportunity:** Agent runtime libraries cho permissions, sanitized subprocesses, approval state machines.
- **Risk:** False sense of security nếu chỉ cover một số tool paths.
- **Status:** **Established** về nguyên tắc, **Growing** về agent-specific implementation.
