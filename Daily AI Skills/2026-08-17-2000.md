## 1. Executive Summary

### 1. Bounded retry nên áp dụng cho **logical operation**, không chỉ từng HTTP/WebSocket call
- **One-sentence summary:** Guardian sampler trên Codex `main` dùng `MAX_SAMPLING_RETRIES = 2` cho toàn bộ sampling flow: lease connection, start request và consume stream. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, retry engineering, long-running agents, verifier reliability.
- **Why it matters:** Agent loops thường gọi nhiều transport phases trong một logical step; retry từng phase riêng có thể khiến tổng số lần thử không kiểm soát hoặc bỏ sót failure ở phase khác.
- **Practical implication:** Một step nên có shared `RetryBudget`, error classification và stop condition rõ ràng.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex retry transient connection timeout, retryable/stream failures, overload, transport timeout/connection/network, HTTP `5xx` và `429`, tối đa hai retry. Tests cover recovery sau prewarm failure, `503`, và dừng khi retry budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Đây là pattern phù hợp cho QA agents, research agents, code-review agents, CI/CD agents và MCP clients: retry phải bounded, category-aware và observable.
- **Recommendation:** Chuẩn hóa `RetryDecision { retryable, category, attempt, maxAttempts, backoff, idempotencySafe, resetTransport }` và lưu telemetry cho từng attempt.
- **Uncertainty:** `2` retries là implementation choice của Guardian, chưa có evidence rằng là budget tối ưu cho workload khác.

### 2. Auth recovery không chỉ là refresh token: phải xử lý **stale transport state**
- **One-sentence summary:** Khi sampling gặp `401`, Codex dùng `UnauthorizedRecovery` từ auth manager và clear idle pooled WebSocket connections trước khi retry. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Authentication, persistent connections, MCP/API clients, long-running agents.
- **Why it matters:** Token đã refresh nhưng pooled connection còn gắn auth state cũ có thể tạo loop `401 → refresh → reuse stale transport → 401`.
- **Practical implication:** Credential lifecycle và connection/session lifecycle phải được model cùng nhau.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex advances unauthorized recovery strategy khi có `401`, clear idle connections và retry khi recovery còn khả dụng. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Với HTTP/2, WebSocket, MCP sessions và long-lived browser/controller channels, invalidating stale resources sau credential change là reliability requirement.
- **Recommendation:** Trong .NET, kiểm tra `HttpClient`, WebSocket và MCP connection nào phải recreate khi token/account/tenant context đổi; thêm regression test cho stale-auth connection reuse.
- **Uncertainty:** Có cần rebuild transport hay chỉ rebuild request headers phụ thuộc protocol và auth binding cụ thể.

### 3. Prewarm nên là **optimization**, không phải hard dependency
- **One-sentence summary:** Guardian sampler giờ vẫn khởi tạo khi initial WebSocket prewarm thất bại; first real sample có thể tạo fresh connection. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Startup resilience, cache/warm-pool design, service initialization.
- **Why it matters:** Cache warmup, browser prelaunch, MCP preconnect hay repo pre-index nếu fail không nên mặc định biến thành total service outage.
- **Practical implication:** Init dependencies cần được phân loại `Required`, `Degradable`, `Deferred`.
- **Priority:** **High**.
- **Confirmed facts:** Codex no longer fails sampler init on initial prewarm connection failure; test xác minh first sample vẫn recover thành công. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Đây là pattern rất phù hợp với browser automation pools và agent services: fail-open về availability, nhưng vẫn log degraded-startup signal.
- **Recommendation:** Chỉ fail startup với dependency thật sự bắt buộc; best-effort optimization nên degrade latency, không degrade correctness.
- **Uncertainty:** Với hệ thống có latency SLO rất chặt, failed prewarm vẫn có thể là operational incident dù service còn available.

### 4. Skill routing đang trở thành **hybrid retrieval + recent-use procedural memory**
- **One-sentence summary:** Codex thêm shadow selectors fuse recently invoked skills với character routing-card matches bằng Reciprocal Rank Fusion, và một variant thêm weighted lexical matches. [Codex #38993, 17/08/2026](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Skills, context engineering, multi-turn memory, routing evaluation.
- **Why it matters:** Turn như “continue”, “retry”, “fix that” chứa ít lexical signal nhưng recent skill history thường là strong prior.
- **Practical implication:** Skill router nên fuse `current-query relevance`, `recent-use history`, `structured dependencies/routing metadata` và lexical/semantic signals.
- **Priority:** **High**.
- **Confirmed facts:** Selectors `lru_plus_character_routing_v1` và `lru_plus_lexical_character_routing_v1` dùng RRF với `K=10`, cap 50 candidates; tests cover cold start, duplicate removal, exact matches, deterministic ranking, truncation metadata và recover skill từ earlier turn. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Đây là short-term procedural memory nhẹ hơn việc inject full transcript chỉ để giữ workflow continuity.
- **Recommendation:** Chạy router candidates ở shadow mode và đo `top-1 accuracy`, `top-k recall`, wrong-skill rate, downstream task success, latency và tokens.
- **Uncertainty:** Hai selectors vẫn ở shadow experiment; chưa có evidence chúng đã trở thành production default.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Quản lý **context như budget allocation**, không phải một prompt dài
- **Problem:** Rules, skills catalog, repository context, conversation history, tool outputs và screenshots đều cạnh tranh cùng model context.
- **Proposed improvement:** Tách context thành các buckets có budget: `policy`, `skill discovery`, `repo context`, `task evidence`, `conversation`, `tool outputs`, `visual evidence`.
- **Why it may work:** Codex hiện đã explicit hóa budget cho skill catalog, trong khi Guardian giới hạn image count/bytes. Hai thay đổi độc lập cùng chỉ ra rằng bounded context surfaces dễ predict và test hơn. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Image bounds](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** Cursor/Claude/Codex reusable skills, large monorepos, QA agents, interview agents, research agents.
- **Limitations:** Budget quá nhỏ làm giảm recall; budget quá lớn có thể tăng latency/cost và irrelevant context.
- **Risks:** Chỉ optimize token count nhưng không đo task success sẽ dẫn đến false efficiency.
- **Recommendation:** Mỗi budget experiment phải đo `task success`, `correct skill/tool selection`, `input tokens`, `latency`, `cost`, `failure reason`.

### B. Dùng **routing metadata nhỏ + lazy-load full skill**
- **Problem:** Inject full content của hàng chục/hàng trăm skills làm context phình lớn.
- **Proposed improvement:** Phase 1 chỉ expose routing card: name, purpose, dependencies, trigger hints, capabilities; Phase 2 load full procedure khi skill được chọn.
- **Why it may work:** Codex skill routing experiments dùng character routing-card metadata và recent-use history để rank candidates thay vì cần toàn bộ skill text. [Codex #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Skill catalog lớn, multi-role agent packs, reusable rules/skills across repositories.
- **Limitations:** Metadata kém chất lượng vẫn làm router miss skill đúng.
- **Risks:** Overfitting routing card cho benchmark thay vì real task distribution.
- **Recommendation:** Maintain eval set có short query, ambiguous query, multi-turn continuation, tool dependency, wrong-skill distractors.

### C. Tách **facts / assumptions / inferences / recommendations** thành artifact có schema
- **Problem:** Long-running research/architecture agents dễ trộn factual evidence với suy luận và recommendation.
- **Proposed improvement:** Dùng structured decision artifact: `Facts`, `Evidence`, `Assumptions`, `Inferences`, `Unknowns`, `Risks`, `Decision`, `Verification`.
- **Why it may work:** Config provenance, capability profiles và evidence manifests đang trở thành first-class runtime concepts trong các Codex changes hôm nay; reasoning artifacts nên có provenance tương tự.
- **Suitable use cases:** Architecture planning, root-cause analysis, interview story verification, technical research, code review.
- **Limitations:** Tăng overhead cho task nhỏ.
- **Risks:** Agent có thể điền schema cho đủ nhưng evidence yếu.
- **Recommendation:** Require citation/evidence pointer cho every fact và explicit confidence cho inference.

### D. Config resolution phải có **explainability**
- **Problem:** Global defaults, model defaults, admin requirements, repo rules, user overrides, environment restrictions và per-run values dễ tạo hidden precedence bugs.
- **Proposed improvement:** Mỗi resolved value lưu `value`, `source`, `sourceVersion`, `resolvedAt`, `overriddenBy`.

## 4. Agent, Workflow, and Loop Engineering

### A. Retry loop nên là **classify → retry/recover → verify → stop**
- **Problem:** Generic retry mọi lỗi gây loop vô ích và có thể lặp side effect.
- **Technique:** `classify(error)` → check idempotency → choose recovery action → consume retry budget → retry → verify success → stop when budget exhausted.
- **Expected benefit:** Ít infinite loop hơn, failure diagnostics tốt hơn, predictable latency/cost.
- **Failure risks:** Sai classification có thể retry non-retryable errors hoặc fail quá sớm.
- **Suitable use cases:** API/MCP calls, browser navigation, CI jobs, long-running verifiers.
- **Concrete rule:** Retry only when `retryable && idempotencySafe && attempts < budget`; auth failures có separate recovery path; quota/context/invalid-request errors phải fail/replan, không retry mù. Codex #38997 explicitly không retry context-window exceeded, quota, invalid request và một số policy failures. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)

### B. Sau 2 lỗi cùng signature, chuyển từ **retry** sang **re-plan/root-cause**
- **Problem:** Agent dễ mắc low-value loop khi cùng một failure lặp lại.
- **Technique:** Hash normalized failure signature (`category + operation + key error markers`). Nếu signature lặp >=2 lần, stop retry path và chạy root-cause/re-plan step.
- **Expected benefit:** Giảm token/time burn và tăng khả năng đổi strategy.
- **Failure risks:** Signature quá coarse có thể group lỗi khác nhau.
- **Suitable use cases:** QA automation, code-fix-test loops, CI/CD debugging, web automation.
- **Recommendation:** Persist `attempt`, `failureSignature`, `recoveryTried`, `nextDecision`, `evidence`.

### C. Shadow evaluation cho **routing/planning/verifier thresholds**
- **Problem:** Đổi decision layer trực tiếp có blast radius lớn.
- **Technique:** Chạy candidate decision logic song song nhưng không điều khiển execution; ghi active vs shadow decisions và downstream outcome.
- **Expected benefit:** Có evidence trước khi rollout.
- **Failure risks:** Shadow result không hoàn toàn phản ánh counterfactual execution path.
- **Suitable use cases:** Skill routing, model routing, planner variants, code-review heuristics, retry policy changes.
- **Confirmed basis:** Codex #38993 đưa new skill selectors vào existing shadow-selection experiment thay vì promote ngay. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)

### D. `Project → Thread/Run → Step → Evidence/Artifact` thay cho transcript-only state
- **Problem:** Dùng conversation transcript làm durable state gây khó resume, fork, retry, audit và compare runs.
- **Technique:** Tách project/workspace identity, run/thread execution, step/tool calls và evidence/artifacts.
- **Expected benefit:** Resume/fork rõ ràng, context handoff gọn, regression dễ hơn.
- **Failure risks:** State model phức tạp hơn và cần migration/versioning.
- **Suitable use cases:** QA agent suites, research agents, interview engines, code-review systems, knowledge-transfer workflows.
- **Confirmed basis:** Experimental Codex app-server Project APIs thêm project lifecycle, thread assignment, fork inheritance và change notifications. [Codex #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

[OpenCode #42634, 17/08/2026](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)

**Analysis:** Multi-provider abstraction nên normalize orchestration interface nhưng không flatten protocol semantics. Tool calls, reasoning controls, output token parameters và auth behavior có thể khác giữa native provider APIs.

**Recommendation:** Nếu xây provider layer riêng, dùng `IModelProvider`/normalized domain model ở bên trong nhưng giữ provider-native adapter ở transport boundary; regression-test reasoning/tool payloads theo từng route.

**Uncertainty:** OpenCode change trên `main` chưa đồng nghĩa stable `v1.18.18` đã chứa behavior này.

## 7. Opportunities and Trends to Watch

### 1. **Agent reliability đang chuyển từ prompt engineering sang runtime engineering**
- **What is changing:** Retry budgets, auth recovery, transport reset, permission overlays, secret scrubbing, evidence bounds đều xuất hiện ở runtime layer.
- **Why it matters:** Prompt hay không thể sửa network failure, stale credentials, leaked env vars hay stale approvals.
- **Opportunity:** Xây reusable `.NET Agent Runtime` library cho retries, checkpoints, permissions, telemetry, evidence và process isolation.
- **Risk:** Over-engineering cho workflow nhỏ.
- **Status:** **Growing**.

### 2. **Skill systems đang hội tụ về retrieval architecture**
- **What is changing:** Explicit catalog token budgets + hybrid routing + shadow selectors.
- **Why it matters:** Khi skills tăng, “list all skills in prompt” không scale.
- **Opportunity:** Skill-router benchmark harness hoặc vendor-neutral skill registry cho Cursor/Claude/Codex/OpenCode.
- **Risk:** Benchmark không phản ánh real task distribution.
- **Status:** **Growing**.

### 3. **Verifier agents đang cần evidence parity với executor**
- **What is changing:** Multimodal transcript evidence và model-aware reviewer settings.
- **Why it matters:** Independent verifier chỉ có giá trị nếu context không bị thiếu material evidence.
- **Opportunity:** Evidence store + verifier SDK cho browser QA, code review, incident response.
- **Risk:** Screenshots/logs có thể chứa credentials/PII.
- **Status:** **Early signal**.

### 4. **Feature enablement và authorization đang được tách thành nhiều dimensions**
- **What is changing:** Codex effective feature config đơn giản hóa app/plugin gating, trong khi command policies và approvals vẫn là separate enforcement layers.
- **Why it matters:** `enabled=true` không đủ để kết luận tool được phép chạy.
- **Opportunity:** Capability resolver với explainable decision: feature, policy, credential, approval, environment.
- **Risk:** Nếu UI/telemetry không explain final decision, user vẫn thấy behavior khó hiểu.
- **Status:** **Growing**.

### 5. **Provider abstraction nhưng giữ native protocol semantics**
- **What is changing:** OpenCode Cloudflare Gateway dùng native OpenAI/Anthropic passthrough thay vì flatten mọi provider qua compatible API.
- **Why it matters:** Reasoning/tool-call semantics có thể mất hoặc sai khi abstraction quá mạnh.
- **Opportunity:** Multi-provider .NET gateway với normalized orchestration + native transport adapters.
- **Risk:** Maintenance complexity và provider-specific regression matrix tăng.
- **Status:** **Established direction, implementation still evolving**.
