## 1. Executive Summary

### 1. Guardian sampling chuyển từ “retry cục bộ” sang **bounded retry across the full sampling flow**
- **One-sentence summary:** Codex `main` thêm `MAX_SAMPLING_RETRIES = 2` và một retry classifier chung cho lỗi transient khi lease connection, start request và consume response stream. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, retry strategy, verifier reliability, long-running agents.
- **Why it matters:** Retry chỉ ở một điểm dễ bỏ sót failure xảy ra ở phase khác của cùng logical operation. Với agent loops, retry policy phải nhìn **toàn bộ operation boundary**, không chỉ một API call.
- **Practical implication:** Các QA/research/review agents nên có một `RetryBudget` cho một logical step, shared giữa connect/start/stream phases, và stop rõ ràng khi budget hết.
- **Priority:** **Critical**.
- **Confirmed facts:** Commit retry tối đa hai lần cho connection timeout, retryable/stream errors, server overload, transport timeout/connection/network, HTTP 5xx và `429`; tests cover recovery sau prewarm failure, recovery sau `503`, và dừng sau khi retry budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Đây là pattern tốt hơn `while(true) retry`: bounded, error-class-aware, testable và có stop condition.
- **Recommendation:** Chuẩn hóa `RetryDecision { retryable, category, attempt, maxAttempts, backoff, idempotencySafe, resetConnection }` và log ở từng attempt.
- **Uncertainty:** Commit không chứng minh `2` retries là tối ưu cho mọi workload; nên benchmark theo failure distribution thực tế.

### 2. `401` recovery cần **credential refresh + connection-pool invalidation**
- **One-sentence summary:** Khi Guardian sampling gặp Unauthorized, Codex dùng configured auth manager để recover credential và clear idle pooled WebSocket connections trước khi retry. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Authentication recovery, connection pools, MCP/API clients, long-running agents.
- **Why it matters:** Refresh token mà vẫn reuse connection chứa stale auth state có thể tạo loop `401 → refresh → 401` khó debug.
- **Practical implication:** Auth recovery phải invalidate những transport resources có thể mang credential cũ, không chỉ update token object.
- **Priority:** **Critical** cho long-lived connections.
- **Confirmed facts:** Codex obtains `UnauthorizedRecovery`, advances recovery strategy on `401`, clears idle connections, rồi retry nếu recovery còn khả dụng. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Credential lifecycle và connection lifecycle là coupled state; hệ thống agent dùng WebSocket/HTTP2/MCP persistent transport cần model chúng cùng nhau.
- **Recommendation:** Với .NET, khi credential refresh xảy ra, đánh giá `HttpClient`/WebSocket/MCP session nào phải recreate; thêm regression test cho stale-auth connection reuse.
- **Uncertainty:** Mức độ cần rebuild transport phụ thuộc auth/header binding và protocol implementation cụ thể.

### 3. Prewarm nên là **optimization, không phải availability dependency**
- **One-sentence summary:** Guardian sampler giờ vẫn khởi tạo nếu initial WebSocket prewarm thất bại; first real sample có thể mở fresh connection sau đó. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Startup resilience, warm pools, agent service initialization.
- **Why it matters:** Optimization như prewarm/cache/warm connection không nên biến một recoverable startup hiccup thành service outage.
- **Practical implication:** Phân loại startup dependencies thành `required` vs `best-effort`; prewarm failure nên degrade latency chứ không nhất thiết fail process.
- **Priority:** **High**.
- **Confirmed facts:** Loop prewarm không còn fail sampler khi connection đầu tiên lỗi; test `sampler_recovers_after_initial_prewarm_failures` xác minh sample đầu tiên có thể recover. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Pattern này áp dụng trực tiếp cho vector-cache warmup, browser pool warmup, MCP preconnect và repository index prefetch.
- **Recommendation:** Đánh dấu mọi init step bằng `Required`, `Degradable`, hoặc `Deferred`; service chỉ fail startup với `Required` dependencies.
- **Uncertainty:** Nếu latency SLO cực chặt, prewarm failure vẫn có thể ảnh hưởng production dù availability còn giữ được.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Đưa retry policy ra khỏi prompt thành **runtime policy object**
- **Problem:** Prompt kiểu “nếu lỗi thì retry tối đa 2 lần” không bảo đảm mọi code path đều tuân thủ và dễ bị mất sau context compaction.
- **Proposed improvement:** Tạo structured runtime object, ví dụ:

```text
RetryPolicy
- maxAttempts
- retryableCategories
- nonRetryableCategories
- backoffStrategy
- idempotencyRequirement
- resetTransportOn
- refreshAuthOn
- deadline
```

- **Why it may work:** Codex #38997 gom classification + retry budget vào sampler runtime thay vì phân tán ở stream branch riêng lẻ. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Suitable use cases:** Browser QA agents, research agents gọi web/API, CI agents, MCP clients, code-review agents gọi external tools.
- **Limitations:** Retry không chữa được invalid request, quota exhausted, context overflow, deterministic code bug hoặc policy rejection.
- **Risks:** Retry non-idempotent operation có thể tạo duplicate side effects; mọi retry policy phải biết operation có safe-to-repeat hay không.
- **Confirmed facts:** Codex explicitly marks several categories non-retryable như invalid request, quota exceeded, context-window exceeded và policy violations.
- **Analysis:** “Retry everything” là anti-pattern; error taxonomy phải là input của control flow.
- **Recommendation:** Mỗi agent tool trả structured `FailureCategory` thay vì chỉ exception string.
- **Uncertainty:** Backoff behavior chi tiết của commit này không chứng minh một strategy duy nhất phù hợp mọi integration.

### B. Skill routing: **metadata nhỏ trước, procedure lớn sau**
- **Problem:** Catalog skills lớn làm token budget tăng nhưng vẫn có thể route sai.
- **Proposed improvement:** Phase 1 inject compact routing metadata (`name`, short purpose, dependencies, trigger examples); phase 2 chỉ load full skill instructions sau selection.
- **Why it may work:** Codex hiện vừa thêm explicit catalog token budget (#38978) vừa thử hybrid skill routing (#38993). [Budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Routing](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor skills, Codex skills, Claude reusable workflows, QA/research/interview/code-review skill libraries.
- **Limitations:** Compact metadata quá ngắn có thể giảm recall; recent-use signal có thể bias agent vào skill cũ dù task đã chuyển domain.
- **Risks:** Sticky routing / confirmation bias.
- **Recommendation:** Track `why_selected` và expose top-N candidates để debug wrong-skill cases.

### C. Config phải có **provenance và precedence explainability**
- **Problem:** Khi model defaults, feature config, repo rules, environment policy và local overrides cùng tồn tại, bug dễ nằm ở resolution order.
- **Proposed improvement:** Mọi resolved field mang metadata `value`, `source`, `sourceVersion`, `overriddenBy`, `resolvedAt`.
- **Why it may work:** Guardian model-catalog defaults vẫn nhường precedence cho explicit local config; plugin gates cũng vừa được gom về effective feature config. [#38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7) · [#38994](https://github.com/openai/codex/commit/3666a46ea3265442c3e374f7c5f18df650b17005)
- **Suitable use cases:** Cursor rules, Codex config, enterprise agent platforms, .NET agent runners.
- **Limitations:** Tăng telemetry/storage.
- **Risks:** Nếu log raw secrets/config values, observability lại trở thành data leak.
- **Recommendation:** Có command kiểu `agent config explain`, nhưng redact sensitive values.

### D. Evidence context phải có **budget + provenance + redaction**
- **Problem:** Browser/QA agents tạo nhiều screenshots, DOM snapshots, logs và tool outputs.
- **Proposed improvement:** `EvidenceEnvelope` có `type`, `source`, `capturedAt`, `hash`, `redacted`, `size`, `artifactRef`, `relevance`, sau đó apply count/byte/token budget.

- **Limitations:** Recency-only selection có thể bỏ mất screenshot quan trọng cũ hơn.
- **Risks:** Screenshots có thể chứa PII, tokens, customer data.
- **Recommendation:** Dedupe bằng content hash; ưu tiên `latest + last-failure + pre-action`; redact trước forwarding.

## 4. Agent, Workflow, and Loop Engineering

### A. Retry budget nên thuộc **logical step**, không thuộc từng API layer
- **Problem:** Nếu HTTP client retry 2 lần, WebSocket layer retry 2 lần, agent loop lại retry 2 lần, tổng attempts có thể bùng nổ ngoài dự kiến.
- **Technique:** Một `StepRetryBudget` dùng chung cho các failure phase của cùng action; nested clients report failure category nhưng không tự loop vô hạn.
- **Expected benefit:** Predictable latency/cost; dễ xác định stop condition.
- **Failure risks:** Nếu quá ít attempts có thể fail sớm khi provider chập chờn; nếu quá nhiều có thể che outage thật.
- **Suitable use cases:** MCP call, browser action, external API, model verifier call.
- **Confirmed facts:** #38997 áp một budget chung qua connection lease, request start và response stream.
- **Analysis:** Đây là pattern nên đưa vào state machine của agent loop.
- **Recommendation:** Telemetry: `attempt`, `failure_category`, `elapsed`, `retry_decision`, `remaining_budget`.

### B. Recovery state machine nên tách **transient**, **auth**, **permanent**, **policy**
- **Problem:** Tất cả exceptions đi vào một retry handler làm hệ thống khó kiểm soát.
- **Technique:**
  1. `TransientTransport` → bounded retry
  2. `Unauthorized` → auth recovery + transport invalidation
  3. `PermanentInput` → fail fast
  4. `Policy/Safety` → stop/escalate
  5. `Quota` → stop hoặc route khác nếu policy cho phép
- **Expected benefit:** Ít useless loops, dễ RCA.
- **Failure risks:** Misclassification có thể biến permanent error thành retry storm.
- **Suitable use cases:** Research agents, CI agents, interview pipeline, code-review tools.
- **Recommendation:** Unit-test classifier bằng failure matrix, không chỉ happy-path integration tests.

### C. Prewarm/cache/indexing phải có **degradation semantics**
- **Problem:** Agent service fail startup vì một optimization không sẵn sàng.
- **Technique:** Mỗi dependency khai báo `Required | Degradable | Lazy`.
- **Expected benefit:** Tăng availability; giảm coupling startup.
- **Failure risks:** Degraded mode có thể tăng latency và dẫn tới cascading timeouts.
- **Suitable use cases:** Browser pools, repo indexes, embeddings cache, MCP connections, local tool servers.
- **Recommendation:** Khi degraded, emit explicit health status và điều chỉnh deadline của first task.

### D. Shadow decision path trước khi promote routing/planning
- **Problem:** Thay router/planner trực tiếp làm regression khó phát hiện.
- **Technique:** Active decision + shadow decisions chạy song song; only active drives execution.
- **Expected benefit:** Offline-like comparison trên traffic thật mà không đổi behavior.
- **Failure risks:** Tăng compute; shadow system có thể đọc sensitive context nếu permission không được kiểm soát.
- **Suitable use cases:** Skill routing, model routing, plan selection, verifier thresholds, retry policy variants.
- **Confirmed facts:** #38993 sử dụng existing shadow-selection experiment.
- **Recommendation:** Promote chỉ khi đủ samples và không regression ở safety/cost/latency slices.

### E. Long-running agent state nên tách **Project → Run/Thread → Step → Artifact/Evidence**
- **Problem:** Transcript là state store duy nhất làm retry/resume/fork khó.
- **Technique:** Durable project state riêng; execution attempts riêng; evidence/artifacts immutable hoặc versioned.
- **Expected benefit:** Resume, fork, audit, replay và regression dễ hơn.
- **Failure risks:** Schema complexity và migration cost.
- **Suitable use cases:** QA agent, research agent, interview intelligence, architecture planning.
- **Confirmed facts:** Codex experimental Project APIs có project lifecycle, thread association, fork inheritance và notifications. [#38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Recommendation:** Persist `Checkpoint` sau mỗi irreversible side effect hoặc major decision.

| **GitHub Actions / Azure DevOps agent steps** | Retry external verifier/API call without rerunning whole pipeline | Side-effect duplication; secret inheritance into scripts | **Moderate** | Retry read/verify steps; gate writes separately |
| **Teams/Slack agent actions** | Plugin skill routing dựa trên structured dependency metadata | Posting is side effect; require user/policy approval | **Moderate** | Separate read skill from send/post skill |
| **Plugin-provided hooks** | Reusable build/test/review automation | Hooks are untrusted subprocess boundary | **Advanced** | Feature enablement ≠ authorization; scrub env |
| **Local file / repo agents** | Cheap deterministic tools for evidence and verification | Path traversal / write scope | **Easy–Moderate** | Explicit read/write roots and audit logs |
| **Model/provider gateway** | Preserve provider-native tool/reasoning semantics | Auth routing and capability mismatches | **Advanced** | Prefer normalized interface + native adapters |

### Analysis
Integration reliability is increasingly determined by **transport state, auth state, permission state, feature state and retry state together**, not by tool-call prompt quality alone.

### Recommendation
Thiết kế connector/tool runtime như state machine có observable transitions thay vì helper method đơn lẻ.

### Uncertainty
Không phải mọi external platform hỗ trợ cùng recovery semantics; MCP, WebSocket, REST và browser sessions cần policies riêng.

## 7. Opportunities and Trends to Watch

### Trend 1. **Retry engineering trở thành một phần của agent reasoning runtime**
- **What is changing:** Retry được encode thành bounded, classified runtime behavior thay vì prompt instruction hoặc generic HTTP retry.
- **Why it matters:** Agent chains có nhiều failure surfaces và side effects.
- **Opportunity:** Xây reusable reliability layer cho .NET agents: failure taxonomy, retry budgets, idempotency, checkpoints, transport reset.
- **Risk:** Retry stack chồng nhau gây exponential attempts và cost.
- **Status:** **Growing**.
- **Evidence:** Codex #38997.

### Trend 2. **Skill systems đang hội tụ về retrieval architecture**
- **What is changing:** Catalog token budget + hybrid ranking + recent-use memory + shadow eval.
- **Why it matters:** Một kho skills lớn không thể được quản lý bằng “inject tất cả và để model tự chọn”.
- **Opportunity:** Vendor-neutral Skill Router SDK/eval harness cho Cursor/Claude/Codex-style skill catalogs.
- **Risk:** Over-engineering nếu catalog chỉ có vài skills.
- **Status:** **Growing**.
- **Evidence:** Codex #38978 + #38993.

### Trend 3. **Agent configuration đang trở thành capability/control plane**
- **What is changing:** Model-owned defaults, effective runtime feature config, environment restrictions và policy fingerprints.
- **Why it matters:** Behavior ngày càng phụ thuộc structured metadata/config version hơn prompt đơn thuần.
- **Opportunity:** Config explainability, provenance, policy diff, regression tools cho enterprise agents.
- **Risk:** Configuration sprawl nếu không có schema/precedence rõ.
- **Status:** **Growing**.
- **Evidence:** Codex #38990, #38994, #38942.

### Trend 4. **Verifier symmetry chuyển từ text-only sang multimodal evidence**
- **What is changing:** Review/safety path bắt đầu nhận image evidence từ transcript/tool outputs.
- **Why it matters:** Browser/UI agents nếu verifier không thấy visual state sẽ đánh giá thiếu context.
- **Opportunity:** Evidence SDK cho screenshot/DOM/log provenance + redaction + budget.
- **Risk:** Privacy leakage, payload growth, overreliance on screenshots.
- **Status:** **Early signal**.
- **Evidence:** Codex #38987.

### Trend 5. **Runtime security đang tách rõ enablement, authorization, approval và secret scope**
- **What is changing:** Feature gate simplification song song với restrictive environment policy và subprocess secret isolation.
- **Why it matters:** Agent càng nhiều plugins/hooks thì security càng không thể nằm trong prompt.
- **Opportunity:** Policy engine cho agent tools, MCP servers và CI/CD integrations.
- **Risk:** UX tệ nếu approval quá nhiều hoặc policy không explainable.
- **Status:** **Established direction, implementation still evolving**.
- **Evidence:** Codex #38994, #38942, #38941.
