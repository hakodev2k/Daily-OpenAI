- **Proposed improvement:** Trước task, inject compact manifest:
  - tool + version
  - release channel
  - supported hooks/features
  - permission mode
  - context/input limits
  - MCP capability set
- **Why it may work:** Agent quyết định dựa trên runtime facts thay vì docs chung.
- **Suitable use cases:** Codex/Claude/OpenCode interchangeable workflows, CI agents, managed workstations.
- **Limitations:** Capability probing cần maintenance.
- **Risks:** Manifest stale nếu cache quá lâu.
- **Recommendation:** Cache theo `tool binary hash/version + config hash`, không theo ngày.
- **Uncertainty:** Vendor có thể có server-side capabilities không probe được local.

### B. Phân tách `policy instructions` khỏi `policy enforcement`

- **Problem:** Rule kiểu “đừng deploy production” trong Markdown không phải security boundary.
- **Proposed improvement:**
  - Rule/Skill nói **khi nào** action hợp lệ.
  - Runtime policy nói **action nào thực sự được phép**.
  - Approval state lưu riêng.
- **Why it may work:** Codex environment policy hôm nay là evidence rõ cho deny-overrides runtime enforcement. [Commit](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** QA agent, deployment agent, DB migration agent, Microsoft Graph/Exchange automation.
- **Limitations:** Policy engine phức tạp hơn prompt-only system.
- **Risks:** Rule/runtime policy drift.
- **Recommendation:** Test policy bằng deterministic tests, không LLM-as-a-judge.

### C. Context limits phải là runtime metadata, không phải constant trong Skill

- **Problem:** OpenCode vừa phải sửa model-limit metadata để match Codex subscription path; limit có thể khác theo access surface.
- **Proposed improvement:** `ModelCapabilityRegistry` lấy limit từ runtime/provider config và versioned source.

- **Suitable use cases:** research agents, long code-review sessions, multi-repo architecture analysis.
- **Limitations:** Provider metadata có thể không hoàn hảo.
- **Risks:** Incorrect registry still produces wrong budgeting.
- **Recommendation:** Thêm headroom 10–20% và fail-safe compaction.

## 4. Agent, Workflow, and Loop Engineering

### A. Change-detection loop nên có stop condition

- **Problem:** Scheduler chạy gần nhau có thể tạo briefing giống nhau, tốn token/API/GitHub commits.
- **Technique:** `fetch latest state → compute fingerprints → if no material delta → generate delta-only report`.
- **Expected benefit:** Giảm repetition và tập trung vào actionable work.
- **Failure risks:** Fingerprint quá coarse bỏ sót small security fix.
- **Suitable use cases:** daily radars, release monitors, job scans, repository watchers.
- **Recommendation:** Classify changes theo `security > breaking > workflow > feature > cosmetic`; cosmetic-only có thể không trigger deep report.

### B. Capability gate trước execution

- **Problem:** Agent Skill gọi feature không tồn tại trên installed version.
- **Technique:** Step 0 chạy capability probe và reject/route fallback nếu thiếu.
- **Expected benefit:** Failure sớm, dễ hiểu hơn runtime mystery.
- **Failure risks:** Probe có thể khác behavior thực tế.
- **Suitable use cases:** Codex/Claude CLI, MCP clients, Playwright/browser toolchains.
- **Recommendation:** Capability gate phải có deterministic fallback.

### C. Approval cache phải phụ thuộc policy state

- **Problem:** User từng approve command nhưng environment policy sau đó thay đổi.
- **Technique:** Approval cache key = `action + target + policy fingerprint + environment identity`.
- **Expected benefit:** Không reuse consent trong context quyền khác.
- **Failure risks:** Quá nhiều re-approval nếu fingerprint thay đổi vì noise.
- **Suitable use cases:** shell commands, deployments, data writes, email send, GitHub writes.
- **Evidence:** Codex commit #38942 đưa policy fingerprint vào cached approvals. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### D. Secret scrub là post-merge transform

- **Problem:** Config override có thể reintroduce secret sau khi initial environment đã sanitized.
- **Technique:** Compose env → apply task overrides → **scrub secrets cuối cùng** → spawn process.
- **Expected benefit:** Giảm credential leakage qua build/test/hooks.
- **Failure risks:** Unknown secret names hoặc secret embedded trong value/path.
- **Suitable use cases:** .NET `Process`, Node child processes, GitHub Actions runners, local agent hooks.

- **Risk:** Telemetry có thể leak sensitive context nếu không redacted.

### Trend 5. Low-value monitoring loops cần được tự phát hiện

- **What is changing:** Tooling update feeds có thể được poll nhiều lần nhưng không đổi.
- **Why it matters:** Agent scheduler nên biết khi nào “nothing changed” và giảm work.
- **Opportunity:** Fingerprint-based delta reports, adaptive polling, event-triggered deep dive.
- **Risk:** Over-aggressive suppression bỏ sót subtle security signal.
- **Status:** **Early signal** cho personal agent engineering, **Established** trong traditional monitoring.
