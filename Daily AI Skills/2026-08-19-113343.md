## 3. Prompt, Skills, Rules, and Context Engineering

### A. Permission-aware skills: skill phải khai báo risk, không chỉ procedure

**Problem:** `SKILL.md`, Cursor rules hoặc custom instructions thường mô tả “làm gì” nhưng không mô tả “hành động nào cần approval”.

**Proposed improvement:** Mỗi reusable skill thêm metadata/convention:

```text
Risk class: READ_REMOTE
Writes: none
Secrets: none
Human approval: not required
External side effects: none
Stop conditions: 2 failed retries or missing evidence
```

Với skill ghi GitHub/DB:

```text
Risk class: WRITE_REMOTE_REVERSIBLE
Human approval: required before write
Required preview: target + diff + scope
Idempotency: required
```

**Why it may work:** Runtime permission layer và prompt instruction cùng dùng một vocabulary, giảm mismatch giữa agent intent và executor policy.

**Suitable use cases:** Codex skills, Claude skills/plugins, Cursor rules, code-review agents, QA agents, Teams approval workflows.

**Limitations:** Metadata chỉ hữu ích nếu host enforce; model đọc metadata không phải security boundary.

**Risks:** False sense of safety nếu chỉ viết “approval required” nhưng tool vẫn có unrestricted token.

**Recommendation:** Permission metadata phải được map sang policy engine/tool scopes, không chỉ prompt text.

**Uncertainty:** Không có cross-tool standard chung cho risk metadata; cần internal convention.

---

### B. Context budget nên được test như memory budget

**Problem:** Prompt/context inflation thường được phát hiện muộn khi agent auto-compact nhiều, cache miss hoặc reasoning xuống chất lượng.

**Proposed improvement:** Đặt context SLO cho từng role:

- Code review agent: target context ≤ X% window trước review.
- Research agent: raw evidence spill-to-file, prompt chỉ giữ citation index + summaries.
- Architecture agent: load ADR/domain context theo task, không load toàn bộ knowledge base.

**Why it may work:** Agent SDK hiện exposing structured `context_usage`, và Claude Code tiếp tục cải thiện cache/context-limit behavior. [Agent SDK changelog](https://github.com/anthropics/claude-agent-sdk-typescript/blob/main/CHANGELOG.md)

**Suitable use cases:** Long-running agents, large .NET solutions, multi-repo research.

**Limitations:** “ít context” không luôn tốt; một số task cần full dependency graph/history.

**Risks:** Aggressive pruning bỏ mất constraint quan trọng.

**Recommendation:** Measure task success vs context usage, không optimize token đơn độc.

**Uncertainty:** Threshold tốt nhất cần empirical benchmark theo repository.

---

### C. Separate `Facts / Decisions / Working State / Messages`

**Problem:** Multi-agent context thường trộn evidence bền vững với transient chatter.

**Proposed improvement:** Handoff package chia thành:

1. **Facts:** source-grounded evidence.
2. **Decisions:** accepted choices + rationale.
3. **Working State:** branch, files changed, tests, blockers.
4. **Messages:** agent-to-agent requests, expiry và status.

**Why it may work:** Cross-session messaging đang trở thành capability thực tế; separating durable state giúp tránh dùng chat history như database.

**Suitable use cases:** Architect -> Developer -> QA -> Reviewer agent pipeline.

**Limitations:** Cần orchestration/storage ngoài prompt.

**Risks:** State duplication và stale snapshots.

**Recommendation:** Decisions cần version/id; working state phải revalidate trước side effect.

## 4. Agent, Workflow, and Loop Engineering

### Workflow 1 — Resource-bounded `test-fix-retest`

**Problem:** Build/test tool có thể ngốn RAM/CPU hoặc chạy quá lâu dù model loop vẫn còn budget.

**Technique:**

`Plan -> run tool with CPU/memory/time limits -> classify result -> fix -> retest -> stop/escalate`

Budget tối thiểu:

- retry count
- wall-clock timeout
- subprocess memory ceiling
- token/cost ceiling
- external-write budget

**Expected benefit:** Giảm runaway builds và low-value loops.

**Failure risks:** Limit quá thấp tạo false failure.

**Suitable use cases:** `dotnet test`, integration tests, EF Core migrations, static analyzers, Docker builds.

**Concrete test method:** Chạy 30 tasks với 3 memory profiles; đo completion rate, OOM/timeout rate và human rework.

---

### Workflow 2 — Permission re-check sau context/session handoff

**Problem:** Agent B nhận message từ Agent A và tưởng rằng quyền của A được chuyển theo.

**Technique:** Message truyền request + evidence; target executor **re-authorizes** dựa trên target session/tool policy.

**Expected benefit:** Ngăn privilege transitivity.

**Failure risks:** Approval fatigue nếu policy quá granular.

**Suitable use cases:** Research agent yêu cầu coding agent sửa file, reviewer agent yêu cầu GitHub write, Teams approval -> executor.

**Recommendation:** Reuse permission class metadata nhưng không reuse credential/approval token trừ khi token được scope rõ cho exact action hash.

---

### Workflow 3 — Agent message delivery phải có expiry và idempotency

**Problem:** Cross-session message có thể đến muộn sau khi task đã thay đổi hoặc được gửi lại sau reconnect.

**Technique:** Mỗi command message có:

```text
message_id
workflow_id
expected_state_version
expires_at
idempotency_key
requested_action
```

**Expected benefit:** Giảm stale/duplicate execution.

**Failure risks:** Complexity tăng; cần state store.

**Suitable use cases:** Background agents, remote-control sessions, event-driven agents.

**Recommendation:** Nếu `expected_state_version` mismatch, target không execute; trả `needs-refresh`.

---

### Workflow 4 — Background-agent health check thay vì chờ vô hạn

**Problem:** Agent phụ có thể bị stuck vì rate limit, background tool hoặc permission prompt.

**Technique:** Periodic check-in chỉ khi no-progress vượt threshold; classification:

- progressing
- blocked_on_permission
- blocked_on_rate_limit
- blocked_on_tool
- no_new_evidence
- failed

**Expected benefit:** Parent agent có thể decide retry/cancel/escalate thay vì spin.

**Failure risks:** Polling quá dày gây overhead.

**Suitable use cases:** Deep code review, research fan-out, CI root-cause analysis.

**Evidence:** Claude Code recent changelog thêm nhiều fixes cho background tasks, waiting goals và rate-limit/session behavior, cho thấy đây là failure mode thực tế. [Claude Code changelog](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
