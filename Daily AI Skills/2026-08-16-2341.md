## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách policy khỏi procedure

- **Problem:** Một file instruction lớn thường trộn coding conventions, architecture constraints, test steps, release steps và role-specific behavior. Agent phải ingest quá nhiều context kể cả khi không cần.
- **Proposed improvement:**
  - **Rules:** stable constraints — naming, architecture boundaries, forbidden patterns, security requirements.
  - **Skills:** procedural know-how — “review EF Core query”, “run migration safety check”, “create ADR”, “debug Hangfire job”.
  - **Agent definitions:** role + tool scope + output contract.
  - **Hooks:** deterministic enforcement.
- **Why it may work:** Cursor mô tả Skills là phù hợp cho dynamic context discovery/procedural instructions trong khi rules phù hợp persistent declarative guidance; Claude Code cũng đang tăng validation/hardening cho skills. [Cursor 2.4](https://cursor.com/changelog/2-4), [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- **Suitable use cases:** monorepo, .NET solution nhiều bounded context, QA agents, code review agents.
- **Limitations:** Skill discovery có thể không trigger đúng; rule matching theo path có thể thiếu context business.
- **Risks:** duplicated/conflicting instructions giữa layers.
- **Recommendation:** Dùng một “instruction ownership matrix”: mỗi rule chỉ có một nguồn canonical.
- **Uncertainty:** Không có chuẩn vendor-neutral đầy đủ cho precedence giữa rules/skills/hooks.

### B. Biến assumptions thành artifact có thể kiểm tra

- **Problem:** Agent thường âm thầm suy luận requirement và tiếp tục loop trên assumption sai.
- **Proposed improvement:** Bắt buộc output nội bộ theo schema:
  1. Facts/evidence
  2. Assumptions
  3. Inferences
  4. Unknowns
  5. Decisions
  6. Verification plan
- **Why it may work:** Nó biến reasoning state thành object reviewable thay vì implicit context.
- **Suitable use cases:** root-cause analysis, architecture planning, requirement analysis, data migration.
- **Limitations:** tăng verbosity/context nếu dùng cho task nhỏ.
- **Risks:** agent có thể “formalize” assumption nhưng vẫn sai.
- **Recommendation:** Chỉ persist assumptions có khả năng ảnh hưởng quyết định; mỗi assumption phải gắn verification method.
- **Uncertainty:** Đây là engineering recommendation, không phải claim rằng model sẽ tự động chính xác hơn.

### C. Context handoff nên là state compression có cấu trúc, không phải conversation dump

- **Problem:** Khi chuyển từ planner → implementer → reviewer, truyền cả transcript làm tăng noise và inherited bias.
- **Proposed improvement:** Handoff object gồm goal, constraints, changed files, unresolved questions, evidence links, tests run, failures, next action.
- **Why it may work:** Forked subagents của Claude Code làm context inheritance dễ hơn, nhưng không loại bỏ nhu cầu kiểm soát inherited assumptions. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- **Suitable use cases:** multi-agent implementation, long-running QA/research agents.
- **Limitations:** cần cơ chế update state nhất quán.
- **Risks:** summary omission.
- **Recommendation:** Handoff phải có “what was NOT verified”.

## 4. Agent, Workflow, and Loop Engineering

### A. Plan → Execute → Verify → Decide, không phải Plan → Execute → Repeat

- **Problem:** Nhiều agent loop bị low-value repetition: sửa lỗi, chạy lại, thấy lỗi khác, sửa tiếp mà không reevaluate strategy.
- **Technique:** Sau mỗi execution batch, thêm explicit decision checkpoint:
  - expected outcome?
  - actual outcome?
  - new evidence?
  - same failure signature?
  - retry hay re-plan?
  - stop condition đã đạt chưa?
- **Expected benefit:** giảm blind retries và token/tool waste.
- **Failure risks:** checkpoint quá thường xuyên làm workflow chậm.
- **Suitable use cases:** CI fix, flaky test, browser automation, integration debugging.
- **Recommendation:** Sau 2 lần failure cùng signature, bắt buộc root-cause branch thay vì retry branch.
- **Uncertainty:** Threshold 2 là heuristic; nên tune theo workflow.

### B. Forked subagent cho verification độc lập

- **Problem:** Agent tự review output của chính mình dễ giữ nguyên framing ban đầu.
- **Technique:** Dùng một fork/subagent chuyên verifier với objective khác: tìm counterexample, missing test, security regression, architecture violation.
- **Expected benefit:** tăng diversity của failure search.
- **Confirmed supporting capability:** Claude Code 2.1.232 hỗ trợ forked subagent kế thừa context và chạy background. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- **Failure risks:** fork kế thừa cả bias từ parent.
- **Recommendation:** Verifier prompt phải yêu cầu challenge assumptions và ưu tiên evidence độc lập.
- **Suitable use cases:** code review, migration plan, API breaking-change assessment.

### C. Resource guardrails là phần của agent design

- **Problem:** Build/test command có thể chiếm RAM/CPU, làm session hoặc runner treo.
- **Technique:** memory/time/process limits + cancellation + cleanup + retry budget.
- **Confirmed capability:** Claude Code 2.1.233 thêm `CLAUDE_CODE_TOOL_MEMORY_LIMIT` cho Bash commands trên Linux. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- **Expected benefit:** failure chuyển từ “machine/session stuck” sang bounded failure có thể xử lý.
- **Failure risks:** limit quá thấp gây false failure.
- **Recommendation:** log peak memory và tune theo `dotnet build`, test suite, Playwright, npm restore riêng.

### D. Permission prompt là một workflow state, không phải UI nuisance

- **Problem:** Agent dài hạn thường fail khi gặp approval và runtime/network lifecycle thay đổi.
- **Technique:** Model hóa states `WaitingForApproval`, `Approved`, `Denied`, `Expired`, `SessionRecovered`.
- **Evidence:** Claude Code 2.1.233 sửa cloud sessions bị coi là lost trong lúc chờ permission prompt; Notification hooks cũng được sửa cho permission prompts trong Desktop/VS Code. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).
- **Expected benefit:** agent orchestration rõ ràng hơn và dễ resume.
- **Suitable use cases:** destructive DB actions, git push, secrets, production access, external messages.

- **Existing workflow to improve:** research agents, interview agents, architecture workflows.
- **What to change/test:** parent tạo 2 forked workers: `proposer` và `challenger`; final synthesizer chỉ nhận evidence + decisions + unresolved uncertainty.
- **Expected benefit:** trade-off analysis tốt hơn và giảm single-frame bias.
- **Effort:** **1 hour** để prototype.
- **Evidence base:** Claude Code `2.1.232` hỗ trợ forked subagent/context inheritance. [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md).

### 4. Tạo permission/state model cho agent có external side effects

- **Relevance:** Teams/GitHub/DB/Azure integrations có write operations; approval phải là state rõ ràng.
- **Existing workflow to improve:** MCP/Teams integrations, automation agents, deployment helpers.
- **What to change/test:** state machine `Draft → NeedsApproval → Approved → Executing → Verified → Completed/Failed`.
- **Expected benefit:** auditability và failure recovery tốt hơn.
- **Effort:** **Half a day**.
- **Recommendation:** Không cho agent chuyển từ analysis sang destructive write nếu không có state transition được kiểm tra.

### 5. Build một “agent regression harness” dùng chung model/vendor

- **Relevance:** Cursor, Claude Code, Codex, Copilot thay đổi nhanh; cảm giác “model này tốt hơn” rất dễ sai.
- **Existing workflow to improve:** model/tool evaluation, code review agent, interview agent, QA agent.
- **What to change/test:** bộ 20–30 tasks có expected artifacts + deterministic validators + latency/cost/failure tracking.
- **Expected benefit:** quyết định tool/model dựa trên dữ liệu thực tế của workflow .NET của bạn.
- **Effort:** **Several days**.
- **Recommendation:** Đây là khoản đầu tư có leverage cao nhất nếu sử dụng nhiều coding agents lâu dài.

## 7. Opportunities and Trends to Watch

### Trend 1. Agent runtime đang tách khỏi chat UI

- **What is changing:** VS Code Agent Host, cloud/background agents, remote control và session portability đều hướng tới runtime độc lập khỏi cửa sổ chat.
- **Why it matters:** Agent engineering sẽ gần distributed workflow/system design hơn prompt writing.
- **Opportunity:** Xây tool/skill/state protocol portable giữa IDE, CLI và cloud agents.
- **Risk:** API/protocol còn thay đổi.
- **Status:** **Growing**.

### Trend 2. Skills trở thành software supply-chain surface

- **What is changing:** Cursor và Claude Code đều coi skills/plugins/hooks là reusable capability; Claude Code đang thêm hardening/validation.
- **Why it matters:** Một `SKILL.md` có thể ảnh hưởng tool behavior và workflow execution.
- **Opportunity:** skill linting, permission manifest, static analysis, regression tests cho AI instructions.
- **Risk:** malicious/overprivileged skills, hidden tool escalation.
- **Status:** **Growing**.

### Trend 3. Multi-agent chuyển từ “parallel prompts” sang session/message primitives

- **What is changing:** forked subagents, background agents, cross-session messaging và agent session infrastructure xuất hiện trong mainstream coding tools.
- **Why it matters:** Coordination design — ownership, handoff, stop conditions, conflict resolution — trở thành kỹ năng riêng.
- **Opportunity:** reusable orchestration patterns cho research/review/QA.
- **Risk:** concurrency noise, duplicated work, inherited assumptions.
- **Status:** **Growing**.

### Trend 4. Deterministic validation sẽ quan trọng hơn LLM self-confidence

- **What is changing:** Tool ecosystems thêm hooks, CI integration, browser tools, managed policies và review controls.
- **Why it matters:** Agent output chỉ đáng tin khi có executable evidence: tests, schemas, linters, diffs, policies.
- **Opportunity:** agent evaluation harness, contract tests, policy-as-code cho agent actions.
- **Risk:** quá phụ thuộc LLM-as-a-judge mà thiếu deterministic checks.
- **Status:** **Established** về nguyên tắc, **Growing** về tooling.

### Trend 5. “Model routing” giảm giá trị của model-specific prompt tricks

- **What is changing:** GitHub Copilot và Cursor đã đưa model routing/auto selection vào workflow.
- **Why it matters:** Prompt quá phụ thuộc một model có thể nhanh chóng mất giá trị.
- **Opportunity:** viết task contracts, examples, acceptance criteria và tool policies portable hơn.
- **Risk:** router opacity khiến reproducibility giảm.
- **Status:** **Growing**.
