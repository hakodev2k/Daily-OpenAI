## 1. Executive Summary

### 1. Guardian v2 defaults chuyển safety/review behavior sang **model-aware capability metadata**

- **One-sentence summary:** Codex `main` thêm `guardian_v2` defaults vào model catalog cho classifier instructions, review threshold, reasoning effort, transcript sources/limits và action/compaction token limits; explicit local `[features.guardianv2]` vẫn override catalog values. [Codex #38990, 17/08/2026](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Affected skill area:** Agent safety, review agents, capability discovery, config layering, evaluation reproducibility.
- **Why it matters:** Cùng một workflow nhưng khác model có thể cần review threshold, reasoning effort hoặc transcript budget khác nhau. Hard-code một bộ defaults toàn cục làm tăng nguy cơ tuning sai theo model family.
- **Practical implication:** Agent runtime nên resolve behavior từ **capability/config stack** thay vì chỉ model name + prompt.
- **Priority:** **Critical** cho agent platform; **High** cho coding agents cá nhân.
- **Confirmed facts:** Model catalog có thể cung cấp classifier prompt, threshold theo basis points, reasoning effort, transcript source/limits, action-token limit, classifier-instruction-token limit và parent-compaction-token limit; local overrides có precedence. Tests cover serialization, model overrides và local-override precedence. [Source](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Analysis:** Model identity đang trở thành một **capability profile**, không chỉ là tên endpoint. Agent frameworks cần biết model-specific review, context, tool và transport behavior.
- **Recommendation:** Tạo `ModelCapabilityProfile` gồm `context`, `tooling`, `permissions`, `review`, `multimodal`, `tokenBudgets`, `transport`, `sourceVersion`; persist resolved profile vào mỗi run.
- **Uncertainty:** Đây là source-level design trên Codex `main`; chưa có evidence public rằng stable `0.147.0` hoặc mọi hosted Codex session đang dùng mechanism này.

### 2. Config precedence đã trở thành **correctness concern**, không chỉ vấn đề configuration hygiene

- **One-sentence summary:** Guardian v2 resolve model defaults nhưng vẫn giữ local config là lớp override, và model overrides phải preserve catalog configuration mới. [Codex #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Affected skill area:** Rules, reusable instructions, model routing, policy debugging.
- **Why it matters:** Khi hệ thống có global defaults, model defaults, repo rules, environment restrictions, user overrides và per-task values, bug có thể xuất hiện từ **precedence order** dù từng config riêng lẻ đều đúng.
- **Practical implication:** Mỗi effective setting nên có provenance: `value`, `source`, `sourceVersion`, `resolvedAt`, `overriddenBy`.
- **Priority:** **High**.
- **Confirmed facts:** Codex chỉ lấy model default khi local field tương ứng chưa set; local Guardian config được giữ để re-resolve khi model context thay đổi. [Source](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Analysis:** Config resolution nên là deterministic function có test matrix và explainability, thay vì logic rải rác trong prompt/runtime.
- **Recommendation:** Thêm debug command kiểu `agent config explain` hiển thị final effective config và nguồn của từng value.
- **Uncertainty:** Chưa có benchmark public về overhead vận hành của model-owned defaults ở quy mô lớn.

- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }` và chỉ forward bounded evidence liên quan.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Biến config thành một **resolved artifact có provenance**

- **Problem:** Khi model defaults, repo rules, environment policy và task overrides chồng lên nhau, developer rất khó biết “giá trị cuối cùng đến từ đâu”.
- **Proposed improvement:** Resolve config thành một immutable artifact, ví dụ:

```text
EffectiveConfig
  review.threshold = 0.65   source=model-catalog:gpt-X@rev42
  review.reasoning = high   source=repo:.agent/config.toml
  tool.git.push = deny      source=environment:prod
  skill.catalogBudget = 1200 source=user
```

- **Why it may work:** Codex #38990 cho thấy local-vs-model-default precedence được test explicit, nghĩa là config source/precedence có thể và nên được deterministic hóa.
- **Suitable use cases:** Cursor rules, Codex/Claude skill packs, QA agents, architecture agents, CI/CD agents, model routing.
- **Limitations:** Cần schema/versioning tốt; nếu layer quá nhiều có thể khó vận hành.
- **Risks:** “Local override luôn thắng” không phù hợp cho mọi security setting; enforced policy phải có lớp authority cao hơn user config.
- **Recommendation:** Tách `defaults` khỏi `requirements`. Defaults có thể override; requirements chỉ được tighten.

### B. Skill metadata nên phục vụ **routing**, không chứa full procedure

- **Problem:** Skill catalog càng dài càng chiếm context, khiến discovery metadata lấn requirements và evidence.
- **Proposed improvement:** Catalog chỉ giữ `name`, `trigger`, `outcome`, `exclusions`, `costHint`; procedure/examples/commands load sau khi skill được chọn.
- **Why it may work:** Codex đã tạo explicit budget cho catalog, cho thấy skill discovery là bounded context surface. [Codex #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Cursor skills, Codex skills, Claude commands/agents, role-based knowledge packs.
- **Limitations:** Metadata quá ngắn có thể giảm routing recall.
- **Risks:** Similar skills có thể route sai nếu trigger/exclusions không đủ distinct.
- **Recommendation:** Benchmark 20–50 realistic tasks với 4 budget levels; measure routing recall và task success.

### C. Tách **Text Context Budget** và **Visual Evidence Budget**

- **Problem:** Text, screenshots, tool outputs và skill catalog thường bị xem như một context bucket chung.
- **Proposed improvement:** Log riêng `text_tokens`, `skill_tokens`, `tool_tokens`, `image_count`, `image_bytes`, `evidence_priority`.
- **Why it may work:** Codex đang budget riêng skill catalog và Guardian visual transcript.
- **Suitable use cases:** Browser QA, screenshot-based review, incident investigation, UI regression.
- **Limitations:** Provider/model khác nhau có cách tính image cost khác nhau.
- **Risks:** Cắt visual evidence quá sớm có thể làm verifier mất critical state.
- **Recommendation:** Dùng policy `latest state + failure state + one pre-action state`, sau đó benchmark với full history.

## 4. Agent, Workflow, and Loop Engineering

### A. Resolve capability trước khi execute

- **Problem:** Workflow thường assume mọi model/tool có cùng capabilities.
- **Technique:** Thêm bước `ResolveCapabilities` trước Plan/Execute:

```text
ResolveCapabilities
→ ResolvePolicy
→ Plan
→ Execute
→ Verify
→ Decide
```

- **Expected benefit:** Tránh dùng feature chưa ship, wrong context assumptions, model-specific threshold mismatch và provider incompatibility.
- **Failure risks:** Capability registry stale hoặc catalog source thay đổi không được versioned.
- **Suitable use cases:** Multi-model coding agents, Codex/Claude/OpenCode runners, model router, evaluation harness.
- **Concrete validation:** Chạy cùng benchmark với `capability probe ON/OFF`; đo unsupported-tool errors, config mismatches và failed runs.

### B. Verifier symmetry: reviewer phải nhận đủ evidence class mà executor dùng

- **Problem:** Executor dùng screenshot nhưng verifier chỉ đọc transcript text.
- **Technique:** `EvidenceEnvelope` chung cho executor và verifier, kèm bounded selection + redaction.
- **Expected benefit:** Giảm false-pass/false-fail trong browser QA và visual regression.
- **Failure risks:** Leakage của PII/secrets trong screenshot; payload phình nếu dedupe kém.
- **Suitable use cases:** Playwright/Selenium QA agents, incident agents, UI code-review agents.
- **Concrete validation:** Tạo 20 test cases mà textual state cố ý ambiguous nhưng screenshot quyết định được; compare verifier accuracy có/không có visual evidence.

### C. Approval cache phải phụ thuộc policy revision

- **Problem:** Human approval cũ có thể trở nên không hợp lệ khi environment/policy thay đổi.
- **Technique:** Cache key = `commandFingerprint + policyFingerprint + environment + scope`.
- **Expected benefit:** Hạn chế stale approvals.
- **Failure risks:** Approval prompts tăng nếu fingerprint quá nhạy.
- **Suitable use cases:** database migration, deployment, Git push/merge, cloud changes.
- **Concrete validation:** Approve command dưới policy A → đổi policy B restrictive hơn → ensure command xin fresh approval hoặc bị deny.

### D. `NO_MATERIAL_DELTA` như stop state

- **Problem:** Research agents dễ rơi vào low-value loops khi không có nguồn mới.
- **Technique:** State machine có `NO_MATERIAL_DELTA`, `SOURCE_EXHAUSTED`, `EVIDENCE_SUFFICIENT`, `CONFLICT_NEEDS_REVIEW`.
- **Expected benefit:** Giảm polling, context churn và fabricated filler.
- **Failure risks:** Stop quá sớm nếu source coverage kém.
- **Suitable use cases:** daily briefings, release monitoring, issue triage, market/news agents.
- **Concrete validation:** Track duplicate-source fetches/run và percentage of runs stopped without added evidence.

## 5. Hooks and Integrations

| Integration / hook | Workflow benefit | Security / permission concern | Difficulty |
|---|---|---|---|
| **.NET `ProcessStartInfo` sanitizer** | Prevent secrets leaking vào build/test hooks | Must sanitize after all environment merges; Windows env names case-insensitive | **Easy–Moderate** |
| **Playwright/Selenium screenshot evidence → verifier** | Cho QA agent visual proof thay vì chỉ logs | PII/token redaction, retention, image budget | **Moderate** |
| **GitHub Actions evaluator** | Run deterministic agent regression on PR | Avoid write token on untrusted PR; pin tool/model versions | **Moderate** |
| **MCP capability registry** | Expose model/tool capabilities, constraints và versions | Tool description itself can be untrusted; permission scope must remain runtime-enforced | **Advanced** |
| **Teams/Slack review gate** | Human approval cho high-risk action | Identity binding, stale approval, replay protection | **Advanced** |
| **Model catalog / capability source** | Model-aware defaults without hardcoding in every client | Remote metadata changes can alter behavior; require version/provenance | **Experimental** |

**Confirmed facts:** Codex #38990 demonstrates remote/model catalog defaults plus local overrides; #38942 shows policy fingerprinting can participate in approval semantics.  
**Analysis:** A useful enterprise pattern is to keep **configuration discovery** flexible but **permission enforcement** monotonic and runtime-controlled.  
**Recommendation:** Do not let MCP/tool metadata grant permissions by itself; it may describe capabilities, while runtime policy decides authority.  
**Uncertainty:** Tool ecosystems differ substantially; this pattern still needs product-specific implementation tests.

## 7. Opportunities and Trends to Watch

### 1. **Model-owned capability/config metadata**
- **What is changing:** Model catalog bắt đầu chứa không chỉ display metadata mà cả defaults ảnh hưởng review behavior.
- **Why it matters:** Agent runtime có thể trở nên model-aware mà không hardcode từng model family.
- **Opportunity:** Build vendor-neutral `CapabilityProfile` layer cho model routing/evaluation.
- **Risk:** Remote catalog changes có thể làm behavior drift nếu không pin/version.
- **Status:** **Early signal**.

### 2. **Context budgeting theo surface**
- **What is changing:** Skill catalog có token budget; visual evidence có count/byte budget.
- **Why it matters:** “Context window lớn” không loại bỏ nhu cầu allocation.
- **Opportunity:** Context observability dashboard và per-surface regression metrics.
- **Risk:** Over-engineering budget trước khi có workload data.
- **Status:** **Growing**.

### 3. **Verifier symmetry cho multimodal agents**
- **What is changing:** Safety/review layer bắt đầu nhận image-bearing transcript evidence.
- **Why it matters:** Executor/verifier context mismatch là failure mode thực tế trong browser/UI automation.
- **Opportunity:** Multimodal QA verifier, screenshot provenance, deterministic visual evidence selection.
- **Risk:** Privacy, cost, duplicated screenshots.
- **Status:** **Growing**.

### 4. **Monotonic permission stacks**
- **What is changing:** Environment policy chỉ được restrict, approval cache gắn policy fingerprint.
- **Why it matters:** Permission becomes compositional and auditable.
- **Opportunity:** Reusable agent security middleware cho .NET/MCP/CI agents.
- **Risk:** Excessive prompts nếu policy fingerprinting không ổn định.
- **Status:** **Established pattern, growing implementation support**.

### 5. **Agent state tách khỏi conversation transcript**
- **What is changing:** Experimental Project APIs reinforce project/thread/run separation.
- **Why it matters:** Long-running agents cần durable state, checkpoints và artifacts ngoài chat history.
- **Opportunity:** Build a reusable .NET `AgentRunStore` for QA/research/interview workflows.
- **Risk:** Schema complexity và migration burden.
- **Status:** **Growing**.
