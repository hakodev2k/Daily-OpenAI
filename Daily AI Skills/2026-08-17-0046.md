### 2. MCP `2026-07-28` đã chuyển core protocol sang stateless request/response — thay đổi kiến trúc lớn cho agent integrations

- **Confirmed facts:** MCP `2026-07-28` loại bỏ `initialize`/`initialized` handshake và `Mcp-Session-Id` khỏi protocol core, chuyển mỗi request thành self-describing request; thêm `server/discover`, `Mcp-Method`/`Mcp-Name` headers, cache hints, Multi Round-Trip Requests (MRTR), extensions framework và authorization hardening. [MCP 2026-07-28 announcement](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-07-28-spec-ga/index.md)
- **Affected skill area:** MCP server architecture, distributed agent systems, gateway routing, auth, scaling.
- **Why it matters:** MCP server giờ có thể chạy sau ordinary round-robin load balancer mà không cần protocol-level session affinity cho core request flow.
- **Practical implication:** Với .NET MCP services chạy trên Azure Container Apps/App Service/Kubernetes, stateless-by-default có thể đơn giản hóa horizontal scaling và recovery.
- **Priority:** **Critical** nếu đang build MCP server mới; **High** nếu đang duy trì server cũ.
- **Analysis:** Đây là thay đổi đáng học hơn một model release vì nó tác động trực tiếp tới system design, state ownership và failure recovery.
- **Recommendation:** Mọi MCP architecture mới nên bắt đầu bằng câu hỏi “state nào thực sự là application state?” thay vì mặc định giữ connection/session state ở transport layer.
- **Uncertainty:** Ecosystem clients có thể chưa đồng loạt support revision mới; cần giữ protocol negotiation/backward compatibility khi rollout.

### 4. MCP Tasks và MRTR làm rõ cách thiết kế long-running agent work mà không cần open bidirectional session

- **Confirmed facts:** MCP `2026-07-28` đưa Tasks ra khỏi experimental core sang extension `io.modelcontextprotocol/tasks`; server-to-client interactions được redesign quanh MRTR thay vì yêu cầu persistent bidirectional stream. [MCP spec announcement](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-07-28-spec-ga/index.md)
- **Affected skill area:** Long-running agents, job state, polling/subscription, recoverability.
- **Why it matters:** Long-running task nên có explicit lifecycle/state handle thay vì gắn tuổi thọ công việc vào một socket/session cụ thể.
- **Practical implication:** Pattern này rất phù hợp với research agent, QA batch run, repository scan, video/test generation hoặc Azure background processing.
- **Priority:** **High**.
- **Analysis:** Đây là cùng một nguyên tắc với durable background jobs: transport reconnect không nên làm mất logical task.
- **Recommendation:** Thiết kế task state gồm `Queued → Running → WaitingForInput/Approval → Verifying → Completed/Failed/Cancelled`, cùng idempotency key và checkpoint data.
- **Uncertainty:** Tasks extension ecosystem còn mới; cần test client/tool interoperability trước khi phụ thuộc sâu.

- **Affected skill area:** Security, permission boundaries, MCP gateway, tool authorization.
- **Why it matters:** Agent tool permission có thể được enforced ở network/gateway layer thay vì chỉ dựa vào prompt hoặc application code.
- **Practical implication:** Có thể xây policy như “research agent được `search/read`, deployment agent mới được `deploy`, production write cần step-up approval”.
- **Priority:** **High**.
- **Analysis:** Đây là hướng phù hợp với zero-trust agent design: model quyết định **muốn làm gì**, nhưng policy layer quyết định **được phép làm gì**.
- **Recommendation:** Với MCP gateway, log `client identity + tool name + scope + decision + correlation id`; không log secret arguments trừ khi đã redacted.
- **Uncertainty:** Gateway vendors có thể triển khai header/policy semantics khác nhau; cần conformance test.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Version-aware instructions thay vì “one prompt forever”

- **Problem:** Agent harness thay đổi nhanh; rule hoặc skill viết theo behavior của một version có thể silent-regress khi runtime đổi.
- **Proposed improvement:** Gắn metadata cho instruction assets:

```yaml
instruction_version: 3
validated_with:
  codex: "stable-baseline"
  claude_code: "2.1.x"
  opencode: "1.18.x"
last_regression_run: "2026-08-17"
```

- **Why it may work:** Nó biến prompt/rule/skill thành versioned engineering artifact thay vì prose không có lifecycle.
- **Suitable use cases:** `AGENTS.md`, Cursor rules, Claude skills, Codex skills, QA-agent instructions.
- **Limitations:** Runtime-specific behavior không phải lúc nào cũng map cleanly về version string.
- **Risks:** False confidence nếu metadata được update mà regression suite không chạy thật.
- **Recommendation:** Metadata chỉ được bump khi automated eval pass.
- **Uncertainty:** Đây là engineering recommendation; chưa có cross-vendor standard bắt buộc.

### B. Context contract cho MCP tools

- **Problem:** Agent thường gọi tool với context implicit từ conversation; server khó biết identity, capabilities hoặc intent nào là authoritative.
- **Proposed improvement:** Với MCP 2026-07-28, tận dụng self-describing request model và bổ sung application-level metadata có kiểm soát: correlation id, task id, approval state, data classification.
- **Why it may work:** Protocol mới đã di chuyển client/protocol metadata vào request và hỗ trợ stateless routing. [MCP 2026-07-28](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-07-28-spec-ga/index.md)
- **Suitable use cases:** GitHub MCP, database MCP, Teams/Slack integration, Azure operations.
- **Limitations:** Không nên nhét toàn bộ conversation hoặc secret vào metadata.
- **Risks:** Metadata spoofing nếu trust boundary không rõ.
- **Recommendation:** Authenticated identity phải đến từ gateway/auth layer; model-supplied `userId` không được coi là authoritative.

### C. Rules/Skills cần explicit compatibility tests

- **Problem:** Một `SKILL.md` có thể “load được” nhưng semantic behavior thay đổi sau runtime upgrade.
- **Proposed improvement:** Mỗi skill quan trọng có 3 lớp test:
  - **Discovery test:** agent có chọn đúng skill không?
  - **Execution test:** đúng commands/tools có được dùng không?
  - **Outcome test:** artifact có đạt deterministic acceptance criteria không?
- **Why it may work:** Tách failure “agent không chọn skill” khỏi “skill logic sai” và “model execution sai”.
- **Suitable use cases:** migration safety, EF Core review, security review, release workflow.
- **Limitations:** Tốn công duy trì fixtures.
- **Recommendation:** Chỉ cần 3–5 golden tasks mỗi skill để bắt regression lớn.

### D. Facts / Analysis / Recommendation / Uncertainty nên trở thành output schema cho research agents

- **Problem:** Research agent dễ trộn source fact và suy luận.
- **Proposed improvement:** Enforce 4 fields ở mỗi major claim, đúng cấu trúc briefing này.
- **Why it may work:** Người review có thể nhìn ngay phần nào cần source và phần nào là judgment.
- **Suitable use cases:** technology radar, architecture research, security investigation, interview knowledge engine.
- **Risks:** Agent có thể gắn nhãn “Confirmed” sai; deterministic source checks vẫn cần thiết.
- **Recommendation:** `Confirmed` bắt buộc có citation; nếu không có source thì downgrade thành `Analysis` hoặc `Uncertainty`.

## 4. Agent, Workflow, and Loop Engineering

### A. Canary version testing cho coding agents

- **Problem:** Upgrade agent CLI/harness trực tiếp có thể tạo regression không nhìn thấy ngay.
- **Technique:** Chạy 5–10% regression tasks trên prerelease/new runtime, không dùng production repository writes.
- **Expected benefit:** Phát hiện thay đổi permission/tool/context trước khi rollout.
- **Failure risks:** Canary task set không đại diện workload thực.
- **Suitable use cases:** Codex alpha hiện tại, Claude Code upgrades, OpenCode releases.
- **Recommendation:** Codex `0.148.0-alpha.20` là candidate tốt để thực hành pattern này hôm nay. [Codex release](https://github.com/openai/codex/releases/tag/rust-v0.148.0-alpha.20)

### B. Durable task state độc lập transport

- **Problem:** Long-running agent bị coi như “một conversation connection”; disconnect có thể gây duplicate/restart confusion.
- **Technique:** Tách:
  - `TaskId`
  - logical state
  - checkpoint
  - result artifacts
  - approval state
  - retry budget
  khỏi HTTP/WebSocket/CLI session.
- **Expected benefit:** Resume/recovery rõ hơn, hỗ trợ horizontal scaling.
- **Evidence:** MCP 2026-07-28 bỏ protocol session core và đưa Tasks thành extension; MRTR thay thế nhiều nhu cầu bidirectional session. [MCP announcement](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-07-28-spec-ga/index.md)
- **Failure risks:** Task store trở thành distributed-system dependency mới.
- **Suitable use cases:** QA suites, research jobs, background code analysis, document generation.

### C. Protocol negotiation là một branch cần test, không phải implementation detail

- **Problem:** Client mới + server cũ hoặc ngược lại có thể silently fallback.
- **Technique:** Test matrix:

| Client | Server | Expected |
|---|---|---|
| 2026-07-28 | 2026-07-28 | discovery/stateless path |
| modern C# client | legacy server | fallback initialize |
| legacy client | modern stateless server | backward-compatible handling |
| strict modern client | legacy server | explicit failure |

- **Expected benefit:** Không nhầm “works” với “đang chạy đúng protocol era”.
- **Evidence:** C# SDK docs mô tả automatic probing/fallback và ability to pin `ProtocolVersion`. [C# SDK stateless docs](https://github.com/modelcontextprotocol/csharp-sdk/blob/main/docs/concepts/stateless/stateless.md)
- **Recommendation:** Log negotiated protocol version như telemetry field.

### D. Retry phải dựa trên failure class

- **Problem:** Agent thường retry mọi lỗi giống nhau.
- **Technique:** Classify:
  - transient network
  - auth/permission
  - tool validation
  - deterministic test failure
  - protocol mismatch
  - missing evidence/context
  - user approval required
- **Expected benefit:** Mỗi class có policy riêng: retry, refresh auth, re-plan, stop, ask approval.
- **Failure risks:** Misclassification.
- **Recommendation:** Protocol mismatch (`-32020`/`-32021`/`-32022` trong MCP era mới) không nên blind retry; phải negotiate/fail explicitly. [C# SDK docs](https://github.com/modelcontextprotocol/csharp-sdk/blob/main/docs/concepts/stateless/stateless.md)

## 5. Hooks and Integrations

### 1. ASP.NET Core MCP server + Azure-hosted stateless deployment

- **Can integrate:** `ModelContextProtocol.AspNetCore` với ASP.NET Core service, containerize và chạy sau Azure load balancer/reverse proxy.
- **Workflow benefit:** Tool services scale giống standard HTTP service hơn khi không phụ thuộc protocol session.
- **Security concerns:** Authenticate at gateway/service; enforce tool-level authorization; redact tool args in logs.
- **Difficulty:** **Moderate**.
- **Recommendation:** Prototype read-only MCP tools trước, ví dụ `search-code-metadata`, `get-build-status`, `get-architecture-doc`.

### 2. MCP gateway policy dựa trên tool/method headers

- **Can integrate:** reverse proxy/API gateway có thể nhìn method/tool metadata theo spec mới.
- **Workflow benefit:** Central policy và observability trước khi request đến tool implementation.
- **Security concerns:** Không trust headers từ unauthenticated client; gateway phải bind identity + authorization policy.
- **Difficulty:** **Advanced**.
- **Evidence:** Spec 2026-07-28 đưa method/tool names vào `Mcp-Method` và `Mcp-Name` headers cho routing/authorization use cases. [MCP announcement](https://github.com/modelcontextprotocol/modelcontextprotocol/blob/main/blog/content/posts/2026-07-28-spec-ga/index.md)

### 3. Codex prerelease canary trong GitHub Actions

- **Can integrate:** Một non-blocking workflow chạy regression tasks với alpha binary/version và upload report artifact.
- **Workflow benefit:** Phát hiện incompatibility sớm mà không ảnh hưởng main development path.
- **Security concerns:** Không cấp production secrets/write token; dùng read-only repository hoặc synthetic fixture repo.
- **Difficulty:** **Moderate**.
- **Recommendation:** Chỉ alert khi metric vượt threshold, ví dụ success rate giảm >10% hoặc permission/tool error xuất hiện mới.

### 4. MCP Tasks ↔ Hangfire/Azure Functions mapping

- **Can integrate:** MCP task id map sang Hangfire job id hoặc durable backend job record.
- **Workflow benefit:** Agent-facing task semantics có durable execution backend quen thuộc với .NET.
- **Security concerns:** Không expose raw internal job management APIs cho model; wrap bằng allowlisted operations.
- **Difficulty:** **Moderate**.
- **Analysis:** Đây là kiến trúc suy luận từ MCP Tasks/stateless principles, không phải official recommendation rằng Hangfire là implementation bắt buộc.

### 5. Teams/Slack approval adapter

- **Can integrate:** Agent task chuyển sang `WaitingForApproval`; approval UI gửi signed decision trở lại orchestrator.

## 7. Opportunities and Trends to Watch

### Trend 1. Stateless agent integration protocols

- **What is changing:** MCP bỏ protocol session core và chuyển metadata/capability vào request.
- **Why it matters:** Agent tools có thể scale giống modern web services hơn.
- **Opportunity:** .NET/Azure MCP gateway, observability middleware, policy-as-code.
- **Risk:** Application vẫn có state; gọi protocol “stateless” không có nghĩa toàn hệ thống không cần persistence.
- **Status:** **Established** ở spec, **Growing** ở ecosystem adoption.

### Trend 2. Agent compatibility/evaluation sẽ trở thành một engineering discipline riêng

- **What is changing:** Runtime/model/harness releases diễn ra nhanh, kể cả prerelease như Codex alpha hiện tại.
- **Why it matters:** “Nâng version” có thể thay tool behavior mà compile/test truyền thống không phát hiện.
- **Opportunity:** Agent regression test frameworks, golden tasks, behavioral diffing.
- **Risk:** Benchmark không đại diện workload thật.
- **Status:** **Growing**.

### Trend 3. Authorization chuyển từ prompt-level sang infrastructure-level

- **What is changing:** MCP gateway-friendly headers, issuer validation, step-up patterns; coding agents cũng ngày càng có explicit sandbox/approval models.
- **Why it matters:** Security policy phải tồn tại độc lập khỏi model output.
- **Opportunity:** Agent access gateway, signed approvals, tool-level policy engines.
- **Risk:** Overly broad tool definitions vẫn có thể bypass intent-level controls dù network auth đúng.
- **Status:** **Growing**.

### Trend 4. Long-running agents ngày càng giống durable workflow engines

- **What is changing:** Tasks, checkpoints, background agents, resumable sessions và independent agent hosts đều đẩy agent work ra khỏi synchronous chat model.
- **Why it matters:** Skills cần mở rộng từ prompt engineering sang state-machine, idempotency và failure recovery.
- **Opportunity:** Reuse kinh nghiệm Hangfire/Azure Functions/Durable workflows cho agent systems.
- **Risk:** Dùng LLM orchestration cho phần nên deterministic có thể làm hệ thống phức tạp vô ích.
- **Status:** **Growing**.

### Trend 5. Open-source harnesses là công cụ kiểm tra portability

- **What is changing:** OpenCode tiếp tục có stable releases trong khi Codex/Claude/Cursor/Copilot phát triển ecosystem riêng.
- **Why it matters:** Một skill tốt nên tách domain procedure khỏi vendor-specific plumbing càng nhiều càng tốt.
- **Opportunity:** Cross-harness instruction standardization và compatibility layer.
- **Risk:** “Write once run everywhere” có thể bị overhype vì permission/tool/context semantics vẫn khác.
- **Status:** **Early signal / Growing**.
