### 1. Codex thêm environment-specific command policy chỉ được phép **siết chặt**, không được nới quyền

- **One-sentence summary:** Codex vừa merge cơ chế `EnvironmentConfig.exec_policy` để mỗi environment có thể thêm restrictive execution policy lên trên command policy hiện tại, nhưng policy ở environment không được chứa `allow` rules; thay đổi policy cũng làm invalid cached approvals. [OpenAI Codex commit #38942, 2026-08-17 04:32 UTC / 11:32 UTC+7](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Affected skill area:** Permission boundaries, sandboxing, environment policy, approval caching, secure agent execution.
- **Why it matters:** Đây là một pattern rất mạnh cho agent engineering: **lower-level execution environment được quyền giảm quyền, không được tự mở rộng quyền**. Nó gần với security lattice / deny-overrides hơn là prompt-level instruction.
- **Practical implication:** Khi thiết kế QA agent, research agent hoặc code-review agent chạy ở nhiều environment, có thể gắn policy theo environment như `read-only`, cấm package install, cấm outbound network hoặc cấm một nhóm command—even nếu user/session trước đó từng approve prefix tương tự.
- **Priority:** **Critical**.
- **Confirmed facts:** Commit thêm optional restrictive execution policy, reject environment policy có allow rules, merge environment policy vào shell execution/approval decisions, và đưa policy fingerprint vào cached approval keys để policy đổi thì approval cũ không còn được reuse. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Analysis:** Đây là một trong những thay đổi đáng học nhất hôm nay vì nó minh họa cách tách **model intent** khỏi **runtime authority**. Model có thể muốn chạy lệnh, nhưng environment vẫn có quyền phủ định.
- **Recommendation:** Áp dụng cùng pattern vào agent framework riêng: `GlobalPolicy ∩ WorkspacePolicy ∩ EnvironmentPolicy ∩ TaskPolicy`, trong đó layer dưới chỉ được làm tập quyền nhỏ hơn.
- **Uncertainty:** Đây là code đã merge vào main; chưa có evidence trong nguồn kiểm tra rằng behavior này đã ship trong stable Codex CLI release công khai tại thời điểm 13:23 UTC+7.

### 2. Codex harden credential isolation: execution-server token không còn được phép lọt vào child process hoặc command hooks

- **One-sentence summary:** Codex merge fix đưa `CODEX_EXEC_SERVER_NOISE_AUTH_TOKEN` vào danh sách non-inheritable environment variables và kiểm tra case-insensitive scrubbing sau policy overrides, cho cả shell commands và command hooks. [OpenAI Codex commit #38941, 2026-08-17 04:12 UTC / 11:12 UTC+7](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Affected skill area:** Secret management, hooks, subprocess isolation, sandbox security, least privilege.
- **Why it matters:** Coding agents thường chạy arbitrary build/test scripts và hooks. Nếu credential của agent runtime bị inherited xuống child process, một tool, script hoặc malicious dependency có thể đọc được credential vượt quá quyền cần thiết.
- **Practical implication:** Hooks và subprocess nên được xem là **untrusted execution boundary**, không phải extension nội bộ mặc định đáng tin.
- **Priority:** **Critical**.
- **Confirmed facts:** Commit mô tả execution-server credential “must not be exposed to model-reachable commands or command hooks”, thêm token vào shared non-inheritable list và test cả case variant sau shell environment policy override. [Source](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Analysis:** Pattern cần copy sang mọi AI agent backend: secret scrub phải chạy **sau khi merge environment overrides**, vì nếu scrub trước rồi sau đó một config/hook layer set lại secret thì vẫn leak.
- **Recommendation:** Trong .NET worker/agent runtime, build một `SanitizedProcessEnvironment` allowlist hoặc denylist hardened theo case-insensitive comparison trên Windows; chạy regression test để bảo đảm hooks không nhìn thấy control-plane credentials.
- **Uncertainty:** Fix cụ thể nói về internal Codex execution credential; không có nghĩa mọi secret class khác đều đã được scrub hoàn chỉnh.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Rule mới nên được thiết kế theo “monotonic restriction”

- **Problem:** Một agent có nhiều lớp config: global, repo, environment, task, user override. Nếu mọi layer đều có thể allow/deny tự do, precedence trở nên khó audit và một layer thấp có thể vô tình mở quyền mà policy trên cao cố chặn.
- **Proposed improvement:** Chia config thành hai loại rõ ràng:
  1. **Capability grants** chỉ đến từ trusted authority.
  2. **Restrictions** có thể được thêm ở environment/task level.

  Effective permission là intersection của grants với tất cả restrictions.
- **Why it may work:** Codex vừa merge design cho environment execution policy chỉ được chứa restrictions, không allow rules. [Commit #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** production debugging agents, database agents, CI agents, repo agents chạy trên shared runners.
- **Limitations:** Một số workflow cần temporary escalation; monotonic restriction thuần túy không giải quyết approval escalation.
- **Risks:** Nếu policy quá chặt, agent dễ fail với lỗi permission nhưng không hiểu nguyên nhân.
- **Recommendation:** Tách `BaseAuthority` và `TemporaryApproval`; temporary approval không được override hard-deny environment policy.
- **Uncertainty:** Đây là architecture recommendation rút ra từ Codex implementation, không phải claim rằng mọi framework phải dùng cùng schema.

### B. Secrets phải được scrub **sau** context/environment merge

- **Problem:** Nhiều framework sanitize process env trước, sau đó apply user/workspace/hook overrides. Điều này tạo “reintroduction bug”: secret bị xóa rồi được layer sau set lại.
- **Proposed improvement:** Pipeline nên là:

  `Host env → user overrides → workspace overrides → tool/hook env → policy transforms → final secret scrub → spawn process`

- **Why it may work:** Codex fix mới test trực tiếp case policy override set lại credential bằng khác casing rồi đảm bảo final child process/hook vẫn không nhận token. [Commit #38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Suitable use cases:** `ProcessStartInfo` trong .NET, Playwright worker, shell hooks, Git hooks, test runners, Docker wrappers.
- **Limitations:** Denylist chỉ bảo vệ secret đã biết; unknown secrets vẫn có thể leak.
- **Risks:** Scrub nhầm env var cần thiết có thể làm build/tool fail.
- **Recommendation:** Với high-risk agents, prefer allowlist minimal environment + explicit opt-in vars; nếu dùng denylist, có canonical secret registry và case-insensitive match trên Windows.

### C. Context limit phải là capability metadata có source/version, không phải prompt constant

- **Problem:** Agent prompt packing thường giả định model context theo model name. Nhưng cùng một model family có thể khác limit theo harness/subscription/API surface.
- **Proposed improvement:** `ModelCapabilityRegistry` nên lưu:
  - provider/model/access path;
  - max context;
  - max input;
  - max output;
  - reasoning/tool support;
  - source URL;
  - last verified timestamp;
  - confidence/status.
- **Why it may work:** OpenCode vừa phải sửa GPT-5.6 metadata cho ChatGPT subscription path để match Codex limits. [Commit #39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Suitable use cases:** multi-model router, research agent, long coding session, knowledge agent.
- **Limitations:** Capability data thay đổi nhanh và có thể không public đầy đủ.
- **Risks:** Stale registry gây compaction quá muộn hoặc wasted context.
- **Recommendation:** Nếu runtime trả capability/limit metadata, ưu tiên runtime; static registry chỉ là fallback.

### D. “Project context” không nên đồng nhất với “conversation context”

- **Problem:** Nếu mọi project state nằm trong chat transcript, mỗi run mới phải ingest transcript cũ, làm context phình và dễ inherited assumptions.
- **Proposed improvement:** Tách:
  - `Project metadata`: goal, roots, architecture, policies.
  - `Run/thread`: task cụ thể.
  - `Durable artifacts`: findings, decisions, test evidence.
  - `Ephemeral transcript`: raw interaction.
- **Why it may work:** Codex experimental Project APIs tách project identity/roots/metadata khỏi thread, hỗ trợ assignment và fork inheritance. [Commit #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Suitable use cases:** interview intelligence, QA automation, research agents, multi-repo architecture review.
- **Limitations:** Cần decide dữ liệu nào promote từ ephemeral → durable.
- **Risks:** Durable state sai/outdated có thể gây bias lâu dài.
- **Recommendation:** Mỗi durable fact phải có source/evidence + freshness + owner.

## 4. Agent, Workflow, and Loop Engineering

### A. Approval cache phải phụ thuộc policy version/fingerprint

- **Problem:** User approve command hôm qua trong environment A, hôm nay policy đã chặt hơn nhưng agent reuse approval cũ → security bypass logic.
- **Technique:** Cache key không chỉ là command/tool signature; thêm `policy_fingerprint`, identity, workspace/environment id và risk class.
- **Evidence:** Codex commit #38942 thêm environment policy fingerprint vào cached approval keys để policy change yêu cầu fresh approval. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Expected benefit:** Approval không sống lâu hơn policy context tạo ra nó.
- **Failure risks:** Policy hash thay đổi quá thường xuyên làm mất benefit của cached approvals.
- **Suitable use cases:** shell commands, DB writes, Azure operations, git push, external messages.
- **Recommendation:** Cache approval theo semantic permission—not raw prompt text—and invalidate khi authority/policy changes.

### B. Project → Thread → Fork nên có explicit inheritance rules

- **Problem:** Khi fork agent, cái gì được inherit? Project id? permissions? secrets? durable memory? task-local assumptions?
- **Technique:** Define inheritance matrix:
  - project id: inherit;
  - read-only project metadata: inherit;
  - task assumptions: inherit nhưng mark unverified;
  - approvals: **không inherit mặc định**;
  - secrets: re-resolve theo child authority;
  - mutable working state: snapshot/version.
- **Evidence:** Codex Project API commit có thread project assignment và fork inheritance cho project id, nhưng security-sensitive inheritance vẫn cần runtime policy riêng. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Expected benefit:** Multi-agent workflow dễ reasoning và audit hơn.
- **Failure risks:** Over-inheritance làm child agent mang bias/quyền thừa; under-inheritance làm mất context.
- **Suitable use cases:** parent planner → implementation subagent → verifier; research fan-out.

### C. Gateway architecture: preserve native provider semantics khi cần

- **Problem:** Một normalized chat API có thể làm mất provider-specific reasoning, tool, cache hoặc streaming semantics.
- **Technique:** Gateway chia hai layer:
  1. governance/routing/telemetry common;
  2. provider protocol adapters native.
- **Evidence:** OpenCode chuyển OpenAI qua Responses API passthrough và Anthropic qua Messages API thay vì chỉ dùng unified compatible chat path. [Source](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Expected benefit:** Giữ feature fidelity mà vẫn có central gateway.
- **Failure risks:** Adapter count tăng, test matrix lớn hơn.
- **Suitable use cases:** enterprise model gateway, multi-provider coding agents, AI platform teams.
- **Recommendation:** Capability-driven adapter selection, không chọn adapter chỉ theo model name string.

### D. “Environment” nên là security boundary, không chỉ machine target

- **Problem:** Nhiều agent framework dùng environment chỉ để chứa URL/container image. Nhưng command policy, file roots, network egress, credentials và approval rules mới quyết định risk thực tế.
- **Technique:** Environment descriptor nên có:
  - filesystem roots;
  - network policy;
  - command policy;
  - secret profile;
  - approval policy;
  - resource limits;
  - tool/MCP allowlist;
  - audit sink.
- **Evidence:** Các Codex changes hôm nay đồng thời chạm environment exec policy, managed requirements và secret isolation—cho thấy runtime environment là một policy container chứ không chỉ compute target. [#38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929) · [#38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Expected benefit:** Dễ reason về blast radius và dễ chuyển agent giữa local/QA/prod-like contexts.

## 5. Hooks and Integrations

### 1. Command hooks: chạy như untrusted subprocess

- **What can be integrated:** pre/post tool hooks, session hooks, test/lint hooks, artifact hooks.
- **Workflow benefit:** deterministic validation và automation quanh agent loop.
- **Security/permission concerns:** Hook có thể đọc environment, filesystem, network; vì vậy không nên inherit control-plane credentials. Codex fix mới trực tiếp cover command hooks. [Commit #38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Difficulty:** **Moderate**.
- **Recommendation:** Mỗi hook có explicit env allowlist + timeout + cwd + network profile; log exit code/stdout metadata nhưng redact sensitive values.

### 2. Cloudflare AI Gateway + native OpenAI/Anthropic APIs

- **What can be integrated:** central routing/observability/BYOK với OpenAI Responses API và Anthropic Messages API native semantics.
- **Workflow benefit:** Một gateway cho governance nhưng model adapter vẫn giữ provider capability.
- **Security/permission concerns:** Không forward gateway token như upstream provider token; distinguish gateway credential và provider credential. OpenCode commit mới thay đổi chính điểm này. [Commit #42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Difficulty:** **Advanced**.
- **Recommendation:** Test request body/headers ở gateway boundary; không chỉ test final text response.

### 3. Windows Codex managed policy deployment

- **What can be integrated:** Intune/GPO/bootstrap scripts/enterprise images ghi `%ProgramData%\OpenAI\Codex\requirements.toml`.
- **Workflow benefit:** Enforce agent sandbox/approval/model requirements ngoài user config.
- **Security/permission concerns:** File path/ACL phải thực sự admin-controlled; user-writable requirements file làm mất ý nghĩa policy.
- **Difficulty:** **Moderate**.
- **Evidence:** Windows legacy `managed_config.toml` đang được loại khỏi automatic managed config path trong main. [Commit #38947](https://github.com/openai/codex/commit/c6058ccaa91ab17159cf805bf4d6d4edd87fe5fc)

### 4. Project state API pattern cho research/QA/interview systems

- **What can be integrated:** SQLite/PostgreSQL project store, event notifications, project-to-run assignment, fork inheritance.
- **Workflow benefit:** Durable context không phụ thuộc một chat transcript.
- **Security/permission concerns:** Project metadata có thể chứa sensitive repo paths/business context; cần per-project ACL.
- **Difficulty:** **Moderate**.
- **Evidence:** Codex experimental Project APIs. [Commit #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

### 5. Locked-down devcontainers và outbound network allowlist

- **What can be integrated:** iptables/nftables/proxy allowlist cho agent container.
- **Workflow benefit:** Giảm data exfiltration surface và dependency on unrestricted internet.
- **Security/permission concerns:** Domain allowlist drift, DNS/CDN changes, indirect redirects.
- **Difficulty:** **Advanced** nếu production-grade; **Moderate** cho local sandbox.
- **Evidence:** Claude Code upstream vẫn maintain explicit devcontainer firewall domain list và vừa remove một Statsig hostname. [Commit #72451](https://github.com/anthropics/claude-code/commit/ae58f7a0a23f0fddedd668de74622ff46646526b)

## 7. Opportunities and Trends to Watch

### Trend 1. Agent permission model đang chuyển từ “approval prompt” sang composable policy layers

- **What is changing:** Codex main đang thêm environment-specific restrictive execution policy và invalidation của cached approval theo policy fingerprint.
- **Why it matters:** Approval UI một mình không đủ; authority phải có machine-enforced policy semantics.
- **Opportunity:** Xây policy-as-code cho agent tools, shell, network, DB và external actions.
- **Risk:** Policy language quá phức tạp sẽ khó debug và khiến developers bypass nó.
- **Status:** **Growing**.

### Trend 2. Control-plane credentials đang được tách mạnh khỏi model-reachable execution plane

- **What is changing:** Codex explicitly scrub execution-server auth token khỏi commands/hooks.
- **Why it matters:** Agent infrastructure bắt đầu giống secure orchestration platform hơn một CLI wrapper.
- **Opportunity:** Standardized secret-boundary libraries cho agent runners; .NET package cho sanitized subprocess execution là một project idea có giá trị.
- **Risk:** Chỉ scrub vài known variables tạo false sense of security.
- **Status:** **Growing**.

### Trend 3. Persistent “Project” state trở thành primitive bên cạnh session/thread

- **What is changing:** Codex app-server experimental Project APIs formalize roots, metadata, ordering và thread assignment.
- **Why it matters:** Long-running agent systems cần durable organizational state vượt qua một transcript.
- **Opportunity:** Multi-agent project memory/state layer portable giữa Codex/Claude/Cursor/custom agents.
- **Risk:** Persistent memory dễ tích tụ stale assumptions.
- **Status:** **Early signal**.

### Trend 4. AI gateways sẽ phải giữ provider-native semantics thay vì chỉ OpenAI-compatible normalization

- **What is changing:** OpenCode route OpenAI/Anthropic qua native passthrough khi dùng Cloudflare AI Gateway.
- **Why it matters:** New reasoning/tool APIs ngày càng khác biệt; lowest-common-denominator abstractions có thể break features.
- **Opportunity:** Capability-aware gateway/router, protocol adapters, conformance testing.
- **Risk:** Adapter explosion, vendor-specific code và maintenance cost.
- **Status:** **Growing**.

### Trend 5. Model capability metadata trở thành runtime concern

- **What is changing:** OpenCode phải sửa GPT-5.6 context/input limits theo ChatGPT subscription path.
- **Why it matters:** Model name không đủ để xác định context budget và feature set.
- **Opportunity:** Automated capability discovery + registry + regression checks.
- **Risk:** Metadata drift, undocumented provider changes.
- **Status:** **Established problem, Growing tooling need**.
