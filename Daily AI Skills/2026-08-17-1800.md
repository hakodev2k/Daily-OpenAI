## 1. Executive Summary

### 1. Codex Guardian v2 bắt đầu đưa **visual evidence** vào transcript sampling

- **One-sentence summary:** Codex `main` thêm `features.guardianv2.transcript.include_images`, cho phép Guardian v2 nhận ảnh gần đây từ user/assistant messages và configured tool outputs; context ảnh bị giới hạn ở **4 ảnh gần nhất** và **8 MiB tổng**, còn image detail hints được bỏ khi tạo sampling request. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal agent context, safety/verification, browser/GUI automation, evidence collection, tool-output validation.
- **Why it matters:** Nhiều agent workflow thực tế — browser automation, UI QA, screenshot-based debugging, visual diff — tạo evidence bằng ảnh. Nếu verifier/safety layer chỉ thấy text transcript thì decision có thể thiếu phần context quan trọng nhất.
- **Practical implication:** Với QA/browser agents, screenshot không nên chỉ là artifact cuối cùng; một bounded subset của ảnh gần đây có thể trở thành input cho verifier/guardian, nhưng cần policy rõ về privacy, retention và size limits.
- **Priority:** **Critical** cho multimodal/browser agents; **High** cho coding agents có screenshot/tool-image output.
- **Confirmed facts:** Setting là opt-in và mặc định `false`; commit lấy ảnh từ user/assistant messages và tool outputs, giữ tối đa 4 ảnh gần nhất, giới hạn 8 MiB tổng, và bỏ `detail` hints trước sampling.
- **Analysis:** Đây là pattern đáng chú ý: **evidence channels phải đi cùng verification channels**. Nếu executor nhìn thấy ảnh nhưng reviewer/guardian chỉ thấy text, hệ thống có asymmetric context và dễ đưa ra verdict sai.
- **Recommendation:** Với QA agent, browser agent hoặc incident agent, thiết kế `EvidenceEnvelope` chứa `text + screenshot/image + source + timestamp + hash + redaction status`; verifier chỉ nhận bounded evidence cần thiết.
- **Uncertainty:** Đây là Guardian v2 source-level behavior trên `main`; chưa có evidence public rằng stable Codex 0.147.0 đã ship feature này hoặc Guardian v2 là default path cho mọi user.

### 2. Multimodal context cần **budget và recency policy**, không phải gửi toàn bộ ảnh

- **One-sentence summary:** Codex không forward toàn bộ visual history mà dùng bounded recency: tối đa bốn ảnh gần nhất và 8 MiB tổng. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Context engineering, long-running agents, browser automation, cost/latency control.
- **Why it matters:** Ảnh có thể chiếm context/cost lớn và thường lặp lại giữa các bước; unlimited visual history dễ tăng latency mà không tăng decision quality.
- **Practical implication:** Multimodal agents nên có `visual evidence budget`, recency window, deduplication và escalation rule thay vì attach mọi screenshot.
- **Priority:** **High**.
- **Confirmed facts:** Commit dùng bounded queue cho ảnh và evict ảnh cũ khi vượt count/byte budget.
- **Analysis:** Đây là phiên bản multimodal của context compaction: giữ **evidence có giá trị cao nhất**, không giữ toàn bộ history.
- **Recommendation:** Test policy `latest state + failure screenshot + one pre-action screenshot`; deduplicate theo perceptual/file hash; chỉ escalate full-resolution evidence khi verifier không đủ confidence.
- **Uncertainty:** Commit không cung cấp benchmark về 4 ảnh/8 MiB là tối ưu cho mọi task.

- **Why it matters:** Khi reusable skills tăng, metadata discovery cạnh tranh trực tiếp token với requirements, code, evidence và conversation state.
- **Practical implication:** Skill catalog nên được coi là một **bounded retrieval surface** có budget, telemetry và routing regression tests riêng.
- **Priority:** **High**.
- **Confirmed facts:** Config là positive integer; value configured bị cap ở 10.000; default không set vẫn là 2% model context; tests cover parsing, override, cap và rendering under budget.
- **Analysis:** Context engineering nên quản lý allocation cho từng surface chứ không chỉ cố giảm tổng prompt length.
- **Recommendation:** Đo `correct skill selected`, `wrong skill`, `no skill`, input tokens, latency và task success ở nhiều catalog budgets.

- **Priority:** **Critical**.

- **Analysis:** Least privilege đáng tin cậy hơn khi enforce ngoài model thay vì viết trong prompt/rules.
- **Recommendation:** Model quyền như intersection: `Global ∩ Workspace ∩ Environment ∩ Task ∩ HumanApproval`.
- **Uncertainty:** Source-level change; stable binary chưa xác nhận ship behavior này.

- **Why it matters:** Build/test/package hooks có thể đọc process environment; leaked execution credential tạo quyền thật chứ không chỉ prompt leakage.
- **Practical implication:** .NET agent runner nên sanitize child-process environment **sau mọi merge/override** và ngay trước `Process.Start`.
- **Priority:** **Critical**.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Thêm **Visual Evidence Budget** bên cạnh Text/Skill Context Budget

- **Problem:** Browser/QA agents thường attach screenshot theo từng bước; nếu giữ tất cả, context phình nhanh và nhiều ảnh gần như giống nhau.
- **Proposed improvement:** Quản lý riêng visual context:
  - `max_images`
  - `max_total_bytes`
  - `recency_window`
  - `dedupe_hash`
  - `must_keep` cho failure evidence
  - `redaction_status`
- **Why it may work:** Codex Guardian v2 vừa implement bounded image transcript: max 4 recent images và 8 MiB. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** Playwright/Selenium QA agents, browser research agents, screenshot-based incident analysis, UI code review.
- **Limitations:** Recency không luôn tương đương relevance; ảnh quan trọng có thể cũ hơn bốn bước.
- **Risks:** Screenshot có PII, credentials, access tokens, internal dashboards hoặc customer data.
- **Recommendation:** Mặc định giữ `latest + failure + pre-action`; pin evidence quan trọng theo explicit reason; redact trước khi đưa vào secondary verifier/model.

### B. Tách **evidence metadata** khỏi evidence payload

- **Problem:** Một screenshot nếu không có provenance thì reviewer khó biết nó được chụp trước hay sau action nào, từ environment nào, và có bị chỉnh sửa không.
- **Proposed improvement:** Mỗi artifact có metadata:

```text
EvidenceId
SourceTool
CapturedAt
RunId / StepId
MimeType
Hash
RedactionStatus
RelatedAction
ExpectedState
ObservedState
```

- **Why it may work:** Guardian v2 lấy ảnh từ nhiều nguồn khác nhau — messages và tool outputs — nên source/provenance càng quan trọng.
- **Suitable use cases:** QA agents, code-review evidence, architecture diagrams, browser automation, incident response.
- **Limitations:** Tăng storage và implementation complexity.
- **Risks:** Metadata sai sẽ làm verifier tự tin sai.
- **Recommendation:** Evidence metadata phải do runtime/tool layer tạo, không để model tự khai báo.

### C. Treat Skill Catalog như bounded retrieval surface

- **Problem:** Skill metadata có thể lấn át task context khi skill library tăng.
- **Proposed improvement:** Giữ discovery metadata ngắn và benchmark nhiều budgets.
- **Why it may work:** Codex có explicit skill-catalog token budget và shared rendering budget. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Cursor Rules/Skills, Claude Code skills, Codex skills, internal skill registry.
- **Limitations:** Budget thấp có thể giảm routing recall.
- **Risks:** Teams tối ưu token nhưng làm routing quality giảm mà không biết.
- **Recommendation:** Benchmark `300/600/1200/2400` token budgets trên task corpus; đo routing recall, wrong-skill rate, task success, tokens và latency.

### D. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Một instruction file lớn thường trộn quyền, process và domain facts.
- **Proposed improvement:**
  - `policy/`: deny/approval/data rules
  - `skills/`: reusable procedures
  - `context/`: architecture/domain facts
  - `task/`: objective/acceptance criteria/current evidence
- **Why it may work:** Codex environment policy evidence cho thấy scope-specific policy nên compose rõ và lower layer chỉ restrict authority. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor, Claude Code, Codex, QA/research/review agents.
- **Limitations:** Cần deterministic precedence/loader.
- **Risks:** Duplicate/conflicting instructions.
- **Recommendation:** Precedence contract ngắn và machine-testable; context không được tự grant permission.

## 4. Agent, Workflow, and Loop Engineering

### A. `Execute → Capture Evidence → Verify` phải dùng cùng evidence surface

- **Problem:** Executor có thể nhìn screenshot/tool output nhưng verifier chỉ nhận text summary do executor tự viết.
- **Technique:** Verifier nhận original evidence hoặc bounded copy của original evidence, không chỉ narrative summary.
- **Expected benefit:** Giảm information loss và self-confirmation bias của executor.
- **Failure risks:** Cost tăng; visual evidence có thể leak sensitive data; verifier vẫn có thể hiểu sai ảnh.
- **Suitable use cases:** UI QA, browser agents, migration verification, deployment validation.
- **Confirmed facts:** Guardian v2 source mới có khả năng forward recent images từ messages/tool outputs vào sampling request. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Recommendation:** Reviewer agent phải độc lập về decision, nhưng chia sẻ original evidence với executor ở mức cần thiết.

### B. Evidence compaction nên dùng **recency + importance**, không chỉ recency

- **Problem:** “4 ảnh gần nhất” là bounded strategy tốt nhưng có thể mất failure screenshot cũ hơn.
- **Technique:** Giữ two-tier buffer:
  1. pinned evidence: failure/baseline/security-relevant
  2. rolling recent evidence
- **Expected benefit:** Bounded context nhưng không làm mất key evidence.
- **Failure risks:** Pin quá nhiều → context lại phình; pin sai → noisy evidence.
- **Suitable use cases:** Long-running QA/research/browser workflows.
- **Recommendation:** Runtime pin evidence dựa trên deterministic conditions (`test failed`, `state changed`, `approval requested`) trước khi cho model đề xuất pin bổ sung.

### C. Permission approvals phải invalidated khi policy thay đổi

- **Problem:** Saved approval có thể trở nên quá rộng sau khi runtime policy/config thay đổi.
- **Technique:** Approval key = action fingerprint + policy revision/fingerprint.
- **Expected benefit:** Không reuse authority cũ dưới policy mới.
- **Failure risks:** Approval prompts nhiều hơn nếu fingerprint quá nhạy.
- **Suitable use cases:** Shell commands, DB writes, deployments, file system mutations, MCP writes.
- **Confirmed facts:** Codex environment-policy fingerprint được đưa vào cached approval key. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Recommendation:** Với .NET orchestration, version `PermissionPolicy` và include version/hash trong approval record.

### D. Stop/re-plan dựa trên **failure signature**, không chỉ retry count

- **Problem:** Agent có thể retry ba lần nhưng mỗi lần fail vì nguyên nhân khác; hoặc retry nhiều lần cùng một lỗi mà không re-plan.
- **Technique:** Normalize failure signature theo stage/error class/state; cùng signature 2 lần → re-plan/root-cause mode.
- **Expected benefit:** Giảm low-value loops, phù hợp test-fix-retest.
- **Failure risks:** Signature quá coarse có thể gom nhầm failures.
- **Suitable use cases:** Selenium/Playwright, CI fixes, compilation, integration tests, MCP calls.
- **Recommendation:** Persist `FailureSignature`, attempted remediation, evidence và outcome trong `RunContext`.

### E. Long-running state không nên nằm trong transcript duy nhất

- **Problem:** Transcript compaction có thể mất decision, evidence hoặc progress state.
- **Technique:** Persist `Project → Run → Step → Artifact/Evidence → Decision/Checkpoint`.
- **Expected benefit:** Resume/fork/retry/audit rõ hơn.
- **Failure risks:** State schema drift và stale checkpoints.
- **Suitable use cases:** QA campaigns, research agents, interview intelligence, code-review pipelines.
- **Confirmed facts:** Codex Project APIs tách project association khỏi threads và hỗ trợ fork inheritance. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Recommendation:** Checkpoint chỉ lưu durable facts/decisions/evidence refs, không dump chain-of-thought/transcript.

- **Expected benefit:** Root-cause classification tốt hơn, giảm blind retry và tăng khả năng detect wrong UI state.
- **Effort:** **Half a day** cho một proof-of-concept.
- **Confirmed facts:** Codex Guardian v2 source-level design hiện forward recent message/tool-output images với bounded image context. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Uncertainty:** Lợi ích thực tế phải được đo bằng cùng failure corpus; không nên assume screenshot verifier luôn giảm failure rate.

## 7. Opportunities and Trends to Watch

### 1. **Multimodal governance**, không chỉ multimodal execution

- **What is changing:** Safety/verifier layers bắt đầu nhận visual evidence thay vì chỉ text transcript.
- **Why it matters:** UI/browser/computer-use agents cần evaluator nhìn thấy cùng state mà executor thấy.
- **Opportunity:** Xây reusable `Evidence Gateway` cho screenshot/image redaction, hashing, bounded retention và verifier routing.
- **Risk:** PII/secret leakage và cost tăng đáng kể nếu forward ảnh không kiểm soát.
- **Status:** **Early signal**.
- **Evidence:** Codex Guardian v2 image transcript support vừa merge trên `main`. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)

### 2. **Context budgets per surface** trở thành first-class config

- **What is changing:** Context không còn chỉ có một global window; sub-surfaces như skill catalog đang có explicit budget.
- **Why it matters:** Agent systems nhiều skills/tools/evidence phải trade off giữa discoverability, evidence fidelity, cost và latency.
- **Opportunity:** Context budget profiler/evaluator dùng chung cho Codex/Cursor/Claude/internal agents.
- **Risk:** Over-optimization token cost có thể làm accuracy giảm âm thầm.
- **Status:** **Growing**.

### 3. **Runtime-enforced policy composition** thay thế prompt-only permission rules

- **What is changing:** Policy layer có restrictive overlays, approval invalidation và child-process secret isolation.
- **Why it matters:** Model instructions không phải security boundary.
- **Opportunity:** .NET `AgentPolicyEngine` dùng cho filesystem/commands/DB/MCP/Git/deploy actions.
- **Risk:** Policy quá restrictive tạo approval fatigue hoặc block legitimate automation.
- **Status:** **Growing**.

### 4. **Durable agent state** tách khỏi transcript

- **What is changing:** Project/workspace APIs và explicit run/thread association tiếp tục xuất hiện trong agent runtimes.
- **Why it matters:** Long-running agent cần resume/fork/audit mà không phụ thuộc full chat history.
- **Opportunity:** Generic `AgentRunStore` cho project/run/checkpoint/evidence/artifact.
- **Risk:** Stale state, schema migration, replay consistency.
- **Status:** **Growing**.

### 5. **Native provider semantics** thay vì lowest-common-denominator compatibility

- **What is changing:** OpenCode source gần đây route OpenAI/Anthropic qua native passthrough trong Cloudflare AI Gateway path. [OpenCode commit](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Why it matters:** Generic adapters có thể flatten reasoning/tool/streaming semantics.
- **Opportunity:** Provider capability registry + native adapters trong .NET agent runtime.
- **Risk:** Adapter complexity và test matrix tăng.
- **Status:** **Growing**.
