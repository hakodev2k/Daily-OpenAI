## 3. Prompt, Skills, Rules, and Context Engineering

### A. Vấn đề: instruction artifact đang bị trộn policy, procedure và runtime capability

- **Problem:** Một file `AGENTS.md`, `.cursorrules`, `CLAUDE.md` hoặc prompt lớn thường trộn coding standards, security constraints, workflow steps, tool assumptions và model limits. Khi runtime/version đổi, instruction dễ stale mà không ai biết.
- **Proposed improvement:** Tách thành 4 lớp:
  1. **Policy:** invariant constraints — security, architecture boundaries, forbidden actions.
  2. **Skill:** procedural capability — review EF Core query, debug Hangfire job, design migration, run QA regression.
  3. **Runtime capability manifest:** tool/model/version/limits/MCP availability.
  4. **Task context:** goal, scope, acceptance criteria, evidence, current state.
- **Why it may work:** Codex source changes hôm nay cho thấy runtime policy và capability có lifecycle riêng; OpenCode context-limit fix cho thấy model metadata cũng có thể thay đổi theo access path. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929) · [OpenCode #39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Suitable use cases:** Cursor Rules + Skills, Claude Code Skills, Codex AGENTS/Skills, .NET architecture agents, code review agents.
- **Limitations:** Tách quá nhỏ có thể tăng discovery overhead; cần naming và trigger rõ.
- **Risks:** Capability manifest stale hoặc skill tự assume tool tồn tại vẫn gây failure.
- **Recommendation:** Mỗi skill nên có `requires`, `forbids`, `inputs`, `outputs`, `verification`, `failure behavior`.

### B. Vấn đề: inherited context dễ mang theo assumption sai

- **Problem:** Fork/subagent hoặc long-running thread có lợi về continuity nhưng cũng copy hidden assumptions, stale facts và temporary decisions.
- **Proposed improvement:** Trước khi handoff/fork, tạo structured context packet:
  - `Facts`
  - `Evidence`
  - `Assumptions`
  - `Open questions`
  - `Decisions`
  - `Rejected options`
  - `Next objective`
  - `Verification required`
- **Why it may work:** Structured state giúp downstream agent biết cái gì là evidence và cái gì chỉ là inference; điều này giảm “transcript authority”.
- **Suitable use cases:** Research agents, architecture review, interview intelligence, incident RCA, multi-agent QA.
- **Limitations:** Tốn thêm token và implementation effort.
- **Risks:** Nếu packet được tạo bởi cùng agent mà không verifier, nó có thể tóm tắt sai.
- **Recommendation:** Với high-impact handoff, verifier chỉ kiểm tra packet so với artifacts/source, không “review cảm tính”.

### C. Vấn đề: context budgeting dựa trên model name đơn thuần

- **Problem:** Prompt pipeline thường map `model → context window`, nhưng OpenCode fix hôm nay cho thấy access path có thể thay đổi giới hạn được harness áp dụng. [OpenCode #39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Proposed improvement:** Dùng capability registry có key `(provider, model, access_path, tool_version)` và metadata `context`, `max_input`, `max_output`, `supports_tools`, `supports_reasoning`, `supports_images`, `updated_at`, `source`.
- **Why it may work:** Compaction/truncation quyết định từ evidence runtime thay vì assumption.
- **Suitable use cases:** Long-running research, codebase-scale analysis, multi-model routing.
- **Limitations:** Capability discovery không phải vendor nào cũng expose đầy đủ.
- **Risks:** Registry stale vẫn tạo lỗi; cần fallback margin.
- **Recommendation:** Giữ 10–20% safety buffer và record compaction reason trong run trace.

## 4. Agent, Workflow, and Loop Engineering

### A. Permission-aware execution loop

- **Problem:** Agent có thể retry cùng command dù environment policy đã đổi hoặc approval cũ không còn hợp lệ.
- **Technique:** Mỗi tool execution đi qua pipeline:
  `Intent → Policy evaluation → Approval state → Execute → Observe → Verify → Persist decision`.
  Approval cache phải key theo policy fingerprint, environment, tool và scope.
- **Expected benefit:** Giảm accidental privilege reuse và behavior khó giải thích.
- **Failure risks:** Cache key thiếu dimension; policy layer conflict; approval prompt storm.
- **Suitable use cases:** Codex-like agent runtime, CI agent, deployment agent, QA agent có browser/CLI/MCP tools.
- **Evidence:** Codex #38942 explicitly invalidates cached approvals khi environment policy fingerprint thay đổi. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### B. Secret-safe subprocess loop

- **Problem:** Agent có thể gọi command/hooks với environment chứa control-plane secrets.
- **Technique:** `Build env → merge overrides → remove non-inheritable vars → optional allowlist → spawn → redact logs`.
- **Expected benefit:** Giảm credential exposure từ build scripts/dependencies/hooks.
- **Failure risks:** Secret được truyền qua file, command-line arg hoặc inherited credential store vẫn có thể leak.
- **Suitable use cases:** Playwright QA runner, `dotnet test`, `npm`, migration scripts, Git hooks, command hooks.
- **Evidence:** Codex #38941 implements non-inheritable environment scrubbing cho shell và hooks. [Source](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)

### C. Project-scoped long-running agent state

- **Problem:** Nếu một conversation chứa toàn bộ state, resume/fork/archive/replay rất khó và context ngày càng phình.
- **Technique:** Dùng state hierarchy:
  `Project → Run → Step → Artifact`, với checkpoints và explicit relationships.
- **Expected benefit:** Resume/fork/replay tốt hơn, context nhỏ hơn, audit rõ hơn.
- **Failure risks:** State synchronization, orphan artifacts, migration complexity.
- **Suitable use cases:** QA batches, research pipelines, interview graph generation, knowledge transfer, architecture analysis.
- **Evidence:** Codex experimental Project APIs tách project identity khỏi thread và hỗ trợ fork inheritance. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

### D. Stop-condition trước retry

- **Problem:** Agent loop dễ rơi vào `run → fail → tweak → run` không có learning signal.
- **Technique:** Sau 2 failure cùng signature, bắt buộc branch sang `RootCauseAnalysis`; sau 3 lần không tăng evidence, stop và request human/alternate strategy.
- **Expected benefit:** Giảm low-value loops, token/time waste và destructive repeated actions.
- **Failure risks:** Signature grouping quá thô có thể stop sớm.
- **Suitable use cases:** CI repair, Selenium/Playwright flaky tests, dependency setup, migration/debug agents.
- **Recommendation:** Track `failure_signature`, `new_evidence_count`, `attempt`, `strategy_id`, `state_delta`.

### E. Deterministic verifier tách khỏi generator

- **Problem:** LLM tự đánh giá output của chính nó dễ bias và có thể “pass” vì explanation nghe hợp lý.
- **Technique:** Generator tạo change; verifier chạy compiler/tests/schema/security checks; LLM judge chỉ dùng cho tiêu chí subjective sau deterministic checks.
- **Expected benefit:** Reliability cao hơn và regression dễ đo.
- **Failure risks:** Test suite kém vẫn pass code sai.
- **Suitable use cases:** Code review agent, QA agent, refactoring agent, prompt evaluation.
- **Recommendation:** Acceptance order: `build → tests → static checks → domain invariants → LLM review`.

## 5. Hooks and Integrations

### 1. Cursor hooks → deterministic verification gate

- **What can be integrated:** `afterAgentResponse`, `stop`, `subagentStart`, `beforeSubmitPrompt` và related hooks từ Cursor. [Cursor changelog](https://cursor.com/changelog)
- **Workflow benefit:** Có thể auto-run tests/lint/security checks, inject state hoặc block stop khi acceptance criteria chưa đạt.
- **Security/permission concerns:** Hook command cũng là execution boundary; không truyền secrets không cần thiết và giới hạn filesystem/network access.
- **Difficulty:** **Moderate**.
- **Recommendation:** Bắt đầu bằng one-way verifier hook: agent không được tự sửa verifier result.

### 2. MCP + ASP.NET Core → policy-enforced tool gateway

- **What can be integrated:** MCP tools vào ASP.NET Core service, kết hợp identity, tool allowlist, audit log và environment policy.
- **Workflow benefit:** Research/code/QA agents dùng chung tool contract; business policy nằm ngoài prompt.
- **Security/permission concerns:** Authentication, authorization per tool, argument validation, outbound network policy, secret redaction.
- **Difficulty:** **Moderate → Advanced**.
- **Recommendation:** Tool write operations cần explicit scope; production mutation cần approval token có expiry.

### 3. Teams/Slack → human approval surface

- **What can be integrated:** Agent run gửi decision card/request approval vào Teams/Slack; approval trả về một short-lived signed decision token.
- **Workflow benefit:** Human-in-the-loop không buộc người dùng quay lại IDE/agent UI.
- **Security/permission concerns:** Mapping user identity, replay prevention, approval scope, expiry, audit.
- **Difficulty:** **Advanced**.
- **Recommendation:** Approval payload phải chứa `runId`, `action`, `resource`, `policyHash`, `expiresAt`; không dùng “Approve” generic cho mọi hành động.

### 4. Cloudflare AI Gateway / custom gateway → native provider routing

- **What can be integrated:** Route/OpenTelemetry/billing/cache ở gateway nhưng giữ native OpenAI Responses / Anthropic Messages khi capability cần thiết. [OpenCode #42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Workflow benefit:** Central governance mà không mất provider-specific semantics.
- **Security/permission concerns:** BYOK secret isolation, header stripping, tenant separation, request/response redaction.
- **Difficulty:** **Advanced**.
- **Recommendation:** Viết conformance tests cho từng provider path thay vì assume “OpenAI-compatible = equivalent”.

### 5. GitHub Actions → agent regression harness

- **What can be integrated:** Chạy cùng task set trên stable/prerelease/tool versions và lưu JSON metrics/artifacts.
- **Workflow benefit:** Phát hiện behavior regression trước khi update local/team default.
- **Security/permission concerns:** Giới hạn token, tránh chạy agent với write permission trên untrusted PR, không expose repository secrets cho arbitrary code.
- **Difficulty:** **Moderate**.
- **Recommendation:** Với PR từ fork/untrusted input, agent evaluation nên read-only và không có production credentials.

## 7. Opportunities and Trends to Watch

### 1. Permission model đang dịch từ prompt instruction sang runtime policy

- **What is changing:** Codex source cho thấy environment-specific restrictive policy và approval cache bound với policy fingerprint. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Why it matters:** Prompt không phải security boundary; runtime policy mới có thể enforce.
- **Opportunity:** Xây reusable policy engine cho agent runtimes .NET/MCP.
- **Risk:** Overcomplicated policy UX gây permission fatigue hoặc block legitimate work.
- **Status:** **Growing**.

### 2. Agent memory đang tiến từ transcript sang structured project/run state

- **What is changing:** Project APIs, thread assignment, artifacts/checkpoints và fork inheritance trở thành primitive ngày càng rõ. [Codex #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Why it matters:** Transcript dài không scale cho long-running/multi-agent systems.
- **Opportunity:** Build project-centric agent orchestration layer hoặc knowledge-transfer store.
- **Risk:** State model quá phức tạp tạo migration/sync issues.
- **Status:** **Growing**.

### 3. Gateway abstraction đang dịch sang “unified governance, native semantics”

- **What is changing:** OpenCode route OpenAI/Anthropic qua native provider protocol ngay cả khi đi qua Cloudflare AI Gateway. [OpenCode #42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Why it matters:** Lowest-common-denominator API dễ mất reasoning/tool/provider features.
- **Opportunity:** .NET AI gateway có provider-native adapters, unified policy/telemetry layer.
- **Risk:** Tăng implementation/test matrix.
- **Status:** **Growing**.

### 4. Capability-by-version/access-path sẽ trở thành bắt buộc cho reliable agent systems

- **What is changing:** Source/main, prerelease/stable và subscription/API path có thể có behavior/limits khác nhau.
- **Why it matters:** Agent workflow không thể giả định “model name + vendor” đủ mô tả runtime.
- **Opportunity:** Capability registry + auto-probe + version-aware regression testing.
- **Risk:** Metadata stale hoặc probe không đầy đủ.
- **Status:** **Established** như nhu cầu, **Early signal** về standardization.

### 5. “Agent benchmark” đang dịch từ model benchmark sang harness/workflow benchmark

- **What is changing:** Sự khác biệt ngày càng đến từ tools, policy, context, gateway, version và verifier — không chỉ model weights.
- **Why it matters:** Một model mạnh trong benchmark chung có thể không tốt hơn trong workflow cụ thể nếu harness kém hoặc tool integration khác.
- **Opportunity:** Xây internal engineering benchmark theo task thực tế.
- **Risk:** Benchmark nhỏ dễ overfit; LLM judge-only dễ bias.
- **Status:** **Growing**.
