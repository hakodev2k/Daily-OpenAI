## 1. Executive Summary

### 1. Guardian v2 đưa **visual evidence** vào verifier/safety transcript

- **One-sentence summary:** Codex `main` thêm `features.guardianv2.transcript.include_images`, cho phép Guardian v2 nhận ảnh gần đây từ user/assistant messages và configured tool outputs; visual context bị giới hạn ở **4 ảnh gần nhất** và **8 MiB tổng**, đồng thời bỏ `detail` hint trước sampling. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal QA, browser agents, verifier/safety pipelines, evidence collection.
- **Why it matters:** Browser/UI agents có thể quyết định dựa trên screenshot; nếu executor thấy ảnh nhưng reviewer/verifier chỉ thấy text thì hệ thống có **asymmetric context** và có thể đưa verdict sai.
- **Practical implication:** Screenshot nên là first-class evidence có provenance, timestamp, hash, redaction metadata; verifier chỉ nhận bounded subset phù hợp.
- **Priority:** **Critical** cho browser/UI agents; **High** cho coding agents có image-bearing tool outputs.
- **Confirmed facts:** Setting opt-in, mặc định `false`; ảnh có thể đến từ user, assistant và tool outputs; tối đa 4 ảnh và 8 MiB tổng; tests cover config parsing và forwarding. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Analysis:** Verification channel nên nhận cùng evidence classes mà execution channel đã dùng; nếu không, reviewer có thể đánh giá một trạng thái khác với trạng thái mà executor thực sự thấy.
- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }` cho QA/browser/review agents.
- **Uncertainty:** Chưa có evidence public rằng stable Codex `0.147.0` đã ship behavior này hoặc Guardian v2 là default path cho hosted Codex.

### 2. Multimodal context cần **budget, recency, deduplication và redaction**

- **One-sentence summary:** Codex bounded visual transcript theo số lượng ảnh và tổng bytes thay vì forward toàn bộ visual history. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Context engineering, browser automation, long-running agents, latency/cost control.
- **Why it matters:** UI automation có thể tạo nhiều screenshot gần giống nhau; gửi tất cả tăng payload nhưng không chắc tăng correctness.
- **Practical implication:** Nên có `VisualEvidenceBudget`, recency policy, dedupe bằng hash và privacy redaction trước verifier.
- **Priority:** **High**.
- **Confirmed facts:** Implementation dùng bounded queue và loại ảnh cũ khi vượt count/byte budget.
- **Analysis:** Đây là multimodal equivalent của context compaction: giữ evidence đủ để quyết định, không giữ lịch sử vô hạn.
- **Recommendation:** Benchmark `latest-only`, `latest+failure`, `latest+failure+pre-action`; đo verifier accuracy, latency, payload size và false verdict rate.
- **Uncertainty:** 4 ảnh/8 MiB là implementation choice, chưa có benchmark chứng minh tối ưu cho mọi workflow.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **Text Context Budget** và **Visual Evidence Budget**

- **Problem:** Agent thường gom text, screenshots và tool artifacts vào cùng một context bucket, khó biết lớp nào gây cost/latency.
- **Proposed improvement:** Theo dõi riêng `text_tokens`, `skill_catalog_tokens`, `tool_result_tokens`, `image_count`, `image_bytes`, `evidence_priority`.
- **Why it may work:** Codex hiện quản lý riêng skill-catalog tokens và Guardian image bytes/count, cho thấy context surfaces có thể có budget độc lập. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Image transcript](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** QA browser agents, incident analysis, code review agents có screenshots, research agents có diagrams/images.
- **Limitations:** Không có một budget tối ưu chung cho mọi model/provider.
- **Risks:** Cắt evidence quá mạnh có thể giảm correctness; giữ quá nhiều tăng latency/cost.

### B. Skill metadata nên phục vụ **routing**, không chứa full procedure

- **Problem:** Description dài làm catalog phình nhanh và tiêu token trước khi skill thật sự cần được dùng.
- **Proposed improvement:** Discovery layer chỉ giữ `name`, `trigger`, `expected outcome`, `exclusions`, `cost class`; procedure/examples/scripts load sau routing.
- **Why it may work:** Bounded catalog budget tạo incentive cho progressive disclosure thay vì eager injection.
- **Suitable use cases:** Cursor rules/skills, Codex skills, Claude reusable workflows, role-based agent kits.
- **Limitations:** Metadata quá ngắn có thể làm giảm routing recall.
- **Risks:** Router chọn sai skill nếu triggers overlap.
- **Test method:** 50–100 labeled tasks; đo precision/recall của skill selection ở catalog budgets khác nhau.

### C. Rules phải tách **policy** khỏi **procedure**

- **Problem:** Một file instructions khổng lồ thường trộn “được phép làm gì” với “làm thế nào”, khiến runtime policy khó audit.
- **Proposed improvement:** Tách:
  1. `Policy`: hard constraints, permissions, stop conditions.
  2. `Skill/Procedure`: steps, commands, heuristics.
  3. `Task Context`: yêu cầu hiện tại.
  4. `Evidence`: facts/logs/diffs/screenshots.
- **Why it may work:** Restrictive environment policy của Codex cho thấy policy đáng tin cậy nên được enforce ở runtime layer thay vì chỉ mô tả bằng natural language. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** QA agents, deployment agents, GitHub/CI agents, architecture agents.
- **Limitations:** Cần thêm cấu trúc/configuration management.
- **Risks:** Policy và procedure drift nếu không version cùng nhau.

## 4. Agent, Workflow, and Loop Engineering

### A. **Executor–Verifier Symmetry** cho multimodal workflows

- **Problem:** Executor thấy screenshot nhưng verifier chỉ nhận textual summary.
- **Technique:** Cho verifier access tới bounded, redacted evidence subset từ cùng `EvidenceEnvelope` mà executor dùng.
- **Expected benefit:** Giảm false pass/false fail do reviewer thiếu visual state.
- **Failure risks:** Leak PII/secrets trong screenshot; duplicated images; stale evidence.
- **Suitable use cases:** Playwright/Selenium QA agents, incident agents, UI code review, browser research.
- **Concrete evaluation:** Chạy cùng 30 failure cases với verifier text-only vs text+bounded-images; đo verdict agreement với human labels, latency và image payload.

### B. **Stop conditions** phải explicit để tránh low-value loops

- **Problem:** Agent retry cùng action hoặc research cùng nguồn dù state không thay đổi.
- **Technique:** Mỗi loop có `max_attempts`, `same_error_signature_threshold`, `no_new_evidence_threshold`, `deadline`, `escalation_reason`.
- **Expected benefit:** Giảm token/tool churn và làm failure recovery có cấu trúc.
- **Failure risks:** Stop quá sớm ở transient failures.
- **Suitable use cases:** Test-fix-retest, web research, CI remediation, browser automation.
- **Recommendation:** Sau 2 lần cùng error signature và không có evidence mới → `REPLAN`; sau replan vẫn cùng signature → `ESCALATE`.

### C. **Project → Run → Evidence** thay transcript-centric memory

- **Problem:** Transcript dài khó resume và khó audit.
- **Technique:** Durable state ở project/run records; transcript chỉ là một view.
- **Expected benefit:** Resume/fork/retry rõ ràng, dễ tạo regression corpus.
- **Failure risks:** State duplication; stale project metadata.
- **Suitable use cases:** QA campaign, interview knowledge pipeline, research dossier, architecture review.
- **Recommendation:** Mỗi run lưu `goal`, `inputs`, `assumptions`, `decisions`, `evidence refs`, `result`, `failure reason`, `next checkpoint`.

### D. Approval cache phải **policy-aware**

- **Problem:** Approval “yes” có thể bị reuse sau khi environment/policy đã đổi.
- **Technique:** Key approval bằng `(action fingerprint, policy revision, environment revision, target resource)`.
- **Expected benefit:** Không reuse quyền cũ dưới policy mới.
- **Failure risks:** Quá nhiều approval prompts nếu fingerprint quá chi tiết.
- **Suitable use cases:** Git, deployment, DB mutation, filesystem writes, external API actions.

## 7. Opportunities and Trends to Watch

### 1. **Multimodal verifier/safety pipelines**
- **What is changing:** Verification layer bắt đầu nhận image evidence thay vì chỉ text.
- **Why it matters:** Browser/UI agents cần reviewer thấy cùng state với executor.
- **Opportunity:** Build reusable `EvidenceEnvelope`, image dedupe/redaction, multimodal regression harness.
- **Risk:** Privacy, cost, stale screenshots, unsupported image semantics.
- **Status:** **Growing**.

### 2. **Context budgets theo từng surface**
- **What is changing:** Skill catalog và visual transcript đều có bounded budget riêng.
- **Why it matters:** “Context window lớn” không loại bỏ nhu cầu allocation.
- **Opportunity:** Context telemetry, budget optimizer, routing benchmark tooling.
- **Risk:** Over-tuning budget cho một model/task distribution.
- **Status:** **Growing**.

### 3. **Runtime-enforced permission narrowing**
- **What is changing:** Agent frameworks ngày càng đưa policy enforcement ra khỏi prompt layer.
- **Why it matters:** Prompt rule không phải security boundary.
- **Opportunity:** Policy-as-code cho agent tools, approval fingerprinting, environment-specific restrictions.
