## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách “policy” khỏi “instructions” để giảm prompt-level security assumptions

- **Problem:** Rules/skills thường chứa cả coding convention lẫn permission constraints như “không deploy”, “không xóa file”, “chỉ read-only”. Model có thể hiểu sai hoặc instruction có thể bị context pressure.
- **Proposed improvement:** Phân tầng:
  - `Rules/AGENTS.md`: coding conventions, repository knowledge, quality expectations.
  - `Skills`: reusable procedures và workflow steps.
  - `Runtime Policy`: deny/approval/network/filesystem/command restrictions.
  - `Verifier`: deterministic checks sau execution.
- **Why it may work:** Codex environment policy cho thấy authority có thể được enforce ngoài prompt; đây là stronger guarantee hơn natural-language instruction. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** QA agents, code review agents, research agents, deployment workflows, enterprise coding agents.
- **Limitations:** Cần runtime/harness hỗ trợ policy; chỉ viết schema nhưng không enforce thì không có security benefit.
- **Risks:** Policy quá restrictive làm agent thất bại giả; cần observability để biết failure do model hay policy.
- **Recommendation:** Mỗi rule nên được classify `Knowledge | Procedure | Policy | Validator`. Policy quan trọng không để tồn tại duy nhất trong prompt.

### B. Context handoff nên là structured state, không phải transcript dump

- **Problem:** Long-running agents dễ mang theo nhiều historical turns không còn relevant, gây context bloat và conflict.
- **Proposed improvement:** Handoff artifact gồm:
  - `Goal`
  - `Facts + evidence`
  - `Assumptions`
  - `Decisions + rationale`
  - `Current state`
  - `Failed attempts`
  - `Remaining risks/gaps`
  - `Next action`
  - `Tool/version/capability snapshot`
- **Why it may work:** Codex experimental Project APIs tách project identity khỏi individual thread, cho thấy state container và conversation instance là hai khái niệm riêng. [Codex #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Suitable use cases:** Research agent, interview intelligence, QA batches, architecture planning, knowledge-transfer systems.
- **Limitations:** Structured summaries có thể bỏ mất nuance nếu không giữ source references.
- **Risks:** Agent tự summarize sai rồi propagate error.
- **Recommendation:** Facts phải link evidence; assumptions phải có status `Unverified`; decisions giữ rationale và reversal condition.

### C. Model capability registry phải trở thành một phần của context engineering

- **Problem:** Prompt budget thường dựa vào model name, nhưng effective context có thể phụ thuộc access path/harness.
- **Proposed improvement:** Registry có:
  - `model_id`
  - `provider/access_path`
  - `context_limit`
  - `input_limit`
  - `output_limit`
  - supported tools/features
  - source URL
  - last_verified_at
- **Why it may work:** OpenCode vừa phải sửa GPT-5.6 limits theo ChatGPT subscription path. [OpenCode #39082](https://github.com/anomalyco/opencode/commit/4d68d30b48a99379b2baaf597dbad576707ea36d)
- **Suitable use cases:** Multi-model agents, long context research, codebase analysis, RAG, auto-compaction.
- **Limitations:** Capability data vẫn có thể stale.
- **Risks:** Sai registry dẫn đến false confidence.
- **Recommendation:** Add runtime sanity check và metrics `tokens_before_compaction`, `compaction_count`, `context_overflow_error`.

## 4. Agent, Workflow, and Loop Engineering

### A. Stop-condition cho research/update loops

- **Problem:** Agent có thể tiếp tục search/changelog polling dù không có new evidence.
- **Technique:** `NoMaterialDeltaStopCondition`:
  1. Check primary sources.
  2. Deduplicate against prior run.
  3. Nếu không có release/commit/security/benchmark delta → stop research.
  4. Chuyển sang validation/action synthesis.
- **Expected benefit:** Giảm token/time, giảm repeated content, tăng actionability.
- **Failure risks:** Có thể miss hosted/closed-source update.
- **Suitable use cases:** Daily briefings, dependency radar, security monitoring, release watchers.
- **Recommendation:** Log reason: `NO_NEW_PRIMARY_SOURCE_EVIDENCE` thay vì tiếp tục mở thêm sources tương tự.

### B. Policy-aware approval cache

- **Problem:** Approval cũ có thể không còn hợp lệ khi task/environment policy thay đổi.
- **Technique:** Cache key nên include `policy_fingerprint`, environment id, command/tool identity và relevant scope.
- **Expected benefit:** Không reuse quyền được approve trong context cũ khi authority đã thay đổi.
- **Failure risks:** Cache miss nhiều hơn; UX có thể nhiều approval prompt.
- **Suitable use cases:** Shell execution, production tools, database writes, deployment, external APIs.
- **Evidence:** Codex vừa thêm policy fingerprint vào approval keys. [Codex #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Recommendation:** Với custom agent, approval record nên có `Subject + Action + Resource + PolicyRevision + ExpiresAt`.

### C. Secret-safe subprocess loop

- **Problem:** Tool/script loop có thể vô tình inherit control-plane secrets.
- **Technique:** `BuildFinalEnv → Merge allowed overrides → Scrub sensitive keys → Spawn → Verify no secret leakage`.
- **Expected benefit:** Giảm blast radius khi package/script/hook bị compromise.
- **Failure risks:** Denylist không đầy đủ; child process vẫn đọc secret từ file/socket/credential manager.
- **Suitable use cases:** Build/test, Playwright, Git hooks, shell tools, package managers.
- **Evidence:** Codex fix và tests cho shell/hooks. [Codex #38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Recommendation:** Prefer allowlist cho high-risk production runners; denylist cho developer workstation phải có tests.

### D. `Project → Run → Step → Artifact` thay vì “one giant conversation”

- **Problem:** Agent memory/state gắn chặt vào conversation khiến resume/fork/audit khó.
- **Technique:** Persistent project/workspace chứa multiple runs; run chứa steps/tool calls; artifacts tồn tại độc lập.
- **Expected benefit:** Resume, fork, audit, compare runs, context pruning tốt hơn.
- **Failure risks:** Schema phức tạp hơn; cần garbage collection/versioning.
- **Suitable use cases:** QA agent, interview agent, research pipeline, code review agent, architecture knowledge base.
- **Evidence:** Codex app-server experimental Project APIs và thread-project assignment. [Codex #38940](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Recommendation:** Không tight-couple production schema theo Codex experimental API; chỉ reuse design principle.

## 5. Hooks and Integrations

### 1. .NET process runner + secret scrubbing

- **Can integrate:** `ProcessStartInfo`, custom command hooks, Playwright/CLI/test tools.
- **Workflow benefit:** Cho agent chạy build/test/tool mà không lộ control-plane credentials.
- **Security concerns:** Windows env names case-insensitive; scrub phải chạy sau overrides; secret có thể còn qua files/arguments/stdin.
- **Difficulty:** **Moderate**.
- **Recommended pattern:** `SensitiveEnvironmentVariableRegistry` + integration tests spawn child process in Windows/Linux.

### 2. MCP gateway + policy layer

- **Can integrate:** ASP.NET Core MCP server, API gateway, identity/policy service, Azure-hosted tools.
- **Workflow benefit:** Model request tool; gateway quyết định authorization; audit trail tách khỏi prompt.
- **Security concerns:** Tool arguments có thể chứa PII/secrets; cần redaction; step-up approval cho high-impact actions.
- **Difficulty:** **Advanced**.
- **Recommendation:** Map policy theo `client identity + agent role + tool + resource + environment`.

### 3. Teams/Slack approval bridge

- **Can integrate:** Agent emits pending action → Teams/Slack adaptive message → human approve/reject → resume run.
- **Workflow benefit:** Human approval trở thành explicit workflow state thay vì chờ chat transcript.
- **Security concerns:** Verify approver identity, expiration, replay protection, signed correlation id; không cho message text tự quyết định authority.
- **Difficulty:** **Advanced**.
- **Recommendation:** Approval token bound to exact action hash/policy revision.

### 4. Model gateway giữ native provider protocol

- **Can integrate:** OpenAI Responses API, Anthropic Messages API, gateway/routing/telemetry layer.
- **Workflow benefit:** Unified governance nhưng giữ provider-specific reasoning/tool semantics.
- **Security concerns:** BYOK/token routing, logging, tenant isolation, accidental credential forwarding.
- **Difficulty:** **Advanced**.
- **Evidence:** OpenCode native passthrough design. [OpenCode #42634](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)

## 7. Opportunities and Trends to Watch

### Trend 1. Runtime policy đang trở thành first-class agent primitive

- **What is changing:** Coding agents ngày càng đưa permission, sandbox, command policy và approval logic xuống runtime thay vì chỉ prompt.
- **Why it matters:** Authority cần enforce bằng code/policy engine, không thể dựa hoàn toàn vào LLM compliance.
- **Opportunity:** Xây vendor-neutral `Agent Policy Engine` cho local/.NET workflows.
- **Risk:** UX quá restrictive, policy complexity, false denials.
- **Status:** **Growing**.

### Trend 2. Agent state đang tách khỏi chat/session identity

- **What is changing:** Project/workspace/run concepts ngày càng rõ; conversation chỉ là một view/execution thread.
- **Why it matters:** Long-running agents cần durable state, checkpoints, fork/resume và artifacts.
- **Opportunity:** Framework/schema chung cho QA/research/interview agents.
- **Risk:** Over-engineering cho task ngắn.
- **Status:** **Growing**.

### Trend 3. Gateway abstraction nhưng không flatten provider protocol

- **What is changing:** Routing/telemetry/governance được unify trong gateway, nhưng OpenAI/Anthropic native APIs vẫn được giữ cho provider-specific features.
- **Why it matters:** Lowest-common-denominator abstraction có thể làm mất reasoning/tools semantics.
- **Opportunity:** .NET gateway/harness có capability-aware adapter layer.
- **Risk:** Complexity tăng, testing matrix lớn hơn.
- **Status:** **Growing**.

### Trend 4. Version/capability provenance trở thành requirement cho agent evaluation

- **What is changing:** Tool source/main, prerelease, stable và hosted product có thể lệch nhau; model capabilities phụ thuộc access path.
- **Why it matters:** Không có provenance thì benchmark/regression khó reproducible.
- **Opportunity:** `AgentRunManifest` + capability registry + automated regression dashboard.
- **Risk:** Metadata overhead nếu capture quá nhiều nhưng không dùng.
- **Status:** **Established** về principle, **Growing** trong agent tooling.

### Trend 5. “No new evidence” cần trở thành explicit outcome của research agents

- **What is changing:** High-quality agents cần biết dừng và báo no-delta thay vì fill output bằng repeated/weak sources.
- **Why it matters:** Reliability không chỉ là tìm đúng thông tin mà còn là không bịa “update” khi không có.
- **Opportunity:** Stop-condition/evidence-threshold component dùng chung cho daily radars.
- **Risk:** Stop quá sớm nếu source coverage kém.
- **Status:** **Growing**.
