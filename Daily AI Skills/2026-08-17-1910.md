## 1. Executive Summary

### 1. Guardian v2 defaults chuyển safety/review behavior sang **model-aware capability metadata**

- **One-sentence summary:** Codex `main` thêm `guardian_v2` defaults vào model catalog cho classifier instructions, review threshold, reasoning effort, transcript sources/limits và action/compaction token limits; explicit local `[features.guardianv2]` vẫn override catalog values. [Codex #38990, 17/08/2026](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Affected skill area:** Agent safety, review agents, capability discovery, config layering, evaluation reproducibility.
- **Why it matters:** Cùng một workflow nhưng khác model có thể cần review threshold, reasoning effort hoặc transcript budget khác nhau. Hard-code một bộ defaults toàn cục làm tăng nguy cơ tuning sai theo model family.
- **Practical implication:** Agent runtime nên resolve behavior từ **capability/config stack** thay vì chỉ model name + prompt.
- **Priority:** **Critical** cho agent platform; **High** cho coding agents cá nhân.
- **Confirmed facts:** Model catalog có thể cung cấp classifier prompt, threshold theo basis points, reasoning effort, transcript source/limits, action-token limit, classifier-instruction-token limit và parent-compaction-token limit; local overrides có precedence. Tests cover serialization, model overrides và local-override precedence. [Source](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Analysis:** Model identity đang trở thành một **capability profile**, không chỉ là tên endpoint. Agent frameworks cần biết model-specific review, context, tool và transport behavior.
- **Recommendation:** Tạo `ModelCapabilityProfile` gồm `context`, `tooling`, `permissions`, `review`, `multimodal`, `tokenBudgets`, `transport`, `sourceVersion`; persist resolved profile vào mỗi run.
- **Uncertainty:** Đây là source-level design trên Codex `main`; chưa có evidence public rằng stable `0.147.0` hoặc mọi hosted Codex session đang dùng mechanism này.

### 2. Config precedence đã trở thành **correctness concern**, không chỉ là configuration hygiene

- **One-sentence summary:** Guardian v2 resolve model defaults nhưng vẫn giữ local config là lớp override, và model overrides phải preserve catalog configuration mới. [Codex #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Affected skill area:** Rules, reusable instructions, model routing, policy debugging.
- **Why it matters:** Khi hệ thống có global defaults, model defaults, repo rules, environment restrictions, user overrides và per-task values, bug có thể xuất hiện từ **precedence order** dù từng config riêng lẻ đều đúng.
- **Practical implication:** Mỗi effective setting nên có provenance: `value`, `source`, `sourceVersion`, `resolvedAt`, `overriddenBy`.
- **Priority:** **High**.
- **Confirmed facts:** Codex chỉ lấy model default khi local field tương ứng chưa set; local Guardian config được giữ để re-resolve khi model context thay đổi. [Source](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Analysis:** Config resolution nên là deterministic function có test matrix và explainability, thay vì logic rải rác trong prompt/runtime.
- **Recommendation:** Thêm debug command kiểu `agent config explain` hiển thị final effective config và nguồn của từng value.
- **Uncertainty:** Chưa có benchmark public về overhead vận hành của model-owned defaults ở quy mô lớn.

### 3. Guardian v2 bắt đầu nhận **visual evidence** từ transcript và tool outputs

- **One-sentence summary:** Codex `main` có opt-in `features.guardianv2.transcript.include_images`, lấy ảnh từ user/assistant messages và configured tool outputs, giới hạn tối đa 4 ảnh gần nhất và 8 MiB tổng. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal QA, browser agents, verifier/safety pipelines, evidence collection.
- **Why it matters:** Browser/UI agents thường quyết định dựa trên screenshot; verifier chỉ thấy text sẽ có asymmetric context so với executor.
- **Practical implication:** Screenshot nên là first-class evidence có provenance, timestamp, hash, redaction metadata và bounded retention.
- **Priority:** **Critical** cho browser/UI automation; **High** cho coding agents có image-bearing tool outputs.
- **Confirmed facts:** Setting mặc định `false`; ảnh có thể đến từ user, assistant và tool outputs; bounded queue tối đa 4 ảnh, 8 MiB; detail hints bị bỏ trước sampling. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Analysis:** Verification channel nên có cùng evidence classes với execution channel. Đây là pattern tổng quát cho QA, browser automation và incident agents.
- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }` và chỉ forward bounded evidence liên quan.
- **Uncertainty:** 4 ảnh/8 MiB là implementation choice; chưa có public benchmark chứng minh tối ưu cho mọi task.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Xây **config resolver có provenance** thay vì merge config “âm thầm”

- **Problem:** Agent systems thường có nhiều lớp config nhưng final effective value không giải thích được đến từ đâu.
- **Proposed improvement:** Mỗi setting trả về `{ value, source, sourceVersion, overriddenBy }`; expose một `explain()` view cho model, policy, skills và runtime settings.
- **Why it may work:** Guardian v2 mới dùng model defaults nhưng local config override, nên precedence trực tiếp ảnh hưởng behavior. [Codex #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Suitable use cases:** Cursor Rules, Claude Code config, Codex skills/policies, QA agents, repo-level architecture rules.
- **Limitations:** Cần chuẩn hóa schema cho từng tool/provider.
- **Risks:** Nếu resolver quá linh hoạt, debugging vẫn khó; nên giữ precedence cố định và testable.

### B. Tách **discovery metadata** khỏi full skill procedure

- **Problem:** Catalog lớn dễ tiêu tốn context trước khi agent bắt đầu task thật.
- **Proposed improvement:** Discovery layer chỉ giữ `name`, `trigger`, `expected outcome`, `exclusions`; full procedure, examples và commands chỉ load sau selection.
- **Why it may work:** Codex vừa thêm explicit skill-catalog budget, cho thấy discovery metadata là một bounded context surface. [Codex #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Cursor skills, Codex skills, Claude reusable workflows, interview/code-review agents.
- **Limitations:** Metadata quá ngắn có thể giảm routing recall.
- **Risks:** Wrong-skill routing nếu trigger không discriminative.

### C. Context budget nên được quản lý **theo surface**

- **Problem:** Chỉ theo dõi tổng tokens không cho biết surface nào đang làm chất lượng giảm.
- **Proposed improvement:** Budget riêng cho `Policy`, `SkillCatalog`, `RepoGuidance`, `TaskEvidence`, `Conversation`, `ToolResults`, `VisualEvidence`.
- **Why it may work:** Codex hiện đã có explicit budget cho skill catalog và bounded image transcript. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Visual transcript](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** Long-running QA/research agents, architecture workflows, repo-wide coding agents.
- **Limitations:** Token/image cost semantics khác nhau giữa providers.
- **Risks:** Cắt budget cứng có thể loại critical evidence; nên dùng eval-driven tuning.

## 4. Agent, Workflow, and Loop Engineering

### A. **Resolve → Execute → Verify** với capability snapshot

- **Problem:** Model/runtime config có thể thay đổi giữa các phiên khiến cùng workflow cho kết quả khác nhau nhưng khó giải thích.
- **Technique:** Trước execution, resolve `ModelCapabilityProfile` + effective policy + skill/context budgets; persist snapshot vào run metadata; verifier đọc đúng snapshot đó.
- **Expected benefit:** Reproducibility tốt hơn, root-cause dễ hơn khi regression xảy ra.
- **Failure risks:** Snapshot stale nếu provider thay đổi hosted behavior giữa run; cần timestamp và source version.
- **Suitable use cases:** Code review agents, architecture agents, QA agents, research agents.

### B. **Verifier symmetry** cho multimodal workflows

- **Problem:** Executor thấy screenshot nhưng verifier chỉ thấy text.
- **Technique:** Forward bounded visual evidence cùng text evidence, có provenance/redaction; verifier được access cùng evidence classes với executor.
- **Expected benefit:** Giảm false verdict trong browser/UI QA.
- **Failure risks:** Screenshot có PII/secrets hoặc context dư thừa.
- **Suitable use cases:** Playwright/Selenium QA agents, incident response, visual regression triage.

### C. Retry phải phụ thuộc **failure signature**, không chỉ retry count

- **Problem:** Agent lặp lại cùng action khi root cause không đổi tạo low-value loop.
- **Technique:** Hash failure signature từ error type + tool + target + state; nếu signature lặp 2 lần, stop retry và chuyển sang re-plan/root-cause path.
- **Expected benefit:** Ít token/tool calls vô ích; rõ stop condition.
- **Failure risks:** Signature quá coarse có thể gộp hai lỗi khác nhau.
- **Suitable use cases:** Build/test/fix loops, browser automation, CI repair agents.

### D. Permission model theo **monotonic restriction**

- **Problem:** Local/task scope có thể vô tình mở rộng quyền so với global policy.
- **Technique:** Compose quyền bằng intersection; cache approval phải bind policy revision/fingerprint.
- **Expected benefit:** Least privilege rõ ràng hơn, giảm stale approvals.
- **Failure risks:** Policy quá restrictive gây approval churn.
- **Suitable use cases:** CI/CD agents, migration agents, production support, database tools.

- **Why it matters:** Browser/GUI agents cần verifier symmetry mà không gửi toàn bộ screenshot history.
- **Opportunity:** Evidence store + redaction + dedupe + visual verifier harness.
- **Risk:** Privacy/cost tăng nhanh nếu retention kém.
- **Status:** **Growing**.

### 3. **Context budgeting per surface**
- **What is changing:** Skill catalog và visual evidence đều đang được quản lý bằng explicit budget.
- **Why it matters:** “Longer context” không đồng nghĩa “better context”.
- **Opportunity:** Context telemetry, budget optimizer, retrieval/skill-routing evals.
- **Risk:** Over-optimization theo token có thể cắt critical evidence.
- **Status:** **Growing**.

### 4. **Monotonic permission composition**
- **What is changing:** Lower-level policies chỉ được restrict; approvals gắn policy fingerprint.
- **Why it matters:** Agent quyền cao cần runtime-enforced least privilege.
- **Opportunity:** Policy engine cho coding/QA/CI agents với explicit approval state.
- **Risk:** UX xấu nếu approval granularity quá nhỏ.
- **Status:** **Established pattern, growing adoption**.

### 5. **Capability drift as an evaluation variable**
- **What is changing:** Tool behavior có thể phụ thuộc model, auth mode, route, hosted rollout và source/stable channel.
- **Why it matters:** Benchmark không log capability snapshot sẽ khó reproduce.
- **Opportunity:** Build capability probe + run manifest cho agent eval platforms.
- **Risk:** Probe sai hoặc stale tạo false confidence.
- **Status:** **Early signal**.
