## 1. Executive Summary

### 1. Cost nên là first-class telemetry của agent run
- **One-sentence summary:** Codex app-server có thể emit `codex.turn_cost` qua OTLP cho OpenAI API-key sessions sau completed hoặc aborted turns, kèm estimated USD cost, interruption state, model, speed và reasoning effort. - **Affected skill area:** Agent evaluation, observability, model comparison, cost/latency optimization.
- **Why it matters:** Pass/fail không đủ để đánh giá production fitness; cần biết workflow thành công với chi phí và độ trễ nào.
- **Practical implication:** Mỗi run nên lưu `outcome + latency + cost + model + reasoning effort + retry/interruption`.
- **Priority:** **Critical**.
- **Confirmed facts:** Worker chỉ chạy khi OTLP exporter bật và provider là OpenAI; theo dõi turn lifecycle, completed/aborted state, response count; query turn-cost endpoint; emit estimated USD cost; preserve organization/project headers; bounded polling/retry; re-probe sau auth changes. [Source](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Analysis:** Đây là nền tảng cho `success-per-dollar`, `verification-cost`, `retry-cost` và phát hiện low-value loops.
- **Recommendation:** Thêm cost telemetry vào QA/research/code-review/interview agents và so sánh theo task family, không so model bằng benchmark chung chung.
- **Uncertainty:** Turn-cost endpoint trong commit không được xác nhận là public contract; chỉ nên lấy pattern observability.

## 4. Agent, Workflow, and Loop Engineering

### 1. `Plan → Execute → Verify → Commit State → Decide`
- **Problem:** output visible trước khi async state hoàn tất.
- **Technique:** thêm explicit `StateCommitted` checkpoint trước consumer/reviewer tiếp tục.
- **Expected benefit:** giảm race conditions và flaky handoff.
- **Failure risks:** checkpoint quá coarse tăng latency; checkpoint không atomic vẫn tạo false-ready state.
- **Suitable use cases:** Hangfire/background jobs, browser QA, CI report collection, multi-agent orchestration.

### 2. `Attempt → Classify → Repair → Retry within Budget → Replan/Fail`
- **Problem:** retry blind hoặc per-phase tạo infinite/expensive loops.
- **Technique:** logical-operation retry budget, classify transient/permanent/auth/policy/quota/context failures; repair state trước retry nếu cần.
- **Expected benefit:** predictable failure recovery, measurable retry cost.
- **Failure risks:** wrong classification; duplicate side effects nếu thiếu idempotency.
- **Suitable use cases:** LLM calls, MCP tools, Graph/API calls, browser actions, CI workers.

### 3. Freshness-aware verifier consumption
- **Problem:** async review verdict áp lên state mới hơn state đã được review.
- **Technique:** bind verdict to sequence/version/evidence hash; reject nếu lag vượt workflow-specific bound.
- **Expected benefit:** tránh stale approval và false safety signal.
- **Failure risks:** bound quá chặt gây re-review liên tục; quá lỏng bỏ lọt stale verdict.
- **Suitable use cases:** approval agents, code review sau nhiều patch, browser verification sau navigation/DOM changes.

### 4. Cost-aware loop stop conditions
- **Problem:** loop vẫn “tiến triển” nhưng value nhỏ so với cost/latency.
- **Technique:** thêm `maxAttempts`, `maxCost`, `maxWallTime`, `sameFailureSignatureCount`, `minimumExpectedGain`.
- **Expected benefit:** phát hiện low-value loops sớm hơn.
- **Failure risks:** hard budget có thể dừng task khó ngay trước khi thành công.
- **Suitable use cases:** research agents, RCA, auto-fix/retest, iterative code review.

- **Expected benefit:** giảm hidden config conflicts và support/audit nhanh hơn.
- **Effort:** **Half a day** cho data model; **Several days** nếu tích hợp toàn platform.

## 7. Opportunities and Trends to Watch

### 1. Agent observability đang dịch từ token usage sang outcome-aware cost telemetry
- **What is changing:** cost được gắn trực tiếp với turn lifecycle, model, reasoning effort và interruption.
- **Why it matters:** cho phép model/workflow routing dựa trên empirical task economics.
- **Opportunity:** xây eval dashboard `quality + latency + cost + retry + verifier overhead`.
- **Risk:** tối ưu cost quá sớm có thể giảm quality; estimated cost không phải ground truth hoàn hảo.
- **Status:** **Growing**.

### 2. Verifier correctness đang trở thành vấn đề distributed-state, không chỉ LLM quality
- **What is changing:** freshness counters, committed progress, evidence provenance, policy layering.
- **Why it matters:** async agents cần consistency semantics giống distributed systems.
- **Opportunity:** reusable `EvidenceManifest + VersionedVerdict + Checkpoint` library cho .NET agents.
- **Risk:** complexity tăng nếu mọi workflow đều over-engineer consistency.
- **Status:** **Growing**.

### 3. Skill systems đang chuyển sang retrieval/ranking architecture
- **What is changing:** token budgets, hybrid routing, recent-use memory, shadow evaluation.
- **Why it matters:** skill count sẽ tiếp tục tăng; static prompt injection không scale.
- **Opportunity:** portable skill router dùng chung cho Cursor/Codex/Claude-style workflows.
- **Risk:** router trở thành hidden source of failure nếu không có eval dataset.
- **Status:** **Growing**.

### 4. Runtime policy đang thay behavioral safety prompt
- **What is changing:** environment restrictions, policy-aware approvals, secret scrubbing, managed reviewer constraints.
- **Why it matters:** tool-using agents cần enforceable boundaries.
- **Opportunity:** policy middleware cho MCP/CLI/browser/database tools.
- **Risk:** fragmented policy layers, difficult debugging.
- **Status:** **Established**.

### 5. Provider-native adapters sẽ quan trọng hơn khi model APIs phân hóa
- **What is changing:** OpenCode giữ native OpenAI Responses và Anthropic Messages paths thay vì flatten toàn bộ qua một abstraction. [Source](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Why it matters:** unified interface tiện nhưng có thể làm mất provider-specific capabilities.
- **Opportunity:** `IModelProvider` + `ModelCapabilities` + native request mapper + normalized event layer.
- **Risk:** adapter maintenance cost tăng.
- **Status:** **Growing**.
