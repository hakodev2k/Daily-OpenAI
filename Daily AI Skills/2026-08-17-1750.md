## 1. Executive Summary

### 1. Codex skill-catalog token budget là thay đổi mới quan trọng nhất cho Context Engineering

- **One-sentence summary:** Codex `main` thêm `[skills].max_context_tokens` để override token budget của available-skills catalog; giá trị phải dương, bị cap ở 10.000 tokens, và khi unset vẫn dùng mặc định 2% model context window. [Codex #38978, 17/08/2026](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Affected skill area:** Skills architecture, context budgeting, skill discovery, prompt evaluation.
- **Why it matters:** Khi số reusable skills tăng, metadata discovery cạnh tranh trực tiếp token với requirements, code, repository context và evidence.
- **Practical implication:** Skill catalog nên được coi là một **bounded retrieval surface** có budget, telemetry và regression tests riêng.
- **Priority:** **Critical** cho hệ thống nhiều skills; **High** cho coding agent cá nhân.
- **Confirmed facts:** Commit thêm `SkillsConfig.max_context_tokens`; schema yêu cầu minimum 1; configured budget capped ở 10.000; tests cover parsing, override, cap và rendering dưới budget.
- **Analysis:** Context Engineering nên quản lý **allocation theo surface**, không chỉ cố “rút ngắn prompt”.
- **Recommendation:** Tạo `ContextBudget` riêng cho `Policy`, `Skill Catalog`, `Repository Context`, `Task Evidence`, `Conversation`, `Tool Results` và log token usage theo surface.
- **Uncertainty:** Đây là source-level change trên `main`; stable `0.147.0` chưa xác nhận hỗ trợ option này.

### 2. Skill discovery cần được benchmark như retrieval system, không đo bằng số lượng skills

- **One-sentence summary:** Việc Codex giới hạn catalog bằng percentage/cap cho thấy discovery phải hoạt động dưới bounded context thay vì inject toàn bộ catalog vô hạn. [Codex #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Affected skill area:** Skill routing, prompt evaluation, context engineering.
- **Why it matters:** Budget quá nhỏ có thể bỏ sót skill phù hợp; quá lớn tăng input tokens, latency và làm metadata lấn át task evidence.
- **Practical implication:** Cần đo `routing recall`, `wrong-skill rate`, `no-skill rate`, task success, input tokens và latency.
- **Priority:** **High**.
- **Confirmed facts:** Codex tests xác nhận shared skill-catalog budget và catalog rendering phải nằm trong configured budget.
- **Analysis:** Skill catalog giống một retrieval index; progressive disclosure phù hợp hơn full-procedure injection.
- **Recommendation:** Discovery metadata chỉ giữ `name + trigger + outcome + exclusions`; full procedure/examples/commands chỉ load sau khi skill được chọn.
- **Uncertainty:** Chưa có public benchmark xác định budget tối ưu theo số lượng skills/domain.

### 3. Restrictive environment policy vẫn là security pattern đáng áp dụng nhất trong 24 giờ

- **One-sentence summary:** Codex `main` thêm `EnvironmentConfig.exec_policy`, không cho environment-level policy chứa `allow` rules, merge restrictive overlay vào command policy và bind approval cache với policy fingerprint. [Codex #38942, 17/08/2026](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Affected skill area:** Permission boundaries, human approval, sandboxing, secure agent runtime.
- **Why it matters:** Lower-level scope chỉ nên **giảm authority**, không được tự mở rộng quyền từ global/workspace policy.
- **Practical implication:** QA agent có thể write test data nhưng cấm deploy; research agent read-only; production action có thể buộc fresh approval sau policy change.
- **Priority:** **Critical**.
- **Confirmed facts:** Environment policy không được chứa allow rules; policy fingerprint tham gia cached approval keys.
- **Analysis:** Least privilege đáng tin cậy hơn khi enforce ngoài model thay vì chỉ viết trong prompt/rules.
- **Recommendation:** Model quyền như intersection: `Global ∩ Workspace ∩ Environment ∩ Task ∩ HumanApproval`.
- **Uncertainty:** Source-level change; stable binary chưa xác nhận ship behavior này.

### 4. Secret scrubbing phải là runtime invariant, không phải prompt convention

- **One-sentence summary:** Codex merge fix để `CODEX_EXEC_SERVER_NOISE_AUTH_TOKEN` không inherited xuống shell commands/hooks, kể cả khi environment overrides cố set lại case-variant của biến. [Codex #38941, 17/08/2026](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Affected skill area:** Secrets, hooks, subprocess isolation, secure tool execution.
- **Why it matters:** Build/test/package hooks có thể đọc process environment; leaked execution credential tạo quyền thật chứ không chỉ prompt leakage.
- **Practical implication:** .NET agent runner nên sanitize child-process environment **sau mọi merge/override** và ngay trước `Process.Start`.
- **Priority:** **Critical**.
- **Confirmed facts:** Commit có regression tests cho shell commands và command hooks, gồm case-insensitive scrubbing.
- **Analysis:** Child process/hook là untrusted execution boundary.
- **Recommendation:** Dùng `SanitizedProcessEnvironmentBuilder`, ưu tiên allowlist cho runner nhạy cảm; log tên biến bị loại nhưng không log value.
- **Uncertainty:** Một token được cover không chứng minh mọi secret class trong runtime đều đã được cover.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Biến Context Engineering thành **budget allocation problem**

- **Problem:** Prompt/agent systems thường chỉ đo tổng input tokens, không biết surface nào đang chiếm context.
- **Proposed improvement:** Theo dõi budget cho từng lớp:
  - `Policy / safety`
  - `Skill catalog`
  - `Repository guidance`
  - `Task requirements`
  - `Evidence / logs / diffs`
  - `Conversation history`
  - `Tool schemas/results`
- **Why it may work:** Codex vừa thêm explicit budget cho skill catalog, chứng minh một context surface có thể được quản trị độc lập. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Cursor/Codex/Claude skill libraries, QA agents, research agents, architecture agents.
- **Limitations:** Token estimation có thể khác tokenizer/provider thực tế.
- **Risks:** Budget cứng quá sớm có thể cắt mất critical evidence.
- **Recommendation:** Budget chỉ là guardrail; khi overflow, ưu tiên evidence/requirements hơn catalog/history.

### B. Progressive disclosure cho skills

- **Problem:** Full procedure của hàng chục skills được inject upfront làm catalog phình nhanh.
- **Proposed improvement:** Hai tầng:
  1. **Discovery metadata:** name, trigger, outcome, exclusions.
  2. **Selected skill body:** workflow, commands, examples, validation, stop conditions.
- **Why it may work:** Giảm catalog cost trong khi vẫn giữ depth khi skill được chọn.
- **Suitable use cases:** QA, code review, architecture, incident, research, interview agents.
- **Limitations:** Metadata quá ngắn có thể gây routing collision.
- **Risks:** Sai routing dẫn đến skill body không phù hợp được load.
- **Recommendation:** Mỗi skill có ít nhất 3 positive và 3 negative routing examples; regression-test routing sau mỗi thay đổi description.

### C. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Một file rules lớn dễ trộn security constraints, coding conventions, reusable workflow và task-specific details.
- **Proposed improvement:**
  - `policy/`: deny/approval/data restrictions
  - `skills/`: reusable procedures
  - `context/`: architecture/repo/domain facts
  - `task/`: objective, acceptance criteria, evidence hiện tại
- **Why it may work:** Codex environment-policy change cung cấp evidence rằng policy nên compose theo scope và lower layer chỉ restrict authority. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor Rules/Skills, Claude Code instructions, Codex skills, internal agent platform.
- **Limitations:** Cần deterministic load order.
- **Risks:** Duplicate/conflicting instructions giữa layers.
- **Recommendation:** Ghi rõ precedence contract; context cung cấp facts, không tự grant permission.

### D. Provenance cho decision-critical claims

- **Problem:** Agent dễ biến inference thành fact trong run dài.
- **Proposed improvement:** Gắn type `FACT`, `ASSUMPTION`, `INFERENCE`, `RECOMMENDATION`, `UNKNOWN` tại decision points.
- **Why it may work:** Verifier có thể deterministic-check evidence coverage và phát hiện reasoning drift.
- **Suitable use cases:** Architecture planning, incident RCA, research, code review, interview story verification.
- **Limitations:** Tăng verbosity.
- **Risks:** Label đúng nhưng evidence yếu vẫn có thể gây false confidence.
- **Recommendation:** Chỉ enforce ở decision points, không áp dụng cho mọi câu.

## 4. Agent, Workflow, and Loop Engineering

### A. Skill-routing evaluation loop

- **Problem:** Không biết catalog budget nhỏ hơn có làm mất skill phù hợp hay không.
- **Technique:** Chạy cùng corpus qua các budget `300 / 600 / 1200 / 2400` tokens; giữ model/version/task cố định.
- **Metrics:** `correct skill`, `wrong skill`, `no skill`, task success, input tokens, latency, retry count.
- **Expected benefit:** Tìm budget thấp nhất vẫn giữ routing quality chấp nhận được.
- **Failure risks:** Corpus quá dễ hoặc không đại diện sẽ cho kết luận sai.
- **Suitable use cases:** Skill-heavy agent systems.
- **Recommendation:** Không dùng LLM-as-a-judge làm metric duy nhất; routing expected skill nên deterministic khi task có ground truth.

### B. Permission-policy regression matrix

- **Problem:** Permission rules thường chỉ test happy path.
- **Technique:** Tạo matrix theo `AgentRole × Environment × CommandClass × PriorApprovalState`.
- **Expected benefit:** Phát hiện privilege escalation, stale approval reuse và inconsistent behavior.
- **Failure risks:** Test matrix tăng nhanh.
- **Suitable use cases:** QA agents, CI agents, deploy agents, production-support agents.
- **Recommendation:** Ưu tiên các case: lower-level allow attempt, policy revision after approval, package install, deploy, destructive DB command.

### C. Secret-boundary tests

- **Problem:** Secret có thể bị reintroduced sau environment merge.
- **Technique:** Inject canary secrets, apply config overrides, spawn subprocess/hook, assert secret absence.
- **Expected benefit:** Biến secret isolation thành regression invariant.
- **Failure risks:** Test chỉ cover known env-var names.
- **Suitable use cases:** .NET `ProcessStartInfo`, build tools, shell hooks, browser drivers, MCP subprocess servers.
- **Recommendation:** Include case-insensitive tests trên Windows.

### D. Stop/re-plan rule cho low-value loops

- **Problem:** Agent retry cùng failure signature hoặc research cùng nguồn nhiều lần.
- **Technique:** Nếu `same_signature >= 2`, bắt buộc classify root cause và re-plan; nếu primary-source delta = none, return `NO_MATERIAL_DELTA`.
- **Expected benefit:** Giảm token/time waste và infinite-loop risk.
- **Failure risks:** Re-plan quá sớm với transient failure.
- **Suitable use cases:** QA automation, research, CI-fix, browser automation.
- **Recommendation:** Phân biệt transient infrastructure error với deterministic failure signature trước khi stop.
