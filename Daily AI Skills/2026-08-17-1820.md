## 1. Executive Summary

### 1. Guardian v2 đưa **visual evidence** vào verifier/safety transcript

- **One-sentence summary:** Codex `main` thêm `features.guardianv2.transcript.include_images`, cho phép Guardian v2 nhận ảnh gần đây từ user/assistant messages và configured tool outputs; context ảnh bị giới hạn ở **4 ảnh gần nhất** và **8 MiB tổng**, đồng thời loại `detail` hint khi tạo sampling request. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal QA, browser agents, verifier/safety pipelines, evidence collection.
- **Why it matters:** Browser/UI agents thường quyết định dựa trên screenshot; nếu executor nhìn thấy ảnh nhưng reviewer/guardian chỉ thấy text thì verifier có asymmetric context và dễ đưa ra verdict sai.
- **Practical implication:** Screenshot nên là first-class evidence có provenance, timestamp, hash và redaction metadata; verifier chỉ nhận bounded subset liên quan.
- **Priority:** **Critical** cho browser/UI agents; **High** cho coding agents có image-bearing tool outputs.
- **Confirmed facts:** Setting opt-in, mặc định `false`; lấy ảnh từ user/assistant messages và tool outputs; tối đa 4 ảnh gần nhất và 8 MiB tổng; tests cover config parsing và image forwarding. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Analysis:** Verification channel nên có access tới cùng evidence class mà execution channel đã dùng.
- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }` và đưa bounded evidence vào reviewer/verifier.
- **Uncertainty:** Chưa có evidence public rằng stable Codex `0.147.0` đã ship behavior này hoặc Guardian v2 là default path cho mọi người dùng.

- **Uncertainty:** 4 ảnh/8 MiB là implementation choice, chưa có benchmark chứng minh tối ưu cho mọi workflow.

- **Uncertainty:** Một token được cover không chứng minh mọi secret class đều được cover.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **Text Context Budget** và **Visual Evidence Budget**

- **Problem:** Agent thường gom text, screenshots và tool artifacts vào cùng một “context bucket”, khó biết lớp nào đang gây cost/latency.
- **Proposed improvement:** Theo dõi riêng `text_tokens`, `skill_catalog_tokens`, `tool_result_tokens`, `image_count`, `image_bytes`, `evidence_priority`.
- **Why it may work:** Codex đang quản lý riêng skill-catalog tokens và Guardian visual transcript bytes/count, cho thấy context surfaces có thể có budget độc lập. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Image transcript](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** QA browser agents, code review agents có screenshots, incident analysis, research agents có diagrams/images.
- **Limitations:** Không có một budget tối ưu chung cho mọi model/provider.
- **Risks:** Cắt evidence quá mạnh có thể giảm correctness.

### B. Skill metadata nên phục vụ **routing**, không chứa full procedure

- **Problem:** Description dài làm catalog phình nhanh.
- **Proposed improvement:** Metadata chỉ giữ `name`, `trigger`, `outcome`, `exclusions`; full procedure/examples/commands load sau khi skill được chọn.
- **Why it may work:** Bounded catalog tạo áp lực tối ưu discovery metadata thay vì nhồi procedural context.
- **Suitable use cases:** Cursor/Codex/Claude reusable skill libraries, QA/research/review skills.
- **Limitations:** Metadata quá ngắn hoặc ambiguous làm giảm routing recall.
- **Risks:** Skills có trigger gần nhau dễ collision.
- **Recommendation:** Mỗi skill có ít nhất 3 positive và 3 negative routing examples; regression-test selection.

### C. Facts / Assumptions / Inferences / Recommendations phải là fields riêng

- **Problem:** Agent dễ biến suy luận thành “fact” sau nhiều bước/handoff.
- **Proposed improvement:** Mỗi decision artifact lưu `Fact`, `Evidence`, `Assumption`, `Inference`, `Unknown`, `Recommendation`, `Confidence`.
- **Why it may work:** Handoff giữa planner/executor/reviewer không phụ thuộc transcript dài và giảm “memory drift”.
- **Suitable use cases:** Architecture analysis, incident RCA, research, code review, interview story verification.
- **Limitations:** Tăng structured-output overhead.
- **Risks:** Confidence score không được calibrate có thể tạo false certainty.

## 4. Agent, Workflow, and Loop Engineering

### A. **Evidence symmetry:** executor thấy gì, verifier phải có đường nhận cùng loại evidence

- **Problem:** Executor dựa vào screenshot nhưng reviewer chỉ thấy text.
- **Technique:** Dùng `EvidenceEnvelope` chung; verifier nhận bounded text + image evidence tương ứng.
- **Expected benefit:** Giảm false approval/rejection do missing visual state.
- **Failure risks:** PII/secrets trong screenshot; stale screenshot; image spoofing.
- **Suitable use cases:** Playwright/Selenium QA, browser agents, UI regression, incident triage.

### B. **Plan → Execute → Verify → Decide** với stop/re-plan condition

- **Problem:** Agent có thể lặp test-fix-retest mà không học từ failure signature.
- **Technique:** Sau 2 failures cùng signature, stop retry và chuyển sang root-cause/re-plan; lưu checkpoint trước mỗi side-effectful step.
- **Expected benefit:** Giảm low-value loops và destructive retries.
- **Failure risks:** Signature normalization quá thô có thể coi hai lỗi khác nhau là một.
- **Suitable use cases:** CI repair, flaky browser automation, database migration, deployment validation.

### C. Approval cache phải phụ thuộc **policy revision**

- **Problem:** Approval cũ có thể trở nên quá rộng sau khi policy đổi.
- **Technique:** Key approval bằng `action + resource + policyFingerprint + environment`.
- **Expected benefit:** Approval không survive khi authority boundary thay đổi.
- **Failure risks:** Quá nhiều re-approval nếu fingerprint thay đổi không cần thiết.
- **Suitable use cases:** Shell execution, deployment, data mutation, admin APIs.

### D. Long-running agent cần durable state ngoài transcript

- **Problem:** Transcript dài khó resume, fork và audit.
- **Technique:** `Project → Run → Step → Artifact/Evidence`; transcript chỉ là một data source.
- **Expected benefit:** Resume/retry/fork và postmortem rõ ràng hơn.
- **Failure risks:** State duplication giữa DB và conversation.
- **Suitable use cases:** Research agent, interview intelligence pipeline, QA regression campaigns, repository-wide refactors.
