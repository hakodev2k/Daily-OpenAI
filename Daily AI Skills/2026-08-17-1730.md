## 3. Prompt, Skills, Rules, and Context Engineering

### A. Treat **Skill Catalog** như một context surface có ngân sách riêng

- **Problem:** Khi số skills tăng, discovery metadata có thể chiếm context trước cả code, requirements và evidence.
- **Proposed improvement:** Đặt budget cố định hoặc adaptive cho catalog; track `allocated`, `rendered`, `truncated`, `selected` và downstream task result.
- **Why it may work:** Codex commit mới implement chính pattern budgeted catalog và test rằng rendered metadata nằm trong configured budget. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Codex skills, Cursor skill libraries, Claude reusable workflows, internal agent marketplace.
- **Limitations:** Budget quá thấp có thể giảm discoverability; budget quá cao có thể làm task context bị crowd-out.
- **Risks:** Chọn con số theo cảm tính mà không chạy eval.
- **Recommendation:** Benchmark ít nhất 4 mức budget, ví dụ `300 / 600 / 1200 / 2400`, trên 30–50 representative tasks; đo routing recall, task success, input tokens, latency và cost.

### B. Tối ưu skill metadata cho **discovery**, không biến metadata thành full procedure

- **Problem:** Description dài giúp giải thích nhưng làm catalog phình nhanh.
- **Proposed improvement:** Metadata chỉ chứa `name`, `when to use`, `expected outcome`, `important exclusions`; full procedure load on selection.
- **Why it may work:** Progressive disclosure giúp giảm background context nhưng vẫn giữ procedural depth khi cần.
- **Suitable use cases:** QA skills, research skills, review skills, architecture skills, deployment skills.
- **Limitations:** Description quá ngắn/ambiguous làm giảm routing quality.
- **Risks:** Hai skills có trigger gần nhau dễ collision.
- **Recommendation:** Mỗi skill nên có evaluation cases: ít nhất 3 positive triggers, 3 negative triggers và 2 confusing-neighbor cases.

### C. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Một file rules lớn dễ trộn security constraints, coding conventions, workflow steps và task-specific facts.
- **Proposed improvement:**
  - `policy/`: permissions, data restrictions, approval requirements.
  - `skills/`: reusable procedures/checklists.
  - `context/`: architecture/repo/domain facts.
  - `task/`: objective, acceptance criteria, current evidence.
- **Why it may work:** Codex restrictive environment policy là concrete evidence cho scope-specific policy composition. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor Rules/Skills, Claude Code workflows, Codex skills, QA/research/review agents.
- **Limitations:** Nhiều layers hơn, cần deterministic precedence.
- **Risks:** Duplicate instructions hoặc conflicting defaults.
- **Recommendation:** Viết precedence contract ngắn và machine-testable; context không được tự grant permission.

### D. Provenance-aware context: giữ `FACT / ASSUMPTION / INFERENCE / RECOMMENDATION / UNKNOWN`

- **Problem:** Long-running agent dễ biến inference thành fact sau nhiều turn/tool calls.
- **Proposed improvement:** Gắn type cho claims ở decision points; facts có evidence reference.
- **Why it may work:** Tạo checkpoint deterministic cho verifier/reviewer và giảm reasoning drift.
- **Suitable use cases:** Research, incident analysis, architecture planning, code review, interview story verification.
- **Limitations:** Tăng token usage nếu áp dụng quá rộng.
- **Risks:** Label đúng nhưng evidence vẫn yếu.
- **Recommendation:** Chỉ enforce provenance ở decision points, không áp dụng cho mọi câu.

## 4. Agent, Workflow, and Loop Engineering

### A. `Detect → Classify → Verify → Act → Stop`

- **Problem:** Research/monitoring agent dễ lặp search khi không có delta.
- **Technique:** Sau một bộ primary sources cố định, classify outcome thành `MATERIAL_DELTA`, `CORRECTION`, `NO_MATERIAL_DELTA`, hoặc `INSUFFICIENT_EVIDENCE`.
- **Expected benefit:** Giảm low-value loops, token/cost waste và duplicated briefings.
- **Failure risks:** Source set quá hẹp có thể bỏ sót real update.
- **Suitable use cases:** Daily briefing, release radar, job radar, security advisory monitor.
- **Recommendation:** Stop condition nên dựa trên source coverage + evidence state, không dựa vào “đã search nhiều”.

### B. Skill routing loop: `Discover → Select → Load → Execute → Verify`

- **Problem:** Agent có thể load quá nhiều skill content trước khi biết skill nào phù hợp.
- **Technique:** Catalog metadata bounded; chỉ selected skill mới load full procedure.
- **Expected benefit:** Ít background context hơn, dễ eval skill-selection quality hơn.
- **Failure risks:** Wrong selection khiến downstream execution tốt nhưng sai procedure.
- **Suitable use cases:** QA agent, code review agent, architecture agent, multi-role systems.
- **Recommendation:** Log selected skill ID/version và confidence; verifier phải biết skill nào đã được dùng.

### C. Permission loop phải invalidate approval khi policy đổi

- **Problem:** Approval cũ có thể không còn hợp lệ sau environment/policy change.
- **Technique:** Include policy fingerprint/revision trong approval cache key, giống pattern mới của Codex. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Expected benefit:** Giảm stale approval reuse.
- **Failure risks:** Too-frequent invalidation gây approval fatigue.
- **Suitable use cases:** Shell agents, deployment agents, DB migration tools, CI/CD automation.
- **Recommendation:** Cache approval theo `action + scope + policy_revision + environment_identity`.

### D. Version-aware regression harness

- **Problem:** Agent behavior thay đổi theo model, tool version, provider route, auth mode và config.
- **Technique:** Mỗi eval run log đầy đủ environment metadata và chạy fixed corpus trước/sau update.
- **Expected benefit:** Phân biệt model regression với tool/config regression.
- **Failure risks:** Eval corpus không đại diện production.
- **Suitable use cases:** Codex/Claude/Cursor/OpenCode comparison, QA agents, code-review agents.
- **Recommendation:** Baseline ít nhất 20 task categories: tool selection, edit correctness, permission handling, secret isolation, retry behavior, context recall.

## 5. Hooks and Integrations

### 1. .NET subprocess wrapper + secret sanitization

- **What can be integrated:** `ProcessStartInfo`, CLI tools, test runners, Git commands, Playwright, package managers.
- **Workflow benefit:** Cho phép agent thực thi tool mà không inherited toàn bộ parent environment.
- **Security concerns:** Secrets có thể leak qua env vars, command-line arguments, logs hoặc temp files.
- **Difficulty:** **Moderate**.
- **Recommendation:** Build centralized `SafeProcessRunner` với environment allowlist/denylist, command audit và redaction tests.

### 2. Skill-routing telemetry

- **What can be integrated:** Cursor/Codex/Claude skill libraries, internal agent runner, SQLite/PostgreSQL telemetry.
- **Workflow benefit:** Đo được skill nào được advertised, selected, executed và succeeded.
- **Security concerns:** Không log task secrets hoặc full prompt nếu không cần.
- **Difficulty:** **Moderate**.
- **Recommendation:** Lưu `skill_id`, `skill_version`, `catalog_tokens`, `selection_result`, `task_result`, `latency`, `cost`.

### 3. GitHub Actions regression suite cho skills/rules

- **What can be integrated:** Repository guidance files, skill metadata, evaluation fixtures, deterministic validators.
- **Workflow benefit:** Mỗi thay đổi rule/skill có regression signal thay vì review bằng cảm giác.
- **Security concerns:** Không đưa production credentials vào eval workflow; permission của Actions phải tối thiểu.
- **Difficulty:** **Moderate**.
- **Recommendation:** Trigger khi thay đổi `skills/`, `.cursor/`, `CLAUDE.md`, `AGENTS.md`, policy files; run routing/eval tests trước merge.

### 4. MCP/Teams knowledge-transfer boundary

- **What can be integrated:** MCP server cung cấp approved project facts/runbooks; Teams dùng như human review/approval channel khi có connector phù hợp.
- **Workflow benefit:** Tách source-of-truth knowledge khỏi conversation transcript.
- **Security concerns:** Scope tool permissions; tránh cho research agent write vào knowledge base hoặc Teams nếu chỉ cần read.
- **Difficulty:** **Advanced**.
- **Recommendation:** Start read-only; log source/version của context item; require explicit write approval.

- **What to change/test:** Tách project-level facts/rules khỏi per-run evidence; decision phải reference evidence IDs.
- **Expected benefit:** Resume/fork/review dễ hơn; giảm context handoff bằng transcript dump.
- **Effort:** **Several days**.
- **Recommendation:** Bắt đầu với một agent, ưu tiên QA hoặc Interview Intelligence, rồi reuse schema.

## 7. Opportunities and Trends to Watch

### 1. **Context budget orchestration** trở thành first-class configuration

- **What is changing:** Codex đã expose budget riêng cho skill catalog thay vì chỉ dựa context-window percentage. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Why it matters:** Agent frameworks sẽ cần phân bổ context giữa nhiều competing surfaces.
- **Opportunity:** Context planner/telemetry layer đo và adaptive allocate tokens theo task.
- **Risk:** Dynamic budgeting quá phức tạp có thể tạo instability khó debug.
- **Status:** **Growing**.

### 2. **Skills as retrieval systems**, không còn chỉ là Markdown files

- **What is changing:** Nhiều reusable skills cần discovery, selection, versioning và evaluation.
- **Why it matters:** Scale skill libraries làm routing quality trở thành bottleneck.
- **Opportunity:** Skill catalogs có embeddings/rules/negative triggers/eval harness.
- **Risk:** Over-engineering cho repo chỉ có vài skills.
- **Status:** **Growing**.

### 3. **Runtime policy > prompt policy**

- **What is changing:** Codex environment policy và approval-cache fingerprinting tiếp tục đẩy governance xuống runtime enforcement. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Why it matters:** Prompt không phải security boundary.
- **Opportunity:** Policy engines cho agent tool execution, environment-scoped permissions, auditable approvals.
- **Risk:** Policy complexity và operator fatigue.
- **Status:** **Established** về security principle, **Growing** trong agent tooling.

### 4. **Project-centric agent state** thay conversation-centric state

- **What is changing:** Experimental Codex Project APIs là thêm một signal rằng project/workspace state và execution threads cần lifecycle riêng. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)
- **Why it matters:** Long-running agents cần resume/fork/audit mà không phụ thuộc một chat transcript.
- **Opportunity:** Reusable project/run/evidence schema cho QA, research, architecture, interview agents.
- **Risk:** Schema premature nếu APIs/tooling còn experimental.
- **Status:** **Experimental**.

### 5. Provider-native adapters sau gateway abstraction

- **What is changing:** OpenCode giữ native OpenAI/Anthropic passthrough thay vì flatten mọi provider vào một compat path. [Source](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
- **Why it matters:** Native semantics có thể ảnh hưởng tools, reasoning, streaming và auth.
- **Opportunity:** .NET gateway abstractions với normalized governance + native capability layer.
- **Risk:** Adapter proliferation và test matrix lớn.
- **Status:** **Growing**.
