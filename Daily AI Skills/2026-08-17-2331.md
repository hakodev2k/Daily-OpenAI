# AI Skills & Agent Engineering Briefing — 2026-08-17 23:31 (UTC+7)

## 1. Executive Summary

## 1. Agent observability becomes mandatory
- Confirmed facts: Agent systems increasingly expose execution telemetry such as cost, latency, model, retries, and verification state.
- Analysis: Production AI workflows require measurement beyond task success.
- Recommendation: Store run metadata: task type, model, token usage, cost, latency, tool calls, failures, and verification result.
- Uncertainty: Exact telemetry availability differs by platform.
- Priority: Critical.

## 2. Verification must track state freshness
- Confirmed facts: Async agent workflows need explicit completion signals instead of checking only output existence.
- Analysis: File/message/result presence can happen before the workflow state is committed.
- Recommendation: Use states such as Planned → Executing → OutputReady → Verified → Completed.
- Uncertainty: Implementation patterns vary.
- Priority: Critical.

## 3. Policy-aware agents are replacing simple configuration merging
- Confirmed facts: Enterprise agent systems increasingly separate user preferences from managed security policies.
- Analysis: Effective capability should be calculated from permissions, policies, and runtime context.
- Recommendation: Design agents using desiredConfig vs effectiveConfig.
- Uncertainty: Vendor-specific behavior differs.
- Priority: High.

## 4. Skill routing needs context budgets
- Confirmed facts: Large skill collections create context pressure.
- Analysis: Loading every instruction reduces precision and increases cost.
- Recommendation: Use metadata retrieval, ranking, and bounded skill loading.
- Uncertainty: Optimal routing strategy requires evaluation.
- Priority: High.

## 5. Retry engineering is becoming a core agent skill
- Confirmed facts: Reliable agents need bounded retries and failure classification.
- Analysis: Unlimited retries create cost waste and low-value loops.
- Recommendation: Add retry budget, idempotency checks, checkpoints, and stop conditions.
- Uncertainty: Retry limits depend on workload.
- Priority: High.

## 3. Prompt, Skills, Rules, and Context Engineering

Problem:
- Long prompts become expensive and difficult to maintain.

Improvement:
- Split instructions into reusable skills, repository rules, workflows, and role definitions.

Why it works:
- Smaller targeted context improves retrieval and reduces irrelevant information.

Use cases:
- .NET architecture review agent.
- QA automation agent.
- Code review agent.
- Research agent.

Risks:
- Poor routing can load incomplete knowledge.

## 4. Agent, Workflow, and Loop Engineering

Recommended workflow:

Plan → Execute → Review → Verify → Commit

Required controls:
- Maximum iteration count.
- Failure classification.
- Human approval for risky actions.
- Checkpoints before external side effects.

Suitable uses:
- Code generation.
- Migration planning.
- Test generation.
- Incident analysis.
