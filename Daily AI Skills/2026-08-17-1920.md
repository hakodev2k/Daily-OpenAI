## 1. Executive Summary

### 1. Codex đang thử nghiệm **hybrid skill routing có short-term memory**

- **One-sentence summary:** Codex `main` thêm shadow selectors dùng **RRF** để fuse `recently invoked skills` với `character routing-card matches`, và một biến thể thêm weighted lexical matches. [Codex #38993, 17/08/2026](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Skill routing, context engineering, agent memory, multi-turn workflows, evaluation.
- **Why it matters:** Skill selection chỉ dựa vào text của turn hiện tại dễ fail khi user viết ngắn, dùng pronouns hoặc tiếp tục một workflow đang chạy. Việc đưa **recent skill usage** vào ranking tạo một form short-term procedural memory mà không cần inject full transcript.
- **Practical implication:** Với Cursor/Claude/Codex-style reusable skills, routing nên benchmark ít nhất ba signals: `current-query relevance`, `recently-used skill history`, và `structured routing metadata/dependencies`.
- **Priority:** **Critical** cho platform có nhiều skills; **High** cho personal agent systems.
- **Confirmed facts:** Hai selector mới có method IDs `lru_plus_character_routing_v1` và `lru_plus_lexical_character_routing_v1`; chúng fuse rankings bằng RRF với `RRF_K = 10`, cap results ở 50 candidates, deduplicate candidates và propagate truncation metadata. Tests xác minh cold start, short exact matches, deterministic ranking và recovery của skill đã invoke ở turn trước. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Analysis:** Đây là signal đáng chú ý rằng **skill discovery nên là retrieval problem**, không phải một prompt rule kiểu “hãy chọn skill phù hợp”. Recent-use memory đặc biệt hữu ích cho long-running QA/research workflows nơi task tiếp theo thường tiếp tục task trước.
- **Recommendation:** Với hệ thống skill riêng, thêm shadow evaluation cho `lexical-only`, `semantic/routing-card`, `recent-use`, và `fusion`; đừng đổi production routing trước khi có offline/online metrics.
- **Uncertainty:** Commit đang ở shadow-selection experiment; không có evidence rằng selector mới đã trở thành production/default skill router.

### 2. **Shadow evaluation** là pattern đáng áp dụng trước khi thay đổi agent routing

- **One-sentence summary:** Codex ghi nhận hai selector mới trong **existing shadow-selection experiment** thay vì ngay lập tức thay current selector. [Codex #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Agent evaluation, safe rollout, model/tool routing, regression testing.
- **Why it matters:** Routing changes có thể cải thiện một nhóm task nhưng làm regression ở nhóm khác; nếu chỉ A/B bằng user-visible behavior thì khó debug và có blast radius cao.
- **Practical implication:** Chạy candidate router song song nhưng **không ảnh hưởng execution**, lưu `selected skill`, `rank`, `latency`, `truncated`, `hit/miss`, rồi so với actual downstream success.
- **Priority:** **High**.
- **Confirmed facts:** Commit thêm hai methods vào shadow experiment và telemetry path hiện có; selectors được capped và deterministic-tested.
- **Analysis:** Đây là một cách production-friendly để cải tiến agents: **observe first, switch later**.
- **Recommendation:** Với QA/research/interview agents, thêm `shadow_decision` cho skill/tool/plan selection và giữ execution path hiện tại cho đến khi đủ sample.
- **Uncertainty:** Source public không cho biết acceptance threshold hoặc online metric cụ thể mà Codex dùng để promote selector.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Thiết kế skill routing theo **multi-signal retrieval**, không chỉ description matching

- **Problem:** Một skill catalog lớn thường có nhiều skills với mô tả gần nhau. Query ngắn như “tiếp tục”, “fix cái này”, “review lại” gần như không đủ để lexical/semantic routing chọn đúng.
- **Proposed improvement:** Xây candidate score từ nhiều channels: `current query`, `recently invoked skills`, `structured routing metadata/dependencies`, `lexical exact/weighted match`; sau đó fuse rankings bằng deterministic method như RRF.
- **Why it may work:** Codex #38993 đang shadow-test chính pattern `recent-use + character routing + lexical`, với integration test recover skill đã invoke ở earlier turn. [Source](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor/Codex skills, Claude Code skill-like commands/workflows, QA agents có phase-based flow, research agents, code-review agents, interview agents.
- **Limitations:** Recent-use signal có thể gây inertia — agent cứ chọn skill cũ dù task đã đổi.
- **Risks:** Feedback loop sai nếu một selection error làm recent history tiếp tục bias các turn sau.
- **Test method:** Tạo dataset multi-turn gồm `continue`, `switch domain`, `ambiguous pronoun`, `cold start`, `exact command`, `skill reused after gap`; đo Recall@K, MRR, task success và wrong-skill persistence.

### B. Tách **discovery metadata** khỏi full skill procedure

- **Problem:** Nếu mỗi skill inject cả full instructions để router đọc, context phình nhanh và router có thể bị nhiễu bởi procedural details.
- **Proposed improvement:** Catalog chỉ chứa routing card ngắn: `name`, `purpose`, `inputs`, `dependencies`, `tags`, `examples`, `negative triggers`; full skill procedure chỉ load sau selection.
- **Why it may work:** Codex vừa vừa thêm context budget cho skill catalog (#38978), vừa đầu tư routing-card selectors (#38993), cho thấy discovery surface và execution content là hai concerns riêng. [Skill budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Skill routing](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Reusable `.cursor/rules` + skills, Codex skill catalog, internal role kits, knowledge-transfer systems.
- **Limitations:** Metadata quá ngắn làm giảm recall; metadata quá dài lại quay về context bloat.
- **Risks:** Skill authors optimize descriptions cho router thay vì correctness của procedure.

### C. Config resolution cần **provenance**

- **Problem:** Agent config ngày càng có model defaults, workspace rules, environment restrictions, local overrides và task-level parameters.
- **Proposed improvement:** Mỗi resolved value lưu `value`, `source`, `sourceVersion`, `precedence`, `resolvedAt`.
- **Why it may work:** Guardian v2 model defaults chỉ áp dụng khi local field chưa set, nên precedence trực tiếp ảnh hưởng behavior. [Codex #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Suitable use cases:** Model routing, permissions, review thresholds, context budgets, tool policies.
- **Limitations:** Tăng metadata/telemetry.
- **Risks:** Nếu provenance chỉ log mà không có explain view thì vẫn khó debug.

### D. Tách **Visual Evidence Budget** khỏi text context budget

- **Problem:** Browser agent dễ tạo nhiều screenshots gần giống nhau.
- **Proposed improvement:** Theo dõi riêng `image_count`, `image_bytes`, `image_hash`, `evidence_priority`, `redaction_status`; chỉ forward selected images.
- **Why it may work:** Guardian v2 đã implement bounded visual transcript 4 ảnh/8 MiB. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** Playwright/Selenium QA agents, browser research, UI incident debugging.
- **Limitations:** Không có universal optimal budget.
- **Risks:** Over-compaction có thể loại mất visual root cause.

## 4. Agent, Workflow, and Loop Engineering

### A. Dùng **shadow decisions** trước khi thay router/planner/tool selector

- **Problem:** Thay selection logic trực tiếp vào production khiến regression khó phân biệt giữa model, router và downstream execution.
- **Technique:** Candidate selector chạy song song, chỉ emit decision telemetry; production selector vẫn thực thi. Sau đủ samples, compare `agreement`, `gold/verified correctness`, `downstream success`, `latency`, `cost`.
- **Expected benefit:** Giảm blast radius và tạo evidence trước rollout.
- **Failure risks:** Shadow metric có thể không correlate với actual task success; cần downstream labels.
- **Suitable use cases:** Skill selection, model routing, reviewer selection, test-plan generation, code-review severity routing.

### B. Thêm **recent procedural memory**, nhưng có decay và switch detection

- **Problem:** Multi-turn agent mất workflow continuity nếu mỗi turn route độc lập.
- **Technique:** Maintain recent skill/tool IDs trong bounded LRU; khi query mới rõ ràng đổi domain, reduce recent-use weight hoặc reset history.
- **Expected benefit:** Better continuation for “tiếp tục”, “chạy lại”, “review phần còn lại”.
- **Failure risks:** Sticky wrong-route loop.
- **Suitable use cases:** QA agent chạy batches, research agent nhiều bước, interview agent đang đào sâu một engineering story, code-review agent theo module.
- **Concrete test:** Sau một turn cố ý route sai, đo số turns cần để router recover; đây là **error persistence** metric quan trọng.

### C. `Plan → Execute → Verify → Decide` cần **evidence symmetry**

- **Problem:** Executor thấy screenshot/tool output nhưng verifier chỉ nhận summary text.
- **Technique:** Store evidence in shared envelope and give verifier the minimum relevant raw evidence class.
- **Expected benefit:** Lower false pass/fail in browser/QA workflows.
- **Failure risks:** Privacy leakage, payload inflation.
- **Suitable use cases:** Playwright/Selenium QA, UI regression, incident triage.

### D. Permission changes phải invalidate approval assumptions

- **Problem:** Human approved một command dưới policy cũ nhưng environment/policy đã đổi.
- **Technique:** Bind approval cache to `policy_fingerprint + tool + command_scope + environment`.
- **Expected benefit:** Prevent stale approval from silently expanding authority.
- **Failure risks:** Excessive re-approval nếu fingerprint quá sensitive.
- **Suitable use cases:** Production tooling, CI/CD, database/migration agents, GitHub/Azure operations.

### E. Stop condition cho low-value loops

- **Problem:** Research/QA agents có thể repeat cùng search/test mà không có new evidence.
- **Technique:** Track `new_evidence_count`, `same_failure_signature`, `same_candidate_set`, `confidence_delta`; nếu 2–3 iterations không tạo new evidence, re-plan hoặc stop.
- **Expected benefit:** Giảm cost và tránh “busy loop”.
- **Failure risks:** Stop quá sớm khi external state đang chậm thay đổi.
- **Suitable use cases:** Debugging, flaky test investigation, monitoring, research agents.

- **Workflow có thể cải thiện:** .NET architecture agents, Codex/Cursor rule sets, permission-sensitive automation.
- **What to change/test:** Object trả về final config + provenance cho `model`, `context budgets`, `skills`, `permissions`, `review`, `tools`, `evidence policy`.
- **Expected benefit:** Rút ngắn root-cause analysis khi “cùng prompt nhưng behavior khác”.
- **Effort:** **Half a day**.

### 4. Chuẩn hóa `EvidenceEnvelope` cho QA/browser agents

- **Relevance:** Browser agents hiện thường lưu screenshot/video như artifact cuối, nhưng verifier cần một bounded subset để đánh giá correctness.
- **Workflow có thể cải thiện:** Playwright QA Agent, Selenium scheduled runner, UI regression review.
- **What to change/test:** Metadata tối thiểu: `type`, `source`, `capturedAt`, `hash`, `redacted`, `stepId`, `artifactRef`, `reasonIncluded`.

## 7. Opportunities and Trends to Watch

### 1. **Skill routing đang chuyển từ prompt heuristics sang retrieval/ranking systems**
- **What is changing:** Codex đang có routing cards, lexical selectors, recent-use LRU và fusion experiments.
- **Why it matters:** Skill ecosystems càng lớn, routing quality càng trở thành bottleneck độc lập với model quality.
- **Opportunity:** Build reusable skill-router eval framework hoặc vendor-neutral catalog format.
- **Risk:** Over-engineering router khi catalog còn rất nhỏ.
- **Status:** **Growing**.

### 2. **Agent memory tách thành procedural recency thay vì transcript-only memory**
- **What is changing:** Recent invoked skill IDs được dùng như ranking signal.
- **Why it matters:** Nhiều continuity needs có thể giải quyết bằng structured short-term state rẻ hơn full transcript retrieval.
- **Opportunity:** `RecentActions`, `RecentSkills`, `CurrentPhase`, `LastVerifiedCheckpoint` thành explicit memory channels.
- **Risk:** Sticky errors và stale state.
- **Status:** **Early signal**.

### 3. **Model capability registries đang trở thành runtime infrastructure**
- **What is changing:** Guardian defaults được phân phối qua model catalog; OpenCode cũng cho thấy effective model limits phụ thuộc auth/route.
- **Why it matters:** `model-name` không đủ mô tả runtime behavior.
- **Opportunity:** Unified capability probe/profile layer cho multi-provider agents.
- **Risk:** Registry stale hơn provider reality.
- **Status:** **Growing**.

### 4. **Multimodal evidence sẽ đi sâu vào verifier/safety layers**
- **What is changing:** Guardian v2 có image transcript support.
- **Why it matters:** Browser agents và visual QA không thể được verify tốt bằng text-only context trong mọi case.
- **Opportunity:** Evidence compaction, screenshot redaction, multimodal eval harness.
- **Risk:** Privacy/cost/latency.
- **Status:** **Early signal**.

### 5. **Permission engineering đang rời prompt layer và đi vào runtime policy algebra**
- **What is changing:** Restrictive environment overlays, policy fingerprints, secret scrubbing.
- **Why it matters:** Production agents cần enforceable security guarantees.
- **Opportunity:** Permission-aware agent middleware cho .NET/MCP/GitHub/Azure workflows.
- **Risk:** Complexity và approval fatigue nếu policy model không explainable.
- **Status:** **Growing**.
