## 1. Executive Summary

### 1. Cost nên là first-class telemetry của agent run
- **One-sentence summary:** Codex app-server có thể emit `codex.turn_cost` qua OTLP cho OpenAI API-key sessions sau completed hoặc aborted turns, kèm estimated USD cost, interruption state, model, speed và reasoning effort. [Codex #39006, 17/08/2026](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Affected skill area:** Agent evaluation, observability, model comparison, cost/latency optimization.
- **Why it matters:** Pass/fail không đủ để đánh giá production fitness; cần biết workflow thành công với chi phí và độ trễ nào.
- **Practical implication:** Mỗi run nên lưu `outcome + latency + cost + model + reasoning effort + retry/interruption`.
- **Priority:** **Critical**.
- **Confirmed facts:** Worker chỉ chạy khi OTLP exporter bật và provider là OpenAI; theo dõi turn lifecycle, completed/aborted state, response count; query turn-cost endpoint; emit estimated USD cost; preserve organization/project headers; bounded polling/retry; re-probe sau auth changes. [Source](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Analysis:** Đây là nền tảng cho `success-per-dollar`, `verification-cost`, `retry-cost` và phát hiện low-value loops.
- **Recommendation:** Thêm cost telemetry vào QA/research/code-review/interview agents và so sánh theo task family, không so model bằng benchmark chung chung.
- **Uncertainty:** Turn-cost endpoint trong commit không được xác nhận là public contract; chỉ nên lấy pattern observability.

### 2. Async verifier cần explicit committed-progress signal
- **One-sentence summary:** Codex sửa Guardian tests để đợi `latest_scored_tool_call` advance thay vì chỉ thấy `SecurityRiskScore`, vì output có thể visible trước khi progress state hoàn tất. [Codex #39007, 17/08/2026](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Affected skill area:** Async verification, concurrency, deterministic tests, multi-agent handoff.
- **Why it matters:** “Artifact đã xuất hiện” không đồng nghĩa “state machine đã commit xong”.
- **Practical implication:** Workflow nên có `Started → OutputProduced → StateCommitted → ReadyForConsumption`.
- **Priority:** **Critical**.
- **Confirmed facts:** Guardian stores risk score trước khi advance scored-tool counter; test cũ có thể assert quá sớm; test mới chờ progress counter. [Source](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Analysis:** Pattern áp dụng trực tiếp cho background jobs, CI artifacts, browser screenshots, MCP tasks và asynchronous handoff.
- **Recommendation:** Tests/consumers phải await version/completion markers thay vì polling existence của file/row/message.
- **Uncertainty:** Đây là implementation evidence từ Guardian, không phải API guarantee tổng quát.

### 3. Managed policy phải thắng local feature preference

- **Affected skill area:** Permissions, human approval, enterprise configuration, reviewer architecture.
- **Why it matters:** Local preference không được phép mở lại một review path mà organization policy đã khóa.
- **Practical implication:** Tách `desiredConfig` và `effectiveConfig`; policy layer phải monotonic và authoritative.
- **Priority:** **Critical**.
- **Confirmed facts:** Disable áp dụng cho local requirements và cloud config bundles; `config/read` phản ánh effective `false`; Guardian v2 vẫn được giữ khi `user` reviewer còn allowed. [Source](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)

### 4. Async verdict cần freshness bound riêng với confidence
- **One-sentence summary:** Guardian v2 bỏ qua approval review khi risk score chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async reviewers, state synchronization, approval systems.
- **Why it matters:** Confidence cao không bù được verdict đã stale với state mới.
- **Practical implication:** Reviewer output cần bind với `subjectVersion`, evidence hash và reviewer version.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call`; nếu lag vượt config thì approval review trả `None`; default `3`; tests cover boundary, stale state và recovery. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** `confidence`, `freshness`, `evidence completeness` là ba axes độc lập của verifier correctness.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, evidenceHash, score, decision, createdAt, reviewerVersion }` và reject stale verdict trước execution.
- **Uncertainty:** `3` là Guardian default, chưa có bằng chứng tối ưu cho workload khác.

- **Affected skill area:** Failure recovery, long-running agents, verifier reliability.
- **Why it matters:** Retry per phase dễ làm total attempts phình ra hoặc tạo low-value loops.
- **Practical implication:** Mỗi logical step cần `RetryBudget`, error classifier, idempotency check và stop condition.
- **Priority:** **High**.
- **Confirmed facts:** Retry transient connection/stream/network failures, overload, HTTP `5xx` và `429`; auth `401` có recovery path; tests cover `503` recovery và bounded exhaustion. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Khi ghép với turn-cost telemetry, retry nên được đánh giá theo incremental cost/latency, không chỉ retry count.
- **Recommendation:** Hết budget thì chuyển `ReplanRequired`; side-effecting tool calls cần idempotency key/checkpoint trước retry.
- **Uncertainty:** `2` retries chỉ là Guardian implementation choice.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Treat skill catalog as a retrieval index, not a giant system prompt
- **Problem:** Nhiều reusable skills dễ làm catalog metadata chiếm context, trong khi full instructions hiếm khi cần đồng thời.
- **Proposed improvement:** Giữ routing metadata ngắn; rank candidates; chỉ load full skill sau selection; áp budget riêng cho catalog.
- **Why it may work:** Codex vừa có bounded catalog budget vừa shadow-test multi-signal routing, cho thấy selection quality và token budget đang được xử lý độc lập. [Budget](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Routing](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor skills, Codex skills, QA skill library, interview/code-review skill packs, architecture playbooks.
- **Limitations:** Nếu routing metadata nghèo, giảm budget có thể làm recall tụt.
- **Risks:** Overfitting router vào vocabulary của benchmark; recent-use bias có thể kéo nhầm skill sang task mới.

### B. Separate policy from procedure
- **Problem:** Rules/skills thường trộn “cách làm việc” với “được phép làm gì”.
- **Proposed improvement:** Tách `Procedure`, `Policy`, `Capability`, `ApprovalState` và `EnvironmentRestriction` thành các lớp độc lập.
- **Why it may work:** Codex managed reviewer requirements có thể override local feature preference; environment exec policy chỉ được restrict; token scrubbing được enforce tại runtime. [Reviewer policy](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576) · [Exec policy](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929) · [Secret scrubbing](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)

## 4. Agent, Workflow, and Loop Engineering

### 1. `Plan → Execute → Verify → CommitState → Decide`
- **Problem:** Nhiều loop coi verifier output xuất hiện là đủ để chuyển bước.
- **Technique:** Thêm explicit `CommitState`/version marker sau verifier hoặc executor background work.
- **Expected benefit:** Giảm race conditions, flaky tests và premature handoff.
- **Failure risks:** Deadlock nếu completion marker không được phát khi partial failure.
- **Suitable use cases:** QA agents, async research pipelines, CI-driven code review, background test runners.

### 2. `Attempt → ClassifyFailure → RepairState → RetryWithinBudget → Replan/Fail`
- **Problem:** Blind retry tạo chi phí, latency và duplicate side effects.
- **Technique:** Shared logical-operation retry budget + failure taxonomy + optional state repair + idempotency guard.
- **Expected benefit:** Recovery tốt hơn với transient failures nhưng dừng được low-value loops.
- **Failure risks:** Misclassification có thể retry permanent failures hoặc dừng quá sớm.
- **Suitable use cases:** MCP/API calls, browser automation, model streaming, Git operations, CI/CD actions.

### 3. Freshness-aware verification
- **Problem:** Verifier chạy bất đồng bộ có thể đánh giá action N nhưng verdict được áp cho action N+4.
- **Technique:** Bind verdict với `subjectVersion`; enforce max lag hoặc exact-version match cho high-risk operations.
- **Expected benefit:** Ngăn stale approval/review state.
- **Failure risks:** Quá strict có thể gây nhiều re-review và tăng cost.
- **Suitable use cases:** Destructive commands, database writes, deployment, permission changes, financial/security-sensitive workflows.

### 4. Cost-aware stop conditions
- **Problem:** Agent có thể tiếp tục “cải thiện” dù marginal value thấp.
- **Technique:** Theo dõi cumulative cost/latency/retries cùng quality delta; stop hoặc replan khi không còn improvement có thể đo được.
- **Expected benefit:** Giảm low-value loops và giúp model/router decisions có evidence.
- **Failure risks:** Cost cap quá thấp có thể cắt task khó trước khi đạt chất lượng cần thiết.
- **Suitable use cases:** Research, code review, architecture exploration, test-fix-retest loops.
