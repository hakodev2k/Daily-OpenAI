## 1. Executive Summary

### 1. Cost cần trở thành first-class telemetry của agent run, không chỉ là billing report cuối tháng
- **One-sentence summary:** Codex app-server giờ có thể emit `codex.turn_cost` qua OTLP cho OpenAI API-key sessions sau completed hoặc aborted turns, với estimated USD cost, interruption state, model, speed và reasoning effort. [Codex #39006, 17/08/2026](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Affected skill area:** Agent evaluation, observability, model comparison, cost/latency optimization.
- **Why it matters:** Không thể đánh giá một agent loop chỉ bằng success/failure; hai workflow cùng task success nhưng khác 3× cost hoặc 2× latency là những hệ thống khác nhau về production fitness.
- **Practical implication:** Mỗi agent turn nên có telemetry kết hợp `outcome + latency + token/cost + interruption + model + reasoning effort` để support regression và routing decisions.
- **Priority:** **Critical** cho agent platform có production traffic.
- **Confirmed facts:** Worker chỉ khởi động khi OTLP exporter bật và provider là OpenAI; theo dõi turn lifecycle, response count, completed/aborted state; query turn-cost endpoint; emit estimated USD cost cùng model/speed/reasoning effort; preserve organization/project headers; bounded tracking, retry pending/transient failures; re-probe sau auth changes. [Source](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Analysis:** Cost observability nên được dùng như một eval dimension, không phải hậu kiểm tài chính. Nó mở đường cho `quality-per-dollar`, `success-per-dollar`, `verification-cost`, `retry-cost` và `cost of low-value loops`.
- **Recommendation:** Với QA/research/code-review agents, log tối thiểu `runId, stepId, model, reasoningEffort, startedAt, completedAt, status, latencyMs, estimatedCostUsd, retryCount, verifierCostUsd, outcome`.
- **Uncertainty:** Đây là estimated turn cost từ endpoint nội bộ của Codex app-server; không nên giả định API này là public contract hoặc cost estimator này hoàn hảo cho hệ thống khác.

### 2. Async verifier correctness phải dựa trên **committed progress state**, không chỉ “artifact đã xuất hiện”
- **One-sentence summary:** Codex sửa Guardian approval tests để đợi `latest_scored_tool_call` advance thay vì chỉ chờ `SecurityRiskScore` tồn tại, vì score được lưu trước khi progress counter được cập nhật. [Codex #39007, 17/08/2026](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Affected skill area:** Async verification, concurrency, deterministic tests, race-condition prevention.
- **Why it matters:** Một result object có thể đã visible nhưng related state machine chưa hoàn tất; test hoặc consumer đọc quá sớm sẽ tạo flaky behavior và false confidence.
- **Practical implication:** Async agents cần explicit completion/freshness markers thay vì suy luận “có output = work done”.
- **Priority:** **Critical**.
- **Confirmed facts:** Guardian stores `SecurityRiskScore` trước khi increment `latest_scored_tool_call`; test cũ chỉ chờ score có thể chạy approval assertion khi sampler vẫn đang update progress state; test mới chờ counter advance. [Source](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Analysis:** Đây là pattern chung cho background jobs, browser screenshots, test artifacts, CI reports, MCP tasks và multi-agent handoff: output visibility và state completion là hai events khác nhau.
- **Recommendation:** Dùng explicit lifecycle `Started -> OutputProduced -> StateCommitted -> ReadyForConsumption`; tests phải await `StateCommitted` hoặc version counter, không chỉ file/row/message xuất hiện.
- **Uncertainty:** Commit là test-level fix cho Guardian, nhưng pattern race-condition được suy ra từ implementation evidence chứ không phải một API guarantee tổng quát.

### 3. Managed reviewer policy phải thắng local feature preference
- **One-sentence summary:** Codex force-disable Guardian v2 nếu managed `allowed_approvals_reviewers` không cho phép reviewer `user`, kể cả khi local config bật `guardianv2 = true`. [Codex #39005, 17/08/2026](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Affected skill area:** Permission boundaries, human approval, enterprise config, reviewer architecture.
- **Why it matters:** Local feature config không được phép re-enable một reviewer path mà policy tổ chức đã chủ động loại bỏ.
- **Practical implication:** Config layering nên tách `desiredConfig` khỏi `effectiveConfig`; policy/requirements là authoritative constraints, không phải “một file config khác”.
- **Priority:** **Critical**.
- **Confirmed facts:** Disable áp dụng cho local requirements và cloud config bundles; Guardian v2 vẫn được preserve khi `user` reviewer còn được phép; `config/read` trả effective `false` khi bị override. [Source](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Analysis:** Đây là concrete evidence cho monotonic policy model: lower-level preference không được mở rộng authority bị higher-level policy cắt bỏ.
- **Recommendation:** Mọi agent feature có security/approval effect nên resolve theo `FeatureDesired ∩ OrganizationPolicy ∩ EnvironmentPolicy ∩ HumanApproval`.
- **Uncertainty:** Không nên suy rộng rằng mọi Codex feature đã dùng cùng precedence model.

### 4. Async risk/review verdict cần **freshness bound** riêng với confidence
- **One-sentence summary:** Guardian v2 bỏ qua approval review nếu risk score chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async reviewers, approval systems, agent state synchronization.
- **Why it matters:** Score có thể chính xác với action cũ nhưng stale với action hiện tại; confidence cao không bù được freshness kém.
- **Practical implication:** Reviewer output nên bind với `subjectVersion`/`toolCallIndex` và evidence hash.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call`; nếu lag vượt config thì approval review trả `None`; default lag = 3; tests cover boundary và recovery. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** `confidence`, `freshness`, `evidence completeness` là ba axes độc lập của verifier correctness.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, evidenceHash, decision, score, createdAt, reviewerVersion }` và reject stale verdict trước execution.
- **Uncertainty:** `3` tool calls không có bằng chứng là optimal cho workload khác.

### 5. Retry phải bounded trên toàn logical operation
- **One-sentence summary:** Guardian sampler dùng shared retry budget tối đa 2 lần cho connection lease, request start và stream consumption. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, long-running agents, verifier reliability.
- **Why it matters:** Retry từng phase riêng có thể phình attempt count hoặc tạo low-value loops; retry chỉ một phase thì bỏ sót transient failure ở phase khác.
- **Practical implication:** Logical step nên có `RetryBudget`, error classifier, idempotency check và stop condition.
- **Priority:** **High**.
- **Confirmed facts:** Retry categories gồm timeout/connection/network, retryable/stream errors, overload, HTTP 5xx và `429`; tests verify `503` recovery và stop khi budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Cost telemetry từ #39006 làm retry engineering đáng đo hơn nữa: cần biết `cost of retry` chứ không chỉ retry count.
- **Recommendation:** Sau retry budget hết, chuyển `ReplanRequired`; log incremental cost và latency của từng attempt.
- **Uncertainty:** `2` retries chỉ là Guardian implementation choice.

### 6. Skill systems đang trưởng thành theo ba hướng: **bounded catalog + hybrid routing + recent-use memory**
- **One-sentence summary:** Codex vừa thêm skill-catalog token budget vừa shadow-test RRF selectors kết hợp recent skill history, routing-card matches và optional lexical relevance. [Budget #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Routing #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Affected skill area:** Context engineering, reusable skills, memory, routing evals.
- **Why it matters:** Tăng số skills mà không có retrieval/budget sẽ làm context phình và routing giảm precision.
- **Practical implication:** Skill platform nên tách `catalog metadata`, `selection`, `full skill load`, `usage history` và `eval telemetry`.
- **Priority:** **High**.
- **Confirmed facts:** `[skills].max_context_tokens` default 2% context, cap 10k; selectors dùng RRF `K=10`, cap 50 candidates, tests recover prior-turn skill và deterministic ranking. [Sources above]
- **Analysis:** Mục tiêu phù hợp hơn là `task success per catalog token`, không phải “model biết càng nhiều skills càng tốt”.
- **Recommendation:** Benchmark matrix `catalog budget × router strategy × task family`; chạy candidate router ở shadow mode trước production.
- **Uncertainty:** Chưa có public benchmark chứng minh selector/budget nào tốt nhất.

### 7. Review pipeline đang trở thành **policy-aware + model-aware + multimodal + freshness-aware**
- **One-sentence summary:** Trong cùng ngày, Guardian nhận model-catalog defaults, transcript images, stale-score guard và managed reviewer policy override. [Defaults #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7) · [Images #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e) · [Freshness #39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1) · [Policy #39005](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Affected skill area:** QA/browser verification, security review, evidence engineering, approval orchestration.
- **Why it matters:** Review correctness không chỉ phụ thuộc prompt; nó phụ thuộc correct model profile, evidence symmetry, policy authority và temporal freshness.
- **Practical implication:** Một verifier run cần provenance đầy đủ để reproduce verdict.

- **Confirmed facts:** Model catalog can provide Guardian defaults; image transcript opt-in, max 4 images/8 MiB; stale scores ignored beyond configured lag; managed reviewer requirements can disable Guardian v2. [Sources above]

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Tách **skill discovery metadata** khỏi full skill procedure
- **Problem:** Catalog lớn làm prompt/context phình; model phải đọc nhiều skill không liên quan.
- **Proposed improvement:** Render catalog metadata ngắn (`name`, `purpose`, `triggers`, `constraints`, `dependencies`) trong budget; lazy-load full procedure sau selection.
- **Why it may work:** Codex đã thêm explicit catalog token budget và shadow routing, cho thấy discovery và execution instructions đang được xử lý như hai concerns khác nhau. [#38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor skills/rules, Codex skills, Claude Code reusable workflows, QA/research/interview/code-review skill catalogs.
- **Limitations:** Metadata quá ngắn có thể giảm recall; metadata quá dài phá budget.
- **Risks:** Skill descriptions tối ưu cho router nhưng không phản ánh behavior thật; cần eval chống keyword gaming.
- **Recommendation:** Tạo 20–30 benchmark prompts có ground-truth skill; đo top-1/top-3 recall ở budgets 500/1000/2000/default.
- **Uncertainty:** Không có public benchmark nói budget nào tối ưu.

### B. Rules nên mô tả **invariants**, không cố gánh runtime policy
- **Problem:** Nhiều agent setups dùng rules file để nói “không chạy destructive command”, nhưng tool runtime vẫn có quyền thực thi.
- **Proposed improvement:** Rules chỉ mô tả intent/procedure; runtime enforcement chịu trách nhiệm permissions, env scrubbing, approval, network/file scope.
- **Why it may work:** Codex environment exec policy chỉ được tighten và secret được scrub khỏi child processes/hooks sau env merge. [Policy #38942](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929) · [Secret #38941](https://github.com/openai/codex/commit/89e297729ebc1a8c243cef73c7ab64cd842ecd5a)
- **Suitable use cases:** Cursor rules, Claude Code hooks, Codex skills, CI/CD agents, database migration agents.
- **Limitations:** Cần infrastructure support; prompt-only frameworks khó enforce.
- **Risks:** False sense of safety nếu UI hiển thị “restricted” nhưng subprocess inheritance vẫn rộng.
- **Recommendation:** Mọi high-risk tool có deterministic preflight permission check và post-merge env scrub.

### C. Context handoff cần **version + evidence hash**, không chỉ summary text
- **Problem:** Multi-agent handoff dễ dùng stale summary hoặc evidence không còn đúng với state hiện tại.
- **Proposed improvement:** Handoff packet gồm `subjectVersion`, `facts`, `assumptions`, `evidenceRefs`, `evidenceHash`, `openQuestions`, `decision`, `confidence`, `createdAt`.
- **Why it may work:** Stale Guardian scores bị reject theo tool-call lag; approval tests phải đợi committed progress. [#39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1) · [#39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Suitable use cases:** Planner→Executor, Executor→Verifier, Researcher→Writer, QA Runner→Reviewer, Architecture Analyst→Decision Maker.
- **Limitations:** Versioning overhead cho simple tasks.
- **Risks:** Hash/version tồn tại nhưng không được consumer enforce thì chỉ là metadata trang trí.
- **Recommendation:** Consumer reject handoff nếu version lệch hoặc required evidence missing.

## 4. Agent, Workflow, and Loop Engineering

### A. `Plan -> Execute -> Verify -> Cost/State Check -> Decide`
- **Problem:** Loop truyền thống verify correctness nhưng không kiểm soát cost hoặc stale state.
- **Technique:** Sau verifier, thêm gate kiểm tra `freshness`, `policy`, `retry budget`, `incremental cost`, `progress delta`.
- **Expected benefit:** Dừng low-value loops sớm; tránh dùng stale verdict; có dữ liệu cost-aware replan.
- **Failure risks:** Quá nhiều gates làm workflow phức tạp và latency tăng.
- **Suitable use cases:** QA automation, web/browser agents, code-fix loops, research loops, CI incident remediation.
- **Evidence:** Turn cost telemetry (#39006), stale-score guard (#39001), bounded retry (#38997).
- **Recommendation:** Stop/replan nếu một trong các điều kiện xảy ra: retry budget exhausted, no measurable progress after 2 attempts, verifier stale, cost budget exceeded, policy blocks action.

### B. Async verifier cần **two-phase completion**
- **Problem:** Output có thể xuất hiện trước khi internal progress/state commit hoàn tất.
- **Technique:** Tách `OutputProduced` và `ReviewStateCommitted`; downstream chỉ consume sau phase 2.
- **Expected benefit:** Giảm flaky tests, race-condition approvals và inconsistent dashboards.
- **Failure risks:** Deadlock nếu phase-2 signal bị mất; cần timeout/failure state.
- **Suitable use cases:** Parallel reviewers, background LLM judge, browser screenshot analysis, CI artifact analysis.
- **Evidence:** #39007 trực tiếp cho thấy `SecurityRiskScore` visible trước `latest_scored_tool_call` advance.
- **Recommendation:** Dùng monotonic sequence/version hoặc durable completion event, không poll object existence.

### C. Retry cần **classification + bounded budget + escalation path**
- **Problem:** Generic retry biến permanent failures thành low-value loops.
- **Technique:** Error categories `Transient`, `AuthRecoverable`, `PolicyBlocked`, `InvalidInput`, `Quota`, `Permanent`; chỉ một số category retry.
- **Expected benefit:** Giảm cost/latency và false progress.
- **Failure risks:** Misclassification transient→permanent hoặc ngược lại.
- **Suitable use cases:** API/MCP/WebSocket, browser navigation, flaky tests, Git/CI integrations.
- **Evidence:** Guardian retry classifier và bounded attempts. [#38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Recommendation:** `retry exhausted -> replan/root-cause`, không `retry forever`.

### D. Shadow mode cho routing/planning changes
- **Problem:** Đổi router/planner trực tiếp có thể silently degrade nhiều task families.
- **Technique:** Run candidate decision layer song song nhưng không điều khiển execution; compare active vs shadow choices/outcomes.
- **Expected benefit:** Có evidence trước rollout.
- **Failure risks:** Shadow cost tăng; offline outcome attribution khó nếu candidate không thực sự execute.
- **Suitable use cases:** Skill selection, model routing, verifier threshold, planner decomposition.
- **Evidence:** Codex records multiple candidate skill selectors trong existing shadow experiment. [#38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Recommendation:** Log `activeChoice`, `shadowChoices`, `selectionLatency`, `candidateRecall`, `finalOutcome`.

### Analysis

## 7. Opportunities and Trends to Watch

### Trend 1 — **Cost-aware agent evaluation**
- **What is changing:** Cost đang đi vào run-level telemetry thay vì chỉ billing dashboard. [#39006](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Why it matters:** Agent quality cần được tối ưu theo quality/latency/cost cùng lúc.
- **Opportunity:** Build eval dashboards cho `success-per-dollar`, `retry cost`, `verifier cost`, `cost by skill/model/workflow`.
- **Risk:** Tối ưu cost quá mức làm giảm quality hoặc safety.
- **Status:** **Growing**.

### Trend 2 — **Temporal consistency as an agent-safety primitive**
- **What is changing:** Verifier verdict giờ được bound với progress/freshness thay vì dùng indefinite state. [#39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1) · [#39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Why it matters:** Async multi-agent systems ngày càng dễ gặp race/stale-result bugs.
- **Opportunity:** Versioned handoff/evidence libraries cho agent orchestration.
- **Risk:** Over-engineering cho simple synchronous tasks.
- **Status:** **Growing**.

### Trend 3 — **Policy precedence becoming explicit runtime state**
- **What is changing:** Managed reviewer policy có thể force-disable local safety/reviewer feature và effective config được expose. [#39005](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Why it matters:** Enterprise agents cần explainable authority resolution.
- **Opportunity:** Policy-resolver components, configuration explainers, permission diff tools.
- **Risk:** Complex precedence trees become hard to reason about without tooling.
- **Status:** **Growing**.

### Trend 4 — **Skill catalogs becoming retrieval systems**
- **What is changing:** Token budget + hybrid routing + recent-use memory + shadow eval.
- **Why it matters:** Skills at scale behave more like search/retrieval than static prompt injection.
- **Opportunity:** Vendor-neutral skill registry/router/eval tooling.
- **Risk:** Routing complexity may exceed benefits for small catalogs.
- **Status:** **Growing**.

### Trend 5 — **Observability-first agent architecture**
- **What is changing:** Cost, retry, interruption, reasoning effort, policy override, progress version increasingly become first-class state.
- **Why it matters:** Agent systems without structured telemetry are hard to debug or improve safely.
- **Opportunity:** OpenTelemetry conventions for agents: traces/spans/metrics around plan, tool, verifier, approval, retry, handoff.
- **Risk:** High-cardinality telemetry and accidental sensitive-data capture.
- **Status:** **Early signal → Growing**.
