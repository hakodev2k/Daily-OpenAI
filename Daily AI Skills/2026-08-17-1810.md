## 1. Executive Summary

### 1. Guardian v2 bắt đầu nhận **visual evidence** từ transcript và tool outputs

- **One-sentence summary:** Codex `main` thêm `features.guardianv2.transcript.include_images`, cho phép Guardian v2 nhận ảnh gần đây từ user/assistant messages và configured tool outputs; image context bị giới hạn ở **4 ảnh gần nhất** và **8 MiB tổng**, và `detail` hint được loại khi tạo sampling request. [Codex #38987, 17/08/2026](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Multimodal QA, browser agents, safety/verifier pipelines, evidence collection.
- **Why it matters:** Browser/UI automation thường tạo evidence bằng screenshot. Nếu executor nhìn thấy ảnh nhưng reviewer/guardian chỉ thấy text transcript, hệ thống có **asymmetric context** và có thể đánh giá sai trạng thái thật.
- **Practical implication:** Screenshot cần được model như first-class evidence với source, timestamp, hash và redaction status; verifier chỉ nhận bounded subset liên quan.
- **Priority:** **Critical** cho browser/UI agents; **High** cho coding agents có image-bearing tool outputs.
- **Confirmed facts:** Setting là opt-in, mặc định `false`; source lấy ảnh từ user/assistant messages và tool outputs; tối đa 4 ảnh, 8 MiB tổng; tests cover configuration parsing và forwarding ảnh. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Analysis:** Verification channel nên có access tới cùng evidence class mà execution channel đã dùng. Đây là pattern quan trọng cho QA agents, browser agents và incident agents.
- **Recommendation:** Chuẩn hóa `EvidenceEnvelope { type, source, capturedAt, hash, redacted, artifactRef, confidence }`; text verifier và visual verifier dùng cùng envelope.
- **Uncertainty:** Chưa có evidence public rằng stable Codex `0.147.0` đã ship Guardian v2 image transcript behavior hoặc feature này là default path cho hosted Codex.

### 2. Multimodal context cần **budget + recency + deduplication**, không phải giữ mọi screenshot

- **One-sentence summary:** Codex bounded image transcript theo số lượng và tổng bytes thay vì forward toàn bộ visual history. [Codex #38987](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Affected skill area:** Context engineering, long-running agents, browser automation, cost/latency control.
- **Why it matters:** Screenshot lặp lại nhiều giữa các bước UI; giữ toàn bộ ảnh dễ tăng cost/latency mà không tăng decision quality.
- **Practical implication:** Browser/QA agents nên có `visual evidence budget`, dedupe bằng hash, giữ ảnh lỗi + trạng thái hiện tại + một ảnh pre-action khi cần.
- **Priority:** **High**.
- **Confirmed facts:** Codex dùng bounded queue và evict ảnh cũ khi vượt giới hạn count/bytes.
- **Analysis:** Đây là multimodal equivalent của context compaction.
- **Recommendation:** Test ba policies: `latest-only`, `latest+failure`, `latest+failure+pre-action`; compare verifier accuracy, latency và input cost.
- **Uncertainty:** 4 ảnh/8 MiB là implementation choice của Codex, chưa có benchmark chứng minh tối ưu cho mọi domain.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Thêm **Visual Evidence Budget** bên cạnh Text/Skill Context Budget

- **Problem:** Agent thường có text-budget nhưng screenshot/tool images được attach theo kiểu “có bao nhiêu gửi bấy nhiêu”.
- **Proposed improvement:** Quản lý riêng:
  - `max_images`
  - `max_image_bytes`
  - `recency_window`
  - `dedupe_by_hash`
  - `must_keep_failure_state`
  - `redaction_required`
- **Why it may work:** Codex Guardian v2 mới dùng count/byte bounds cho transcript images. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)
- **Suitable use cases:** Playwright/Selenium QA agents, browser agents, UI incident debugging, screenshot-based code review evidence.
- **Limitations:** Dedupe bằng file hash có thể bỏ sót ảnh visually similar nhưng semantically khác; perceptual hash tốt hơn nhưng tăng complexity.
- **Risks:** Screenshot có PII/secrets; visual evidence phải đi qua redaction/data-classification policy trước verifier.
- **Recommendation:** Log `why_kept`, `why_dropped` cho mỗi visual artifact để audit context compaction.

### B. Tối ưu skill metadata cho **routing**, không cho procedural completeness

- **Problem:** Skill descriptions dài làm catalog phình và cạnh tranh context.
- **Proposed improvement:** Metadata discovery chỉ giữ `name`, `trigger`, `outcome`, `exclusions`; full procedure load sau selection.
- **Why it may work:** Codex thêm explicit catalog budget và shared rendering constraints. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Cursor rules/skills, Codex skills, Claude Code reusable workflows, internal agent catalogs.
- **Limitations:** Trigger quá ngắn gây collisions giữa skills.
- **Risks:** Agent chọn wrong skill nhưng vẫn tự tin thực thi.
- **Recommendation:** Mỗi skill có 3 positive + 3 negative routing examples và regression set chung.

### C. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Một giant rules file dễ trộn permission rules, coding conventions, workflow và task specifics.
- **Proposed improvement:**
  - `policy/`: security/permissions/approval.
  - `skills/`: reusable procedures.
  - `context/`: repo/domain facts.
  - `task/`: objective, acceptance criteria, current evidence.
- **Why it may work:** Environment-specific restrictive policy trong Codex cung cấp evidence rõ rằng policy composition nên có scope/precedence riêng. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor rules, Claude Code `CLAUDE.md`, Codex skills, QA/research agents.
- **Limitations:** Nhiều files hơn, cần deterministic loading order.
- **Risks:** Duplicate/conflicting instructions.
- **Recommendation:** Viết precedence contract ngắn và test conflict cases.

### D. Provenance cho facts/assumptions/inferences

- **Problem:** Long-running agents dễ biến inference thành fact sau vài vòng.
- **Proposed improvement:** Tại decision points, bắt schema `FACT`, `ASSUMPTION`, `INFERENCE`, `RECOMMENDATION`, `UNKNOWN`, kèm evidence refs khi là fact.
- **Why it may work:** Giúp verifier kiểm tra reasoning outputs bằng deterministic structure thay vì prose dài.
- **Suitable use cases:** Research agents, architecture review, incident RCA, interview story verification.
- **Limitations:** Tăng verbosity/token use.
- **Risks:** Label đúng nhưng evidence yếu.
- **Recommendation:** Chỉ enforce ở decision boundaries, không bắt mọi câu.

## 4. Agent, Workflow, and Loop Engineering

### A. `Execute → Capture Evidence → Verify` phải dùng cùng evidence envelope

- **Problem:** Executor dùng screenshot/tool output nhưng verifier chỉ nhận textual summary.
- **Technique:** Mọi step tạo `EvidenceEnvelope`; verifier nhận envelope trực tiếp hoặc bounded projection của nó.
- **Expected benefit:** Giảm context mismatch giữa executor và verifier; dễ audit hơn.
- **Failure risks:** Privacy leak, artifact explosion, stale screenshots.
- **Suitable use cases:** QA agents, browser automation, UI regression, visual incident triage.
- **Recommended test:** 30 failure scenarios, compare text-only verifier vs text+bounded-image verifier; đo verdict accuracy, false approval, latency và cost.

### B. Stop low-value loops bằng **same-signature failure detection**

- **Problem:** Agents dễ lặp lại cùng action với cùng failure signature.
- **Technique:** Hash normalized failure state (`error type + stage + target + key evidence`). Sau 2 lần cùng signature, force `REPLAN` thay vì retry.
- **Expected benefit:** Giảm wasted tool calls và tránh destructive repetition.
- **Failure risks:** Signature normalization quá thô có thể coi hai failures khác nhau là một.
- **Suitable use cases:** Selenium/Playwright, CI fix agents, database migration agents, API debugging.
- **Recommendation:** Store `attempt`, `failure_signature`, `hypothesis`, `changed_variable`, `next_action`.

### C. Approval cache phải phụ thuộc **policy revision**

- **Problem:** Approval cũ có thể trở nên không hợp lệ sau policy/config change.
- **Technique:** Approval key gồm `action fingerprint + policy fingerprint + environment + user/role`.
- **Expected benefit:** Không reuse permission trong context đã thay đổi.
- **Failure risks:** Quá nhiều fresh approvals nếu fingerprint thay đổi vì noise.
- **Suitable use cases:** Deploy agents, production data tools, package install, privileged CLI actions.
- **Evidence:** Codex environment-policy change bind cached approval với policy fingerprint. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### D. Durable state nên ở project/run artifacts, không ở transcript

- **Problem:** Chat transcript phình, khó resume/audit/fork.
- **Technique:** Project-level facts/rules; run-level plan/checkpoints; artifacts/evidence ở storage riêng; transcript chỉ là interaction log.
- **Expected benefit:** Resume và multi-agent handoff tốt hơn.
- **Failure risks:** State divergence nếu write-back không atomic.
- **Suitable use cases:** Research agents, QA suites, interview intelligence, code review systems.

- **Existing workflow improved:** Research agents, Interview Intelligence, code review agents, architecture workflows.
- **What to change/test:** Tách durable `ProjectContext` khỏi `RunContext`; evidence/decisions có IDs và provenance; transcript chỉ là raw history.
- **Expected benefit:** Context handoff gọn hơn và regression evaluation dễ hơn.
- **Effort:** **Several days** nếu migrate hệ thống hiện có.
- **Confirmed facts:** Codex experimental Project APIs model lifecycle riêng cho project/thread. [Source](https://github.com/openai/codex/commit/3b4569a920f6442a23ad724a922810ac5ed1dd2a)

### 5. Thêm policy fingerprint vào high-risk approval workflow

- **Relevance:** Khi agent được phép deploy/write DB/run privileged commands, approval phải gắn với exact policy state.
- **Existing workflow improved:** CI/CD agent, Azure DevOps/GitHub Actions automation, production support agent.
- **What to change/test:** Approval record chứa `actionHash`, `policyHash`, `environment`, `expiresAt`; policy thay đổi → invalidate.

- **Evidence:** Pattern được Codex source áp dụng vào command approval cache. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

## 7. Opportunities and Trends to Watch

### 1. **Multimodal verifier/guardian pipelines** — **Growing**
- **What is changing:** Visual artifacts đang đi vào verification/safety context thay vì chỉ executor context.
- **Why it matters:** Browser/UI agents không thể được đánh giá tốt chỉ bằng text logs.
- **Opportunity:** Build reusable evidence envelope + visual verifier layer cho QA/browser agents.
- **Risk:** PII, screenshot retention, visual prompt injection, increased cost.
- **Evidence:** Codex Guardian v2 image transcript support. [Source](https://github.com/openai/codex/commit/37cf6c84c086229ed78d69e726b965c0252e9b3e)

### 2. **Context budgets per surface** — **Growing**
- **What is changing:** Context không còn được coi là một pool vô hạn; skill catalog và visual evidence đều có explicit bounds.
- **Why it matters:** Cost/latency/accuracy trade-offs có thể được benchmark thay vì cảm tính.
- **Opportunity:** Internal `ContextBudgetManager` cho skills, repo context, memory, evidence, tools.
- **Risk:** Over-optimization cắt mất evidence quan trọng.

### 3. **Runtime-enforced permission composition** — **Established → maturing**
- **What is changing:** Permission boundaries dịch từ prompt conventions sang policy/runtime layers.
- **Why it matters:** Security invariants phải tồn tại dù model reasoning sai.
- **Opportunity:** Policy engine dùng chung cho QA/research/deploy agents.
- **Risk:** Policy complexity và approval fatigue.

### 4. **Durable project state ngoài transcript** — **Growing**
- **What is changing:** Agent products dần tách workspace/project identity khỏi conversation/run.
- **Why it matters:** Long-running systems cần resume, fork, audit, retention và state migration.
- **Opportunity:** Shared state schema cho research/QA/interview/code-review systems.
- **Risk:** State divergence và migration complexity.

### 5. **Provider-native adapters phía sau unified governance** — **Growing**
- **What is changing:** Multi-provider tools giữ native API semantics thay vì flatten tất cả thành compatibility layer.
- **Why it matters:** Tool calls, reasoning controls, streaming và usage semantics khác nhau theo provider.
- **Opportunity:** .NET provider capability registry + native adapters + shared telemetry.
- **Risk:** More adapter maintenance; no guarantee native route is always better.
- **Evidence:** OpenCode native OpenAI/Anthropic passthrough work. [Source](https://github.com/anomalyco/opencode/commit/cba6b5f2f74080239cdc7405efcb83219c980136)
