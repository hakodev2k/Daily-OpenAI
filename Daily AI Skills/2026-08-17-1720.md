## 1. Executive Summary

### 1. Codex skill-catalog token budget là thay đổi mới quan trọng nhất cho Context Engineering

- **One-sentence summary:** Codex `main` vừa thêm `[skills].max_context_tokens` để override token budget dùng cho available-skills catalog; giá trị phải dương, bị cap ở 10.000 tokens, và khi unset vẫn dùng mặc định 2% model context window. [Codex #38978, 17/08/2026](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Affected skill area:** Skills architecture, context budgeting, skill discovery, prompt efficiency.
- **Why it matters:** Khi số reusable skills tăng, metadata discovery có thể cạnh tranh trực tiếp token với requirements, repository context, evidence và conversation state.
- **Practical implication:** Skill catalog nên được coi là một context surface có ngân sách riêng và được benchmark như retrieval system thay vì inject càng nhiều càng tốt.
- **Priority:** **Critical** cho hệ thống có nhiều skills; **High** cho coding agent cá nhân.
- **Confirmed facts:** Commit thêm `SkillsConfig.max_context_tokens`, schema yêu cầu minimum 1, configured value capped ở 10.000; tests cover parsing, override, cap và rendering trong configured budget.
- **Analysis:** Context Engineering nên quản lý **allocation**, không chỉ “rút ngắn prompt”: mỗi surface phải có budget, telemetry và failure mode riêng.
- **Recommendation:** Tạo `ContextBudget` cho ít nhất `Policy`, `Skill Catalog`, `Repository Context`, `Task Evidence`, `Conversation`, `Tool Results`; log estimated/actual token usage cho từng surface.
- **Uncertainty:** Đây là source-level change trên `main`; stable `0.147.0` chưa được xác nhận hỗ trợ option này.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Treat **Skill Catalog** như một context surface có ngân sách riêng

- **Problem:** Khi số skills tăng, discovery metadata có thể chiếm context trước cả code, requirements và evidence.
- **Proposed improvement:** Đặt token budget cố định/adaptive cho catalog và đo usage thực tế.
- **Why it may work:** Codex vừa implement chính pattern này và có tests đảm bảo rendered catalog nằm trong configured budget. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Suitable use cases:** Codex skills, Cursor skill libraries, Claude reusable workflows, internal agent marketplaces.
- **Limitations:** Budget quá thấp có thể giảm skill discoverability hoặc làm descriptions bị shorten.
- **Risks:** Chọn budget theo cảm tính mà không eval recall.
- **Recommendation:** Benchmark 300/600/1200/2400-token catalog budgets trên cùng representative task set; đo routing accuracy, task success, tokens và latency.

### B. Tối ưu skill metadata cho **discovery**, không nhét full procedure vào catalog

- **Problem:** Description dài có vẻ “đầy đủ” nhưng làm catalog phình nhanh và tăng collision/noise.
- **Proposed improvement:** Discovery metadata chỉ chứa:
  - `name`
  - `when to use / trigger`
  - `expected outcome`
  - `important exclusions`

  Full procedure, commands, examples và validation rules chỉ load sau khi skill được selected.
- **Why it may work:** Progressive disclosure giữ discovery cheap nhưng preserve procedural depth.
- **Suitable use cases:** QA agent skills, research skills, code-review skills, architecture skills, deployment skills.
- **Limitations:** Metadata quá ngắn/ambiguous sẽ giảm retrieval quality.
- **Risks:** Hai skills có trigger gần nhau có thể collision.
- **Recommendation:** Mỗi skill nên có ít nhất 3 positive + 3 negative routing examples trong eval corpus.

### C. Tách `Policy`, `Procedure`, `Context`, `Task`

- **Problem:** Giant rules file trộn security, conventions, workflow steps và task-specific details; precedence trở nên mơ hồ.
- **Proposed improvement:**
  - `policy/`: deny/approval/data boundaries.
  - `skills/`: reusable procedures/checklists.
  - `context/`: architecture/repo/domain facts.
  - `task/`: objective, acceptance criteria, current evidence.
- **Why it may work:** Codex restrictive environment policy là evidence trực tiếp cho principle scope-aware policy composition. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)
- **Suitable use cases:** Cursor Rules/Skills, Claude Code project guidance, Codex skills, QA/research/review agents.
- **Limitations:** Nhiều files/layers hơn; cần deterministic precedence.
- **Risks:** Duplicate instructions hoặc contradictions nếu ownership không rõ.
- **Recommendation:** Precedence contract ngắn: `Policy > Environment Restriction > Task > Procedure Defaults`; context chỉ cung cấp facts, không grant permission.

### D. Gắn provenance cho assumption quan trọng

- **Problem:** Qua nhiều bước, inference dễ biến thành “fact” trong architecture review, RCA hoặc research.
- **Proposed improvement:** Dùng labels `FACT`, `ASSUMPTION`, `INFERENCE`, `RECOMMENDATION`, `UNKNOWN`; FACT phải có evidence ref.
- **Why it may work:** Tạo deterministic checkpoint cho verifier/reviewer agent.
- **Suitable use cases:** Research, code review, incident analysis, interview story verification, architecture planning.
- **Limitations:** Tăng verbosity/token usage.
- **Risks:** Correct label không đồng nghĩa strong evidence.
- **Recommendation:** Chỉ bắt provenance tại decision points, không cho mọi câu.

## 4. Agent, Workflow, and Loop Engineering

### A. `Discover → Route → Load → Execute → Verify` cho skill-based agents

- **Problem:** Loading toàn bộ procedures trước khi chọn skill gây context waste và tăng instruction conflicts.
- **Technique:**
  1. **Discover:** expose compact catalog trong budget.
  2. **Route:** chọn 0–N relevant skills.
  3. **Load:** chỉ load full selected skill bodies.
  4. **Execute:** chạy workflow.
  5. **Verify:** deterministic checks + evaluator.
- **Expected benefit:** Context nhỏ hơn, provenance rõ hơn, skill-level observability tốt hơn.
- **Failure risks:** Router miss, wrong-skill selection, excessive multi-skill fan-out.
- **Suitable use cases:** QA agents, code review agents, research agents, interview agents, .NET architecture assistants.
- **Recommendation:** Log `catalog_tokens`, `skills_seen`, `skills_selected`, `selection_reason`, `skill_body_tokens`, `outcome` để eval routing độc lập execution.

### B. Detect low-value loops bằng **same-signature failure** và **no-new-evidence**

- **Problem:** Agent có thể retry cùng approach dù failure signature không đổi hoặc tiếp tục search dù sources không có delta.
- **Technique:** Stop/re-plan khi:
  - cùng `error_signature` xuất hiện 2 lần;
  - N searches không tạo new evidence;
  - verifier confidence không tăng sau retry;
  - same tool/action lặp lại mà state hash không đổi.
- **Expected benefit:** Giảm token/tool waste và tăng khả năng root-cause analysis.
- **Failure risks:** Stop quá sớm với flaky system.
- **Suitable use cases:** Selenium/Playwright QA, CI fixing, research, debugging, code review.
- **Recommendation:** Sau stop condition, emit structured `WhyStopped + Evidence + NextHypothesis`, không chỉ `failed`.

### C. Approval cache phải phụ thuộc policy/version

- **Problem:** Approval cũ có thể trở nên không hợp lệ khi environment policy thay đổi.
- **Technique:** Cache key gồm `action + target + environment + policy_fingerprint + tool_version`.
- **Expected benefit:** Tránh stale approval granting authority ngoài current policy.
- **Failure risks:** Nhiều approval prompts nếu fingerprint quá nhạy.
- **Suitable use cases:** Deploy agents, database mutation, shell automation, Git/GitHub write operations.
- **Confirmed basis:** Codex environment-policy fingerprint được đưa vào cached approval keys. [Source](https://github.com/openai/codex/commit/e38290846c11424567c9c8226f2be8a2886c5929)

### D. Long-running agent state nên tách transcript khỏi durable artifacts

- **Problem:** Conversation grows indefinitely, khó resume/replay/audit.
- **Technique:** Durable state gồm project facts, decisions, checkpoints và evidence; transcript là ephemeral interaction log.
- **Expected benefit:** Resume deterministic hơn, context handoff ngắn hơn, dễ fork experiments.
- **Failure risks:** Stale project facts nếu không version/evidence-link.
- **Suitable use cases:** Research pipeline, interview intelligence, QA regression systems, architecture knowledge transfer.

## 7. Opportunities and Trends to Watch

### 1. **Context budgets trở thành explicit runtime controls** — **Growing**

- **What is changing:** Codex vừa expose budget riêng cho skill catalog thay vì chỉ dùng implicit percentage. [Source](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d)
- **Why it matters:** Agent frameworks sẽ cần quản lý nhiều context surfaces như resource allocation.
- **Opportunity:** Context profiler/optimizer cho rules, skills, repo guidance và tool schemas.
- **Risk:** Tối ưu token quá mức làm giảm retrieval recall/task quality.

### 2. **Skills chuyển từ static prompt files sang routed capability systems** — **Growing**

- **What is changing:** Skill catalogs, routing/search và budget constraints đang khiến skills giống retrieval/tool systems hơn giant instruction files.
- **Why it matters:** Quality phụ thuộc discovery/routing/evaluation, không chỉ skill content.
- **Opportunity:** Skill linter, routing benchmark, collision detector, catalog analyzer.
- **Risk:** Over-engineering small repositories có ít skills.

### 3. **Runtime governance tách khỏi prompt governance** — **Established / strengthening**

- **What is changing:** Permission overlays, approval fingerprints và secret isolation được enforce trong runtime.
- **Why it matters:** Model alignment/instructions không thể thay thế OS/process/tool permission boundaries.
- **Opportunity:** Reusable policy engine cho .NET agent runners/MCP gateways.
- **Risk:** Complex policy merges khó debug nếu thiếu decision trace.

### 4. **Project/workspace trở thành durable unit của agent state** — **Growing**

- **What is changing:** Experimental Codex Project APIs tách project lifecycle khỏi threads.
- **Why it matters:** Multi-run work cần stable scope ngoài conversation.
- **Opportunity:** Unified project/evidence/checkpoint model dùng chung cho QA, research, interview, architecture.
- **Risk:** Tight coupling vào experimental vendor APIs.

### 5. **Provider-native adapters bên dưới common governance layer** — **Growing**

- **What is changing:** OpenCode native passthrough cho OpenAI/Anthropic là signal chống lại lowest-common-denominator abstraction.
- **Why it matters:** Tool/reasoning/streaming semantics có thể khác đáng kể theo provider.
- **Opportunity:** .NET provider capability registry + regression harness.
- **Risk:** Adapter complexity tăng theo số provider/model/route.
