## 1. Executive Summary

### 1. Cost nên trở thành first-class telemetry của agent run
- **One-sentence summary:** Codex app-server có thể emit `codex.turn_cost` qua OTLP cho OpenAI API-key sessions sau completed hoặc aborted turns, kèm estimated USD cost, interruption state, model, speed và reasoning effort. [Codex #39006, 17/08/2026](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Affected skill area:** Agent evaluation, observability, model comparison, cost/latency optimization.
- **Why it matters:** Hai workflows cùng đạt task success nhưng chênh 2–3× cost hoặc latency không có cùng production fitness.
- **Practical implication:** Mỗi run nên log `outcome + latency + estimated cost + model + reasoning effort + retry/interruption` để phát hiện regression và low-value loops.
- **Priority:** **Critical**.
- **Confirmed facts:** Turn-cost worker chỉ chạy khi OTLP exporter bật và provider là OpenAI; theo dõi turn lifecycle, response count, completed/aborted state; query turn-cost endpoint; emit estimated USD cost; preserve organization/project headers; bounded polling/retry; re-probe sau auth changes. [Source](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)
- **Analysis:** Cost observability nên là một eval dimension, không phải billing hậu kiểm. Có thể đo `success-per-dollar`, `verification-cost`, `retry-cost` và `cost of low-value loops`.
- **Recommendation:** Với QA/research/code-review/interview agents, thêm telemetry `runId, stepId, model, reasoningEffort, latencyMs, estimatedCostUsd, retryCount, verifierCostUsd, outcome`.
- **Uncertainty:** Turn-cost endpoint trong commit không được xác nhận là public contract; nên lấy pattern observability, không phụ thuộc endpoint cụ thể.

### 2. Async verifier cần explicit committed-progress signal
- **One-sentence summary:** Codex sửa Guardian approval tests để đợi `latest_scored_tool_call` advance thay vì chỉ chờ `SecurityRiskScore` xuất hiện, vì score có thể visible trước khi progress state hoàn tất. [Codex #39007, 17/08/2026](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Affected skill area:** Async verification, deterministic testing, concurrency, multi-agent handoff.
- **Why it matters:** “Output đã tồn tại” không đồng nghĩa “state machine đã hoàn tất”. Consumer đọc quá sớm có thể tạo flaky behavior và false confidence.
- **Practical implication:** Workflow nên phân biệt `Started → OutputProduced → StateCommitted → ReadyForConsumption`.
- **Priority:** **Critical**.
- **Confirmed facts:** Guardian stores `SecurityRiskScore` trước khi advance `latest_scored_tool_call`; test cũ chờ score có thể assert approval quá sớm; test mới chờ progress counter. [Source](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Analysis:** Pattern này áp dụng cho background jobs, browser screenshots, CI artifacts, MCP tasks và multi-agent handoff.
- **Recommendation:** Tests/consumers phải await explicit completion/version markers thay vì polling file/row/message existence.
- **Uncertainty:** Đây là implementation evidence từ Guardian, không phải API guarantee tổng quát của Codex.

### 3. Managed reviewer policy phải thắng local feature preference
- **One-sentence summary:** Codex force-disable Guardian v2 nếu managed `allowed_approvals_reviewers` không cho phép reviewer `user`, kể cả khi local config bật `guardianv2 = true`. [Codex #39005, 17/08/2026](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Affected skill area:** Permission boundaries, human approval, enterprise config, reviewer architecture.
- **Why it matters:** Local preference không được phép re-enable một approval path mà organization policy đã loại bỏ.
- **Practical implication:** Agent platforms nên tách `desiredConfig` và `effectiveConfig`, với policy/requirements là authoritative constraints.
- **Priority:** **Critical**.
- **Confirmed facts:** Disable áp dụng cho local requirements và cloud config bundles; `config/read` phản ánh effective `false`; Guardian v2 vẫn có thể bật khi `user` reviewer còn allowed. [Source](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576)
- **Analysis:** Đây là concrete evidence cho monotonic policy model, không phải “last config wins”.
- **Recommendation:** Mọi feature liên quan approval/security nên resolve theo `FeatureDesired ∩ OrgPolicy ∩ EnvironmentPolicy ∩ HumanApproval`.
- **Uncertainty:** Không nên suy rộng rằng mọi Codex feature đã dùng cùng precedence model.

### 4. Async verdict cần freshness bound riêng với confidence
- **One-sentence summary:** Guardian v2 bỏ qua approval review nếu risk score chậm hơn latest tool activity quá `max_tool_call_lag`, mặc định 3 tool calls. [Codex #39001, 17/08/2026](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Affected skill area:** Async reviewers, agent state synchronization, approval systems.
- **Why it matters:** Một score có thể rất confident nhưng đã stale với current action.
- **Practical implication:** Reviewer output nên bind với `subjectVersion`/`toolCallIndex`, evidence hash và reviewer version.
- **Priority:** **Critical**.
- **Confirmed facts:** Codex track `latest_tool_call` và `latest_scored_tool_call`; nếu lag vượt config thì approval review trả `None`; default `3`; tests cover boundary và recovery. [Source](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)
- **Analysis:** `confidence`, `freshness`, `evidence completeness` là ba dimensions độc lập của verifier correctness.
- **Recommendation:** Chuẩn hóa `ReviewVerdict { subjectVersion, evidenceHash, decision, score, createdAt, reviewerVersion }` và reject stale verdict trước execution.
- **Uncertainty:** Default `3` không có bằng chứng tối ưu cho workload khác.

### 5. Retry phải bounded trên toàn logical operation
- **One-sentence summary:** Guardian sampler dùng shared retry budget tối đa 2 lần cho connection lease, request start và stream consumption. [Codex #38997, 17/08/2026](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Affected skill area:** Failure recovery, long-running agents, verifier reliability.
- **Why it matters:** Retry từng phase độc lập dễ phình total attempts hoặc tạo low-value loops.
- **Practical implication:** Mỗi logical step cần `RetryBudget`, error classifier, idempotency check và stop condition.
- **Priority:** **High**.
- **Confirmed facts:** Retry categories gồm timeout/connection/network, retryable/stream errors, overload, HTTP 5xx và `429`; tests cover `503` recovery và stop khi budget exhausted. [Source](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)
- **Analysis:** Khi kết hợp turn-cost telemetry, retry có thể được đánh giá bằng incremental cost và latency thay vì chỉ retry count.
- **Recommendation:** Sau retry budget hết, chuyển `ReplanRequired`; log cost/latency per attempt.
- **Uncertainty:** `2` retries chỉ là Guardian implementation choice.

## 3. Prompt, Skills, Rules, and Context Engineering

### A. Bounded context phải đi cùng retrieval quality
- **Problem:** Khi rules/skills tăng dần, catalog metadata tự nó bắt đầu chiếm context và có thể đẩy requirements/code/evidence ra ngoài budget.
- **Proposed improvement:** Tách catalog thành metadata ngắn để discovery; route candidates; chỉ lazy-load full skill khi cần. Đặt explicit context budget cho catalog.
- **Why it may work:** Codex hiện vừa thêm skill catalog token budget vừa thử hybrid router, tức là budget và selection đang được xử lý như hai vấn đề riêng nhưng bổ trợ nhau. [Budget #38978](https://github.com/openai/codex/commit/632e35ce8d5dec43b75dbf99f9e6fa52bed47c3d) · [Routing #38993](https://github.com/openai/codex/commit/ea10ae7d0fe6a2fb0614a32adb5e095853319355)
- **Suitable use cases:** Cursor rules/skills, Codex skills, Claude reusable instructions, QA/research/interview agent catalogs.
- **Limitations:** Router sai thì budget thấp càng làm recall tệ; tăng budget không sửa được ranking sai.
- **Risks:** Overfitting router vào exact names; stale recency signal; skill duplication.
- **Recommendation:** Đo `top-k recall`, downstream task success, token cost và wrong-skill rate theo matrix `budget × router`.

### B. Effective config phải có provenance
- **Problem:** User thấy feature “enabled” trong một config nhưng runtime lại disabled bởi organization policy hoặc model-specific defaults.
- **Proposed improvement:** Tách `desiredConfig`, `effectiveConfig`, `policyConstraints` và `provenance`.
- **Why it may work:** Codex `config/read` giờ phản ánh Guardian v2 effective disabled value khi managed reviewer policy loại `user`; Guardian defaults cũng có thể đến từ model catalog rồi bị local override. [Policy #39005](https://github.com/openai/codex/commit/02e9bfaac7577a3ab77a40de6b0c3cc37b934576) · [Defaults #38990](https://github.com/openai/codex/commit/8bf50439f2ebbcd98785c858e22174f919451cf7)
- **Suitable use cases:** Enterprise agent runners, repo-level rules, multi-model systems, Windows managed config.
- **Limitations:** Provenance model làm config system phức tạp hơn.
- **Risks:** Nếu UI chỉ hiển thị desired value, debugging vẫn khó.
- **Recommendation:** Mỗi resolved field nên expose `effectiveValue`, `source`, `overriddenBy`, `reason`.

### C. Context handoff nên truyền state đã commit, không truyền “best guess”
- **Problem:** Multi-agent handoff dễ đọc artifact trước khi producer hoàn tất mọi state updates.
- **Proposed improvement:** Handoff chỉ phát khi `StateCommitted`; dùng monotonic sequence/version.
- **Why it may work:** Guardian test fix chứng minh output visibility và progress completion có thể lệch nhau. [Codex #39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)
- **Suitable use cases:** Research → writer, executor → verifier, QA runner → report generator, CI → fix agent.
- **Limitations:** Cần durable state hoặc event semantics rõ.
- **Risks:** Nếu producer crash giữa OutputProduced và StateCommitted thì cần recovery path.
- **Recommendation:** Persist `producerVersion`, `artifactHash`, `state=Committed`, `completedAt`; consumer reject non-committed handoff.

## 4. Agent, Workflow, and Loop Engineering

### A. Retry budget + replan boundary
- **Problem:** Agent retry cùng strategy trên cùng failure signature tạo low-value loop.
- **Technique:** Shared retry budget cho logical operation; classify failure; retry transient errors; khi budget hết chuyển `ReplanRequired` thay vì tiếp tục.
- **Expected benefit:** Giảm infinite loops, giảm latency/cost tail, dễ debug.
- **Failure risks:** Retry non-idempotent actions có thể tạo side effect duplicate.
- **Suitable use cases:** API/MCP calls, browser automation, CI retries, verifier sampling.
- **Evidence:** Codex Guardian bounded retry across connect/start/stream và stop khi budget exhausted. [Codex #38997](https://github.com/openai/codex/commit/4885eb6c52c4d9915698671395aaa327072afca9)

### B. Freshness-aware verifier
- **Problem:** Async verifier có thể trả verdict đúng cho state cũ nhưng consumer áp vào state mới.
- **Technique:** Bind verdict vào subject version/tool-call index + evidence hash; enforce allowed lag.
- **Expected benefit:** Giảm stale approvals và false safety conclusions.
- **Failure risks:** Lag threshold quá thấp làm reviewer thường xuyên unavailable; quá cao làm stale verdict lọt qua.
- **Suitable use cases:** Browser QA, code-review agents, deployment approval, long-running execution loops.
- **Evidence:** Guardian v2 mặc định `max_tool_call_lag=3`, bỏ review khi lag vượt threshold. [Codex #39001](https://github.com/openai/codex/commit/8e89e98cf6d4d79f7add5c04ddd4bbd76b1594a1)

### C. Cost-aware agent evaluation
- **Problem:** Pass rate cao có thể che workflow dùng model quá đắt, quá nhiều retries hoặc verifier chiếm phần lớn chi phí.
- **Technique:** Emit run/turn-level cost cùng model, reasoning effort, latency, status và retry metadata.
- **Expected benefit:** So sánh workflow/model dựa trên `quality × cost × latency` thay vì cảm giác.
- **Failure risks:** Estimated cost có thể lag hoặc chưa được pricing đầy đủ.
- **Suitable use cases:** Model routing, prompt evals, QA agents, multi-agent decomposition.
- **Evidence:** Codex app-server turn-cost worker đợi các observed responses được priced, retry pending/transient failures có giới hạn và emit OTLP metric. [Codex #39006](https://github.com/openai/codex/commit/04caa22c8220c24b1428dbeaebcb744bf3875771)

### D. Explicit completion states cho async pipelines
- **Problem:** “Result exists” bị coi nhầm là “step complete”.
- **Technique:** `Started → OutputProduced → StateCommitted → ReadyForConsumption`, với completion version/counter.
- **Expected benefit:** Giảm flaky tests và race conditions giữa producer/consumer.
- **Failure risks:** Event lost hoặc state commit fail cần reconciliation.
- **Suitable use cases:** Background jobs, agents, browser recordings, test result aggregation, MCP tasks.
- **Evidence:** Guardian approval test phải chờ scored-tool-call progress thay vì chỉ thấy risk score. [Codex #39007](https://github.com/openai/codex/commit/def7ed55725052ac4119c759ff8b5952a5f955ee)

## 7. Opportunities and Trends to Watch

### 1. Agent observability chuyển từ token counting sang **cost + outcome + reasoning profile**
- **What is changing:** Turn-level cost được đưa vào telemetry pipeline thay vì chỉ billing backend.
- **Why it matters:** Model/routing/prompt decisions có thể được benchmark theo quality-per-dollar.
- **Opportunity:** Xây internal agent scorecard: success, latency, cost, retry, verifier overhead.
- **Risk:** Tối ưu cost quá mức có thể làm quality giảm nếu objective function kém.
- **Status:** **Growing**.

### 2. Async verifier đang được đối xử như distributed system component
- **What is changing:** Freshness lag, progress counters, committed state, bounded retries xuất hiện trực tiếp trong reviewer implementation.
- **Why it matters:** Agent review không còn chỉ là “gọi thêm một model”. Nó có consistency, concurrency và lifecycle problems.
- **Opportunity:** Reuse distributed-systems patterns: versioning, idempotency, commit markers, stale-read rejection.
- **Risk:** Quá nhiều state-machine complexity nếu workflow nhỏ.
- **Status:** **Growing**.

### 3. Security policy trở thành monotonic constraint, không phải prompt convention
- **What is changing:** Managed reviewer policy, restrictive exec policy và secret scrubbing đều enforce ở runtime/config layer.
- **Why it matters:** Prompt không đủ làm security boundary.
- **Opportunity:** Agent runner framework cho .NET với policy resolver, approval cache fingerprint và process env sanitizer.
- **Risk:** Permission model quá phức tạp gây blocked workflows và poor UX.
- **Status:** **Established** về nguyên tắc, **Growing** trong coding agents.

### 4. Skills đang chuyển từ static prompt injection sang retrieval system
- **What is changing:** Bounded catalog, hybrid ranking, recent-use memory, shadow evaluation.
- **Why it matters:** Skill count có thể scale mà không linearly tăng context.
- **Opportunity:** Vendor-neutral skill router/eval harness cho Cursor/Codex/Claude workflows.
- **Risk:** Router hidden failures khó phát hiện nếu không có shadow eval/ground truth.
- **Status:** **Experimental → Growing**.

### 5. Multimodal verifier cho browser/QA sẽ trở nên phổ biến hơn
- **What is changing:** Guardian can include bounded recent images from messages/tool outputs.
- **Why it matters:** Text-only verifier không thấy visual state mà executor dựa vào.
- **Opportunity:** Evidence-first QA agents với screenshot hash, DOM snapshot, network trace và expected-state assertions.
- **Risk:** PII/secrets trong screenshots, extra context cost, visual hallucination.
- **Status:** **Growing**.
