# Ý tưởng hôm nay: ReturnProof — Bộ hồ sơ bằng chứng hoàn trả hàng thương mại điện tử

## 1. Tóm tắt ý tưởng

ReturnProof là một web app/local-first tool giúp người mua hàng online tạo, lưu và đóng gói **bộ bằng chứng hoàn trả/khiếu nại** gồm video mở hộp, video đóng gói trả hàng, ảnh lỗi, mã vận đơn, ghi chú và mốc thời gian theo từng đơn hàng. Sản phẩm tập trung vào một vấn đề rất cụ thể: khi phát sinh hàng lỗi/sai/móp/vỡ, bằng chứng thường nằm rải rác trong thư viện ảnh, chat và ghi chú, khiến người dùng mất thời gian tìm, nén và gửi đúng nội dung.

- **Quy mô:** Medium
- **Thời gian MVP ước tính:** 2–3 tuần với một developer

### Observation

Trong thực tế, người dùng thường quay video bằng camera điện thoại rồi để chung với hàng trăm ảnh/video khác. Mã đơn, mã vận đơn, ảnh chụp màn hình chat và thời hạn phản hồi lại nằm ở nhiều nơi khác nhau. Công cụ ReturnProof không thay nền tảng thương mại điện tử; nó giải quyết phần **chuẩn bị và quản lý bằng chứng trước khi gửi**.

### Assumption

Giả định cần kiểm chứng là một nhóm người mua thường xuyên trên Shopee/Lazada/TikTok Shop sẽ thấy giá trị trong việc có một quy trình “mở hộp → ghi bằng chứng → đóng gói hoàn trả → xuất bộ hồ sơ” thay vì tự quản lý thủ công.

## 3. Người dùng mục tiêu

**Người dùng MVP:** người mua hàng online thường xuyên tại Việt Nam, đặc biệt là người mua đồ điện tử, phụ kiện, đồ gia dụng hoặc mặt hàng có giá trị trung bình/cao.

- **Bối cảnh:** mỗi tháng có nhiều đơn hàng, đôi lúc phát sinh hàng lỗi, sai mẫu, thiếu phụ kiện hoặc móp vỡ.
- **Pain point:** bằng chứng nằm rải rác; quên quay đúng chi tiết; file quá lớn; khó biết đã có đủ ảnh/video cần thiết chưa.
- **Workaround hiện tại:** camera điện thoại + thư viện ảnh + ghi chú + chat với shop + upload thủ công.
- **Lý do thử:** ứng dụng đưa checklist ngay lúc quay và gom toàn bộ chứng cứ vào một “case” duy nhất.

## 4. Giải pháp đề xuất

### Workflow chính

1. Người dùng tạo một `Return Case` và nhập mã đơn/mã vận đơn, tên sản phẩm, nền tảng mua hàng.
2. Ứng dụng hiển thị checklist quay bằng chứng phù hợp: 6 mặt kiện hàng, mã vận đơn, seal/tem, quá trình mở hộp, lỗi sản phẩm, phụ kiện.
3. Người dùng quay video trực tiếp trong web app hoặc tải video/ảnh có sẵn lên.
4. Hệ thống lưu metadata: thời gian, loại bằng chứng, kích thước, checksum, ghi chú.
5. App kiểm tra thiếu mục nào trong checklist và cảnh báo nếu file vượt ngưỡng cấu hình.
6. Khi cần hoàn trả, người dùng tạo thêm `Return Packing Evidence` với checklist đóng gói.
7. Hệ thống xuất một “evidence pack” gồm thư mục chuẩn hóa, manifest Markdown/PDF-light HTML và danh sách file để upload.

### Input

- Mã đơn hàng
- Mã vận đơn
- Tên sản phẩm
- Ảnh/video
- Ghi chú lỗi
- Deadline phản hồi nếu người dùng biết

### Processing

- Validate loại file/kích thước
- Tính SHA-256 cho từng file
- Chuẩn hóa tên file
- Đánh dấu loại bằng chứng
- Kiểm tra checklist completeness
- Tạo manifest

### Output

Ví dụ:

```text
ReturnCase-SHP-123456/
  01-package-six-sides.jpg
  02-waybill.jpg
  03-unboxing-continuous.webm
  04-product-defect.jpg
  05-accessories.jpg
  06-return-packing.webm
  manifest.md
```

### Key differentiator

Không phải gallery ảnh hay expense tracker. ReturnProof là **workflow evidence-first**, tối ưu cho khiếu nại/hoàn trả với checklist, provenance và packaging rõ ràng.

### Ví dụ end-to-end

Hà nhận một bàn phím cơ bị nứt góc. Trước khi mở hộp, Hà tạo case, app nhắc quay 6 mặt kiện + mã vận đơn. Sau khi mở, Hà đánh dấu “damaged item”, quay cận cảnh vết nứt và chụp seal hộp. Khi yêu cầu trả hàng được chấp nhận, app mở checklist đóng gói và Hà quay video đóng lại toàn bộ phụ kiện. Cuối cùng ReturnProof xuất manifest ghi rõ file nào chứng minh tình trạng bao bì, file nào chứng minh lỗi sản phẩm và file nào chứng minh trạng thái khi gửi trả.

## 5. Tại sao ý tưởng này đáng làm

- **Practical value:** giảm rủi ro quên bằng chứng quan trọng khi đã mở hộp xong.
- **Technical learning:** media capture, local file handling, checksums, metadata, privacy-preserving storage và progressive web app.
- **Solo-friendly:** MVP không cần tích hợp API thương mại điện tử; toàn bộ luồng có thể chạy local-first.
- **Có ích với ít người dùng:** chỉ cần chính developer và vài người thân dùng đã có giá trị.
- **Điểm thất bại:** người dùng có thể thấy “mở app trước khi unbox” là thêm một bước phiền phức.
- **Lý do mạnh nhất để không build:** nếu người dùng chỉ gặp khiếu nại rất hiếm, họ có thể không hình thành thói quen sử dụng công cụ trước khi mở kiện.

## 7. Luồng hoạt động

```text
User tạo case
→ nhập order/tracking data
→ chọn loại sự cố
→ hệ thống tạo checklist
→ user upload/quay media
→ validate type/size/duration
→ tính checksum + lưu metadata
→ đánh dấu checklist hoàn thành
→ lưu file local/server
→ user export evidence pack
→ gửi file lên nền tảng thương mại điện tử
→ cập nhật trạng thái case thủ công
```

### Alternative flows

- **File quá lớn:** app cảnh báo và cho phép người dùng chọn file khác; MVP không tự re-encode để tránh làm biến đổi bằng chứng gốc.
- **Camera bị từ chối quyền:** fallback sang upload file từ máy.
- **Browser không hỗ trợ codec mong muốn:** app kiểm tra `MediaRecorder.isTypeSupported()` và chọn codec khả dụng.
- **Thiếu một mục checklist:** vẫn cho export nhưng manifest hiển thị rõ `Missing Evidence`.
- **Người dùng đóng tab:** metadata được lưu local; file phải được commit vào local store trước khi hiển thị “saved”.

## 8. Kiến trúc đề xuất

### Kiến trúc MVP: modular monolith + local-first frontend

**Frontend:** Vue 3 PWA.

- Cần vì camera/file workflow là phần chính.
- Có thể chạy trực tiếp trên điện thoại.

**Backend:** ASP.NET Core .NET 10.

- Quản lý case, metadata, ZIP export và file endpoints.
- Có thể bỏ backend ở prototype đầu và dùng IndexedDB/OPFS hoàn toàn client-side, nhưng backend giúp dễ mở rộng self-hosted.

**Database:** SQLite cho MVP.

- Chỉ lưu metadata, không cần PostgreSQL ngay.

**File storage:** local disk volume.

- Tổ chức theo `CaseId`.
- Không upload cloud mặc định để giảm privacy risk.

**Background worker:** chưa cần.

- Thumbnail hoặc cleanup có thể chạy inline ở MVP.

**Queue/cache:** không cần.

**Authentication:** không cần cho bản single-user localhost; thêm local account khi public-hosted.

**AI:** không cần.

**Logging:** Serilog console + rolling file.

**Deployment:** Docker Compose trên mini PC/VPS hoặc chạy trực tiếp Windows/Linux.

## 9. Công nghệ đề xuất

### .NET 10 LTS

Microsoft hiện liệt kê .NET 10 là LTS, Active, với thời hạn hỗ trợ đến 14/11/2028. Nguồn: [.NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy).

- **Vì sao phù hợp:** stack quen thuộc, lifecycle dài.
- **Đơn giản hơn:** Minimal API một project.
- **Outgrow:** không cần đổi khi scale vừa; chỉ tách worker nếu media processing trở nên nặng.

### ASP.NET Core

- API, static hosting và ZIP streaming trong cùng app.
- Alternative: Node.js/Fastify nếu muốn full JavaScript.

### EF Core + SQLite

- Dễ setup cho single-user.
- PostgreSQL chỉ cần khi có multi-user/cloud.

### Vue 3 + Vite + PWA

- UI nhanh, dễ dùng trên mobile browser.
- Alternative: vanilla JS ở spike đầu tiên.

### MediaRecorder API

MDN xác nhận MediaStream Recording API cho phép ghi dữ liệu từ `MediaStream` để xử lý/lưu file, và `MediaRecorder` đã được hỗ trợ rộng rãi trên browser hiện đại. Nguồn: [MDN MediaStream Recording API](https://developer.mozilla.org/en-US/docs/Web/API/MediaStream_Recording_API).

### File System / File API

File API cho phép web app đọc file mà người dùng cấp qua file picker hoặc drag-and-drop. File System API hỗ trợ đọc/ghi và quản lý file trong secure context, tùy khả năng browser. Nguồn: [MDN File API](https://developer.mozilla.org/en-US/docs/Web/API/File_API), [MDN File System API](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API).

### Docker

- Phù hợp self-hosted.
- Không bắt buộc trong dev.

### Playwright

- Test luồng tạo case, upload và export.
- Camera thật không cần E2E toàn bộ; mock MediaStream ở test.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Checklist, validation, checksum, file organization và export đều deterministic. Dùng AI ở MVP chỉ tăng cost, latency và privacy risk mà không cải thiện phần cốt lõi.

AI chỉ có thể hữu ích ở phase sau để:

- OCR/tóm tắt nội dung ảnh/video.
- Sinh mô tả khiếu nại từ metadata.

Ngay cả khi thêm, output AI phải chỉ là draft và không được dùng để xác nhận sự thật thay cho bằng chứng gốc.

## 14. Các bài toán kỹ thuật đáng học

1. **Media capture trên browser** — hiểu `getUserMedia`, `MediaRecorder`, codec compatibility và permission lifecycle.
2. **File integrity** — hash, duplicate detection, provenance và immutable original files.
3. **Large file handling** — streaming upload/download thay vì load toàn file vào RAM.
4. **Local-first privacy** — thiết kế hệ thống hữu ích mà không cần cloud.
5. **Failure recovery** — tránh trạng thái metadata đã lưu nhưng file chưa lưu hoặc ngược lại.

## 15. Rủi ro và cách xử lý

### Người dùng quên mở app trước khi unbox

**Mitigation:** PWA shortcut trên home screen, “Start unboxing” flow chỉ 1 tap.

### File video lớn

**Mitigation:** hiển thị size realtime; không tự thay đổi file gốc; optional transcoding chỉ tạo bản copy.

### Privacy

Video có thể chứa địa chỉ, số điện thoại, mã vận đơn.

**Mitigation:** local-first, không analytics mặc định, không cloud upload mặc định, user-controlled retention.

### Security

Không serve file theo path từ request trực tiếp; dùng ID mapping, sanitize tên file và chặn path traversal.

### Chính sách nền tảng thay đổi

**Mitigation:** checklist preset có version/date; không hard-code rằng một rule luôn đúng. Hiển thị “tham khảo chính sách hiện tại của nền tảng”.

### Adoption thấp

**Mitigation:** định vị như PWA rất nhẹ, không yêu cầu signup. Nếu người dùng vẫn không dùng trước khi mở hộp, dừng project sớm.

3. File vượt limit được cảnh báo nhưng file gốc không bị sửa.
4. Restart server, case vẫn tham chiếu đúng file.
5. Export ZIP chứa đúng manifest, hash và toàn bộ evidence đã chọn.

## 17. Cách đo dự án có hữu ích hay không

- **Task completion:** % case có đủ các mục checklist bắt buộc.
- **Time saved:** thời gian từ lúc bắt đầu chuẩn bị đến lúc có evidence pack.
- **Error rate:** % export thất bại hoặc file missing.
- **Repeated use:** người dùng có tạo case lần thứ hai hay không.
- **Reliability:** 100% file lưu phải verify hash đúng khi export.
- **North-star thực tế:** người dùng có thể tìm toàn bộ bằng chứng cho một đơn hàng trong dưới 30 giây.

## 20. Việc cần làm ngay hôm nay

### Thời lượng: 90 phút

### Development objective

Tạo vertical slice đầu tiên:

> Create Return Case → upload một ảnh → tính SHA-256 → hiển thị evidence trong case.

### Files/components cần tạo

```text
ReturnProof.sln
src/ReturnProof.Api/
  Program.cs
  Data/AppDbContext.cs
  Models/ReturnCase.cs
  Models/EvidenceItem.cs
  Endpoints/ReturnCaseEndpoints.cs
  Endpoints/EvidenceEndpoints.cs
src/ReturnProof.Web/
  src/views/CaseView.vue
  src/components/EvidenceUploader.vue
```

### Setup commands

```bash
dotnet new sln -n ReturnProof
dotnet new webapi -n ReturnProof.Api -o src/ReturnProof.Api
dotnet sln add src/ReturnProof.Api/ReturnProof.Api.csproj
cd src/ReturnProof.Api
dotnet add package Microsoft.EntityFrameworkCore.Sqlite
dotnet add package Microsoft.EntityFrameworkCore.Design
```

Frontend:

```bash
npm create vite@latest src/ReturnProof.Web -- --template vue
cd src/ReturnProof.Web
npm install
npm run dev
```

### First vertical slice

API:

```http
POST /api/cases
POST /api/cases/{caseId}/evidence
GET  /api/cases/{caseId}
```

Khi upload file:

1. Stream file xuống `storage/{caseId}/`.
2. Tính SHA-256 bằng `SHA256.Create()` hoặc `SHA256.HashDataAsync` phù hợp implementation.
3. Lưu metadata vào SQLite.
4. Trả về:

```json
{
  "fileName": "package.jpg",
  "sizeBytes": 483221,
  "sha256": "...",
  "category": "package-condition"
}
```

### Expected result

Mở trang Vue, tạo case “Keyboard damaged”, kéo một ảnh vào uploader, sau vài giây thấy tên file, dung lượng và SHA-256 xuất hiện dưới case.

### Verification checklist

- [ ] `dotnet run` khởi động API.
- [ ] Vue gọi được API.
- [ ] Case được lưu trong SQLite.
- [ ] File thực sự xuất hiện dưới `storage/{caseId}`.
- [ ] SHA-256 trong DB khớp hash tính lại từ file.
- [ ] Refresh browser vẫn thấy evidence.
- [ ] Upload filename chứa `../` không thể thoát khỏi storage directory.

### Stop condition

Dừng session khi **một file ảnh có thể được upload, lưu an toàn, hash, persist metadata và hiển thị lại sau refresh**. Chưa làm camera recording, ZIP export, authentication hay AI trong buổi đầu.
