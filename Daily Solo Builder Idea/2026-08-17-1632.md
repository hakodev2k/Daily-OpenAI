# Ý tưởng hôm nay: ImportGuard — CSV/Excel Dry-Run Sandbox cho hệ thống nghiệp vụ

## 1. Tóm tắt ý tưởng

**ImportGuard** là một công cụ web/self-hosted giúp developer hoặc admin import dữ liệu CSV/Excel vào hệ thống một cách an toàn bằng quy trình **map cột → validate → dry-run → xem diff → commit**, thay vì upload file rồi hy vọng dữ liệu đúng. Công cụ đặc biệt hữu ích cho các hệ thống nội bộ có những thao tác nhập hàng loạt như employee, timesheet, leave balance, license, inventory, customer hoặc configuration.

- **Project size:** Medium
- **MVP ước tính:** 2–3 tuần làm ngoài giờ
- **Người dùng chính:** developer/backend engineer hoặc system admin phụ trách import dữ liệu nghiệp vụ
- **Bài toán cốt lõi:** lỗi import hàng loạt thường chỉ được phát hiện sau khi dữ liệu đã ghi vào database, lúc đó rollback và điều tra rất tốn thời gian

## 2. Bài toán thực tế

Các ứng dụng doanh nghiệp thường có nhu cầu nhập dữ liệu hàng loạt từ Excel/CSV: nhân viên mới, cập nhật mã phòng ban, billable hours, license, danh sách khách hàng, danh mục sản phẩm hoặc migration dữ liệu từ hệ thống cũ.

Cách triển khai phổ biến hiện nay thường rơi vào một trong các kiểu:

- viết script SQL tạm thời;
- viết console app chạy một lần;
- tạo API import trực tiếp;
- upload Excel rồi validate ngay trong request;
- dùng bulk insert để đẩy dữ liệu vào bảng đích;
- import vào production rồi sửa các dòng lỗi thủ công.

Vấn đề là file import thực tế thường có nhiều loại lỗi:

- thiếu cột;
- sai kiểu dữ liệu;
- duplicate key;
- mã tham chiếu không tồn tại;
- email hoặc identifier trùng;
- dữ liệu hợp lệ về kiểu nhưng sai business rule;
- file dùng dấu phẩy/dấu chấm khác locale;
- một dòng lỗi khiến cả batch thất bại;
- partial success làm database rơi vào trạng thái khó kiểm soát.

**Confirmed fact:** SQL Server `SqlBulkCopy` hỗ trợ bulk copy và có thể chạy trong transaction để rollback khi lỗi; PostgreSQL có lệnh `COPY` hỗ trợ định dạng CSV và nhiều tuỳ chọn import. Điều này chứng minh phần ghi dữ liệu hàng loạt là khả thi bằng cơ chế native của database, nhưng các API đó không tự giải quyết business validation hay preview thay đổi trước khi commit. [Microsoft Learn — SqlBulkCopy](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/sql/single-bulk-copy-operations) · [PostgreSQL COPY](https://www.postgresql.org/docs/18/sql-copy.html)

**Observation:** các primitive database tập trung vào tốc độ ingest, trong khi nhu cầu của application layer thường là biết trước “nếu import file này thì hệ thống sẽ thay đổi gì”. Đây là khoảng trống mà ImportGuard tập trung xử lý.

**Assumption cần kiểm chứng:** nhiều team nội bộ chấp nhận mất 15–60 phút cho mỗi lần chuẩn bị, validate và sửa file import. Phase 0 phải đo trực tiếp bằng 3–5 lần import thật trước khi đầu tư sâu.

## 3. Người dùng mục tiêu

### Primary user

Backend developer hoặc technical admin đang duy trì một web application có chức năng import dữ liệu định kỳ.

### Context sử dụng

Ví dụ:

- HR gửi file `Employees-August.xlsx`;
- finance gửi file billable hours;
- admin cần cập nhật 500 license records;
- migration cần đổi department code cho 2.000 nhân viên;
- QA cần seed một bộ dữ liệu business-like vào staging.

### Main pain point

Người thực hiện không biết chắc file có an toàn cho đến khi chạy import thật.

### Current workaround

- kiểm tra Excel thủ công;
- chạy query SQL tìm duplicate;
- import vào local database trước;
- tạo bản backup;
- viết script rollback;
- gửi file qua lại để sửa lỗi.

### Lý do họ sẽ thử ImportGuard

Nếu công cụ có thể trả lời trước ba câu hỏi này thì đã tạo giá trị:

1. Dòng nào sẽ fail?
2. Dòng nào sẽ insert/update/skip?
3. Nếu bấm Commit thì database sẽ thay đổi chính xác ra sao?

## 4. Giải pháp đề xuất

ImportGuard cung cấp workflow cố định:

**Upload file → Map column → Parse → Validate → Resolve references → Dry-run → Diff report → User approve → Commit**

### Input

- CSV hoặc XLSX;
- target import profile;
- mapping giữa file column và field;
- optional import mode: Insert Only, Upsert hoặc Validate Only.

### Processing

1. Parse file theo streaming để tránh load toàn bộ file lớn vào RAM.
2. Normalize header và giá trị.
3. Validate schema.
4. Validate data type.
5. Validate business rules.
6. Resolve foreign references.
7. So sánh với dữ liệu hiện tại.
8. Tạo `ImportPlan` gồm Insert / Update / Skip / Error.
9. Chỉ khi user approve mới chạy commit.

### Output

Dashboard ví dụ:

```text
Rows: 1,248
Valid: 1,221
Errors: 27

Planned changes
+ Insert: 184
~ Update: 731
= Unchanged: 306
! Error: 27
```

User có thể click vào từng row để xem:

```text
EmployeeCode: NV-0142
DepartmentCode
  Before: HN-BE
  After : HN-PLATFORM

Title
  Before: Senior Developer
  After : Technical Lead
```

### Tự động hóa

- parsing;
- mapping theo profile;
- validation;
- duplicate detection;
- reference lookup;
- diff generation;
- import audit log.

### User vẫn kiểm soát

- target environment;
- mapping;
- rule profile;
- bỏ qua/sửa lỗi;
- quyết định commit;
- rollback nếu policy cho phép.

### Key differentiator

Không cố trở thành một ETL platform. Điểm khác biệt là **application-safe import với dry-run business-aware**.

### Ví dụ end-to-end

Admin upload file gồm 300 nhân viên.

ImportGuard phát hiện:

- 230 record không thay đổi;
- 42 record đổi department;
- 18 employee mới;
- 6 employee code duplicate trong file;
- 4 department code không tồn tại.

Admin tải `errors.csv`, sửa 10 dòng lỗi rồi upload lại.

Dry-run lần 2:

```text
Insert 18
Update 52
Skip 230
Error 0
```

Admin bấm **Commit**. ImportGuard thực hiện transaction, ghi audit log và trả report cuối cùng.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Có thể dùng ngay cho các dự án cá nhân hoặc hệ thống nội bộ thay vì viết một import script mới mỗi lần.

### Technical learning value

Project chạm vào nhiều bài toán senior backend thực tế:

- streaming file processing;
- schema mapping;
- validation pipeline;
- database metadata;
- transaction boundary;
- bulk operation;
- idempotency;
- auditability;
- concurrency;
- partial failure.

### Phù hợp solo developer

Core domain khá nhỏ:

```text
File -> Row -> Validation -> PlannedChange -> Commit
```

Không cần distributed system hay infrastructure lớn.

### Có ích dù chỉ một người dùng

Chỉ cần dùng lại cho 3–4 migration/import cá nhân đã có giá trị vì giảm số script one-off phải viết.

### Điều gì khiến project thất bại

Nếu cố hỗ trợ “mọi database + mọi Excel + mọi mapping + mọi business rule” ngay từ đầu, project sẽ biến thành ETL platform và mất khả năng hoàn thành.

### Lý do mạnh nhất để không build

Nếu nhu cầu import thực tế rất hiếm, ví dụ chỉ vài lần mỗi năm và mỗi file chỉ 20–30 dòng, Excel + script có thể đơn giản hơn công cụ riêng.

## 6. Phạm vi MVP

### Must have

- duplicate detection trong file;

### Later

- nhiều target database;
- import theo schedule;
- webhook/API ingestion;
- PII masking;
- approval workflow nhiều người;
- reversible import;
- large-file chunk processing;
- Microsoft Graph/SharePoint file source;

## 7. Luồng hoạt động

```text
User uploads CSV
    ↓
File validation
    ↓
Header detection
    ↓
Column mapping
    ↓
Stream parse rows
    ↓
Type validation
    ↓
Business validation
    ↓
Reference lookup
    ↓
Compare with current DB state
    ↓
Create ImportPlan
    ↓
Persist summary + row results
    ↓
Show preview
    ↓
User approves
    ↓
Revalidate stale/conflicting rows
    ↓
Transaction commit
    ↓
Audit result
```

### Alternative flow: file sai format

Dừng trước parsing và trả lỗi rõ ràng:

```text
Required column `EmployeeCode` not found.
Found: EmployeeId, Name, Email
```

### Alternative flow: row lỗi

Không abort toàn bộ dry-run. Mark row `Invalid` và tiếp tục phân tích các row còn lại.

### Failure: database unavailable khi commit

- ImportPlan giữ trạng thái `ReadyToCommit`;
- transaction không bắt đầu hoặc rollback;
- user retry sau;
- không đánh dấu completed.

### Failure: dữ liệu thay đổi sau dry-run

Trước commit, kiểm tra row version/hash hoặc relevant fields. Nếu khác snapshot ban đầu, mark conflict và yêu cầu dry-run lại.

## 8. Kiến trúc đề xuất

Dùng **modular monolith**.

```text
Vue Web UI
   |
ASP.NET Core API
   |
   +-- Import Profiles
   +-- File Parser
   +-- Validation Pipeline
   +-- Diff Planner
   +-- Commit Engine
   +-- Audit
   |
PostgreSQL
```

### Frontend

Vue 3.

Cần UI cho upload, mapping, error table và diff preview. Không cần SPA phức tạp.

### Backend

ASP.NET Core .NET 10.

Chứa toàn bộ logic orchestration.

### Database

PostgreSQL cho metadata của chính ImportGuard:

- import sessions;
- profiles;
- mappings;
- row results;
- audit.

Target database trong MVP có thể cũng là PostgreSQL để giảm scope.

### Background worker

Không bắt buộc cho file nhỏ. MVP có thể chạy parsing trong request/job endpoint.

Khi file vượt vài nghìn dòng, chuyển execution sang `BackgroundService` hoặc Hangfire.

### Scheduler

Không cần trong MVP.

### Queue

Không cần. Database-backed job state đủ cho một instance.

### Cache

Không cần Redis. Có thể cache reference dictionary trong memory trong một import session.

### File storage

Local filesystem volume hoặc Azure Blob Storage.

MVP self-hosted: local Docker volume đơn giản nhất.

### Authentication

Single-user mode trước. Nếu deploy nội bộ, thêm ASP.NET Core Identity hoặc Entra ID sau.

### AI model

Không cần cho core workflow.

### Logging

Serilog hoặc built-in structured logging.

### Deployment

Docker Compose:

```text
importguard-app
postgres
```

Không cần Kubernetes.

## 11. API và tích hợp

### Target database

MVP: PostgreSQL.

**Purpose:** lookup dữ liệu hiện tại và commit thay đổi.

**Authentication:** connection string/service account.

**Privacy:** credentials phải ở environment variables/secret store, không lưu plaintext trong UI database.

**Fallback:** export generated SQL nếu environment không cho write trực tiếp — phase sau.

### PostgreSQL COPY

Có thể dùng cho insert batch lớn. PostgreSQL hỗ trợ `COPY ... FROM STDIN` và CSV. [PostgreSQL documentation](https://www.postgresql.org/docs/18/sql-copy.html)

MVP chưa cần dùng nếu số row nhỏ; parameterized SQL/EF có thể đủ.

### SQL Server SqlBulkCopy — extension

Microsoft document xác nhận `SqlBulkCopy` hỗ trợ bulk insertion và có thể kết hợp transaction để rollback. [Microsoft Learn](https://learn.microsoft.com/en-us/dotnet/framework/data/adonet/sql/single-bulk-copy-operations)

**Authentication:** SQL auth hoặc integrated/managed identity tuỳ môi trường.

**Cost/rate limit:** không có external API rate limit; bottleneck là database throughput/locks.

### Excel/XLSX

ClosedXML phase sau.

Không cần cloud API.

### Notification

MVP không cần.

Later có thể gửi email/Telegram/Teams khi long-running import hoàn tất.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Core import tuyệt đối không nên phụ thuộc AI.

### AI task phù hợp về sau

Gợi ý mapping:

```text
CSV column: Dept
Candidate target fields:
- DepartmentCode
- DepartmentName
```

Model có thể trả:

```json
{
  "source": "Dept",
  "target": "DepartmentCode",
  "confidence": 0.82,
  "reason": "Values resemble short department identifiers"
}
```

### Validation

AI chỉ đề xuất mapping; user phải approve.

Không cho AI tự commit dữ liệu.

### Deterministic fallback

- exact header match;
- normalized-name match;
- alias dictionary;
- manual mapping.

### Risks

- hallucinated mapping;
- gửi schema/dữ liệu nhạy cảm ra external provider;
- latency;
- API cost;
- non-determinism.

Do đó AI không thuộc MVP.

## 14. Các bài toán kỹ thuật đáng học

### 1. Streaming file processing

Không load toàn bộ CSV vào RAM.

Kỹ năng học được:

- `IAsyncEnumerable`;
- streaming parser;
- backpressure;
- memory profiling.

### 2. Dry-run và diff generation

Cần phân biệt:

```text
Insert
Update
Skip
Error
Conflict
```

Kỹ năng:

- deterministic planning;
- change detection;
- domain comparison.

### 3. Transaction và failure recovery

Commit batch phải atomic hoặc có rule rõ ràng khi partial commit.

Kỹ năng:

- transaction boundary;
- rollback;
- lock/concurrency;
- retry semantics.

### 4. Idempotency

Import lại cùng file không được tạo duplicate ngoài ý muốn.

Có thể dùng:

```text
FileHash + ImportProfile + BusinessKey
```

Kỹ năng:

- deduplication;
- idempotent command design.

### 5. Business rule extensibility

Không hard-code toàn bộ rule vào controller.

Ví dụ:

```csharp
public interface IImportRowRule<T>
{
    Task<RuleResult> ValidateAsync(T row, CancellationToken ct);
}
```

Kỹ năng:

- pipeline architecture;
- plugin boundaries;
- testable domain logic.

## 15. Rủi ro và cách xử lý

### Scope explosion

**Risk:** trở thành generic ETL platform.

**Mitigation:** MVP chỉ 1 database + CSV + 1–2 import profile.

### Data privacy

File import có thể chứa PII.

**Mitigation:**

- không log raw row;
- encrypted disk nếu cần;
- retention auto-delete;
- explicit download/delete;
- tránh gửi AI/external service.

### Security

CSV/export có thể chứa formula bắt đầu `=`, `+`, `-`, `@`.

**Mitigation:** sanitize khi tạo downloadable CSV/Excel report để giảm CSV formula injection risk.

### Database dependency

Target schema có thể đổi.

**Mitigation:** profile có version hoặc schema fingerprint; nếu schema mismatch thì block commit.

### Concurrent updates

Dữ liệu thay đổi sau dry-run.

**Mitigation:** re-check row snapshot/hash trước commit.

### Performance

100k+ rows có thể chậm.

**Mitigation:** MVP giới hạn file, sau đó chunk processing + native bulk APIs.

### Incorrect mapping

Sai mapping có thể tạo thay đổi lớn nhưng vẫn syntactically valid.

**Mitigation:** preview summary + sample values + explicit confirmation.

### Maintenance burden

Mỗi business domain có rule khác.

**Mitigation:** giữ engine generic tối thiểu, domain rules ở plugin/profile layer.

## 16. Kiểm thử

### Unit tests

- parser normalization;
- mapping;
- type conversion;
- action classification;
- validation rules.

### Integration tests

Dùng Testcontainers PostgreSQL để test thật transaction và unique constraint.

### E2E tests

Playwright:

```text
upload CSV
→ map
→ dry-run
→ inspect errors
→ commit
```

### Failure-path tests

- DB mất kết nối;
- commit constraint violation;
- stale record;
- malformed CSV;
- duplicate key.

### Security tests

- upload file size limit;
- unsupported MIME;
- path traversal filename;
- formula injection trong export;
- secrets không xuất hiện trong logs.

### 5 test scenario quan trọng nhất

1. **Valid mixed file:** 5 insert + 5 update + 5 unchanged → đúng 15 planned actions.
2. **Invalid reference:** department không tồn tại → row Error và không commit.
3. **Duplicate business key:** hai row cùng employee code → deterministic error.
4. **Commit rollback:** constraint fail ở giữa transaction → database không partial update.
5. **Stale data:** record bị sửa giữa dry-run và commit → conflict thay vì overwrite âm thầm.
