# Ý tưởng hôm nay: PortGuard — Local Exposure Watcher cho Windows, Linux và Docker

## 1. Tóm tắt ý tưởng

PortGuard là một công cụ self-hosted/desktop-lite giúp developer phát hiện **dịch vụ nào đang lắng nghe trên máy, port nào đang bind ra ngoài localhost, process/container nào sở hữu port đó và điều gì vừa thay đổi so với lần quét trước**. Công cụ nhắm tới developer tự chạy nhiều API, database, Docker container hoặc homelab service và muốn tránh vô tình public một port nhạy cảm ra LAN hoặc Internet.

- Người dùng chính: backend developer, solo builder, homelab/self-hosted developer.
- Bài toán chính: rất dễ mở nhầm port của database, dashboard, dev server hoặc container ra `0.0.0.0` mà không nhận ra.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **1–2 tuần**.

## 2. Bài toán thực tế

Developer thường chạy đồng thời nhiều thành phần local: ASP.NET Core API, PostgreSQL, Redis, RabbitMQ, Docker Compose, debug server, admin dashboard, test service hoặc tunnel. Sau nhiều lần chạy project, đổi Compose file hoặc thêm container, việc nhớ chính xác service nào đang expose port nào trở nên khó khăn.

### Confirmed facts

Docker documentation xác nhận rằng khi publish port mà không chỉ định host IP, ví dụ `-p 8080:80`, Docker mặc định bind port lên tất cả host addresses (`0.0.0.0` và có thể cả IPv6), khiến service có khả năng truy cập từ bên ngoài host. Docker Compose cũng ghi rõ nếu không đặt host IP, port mặc định bind `0.0.0.0`.

Nguồn:

- Docker Docs — Port publishing and mapping: https://docs.docker.com/engine/network/port-publishing/
- Docker Docs — Publishing and exposing ports: https://docs.docker.com/get-started/docker-concepts/running-containers/publishing-ports/
- Docker Compose services reference: https://docs.docker.com/reference/compose-file/services/

Windows cung cấp `Get-NetTCPConnection` để lấy current TCP connections cùng local/remote address, port, state và owning process. Linux có `ss` để inspect sockets và socket statistics.

Nguồn:

- Microsoft Learn — Get-NetTCPConnection: https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection
- Linux `ss(8)` manual: https://man7.org/linux/man-pages/man8/ss.8.html

### Observation

Các command hiện tại rất hữu ích nhưng mang tính point-in-time. Developer phải tự đọc output, map PID sang process/container và nhớ trạng thái cũ để biết có port mới xuất hiện hay không.

### Assumption cần kiểm chứng

Một số developer sẽ thấy hữu ích nếu có một watcher nhỏ chỉ cảnh báo khi exposure thay đổi, thay vì phải chủ động chạy `netstat`, `ss`, PowerShell hoặc `docker ps`.

### Workaround hiện tại

- `netstat`, `ss`, `lsof`.
- `Get-NetTCPConnection` + `Get-Process` trên Windows.
- `docker ps`, `docker port`, `docker inspect`.
- Kiểm tra firewall thủ công.
- Nhớ port từ `docker-compose.yml` hoặc `launchSettings.json`.

Nhược điểm chính là dữ liệu phân mảnh và không có lịch sử thay đổi.

### Primary user

### Context of use

### Main pain point

Không biết chính xác port nào đang public ra LAN/Internet và port nào mới xuất hiện sau một thay đổi code/config.

### Current workaround

Chạy từng command kiểm tra socket và container rồi đối chiếu thủ công.

### Reason to try

```text
NEW EXPOSURE
0.0.0.0:5432
Process: docker-proxy

First seen: 15:42:03
Risk: Database port exposed on all interfaces

```

## 4. Giải pháp đề xuất

PortGuard chạy một lightweight agent trên host và định kỳ tạo snapshot của listening sockets.

### Input

- Listening TCP sockets.
- Owning PID/process.
- Docker container/port mapping nếu Docker tồn tại.
- Optional allowlist config.

### Processing

1. Thu thập sockets.
2. Normalize về model chung.
3. Xác định scope của bind address:
   - loopback
   - LAN-specific
   - wildcard/public candidate
4. Map PID sang executable/process.
5. Nếu port thuộc Docker, map tiếp sang container name/image.
6. So sánh với snapshot trước.
7. Tạo finding cho exposure mới hoặc thay đổi.

### Output

- CLI table.
- Local web dashboard nhỏ.
- Optional notification qua Telegram/desktop webhook.

### User control

Người dùng tự đánh dấu port là expected/allowlisted. PortGuard không tự đóng port hoặc sửa firewall trong MVP.

### Key differentiator

Không cố trở thành full network scanner. Tool tập trung vào **change detection trên chính host của developer**, đồng thời correlate socket → process → Docker container → exposure risk.

### Ví dụ end-to-end

Developer sửa Compose từ:

```yaml
ports:
  - "127.0.0.1:5432:5432"
```

thành:

```yaml
ports:
  - "5432:5432"
```

Sau khi `docker compose up -d`, PortGuard phát hiện bind thay đổi từ loopback thành wildcard và tạo warning ngay lập tức.

Developer mở dashboard, thấy container `postgres-dev`, host port `5432` và recommendation quay lại `127.0.0.1:5432:5432`.

## 7. Luồng hoạt động

User cài PortGuard
→ agent kiểm tra OS capabilities
→ thu thập listening sockets
→ normalize records
→ enrich process metadata
→ query Docker metadata nếu có
→ classify exposure
→ lưu snapshot
→ diff với snapshot trước
→ tạo findings
→ dashboard/CLI hiển thị thay đổi
→ optional notification.

### Failure cases

**Không đủ quyền xem process:** vẫn hiển thị socket và PID nếu có; process name = unknown.

**Docker daemon không chạy:** skip Docker enrichment, core scanner vẫn hoạt động.

**Collector command lỗi:** lưu scan run là failed và giữ snapshot trước.

**Port xuất hiện trong vài giây rồi mất:** nếu polling interval dài có thể bỏ sót; MVP chấp nhận limitation này.

**Wildcard bind nhưng firewall đang block:** không kết luận “Internet exposed”; chỉ ghi “listening on all interfaces / potential exposure”.

## 11. API và tích hợp

### Windows NetTCPIP / PowerShell

**Purpose:** enumerate TCP connections/listeners.

**Authentication:** local OS permissions.

**Cost/rate limit:** không có external API cost.

**Privacy:** process names và local topology là machine-sensitive data; không upload mặc định.

**Fallback:** `netstat -ano` parsing.

Nguồn: https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection

### Linux `ss`

**Purpose:** enumerate sockets.

**Authentication:** một số process metadata có thể yêu cầu permission cao hơn.

**Cost:** local command, không có API cost.

**Fallback:** `/proc/net/*`, `netstat` hoặc `lsof` tùy hệ thống.

Nguồn: https://man7.org/linux/man-pages/man8/ss.8.html

### Docker Engine / CLI

**Purpose:** map host port sang container và image.

**Authentication:** local Docker socket/context permissions.

**Security concern:** Docker socket có quyền rất mạnh; agent nên chỉ read metadata và không expose Docker socket qua network.

**Fallback:** bỏ enrichment, vẫn report host process/socket.

Nguồn:

- https://docs.docker.com/engine/network/port-publishing/
- https://docs.docker.com/reference/compose-file/services/

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Risk classification trong MVP có thể deterministic:

```text
127.0.0.1 / ::1 → low exposure
0.0.0.0 / :: → wildcard bind
DB port + wildcard bind → elevated warning
new wildcard bind → notify
```

AI không nên quyết định một port có an toàn hay không vì networking context cần deterministic evidence.

Nếu mở rộng sau này, AI có thể optional để giải thích finding theo ngôn ngữ tự nhiên, nhưng không tham gia detection engine.

## 14. Các bài toán kỹ thuật đáng học

### 1. Cross-platform host inspection

Windows và Linux có command/API khác nhau. Bài toán giúp học abstraction mà không ép hai OS vào cùng implementation.

### 2. Network binding semantics

Phân biệt `127.0.0.1`, `0.0.0.0`, IPv6 wildcard và interface-specific address giúp hiểu sâu hơn TCP/IP và exposure model.

### 3. Process/container correlation

Một host port có thể do application trực tiếp hoặc Docker networking sở hữu. Mapping đúng giúp học OS process model và container networking.

### 4. Change detection và state reconciliation

PortGuard phải nhận biết mới/thay đổi/biến mất mà không spam notification. Đây là bài học tốt về reconciliation loop và state machines nhỏ.

### 5. Security UX và false positives

Không được tuyên bố “Internet exposed” chỉ vì bind wildcard. Tool phải dùng wording chính xác, phân biệt evidence và inference.

## 15. Rủi ro và cách xử lý

### False positives

**Risk:** wildcard bind có thể vẫn bị firewall chặn.

**Mitigation:** gọi finding là “potential exposure”, không khẳng định reachable từ Internet nếu chưa probe từ bên ngoài.

### Privilege requirements

**Risk:** process metadata có thể không đọc được với user thường.

**Mitigation:** degrade gracefully; không bắt buộc admin nếu chỉ cần socket-level info.

### Docker socket security

**Risk:** access Docker socket tương đương quyền mạnh trên host.

**Mitigation:** không proxy socket; chỉ chạy local; documentation cảnh báo rõ; support CLI parsing mode.

### Scope expansion

**Risk:** biến thành SIEM/network IDS.

**Mitigation:** core scope luôn là local listening socket exposure changes.

### Cross-platform maintenance

**Risk:** OS output/permissions khác nhau.

**Mitigation:** collector interfaces + fixture tests từ captured command outputs.

### Adoption

**Risk:** user thấy command line truyền thống đã đủ.

**Mitigation:** validate bằng change detection/alerting — chính phần này phải tiết kiệm công sức rõ ràng.

## 16. Kiểm thử

### Strategy

- Unit test cho bind classification và diff engine.
- Fixture tests cho Windows/Linux collector parsers.
- Integration tests với local sockets thật.
- Docker integration tests.
- Failure-path tests khi collector/Docker unavailable.
- Security tests cho dashboard bind và sensitive metadata.

### 5 test scenario quan trọng nhất

1. Process bind `127.0.0.1:5000` được classify loopback.
2. Process bind `0.0.0.0:5000` được classify wildcard.
3. Docker container đổi từ `127.0.0.1:5432` sang `0.0.0.0:5432` tạo finding `BindingScopeChanged`.
4. Restart agent không tạo duplicate finding cho cùng exposure chưa đổi.
5. Docker daemon offline không làm scan host thất bại.

## 17. Cách đo dự án có hữu ích hay không

Các metric nên tập trung vào giá trị thực:

- **Actionable finding rate:** % findings mà user thực sự acknowledge/fix/allowlist.
- **Detection latency:** thời gian từ khi port xuất hiện đến khi finding được tạo.
- **False-positive rate:** findings bị dismiss vì không đáng quan tâm.
- **Exposure fixes:** số lần user chuyển wildcard bind về loopback hoặc đóng port sau cảnh báo.
- **Repeated use:** số ngày watcher thực sự được bật trong tháng.
- **Reliability:** % scheduled scans hoàn tất thành công.
- **Notification duplication rate:** số cảnh báo lặp không có state change.

Validation cá nhân hợp lý: chạy 30 ngày và xem tool có phát hiện ít nhất 2–3 exposure/configuration changes mà bình thường bạn không chủ động kiểm tra hay không.

```csharp
    string Protocol,
    string LocalAddress,
    int LocalPort,
    int? ProcessId,
    string? ProcessName);
```

Classifier:

```csharp
public enum BindScope
{
    Loopback,
    Wildcard,
    SpecificInterface,
    Unknown
}
```

Rules đầu tiên:

```text
127.0.0.1 → Loopback
::1       → Loopback
0.0.0.0   → Wildcard
::        → Wildcard
other IP  → SpecificInterface
```

Windows prototype có thể gọi:

```powershell
Get-NetTCPConnection -State Listen
```

Linux prototype:

```bash
ss -lntp
```

Output kỳ vọng:

```text
PORTGUARD SCAN

SAFE   127.0.0.1:5000   PortGuard.Api
WARN   0.0.0.0:5432     postgres
SAFE   [::1]:5173        node
WARN   [::]:8080         unknown

2 wildcard listeners detected.
```

### Verification checklist

- [ ] `dotnet run` hiển thị ít nhất các TCP listener hiện tại.
- [ ] `127.0.0.1` được classify `Loopback`.
- [ ] `0.0.0.0` được classify `Wildcard`.
- [ ] IPv6 `::1` và `::` được xử lý riêng.
- [ ] Scanner không crash khi thiếu process name.
- [ ] Có unit tests cho bốn bind rules.
- [ ] Mở một test server bind wildcard và thấy warning xuất hiện.

Có thể tạo test server nhanh bằng ASP.NET Core:

```bash
dotnet new web -n PortGuard.TestServer -o tools/PortGuard.TestServer
dotnet run --project tools/PortGuard.TestServer --urls http://0.0.0.0:5099
```

Sau đó chạy PortGuard và xác nhận `0.0.0.0:5099` được phát hiện.

### Stop condition

Kết thúc session ngay khi bạn có thể:

1. Start một service trên `0.0.0.0:5099`.
2. Chạy `PortGuard scan`.
3. Nhìn thấy warning rõ ràng cho port `5099`.
4. Đổi service sang `127.0.0.1:5099`.
5. Chạy lại và thấy classification chuyển thành `SAFE/Loopback`.

Không làm Docker mapping, database, notification hoặc dashboard trong session đầu tiên.
