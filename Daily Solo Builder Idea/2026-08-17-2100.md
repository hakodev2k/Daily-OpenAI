# Ý tưởng hôm nay: SchemaGym — Phòng tập SQL tạo bài luyện từ schema thật của chính bạn

## 1. Tóm tắt ý tưởng

**SchemaGym** là một ứng dụng local-first giúp developer luyện SQL trực tiếp trên schema thật của database họ đang làm việc, thay vì chỉ luyện trên các bộ dữ liệu mẫu cố định. Công cụ đọc metadata của PostgreSQL hoặc SQL Server, tạo bài tập phù hợp với cấu trúc bảng/quan hệ hiện có, chạy câu trả lời trong một sandbox chỉ đọc và chấm kết quả bằng rule deterministic; AI chỉ dùng tùy chọn để diễn giải đề hoặc gợi ý bài tập mới.

- **Project size:** Medium
- **Estimated MVP time:** 10–14 ngày làm ngoài giờ
- **Người dùng chính:** backend developer muốn nâng kỹ năng SQL bằng dữ liệu/schema quen thuộc
- **Bài toán chính:** học SQL thường bị tách khỏi database thật, khiến kiến thức khó chuyển ngay vào công việc

## 2. Bài toán thực tế

Developer backend thường gặp hai trạng thái trái ngược:

1. Biết cú pháp SQL cơ bản nhưng ít có cơ hội luyện các truy vấn thực tế như join nhiều bảng, aggregation, window function, pagination, anti-join, duplicate detection hoặc data-quality checks.
2. Có database thật ở công việc nhưng không muốn hoặc không được phép dùng production data để thử nghiệm tự do.

Cách phổ biến hiện nay là:

- luyện trên dataset cố định của tutorial;
- dùng LeetCode/HackerRank hoặc các bài SQL độc lập;
- tự nghĩ query trên database local;
- hỏi AI tạo bài tập;
- đọc query của người khác trong codebase.

Các cách này đều hữu ích nhưng có một khoảng trống: **bài tập không gắn trực tiếp với domain/schema mà developer đang hiểu**. Một developer làm hệ thống timesheet, e-commerce hoặc HR sẽ học nhanh hơn nếu bài tập dùng những bảng như `Employees`, `Timesheets`, `Orders`, `Payments`, `LeaveRequests` thay vì `Students`, `Customers` mẫu chung chung.

### Fact đã xác nhận

PostgreSQL có schema chuẩn `information_schema`, tồn tại mặc định trong database và chứa metadata mà ứng dụng có thể truy vấn. Tài liệu PostgreSQL mô tả `information_schema.tables` là view chứa các table/view mà user hiện tại có quyền truy cập. Nguồn: [PostgreSQL 18 — The Information Schema](https://www.postgresql.org/docs/18/infoschema-schema.html) và [PostgreSQL — tables](https://www.postgresql.org/docs/17/infoschema-tables.html).

SQL Server cũng hỗ trợ các `INFORMATION_SCHEMA` views theo định nghĩa ISO để ứng dụng đọc metadata như tables, columns, constraints và relationships; mức metadata nhìn thấy phụ thuộc quyền của user. Nguồn: [Microsoft Learn — System Information Schema Views](https://learn.microsoft.com/en-us/sql/relational-databases/system-information-schema-views/system-information-schema-views-transact-sql?view=sql-server-ver16).

Điều này xác nhận rằng MVP có thể introspect schema qua cơ chế chính thức thay vì scraping hoặc reverse engineering.

### Observation

Các nền tảng luyện SQL phổ biến thường dùng dataset có sẵn để đảm bảo reproducibility. Điều đó tốt cho giáo trình chung, nhưng không tận dụng context domain mà developer đang có trong dự án thực tế.

### Assumption cần kiểm chứng

Giả định chính của SchemaGym là: **developer sẽ thấy bài tập dùng schema quen thuộc hấp dẫn và hữu ích hơn bài tập generic**, miễn là hệ thống không yêu cầu upload dữ liệu nhạy cảm lên cloud.

Nếu người dùng không cảm thấy domain-specific exercise tạo thêm giá trị so với LeetCode/SQLBolt/HackerRank, sản phẩm sẽ không có lý do tồn tại rõ ràng.

## 3. Người dùng mục tiêu

### Primary user

Backend developer từ Junior+ đến Senior đang làm việc với PostgreSQL hoặc SQL Server, biết SQL cơ bản nhưng muốn luyện sâu hơn bằng schema thật.

### Context of use

- trước giờ làm 15–20 phút;
- sau khi gặp một query khó trong project;
- chuẩn bị phỏng vấn backend;
- muốn luyện window function, aggregation, joins hoặc data-quality analysis;
- muốn hiểu schema hiện tại tốt hơn.

### Main pain point

Không thiếu tài liệu SQL, nhưng thiếu bài luyện **đúng domain và đúng mức độ** để chuyển kiến thức thành kỹ năng thực tế.

### Current workaround

- tự viết query ngẫu nhiên;
- copy schema vào ChatGPT và yêu cầu tạo câu hỏi;
- dùng tutorial dataset;
- đọc query production.

### Vì sao họ có thể thử SchemaGym

- schema không cần rời khỏi máy;
- bài tập sinh từ domain quen thuộc;
- có chấm kết quả tự động;
- có progression từ easy → medium → hard;
- có thể dùng ngay với database local/dev.

## 4. Giải pháp đề xuất

SchemaGym kết nối read-only tới một database dev/local, đọc metadata và tạo một **Schema Snapshot** gồm:

- tables;
- columns;
- data types;
- primary keys;
- foreign keys;
- unique constraints;
- nullable/non-nullable;
- optional row-count sample;
- optional value statistics an toàn như min/max/count distinct nếu user bật.

Sau đó engine sinh bài tập từ các template deterministic.

Ví dụ schema:

- `Employees(Id, DepartmentId, Name, IsActive)`
- `Departments(Id, Name)`
- `Timesheets(Id, EmployeeId, WorkDate, Hours)`

SchemaGym có thể tạo bài:

> Liệt kê 5 nhân viên có tổng số giờ làm cao nhất trong tháng hiện tại. Kết quả gồm `EmployeeId`, `Name`, `TotalHours` và sắp xếp giảm dần theo `TotalHours`.

### Input

- connection string local/dev;
- database engine;
- schema cho phép introspect;
- difficulty level;
- chủ đề muốn luyện: join, group by, window function, subquery, CTE, data-quality.

### Processing

1. introspect schema;
2. build graph giữa tables;
3. chọn pattern bài tập phù hợp;
4. generate expected query contract;
5. tạo reference result bằng query chuẩn do engine build hoặc query đã được validate;
6. user chạy câu trả lời trong read-only session;
7. normalize result;
8. so sánh với expected result theo rule.

### Output

- đề bài;
- schema context tối thiểu cần dùng;
- difficulty;
- topic tags;
- query editor;
- execution time;
- result preview;
- pass/fail;
- hint theo từng mức;
- solution chỉ mở khi user yêu cầu.

### What is automated

- schema discovery;
- bài tập từ template;
- chấm result;
- progress tracking;
- chọn bài kế tiếp theo skill gap.

### User control

- chọn database/schema;
- bật/tắt table nhạy cảm;
- quyết định có cho đọc sample data hay chỉ metadata;
- chọn difficulty;
- reset progress;
- xem solution hay không.

### Key differentiator

Không phải generic SQL playground. Điểm khác biệt là:

> **“Practice SQL against the shape of your real domain without sending the database to a third party.”**

### Ví dụ end-to-end

Hà kết nối SchemaGym tới PostgreSQL database local của một project timesheet. Tool phát hiện `Employees → Timesheets` là quan hệ one-to-many. Anh chọn chủ đề `Aggregation + Window Functions`, level Medium.

SchemaGym tạo bài:

> Với mỗi phòng ban, tìm nhân viên có tổng số giờ làm cao nhất trong 30 ngày gần nhất.

Anh viết query dùng CTE + `ROW_NUMBER() OVER (PARTITION BY DepartmentId ORDER BY TotalHours DESC)`. Tool chạy trong transaction read-only, compare result với reference output và báo pass. Sau đó hệ thống đánh dấu kỹ năng `window-function/ranking` đã hoàn thành 1 bài medium.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Ngay cả với một người dùng, SchemaGym có thể trở thành công cụ luyện SQL hàng tuần trên chính project local của developer.

### Technical learning value

Project này có nhiều bài toán đáng học:

- database metadata introspection;
- schema graph;
- safe query execution;
- read-only database permissions;
- SQL result normalization;
- query timeout/cancellation;
- exercise generation;
- deterministic grading;
- optional AI structured generation.

### Vì sao phù hợp solo developer

Core MVP không cần:

- multi-tenant SaaS;
- distributed system;
- queue;
- cloud storage;
- vector database;
- complex AI agent.

Một desktop/local web app với SQLite metadata store là đủ.

### Hữu ích ngay cả rất ít user

Nếu không có user trả tiền, project vẫn có giá trị lớn làm personal learning tool và portfolio project về database engineering.

### Điều gì khiến ý tưởng thất bại

- bài sinh ra lặp lại hoặc quá dễ;
- grading false negative vì hai query đúng nhưng order khác nhau;
- setup database connection quá khó;
- user lo ngại tool có thể sửa dữ liệu;
- schema quá ít dữ liệu khiến bài không meaningful.

### Lý do mạnh nhất để không build

Developer đã có rất nhiều tài nguyên SQL miễn phí. Nếu domain-specific practice không tạo trải nghiệm học tốt hơn đáng kể, SchemaGym dễ trở thành một SQL playground phức tạp nhưng không thiết yếu.

## 7. Luồng hoạt động

### Main flow

User thêm database connection
→ app test connection
→ app mở read-only connection
→ đọc metadata
→ build SchemaSnapshot
→ user chọn topic/difficulty
→ ExerciseGenerator chọn template
→ build exercise specification
→ reference executor tính expected result
→ user viết SQL
→ SafeQueryValidator kiểm tra statement
→ query chạy với timeout
→ normalize output
→ ResultGrader so sánh
→ lưu attempt
→ cập nhật progress.

### Alternative flow: schema có dữ liệu nhạy cảm

User chọn `Metadata only`.

→ tool chỉ đọc schema, không đọc value samples.

Một số bài cần dữ liệu thực tế sẽ bị disable.

### Alternative flow: database gần như trống

Nếu row count quá thấp:

→ app báo exercise không đủ meaningful;
→ user có thể tạo một sandbox clone bằng synthetic data về sau;
→ MVP chưa tự sinh data.

### Failure case: query có `UPDATE`, `DELETE`, `INSERT`, DDL

→ validator reject trước execution.

Ngoài parser-level guard, connection dùng credential read-only để defense in depth.

### Failure case: query chạy quá lâu

→ cancellation token + command timeout;
→ transaction rollback;
→ attempt được ghi `TimedOut`.

### Failure case: result đúng nhưng khác thứ tự

ExerciseSpec phải xác định rõ `OrderingRequired`.

- nếu false → compare như multiset;
- nếu true → compare theo row order.

## 11. API và tích hợp

### PostgreSQL `information_schema`

**Purpose:** đọc schema metadata.

**Authentication:** database credential.

**Cost/rate limit:** không có API charge; chỉ là DB query local/server.

**Privacy:** metadata có thể chứa table/column names nhạy cảm về domain; không gửi ra ngoài.

**Fallback:** user import schema DDL thủ công ở phase sau.

### SQL Server `INFORMATION_SCHEMA`

**Purpose:** adapter thứ hai.

**Authentication:** SQL login hoặc Windows/Entra tùy môi trường.

**Permission concern:** metadata visibility phụ thuộc securables mà user có quyền thấy.

**Fallback:** chỉ hỗ trợ PostgreSQL ở MVP.

### AI API — optional later

**Purpose:** biến deterministic ExerciseSpec thành prompt tự nhiên hơn hoặc tạo variation khó hơn.

**Authentication:** API key user-owned.

**Cost:** phụ thuộc provider/model.

**Privacy:** schema names có thể nhạy cảm; phải hiển thị rõ context sẽ gửi trước khi gọi.

**Fallback:** deterministic template engine.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

AI không nên nằm trong core MVP vì:

- schema graph có thể xử lý deterministic;
- exercise templates có thể sinh deterministic;
- query execution/chấm kết quả phải deterministic;
- privacy tốt hơn nếu không gửi schema ra ngoài.

### Exact AI task về sau

AI nhận **sanitized schema subset + ExerciseSpec** và tạo:

```json
{
  "prompt": "...",
  "hint1": "...",
  "hint2": "...",
  "explanation": "..."
}
```

AI không quyết định pass/fail.

### Required context

- table names;
- relevant columns;
- relationships;
- topic;
- difficulty;
- deterministic expected behavior.

### Validation

- JSON schema validation;
- referenced table/column phải tồn tại;
- AI không được tự tạo column;
- reference query không lấy từ AI nếu chưa chạy/verify.

### Deterministic fallback

Template renderer.

### Risks

- hallucinated column;
- leak schema metadata;
- cost;
- latency;
- bài tập nghe tự nhiên nhưng logically invalid.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

**Goal:** xác nhận domain-specific SQL practice tạo thêm giá trị.

**Main tasks:**

1. Chọn 1 PostgreSQL schema local có 5–10 bảng.
2. Tự tạo 10 bài tập từ schema đó.
3. Làm thử trong 3 ngày.
4. So sánh cảm giác học với một bộ bài generic.
5. Hỏi 2–3 backend developer xem họ có muốn tool tự sinh kiểu này không.

**Expected output:** danh sách exercise patterns thực sự hữu ích.

**Completion criteria:** ít nhất 5 pattern có thể tái sử dụng trên nhiều schema và người thử cho rằng domain-specific context giúp bài dễ liên hệ hơn.

### Phase 1 — Core MVP

**Goal:** end-to-end PostgreSQL.

**Tasks:**

- connection profile;
- schema introspection;
- schema graph;
- 5 exercise templates;
- query editor;
- safe executor;
- deterministic grader;
- attempt history.

**Expected output:** user connect DB → generate bài → submit SQL → pass/fail.

**Completion criteria:** hoàn thành 20 generated exercises trên một database local mà không cần sửa tay prompt/spec.

### Phase 2 — Reliability

**Goal:** không làm hỏng database và giảm false grading.

**Tasks:**

- read-only database user docs;
- statement parser/validator;
- command timeout;
- cancellation;
- result normalization;
- transaction read-only;
- logging redaction;
- integration tests;
- schema fingerprint.

**Completion criteria:** destructive query bị chặn; query timeout được cancel; app restart không mất progress.

### Phase 3 — Useful expansion

**Goal:** tăng chiều sâu học tập.

**Tasks:**

- SQL Server adapter;
- window functions;
- CTE exercises;
- anti-join;
- query-plan challenges;
- topic progression;
- schema refresh.

**Completion criteria:** cùng một core exercise engine hoạt động trên PostgreSQL và SQL Server qua adapter abstraction.

### Phase 4 — Production readiness

**Goal:** có thể public OSS/self-host.

**Tasks:**

- Docker option;
- secure secret handling;
- docs;
- sample demo database;
- health endpoint;
- CI;
- Playwright E2E;
- release packaging.

**Completion criteria:** một user mới clone repo, chạy demo database và hoàn thành bài đầu tiên trong dưới 10 phút.

## 14. Các bài toán kỹ thuật đáng học

### 1. Schema introspection đa database

PostgreSQL và SQL Server đều có `INFORMATION_SCHEMA`, nhưng chi tiết metadata và type mapping khác nhau.

Skill nâng được:

- adapter pattern;
- metadata modeling;
- database portability.

### 2. Safe query execution

Chỉ string-check `StartsWith("SELECT")` là không đủ.

Cần defense in depth:

- read-only credential;
- SQL parser/validator;
- read-only transaction;
- timeout;
- cancellation.

Skill:

- security boundary;
- least privilege;
- failure containment.

### 3. Result-equivalence grading

Hai query khác nhau có thể trả cùng result.

Cần xử lý:

- null;
- decimal precision;
- timestamps;
- ordering;
- duplicate rows;
- column aliases.

Skill:

- canonicalization;
- deterministic comparison;
- data quality.

### 4. Exercise generation từ schema graph

Ví dụ join exercise chỉ có ý nghĩa nếu có relationship path hợp lệ.

Skill:

- graph traversal;
- rule engine;
- domain-driven generation.

### 5. Query cancellation và resource control

Một query học tập có thể vô tình Cartesian join hàng triệu row.

Skill:

- command timeout;
- cancellation token;
- resource safeguards;
- operational reliability.

## 15. Rủi ro và cách xử lý

### Risk: destructive query

**Mitigation:**

- read-only DB user bắt buộc khuyến nghị;
- transaction read-only nơi engine hỗ trợ;
- parser reject DML/DDL;
- command timeout.

### Risk: schema/database nhạy cảm

**Mitigation:**

- local-first;
- không telemetry schema mặc định;
- AI disabled mặc định;
- schema exclusion list;
- redact connection strings/logs.

### Risk: reference result sai

Nếu ExerciseGenerator build query sai, user có thể bị chấm fail oan.

**Mitigation:**

- exercise template có test riêng;
- reference query chạy trước khi phát bài;
- nếu reference query fail → không publish exercise;
- button `Report bad exercise` local.

### Risk: data distribution làm bài vô nghĩa

Ví dụ top-N nhưng bảng chỉ có 1 row.

**Mitigation:**

- lightweight preconditions như row count;
- exercise template có `CanGenerate()`;
- skip bài không đủ dữ liệu.

### Risk: scope creep thành full SQL IDE

**Mitigation:**

Không xây schema designer, migration editor, DB admin, table browser đầy đủ. Chỉ thêm feature nếu phục vụ practice loop.

### Risk: grading theo result nhưng query inefficient

MVP chấm correctness trước. Performance training là phase riêng dùng `EXPLAIN`.

### Risk: nhiều dialect SQL

MVP chỉ PostgreSQL. Không cố normalize toàn bộ dialect từ đầu.

### Unit tests

Dùng PostgreSQL Testcontainers với schema fixture.

5. progress tăng.

### Failure-path tests

- wrong password;
- permission denied;
- query timeout;
- malformed SQL;
- destructive statement;
- DB disconnected giữa query.

### Security tests

- connection string không xuất hiện trong logs;
- rejected DML không được gửi tới DB;
- metadata exclusion hoạt động.

### Data-quality tests

- compare NULL;
- duplicate rows;
- timestamp precision;
- case-sensitive text;
- unordered result.

### Năm test scenario quan trọng nhất

1. Schema có `Employees -> Timesheets`: generator tạo join exercise hợp lệ và reference query chạy được.
2. User submit query khác cú pháp nhưng cùng result: grader phải pass.
3. User submit `DELETE FROM Timesheets`: request bị reject và DB không thay đổi.
4. Query Cartesian join vượt timeout: bị cancel và UI nhận trạng thái `TimedOut`.
5. Exercise không yêu cầu order: cùng rows nhưng khác order vẫn pass.

### First vertical slice

#### 1. Model

`SchemaGym.Core/SchemaTable.cs`

```csharp
public sealed record SchemaColumn(
    string Name,
    string DataType,
    bool IsNullable);

public sealed record SchemaTable(
    string Schema,
    string Name,
    IReadOnlyList<SchemaColumn> Columns);
```

#### 2. Interface

```csharp
public interface ISchemaReader
{
    Task<IReadOnlyList<SchemaTable>> ReadAsync(
        CancellationToken cancellationToken = default);
}
```

#### 3. PostgreSQL implementation

Query `information_schema.tables` + `information_schema.columns`.

Chỉ lấy `BASE TABLE` trong schema user chọn, ví dụ `public`.

#### 4. API

```http
GET /api/schema
```

Response ví dụ:

```json
[
  {
    "schema": "public",
    "name": "employees",
    "columns": [
      { "name": "id", "dataType": "uuid", "isNullable": false },
      { "name": "name", "dataType": "text", "isNullable": false }
    ]
  }
]
```

docker run --name schemagym-postgres \

## Kết luận lựa chọn

**Confirmed fact:** PostgreSQL và SQL Server đều cung cấp metadata schema qua cơ chế chính thức, nên project khả thi mà không cần scraping hoặc proprietary enterprise data.

**Observation:** developer có nhiều nền tảng luyện SQL, nhưng phần lớn bài luyện tách khỏi schema/domain trong công việc hằng ngày.

**Assumption:** practice trên schema quen thuộc sẽ giúp developer duy trì hứng thú và chuyển kiến thức SQL vào công việc nhanh hơn.

**Recommendation:** MVP chỉ tập trung vào `schema introspection → deterministic exercise → safe query execution → result grading`. Không biến project thành database IDE, không dùng AI làm grader và không hỗ trợ nhiều SQL dialect ngay từ đầu.
