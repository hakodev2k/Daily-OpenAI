# Ý tưởng hôm nay: Migration Rehearsal Lab — Phòng thử nghiệm migration database trước production

## 1. Tóm tắt ý tưởng

**Migration Rehearsal Lab** là một công cụ self-hosted/CLI dành cho developer .NET, tự động lấy migration hiện tại, dựng một database tạm có schema gần giống môi trường thật, chạy migration, đo thời gian, phát hiện thao tác có nguy cơ khóa bảng hoặc mất dữ liệu, rồi sinh báo cáo “go / review / block” trước khi deploy.

Mục tiêu chính là biến việc kiểm tra database migration từ một bước thủ công dễ bị bỏ qua thành một bài rehearsal có thể lặp lại trong local hoặc CI.

- **Người dùng:** backend developer hoặc team nhỏ dùng EF Core với SQL Server/PostgreSQL.
- **Bài toán:** migration chạy tốt trên database dev nhỏ nhưng có thể gây downtime, lock, mất dữ liệu hoặc fail khi lên production.
- **Quy mô:** Medium.
- **Thời gian MVP ước tính:** 2–3 tuần làm ngoài giờ.

## 2. Bài toán thực tế

Database migration thường được kiểm tra theo một trong các cách sau:

- developer chạy `dotnet ef database update` trên local;
- review file migration C#;
- generate SQL script rồi đọc thủ công;
- chạy thử trên staging;
- hoặc tệ hơn, để application tự migrate lúc startup.

Các cách này chưa trả lời tốt câu hỏi quan trọng nhất: **migration này sẽ cư xử thế nào trên một database có schema, constraint và lượng dữ liệu gần với production?**

### Fact đã xác nhận

Microsoft khuyến nghị phải review và test migration trước production, đồng thời coi SQL script là cách triển khai phù hợp hơn cho production vì có thể review trước. EF Core cũng hỗ trợ idempotent script và migration bundle. Nguồn: [Microsoft Learn — Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying).

Tài liệu PostgreSQL hiện tại cho biết nhiều dạng `ALTER TABLE` mặc định cần `ACCESS EXCLUSIVE` lock nếu tài liệu của subcommand không ghi rõ mức lock thấp hơn. Đây là loại rủi ro dễ bị bỏ qua khi chỉ nhìn migration C#. Nguồn: [PostgreSQL — ALTER TABLE](https://www.postgresql.org/docs/current/sql-altertable.html).

SQL Server cũng phân biệt online và offline index operations; các thao tác offline có thể giữ exclusive lock trên dữ liệu/index trong thời gian thực hiện. Nguồn: [Microsoft Learn — Perform index operations online](https://learn.microsoft.com/en-us/sql/relational-databases/indexes/perform-index-operations-online).

### Quan sát

Một migration chỉ mất vài trăm mili-giây trên local database có 1.000 rows nhưng có thể trở thành thao tác kéo dài đáng kể trên bảng lớn. Việc staging có dataset nhỏ cũng không chứng minh được migration an toàn về lock hoặc runtime.

### Assumption cần kiểm chứng

Developer/team nhỏ thường không có một môi trường disposable chứa dataset đủ gần production chỉ để rehearsal migration. Đây là giả định cần validate qua 5–10 cuộc trao đổi trước khi đầu tư vào UI hoặc multi-database support.

## 3. Người dùng mục tiêu

### Primary user

Backend developer .NET làm việc với:

- ASP.NET Core;
- EF Core;
- SQL Server hoặc PostgreSQL;
- migration chạy qua CI/CD hoặc deployment pipeline.

### Context sử dụng

Trước khi merge PR có migration hoặc trước khi release production, developer chạy một lệnh như:

```bash
mrlab rehearse --project ./src/App.Infrastructure --profile staging-like
```

### Pain point chính

Developer biết migration “compile được” nhưng không biết:

- có drop/rename nhầm column hay không;
- có scan/update cả bảng lớn hay không;
- có lock mạnh hay không;
- rollback có chạy được không;
- schema sau migration có đúng như kỳ vọng không;
- mất bao lâu trên dataset representative.

### Workaround hiện tại

- đọc SQL bằng mắt;
- thử trên staging;
- clone database thủ công;
- snapshot/restore database rồi chạy migration;
- chấp nhận rủi ro và monitor khi deploy.

### Vì sao họ thử công cụ này

Nếu một lệnh có thể cho ra report trong vài phút và chạy được trong CI thì chi phí sử dụng thấp hơn nhiều so với dựng thủ công một rehearsal environment.

## 4. Giải pháp đề xuất

Migration Rehearsal Lab chạy một “migration rehearsal” trong database disposable.

### Input

- đường dẫn project chứa `DbContext` và migrations;
- database engine: PostgreSQL hoặc SQL Server;
- baseline source:
  - migration cũ;
  - SQL schema dump;
  - hoặc database snapshot/template đã được sanitize;
- data profile:
  - empty;
  - generated-small;
  - generated-medium;
  - custom SQL seed;
- migration target.

### Processing

1. tạo container/database disposable;
2. dựng baseline schema;
3. seed lượng dữ liệu định trước;
4. generate SQL migration script;
5. static-analyze các statement nguy hiểm;
6. chạy migration thật;
7. ghi duration từng statement khi có thể;
8. kiểm tra schema cuối;
9. chạy smoke queries;
10. thử rollback nếu project hỗ trợ migration xuống;
11. xóa environment tạm.

### Output

Một Markdown/JSON report ví dụ:

```text
Migration: 202608171540_AddEmployeeExternalId
Result: REVIEW
Duration: 8.42s

Risks:
- ALTER TABLE Employees ALTER COLUMN ...
- PostgreSQL ACCESS EXCLUSIVE lock likely
- UPDATE Employees touches ~250,000 seeded rows
- Down migration drops column and loses generated values

Checks:
✓ migration applied
✓ schema fingerprint expected
✓ smoke queries passed
⚠ rollback is destructive
```

### Phần tự động

- tạo/xóa database rehearsal;
- generate migration script;
- static rule scan;
- thực thi và đo runtime;
- schema comparison;
- report.

### Phần người dùng kiểm soát

- chọn baseline;
- chọn data volume;
- định nghĩa thresholds;
- approve/ignore rule;
- quyết định có block CI hay không.

### Differentiator

Không phải migration runner. Điểm khác biệt là **rehearsal + risk evidence**: chạy migration trên môi trường disposable và kết hợp static analysis với runtime evidence trước production.

### Ví dụ end-to-end

Developer thêm index mới cho bảng `TimesheetEntry` khoảng hàng trăm nghìn hoặc hàng triệu rows trong môi trường thật.

1. Developer tạo migration EF Core.
2. Chạy `mrlab rehearse`.
3. Tool dựng PostgreSQL container và seed 500.000 rows synthetic.
4. Tool generate SQL.
5. Analyzer nhận ra `CREATE INDEX` thông thường thay vì phương án concurrent phù hợp với use case PostgreSQL.
6. Migration thực tế mất 18 giây trong rehearsal.
7. Report đánh dấu `REVIEW` vì vượt threshold 10 giây và có lock-sensitive operation.
8. Developer chỉnh migration hoặc lên kế hoạch maintenance window.
9. Chạy lại và so sánh report.

## 5. Tại sao ý tưởng này đáng làm

### Giá trị thực tế

- giảm khả năng migration bất ngờ fail khi deploy;
- biến review migration thành quy trình có evidence;
- dễ đưa vào PR/CI;
- hữu ích ngay cho chính developer trước khi có user bên ngoài.

### Giá trị học tập

Dự án buộc phải hiểu sâu:

- EF Core migrations internals;
- PostgreSQL/SQL Server DDL và lock semantics;
- disposable integration environments;
- schema introspection;
- CI gating;
- failure recovery.

### Vì sao phù hợp solo developer

MVP chỉ cần:

- một CLI;
- PostgreSQL trước;
- Docker;
- rule engine đơn giản;
- report Markdown.

Không cần SaaS, queue, authentication hay frontend ngay từ đầu.

### Vẫn hữu ích khi chỉ có một user

Một developer có nhiều project database vẫn có thể dùng tool trước mỗi migration quan trọng. Giá trị không phụ thuộc network effect.

### Điều khiến dự án thất bại

Nếu runtime rehearsal không phản ánh production đủ tốt, report có thể tạo cảm giác an toàn giả.

### Lý do mạnh nhất để không build

Nếu workflow hiện tại đã có staging clone gần production, DBA review migration, automated performance testing và deployment gate tốt, công cụ này có thể không tạo thêm nhiều giá trị.

## 6. Phạm vi MVP

### Must have

1. CLI chạy trên .NET.
2. Hỗ trợ **PostgreSQL trước**.
3. Nhận một EF Core project + target migration.
4. Tạo PostgreSQL disposable container.
5. Apply baseline migration.
6. Seed data qua user-provided SQL script.
7. Generate SQL từ migration mới.
8. Static rules tối thiểu:
   - `DROP TABLE`;
   - `DROP COLUMN`;
   - `ALTER COLUMN`;
   - `UPDATE` không có `WHERE`;
   - `DELETE` không có `WHERE`;
   - `CREATE INDEX`;
   - các `ALTER TABLE` cần review lock.
9. Apply target migration và đo duration tổng.
10. Export Markdown + JSON report.
11. Exit code:
   - `0 = PASS`;
   - `2 = REVIEW`;
   - `3 = BLOCK/FAIL`.

### Should have

- schema fingerprint trước/sau;
- custom thresholds;
- migration rollback test;
- baseline Docker image caching;
- GitHub Actions example;
- per-statement timing nếu execution strategy cho phép.

### Later

- SQL Server;
- Azure SQL;
- sanitized production snapshot import;
- lock observation bằng database system views;
- auto-generated representative data;
- web dashboard;
- PR comment bot;
- migration history/trend analysis.

## 7. Luồng hoạt động

### Happy path

User command
→ validate project/config
→ build project
→ start disposable PostgreSQL
→ apply baseline migrations
→ seed test data
→ generate target SQL
→ static risk scan
→ execute migration
→ inspect final schema
→ run smoke checks
→ create report
→ dispose database/container
→ return exit code.

### Alternative flow: migration compile fail

- stop trước khi tạo database nếu có thể;
- report `BUILD_FAILED`;
- không đánh dấu migration unsafe, chỉ đánh dấu rehearsal chưa hoàn thành.

### Alternative flow: seed fail

- giữ log;
- report invalid rehearsal dataset;
- không tiếp tục migration test.

### Failure: migration timeout

- kill/cancel operation theo timeout;
- thu runtime logs;
- mark `BLOCK`;
- cleanup container.

### Failure: container cleanup lỗi

- đánh dấu orphan resource ID;
- command `mrlab cleanup` dọn các container có label của tool.

### Failure: rollback thất bại

Không làm fail rehearsal mặc định vì nhiều migration intentionally irreversible; thay vào đó report rõ `ROLLBACK_NOT_VERIFIED` hoặc `ROLLBACK_DESTRUCTIVE`.

## 8. Kiến trúc đề xuất

MVP nên là **CLI modular monolith**, không cần web app.

```text
mrlab CLI
  ├─ ProjectInspector
  ├─ MigrationScriptGenerator
  ├─ RehearsalEnvironment
  │    └─ PostgreSqlDockerProvider
  ├─ SeedRunner
  ├─ RiskAnalyzer
  ├─ MigrationExecutor
  ├─ SchemaInspector
  └─ ReportRenderer
```

### Frontend

Không cần trong MVP. CLI + Markdown report đủ để validate workflow.

### Backend/API

Không cần HTTP API. Logic nằm trong application layer của CLI để sau này có thể reuse cho web/API.

### Database

Không cần database riêng để lưu metadata trong MVP. Mỗi run có JSON report.

### Background worker / scheduler

Không cần. Rehearsal là command explicit chạy local hoặc CI.

### Queue/cache

Không cần.

### File storage

Local artifacts directory:

```text
.artifacts/mrlab/{run-id}/
  migration.sql
  report.md
  report.json
  logs.txt
```

### Authentication

Không cần nếu chỉ chạy local/CI. Database credentials truyền qua environment variables hoặc ephemeral container.

### External APIs

Không bắt buộc.

### AI model

Không cần cho core workflow.

### Logging

Structured console logging + log file.

### Deployment

- publish self-contained CLI;
- hoặc distribute như .NET tool;
- Docker chỉ dùng để dựng database rehearsal.

### .NET 10 LTS

Tại thời điểm 17/08/2026, .NET 10 là LTS và được Microsoft support tới tháng 11/2028. Nguồn: [Microsoft Learn — .NET releases and support](https://learn.microsoft.com/en-us/dotnet/core/releases-and-support).

**Vì sao phù hợp:** stack quen thuộc, tốt cho CLI, process execution, EF Core integration và CI.

**Đơn giản hơn:** .NET 8 nếu project hiện tại vẫn đang ở .NET 8.

**Outgrow khi:** gần như không phải vấn đề; architecture mới là giới hạn chứ không phải runtime.

### System.CommandLine hoặc Spectre.Console.Cli

Dùng cho CLI parsing và UX.

**Đơn giản hơn:** parse args thủ công cho spike đầu tiên.

### EF Core 10

Dùng để tương tác với migration project nếu target application dùng EF Core tương ứng.

EF Core hỗ trợ generate SQL script, idempotent script và migration bundle; đây là nền tảng phù hợp để tool không phải tự phát minh migration engine. Nguồn: [Microsoft Learn — Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying).

### PostgreSQL 18 container

Tài liệu PostgreSQL current tại thời điểm nghiên cứu đang ở major 18. Tuy nhiên MVP nên cho phép user pin version, ví dụ `17` hoặc `18`, để rehearsal giống production hơn.

**Đơn giản hơn:** một PostgreSQL version cố định trong giai đoạn đầu.

### Testcontainers for .NET

Dùng để tạo disposable PostgreSQL container từ test/run code.

**Đơn giản hơn:** gọi `docker run` bằng process.

**Outgrow khi:** cần remote rehearsal environment hoặc cloud database provisioning.

### Npgsql

Schema introspection và execution trực tiếp PostgreSQL.

### Docker

Cần cho disposable database. Không dùng Kubernetes.

### xUnit + Testcontainers

Integration tests thật với PostgreSQL.

### GitHub Actions

Sau MVP, command có thể chạy như CI step và upload report artifact.

## 11. API và tích hợp

### EF Core CLI / design-time services

**Purpose:** build project, inspect migrations, generate SQL.

**Authentication:** không có.

**Cost/rate limit:** không có.

**Privacy:** source code chỉ xử lý local/CI.

**Fallback:** gọi `dotnet ef migrations script` bằng process trước; sau này mới tích hợp sâu `IMigrator`.

Microsoft xác nhận `dotnet ef migrations script --idempotent` và migration bundles là các deployment mechanisms chính thức. Nguồn: [Microsoft Learn — Applying Migrations](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying).

### Docker Engine

**Purpose:** chạy disposable PostgreSQL.

**Authentication:** local socket/daemon permission.

**Cost:** không có ngoài compute local/CI.

**Privacy:** dataset nên là synthetic hoặc sanitized.

**Fallback:** cho phép user truyền connection string tới database rehearsal họ tự provision.

### PostgreSQL system catalogs

**Purpose:** đọc tables, columns, indexes, constraints, migration history.

**Authentication:** database credential của rehearsal DB.

**Rate limit:** không có.

**Privacy:** chỉ rehearsal DB.

### GitHub Actions — later

**Purpose:** chạy tool trên PR và upload artifact.

**Authentication:** không cần GitHub API cho MVP nếu chỉ là command step.

**Fallback:** Azure DevOps/Jenkins/local CLI.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Core problem cần deterministic evidence:

- migration SQL cụ thể;
- statement classification;
- lock-risk rule;
- runtime duration;
- schema result;
- exit code.

LLM không nên quyết định migration “safe” hay “unsafe” vì có nguy cơ hallucination và khó tái lập.

### AI có thể xuất hiện sau này ở vai trò optional

Một LLM có thể giải thích report thành ngôn ngữ dễ hiểu:

```json
{
  "summary": "...",
  "risk_explanations": [...],
  "questions_for_reviewer": [...]
}
```

Nhưng verdict cuối vẫn dựa trên deterministic rule + runtime measurement.

### Deterministic fallback

Markdown template + rule descriptions cố định.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

**Goal:** chứng minh developer thực sự muốn rehearsal migration thay vì chỉ static lint.

**Tasks:**

- lấy 5 migration cũ từ project cá nhân/công việc không chứa dữ liệu nhạy cảm;
- tự generate SQL;
- ghi lại các failure/risk từng gặp;
- hỏi 5 developer: “trước deploy bạn kiểm migration như thế nào?”;
- thử workflow thủ công bằng Docker.

**Expected output:** danh sách 5–10 risk rule thực sự hữu ích.

**Completion criteria:** ít nhất 3 người xác nhận họ từng gặp migration gây deploy issue hoặc họ muốn pre-deploy evidence tốt hơn.

### Phase 1 — Core MVP

**Goal:** một command chạy được end-to-end với PostgreSQL.

**Tasks:**

- CLI project;
- parse config;
- spin PostgreSQL container;
- apply baseline;
- seed SQL;
- generate target SQL;
- run static rules;
- apply target migration;
- render report.

**Expected output:** `report.md` + exit code.

**Completion criteria:** chạy thành công trên sample project gồm ít nhất 3 migrations và phát hiện được một migration intentionally destructive.

### Phase 2 — Reliability

**Goal:** tool đáng tin hơn cho CI.

**Tasks:**

- timeout/cancellation;
- cleanup orphan container;
- structured logs;
- schema fingerprint;
- retry chỉ cho infrastructure failure, không retry migration SQL lỗi;
- xUnit integration tests;

**Expected output:** repeatable run cùng input cho kết quả tương đương.

**Completion criteria:** 20 consecutive CI runs không để orphan container và report đúng pass/fail fixtures.

### Phase 3 — Useful expansion

**Goal:** tăng độ gần production.

**Tasks:**

- configurable data sizes;
- SQL Server provider;

**Expected output:** dùng được trong ít nhất hai project thật.

**Completion criteria:** developer có thể thêm tool vào repo mới trong dưới 15 phút.

**Goal:** phát hành như một developer tool duy trì được.

**Tasks:**

- signed/reproducible releases nếu cần;
- NuGet/.NET tool packaging;

- telemetry opt-in hoặc không telemetry mặc định;
- compatibility matrix;
- report schema version;
- backup cho bất kỳ hosted dashboard nào nếu sau này có.

**Expected output:** versioned CLI có changelog và upgrade path.

**Completion criteria:** install → configure → first rehearsal có thể hoàn thành chỉ bằng tài liệu public.

## 14. Các bài toán kỹ thuật đáng học

### 1. Disposable integration environments

Phải tạo, chuẩn bị và cleanup database container reliably.

**Skill học được:** Testcontainers, Docker lifecycle, deterministic integration testing.

### 2. Database lock-risk reasoning

Không chỉ parse SQL mà phải map statement sang lock behavior theo database engine/version.

PostgreSQL ghi rõ nhiều dạng `ALTER TABLE` lấy `ACCESS EXCLUSIVE` lock nếu không có ngoại lệ. Nguồn: [PostgreSQL — ALTER TABLE](https://www.postgresql.org/docs/current/sql-altertable.html).

**Skill học được:** concurrency, DDL locks, production database operations.

### 3. Safe static analysis

Regex đơn thuần sẽ sớm yếu. Tool cần tokenizer/parser hoặc ít nhất statement-aware scanner.

**Skill học được:** SQL parsing, rule engines, false-positive management.

### 4. Failure classification

Phân biệt:

- migration bug;
- seed bug;
- Docker failure;
- timeout;
- schema assertion failure.

**Skill học được:** resilient workflows và diagnostics.

### 5. CI gating không gây phiền

Nếu rule quá nhạy, developer sẽ disable tool.

**Skill học được:** severity design, suppressions, baseline policy, developer experience.

## 15. Rủi ro và cách xử lý

### Risk: rehearsal dataset không giống production

**Mitigation:** report phải ghi rõ row count/profile và tuyệt đối không tuyên bố “production safe”. Dùng ngôn ngữ “risk detected / no risk detected under this rehearsal profile”.

### Risk: false positives từ static rules

**Mitigation:** severity `INFO/WARN/BLOCK`, rule suppression có lý do, rule ID stable.

### Risk: false negatives

**Mitigation:** static scan chỉ là một signal. Luôn chạy migration thật và hiển thị limitations của report.

### Risk: scope tăng thành full database deployment platform

**Mitigation:** MVP chỉ rehearsal. Không deploy production database.

### Risk: production data privacy

**Mitigation:** mặc định synthetic seed. Không hỗ trợ production clone trong MVP. Nếu thêm sau này, require sanitization workflow và explicit opt-in.

### Risk: Docker unavailable trong CI

**Mitigation:** hỗ trợ `--connection` tới rehearsal DB do user tự quản lý ở phase sau.

### Risk: engine/version differences

**Mitigation:** pin exact DB major version trong config và lưu version vào report.

### Risk: runtime cost trong CI

**Mitigation:** cache baseline image/schema, configurable seed size, chỉ chạy khi migration files thay đổi.

### Risk: legal/platform

Thấp vì tool chạy trên source/database mà user sở hữu hoặc có quyền sử dụng; tuy nhiên không nên tự động copy production data.

### 5 test scenario quan trọng nhất

1. **Add nullable column:** rehearsal phải PASS và schema cuối có column.
2. **Drop column:** rule phải BLOCK hoặc REVIEW tùy policy trước khi apply.
3. **Full-table update:** tool phải phát hiện statement không có `WHERE` và đo runtime trên seeded rows.
4. **Broken migration:** SQL fail giữa run; report phải chỉ ra migration failure và cleanup container.
5. **Timeout:** migration vượt threshold hard timeout; process bị cancel, artifact/log vẫn được tạo và không để orphan container.

## 20. Việc cần làm ngay hôm nay

### Development objective — 60–120 phút

Tạo vertical slice đầu tiên:

> Một CLI nhận file SQL migration, scan 5 rule nguy hiểm và xuất `report.md` với exit code.

Chưa cần Docker, EF Core integration hay database execution.

### Files/components cần tạo

```text
MigrationRehearsalLab.sln
src/
  MrLab.Cli/
    Program.cs
    Commands/AnalyzeCommand.cs
  MrLab.Core/
    Analysis/SqlRiskAnalyzer.cs
    Analysis/RiskFinding.cs
    Analysis/RiskSeverity.cs
    Reporting/MarkdownReportRenderer.cs
samples/
  risky-migration.sql
tests/
  MrLab.Core.Tests/
```

### Setup commands

```bash
dotnet new sln -n MigrationRehearsalLab

dotnet new console -n MrLab.Cli -o src/MrLab.Cli
dotnet new classlib -n MrLab.Core -o src/MrLab.Core
dotnet new xunit -n MrLab.Core.Tests -o tests/MrLab.Core.Tests

dotnet sln add src/MrLab.Cli/MrLab.Cli.csproj
dotnet sln add src/MrLab.Core/MrLab.Core.csproj
dotnet sln add tests/MrLab.Core.Tests/MrLab.Core.Tests.csproj

dotnet add src/MrLab.Cli/MrLab.Cli.csproj reference src/MrLab.Core/MrLab.Core.csproj
dotnet add tests/MrLab.Core.Tests/MrLab.Core.Tests.csproj reference src/MrLab.Core/MrLab.Core.csproj
```

### First rules

Detect case-insensitively, statement-aware ở mức tối thiểu:

1. `DROP TABLE` → BLOCK
2. `DROP COLUMN` → BLOCK
3. `DELETE FROM ...` không có `WHERE` → BLOCK
4. `UPDATE ...` không có `WHERE` → REVIEW
5. `ALTER TABLE` → REVIEW với message cần kiểm lock semantics

### Sample SQL

```sql
ALTER TABLE employees ADD COLUMN external_id text;
UPDATE employees SET external_id = id::text;
ALTER TABLE employees DROP COLUMN legacy_code;
```

### Expected result

```text
Migration Rehearsal Lab
Status: BLOCK
Findings: 3

[REVIEW] ALTER_TABLE — review lock behavior
[REVIEW] UPDATE_WITHOUT_WHERE — may touch entire table
[BLOCK] DROP_COLUMN — destructive schema change

Report: .artifacts/mrlab/report.md
```

CLI phải trả non-zero exit code khi có `BLOCK`.

### Verification checklist

- [ ] `dotnet test` pass.
- [ ] sample SQL tạo đúng 3 findings mong đợi.
- [ ] `DROP COLUMN` làm exit code khác 0.
- [ ] `report.md` được tạo và đọc được.
- [ ] một file SQL an toàn như `CREATE TABLE demo...` không bị block.
- [ ] analyzer không gửi bất kỳ nội dung nào ra network.

### Stop condition

Dừng phiên coding đầu tiên ngay khi:

1. CLI chạy được trên `samples/risky-migration.sql`;
2. report Markdown xuất hiện;
3. 5 rule có unit test;
4. exit code phản ánh verdict.

Không thêm Docker, EF Core, PostgreSQL execution hoặc frontend trong phiên đầu. Vertical slice này đã đủ để chứng minh rule engine + CLI UX trước khi tiến tới rehearsal thật.
