# Ý tưởng hôm nay: Personal Knowledge Sync Agent

## 1. Tóm tắt ý tưởng
Một công cụ cá nhân giúp tự động thu thập, đồng bộ và tổ chức kiến thức kỹ thuật từ nhiều nguồn như GitHub, tài liệu Markdown, bookmark, RSS và ghi chú cá nhân thành một kho tri thức có thể tìm kiếm. Dự án Medium, MVP khoảng 3-4 tuần.

## 2. Bài toán thực tế
Developer thường lưu kiến thức ở nhiều nơi: README, issue, blog, chat, bookmark, file local nhưng khó tìm lại khi cần. Giải pháp hiện tại thường là bookmark hoặc ghi chú thủ công, dễ phân tán và mất thời gian.

## 3. Người dùng mục tiêu
Developer học công nghệ mới, đặc biệt backend developer cần duy trì kiến thức dài hạn. Pain point chính là biết nhiều nguồn nhưng không có hệ thống tổng hợp cá nhân.

## 4. Giải pháp đề xuất
Người dùng kết nối nguồn dữ liệu, hệ thống định kỳ đồng bộ nội dung, phân loại theo chủ đề và tạo chỉ mục tìm kiếm. Ví dụ khi học Azure Functions, developer có thể tìm lại toàn bộ tài liệu, code snippet và ghi chú liên quan.

Điểm khác biệt: tập trung vào knowledge workflow cá nhân thay vì một ứng dụng ghi chú chung.

## 5. Tại sao đáng làm
Có giá trị ngay cho chính developer xây dựng. Dự án giúp học về search, indexing, background processing, data synchronization và AI workflow. Rủi ro lớn nhất là phạm vi dễ mở rộng quá mức.

## 6. Phạm vi MVP

### Must have
- Import Markdown folder
- Import GitHub repository README/issues
- Full-text search
- Tag và category
- Lịch sử đồng bộ

### Should have
- Semantic search
- Browser extension lưu tài liệu
- Daily digest

### Later
- Multi-user
- Mobile app
- AI knowledge assistant

## 7. Luồng hoạt động
Nguồn dữ liệu → validate quyền truy cập → đồng bộ background → normalize content → lưu database → index search → người dùng truy vấn → trả kết quả.

Failure: API lỗi thì retry; dữ liệu trùng dùng checksum để tránh lưu lại.

## 8. Kiến trúc đề xuất
Modular monolith:
- Web UI
- ASP.NET Core API
- Background Worker
- PostgreSQL
- Search engine
- File storage

Không cần microservice ở MVP.

## 9. Công nghệ đề xuất
.NET 8/9, ASP.NET Core, EF Core, PostgreSQL, Vue, Hangfire hoặc BackgroundService, Docker, GitHub Actions.

Có thể dùng OpenSearch khi dữ liệu lớn; MVP chỉ cần PostgreSQL Full Text Search.

## 10. Thiết kế dữ liệu
KnowledgeItem: Id, Title, Content, Source, Hash, CreatedAt.
SourceConnection: loại nguồn, credential reference, trạng thái sync.
SyncJob: thời gian chạy, kết quả, lỗi.
Tag: phân loại kiến thức.

## 11. API và tích hợp
GitHub API để lấy repository và issue.
Filesystem watcher để đọc Markdown local.
RSS parser cho blog kỹ thuật.
Fallback: import file thủ công.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng optional.

Có thể dùng AI để:
- Tóm tắt tài liệu dài
- Gợi ý tag
- Sinh câu hỏi ôn tập

Kết quả cần validate bằng dữ liệu gốc; không dùng AI cho tìm kiếm chính.

## 13. Kế hoạch triển khai

Phase 0: Chọn 3 nguồn dữ liệu cá nhân và đo nhu cầu.

Phase 1: Xây import Markdown, database, search.

Phase 2: Thêm retry, logging, test, bảo mật credential.

Phase 3: Thêm GitHub integration và semantic search.

Phase 4: Deploy VPS hoặc self-host.

## 14. Bài toán kỹ thuật đáng học
- Data synchronization: học xử lý dữ liệu thay đổi.
- Search indexing: học retrieval system.
- Background processing: học workflow đáng tin cậy.
- Deduplication: học xử lý dữ liệu trùng.

## 15. Rủi ro và xử lý
Scope lớn → giới hạn nguồn dữ liệu.

Privacy → lưu local hoặc self-host.

API dependency → có cơ chế import offline.

## 16. Kiểm thử
1. Import file Markdown thành công.
2. Đồng bộ GitHub lỗi và retry đúng.
3. Search trả đúng tài liệu.
4. Không tạo duplicate khi sync lại.
5. Credential không bị log ra ngoài.

## 17. Đo hiệu quả
- Thời gian tìm lại kiến thức giảm.
- Số lần sử dụng search mỗi tuần.
- Số tài liệu được tổ chức tự động.
- Tỷ lệ sync thành công.

## 18. Khả năng mở rộng
Có thể phát triển thành AI learning assistant, team engineering wiki hoặc self-hosted knowledge platform.

## 19. Mô hình giá trị
Personal utility, portfolio project, open-source project. Có thể phát triển thành SaaS cho developer team nhỏ.

## 20. Việc cần làm ngay hôm nay
Trong 60-120 phút:

1. Tạo solution:
- KnowledgeSync.Api
- KnowledgeSync.Core
- KnowledgeSync.Infrastructure

2. Cài PostgreSQL và EF Core.

3. Tạo entity KnowledgeItem.

4. Viết API POST /knowledge/import nhận file Markdown.

5. Lưu dữ liệu và tạo endpoint GET /knowledge/search.

Hoàn thành khi có thể import một file README.md và tìm kiếm nội dung từ trình duyệt.
