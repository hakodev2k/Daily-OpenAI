# Ý tưởng hôm nay: AI Code Review Memory Agent

## 1. Tóm tắt ý tưởng
Một công cụ cá nhân dành cho developer giúp lưu lại các lỗi code review, quyết định kỹ thuật, feedback từ team và biến chúng thành kho kinh nghiệm có thể tra cứu trước khi tạo Pull Request mới. Dự án Medium, MVP khoảng 3-4 tuần.

## 2. Bài toán thực tế
Developer thường nhận nhiều feedback lặp lại: naming, architecture, performance, security, testing. Sau vài tháng, các bài học này bị phân tán trong PR, chat hoặc ticket. Đây là giả định dựa trên quy trình phát triển phần mềm phổ biến.

## 3. Người dùng mục tiêu
Senior developer làm việc với nhiều repository. Pain point là lặp lại cùng lỗi và mất thời gian nhớ các quy tắc của từng dự án.

## 4. Giải pháp đề xuất
Người dùng kết nối repository hoặc nhập feedback review. Hệ thống lưu rule, context, ví dụ tốt/xấu và hỗ trợ kiểm tra trước khi tạo PR.

Ví dụ: Developer chuẩn bị PR EF Core query mới. Agent kiểm tra các rule đã lưu và cảnh báo có nguy cơ N+1 query.

## 5. Tại sao đáng làm
Có giá trị ngay cho cá nhân, phù hợp với kinh nghiệm .NET, GitHub, AI agent. Rủi ro lớn nhất là dữ liệu rule không đủ chất lượng.

## 6. Phạm vi MVP

### Must have
- Lưu review rule.
- Import PR comment thủ công.
- Search rule.
- CLI kiểm tra code checklist.

### Should have
- GitHub integration.
- AI đề xuất rule mới.
- Dashboard thống kê lỗi.

### Later
- IDE extension.
- Team knowledge sharing.
- MCP server cho coding agent.

## 7. Luồng hoạt động
Developer thêm feedback → validate → lưu database → phân loại rule → chạy kiểm tra khi tạo PR → trả cảnh báo.

Failure: GitHub unavailable, AI lỗi, rule sai cần rollback.

## 8. Kiến trúc đề xuất
- Frontend: Vue 3.
- Backend: ASP.NET Core modular monolith.
- Database: PostgreSQL.
- Worker: BackgroundService xử lý đồng bộ.
- Search: PostgreSQL Full Text Search.
- Auth: Microsoft Entra ID hoặc local account.

Không cần microservice.

## 9. Công nghệ đề xuất
.NET 10, ASP.NET Core, EF Core, PostgreSQL, Vue 3, Docker, GitHub Actions. Stack phù hợp với developer .NET và dễ triển khai VPS/Azure.

## 10. Thiết kế dữ liệu ban đầu
ReviewRule: Id, Title, Description, Category, Severity.

ReviewExample: Id, RuleId, BadCode, GoodCode.

Repository: Id, Name, Url.

Feedback: Id, Source, Content, CreatedAt.

## 11. API và tích hợp
- GitHub API: lấy PR comment, cần token.
- OpenAI API: optional để phân loại feedback.
- Git CLI: lấy diff local.

Fallback: hoạt động bằng dữ liệu nhập tay.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng optional. Dùng để phân loại feedback, tạo rule và giải thích lỗi. Kết quả phải được developer xác nhận.

## 13. Kế hoạch triển khai

### Phase 0
Thu thập 50 feedback code review cá nhân.

### Phase 1
Xây database, API, UI, search rule.

### Phase 2
Thêm test, logging, retry, backup.

### Phase 3
Thêm GitHub integration và CLI.

### Phase 4
Deploy, monitoring, documentation.

## 14. Các bài toán kỹ thuật đáng học
- Git diff processing: hiểu source analysis.
- Rule engine: thiết kế workflow kiểm tra.
- Background sync: retry/idempotency.
- AI evaluation: kiểm soát output model.

## 15. Rủi ro và cách xử lý
Scope tăng → giới hạn MVP cá nhân.

AI hallucination → chỉ dùng AI hỗ trợ.

Code privacy → ưu tiên self-host hoặc không gửi source code.

## 16. Kiểm thử
1. Tạo rule và tìm kiếm.
2. Import feedback.
3. GitHub sync thất bại.
4. CLI chạy với diff thật.
5. AI trả kết quả không hợp lệ.

## 17. Cách đo hữu ích
- Số warning tránh được.
- Thời gian review giảm.
- Số rule được tái sử dụng.
- Tỷ lệ cảnh báo hữu ích.

## 18. Khả năng mở rộng
Có thể phát triển thành developer productivity platform, MCP tool cho AI coding agent hoặc sản phẩm quản lý engineering knowledge.

## 19. Mô hình giá trị
Personal utility, Portfolio project, Open-source. SaaS team nhỏ là hướng mở rộng nếu có nhu cầu.

## 20. Việc cần làm ngay hôm nay
Trong 60-120 phút:

1. Tạo solution ASP.NET Core.
2. Tạo entity ReviewRule.
3. Setup PostgreSQL và EF migration.
4. Tạo API POST /rules.
5. Tạo trang Vue hiển thị rule.

Kết quả: có thể tạo một rule code review và tìm lại được.

Verification:
- API chạy.
- Database lưu dữ liệu.
- UI hiển thị rule.

Stop condition: hoàn thành vòng lặp tạo → lưu → tìm kiếm rule đầu tiên.
