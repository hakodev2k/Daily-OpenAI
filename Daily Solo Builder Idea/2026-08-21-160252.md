# Ý tưởng hôm nay: ShareScope — OneDrive & SharePoint Sharing-Link Exposure Auditor

## 1. Tóm tắt ý tưởng

**ShareScope** là một công cụ self-hosted giúp developer hoặc knowledge worker quét OneDrive/SharePoint để phát hiện file/folder đang được chia sẻ bằng link hoặc explicit permission, đặc biệt là các link không có ngày hết hạn, link có quyền `write`, quyền chia sẻ cũ và các item thay đổi permission theo thời gian. Sản phẩm tập trung vào câu hỏi thực tế: *“Những tài liệu nào của tôi đang được chia sẻ rộng hơn cần thiết, và quyền nào đáng review trước?”*

- Người dùng chính: developer hoặc nhân viên kỹ thuật dùng Microsoft 365 cho tài liệu cá nhân/team nhỏ.
- Vấn đề chính: file được chia sẻ theo nhu cầu tức thời nhưng permission thường tồn tại lâu hơn mục đích ban đầu.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.

## 2. Bài toán thực tế

Việc chia sẻ file trong OneDrive/SharePoint rất tiện: người dùng tạo link view/edit hoặc cấp quyền trực tiếp cho một người. Vấn đề xuất hiện sau vài tuần hoặc vài tháng: người dùng không còn nhớ link nào vẫn hoạt động, ai còn quyền, permission nào kế thừa từ folder cha và link nào chưa có expiration.

### Confirmed facts

Microsoft Graph v1.0 hỗ trợ lấy **effective sharing permissions** của một `driveItem` qua endpoint `GET /drives/{drive-id}/items/{item-id}/permissions`. Permission có thể là sharing link, invitation hoặc quyền trực tiếp; API trả các trường như `roles`, `link`, `grantedToV2`, `grantedToIdentitiesV2` và có thể có `inheritedFrom`. Nguồn chính thức: https://learn.microsoft.com/en-us/graph/api/driveitem-list-permissions?view=graph-rest-1.0

Permission resource của Microsoft Graph có `expirationDateTime`, `roles`, `link`, `shareId` và methods để list/get/update/delete permission. Sharing link có thể cấp read hoặc write access. Nguồn: https://learn.microsoft.com/en-us/graph/api/resources/permission?view=graph-rest-1.0

Microsoft Graph cũng hỗ trợ `driveItem: delta` để theo dõi thay đổi trong drive theo thời gian bằng `@odata.deltaLink`, thay vì phải enumerate toàn bộ hierarchy ở mọi lần scan. Nguồn: https://learn.microsoft.com/en-us/graph/api/driveitem-delta?view=graph-rest-1.0

### Observation

Microsoft 365 đã có UI để xem/manage sharing của từng file. Khoảng trống phù hợp cho một solo tool không phải “một UI share file khác”, mà là:

- cross-folder exposure inventory;
- risk rules deterministic;
- lịch sử thay đổi;
- review queue;
- reminder cho permission cũ;
- evidence trước khi user tự revoke.

### Assumption cần validate

Tool hữu ích nhất với người dùng có hàng trăm/thousands file trong OneDrive hoặc nhiều SharePoint document libraries và thường chia sẻ tài liệu. Nếu user chỉ có vài file shared, UI Microsoft 365 có thể đã đủ.

## 3. Người dùng mục tiêu

Primary user của MVP là **developer hoặc technical lead dùng OneDrive/SharePoint hằng ngày**, có quyền truy cập chính drive/site của mình và thường gửi tài liệu qua sharing link.

Context sử dụng:

- chia sẻ file thiết kế, proposal, spreadsheet, report;
- gửi link cho vendor/client/team khác;
- share folder tạm thời để phối hợp;
- dùng edit link trong vài ngày rồi quên revoke.

Pain point chính: họ có thể biết cách xem permission của *một file*, nhưng không biết nhanh **toàn bộ exposure đang tồn tại**.

Workaround hiện tại:

- nhớ lại từng file đã share;
- mở OneDrive/SharePoint UI;
- dùng spreadsheet tự ghi;
- chờ security review hoặc incident mới kiểm tra.

Họ sẽ thử ShareScope nếu setup read-only, không tải nội dung file và đưa ra một danh sách review có evidence rõ ràng.

## 4. Giải pháp đề xuất

### Main workflow

```text
Connect Microsoft 365
→ chọn drive/site cần audit
→ enumerate drive items
→ lấy permission metadata
→ normalize sharing model
→ evaluate policies
→ persist snapshot
→ dashboard review
→ user mark Reviewed / Keep / Revoke manually
→ next scan diff thay đổi
```

### Input

- Tenant/account authentication.
- OneDrive hoặc SharePoint drive/site target.
- Rules như:
  - link không expiration;
  - write link;
  - permission cũ hơn N ngày;
  - external identity;
  - anonymous/organization link nếu API metadata cho phép phân biệt;
  - item thuộc protected path.

### Processing

Deterministic code:

- enumerate item IDs;
- đọc permission collections;
- xác định direct vs inherited khi metadata hỗ trợ;
- normalize identities;
- tính age;
- classify risk;
- compare snapshot cũ/mới;
- dùng delta token cho incremental scan sau initial scan.

### Output

Ví dụ:

```text
File: /Projects/Client-A/Architecture.xlsx
Risk: High

- Sharing link role: write
- No expiration date
- Permission first observed: 74 days ago
- External recipient detected: 1
- Direct permission: yes

Recommended action: Review whether edit access is still required
```

### Điều được tự động hóa

- discovery;
- normalization;
- rule evaluation;
- snapshot diff;
- review backlog;
- optional scheduled scan.

### Điều vẫn do user kiểm soát

MVP **không tự revoke permission**. User review evidence rồi tự xử lý trong Microsoft 365 UI hoặc bật explicit write action ở phase sau.

### Key differentiator

**Exposure review theo thời gian**, không phải file browser.

### Ví dụ end-to-end

Ba tháng trước user share một folder với vendor bằng edit link. Project đã xong nhưng link vẫn còn. ShareScope initial scan ghi nhận permission; rule `write + no expiry + age > 30d` tạo finding High. User mở finding, xác nhận project đã kết thúc, dùng link sang Microsoft 365 để revoke permission, rồi scan lại. Permission biến mất và finding chuyển `Resolved` với snapshot evidence trước/sau.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Có thể dùng ngay với tài khoản Microsoft 365 cá nhân/công việc được phép. Không cần user khác mới có giá trị.

### Technical learning value

Project luyện:

- Microsoft Graph Files APIs;
- permission modeling;
- delta synchronization;
- pagination;
- eventual consistency;
- privacy-preserving metadata storage;
- security policy engine;
- incremental background scanning.

### Phù hợp solo developer

MVP chỉ cần một account/tenant, một hoặc vài drive, read-only Graph access và PostgreSQL/SQLite. Không cần crawler web, AI hay distributed system.

### Hữu ích với rất ít user

Ngay cả single-user self-hosted instance cũng là một personal security dashboard.

### Điều khiến ý tưởng thất bại

- permission APIs không trả đủ context cho loại account/site user đang dùng;
- initial scan quá chậm trên drive lớn;
- nhiều false positive do inherited permissions;
- user không có nhu cầu review sharing thường xuyên;
- Microsoft 365 native UI đã đáp ứng đủ.

### Lý do mạnh nhất để không build

**Permission visibility phụ thuộc caller và ownership.** Microsoft documentation ghi rõ permission collection chứa thông tin nhạy cảm; owner có thể nhận đầy đủ hơn non-owner. Vì vậy tool không thể hứa “toàn bộ tenant exposure” nếu chỉ chạy bằng quyền user thông thường.

## 7. Luồng hoạt động

```text
User connects account
→ validate scopes
→ enumerate target drive
→ persist item IDs
→ fetch permissions per relevant item
→ normalize
→ evaluate policies
→ save snapshot/findings
→ render dashboard
→ user reviews
→ next scan uses deltaLink
→ re-fetch permissions for changed items
→ diff
→ resolve or update findings
```

### Failure: Graph 429

Respect `Retry-After`, backoff và checkpoint. Không restart toàn scan.

### Failure: permission endpoint 403

Đánh dấu item `PermissionVisibility=Unavailable`, không suy luận rằng item “không shared”.

### Failure: file bị xóa giữa enumeration và permission fetch

Coi 404 là stale item; reconcile ở cuối scan.

### Failure: partial scan

Scan được đánh dấu `Partial`; không dùng partial snapshot để tự động resolve findings cũ.

### Failure: delta token invalid/expired

Fallback về full rescan cho target đó và tạo scan note.

## 11. API và tích hợp

### Microsoft Graph — List driveItem permissions

Purpose: lấy effective sharing permissions.

Endpoint mẫu:

```http
GET /drives/{drive-id}/items/{item-id}/permissions
```

Microsoft document least-privileged delegated permission là `Files.Read`; application permission là `Files.Read.All` cho API này, tùy scenario. Nguồn: https://learn.microsoft.com/en-us/graph/api/driveitem-list-permissions?view=graph-rest-1.0

Concern:

- owner/non-owner visibility khác nhau;
- một số secret-like fields chỉ trả cho callers đủ quyền;
- permission data nhạy cảm.

Fallback: nếu không đủ visibility, UI phải hiển thị capability limitation thay vì “safe”.

### Microsoft Graph — Drive delta

Purpose: incremental synchronization.

Endpoint:

```http
GET /drives/{drive-id}/root/delta
```

Response dùng `@odata.nextLink` khi còn page và `@odata.deltaLink` khi đã hoàn tất state. Nguồn: https://learn.microsoft.com/en-us/graph/api/driveitem-delta?view=graph-rest-1.0

Fallback: nếu delta state invalid thì full rescan.

### Permission delete/update — Later

Graph permission resource hỗ trợ delete/update methods. Tuy nhiên MVP không cần write permission. Nguồn: https://learn.microsoft.com/en-us/graph/api/resources/permission?view=graph-rest-1.0

### Rate-limit concern

Không scan permission của mọi item mỗi vài phút. Initial scan có thể chậm; sau đó dùng delta, path filters và concurrency giới hạn.

### Privacy concern

- không lưu file body;
- không persist raw sharing URL nếu không cần;
- mask identity/email nếu chỉ cần classify external/internal;
- encrypt auth/token state.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Các finding core có thể deterministic:

```text
write link + no expiration + age > 30d => High
external direct access + protected path => High
read link + expiration in 5d => Informational
inherited permission => Review parent instead of child
```

AI không cải thiện đáng kể discovery/revoke safety và tạo thêm privacy risk vì metadata chia sẻ khá nhạy cảm.

Nếu sau này dùng AI, chỉ nên tóm tắt nhiều findings thành human-readable review note. AI không được quyết định revoke.

## 14. Các bài toán kỹ thuật đáng học

### 1. Incremental synchronization bằng delta

Học cách quản lý `nextLink`, `deltaLink`, deleted items, checkpoint và replay-safe sync.

### 2. Permission normalization

Một permission có thể là link, invitation, direct grant hoặc inherited. Cần biến nhiều shape thành domain model thống nhất mà không mất evidence.

### 3. Rate limiting và bounded concurrency

Drive lớn có thể có hàng nghìn items. Scanner phải giữ concurrency vừa đủ, retry đúng cách và không tự tạo Graph throttling storm.

### 4. Explainable security policies

Mỗi finding phải trả lời được “vì sao bị đánh dấu”, không dùng opaque score.

### 5. Privacy-preserving metadata

Cần thiết kế sao cho tool hữu ích mà không trở thành một bản sao thứ hai của sensitive sharing URLs, email và file content.

## 15. Rủi ro và cách xử lý

### Permission visibility không đầy đủ

**Mitigation:** capability indicator, `Unknown` state, không mặc định `NoPermission = Safe`.

### Initial scan quá chậm

**Mitigation:** scan metadata trước, bounded concurrency, filter path, checkpoint và delta sau initial scan.

### False positive do inherited permissions

**Mitigation:** hiển thị inherited/direct rõ ràng; rule hướng user tới ancestor khi có evidence.

### Privacy/security

**Mitigation:** read-only MVP, không file content, mask identity, encrypted token state, self-host first.

### API dependency

**Mitigation:** adapter layer, Graph v1.0 only, contract tests và graceful partial scan.

### Scope creep

**Mitigation:** không làm Purview, DLP, tenant-wide governance hoặc auto-remediation trong MVP.

### User adoption

**Mitigation:** validate bằng chính drive của developer trước; nếu không tìm được finding có hành động trong 1–2 tuần thì dừng.

### 5 scenario quan trọng nhất

1. `write` link không expiration, first observed 45 ngày → High.
2. Permission inherited từ parent → finding chỉ rõ ancestor/review parent.
3. Graph trả 403 cho permission API → state `Unknown`, không `Safe`.
4. Scan page 3 bị 429 rồi recover → không duplicate items/permissions.
5. Partial scan thiếu permission cũ → finding cũ không tự resolve.

## Research notes

### Confirmed facts

- Microsoft Graph v1.0 có API list effective sharing permissions của `driveItem`.
- Permission resource biểu diễn link/direct/invitation permissions và có expiration metadata.
- Graph có API delete/update permission, nhưng MVP không cần write access.
- `driveItem: delta` hỗ trợ incremental tracking bằng delta links.
- .NET 10 là LTS Active tại thời điểm 21/08/2026 theo Microsoft support policy.

### Observations

Khoảng trống phù hợp không phải “share file”, mà là **persistent sharing exposure review + explainable policy + history**.

### Assumptions

- User có đủ số lượng shared items để cross-file dashboard đáng giá.
- Read-only setup dễ chấp nhận hơn auto-remediation.
- Permission age dựa trên `first observed` vẫn hữu ích dù Graph không phải lúc nào cũng cung cấp original creation timestamp cho mọi loại permission.

### Recommendation

Build **single-item permission CLI trước**, rồi full-drive read-only scanner. Chỉ thêm revoke/update khi read-only workflow chứng minh được giá trị thực tế.
