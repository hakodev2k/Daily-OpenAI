# Ý tưởng hôm nay: SchemaSeed — Constraint-Aware Test Data Generator cho EF Core

## 1. Tóm tắt ý tưởng

SchemaSeed là một developer tool dành cho dự án .NET dùng Entity Framework Core, tự đọc EF Core model metadata để sinh **test data có quan hệ hợp lệ, đúng kiểu dữ liệu và tôn trọng constraint** thay vì viết hàng trăm dòng seeding thủ công. Người dùng chính là backend developer cần dựng nhanh database test/dev có dữ liệu đủ thực tế để kiểm tra query, pagination, validation, reporting và integration test.

- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.
- Giá trị cốt lõi: biến `DbContext.Model` thành một kế hoạch sinh dữ liệu có thể lặp lại bằng seed cố định.

## 2. Bài toán thực tế

Backend application thường có nhiều entity liên kết với nhau: `User`, `Order`, `OrderItem`, `Product`, `Category`, `Payment`, `Notification`... Khi cần test một màn hình hoặc integration test, developer thường phải:

- tự viết seed code;
- tạo JSON fixture;
- dùng SQL script;
- copy một phần dữ liệu từ môi trường khác;
- hoặc dùng Faker/Bogus nhưng vẫn tự định nghĩa rule và thứ tự insert.

Vấn đề xuất hiện lặp lại mỗi khi schema thay đổi, entity mới được thêm hoặc một test scenario cần lượng dữ liệu lớn hơn.

**Confirmed facts:** EF Core expose runtime model metadata qua `IModel`; API `GetEntityTypes()` trả về toàn bộ entity types trong model, nên tool có thể inspect model thay vì parse source code bằng regex. Microsoft cũng cung cấp metadata cho relationship, key và property mappings thông qua EF Core metadata APIs. Nguồn: [Microsoft Learn — IModel.GetEntityTypes](https://learn.microsoft.com/en-us/dotnet/api/microsoft.entityframeworkcore.metadata.imodel.getentitytypes?view=efcore-10.0).

EF Core hiện có `UseSeeding`/`UseAsyncSeeding` cho database initialization, nhưng mục tiêu của tính năng đó là cung cấp nơi chạy seeding logic chứ không tự suy luận dữ liệu phù hợp với model. Nguồn: [Microsoft Learn — Data Seeding](https://learn.microsoft.com/en-us/ef/core/modeling/data-seeding).

Bogus là một thư viện open-source phổ biến trong .NET để sinh fake data và hỗ trợ fixed random seed để tạo dữ liệu lặp lại. Tuy nhiên, developer vẫn phải mô tả các rule domain của mình. Nguồn: [Bogus GitHub](https://github.com/bchavez/Bogus).

**Observation:** tooling đã giải quyết tốt phần “sinh tên/email/address giả”, nhưng khoảng trống thực tế vẫn nằm ở việc hiểu model relationship, thứ tự insert, nullable/required, unique constraint và tạo một dataset nhất quán giữa nhiều entity.

**Assumption cần validate:** developer .NET sẽ thấy hữu ích nếu chỉ cần cài package/CLI, chọn `DbContext`, thêm một file override rule nhỏ và nhận được database seed đủ tốt để dùng ngay.

## 3. Người dùng mục tiêu

### Primary user

Backend developer .NET làm việc với EF Core trong dự án vừa và nhỏ.

**Context:**

- cần tạo database local mới;
- chạy integration test trong CI;
- demo một feature;
- kiểm tra query/report/pagination với hàng nghìn row;
- tái tạo dataset test giống nhau trên nhiều máy.

**Pain point:** schema càng lớn thì seed script càng khó giữ đồng bộ với entity model.

**Current workaround:** `HasData`, custom seeder, SQL fixture hoặc Bogus code viết riêng cho từng entity.

**Lý do thử SchemaSeed:** giảm phần boilerplate, nhưng vẫn cho phép override business rule quan trọng thay vì cố sinh mọi thứ hoàn toàn tự động.

## 4. Giải pháp đề xuất

SchemaSeed cung cấp CLI và package runtime.

Ví dụ:

```bash
schemaseed inspect --project ./src/MyApp.Infrastructure --context AppDbContext
schemaseed generate --context AppDbContext --rows 100 --seed 2026
```

Tool sẽ:

1. Load assembly chứa `DbContext`.
2. Khởi tạo context bằng design-time factory hoặc configuration do user chỉ định.
3. Đọc `DbContext.Model`.
4. Xây dependency graph từ foreign keys.
5. Phân loại property theo CLR type, nullability, max length, key, generated value và relationship.
6. Sinh default generators.
7. Áp dụng override rules từ `schemaseed.yaml` hoặc C# configuration.
8. Tạo object graph theo thứ tự dependency.
9. Validate dataset trước khi insert.
10. Insert vào database test hoặc export JSON/SQL-compatible fixture.

### Ví dụ concrete

Một project có:

```text
Customer 1 --- n Order 1 --- n OrderItem n --- 1 Product
```

Developer cấu hình:

```yaml
entities:
  Customer:
    count: 50
  Product:
    count: 100
  Order:
    count: 500
    rules:
      Status: [Pending, Paid, Cancelled]
```

SchemaSeed tự tạo customer/product trước, sau đó tạo order và order item có FK hợp lệ.

**Automated:** metadata inspection, dependency ordering, primitive fake data, FK assignment, repeatable generation, bulk batching.

**User control:** entity count, ignored entities, domain-specific fields, distributions, fixed values và custom generator.

**Key differentiator:** tool không cố thay thế Bogus; nó dùng model-aware generation để giải quyết phần relational orchestration mà Faker thông thường không biết.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Có thể dùng ngay cho project cá nhân .NET có EF Core. Ngay cả chỉ một người dùng, tool vẫn giúp giảm thời gian dựng database test mới.

### Technical learning value

Project đụng tới:

- EF Core metadata;
- reflection/design-time assembly loading;
- graph algorithms;
- relational constraints;
- deterministic random generation;
- bulk data insertion;
- CLI UX;
- integration testing với database thật.

### Phù hợp solo developer

Core engine có phạm vi rõ: inspect model → build plan → generate → validate → insert. Không cần frontend trong MVP và không cần cloud service.

### Project vẫn hữu ích với rất ít user

Nếu tool chỉ phục vụ chính các project cá nhân, nó vẫn có giá trị như CLI nội bộ và thư viện reusable.

### Điều gì làm dự án thất bại

Nếu tool cố tự suy luận business semantics quá sâu, kết quả sẽ không đáng tin và configuration sẽ phức tạp hơn tự viết Bogus.

### Lý do mạnh nhất không nên build

Nếu các database hiện tại nhỏ và seeding code hiếm khi thay đổi, một file Bogus seeder viết tay có thể đơn giản hơn đáng kể.

## 6. Phạm vi MVP

### Must have

- Hỗ trợ .NET 10 + EF Core 10.
- Nhận một `DbContext`.
- Inspect entity, property, primary key, nullable và foreign key.
- Hỗ trợ scalar types phổ biến: `string`, numeric, `bool`, `Guid`, `DateTime`, enum.
- Tạo dependency graph cho entity insertion order.
- Sinh deterministic dataset bằng `--seed`.
- Cho phép set số record/entity.
- Cho phép ignore entity/property.
- Custom rule đơn giản cho một property.
- Insert vào PostgreSQL hoặc SQL Server test database thông qua chính EF Core provider của project.
- Dry-run report trước khi ghi DB.

### Should have

- Unique-index awareness.
- Min/max/max-length heuristics.
- Weighted enum distribution.
- Batch `SaveChanges`.
- JSON export.
- `--truncate-first` với explicit confirmation.
- Scenario presets như `small`, `medium`, `stress`.

### Later

- Roslyn source generator.
- Visual rule editor.
- Semantic inference từ property names.
- Testcontainers integration.
- Snapshot/versioned fixture.
- Data anonymization từ production dump.
- AI-assisted rule suggestion.

## 7. Luồng hoạt động

```text
Developer chạy CLI
→ load project/context
→ validate context creation
→ inspect EF model
→ build entity dependency graph
→ detect unsupported/cyclic relationships
→ merge default rule + user overrides
→ generate in-memory plan
→ validate keys/FKs/required fields
→ preview summary
→ insert theo dependency order
→ store run manifest
→ return success/failure report
```

### Alternative flows

**DbContext không khởi tạo được:** trả lỗi rõ cách cung cấp `IDesignTimeDbContextFactory` hoặc connection option.

**Circular FK:** phát hiện strongly connected component; nếu FK nullable thì insert trước rồi update; nếu required cycle thì đánh dấu unsupported trong MVP.

**Unique collision:** retry generator với giới hạn; hết retry thì fail record thay vì insert dữ liệu sai.

**Database đã có data:** mặc định không xóa; user phải explicit chọn mode append hoặc clean.

**Provider-specific failure:** giữ generation plan để user reproduce được cùng dataset.

## 9. Công nghệ đề xuất

### .NET 10 LTS

Tại ngày chạy này, .NET 10 là LTS active và được Microsoft support đến tháng 11/2028. Nguồn: [.NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy).

**Vì sao phù hợp:** tool được viết cho ecosystem .NET/EF Core và cần reflection/runtime model access.

**Simpler alternative:** target .NET 8 để tương thích project cũ hơn, nhưng MVP nên ưu tiên một version trước.

### EF Core 10 metadata APIs

Dùng `DbContext.Model.GetEntityTypes()` và metadata interfaces thay vì parse migration/source code.

**Vì sao phù hợp:** model runtime là representation mà EF thực sự dùng.

**Outgrow point:** hỗ trợ nhiều EF major version có thể cần adapter package riêng.

### Bogus

Dùng cho primitive/domain-neutral generators như name, email, address, lorem và deterministic random seed.

**Simpler alternative:** `System.Random` + generator nhỏ tự viết cho MVP đầu tiên.

**Outgrow point:** khi user muốn custom locale hoặc domain dataset, expose extension interface thay vì hard-code.

### System.CommandLine hoặc Spectre.Console.Cli

Dùng cho CLI parsing và UX.

**Simpler alternative:** parse args thủ công trong prototype.

### xUnit + Testcontainers

Dùng integration test với PostgreSQL/SQL Server thật.

Microsoft cảnh báo EF Core InMemory provider có nhiều khác biệt so với relational database thật và không khuyến nghị nó cho nhiều kiểu test. Nguồn: [Microsoft Learn — Testing EF Core Applications](https://learn.microsoft.com/en-us/ef/core/testing/).

### GitHub Actions

Build, test, pack NuGet và chạy integration tests.

## 10. Thiết kế dữ liệu ban đầu

**Purpose:** mô tả cách sinh một entity.

- `EntityName`

- `ClrType`
- `IsNullable`
- `MaxLength`
- `IsPrimaryKey`
- `IsGenerated`
- `GeneratorType`
- `CustomRule`

Fields:

- `PrincipalEntity`
- `DependentEntity`
- `ForeignKeyProperties`
- `IsRequired`
- `Cardinality`

### `SeedRunManifest`

Fields:

- `RunId`
- `RandomSeed`
- `ModelHash`
- `StartedAt`
- `EntityCounts`
- `Warnings`
- `Result`

Retention: optional 30–90 ngày hoặc commit cùng test artifacts.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

AI không nên nằm trong core generation engine.

Deterministic code xử lý tốt hơn cho:

- CLR types;
- nullability;
- keys;
- FK graph;
- insertion order;
- uniqueness;
- fixed random seed.

AI có thể thêm sau để **gợi ý semantic rule** từ tên property và surrounding model, ví dụ `Email`, `PhoneNumber`, `PostalCode`, `Slug`.

Nếu thêm AI:

- Input: entity/property metadata, không gửi database content.
- Output structured: `{ generator, parameters, confidence }`.
- Validation: whitelist generator types + schema validation.
- Fallback: deterministic generic generator.
- Risk: hallucinate domain semantics, cost, latency và accidental exposure của schema nhạy cảm.

Do đó MVP không cần AI API.

## 14. Các bài toán kỹ thuật đáng học

### 1. Runtime metadata inspection

Học sâu cách EF Core biến entity configuration thành runtime model.

### 2. Dependency graph và cycle handling

Foreign key graph tạo bài toán topological sorting và strongly connected components thực tế.

### 3. Deterministic generation

Cùng seed phải tạo dataset ổn định bất chấp batching/order thay đổi không cần thiết. Đây là bài học tốt về reproducibility trong test infrastructure.

### 4. Constraint-aware generation

Required, unique, max length, enum, generated columns và FK buộc engine phải phân biệt schema constraint với domain rule.

### 5. Database testing fidelity

Tool khuyến khích kiểm thử với provider thật thay vì dựa quá nhiều vào InMemory provider, giúp hiểu provider-specific behavior và integration testing tốt hơn.

## 15. Rủi ro và cách xử lý

### Quá nhiều edge case EF Core

**Risk:** owned types, TPH/TPT/TPC inheritance, composite keys, shadow properties, value converters, temporal tables và provider-specific features làm scope phình nhanh.

**Mitigation:** MVP support matrix rõ ràng; unsupported feature phải warning/fail chứ không cố đoán.

### Sinh dữ liệu hợp schema nhưng vô nghĩa về business

**Mitigation:** default generator chỉ giải quyết structural validity; domain semantics phải thông qua override rule.

### Accidentally chạy vào production DB

**Risk nghiêm trọng.**

**Mitigation:** mặc định từ chối host/database name match production patterns; require explicit `--allow-nonlocal`; hiển thị connection target; không có delete/truncate implicit.

### Performance

**Risk:** EF tracking hàng trăm nghìn entities gây memory cao.

**Mitigation:** MVP giới hạn dataset; batch insert và `ChangeTracker.Clear()`; benchmark trước khi thêm bulk library.

### EF Core version compatibility

Provider thường gắn với major version EF Core. Nguồn: [Database Providers](https://learn.microsoft.com/en-us/ef/core/providers/).

**Mitigation:** publish adapter theo major version và CI matrix.

### Maintenance burden

**Mitigation:** giữ core nhỏ, support PostgreSQL + SQL Server trước, không cố hỗ trợ mọi provider ngay.

## 16. Kiểm thử

### Strategy

- Unit test graph ordering, generator selection, uniqueness retry và deterministic seed.
- Integration test metadata inspection bằng sample DbContext.
- Integration test database thật qua Testcontainers.
- CLI end-to-end test từ empty DB đến populated DB.
- Failure-path test cho unsupported cycles và invalid config.
- Security test đảm bảo production guard không bị bypass dễ dàng.

### 5 test scenario quan trọng nhất

1. `Customer → Order → OrderItem` được insert đúng dependency và không có orphan FK.
2. Hai lần chạy với cùng random seed trên DB sạch sinh cùng dataset snapshot.
3. Unique field collision được retry và cuối cùng vẫn unique.
4. Required FK cycle không thể resolve làm command fail trước khi ghi dữ liệu.
5. Connection target bị đánh dấu production khiến command từ chối write nếu chưa có explicit override.

### Verification checklist

- [ ] CLI tìm đủ 3 entity.
- [ ] Primary key được detect đúng.
- [ ] Required/string max length được đọc đúng nếu đã cấu hình.
- [ ] Foreign key principal/dependent được detect đúng.
- [ ] Generation order là `Customer → Order → OrderItem`.
- [ ] Không dùng regex/source parsing.
- [ ] Có ít nhất một unit test cho topological ordering.

### Stop condition

Dừng session ngay khi CLI có thể tạo dependency plan chính xác từ `DbContext.Model` và test graph ordering pass. Không thêm Bogus, YAML, database insertion, UI hay AI trong session đầu tiên.
