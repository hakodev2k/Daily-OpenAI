# Ý tưởng hôm nay: Dependency & Runtime End-of-Life Radar

## 1. Tóm tắt ý tưởng

**Dependency & Runtime End-of-Life Radar** là một công cụ self-hosted dành cho developer/team nhỏ, tự động quét repository để phát hiện các công nghệ có nguy cơ “hết hạn kỹ thuật”: .NET runtime sắp End of Support, NuGet package đã deprecated, Docker base image cũ, GitHub Actions version lỗi thời hoặc dependency đã lâu không được cập nhật. Điểm khác biệt không phải chỉ báo “có version mới”, mà là trả lời câu hỏi **“cái gì cần nâng cấp trước, trước deadline nào, và rủi ro nếu trì hoãn là gì?”**.

- **Project size:** Medium
- **Estimated MVP time:** 2–4 tuần làm ngoài giờ
- **Primary category:** Developer productivity / Security & maintenance
- **Mục tiêu MVP:** scan một hoặc nhiều .NET repository, tạo health report theo deadline và gửi cảnh báo khi dependency/runtime đi vào vùng nguy hiểm.

## 2. Bài toán thực tế

### Confirmed facts

Microsoft công bố lifecycle chính thức cho các bản .NET. Tính đến 17/08/2026, .NET 10 là LTS và còn Active support tới 14/11/2028; .NET 8 và .NET 9 đều có End of Support vào 10/11/2026. Điều này có nghĩa một ứng dụng vẫn build và chạy bình thường nhưng có thể chỉ còn vài tháng trước khi runtime rơi khỏi support window. Nguồn: [Official .NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy).

NuGet hỗ trợ metadata deprecation trong V3 API. Một package có thể được đánh dấu `Legacy`, `CriticalBugs` hoặc `Other`, và có thể chỉ định package thay thế. `dotnet list package --deprecated` cũng có thể hiển thị dependency đã deprecated. Nguồn: [NuGet package metadata](https://learn.microsoft.com/en-us/nuget/api/registration-base-url-resource) và [Deprecating packages on nuget.org](https://learn.microsoft.com/en-us/nuget/nuget-org/deprecate-packages).

GitHub Dependabot hỗ trợ version updates cho nhiều ecosystem, trong đó có Docker và GitHub Actions; nó có thể mở pull request khi có version mới. Nguồn: [GitHub Dependabot version updates](https://docs.github.com/en/code-security/concepts/supply-chain-security/dependabot-version-updates) và [Configuring Dependabot version updates](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/configure-version-updates).

Docker Scout có thể đánh giá base image, phát hiện base image lỗi thời và đưa ra recommendation để refresh/update. Nguồn: [Docker Scout recommendations](https://docs.docker.com/reference/cli/docker/scout/recommendations/) và [Docker Scout policies](https://docs.docker.com/scout/policy/local/).

### Observation

Các công cụ hiện tại thường giải quyết từng lát cắt riêng:

- Dependabot: dependency version update;
- `dotnet list package`: NuGet state;
- .NET support page: runtime lifecycle;
- Docker Scout: image/security state;
- GitHub Actions ecosystem: action updates.

Developer vẫn phải tự tổng hợp chúng để trả lời câu hỏi quan trọng hơn:

> Repository nào đang gần đến “maintenance deadline”, thứ gì phải xử lý trước, và nếu không làm thì rủi ro operational/security/support là gì?

### Vấn đề thực tế

Trong nhiều repository, technical debt liên quan dependency không tạo lỗi tức thì. Những ví dụ phổ biến:

- project target `.NET 8` trong khi EOS chỉ còn vài tháng;
- Dockerfile vẫn dùng `mcr.microsoft.com/dotnet/aspnet:8.0`;
- NuGet package đã deprecated nhưng build không fail;
- GitHub workflow vẫn dùng action major version cũ;
- package update PR tồn tại nhưng bị bỏ qua vì không ai biết mức ưu tiên;
- nhiều repo dùng cùng runtime cũ nhưng không có dashboard tổng hợp.

Hậu quả thường đến muộn: lúc cần security patch, lúc package ngừng support, lúc pipeline action thay đổi hoặc lúc migration trở thành gấp.

### Assumption cần validate

Giả định MVP là developer/team nhỏ có từ 5–30 repository sẽ thấy giá trị nếu có một **maintenance radar** gom tất cả lifecycle risk thành một danh sách ưu tiên rõ ràng. Cần phỏng vấn 3–5 developer/Tech Lead để xác nhận họ có thực sự cần dashboard + deadline prioritization hay chỉ Dependabot đã đủ.

## 3. Người dùng mục tiêu

### Primary user

Backend developer, Tech Lead hoặc solo developer quản lý nhiều repository .NET có Docker/GitHub Actions.

### Context of use

- có nhiều project .NET đang active hoặc semi-maintained;
- package updates không được xử lý đều đặn;
- có Dockerfile và CI/CD;
- không có dedicated platform/security team;
- muốn nhìn health state của tất cả repo trong một dashboard.

### Main pain point

Không biết repository nào cần upgrade trước cho tới khi dependency/runtime trở thành vấn đề gấp.

### Current workaround

- kiểm tra .NET support page thủ công;
- Dependabot PR;
- `dotnet list package --outdated`;
- `dotnet list package --deprecated`;
- xem Docker tags;
- review GitHub Actions thủ công;
- ghi issue “upgrade later”.

### Lý do họ sẽ thử

Chỉ cần trỏ tool vào repository local hoặc GitHub URL/token. Sau scan đầu tiên, họ nhận ngay một danh sách có mức độ ưu tiên và deadline.

## 4. Giải pháp đề xuất

Tool tạo một **technology lifecycle inventory** cho mỗi repository.

### Main workflow

1. User add repository.
2. Scanner đọc:
   - `*.csproj`;
   - `global.json`;
   - `Directory.Packages.props`;
   - `Dockerfile`;
   - `.github/workflows/*.yml`;
   - `dependabot.yml` nếu có.
3. Hệ thống extract runtime/package/action/image versions.
4. Enricher gọi các nguồn metadata chính thức hoặc deterministic command.
5. Rule engine tính risk score.
6. Dashboard xếp hạng các item:
   - Critical;
   - Due Soon;
   - Deprecated;
   - Outdated;
   - Healthy.
7. User xem remediation plan.
8. Scheduler scan lại theo ngày/tuần.
9. Nếu item chuyển từ Healthy → Due Soon/Critical, gửi notification.

### Input

- local repository path hoặc GitHub repository;
- optional GitHub token;
- warning windows, ví dụ 180/90/30 ngày trước EOS;
- package ignore rules.

### Processing

- source file discovery;
- dependency extraction;
- metadata lookup;
- cache metadata;
- lifecycle evaluation;
- score calculation;
- snapshot comparison;
- notification decision.

### Output

Ví dụ:

```text
Repository: employee-api
Health Score: 63/100

CRITICAL
- TargetFramework: net8.0
  End of Support: 2026-11-10
  Days remaining: 85
  Recommendation: Plan .NET 10 migration now

WARNING
- Package: Some.Legacy.Package 2.3.1
  Status: Deprecated / Legacy
  Alternative: Some.New.Package

INFO
- actions/checkout@v5
  New major release detected: v6
```

### Tự động hóa

- scheduled scans;
- metadata refresh;
- lifecycle calculation;
- severity transitions;
- notification;
- historical trend.

### User control

- suppress item;
- set target remediation date;
- set repository criticality;
- change warning thresholds;
- decide whether to upgrade.

### Key differentiator

Không cố thay Dependabot. Radar tập trung vào **maintenance planning theo deadline** và tổng hợp nhiều loại technology dependency vào một view.

### Ví dụ end-to-end

User add 8 repository .NET.

Scanner phát hiện 5 repo target `net8.0`. Lifecycle source cho biết .NET 8 EOS ngày 10/11/2026. Hệ thống tính còn 85 ngày và đánh dấu các repo production là `Critical`, repo demo là `Warning`. Dashboard tạo migration batch:

```text
Upgrade Wave 1
- Payroll API
- Employee API
- Notification Worker

Reason: Production + .NET 8 EOS < 90 days
```

User không cần nhớ lifecycle date hoặc mở từng repo để kiểm tra.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Technical debt được chuyển từ khái niệm mơ hồ thành deadline cụ thể.

### Technical learning value

Dự án giúp luyện:

- repository parsing;
- NuGet protocol;
- GitHub API;
- dependency inventory;
- background jobs;
- caching;
- rule engine;
- lifecycle modeling;
- secure token handling;
- idempotent scans;
- report generation.

### Phù hợp solo developer

MVP không cần tự xây vulnerability database hay dependency resolver. Có thể dùng deterministic parsers và official APIs/CLI.

### Hữu ích dù chỉ có một user

Một solo developer quản lý nhiều repo cá nhân vẫn có thể dùng như maintenance dashboard.

### Điều làm dự án thất bại

Nếu người dùng chỉ quản lý 1–2 repo và Dependabot đã đủ, dashboard riêng có thể dư thừa.

### Strongest reason not to build

Nếu validation cho thấy user chỉ quan tâm “có version mới hay không”, Dependabot + Renovate đã giải quyết tốt hơn. Dự án chỉ đáng làm nếu **lifecycle deadline + multi-repo prioritization** là nhu cầu thật.

## 7. Luồng hoạt động

```text
User adds repository
        ↓
Validate repository path/access
        ↓
Discover manifest files
        ↓
Extract runtimes/packages/images/actions
        ↓
Normalize dependency identities
        ↓
Fetch lifecycle/deprecation metadata
        ↓
Evaluate rules
        ↓
Persist scan snapshot
        ↓
Compare with previous snapshot
        ↓
Severity increased?
   ┌────┴────┐
  No        Yes
  ↓          ↓
Dashboard   Notification
```

### Alternative flows và failure cases

**Repository inaccessible**

- scan status `RepositoryUnavailable`;
- giữ snapshot cũ;
- không reset health score về 0.

**NuGet API timeout**

- dùng cached metadata;
- đánh dấu metadata stale;
- retry sau.

**Package không tồn tại trên nuget.org**

- đánh dấu `UnknownSource`;
- không suy đoán deprecation.

**Malformed csproj**

- lưu parser error theo file;
- tiếp tục scan các file còn lại nếu có thể.

**GitHub Action dùng local action**

Ví dụ `uses: ./.github/actions/foo` không lookup remote version.

**Docker image private registry**

- extract image reference;
- metadata lookup optional;
- không gửi credential nếu chưa cấu hình.

## 9. Công nghệ đề xuất

### .NET 10 LTS

Tính đến 17/08/2026, .NET 10 là LTS, Active support, EOS 14/11/2028. .NET 8 và .NET 9 cùng kết thúc support ngày 10/11/2026. Đây chính là một use case thực tế cho sản phẩm. Nguồn: [Official .NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy).

**Why fit:** phù hợp stack, lifecycle dài, tốt cho background/service tooling.

**Simpler alternative:** .NET 8 nếu môi trường build hiện tại bắt buộc, nhưng không hợp lý cho project mới vào thời điểm này do EOS gần.

**Outgrow:** runtime khó là bottleneck; scalability issue sẽ ở scanner throughput/API limits.

### ASP.NET Core

Minimal API hoặc controller đều phù hợp.

**Simpler alternative:** CLI-only MVP trước dashboard.

### EF Core + PostgreSQL

Phù hợp historical snapshots và query dashboard.

**Simpler alternative:** SQLite cho bản local đầu tiên.

### NuGet.Protocol

Microsoft cung cấp `NuGet.Protocol` để tương tác HTTP/folder-based package feeds. Nguồn: [NuGet Client SDK](https://learn.microsoft.com/en-us/nuget/reference/nuget-client-sdk).

**Why fit:** tránh tự xây raw HTTP protocol toàn bộ.

**Simpler alternative:** gọi `dotnet list package --deprecated` và parse output JSON/text nếu version CLI hỗ trợ format cần thiết.

### Hangfire

Phù hợp scheduled scans và retries.

**Simpler alternative:** `BackgroundService` + timer/cron.

### YamlDotNet

Parse `.github/workflows/*.yml` an toàn hơn regex đơn thuần.

### System.Xml.Linq

Đủ để parse csproj/props ở MVP; không cần MSBuild evaluation engine ngay từ đầu.

### Docker

Đóng gói self-hosted tool.

### Playwright

E2E dashboard flow.

### GitHub Actions

CI build/test/publish image.

## 11. API và tích hợp

### NuGet V3 Registration API

**Purpose:** package metadata và deprecation.

NuGet documentation xác nhận registration metadata có trường deprecation với reason, message và alternate package. Nguồn: [Package Metadata, NuGet API](https://learn.microsoft.com/en-us/nuget/api/registration-base-url-resource).

**Auth:** không cần với nuget.org public feed.

**Rate/cost:** cần caching và không query lặp package/version mỗi scan.

**Privacy:** chỉ package ID/version được gửi tới feed.

**Fallback:** `dotnet list package --deprecated`.

### GitHub API

**Purpose:** optional repository fetch, default branch SHA và metadata.

**Auth:** fine-grained token/GitHub App sau MVP.

**Rate limit:** phải cache và scan theo commit SHA để bỏ qua repo không đổi.

**Privacy:** private repositories yêu cầu permission tối thiểu.

**Fallback:** local checkout mode.

### `dotnet` CLI

**Purpose:** cross-check package state.

`dotnet list package --deprecated` được NuGet documentation mô tả là cách để consumer thấy package deprecated.

**Auth:** thừa hưởng NuGet config/feed credential của host.

**Privacy:** package feeds private có thể chứa internal names.

**Fallback:** static manifest parser.

### Docker Scout CLI — optional

Docker Scout có recommendation cho base image updates và policy `No outdated base images`. Nguồn: [Docker Scout recommendations](https://docs.docker.com/reference/cli/docker/scout/recommendations/) và [Evaluate policies](https://docs.docker.com/scout/policy/local/).

**Auth:** phụ thuộc registry/scout usage.

**Cost:** không nên bắt buộc MVP.

**Fallback:** chỉ inventory Docker image và flag runtime major known-EOS.

### Dependabot metadata/config

GitHub xác nhận Dependabot có thể monitor Docker và GitHub Actions version updates. Đây là lý do Radar không nên copy chức năng auto-update mà chỉ dùng data/context để đưa ra maintenance priority. Nguồn: [Configuring Dependabot version updates](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/configure-version-updates).

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

AI không cần cho detection, vì lifecycle/deprecation/version parsing đều deterministic.

### AI task hợp lý về sau

Sinh migration brief dựa trên findings:

```json
{
  "repository": "employee-api",
  "upgradeFrom": ".NET 8",
  "upgradeTo": ".NET 10",
  "riskAreas": [
    "EF Core provider compatibility",
    "ASP.NET Core breaking changes",
    "Docker base image"
  ],
  "suggestedValidation": [
    "run integration tests",
    "compare API behavior",
    "rebuild container"
  ]
}
```

### Required context

- current runtime;
- target runtime;
- package inventory;
- known findings;
- repo structure summary.

### Validation

- JSON Schema;
- AI không được tạo lifecycle date;
- dates/severity luôn lấy từ deterministic source;
- AI recommendation chỉ là supplemental.

### Deterministic fallback

Template remediation plan theo finding type.

### Risks

- hallucinated breaking changes;
- gửi source/package metadata ra external model;
- cost/latency.

Kết luận: **không dùng AI trong MVP**.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

**Goal:** xác nhận multi-repo lifecycle prioritization là pain thật.

**Tasks:**

- hỏi 3–5 developer đang quản lý nhiều repo;
- cho họ xem mock report gồm runtime EOS/package deprecated;
- hỏi Dependabot hiện tại còn thiếu gì;
- đo xem họ có biết EOS date của runtime đang dùng không.

**Expected output:** pain map.

**Completion criteria:** ít nhất 2 người muốn một view deadline/priority thay vì chỉ update PR.

**Goal:** scan local .NET repo và tạo report.

**Tasks:**

- parse csproj;
- detect target framework;
- parse package references;
- lookup NuGet deprecation;

- save scan;

**Expected output:** repository report có findings thật.

**Completion criteria:** repo target net8.0 được đánh dấu theo EOS window và deprecated NuGet package được detect đúng.

## 14. Các bài toán kỹ thuật đáng học

### 1. Static repository analysis

Cần parse nhiều format: XML, YAML, Dockerfile.

**Skill:** source configuration parsing, tolerant parsers, normalization.

### 2. Lifecycle rule engine

Ví dụ:

```text
EOS passed                       → Critical
EOS <= 30 days                   → Critical
EOS <= 90 days                   → Warning
Deprecated package               → Warning/Critical based on reason
Unknown metadata                 → Info
```

**Skill:** policy/rule modeling và explainable decisions.

### 3. Metadata caching + rate limiting

Không thể gọi NuGet/GitHub API cho mọi item mỗi scan.

**Skill:** cache TTL, conditional refresh, throttling.

### 4. Idempotent background scans

Job retry không được nhân đôi findings/notifications.

**Skill:** idempotency key, distributed-safe thinking dù MVP single node.

### 5. Dependency identity normalization

`Microsoft.EntityFrameworkCore`, Docker image tags và GitHub Action refs có semantic version rules khác nhau.

**Skill:** version models, ecosystem adapters, abstraction boundaries.

## 15. Rủi ro và cách xử lý

### Technical complexity

**Risk:** cố hỗ trợ quá nhiều ecosystem.

**Mitigation:** MVP chỉ `.NET + NuGet`; Docker/Actions là phase tiếp theo.

### Scope expansion

**Risk:** biến thành Renovate/Dependabot clone.

**Mitigation:** không auto-update ở MVP; chỉ inventory + deadline + priority.

### Data privacy

**Risk:** private repo names và internal packages.

**Mitigation:** local/self-hosted mode trước; chỉ gửi minimum metadata ra API cần thiết.

### Security

**Risk:** GitHub token có quyền rộng.

**Mitigation:** fine-grained token, read-only scopes, encrypted-at-rest, secret redaction.

### API dependency

**Risk:** NuGet/GitHub API unavailable.

**Mitigation:** cache metadata + stale status.

### Unreliable lifecycle data

**Risk:** support date thay đổi hoặc nguồn page format thay đổi.

**Mitigation:** source lifecycle data qua maintainable adapter; record source URL/fetched date; allow manual override.

### Cost

MVP chi phí thấp. PostgreSQL + app trên VPS nhỏ đủ cho hàng chục repo.

### Legal/platform restrictions

Không scrape private sites; chỉ dùng repo user có quyền và public/official metadata endpoints.

### User adoption

**Risk:** report quá nhiều noise.

**Mitigation:** criticality weighting, snooze, only-notify-on-transition.

### Maintenance burden

**Risk:** ecosystem formats/version semantics đổi.

**Mitigation:** adapter architecture + test fixtures theo ecosystem.

Trong session đầu, lifecycle data có thể hard-code dưới dạng test fixture/config:

```csharp

    Major: 8,
    ReleaseType: "LTS",
    SupportStatus: "Maintenance",
    EndOfSupport: new DateOnly(2026, 11, 10));
```

Mục tiêu session không phải tự động crawl support page. Chỉ chứng minh inventory + rule engine hoạt động.

### Expected result

Chạy API với một repo .NET 8 thực tế và nhận JSON report có:

- detected `TargetFramework`;
- direct NuGet packages;
- days-to-EOS;
- severity.

### Verification checklist

- [ ] `dotnet build` thành công.
- [ ] Scanner tìm tất cả `*.csproj` bên dưới repo root.
- [ ] `TargetFramework` và `TargetFrameworks` đều được xử lý.
- [ ] `PackageReference Include/Version` được parse.
- [ ] `net8.0` map đúng EOS `2026-11-10` trong fixture.
- [ ] Days remaining tính theo UTC/date deterministic.
- [ ] Repo path ngoài allow-root bị reject.
- [ ] Unit test cho severity 180/90/30/0-day boundary.
- [ ] API trả visible JSON result.

### Stop condition

Dừng session khi một repository .NET thật có thể được scan end-to-end và API trả đúng framework/package inventory cùng lifecycle severity. **Không thêm database, Hangfire, NuGet API, GitHub integration hoặc UI trong session đầu.**

Đây là một dự án đáng thử vì nó không cạnh tranh trực tiếp với package update bots. Giá trị cốt lõi là **biến dependency debt thành maintenance deadlines có thứ tự ưu tiên**. MVP nên bắt đầu rất nhỏ với `.NET runtime + NuGet deprecation`; chỉ khi người dùng thực sự dùng report để lên kế hoạch upgrade mới thêm Docker, GitHub Actions, CVE hoặc auto-PR.
