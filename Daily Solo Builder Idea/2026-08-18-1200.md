# Ý tưởng hôm nay: Personal Workflow Replay Assistant

## 1. Tóm tắt ý tưởng

Xây dựng công cụ ghi nhận và phân tích các workflow lặp lại trên máy tính để giúp developer tự động hóa những thao tác tốn thời gian. Người dùng có thể mô tả một quy trình thường làm, ghi lại các bước thủ công, sau đó tạo thành checklist, script hoặc automation workflow.

Quy mô: Medium. MVP dự kiến 3-4 tuần.

## 2. Bài toán thực tế

Nhiều developer và nhân viên văn phòng lặp lại các chuỗi thao tác như chuẩn bị môi trường, kiểm tra log, tạo báo cáo, kiểm thử thủ công hoặc xử lý file. Hiện nay họ thường ghi nhớ bằng kinh nghiệm, tạo tài liệu rời rạc hoặc tự viết script khi vấn đề đã trở nên khó chịu.

Giả định: nhóm nhỏ thường có nhiều quy trình cá nhân chưa được chuẩn hóa.

## 3. Người dùng mục tiêu

Primary user: Developer làm việc với nhiều dự án và công cụ.

Pain point: mất thời gian lặp lại cùng một chuỗi thao tác nhưng không biết nên tự động hóa từ đâu.

Current workaround: bookmark, note, script cá nhân, copy command từ lịch sử terminal.

## 4. Giải pháp đề xuất

Workflow:

- Người dùng tạo một workflow mới.
- Ghi lại các bước thực hiện bằng text, command hoặc file input.
- Hệ thống lưu sequence và metadata.
- Người dùng chạy lại workflow hoặc xuất thành script.

Ví dụ: một .NET developer tạo workflow "Chuẩn bị debug production issue": lấy log → lọc exception → tạo summary → gửi báo cáo. Tool lưu lại quy trình và giúp chạy lại nhanh hơn.

Điểm khác biệt: tập trung vào biến workflow cá nhân thành automation có thể tái sử dụng thay vì chỉ quản lý task.

## 5. Tại sao ý tưởng này đáng làm

Giá trị thực tế: giảm thời gian cho các công việc lặp lại.

Giá trị kỹ thuật: học workflow engine, automation design, command execution, audit trail.

Phù hợp solo developer vì MVP chỉ cần hỗ trợ workflow dạng text/command.

Lý do thất bại: người dùng có thể thấy việc ghi lại workflow còn mất thời gian hơn lợi ích nhận được.

## 6. Phạm vi MVP

### Must have

- Tạo workflow.
- Thêm step dạng command hoặc manual action.
- Chạy workflow từng bước.
- Lưu lịch sử execution.

### Should have

- Export PowerShell/Bash script.
- Schedule workflow.
- Notification khi hoàn thành.

### Later

- Browser automation.
- AI workflow suggestion.
- Marketplace workflow.

## 7. Luồng hoạt động

User tạo workflow → validate step → lưu database → execute runner → ghi log → trả kết quả.

Failure cases:

- Command thất bại.
- Permission không đủ.
- Workflow timeout.

## 8. Kiến trúc đề xuất

- Frontend: Vue 3 dashboard.
- Backend: ASP.NET Core modular monolith.
- Database: PostgreSQL.
- Worker: BackgroundService xử lý execution.
- Queue: không cần ở MVP, có thể thêm khi workflow dài.
- Storage: local storage cho artifact.
- Logging: Serilog.

Không dùng microservices vì domain ban đầu nhỏ.

## 9. Công nghệ đề xuất

- .NET 10 + ASP.NET Core: phù hợp backend workflow.
- EF Core + PostgreSQL: quản lý workflow và execution history.
- Vue 3: xây UI nhanh.
- Docker: chạy local và deploy VPS.
- GitHub Actions: CI/CD.

Alternative đơn giản hơn: CLI .NET thuần trước khi làm web.

## 11. API và tích hợp

- GitHub API: lấy repository context nếu cần.
- Local shell execution: chạy command.
- Slack/Telegram webhook: gửi notification.

Cần kiểm soát permission vì command execution có rủi ro bảo mật.

## 12. AI có thực sự cần thiết không?

AI hữu ích nhưng optional.

Có thể dùng AI để:

- Gợi ý bước automation từ mô tả workflow.
- Giải thích lỗi execution.

Không dùng AI để chạy workflow hoặc quyết định quyền thực thi.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

Tạo CLI lưu workflow JSON và chạy step đơn giản.

Hoàn thành khi có thể tự động hóa một workflow cá nhân.

### Phase 1 — Core MVP

Xây backend, database, dashboard và execution engine.

### Phase 2 — Reliability

Thêm retry, timeout, permission check, test.

### Phase 3 — Useful expansion

Thêm export script và notification.

### Phase 4 — Production readiness

Deploy, backup, monitoring, documentation.

## 14. Các bài toán kỹ thuật đáng học

1. Workflow engine: thiết kế execution state machine.
2. Retry/idempotency: xử lý chạy lại an toàn.
3. Permission sandboxing: giới hạn command nguy hiểm.
4. Background processing: quản lý tác vụ dài.

## 15. Rủi ro và cách xử lý

- Security: giới hạn command và require confirmation.
- Scope creep: chỉ hỗ trợ workflow đơn giản ban đầu.
- Khó dùng: bắt đầu bằng CLI trước.

## 16. Kiểm thử

1. Workflow chạy thành công.
2. Step lỗi giữa chừng.
3. Retry sau failure.
4. User không có permission.
5. Workflow bị timeout.

## 17. Cách đo dự án có hữu ích hay không

- Số workflow được tạo.
- Số lần chạy automation.
- Thời gian tiết kiệm mỗi tuần.
- Tỷ lệ workflow thành công.

## 20. Việc cần làm ngay hôm nay

Mục tiêu 90 phút: tạo CLI workflow runner đầu tiên.

Files:

- src/WorkflowRunner/Program.cs
- src/WorkflowRunner/Models/Workflow.cs
- src/WorkflowRunner/Services/ExecutionEngine.cs
- tests/WorkflowRunner.Tests.cs

Commands:

```bash
dotnet new console -n WorkflowRunner
dotnet new xunit -n WorkflowRunner.Tests
```

Vertical slice:

Input: workflow.json chứa 3 bước command.

Output: execution log hiển thị trên terminal.

Verification:

- Chạy workflow thành công.
- Xử lý một step lỗi.
- Lưu execution history.

Stop condition: CLI có thể chạy lại cùng một workflow và trả kết quả nhất quán.
