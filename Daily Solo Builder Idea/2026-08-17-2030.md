# Ý tưởng hôm nay: ContextDeck — Biến câu tiếng Anh kỹ thuật bắt gặp khi đọc web thành bộ ôn tập theo ngữ cảnh

## 1. Tóm tắt ý tưởng

**ContextDeck** là một browser extension + web app giúp developer lưu nhanh những câu, cụm từ hoặc thuật ngữ tiếng Anh kỹ thuật họ gặp khi đọc tài liệu, issue, PR, blog hoặc documentation, sau đó biến chúng thành một hàng đợi ôn tập theo ngữ cảnh thay vì học vocabulary rời rạc. Sản phẩm dành cho developer đang cải thiện tiếng Anh công việc nhưng không muốn tách việc học ra khỏi luồng đọc kỹ thuật hằng ngày.

- **Kích thước:** Medium
- **MVP ước tính:** 10–14 ngày làm ngoài giờ
- **Core value:** chọn một đoạn text trên web → lưu context + source → tạo card → ôn lại sau theo lịch spaced repetition.

## 2. Bài toán thực tế

Developer đọc rất nhiều nội dung tiếng Anh: documentation, GitHub issue, release note, Stack Overflow, blog kỹ thuật, RFC, changelog, pull request, error message. Trong quá trình đó thường gặp các cụm từ như:

- `backward-compatible change`
- `root cause remains unclear`
- `the request is idempotent`
- `we need to narrow the blast radius`
- `this approach does not scale well`

Nhiều câu rất hữu ích trong công việc nhưng bị quên ngay sau khi đóng tab.

### Cách xử lý hiện tại

Người học thường:

- copy vào Notes/Notion;
- tra Google Translate rồi bỏ đó;
- tự tạo Anki card thủ công;
- lưu bookmark cả trang;
- chụp màn hình;
- gửi câu vào ChatGPT để hỏi nghĩa.

Các cách này bị phân mảnh. Việc “gặp câu → lưu → tạo bài ôn → ôn đúng lúc” có quá nhiều bước nên thường bị bỏ qua.

### Fact đã xác nhận

Chrome Extensions hỗ trợ thêm context-menu item cho text được chọn. API `chrome.contextMenus` có context `selection`, và event data có trường `selectionText`, nghĩa là extension có thể triển khai flow “bôi đen câu → right click → Save to ContextDeck” mà không phải scrape DOM toàn trang. Nguồn: [Chrome for Developers — chrome.contextMenus](https://developer.chrome.com/docs/extensions/reference/api/contextMenus).

Nghiên cứu HCI “Broccoli: Sprinkling Lightweight Vocabulary Learning into Everyday Information Diets” cho thấy một hướng học vocabulary tích hợp trực tiếp vào nội dung người dùng đang tiêu thụ là khả thi và có thể giảm cognitive overhead so với tách hoàn toàn sang workflow học riêng. Đây không phải bằng chứng rằng ContextDeck chắc chắn hiệu quả, nhưng là tín hiệu nghiên cứu hỗ trợ ý tưởng “học từ ngữ cảnh thật”. Nguồn: [Broccoli paper](https://arxiv.org/abs/2104.07941).

### Observation

Công cụ flashcard hiện có thường tối ưu cho việc quản lý deck/card. Điểm chưa được giải quyết trực tiếp trong workflow của developer là bước **capture sentence from technical reading with source context** thật nhanh rồi ôn lại đúng chính câu đó.

### Assumption cần kiểm chứng

Một developer có thể thấy giá trị nếu việc lưu card mất dưới 3–5 giây. Nếu phải sửa nhiều metadata hoặc viết definition thủ công, sản phẩm sẽ thất bại vì friction cao hơn lợi ích.

## 3. Người dùng mục tiêu

### Primary user

Developer Việt Nam ở mức tiếng Anh A2–B1/B2 đang đọc documentation tiếng Anh hằng ngày và muốn cải thiện vocabulary/cách diễn đạt phục vụ công việc.

### Context sử dụng

- đọc Microsoft Learn;
- đọc GitHub issue/PR;
- đọc release note;
- debug từ error message;
- đọc blog kiến trúc;
- đọc API docs.

### Pain point chính

Người dùng hiểu được ý chung khi đọc nhưng không giữ lại được những phrase có giá trị để dùng lại trong meeting, chat, email hoặc code review.

### Workaround hiện tại

Copy vào Notion/Anki hoặc hỏi AI rồi quên.

### Lý do họ thử ContextDeck

Vì ContextDeck giảm workflow thành một thao tác:

> Select text → Save → review later.

Không cần mở app học trong lúc đang đọc.

## 4. Giải pháp đề xuất

### Main workflow

1. User bôi đen một câu tiếng Anh trên trình duyệt.
2. Right-click → `Save to ContextDeck`.
3. Extension gửi:
   - selected text;
   - page title;
   - page URL;
   - timestamp.
4. Backend normalize text và chống duplicate.
5. Hệ thống tạo một card ở trạng thái `New`.
6. Khi user mở trang review, card xuất hiện theo lịch spaced repetition.
7. User tự đánh giá `Again / Hard / Good / Easy`.
8. Scheduler tính ngày review tiếp theo.

### Input

- selected sentence;
- URL;
- page title;
- optional manual note;
- optional translation/explanation.

### Processing

Deterministic core:

- normalize whitespace;
- hash sentence + source;
- duplicate detection;
- card state;
- review scheduling;
- retention metrics.

Optional AI:

- giải nghĩa bằng tiếng Việt;
- extract 1–3 useful phrases;
- tạo example sentence liên quan software engineering;
- giải thích grammar pattern.

### Output

Mỗi card hiển thị:

- original sentence;
- source title;
- source link;
- highlighted phrase;
- Vietnamese explanation nếu có;
- user note;
- next review date.

### User control

User quyết định:

- card nào đáng giữ;
- nghĩa nào đúng;
- phrase nào cần học;
- xóa/suspend card;
- mức độ nhớ sau mỗi review.

### Key differentiator

Không cạnh tranh với Anki bằng “flashcard tốt hơn”. Differentiator là **capture technical English from real browsing context** cực nhanh, giữ nguyên source, rồi đưa vào learning loop.

### Ví dụ end-to-end

Hà đọc một GitHub issue và gặp câu:

> `The fix reduces the blast radius but does not eliminate the underlying race condition.`

Anh bôi đen câu, right-click `Save to ContextDeck`. Buổi tối, card xuất hiện. Front side chỉ hiện câu và che cụm `blast radius`. Back side hiển thị nghĩa ngắn, source URL và một note: “blast radius = phạm vi ảnh hưởng khi sự cố xảy ra”. Sau khi chọn `Good`, card được lên lịch lại sau vài ngày.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Sản phẩm gắn việc học vào đúng nơi người dùng đã dành thời gian mỗi ngày: đọc nội dung kỹ thuật.

### Technical learning value

Dự án có nhiều bài toán đáng học:

- browser extension architecture;
- extension permission design;
- sync giữa extension và backend;
- offline queue;
- duplicate detection;
- scheduling algorithm;
- structured AI output;
- privacy boundaries;
- E2E testing extension + web app.

### Vì sao phù hợp solo developer

MVP chỉ cần:

- một Chrome extension;
- một ASP.NET Core API;
- SQLite/PostgreSQL;
- một review page nhỏ.

Không cần real-time infrastructure hay scraping pipeline.

### Vẫn hữu ích nếu chỉ có một user

Đây là personal utility rõ ràng. Một người dùng duy nhất vẫn có giá trị vì toàn bộ dữ liệu phục vụ chính người học.

### Điều gì khiến nó fail

Nếu capture chậm hoặc review UX tệ, user sẽ quay lại copy text vào ChatGPT/Anki.

### Lý do mạnh nhất để không build

Anki và các flashcard app đã rất mạnh. Nếu ContextDeck chỉ trở thành một flashcard app khác, nó không đáng xây. Giá trị phải nằm ở capture workflow + technical-context learning, không phải deck management chung chung.

## 7. Luồng hoạt động

### Flow chính

User select text
→ Chrome context menu
→ extension validate text length
→ build capture payload
→ POST backend
→ backend normalize
→ duplicate check
→ persist Card
→ return saved status
→ card enters review queue
→ user reviews
→ save ReviewEvent
→ scheduler updates `NextReviewAt`.

### Offline flow

POST fail
→ extension lưu payload vào `chrome.storage.local`
→ badge hiển thị số capture chưa sync
→ lần sau browser online, extension retry
→ backend dùng idempotency key để tránh duplicate.

### Duplicate flow

Same normalized sentence + same canonical URL đã tồn tại
→ backend trả existing card
→ extension hiển thị `Already saved`.

### Invalid flow

- selection rỗng;
- > 2.000 ký tự;
- URL scheme nhạy cảm như `chrome://`;
- password/input selection không có context phù hợp.

→ không capture hoặc yêu cầu manual confirmation.

### Review flow

GET `/api/reviews/due`
→ trả card due theo priority
→ user rating
→ POST ReviewEvent
→ schedule next interval
→ next card.

## 8. Kiến trúc đề xuất

### Tổng thể

**Modular Monolith + Browser Extension**.

Không cần microservices.

### Module backend

- `Cards`
- `Captures`
- `Reviews`
- `Scheduling`
- `Exports`
- `AiEnrichment` — để trống trong MVP.

### Chrome Extension

Các phần:

- `manifest.json`
- background service worker;
- context-menu registration;
- sync queue;
- options page cho API URL/token;
- popup đơn giản.

Chrome official docs xác nhận `contextMenus` permission và selection context được hỗ trợ cho extension. Nguồn: [Chrome contextMenus API](https://developer.chrome.com/docs/extensions/reference/api/contextMenus).

### Backend

ASP.NET Core Web API.

Nhiệm vụ:

- authentication token;
- validation;
- persistence;
- duplicate detection;
- review schedule;
- export.

### Database

SQLite cho local/self-hosted single-user.

PostgreSQL nếu chuyển hosted multi-user.

### Background worker

Không bắt buộc cho core MVP.

`NextReviewAt` được tính ngay khi rating. Dashboard query card đến hạn trực tiếp từ DB.

Chỉ cần worker khi thêm daily digest hoặc AI enrichment queue.

### Queue

Không cần message broker.

Offline queue nằm ở extension storage; backend có idempotency.

### Cache

Không cần Redis.

### File storage

Không cần cho MVP.

### Authentication

Single-user API token là đủ cho bản personal/self-hosted.

Cloud multi-user về sau dùng OIDC/ASP.NET Core Identity.

### AI

Không có trong core path.

### Logging

`ILogger` structured logs, tuyệt đối không log toàn bộ selected sentence ở Information level nếu user coi nội dung đọc là riêng tư.

### Deployment

- backend self-hosted trên mini PC/VPS;
- extension cài unpacked trong development;
- production có thể publish Chrome Web Store sau khi policy/permission review rõ ràng.

## 11. API và tích hợp

### Chrome `contextMenus`

**Purpose:** capture selected text ngay tại trang đang đọc.

**Authentication:** không có auth external; extension dùng Chrome API.

**Permission concern:** manifest cần `contextMenus` permission. Chỉ nên xin permission tối thiểu. Chrome docs cho phép context `selection` và cung cấp `selectionText`. Nguồn: [Chrome Extensions Context Menus API](https://developer.chrome.com/docs/extensions/reference/api/contextMenus).

**Fallback:** popup có textarea để paste thủ công.

### `chrome.storage.local`

**Purpose:** local retry queue và extension settings.

**Privacy:** không lưu vô hạn. Xóa payload khỏi local queue sau khi backend xác nhận.

### Self-hosted ContextDeck API

Endpoints đề xuất:

- `POST /api/captures`
- `GET /api/cards/recent`
- `GET /api/reviews/due`
- `POST /api/cards/{id}/reviews`
- `PATCH /api/cards/{id}`
- `POST /api/cards/{id}/suspend`
- `GET /api/export`

### AI API — Later

Có thể tích hợp OpenAI hoặc model local, nhưng không bắt buộc.

**Fallback:** user tự nhập note/meaning.

### Anki export — Later

Ưu tiên xuất CSV/TSV/APKG-compatible workflow sau khi kiểm chứng nhu cầu; không cần AnkiConnect trong MVP.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Không dùng AI cho scheduling, deduplication hoặc review state.

### AI task hợp lý

Từ sentence:

> `The proposed fix narrows the blast radius but leaves the race condition unresolved.`

AI trả structured result:

```json
{
  "summaryVi": "Bản sửa giảm phạm vi ảnh hưởng nhưng chưa giải quyết race condition.",
  "phrases": [
    {
      "text": "narrow the blast radius",
      "meaningVi": "giảm phạm vi ảnh hưởng"
    },
    {
      "text": "leave ... unresolved",
      "meaningVi": "để ... chưa được giải quyết"
    }
  ],
  "grammarNote": "leave + object + adjective/past participle"
}
```

### Required context

Chỉ gửi:

- selected sentence;
- tối đa 1–2 câu context nếu user bật;
- learner language = Vietnamese;
- domain = software engineering.

Không tự gửi toàn page.

### Validation

- JSON schema validation;
- phrase phải tồn tại trong source sentence nếu loại `extracted`;
- giới hạn 1–3 phrase;
- user có thể edit;
- AI result không thay original text.

### Deterministic fallback

Card vẫn hoạt động hoàn chỉnh mà không có AI.

### Risks

- hallucinated meaning;
- oversimplification;
- source text có thông tin công ty/private code;
- token cost;
- latency.

Recommendation: AI enrichment phải **opt-in per card hoặc opt-in globally**, không tự động gửi text ra ngoài theo default.

## 14. Các bài toán kỹ thuật đáng học

### 1. Browser extension permission boundary

Mục tiêu là capture đủ dữ liệu nhưng xin ít permission nhất.

Kỹ năng:

- Manifest V3;
- service worker lifecycle;
- principle of least privilege;
- extension storage.

### 2. Offline-first capture queue

User phải có thể save ngay cả khi self-hosted backend không chạy.

Kỹ năng:

- local durable queue;
- retry;
- idempotency;
- sync reconciliation.

### 3. Duplicate detection

Cùng câu có thể được lưu từ cùng URL hoặc khác URL.

Kỹ năng:

- canonicalization;
- normalized hashing;
- user-friendly duplicate policy.

### 4. Spaced review scheduling

MVP có thể dùng heuristic đơn giản trước khi cân nhắc FSRS.

Kỹ năng:

- state machine;
- time-based scheduling;
- algorithm evaluation;
- retention metrics.

### 5. Privacy-preserving AI enrichment

AI chỉ nên nhận context nhỏ nhất cần thiết.

Kỹ năng:

- data minimization;
- structured output validation;
- opt-in design;
- provider abstraction.

## 15. Rủi ro và cách xử lý

### Rủi ro 1: trở thành clone Anki

**Mitigation:** không xây deck editor phức tạp. Tập trung capture workflow và technical-context review.

### Rủi ro 2: capture quá nhiều, review backlog bùng nổ

**Mitigation:**

- daily new-card limit;
- auto-suspend card không review sau X ngày;
- show `Inbox` để user triage;
- cho phép Save as reference thay vì learning card.

### Rủi ro 3: privacy

Selected text có thể đến từ internal docs hoặc source code.

**Mitigation:**

- self-hosted default;
- không log full text;
- AI off by default;
- domain blacklist;
- local-only mode về sau.

### Rủi ro 4: extension permission bị user nghi ngại

**Mitigation:** chỉ dùng `contextMenus`, `storage` và host permission cho chính ContextDeck API nếu có thể. Tránh `tabs`/`<all_urls>` nếu không thực sự cần.

### Rủi ro 5: scheduling algorithm không tốt

**Mitigation:** MVP dùng rule đơn giản, log review history đầy đủ, sau đó mới benchmark FSRS/SM-2-style approaches.

### Rủi ro 6: AI nghĩa sai

**Mitigation:** AI output luôn editable, original sentence/source không thay đổi, không auto-promote nghĩa AI thành “truth”.

### Rủi ro 7: scope expansion sang full English learning platform

**Mitigation:** không làm lesson course, speaking trainer, grammar curriculum hoặc TOEIC engine trong MVP.

## 20. Việc cần làm ngay hôm nay

### Thời lượng

**90–120 phút**.

### Objective

Xây vertical slice đầu tiên:

> “Bôi đen text trên một webpage → right-click Save to ContextDeck → extension POST payload → ASP.NET Core API trả JSON confirmation.”

Chưa cần database hoặc review scheduler.

### Bước 1 — Tạo backend

```bash
mkdir ContextDeck
cd ContextDeck

dotnet new sln -n ContextDeck
dotnet new webapi -n ContextDeck.Api -f net10.0
dotnet new xunit -n ContextDeck.Tests -f net10.0

dotnet sln add ContextDeck.Api/ContextDeck.Api.csproj
dotnet sln add ContextDeck.Tests/ContextDeck.Tests.csproj
```

### Bước 2 — Tạo capture DTO

File:

`ContextDeck.Api/Captures/CaptureRequest.cs`

```csharp
public sealed record CaptureRequest(
    string ClientCaptureId,
    string Text,
    string PageUrl,
    string PageTitle,
    DateTimeOffset CapturedAt);
```

### Bước 3 — Tạo endpoint tạm thời

`POST /api/captures`

Validation:

- `Text` không rỗng;
- max 2.000 chars;
- URL phải absolute HTTP/HTTPS;
- `ClientCaptureId` bắt buộc.

Response:

```json
{
  "status": "saved",
  "textPreview": "The fix reduces the blast radius...",
  "sourceHost": "github.com"
}
```

Chưa persistence; chỉ validate và echo safe preview.

### Bước 4 — Tạo extension folder

```text
ContextDeck.Extension/
  manifest.json
  background.js
```

`manifest.json` tối thiểu:

```json
{
  "manifest_version": 3,
  "name": "ContextDeck Dev",
  "version": "0.1.0",
  "permissions": ["contextMenus", "storage"],
  "background": {
    "service_worker": "background.js"
  }
}
```

### Bước 5 — Register context menu

Trong `background.js`:

```javascript
chrome.runtime.onInstalled.addListener(() => {
  chrome.contextMenus.create({
    id: "save-contextdeck",
    title: "Save to ContextDeck",
    contexts: ["selection"]
  });
});
```

Chrome docs xác nhận `selection` là context hợp lệ và `selectionText` có trong click event. Nguồn: [Chrome contextMenus](https://developer.chrome.com/docs/extensions/reference/api/contextMenus).

### Bước 6 — POST selected text

Trong `chrome.contextMenus.onClicked`:

- lấy `info.selectionText`;
- lấy `info.pageUrl`;
- tạo `crypto.randomUUID()`;
- POST `https://localhost:<port>/api/captures`.

Tạm thời `PageTitle` có thể để `Unknown` để tránh xin thêm permission trong buổi đầu.

### Bước 7 — Chạy API

```bash
dotnet run --project ContextDeck.Api
```

### Bước 8 — Load unpacked extension

Chrome:

```text
chrome://extensions
→ Developer mode
→ Load unpacked
→ chọn ContextDeck.Extension
```

### Bước 9 — Manual test

Mở một trang documentation bất kỳ.

Bôi đen:

```text
The operation is idempotent.
```

Right-click → `Save to ContextDeck`.

Xem API log hoặc DevTools để xác nhận request tới backend.

### Verification checklist

- [ ] Extension load không lỗi.
- [ ] Context menu chỉ xuất hiện khi có text selection.
- [ ] `selectionText` được gửi đúng.
- [ ] Backend reject text rỗng hoặc quá dài.
- [ ] Backend chỉ nhận HTTP/HTTPS URL.
- [ ] Request chứa `ClientCaptureId` unique.
- [ ] Không cần `<all_urls>` permission trong vertical slice đầu tiên.
- [ ] `dotnet test` chạy pass cho validation tests.

### Expected result

Sau buổi đầu, bạn có một interaction thật ngay trong browser: chọn câu trên web và gửi nó vào API .NET của chính mình.

### Stop condition

Dừng khi flow `selection → context menu → POST → validated JSON response` chạy ổn định ít nhất 5 lần trên 3 website khác nhau. Không thêm database, AI, Vue hoặc spaced repetition trước khi capture flow này đủ nhanh và ít friction.
