# Ý tưởng hôm nay: Local Exposure Map — Bản đồ dịch vụ đang mở cổng trên máy dev và server

## 1. Tóm tắt ý tưởng

**Local Exposure Map** là một công cụ local/self-hosted giúp developer nhìn thấy chính xác dịch vụ nào đang lắng nghe trên máy Windows/Linux, dịch vụ nào chỉ bind `localhost`, dịch vụ nào bind `0.0.0.0`/`::`, dịch vụ nào đến từ Docker, và dịch vụ nào có nguy cơ bị truy cập từ LAN hoặc Internet. Mục tiêu là giải quyết tình trạng “tưởng chỉ chạy local nhưng thực tế đã expose ra ngoài”, đặc biệt với database, admin UI, development API, Redis, dashboard và container.

- **Người dùng chính:** developer/self-hoster chạy nhiều service, Docker container hoặc local dev server.
- **Bài toán chính:** khó biết toàn bộ network exposure hiện tại của máy và mức độ rủi ro của từng listener.
- **Quy mô:** Medium.
- **Thời gian MVP ước tính:** 7–12 ngày làm ngoài giờ.

## 2. Bài toán thực tế

Một máy phát triển hiện đại có thể đồng thời chạy ASP.NET Core, PostgreSQL/SQL Server, Redis, frontend dev server, Docker Compose, local AI tool, admin UI và nhiều daemon khác. Khi số lượng service tăng, developer thường nhớ port theo ứng dụng chứ không nhìn hệ thống như một “attack surface” hoàn chỉnh.

**Confirmed facts từ tài liệu chính thức:**

- Docker ghi rõ rằng khi publish port mà không chỉ định host IP, port được bind lên tất cả network interface (`0.0.0.0`) theo mặc định; tài liệu Docker còn cảnh báo published ports có thể truy cập từ bên ngoài host. Nguồn: [Docker Docs — Port publishing and mapping](https://docs.docker.com/engine/network/port-publishing/).
- Docker Compose cũng ghi rõ nếu không đặt host IP trong `ports`, mapping sẽ bind lên `0.0.0.0`. Nguồn: [Docker Compose services reference](https://docs.docker.com/reference/compose-file/services/).
- Windows cung cấp `Get-NetTCPConnection` để lấy TCP connections/listeners. Nguồn: [Microsoft Learn — Get-NetTCPConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection).
- Linux có `ss`, công cụ dùng để xem socket statistics và TCP/UDP sockets. Nguồn: [Linux man page — ss(8)](https://man7.org/linux/man-pages/man8/ss.8.html).

**Quan sát:** developer thường dùng `docker ps`, `netstat`, `ss`, `Get-NetTCPConnection`, Docker Desktop hoặc kiểm tra config từng service. Những công cụ này cho dữ liệu tốt nhưng bị phân mảnh: process nằm ở một nơi, Docker mapping ở nơi khác, firewall ở nơi khác, còn đánh giá rủi ro lại phụ thuộc kinh nghiệm người đọc.

**Giả định cần validation:** nhiều developer/self-hoster sẽ thấy giá trị nếu một dashboard duy nhất trả lời nhanh ba câu: “đang mở port gì?”, “ai mở?”, “có thực sự cần expose rộng như vậy không?”.

## 3. Người dùng mục tiêu

### Primary user

Developer backend hoặc self-hoster có máy Windows/Linux chạy nhiều local service và Docker container.

### Context sử dụng

- Trước khi demo trong mạng công ty/quán cà phê.
- Sau khi chạy một Docker Compose mới.
- Khi cài local AI/database/dashboard tool.
- Trước khi deploy lên VPS.
- Khi audit một mini PC/home server.

### Pain point chính

Không có một view đơn giản kết hợp:

- listener IP,
- port,
- protocol,
- process,
- executable/container,
- Docker mapping,
- loại exposure,
- lịch sử thay đổi.

### Workaround hiện tại

Chạy thủ công `netstat`, `ss`, PowerShell, `docker ps`, `docker inspect` rồi tự suy luận.

### Lý do họ sẽ thử

Không cần agent cloud, không cần gửi telemetry ra ngoài, cài một binary/container là có thể thấy ngay “port 5432 đang bind all interfaces vì Compose thiếu `127.0.0.1`”.

## 4. Giải pháp đề xuất

Local Exposure Map quét listener định kỳ hoặc theo yêu cầu, enrich dữ liệu bằng process metadata và Docker metadata, sau đó phân loại từng endpoint.

### Main workflow

1. Người dùng chạy `lem scan` hoặc mở dashboard.
2. Agent đọc TCP/UDP listeners của host.
3. Với mỗi listener, xác định PID/process nếu OS cho phép.
4. Nếu Docker khả dụng, đọc container/port mapping tương ứng.
5. Rule engine phân loại:
   - `LoopbackOnly`
   - `LanPotential`
   - `AllInterfaces`
   - `ContainerPublished`
   - `Privileged/System`
   - `Unknown`
6. Tool gán severity theo rule cấu hình được.
7. Dashboard hiển thị findings và gợi ý remediation.
8. Người dùng mark `Expected`, `Ignore until...` hoặc sửa config rồi re-scan.

### Input

- OS socket table.
- Process metadata.
- Docker Engine metadata nếu có.
- Optional allowlist file.

### Processing

Deterministic parsing + risk rules. Không cần AI.

### Output

Ví dụ:

```text
HIGH  0.0.0.0:5432  postgres  docker:dev-db
Reason: PostgreSQL is published on all interfaces.
Suggested fix: bind host port to 127.0.0.1 when remote access is not required.
```

### Phần tự động

- Thu thập listener.
- Match PID/process/container.
- Detect exposure category.
- Compare với baseline scan.
- Alert khi xuất hiện endpoint mới có severity cao.

### Phần người dùng kiểm soát

- Rule severity.
- Allowlist.
- Notification.
- Scan interval.
- Không tự động đóng port trong MVP.

### Key differentiator

Không phải port scanner từ bên ngoài. Tool chạy ngay trên host nên biết **port nào**, **process nào**, **container nào**, **bind address nào**, và **thay đổi từ lúc nào**.

### Ví dụ end-to-end

Developer chạy PostgreSQL bằng Compose:

```yaml
ports:
  - "5432:5432"
```

Local Exposure Map phát hiện `0.0.0.0:5432`, map về container `postgres-dev`, đánh severity `High`, trích dẫn config remediation tương đương:

```yaml
ports:
  - "127.0.0.1:5432:5432"
```

Sau khi user sửa Compose và re-scan, finding chuyển thành `Resolved`.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Nó có giá trị ngay cả khi chỉ có một người dùng: chính developer có thể dùng để audit workstation, WSL host, mini PC hoặc VPS cá nhân.

### Technical learning value

Project chạm vào:

- OS networking,
- process inspection,
- Docker Engine API,
- security rule design,
- cross-platform abstraction,
- background scans,
- change detection,
- local privilege boundaries.

### Vì sao phù hợp solo developer

Core logic nhỏ: collect → normalize → classify → display. Không cần distributed system, không cần dataset lớn và không phụ thuộc third-party SaaS.

### Có ích dù rất ít user

Nếu tool chỉ bảo vệ được 2–3 máy cá nhân và giúp tránh một lần expose database/admin tool không chủ ý, nó vẫn hoàn thành vai trò personal utility.

### Điều làm project thất bại

Nếu findings quá noisy hoặc cứ đánh `High` cho mọi `0.0.0.0`, user sẽ bỏ qua cảnh báo.

### Lý do mạnh nhất để không build

Power users đã quen với firewall, `ss`, Docker Desktop và monitoring stack có thể không cần thêm tool. Vì vậy giá trị phải nằm ở **correlation + history + actionable explanation**, không phải chỉ wrap `netstat`.

## 6. Phạm vi MVP

### Must have

- Scan TCP listening sockets trên Windows và Linux.
- Chuẩn hóa `LocalAddress`, `Port`, `Protocol`, `PID`, `ProcessName`.
- Phân biệt loopback và all-interface binding.
- Docker integration cơ bản: container name + published ports.
- Rule engine với 4 severity: Info, Low, Medium, High.
- JSON output từ CLI.
- Dashboard một trang liệt kê findings.
- Baseline snapshot và diff: New / Unchanged / Resolved.
- Allowlist theo port/process/container.

### Should have

- UDP listener support đầy đủ.
- Notification Telegram/email khi có finding High mới.
- Import Docker Compose để chỉ ra file/service gây exposure.
- Tags như `database`, `admin`, `dev-server`.
- Scan history 30 ngày.
- “Why this is risky” explanation.

### Later

- Firewall rule inspection.
- Public-IP reachability probe.
- WSL-specific correlation.
- Kubernetes/minikube support.
- Remote multi-host dashboard.
- Auto-remediation PR/config patch.
- CVE lookup theo process/container image.

## 7. Luồng hoạt động

```text
User triggers scan
→ OS collector validates permissions
→ read socket listeners
→ enrich PID/process metadata
→ query Docker if available
→ normalize endpoints
→ rule engine evaluates exposure
→ compare against latest baseline
→ persist scan + findings
→ dashboard renders result
→ optional notification for new High findings
```

### Alternative flows

**Docker không chạy:** bỏ qua Docker enrichment, host listeners vẫn hoạt động.

**Không đọc được process owner:** giữ endpoint với `ProcessName = Unknown`, không fail cả scan.

**Permission denied:** ghi rõ collector nào thiếu quyền, thay vì trả dashboard trống.

**PID biến mất giữa lúc scan:** coi là transient; bỏ process enrichment nhưng giữ socket snapshot.

**IPv6 listener:** normalize `::`, `::1` riêng với IPv4.

**Port hợp lệ nhưng intentionally public:** user add allowlist với lý do và expiry date.

- process correlation,
- Docker correlation,

### 3. Database

SQLite đơn giản hơn nếu chạy một host. PostgreSQL phù hợp nếu muốn dashboard containerized và multi-host về sau.

Vue 3 nhỏ, gồm:

- Current Exposure
- Scan History
- Rules/Allowlist

### 5. Background worker

`BackgroundService` là đủ để scan mỗi 5–15 phút. Không cần Hangfire ban đầu trừ khi muốn dashboard job history/retry UI.

### 6. Docker integration

Kết nối local Docker Engine qua socket/named pipe. Read-only logic trong MVP.

### 7. Cache/queue

Không cần Redis, RabbitMQ hay queue.

### 8. Authentication

Single-user local deployment: optional local password/API key. Nếu bind chỉ localhost, có thể chưa cần account system trong vertical slice đầu tiên.

### 9. Logging

Structured logging với Serilog hoặc built-in `ILogger`.

### 10. Deployment

Hai mode:

- native executable trên Windows/Linux,
- Docker dashboard + host agent.

## 11. API và tích hợp

### Windows NetTCPIP PowerShell module

**Purpose:** lấy TCP connections/listeners.

**Authentication:** local OS permissions.

**Cost/rate limit:** không có SaaS cost.

**Privacy:** dữ liệu process ở local.

**Fallback:** `netstat -ano`.

Nguồn: [Microsoft Learn — Get-NetTCPConnection](https://learn.microsoft.com/en-us/powershell/module/nettcpip/get-nettcpconnection).

### Linux `ss`

**Purpose:** socket inventory.

**Authentication:** một số process detail có thể cần elevated permission.

**Cost:** none.

**Fallback:** `/proc/net/*` hoặc `netstat` nếu có.

Nguồn: [ss(8)](https://man7.org/linux/man-pages/man8/ss.8.html).

### Docker Engine

**Purpose:** map host port về container/service.

**Authentication:** local Docker socket/named pipe.

**Privacy/security:** Docker socket là privileged interface; tool chỉ nên xin read access và không expose socket qua network.

**Fallback:** `docker ps`/`docker inspect`.

Confirmed fact: Docker document rằng mapping không chỉ định host IP sẽ bind tất cả interface và published port có thể accessible bên ngoài host. Nguồn: [Docker Port Publishing](https://docs.docker.com/engine/network/port-publishing/).

### Notification channel

Telegram webhook/bot có thể thêm sau MVP.

Fallback: local dashboard badge và exit code CLI.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Risk classification có thể làm tốt hơn bằng deterministic rules:

```text
if Address is loopback => Info
if Address is 0.0.0.0 or :: and Port in SensitivePorts => High
if DockerPublished && HostIp missing => Medium/High
if finding newly appeared => increase attention
```

AI có thể được thêm sau để viết explanation thân thiện, nhưng không nên dùng AI để quyết định exposure vì:

- dễ hallucinate,
- khó test reproducibly,
- không cần gửi local process/network data ra cloud,
- deterministic rule dễ audit hơn.

## 14. Các bài toán kỹ thuật đáng học

### 1. Cross-platform OS inspection

Học cách abstraction khác biệt giữa Windows và Linux mà vẫn giữ normalized domain model.

### 2. Process/socket correlation

Socket có thể biến mất hoặc PID tái sử dụng giữa hai bước collection; đây là bài tập tốt về snapshot consistency và race conditions.

### 3. Docker networking semantics

Hiểu host bind, bridge networking, published port, IPv4/IPv6 và container isolation sâu hơn.

### 4. Security rule design

Học cách xây rule có explainability, severity và suppress/allowlist mà không gây alert fatigue.

### 5. Change detection

Stable fingerprint phải phân biệt “cùng service restart PID mới” với “exposure mới thật sự”. Đây là bài toán normalization/idempotency thực tế.

## 15. Rủi ro và cách xử lý

### False positives

**Risk:** `0.0.0.0` không luôn là lỗi; web server public có thể intentional.

**Mitigation:** allowlist + profile + explanation thay vì auto-block.

### Quyền truy cập cao

**Risk:** process metadata hoặc Docker socket có thể yêu cầu permission nhạy cảm.

**Mitigation:** principle of least privilege; collector degrade gracefully khi thiếu quyền; không yêu cầu Docker socket nếu Docker integration tắt.

### Scope creep

**Risk:** dễ biến thành vulnerability scanner/firewall manager.

**Mitigation:** MVP chỉ trả lời host exposure; không CVE, không auto firewall, không cloud security posture.

### Platform differences

**Risk:** Windows/Linux output format khác nhau.

**Mitigation:** tách `IListenerCollector`; contract test với fixture output.

### Security của chính tool

**Risk:** dashboard expose inventory process/network nhạy cảm.

**Mitigation:** default bind `127.0.0.1`; nếu remote mode thì bắt buộc auth/TLS.

### Maintenance burden

**Risk:** parsing CLI output có thể thay đổi.

**Mitigation:** ưu tiên structured PowerShell object JSON và Docker API; Linux `ss` parser có fixtures nhiều distro.

### Integration tests

### Failure-path tests

- Docker daemon unavailable,

### Security tests

- dashboard mặc định chỉ localhost,
- API không expose executable path nếu privacy mode bật,
- reject remote bind nếu chưa cấu hình auth.

### Năm scenario quan trọng nhất

1. Container `-p 8080:80` được detect là all-interface published.
2. Container `-p 127.0.0.1:8080:80` được detect là loopback-only.
3. Native ASP.NET Core process bind `127.0.0.1:5000` không bị High.
4. PostgreSQL bind `0.0.0.0:5432` tạo High finding và stable fingerprint qua restart PID.
5. Docker unavailable vẫn hoàn tất scan host và báo integration status `Unavailable`, không crash.

## 17. Cách đo dự án có hữu ích hay không

### Product usage metric

Số scan người dùng chủ động chạy mỗi tuần và số host tiếp tục scan sau 30 ngày.

### Time saved

So sánh thời gian trả lời “máy đang expose những gì?” bằng tool với quy trình `netstat + docker ps + inspect` thủ công.

Mục tiêu ban đầu: dưới 30 giây để có danh sách có giải thích.

### Task completion rate

Tỷ lệ findings High mà user có thể classify `Fix` hoặc `Expected` trong một phiên.

### Error rate

Collector failure < 1% scans trên môi trường đã support.

### Repeated use

Có ít nhất một user dùng baseline diff hàng tuần trong 4 tuần.

### Technical reliability

- scan hoàn tất < 5 giây trên workstation bình thường,
- không duplicate finding khi chỉ PID thay đổi,
- dashboard load < 1 giây với 10.000 observations lịch sử.

Không có AI quality metric vì AI không dùng.

### First vertical slice

`WindowsTcpCollector` gọi PowerShell:

```powershell
Get-NetTCPConnection -State Listen |
Select-Object LocalAddress,LocalPort,OwningProcess |
ConvertTo-Json
```

C# parse JSON thành:

```csharp
public sealed record ListenerEndpoint(
    string LocalAddress,
    int Port,
    int? ProcessId,
    ExposureType Exposure);
```

Classifier:

```csharp
if (address is "127.0.0.1" or "::1")
    return ExposureType.LoopbackOnly;

if (address is "0.0.0.0" or "::")
    return ExposureType.AllInterfaces;

return ExposureType.InterfaceSpecific;
```

CLI output:

```text
ADDRESS       PORT   PID    EXPOSURE
127.0.0.1     5000   14220  LoopbackOnly
0.0.0.0       5432   22104  AllInterfaces
::            8080   33100  AllInterfaces
```

### Expected result

Sau 60–120 phút, chạy:

```bash
dotnet run --project src/LocalExposureMap.Cli
```

và nhìn thấy danh sách listener thật của máy được classify.

### Verification checklist

- [ ] Có ít nhất một listener được đọc từ máy thật.
- [ ] `127.0.0.1` và `::1` được classify `LoopbackOnly`.
- [ ] `0.0.0.0` và `::` được classify `AllInterfaces`.
- [ ] JSON PowerShell parse được khi chỉ có 1 hoặc nhiều record.
- [ ] Nếu PowerShell command fail, CLI trả error rõ ràng và exit code khác 0.
- [ ] Có unit tests cho IPv4/IPv6 classifier.

### Stop condition

Dừng buổi đầu ngay khi CLI có thể quét máy thật, in bảng và unit tests classifier pass. **Không** thêm Docker, database, Vue hay notifications trong session đầu tiên.
