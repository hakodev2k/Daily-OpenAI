# Ý tưởng hôm nay: EnvDrift — Configuration Drift Sentinel cho staging/production

## 1. Tóm tắt ý tưởng

**EnvDrift** là một công cụ self-hosted theo dõi sự khác biệt cấu hình giữa các môi trường như Development, Staging và Production, tập trung vào app settings, feature flags, connection metadata và secret references mà không cần lưu plaintext secret. Công cụ giúp developer phát hiện sớm các lỗi kiểu “code giống nhau nhưng production khác config”, đặc biệt phù hợp với ASP.NET Core/Azure App Service.

- **Project size:** Medium
- **Estimated MVP time:** 2–3 tuần làm ngoài giờ
- **Giá trị cốt lõi:** biến configuration drift từ một lỗi chỉ được phát hiện sau deploy thành một signal có thể kiểm tra và cảnh báo trước.

## 2. Bài toán thực tế

### Confirmed facts

Azure App Service cung cấp API để đọc application settings của một app. Tài liệu REST hiện tại mô tả `List Application Settings` qua Azure Resource Manager và hỗ trợ xác thực Azure AD/OAuth2. Điều này cho phép một tool có quyền phù hợp thu thập cấu hình thực tế đang chạy thay vì chỉ dựa vào file config trong repository.

Nguồn: [Microsoft Learn — Web Apps: List Application Settings](https://learn.microsoft.com/en-us/rest/api/appservice/web-apps/list-application-settings?view=rest-appservice-2025-05-01)

Azure App Service hỗ trợ deployment slots và cho phép đánh dấu app setting là **slot-specific**, nghĩa là setting đó không được swap giữa slot. Vì vậy staging và production có thể chủ động khác nhau ở một số key, nên công cụ drift detection phải hỗ trợ allowlist/policy thay vì yêu cầu hai môi trường giống tuyệt đối.

Nguồn: [Microsoft Learn — Set up staging environments in Azure App Service](https://learn.microsoft.com/en-us/azure/app-service/deploy-staging-slots)

Azure App Service cũng hỗ trợ Key Vault references trong app settings. Microsoft khuyến nghị giữ secret trong Key Vault và dùng reference trong application settings; các reference không chỉ là giá trị config thông thường mà còn có lifecycle/cache riêng.

Nguồn: [Microsoft Learn — Use Key Vault references as app settings](https://learn.microsoft.com/en-us/azure/app-service/app-service-key-vault-references)

Khái niệm configuration drift là một bài toán phổ biến trong infrastructure tooling. HashiCorp định nghĩa drift là khi trạng thái thực tế khác với cấu hình mong muốn và cung cấp health assessment để phát hiện drift định kỳ.

Nguồn: [HashiCorp — Use health assessments to detect infrastructure drift](https://developer.hashicorp.com/terraform/tutorials/cloud/drift-detection)

### Observation

Terraform giải quyết drift ở tầng infrastructure mà Terraform quản lý. Tuy nhiên nhiều team vẫn có application configuration nằm ngoài IaC hoàn chỉnh: App Service settings, slot settings, environment variables, manual portal changes, feature flags hoặc Key Vault references. Đây là khoảng trống phù hợp cho một tool nhỏ, tập trung vào **runtime application configuration** chứ không cạnh tranh với Terraform.

### Bài toán cụ thể

Các lỗi thường gặp:

- staging có `FeatureX=true`, production quên bật;
- connection string reference trỏ nhầm database;
- một environment thiếu key mới;
- `ASPNETCORE_ENVIRONMENT` hoặc endpoint URL khác mong đợi;
- một app setting bị sửa thủ công trên Azure Portal;
- secret đã rotate nhưng một environment vẫn trỏ version cũ;
- deployment slot có setting chưa đánh dấu slot-specific;
- production chứa key cũ mà code không còn dùng.

Developer thường phát hiện qua logs, bug report, Azure Portal hoặc so thủ công từng environment. Việc này lặp lại, dễ bỏ sót và không tạo được lịch sử thay đổi.

### Assumption cần validation

MVP giả định rằng developer/team nhỏ có ít nhất 2 môi trường và thường xuyên deploy sẽ thấy hữu ích nếu có báo cáo “missing / unexpected / changed / allowed difference” trước hoặc ngay sau deployment. Cần kiểm chứng giả định này với 3–5 developer trước khi đầu tư integration rộng.

## 3. Người dùng mục tiêu

### Primary user

Backend developer hoặc DevOps-minded developer trong team nhỏ đang vận hành ASP.NET Core trên Azure App Service/Azure Functions với staging và production riêng.

### Context of use

- deploy vài lần mỗi tuần;
- có nhiều app settings;
- một phần config được chỉnh qua portal/pipeline;
- không phải toàn bộ hạ tầng/config đều nằm trong Terraform/Bicep;
- developer có quyền read configuration nhưng muốn tránh lưu plaintext secrets.

### Main pain point

Không biết một lỗi sau deploy đến từ code hay do configuration giữa environments đã lệch nhau.

### Current workaround

- mở Azure Portal ở hai tab;
- export app settings rồi diff thủ công;
- đọc pipeline variables;
- kiểm tra logs khi lỗi xuất hiện;
- dùng spreadsheet/wiki ghi lại expected config.

### Lý do họ sẽ thử

MVP có thể chạy read-only, không sửa Azure resource, và ngay lần scan đầu đã cho thấy key nào thiếu hoặc khác policy.

## 4. Giải pháp đề xuất

EnvDrift quản lý một **Configuration Manifest** cho từng application và so sánh manifest đó với cấu hình thực tế của từng environment.

### Main workflow

1. User tạo application, ví dụ `Employee API`.
2. Định nghĩa environments: `staging`, `production`.
3. Kết nối Azure bằng managed identity/service principal có quyền read cần thiết.
4. Tool đọc app settings từ từng environment.
5. Trước khi lưu, mỗi value được chuyển thành một trong các dạng:
   - `plain metadata` cho value không nhạy cảm được user cho phép;
   - `reference metadata` cho Key Vault reference;
   - `HMAC fingerprint` cho secret/sensitive value.
6. Tool tạo snapshot và chạy policy comparison.
7. Dashboard phân loại:
   - `MissingKey`
   - `UnexpectedKey`
   - `DifferentValue`
   - `DifferentSecretFingerprint`
   - `DifferentReferenceTarget`
   - `AllowedDifference`
8. Nếu có drift mới ngoài policy, gửi Telegram/webhook.
9. User có thể approve difference hoặc sửa môi trường rồi rescan.

### Input

- Azure subscription/resource group/app/slot.
- Environment mapping.
- Rules cho từng key.
- Sensitivity classification.

### Processing

- authenticate Azure;
- fetch configuration;
- normalize key/value;
- fingerprint sensitive values;
- compare environment snapshot với desired manifest hoặc reference environment;
- persist drift report;
- evaluate notification policy.

### Output

- drift summary;
- key-level differences;
- severity;
- environment affected;
- first seen / last seen;
- remediation hint.

### Automated

- scheduled scan;
- drift classification;
- deduplication;
- notification;
- history tracking.

### User control

- key nào sensitive;
- environment nào là baseline;
- difference nào được phép;
- severity;
- có lưu non-secret value hay chỉ fingerprint.

### Key differentiator

**Không lưu plaintext secret mặc định.** Tool chỉ cần biết “giống hay khác” thông qua HMAC fingerprint và reference metadata. Nó tập trung vào application config drift giữa environments, không cố thay thế Terraform hay secret manager.

### Ví dụ end-to-end

Production có:

```text
Graph__BaseUrl=https://graph.microsoft.com
Feature__NewApproval=true
ConnectionStrings__Main=@Microsoft.KeyVault(.../prod-db/...)
```

Staging có:

```text
Graph__BaseUrl=https://graph.microsoft.com
Feature__NewApproval=true
ConnectionStrings__Main=@Microsoft.KeyVault(.../staging-db/...)
```

Policy cho phép `ConnectionStrings__Main` khác giữa environments nên report sạch.

Sau đó ai đó sửa production:

```text
Feature__NewApproval=false
```

Scan tiếp theo tạo drift mới:

```text
HIGH  Feature__NewApproval
staging=true
production=false
First seen: 2026-08-17 10:00 UTC+7
```

Developer biết ngay đây là config drift chứ không cần debug code trước.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Lỗi cấu hình là loại lỗi lặp lại và thường không thể bắt chỉ bằng unit test. Công cụ giúp rút ngắn thời gian xác định nguyên nhân khi “works in staging, fails in production”.

### Technical learning value

Dự án có nhiều bài toán đáng học:

- Azure Resource Manager authentication;
- secret-safe data processing;
- HMAC fingerprints;
- background jobs;
- policy engine nhỏ;
- configuration normalization;
- idempotent alerts;
- audit history.

### Phù hợp solo developer

MVP chỉ cần hỗ trợ **một provider: Azure App Service** và một kiểu comparison. Không cần xây multi-cloud ngay.

### Hữu ích ngay cả với một user

Bạn có thể dùng trực tiếp cho các API cá nhân hoặc project công việc có staging/production, nên không phụ thuộc việc có khách hàng.

### Điều làm dự án thất bại

Nếu toàn bộ target users đã quản lý config hoàn toàn bằng Terraform/Bicep và cấm manual changes, giá trị bổ sung có thể thấp.

### Lý do mạnh nhất để không build

Nếu validation cho thấy pain point thật sự chỉ là “config chưa được đưa vào IaC”, giải pháp tốt hơn có thể là chuẩn hóa IaC thay vì thêm một monitoring layer.

## 7. Luồng hoạt động

```text
User configures Azure target
        ↓
Authenticate with DefaultAzureCredential
        ↓
Read application settings
        ↓
Normalize keys
        ↓
Classify sensitive values
        ↓
Sensitive? ── yes ──> HMAC fingerprint only
        │
        no
        ↓
Store allowed metadata/value according to policy
        ↓
Create snapshot
        ↓
Compare with baseline/reference environment
        ↓
Apply allow-difference rules
        ↓
Persist drift findings
        ↓
New actionable drift?
        ↓ yes
Send notification
```

### Failure cases

**Azure authentication fails**

- scan = `AuthenticationFailed`;
- không thay baseline;
- không tạo drift giả.

**Azure API timeout/rate limit**

- retry với exponential backoff;
- giữ scan status riêng.

**Một environment đọc được, environment kia lỗi**

- report `PartialScan`;
- không kết luận key missing.

**HMAC key bị rotate**

- fingerprints cũ không so trực tiếp được;
- version fingerprint key trong snapshot;
- chạy full rescan sau rotation.

**Key biến mất rồi xuất hiện lại**

- reopen/resolved lifecycle thay vì tạo duplicate finding.

## 11. API và tích hợp

### Azure App Service application settings

**Purpose:** đọc effective application settings.

**Authentication:** Azure AD qua service principal, developer login hoặc managed identity.

**Cost/rate limit:** không có lý do để scan quá thường xuyên; MVP dùng mỗi 15 phút–24 giờ tùy user.

**Privacy:** API trả actual settings, vì vậy process phải tránh logging raw values.

**Fallback:** import sanitized JSON manifest nếu user chưa muốn cấp Azure access.

Nguồn: [Web Apps — List Application Settings](https://learn.microsoft.com/en-us/rest/api/appservice/web-apps/list-application-settings?view=rest-appservice-2025-05-01)

### Azure Key Vault references

**Purpose:** nhận biết app setting đang trỏ tới secret reference nào thay vì so secret plaintext.

**Authentication:** chỉ cần quyền đọc App Service config ở use case reference parsing; đọc actual secret là optional và không nên có trong MVP.

**Privacy:** không fetch secret value mặc định.

**Fallback:** chỉ compare reference string/target metadata.

Nguồn: [Use Key Vault references as app settings](https://learn.microsoft.com/en-us/azure/app-service/app-service-key-vault-references)

### Telegram Bot API

**Purpose:** notification.

**Authentication:** bot token.

**Privacy:** chỉ gửi key name, environment và drift type; không gửi actual sensitive value.

**Fallback:** dashboard-only hoặc generic webhook.

## 12. AI có thực sự cần thiết không?

**AI is not necessary** cho MVP.

Configuration drift là bài toán deterministic:

- key có/không;
- fingerprint giống/khác;
- reference target giống/khác;
- policy allow/deny.

AI có thể thêm sau để viết remediation explanation, nhưng không nên quyết định drift hoặc severity nếu rule thông thường đã xử lý chính xác hơn, rẻ hơn và bảo mật hơn.

## 14. Các bài toán kỹ thuật đáng học

### 1. Privacy-preserving fingerprints

Không thể dùng SHA-256 trực tiếp cho secret có entropy thấp vì dễ brute force. Dùng HMAC-SHA256 với server-side key giúp fingerprint khó bị đoán hơn.

**Skill:** applied cryptography và secret handling.

### 2. Configuration normalization

Cần xử lý casing, whitespace, URI canonicalization và provider-specific representation.

**Skill:** deterministic comparison/data quality.

### 3. Drift lifecycle + idempotency

Một drift không nên gửi notification mới ở mỗi scan.

**Skill:** state machine nhỏ, deduplication, background processing.

### 4. Azure permission boundary

Tool cần đủ quyền đọc config nhưng không nên có quyền sửa resource.

**Skill:** least privilege, managed identity, Azure RBAC.

### 5. Reliable scheduled scans

Cần phân biệt “environment down” với “config missing”.

**Skill:** retry, partial failure, observability.

## 15. Rủi ro và cách xử lý

### Data privacy

**Risk:** App Service API có thể trả secret plaintext.

**Mitigation:** redact ngay trong memory pipeline; không log raw response; sensitive-by-default patterns; persist HMAC only.

### Security

**Risk:** credential của tool có quyền quá lớn.

**Mitigation:** read-only custom role hoặc quyền tối thiểu; ưu tiên managed identity; không triển khai auto-fix ở MVP.

### False positives

**Risk:** staging và prod vốn phải khác.

**Mitigation:** comparison policy rõ ràng: `MustMatch`, `MustExist`, `MayDiffer`, `Ignore`.

### Scope expansion

**Risk:** chuyển thành full secrets/config management platform.

**Mitigation:** chỉ monitor + report, không trở thành secret store.

### API dependency

**Risk:** Azure API unavailable/rate-limited.

**Mitigation:** retry, backoff, partial scan state.

### HMAC key rotation

**Risk:** fingerprints trước/sau rotation không match.

**Mitigation:** version key và rescan tất cả targets sau rotation.

### User adoption

**Risk:** team thấy portal/manual diff đủ dùng.

**Mitigation:** đo frequency và time-to-diagnosis trong validation trước khi build UI lớn.

### Maintenance

**Risk:** provider APIs thay đổi.

**Mitigation:** adapter interface + pin Azure SDK version + contract tests.

## 16. Kiểm thử

### Strategy

- **Unit:** normalization, policy evaluation, HMAC fingerprint, lifecycle.
- **Integration:** PostgreSQL + Azure provider abstraction.
- **E2E:** Playwright dashboard flow.
- **Failure-path:** timeout/auth/rate limit/partial environment failure.
- **Security:** verify no raw secret in logs/database/API response.
- **Data quality:** deterministic result cho cùng snapshot.

### 5 test scenarios quan trọng

1. Production thiếu key bắt buộc → `MissingKey` severity High.
2. Secret plaintext khác → chỉ fingerprint khác; database không chứa secret.
3. Key được rule `MayDiffer` → không tạo actionable drift.
4. Azure scan chạy lại với cùng dữ liệu → không duplicate finding/notification.
5. Một environment fetch thất bại → scan `Partial`, không report hàng loạt missing keys giả.

## 17. Cách đo dự án có hữu ích hay không

- **Product usage:** số applications vẫn enabled sau 30 ngày.
- **Time saved:** thời gian xác định lỗi do config trước/sau khi dùng tool.
- **Task completion:** tỷ lệ scheduled scans hoàn thành.
- **Error rate:** false-positive drift rate.
- **Repeated use:** số lần user mở report sau alert và resolve/acknowledge finding.
- **Reliability:** không duplicate alert, không mất drift state sau restart.
- **Security metric:** zero plaintext sensitive values trong persisted storage/logs qua automated test.

Không dùng page view hay số notification làm vanity metric.

### First vertical slice

Endpoint:

```http
POST /api/drift/compare
```

Expected response:

```json
{
  "hasActionableDrift": true,
  "findings": [
    {
      "key": "Feature__NewApproval",
      "type": "DifferentValue",
      "severity": "High"
    }
  ]
}
```

`ConnectionStrings__Main` phải được fingerprint và không xuất hiện plaintext trong response/log.

### Verification checklist

- [ ] `dotnet build` pass.
- [ ] Hai sample JSON được load thành dictionary.
- [ ] `SecretFingerprinter` dùng `HMACSHA256`, không dùng SHA-256 thuần cho secret.
- [ ] Same secret + same HMAC key → same fingerprint.
- [ ] Different secret → different fingerprint.
- [ ] Rule `MayDifferSensitive` không tạo actionable drift.
- [ ] `Feature__NewApproval` tạo `DifferentValue`.
- [ ] Unit test kiểm tra raw secret không xuất hiện trong serialized report.
- [ ] Endpoint trả report nhìn thấy được bằng Swagger/curl.

### Stop condition

Dừng session khi endpoint có thể so sánh hai config files, xử lý sensitive values bằng HMAC và trả đúng một actionable drift cho sample trên. **Không thêm PostgreSQL, Hangfire, Vue hay Azure integration trong buổi đầu.**
