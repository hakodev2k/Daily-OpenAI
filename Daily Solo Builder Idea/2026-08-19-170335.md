# Ý tưởng hôm nay: PromptShield Local — Privacy Gateway trước khi gửi dữ liệu vào AI API

## 1. Tóm tắt ý tưởng

PromptShield Local là một gateway self-hosted chạy cục bộ hoặc trong mạng riêng, đứng giữa ứng dụng/dev tool và AI API để **phát hiện, che hoặc thay thế PII, secret và dữ liệu nhạy cảm trước khi prompt rời khỏi máy**, sau đó có thể khôi phục các placeholder ở phía client khi cần. Công cụ giúp developer dùng AI API an toàn hơn trong các workflow chứa log, stack trace, email, ticket, source snippet hoặc dữ liệu khách hàng.

- Người dùng chính: developer cá nhân, backend developer, QA/automation engineer dùng AI API trong công việc.
- Vấn đề chính: dữ liệu gửi vào AI thường chứa thông tin nhạy cảm mà người dùng không nhận ra trước khi request được gửi đi.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.

## 2. Bài toán thực tế

Developer ngày càng gửi nhiều loại dữ liệu thực tế cho AI:

- stack trace;
- application logs;
- SQL query và sample data;
- email hoặc ticket;
- JSON từ API;
- config file;
- code chứa endpoint nội bộ;
- test data có tên, email, số điện thoại;
- payload từ production incident.

### Confirmed facts

OpenAI công khai rằng dữ liệu gửi qua API không được dùng để train model theo mặc định nếu khách hàng không chủ động opt in. Tuy nhiên, tài liệu data controls cũng mô tả abuse-monitoring logs và application state với retention khác nhau tùy endpoint và cấu hình. Một số khách hàng đủ điều kiện có thể dùng Zero Data Retention hoặc Modified Abuse Monitoring, nhưng các chế độ này cần được phê duyệt và một số capability vẫn có giới hạn tương thích. Nguồn: [OpenAI — Data controls in the API platform](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint).

Microsoft Presidio cung cấp framework open-source cho nhận diện và anonymization PII bằng recognizer, regex, NER và custom logic. Presidio cũng cảnh báo rõ rằng detection tự động **không đảm bảo** phát hiện toàn bộ thông tin nhạy cảm, vì vậy cần có thêm lớp bảo vệ và validation. Nguồn: [Microsoft Presidio Analyzer](https://github.com/microsoft/presidio/blob/main/docs/analyzer/index.md) và [Presidio FAQ](https://github.com/microsoft/presidio/blob/main/docs/faq.md).

### Observation

Các provider có data-control riêng, nhưng developer vẫn phải tự quyết định **dữ liệu nào nên được gửi ngay từ đầu**. Đây là vấn đề khác với việc provider có lưu dữ liệu bao lâu.

### Assumption cần validation

Một nhóm developer sẽ chấp nhận chạy một local proxy nếu nó:

- không làm thay đổi workflow hiện tại quá nhiều;
- không gửi raw sensitive data tới service thứ ba;
- có khả năng review/redact rõ ràng;
- không làm latency tăng đáng kể.

### Workaround hiện tại

Người dùng thường:

- xóa dữ liệu thủ công trước khi paste;
- dùng fake data;
- tự viết regex tạm;
- chỉ dựa vào policy của AI provider;
- hoặc đơn giản bỏ qua vì thao tác masking quá mất thời gian.

Các cách này dễ bị lỗi vì sensitive data có thể nằm sâu trong JSON, log, URL, header hoặc source code.


## 4. Giải pháp đề xuất

PromptShield Local cung cấp một HTTP endpoint tương thích với workflow hiện tại. Client gửi prompt tới gateway thay vì gửi trực tiếp tới provider.

### Main workflow

Input:

```text
POST /v1/sanitize-and-forward
```

Request chứa:

- model/provider target;
- prompt/messages;
- optional metadata;
- redaction policy.

Gateway thực hiện:

1. Parse request.
2. Chạy detector deterministic.
3. Phát hiện PII + secrets + custom patterns.
4. Áp dụng policy:
   - block;
   - mask;
   - tokenize thành placeholder;
   - allow.
5. Ghi local audit metadata không chứa raw secret.
6. Forward request đã sanitize tới AI API.
7. Nhận response.
8. Nếu policy cho phép, restore placeholder theo mapping local.
9. Trả response về client.

### Ví dụ cụ thể

Input:

```text
Customer john@example.com gets error when calling
https://internal-orders.company.local/api/orders/123.
Authorization header contained a bearer token.
```

Gateway chuyển thành:

```text
Customer <EMAIL_1> gets error when calling
<INTERNAL_URL_1>/api/orders/123.
Authorization header contained <SECRET_1>.
```

AI trả lời dựa trên placeholder.

Gateway có thể giữ mapping cục bộ:

```text
<EMAIL_1> -> original value
<INTERNAL_URL_1> -> original value
```

Nhưng mặc định không cần restore nếu response không phụ thuộc vào giá trị thật.

### Key differentiator

Không phải một generic DLP enterprise platform. MVP tập trung duy nhất vào **developer-to-AI traffic**, self-hosted, dễ tích hợp với CLI và app .NET.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Có thể dùng ngay cho:

- debug log;
- code review với AI;
- incident analysis;
- support ticket summarization;
- document extraction;
- test generation từ production-like data.

### Technical learning value

Dự án cho phép học sâu:

- privacy engineering;
- sensitive-data classification;
- reverse proxy;
- request transformation;
- deterministic policy engine;
- secure local storage;
- structured logging;
- provider abstraction.

### Vì sao phù hợp solo developer

Core scope nhỏ và rõ:

```text
Detect → transform → forward → audit
```

Không cần xây model riêng, không cần distributed architecture và không cần dataset lớn ở MVP.

### Vì sao vẫn hữu ích với một người dùng

Developer có thể tự dùng gateway này cho các tool cá nhân, script, AI workflows và project nội bộ của chính mình.

### Điều gì có thể làm dự án thất bại

- Detection false positive quá nhiều.
- False negative khiến người dùng mất niềm tin.
- Setup proxy phức tạp hơn lợi ích nhận được.
- Latency quá cao.

### Lý do mạnh nhất để không build

Không hệ thống detector nào đảm bảo bắt được toàn bộ dữ liệu nhạy cảm. Nếu user kỳ vọng “bật tool là tuyệt đối an toàn”, sản phẩm sẽ tạo false sense of security.

## 7. Luồng hoạt động

### Normal flow

User/client gửi request
→ gateway validate payload
→ extract text fields
→ run detection pipeline
→ aggregate detections
→ apply policy
→ replace values bằng placeholders
→ forward sanitized request
→ nhận response
→ optional placeholder restoration
→ trả result
→ ghi audit metadata.

### Preview flow

User gửi dữ liệu tới:

```text
POST /scan
```

Gateway chỉ trả:

```json
{
  "risk": "high",
  "entities": [
    { "type": "EMAIL", "count": 2 },
    { "type": "SECRET", "count": 1 }
  ]
}
```

Không gọi AI API.

### Failure cases

#### Detector service unavailable

Default policy:

```text
fail closed
```

Request không được forward.

#### AI provider timeout

Không retry request vô hạn. Trả provider error và giữ audit status.

#### Payload quá lớn

Trả `413 Payload Too Large`.

#### Low-confidence detection

Tùy policy:

- warn;
- mask;
- allow.

#### Mapping restore bị mất

Response vẫn trả placeholder, không cố suy đoán original value.

## 11. API và tích hợp

### OpenAI API

**Purpose:** provider đầu tiên để validation.

**Authentication:** credential của user được cấu hình ngoài database.

**Cost/rate-limit:** phụ thuộc model và tài khoản provider; gateway phải pass through provider errors thay vì tự giả định limit.

**Privacy concern:** mục tiêu của gateway là giảm lượng sensitive content gửi đi, nhưng không thay thế việc đọc data-control policy của provider.

**Fallback:** `/scan` và `/sanitize` vẫn hoạt động offline dù provider unavailable.

Nguồn data-control: [OpenAI Data Controls](https://platform.openai.com/docs/models/default-usage-policies-by-endpoint).

### Microsoft Presidio

**Purpose:** PII detection nâng cao.

**Authentication:** nếu chạy local sidecar thì không cần public authentication; chỉ bind private network/container network.

**Cost:** open-source; chi phí chính là compute.

**Privacy:** giữ toàn bộ PII processing trong local environment.

**Fallback:** built-in .NET detector pipeline.

### Regex / checksum recognizers

Dùng cho những entity có deterministic structure như:

- email;
- IPv4;
- JWT-like token shape;
- connection string key names;
- internal host patterns.

Không cần external API.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Core detection/redaction nên càng deterministic càng tốt.

Không nên gửi sensitive text cho một AI model chỉ để hỏi model xem text có sensitive hay không, vì như vậy đã phá mục đích chính của sản phẩm.

AI chỉ có thể là optional future feature cho:

- giải thích policy;
- tạo rule suggestion từ sanitized sample;
- classify risk trên dữ liệu đã redacted.

### Deterministic fallback

Luôn tồn tại:

```text
regex + validators + recognizers + policy engine
```

### Validation

Detection accuracy phải đo bằng labeled test corpus chứ không dựa vào impression.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

**Goal:** xác nhận tool bắt được sensitive data thực sự gặp trong workflow.

**Tasks:**

- Thu thập 20–30 đoạn log/sample đã tự sanitize thủ công.
- Label entity mong muốn.
- Viết một prototype regex scanner.
- Đo false positive/false negative.

**Expected output:** danh sách 5–8 entity type đáng hỗ trợ đầu tiên.

**Completion criteria:** prototype tìm được phần lớn entity đã label mà không tạo quá nhiều false positive.

### Phase 1 — Core MVP

**Goal:** scan → sanitize → forward end-to-end.

**Tasks:**

- ASP.NET Core API.
- Detector abstraction.
- Built-in recognizers.
- Policy engine.
- Placeholder generator.
- Provider adapter.
- `/scan` endpoint.
- `/forward` endpoint.

**Expected output:** một real request được sanitize trước khi gửi tới provider.

**Completion criteria:** network capture/log verification chứng minh raw sensitive value không xuất hiện trong outbound body.

### Phase 2 — Reliability

**Goal:** xử lý an toàn khi detector/provider lỗi.

**Tasks:**

- fail-closed mode;
- request size limit;

- no-body logging policy;

- unit/integration tests;
- audit records.

**Expected output:** failure path có hành vi predictable.

**Completion criteria:** detector failure không vô tình forward raw request.

### Phase 3 — Useful expansion

**Goal:** tăng detection quality và usability.

**Tasks:**

- Presidio sidecar;
- custom rule packs;
- JSON-path policy;
- CLI;
- project profiles;
- dashboard scan preview.

**Expected output:** hỗ trợ nhiều workflow mà không cần chỉnh source client nhiều.

### Phase 4 — Production readiness

**Goal:** self-hosted ổn định.

**Tasks:**

- Docker image;
- Docker Compose;
- health checks;
- encrypted config;
- backup rules;
- retention cleanup;
- metrics;
- security documentation;

**Completion criteria:** chạy liên tục 7 ngày với logs sạch, không lưu raw prompt ngoài ý muốn và recovery test thành công.

## 14. Các bài toán kỹ thuật đáng học

### 1. Privacy-preserving data handling

Học cách thiết kế hệ thống mà sensitive value không vô tình xuất hiện trong:

- logs;
- exception messages;
- metrics;
- audit DB.

### 2. Detection precision vs recall

Một detector quá aggressive gây false positive; detector quá lỏng gây data leak.

Kỹ năng cải thiện:

- regex design;
- confidence scoring;
- context-aware detection;
- validation corpus.

### 3. Secure tokenization

Placeholder restoration yêu cầu mapping tạm thời an toàn.

Kỹ năng học được:

- encryption at rest;
- TTL;
- in-memory secret handling;
- key management.

### 4. Reverse proxy/request transformation

Gateway phải giữ đúng:

- HTTP semantics;
- headers cần thiết;
- streaming behavior;
- timeout;
- cancellation.

### 5. Policy engine

Ví dụ:

```text
EMAIL -> tokenize
PRIVATE_IP -> mask
API_SECRET -> block
INTERNAL_URL -> tokenize
```

Kỹ năng học được: rule composition và deterministic decision systems.

## 15. Rủi ro và cách xử lý

### False negatives

**Risk:** sensitive data không được phát hiện.

**Mitigation:**

- không quảng bá “100% safe”;
- custom rules;
- layered detectors;
- labeled regression corpus;
- optional block-on-unknown patterns.

### False positives

**Risk:** code/log bị mask quá mức.

**Mitigation:**

- confidence threshold;
- allowlist;
- per-project policies;
- preview mode.

### Gateway trở thành nơi tập trung secret

**Risk:** nếu lưu raw data thì tool tự tạo thêm attack surface.

**Mitigation:**

- no raw prompt persistence mặc định;
- short-lived mapping;
- encryption;
- localhost-first deployment.

### Credential leakage qua logs

**Mitigation:**

- never log request body;
- redact exception output;
- test logging pipeline riêng.

### Provider API dependency

**Mitigation:** provider adapter interface và `/scan` hoạt động offline.

### Scope creep

**Risk:** biến thành enterprise DLP suite.

**Mitigation:** giữ MVP trong phạm vi AI prompt/text traffic.

### Performance

**Risk:** NLP detector tăng latency.

**Mitigation:**

- regex fast path;
- Presidio optional;
- cache recognizers;
- benchmark P50/P95.

### User adoption

Tool có thể thất bại nếu setup phức tạp.

**Mitigation:** một command Docker hoặc CLI proxy mode.

### Security tests

- raw secret không xuất hiện trong log;
- path/header sanitization;
- unauthorized network access khi network mode bật.

### Data-quality tests

Dùng labeled corpus cho detection metrics.

### 5 test scenario quan trọng nhất

1. Prompt có email + private hostname → cả hai được tokenize trước outbound request.
2. Prompt có secret pattern thuộc policy `block` → request không bao giờ tới provider.
3. Detector throw exception trong `fail-closed` mode → gateway trả lỗi và không forward.
4. Audit DB không chứa raw sensitive value.
5. Placeholder restore chỉ hoạt động với đúng correlation mapping và hết hạn đúng TTL.

## 17. Cách đo dự án có hữu ích hay không

### Product usage metric

Số request AI thực tế đi qua gateway mỗi tuần.

% request được sanitize và forward thành công mà user không phải chỉnh tay.

- scan failures;
- provider forwarding failures;
- false blocking rate.

Có tiếp tục dùng gateway sau 2–4 tuần hay quay lại gọi provider trực tiếp.

### Technical reliability

- P95 gateway overhead;
- percentage request không lưu raw content;
- fail-closed correctness.

### Detection quality

Quan trọng hơn vanity metric:

- Precision theo entity type.
- Recall theo entity type.
- False-negative count trên regression corpus.

Mục tiêu MVP hợp lý không phải 100%, mà là có benchmark rõ và cải thiện liên tục.

## 20. Việc cần làm ngay hôm nay

### Development objective

Trong **60–120 phút**, tạo vertical slice đầu tiên:

```text
POST text → detect email/IP → tokenize → trả sanitized text
```

Chưa gọi AI API.

### Files/components cần tạo

```text
PromptShieldLocal.sln
src/
  PromptShield.Api/
    Program.cs
    Detection/
      ISensitiveDataDetector.cs
      RegexSensitiveDataDetector.cs
    Sanitization/
      Sanitizer.cs
      SanitizationResult.cs
    Models/
      ScanRequest.cs
      ScanResponse.cs
tests/
  PromptShield.Tests/
```

### Setup commands

```bash
dotnet new sln -n PromptShieldLocal
dotnet new webapi -n PromptShield.Api -o src/PromptShield.Api
dotnet new xunit -n PromptShield.Tests -o tests/PromptShield.Tests
dotnet sln add src/PromptShield.Api
dotnet sln add tests/PromptShield.Tests
dotnet add tests/PromptShield.Tests reference src/PromptShield.Api
```

### First vertical slice

Tạo endpoint:

```text
POST /scan
```

Input:

```json
{
  "text": "User jane@example.com failed connecting to 10.0.0.12"
}
```

Expected response:

```json
{
  "sanitizedText": "User <EMAIL_1> failed connecting to <PRIVATE_IP_1>",
  "detections": [
    { "type": "EMAIL", "count": 1 },
    { "type": "PRIVATE_IP", "count": 1 }
  ]
}
```

### Implement detector đầu tiên

Support đúng 2 entity:

- email;
- private IPv4.

Không thêm secret scanning hoặc Presidio trong session đầu.

### Integration test

Test endpoint bằng `WebApplicationFactory` hoặc chạy API thật.

### Manual verification

```bash
curl -X POST http://localhost:5000/scan \
  -H "Content-Type: application/json" \
  -d '{"text":"User jane@example.com failed connecting to 10.0.0.12"}'
```

### Verification checklist

- [ ] Email được thay bằng placeholder.
- [ ] Private IPv4 được thay bằng placeholder.
- [ ] Original text không xuất hiện trong application log.
- [ ] Same value xuất hiện hai lần dùng cùng placeholder trong cùng request.
- [ ] Hai value khác nhau nhận placeholder khác nhau.
- [ ] Có ít nhất 5 unit tests pass.
- [ ] `dotnet test` pass.

### Expected result

Cuối session có một API chạy thật có thể chứng minh concept:

```text
raw input → sensitive detection → deterministic tokenization → safe output
```

### Stop condition

Dừng session khi endpoint `/scan` chạy ổn và test chứng minh email/private IP được sanitize chính xác. Không thêm database, AI provider, Presidio, Vue dashboard hoặc Docker trước khi vertical slice này hoàn tất.
