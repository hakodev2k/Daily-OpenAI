# Ý tưởng hôm nay: SpeakBacklog — Workplace English Shadowing Coach từ chính câu nói kỹ thuật của bạn

## 1. Tóm tắt ý tưởng

SpeakBacklog là một ứng dụng web cá nhân giúp developer luyện **Workplace English** bằng chính các câu thường gặp trong công việc: daily update, bug report, code review, giải thích root cause, estimate, blocker, incident và technical discussion. Người dùng nhập hoặc dán một câu tiếng Anh mình muốn nói trong thực tế, ứng dụng tạo bài shadowing ngắn, thu âm giọng đọc, chấm pronunciation/fluency bằng Azure Speech và lưu lại các lỗi phát âm lặp lại để ôn tập có chủ đích.

- Người dùng chính: developer Việt Nam cần nói tiếng Anh trong môi trường kỹ thuật.
- Bài toán chính: học pronunciation bằng nội dung chung chung không chuyển hóa tốt sang những câu thật sự phải nói ở nơi làm việc.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.

## 2. Bài toán thực tế

Developer có thể đọc tài liệu tiếng Anh khá tốt nhưng vẫn gặp khó khi phải nói nhanh và rõ trong các tình huống như:

- “I’m still investigating the root cause.”
- “The deployment failed because the environment variable was missing.”
- “I think we should keep this logic inside the application layer.”
- “The API is backward compatible, but the response latency increased.”
- “I’ll need one more day because the integration test is still unstable.”

Vấn đề không chỉ nằm ở vocabulary. Người học còn phải xử lý đồng thời pronunciation, rhythm, pausing, stress, fluency và khả năng gọi lại câu đúng lúc.

### Confirmed facts

Microsoft Azure Speech hiện có **Pronunciation Assessment** trên Speech SDK. Với scripted assessment, hệ thống có thể trả các chỉ số như Accuracy, Fluency, Completeness và Prosody; kết quả có thể đi xuống word, syllable và phoneme level tùy locale. Microsoft cũng hỗ trợ IPA phoneme output cho `en-US`. Nguồn: [Microsoft Learn — Pronunciation Assessment](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment).

Azure Speech hỗ trợ real-time và batch speech-to-text, nên MVP có thể dùng microphone browser hoặc upload audio rồi đánh giá mà không phải tự huấn luyện speech model. Nguồn: [Microsoft Learn — Speech to Text](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-to-text).

Microsoft hiện liệt kê nhiều locale được hỗ trợ cho pronunciation assessment; tuy nhiên một số tính năng nâng cao phụ thuộc locale, và `en-US` có coverage tốt nhất cho phoneme/prosody. Nguồn: [Microsoft Learn — Language Support](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=pronunciation-assessment).

### Observation

Các công cụ pronunciation phổ biến thường đưa người học qua lesson có sẵn. Điều này hữu ích cho nền tảng, nhưng developer thường cần luyện một tập câu rất hẹp và lặp lại trong công việc của chính họ.

### Assumption cần kiểm chứng

Một developer sẽ luyện đều hơn nếu mỗi session chỉ mất 5–10 phút và nội dung bài tập xuất phát từ chính câu họ sắp dùng trong meeting, code review hoặc incident discussion.

### Workaround hiện tại

Người học thường:

- Đọc câu bằng Google Translate/TTS rồi nhại lại.
- Dùng YouTube để luyện shadowing chung.
- Dùng app pronunciation với lesson có sẵn.
- Ghi âm bằng điện thoại rồi tự nghe lại.
- Hỏi AI sửa câu nhưng không có tracking pronunciation dài hạn.

Các cách này không tạo được vòng lặp: **câu công việc thật → luyện nói → đo lỗi → lưu lỗi lặp lại → ôn lại đúng lỗi đó**.

## 3. Người dùng mục tiêu

### Primary user

Developer Việt Nam có thể đọc tiếng Anh ở mức cơ bản đến trung cấp nhưng cần nói thường xuyên trong môi trường kỹ thuật.

### Context of use

- Trước daily standup.
- Trước refinement/planning.
- Trước demo.
- Khi chuẩn bị giải thích một bug hoặc root cause.
- Khi sắp trao đổi với QA/client/đồng nghiệp quốc tế.
- Khi muốn luyện các câu technical English thường xuyên xuất hiện trong công việc.

### Main pain point

Biết ý muốn nói nhưng câu nói ra chậm, ngắt sai chỗ, phát âm thiếu rõ ràng hoặc phải dịch trong đầu quá lâu.

### Current workaround

Viết câu ra, dùng TTS nghe mẫu, rồi đọc đi đọc lại mà không có dữ liệu cho biết lỗi nào đang lặp lại qua nhiều ngày.

### Lý do họ sẽ thử SpeakBacklog

Nội dung không phải textbook. Nó là **backlog các câu mà chính người dùng cần nói thật**, được biến thành bài luyện pronunciation có tracking cụ thể.

## 4. Giải pháp đề xuất

Người dùng tạo một “speech item” bằng một trong ba input đơn giản:

1. Nhập câu trực tiếp.
2. Dán một đoạn update/technical explanation.
3. Chọn template như `Daily Update`, `Bug Explanation`, `Code Review`, `Estimate`, `Blocker` rồi điền nội dung.

Ứng dụng sau đó:

1. Chuẩn hóa text thành các câu ngắn vừa luyện.
2. Tạo audio mẫu bằng text-to-speech hoặc cho người dùng dùng browser TTS trong MVP.
3. Hiển thị phrase chunking, ví dụ:

```text
I’m still investigating / the root cause / of the deployment failure.
```

4. Người dùng nghe mẫu.
5. Người dùng bấm Record và đọc lại.
6. Backend gửi audio + reference text tới Azure Pronunciation Assessment.
7. UI hiển thị:
   - Accuracy
   - Fluency
   - Completeness
   - Prosody nếu locale hỗ trợ
   - từ nào có score thấp
   - phoneme khó ở `en-US`
8. Người dùng retry ngay.
9. Hệ thống lưu attempt.
10. Những từ/phoneme thường xuyên yếu được đưa vào “Practice Queue”.

### Concrete example

Người dùng chuẩn bị daily update:

```text
Yesterday I fixed the calendar synchronization issue.
Today I’m adding integration tests for the update flow.
I’m currently blocked by an intermittent Microsoft Graph error.
```

SpeakBacklog chia thành ba speech items. Người dùng luyện câu thứ ba và nhận thấy `intermittent` có accuracy thấp, đồng thời fluency giảm ở đoạn `blocked by an intermittent`.

Sau ba lần retry, score tốt hơn. Hệ thống ghi nhận `intermittent` là một từ khó và đưa vào practice queue ngày hôm sau cùng hai câu mới dùng từ này.

### Automated

- Speech scoring.
- Word/phoneme error extraction.
- Attempt history.
- Practice queue.
- Spaced re-practice đơn giản.

### User-controlled

- Câu nào được lưu.
- Có gửi audio lên cloud hay không.
- Locale phát âm.
- Có giữ audio sau khi chấm hay chỉ giữ score.
- Có dùng AI để rewrite câu hay không.

### Key differentiator

Không phải “học pronunciation toàn diện”. SpeakBacklog là **personal pronunciation backlog cho câu workplace English thực tế của chính người dùng**.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Ngay cả khi chỉ có một người dùng, ứng dụng vẫn hữu ích hàng ngày vì có thể dùng trước meeting hoặc daily standup.

### Technical learning value

Dự án kết hợp:

- Browser audio recording.
- Streaming/upload audio.
- Azure Speech SDK.
- Parsing structured speech assessment result.
- Time-series learning data.
- Scheduling spaced practice.
- Privacy-aware media retention.
- Optional AI text rewriting.

### Vì sao phù hợp solo developer

Core workflow nhỏ và rất rõ:

```text
Text → Record → Assess → Show mistakes → Retry → Save history
```

Không cần social network, teacher marketplace, realtime classroom hay mobile app ở MVP.

### Vì sao vẫn đáng dùng với rất ít user

Giá trị cá nhân không phụ thuộc network effect. Một developer có thể dùng hàng trăm câu riêng của mình và xây dần một corpus Workplace English sát công việc.

### Điều gì làm ý tưởng thất bại

- Người dùng thấy score không đủ đáng tin để thay đổi cách luyện.
- Flow record/assess quá chậm làm mất thói quen luyện ngắn.
- App trở thành “English learning platform” quá rộng và mất lợi thế niche.

### Lý do mạnh nhất để không build

Nếu mục tiêu chỉ là pronunciation tổng quát, các sản phẩm chuyên dụng hiện tại có UX và dataset tốt hơn nhiều. Dự án chỉ đáng làm nếu tập trung mạnh vào **technical workplace phrases + personal error history**.

## 7. Luồng hoạt động

### Normal flow

User tạo speech item
→ validate text length/locale
→ lưu reference text
→ user record audio
→ browser gửi audio blob
→ backend validate format/size
→ gọi Azure Pronunciation Assessment
→ normalize result
→ xóa raw audio nếu retention = none
→ lưu attempt + word scores
→ trả result
→ UI highlight từ yếu
→ nếu score dưới threshold thì enqueue practice item.

### Retry flow

User bấm Retry
→ record lần mới
→ assessment mới
→ tạo attempt riêng
→ hiển thị delta so với attempt trước
→ nếu vượt mastery threshold nhiều lần liên tiếp thì giảm priority trong practice queue.

### Failure cases

#### Microphone permission denied

Hiển thị hướng dẫn permission và hỗ trợ upload `.wav`/`.webm` nếu browser cho phép format phù hợp.

#### Azure Speech timeout

Attempt ở trạng thái `AssessmentFailed`, cho phép retry mà không mất speech item.

#### Unsupported locale/feature

Fallback sang score subset được hỗ trợ; không giả định mọi locale đều có phoneme/prosody giống nhau.

#### Audio quá nhỏ hoặc quá ngắn

Reject sớm với validation thông báo rõ.

#### Network mất giữa upload

Không tạo attempt completed; retry upload.

#### User nói khác reference text

Completeness/miscue data được dùng để giải thích thay vì chỉ kết luận pronunciation thấp.

## 8. Kiến trúc đề xuất

### Frontend — Vue 3 + Vite

Cần UI phản hồi nhanh cho record/retry/highlight result. Vue phù hợp vì MVP chủ yếu là vài màn hình tương tác.

Các view chính:

- Practice Today
- Speech Items
- Record & Assess
- Attempt History
- Weak Words

### Backend — ASP.NET Core .NET 10 modular monolith

.NET 10 hiện là LTS và đang được Microsoft hỗ trợ active đến tháng 11/2028. Nguồn: [Official .NET Support Policy](https://dotnet.microsoft.com/en-us/platform/support/policy).

Modules:

- `SpeechItems`
- `Recording`
- `Assessment`
- `PracticeQueue`
- `Progress`

Không cần microservices.

### Database — PostgreSQL

Lưu text, assessment metadata, word scores, practice state và user preferences.

### Background worker

MVP không bắt buộc nếu assessment được xử lý sync trong vài giây. Sau đó có thể thêm `BackgroundService` cho cleanup, reminders và spaced-practice scheduling.

### Queue

Không cần ở MVP. Chỉ thêm nếu chuyển sang batch audio hoặc retry jobs.

### Cache

Không cần.

### File storage

Mặc định **không giữ audio** sau khi assessment thành công. Nếu user bật retention, MVP có thể dùng local filesystem volume; cloud variant có thể dùng Azure Blob Storage.

### Authentication

MVP self-hosted single-user có thể dùng local password hoặc reverse-proxy auth. Không cần OAuth ngay.

### External API

Azure Speech Pronunciation Assessment là integration chính.

### AI model

Không bắt buộc cho core MVP.

### Logging

Structured logs với:

- Assessment ID
- Speech Item ID
- latency
- Azure status
- audio duration
- nhưng không log raw text/audio nếu user bật privacy mode.

### Deployment

Docker Compose:

```text
web
api
postgres
```

Có thể chạy trên VPS, mini PC hoặc Azure Container Apps/App Service.

## 9. Công nghệ đề xuất

### .NET 10 + ASP.NET Core

**Why:** LTS hiện tại, mạnh cho API, background processing và Azure SDK.

**Simpler alternative:** Minimal API project duy nhất không chia layer phức tạp.

**Outgrow point:** chỉ cần tách assessment worker riêng khi concurrency tăng đáng kể.

### EF Core + PostgreSQL

**Why:** schema quan hệ nhỏ nhưng có history và query theo thời gian.

**Simpler alternative:** SQLite cho single-user local MVP.

**Outgrow point:** PostgreSQL đủ lâu dài; không có lý do sớm để thêm NoSQL.

### Vue 3 + Vite

**Why:** UI state tương tác record/retry phù hợp SPA nhẹ.

**Simpler alternative:** Razor Pages nếu muốn giảm số project.

**Outgrow point:** gần như không cần thay framework trừ khi xây native mobile.

### Azure Speech SDK

**Why:** Pronunciation Assessment đã cung cấp các score cần thiết thay vì tự xây acoustic model.

**Simpler alternative:** ban đầu chỉ dùng Speech SDK cho assessment, browser `speechSynthesis` cho sample voice.

**Outgrow point:** nếu chi phí/privacy trở thành vấn đề lớn, nghiên cứu local speech scoring là một project riêng.

### MediaRecorder API

**Why:** browser-native recording, giảm dependency frontend.

**Simpler alternative:** upload file audio có sẵn.

### Docker

**Why:** dễ self-host và tái tạo môi trường.

### Playwright

**Why:** test UI state và practice workflow; microphone hardware thực có thể mock ở integration layer.

### GitHub Actions

Build, test, Docker image publish.

## 10. Thiết kế dữ liệu ban đầu

### SpeechItem

**Purpose:** một câu hoặc đoạn ngắn cần luyện.

Fields:

- `Id`
- `Text`
- `Locale`
- `Category`
- `CreatedAt`
- `Status`
- `MasteryScore`
- `NextPracticeAt`

Relationship: một SpeechItem có nhiều AssessmentAttempt.

Retention: giữ cho tới khi user xóa.

### AssessmentAttempt

**Purpose:** một lần thu âm và assessment.

Fields:

- `Id`
- `SpeechItemId`
- `CreatedAt`
- `AccuracyScore`
- `FluencyScore`
- `CompletenessScore`
- `ProsodyScore`
- `DurationMs`
- `Provider`
- `ProviderLatencyMs`
- `Status`

Retention: giữ score/history lâu dài; không cần giữ raw provider response vô hạn.

### WordAssessment

**Purpose:** chi tiết từ yếu trong mỗi attempt.

Fields:

- `Id`
- `AssessmentAttemptId`
- `Word`
- `AccuracyScore`
- `ErrorType`
- `StartOffset`
- `Duration`

Retention: cùng attempt.

### PhonemeAssessment

Chỉ lưu khi provider/locale trả dữ liệu.

Fields:

- `Id`
- `WordAssessmentId`
- `Phoneme`
- `AccuracyScore`

Có thể bỏ entity này trong tuần đầu để giữ schema nhỏ.

### PracticeState

**Purpose:** spaced re-practice đơn giản.

Fields:

- `SpeechItemId`
- `Priority`
- `FailureStreak`
- `SuccessStreak`
- `NextPracticeAt`
- `LastPracticedAt`

## 11. API và tích hợp

### Azure Speech Pronunciation Assessment

**Purpose:** chấm pronunciation theo reference text.

**Authentication:** Azure Speech resource credential hoặc token; credential chỉ ở backend.

**Cost/rate concern:** dịch vụ tính usage theo pricing Azure Speech; cần theo dõi quota/budget. Microsoft ghi rõ pronunciation assessment dựa trên Speech service pricing. Nguồn: [Microsoft Learn](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/how-to-pronunciation-assessment).

**Privacy:** audio được gửi tới cloud provider để xử lý, nên UI phải nói rõ và user phải kiểm soát retention.

**Fallback:** nếu provider unavailable, giữ speech item và cho retry sau; không fake score.

### Azure Speech-to-Text

**Purpose:** optional cho unscripted practice hoặc xác nhận user đã nói câu nào.

**Authentication:** cùng Azure Speech resource.

**Cost:** usage-based.

**Fallback:** scripted MVP không cần gọi STT riêng.

### Browser MediaRecorder

**Purpose:** thu audio.

**Authentication:** browser microphone permission.

**Cost:** none.

**Privacy:** audio nằm local trước khi user submit.

**Fallback:** upload file audio.

### Browser Speech Synthesis / Azure TTS

**Purpose:** phát sample pronunciation.

MVP có thể dùng browser-native speech synthesis để tránh thêm cloud cost. Azure TTS là extension khi cần voice consistency.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Core value không cần generative AI. Pronunciation scoring là speech model/API chuyên dụng và kết quả có cấu trúc rõ ràng.

### AI task hợp lý về sau

Rewrite một câu technical English sao cho tự nhiên hơn nhưng giữ nguyên intent.

Input:

```json
{
  "original": "Yesterday I investigate this bug but still not found root cause",
  "context": "daily standup",
  "level": "B1"
}
```

Expected structured output:

```json
{
  "recommended": "Yesterday, I investigated the bug, but I still haven't found the root cause.",
  "alternatives": [
    "I investigated the bug yesterday, but the root cause is still unclear."
  ],
  "notes": [
    "Use past tense for investigated."
  ]
}
```

### Validation

- Output phải parse được JSON schema.
- Không tự thay đổi technical facts.
- User luôn chọn câu cuối cùng trước khi lưu.

### Deterministic fallback

Người dùng nhập câu trực tiếp; pronunciation workflow vẫn hoạt động đầy đủ.

### Risks

- Hallucination làm thay đổi meaning.
- Privacy nếu gửi nội dung nội bộ lên model.
- Cost và latency.

Vì vậy AI không nên nằm trong Phase 1.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

**Goal:** chứng minh người dùng thực sự có các câu workplace English muốn luyện lặp lại.

**Main tasks:**

- Thu thập 20–30 câu bản thân đã dùng hoặc muốn dùng trong daily/code review/bug discussion.
- Dùng Azure Foundry Pronunciation Assessment thủ công với 10 câu.
- Ghi lại xem word-level feedback có giúp sửa cách đọc không.

**Expected output:** một corpus nhỏ gồm câu thật + từ khó.

**Completion criteria:** ít nhất 5 câu cho thấy retry sau feedback cải thiện rõ score hoặc độ tự tin chủ quan.

### Phase 1 — Core MVP

**Goal:** hoàn thành vertical workflow Text → Record → Assess → Result → Retry.

**Main tasks:**

- SpeechItem CRUD tối thiểu.
- Browser recorder.
- Backend audio endpoint.
- Azure Speech adapter.
- Result normalization.
- Word highlight UI.
- Attempt persistence.

**Expected output:** user có thể luyện một câu thật end-to-end.

**Completion criteria:** 10 câu được luyện và lịch sử attempt được lưu chính xác.

### Phase 2 — Reliability

**Goal:** app không mất dữ liệu và xử lý failure rõ ràng.

**Main tasks:**

- Audio validation.
- API timeout/retry policy phù hợp.
- Secret handling.
- Privacy settings.
- Cleanup temp audio.
- Integration tests.
- Error telemetry.

**Expected output:** provider/network failure không làm hỏng practice state.

**Completion criteria:** failure-path tests pass và temp audio được cleanup chắc chắn.

### Phase 3 — Useful expansion

**Goal:** biến app từ demo thành tool luyện hàng ngày.

**Main tasks:**

- Practice queue.
- Mastery logic.
- Weak-word report.
- IPA/phoneme view.
- Category/tag.
- Daily five-minute session.
- Optional sample voice.

**Expected output:** user mở app và ngay lập tức có 5–10 câu nên luyện hôm nay.

**Completion criteria:** dùng liên tục ít nhất 10 ngày mà không cần tự chọn lại toàn bộ câu.

### Phase 4 — Production readiness

**Goal:** self-hosted ổn định và có thể chia sẻ cho vài user.

**Main tasks:**

- Docker Compose.
- GitHub Actions.
- DB migration/backup.
- Health checks.
- OpenTelemetry/basic metrics.
- Config docs.
- Data deletion/export.
- Azure budget/quota documentation.

**Expected output:** deploy một command và restore được dữ liệu.

**Completion criteria:** chạy ổn định 2 tuần với backup/restore test thành công.

## 14. Các bài toán kỹ thuật đáng học

### 1. Browser audio capture và codec compatibility

MediaRecorder output khác nhau theo browser. Cần hiểu MIME negotiation, sample rate, transcoding requirement và upload streaming.

**Skill gained:** browser media APIs + robust file validation.

### 2. Normalize third-party speech assessment result

Provider response có nhiều level: full text, word, syllable, phoneme.

**Skill gained:** adapter pattern, external API normalization, defensive parsing.

### 3. Privacy-preserving audio workflow

Audio là dữ liệu nhạy cảm hơn text thông thường.

**Skill gained:** ephemeral storage, secure upload, retention policy, redacted logging.

### 4. Personal learning scheduling

Practice queue không cần ML nhưng cần logic ưu tiên hợp lý dựa trên score, repetition và time.

**Skill gained:** deterministic spaced repetition và scoring design.

### 5. Meaningful progress metrics

Score provider có thể dao động theo microphone/noise.

**Skill gained:** rolling average, trend analysis, confidence-aware UI, tránh overfit vào một lần đo.

## 15. Rủi ro và cách xử lý

### Speech score không ổn định

**Risk:** microphone, noise và accent làm score dao động.

**Mitigation:** hiển thị trend qua nhiều attempt, không coi một score là ground truth tuyệt đối.

### Data privacy

**Risk:** câu workplace có thể chứa project/client information.

**Mitigation:** cảnh báo không nhập secret; local/self-hosted DB; audio không giữ mặc định; optional redaction; không log raw content.

### Cloud dependency

**Risk:** Azure unavailable hoặc credential hết hạn.

**Mitigation:** graceful failure, queue retry thủ công, speech item vẫn dùng được offline để self-practice.

### Cost

**Risk:** nhiều audio attempt gây chi phí ngoài dự kiến.

**Mitigation:** hard daily assessment limit, usage counter, configurable budget threshold.

### Scope expansion

**Risk:** biến thành full TOEIC/English platform.

**Mitigation:** chỉ hỗ trợ spoken workplace phrases trong MVP.

### AI rewrite thay đổi meaning

**Risk:** câu kỹ thuật bị rewrite sai fact.

**Mitigation:** AI optional; user review; không auto-replace original.

### User adoption

**Risk:** record mỗi ngày tạo friction.

**Mitigation:** session 5 phút, one-click retry, giữ câu ngắn.

## 16. Kiểm thử

### Strategy

- Unit tests cho practice scheduling, mastery threshold và score aggregation.
- Integration tests cho Azure adapter bằng mock/stub response fixtures.
- Contract tests cho provider response parser.
- E2E Playwright cho text → record/upload mock → result → retry.
- Failure-path tests cho timeout, malformed audio, unsupported locale.
- Security tests cho upload size/path handling và secret leakage.

### 5 test scenario quan trọng nhất

1. User tạo câu, upload audio hợp lệ và nhận normalized score.
2. Word có accuracy thấp được highlight và đưa vào weak-word report.
3. Retry tạo attempt mới, không overwrite attempt cũ.
4. Azure timeout không làm mất SpeechItem và không đánh dấu mastery sai.
5. Audio được xóa khỏi temporary storage sau assessment khi retention = none.

## 17. Cách đo dự án có hữu ích hay không

### Product usage metric

Số **completed practice sessions/week**, không phải page view.

### Time saved

Thời gian chuẩn bị spoken English trước meeting giảm từ việc tự tìm TTS/ghi âm/manual notes xuống một workflow duy nhất.

### Task completion rate

% speech item được luyện ít nhất 3 attempts hoặc đạt mastery threshold.

### Pronunciation progress

Median score của cùng speech item qua lần đầu và best-of-next-3 attempts.

Không dùng score giữa các câu khác nhau để kết luận quá mạnh.

### Repeated use

Số tuần có ít nhất 3 practice sessions.

### Reliability

- Assessment success rate.
- Provider latency p50/p95.
- Temp-audio cleanup success rate.

### Validation target cá nhân

Trong 30 ngày:

- tạo ít nhất 50 workplace phrases;
- luyện ít nhất 15 ngày;
- có ít nhất 20 câu được chuyển sang mastered;
- xác định được top 10 từ/phoneme lặp lại nhiều nhất.

Nếu không đạt repeated-use dù app chạy ổn, vấn đề có thể nằm ở habit/UX chứ không phải kỹ thuật.

## 20. Việc cần làm ngay hôm nay

### Development objective

Trong **60–120 phút**, tạo vertical slice nhỏ nhất:

```text
Nhập câu → upload một file WAV → gọi pronunciation assessment → in Accuracy/Fluency + từ yếu ra terminal/API response
```

Chưa làm database và frontend hoàn chỉnh.

### Files/components cần tạo

```text
SpeakBacklog.sln
src/
  SpeakBacklog.Api/
    Program.cs
    Speech/
      IPronunciationAssessmentService.cs
      AzurePronunciationAssessmentService.cs
      PronunciationAssessmentResult.cs
      WordScore.cs
tests/
  SpeakBacklog.Tests/
    PronunciationResultParserTests.cs
samples/
  sample.wav
```

### Setup commands

```bash
dotnet new sln -n SpeakBacklog
dotnet new webapi -n SpeakBacklog.Api -o src/SpeakBacklog.Api
dotnet new xunit -n SpeakBacklog.Tests -o tests/SpeakBacklog.Tests
dotnet sln add src/SpeakBacklog.Api
dotnet sln add tests/SpeakBacklog.Tests
dotnet add tests/SpeakBacklog.Tests reference src/SpeakBacklog.Api
```

Cài Azure Speech SDK package phù hợp với .NET theo tài liệu Microsoft hiện hành.

Environment variables chỉ chứa credential ở local secret store hoặc shell environment; không commit credential vào repository.

### First vertical slice

Tạo endpoint:

```text
POST /api/pronunciation/assess
```

Multipart fields:

```text
text: "I’m still investigating the root cause."
locale: "en-US"
audio: sample.wav
```

Response tối thiểu:

```json
{
  "accuracy": 82.4,
  "fluency": 76.1,
  "completeness": 100,
  "weakWords": [
    {
      "word": "investigating",
      "accuracy": 58.0
    }
  ]
}
```

### Expected result

Chạy API local và gửi một audio file của chính bạn. Terminal hoặc Swagger response hiển thị ít nhất overall accuracy, fluency và danh sách từ có accuracy dưới threshold.

### Verification checklist

- [ ] API nhận `multipart/form-data`.
- [ ] Reject file không phải audio hoặc quá size limit.
- [ ] Reference text được gửi đúng tới assessment service.
- [ ] Azure response được map sang DTO của app.
- [ ] Có ít nhất một word score trong response.
- [ ] Không log credential.
- [ ] Temp audio bị xóa sau request.
- [ ] Có unit test parser dùng fixture JSON đã loại dữ liệu nhạy cảm.

### Stop condition

Kết thúc session ngay khi chạy được một command tương đương:

```bash
curl -X POST http://localhost:5000/api/pronunciation/assess \
  -F 'text=I am still investigating the root cause.' \
  -F 'locale=en-US' \
  -F 'audio=@samples/sample.wav'
```

và nhận JSON có score + weak words từ audio thật. Không làm login, practice queue, AI rewrite, dashboard hoặc PostgreSQL trong session đầu tiên.
