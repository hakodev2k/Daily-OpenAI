# Ý tưởng hôm nay: API Contract Guardian - Trợ lý phát hiện breaking change cho API

## 1. Tóm tắt ý tưởng
Một công cụ dành cho backend developer giúp tự động kiểm tra thay đổi API giữa các phiên bản và cảnh báo breaking change trước khi deploy. MVP hướng tới solo developer và team nhỏ, quy mô Medium, có thể hoàn thành trong 3-4 tuần.

## 2. Bài toán thực tế
Khi API thay đổi response, request model, validation hoặc authentication flow, frontend, mobile app hoặc hệ thống tích hợp có thể bị lỗi mà không phát hiện sớm. Developer thường review thủ công Swagger diff hoặc chỉ phát hiện sau khi QA/production gặp lỗi.

## 3. Người dùng mục tiêu
Backend developer, technical lead và team nhỏ xây dựng REST API.
Pain point: không có cách đơn giản để biết thay đổi API hiện tại có ảnh hưởng consumer cũ hay không.

## 4. Giải pháp đề xuất
Người dùng kết nối repository hoặc upload OpenAPI specification của phiên bản cũ và mới. Hệ thống phân tích diff, phân loại thay đổi thành safe change, warning hoặc breaking change.

Ví dụ: đổi field Customer.Name thành required hoặc xóa field trong response sẽ được đánh dấu trước khi merge pull request.

## 5. Tại sao đáng làm
Dự án phù hợp với kinh nghiệm .NET, REST API và CI/CD. Có giá trị ngay khi dùng cho chính các dự án cá nhân. Rủi ro lớn nhất là cạnh tranh với các API governance tool lớn.

## 6. Phạm vi MVP

### Must have
- Import OpenAPI JSON/YAML
- So sánh hai phiên bản API
- Rule engine phát hiện breaking change
- Xuất báo cáo Markdown/HTML

### Should have
- GitHub Actions integration
- Pull request comment
- History tracking

### Later
- AI giải thích impact
- API consumer mapping
- SaaS dashboard

## 7. Luồng hoạt động
Upload spec → validate schema → parse endpoint/model → compare version → apply rules → generate report → notify.

Nếu không parse được spec, trả lỗi chi tiết và không đánh giá sai.

## 8. Kiến trúc đề xuất
Modular monolith:
- ASP.NET Core API
- Vue frontend
- PostgreSQL lưu project và report
- Background worker xử lý scan lớn
- Object storage lưu OpenAPI file

Không cần microservice.

## 9. Công nghệ đề xuất
- .NET 10 + ASP.NET Core
- Microsoft.OpenApi hoặc NSwag
- EF Core + PostgreSQL
- Vue 3
- Hangfire cho background job
- Docker + GitHub Actions

## 10. Thiết kế dữ liệu ban đầu
Project: Id, Name, RepositoryUrl.
ApiSpec: Id, ProjectId, Version, ContentPath, CreatedAt.
ScanResult: Id, ApiSpecId, Severity, Report, CreatedAt.

## 11. API và tích hợp
GitHub API để lấy OpenAPI từ repository, cần token với quyền phù hợp. Có thể fallback bằng upload file thủ công.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng optional. Có thể dùng để giải thích impact bằng ngôn ngữ tự nhiên. Rule engine vẫn phải là nguồn quyết định chính.

## 13. Kế hoạch triển khai

### Phase 0
Thu thập 20 thay đổi API thực tế và xác định rule.

### Phase 1
Build upload spec, diff engine và report.

### Phase 2
Thêm test, caching, error handling.

### Phase 3
Thêm CI integration.

### Phase 4
Deploy và monitoring.

## 14. Các bài toán kỹ thuật đáng học
- OpenAPI parsing: hiểu API contract.
- Rule engine: thiết kế business rules.
- CI integration: automation workflow.
- Version comparison: data modeling.

## 15. Rủi ro và cách xử lý
Rule không đầy đủ → cho phép custom rule.

API đặc thù → bắt đầu với REST/OpenAPI chuẩn.

## 16. Kiểm thử
1. Phát hiện xóa endpoint.
2. Phát hiện đổi response type.
3. Không báo lỗi với additive change.
4. Scan lỗi file không hợp lệ.
5. CI chạy ổn định.

## 17. Cách đo dự án hữu ích
- Số breaking change phát hiện trước deploy.
- Thời gian review API giảm.
- Số lần rollback API giảm.

## 18. Khả năng mở rộng
Có thể mở rộng thành API quality platform, developer tool open-source hoặc SaaS cho team nhỏ.

## 19. Mô hình giá trị
- Portfolio project
- Developer tool
- Open-source project
- Có thể SaaS hóa cho team.

## 20. Việc cần làm ngay hôm nay
Trong 60-120 phút:
1. Tạo ASP.NET Core solution.
2. Thêm package OpenAPI parser.
3. Tạo model ApiSpec.
4. Implement API upload file.
5. Viết rule đầu tiên: detect removed endpoint.
6. Tạo report JSON.

Kết quả cần đạt: upload hai OpenAPI file và nhận được cảnh báo thay đổi API đầu tiên.
