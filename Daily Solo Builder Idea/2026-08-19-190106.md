# Ý tưởng hôm nay: CaptionLint — Subtitle & Caption Accessibility QA

## 1. Tóm tắt ý tưởng

CaptionLint là một công cụ self-hosted giúp developer, QA và content creator **kiểm tra chất lượng kỹ thuật của subtitle/caption trước khi publish**: timestamp lỗi, cue chồng nhau, thời lượng quá ngắn/dài, tốc độ đọc quá cao, dòng quá dài, khoảng trống bất thường và các dấu hiệu accessibility kém. Thay vì chỉ xem video bằng mắt rồi dò lỗi thủ công, người dùng có một report tự động có severity, vị trí cue và gợi ý sửa.

- Người dùng chính: developer hoặc QA phụ trách video learning, documentation, training hoặc media nội bộ.
- Bài toán chính: subtitle có thể tồn tại nhưng vẫn khó đọc, sync kém hoặc có lỗi format khiến trải nghiệm accessibility giảm mạnh.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.

## 2. Bài toán thực tế

### Confirmed facts

W3C Web Accessibility Initiative nêu rõ captions cung cấp phiên bản văn bản đồng bộ của lời nói và thông tin âm thanh cần thiết để hiểu nội dung. Với video prerecorded có audio quan trọng, captions là yêu cầu ở WCAG Level A; live captions thuộc Level AA. W3C cũng lưu ý automatic captions thường vẫn cần được chỉnh sửa để đạt độ chính xác phù hợp.

Nguồn:

- W3C WAI — Captions/Subtitles: https://www.w3.org/WAI/media/av/captions/
- W3C WAI — Transcripts: https://www.w3.org/WAI/media/av/transcripts/
- W3C WebVTT specification: https://www.w3.org/TR/webvtt1/

WebVTT là định dạng chuẩn dùng cho text track gắn với audio/video trên web và có thể biểu diễn captions, subtitles, descriptions, chapters và metadata theo thời gian.

### Observation

Nhiều workflow hiện tập trung vào việc “có file subtitle hay chưa” hơn là kiểm tra sâu chất lượng cue. Một file có thể parse được nhưng vẫn có nhiều vấn đề:

- hai cue overlap nhau;
- cue chỉ tồn tại vài trăm milliseconds;
- một dòng chứa quá nhiều ký tự;
- text hiển thị quá nhanh để đọc;
- khoảng trống dài giữa hai cue dù audio vẫn tiếp tục;
- punctuation hoặc speaker labeling không nhất quán;
- timestamp lệch sau khi video được cắt/chèn đoạn.

### Assumption cần kiểm chứng

Team nhỏ có nhu cầu kiểm tra subtitle tự động trong CI hoặc trước khi publish, nhưng không muốn mua một media QA platform lớn chỉ để bắt các lỗi deterministic này.

### Cách mọi người hiện xử lý

- Mở file SRT/VTT trong editor.
- Xem video thủ công.
- Dùng player preview.
- Sửa cue bằng Subtitle Edit/Aegisub hoặc công cụ tương tự.
- Dựa vào feedback sau khi publish.

Những cách này hữu ích cho chỉnh sửa, nhưng việc lặp lại QA sau mỗi thay đổi video/subtitle vẫn tốn thời gian.

## 3. Người dùng mục tiêu

**Primary user:** developer hoặc QA engineer chịu trách nhiệm pipeline video/documentation nội bộ có subtitle.

- Context: training video, product demo, onboarding, technical tutorial, recorded webinar.
- Main pain point: subtitle file có hàng trăm hoặc hàng nghìn cue, rất khó review đều tay.
- Current workaround: mở player và xem thủ công từng đoạn.
- Lý do thử CaptionLint: có report deterministic trong vài giây và có thể đưa vào CI.

MVP không cố phục vụ studio phim, dịch thuật chuyên nghiệp hoặc live captioning.

## 4. Giải pháp đề xuất

Người dùng upload hoặc chỉ định một file `.vtt`/`.srt`.

CaptionLint sẽ:

1. Parse toàn bộ cue.
2. Normalize timestamp và text.
3. Chạy rule engine.
4. Tính các metric như cue duration, characters per second, line length, gap, overlap.
5. Gán severity: info / warning / error.
6. Xuất report web + JSON + exit code cho CI.

### Input

- `.vtt` hoặc `.srt`.
- Optional: duration của video.
- Optional: project rule profile.

### Processing

Rule engine deterministic chạy trên từng cue và trên quan hệ giữa cue hiện tại/cue kế tiếp.

### Output

Ví dụ:

```text
ERROR  Cue 184
00:12:33.140 --> 00:12:33.620
Duration: 480 ms
Text: "The deployment completed successfully."

Rule: MIN_CUE_DURATION
Recommendation: increase cue duration or merge with neighboring cue.
```

### Cái gì được tự động

- Parsing.
- Validation syntax.
- Timing checks.
- Readability metrics.
- Duplicate/overlap detection.
- Report generation.

### Cái gì người dùng vẫn kiểm soát

- Threshold.
- Rule enable/disable.
- Language profile.
- Accept/reject từng warning.
- Việc chỉnh sửa subtitle thật sự.

### Điểm khác biệt chính

Không cố trở thành subtitle editor. CaptionLint là **lint/test framework cho caption**, tương tự ESLint hoặc Roslyn analyzer nhưng dành cho timed text.

## 7. Luồng hoạt động

User chạy:

```bash
captionlint check ./captions/lesson-01.vtt
```

→ detect file type
→ parse file
→ validate syntax
→ normalize cue model
→ chạy rule engine
→ aggregate violations
→ calculate summary
→ render terminal output
→ write optional JSON/HTML report
→ return exit code.

### Alternative flows

**File parse lỗi**

→ dừng semantic rules
→ trả parse error có line/column.

**Unknown extension nhưng nội dung hợp lệ**

→ thử format detection theo header.

**Không có violation**

→ exit code `0`.

**Có warning nhưng không có error**

→ mặc định exit code `0`; CI policy có thể cấu hình strict mode.

**Có error**

→ exit code khác `0`.

## 10. Thiết kế dữ liệu ban đầu

Không cần relational database. Chỉ cần một canonical object model nhỏ.

### CaptionDocument

**Purpose:** biểu diễn một subtitle file đã parse.

Fields:

- `Format`
- `SourcePath`
- `Language`
- `Cues`
- `Metadata`

Relationship: chứa nhiều `CaptionCue`.

Retention: chỉ tồn tại trong process ở MVP.

### CaptionCue

**Purpose:** đơn vị subtitle chuẩn hóa.

Fields:

- `Index`
- `Start`
- `End`
- `Lines`
- `RawText`
- `Settings`

Derived values:

- `Duration`
- `CharacterCount`
- `CharactersPerSecond`

### LintViolation

**Purpose:** kết quả một rule.

Fields:

- `RuleId`
- `Severity`
- `CueIndex`
- `Message`
- `ActualValue`
- `ExpectedRange`
- `Suggestion`

### RuleProfile

**Purpose:** threshold theo project.

Fields:

- `RuleId`
- `Enabled`
- `Severity`
- `Parameters`

Retention: lưu trong config file version-controlled.

**Purpose:** lấy media duration hoặc stream metadata.

**Authentication:** không có.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Core MVP không cần AI. Các rule timing, overlap, line length, CPS và syntax phải deterministic.

AI chỉ đáng cân nhắc ở phase sau cho một task cụ thể:

### AI task

So sánh caption text với transcript hoặc audio transcription để gợi ý:

- thiếu câu;
- paraphrase làm mất ý;
- speaker label không nhất quán;
- terminology có khả năng sai.

### Required context

- caption cues;
- transcript reference hoặc speech-to-text result;
- optional terminology glossary.

### Structured output

```json
{
  "cueIndex": 42,
  "type": "possible_omission",
  "confidence": 0.84,
  "explanation": "..."
}
```

### Validation

AI result chỉ là warning, không được tự động fail build mặc định.

### Deterministic fallback

Nếu không có AI, toàn bộ core lint vẫn hoạt động.

### Risks

- hallucination;
- cost;
- latency;
- gửi nội dung media ra bên ngoài;
- false positives với thuật ngữ kỹ thuật.

## 15. Rủi ro và cách xử lý

### False positives

**Risk:** warning quá nhiều khiến user bỏ tool.

**Mitigation:** sensible defaults + per-rule config + baseline + suppression.

### Rule mang tính chủ quan

**Risk:** line length hoặc CPS không có một con số duy nhất phù hợp mọi ngôn ngữ.

**Mitigation:** ghi rõ đây là configurable heuristic, không tuyên bố threshold là WCAG requirement nếu nguồn không nói vậy.

### Format complexity

**Risk:** WebVTT có cue settings và metadata phức tạp hơn SRT.

**Mitigation:** MVP parse subset phổ biến trước, giữ raw settings để không mất dữ liệu.

### Scope expansion

**Risk:** biến project thành full subtitle editor/video platform.

**Mitigation:** giữ nguyên product boundary: lint, validate, report.

### AI privacy

**Risk:** nếu thêm AI, transcript có thể chứa dữ liệu nhạy cảm.

**Mitigation:** AI off by default; local-only core; explicit opt-in.

### Maintenance burden

**Risk:** nhiều format/vendor profile.

**Mitigation:** chỉ support SRT + WebVTT trước; plugin format về sau.

## 16. Kiểm thử

### Strategy

- Unit tests cho từng rule.
- Parser tests với valid/invalid fixtures.
- Property-based tests cho timestamp ordering nếu cần.
- Integration tests cho CLI exit code và JSON report.
- End-to-end test với sample folder.
- Security test cho path handling và output escaping trong HTML report.

### 5 test scenario quan trọng nhất

1. Hai cue overlap 500 ms phải sinh đúng một `OVERLAP` violation.
2. Cue có `End <= Start` phải là error.
3. File WebVTT hợp lệ không có issue phải trả exit code `0`.
4. Config override threshold phải thay đổi kết quả deterministic.
5. Malformed timestamp phải báo line/cue context thay vì crash process.

3. tạo `CaptionCue`;
4. sort theo `Start`;
5. nếu `current.End > next.Start` thì báo overlap;
6. nếu `End <= Start` thì báo invalid duration;
7. print report.

Expected output:

```text
CaptionLint
File: sample-overlap.vtt

ERROR OVERLAP
Cue 1 overlaps Cue 2 by 200 ms

Summary: 1 error, 0 warnings
```

### Verification checklist

- [ ] `dotnet build` thành công.
- [ ] Parser đọc được sample WebVTT.
- [ ] Overlap 200 ms được detect chính xác.
- [ ] File không overlap không báo lỗi.
- [ ] `End <= Start` được detect.
- [ ] Có ít nhất 3 unit tests pass.
- [ ] CLI trả non-zero exit code nếu có error.

### Stop condition

Dừng session ngay khi command:

```bash
dotnet run --project src/CaptionLint.Cli -- ./tests/CaptionLint.Core.Tests/Fixtures/sample-overlap.vtt
```

in được overlap report chính xác và test suite pass. Chưa làm SRT, HTML report, config system, AI hoặc video preview trong session đầu tiên.
