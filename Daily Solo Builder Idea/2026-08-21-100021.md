# Ý tưởng hôm nay: DraftVault — Trình cứu hộ form theo cơ chế opt-in, local-first và privacy-aware

## 1. Tóm tắt ý tưởng

**DraftVault** là một browser extension giúp người dùng tự động lưu tạm nội dung đang nhập vào các form dài trên những website họ **chủ động cho phép**, sau đó khôi phục khi tab bị reload, session hết hạn, browser crash hoặc người dùng lỡ đóng trang. Điểm khác biệt không phải “autosave mọi thứ trên mọi website”, mà là **per-site opt-in + không lưu password/file + preview diff trước restore + local-only + retention ngắn + field sensitivity rules**.

Người dùng chính là developer, QA, nhân viên vận hành hoặc người thường xuyên điền form dài trong dashboard nội bộ, support portal, job application, government form hoặc CMS. **Quy mô: Medium. MVP ước tính: 7–12 ngày làm ngoài giờ.**

## 2. Bài toán thực tế

### Confirmed facts

Browser extensions có thể dùng content scripts để đọc/thay đổi DOM của trang khi đã có host permission phù hợp. Chrome và MDN đều document content scripts như cơ chế extension chạy trong context của trang và có thể giao tiếp với extension background/service worker.

Nguồn:

- Chrome: https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts
- MDN: https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Content_scripts

Chrome `chrome.storage` cho phép extension lưu dữ liệu theo scope của extension, bất đồng bộ, và `storage.local` có quota mặc định khoảng 10 MB; Chrome khuyến nghị tránh dùng Web Storage của page cho dữ liệu extension. MDN cũng lưu ý extension storage **không mặc định được mã hóa**, nên không nên coi nó như nơi an toàn cho thông tin bí mật.

Nguồn:

- Chrome Storage API: https://developer.chrome.com/docs/extensions/reference/api/storage
- MDN Storage API: https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/API/storage

Các extension form-recovery hiện vẫn tồn tại và được cập nhật trong 2025–2026, ví dụ Form Recovery, FormGhost, Form Recover, Lazarus/Form Recovery derivatives và các Firefox add-ons. Điều này xác nhận category vẫn có nhu cầu sử dụng thực tế, nhưng cũng cho thấy đây **không phải ý tưởng hoàn toàn mới**.

Ví dụ hiện tại:

- https://chromewebstore.google.com/detail/form-recovery/llccaclmlhflokcjcmcphgcfhjbjhhge
- https://chromewebstore.google.com/detail/formghost-%E2%80%94-never-lose-fo/hecjmagdnfhdkkhfanohgpomjkkknmhp
- https://chromewebstore.google.com/detail/form-recover/bfljnfaebdgaioklhiiocnhodcnpecob
- https://addons.mozilla.org/en-US/firefox/addon/form-history-control/

### Observation

Nhiều extension cùng category quảng bá “works on every website”, “autosave everything”, “all local” hoặc “restore one-click”. Giá trị cạnh tranh của DraftVault vì vậy không nên là thêm một form autosaver chung chung.

Khoảng trống hợp lý hơn cho một solo project là tập trung vào **privacy-preserving workflow recovery**:

- chỉ kích hoạt sau khi user allow domain;
- hiển thị chính xác loại field nào đang được lưu;
- mặc định loại bỏ password, OTP, payment và file input;
- cho phép exclude CSS selector/field name;
- retention ngắn và auto-delete;
- restore có preview thay vì inject âm thầm;
- fingerprint form để tránh restore nhầm draft vào một form khác trên cùng URL;
- giữ history 2–5 snapshot thay vì chỉ bản cuối.

### Assumption cần validate

Người dùng thực sự thấy khó chịu nhất ở **form dài hoặc admin dashboard dễ mất state**, không phải form login/checkout ngắn. Đây là giả định sản phẩm cần kiểm chứng bằng usage thật và phỏng vấn nhỏ, không phải số liệu thị trường đã xác nhận.

## 3. Người dùng mục tiêu

### Primary user

Một developer/QA/operations user thường xuyên nhập dữ liệu vào web form dài trong tool nội bộ hoặc SaaS dashboard.

### Context sử dụng

Ví dụ:

- tạo ticket dài;
- nhập root-cause report;
- chỉnh CMS content;
- điền QA test evidence;
- điền application form;
- nhập cấu hình dài trong admin portal;
- viết comment/report trong các SPA có session timeout.

### Main pain point

Sau 10–30 phút nhập dữ liệu, user có thể mất nội dung vì:

- session hết hạn;
- route SPA reset component state;
- page refresh;
- tab crash;
- browser restart;
- navigation nhầm;
- form submit fail rồi app render lại form trống.

### Current workaround

- soạn nội dung dài trong Notepad/VS Code trước;
- copy clipboard thường xuyên;
- dùng browser autofill;
- dùng extension autosave toàn cục;
- hy vọng app có draft feature riêng.

### Vì sao họ thử DraftVault

Vì họ muốn “insurance” cho form dài nhưng **không muốn một extension có toàn quyền lưu mọi thứ họ gõ trên mọi website**.

## 4. Giải pháp đề xuất

### Main workflow

```text
User mở một website
→ bấm DraftVault
→ Allow this site
→ extension inject content script cho origin đó
→ detect eligible fields
→ debounce input changes
→ normalize form + field identities
→ redact/exclude sensitive fields
→ save encrypted local snapshot
→ nếu reload/session reset
→ detect compatible draft
→ show restore preview
→ user chọn field cần restore
→ inject values + dispatch input/change events
→ mark recovery event
```

### Input

- origin được user allow;
- text inputs được phép;
- textarea;
- selected `contenteditable` elements;
- checkbox/radio/select trong phase sau;
- optional CSS exclude rules;
- retention policy.

### Processing

DraftVault xác định một **FormSignature** từ:

- origin;
- normalized path hoặc route pattern;
- form id/name nếu có;
- danh sách field labels/names/types;
- structural hash đơn giản.

Mỗi field có **FieldSignature** từ:

- `name`;
- `id`;
- associated label text;
- `aria-label`;
- DOM neighborhood hash;
- type.

Autosave dùng debounce 500–1500 ms, nhưng chỉ ghi snapshot mới nếu hash nội dung thay đổi.

### Output

Popup/side panel hiển thị:

```text
Draft found
Site: qa.example.com
Page: /incident/new
Saved: 10:42:11
Fields: 7
Age: 3 min

Changed since current page:
- Summary: 83 chars
- Root Cause: 1,248 chars
- Impact: 402 chars

[Preview] [Restore selected] [Discard]
```

### Tự động hóa

- detect fields;
- autosave;
- deduplicate snapshots;
- retention cleanup;
- draft detection;
- field matching;
- diff generation.

### User vẫn kiểm soát

- domain nào được theo dõi;
- field nào exclude;
- khi nào restore;
- snapshot nào được dùng;
- khi nào clear toàn bộ vault.

### Key differentiator

**Opt-in recovery with explainable capture.** User luôn biết website nào được phép, field nào đang được lưu và dữ liệu nào chuẩn bị restore.

### Ví dụ end-to-end

Một QA engineer đang điền bug report dài trên một internal portal. User đã allow domain này từ trước. DraftVault autosave 6 text fields vào local vault, nhưng bỏ qua field API token vì selector/name match sensitive policy.

Session portal hết hạn; sau khi login lại, route `/bug/new` render form trống. DraftVault phát hiện form signature gần khớp snapshot 4 phút trước, hiện preview. User bỏ chọn field “Environment” vì portal đã tự fill giá trị mới, restore 5 field còn lại. Extension dispatch `input`/`change` để React/Vue app nhận state đúng. User tiếp tục submit bình thường.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Đây là utility mà developer có thể dùng ngay cho các dashboard/testing site của chính mình. Giá trị không phụ thuộc vào network effect hay lượng user lớn.

### Technical learning value

Dự án có nhiều bài toán thú vị hơn vẻ ngoài:

- DOM mutation;
- dynamic SPAs;
- form/field identity;
- Shadow DOM;
- contenteditable;
- extension permissions;
- local encryption;
- cross-browser WebExtensions;
- storage quota;
- restore event compatibility;
- privacy-by-design.

### Vì sao phù hợp solo developer

Core MVP hoàn toàn chạy client-side. Không database server, không cloud API, không payment, không scraping.

### Hữu ích với rất ít user

Một user duy nhất vẫn nhận giá trị mỗi lần recover được một form dài.

### Điều gì làm ý tưởng thất bại

- restore không ổn định trên React/Angular/Shadow DOM;
- extension cần host permission quá rộng;
- người dùng không tin tool lưu nội dung form;
- category hiện tại đã đủ tốt;
- form mất dữ liệu quá hiếm nên user quên mất extension tồn tại.

### Lý do mạnh nhất để không build

**Trust problem.** Một extension đọc form content có mức nhạy cảm rất cao. Nếu permission model và privacy UX không tốt, user sẽ đúng khi không cài nó.

## 6. Phạm vi MVP

### Must have

- Chrome/Chromium Manifest V3.
- Per-origin opt-in.
- Chỉ hỗ trợ `input[type=text|email|search|number]` và `textarea` ở MVP.
- Bỏ qua `password`, file inputs và hidden inputs.
- Configurable denylist field names/selectors.
- Debounced autosave.
- FormSignature + FieldSignature V1.
- Local vault.
- AES-GCM encryption bằng Web Crypto với key chỉ lưu local theo thiết kế MVP.
- Retention 24h/3d/7d.
- Giới hạn snapshots per form.
- Restore preview.
- Restore selected fields.
- Manual “Save snapshot now”.
- Clear site data / clear all.
- Activity log metadata không chứa raw values.

### Should have

- `contenteditable`.
- checkbox/radio/select.
- SPA route tracking.
- MutationObserver cho dynamic forms.
- session-only mode.
- field-level restore history.
- side panel.
- export/import encrypted vault.

### Later

- Firefox.
- Shadow DOM support tốt hơn.
- iframe support.
- optional passphrase-derived key.
- enterprise managed allowlist.
- sync giữa devices bằng encrypted blob.
- team/internal distribution.

Không làm cloud sync trong MVP.

## 7. Luồng hoạt động

### Normal flow

```text
User enables site
→ request host permission for origin
→ register/inject content script
→ scan eligible fields
→ listen input events
→ debounce
→ sensitivity filter
→ compute signatures
→ encrypt draft
→ chrome.storage.local
→ retention cleanup
```

Khi quay lại trang:

```text
page loaded
→ compute form signature
→ query compatible snapshots
→ compare current values
→ show restore candidate
→ user previews
→ restore selected values
→ dispatch DOM input/change events
→ verify field values
```

### Alternative flow: DOM thay đổi nhẹ

Nếu exact signature không match nhưng origin/path + phần lớn FieldSignature match, hiển thị `Possible match` thay vì auto offer high-confidence restore.

### Failure: storage quota

- dừng tạo version mới;
- cleanup expired drafts;
- giữ snapshot mới nhất mỗi form;
- báo user storage pressure.

### Failure: page CSP

Content scripts của extension có isolated world và không phụ thuộc vào việc inject remote JS. Không dùng remote code.

### Failure: React controlled input không nhận value

Restore adapter phải set native value setter phù hợp và dispatch events; nếu validation sau restore cho thấy DOM value quay lại trạng thái cũ thì đánh dấu field `RestoreFailed` thay vì tuyên bố success.

### Failure: sensitive field bị nhận nhầm là normal

Default-deny cho các signals như:

```text
password
passcode
otp
cvv
cvc
card
secret
token
api_key
private_key
```

Nếu uncertainty cao, skip và hiển thị “Excluded by safety rule”.

Không cần.

### Authentication

### External API

Không có.

### AI

Không cần.

## 9. Công nghệ đề xuất

### TypeScript

Phù hợp nhất vì browser extension APIs và DOM đều native JavaScript ecosystem.

**Vì sao không dùng .NET:** Blazor/WebAssembly làm extension content script/service worker phức tạp hơn rất nhiều mà không có lợi ích tương xứng. Đây là trường hợp nên chọn công nghệ khác stack quen thuộc.

### Manifest V3

Là kiến trúc extension hiện tại của Chromium.

### Chrome Extensions APIs

- `storage` cho vault/settings;
- `scripting` cho dynamic injection;
- `permissions` cho optional host permissions;
- `alarms` cho cleanup;
- `runtime` messaging.

### Web Crypto API

AES-GCM encryption cho local draft blobs.

Lưu ý: encryption key management local-only không biến compromised browser profile thành môi trường an toàn tuyệt đối. Mục tiêu là giảm plaintext-at-rest, không hứa “zero-access security”.

### Vite

Build TypeScript extension nhanh và gọn.

### Vitest

Unit test signature, policy, diff và retention.

### Playwright

Rất phù hợp để mở Chromium với unpacked extension và test end-to-end trên các fixture pages.

### Optional Vue 3

Dùng cho side panel nếu UI phức tạp hơn. Không cần ở session đầu.

## 11. API và tích hợp

### Chrome `storage`

Purpose: persistent extension-local data. Permission cần: `storage`.

Chrome document `storage.local` quota mặc định khoảng 10 MB và có thể request `unlimitedStorage`, nhưng MVP **không nên xin unlimitedStorage**; quota là guardrail tốt để buộc retention nhỏ.

Nguồn: https://developer.chrome.com/docs/extensions/reference/api/storage

Privacy concern: extension storage không nên được coi là encrypted secret store. DraftVault mã hóa payload trước khi persist và vẫn loại sensitive fields trước bước encryption.

Fallback: nếu storage write fail, hiện icon/warning rõ rằng autosave đang unavailable; không giả vờ “protected”.

### `scripting` + optional host permissions

Purpose: inject content script chỉ vào origin user cho phép.

Nguồn content script capability: https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts

Privacy principle: tránh khai báo blanket `<all_urls>` ở MVP nếu flow optional permission per-site đáp ứng được use case.

### Web Crypto API

Purpose: encrypt/decrypt local draft blob.

Authentication/cost: không cần external service.

Fallback: nếu crypto init lỗi, DraftVault nên disable autosave cho session thay vì fallback plaintext âm thầm.

### Firefox — Later

MDN xác nhận WebExtensions storage/content script model tương tự, nhưng differences về APIs/permissions cần compatibility layer. Không cần support trong MVP.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Toàn bộ core problem giải quyết tốt hơn bằng deterministic logic:

- field detection;
- sensitivity rules;
- signatures;
- diff;
- restore matching;
- retention.

Không nên gửi form content cho LLM chỉ để đoán field sensitivity hoặc khôi phục dữ liệu. Điều đó làm tăng privacy risk, cost, latency và phá vỡ local-first proposition.

Nếu tương lai muốn AI, use case hợp lý nhất chỉ là local/on-device classification cho field labels khó xác định, nhưng vẫn không cần cho MVP.

## 14. Các bài toán kỹ thuật đáng học

### 1. Stable form/field identity

DOM IDs có thể random theo render, labels có thể thay đổi, SPA route có thể cùng URL nhưng khác state.

Kỹ năng cải thiện: normalization, hashing, fuzzy matching deterministic.

### 2. Controlled input restoration

Set `element.value` không phải lúc nào cũng làm React/Vue state cập nhật.

Kỹ năng cải thiện: DOM event model, framework-controlled forms, browser automation internals.

### 3. Permission minimization

Extension muốn hoạt động “mọi lúc” thường dễ xin quyền toàn website. DraftVault phải thiết kế tốt với optional per-origin permissions.

Kỹ năng cải thiện: browser security model và least privilege UX.

### 4. Privacy-preserving local storage

Không chỉ encryption; cần data minimization, retention và deny sensitive fields từ trước persist.

Kỹ năng cải thiện: threat modeling, cryptography usage, secure local apps.

### 5. Dynamic DOM/SPA behavior

Form có thể xuất hiện sau API call, modal hoặc route navigation.

Kỹ năng cải thiện: MutationObserver, lifecycle detection và robust content scripts.

## 15. Rủi ro và cách xử lý

### Data privacy

**Risk:** extension lưu nội dung nhạy cảm.

**Mitigation:** opt-in site; password/file hard-block; configurable deny patterns; no network; encrypted local payload; retention ngắn; clear-all; visible capture indicator.

### Permission trust

**Risk:** user sợ extension đọc toàn browsing data.

**Mitigation:** optional host permission per site; open source; no `<all_urls>` trong MVP nếu có thể; explain permissions trong UI.

### Restore sai form

**Risk:** snapshot của form A bị inject vào form B.

**Mitigation:** confidence threshold; preview; exact field matching; user confirmation; không auto-restore.

### Modern framework incompatibility

**Risk:** DOM value đổi nhưng app state không đổi.

**Mitigation:** adapters + event dispatch + post-restore verification + fixture test React/Vue.

### Storage limit

**Risk:** draft history đầy quota.

**Mitigation:** short retention, content hashing, snapshot cap, cleanup, no binary data.

### Scope expansion

**Risk:** biến thành password manager/autofill/cloud sync platform.

**Mitigation:** product boundary rõ: temporary recovery, không identity/payment autofill.

### Browser store policy/maintenance

**Risk:** Manifest/API policies thay đổi.

**Mitigation:** dùng documented MV3 APIs; integration tests trên stable Chromium; tránh unsupported hacks.

### User adoption

**Risk:** existing extensions đã đủ tốt.

**Mitigation:** validate bằng privacy-conscious niche và real internal forms; nếu differentiator không rõ, giữ project như personal tool/open-source learning project thay vì thương mại hóa.

- 0 password/file persisted;
- 0 network upload từ core extension;

Không áp dụng.

## 20. Việc cần làm ngay hôm nay

### Development objective

Trong **60–120 phút**, tạo vertical slice nhỏ nhất:

> Trên một fixture page, type vào textarea → extension autosave local → reload → bấm Restore → nội dung quay lại.

Chưa encryption, chưa React support, chưa side panel.

### Files/components cần tạo

```text
DraftVault/
├── manifest.json
├── src/
│   ├── content.ts
│   ├── service-worker.ts
│   ├── popup.ts
│   ├── popup.html
│   ├── field-signature.ts
│   └── draft-store.ts
├── fixtures/
│   └── basic-form.html
├── tests/
│   └── field-signature.test.ts
├── package.json
└── vite.config.ts
```

### Setup commands

```bash
mkdir DraftVault
cd DraftVault
npm init -y
npm install -D typescript vite vitest @types/chrome
npx tsc --init
```

Manifest tối thiểu:

```json
{
  "manifest_version": 3,
  "name": "DraftVault Dev",
  "version": "0.0.1",
  "permissions": ["storage", "scripting", "activeTab"],
  "background": {
    "service_worker": "service-worker.js",
    "type": "module"
  },
  "action": {
    "default_popup": "popup.html"
  }
}
```

Ở phiên đầu, dùng `activeTab` để user click extension rồi inject script vào tab hiện tại. Chưa cần xin persistent host permission.

### First vertical slice

`content.ts`:

- tìm tất cả textarea;
- generate key từ `location.origin + location.pathname + textarea.name/id/index`;
- listen `input`;
- debounce 700 ms;
- gửi message tới service worker;
- service worker lưu vào `chrome.storage.local`;
- khi user click Restore trong popup, gửi message content script đọc draft và set value;
- dispatch `input` event.

### Expected result

Test thủ công:

```text
1. Load extension unpacked.
2. Open fixtures/basic-form.html qua local dev server.
3. Click extension → Enable for this tab.
4. Type: "This text must survive reload".
5. Reload page.
6. Click Restore.
7. Text appears again.
```

### Verification checklist

- [ ] Không lưu `input[type=password]`.
- [ ] Reload mất page state nhưng draft vẫn còn.
- [ ] Restore chỉ chạy khi user click.
- [ ] `chrome.storage.local` chứa đúng draft key/value của textarea fixture.
- [ ] Console không log raw draft trong production path.
- [ ] Input event được dispatch sau restore.
- [ ] `npm test` có ít nhất 3 tests cho field key/signature helper.
- [ ] Không có network request nào từ extension.

### Stop condition

Dừng ngay khi đạt được:

> **Một textarea trên fixture page có thể được autosave và restore sau reload bằng extension unpacked.**

Không bắt đầu encryption, React adapter, dynamic permissions, history hoặc Firefox trước khi slice này chạy ổn.

## Research notes

### Confirmed facts

- Chromium/Firefox WebExtensions cho phép content scripts tương tác với page DOM khi có permission phù hợp.
- Extension Storage API cung cấp local persistent storage nhưng không nên được xem như encrypted confidential store mặc định.
- `storage.local` trên Chrome hiện có quota mặc định khoảng 10 MB.
- Nhiều form-recovery extensions đang tồn tại/cập nhật trong 2025–2026, nên bài toán là có thật nhưng category cạnh tranh.

### Observations

Phần lớn sản phẩm trong category cạnh tranh bằng “auto-save everywhere”, “one-click restore” và “local privacy”. Một solo project mới cần khác biệt bằng **permission minimization, explainable capture, sensitivity filtering và restore confidence** thay vì chỉ copy autosave.

### Assumptions

- User sẵn sàng opt-in vài website quan trọng thay vì cho extension quyền toàn bộ web.
- Long-form/internal-dashboard users coi privacy và restore accuracy quan trọng hơn convenience tuyệt đối.
- Local-only/no-account là lợi thế đủ mạnh cho personal/open-source adoption.

### Recommendation

Bắt đầu bằng **activeTab + one textarea + manual restore**. Chỉ khi vertical slice đáng tin mới nâng lên persistent per-origin permission và encrypted history.
