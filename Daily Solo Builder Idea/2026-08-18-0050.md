# Ý tưởng hôm nay: Dev Context Memory Vault

## 1. Tóm tắt ý tưởng

Một công cụ cá nhân giúp developer tự động lưu, tìm kiếm và tái sử dụng context khi làm việc với nhiều dự án, AI coding assistant và tài liệu kỹ thuật. Người dùng lưu quyết định kiến trúc, lỗi đã xử lý, command, snippet, prompt và bài học; hệ thống giúp truy xuất đúng thông tin khi cần.

- Đối tượng: developer làm nhiều dự án hoặc dùng AI hỗ trợ coding.
- Quy mô: Medium.
- MVP: 2–4 tuần.

## 2. Bài toán thực tế

Developer thường mất thời gian tìm lại:
- Vì sao một quyết định kỹ thuật được đưa ra.
- Cách xử lý một bug từng gặp.
- Cấu hình môi trường, command, workaround.
- Context cần cung cấp lại cho AI assistant.

Hiện nay nhiều người dùng bookmark, file markdown, chat history hoặc note cá nhân. Các cách này dễ phân tán và khó tìm kiếm. Đây là nhận định dựa trên thói quen làm việc phổ biến, cần xác thực thêm với người dùng thực tế.

## 3. Người dùng mục tiêu

Primary user:
- Senior developer, tech lead hoặc solo builder.
- Làm nhiều repository cùng lúc.
- Sử dụng ChatGPT, Copilot, Cursor hoặc Claude Code.

Pain point: mất context sau vài ngày hoặc vài tuần quay lại dự án.

## 4. Giải pháp đề xuất

Ứng dụng cung cấp một "bộ nhớ kỹ thuật cá nhân":

Workflow:
1. Developer ghi lại một knowledge item.
2. Gắn project, technology, loại thông tin.
3. Hệ thống index nội dung.
4. Khi cần, tìm kiếm theo vấn đề hoặc project.
5. Xuất context package để đưa vào AI assistant.

Ví dụ: Khi quay lại dự án Exchange integration sau 1 tháng, developer tìm "Graph Calendar permission issue" và nhận lại các lỗi, giải pháp, code sample, decision log trước đây.

Điểm khác biệt: tập trung vào engineering context thay vì note thông thường.

## 5. Tại sao ý tưởng này đáng làm

Giá trị:
- Hữu ích ngay cho chính developer tạo ra nó.
- Học được search, indexing, knowledge management.
- Có thể mở rộng thành developer productivity tool.

Phù hợp solo developer vì MVP chỉ cần một ứng dụng cá nhân.

Có thể thất bại nếu người dùng không có thói quen lưu context. Lý do mạnh nhất để không xây dựng: các AI assistant ngày càng có memory tích hợp.

## 6. Phạm vi MVP

### Must have
- CRUD knowledge item.
- Tag project, technology, category.
- Full text search.
- Markdown editor.
- Export context bundle.

### Should have
- Git repository integration.
- Import markdown.
- Browser extension capture.
- AI summary.

### Later
- Team sharing.
- Knowledge graph.
- Enterprise version.

## 7. Luồng hoạt động

User tạo knowledge item
→ validate metadata
→ lưu database
→ index search
→ tìm kiếm khi cần
→ tạo context package
→ copy sang AI tool hoặc IDE.

Failure cases:
- Duplicate knowledge: hỗ trợ merge sau.
- Search không chính xác: cải thiện ranking.
- AI unavailable: vẫn hoạt động với search thường.

## 8. Kiến trúc đề xuất

Modular monolith:

- Frontend: Vue/React.
- Backend: ASP.NET Core API.
- Database: PostgreSQL.
- Search: PostgreSQL Full Text Search trước, Elasticsearch/OpenSearch sau nếu cần.
- Background worker: xử lý indexing.
- Storage: local filesystem hoặc Azure Blob nếu có file đính kèm.
- Authentication: local account cho MVP.

Không cần microservice.

## 9. Công nghệ đề xuất

- .NET 10 + ASP.NET Core: phù hợp backend và kinh nghiệm cá nhân.
- EF Core: quản lý dữ liệu nhanh.
- PostgreSQL: tốt cho full text search ban đầu.
- Vue: phù hợp nếu muốn frontend nhẹ.
- Docker: dễ deploy local/VPS.
- GitHub Actions: build/test tự động.

Đơn giản hơn: SQLite + Blazor Server cho bản cá nhân.

## 10. Thiết kế dữ liệu ban đầu

KnowledgeItem:
- Id
- Title
- ContentMarkdown
- Category
- CreatedAt
- UpdatedAt

Project:
- Id
- Name
- RepositoryUrl

Tag:
- Id
- Name

Relationship:
Project 1-n KnowledgeItem.
KnowledgeItem n-n Tag.

Giữ lịch sử thay đổi nếu muốn phục hồi context.

## 11. API và tích hợp

- GitHub API: lấy repository metadata. Cần token nếu truy cập private repo.
- OpenAI API hoặc model khác: tạo summary/context extraction. Chi phí cần kiểm soát.
- File system: import markdown.

Fallback: hệ thống vẫn dùng được hoàn toàn offline.

## 12. AI có thực sự cần thiết không?

AI hữu ích nhưng optional.

Task:
- Tóm tắt knowledge dài.
- Trích xuất technology, lỗi, solution.
- Tạo context prompt.

Validation:
- Người dùng duyệt trước khi lưu.
- Không cho AI tự thay đổi dữ liệu gốc.

Rủi ro: chi phí, hallucination, dữ liệu nhạy cảm.

## 13. Kế hoạch triển khai

Task:

### Phase 3 — Expansion

## 14. Các bài toán kỹ thuật đáng học

1. Search ranking: học information retrieval.
2. Knowledge synchronization: xử lý dữ liệu thay đổi.
3. AI structured extraction: kiểm soát output model.
4. Data privacy: bảo vệ source code và tài liệu.
5. Backup/versioning: quản lý lịch sử kiến thức.

## 15. Rủi ro và cách xử lý

- Scope creep: giới hạn MVP là personal tool.
- Dữ liệu nhạy cảm: hỗ trợ self-hosted.
- Không nhập dữ liệu: tạo CLI capture nhanh.
- AI cost: chỉ gọi khi người dùng yêu cầu.

## 16. Kiểm thử

Năm scenario quan trọng:
1. Tạo và tìm knowledge item.
2. Import markdown lớn.
3. Search không có kết quả.
4. Backup/restore dữ liệu.
5. AI trả output sai format.

## 17. Cách đo dự án có hữu ích

Metrics:
- Số knowledge item được tạo.
- Thời gian tìm lại thông tin.
- Số lần sử dụng context export.
- Tỷ lệ quay lại hàng tuần.
- Search success rate.

## 20. Việc cần làm ngay hôm nay

Mục tiêu 90 phút: tạo vertical slice lưu và tìm knowledge.

Steps:

1. Tạo solution:
```
dotnet new webapi -n ContextVault.Api
```

2. Tạo entity:
- KnowledgeItem.

3. Setup EF Core + PostgreSQL.

4. Tạo API:
- POST /knowledge
- GET /knowledge/search?q=

5. Tạo UI đơn giản nhập markdown và search.

Kết quả mong đợi:
- Có thể lưu một note kỹ thuật.
- Tìm lại bằng keyword.

Verification:
- Restart app không mất dữ liệu.
- Search trả đúng item.

Stop condition:
Không thêm AI, Git integration hoặc UI đẹp trước khi workflow cơ bản hoạt động.
