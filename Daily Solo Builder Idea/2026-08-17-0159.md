# Ý tưởng hôm nay: Prompt Firewall — Local Data-Loss Guard cho AI Coding Tools

## 1. Tóm tắt ý tưởng

**Prompt Firewall** là một local/self-hosted guard giúp developer kiểm tra prompt, code snippet, log, stack trace hoặc file context trước khi gửi sang AI coding tools. Công cụ phát hiện secrets, PII và dữ liệu nhạy cảm, hiển thị risk report, cho phép redact/mask có kiểm soát và chỉ chuyển phần nội dung đã được người dùng phê duyệt.

- **Project size:** Medium
- **Estimated MVP time:** 2–4 tuần làm ngoài giờ
- **Người dùng chính:** developer dùng ChatGPT, Codex, Claude Code, Cursor, Copilot hoặc AI API trong công việc có code/log/config nhạy cảm.
- **Bài toán chính:** developer thường copy context thật để AI hiểu vấn đề, nhưng context đó có thể vô tình chứa API key, connection string, email, token, tenant ID, customer data hoặc internal identifiers.

## 2. Bài toán thực tế

### Confirmed facts

OWASP GenAI Security Project liệt kê **Sensitive Information Disclosure** là một rủi ro quan trọng của ứng dụng LLM. Tài liệu mô tả dữ liệu nhạy cảm có thể bao gồm PII, financial details, credentials, proprietary business data và source code; một mitigation được nêu là sanitization trước khi dữ liệu đi vào model.

Nguồn: [OWASP — LLM02:2025 Sensitive Information Disclosure](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/)

Gitleaks là một secret scanner open-source có thể scan git repository, directory/file và cả dữ liệu qua `stdin`, phù hợp để tận dụng như deterministic detector cho API keys, passwords và tokens thay vì tự viết hàng trăm regex từ đầu.

Nguồn: [Gitleaks](https://github.com/gitleaks/gitleaks)

Microsoft Presidio cung cấp `presidio-analyzer` để phát hiện PII trong text bằng recognizers/regex/NER và `presidio-anonymizer` để replace, redact, hash, mask hoặc encrypt entity đã phát hiện. Presidio cũng có thể chạy dưới dạng HTTP service hoặc container local.

Nguồn:

- [Presidio Analyzer](https://microsoft.github.io/presidio/analyzer/)
- [Presidio Anonymizer](https://microsoft.github.io/presidio/anonymizer/)

### Observation

Secret scanners thường tối ưu cho source control/CI, trong khi PII tooling thường là library/service. Khoảng trống thực dụng cho developer là một **pre-send inspection layer** có UX rõ ràng ngay trước khi dữ liệu được đưa vào AI.

### Bài toán cụ thể

Developer thường làm các việc sau:

- copy exception log vào AI để debug;
- paste `appsettings.json` hoặc environment variables;
- gửi HTTP request/response thực tế;
- paste SQL query kèm customer identifiers;
- gửi email payload hoặc Microsoft Graph object;
- đưa file code có hardcoded test secret;
- copy terminal output gồm signed URL hoặc token;
- attach diagnostic file cho coding agent.

Việc review thủ công trước khi paste có ba vấn đề:

1. secret có thể nằm giữa log dài hàng nghìn dòng;
2. developer khó nhớ tất cả pattern của credentials/PII;
3. redaction thủ công làm mất thời gian và dễ làm hỏng context cần thiết để AI phân tích.

### Assumption cần validation

MVP giả định developer sẵn sàng thêm một bước `scan → review → redact → copy/send` nếu thao tác mất dưới vài giây và false-positive đủ thấp. Cần validation với 5–10 developer thường xuyên dùng AI coding assistant.

## 3. Người dùng mục tiêu

### Primary user

Backend/full-stack developer dùng AI để debug hoặc review code của hệ thống thật.

### Context of use

- làm việc với production/staging logs;
- config có secrets;
- dữ liệu user/customer;
- internal API payload;
- AI coding assistant được dùng hàng ngày.

### Main pain point

Developer muốn cung cấp đủ context cho AI nhưng không muốn phải đọc thủ công từng dòng để chắc chắn không gửi nhầm credential hoặc dữ liệu cá nhân.

### Current workaround

- tự search `password`, `token`, `secret`;
- replace tên/email bằng tay;
- tạo sample data giả;
- tránh paste context quan trọng;
- chỉ dùng AI cho code ít nhạy cảm;
- chạy secret scanner riêng nhưng không có redaction workflow.

### Lý do họ sẽ thử

Tool có thể chạy hoàn toàn local, không cần gửi raw content lên server riêng, và có thể bắt đầu bằng một CLI rất nhỏ:

```bash
cat error.log | prompt-firewall scan
```

## 4. Giải pháp đề xuất

Prompt Firewall đóng vai trò như một **local privacy/security boundary** trước AI.

### Main workflow

```text
Raw prompt / file / clipboard
        ↓
Normalize input
        ↓
Secret detector
        ↓
PII detector
        ↓
Custom organization rules
        ↓
Merge + de-duplicate findings
        ↓
Risk score
        ↓
Preview highlighted findings
        ↓
User chooses redact / keep / block
        ↓
Generate sanitized content
        ↓
Copy / forward to configured AI endpoint
```

### Input

MVP hỗ trợ:

- plain text;
- stdin;
- text file;
- clipboard text;
- JSON/log/config text.

### Processing

1. Kiểm tra kích thước và loại input.
2. Chạy deterministic secret detection.
3. Chạy PII analysis local.
4. Áp dụng custom regex/domain rules.
5. Chuẩn hóa findings thành common model.
6. Resolve overlap giữa detectors.
7. Tính severity/risk score.
8. Tạo sanitized preview.

### Output

- số findings theo severity;
- category: `SECRET`, `PII`, `INTERNAL_DATA`;
- vị trí line/offset;
- detector/rule tạo finding;
- confidence nếu detector hỗ trợ;
- recommended action;
- sanitized text.

### Automated

- detection;
- masking/redaction;
- deterministic policy;
- safe placeholder generation;
- audit summary không chứa raw secret.

### User control

User quyết định:

- finding nào được giữ nguyên;
- category nào auto-block;
- placeholder strategy;
- có lưu history hay không;
- có forward trực tiếp tới AI endpoint hay chỉ copy sanitized result.

### Key differentiator

Không phải một secret scanner mới và cũng không phải một AI chat client mới. Điểm khác biệt là **developer-oriented pre-send firewall** kết hợp secret + PII + custom rule + reversible context-preserving redaction.

### Concrete example

Developer có log:

```text
POST /api/orders failed
Authorization: Bearer eyJhbGciOi...
CustomerEmail: ha@example.com
Tenant: niteco-prod
ConnectionString=Server=prod-db;User Id=admin;Password=P@ssw0rd;
Exception: TimeoutException at OrderService.cs:182
```

Prompt Firewall phát hiện:

- Bearer token → `CRITICAL`;
- email → `MEDIUM`;
- connection string/password → `CRITICAL`;
- `niteco-prod` → custom internal identifier `LOW/MEDIUM`.

Sanitized output:

```text
POST /api/orders failed
Authorization: Bearer <SECRET_1>
CustomerEmail: <EMAIL_1>
Tenant: <INTERNAL_ENV_1>
ConnectionString=<CONNECTION_STRING_1>
Exception: TimeoutException at OrderService.cs:182
```

Stack trace và business context vẫn còn nguyên, trong khi sensitive values được loại bỏ.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Tool bảo vệ đúng workflow developer đang thực hiện thường xuyên: chia sẻ context cho AI. Giá trị có thể xuất hiện ngay với một user duy nhất, không cần network effect.

### Technical learning value

Dự án có nhiều bài toán thực tế:

- process orchestration;
- streaming input;
- text span merging;
- PII detection;
- secret scanning;
- configurable policy engine;
- privacy-preserving audit log;
- local proxy/API gateway;
- CLI UX;
- extension/plugin integration.

### Suitable for solo developer

Các detector cốt lõi đã có tooling mature. Người build tập trung vào orchestration, policy, UX và integration thay vì training model.

### Vẫn hữu ích với rất ít users

Đây có thể là personal CLI dùng hàng ngày trước khi copy logs/config sang AI.

### What would make it fail

- quá nhiều false positives;
- scan chậm;
- setup Presidio quá nặng cho use case đơn giản;
- developer bỏ qua tool vì thêm friction;
- redaction phá vỡ context khiến AI trả lời kém.

### Strongest reason not to build

Nếu validation cho thấy developer chỉ cần scan secrets trong repo và không quan tâm pre-send PII/redaction, Gitleaks + policy hiện có đã đủ và không nên xây thêm sản phẩm.

## 7. Luồng hoạt động

### Happy path

```text
User executes prompt-firewall sanitize error.log
        ↓
Validate file + size
        ↓
Read text locally
        ↓
Run secret detector
        ↓
Run PII detector
        ↓
Run custom policies
        ↓
Normalize findings
        ↓
Resolve overlapping spans
        ↓
Render review summary
        ↓
Apply redaction
        ↓
Write sanitized text to stdout/file/clipboard
```

### Alternative flow — detector unavailable

Nếu Presidio container down:

- secret scan vẫn chạy;
- kết quả đánh dấu `partial_scan=true`;
- exit code riêng cho degraded mode;
- user có thể policy `fail-closed` hoặc `fail-open`.

### False positive

User chọn `allow once` hoặc thêm fingerprint vào allowlist.

### Large log file

- hard size limit;
- streaming/chunking;
- overlap window giữa chunks để tránh entity bị cắt đôi.

### Binary/non-text input

Reject trong MVP với message rõ ràng.

### Detector timeout

Cancellation timeout; không silently xem input là safe.

**Không cần trong core MVP.** Config + allowlist có thể là file local.

Nếu cần audit/history sau này mới thêm SQLite.

### Background worker

Không cần.

### Scheduler

Không cần.

### Queue

Không cần.

### Cache

Optional in-memory cache cho detector health/config; không cần distributed cache.

Không lưu raw prompts mặc định. Sanitized output chỉ lưu khi user chỉ định path.

Không cần cho detection core.

## 11. API và tích hợp

### Gitleaks

**Purpose:** secret detection.

**Authentication:** none local.

**Cost/rate limit:** none; compute local.

**Privacy:** input không rời host nếu binary/container local.

**Fallback:** built-in minimal secret rules nếu executable unavailable.

### Presidio Analyzer

**Purpose:** PII detection.

**Authentication:** local container không cần; network exposure phải bảo vệ.

**Cost:** local compute; NLP model tăng memory footprint.

**Privacy:** chạy local để không gửi PII cho third party.

**Fallback:** regex recognizers cho email, phone, IP, credit-card-like patterns; kết quả phải ghi rõ reduced coverage.

### Presidio Anonymizer

Có thể dùng trực tiếp hoặc tự sanitize ở .NET dựa trên normalized spans. MVP nên tự sanitize ở core để một engine kiểm soát overlap và placeholder consistency.

### Clipboard

OS-specific clipboard library hoặc command adapter.

**Privacy concern:** clipboard vốn có risk; chỉ copy sanitized output theo explicit command.

### Future OpenAI-compatible proxy

Có thể expose local endpoint tương thích request format của một số AI clients và inspect request trước khi forward. Đây là future scope, không MVP vì auth/TLS/streaming/compatibility sẽ làm dự án phình nhanh.

## 12. AI có thực sự cần thiết không?

**AI is not necessary** cho MVP.

Detection security-sensitive cần ưu tiên deterministic rules, known secret patterns, checksums, recognizers và explainable confidence.

### Vì sao không dùng LLM để scan

- gửi raw sensitive content tới model để hỏi “có sensitive không?” phá vỡ mục tiêu privacy;
- non-deterministic;
- hallucination/false negative khó chấp nhận;
- tăng latency/cost;
- khó audit.

### AI có thể dùng sau này ở đâu

Chỉ sau khi deterministic sanitizer đã chạy, AI local có thể giúp classify **sanitized business sensitivity**, ví dụ internal project name hoặc proprietary feature description. Nhưng đây là speculative extension và không phải core.

## 14. Các bài toán kỹ thuật đáng học

### 1. Text span reconciliation

Gitleaks, Presidio và custom detector có thể trả findings overlap nhau.

Ví dụ một connection string vừa chứa password vừa bị nhận diện như generic secret.

Cần algorithm:

- sort spans;
- severity precedence;
- merge compatible findings;
- preserve strongest finding;
- tránh replace offset sai sau lần redaction đầu tiên.

**Skill:** interval algorithms, immutable transformations.

### 2. Privacy-preserving logging

Tool security có thể tự trở thành source leak nếu log raw input.

**Skill:** secure observability, structured logging, threat modeling.

### 3. Process isolation

Gọi Gitleaks CLI cần:

- no shell interpolation;
- stdin piping;
- cancellation;
- timeout;
- stderr capture;
- version pinning;
- exit code interpretation.

**Skill:** robust process orchestration.

### 4. Policy engine

Không phải mọi PII đều cần block. Email test có thể được giữ; production token phải block.

**Skill:** configurable rules, precedence, explainability.

### 5. Local integration boundary

Local HTTP API/plugin cần tiện nhưng không tạo cửa vào cho process/webpage khác đọc sanitized/raw data.

**Skill:** localhost security, origin/token controls, least privilege.

## 15. Rủi ro và cách xử lý

### False negatives

**Risk:** nguy hiểm nhất; developer tưởng content an toàn.

**Mitigation:** luôn nói rõ tool “reduces risk, does not guarantee safety”; combine detectors; strict rules cho high-value credential classes; regression corpus.

### False positives

**Risk:** quá nhiều warning khiến user ignore tool.

**Mitigation:** fingerprint allowlist, confidence threshold, category policy và easy one-time override.

### Sensitive data trong logs của chính tool

**Mitigation:** raw input never logged; redact exception context; telemetry off mặc định.

### Presidio resource footprint

**Risk:** NLP container nặng cho máy developer.

**Mitigation:** PII engine optional; fast regex-only profile; lazy start; document memory usage.

### External detector dependency

**Risk:** Gitleaks/Presidio behavior thay đổi.

**Mitigation:** pin versions, adapter contract tests, explicit compatibility matrix.

### Scope expansion

**Risk:** biến thành enterprise DLP gateway.

**Mitigation:** MVP chỉ local developer workflow; không build admin dashboard/SSO/cloud proxy.

### Security of local API

**Risk:** malicious webpage/process gọi endpoint.

**Mitigation:** loopback only, random session token, request size limit, optional disable HTTP entirely.

### Legal/compliance

Không quảng cáo tool như compliance guarantee. Đây là developer safety layer, không thay thế organization data governance/DLP policy.

### Maintenance burden

Rules phải được cập nhật theo credential formats mới.

**Mitigation:** reuse established detectors; custom rule packs versioned riêng.

- code identifiers dễ false-positive;
- mixed English/Vietnamese text.

### 5 test scenarios quan trọng nhất

1. Log chứa Bearer token + email + stack trace → token/email redact, stack trace giữ nguyên.
2. Connection string có password tạo overlapping findings → output không bị corrupt.
3. Presidio down trong `fail-closed` → command không báo safe/success.
4. Known false positive đã allowlist → không block nhưng report giải thích exemption.
5. Input chứa malicious filename/shell chars → không dẫn đến command injection khi gọi detector.

### First supported rules

Chỉ implement 3 rule dễ test:

1. email address;
2. `password=...` / `Password: ...` style value;
3. `Authorization: Bearer ...`.

### Finding model

```csharp
public sealed record Finding(
    string RuleId,
    string Category,
    string Severity,
    int Start,
    int Length,
    string Placeholder);
```

### Important implementation rule

Không replace text từ đầu đến cuối vì offset sẽ thay đổi. Sort findings theo `Start` descending rồi replace từ cuối chuỗi về đầu, hoặc build output immutable từ spans.

### Sample input

```text
Customer email: ha@example.com
Authorization: Bearer abc.def.ghi
Password=P@ssw0rd123
TimeoutException at EmployeeService.cs:88
```

### Expected output

```text
Customer email: <EMAIL_1>
Authorization: Bearer <SECRET_1>
Password=<SECRET_2>
TimeoutException at EmployeeService.cs:88
```

CLI summary:

```text
3 sensitive findings
CRITICAL  bearer-token   line 2
CRITICAL  password       line 3
MEDIUM    email          line 1
Sanitized: samples/unsafe-log.sanitized.txt
```

### Verification checklist

- [ ] `dotnet build` pass.
- [ ] Có ít nhất 3 detector rules.
- [ ] Findings chứa chính xác offsets.
- [ ] Multiple replacements không corrupt text.
- [ ] Raw sensitive values không xuất hiện trong application logs.
- [ ] Unit test verify sanitized output chính xác.
- [ ] Input không có finding trả exit code success và output unchanged.
- [ ] Có test overlapping spans dù prototype detector chưa sinh overlap thực tế.

### Stop condition

Dừng session khi command sau chạy được end-to-end:

```bash
dotnet run --project src/PromptFirewall.Cli -- sanitize samples/unsafe-log.txt
```

và tạo file sanitized có ba giá trị nhạy cảm đã được thay thế nhưng stack trace/context còn nguyên.

## Final assessment

**Prompt Firewall đáng build nếu mục tiêu là một local-first developer workflow tool, không phải enterprise DLP platform.** MVP có thể nhỏ vì detector engine được tái sử dụng, nhưng vẫn chứa nhiều engineering challenge đủ sâu: span reconciliation, secure process execution, configurable policy, privacy-safe logging và localhost integration.

Điểm quyết định là UX: nếu developer có thể sanitize context trong vài giây mà vẫn giữ đủ thông tin để AI debug tốt, tool có giá trị sử dụng hàng ngày. Nếu scan gây nhiều false positives hoặc thêm quá nhiều bước, user sẽ bỏ qua bất kể detector tốt đến đâu.
