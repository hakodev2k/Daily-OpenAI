# Ý tưởng hôm nay: Bug Capsule — Browser Trace Recorder cho QA và Developer

## 1. Tóm tắt ý tưởng

**Bug Capsule** là một browser extension + web dashboard giúp QA, developer hoặc product team ghi lại một lỗi web thành một “capsule” có đầy đủ bằng chứng kỹ thuật: screenshot, URL, viewport, browser version, user steps, console errors, network metadata và các request thất bại trong khoảng thời gian xảy ra lỗi. Thay vì gửi một ticket kiểu “em bấm nút Save thì lỗi”, người báo bug có thể gửi một artifact gần giống mini trace để developer hiểu và tái hiện nhanh hơn.

- **Project size:** Medium
- **Estimated MVP time:** 2–4 tuần làm ngoài giờ
- **Primary user:** QA hoặc developer kiểm thử web application
- **Core problem:** thông tin tái hiện bug thường thiếu, phân tán và mất nhiều vòng hỏi lại

## 2. Bài toán thực tế

### Confirmed facts

Chrome Extension API hiện cung cấp `chrome.debugger`, cho phép extension attach vào tab và dùng Chrome DevTools Protocol để quan sát các domain như `Network`, `Runtime`, `Console`, `Log`, `DOM`, `Page`, `Performance` và nhiều domain khác. Extension phải khai báo quyền `debugger`, và đây là quyền mạnh nên phải xử lý privacy/security rất cẩn thận.

Nguồn: [Chrome Developers — chrome.debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger)

Chrome cũng cung cấp `chrome.tabs.captureVisibleTab()` để chụp phần hiển thị hiện tại của tab. API này yêu cầu `activeTab` hoặc host permission phù hợp và Chrome giới hạn số lần capture vì đây là operation tương đối nặng.

Nguồn: [Chrome Developers — chrome.tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs)

Playwright Trace Viewer cho thấy một debugging trace hữu ích thường gồm nhiều chiều dữ liệu chứ không chỉ screenshot: action timeline, DOM snapshots, console logs, network requests, metadata và screenshot. Đây là bằng chứng kỹ thuật rõ ràng rằng “timeline + environment + network + console” giúp phân tích lỗi tốt hơn một ảnh đơn lẻ.

Nguồn: [Playwright — Trace Viewer](https://playwright.dev/docs/trace-viewer)

### Observation

Bug report trong nhiều team vẫn được tạo từ các mảnh thông tin riêng lẻ:

- screenshot chụp sau khi lỗi xảy ra;
- mô tả bước tái hiện viết thủ công;
- console log copy từ DevTools;
- network request được gửi riêng;
- browser/version hỏi bổ sung sau;
- developer thử tái hiện lại bằng một account hoặc dữ liệu khác.

Vấn đề không phải thiếu công cụ debug, mà là **người gặp bug và developer thường không thu thập cùng một bộ evidence tại đúng thời điểm lỗi xảy ra**.

### Existing solutions

Thị trường đã có nhiều tool bug capture/browser recording. Điều đó xác nhận đây là một category thật, nhưng cũng có nghĩa Bug Capsule không nên cạnh tranh bằng việc “record màn hình đẹp hơn”. MVP cần tập trung vào một differentiator nhỏ nhưng thực dụng:

> **Local-first technical evidence bundle cho team nhỏ, có privacy redaction rõ ràng và có thể export thành artifact độc lập.**

### Assumptions cần validation

- QA/developer trong team nhỏ sẽ chấp nhận cài browser extension nếu nó giảm vòng hỏi lại khi triage bug.
- Họ cần technical evidence nhiều hơn video recording.
- Self-hosted/local-first có giá trị khi test ứng dụng nội bộ hoặc dữ liệu nhạy cảm.

Không giả định các điểm này là demand đã được chứng minh; cần validation trước khi mở rộng.

## 3. Người dùng mục tiêu

### Primary user

QA Engineer, developer hoặc technical tester trong team 3–20 người đang test web application nội bộ hoặc SaaS.

### Context of use

- test trên staging/UAT;
- thường tạo issue trên GitHub/Jira/Azure DevOps;
- gặp bug frontend/backend interaction khó mô tả;
- developer và QA không phải lúc nào cũng ngồi cùng nhau;
- lỗi có thể phụ thuộc browser state, account, request sequence hoặc API response.

### Main pain point

Sau khi nhận ticket, developer vẫn phải hỏi:

- URL nào?
- bấm gì trước đó?
- request nào fail?
- status code bao nhiêu?
- console có lỗi gì?
- browser/version gì?
- lỗi xảy ra trước hay sau response X?

### Current workaround

QA thường gửi screenshot/video + text steps, sau đó mở DevTools lại để tìm thêm thông tin nếu developer yêu cầu.

### Lý do họ sẽ thử Bug Capsule

Một thao tác **Start Capture → reproduce bug → Stop → Share Capsule** có thể thay thế nhiều bước thu thập thủ công.

## 4. Giải pháp đề xuất

Bug Capsule gồm browser extension capture evidence và dashboard để xem lại một session.

### Main workflow

1. QA mở trang cần test.
2. Click extension → `Start Capture`.
3. Extension attach debugger vào tab.
4. Trong lúc QA thao tác, extension ghi lại:
   - timestamp;
   - URL/navigation;
   - click/input step ở mức metadata;
   - console error/warning;
   - network request metadata;
   - failed request;
   - response status;
   - viewport/browser metadata.
5. QA gặp lỗi và click `Capture Bug`.
6. Extension chụp screenshot hiện tại.
7. QA nhập title + expected result + actual result.
8. Extension thực hiện redaction rule.
9. Capsule được lưu local hoặc upload vào self-hosted backend.
10. Developer mở dashboard và xem timeline từ vài giây/phút trước lỗi.

### Input

- active browser tab;
- user actions;
- browser console/network events;
- optional screenshot;
- short bug description.

### Processing

- event capture;
- normalize timeline;
- redact sensitive headers/fields;
- truncate oversized payloads;
- group duplicate console errors;
- detect failed/slow requests;
- persist capsule.

### Output

Một capsule gồm:

```text
Bug summary
Environment
Timeline
User actions
Screenshot
Console errors
Network failures
Selected request details
Exportable Markdown/JSON
```

### What is automated

- timestamp correlation;
- environment collection;
- console/network capture;
- grouping failed requests;
- screenshot metadata;
- Markdown report generation.

### What remains under user control

- thời điểm bắt đầu/dừng capture;
- field nào được phép lưu;
- request/response body có được capture hay không;
- redact rule;
- capsule có upload hay chỉ giữ local;
- bug summary và expected behavior.

### Key differentiator

**Không record toàn bộ browser một cách mặc định.** Tool chỉ thu thập evidence cần thiết, hỗ trợ strict allowlist/redaction và có thể export thành một artifact local để đính kèm vào issue.

### Example end-to-end

QA test màn Edit Employee.

1. Start Capture.
2. Mở employee `123`.
3. Thay `Office` từ Hanoi sang Stockholm.
4. Click Save.
5. UI hiện generic error.
6. Capture Bug.

Capsule cho thấy:

```text
10:31:12 GET /api/employees/123 -> 200
10:31:28 User clicked #save-button
10:31:28 PUT /api/employees/123 -> 400
10:31:28 ConsoleError: Failed to update employee
10:31:29 Screenshot captured
```

Developer mở request detail và thấy response sanitized:

```json
{
  "errorCode": "OFFICE_NOT_ALLOWED",
  "field": "officeId"
}
```

Developer có thể bắt đầu debug ngay mà không cần hỏi QA request nào fail.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Giảm thời gian triage và số vòng hỏi lại giữa QA ↔ developer.

### Technical learning value

Dự án buộc người làm học nhiều chủ đề rất thực tế:

- Chrome Extension Manifest V3;
- Chrome DevTools Protocol;
- browser permission model;
- event correlation;
- structured logging;
- sensitive-data redaction;
- file artifact format;
- Playwright E2E;
- self-hosted deployment.

### Suitable for a solo developer

MVP không cần screen recording/video encoding, AI, cloud infrastructure hoặc integration issue tracker. Extension + API + dashboard đơn giản là đủ.

### Useful even with one user

Một developer tự test side project vẫn có thể dùng Bug Capsule để ghi lại lỗi intermittent hoặc lưu evidence trước khi context biến mất.

### What would make it fail

- debugger permission khiến user không tin tưởng;
- capture quá nhiều dữ liệu gây privacy risk;
- report quá lớn và khó đọc;
- giá trị không hơn DevTools + screenshot đáng kể.

### Strongest reason not to build

Nếu validation cho thấy team đã dùng một bug-reporting product hiện tại và họ hài lòng, việc xây thêm extension mới có thể không đáng công. MVP chỉ nên tiếp tục nếu local-first/privacy/evidence workflow thực sự là gap.

## 6. Phạm vi MVP

### Must have

- Chrome extension Manifest V3.
- Start/Stop capture cho active tab.
- Capture URL + navigation timestamp.
- Capture console error/warning.
- Capture network request metadata:
  - method;
  - URL;
  - status;
  - duration;
  - resource type.
- Highlight HTTP 4xx/5xx và failed requests.
- Capture visible screenshot khi user nhấn `Capture Bug`.
- Browser + viewport metadata.
- User nhập title, expected, actual.
- Built-in redaction cho:
  - `Authorization`;
  - `Cookie`;
  - `Set-Cookie`;
  - token-like query params;
  - common password fields.
- Local capsule JSON.
- Export Markdown summary.
- Simple web viewer hoặc extension page để xem timeline.

### Should have

- User action timeline: click/input/navigation.
- Custom redaction patterns.
- Capture request/response body với explicit opt-in.
- ZIP export gồm JSON + screenshot + Markdown.
- Upload vào self-hosted backend.
- Expiration/retention policy.
- “Copy issue template” button.

### Later

- GitHub/Jira/Azure DevOps issue creation.
- Screen recording.
- Session replay.
- DOM snapshots.
- Generate Playwright test draft.
- AI-assisted bug summary.
- Team workspaces.
- SSO.
- OpenTelemetry correlation.

## 7. Luồng hoạt động

```text
User clicks Start Capture
        ↓
Validate active tab + permissions
        ↓
Attach chrome.debugger
        ↓
Enable Network / Runtime / Log domains
        ↓
Collect events in memory buffer
        ↓
User reproduces bug
        ↓
User clicks Capture Bug
        ↓
Capture screenshot + environment metadata
        ↓
Apply redaction rules
        ↓
Normalize timeline
        ↓
Persist local capsule
        ↓
Generate Markdown summary
        ↓
User reviews evidence
        ↓
Export / upload / attach to issue
```

### Alternative flow: debugger attach fails

- Show clear error.
- Fallback to screenshot + manually entered steps.
- Không giả vờ network/console đã được capture.

### Alternative flow: request body quá lớn

- Store size + content type + hash.
- Không lưu full payload.

### Alternative flow: sensitive domain

- Allow user/domain denylist.
- Extension auto-disables capture.

### Alternative flow: browser closes giữa session

- Flush rolling buffer vào `chrome.storage.session` hoặc IndexedDB theo interval nhỏ.
- Session chưa hoàn tất có status `Interrupted`.

## 9. Công nghệ đề xuất

### TypeScript + Chrome Extension Manifest V3

**Why it fits:** Chrome APIs là phần cốt lõi; TypeScript giúp quản lý event contracts tốt.

**Simpler alternative:** JavaScript thuần.

**Outgrow:** khi cần cross-browser thì trừu tượng hóa adapter cho Firefox/Edge.

### chrome.debugger + Chrome DevTools Protocol

Chrome xác nhận API này có thể instrument network, debug JavaScript và truy cập các domain như Network, Runtime, Log, DOM, Page và Performance.

Nguồn: [Chrome Developers — chrome.debugger](https://developer.chrome.com/docs/extensions/reference/api/debugger)

**Why it fits:** không cần inject monkey-patch vào `fetch`/XHR của ứng dụng.

**Simpler alternative:** content script intercept console + monkey-patch fetch, nhưng kém đầy đủ và dễ ảnh hưởng trang.

### chrome.tabs.captureVisibleTab

Chrome cung cấp API chụp visible region của active tab, phù hợp với one-shot screenshot khi tạo bug capsule.

Nguồn: [Chrome Developers — chrome.tabs](https://developer.chrome.com/docs/extensions/reference/api/tabs)

### chrome.storage / IndexedDB

`chrome.storage` phù hợp với settings/small metadata nhưng có quota; Chrome hiện mô tả `storage.local` có giới hạn mặc định khoảng 10 MB. Capsule lớn nên dùng IndexedDB hoặc export file thay vì nhét toàn bộ ảnh/body vào storage API.

Nguồn: [Chrome Developers — chrome.storage](https://developer.chrome.com/docs/extensions/reference/api/storage)

### ASP.NET Core 10 — optional backend

Dùng khi cần sharing/team mode.

**Why it fits:** phù hợp skill backend hiện có, dễ host Docker và build API nhanh.

**Simpler alternative:** không có backend, chỉ export ZIP.

### PostgreSQL — optional backend

Chỉ lưu metadata, không lưu screenshot binary trực tiếp nếu artifact tăng nhanh.

### Vue 3

Phù hợp cho viewer/dashboard timeline.

### Playwright

Dùng để E2E extension/viewer và test artifact workflow. Playwright Trace Viewer cũng là reference tốt cho UX timeline vì nó kết hợp action, screenshot, console và network trong cùng một trace.

Nguồn: [Playwright — Trace Viewer](https://playwright.dev/docs/trace-viewer)

### Docker Compose

Chỉ cần khi backend được thêm.

## 11. API và tích hợp

### Chrome Extension APIs

**Purpose:** tab capture, debugger attach, local storage.

**Authentication:** không cần external auth.

**Cost:** không có API billing.

**Permissions/privacy:** đây là concern lớn nhất; `debugger` permission rất mạnh và user phải hiểu extension đang thu thập gì.

**Fallback:** screenshot + manual report nếu debugger permission không được cấp.

### Chrome DevTools Protocol

**Purpose:** Network/Runtime/Log events.

**Authentication:** không cần khi dùng qua `chrome.debugger` trên tab user cho phép.

**Privacy:** network metadata có thể chứa PII/token; redaction phải chạy trước persistence.

### GitHub Issues — later

Có thể export Markdown trước; direct integration chỉ thêm khi MVP đã chứng minh giá trị.

**Fallback:** copy Markdown vào clipboard.

### Jira/Azure DevOps — later

Không nằm trong MVP để tránh OAuth/config complexity.

### Playwright — testing only

Không cần nhúng Playwright vào extension runtime. Dùng làm E2E/test framework và có thể sinh test draft ở phase sau.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

MVP không cần AI.

### Exact AI task — later

AI có thể nhận structured capsule đã sanitize để:

- viết bug summary;
- nhóm probable symptoms;
- đề xuất missing reproduction step;
- tạo draft Playwright test.

### Required context

Chỉ gửi:

- timeline event;
- sanitized console error;
- sanitized network failure;
- expected/actual result.

Không gửi raw cookie/token/request body mặc định.

### Expected structured output

```json
{
  "summary": "string",
  "likelyFailurePoint": "string|null",
  "reproductionSteps": ["string"],
  "suggestedChecks": ["string"],
  "confidence": 0.0
}
```

### Validation

- JSON Schema;
- AI output luôn hiển thị dưới label `AI analysis`;
- không được thay đổi raw evidence;
- user phải verify trước khi tạo issue.

### Deterministic fallback

Template:

```text
{N} failed network requests
{M} console errors
Last failed request: {method} {url} -> {status}
```

### Risks

- hallucination;
- gửi dữ liệu nhạy cảm ra ngoài;
- latency/cost;
- AI có thể suy đoán root cause sai.

Do đó AI không nằm trong core MVP.

## 14. Các bài toán kỹ thuật đáng học

### 1. Browser permission boundaries

`chrome.debugger` là quyền mạnh. Thiết kế “capture only after explicit Start” là bắt buộc về UX và security.

**Skill:** browser security, permission design, least privilege.

### 2. Event correlation

Network, console và user actions là các event stream khác nhau. Phải normalize timestamp và kết hợp thành timeline có ý nghĩa.

**Skill:** event modeling, distributed-style timeline reasoning ở phạm vi browser.

### 3. Privacy-preserving capture

Bug artifact có thể chứa JWT, cookie, email, employee data hoặc request body nhạy cảm.

**Skill:** redaction pipeline, secret detection, privacy by design.

### 4. Bounded storage

Network traffic có thể tăng cực nhanh.

**Skill:** ring buffer, truncation, retention, content hashing, artifact sizing.

### 5. Extension lifecycle

Manifest V3 service worker có lifecycle khác app web thông thường.

**Skill:** browser background execution, state recovery, durable extension storage.

## 15. Rủi ro và cách xử lý

### Technical complexity

**Risk:** DevTools Protocol event model khá lớn.

**Mitigation:** MVP chỉ enable `Network`, `Runtime`, `Log`, `Page`; không làm full DevTools clone.

### Scope expansion

**Risk:** biến thành session-replay platform.

**Mitigation:** không video, không full DOM replay, không analytics ở MVP.

### Data privacy

**Risk:** capture token/PII.

**Mitigation:** redact trước persistence; denylist headers mặc định; body capture opt-in; domain rules.

### Security

**Risk:** malicious exported capsule hoặc dashboard render untrusted HTML.

**Mitigation:** JSON encode, strict CSP, never render response body as raw HTML, sanitize Markdown.

### Browser API dependency

**Risk:** Chrome permission/API behavior thay đổi.

**Mitigation:** abstraction layer `IBrowserCaptureAdapter`, pin minimum Chrome version, integration test với current stable.

### Cost

Local MVP gần như chỉ có development cost.

Backend phase sau cần object storage nhưng capsule có thể enforce size cap.

### Legal/platform restrictions

Không capture website ngoài phạm vi user có quyền test. Chrome Store distribution có thể yêu cầu giải thích rõ permission/data handling.

### User adoption

**Risk:** QA thấy setup extension phiền.

**Mitigation:** một click start, zero project integration, export local trước.

### Maintenance burden

**Risk:** Chrome/CDP evolve.

**Mitigation:** giữ subset domain nhỏ, contract tests trên fixtures.

## 16. Kiểm thử

### Unit tests

- URL sanitizer;
- header redaction;
- query parameter redaction;
- timeline ordering;
- payload truncation;
- capsule schema serialization.

### Integration tests

- fake page tạo console error;
- fake API trả 500;
- extension capture event;
- interrupted session recovery.

### End-to-end tests

Playwright launch Chromium với extension trong development mode, thực hiện flow và verify exported capsule.

### Failure-path tests

- debugger attach denied;
- tab đóng giữa capture;
- page reload;
- 10 MB response body;
- service worker restart.

### Security tests

- Authorization header;
- Cookie;
- access_token query param;
- password input;
- XSS payload trong response body.

### 5 test scenarios quan trọng nhất

1. **API 500:** request 500 phải xuất hiện đúng timestamp/status trong capsule.
2. **Secret redaction:** JWT trong Authorization và cookie tuyệt đối không xuất hiện trong export.
3. **Reload giữa capture:** session vẫn tiếp tục hoặc kết thúc có trạng thái rõ ràng, không corrupt artifact.
4. **Large payload:** body lớn bị truncate/omit nhưng metadata vẫn giữ.
5. **XSS evidence:** response chứa `<script>` không được execute khi mở viewer.

### First vertical slice behavior

Popup có 2 nút:

```text
Start Capture
Stop Capture
```

`Start Capture`:

1. get active tab;
2. `chrome.debugger.attach({ tabId }, "1.3")`;
3. enable:
   - `Network.enable`;
   - `Runtime.enable`;
   - `Log.enable`;
4. listen `chrome.debugger.onEvent`;
5. giữ event trong memory array.

Chỉ lưu các event sau:

```text
Network.responseReceived where status >= 400
Network.loadingFailed
Runtime.consoleAPICalled for error/warning
Log.entryAdded for error/warning
```

`Stop Capture`:

- detach debugger;
- show event list JSON trong popup hoặc simple page.

### Sample expected result

Mở một local page có JavaScript:

```js
console.error("Demo checkout failure");
fetch("https://httpstat.us/500");
```

Extension viewer phải hiển thị đại loại:

```json
[
  {
    "type": "console",
    "level": "error",
    "message": "Demo checkout failure"
  },
  {
    "type": "network",
    "method": "GET",
    "url": "https://httpstat.us/500",
    "status": 500
  }
]
```

### Verification checklist

- [ ] Extension load được bằng `Load unpacked`.
- [ ] Start Capture attach đúng active tab.
- [ ] HTTP 500 xuất hiện trong event list.
- [ ] `console.error()` xuất hiện trong event list.
- [ ] Stop Capture detach debugger.
- [ ] Không lưu request/response body.
- [ ] Không lưu `Authorization`/Cookie trong session đầu.
- [ ] Reload tab không làm extension crash.
- [ ] Có unit test đầu tiên cho sanitizer interface dù logic còn tối thiểu.

### Stop condition

Dừng coding session ngay khi có thể:

```text
open page
→ start capture
→ trigger console error + HTTP 500
→ stop capture
→ see both events in extension UI
```

Không thêm screenshot, backend, database, sharing, AI hoặc issue integration trước khi vertical slice này hoạt động ổn định.

Bug Capsule đáng làm nếu validation cho thấy team nhỏ thực sự mất thời gian vì bug report thiếu technical evidence và họ muốn một giải pháp local-first/self-hosted hơn là session recording SaaS.
