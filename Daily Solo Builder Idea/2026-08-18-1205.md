# Ý tưởng hôm nay: Local AI Knowledge Sync Agent

## 1. Tóm tắt ý tưởng

Một ứng dụng chạy local giúp developer tự động đồng bộ, lập chỉ mục và tìm kiếm kiến thức cá nhân từ code repository, tài liệu Markdown, PDF, issue, meeting notes và file kỹ thuật. Dự án giúp developer giảm thời gian tìm lại thông tin cũ mà vẫn giữ dữ liệu riêng tư trên máy.

- Người dùng: Developer, technical lead, freelancer.
- Quy mô: Medium.
- MVP: 3–4 tuần.

## 2. Bài toán thực tế

Developer thường có nhiều nguồn kiến thức phân tán: Git repository, wiki, README, tài liệu dự án, chat export và ghi chú cá nhân. Việc tìm lại quyết định kỹ thuật hoặc cách xử lý lỗi cũ thường mất nhiều thời gian.

Giả định: cá nhân làm nhiều dự án song song sẽ có nhu cầu cao hơn về công cụ tìm kiếm kiến thức riêng.

## 3. Người dùng mục tiêu

Primary user:

- Senior developer hoặc technical lead có nhiều repository.

Pain point:

- Không nhớ thông tin nằm ở đâu.
- Khó tái sử dụng giải pháp đã từng làm.

Workaround:

- Search thủ công trong IDE, GitHub, folder tài liệu.

## 4. Giải pháp đề xuất

Ứng dụng chạy local:

1. User chọn folder/project.
2. Agent scan file được cho phép.
3. Hệ thống tạo index.
4. User đặt câu hỏi hoặc tìm kiếm.
5. Tool trả kết quả kèm nguồn gốc file.

Ví dụ: hỏi "Lần trước tôi xử lý retry RabbitMQ như thế nào?" và nhận lại các file, đoạn code liên quan.

Điểm khác biệt: ưu tiên local-first, kiểm soát dữ liệu, phục vụ workflow developer thay vì chatbot chung chung.

## 5. Tại sao ý tưởng này đáng làm

Giá trị:

- Có thể dùng ngay cho chính công việc hàng ngày.
- Học AI engineering thực tế.

Kỹ thuật:

- Search engine.
- Embedding.
- Local AI workflow.
- Document processing.

Có thể thất bại nếu user không tin tưởng việc cấp quyền đọc dữ liệu.

Lý do không nên làm: nếu chỉ dùng cho một vài file nhỏ, IDE search đã đủ tốt.

## 6. Phạm vi MVP

### Must have

- Scan Markdown, txt, code file.
- Tạo local index.
- Semantic search.
- Hiển thị file nguồn.

### Should have

- PDF extraction.
- Git history integration.
- VS Code extension.

### Later

- Multi-agent analysis.
- Team knowledge server.
- Cloud synchronization.

## 7. Luồng hoạt động

User chọn workspace
→ validate permission
→ background scan
→ extract content
→ tạo index
→ search/query
→ trả kết quả

Failure:

- File bị lỗi.
- Không đủ quyền đọc.
- Index outdated.

## 8. Kiến trúc đề xuất

Modular monolith local application:

- Backend: .NET Worker/API.
- Database: SQLite.
- Storage: local filesystem.
- Search: SQLite FTS hoặc vector database nhẹ.
- UI: Vue hoặc desktop app.
- Scheduler: BackgroundService.

Không cần cloud hoặc microservice ở MVP.

## 9. Công nghệ đề xuất

- .NET 10: phù hợp kinh nghiệm backend.
- EF Core + SQLite: đơn giản, portable.
- Vue 3 hoặc MAUI: UI phù hợp.
- ONNX/local model hoặc OpenAI API tùy nhu cầu.
- Docker không bắt buộc cho bản local.

## 11. API và tích hợp

File system:

- Input chính.
- Không cần authentication.

Git:

- Có thể đọc commit history.
- Fallback: chỉ dùng file hiện tại.

AI API:

- Optional.
- Cần quản lý privacy.

## 12. AI có thực sự cần thiết không?

AI useful but optional.

AI dùng cho:

- Semantic search.
- Tóm tắt tài liệu.
- Trả lời dựa trên context.

Validation:

- Luôn trả citation file nguồn.
- Có fallback keyword search.

Rủi ro:

- Chi phí.
- Hallucination.
- Lộ dữ liệu nếu gửi cloud.

## 13. Kế hoạch triển khai

### Phase 0 — Validation

Dùng chính repository cá nhân để đo khả năng tìm kiếm.

### Phase 1 — Core MVP

Build scanner, database, search API.

Hoàn thành khi tìm được nội dung từ project cũ.

### Phase 2 — Reliability

Thêm test, incremental indexing, logging.

### Phase 3 — Expansion

Thêm IDE extension và AI summary.

### Phase 4 — Production

Đóng gói installer, backup, documentation.

## 14. Các bài toán kỹ thuật đáng học

1. Incremental indexing - xử lý dữ liệu thay đổi.
2. Search ranking - cải thiện kết quả.
3. Vector retrieval - ứng dụng AI thực tế.
4. Privacy design - xây local-first software.

## 15. Rủi ro và cách xử lý

- Scope lớn: chỉ hỗ trợ vài loại file trước.
- Privacy: mặc định local.
- AI cost: cho phép disable AI.
- Performance: giới hạn workspace.

## 16. Kiểm thử

5 scenario:

1. Scan repository mới.
2. File thay đổi và re-index.
3. File bị xóa.
4. Search không có kết quả.
5. AI trả kết quả sai nguồn.

- Search success rate.

- Memory usage.

## 20. Việc cần làm ngay hôm nay

Mục tiêu 60–120 phút: tạo CLI local search đầu tiên.

Tasks:

```bash
dotnet new console -n KnowledgeSyncAgent
```

Tạo:

```
/src
  Scanner
  Indexer
  Search
  Models
```

Implement:

- Đọc file Markdown.
- Lưu metadata SQLite.
- Search keyword.
- In kết quả kèm đường dẫn.

Verification:

- Scan một repository thật.
- Tìm được một đoạn code hoặc tài liệu.

Stop condition:

CLI trả về đúng file nguồn chứa nội dung cần tìm.
