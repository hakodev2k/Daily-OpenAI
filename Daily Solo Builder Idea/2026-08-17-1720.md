# Ý tưởng hôm nay: ShareSafe — Screenshot Privacy Scanner

## 1. Tóm tắt ý tưởng

**ShareSafe** là một ứng dụng desktop nhẹ giúp developer và nhân viên văn phòng kiểm tra ảnh chụp màn hình trước khi gửi lên Slack, Teams, email, ticket, GitHub issue hoặc tài liệu nội bộ. Ứng dụng dùng OCR và các rule deterministic để phát hiện chuỗi nhạy cảm như email, access token, API key, connection string, IP nội bộ, đường dẫn máy cá nhân, tên người dùng, số điện thoại hoặc dữ liệu khách hàng, sau đó cho phép người dùng blur/redact trực tiếp trước khi chia sẻ.

- **Người dùng chính:** developer, QA, support engineer, DevOps.
- **Bài toán:** screenshot thường vô tình chứa dữ liệu nhạy cảm mà người gửi không chú ý.
- **Kích thước:** Medium.
- **MVP ước tính:** 2–3 tuần cho một developer.

## 2. Bài toán thực tế

### Confirmed facts

Microsoft hiện cung cấp Windows AI Text Recognition APIs có thể nhận diện text trong ảnh và trả về word/line boundaries cùng confidence score. Tài liệu của Microsoft cũng lưu ý text nhỏ hoặc khó đọc có thể tạo kết quả không chính xác. Điều này cho thấy việc xây dựng pipeline OCR cục bộ trên Windows là khả thi nhưng vẫn cần cơ chế review của người dùng.

Nguồn: [Microsoft Learn — Get Started with Text Recognition (OCR)](https://learn.microsoft.com/windows/ai/apis/text-recognition)

Tesseract là OCR engine mã nguồn mở, hỗ trợ Unicode UTF-8, hơn 100 ngôn ngữ và nhiều định dạng ảnh phổ biến. Nó có thể chạy local hoàn toàn và không bắt buộc phải gửi ảnh ra cloud.

Nguồn: [Tesseract OCR — Official GitHub Repository](https://github.com/tesseract-ocr/tesseract)

### Observation

Trong công việc software, screenshot thường được dùng để báo bug, gửi log, review UI, báo lỗi production hoặc mô tả cấu hình. Một ảnh có thể đồng thời chứa nhiều vùng không liên quan tới vấn đề chính nhưng vẫn lộ thông tin như:

- bearer token;
- connection string;
- email nhân viên;
- customer ID;
- private hostname;
- database name;
- local filesystem path;
- browser tab chứa tên dự án hoặc khách hàng;
- terminal history;
- environment variables;
- source code có secret.

### Assumption

Một nhóm developer nhỏ có khả năng đang xử lý việc này bằng cách tự nhìn ảnh rồi mở Paint, Snipping Tool hoặc editor để che từng vùng. Quy trình đó phụ thuộc hoàn toàn vào trí nhớ và khả năng quan sát của người gửi.

### Analysis

Vấn đề không phải là “thiếu công cụ chụp màn hình”; vấn đề là thiếu một **privacy gate ngay trước thời điểm chia sẻ**. ShareSafe nên tập trung vào bước này thay vì trở thành một screenshot manager tổng quát.

## 3. Người dùng mục tiêu

### Primary user

Developer hoặc QA làm việc với hệ thống có dữ liệu nội bộ và thường xuyên gửi screenshot để trao đổi bug hoặc incident.

### Context sử dụng

Ví dụ:

1. QA thấy lỗi ở môi trường staging.
2. Chụp ảnh browser + DevTools Network.
3. Ảnh vô tình chứa Authorization header, email test, tenant ID và URL nội bộ.
4. QA chuẩn bị gửi ảnh vào ticket.

### Main pain point

Người dùng phải nhớ tự kiểm tra toàn ảnh mỗi lần chia sẻ. Một vùng nhỏ ở terminal hoặc DevTools rất dễ bị bỏ sót.

### Current workaround

- crop thủ công;
- blur bằng Paint hoặc editor;
- copy screenshot vào PowerPoint rồi phủ rectangle;
- retake screenshot;
- không chia sẻ ảnh có nhiều thông tin.

### Vì sao họ thử ShareSafe

Vì sản phẩm không thay đổi workflow nhiều: **paste ảnh → scan → review → redact → copy/share**.

## 4. Giải pháp đề xuất

### Workflow chính

1. Người dùng chụp screenshot.
2. Paste hoặc kéo ảnh vào ShareSafe.
3. App chạy OCR local.
4. Text OCR được đưa qua rule engine.
5. Rule engine đánh dấu các vùng khả nghi.
6. UI highlight từng detection.
7. Người dùng chọn:
   - redact;
   - blur;
   - ignore once;
   - trust pattern.
8. App tạo ảnh sanitized.
9. Người dùng copy ảnh mới vào clipboard hoặc save file.

### Input

- PNG/JPEG/WebP screenshot.
- Clipboard image.

### Processing

- OCR.
- normalize text.
- detect pattern.
- map detection ngược về bounding box trên ảnh.
- confidence scoring.
- merge overlapping regions.

### Output

- ảnh đã redact;
- danh sách detection;
- loại dữ liệu phát hiện;
- confidence;
- optional scan report không chứa raw secret.

### Automated

- OCR;
- pattern detection;
- đề xuất vùng cần che;
- merge vùng;
- tạo sanitized image.

### User control

- quyết định vùng nào thực sự cần che;
- whitelist một pattern;
- điều chỉnh rectangle;
- chọn blur hay solid redaction.

### Key differentiator

ShareSafe không phải screenshot editor. Điểm khác biệt là **security-aware screenshot linting**: giống secret scanner cho source code nhưng chạy trên pixel trước khi screenshot rời khỏi máy.

### Ví dụ end-to-end

Một backend developer chụp ảnh Postman để hỏi đồng nghiệp vì API trả 401. Screenshot chứa:

```text
Authorization: Bearer eyJhbGciOi...
userEmail: ha@example.com
https://api-staging.internal.company.local
```

ShareSafe OCR ảnh và đánh dấu ba vùng:

- JWT-like token → Critical;
- email → Medium;
- internal hostname → Medium.

Developer giữ hostname vì cần debug, nhưng redact token và email. App tạo ảnh mới rồi copy lại clipboard. Người dùng paste ảnh sanitized trực tiếp vào Teams.

## 5. Tại sao ý tưởng này đáng làm

### Practical value

Sản phẩm có thể dùng ngay cho chính developer khi:

- gửi screenshot cho AI coding tools;
- đăng GitHub issue;
- gửi lỗi lên Slack/Teams;
- viết tài liệu;
- báo incident;
- gửi log cho vendor.

### Technical learning value

Dự án kết hợp nhiều chủ đề đáng học:

- OCR;
- image coordinate mapping;
- secret detection;
- privacy-first local processing;
- desktop UI;
- clipboard APIs;
- secure configuration;
- false-positive handling.

### Suitable for solo developer

MVP không cần backend, SaaS, authentication hay database server. Một desktop application local-first là đủ chứng minh giá trị.

### Useful với rất ít user

Ngay cả khi chỉ có một người dùng, app vẫn có giá trị vì nó giảm nguy cơ tự mình chia sẻ nhầm secret.

### Điều gì khiến dự án thất bại

Nếu false positive quá nhiều, người dùng sẽ bỏ qua warning. Nếu OCR bỏ sót text quan trọng, họ sẽ mất niềm tin vào app.

### Lý do mạnh nhất để không build

Các screenshot editor hiện có đã cho phép blur/redact thủ công rất nhanh. ShareSafe chỉ đáng build nếu detection tự động thực sự tiết kiệm thời gian mà không tạo quá nhiều noise.

## 6. Phạm vi MVP

- local OCR;
- detection engine cho 6–8 loại pattern;

- whitelist;
- blur mode;
- configurable severity;
- save sanitized image;

### Later

## 7. Luồng hoạt động

```text
Paste screenshot
→ validate image
→ normalize resolution/orientation
→ OCR
→ OCR words + bounding boxes
→ normalize extracted text
→ pattern matching
→ aggregate detections
→ calculate severity/confidence
→ render overlay
→ user review
→ redact selected regions
→ generate clean bitmap
→ copy/save result
```

### Failure cases

#### OCR thất bại

App hiển thị:

```text
OCR could not confidently read this image.
Manual review is required.
```

Không được coi ảnh là “safe”.

#### Text quá nhỏ

Nếu confidence thấp, vùng vẫn có thể được highlight với nhãn `Low OCR confidence`.

#### Detection overlap

Ví dụ JWT nằm trong cả một Authorization header. Merge rectangle hoặc ưu tiên rule severity cao hơn.

#### Clipboard không có image

Không throw exception ra UI; hiển thị action rõ ràng.

#### Regex chạy quá lâu

Rule engine phải có timeout hoặc tránh regex dễ gây catastrophic backtracking.

#### User bỏ qua warning Critical

Yêu cầu confirmation trước khi copy nếu vẫn còn detection Critical chưa xử lý.

## 11. API và tích hợp

### Tesseract OCR

**Purpose:** OCR local.

**Authentication:** không cần.

**Cost/rate limit:** không có API billing vì chạy local.

**Privacy:** ảnh không rời máy.

**Fallback:** manual mode hoặc Windows OCR.

Nguồn: [Official Tesseract GitHub](https://github.com/tesseract-ocr/tesseract)

### Windows Text Recognition API

**Purpose:** OCR native trên Windows và lấy text boundaries/confidence.

**Authentication:** không cần cloud credential cho local API.

**Cost:** không phải cloud request theo mô hình API được mô tả trong Windows App SDK.

**Constraint:** cần kiểm tra OS/hardware support trước khi bật engine.

**Fallback:** Tesseract.

Nguồn: [Microsoft Learn](https://learn.microsoft.com/windows/ai/apis/text-recognition)

### Clipboard API

**Purpose:** paste/copy screenshot.

**Authentication:** không cần.

**Privacy:** toàn bộ local.

**Fallback:** drag/drop file.

### Optional future integration: GitHub secret patterns

Không cần gọi GitHub API. Có thể cung cấp deterministic pattern packs cho common token formats dựa trên documentation công khai và test fixtures giả.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Core MVP không cần LLM.

OCR + regex/rule engine giải quyết phần lớn các detection có format rõ ràng và đáng tin cậy hơn.

### AI chỉ đáng thêm sau này cho semantic detection

Ví dụ OCR đọc được:

```text
Customer: Nguyen Van A
Contract: ACME Migration Project
Internal note: salary adjustment
```

Không regex nào biết chắc đây là dữ liệu nhạy cảm theo context. Một local hoặc cloud LLM có thể classify từng text block.

### Exact AI task

Input:

```json
{
  "blocks": [
    {"id":"b1","text":"..."},
    {"id":"b2","text":"..."}
  ]
}
```

Expected output:

```json
{
  "detections": [
    {
      "blockId":"b1",
      "category":"possible-personal-data",
      "confidence":0.82,
      "reason":"contains a person's full name"
    }
  ]
}
```

### Validation

AI không trực tiếp redact ảnh. Nó chỉ tạo suggestion; user phải review.

### Deterministic fallback

Nếu AI unavailable, toàn bộ regex/rule engine vẫn hoạt động.

### Risks

- hallucination;
- data leakage nếu gửi OCR text lên cloud;
- latency;
- token cost;
- inconsistent classification.

Recommendation: **không đưa AI vào Phase 1–2**.

## 15. Rủi ro và cách xử lý

### OCR bỏ sót dữ liệu

**Risk:** false negative tạo cảm giác an toàn giả.

**Mitigation:**

- không dùng wording “100% safe”;
- hiển thị OCR confidence;
- cảnh báo manual review;
- nhiều OCR engine optional;
- test fixture thực tế.

### False positive quá nhiều

**Risk:** user ignore mọi warning.

**Mitigation:**

- severity tiers;
- conservative built-in rules;
- allowlist;
- category toggle;
- measure precision thay vì chỉ detection count.

### Sensitive data bị log

**Risk:** app tự tạo một bản leak khác.

**Mitigation:**

- never log raw OCR text;
- never persist screenshot mặc định;
- masked previews;
- explicit opt-in cho diagnostics.

### Scope expansion

**Risk:** biến thành Snagit/ShareX clone.

**Mitigation:** giữ product boundary:

```text
scan → warn → redact → copy
```

Không build screenshot library, cloud storage, annotation suite trong MVP.

### OCR dependency

**Risk:** Tesseract setup/package phức tạp.

**Mitigation:** đóng gói traineddata cần thiết cùng installer; define `IOcrEngine` để thay backend.

### User adoption

**Risk:** manual check vẫn nhanh hơn.

**Mitigation:** hotkey, clipboard-first UX và one-click redact phải là KPI cốt lõi.

### Platform restriction

Windows-only MVP giới hạn user base.

Mitigation: architecture giữ `Detection` và `Imaging` độc lập với WPF để có thể tái sử dụng khi port.

- overlapping rectangles;
- whitelist.

### Integration tests

- OCR fixture → detection result;
- image redaction → output bitmap.

### End-to-end tests

Native UI automation có thể thêm sau; MVP ưu tiên integration tests vì phần quan trọng nằm trong OCR/detection pipeline.

### Failure-path tests

- invalid image;
- OCR timeout;
- no text;
- low-confidence OCR;
- clipboard unavailable.

### Security tests

Kiểm tra logs/config/history không chứa raw fake secret sau mỗi test run.

### Data-quality tests

Fixture corpus nên có screenshot từ:

- Postman;
- browser DevTools;
- terminal;
- VS Code;
- configuration file;
- Azure Portal mockup.

### 5 test scenario quan trọng nhất

1. Screenshot có fake JWT → detect đúng vùng → redact hoàn toàn.
2. Screenshot không có dữ liệu nhạy cảm → không tạo warning noise lớn.
3. OCR fail → app cảnh báo, không đánh dấu ảnh safe.
4. Hai detection overlap → redaction không bỏ sót pixel.
5. Sau scan một fake API key → search toàn bộ logs/database không tìm thấy raw key.

## 17. Cách đo dự án có hữu ích hay không

### Product usage metric

`Sanitized screenshots per active week`.

Không đo page views.

### Time saved

Median:

```text
paste → reviewed → copied
```

Target ban đầu: dưới 15 giây cho screenshot thông thường.

### Task completion rate

Tỷ lệ scan session kết thúc bằng `copy sanitized image`.

### Detection usefulness

Theo dõi:

```text
accepted detections / total detections
```

Nếu user ignore 80–90% warning thì rule engine đang quá noisy.

### Error rate

- OCR failure rate;
- clipboard failure rate;
- redaction rendering failure rate.

### Repeat usage

Số tuần user quay lại sử dụng ít nhất một lần quan trọng hơn tổng launch count.

### Technical reliability

- crash-free scan rate;
- percentage of fixture secrets correctly detected.

### AI quality

Không áp dụng cho MVP vì AI chưa được dùng.

## 20. Việc cần làm ngay hôm nay

### Thời lượng

Khoảng 90 phút.

### Development objective

Tạo vertical slice đầu tiên:

```text
PNG screenshot
→ OCR
→ detect email/JWT
→ in detection + bounding box ra console
```

Chưa cần WPF UI.

### Files/components cần tạo

```text
ShareSafe.sln
src/
  ShareSafe.Core/
    Ocr/
      IOcrEngine.cs
      OcrWord.cs
    Detection/
      DetectionRule.cs
      DetectionResult.cs
      SensitiveTextDetector.cs
  ShareSafe.Cli/
    Program.cs
tests/
  ShareSafe.Core.Tests/
fixtures/
  sample-sensitive.png
```

### Setup

```bash
dotnet new sln -n ShareSafe

dotnet new classlib -n ShareSafe.Core -o src/ShareSafe.Core
dotnet new console -n ShareSafe.Cli -o src/ShareSafe.Cli
dotnet new xunit -n ShareSafe.Core.Tests -o tests/ShareSafe.Core.Tests

dotnet sln add src/ShareSafe.Core/ShareSafe.Core.csproj
dotnet sln add src/ShareSafe.Cli/ShareSafe.Cli.csproj
dotnet sln add tests/ShareSafe.Core.Tests/ShareSafe.Core.Tests.csproj

dotnet add src/ShareSafe.Cli/ShareSafe.Cli.csproj reference src/ShareSafe.Core/ShareSafe.Core.csproj
dotnet add tests/ShareSafe.Core.Tests/ShareSafe.Core.Tests.csproj reference src/ShareSafe.Core/ShareSafe.Core.csproj
```

Chọn một Tesseract .NET wrapper phù hợp sau khi kiểm tra maintenance/license hiện tại, hoặc trong session đầu có thể gọi executable `tesseract` bằng `Process` để tránh dành thời gian vào binding.

Ví dụ flow CLI mong muốn:

```bash
dotnet run --project src/ShareSafe.Cli -- fixtures/sample-sensitive.png
```

Expected output:

```text
OCR: 47 words

[CRITICAL] jwt
bbox: x=442 y=317 w=505 h=28
preview: eyJhb...D2Q

[MEDIUM] email
bbox: x=215 y=198 w=184 h=24
preview: h***@example.com
```

### First detector

Ban đầu chỉ cần hai pattern:

```text
Email
JWT-like token
```

Không cần build 20 rule ngay.

### Verification checklist

- [ ] CLI nhận PNG path.
- [ ] OCR trả text từ fixture.
- [ ] Có bounding box cho từng OCR word hoặc line.
- [ ] Fake email được detect.
- [ ] Fake JWT được detect.
- [ ] Console không in full secret.
- [ ] Unit test detector pass.
- [ ] Không file nào ngoài fixture chứa raw fake secret.

### Stop condition

Dừng session ngay khi command sau chạy end-to-end:

```bash
dotnet run --project src/ShareSafe.Cli -- fixtures/sample-sensitive.png
```

và trả về ít nhất một detection có bounding box chính xác.

Không làm WPF UI, installer, blur effect, database hoặc AI trong session đầu.
