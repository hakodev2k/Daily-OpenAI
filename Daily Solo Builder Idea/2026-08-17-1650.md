# Ý tưởng hôm nay: CSV Reconcile Studio — Trình đối soát file CSV/Excel có thể giải thích được

## 1. Tóm tắt ý tưởng

**CSV Reconcile Studio** là một công cụ web/self-hosted giúp người dùng nhập hai file dữ liệu dạng CSV/TSV/XLSX — ví dụ dữ liệu giao dịch từ hai hệ thống, danh sách thanh toán và hóa đơn, hoặc export từ ngân hàng và phần mềm nội bộ — sau đó tự động chuẩn hóa, ghép bản ghi, phát hiện chênh lệch và tạo báo cáo đối soát có thể giải thích được.

Thay vì chỉ so sánh từng dòng theo thứ tự, công cụ dùng rule deterministic như exact match, normalized match, date tolerance, amount tolerance và composite key để tìm cặp bản ghi phù hợp. Người dùng vẫn kiểm soát rule và quyết định cuối cùng.

- **Project size:** Medium
- **Estimated MVP time:** khoảng 2–4 tuần làm ngoài giờ, hoặc 7–10 ngày tập trung
- **Đối tượng chính:** developer/QA/finance-ops ở nhóm nhỏ thường xuyên phải đối soát file export thủ công

## 2. Bài toán thực tế

### Vấn đề hiện tại

Rất nhiều hệ thống cho phép export dữ liệu ra CSV hoặc Excel nhưng không có API tích hợp trực tiếp với nhau. Khi cần kiểm tra xem hai nguồn dữ liệu có khớp hay không, người dùng thường phải:

- mở hai file bằng Excel;
- dùng `VLOOKUP`, `XLOOKUP`, `SUMIFS`, Power Query hoặc script tự viết;
- đổi format ngày, số tiền, mã giao dịch;
- xử lý khoảng trắng, casing, dấu phân cách, BOM, encoding;
- tự xem từng dòng bị lệch;
- copy kết quả sang file báo cáo khác.

Vấn đề lặp lại ở nhiều tình huống: đối soát payment, invoice, payroll, order, timesheet, inventory snapshot, billing, webhook export, migration result hoặc dữ liệu QA.

### Fact đã xác nhận

PostgreSQL hỗ trợ import/export dữ liệu dạng CSV qua `COPY`, với các tùy chọn cho delimiter, quote, escape, header, encoding và xử lý lỗi; tài liệu chính thức cũng lưu ý rằng CSV trong thực tế không hoàn toàn đồng nhất và có thể có nhiều biến thể khó xử lý. Nguồn: PostgreSQL documentation — `COPY`: https://www.postgresql.org/docs/18/sql-copy.html

Trong .NET, `TextFieldParser` hỗ trợ đọc structured text dạng delimited hoặc fixed-width và có hỗ trợ fields nằm trong quotation marks. Nguồn: Microsoft Learn — `TextFieldParser`: https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.fileio.textfieldparser

### Quan sát

Điểm khó của đối soát không nằm ở việc “đọc CSV” mà nằm ở:

1. hai nguồn có schema khác nhau;
2. cùng một dữ liệu nhưng format khác;
3. không phải lúc nào cũng có một khóa duy nhất tuyệt đối;
4. một số chênh lệch là hợp lệ trong tolerance;
5. người dùng cần biết **vì sao** hệ thống ghép hai dòng với nhau.

### Assumption

Giả định cho MVP: nhóm nhỏ thường xuyên phải lặp lại một logic đối soát tương tự và sẵn sàng định nghĩa mapping/rule một lần để dùng lại nhiều lần.

### Vì sao cách hiện tại bất tiện

- spreadsheet formula dễ vỡ khi column đổi tên hoặc vị trí;
- script ad-hoc khó tái sử dụng;
- khó audit logic match;
- khó kiểm tra edge case như duplicate transaction;
- khó chạy lại theo cùng rule và so sánh kết quả qua nhiều lần;
- báo cáo thường chỉ cho thấy “không khớp” chứ không giải thích nguyên nhân.

## 3. Người dùng mục tiêu

### Primary user cho MVP

**Developer hoặc QA engineer trong team nhỏ** thường phải kiểm tra output giữa hai hệ thống bằng file export.

Ví dụ:

- QA so sánh dữ liệu trước/sau migration;
- backend developer kiểm tra payment provider export với database export;
- tester đối soát API migration V1/V2;
- engineer kiểm tra payroll/timesheet export từ hai hệ thống;
- người vận hành nội bộ kiểm tra invoice với payment.

### Context sử dụng

Người dùng có hai file:

- `system-a.csv`
- `system-b.csv`

Hai file mô tả cùng một tập giao dịch nhưng:

- tên cột khác nhau;
- thứ tự khác nhau;
- ngày khác timezone;
- amount có rounding;
- identifier đôi khi thiếu;
- một nguồn có duplicate.

### Pain point chính

Mỗi lần đối soát lại phải viết lại công thức hoặc script.

### Workaround hiện tại

- Excel / Google Sheets;
- Power Query;
- SQL staging table;
- Python/Pandas script;
- C# console app dùng một lần.

### Vì sao họ sẽ thử sản phẩm

Nếu tool cho phép tạo một **Reconciliation Profile** một lần rồi chạy lại nhiều file khác nhau bằng cùng rule, nó có thể tiết kiệm thời gian ngay cả khi chỉ có một người dùng duy nhất.

## 4. Giải pháp đề xuất

### Workflow chính

1. Upload Source A.
2. Upload Source B.
3. Tool đọc header và sample rows.
4. Người dùng map field tương ứng.
5. Người dùng định nghĩa match rules.
6. Tool normalize dữ liệu.
7. Matching engine tìm candidate pairs.
8. Tool phân loại kết quả:
   - Exact Match
   - Match With Tolerance
   - Ambiguous Match
   - Only In A
   - Only In B
   - Duplicate
   - Value Conflict
9. Người dùng xem diff chi tiết.
10. Export report CSV/JSON.

### Input

Ví dụ Source A:

```csv
TransactionId,CreatedAt,Amount,CustomerEmail
A001,2026-08-17T08:00:00Z,1250000,User@Example.com
A002,2026-08-17T08:10:00Z,300000,user2@example.com
```

Source B:

```csv
reference,date,total,email
A001,2026-08-17 15:00:03+07,1250000,user@example.com
A002,2026-08-17 15:10:00+07,299999,user2@example.com
```

### Processing

Profile:

- `TransactionId` ↔ `reference`: exact
- `CreatedAt` ↔ `date`: UTC normalized, tolerance ±10 seconds
- `Amount` ↔ `total`: tolerance ±1
- email: trim + lowercase

### Output

```text
A001: MATCH
- TransactionId: exact
- CreatedAt: +3 seconds, within tolerance
- Amount: exact
- Email: normalized match

A002: MATCH_WITH_TOLERANCE
- Amount delta: -1
```

### Automated

- delimiter detection;
- basic encoding detection;
- column sampling;
- normalization;
- matching;
- duplicate detection;
- diff calculation;
- summary metrics.

### User control

- chọn key;
- chọn match strategy;
- chọn tolerance;
- quyết định ambiguous match;
- quyết định field nào chỉ informative;
- quyết định export.

### Differentiator

**Không phải file diff tool.**

Differentiator là reconciliation theo semantic rule và tạo **explainable match evidence** cho từng cặp record.

## 7. Luồng hoạt động

### Happy path

```text
Upload A + B
→ detect format
→ parse header
→ preview
→ map columns
→ validate rules
→ normalize records
→ index candidate keys
→ match
→ classify result
→ persist run summary
→ show diff
→ export report
```

### Alternative flow — duplicate key

```text
A có 2 rows cùng TransactionId
→ engine không tự chọn ngẫu nhiên
→ mark Ambiguous/Duplicate
→ hiển thị cả candidate rows
→ user review
```

### Alternative flow — file malformed

```text
parse error tại row 190
→ không crash toàn process
→ report row + raw excerpt + reason
→ cho user chọn stop hoặc skip malformed rows
```

### Alternative flow — encoding problem

Nếu decode UTF-8 lỗi:

- thử BOM;
- cho user chọn encoding;
- không silently replace ký tự rồi tiếp tục.

### Alternative flow — weak key

Nếu key không unique:

- cảnh báo trước khi chạy;
- đề xuất thêm secondary field;
- không auto match chỉ dựa trên row order.

### Failure case — file quá lớn

MVP đặt hard limit, ví dụ 100 MB/file hoặc 500k rows.

Sau này chuyển sang streaming processing và external temp storage.

**Vue 3**.

- run metadata;

Không cần MVP.

Không cần MVP.

## 9. Công nghệ đề xuất

Nếu muốn compatibility rộng hơn, .NET 8 vẫn là lựa chọn đơn giản cho môi trường đã có sẵn runtime cũ hơn.

Dùng cho:

- profile CRUD;
- reconciliation endpoint;
- report download.

### EF Core

Dùng quản lý metadata và profile.

Không bắt buộc dùng EF cho bulk data processing.

### PostgreSQL

Phù hợp cho metadata và query result summary.

PostgreSQL cũng có built-in `COPY` cho CSV import/export nếu sau này cần bulk loading. Tài liệu chính thức mô tả hỗ trợ `FORMAT csv`, delimiter, quote, escape, header, encoding và error handling. Nguồn: https://www.postgresql.org/docs/18/sql-copy.html

### CSV parser

Khuyến nghị dùng một parser streaming chuyên dụng hoặc `TextFieldParser`/custom abstraction thay vì `string.Split(',')`.

Microsoft document `TextFieldParser` hỗ trợ delimited/fixed-width và quoted fields. Nguồn: https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.fileio.textfieldparser

Một lựa chọn practical khác trong .NET ecosystem là CsvHelper, nhưng cần kiểm tra license/version tại thời điểm tích hợp.

### Vue 3 + TypeScript

Phù hợp để làm mapping UX nhanh.

Simpler alternative: Razor Pages.

Nếu UI chỉ có 2–3 màn hình, Razor Pages có thể nhanh hơn Vue.

### Docker

Dùng để đảm bảo PostgreSQL và app reproducible.

### Playwright

Dùng cho end-to-end upload → map → reconcile → export.

### GitHub Actions

Workflow:

```text

→ build
→ test
→ docker build
```

### Khi nào outgrow stack

Chỉ cần queue/distributed workers khi:

- file hàng triệu rows;
- nhiều concurrent users;
- scheduled batch reconciliation;
- remote source connectors.

Trước đó, modular monolith là đủ.

- `OnlyBCount`

Có thể không cần table riêng trong MVP.

## 11. API và tích hợp

### 1. CSV/TSV file input

**Purpose:** nguồn dữ liệu chính.

**Authentication:** không cần.

**Cost/rate-limit:** không có external cost.

**Privacy:** file có thể chứa PII; phải xử lý local/self-hosted và xóa theo TTL.

**Fallback:** nếu parse lỗi, cung cấp delimiter/encoding override.

### 2. XLSX support — Phase 2

Có thể dùng ClosedXML hoặc thư viện tương đương.

**Cost:** cần kiểm tra license dependency cụ thể trước khi ship commercial build.

**Fallback:** yêu cầu export CSV.

### 3. PostgreSQL connector — Later

Có thể đọc query result trực tiếp qua Npgsql.

**Auth:** database credentials.

**Privacy:** rủi ro cao hơn file upload.

**Fallback:** CSV export.

### 4. SQL Server connector — Later

Có thể dùng `Microsoft.Data.SqlClient`.

**Auth:** SQL login hoặc integrated/Entra authentication tùy deployment.

**Fallback:** CSV export.

### 5. Object storage — Later

Azure Blob hoặc S3-compatible.

Không cần cho local MVP.

## 12. AI có thực sự cần thiết không?

**AI is not necessary.**

Core problem cần tính reproducible và explainable cao hơn khả năng “đoán”.

### Vì sao deterministic tốt hơn

Nếu hai giao dịch được match, hệ thống phải giải thích chính xác:

```text
reference exact
amount difference = 1
date difference = 3 sec
email lowercased equal
```

LLM không cần thiết cho việc này.

### AI có thể thêm sau ở vai trò optional

Một tính năng phụ có thể là:

> “Gợi ý mapping column dựa trên header + sample.”

Ví dụ:

```json
{
  "sourceA": "CreatedAt",
  "sourceB": "transaction_date",
  "confidence": 0.87
}
```

Nhưng phải yêu cầu người dùng approve.

### Deterministic fallback

- exact header match;
- normalized header match;
- synonym dictionary;
- compatible datatype check.

### Risks nếu thêm AI

- gửi sample data ra ngoài;
- hallucinated mappings;
- cost;
- latency;
- privacy.

Do đó không dùng AI trong MVP.

- stream parsing;
- encoding;

## 15. Rủi ro và cách xử lý

### Rủi ro 1 — Scope biến thành ETL platform

- warehouse sync.

### Rủi ro 2 — Matching sai nhưng trông có vẻ đúng

**Mitigation:**

**Mitigation:**

- file TTL;

- encryption at rest nếu cloud;
- sanitize filenames;

### Rủi ro 4 — CSV edge cases

**Mitigation:**

- fixture có quotes/newlines/BOM/UTF-8;

### Rủi ro 5 — Performance

**Mitigation:**

- benchmark trước khi thêm distributed architecture.

### Rủi ro 6 — User adoption

Nếu tạo profile mất 20 phút thì Excel có thể vẫn nhanh hơn.

**Mitigation:**

- auto detect column;
- good defaults;
- clone profile;
- sample preview ngay khi upload;

### Rủi ro 7 — Commercial maintenance burden

Input formats và data sources rất đa dạng.

**Mitigation:**

Giới hạn supported contract rõ:

## 20. Việc cần làm ngay hôm nay

### Development objective

Trong **90 phút**, tạo vertical slice đầu tiên:

> Đọc hai CSV, match theo một column ID bất kể row order, sau đó trả về `Matched`, `OnlyA`, `OnlyB`.

Chưa cần web UI đẹp, database hoặc auth.

### Step 1 — Tạo solution

```bash
mkdir CsvReconcileStudio
cd CsvReconcileStudio

dotnet new sln -n CsvReconcileStudio

dotnet new webapi -n CsvReconcile.Api -o src/CsvReconcile.Api
dotnet new classlib -n CsvReconcile.Core -o src/CsvReconcile.Core
dotnet new xunit -n CsvReconcile.Core.Tests -o tests/CsvReconcile.Core.Tests

dotnet sln add src/CsvReconcile.Api/CsvReconcile.Api.csproj
dotnet sln add src/CsvReconcile.Core/CsvReconcile.Core.csproj
dotnet sln add tests/CsvReconcile.Core.Tests/CsvReconcile.Core.Tests.csproj

dotnet add src/CsvReconcile.Api/CsvReconcile.Api.csproj reference src/CsvReconcile.Core/CsvReconcile.Core.csproj
dotnet add tests/CsvReconcile.Core.Tests/CsvReconcile.Core.Tests.csproj reference src/CsvReconcile.Core/CsvReconcile.Core.csproj
```

### Step 2 — Tạo files

```text
src/CsvReconcile.Core/
  Models/SourceRow.cs
  Models/ReconciliationSummary.cs
  Parsing/SimpleCsvReader.cs
  Matching/ExactKeyReconciler.cs

tests/CsvReconcile.Core.Tests/
  ExactKeyReconcilerTests.cs

samples/
  source-a.csv
  source-b.csv
```

### Step 3 — Model đơn giản

```csharp
public sealed record SourceRow(
    int RowNumber,
    IReadOnlyDictionary<string, string> Values);

public sealed record ReconciliationSummary(
    int Matched,
    IReadOnlyList<string> OnlyA,
    IReadOnlyList<string> OnlyB);
```

### Step 4 — Vertical slice matching

`ExactKeyReconciler` nhận:

```csharp
Reconcile(
    IReadOnlyList<SourceRow> sourceA,
    IReadOnlyList<SourceRow> sourceB,
    string sourceAKey,
    string sourceBKey)
```

Implementation đầu tiên:

1. build dictionary B theo key;
2. iterate A;
3. nếu key tồn tại → matched;
4. nếu không → OnlyA;
5. cuối cùng lấy unmatched B → OnlyB;
6. nếu duplicate key → throw domain exception rõ ràng hoặc trả duplicate result.

### Step 5 — Sample data

`source-a.csv`:

```csv
TransactionId,Amount
A001,100
A002,200
A003,300
```

`source-b.csv`:

```csv
reference,total
A003,300
A001,100
A004,400
```

Expected:

```json
{
  "matched": 2,
  "onlyA": ["A002"],
  "onlyB": ["A004"]
}
```

### Step 6 — API endpoint tạm

Có thể tạo endpoint:

```text
POST /api/reconcile/exact
```

Request multipart:

- `sourceA`
- `sourceB`
- `sourceAKey`
- `sourceBKey`

Response summary JSON.

### Step 7 — Tests

Viết ít nhất 4 tests:

```text
same records different order → all match
missing A row → OnlyB
missing B row → OnlyA
duplicate key → explicit failure
```

Run:

```bash
dotnet test
```

Sau đó:

```bash
dotnet run --project src/CsvReconcile.Api
```

Dùng curl hoặc Swagger gửi hai sample files.

### Expected result cuối phiên

Bạn có thể gửi hai CSV khác row order và nhận được:

```json
{
  "matched": 2,
  "onlyA": ["A002"],
  "onlyB": ["A004"]
}
```

Đây là kết quả testable và đã chứng minh core value đầu tiên: **reconciliation không phụ thuộc row order**.

### Verification checklist

- [ ] Hai file được parse đúng.
- [ ] Row order khác nhau vẫn match.
- [ ] Missing record được phân loại đúng.
- [ ] Duplicate key không bị silently overwrite.
- [ ] Có unit test chạy pass.
- [ ] API trả JSON summary.
- [ ] Không dùng `string.Split(',')` nếu parser đã bước sang quoted CSV.

### Stop condition

Dừng phiên coding ngay khi:

1. 4 unit tests pass;
2. endpoint chạy được với sample files;
3. summary đúng với expected output.

**Không** thêm database, Vue, auth, AI, scheduler hoặc fuzzy matching trong phiên đầu tiên.

## Research notes

### Confirmed facts

- PostgreSQL `COPY` hỗ trợ CSV với delimiter, quote, escape, header, encoding và nhiều tùy chọn import/export; tài liệu cũng lưu ý CSV trong thực tế có nhiều biến thể và không phải mọi file đều import dễ dàng. Nguồn chính thức: PostgreSQL 18 Documentation — https://www.postgresql.org/docs/18/sql-copy.html
- .NET `TextFieldParser` hỗ trợ structured text dạng delimited hoặc fixed-width và hỗ trợ quoted fields. Nguồn chính thức: Microsoft Learn — https://learn.microsoft.com/en-us/dotnet/api/microsoft.visualbasic.fileio.textfieldparser

### Observation

Các API/parsing primitive hiện có đủ để xây MVP hoàn toàn deterministic; không cần phụ thuộc website scraping hoặc AI service.

### Analysis

Giá trị khác biệt không nằm ở “CSV parser”, mà nằm ở reusable reconciliation profiles, deterministic matching, ambiguity handling và explainable evidence.

### Assumptions cần validation

- Người dùng có workflow đối soát lặp lại nhiều lần.
- Họ chấp nhận cấu hình rule một lần để tiết kiệm thời gian cho các lần sau.
- Hai nguồn có ít nhất một tập field có thể dùng để tạo candidate match ổn định.

### Recommendation

Bắt đầu bằng use case cá nhân có dữ liệu thật: migration verification hoặc đối soát export giữa hai hệ thống. Nếu sau 3–5 lần dùng mà saved profile không thực sự tiết kiệm thời gian so với script/Excel, nên dừng project thay vì mở rộng thành ETL platform.
