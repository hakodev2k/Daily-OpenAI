# Ý tưởng hôm nay: MigrationDryRun — EF Core Migration Rehearsal & Risk Scanner

## 1. Tóm tắt ý tưởng

MigrationDryRun là một developer tool self-hosted giúp developer **rehearse migration database trước khi deploy thật**: lấy schema hiện tại, dựng một database tạm, apply EF Core migration, đo thời gian, phát hiện thao tác rủi ro và xuất báo cáo có thể dùng trong pull request hoặc CI. Công cụ đặc biệt phù hợp với backend developer .NET thường xuyên thay đổi schema nhưng chưa có một bước kiểm tra migration độc lập khỏi application startup.

- Người dùng chính: .NET backend developer hoặc solo SaaS developer dùng EF Core.
- Bài toán chính: migration chạy tốt trên database dev nhỏ nhưng có thể fail, lock lâu hoặc gây data loss khi áp dụng lên môi trường thật.
- Quy mô: **Medium**.
- Thời gian MVP ước tính: **2–3 tuần**.

## 2. Bài toán thực tế

### Confirmed facts

Microsoft hiện khuyến nghị developer **inspect và test migration trước khi áp dụng production**, vì migration được sinh tự động có thể chứa thay đổi không đúng ý định như drop column thay vì rename. EF Core hỗ trợ generated SQL scripts, idempotent scripts và migration bundles để triển khai migration có kiểm soát. Microsoft cũng cảnh báo việc apply migration trực tiếp khi application startup có nhiều nhược điểm trong production, bao gồm quyền schema quá cao, khó review SQL và rủi ro khi nhiều instance cùng hoạt động.

Nguồn chính thức:

- Microsoft Learn — Applying Migrations: https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying
- Microsoft Learn — EF Core CLI: https://learn.microsoft.com/en-us/ef/core/cli/dotnet
- Microsoft Learn — Migrations Overview: https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/

.NET 10 hiện là bản LTS được Microsoft hỗ trợ tới tháng 11/2028, phù hợp làm runtime mặc định cho một project mới trong năm 2026.

- Microsoft Learn — .NET releases and support: https://learn.microsoft.com/en-us/dotnet/core/releases-and-support

### Observation

EF Core đã có công cụ tạo và apply migration rất tốt, nhưng workflow phổ biến vẫn thiên về:

1. Generate migration.
2. Review source hoặc SQL bằng mắt.
3. Chạy trên local/dev.
4. Deploy staging/production.

Khoảng trống hữu ích cho solo developer là một tool tập trung riêng vào **migration rehearsal** và đưa ra một report nhất quán trước khi deploy.

### Assumption cần kiểm chứng

Developer có thể sẵn sàng thêm một bước CI 30–120 giây nếu report giúp bắt được migration nguy hiểm trước production và giảm thời gian rollback/debug.

## 3. Người dùng mục tiêu

### Primary user

Backend developer dùng:

- ASP.NET Core;
- EF Core;
- PostgreSQL hoặc SQL Server;
- GitHub Actions/Azure DevOps;
- nhiều môi trường dev/staging/production.

### Context of use

Trước khi merge một PR có migration hoặc trước khi deploy release mới.

### Main pain point

Developer biết migration “compile được” nhưng chưa chắc:

- apply thành công trên schema đang chạy;
- mất bao lâu;
- có thao tác phá dữ liệu hay không;
- có tạo table scan hoặc rewrite lớn không;
- có rollback được không;
- migration có phụ thuộc trạng thái data đặc biệt hay không.

### Current workaround

- review migration C#;
- generate SQL rồi đọc thủ công;
- clone database staging;
- chạy `dotnet ef database update` bằng tay;
- phụ thuộc CI integration test nếu có.

### Lý do họ sẽ thử tool

Một command duy nhất có thể trả về kết quả dạng:

```text
Migration: 20260819_AddOrderReference
Status: PASS_WITH_WARNINGS
Apply duration: 3.2s
Rollback: PASS
Risk findings:
- DROP COLUMN detected
- CREATE INDEX without explicit online/concurrent strategy
- NOT NULL column added without visible backfill/default
```

## 4. Giải pháp đề xuất

### Main workflow

Developer chạy:

```bash
migrationdryrun analyze ./src/MyApp --provider postgres
```

Tool sẽ:

1. Phát hiện project EF Core và `DbContext`.
2. Generate SQL từ migration pending.
3. Parse SQL thành tập operations cơ bản.
4. Tạo ephemeral database bằng Docker.
5. Đưa schema baseline vào database tạm.
6. Apply migration.
7. Chạy validation queries.
8. Nếu có downgrade path, thử rollback trong một database disposable riêng.
9. Ghi duration, exception, warnings và schema diff.
10. Xuất Markdown/JSON report.

### Input

- path project `.csproj`;
- provider: PostgreSQL/SQL Server;
- optional baseline SQL hoặc migration target;
- optional test dataset generator;
- policy file `migrationdryrun.yml`.

### Processing

Core deterministic engine:

- invoke `dotnet ef migrations script`;
- parse SQL heuristically;
- execute trên disposable database;
- inspect database metadata trước/sau;
- measure duration;
- run configured assertions.

### Output

- terminal summary;
- `migration-report.md`;
- `migration-report.json` cho CI;
- exit code non-zero nếu violation vượt threshold.

### What is automated

- environment setup;
- script generation;
- database reset;
- apply/rollback test;
- schema diff;
- risk checks;
- report generation.

### What remains under user control

- baseline data được phép dùng;
- risk threshold;
- provider-specific rules;
- việc approve migration;
- production deployment.

### Key differentiator

Không cố thay thế EF Core migrations. Tool chỉ đóng vai trò **pre-flight test harness** cho migration.

### Ví dụ end-to-end

Developer thêm field bắt buộc:

```csharp
public string ExternalReference { get; set; }
```

vào bảng `Orders` đang có dữ liệu.

MigrationDryRun chạy và phát hiện generated migration thêm column `NOT NULL`. Disposable DB chứa 10.000 sample records được dựng từ fixture. Migration fail vì row cũ không có giá trị phù hợp.

Developer sửa migration thành quy trình:

1. thêm nullable column;
2. backfill;
3. convert sang NOT NULL.

Chạy lại tool → PASS.

## 7. Luồng hoạt động

```text
Developer creates migration
→ MigrationDryRun validates project
→ generates SQL
→ starts disposable DB
→ restores baseline/schema
→ seeds optional dataset
→ applies candidate migration
→ captures timings/errors
→ compares schema
→ runs policy checks
→ optionally rehearses rollback
→ generates report
→ exits pass/warn/fail
```

### Failure cases

**Docker unavailable** → fail fast với hướng dẫn rõ ràng.

**`dotnet ef` missing** → detect trước khi tạo environment.

**Migration compilation fails** → report build failure, không tiếp tục.

**Baseline restore fails** → classify là environment failure thay vì migration failure.

**Migration timeout** → stop execution, giữ logs, đánh dấu `TIMED_OUT`.

**Rollback không khả dụng** → cảnh báo thay vì tự suy đoán rollback an toàn.

**SQL parser không hiểu statement** → classify `UNKNOWN_OPERATION`; không tự coi là safe.

## 11. API và tích hợp

### EF Core CLI

**Purpose:** generate migration SQL.

**Authentication:** không cần.

**Cost/rate limit:** không có network API cost.

**Privacy:** source code ở local/CI; không upload.

**Fallback:** cho phép truyền SQL script trực tiếp nếu project không chạy được `dotnet ef`.

### Docker Engine

**Purpose:** ephemeral PostgreSQL.

**Authentication:** local socket/context của developer.

**Cost:** chỉ local compute/storage.

**Privacy:** sample data nằm local.

**Fallback:** cho phép user truyền connection string tới disposable database tự quản.

### PostgreSQL

**Purpose:** migration rehearsal target đầu tiên.

**Authentication:** temporary credential generated per run.

**Cost:** local container.

**Fallback:** external disposable PostgreSQL instance.

### GitHub Actions

**Purpose:** chạy pre-flight trong CI.

**Authentication:** không cần GitHub API cho MVP; chỉ chạy command trong workflow.

**Cost concern:** workflow minutes và Docker startup time.

**Fallback:** local execution.

## 12. AI có thực sự cần thiết không?

**AI is useful but optional.**

Core safety engine không nên dùng AI.

### AI task có thể thêm sau

Chuyển deterministic findings thành phần giải thích dễ hiểu:

```json
{
  "risk": "NOT_NULL_COLUMN_ON_EXISTING_TABLE",
  "severity": "high",
  "evidence": "...",
  "suggested_pattern": "expand-backfill-contract"
}
```

AI nhận:

- structured findings;
- migration SQL đã redacted;
- provider metadata;
- không cần production data.

### Validation

AI không quyết định pass/fail. Severity và exit code luôn do deterministic rules quyết định.

### Fallback

Không có API key → report vẫn đầy đủ, chỉ thiếu natural-language explanation.

### Risks

- hallucination;
- source code/privacy;
- latency;
- API cost.

Vì vậy AI không thuộc MVP.

## 14. Các bài toán kỹ thuật đáng học

### 1. Disposable infrastructure

Tạo database có lifecycle ngắn, predictable và cleanup đúng cách.

**Skill:** Testcontainers, Docker lifecycle, integration test isolation.

### 2. Schema diff normalization

Provider có metadata khác nhau. Tool phải normalize table/column/index/constraint đủ ổn định để diff.

**Skill:** database catalog, canonical representation.

### 3. Migration risk classification

Không phải `ALTER TABLE` nào cũng nguy hiểm như nhau.

**Skill:** database migration patterns, expand-contract, data backfill, backward compatibility.

### 4. Long-running operation timeout

Migration có thể treo do lock hoặc query lâu.

**Skill:** cancellation, timeout, process management, failure recovery.

### 5. CI exit semantics

Phân biệt warning, policy violation, infrastructure failure và migration failure.

**Skill:** developer-tool UX và automation design.

## 15. Rủi ro và cách xử lý

### False positives

**Risk:** report quá nhiều warning khiến developer bỏ qua tool.

**Mitigation:** chỉ 5–8 high-signal rules ở MVP; configurable severity; evidence rõ.

### Rehearsal không giống production

**Risk:** sample DB nhỏ không phản ánh lock/duration production.

**Mitigation:** định vị sản phẩm là correctness/risk rehearsal, không hứa performance prediction chính xác. Sau này hỗ trợ metadata-based scaling estimate.

### Sensitive data

**Risk:** user copy production dump vào sandbox.

**Mitigation:** docs khuyến nghị schema/sanitized fixtures; tool không yêu cầu production data; optional scanner chặn known-sensitive columns.

### Provider differences

**Risk:** PostgreSQL rules không áp dụng SQL Server.

**Mitigation:** provider-specific analyzers; chỉ PostgreSQL ở MVP.

### Docker dependency

**Risk:** CI runner không cho Docker.

**Mitigation:** hỗ trợ external disposable DB connection string.

### Scope creep

**Risk:** biến thành full database deployment platform.

**Mitigation:** không apply production, không manage release, không store secrets.

### 5 test scenario quan trọng nhất

1. Add nullable column → PASS.
2. Drop existing column → HIGH warning/fail theo policy.
3. Add NOT NULL column trên table có rows mà không có migration strategy phù hợp → migration failure hoặc high-risk finding.
4. Migration SQL lỗi giữa chừng → run FAIL và disposable DB được cleanup.
5. Tool timeout khi statement chạy quá lâu → process/container được cancel và report ghi `TIMED_OUT`.

## 20. Việc cần làm ngay hôm nay

### Development objective

Trong **60–120 phút**, tạo vertical slice đầu tiên:

```text
EF migration SQL file
→ scanner đọc SQL
→ phát hiện destructive operations
→ in Markdown report
→ trả exit code
```

Chưa cần Docker trong session đầu tiên.

### Files/components cần tạo

```text
MigrationDryRun.sln

  MigrationDryRun.Cli/
    Program.cs
    Analysis/
      MigrationAnalyzer.cs
      MigrationFinding.cs
      Rules/
        DropTableRule.cs
        DropColumnRule.cs
        AddNotNullColumnRule.cs
    Reporting/
      MarkdownReportWriter.cs
tests/
  MigrationDryRun.Tests/
```

### Setup commands

```bash
dotnet new sln -n MigrationDryRun
dotnet new console -n MigrationDryRun.Cli -o src/MigrationDryRun.Cli
dotnet new xunit -n MigrationDryRun.Tests -o tests/MigrationDryRun.Tests
dotnet sln add src/MigrationDryRun.Cli
dotnet sln add tests/MigrationDryRun.Tests
dotnet add tests/MigrationDryRun.Tests reference src/MigrationDryRun.Cli
```

### First vertical slice

Tạo sample file:

```sql
ALTER TABLE orders DROP COLUMN legacy_reference;
ALTER TABLE orders ADD COLUMN external_reference text NOT NULL;
```

Command:

```bash
dotnet run --project src/MigrationDryRun.Cli -- analyze sample.sql
```

Expected output:


### Verification checklist

- [ ] CLI nhận path SQL.
- [ ] `DROP COLUMN` được detect.
- [ ] `ADD ... NOT NULL` được detect.
- [ ] Comment/string đơn giản không tạo false positive trong test đã viết.
- [ ] Markdown report được tạo.
- [ ] Không finding → exit code `0`.
- [ ] High-severity finding → exit code khác `0`.
- [ ] Có ít nhất 5 unit tests pass.

### Stop condition

Kết thúc session khi command trên đọc được một migration SQL thật hoặc sample SQL, tạo report và CI có thể dựa vào exit code để pass/fail. Không làm Docker, PostgreSQL execution, UI, AI hoặc GitHub integration trong session đầu tiên.
