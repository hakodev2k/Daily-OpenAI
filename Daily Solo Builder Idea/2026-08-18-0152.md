# Ý tưởng hôm nay: Local AI Workflow Recorder - Trình ghi lại quy trình làm việc cá nhân

## 1. Tóm tắt ý tưởng
Một công cụ giúp developer ghi lại và chạy lại các quy trình kỹ thuật lặp lại như debug, kiểm tra API, lấy log hoặc triển khai. MVP quy mô Medium, một developer có thể hoàn thành trong 3-4 tuần.

## 2. Bài toán thực tế
Nhiều thao tác kỹ thuật lặp lại đang nằm trong trí nhớ cá nhân, terminal history hoặc tài liệu rời rạc. Khi xử lý sự cố, developer phải lặp lại nhiều bước thủ công.

## 3. Người dùng mục tiêu
.NET developer, technical lead và solo builder muốn tự động hóa workflow cá nhân mà không cần xây hệ thống enterprise.

## 4. Giải pháp đề xuất
Người dùng tạo workflow gồm các bước HTTP request, command, script và validation. Hệ thống lưu cấu hình, chạy workflow, lưu kết quả và lịch sử.

Ví dụ: Workflow "Production API Check" tự gọi health endpoint, kiểm tra database connection, lấy log và tạo báo cáo.

## 5. Tại sao đáng làm
Có giá trị ngay cho người xây dựng, đồng thời học workflow engine, background processing, security và automation. Rủi ro chính là phạm vi quá rộng nên MVP cần giới hạn loại step.

## 6. Phạm vi MVP
### Must have
- Tạo workflow.
- Chạy HTTP step.
- Lưu execution history.
- Hiển thị kết quả.

### Should have
- Scheduled execution.
- Retry policy.
- Secret storage.

### Later
- AI tạo workflow.
- Chia sẻ workflow.
- Marketplace.

## 7. Luồng hoạt động
User tạo workflow → validate → lưu database → execute step → lưu log → trả kết quả.

Step lỗi có thể retry hoặc dừng theo policy.

## 8. Kiến trúc đề xuất
Modular monolith:
- ASP.NET Core API.
- Vue frontend.
- PostgreSQL.
- Background worker.
- Logging.

Không dùng microservice trong MVP.

## 9. Công nghệ đề xuất
- .NET 10 + ASP.NET Core.
- EF Core + PostgreSQL.
- Hangfire hoặc BackgroundService.
- Docker.
- Vue.

Stack này phù hợp cho solo developer và dễ mở rộng.

## 10. Thiết kế dữ liệu ban đầu
Workflow: Id, Name, Description, CreatedAt.

WorkflowStep: Id, WorkflowId, Type, Config, Order.

Execution: Id, WorkflowId, Status, StartedAt, FinishedAt.

ExecutionLog: Id, ExecutionId, Message.

## 11. API và tích hợp
REST API nội bộ, HTTP client, local command runner. Nếu tích hợp GitHub cần OAuth và giới hạn permission.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng optional. Có thể tạo workflow draft từ mô tả tự nhiên, nhưng người dùng phải duyệt trước khi chạy.

## 13. Kế hoạch triển khai
### Phase 0
Chọn 3 workflow thực tế.

### Phase 1
Xây workflow CRUD và executor.

### Phase 2
Thêm retry, timeout, test, security.

### Phase 3
Thêm scheduler và template.

### Phase 4
Deploy self-hosted/VPS và monitoring.

## 14. Các bài toán kỹ thuật đáng học
- Workflow engine.
- Retry và idempotency.
- Secure execution.
- Background jobs.
- Audit logging.

## 15. Rủi ro và cách xử lý
Command nguy hiểm → whitelist.

Scope lớn → giới hạn step.

Log chứa secret → masking.

## 16. Kiểm thử
1. Workflow chạy thành công.
2. Step lỗi retry đúng.
3. Timeout được xử lý.
4. Secret không lộ trong log.
5. Import/export không mất dữ liệu.

## 17. Cách đo dự án hữu ích
- Số workflow sử dụng mỗi tuần.
- Thời gian tiết kiệm.
- Tỷ lệ chạy thành công.

## 18. Khả năng mở rộng
Có thể phát triển thành developer automation platform hoặc MCP automation server.

## 19. Mô hình giá trị
- Personal utility.
- Portfolio project.
- Open-source developer tool.

## 20. Việc cần làm ngay hôm nay
Trong 60-120 phút:
1. Tạo ASP.NET Core solution.
2. Tạo Workflow entity.
3. Tạo API tạo workflow.
4. Implement HTTP executor.
5. Lưu execution log.
6. Tạo trang hiển thị lịch sử chạy.

Kết quả: tạo và chạy được một workflow từ giao diện web.
