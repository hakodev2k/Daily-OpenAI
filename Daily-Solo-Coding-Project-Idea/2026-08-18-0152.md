# Ý tưởng hôm nay: Dev Memory Vault - Kho kiến thức kỹ thuật cá nhân tự đồng bộ

## 1. Tóm tắt ý tưởng
Một công cụ dành cho developer để lưu lại quyết định kỹ thuật, lỗi đã xử lý, đoạn code quan trọng, tài liệu và bài học dự án thành một kho tri thức có thể tìm kiếm. MVP tập trung vào cá nhân developer hoặc team nhỏ, quy mô Medium, có thể hoàn thành trong 2-4 tuần.

## 2. Bài toán thực tế
Developer thường gặp lại các vấn đề đã từng giải quyết nhưng mất thời gian tìm trong chat, ticket, repository hoặc bookmark. Cách lưu hiện tại thường phân tán và khó truy vấn theo ngữ cảnh.

## 3. Người dùng mục tiêu
.NET developer, technical lead hoặc solo builder cần xây dựng kiến thức dài hạn. Pain point chính là mất lại thời gian nghiên cứu những vấn đề cũ.

## 4. Giải pháp đề xuất
Người dùng nhập incident, decision, snippet hoặc tài liệu. Hệ thống lưu metadata, lập chỉ mục và cho phép tìm kiếm theo dự án, công nghệ, lỗi hoặc chủ đề. Khác biệt là tập trung vào engineering memory thay vì ghi chú chung.

Ví dụ: Sau 6 tháng, developer tìm "Exchange Online forwarding issue" và thấy lại nguyên nhân, cách fix, PowerShell command và bài học trước đây.

## 5. Tại sao đáng làm
Dự án có giá trị ngay cho chính người xây dựng. Nó giúp học search, indexing, knowledge management và AI retrieval. Rủi ro lớn nhất là biến thành ứng dụng note thông thường.

## 6. Phạm vi MVP

### Must have
- Tạo engineering note
- Tag công nghệ/project
- Full text search
- Markdown editor
- Export/import dữ liệu

### Should have
- Git integration
- Browser extension lưu tài liệu
- Semantic search

### Later
- Multi-user collaboration
- AI assistant
- Knowledge graph

## 7. Luồng hoạt động
User tạo note → validate metadata → lưu database → indexing → tìm kiếm → hiển thị kết quả.

Nếu AI/search lỗi, fallback về full text search truyền thống.

## 8. Kiến trúc đề xuất
Modular monolith:
- Frontend web
- ASP.NET Core API
- PostgreSQL
- Background worker cho indexing
- File storage cho attachment
- Logging

Không cần microservice trong MVP.

## 9. Công nghệ đề xuất
- .NET 10 / ASP.NET Core
- EF Core
- PostgreSQL + pgvector nếu cần semantic search
- Vue hoặc React
- Hangfire cho background jobs
- Docker
- GitHub Actions

## 10. Thiết kế dữ liệu ban đầu
EngineeringNote: Id, Title, Content, Project, Tags, CreatedAt.

Attachment: FileName, Path, NoteId.

Tag: Id, Name.

## 11. API và tích hợp
Có thể tích hợp GitHub API để lấy repository context. Cần OAuth token và giới hạn quyền truy cập. Fallback là nhập thủ công.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng không bắt buộc. Có thể dùng AI để tóm tắt incident, tạo tag hoặc semantic search. Output phải được kiểm tra bởi người dùng.

## 13. Kế hoạch triển khai

### Phase 0
Tạo vài chục note mẫu và kiểm tra khả năng tìm lại kiến thức.

### Phase 1
Xây CRUD note + search.

### Phase 2
Thêm test, backup, authentication.

### Phase 3
Thêm Git integration và semantic search.

### Phase 4
Deploy VPS/Azure, monitoring.

## 14. Các bài toán kỹ thuật đáng học
- Search indexing: học information retrieval.
- Background processing: học reliability.
- Data modeling: học knowledge architecture.
- AI retrieval: học RAG thực tế.

## 15. Rủi ro và xử lý
Scope phình to → giữ MVP nhỏ.

Dữ liệu cá nhân nhạy cảm → encryption và self-host option.

AI sai → luôn có manual verification.

## 16. Kiểm thử
5 scenario quan trọng:
1. Tạo note thành công.
2. Search trả đúng kết quả.
3. Import/export không mất dữ liệu.
4. Background indexing retry khi lỗi.
5. Permission không cho truy cập dữ liệu người khác.

## 17. Cách đo hữu ích
- Số lần tìm lại kiến thức thành công.
- Thời gian giảm khi debug.
- Số note được tái sử dụng.

## 18. Khả năng mở rộng
Có thể phát triển thành knowledge platform cho team engineering, AI coding assistant context server hoặc MCP server.

## 19. Mô hình giá trị
- Personal utility
- Portfolio project
- Open-source project
- Có thể phát triển SaaS cho team nhỏ.

## 20. Việc cần làm ngay hôm nay
Trong 60-120 phút:

1. Tạo solution ASP.NET Core API.
2. Tạo Vue frontend.
3. Tạo Entity EngineeringNote.
4. Implement POST/GET note.
5. Làm trang tạo và xem note.
6. Chạy Docker PostgreSQL.

Kết quả cần đạt: tạo được một note kỹ thuật và xem lại trên web.
