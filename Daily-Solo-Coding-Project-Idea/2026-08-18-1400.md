# Ý tưởng hôm nay: Personal Engineering Decision Journal

## 1. Tóm tắt ý tưởng

Một ứng dụng giúp developer ghi lại các quyết định kỹ thuật quan trọng trong dự án, lý do lựa chọn, trade-off và kết quả sau triển khai. Mục tiêu là biến kinh nghiệm phát triển phần mềm thành một hệ thống kiến thức có thể tìm kiếm và review lại.

Quy mô: Medium. MVP dự kiến 2-3 tuần.

## 2. Bài toán thực tế

Developer thường đưa ra nhiều quyết định như chọn database, kiến trúc API, thư viện, cách xử lý performance hoặc security nhưng sau vài tháng rất khó nhớ vì sao quyết định đó được đưa ra.

Hiện tại nhiều người lưu trong chat, issue, document rời rạc hoặc không lưu lại. Điều này làm mất kiến thức dự án và khiến team dễ lặp lại tranh luận cũ.

## 3. Người dùng mục tiêu

Primary user: Senior developer, technical lead hoặc software architect.

Pain point: cần duy trì lịch sử quyết định kỹ thuật khi dự án kéo dài nhiều tháng hoặc nhiều năm.

## 4. Giải pháp đề xuất

Người dùng tạo một Decision Record:

Input:
- Problem
- Context
- Options
- Decision
- Trade-offs
- Expected impact

System lưu trữ, liên kết với repository, issue hoặc release.

Ví dụ: Developer chọn PostgreSQL thay SQL Server. Sau 6 tháng có thể xem lại lý do, benchmark và kết quả thực tế.

Differentiator: tập trung vào engineering decisions thay vì ghi chú chung.

## 5. Tại sao đáng làm

Giá trị thực tế cao cho chính developer sử dụng hàng ngày. Đây cũng là project tốt để học knowledge management, search, audit history và AI hỗ trợ phân tích.

Điểm thất bại lớn nhất: nếu workflow nhập liệu quá mất thời gian, developer sẽ không dùng.

## 6. Phạm vi MVP

### Must have
- Tạo và quản lý Decision Record
- Tag theo project, technology
- Search
- Markdown editor
- Export Markdown

### Should have
- GitHub integration
- Timeline theo project
- Review reminder

### Later
- Team collaboration
- AI summary
- Decision quality scoring

## 7. Luồng hoạt động

User tạo quyết định → validation dữ liệu → lưu database → index tìm kiếm → hiển thị timeline → export hoặc chia sẻ.

Failure cases:
- Conflict khi nhiều người sửa record
- Mất dữ liệu export
- Repository không còn tồn tại

## 8. Kiến trúc đề xuất

Modular monolith:

- Frontend: Vue hoặc React
- Backend: ASP.NET Core Web API
- Database: PostgreSQL
- Search: PostgreSQL Full Text Search trước, Elasticsearch khi cần
- Background worker: xử lý export và đồng bộ GitHub
- Storage: local/S3 compatible storage cho attachment

Không cần microservice.

## 9. Công nghệ đề xuất

- .NET 10 / ASP.NET Core: phù hợp với backend business application
- EF Core: quản lý dữ liệu nhanh
- PostgreSQL: hỗ trợ JSONB và full-text search
- Vue: nhanh cho dashboard nội bộ
- Docker + GitHub Actions: deployment đơn giản

## 10. Thiết kế dữ liệu ban đầu

DecisionRecord:
- Id
- Title
- Context
- Problem
- Decision
- Consequences
- Status
- CreatedBy
- CreatedAt

Project:
- Id
- Name
- RepositoryUrl

Tag:
- Id
- Name

Relationship:
Project 1-n DecisionRecord.

## 11. API và tích hợp

Có thể tích hợp:
- GitHub API: lấy repository metadata
- OpenAI API: hỗ trợ tóm tắt hoặc review decision (optional)

Fallback: hệ thống vẫn hoạt động độc lập.

## 12. AI có thực sự cần thiết không?

AI hữu ích nhưng optional.

AI có thể:
- Tóm tắt decision dài
- Phát hiện missing trade-off
- Gợi ý câu hỏi review

Không dùng AI để thay thế quyết định của developer.

## 13. Kế hoạch triển khai

### Phase 0 — Validation
Tạo 20 decision records cá nhân và kiểm tra khả năng tìm lại thông tin.

### Phase 1 — Core MVP
Build CRUD, markdown editor, search.

### Phase 2 — Reliability
Thêm auth, tests, backup, audit log.

### Phase 3 — Expansion
GitHub integration, AI assistant.

### Phase 4 — Production
Deploy, monitoring, documentation.

## 14. Các bài toán kỹ thuật đáng học

1. Search và indexing — học information retrieval.
2. Audit history — học event tracking.
3. Git integration — học API synchronization.
4. AI structured output — học AI workflow validation.

## 15. Rủi ro và xử lý

- Scope quá lớn → giữ MVP cá nhân trước.
- Không ai nhập dữ liệu → tối ưu workflow dưới 1 phút.
- Privacy → hỗ trợ self-host.

## 16. Kiểm thử

5 scenario quan trọng:
1. Tạo decision record.
2. Search theo technology.
3. Export Markdown.
4. Restore backup.
5. Permission validation.

## 17. Đo độ hữu ích

Metrics:
- Số decision được tạo mỗi tháng.
- Thời gian tìm lại quyết định cũ.
- Số lần tránh được việc phân tích lại vấn đề.
- Search success rate.

## 18. Khả năng mở rộng

- Internal engineering knowledge base.
- Open-source ADR platform.
- Plugin cho IDE.
- Integration với Jira/GitHub.

## 19. Mô hình giá trị

- Personal utility.
- Portfolio project.
- Có thể phát triển thành SaaS cho team nhỏ.

## 20. Việc cần làm ngay hôm nay

Trong 60-120 phút:

1. Tạo solution ASP.NET Core Web API.
2. Tạo PostgreSQL database.
3. Tạo entity DecisionRecord.
4. Implement POST/GET API.
5. Tạo trang Vue hiển thị danh sách decision.

Kết quả cần đạt:
- Có thể tạo một quyết định kỹ thuật.
- Có thể xem lại trên UI.
- Có dữ liệu lưu thật trong database.

Stop condition: hoàn thành một vertical slice từ UI → API → Database.
