# Ý tưởng hôm nay: Personal API Contract Guardian

## 1. Tóm tắt ý tưởng
Một công cụ dành cho developer giúp theo dõi sự thay đổi của API contract giữa các phiên bản backend, phát hiện breaking change trước khi deploy và tạo báo cáo dễ hiểu. Dự án Medium, MVP khoảng 2-4 tuần.

## 2. Bài toán thực tế
Developer thường thay đổi DTO, endpoint, validation hoặc response structure nhưng không nhận ra ảnh hưởng tới client khác. MVP giả định tập trung vào các dự án cá nhân hoặc team nhỏ.

## 3. Người dùng mục tiêu
.NET backend developer hoặc team nhỏ cần bảo vệ REST API khỏi thay đổi ngoài ý muốn.

## 4. Giải pháp đề xuất
Import OpenAPI specification của hai phiên bản API, so sánh contract, phát hiện thay đổi và sinh báo cáo. Ví dụ trước khi merge PR, developer chạy tool để biết endpoint nào bị đổi response.

## 5. Tại sao đáng làm
Có giá trị ngay cho chính developer xây dựng API. Học thêm API governance, versioning, CI/CD integration. Rủi ro lớn nhất là cạnh tranh với các công cụ contract testing hiện có.

## 6. MVP
### Must have
- Import OpenAPI JSON
- Compare hai version
- Detect breaking changes
- Generate Markdown report

### Should have
- GitHub Action
- Pull request comment
- Ignore rules

### Later
- AI explanation
- Dashboard lịch sử API
- Team management

## 7. Luồng hoạt động
Developer upload spec cũ và mới → validate → compare schema → lưu kết quả → tạo report → trả cảnh báo.

## 8. Kiến trúc đề xuất
Modular monolith gồm Web UI, ASP.NET Core API, PostgreSQL, background worker cho scan định kỳ. Không cần microservice.

## 9. Công nghệ đề xuất
.NET 8/9, ASP.NET Core, EF Core, PostgreSQL, Vue, Docker, GitHub Actions. Có thể thay Vue bằng Blazor nếu muốn giảm frontend.

## 10. Thiết kế dữ liệu
Project, ApiSpec, ComparisonRun, ChangeRule, Report. Lưu metadata và lịch sử so sánh.

## 11. API và tích hợp
OpenAPI parser, GitHub API, CI pipeline. Fallback là chạy CLI local.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng không bắt buộc. Có thể dùng để giải thích breaking change bằng ngôn ngữ tự nhiên; kết quả phải kiểm tra dựa trên rule engine.

## 13. Kế hoạch triển khai
Phase 0: thử với một API cá nhân.
Phase 1: parser và compare engine.
Phase 2: test, logging, CI.
Phase 3: GitHub integration.
Phase 4: deploy và documentation.

## 14. Bài toán kỹ thuật đáng học
- Schema diff engine
- Semantic versioning
- CI automation
- Rule validation
- Large specification handling

## 15. Rủi ro và xử lý
False positive → cho phép custom rules. Scope lớn → chỉ hỗ trợ REST/OpenAPI trước.

## 16. Kiểm thử
Test schema change, removed endpoint, changed type, auth change, invalid document.

## 17. Đo hiệu quả
Số breaking change phát hiện, thời gian review giảm, số lần rollback giảm.

## 18. Khả năng mở rộng
GraphQL support, SDK generation, enterprise policy.

## 19. Mô hình giá trị
Portfolio project, open-source, có thể phát triển thành developer SaaS.

## 20. Việc cần làm ngay hôm nay
Tạo solution .NET gồm ApiGuardian.Api và ApiGuardian.Core, thêm OpenAPI parser, tạo command nhận hai file JSON và in ra danh sách thay đổi đầu tiên. Hoàn thành khi chạy được một comparison thực tế từ terminal.
