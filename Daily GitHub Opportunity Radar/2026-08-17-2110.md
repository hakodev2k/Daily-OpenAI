## 5. Tool I Can Apply Today

**Tool:** `unclecode/toolshrink`  
**Problem it solves:** giảm tool output cho agent theo cấu trúc/ý nghĩa thay vì cắt head/tail mù.  
**Relevant workflow:** AI-assisted debugging, CI/test analysis, Playwright QA, build/log review, multi-agent coding workflows.  
**Adoption difficulty:** Easy–Moderate  
**Production readiness:** Experimental  

**Where it fits:** đặt giữa tool execution và LLM context. Với workflow .NET, có thể feed output `dotnet test`, `dotnet build`, Playwright, Docker logs hoặc CI logs qua reducer trước khi chuyển cho agent.

**What it could improve:** giảm token waste, giữ failure lines/summary, giảm khả năng agent đọc phần “pass spam” nhưng mất lỗi ở giữa.

**Integration approach:** bắt đầu như standalone library/process trong một QA/CI-agent experiment. Không cần thay toàn bộ agent runtime; chỉ intercept output ở một tool path trước.

**Required permissions/data access:** local filesystem nếu bật spill store; adapter cần quyền đọc tool result và thay response trước khi vào model context.

**Privacy/security concerns:** full raw output được spill xuống disk có thể chứa secrets, HTTP headers hoặc personal data. Cần retention ngắn, directory permission chặt và cân nhắc redaction trước khi spill.

**Maintenance burden:** thấp nếu chỉ dùng built-in reducers; tăng nếu tự viết reducer cho `dotnet test`, MSBuild, Azure DevOps logs hoặc custom app logs.

**Smallest proof of concept:** dùng một output `dotnet test` 10k–50k chars có 1–3 failing tests, cap xuống 2k–5k chars, sau đó hỏi cùng một model xác định root cause từ bản raw-truncated và bản semantic-reduced.

**How it maps to current tools:**
- **Codex / Claude Code:** hiện chưa có adapter chính thức trong repo; có thể dùng như preprocessing layer trong script/tool wrapper.
- **GitHub Actions / Azure DevOps:** dùng reducer trên logs trước khi gửi sang AI review agent.
- **Playwright / QA agents:** reducer `tests`, `stacktrace`, `log` phù hợp trực tiếp.
- **MCP:** pattern rất phù hợp để bổ sung một response-budget middleware trước khi tool result được serialize cho model.

## 6. Product or Learning Opportunity

### Developer tool idea — Agent Context Budget Gateway

**Problem:** Tool servers thường trả full payload; truncation hiện tại thường chỉ cắt theo char/token count, dễ mất failure/context quan trọng.

**Intended user:** developers xây MCP servers, QA agents, coding agents hoặc internal automation có tool output lớn.

**Why opportunity may exist:** `toolshrink` cho thấy semantic reduction hữu ích ở client/runtime layer, trong khi Vayu #767 cho thấy một MCP implementation thật có thể blow up context vì response body không bounded.

**Smallest version:**
- proxy/wrapper nhận tool result;
- classify `json/test/build/log/diff/http`;
- enforce byte/token budget;
- thêm `truncated`, `originalBytes`, `strategy`, `artifactRef`;
- optional local artifact store để agent fetch full output có chủ đích.

**Worth exploring now?** Có ở mức learning/open-source prototype. Chưa có đủ bằng chứng để coi là Micro-SaaS, nhưng đây là bài tập rất tốt về context engineering, tool contracts, observability và failure recovery.
