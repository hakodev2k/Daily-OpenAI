## 3. Important Release or Update

### Microsoft Agent Framework — .NET `StreamingRun.WatchStreamAsync()` reliability report

**Release date:** Không phải release; issue được mở ngày **17/08/2026 19:30 UTC+7**.  
**Release type:** Reliability / Integration  
**Action:** **Investigate**  
**Source:** https://github.com/microsoft/agent-framework/issues/7694

**Confirmed facts:** Issue author báo cáo `StreamingRun.WatchStreamAsync()` trên `Microsoft.Agents.AI.Workflows 1.13.0` có thể ngừng yield event sau một executor turn dài dù executor đã hoàn thành thành công. Hai trường hợp được mô tả gồm turn khoảng 10 phút; không có `WorkflowFailedEvent`, `RequestInfoEvent`, terminal event hay exception. Môi trường được nêu là .NET 10, macOS Apple Silicon và Linux CI, dùng `InProcessExecution` với OpenAI-compatible local endpoint. Tại thời điểm kiểm tra issue còn open, chưa assigned, chưa có maintainer response và chưa thấy open PR liên quan.

**Analysis:** Đây là failure mode nguy hiểm hơn exception thông thường vì consumer đang dùng `await foreach` có thể không phân biệt “workflow đang chạy” với “event stream đã mất tiến triển”. Với long-running agent, background orchestration hoặc CI agent, silence không nên được coi là trạng thái hợp lệ vô thời hạn.

**Opportunity:** Dùng issue này làm checklist kiến trúc cho mọi agent runner của riêng mình:

- durable event trace thay vì chỉ giữ event trong memory;
- explicit heartbeat/progress timestamp;
- bounded silence timeout;
- cooperative cancellation trước hard-kill;
- terminal state phải được xác nhận bằng durable state/event, không suy luận từ việc stream im lặng.

**Risk or uncertainty:** Đây hiện là bug report từ user, chưa phải maintainer-confirmed defect. Issue chưa có minimal isolated reproduction và chính tác giả cũng nói duration correlation mới chỉ là giả thuyết. Không nên kết luận `WatchStreamAsync()` nói chung bị lỗi cho mọi workload.

**Should test now?** Có, nếu đang thử Microsoft Agent Framework cho long-running workflow. Một sandbox test với executor giả lập sleep 30s/2m/5m và event timestamps có giá trị hơn việc upgrade production ngay.

**Problem:** Hai signal độc lập hôm nay cùng chỉ vào một vấn đề: WorkTime #7 cho thấy subagent có thể thao tác nhầm state của parent; DAM #3350 cho thấy GitHub chỉ ghi identity của agent credential, không ghi human initiator. **Intended user:** team dùng Claude Code/Codex/shared Slack agents/MCP agents để tạo issue, PR, comment, deploy hoặc thay đổi external systems.

**Why opportunity may exist:** Agent systems ngày càng có nhiều actor: human initiator, main agent, subagent, tool credential, approver. Nhiều integration vẫn chỉ audit “credential nào gọi API”, không audit “ai yêu cầu, agent nào thực thi, ai approve”.

**Smallest version:** một local/server middleware tạo immutable action envelope:

`human_initiator -> parent_run -> subagent_run -> tool_call -> approval -> external_action`

và inject một signed attribution block vào GitHub issue/PR/comment, đồng thời lưu ledger riêng. Không cần xây agent framework mới.

**Worth exploring now:** **Yes, as a learning/open-source project**, đặc biệt vì có thể implement bằng ASP.NET Core + PostgreSQL/SQLite và gắn vào GitHub/MCP workflow hiện có. Chưa nên thành SaaS trước khi xác nhận nhu cầu ở nhiều team.
