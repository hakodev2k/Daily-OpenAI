### dweigend/joplin-mcp-server — security issue #10

**Update date:** 2026-08-19 06:04:47 UTC, tương đương 13:04:47 UTC+7  
**Release type:** **Security**  
**Action:** **Investigate / Monitor patch**  
**Issue:** https://github.com/dweigend/joplin-mcp-server/issues/10

**Confirmed facts from the issue report:**
- Joplin Data API authentication dùng `token` query parameter, vì vậy token nằm trong request URL.
- Reporter chỉ ra `src/joplin/joplin_api.py`, `JoplinAPI._make_request` đang log/re-raise raw `requests` exceptions ở timeout/request-error branches.
- `requests`/`urllib3` exception có thể chứa full URL, bao gồm query string.
- MCP tool handlers của project có đường trả error text về caller, vì vậy reporter cảnh báo cùng secret có thể xuất hiện cả trong log và response về MCP client.
- Issue hiện **open**, chưa có assignee, 0 comments tại thời điểm kiểm tra.
- Reporter nói họ đã có implementation trong downstream fork và sẵn sàng mở PR.

**Analysis:**
- Nếu behavior được maintainer xác nhận, impact đáng quan tâm hơn một generic log leak vì MCP client/agent có thể đưa error text tiếp vào model context, trace hoặc downstream observability.
- Pattern này không riêng Joplin: bất kỳ MCP integration nào dùng API key/token trong URL đều cần sanitize exception, telemetry và tool error payload.

**Who is affected:**
- Người chạy `joplin-mcp-server` với Joplin Data API token.
- Agent clients lưu transcript/tool results hoặc centralized logs.

**Compatibility / migration concern:**
- Fix nên giữ actionable error message nhưng loại token khỏi exception chain; nếu chỉ `replace()` ở log mà vẫn re-raise original exception, traceback hoặc higher-level handler vẫn có thể lộ URL.

**Security / operational risk:**
- Đây mới là issue report; chưa có maintainer confirmation hoặc merged patch tại thời điểm rà soát.
- Không nên log hoặc copy raw reproduction output có token thật trong quá trình test.

**Nên test ngay?** Nếu đang dùng project này, **có**: test với fake token trong isolated environment và kiểm tra cả console log, structured logs, MCP error payload và traceback. Nếu không dùng project, nên lấy đây làm security checklist item cho mọi MCP/API integration của mình.

### Integration idea — `.NET MCP Capability Snapshot & Semantic Diff`

**Inspiration:** https://github.com/dgenio/contextweaver/issues/856

**Problem:** Khi MCP/OpenAPI tool definitions thay đổi, Git text diff không trả lời trực tiếp “agent vừa mất tool nào?”, “argument nào vừa trở thành required?”, “change này breaking hay documentation-only?”.

**Intended user:** .NET teams xây AI agents, MCP servers, internal APIs hoặc CI/CD cho tool contracts.

**Why the opportunity may exist:** ContextWeaver issue #856 mô tả một D1 slice rất cụ thể: deterministic snapshot + semantic diff cho MCP/OpenAPI capability surface, không execute tools và không cần model/provider account. Đây là một problem shape có thể triển khai độc lập trong .NET.

**Smallest version:**
- CLI .NET: `snapshot`, `diff`, `verify`.
- Input đầu tiên: MCP `tools/list` JSON fixture hoặc OpenAPI document.
- Canonical JSON sorted deterministically.
- Diff categories: added/removed, required argument changes, type/enum changes, description-only.
- GitHub Action fail khi có `contract_breaking` change mà PR chưa acknowledge.

**Worth exploring now:** **Yes, như learning/open-source project**. Chưa cần biến thành SaaS; giá trị đầu tiên là CI artifact rõ ràng cho agent-tool contract changes.
