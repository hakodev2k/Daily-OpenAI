**Opportunity:** Với các agent review/QA của riêng bạn, nên ưu tiên structured status (`status`, `code`, typed event, JSON schema, HTML sentinel có contract) thay vì dò câu chữ từ model output.

**Tool:** `nicobailon/pi-subagents`  
**Repository:** https://github.com/nicobailon/pi-subagents  
**Problem it solves:** Delegation sang focused child agents cho scouting, implementation, code review, parallel audits, research và saved workflows.  
**Relevant workflow:** AI-assisted development / multi-agent review loop  
**Adoption difficulty:** Moderate  
**Production readiness:** Unclear — nên coi là development tooling và sandbox-evaluate trước khi phụ thuộc vào nó cho critical automation.

**Confirmed facts từ README:**

- Cài qua `pi install npm:pi-subagents`.
- Built-in agents gồm `scout`, `researcher`, `worker`, `reviewer`, `oracle`, `delegate`.
- README đề xuất loop `clarify → scout → worker → fresh reviewers → worker`.
- Có parallel reviewers, foreground/background runs, FleetView, observability artifacts, bounded spawn count và docs riêng cho model fallbacks, watchdog, workflows và extension API.
- README nói `maxSubagentSpawnsPerRun` mặc định 64 và tách biệt với active concurrency/session-wide spawn budget.

**Analysis:** Tool đáng test không phải vì “nhiều agent hơn”, mà vì nó cho một reference implementation khá rõ về separation of roles, fresh reviewer context, orchestration budget và observability — những thứ có thể chuyển thành rules/workflows cho Cursor, Claude Code hoặc Codex dù bạn không dùng Pi lâu dài.

**Integration approach:** Không cần tích hợp trực tiếp vào .NET app. Dùng nó ở developer workflow trên một repo sandbox hoặc một branch nhỏ; sau đó port các pattern hữu ích sang `.claude/`, repository instructions, GitHub Actions hoặc custom agent runner.

**Permissions/data access:** Các child agents có thể đọc/edit repo hoặc gọi tools tùy cấu hình. Cần xem kỹ child tool permissions, background run behavior và model/provider credentials trước khi cho chạy trên repo công việc.

**Privacy/security concerns:** Không đưa secret, production config hoặc privileged MCP tools vào thử nghiệm đầu tiên. Model fallback và background orchestration có thể làm dữ liệu đi qua provider khác nếu cấu hình fallback không được kiểm soát rõ.

**Maintenance burden:** Moderate — multi-agent workflow cần budget, stop conditions, review loop cap, provider fallback và observability; issue #1215 cho thấy ngay cả một error phrase cũng có thể phá degradation path.

### Smallest proof of concept

Trong 45–60 phút:

1. Clone một repo cá nhân nhỏ hoặc tạo branch sandbox.
2. Cài `pi-subagents`.
3. Cho `scout` phân tích một flow nhỏ, ví dụ ASP.NET Core endpoint + service + EF Core query.
4. Cho `reviewer` chạy hai góc song song: correctness và tests.
5. So sánh output với workflow hiện tại của Claude Code/Codex/Cursor: context usage, duplicate findings, thời gian, chất lượng actionable feedback.
6. Chỉ tiếp tục nếu orchestration giúp giảm thao tác thủ công mà không tạo quá nhiều duplicate work hoặc provider cost.

### Developer tool idea — `Agent Context Drift Checker`

**Problem:** `AGENTS.md`, `CLAUDE.md`, `copilot-instructions.md`, `.cursor/rules`, architecture docs và prompt assets thường chứa version, path, test counts, command hoặc trạng thái migration. Khi repo thay đổi, các câu này stale nhưng vẫn được AI agent xem như authoritative context.

**Intended user:** Team dùng Cursor, Claude Code, Codex, Copilot hoặc custom coding agents trên repo sống lâu.

**Why the opportunity may exist:** `GEWIS/gewisweb#2164` là một tín hiệu cụ thể: repo instruction có thể tự mâu thuẫn với source-of-truth như `composer.json` và test tree, và agent sau đó làm việc dựa trên thông tin sai.

**Smallest version:** CLI đọc các instruction files, detect các claim có thể kiểm chứng như package/runtime version, referenced path/file tồn tại hay không, command/package name, test directory existence; compare với repo hiện tại và emit Markdown/JSON warnings trong CI. Không cần LLM cho các check deterministic đầu tiên.

**Worth exploring now:** **Yes, ở mức learning/personal tool.** Đây là bài tập tốt về static analysis, source-of-truth hierarchy, repository metadata và agent context engineering. Nếu làm bằng .NET CLI, nó cũng khớp trực tiếp với stack hiện tại.

**Risk:** Không nên cố tự động “sửa” prose bằng AI ngay từ đầu; false-positive/false-edit có thể nguy hiểm hơn drift. Bản đầu chỉ nên detect và report.
