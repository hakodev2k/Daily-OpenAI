## 3. Important Release or Update

### Gentleman-Programming/gentle-ai — Issue #3411: Delegation contract is prose-only

**Release date:** 2026-08-17 21:00 VN (issue created 14:00:36 UTC)  
**Release type:** Feature / Reliability design update  
**Action:** Investigate

Source: https://github.com/Gentleman-Programming/gentle-ai/issues/3411

**Confirmed facts:** issue báo cáo trên `gentle-ai 2.4.0-rc.8` + OpenCode 1.17.20 rằng orchestrator được mô tả là coordinator nhưng vẫn có unrestricted `bash`, `edit`, `write`, `read`. Báo cáo đo một cửa sổ khoảng 10 ngày với 26 orchestrator sessions và 106 subagent sessions. Orchestrator chiếm 594M cache-read tokens, khoảng 72% tổng cache-read; một agent có 2,167 direct tool calls so với 53 `task` delegations. Worst case là session 689 turns, ~194M cache-read, 0 delegations. Issue hiện **open**, không assigned, 0 comments.

**Analysis:** đây là một ví dụ thực tế rất mạnh cho nguyên tắc “policy written in prompts is not enforcement”. Agent càng chạy lâu, prompt-only delegation rules càng dễ bị instruction drift; nếu orchestrator có đủ quyền thực thi thì nó có xu hướng tự làm thay vì giữ context mỏng.

**Opportunity:** áp dụng ngay vào agent architecture của riêng mình bằng cách tách **coordinator permissions** khỏi **worker permissions**, đặt hard budget cho turn/context, và trigger handoff/compaction trước khi session trở thành “marathon”. Với .NET/QA agents, có thể buộc orchestrator chỉ được `task`, read summary và approve/reject, còn build/test/edit chạy trong worker riêng.

**Risk or uncertainty:** issue chưa có maintainer response và nội dung issue nói rõ PR có thể bị reject nếu linked issue chưa có `status:approved`; tại thời điểm fetch không thấy label đó. Vì vậy đây chưa phải contribution target tốt ngay bây giờ.

### nimbuscloud-ai/suss — Issue #424: Align runtime vocabulary with OpenTelemetry Semantic Conventions

**Release date:** 2026-08-17 21:00 VN (issue created 14:00:53 UTC)  
**Release type:** Integration / Architecture  
**Action:** Test

Source: https://github.com/nimbuscloud-ai/suss/issues/424

**Confirmed facts:** issue đề xuất map các khái niệm riêng như `storage.storageSystem`, `storage.scope`, `storage.container`, `message-bus.channel`, REST route sang `db.system.name`, `db.namespace`, `db.collection.name`, `messaging.destination.name`, `http.route`, `service.name` và `cloud.resource_id` khi OpenTelemetry đã có semantic term tương ứng. OpenTelemetry hiện duy trì Semantic Conventions như một vocabulary chuẩn chung cho traces, metrics, logs, resources và các domain như database, messaging, HTTP, CI/CD và .NET. Official sources: https://opentelemetry.io/docs/specs/semconv/ và https://opentelemetry.io/docs/specs/semconv/dotnet/

**Analysis:** đây không chỉ là naming cleanup. Nếu architecture inventory dùng cùng vocabulary với runtime traces, ta có thể so sánh “service có thể gọi gì” với “service thực sự đã gọi gì” mà giảm mapping thủ công.

**Opportunity:** thử một mini “architecture-to-trace contract” cho ASP.NET Core: mô tả outbound DB/API/message-bus dependencies bằng OTel semantic keys rồi đối chiếu với traces thực tế trong test hoặc staging.

**Risk or uncertainty:** một số Semantic Convention groups vẫn ở trạng thái Development/Mixed; không nên hard-code toàn bộ thành public contract bất biến mà không theo dõi stability/versioning.

## 5. Tool I Can Apply Today

**Tool:** OpenTelemetry Semantic Conventions  
**Problem it solves:** chuẩn hóa tên attributes/operations giữa code, architecture metadata, traces, metrics và logs  
**Relevant workflow:** ASP.NET Core observability, distributed systems, API/DB/message-bus tracing, architecture review  
**Adoption difficulty:** Easy–Moderate  
**Production readiness:** Mixed — OpenTelemetry ecosystem mature, nhưng từng semantic convention group có stability riêng

Official sources: https://opentelemetry.io/docs/specs/semconv/ và https://opentelemetry.io/docs/specs/semconv/dotnet/

**Where it fits:** trong .NET service có `ActivitySource`, OpenTelemetry SDK/exporter hoặc Azure Monitor/OpenTelemetry pipeline, dùng semantic names chuẩn cho HTTP, DB, messaging và service resources thay vì invent custom attributes trùng nghĩa.

**What it improves:** giảm vocabulary drift giữa teams/tools và mở đường cho automated checks như “declared dependency vs observed dependency”.

**Integration approach:** bắt đầu từ một ASP.NET Core service; inventory các custom tags hiện tại rồi map sang semconv stable/recommended tương ứng. Không đổi tất cả cùng lúc.

**Permissions/data access:** không yêu cầu quyền đặc biệt ngoài telemetry pipeline hiện có; dữ liệu traces có thể chứa URL, DB metadata hoặc identifiers nên vẫn cần scrub/retention policy.

**Privacy/security:** tránh record SQL text, secrets, auth headers hoặc PII chỉ vì semantic schema có chỗ để attach attributes.

**Maintenance burden:** thấp nếu chỉ dùng conventions stable; cao hơn nếu bám các attributes Development và phải migrate khi spec thay đổi.

### Smallest proof of concept

Trong 60 phút, chọn một ASP.NET Core API có PostgreSQL/SQL Server và một outbound HTTP call. Liệt kê custom telemetry attributes hiện tại, map chúng sang các semantic names chính thức, chạy một request end-to-end và kiểm tra trace có thể được query nhất quán theo `service.name`, HTTP route và DB system. Nếu việc query/correlation rõ ràng hơn mà không tăng telemetry noise, đáng mở rộng sang message bus và background jobs.
