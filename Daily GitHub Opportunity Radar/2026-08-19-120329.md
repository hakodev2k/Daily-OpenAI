## 3. Important Release or Update

### Model Context Protocol C# SDK — v2.0.0

**Release date:** 2026-07-28  
**Release type:** Breaking change / Feature / Integration  
**Action:** **Test before upgrade**  
**Release:** https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.0.0

**Confirmed facts from release notes:**
- v2.0.0 stable align với MCP `2026-07-28` specification.
- `HttpServerTransportOptions.Stateless` mặc định chuyển sang `true`.
- Stateless HTTP dùng discovery-first negotiation thay cho legacy `initialize` session flow.
- Release thêm multi-round-trip requests, caching hints, standardized headers, OAuth/token-cache hardening và dedicated extension packages cho MCP Apps/Tasks.
- SDK vẫn có down-level interoperability với peers dùng protocol `2025-11-25` và cũ hơn.

**Analysis:**
- Đây là thay đổi architecture đáng kể cho .NET MCP server: server nào đang dựa vào transport session state hoặc unsolicited server-to-client requests cần review kỹ trước khi nâng.
- Stateless-by-default phù hợp hơn với scale-out ASP.NET Core, container/Kubernetes và serverless patterns vì giảm coupling vào in-memory session transport.
- Với background agent hoặc MCP server tích hợp Azure, đây là thời điểm tốt để tách application state khỏi transport state.

**Who is affected:**
- .NET MCP server/client đang dùng `modelcontextprotocol/csharp-sdk` 1.x hoặc preview 2.x.
- Server dùng Streamable HTTP, stateful sessions, sampling/logging/roots legacy capabilities hoặc experimental Tasks APIs.

**Compatibility / migration concerns:**
- Nếu hệ thống cần legacy stateful behavior, phải chủ động đặt `Stateless = false` và kiểm tra warnings/compatibility.
- Experimental APIs từ preview có breaking changes; không nên chỉ bump NuGet rồi deploy.
- Cần integration-test cả old client/new server và new client/old server nếu hệ thống có mixed versions.

**Security / operational risk:**
- OAuth và token-cache behavior được harden; custom auth code nên được retest thay vì assume semantics cũ.
- Stateless transport không tự giải quyết business/session state; application vẫn phải quản lý explicit state handles hoặc persistence đúng cách.

**Nên test ngay?** **Có**, trong sandbox hoặc branch riêng nếu đang xây MCP bằng C#.

## 5. Tool I Can Apply Today

**Tool:** `mcp-probe`  
**Repository:** https://github.com/itguruhaseeb/mcp-probe  
**Problem it solves:** Phát hiện MCP server handshake/schema/latency problems trước khi một LLM gặp lỗi lúc runtime.  
**Relevant workflow:** MCP server development, CI, QA agent infrastructure.  
**Adoption difficulty:** Easy  
**Production readiness:** Experimental / Early

**Confirmed facts:**
- CLI chạy trực tiếp qua `npx @hafsar/mcp-probe -- <server-command>`.
- Nó kiểm tra `initialize`, `tools/list`, JSON Schema, resources/prompts và latency.
- `--call` chỉ round-trip các tool không có required parameters, để giảm nguy cơ tự fabricating destructive arguments.
- `--json` tạo output dùng được trong CI và process exit non-zero khi có hard failure.
- README hiện có per-request `--timeout <ms>` mặc định 10000 ms.
- Repository metadata ghi nhận push mới ngày 2026-08-19, MIT license; current footprint nhỏ nên không có cơ sở gọi nó production-proven.

**Where it fits:**
- Chạy ngay sau build/test của MCP server.
- Có thể thêm như smoke-test job trước khi publish Docker image/NuGet/app deployment.
- Hữu ích đặc biệt nếu tool schemas được generate từ C#/attributes và dễ drift sau refactor.

**Integration approach:**
- .NET MCP server dùng stdio: build project rồi chạy `mcp-probe` trỏ vào `dotnet run --project ...` hoặc executable publish output.
- GitHub Actions/Azure DevOps: dùng `--json`, lưu report artifact và fail pipeline khi schema invalid.
- Với HTTP-only MCP server, hiện README nói roadmap mới dự kiến thêm HTTP/SSE backends; vì vậy không nên assume tool đã cover transport đó.

**Required permissions / data access:** Chỉ cần quyền khởi chạy target server và đọc stdio; `--call` nên chỉ bật với test server hoặc tool set đã review.

**Privacy/security concerns:**
- Không chạy `--call` lên MCP server production có tool side effects chỉ vì tool không có required args.
- CI logs có thể chứa server metadata/tool descriptions; cần scrub nếu descriptions chứa internal details.

**Maintenance burden:** Low cho PoC; Medium nếu dùng làm hard CI gate vì cần pin version và review behavior khi MCP protocol thay đổi.

### Smallest proof of concept — 20–40 phút

- Chạy tool trên một MCP server local hiện có.
- Lưu `--json` output.
- Cố tình sửa một `inputSchema.required` trỏ tới property không tồn tại.
- Xác nhận probe fail và CI/local command trả non-zero.

**Expected result:** Có một lightweight protocol/schema gate trước integration test bằng LLM thật.  
**Worth further investigation if:** Nó bắt được schema regressions nhanh hơn agent-level tests và output JSON đủ ổn định để lưu như CI artifact.
