### Model Context Protocol C# SDK v2.2.0

**Release date:** 2026-08-13  
**Release type:** Feature / Compatibility / Integration  
**Action:** Test  

**Confirmed facts:** GitHub release `v2.2.0` được publish ngày 2026-08-13 và phát hành các package `ModelContextProtocol`, `ModelContextProtocol.Core`, `ModelContextProtocol.AspNetCore` cùng các extension packages. So sánh `v2.1.0...v2.2.0` cho thấy 9 commits và thêm mới `src/ModelContextProtocol.AspNetCore/HttpServerSessionMode.cs`, các test hybrid-session/stateful-fallback, thay đổi `StreamableHttpHandler`, `HttpServerTransportOptions` và tài liệu stateless/transports. Sources: https://github.com/modelcontextprotocol/csharp-sdk/releases/tag/v2.2.0 và https://github.com/modelcontextprotocol/csharp-sdk/compare/v2.1.0...v2.2.0

`HttpServerSessionMode` xác nhận ba mode:

- `Stateless`: không giữ state giữa requests, phù hợp load balancing không cần session affinity; một số server-to-client capabilities bị vô hiệu hóa.
- `Stateful`: server giữ long-lived session cho client; protocol 2026-07-28+ bị từ chối để dual-path client downgrade về flow `initialize`.
- `StatefulForInitializeClients`: client cũ dùng `initialize` nhận stateful session, còn client protocol 2026-07-28+ chạy stateless trên cùng endpoint.

Source: https://github.com/modelcontextprotocol/csharp-sdk/blob/v2.2.0/src/ModelContextProtocol.AspNetCore/HttpServerSessionMode.cs

**Analysis:** Đây là thay đổi rất thực tế nếu bạn xây MCP server trên ASP.NET Core. Vấn đề không chỉ là “upgrade SDK”, mà là quyết định server có giữ session affinity hay phục vụ song song client cũ/mới. Hybrid mode giúp migration dần mà không ép mọi client đổi cùng lúc.

**Opportunity:** Dựng một ASP.NET Core MCP sandbox với hai client profile: một client legacy `initialize`, một client protocol 2026-07-28+, rồi quan sát headers, GET/DELETE behavior và routing khi chạy sau reverse proxy/load balancer.

**Risk or uncertainty:** Nếu application đang dựa vào sampling, elicitation, roots hoặc unsolicited server-to-client messages thì stateless mode thay đổi capability surface. Hybrid endpoint dễ tạo mental model phức tạp hơn trong logging/observability vì hai nhóm client có lifecycle khác nhau. Không nên đổi mode production mà chưa có integration tests qua proxy và multi-instance deployment.
