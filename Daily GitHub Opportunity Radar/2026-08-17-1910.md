### UsefulSoftwareCo/executor — toolkit MCP SQLite-lock fix candidate (PR #1619)

**Release date:** 17/08/2026 là ngày issue/PR xuất hiện; patch hiện là PR, chưa phải release đã phát hành.  
**Release type:** Integration  
**Action:** Investigate / Monitor

**Confirmed facts:**
- Issue #1618 báo lỗi trên Executor 1.5.40 và nói cùng code path vẫn tồn tại trong 1.5.41.
- Default `/mcp` initialize thành công nhưng toolkit-scoped `/mcp/toolkits/<slug>` trả HTTP 500.
- Root cause được mô tả là `createConfigForResource` gọi `createExecutorHandle`, khiến daemon cố acquire cùng local SQLite ownership lock lần hai.
- PR #1619 đã được mở ngay sau issue, với hướng sửa reuse daemon-owned DB handle, giữ toolkit-specific plugin config và thêm HTTP regression test.
- PR ghi nhận focused test `src/serve.test.ts` có 16 tests pass cùng typecheck/lint/format checks; một repository-wide test path gặp Node ABI mismatch ngoài phạm vi patch.

Sources:  
https://github.com/UsefulSoftwareCo/executor/issues/1618  
https://github.com/UsefulSoftwareCo/executor/pull/1619  
https://github.com/UsefulSoftwareCo/executor

**Analysis:** đây là một ví dụ tốt về lỗi lifecycle trong process-local infrastructure: một abstraction “create handle” hợp lý khi chạy độc lập nhưng sai khi gọi bên trong server đã sở hữu resource singleton. Pattern tương tự có thể xuất hiện trong .NET khi nhiều scoped service vô tình tự mở thêm SQLite/LevelDB/file lock, hoặc khi background worker tạo nested host/service provider.

**Opportunity:** dùng patch như một mini design review để rút ra rule: server-owned resources phải được truyền vào child scope thay vì child scope tự acquire ownership lần nữa.

**Risk or uncertainty:** PR #1619 chưa merge tại thời điểm kiểm tra; chưa nên coi lỗi đã fixed trong release.
