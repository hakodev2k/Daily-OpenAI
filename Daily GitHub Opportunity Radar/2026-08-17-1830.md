## 5. Tool I Can Apply Today

**Tool:** Two-stage private-key scanner pattern inspired by `ci-runner-infra#176`  
**Problem it solves:** giảm false positives của secret scanning mà không làm yếu prefilter  
**Relevant workflow:** GitHub Actions, Azure DevOps, self-hosted runners, artifact/cache validation  
**Adoption difficulty:** Easy  
**Production readiness:** Pattern is simple; production readiness depends on your implementation and test corpus

**Confirmed facts:** Issue #176 cho biết regex chỉ match `-----BEGIN ... PRIVATE KEY-----` bắt 71 files trong dependency tree; 49 files là real test-fixture keys, 22 files chỉ chứa chuỗi header trong source code. Đề xuất là giữ regex header làm prefilter, sau đó chỉ coi là real key khi tồn tại matching `END` marker và body có dạng PEM/base64.  
Source: https://github.com/Dima-Spectorr/ci-runner-infra/issues/176

**Analysis:** Đây là pattern hay cho CI guardrails: “cheap broad detector → precise confirmation”. Nó giảm alert fatigue mà không biến gate thành allowlist khổng lồ theo package hash. Cùng tư duy này áp dụng được cho API-key scans, `.env` scans, generated fixtures, certificate/private-key bundles và agent-generated artifacts.

**Integration approach:**
- Stage 1: grep/regex nhanh để tìm candidate files.
- Stage 2: parser/check chặt hơn trên candidate content, xác minh full PEM block thay vì text mention.
- Stage 3: regression corpus gồm true positive, false positive, malformed PEM, multiline variants và generated dependency files.
- Stage 4: chỉ fail CI trên confirmed secret; log false-positive-classification metrics riêng để theo dõi drift.

**Required permissions/data access:** Chỉ cần read workspace/cache/artifact path trong runner. Không cần external API nếu chạy local trong CI.

**Privacy/security concerns:** Không upload secret contents ra service ngoài; logs chỉ nên in filename + classification, không dump plaintext key. Nếu scan cache/shared runner, phải đảm bảo scanner không tự lưu copy của secrets vào artifact.

**Maintenance burden:** Thấp nếu confirmation logic được test bằng fixtures; cao nếu tiếp tục dùng allowlist hash theo từng dependency version.

**Smallest proof of concept:** Trong một repo test, tạo 5 fixtures: real PEM, header-only string, header+footer không body, malformed base64, escaped header trong source. Chạy scanner cũ vs two-stage scanner và so precision/recall.

**Relevance to .NET / agents:** Có thể chạy trước `dotnet test`, Playwright tests hoặc trước khi agent artifacts được upload. Với Codex/Claude Code workflows, đây cũng là guardrail tốt trước bước commit/push để ngăn agent vô tình đưa credential fixture thật vào patch.
