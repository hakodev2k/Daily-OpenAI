# 1. Clean Architecture và ranh giới phụ thuộc

### 1. What is it?

Clean Architecture là cách tổ chức hệ thống dựa trên nguyên tắc dependency chỉ hướng vào business rule. Domain không phụ thuộc framework, database hay API.

### 2. Why does it exist?

Mục tiêu là tránh việc nghiệp vụ bị khóa chặt vào công nghệ. Khi database, UI hoặc external service thay đổi, phần lõi vẫn ổn định.

### 3. How does it work?

```text
API
 ↓
Application
 ↓
Domain
 ↑
Infrastructure
```

### 4. Practical example

ASP.NET Core API gọi Application Service, Application sử dụng Domain Entity và Infrastructure triển khai repository.

### 5. Real production scenario

Hệ thống quản lý nhân sự có thể thay SQL Server bằng PostgreSQL mà không thay đổi business rule.

### 6. Common mistakes

Tạo quá nhiều layer nhưng không có boundary thật sự. Đưa business logic vào Controller.

### 7. Trade-offs

Ưu điểm: dễ test, dễ mở rộng.

Chi phí: nhiều abstraction hơn.

### 8. Junior → Middle → Senior

Junior hiểu trách nhiệm layer. Middle triển khai dependency injection. Senior quyết định boundary phù hợp.

### 9. Key takeaway

Architecture tốt không phải nhiều folder mà là kiểm soát dependency.

# 2. CQRS trong hệ thống nghiệp vụ phức tạp

CQRS tách Read Model và Write Model để tối ưu từng luồng xử lý.

Ví dụ hệ thống Timesheet có command SubmitTimesheet và query GetMonthlyReport với nhu cầu khác nhau.

Trade-off chính là tăng độ phức tạp và có thể cần eventual consistency.

---

# 3. Idempotency trong REST API

Idempotency giúp request gửi nhiều lần nhưng kết quả nghiệp vụ chỉ xảy ra một lần.

Ví dụ payment API dùng Idempotency-Key để tránh charge khách hàng hai lần.

---

# 4. EF Core Optimistic Concurrency

Dùng version column hoặc concurrency token để phát hiện dữ liệu bị thay đổi bởi transaction khác.

Ví dụ Employee.RowVersion giúp tránh ghi đè dữ liệu cập nhật đồng thời.

---

# 5. Azure Service Bus và xử lý bất đồng bộ

Azure Service Bus giúp tách producer và consumer.

```text
API → Queue → Worker → Database
```

Phù hợp cho email, file processing, integration workflow.

# 6. Managed Identity trên Azure

Managed Identity loại bỏ việc lưu secret connection trong ứng dụng.

Ứng dụng App Service có thể truy cập Key Vault bằng identity được Azure quản lý.

---

# 7. Redis Cache Aside Pattern

Application kiểm tra cache trước, nếu miss thì đọc database rồi cập nhật cache.

Cần thiết kế cache expiration và invalidation rõ ràng.

---

# 8. OpenTelemetry và Distributed Tracing

OpenTelemetry chuẩn hóa logs, metrics và traces để điều tra lỗi production.

Ví dụ trace một request đi qua API, Service Bus và Worker.

---

# 9. RAG Pipeline cho ứng dụng AI

RAG kết hợp LLM với dữ liệu riêng thông qua embeddings và vector search.

Luồng:

```text
User → Retrieval → Context → LLM → Response
```

Cần kiểm soát chunking, security và token cost.

# 10. Feature Flag trong quy trình phát hành

Feature Flag cho phép bật/tắt tính năng mà không cần deploy lại.

Dùng cho canary release, A/B testing và giảm rủi ro production.
