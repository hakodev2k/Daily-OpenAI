# 1. Clean Architecture và ranh giới phụ thuộc

## 1. What is it?

Clean Architecture là cách tổ chức hệ thống dựa trên nguyên tắc dependency chỉ đi vào bên trong. Business rule không phụ thuộc framework, database hoặc external service.

## 2. Why does it exist?

Mục tiêu là giảm coupling, giúp hệ thống dễ thay đổi và kiểm thử.

## 3. How does it work?

```text
API
 ↓
Application
 ↓
Domain
 ↑
Infrastructure
```

## 4. Practical example

ASP.NET Core API gọi Application Service, Application sử dụng Domain Entity và Infrastructure triển khai repository.

## 5. Real production scenario

Hệ thống quản lý nhân sự có thể thay SQL Server bằng PostgreSQL mà không thay đổi business rule.

## 6. Common mistakes

- Biến Clean Architecture thành folder structure cứng nhắc.
- Đưa business logic vào Controller.

## 7. Trade-offs

Ưu điểm: dễ test, dễ mở rộng.

Chi phí: nhiều abstraction hơn.

## 8. Junior → Middle → Senior

Junior hiểu layer.
Middle biết thiết kế dependency.
Senior quyết định boundary phù hợp.

## 9. Key takeaway

- Dependency direction quan trọng hơn tên folder.
- Domain nên độc lập với công nghệ.

# 2. Event-Driven Architecture

## 1. What is it?

Kiến trúc trong đó các thành phần giao tiếp thông qua event.

## 2. Why does it exist?

Giúp giảm coupling giữa các module.

## 3. How does it work?

Producer phát event → Message Broker → Consumer xử lý.

## 4. Practical example

OrderCreatedEvent được gửi tới service gửi email và cập nhật inventory.

## 5. Real production scenario

E-commerce xử lý thanh toán, notification, shipping độc lập.

## 6. Common mistakes

Không xử lý duplicate event và retry.

## 7. Trade-offs

Tăng scalability nhưng khó debug hơn.

## 8. Junior → Middle → Senior

Junior hiểu message flow.
Middle xử lý retry.
Senior thiết kế consistency.

## 9. Key takeaway

Event-driven phù hợp khi cần scale và tách hệ thống.

# 3. Idempotency trong REST API

Idempotency đảm bảo gửi cùng một request nhiều lần không tạo kết quả sai.

Ví dụ payment API sử dụng Idempotency-Key để tránh charge nhiều lần.

Production cần lưu request state, timeout và retry strategy.

# 4. EF Core Query Optimization

Tối ưu EF Core tập trung vào query thực tế sinh ra SQL.

Ví dụ sử dụng projection:

```csharp
var users = await db.Users
    .Select(x => new UserDto { Id = x.Id })
    .ToListAsync();
```

Tránh Include quá mức và N+1 query.

# 5. Azure Service Bus

Azure Service Bus là message broker cho hệ thống phân tán.

Dùng khi cần reliable messaging, retry, dead-letter queue.

Production cần monitor queue length, failed messages và throughput.

# 6. Managed Identity trên Azure

Managed Identity giúp ứng dụng Azure truy cập resource mà không cần lưu secret.

Ví dụ App Service đọc Azure Key Vault bằng identity của chính nó.

# 7. Redis Cache Aside Pattern

Application kiểm tra cache trước, nếu miss thì đọc database và cập nhật cache.

Cần chú ý cache invalidation, TTL và dữ liệu không nên cache.

# 8. OpenTelemetry và Distributed Tracing

OpenTelemetry chuẩn hóa logs, metrics, traces.

Giúp tìm bottleneck trong microservices bằng trace correlation.

# 9. RAG Pipeline cho AI Application

RAG kết hợp LLM với dữ liệu riêng bằng embeddings và vector search.

Flow:

User → Embedding → Vector DB → Context → LLM → Response

Cần kiểm soát context size, security và evaluation.

# 10. Feature Flags trong Production Release

Feature Flag cho phép bật/tắt tính năng mà không deploy lại.

Dùng cho canary release, A/B testing và giảm rủi ro production.

Cần quản lý lifecycle để tránh tích tụ flag cũ.
