# 1. Clean Architecture Dependency Rule

### 1. What is it?

Clean Architecture đặt business logic ở trung tâm và dependency hướng vào trong.

### 2. Why does it exist?

Giúp domain không bị khóa bởi database, framework hoặc external service.

### 3. How does it work?

```text
API -> Application -> Domain
             ^
             |
       Infrastructure
```

### 4. Practical example

ASP.NET Core dùng interface repository trong Application, EF Core nằm ở Infrastructure.

### 5. Real production scenario

Có thể đổi SQL Server sang PostgreSQL mà không đổi nghiệp vụ.

### 6. Common mistakes

Chỉ chia folder nhưng dependency vẫn sai hướng.

### 7. Trade-offs

Dễ test hơn nhưng nhiều abstraction hơn.

### 8. Junior → Middle → Senior

Junior hiểu layer. Middle thiết kế dependency. Senior xác định boundary.

### 9. Key takeaway

Boundary quan trọng hơn số lượng project.

# 2. CQRS

CQRS tách Command thay đổi dữ liệu và Query đọc dữ liệu.

Flow:

```text
Client -> API -> Command Handler -> Write DB
Client -> API -> Query Handler -> Read DB
```

Dùng khi read/write có workload khác nhau. Không nên áp dụng cho CRUD nhỏ vì tăng complexity.

# 3. OAuth 2.0 và OpenID Connect

OAuth xử lý quyền truy cập, OpenID Connect xử lý danh tính.

Ví dụ ASP.NET Core validate JWT từ Microsoft Entra ID.

Production cần kiểm tra issuer, audience, token lifetime và claims.

# 4. SQL Indexing

Index giúp database tìm dữ liệu nhanh hơn.

```sql
CREATE INDEX IX_User_Email ON Users(Email);
```

Cần đọc execution plan vì index sai có thể làm chậm INSERT/UPDATE.

# 5. Azure API Management

APIM là gateway quản lý API.

```text
Client -> APIM -> API -> Database
```

Dùng cho authentication, rate limit, policy và monitoring. Không đặt business logic vào gateway.

# 6. Azure Container Apps

Container Apps cung cấp môi trường chạy container managed.

Phù hợp khi cần container, autoscaling nhưng không muốn quản lý Kubernetes.

Cần quan tâm revision, ingress, scaling và cost.

# 7. Cache Invalidation

Cache nhanh nhưng dữ liệu cũ là rủi ro lớn.

Các chiến lược:
- TTL
- Remove on update
- Versioned key

Cần thiết kế fallback khi Redis unavailable.

---

# 8. OpenTelemetry

OpenTelemetry kết nối logs, metrics và traces.

```text
Request
 -> API Trace
 -> Database Call
 -> External Service
```

Giúp tìm root cause trong hệ thống distributed.

---

# 9. RAG Context Engineering

RAG kết hợp LLM với dữ liệu riêng.

```text
Question -> Embedding -> Vector Search -> Context -> LLM
```

Cần kiểm soát context size, permission, hallucination và cost.

---

# 10. Incident Management

Quy trình xử lý sự cố:

```text
Detect -> Mitigate -> Investigate -> Fix -> Prevent
```

Postmortem tập trung cải thiện hệ thống, không tìm người chịu lỗi.

- Senior engineering tập trung vào boundary, reliability và trade-off.
- Production system cần observability và khả năng phục hồi.
- Công nghệ chỉ có giá trị khi giải quyết đúng vấn đề.
