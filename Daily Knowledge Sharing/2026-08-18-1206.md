# 1. Clean Architecture và ranh giới phụ thuộc

### 1. What is it?
Clean Architecture là cách tổ chức hệ thống dựa trên nguyên tắc business rules không phụ thuộc framework, database hay external service.

### 2. Why does it exist?
Mục tiêu là giảm coupling để thay đổi UI, database hoặc infrastructure mà không phá vỡ domain logic.

### 3. How does it work?

```text
API
 |
Application
 |
Domain
 ^
 |
Infrastructure
```

Dependency hướng vào bên trong. Domain không biết EF Core, SQL hay Azure.

### 4. Practical example
ASP.NET Core project có Domain chứa Entity và business rule, Application chứa use case, Infrastructure chứa EF Core DbContext.

### 5. Real production scenario
Hệ thống SaaS cần đổi SQL Server sang PostgreSQL mà không thay đổi nghiệp vụ.

### 6. Common mistakes
- Tạo quá nhiều layer nhưng không có boundary thực sự.
- Đưa business logic vào Controller.

### 7. Trade-offs
Ưu điểm: dễ test, dễ mở rộng. Chi phí: nhiều abstraction hơn.

### 8. Junior → Middle → Senior
Junior hiểu trách nhiệm layer. Middle biết thiết kế dependency. Senior quyết định boundary phù hợp.

### 9. Key takeaway
Architecture tốt không phải nhiều folder mà là dependency đúng hướng.

# 2. Domain-Driven Design: Bounded Context

### 1. What is it?
Bounded Context xác định phạm vi mà một domain model có ý nghĩa.

### 2. Why does it exist?
Một model dùng cho toàn hệ thống thường tạo ra coupling và ambiguity.

### 3. How does it work?
Một hệ thống có thể tách Sales, Payment, Inventory thành các context riêng.

### 4. Practical example
Order trong Sales khác Order trong Shipping.

### 5. Real production scenario
E-commerce lớn thường chia domain theo business capability.

### 6. Common mistakes
Tách microservice quá sớm khi chưa hiểu domain.

### 7. Trade-offs
Rõ trách nhiệm hơn nhưng cần giao tiếp giữa context.

### 8. Junior → Middle → Senior
Senior cần biết khi nào nên chia context.

### 9. Key takeaway
DDD tập trung vào business boundary trước technology boundary.

# 3. Idempotency trong REST API

### 1. What is it?
Idempotency đảm bảo gửi cùng một request nhiều lần vẫn tạo một kết quả hợp lệ.

### 2. Why does it exist?
Network retry có thể khiến payment hoặc order bị tạo trùng.

### 3. How does it work?
Client gửi Idempotency-Key, server lưu trạng thái xử lý.

### 4. Practical example
POST /payments với key PAY-123 chỉ tạo một transaction.

### 5. Real production scenario
Payment gateway và webhook cần idempotency.

### 6. Common mistakes
Không lưu kết quả response hoặc key hết hạn sai.

### 7. Trade-offs
Tăng reliability nhưng cần storage và cleanup.

### 8. Junior → Middle → Senior
Senior quan tâm distributed failure và retry strategy.

### 9. Key takeaway
Retry mà không idempotent có thể tạo lỗi dữ liệu.

# 4. EF Core Query Optimization

### 1. What is it?
Tối ưu cách EF Core sinh SQL và truy xuất dữ liệu.

### 2. Why does it exist?
ORM tiện lợi nhưng có thể tạo query chậm.

### 3. How does it work?
Dùng projection, Include hợp lý, AsNoTracking.

### 4. Practical example
```csharp
var users = await db.Users
    .AsNoTracking()
    .Select(x => new { x.Id, x.Name })
    .ToListAsync();
```

### 5. Real production scenario
API danh sách hàng triệu bản ghi.

### 6. Common mistakes
Load toàn bộ entity khi chỉ cần vài field.

### 7. Trade-offs
Query tối ưu hơn nhưng code phức tạp hơn.

### 8. Junior → Middle → Senior
Senior cần đọc execution plan.

### 9. Key takeaway
Đo SQL thực tế thay vì đoán.

# 5. Optimistic Concurrency

### 1. What is it?
Kiểm tra dữ liệu có bị thay đổi trước khi update.

### 2. Why does it exist?
Ngăn user ghi đè thay đổi của nhau.

### 3. How does it work?
Dùng rowversion hoặc version column.

### 4. Practical example
Employee profile update với SQL Server rowversion.

### 5. Real production scenario
CRM, HR, ERP.

### 6. Common mistakes
Không xử lý conflict.

### 7. Trade-offs
Không lock lâu nhưng cần merge strategy.

### 8. Junior → Middle → Senior
Senior thiết kế conflict resolution.

### 9. Key takeaway
Concurrency là vấn đề business, không chỉ database.

# 6. Azure Service Bus trong Event-Driven Architecture

### 1. What is it?
Message broker giúp các component giao tiếp bất đồng bộ.

### 2. Why does it exist?
Giảm coupling giữa producer và consumer.

### 3. How does it work?

```text
API -> Service Bus -> Worker -> Database
```

### 4. Practical example
OrderCreated event gửi notification.

### 5. Real production scenario
SaaS background processing.

### 6. Common mistakes
Không xử lý duplicate message.

### 7. Trade-offs
Scalable hơn nhưng tăng eventual consistency.

### 8. Junior → Middle → Senior
Senior thiết kế retry, dead-letter queue.

### 9. Key takeaway
Async architecture cần failure handling.

# 7. Managed Identity trên Azure

### 1. What is it?
Cơ chế Azure cấp identity cho service mà không cần lưu secret.

### 2. Why does it exist?
Giảm rủi ro secret leakage.

### 3. How does it work?
App Service lấy token từ Azure AD để gọi resource.

### 4. Practical example
.NET app truy cập Key Vault.

### 5. Real production scenario
Enterprise cloud application.

### 6. Common mistakes
Cấp quyền quá rộng.

### 7. Trade-offs
Bảo mật hơn nhưng cần IAM management.

### 8. Junior → Middle → Senior
Senior thiết kế least privilege.

### 9. Key takeaway
Không lưu credential nếu platform có identity.

# 10. RAG Pipeline cho AI Application

### 1. What is it?
Retrieval Augmented Generation kết hợp LLM với dữ liệu riêng.

### 2. Why does it exist?
LLM không biết dữ liệu nội bộ và có thể hallucination.

### 3. How does it work?

```text
Document -> Embedding -> Vector DB -> Retrieve -> LLM
```

### 4. Practical example
AI assistant tìm tài liệu kỹ thuật công ty.

### 5. Real production scenario
Enterprise knowledge chatbot.

### 6. Common mistakes
Chunking sai, context quá dài, thiếu evaluation.

### 7. Trade-offs
Accuracy cao hơn nhưng pipeline phức tạp.

### 8. Junior → Middle → Senior
Senior quan tâm security, cost, latency.

### 9. Key takeaway
RAG là engineering pipeline, không chỉ gọi API AI.
