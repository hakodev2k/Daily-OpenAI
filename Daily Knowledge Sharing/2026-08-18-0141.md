# 1. Clean Architecture và Dependency Rule

## 1. What is it?

Clean Architecture là cách tổ chức hệ thống theo business rule, trong đó dependency luôn hướng vào phía domain. Business không phụ thuộc framework, database hay external service.

## 2. Why does it exist?

Code thường xuống cấp khi controller gọi trực tiếp database, business logic nằm trong ORM model và thay đổi công nghệ gây ảnh hưởng toàn hệ thống.

## 3. How does it work?

```text
API
 ↓
Application
 ↓
Domain
 ↑
Infrastructure
```

Domain chứa rule quan trọng nhất. Infrastructure implement interface do Application hoặc Domain định nghĩa.

## 4. Practical example

ASP.NET Core:

```csharp
public interface IEmployeeRepository
{
    Task<Employee?> GetAsync(int id);
}
```

Application chỉ biết interface, không biết SQL Server hay EF Core.

## 5. Real production scenario

Hệ thống quản lý nhân sự có thể thay SQL Server bằng PostgreSQL mà không thay đổi nghiệp vụ.

## 6. Common mistakes

- Chỉ chia folder nhưng dependency vẫn ngược.
- Đưa business rule vào controller.

## 7. Trade-offs

Ưu điểm: dễ test, dễ mở rộng.
Rủi ro: nhiều abstraction nếu áp dụng máy móc.

## 8. Junior → Middle → Senior

Junior hiểu layer responsibility.
Middle thiết kế dependency.
Senior quyết định boundary phù hợp.

## 9. Key takeaway

Architecture tốt bảo vệ business logic khỏi thay đổi bên ngoài.

# 2. CQRS trong hệ thống Backend hiện đại

## 1. What is it?

CQRS tách Command (thay đổi dữ liệu) và Query (đọc dữ liệu) thành hai luồng khác nhau.

## 2. Why does it exist?

Một model dùng cho cả đọc và ghi thường khó tối ưu khi hệ thống phức tạp.

## 3. How does it work?

```text
Request
  |
  +--> Command Handler --> Database
  |
  +--> Query Handler --> Read Model
```

## 4. Practical example

Order creation dùng command, dashboard doanh thu dùng query model tối ưu riêng.

## 5. Real production scenario

E-commerce có hàng triệu lượt xem sản phẩm nhưng ít thao tác mua hàng.

## 6. Common mistakes

Dùng CQRS cho CRUD đơn giản làm tăng complexity.

## 7. Trade-offs

Đổi complexity lấy khả năng scale và tối ưu riêng.

## 8. Junior → Middle → Senior

Junior hiểu separation.
Middle implement handler.
Senior quyết định khi nào cần CQRS.

## 9. Key takeaway

CQRS là công cụ giải quyết complexity, không phải mặc định cho mọi API.

# 3. Idempotency trong REST API

Idempotency đảm bảo gửi cùng một request nhiều lần nhưng kết quả cuối giống nhau.

Ví dụ thanh toán:

```http
POST /payments
Idempotency-Key: abc-123
```

Server lưu key và trả lại kết quả cũ nếu request bị retry.

Production cần thiết kế cho network failure, timeout và duplicate request.

# 4. Database Indexing và Query Optimization

Index giúp database tìm dữ liệu nhanh hơn thay vì scan toàn bộ table.

Ví dụ:

```sql
CREATE INDEX IX_User_Email
ON Users(Email);
```

Cần kiểm tra execution plan, selectivity và chi phí write khi thêm index.

Sai lầm phổ biến là tạo quá nhiều index làm chậm INSERT/UPDATE.

# 5. Azure Service Bus và Event-driven Processing

Azure Service Bus cung cấp message broker để tách producer và consumer.

```text
API
 |
Message
 |
Azure Service Bus
 |
Worker
```

Production cần xử lý retry, dead-letter queue, duplicate message và monitoring.

# 6. Azure App Service Production Architecture

Azure App Service giúp host web application mà không quản lý server.

Kiến trúc phổ biến:

```text
Client
 |
Front Door
 |
App Service
 |
Azure SQL / Redis
```

Cần quan tâm deployment slot, scaling rule, health check và Managed Identity.

# 7. Cache Aside Pattern với Redis

Cache Aside là pattern ứng dụng tự quản lý cache.

```text
Request
 |
Redis
 |
Miss -> Database -> Redis
```

Cần thiết kế TTL, invalidation và fallback khi Redis lỗi.

Không nên cache dữ liệu thay đổi liên tục hoặc dữ liệu nhạy cảm không phù hợp.

# 8. OpenTelemetry và Distributed Tracing

Distributed tracing theo dõi request đi qua nhiều service.

Ví dụ:

```text
API -> Service A -> Service B -> Database
```

Trace giúp tìm bottleneck trong microservices.

Production cần kết hợp logs, metrics và traces.

# 9. RAG Architecture cho AI Application

RAG kết hợp LLM với dữ liệu riêng bằng retrieval trước khi generate.

```text
Question
 |
Embedding
 |
Vector Search
 |
Context
 |
LLM
```

Cần kiểm soát chunking, embedding quality, security và token cost.

# 10. Feature Flags trong Continuous Delivery

Feature Flag cho phép bật/tắt tính năng mà không cần deploy lại.

Ví dụ:

```csharp
if(featureManager.IsEnabled("NewApprovalFlow"))
{
    UseNewFlow();
}
```

Production dùng cho canary release, A/B testing và rollback nhanh.

Trade-off là cần quản lý lifecycle của flag để tránh technical debt.

- Kiến trúc tốt tập trung vào boundary và dependency.
- Production system cần thiết kế cho lỗi, retry và quan sát được.
- AI, cloud và distributed system đều cần kiểm soát complexity thay vì chỉ thêm công nghệ.
