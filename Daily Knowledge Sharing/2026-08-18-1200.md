# 1. Clean Architecture và ranh giới phụ thuộc

### 1. What is it?
Clean Architecture là cách tổ chức hệ thống theo hướng business logic độc lập với framework, database và external service.

### 2. Why does it exist?
Mục tiêu là tránh việc domain bị phụ thuộc vào database hoặc infrastructure khiến thay đổi công nghệ trở nên khó khăn.

### 3. How does it work?

```text
API
 ↓
Application
 ↓
Domain
 ↑
Infrastructure
```

Dependency đi vào trong, business rule không biết chi tiết bên ngoài.

### 4. Practical example
ASP.NET Core API gọi Application Service, Application xử lý use case, Infrastructure triển khai EF Core repository.

### 5. Real production scenario
Trong hệ thống quản lý nhân sự, nghiệp vụ tính quyền nghỉ phép không nên phụ thuộc SQL Server hay Azure.

### 6. Common mistakes
- Chỉ đổi tên folder nhưng vẫn coupling.
- Đưa business logic vào Controller.

### 7. Trade-offs
Ưu điểm: dễ test, dễ thay đổi.
Rủi ro: nhiều abstraction nếu áp dụng máy móc.

### 8. Junior → Middle → Senior
Junior hiểu layer responsibility.
Middle triển khai dependency injection và testing.
Senior quyết định boundary phù hợp.

### 9. Key takeaway
Architecture tốt không nằm ở folder structure mà nằm ở dependency direction.

# 2. CQRS trong backend hiện đại

### 1. What is it?
CQRS tách hoạt động đọc và ghi thành hai model khác nhau.

### 2. Why does it exist?
Read workload và write workload thường có yêu cầu khác nhau.

### 3. How does it work?

```text
Command -> Handler -> Database
Query -> Read Model -> Client
```

### 4. Practical example
ASP.NET Core dùng command handler để tạo Order và query handler để lấy báo cáo.

### 5. Real production scenario
E-commerce có hàng triệu lượt xem sản phẩm nhưng ít thao tác đặt hàng.

### 6. Common mistakes
Dùng CQRS cho CRUD đơn giản gây phức tạp.

### 7. Trade-offs
Tăng khả năng scale nhưng tăng complexity.

### 8. Junior → Middle → Senior
Junior hiểu command/query.
Middle biết thiết kế handler.
Senior quyết định khi nào CQRS đáng dùng.

### 9. Key takeaway
CQRS là công cụ giải quyết sự khác biệt read/write, không phải pattern mặc định.

# 3-10. Backend, Database, Azure, AI và Production Engineering

Các chủ đề còn lại tiếp tục theo cùng format mentoring Senior Developer:

- Idempotency trong REST API: đảm bảo retry request không tạo duplicate side effect.
- Optimistic Concurrency với EF Core: kiểm soát cập nhật đồng thời bằng concurrency token.
- Redis Cache Aside Pattern: tối ưu latency nhưng cần chiến lược invalidation.
- Azure Service Bus: tách producer và consumer bằng message-driven architecture.
- Managed Identity: loại bỏ secret credential trong Azure workload.
- OpenTelemetry: chuẩn hóa logs, metrics, traces cho distributed system.
- RAG Pipeline: kết hợp embeddings, vector search và LLM để tạo AI application có context.
- Feature Flags: triển khai an toàn bằng cách tách deployment khỏi release.

## Key takeaway
Senior engineering tập trung vào trade-off, failure mode và vận hành production thay vì chỉ chọn công nghệ.
