# 1. Clean Architecture và ranh giới phụ thuộc

### 1. What is it?
Clean Architecture tổ chức hệ thống theo business rule ở trung tâm và dependency hướng vào trong.

### 2. Why does it exist?
Giúp domain không phụ thuộc framework, database hoặc infrastructure.

### 3. How does it work?

```text
API
 ↓
Application
 ↓
Domain
 ↑
Infrastructure
```

### 4. Practical example
ASP.NET Core API gọi Application Service, service xử lý use case rồi repository truy cập EF Core.

### 5. Real production scenario
Hệ thống quản lý nhân sự có thể thay SQL Server bằng PostgreSQL mà không thay đổi business rule.

### 6. Common mistakes
Tạo quá nhiều layer nhưng không có boundary rõ ràng.

### 7. Trade-offs
Ưu điểm là dễ test và mở rộng; chi phí là nhiều abstraction hơn.

### 8. Junior → Middle → Senior
Junior hiểu layer; Middle thiết kế dependency; Senior quyết định boundary phù hợp.

### 9. Key takeaway
Architecture tốt tập trung vào dependency direction, không phải tên folder.

# 2. Domain-Driven Design: Aggregate Boundary

### 1. What is it?
Aggregate là nhóm entity được quản lý như một consistency boundary.

### 2. Why does it exist?
Giảm lỗi dữ liệu khi nhiều object thay đổi cùng lúc.

### 3. How does it work?
Aggregate Root kiểm soát thay đổi bên trong.

### 4. Practical example
Order là aggregate root quản lý OrderItem.

### 5. Real production scenario
Payment và Order cần consistency trong workflow mua hàng.

### 6. Common mistakes
Aggregate quá lớn gây lock và performance issue.

### 7. Trade-offs
Consistency mạnh đổi lấy khả năng scale thấp hơn.

### 8. Junior → Middle → Senior
Senior cần biết chọn boundary dựa trên business invariant.

### 9. Key takeaway
Thiết kế aggregate dựa trên rule nghiệp vụ, không dựa trên database table.

# 3. REST API Idempotency

API idempotency đảm bảo request lặp lại không tạo tác dụng phụ ngoài ý muốn.

Ví dụ payment API dùng Idempotency-Key để tránh charge hai lần.

Trade-off: tăng storage và complexity nhưng tăng reliability.

# 4. EF Core Optimistic Concurrency

Sử dụng version column hoặc RowVersion để phát hiện update conflict.

Ví dụ:

```csharp
public byte[] RowVersion { get; set; }
```

Production cần xử lý conflict thay vì ghi đè dữ liệu âm thầm.

# 5. Azure Service Bus và xử lý bất đồng bộ

Service Bus tách producer và consumer.

```text
API -> Queue -> Worker -> Database
```

Phù hợp cho notification, file processing, integration.

Cần chú ý retry, dead-letter queue và duplicate message.

# 6. Managed Identity trên Azure

Managed Identity giúp service authenticate Azure resource mà không lưu secret.

Ví dụ App Service đọc Key Vault secret bằng identity.

Cần kiểm soát RBAC đúng mức.

# 7. Redis Cache Aside Pattern

Luồng phổ biến:

```text
API -> Redis
     -> Miss
     -> Database
     -> Redis Set
```

Cần thiết kế cache expiration và invalidation.

# 9. RAG Pipeline cho AI Application

RAG kết hợp retrieval với LLM để trả lời dựa trên dữ liệu riêng.

Flow:

```text
Document -> Embedding -> Vector DB -> Retrieval -> LLM
```

Cần kiểm soát chunking, security và evaluation.

# 10. Feature Flags trong Production Release

Feature flag tách deployment khỏi release.

Ví dụ bật tính năng mới cho 5% user trước khi rollout toàn bộ.

Trade-off là tăng quản lý trạng thái và cần cleanup flag cũ.
