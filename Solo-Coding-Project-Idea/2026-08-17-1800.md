# Ý tưởng hôm nay: Dev Memory Vault - Kho tri thức kỹ thuật cá nhân tự động

## 1. Tóm tắt ý tưởng
Một công cụ dành cho developer giúp tự động lưu lại các quyết định kỹ thuật, lỗi đã xử lý, đoạn code quan trọng, bài học debugging và biến chúng thành kho tri thức có thể tìm kiếm lại. MVP tập trung vào cá nhân developer, quy mô Small/Medium, thời gian khoảng 2-4 tuần.

## 2. Bài toán thực tế
Developer thường gặp lại các vấn đề tương tự: lỗi production, cách cấu hình Azure, workaround thư viện, quyết định kiến trúc. Hiện nay thông tin thường nằm trong chat, ticket, bookmark hoặc file cá nhân nên khó tái sử dụng. Đây là giả định dựa trên trải nghiệm phổ biến của kỹ sư phần mềm.

## 3. Người dùng mục tiêu
Primary user: Senior .NET developer làm nhiều dự án song song. Họ cần ghi nhớ context kỹ thuật dài hạn nhưng không muốn viết tài liệu thủ công.

## 4. Giải pháp đề xuất
Người dùng nhập một ghi chú kỹ thuật, link PR, log lỗi hoặc command đã dùng. Hệ thống lưu trữ, gắn tag, tạo liên kết và hỗ trợ tìm kiếm. Điểm khác biệt là tập trung vào "memory của developer" thay vì ghi chú chung.

Ví dụ: Sau khi xử lý lỗi Microsoft Graph, developer lưu nguyên nhân, solution, permission cần thiết. Sáu tháng sau chỉ cần tìm "Graph calendar permission" để lấy lại kinh nghiệm.

## 5. Tại sao đáng làm
Có giá trị ngay cả khi chỉ dùng cá nhân. Dự án giúp học search, indexing, background processing, AI retrieval và knowledge management. Rủi ro lớn nhất là người dùng không duy trì thói quen nhập dữ liệu.

## 6. Phạm vi MVP

### Must have
- CRUD technical memories
- Tag và category
- Full text search
- Markdown editor
- Import/export backup

### Should have
- GitHub integration
- Browser extension lưu nhanh
- Auto tagging

### Later
- Team knowledge sharing
- AI assistant
- Semantic search

## 7. Luồng hoạt động
User tạo memory → validate dữ liệu → lưu database → tạo index tìm kiếm → người dùng tìm kiếm → trả về kiến thức liên quan.

Failure cases: dữ liệu trùng, file đính kèm lỗi, index thất bại cần retry.

## 8. Kiến trúc đề xuất
- Frontend: Vue hoặc React
- Backend: ASP.NET Core modular monolith
- Database: PostgreSQL
- Search: PostgreSQL Full Text Search trước, Elasticsearch sau nếu cần
- Background worker: BackgroundService cho indexing
- Storage: local/S3 compatible cho attachment
- Auth: local account hoặc Microsoft Entra ID

Không cần microservice trong MVP.

## 9. Công nghệ đề xuất
.NET 10, ASP.NET Core, EF Core, PostgreSQL, Vue 3, Docker, GitHub Actions. Đây là stack phù hợp với kinh nghiệm backend và dễ mở rộng. SQLite là lựa chọn đơn giản hơn khi chỉ dùng cá nhân.

## 10. Thiết kế dữ liệu ban đầu
Memory: Id, Title, Content, Type, CreatedAt, UpdatedAt.

Tag: Id, Name.

Attachment: Id, MemoryId, Path, Metadata.

MemoryTag: quan hệ nhiều-nhiều.

## 11. API và tích hợp
- GitHub API: lấy repository, issue, PR link. Cần token nếu truy cập private repo.
- Markdown parser library: render nội dung.
- Optional OpenAI API: tạo summary/tag.

Fallback: hệ thống vẫn hoạt động không cần API ngoài.

## 12. AI có thực sự cần thiết không?
AI hữu ích nhưng không bắt buộc. Có thể dùng để tóm tắt note dài, đề xuất tag và tạo câu hỏi tìm kiếm. Output phải được validate bởi người dùng. Chi phí và privacy là rủi ro.

## 13. Kế hoạch triển khai

### Phase 0
Tạo 20-30 memory mẫu để kiểm tra nhu cầu tìm lại.

### Phase 1
Build API, UI, database, search cơ bản.

### Phase 2
Thêm test, backup, logging, xử lý lỗi.

### Phase 3
Thêm GitHub integration và browser extension.

### Phase 4
Deploy VPS/Azure, monitoring, documentation.

## 14. Các bài toán kỹ thuật đáng học
- Full text search: nâng cao khả năng xây dựng hệ thống tìm kiếm.
- Index synchronization: học consistency.
- Background processing: học retry/idempotency.
- Knowledge retrieval: nền tảng cho AI agent.

## 15. Rủi ro và cách xử lý
Scope tăng quá nhanh → giữ MVP cá nhân.

Dữ liệu nhạy cảm → mã hóa hoặc self-host.

AI trả kết quả sai → chỉ dùng AI cho hỗ trợ, không quyết định.

## 16. Kiểm thử
Năm scenario quan trọng:
1. Tạo và tìm kiếm memory.
2. Import backup.
3. Index lỗi và retry.
4. Permission authentication.
5. Attachment upload thất bại.

## 17. Cách đo hữu ích
- Số memory được tạo mỗi tuần.
- Thời gian tìm lại solution giảm.
- Số lần tái sử dụng kiến thức.
- Search success rate.

## 18. Khả năng mở rộng
Có thể phát triển thành knowledge platform cho team nhỏ, plugin IDE, MCP server cho AI coding agent hoặc open-source self-hosted tool.

## 19. Mô hình giá trị
Phù hợp nhất: Personal utility, Portfolio project, Open-source project. Có thể phát triển SaaS cho team nếu nhu cầu thực tế xuất hiện.

## 20. Việc cần làm ngay hôm nay
Mục tiêu 60-120 phút: tạo vertical slice đầu tiên.

Tasks:
1. Tạo solution ASP.NET Core Web API.
2. Tạo entity Memory.
3. Setup PostgreSQL + EF Core migration.
4. Tạo API POST /memories.
5. Tạo trang Vue hiển thị danh sách memory.

Kết quả mong đợi: có thể tạo một technical note và xem lại trên giao diện.

Verification:
- API chạy thành công.
- Database lưu được dữ liệu.
- UI hiển thị dữ liệu.

Stop condition: dừng khi hoàn thành vòng lặp tạo → lưu → xem lại đầu tiên.
