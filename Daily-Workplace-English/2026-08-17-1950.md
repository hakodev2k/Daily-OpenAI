# Daily Workplace English — Ngày 30

- **Ngày:** 17/08/2026 (UTC+7)
- **Tình huống công việc:** Giải thích performance concern khi một EF Core query mới có thể gây tải lớn lên SQL Server
- **Kỹ năng giao tiếp chính:** Nêu performance risk có bằng chứng, phân biệt current behavior với potential impact, và đề xuất cách đo trước khi tối ưu
- **Thời gian học:** 20–25 phút
- **Độ khó:** Lower-intermediate

## 1. Tình huống hôm nay

Bạn đang review một thay đổi trong ASP.NET Core API. Một endpoint mới dùng Entity Framework Core để load danh sách dữ liệu cùng nhiều navigation properties. Trên local và QA environment, endpoint vẫn trả về kết quả đúng và khá nhanh vì dữ liệu chưa nhiều.

Những người liên quan gồm bạn, một backend engineer khác và Technical Lead. Bạn nhận thấy query có thể tạo ra lượng dữ liệu lớn khi chạy trên production, đặc biệt nếu số record tăng và nhiều relation được include cùng lúc.

Bạn chưa thể khẳng định đây là một performance bug vì chưa có production metrics. Tuy nhiên, bạn muốn nêu concern trước khi release và đề xuất cách kiểm tra bằng SQL execution plan, query timing và số lượng rows được trả về.

Khó khăn giao tiếp là tránh hai thái cực:

- Khẳng định quá sớm: “This query will be slow in production.”
- Nói quá mơ hồ: “Maybe there is a performance issue.”

Cấu trúc nên dùng:

**Observation → Current evidence → Potential impact → Measurement plan → Optimization only if needed**

## 2. Bạn cần nói gì?

Trong tình huống này, mục tiêu giao tiếp là:

- Nêu chính xác điều bạn quan sát trong query.
- Phân biệt điều đã biết với điều chỉ là risk tiềm năng.
- Giải thích vì sao production data volume có thể làm behavior khác QA.
- Đề xuất cách đo cụ thể trước khi quyết định tối ưu.
- Tránh tối ưu sớm nếu metrics chưa cho thấy vấn đề thực tế.

Một cách nói tốt là tập trung vào **evidence và verification**, thay vì tranh luận dựa trên cảm giác.

## 3. Đoạn hội thoại hoặc mẫu trình bày

**You:** “I have one performance concern about this EF Core query.”  
*Tôi có một điểm lo ngại về performance của EF Core query này.*

**Engineer:** “What do you think could be a problem?”  
*Bạn nghĩ điểm nào có thể là vấn đề?*

**You:** “The query includes several related collections, so it may return significantly more rows as the data grows.”  
*Query đang include nhiều collection liên quan, vì vậy số lượng rows trả về có thể tăng đáng kể khi dữ liệu lớn lên.*

**You:** “It performs well in QA right now, but the dataset there is much smaller than production.”  
*Hiện tại nó chạy tốt ở QA, nhưng dataset ở đó nhỏ hơn production rất nhiều.*

**Engineer:** “Do you think we should rewrite it before release?”  
*Bạn có nghĩ chúng ta nên viết lại query trước khi release không?*

**You:** “Not necessarily. I’d like to measure the generated SQL, execution time, and row count first.”  
*Chưa chắc cần. Tôi muốn đo generated SQL, execution time và số lượng rows trước.*

**You:** “If the numbers show a real bottleneck, we can then decide whether to split the query, project only the required fields, or add an index.”  
*Nếu số liệu cho thấy bottleneck thực sự, lúc đó chúng ta có thể quyết định split query, chỉ project các field cần thiết hoặc thêm index.*

**Technical Lead:** “That sounds reasonable. Please add the measurements to the PR.”  
*Nghe hợp lý. Hãy thêm các số liệu đo vào PR.*

## 4. Các cụm từ quan trọng

### 1. “I have one performance concern about…”

- **Nghĩa:** Tôi có một điểm lo ngại về performance của…
- **Khi dùng:** Khi muốn nêu risk rõ ràng nhưng chưa kết luận đó là bug.
- **Ví dụ thêm:** “I have one performance concern about loading all records before applying the filter.”

### 2. “It performs well in … right now, but…”

- **Nghĩa:** Hiện tại nó chạy tốt ở…, nhưng…
- **Khi dùng:** Khi current environment chưa thể đại diện hoàn toàn cho production.
- **Ví dụ thêm:** “It performs well in local testing right now, but we only have a few hundred records.”

### 3. “It may return significantly more…”

- **Nghĩa:** Nó có thể trả về nhiều hơn đáng kể…
- **Khi dùng:** Khi mô tả potential impact nhưng chưa có dữ liệu chắc chắn.
- **Ví dụ thêm:** “This endpoint may return significantly more data after the new customer migration.”

### 4. “I’d like to measure … first.”

- **Nghĩa:** Tôi muốn đo/kiểm tra … trước.
- **Khi dùng:** Khi muốn chuyển từ opinion sang evidence.
- **Ví dụ thêm:** “I’d like to measure the API latency first before we introduce caching.”

### 5. “If the numbers show a real bottleneck…”

- **Nghĩa:** Nếu số liệu cho thấy bottleneck thực sự…
- **Khi dùng:** Khi quyết định optimization dựa trên metrics.
- **Ví dụ thêm:** “If the numbers show a real bottleneck, we can optimize the serialization step.”

### 6. “Not necessarily.”

- **Nghĩa:** Không nhất thiết / chưa chắc cần như vậy.
- **Khi dùng:** Khi muốn phản hồi một đề xuất mà không phủ nhận hoàn toàn.
- **Ví dụ thêm:** “Do we need Redis for this?” — “Not necessarily. Let’s check the database query first.”

### 7. “We can then decide whether to…”

- **Nghĩa:** Sau đó chúng ta có thể quyết định liệu có nên…
- **Khi dùng:** Khi muốn trì hoãn quyết định kỹ thuật cho đến khi có đủ thông tin.
- **Ví dụ thêm:** “We can then decide whether to increase the timeout or change the retry strategy.”

## 5. Từ vựng trong tình huống

### 1. bottleneck — noun

- **IPA:** /ˈbɒt.l.nek/
- **Nghĩa:** điểm nghẽn hiệu năng
- **Ví dụ:** “The query may become a bottleneck when the table grows.”
- **Collocation:** performance bottleneck, identify a bottleneck

### 2. dataset — noun

- **IPA:** /ˈdeɪ.tə.set/
- **Nghĩa:** tập dữ liệu
- **Ví dụ:** “The QA dataset is much smaller than production.”
- **Collocation:** large dataset, production dataset

### 3. execution time — noun phrase

- **IPA:** /ˌek.sɪˈkjuː.ʃən taɪm/
- **Nghĩa:** thời gian thực thi
- **Ví dụ:** “We should compare the execution time before and after the change.”
- **Collocation:** measure execution time, query execution time

### 4. projection — noun

- **IPA:** /prəˈdʒek.ʃən/
- **Nghĩa:** việc chọn đúng các field cần lấy ra trong query
- **Ví dụ:** “A smaller projection may reduce the amount of transferred data.”
- **Collocation:** query projection, project required fields

### 5. generated SQL — noun phrase

- **IPA:** /ˈdʒen.ə.reɪ.tɪd ˌes.kjuːˈel/
- **Nghĩa:** câu SQL do EF Core sinh ra
- **Ví dụ:** “Let’s inspect the generated SQL before changing the query.”
- **Collocation:** inspect generated SQL, review generated SQL

### 6. row count — noun phrase

- **IPA:** /rəʊ kaʊnt/
- **Nghĩa:** số lượng rows
- **Ví dụ:** “The row count may grow quickly because of the joins.”
- **Collocation:** check row count, high row count

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Hedging với `may`, `might`, `could`

Khi chưa chắc chắn về nguyên nhân hoặc impact, dùng `may`, `might`, `could` để tránh nói quá chắc.

**Cấu trúc:**

`Subject + may/might/could + verb`

Ví dụ trong bài:

- “It **may return** significantly more rows as the data grows.”
- “The query **could become** a bottleneck in production.”

**Khi dùng:**

- Khi có dấu hiệu nhưng chưa đủ bằng chứng.
- Khi nói về risk tiềm năng.
- Khi review design hoặc performance.

**Không nên:**

- “This query will be slow.” nếu chưa có metrics.

**Nên:**

- “This query may become slow with a much larger dataset.”

### Lỗi thường gặp

Sai: “This query maybe slow.”  
Đúng: “This query **may be** slow.”

`maybe` là adverb mang nghĩa “có lẽ”, còn `may be` là modal verb + verb `be`.

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“This query is bad for performance.”

### Tự nhiên và chuyên nghiệp hơn

“I have one performance concern about how this query will behave with a larger dataset.”

### Giải thích

Câu đầu kết luận quá mạnh và dễ khiến người nghe cảm thấy bạn đang chê solution. Câu thứ hai chỉ rõ concern nằm ở behavior khi scale.

### Chưa tự nhiên hoặc quá trực tiếp

“We need to optimize this before release.”

### Tự nhiên và chuyên nghiệp hơn

“I’d like to measure the query first and optimize it if the numbers show a real bottleneck.”

### Giải thích

Optimization nên dựa trên evidence. Câu thứ hai cho thấy bạn có plan kiểm chứng trước khi thay đổi code.

### Chưa tự nhiên hoặc quá trực tiếp

“QA is too small, so this result is not useful.”

### Tự nhiên và chuyên nghiệp hơn

“The query performs well in QA, but the dataset there is much smaller than production.”

### Giải thích

Không cần phủ nhận hoàn toàn kết quả QA. Bạn chỉ cần nói rõ limitation của environment hiện tại. Giao tiếp trực tiếp vẫn phù hợp khi mô tả sự cố khẩn cấp hoặc fact chắc chắn, nhưng ở đây cần phân biệt rõ fact và risk.

## 8. Phát âm và luyện nói

### Phrase 1: “I have one performance concern about this query.”

- **Stress:** nhấn vào **performance**, **concern**, **query**.
- **Connected speech:** “concern about” nối nhẹ giữa /n/ và /ə/.
- **Gợi ý cho người Việt:** không đọc từng từ tách rời; giữ nhịp theo nhóm “performance concern / about this query”.
- **Pause:** “I have one performance concern / about this query.”

### Phrase 2: “I’d like to measure the execution time first.”

- **Stress:** nhấn **measure**, **execution time**, **first**.
- **Reduced sound:** “I’d like to” thường được nói nhanh hơn, không cần nhấn từng từ.
- **Gợi ý:** tập trung làm rõ từ “measure” và cụm “execution time”.
- **Pause:** “I’d like to measure / the execution time first.”

### Phrase 3: “If the numbers show a real bottleneck, we can optimize it.”

- **Stress:** nhấn **numbers**, **real bottleneck**, **optimize**.
- **Connected speech:** “show a” thường nối tự nhiên thành một cụm.
- **Gợi ý:** không lên giọng ở giữa câu; pause nhẹ sau mệnh đề `if`.
- **Pause:** “If the numbers show a real bottleneck, / we can optimize it.”

### Shadowing script

“I have one performance concern about this query.”  
“It performs well in QA, but the production dataset is much larger.”  
“I’d like to measure the generated SQL and execution time first.”  
“If the numbers show a real bottleneck, we can decide how to optimize it.”

Luyện theo thứ tự:

1. Đọc chậm từng câu.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp lại từng câu một.
4. Ghi âm giọng của bạn.
5. Nói lại toàn bộ đoạn mà không nhìn text.

## 10. Bài tập thực hành chủ động

### Scenario

Bạn đang review một ASP.NET Core endpoint dùng EF Core. Query hiện load toàn bộ entity cùng hai collection liên quan. QA test cho kết quả ổn, nhưng production có dữ liệu lớn hơn nhiều.

### Nhiệm vụ

Hãy nói hoặc viết một update dài khoảng 5–7 câu cho Technical Lead.

Bạn cần có đủ các ý:

- Nêu performance concern.
- Nói rõ QA hiện vẫn chạy tốt.
- Giải thích vì sao production có thể khác.
- Nói bạn chưa muốn optimize ngay.
- Đề xuất ít nhất hai metrics cần đo.
- Nêu next action nếu metrics cho thấy bottleneck.

### Cấu trúc gợi ý

**Concern → Current evidence → Risk → Measurement → Conditional action**

### Useful phrases

- “I have one performance concern about…”
- “It performs well in QA right now, but…”
- “It may…”
- “I’d like to measure … first.”
- “If the numbers show a real bottleneck…”

### Tiêu chí hoàn thành

- 5–7 câu.
- Không khẳng định performance problem như một fact nếu chưa có metrics.
- Có ít nhất hai measurement cụ thể.
- Có một conditional next action.

## 12. Mẫu trả lời tham khảo

“I have one performance concern about this EF Core query. It performs well in QA right now, but the production dataset is much larger. Because we are loading multiple related collections, the query may return significantly more rows as the data grows. **I’d like to measure the generated SQL, execution time, and row count first.** I don’t think we need to optimize it before we have those numbers. **If the metrics show a real bottleneck, we can then decide whether to split the query or project only the required fields.**”

Các mẫu câu nên tái sử dụng:

- **“I’d like to measure … first.”**
- **“If the metrics show …, we can then decide whether to …”**
