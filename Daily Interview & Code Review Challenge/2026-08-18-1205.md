# Câu 1 — Vì sao async API vẫn làm cạn Thread Pool?

**Loại câu hỏi:** Internal mechanism trong production scenario  
**Độ khó:** Senior  
**Thời gian trả lời đề xuất:** 10 phút  
**Kỹ năng được đánh giá:** async/await internals, diagnostics, performance

## Bối cảnh
Một ASP.NET Core Web API .NET 8 xử lý nhiều request gọi Microsoft Graph và PostgreSQL. Sau khi tăng traffic, latency tăng mạnh dù CPU không cao. Một số endpoint bắt đầu timeout.

## Câu hỏi chính
Giải thích điều gì xảy ra bên trong với Task, Thread Pool và I/O async trong trường hợp này. Những hiểu nhầm phổ biến nào có thể dẫn đến lỗi thiết kế? Bạn xác minh giả thuyết bằng cách nào?

## Câu hỏi làm rõ nên cân nhắc
- Có đoạn code sync-over-async như `.Result` hoặc `.Wait()` không?
- Dependency bên ngoài có timeout rõ ràng không?
- Thread Pool metrics hiện tại thế nào?
- Request nào chiếm thời gian lâu nhất?

## Gợi ý tư duy
- Gợi ý 1: Phân biệt CPU work và I/O wait.
- Gợi ý 2: Kiểm tra blocking và continuation.
- Gợi ý 3: Dùng tracing, metrics và profiling để xác nhận.

## Cấu trúc trả lời đề xuất
1. Làm rõ workload
2. Giải thích runtime behavior
3. Xác định giả thuyết
4. Đo lường bằng telemetry
5. Đề xuất fix
6. Kiểm thử và theo dõi

## Ý chính của câu trả lời tốt

### Bắt buộc
- Hiểu async không tạo thêm thread cho I/O.
- Phân biệt blocking và awaiting.
- Nêu cách kiểm tra thực tế.

### Điểm cộng
- Đề cập ThreadPool starvation.
- Đề cập timeout, cancellation.

### Nâng cao
- Phân tích connection pool và downstream dependency.

## Hướng giải quyết tham khảo
Ưu tiên tìm blocking call, thiếu cancellation, timeout không hợp lý hoặc dependency chậm. Dùng OpenTelemetry, logs, runtime counters và load test để xác minh. Fix thường gồm async end-to-end, timeout policy, retry có kiểm soát và giới hạn concurrency.

## Mẫu trả lời trong phỏng vấn
"Em sẽ không kết luận ngay async bị lỗi. Em sẽ kiểm tra request flow, xác định thời gian nằm ở CPU hay I/O, xem có blocking call hay không. Nếu Thread Pool bị starvation, em sẽ tìm đoạn sync-over-async hoặc xử lý đồng bộ trong pipeline..."

## Câu hỏi đào sâu
- Nếu đổi sang nhiều worker thread có giải quyết không?
- Khi nào dùng Task.Run trong ASP.NET Core?
- Làm sao giới hạn request tới external API?

## Lỗi trả lời thường gặp
- Nghĩ async luôn nhanh hơn.
- Chỉ tăng thread thay vì tìm nguyên nhân.
- Không nói về đo lường.

# Câu 2 — Thiết kế hệ thống đồng bộ lịch Outlook cho người dùng

**Loại câu hỏi:** System design  
**Độ khó:** Senior+  
**Thời gian trả lời đề xuất:** 20 phút  
**Kỹ năng được đánh giá:** Architecture, consistency, Microsoft Graph integration

## Bối cảnh
Một hệ thống quản lý sự kiện cần tạo và cập nhật calendar event trên Microsoft 365 cho hàng nghìn người dùng. User có thể thay đổi thời gian sự kiện, nhưng không được cấp application permission quá rộng.

## Câu hỏi chính
Thiết kế solution đảm bảo đồng bộ event, xử lý permission boundary, retry, lỗi Graph API và tránh duplicate calendar item.

## Câu hỏi làm rõ nên cân nhắc
- Ai là owner của event?
- Có cần real-time update không?
- Token refresh xử lý thế nào?
- Khi Graph lỗi thì dữ liệu nào là source of truth?

## Gợi ý tư duy
- Gợi ý 1: Xác định ownership và consistency model.
- Gợi ý 2: Nghĩ về delegated permission, state tracking.
- Gợi ý 3: Thiết kế retry cùng idempotency.

## Hướng giải quyết tham khảo
Dùng application database làm source of truth, lưu external event id, trạng thái sync, retry metadata. Thiết kế background worker, idempotency key, audit log và monitoring. Không chọn application permission rộng nếu business không yêu cầu.

## Câu 3 — Thiết kế AI agent review code an toàn

**Loại câu hỏi:** AI engineering  
**Độ khó:** Senior+  
**Thời gian trả lời đề xuất:** 15 phút  
**Kỹ năng được đánh giá:** Context engineering, AI evaluation, security

## Bối cảnh
Team muốn dùng AI agent hỗ trợ review pull request .NET. Agent đọc source code, coding rules, issue và có thể chạy test.

## Câu hỏi chính
Thiết kế workflow agent như thế nào để feedback đáng tin cậy và không tạo rủi ro bảo mật?

## Hướng giải quyết tham khảo
Cần giới hạn permission, cung cấp context có kiểm soát, dùng structured output, validate bằng compiler/test, yêu cầu human approval và đo chất lượng feedback.
