# Code Review Challenge 1 — Tenant isolation bị phá vỡ trong API xuất báo cáo

## Bối cảnh

Một cổng quản trị B2B cho phép người dùng đăng nhập qua Entra ID và xuất báo cáo chi phí theo tenant. Mỗi người có thể thuộc nhiều tenant với quyền khác nhau. API nhận khoảng 500 request/phút; báo cáo có thể chứa dữ liệu nhạy cảm. Frontend gửi tenant đang chọn trong query string. Hệ thống xác thực JWT tại middleware; quyền truy cập từng tenant lưu trong SQL Server. Production nhận phản ánh người dùng xem được báo cáo của tenant khác khi đoán ID, và p95 tăng khi tải cao. Không được tin tenant ID từ client là bằng chứng phân quyền.

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/reports")]
public sealed class ReportsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<ReportsController> _logger;

    public ReportsController(AppDbContext db, ILogger<ReportsController> logger)
    {
        _db = db;
        _logger = logger;
    }

    [HttpGet("expenses")]
    public async Task<IActionResult> Expenses(
        Guid tenantId, DateTime from, DateTime to)
    {
        var userId = User.FindFirst("oid")?.Value;
        _logger.LogInformation(
            "Export requested by {User} for {Tenant}", userId, tenantId);

        if (from > to) return BadRequest("Invalid range");

        var rows = await _db.Expenses
            .Include(x => x.Employee)
            .Where(x => x.TenantId == tenantId
                     && x.IncurredAt >= from && x.IncurredAt <= to)
            .OrderByDescending(x => x.IncurredAt)
            .ToListAsync();

        var output = rows.Select(x => new
        {
            x.Id,
            x.Amount,
            x.Employee.FullName,
            x.Employee.Email,
            x.Description
        }).ToList();

        return Ok(output);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Không kiểm tra quyền đối với tenant được yêu cầu

**Vấn đề:** `[Authorize]` chỉ đòi hỏi principal đã xác thực, không kiểm tra membership và permission trên `tenantId`.

**Tại sao xảy ra:** Client điều khiển tenant ID và query lọc trực tiếp theo ID đó.

**Ảnh hưởng production:** Bất kỳ tài khoản hợp lệ nào có thể truy cập dữ liệu tenant khác nếu biết/đoán ID.

**Cách sửa:** Xác minh membership và quyền `Reports.Read` trên tenant đích bằng server-side policy/service; từ chối trước khi truy vấn dữ liệu. Rà soát access log, thu hồi export link nếu có và đánh giá phạm vi incident.

### [High] — Nhận dạng user chưa đủ ngữ cảnh

**Vấn đề:** Chỉ lấy claim `oid` để nhận dạng.

**Tại sao xảy ra:** Object ID cần được diễn giải trong ngữ cảnh issuer/identity tenant; cấu hình token validation và claim mapping cũng phải được xác minh.

**Ảnh hưởng production:** Mapping membership sai hoặc nhầm danh tính giữa nguồn token.

**Cách sửa:** Sử dụng định danh nội bộ được ánh xạ từ cặp issuer + subject (hoặc issuer/tenant + object ID theo chính sách xác thực đã xác minh). Cấu hình validation issuer, audience và token phù hợp.

### [High] — Không giới hạn khối lượng dữ liệu trả về

**Vấn đề:** Load toàn bộ entities rồi materialize một danh sách output thứ hai.

**Tại sao xảy ra:** Không có giới hạn khoảng thời gian, số hàng, dung lượng hoặc quy trình export lớn.

**Ảnh hưởng production:** Memory/GC tăng, timeout, áp lực SQL và response lớn.

**Cách sửa:** Giới hạn range, dùng projection, phân trang có giới hạn; nếu cần export lớn, dùng background export có quota, lưu file an toàn và URL truy cập có thời hạn.

### [Medium] — Truy vấn thừa dữ liệu và tracking

**Vấn đề:** `Include(Employee)` cùng `ToListAsync` materialize entities tracked, trong khi endpoint chỉ đọc một số cột.

**Tại sao xảy ra:** Query được viết theo entity graph thay vì DTO projection.

**Ảnh hưởng production:** Tăng I/O, allocation và change tracker overhead.

**Cách sửa:** `AsNoTracking`, `Select` trước materialization, kiểm tra execution plan và index theo tenant/date.

### [Medium] — Thiếu cancellation và chuẩn hóa thời gian

**Vấn đề:** Không truyền `RequestAborted`; `DateTime` đầu vào chưa có quy ước UTC/timezone rõ ràng.

**Tại sao xảy ra:** API contract không chuẩn hóa thời gian và vòng đời request.

**Ảnh hưởng production:** Query tiếp tục sau khi client hủy; sai lệch ranh giới ngày hoặc thiếu bản ghi.

**Cách sửa:** Dùng `DateTimeOffset`, UTC, khoảng nửa mở `[from, to)`, cancellation token và validation khoảng thời gian.

### [Medium] — Thiếu audit và giới hạn chống lạm dụng

**Vấn đề:** Log hiện tại chưa thể hiện kết quả authorization, lượng dữ liệu hoặc outcome của export.

**Tại sao xảy ra:** Logging tập trung vào việc nhận request, không có audit event và quota.

**Ảnh hưởng production:** Khó điều tra truy cập trái phép và phát hiện export bất thường.

**Cách sửa:** Audit actor, tenant, policy, outcome, count và correlation ID; giới hạn tần suất/dung lượng, không ghi nội dung báo cáo vào log.

## Phiên bản đề xuất

Ví dụ sau giả định middleware đã validate JWT, `ICurrentActor` ánh xạ identity hợp lệ sang user nội bộ, `ITenantAccess` tra membership/permission từ nguồn server-side. Các interface là abstraction ứng dụng, không phải API built-in của ASP.NET Core.

```csharp
[Authorize]
[ApiController]
[Route("api/tenants/{tenantId:guid}/reports")]
public sealed class ReportsController(
    AppDbContext db,
    ICurrentActor actor,
    ITenantAccess access,
    ILogger<ReportsController> logger) : ControllerBase
{
    [HttpGet("expenses")]
    public async Task<IActionResult> Expenses(
        Guid tenantId, DateTimeOffset from, DateTimeOffset to,
        int limit = 200, CancellationToken ct = default)
    {
        if (from >= to || to - from > TimeSpan.FromDays(31))
            return BadRequest("Invalid date range");
        if (limit is < 1 or > 500)
            return BadRequest("Invalid limit");

        var userId = actor.RequireInternalUserId();
        if (!await access.CanReadReportsAsync(userId, tenantId, ct))
        {
            logger.LogWarning("Report access denied for tenant {TenantId}",
                tenantId);
            return Forbid();
        }

        var start = from.UtcDateTime;
        var end = to.UtcDateTime;

        var rows = await db.Expenses.AsNoTracking()
            .Where(x => x.TenantId == tenantId
                     && x.IncurredAt >= start && x.IncurredAt < end)
            .OrderByDescending(x => x.IncurredAt)
            .ThenByDescending(x => x.Id)
            .Select(x => new ExpenseDto(
                x.Id, x.Amount, x.Employee.FullName))
            .Take(limit)
            .ToListAsync(ct);

        logger.LogInformation(
            "Report returned {Count} rows for tenant {TenantId}",
            rows.Count, tenantId);
        return Ok(rows);
    }
}

public sealed record ExpenseDto(Guid Id, decimal Amount, string EmployeeName);

public interface ICurrentActor
{
    Guid RequireInternalUserId();
}
public interface ITenantAccess
{
    Task<bool> CanReadReportsAsync(
        Guid userId, Guid tenantId, CancellationToken ct);
}
```

Lưu ý: Đây là API lấy trang đầu, **không phải export đầy đủ**. Nếu cần duyệt hết, thêm cursor/keyset dựa trên `(IncurredAt, Id)`, và đảm bảo query membership không tạo TOCTOU nghiêm trọng nếu quyền bị thu hồi giữa các bước. Có thể bổ sung database row-level security như lớp phòng thủ thứ hai khi phù hợp; không thay thế kiểm thử authorization.

## Giải thích thiết kế sau khi sửa

Authorization được thực hiện trước truy vấn dữ liệu tenant. Identity được ánh xạ về user nội bộ; query chỉ lấy cột cần thiết và giới hạn kết quả. `CancellationToken` gắn với request, còn khoảng thời gian được chuẩn hóa. Cần thiết kế index phù hợp với `TenantId, IncurredAt, Id` sau khi kiểm tra execution plan, không tạo index theo phỏng đoán.

## Trade-offs

Membership lookup tăng một lần truy cập dữ liệu, có thể tối ưu bằng cache ngắn hạn với chiến lược revoke rõ ràng. Giới hạn page giúp ổn định API nhưng buộc client phân trang; export lớn đòi hỏi workflow bất đồng bộ, retention, mã hóa và kiểm soát download. Database row-level security tăng defense-in-depth nhưng cũng tăng độ phức tạp vận hành và connection context.

## Cách kiểm thử

1. **Security integration:** User thuộc tenant A thử lấy tenant B, kể cả khi biết ID; phải bị từ chối.
2. **Authorization matrix:** Viewer, ReportReader, admin, revoked membership, user nhiều tenant và identity khác issuer.
3. **Database test:** Kiểm tra boundary UTC, thứ tự ổn định, projection và không trả trường nhạy cảm ngoài contract.
4. **Load test:** p95, memory và query plan với dữ liệu lớn; xác nhận giới hạn 500 bản ghi.
5. **Failure-path:** Hủy HTTP request giữa truy vấn; kiểm tra query cancellation và telemetry.

## Quan sát trong production

Theo dõi denied/allowed report requests theo tenant (không dùng tenant ID làm high-cardinality metric label), số bản ghi, p95/p99, SQL duration, allocated bytes, 429, 403 và trace correlation trong Application Insights. Audit quyền truy cập cần retention và access control riêng; alert khi có pattern export bất thường.

<script setup lang="ts">
import { ref, watch, onMounted } from 'vue';

type Product = { id: string; name: string; price: number };
const query = ref('');
const category = ref('all');
const products = ref<Product[]>([]);
const loading = ref(false);
const error = ref('');
const token = localStorage.getItem('access_token') ?? '';

async function loadProducts() {
  loading.value = true;
  error.value = '';
  try {
    const url = '/api/products?search=' + query.value +
      '&category=' + category.value;
    const response = await fetch(url, {
      headers: { Authorization: 'Bearer ' + token }
    });
    const data = await response.json();
    products.value = data.items;
  } catch (e) {
    error.value = String(e);
  } finally {
    loading.value = false;
  }
}

watch([query, category], loadProducts);
onMounted(loadProducts);
</script>

<template>
  <input v-model="query" placeholder="Search products" />

    <option value="all">All</option>
    <option value="hardware">Hardware</option>
    <option value="software">Software</option>
  </select>
  <p v-if="loading">Loading...</p>
  <p v-if="error">{{ error }}</p>

</template>

## Kết quả code review tham khảo

### [High] — Response cũ ghi đè response mới

**Vấn đề:** Không có cancellation hoặc request version guard.

**Tại sao xảy ra:** Network response không đảm bảo thứ tự hoàn thành giống thứ tự gửi.

**Ảnh hưởng production:** UI hiển thị dữ liệu không khớp filter; người dùng đưa ra quyết định sai.

**Cách sửa:** Abort request cũ và chỉ commit kết quả của generation mới nhất.

### [High] — Không xử lý HTTP error và token lifecycle

**Vấn đề:** `fetch` resolve khi nhận 401/500; code parse JSON và dùng `data.items` như response thành công. Token bị chụp một lần và đọc từ localStorage.

**Tại sao xảy ra:** Nhầm HTTP status với exception và bỏ qua refresh/authentication lifecycle.

**Ảnh hưởng production:** UI lỗi ngầm, kết quả sai; token trong localStorage tăng rủi ro bị đánh cắp khi có XSS.

**Cách sửa:** Kiểm tra `response.ok`, xử lý 401 qua auth service, dùng auth architecture đã được threat-model (ưu tiên HttpOnly secure cookie/BFF khi phù hợp); không tự động retry vô hạn.

### [Medium] — Loading state bị sai do request overlap

**Vấn đề:** Request cũ có thể đặt `loading=false` trong khi request mới vẫn chạy.

**Tại sao xảy ra:** Shared state được thay đổi bởi nhiều async invocations.

**Ảnh hưởng production:** Spinner nhấp nháy, trạng thái UI không đáng tin.

**Cách sửa:** Chỉ request hiện hành được cập nhật loading/error/results.

### [Medium] — Không debounce hoặc kiểm soát lưu lượng

**Vấn đề:** Mỗi lần gõ gửi request ngay.

**Tại sao xảy ra:** Watcher không gom thay đổi nhanh.

**Ảnh hưởng production:** Tăng tải API, rate limit và chi phí backend.

**Cách sửa:** Debounce hợp lý, min query length nếu nghiệp vụ cho phép; backend vẫn phải có rate limit.

### [Medium] — Query string không encode và thiếu kiểm tra schema

**Vấn đề:** Nối chuỗi trực tiếp, response được tin tưởng.

**Tại sao xảy ra:** Ký tự `&`, `#`, dấu tiếng Việt hoặc dữ liệu malformed không được xử lý đúng.

**Ảnh hưởng production:** Query bị thay đổi ý nghĩa hoặc UI exception.

**Cách sửa:** `URLSearchParams` và validation runtime đối với payload quan trọng.

### [Medium] — Không cleanup khi component unmount

**Vấn đề:** Pending requests không được abort khi rời trang.

**Tại sao xảy ra:** Không có cleanup hook.

**Ảnh hưởng production:** Lãng phí tài nguyên và có thể thực hiện cập nhật state không còn liên quan.

**Cách sửa:** AbortController cleanup và invalidate generation.

## Phiên bản đề xuất

Ví dụ dùng `useProductAuth` làm abstraction ứng dụng cung cấp header hợp lệ ở thời điểm request; không giả định đây là Vue API. Nếu dùng BFF cookie-based, bỏ header Authorization và cấu hình CSRF phù hợp.

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';
import { useProductAuth } from '@/auth/useProductAuth';

type Product = { id: string; name: string; price: number };
const query = ref('');
const category = ref('all');
const products = ref<Product[]>([]);
const loading = ref(false);
const error = ref('');
const auth = useProductAuth();

let timer: ReturnType<typeof setTimeout> | undefined;
let controller: AbortController | undefined;
let generation = 0;

async function load(version: number) {
  controller?.abort();
  const current = new AbortController();
  controller = current;
  loading.value = true;
  error.value = '';

  try {
    const params = new URLSearchParams({
      search: query.value.trim(),
      category: category.value
    });
    const response = await fetch('/api/products?' + params, {
      signal: current.signal,
      headers: await auth.getHeaders()
    });
    if (!response.ok) {
      if (response.status === 401) {
        auth.onUnauthorized();
        throw new Error('Authentication required');
      }
      throw new Error('Product search unavailable');
    }
    const payload: unknown = await response.json();
    if (!isProductPage(payload)) throw new Error('Invalid API response');
    if (version === generation) products.value = payload.items;
  } catch (e) {
    if (version === generation && !current.signal.aborted)
      error.value = e instanceof Error ? e.message : 'Unknown error';
  } finally {
    if (version === generation) loading.value = false;
  }
}

function isProductPage(value: unknown): value is { items: Product[] } {
  if (typeof value !== 'object' || value === null ||
      !('items' in value) || !Array.isArray(value.items)) return false;
  return value.items.every((x: unknown) =>
    typeof x === 'object' && x !== null &&
    'id' in x && typeof x.id === 'string' &&
    'name' in x && typeof x.name === 'string' &&
    'price' in x && typeof x.price === 'number');
}

watch([query, category], () => {
  generation++;
  controller?.abort();
  clearTimeout(timer);
  loading.value = true;
  timer = setTimeout(() => void load(generation), 300);
}, { immediate: true });

onUnmounted(() => {
  generation++;
  clearTimeout(timer);
  controller?.abort();
});
</script>

<template>
  <input v-model="query" placeholder="Search products" />
  <select v-model="category">
    <option value="all">All</option>
    <option value="hardware">Hardware</option>
    <option value="software">Software</option>
  </select>
  <p v-if="loading">Loading...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <ul>
    <li v-for="item in products" :key="item.id">
      {{ item.name }} — {{ item.price }}
    </li>
  </ul>
</template>
```

**Điểm cần hoàn thiện khi tích hợp thực tế:** `auth.getHeaders()` phải xử lý token refresh theo policy của ứng dụng; nếu refresh chậm, generation guard vẫn ngăn stale results nhưng không hủy chính thao tác refresh trừ khi auth service hỗ trợ signal. Thêm timeout và retry có giới hạn nếu SLO yêu cầu. Cân nhắc giữ dữ liệu cũ trong lúc tải nhưng phải gắn nhãn stale để tránh gây hiểu nhầm.

## Giải thích thiết kế sau khi sửa

Generation guard bảo vệ tính đúng đắn ngay cả khi abort không kịp ngăn response. Debounce giảm request burst; AbortController tiết kiệm tài nguyên; `response.ok` và schema validation tách lỗi mạng, lỗi HTTP và lỗi contract. Auth được tách khỏi component để quản lý vòng đời token tập trung.

## Trade-offs

Debounce thêm khoảng trễ trước khi tìm kiếm; cancellation không đảm bảo backend dừng mọi xử lý đã bắt đầu. Validation runtime có overhead và cần đồng bộ với API contract. Dùng thư viện query-state như TanStack Query có thể giảm code tự quản lý nhưng tăng dependency và yêu cầu thống nhất cache keys, stale policy.

## Cách kiểm thử

1. **Playwright E2E:** Intercept response A chậm hơn B; UI cuối cùng chỉ hiển thị B.
2. **Failure-path:** Trả 401, 429, 500, invalid JSON và malformed schema; UI hiển thị lỗi đúng và không dùng kết quả sai.
3. **Concurrency test:** Gõ liên tục, đổi category rồi unmount; kiểm tra request cũ bị hủy và loading state không bị reset sớm.
4. **API contract test:** Từ khóa chứa dấu tiếng Việt, `&`, `#` và khoảng trắng; server nhận đúng query.
5. **Load/browser test:** Đếm requests/keystroke và thời gian từ input đến kết quả; xác nhận debounce giảm burst.

## Quan sát trong production

Theo dõi request duration, error rate theo status, số abort, số stale response bị bỏ qua, debounce-to-result latency và số lần auth refresh thất bại. Dùng correlation ID để nối browser telemetry với API trace; không log access token hoặc toàn bộ query nếu chứa dữ liệu nhạy cảm.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào nên giữ stale results để cải thiện UX, và làm sao không đánh lừa người dùng?
2. Nếu hai component cùng tìm kiếm một key, thiết kế deduplication và cache như thế nào?
3. Thiết kế refresh token single-flight để tránh nhiều request cùng refresh khi 401?

## Kiến thức trọng tâm

Tenant isolation là quyết định authorization theo từng resource, không phải chỉ xác thực JWT. Trong UI bất đồng bộ, thứ tự hoàn thành request không đảm bảo thứ tự phát sinh thao tác. Cả hai trường hợp đều cần bảo vệ correctness tại boundary, kiểm thử failure path và telemetry có thể xác minh.
