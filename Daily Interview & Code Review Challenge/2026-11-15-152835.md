## Bối cảnh

Sau khi triển khai, một khách hàng thấy dữ liệu tenant khác, instance restart vì memory, và Excel hiển thị sai cột. JWT đã được xác thực; quyền export là permission riêng. ## Đoạn code cần review

```csharp
[ApiController]
[Route("api/requisitions")]
public sealed class ExportController(HiringDbContext db) : ControllerBase
{
    [HttpGet("export")]
    [Authorize]
    public async Task<IActionResult> Export(
        [FromQuery] Guid tenantId,
        [FromQuery] string? search)
    {
        var query = db.Requisitions
            .Include(r => r.Approvals)
            .Where(r => r.TenantId == tenantId);
        if (!string.IsNullOrWhiteSpace(search))
            query = query.Where(r => r.Title.Contains(search));

        var rows = await query.ToListAsync();
        var builder = new StringBuilder();
        builder.AppendLine("Id,Title,Status,ApproverEmail");
        foreach (var row in rows)
        {
            var email = row.Approvals
                .OrderByDescending(a => a.CreatedAt)
                .FirstOrDefault()?.Email ?? "";
            builder.AppendLine(
                $"{row.Id},{row.Title},{row.Status},{email}");
        }
        return File(Encoding.UTF8.GetBytes(builder.ToString()),
            "text/csv", "requisitions.csv");
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Cross-tenant IDOR

**Vấn đề:** Client tự chọn tenantId.  
**Tại sao xảy ra:** Authorize chỉ xác thực user, không ràng buộc tenant.  
**Ảnh hưởng production:** Xuất dữ liệu khách hàng khác.  
**Cách sửa:** Resolve tenant từ trusted claims hoặc server-side membership, bắt buộc tenant predicate trong query.

### [High] — Thiếu permission export

**Vấn đề:** Bất kỳ authenticated user nào cũng export được.  
**Tại sao xảy ra:** Không kiểm tra policy và resource permissions.  
**Ảnh hưởng production:** Lộ dữ liệu nội bộ.  
**Cách sửa:** Authorize policy RequisitionExport; kiểm tra membership nếu user có nhiều tenant.

### [High] — CSV formula injection

**Vấn đề:** Title/email có thể bắt đầu bằng =,+,-,@.  
**Tại sao xảy ra:** Ghi dữ liệu không đáng tin cậy trực tiếp cho spreadsheet.  
**Ảnh hưởng production:** Công thức độc hại hoặc dữ liệu bị diễn giải sai.  
**Cách sửa:** Neutralize formula-like cells, kể cả leading whitespace/control characters; kiểm thử Excel/LibreOffice.

### [High] — Memory amplification

**Vấn đề:** ToListAsync, StringBuilder, ToString và GetBytes cùng giữ dữ liệu.  
**Tại sao xảy ra:** Eager materialization toàn bộ export.  
**Ảnh hưởng production:** OOM/GC và làm chậm request khác.  
**Cách sửa:** Stream kết quả đã projection; quota concurrent exports, background job cho file lớn.

### [Medium] — Load dư approvals

**Vấn đề:** Include toàn bộ collection dù chỉ cần email mới nhất.  
**Tại sao xảy ra:** Query shape chưa tối ưu.  
**Ảnh hưởng production:** SQL traffic, tracking và allocation cao.  
**Cách sửa:** Projection subquery lấy latest approval; đo generated SQL/execution plan.

### [Medium] — CSV serialization sai

**Vấn đề:** Comma, quote, CRLF làm lệch cột.  
**Tại sao xảy ra:** String interpolation không escape CSV.  
**Ảnh hưởng production:** File hỏng hoặc sai dữ liệu.  
**Cách sửa:** Dùng CSV library với RFC 4180 escaping.

### [Medium] — Không cancellation

**Vấn đề:** Không truyền RequestAborted vào query.  
**Tại sao xảy ra:** Thiếu CancellationToken.  
**Ảnh hưởng production:** Client đã ngắt nhưng server vẫn chạy.  
**Cách sửa:** Propagate token đến DB và stream.

### [Medium] — Không có quota, ordering

**Vấn đề:** Một user có thể xuất lượng lớn không giới hạn, thứ tự không xác định.  
**Tại sao xảy ra:** Thiếu export contract.  
**Ảnh hưởng production:** Resource exhaustion và khó kiểm tra tính nhất quán.  
**Cách sửa:** Stable ordering, concurrency limits và chuyển large export sang job; xác định snapshot semantics.

### [Low] — Thiếu audit

**Vấn đề:** Không có audit outcome, rows, duration.  
**Tại sao xảy ra:** Export chưa có telemetry contract.  
**Ảnh hưởng production:** Khó điều tra lộ dữ liệu.  
**Cách sửa:** Audit user/tenant/request ID và outcome, không log nội dung requisition.

## Phiên bản đề xuất

Giả định JWT issuer đáng tin cậy phát hành tenant_id, policy RequisitionExport đã đăng ký; với multi-tenant membership cần kiểm tra quyền server-side. Ví dụ minh họa streaming, cần compile/test trên target framework.

```csharp
[ApiController]
[Route("api/requisitions")]
public sealed class ExportController(HiringDbContext db) : ControllerBase
{
    [HttpGet("export")]
    [Authorize(Policy = "RequisitionExport")]
    public async Task Export([FromQuery] string? search,
                             CancellationToken ct)
    {
        if (!Guid.TryParse(User.FindFirst("tenant_id")?.Value,
                           out var tenantId))
        {
            Response.StatusCode = 403;
            return;
        }

        Response.ContentType = "text/csv; charset=utf-8";
        Response.Headers.ContentDisposition =
            "attachment; filename=\"requisitions.csv\"";

        var query = db.Requisitions.AsNoTracking()
            .Where(r => r.TenantId == tenantId);
        if (!string.IsNullOrWhiteSpace(search))
            query = query.Where(r => r.Title.Contains(search));

        var rows = query.OrderBy(r => r.Id).Select(r => new
        {
            r.Id, r.Title, r.Status,
            Email = r.Approvals.OrderByDescending(a => a.CreatedAt)
                .ThenByDescending(a => a.Id)
                .Select(a => a.Email).FirstOrDefault()
        }).AsAsyncEnumerable();

        await using var writer = new StreamWriter(
            Response.Body, new UTF8Encoding(true), leaveOpen: true);
        await writer.WriteLineAsync("Id,Title,Status,ApproverEmail");
        await foreach (var row in rows.WithCancellation(ct))
        {
            await writer.WriteLineAsync(
                string.Join(",", Csv(row.Id.ToString()),
                    Csv(row.Title), Csv(row.Status.ToString()),
                    Csv(row.Email)).AsMemory(), ct);
        }
        await writer.FlushAsync(ct);
    }

    private static string Csv(string? value)
    {
        var s = value ?? "";
        var trimmed = s.TrimStart();
        if (trimmed.Length > 0 && "=+-@".Contains(trimmed[0]))
            s = "'" + s;
        return "\"" + s.Replace("\"", "\"\"") + "\"";
    }
}
```

Đây là mẫu minh họa, không phải CSV sanitizer hoàn chỉnh: cần kiểm thử control characters, spreadsheet variants và dùng library đã kiểm chứng. Khi response bắt đầu, lỗi giữa stream không thể đổi sang ProblemDetails; client phải phát hiện file truncated. Cần limit export và kiểm soát connection lifetime.

## Giải thích thiết kế sau khi sửa

Enforce tenant trước query, projection giảm dữ liệu và streaming giảm peak memory. Stable ordering không đồng nghĩa snapshot consistency; nếu dữ liệu thay đổi giữa export, cần xác định isolation requirement.

## Trade-offs

Streaming giữ HTTP/DB connection lâu, đặc biệt với slow client. Background export vào Blob Storage tốn thêm job lifecycle, quota, cleanup, authorization cho download nhưng phù hợp hàng triệu dòng. Projection có thể tạo correlated subquery, cần đo execution plan trước khi thêm index.

## Cách kiểm thử

1. Security integration: user tenant A không thể lấy tenant B; user thiếu export permission nhận 403.
2. CSV: quote, comma, CRLF, unicode và formula-like cells; round-trip với CSV reader và spreadsheet mục tiêu.
3. Load: 20 export lớn đồng thời, đo RSS, GC, DB pool và p95 của API khác.
4. Cancellation: ngắt client giữa stream và xác minh DB cancellation.
5. SQL: so sánh execution plan, row count và kết quả khi approvals có cùng timestamp.

## Quan sát trong production

Application Insights: request duration, SQL dependency duration, export rows/bytes, cancellations, OOM/restarts, active exports; audit user/tenant/request ID/permission decision. Alert khi 403 export bất thường hoặc p99/GC tăng. Không log nội dung requisition.

## Câu hỏi phỏng vấn mở rộng

1. Nếu yêu cầu export 2 triệu dòng, thiết kế background job và SAS download ra sao?
2. Khi cần snapshot consistency trong lúc dữ liệu thay đổi, bạn chọn chiến lược nào?
3. Quyền export bị revoke trong lúc job chạy: cần xử lý thế nào?

```tsx
type Job = { id: string; title: string; department: string };
type Detail = Job & { description: string };
const cache = new Map<string, Job[]>();

export function JobSearch({ token }: { token: string }) {
  const [query, setQuery] = React.useState("");
  const [department, setDepartment] = React.useState("all");
  const [jobs, setJobs] = React.useState<Job[]>([]);
  const [selected, setSelected] = React.useState<Detail | null>(null);
  const [loading, setLoading] = React.useState(false);
  const [error, setError] = React.useState("");

  React.useEffect(() => {
    const key = query + ":" + department;
    if (cache.has(key)) {
      setJobs(cache.get(key)!);
      return;
    }
    setLoading(true);
    fetch("/api/jobs?q=" + query + "&department=" + department, {
      headers: { Authorization: "Bearer " + token }
    })
      .then(r => r.json())
      .then(data => {
        cache.set(key, data);
        setJobs(data);
      })
      .catch(e => setError(String(e)))
      .finally(() => setLoading(false));
  }, [query, department, token]);

  async function openJob(id: string) {
    setLoading(true);
    const r = await fetch("/api/jobs/" + id, {
      headers: { Authorization: "Bearer " + token }
    });
    setSelected(await r.json());
    setLoading(false);
  }

  return <section>
    <input value={query} onChange={e => setQuery(e.target.value)} />
    <select value={department}
      onChange={e => setDepartment(e.target.value)}>
      <option value="all">All</option>
      <option value="engineering">Engineering</option>
    </select>
    {loading && <p>Loading...</p>}
    {error && <p role="alert">{error}</p>}
    {jobs.map(j => <button key={j.id}
      onClick={() => openJob(j.id)}>{j.title}</button>)}
    {selected && <article><h2>{selected.title}</h2>
      <p>{selected.description}</p></article>}
  </section>;
}
```

## Phiên bản đề xuất

```tsx
type Job = { id: string; title: string; department: string };
type Detail = Job & { description: string };

async function getJson<T>(url: string, token: string,
                          signal: AbortSignal): Promise<T> {
  const response = await fetch(url, {
    headers: { Authorization: `Bearer ${token}` }, signal
  });
  if (!response.ok) throw new Error(`HTTP ${response.status}`);
  return await response.json() as T;
}

export function JobSearch({ token, sessionKey }:
  { token: string; sessionKey: string }) {
  const [query, setQuery] = React.useState("");
  const [department, setDepartment] = React.useState("all");
  const [jobs, setJobs] = React.useState<Job[]>([]);
  const [selectedId, setSelectedId] = React.useState<string | null>(null);
  const [selected, setSelected] = React.useState<Detail | null>(null);
  const [listLoading, setListLoading] = React.useState(false);
  const [detailLoading, setDetailLoading] = React.useState(false);
  const [listError, setListError] = React.useState("");
  const [detailError, setDetailError] = React.useState("");

  React.useEffect(() => {
    const controller = new AbortController();
    setJobs([]); setListError(""); setListLoading(true);
    const params = new URLSearchParams({ q: query, department });
    getJson<Job[]>(`/api/jobs?${params}`, token, controller.signal)
      .then(data => { if (!controller.signal.aborted) setJobs(data); })
      .catch(e => { if (!controller.signal.aborted) setListError(String(e)); })
      .finally(() => {
        if (!controller.signal.aborted) setListLoading(false);
      });
    return () => controller.abort();
  }, [query, department, token, sessionKey]);

  React.useEffect(() => {
    const controller = new AbortController();
    setSelected(null); setDetailError("");
    setDetailLoading(selectedId !== null);
    if (selectedId !== null) {
      getJson<Detail>(
        `/api/jobs/${encodeURIComponent(selectedId)}`,
        token, controller.signal)
        .then(data => {
          if (!controller.signal.aborted) setSelected(data);
        })
        .catch(e => {
          if (!controller.signal.aborted) setDetailError(String(e));
        })
        .finally(() => {
          if (!controller.signal.aborted) setDetailLoading(false);
        });
    }
    return () => controller.abort();
  }, [selectedId, token, sessionKey]);

  return <section>
    <label>Search jobs
      <input value={query} onChange={e => setQuery(e.target.value)} />
    </label>
    <label>Department
      <select value={department}
        onChange={e => setDepartment(e.target.value)}>
        <option value="all">All</option>
        <option value="engineering">Engineering</option>
      </select>
    </label>
    {listLoading && <p role="status">Loading jobs...</p>}
    {listError && <p role="alert">{listError}</p>}
    {!listLoading && !listError && jobs.length === 0 && <p>No results</p>}
    {jobs.map(job => <button key={job.id}
      onClick={() => setSelectedId(job.id)}>{job.title}</button>)}
    {detailLoading && <p role="status">Loading detail...</p>}
    {detailError && <p role="alert">{detailError}</p>}
    {selected && <article><h2>{selected.title}</h2>
      <p>{selected.description}</p></article>}
  </section>;
}
```

Ví dụ chưa có runtime schema validation; production cần kiểm tra JSON shape. Abort không bảo đảm backend ngừng xử lý. SessionKey phải đổi khi identity/authorization context đổi, không chỉ khi access token refresh.

## Giải thích thiết kế sau khi sửa

Mỗi effect sở hữu request lifecycle và AbortController. Separate state tránh tranh chấp spinner. Key theo session reset selection và jobs, ngăn stale state giữa hai identity. Không cache protected data trong module scope.

## Trade-offs

Không cache làm tăng network requests. Có thể dùng TanStack Query với session-aware keys và clear cache khi logout nhưng thêm complexity. Debounce giảm traffic và thêm độ trễ; quyết định dựa trên request rate và typing-to-result latency. Cancellation không thay thế server authorization.

## Cách kiểm thử

1. Race test: response cũ trả sau response mới không được ghi đè.
2. Session test: logout/login khác identity không còn list/detail cũ.
3. Failure-path: HTTP 401/403/500, invalid JSON và aborted requests.
4. Playwright: gõ nhanh, đổi filter, mở nhiều detail trên mạng chậm.
5. Accessibility: keyboard, labels, status và empty state.

## Quan sát trong production

Browser metrics: HTTP status, request duration, abort count, JS errors, detail latency, correlation ID; không log token. Application Insights nối frontend request với backend traces. Alert nếu 401/403, unhandled rejections hoặc frontend error rate tăng sau release.
