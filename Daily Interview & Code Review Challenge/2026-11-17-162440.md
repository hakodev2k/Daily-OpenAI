## Bối cảnh

Catalog có 2 triệu sản phẩm trong PostgreSQL; nhân viên vẫn cập nhật giá và unpublish trong lúc reindex. Elasticsearch phục vụ search qua alias catalog-read. Hệ thống phải giữ eventual consistency trong 2 phút, job có thể restart khi deploy. PostgreSQL là source of truth; chưa xác nhận có CDC.

## Đoạn code cần review

```csharp
public sealed class ReindexJob
{
    private readonly CatalogDbContext _db;
    private readonly HttpClient _search;
    public ReindexJob(CatalogDbContext db, IHttpClientFactory factory)
    {
        _db = db;
        _search = factory.CreateClient("elastic");
    }

    public async Task Run(CancellationToken ct)
    {
        var index = "catalog-" + DateTime.UtcNow.ToString("yyyyMMddHHmm");
        await _search.PutAsync($"/{index}", null, ct);
        var products = await _db.Products
            .Where(x => x.Published).ToListAsync(ct);
        foreach (var p in products)
        {
            await _search.PutAsJsonAsync($"/{index}/_doc/{p.Id}",
                new { p.Name, p.Price, p.UpdatedAt }, ct);
        }
        await _search.PostAsJsonAsync("/_aliases", new {
            actions = new object[] {
                new { remove = new { index = "catalog-*", alias = "catalog-read" } },
                new { add = new { index, alias = "catalog-read" } }
            }
        }, ct);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Snapshot và cutover bỏ sót write

**Vấn đề:** Snapshot và cutover bỏ sót write.  
**Tại sao xảy ra:** Query chỉ đọc tại một thời điểm, trong khi dữ liệu tiếp tục thay đổi.  
**Ảnh hưởng production:** Giá và trạng thái publish bị stale sau cutover.  
**Cách sửa:** Dùng durable outbox/change log, watermark, backfill rồi replay delta; giữ projection liên tục sau swap.

### [High] — Không xử lý unpublish và delete

**Vấn đề:** Không xử lý unpublish và delete.  
**Tại sao xảy ra:** Chỉ chọn Published=true, không có tombstone.  
**Ảnh hưởng production:** Sản phẩm đã rút vẫn hiện trong search.  
**Cách sửa:** Phát delete operation theo product version và replay idempotently.

### [High] — Bỏ qua HTTP status và mapping

**Vấn đề:** Bỏ qua HTTP status và mapping.  
**Tại sao xảy ra:** HttpClient không throw khi 4xx/5xx.  
**Ảnh hưởng production:** Có thể swap sang index thiếu dữ liệu.  
**Cách sửa:** EnsureSuccessStatusCode, validate mapping, kiểm tra bulk partial failures.

### [High] — Không có checkpoint hoặc single-owner cutover

**Vấn đề:** Không có checkpoint hoặc single-owner cutover.  
**Tại sao xảy ra:** Job chạy lại từ đầu và tên index có thể trùng.  
**Ảnh hưởng production:** Nhiều worker tranh alias, restart lãng phí.  
**Cách sửa:** Checkpoint, lease/fencing, run ID và resume.

### [Medium] — Materialize 2 triệu tracked entities

**Vấn đề:** Materialize 2 triệu tracked entities.  
**Tại sao xảy ra:** ToListAsync và tracking mặc định.  
**Ảnh hưởng production:** OOM, GC, latency.  
**Cách sửa:** Keyset batches, projection và AsNoTracking.

### [Medium] — Một HTTP request cho mỗi product

**Vấn đề:** Một HTTP request cho mỗi product.  
**Tại sao xảy ra:** Không bulk/backpressure.  
**Ảnh hưởng production:** Reindex kéo dài và dễ bị throttling.

## Phiên bản đề xuất

Mã minh họa dưới đây sử dụng các abstraction tự định nghĩa; cần triển khai bằng repository, outbox và Elasticsearch client phù hợp.

```csharp
public async Task ReindexAsync(CancellationToken ct)
{
    await using var lease = await _lease.AcquireAsync(ct);
    var watermark = await _changes.CurrentSequenceAsync(ct);
    var target = await _index.CreateVersionedAsync(ct);
    long lastId = 0;
    while (true)
    {
        var batch = await _catalog.ReadAfterIdAsync(lastId, 500, ct);
        if (batch.Count == 0) break;
        await _index.BulkCheckedAsync(target, batch, ct);
        lastId = batch[^1].Id;
        await lease.CheckpointAsync(target, lastId, watermark, ct);
    }
    var cursor = watermark;
    while (await _changes.ReadAfterAsync(cursor, 500, ct) is { Count: > 0 } events)
    {
        await _index.ApplyVersionedAsync(target, events, ct);
        cursor = events[^1].Sequence;
        await lease.SaveCursorAsync(cursor, ct);
    }
    await _index.ValidateAsync(target, ct);
    await lease.AssertOwnerAsync(ct);
    await _index.AtomicAliasSwapAsync("catalog-read", target, ct);
    await _changes.EnsureContinuousProjectionAsync(target, cursor, ct);
}
```

## Giải thích thiết kế sau khi sửa

Tách backfill, delta replay và alias cutover; mọi write cần đi qua durable change feed có ordering/version. Continuous projection phải tiếp tục sau cutover, và handoff không được tạo khoảng hở. Nếu backfill không có snapshot ổn định, version/tombstone phải ngăn dữ liệu cũ ghi đè dữ liệu mới.

## Trade-offs

Outbox, lease và checkpoint tăng complexity; với catalog nhỏ và maintenance window, rebuild khi tạm dừng write có thể đơn giản hơn. Mã minh họa dùng abstractions tự định nghĩa, không phải Elasticsearch SDK APIs. Phải đóng race giữa replay và continuous projection bằng handoff cursor có bảo đảm, không chỉ gọi hai hàm liên tiếp.

## Cách kiểm thử

1. Insert/update/unpublish trong backfill và sát alias swap; kiểm tra consistency sau SLA.
2. Kill worker sau checkpoint và sau swap; resume không mất event.
3. Hai worker chạy đồng thời; chỉ lease owner được swap.
4. Load 2 triệu rows; đo peak memory, bulk failures và replay lag.
5. Inject HTTP 429/503, mapping error và bulk partial failures.

## Quan sát trong production

Application Insights hoặc Kibana: runId, index version, watermark, replay cursor, alias target, backfill throughput, bulk failures, p95 search latency, mismatch samples; alert khi replay lag đe dọa SLA.

Latency 50–900 ms, API đôi lúc trả 401/500; dữ liệu gồm email nội bộ. Auth provider cấp token, chưa xác nhận token thay đổi khi chuyển tenant.

## Đoạn code cần review

```tsx
type Person = { id: string; name: string; email: string };

export function PeopleSearch({
  tenantId, accessToken
}: { tenantId: string; accessToken: string }) {
  const [query, setQuery] = React.useState("");
  const [people, setPeople] = React.useState<Person[]>([]);
  const [loading, setLoading] = React.useState(false);
  const cache = React.useRef<Record<string, Person[]>>({});

  React.useEffect(() => {
    const key = query.trim().toLowerCase();
    if (cache.current[key]) {
      setPeople(cache.current[key]);
      return;
    }
    setLoading(true);
    fetch(`/api/people?tenantId=${tenantId}&q=${query}`, {
      headers: { Authorization: `Bearer ${accessToken}` }
    })
      .then(r => r.json())
      .then(data => {
        cache.current[key] = data;
        setPeople(data);
      })
      .catch(() => setPeople([]))
      .finally(() => setLoading(false));
  }, [query, tenantId]);

  return <section>
    <input value={query} onChange={e => setQuery(e.target.value)} />
    {loading && <span>Loading...</span>}
    <ul>{people.map(p =>
      <li key={p.id}>{p.name} — {p.email}</li>)}</ul>
  </section>;
}
```

## Phiên bản đề xuất

Phiên bản dưới đây bỏ cache PII và kiểm tra scope ngay tại render để tránh flash dữ liệu cũ.

```tsx
type Person = { id: string; name: string; email: string };
export function PeopleSearch({ tenantId, accessToken, sessionKey }: {
  tenantId: string; accessToken: string; sessionKey: string
}) {
  const [query, setQuery] = React.useState("");
  const [state, setState] = React.useState<{
    scope: string; items: Person[]; loading: boolean; error: string | null
  }>({ scope: "", items: [], loading: false, error: null });
  const scope = JSON.stringify([sessionKey, tenantId, query]);
  React.useEffect(() => {
    const controller = new AbortController();
    let active = true;
    setState({ scope, items: [], loading: true, error: null });
    const timer = setTimeout(async () => {
      try {
        const params = new URLSearchParams({ tenantId, q: query });
        const response = await fetch(`/api/people?${params}`, {
          headers: { Authorization: `Bearer ${accessToken}` },
          signal: controller.signal
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data: unknown = await response.json();
        if (!Array.isArray(data) || !data.every(p =>
          p && typeof p.id === "string" &&
          typeof p.name === "string" && typeof p.email === "string"))
          throw new Error("Invalid response");
        if (active) setState({ scope, items: data as Person[],
          loading: false, error: null });
      } catch {
        if (active) setState({ scope, items: [],
          loading: false, error: "Không tải được dữ liệu" });
      }
    }, 250);
    return () => { active = false; clearTimeout(timer); controller.abort(); };
  }, [scope, tenantId, query, accessToken]);
  const visible = state.scope === scope ? state :
    { scope, items: [], loading: true, error: null };
  return <section>
    <input value={query} onChange={e => setQuery(e.target.value)} />
    {visible.loading && <span>Loading...</span>}
    {visible.error && <p role="alert">{visible.error}</p>}
    <ul>{visible.items.map(p =>
      <li key={p.id}>{p.name} — {p.email}</li>)}</ul>
  </section>;
}
```

## Giải thích thiết kế sau khi sửa

Effect sở hữu request và cleanup loại bỏ stale completion. Scope ràng buộc state với tenant, session và query. API phải xác thực quyền tenant độc lập; client-side isolation chỉ giảm lỗi hiển thị.

## Trade-offs

Không cache làm tăng request; debounce giảm tải nhưng tăng độ trễ. Abort không bảo đảm server ngừng xử lý. sessionKey phải đổi khi account/session thay đổi. Backend authorization là ranh giới bảo mật thực sự, không thể dựa vào UI.

## Cách kiểm thử

1. Playwright: response tenant A đến sau khi đã chuyển B; không render A.
2. Backend security: token không có quyền tenant phải bị từ chối.
3. 401, 500, invalid JSON và network failure hiển thị error.
4. Typing nhanh, logout/login, đổi tenant liên tục; không stale state.
5. Đo request count và memory với nhiều truy vấn.

## Quan sát trong production

Browser network spans, HTTP status, request count, abort count, client error rate, backend correlation ID; không log token, email hoặc query thô.
