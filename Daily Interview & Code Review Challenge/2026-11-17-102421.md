# Code Review Challenge 1 — Cosmos DB catalog: mất phiên bản khi nhiều worker cập nhật

**Chủ đề:** C#/.NET 8, Cosmos DB, concurrency, partitioning  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 40 phút  
**Số vấn đề cần tìm:** khoảng 8

## Bối cảnh

Một catalog nhận cập nhật SKU từ ERP. Container Cosmos DB partition theo `/tenantId`. Một tenant lớn có 200.000 SKU; nhiều worker xử lý event không đúng thứ tự. ERP cấp `Version` tăng theo SKU. Production có 429, duplicate documents và giá quay về phiên bản cũ. Yêu cầu không chấp nhận stale update; chưa biết RU/s và partition distribution.

## Đoạn code cần review

```csharp
public record ProductEvent(string TenantId, string Sku,
    long Version, decimal Price, int Quantity);

public sealed class CatalogSync(Container container,
    ILogger<CatalogSync> logger)
{
    public async Task Apply(ProductEvent e)
    {
        var query = new QueryDefinition(
            "SELECT * FROM c WHERE c.sku = @sku")
            .WithParameter("@sku", e.Sku);
        using var iterator =
            container.GetItemQueryIterator<ProductDoc>(query);
        ProductDoc? doc = null;
        while (iterator.HasMoreResults)
        {
            var page = await iterator.ReadNextAsync();
            doc = page.FirstOrDefault();
            if (doc != null) break;
        }

        doc ??= new ProductDoc
        {
            Id = Guid.NewGuid().ToString(),
            TenantId = e.TenantId,
            Sku = e.Sku
        };
        doc.Version = e.Version;
        doc.Price = e.Price;
        doc.Quantity = e.Quantity;
        await container.UpsertItemAsync(doc);
        logger.LogInformation("Updated {Sku} {Price}", e.Sku, e.Price);
    }
}

public sealed class ProductDoc
{
    [System.Text.Json.Serialization.JsonPropertyName("id")]
    public string Id { get; set; } = "";
    [System.Text.Json.Serialization.JsonPropertyName("tenantId")]
    public string TenantId { get; set; } = "";
    [System.Text.Json.Serialization.JsonPropertyName("sku")]
    public string Sku { get; set; } = "";
    public long Version { get; set; }
    public decimal Price { get; set; }
    public int Quantity { get; set; }
}
```

## Kết quả code review tham khảo

### [Critical] — Stale event ghi đè dữ liệu mới

**Vấn đề:** Không so sánh `Version`.  
**Tại sao xảy ra:** Event có thể đến không theo thứ tự.  
**Ảnh hưởng production:** Giá và tồn kho quay về trạng thái cũ.  
**Cách sửa:** Chỉ chấp nhận version lớn hơn và dùng conditional write.

### [High] — Lost update

**Vấn đề:** Read-modify-upsert không có concurrency precondition.  
**Tại sao xảy ra:** Hai worker cùng đọc snapshot rồi last-write-wins.  
**Ảnh hưởng production:** Mất update hợp lệ.  
**Cách sửa:** `ReplaceItemAsync` với `IfMatchEtag`; khi 412 đọc lại và đánh giá version.

### [High] — Cross-tenant query

**Vấn đề:** Query chỉ lọc SKU.  
**Tại sao xảy ra:** SKU có thể trùng giữa tenant; không chỉ định partition key.  
**Ảnh hưởng production:** Đọc sai tenant, tăng RU, có nguy cơ ảnh hưởng dữ liệu.  
**Cách sửa:** Stable ID theo SKU và point read với `PartitionKey(tenantId)`; kiểm tra authorization ở ingress.

### [High] — Duplicate document

**Vấn đề:** Random GUID mỗi khi không tìm thấy item.  
**Tại sao xảy ra:** Concurrent create có ID khác nhau.  
**Ảnh hưởng production:** Trùng SKU, query không xác định.  
**Cách sửa:** Deterministic ID và `CreateItemAsync`, xử lý 409.

### [High] — Hot partition

**Vấn đề:** Tenant lớn tập trung toàn bộ workload vào một logical partition.  
**Tại sao xảy ra:** Partition key không phân phối đủ workload.  
**Ảnh hưởng production:** Throttling ngay cả khi tổng throughput còn khả dụng.  
**Cách sửa:** Đo RU và partition metrics; cân nhắc synthetic partition key và migration sang container mới nếu bằng chứng xác nhận.

### [Medium] — Thiếu cancellation và bounded conflict retry

**Vấn đề:** Không nhận CancellationToken và không xử lý 412.  
**Tại sao xảy ra:** Không thiết kế failure path.  
**Ảnh hưởng production:** Worker kéo dài, retry ngoài kiểm soát.  
**Cách sửa:** Propagate token; giới hạn retry conflict; SDK quản lý retry 429 theo cấu hình.

### [Medium] — Thiếu diagnostics

**Vấn đề:** Log không có version, outcome, RU hay activity ID.  
**Tại sao xảy ra:** Không có structured observability contract.  
**Ảnh hưởng production:** Không xác định được stale events hay throttling.  
**Cách sửa:** Ghi version, outcome, RequestCharge, status, latency và trace correlation.

### [Low] — Log dữ liệu thương mại không cần thiết

**Vấn đề:** Log trực tiếp giá.  
**Tại sao xảy ra:** Thiếu data minimization.  
**Ảnh hưởng production:** Tăng chi phí và phạm vi truy cập dữ liệu.  
**Cách sửa:** Log identifiers đã xử lý và metadata tối thiểu.

## Phiên bản đề xuất

Giả định ID được chuẩn hóa theo SKU, input đã được xác thực và ERP version tăng nghiêm ngặt trên từng SKU.

```csharp
public sealed class SafeCatalogSync(Container container)
{
    public async Task<string> ApplyAsync(
        ProductEvent e, CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(e.TenantId) ||
            string.IsNullOrWhiteSpace(e.Sku) ||
            e.Version < 0 || e.Price < 0 || e.Quantity < 0)
            throw new ArgumentException("Invalid update");

        var id = e.Sku.Trim().ToUpperInvariant();
        var pk = new PartitionKey(e.TenantId);

        for (int attempt = 0; attempt < 6; attempt++)
        {
            ItemResponse<ProductDoc> current;
            try
            {
                current = await container.ReadItemAsync<ProductDoc>(
                    id, pk, cancellationToken: ct);
            }
            catch (CosmosException ex)
                when (ex.StatusCode == System.Net.HttpStatusCode.NotFound)
            {
                var created = new ProductDoc
                {
                    Id = id, TenantId = e.TenantId, Sku = e.Sku,
                    Version = e.Version, Price = e.Price,
                    Quantity = e.Quantity
                };
                try
                {
                    await container.CreateItemAsync(
                        created, pk, cancellationToken: ct);
                    return "created";
                }
                catch (CosmosException ex2)
                    when (ex2.StatusCode == System.Net.HttpStatusCode.Conflict)
                {
                    continue;
                }
            }

            if (current.Resource.Version >= e.Version)
                return "stale-or-duplicate";

            var next = current.Resource;
            next.Version = e.Version;
            next.Price = e.Price;
            next.Quantity = e.Quantity;
            try
            {
                await container.ReplaceItemAsync(next, id, pk,
                    new ItemRequestOptions {
                        IfMatchEtag = current.ETag
                    }, ct);
                return "updated";
            }
            catch (CosmosException ex)
                when (ex.StatusCode ==
                    System.Net.HttpStatusCode.PreconditionFailed)
            {
                continue;
            }
        }
        throw new InvalidOperationException(
            "Contention exceeded retry budget");
    }
}
```

## Giải thích thiết kế sau khi sửa

Stable ID ngăn duplicate create trong cùng partition; ETag biến lost update thành conflict có thể phát hiện. Sau conflict phải đọc lại và so sánh version, không chỉ retry cùng payload. Nếu cùng version nhưng payload khác nhau, cần contract xác định đây là data-integrity incident thay vì tự động bỏ qua. Nếu timeout xảy ra sau commit, đọc lại thấy version đã áp dụng. Cách này không tự chữa hot partition.

## Trade-offs

Optimistic concurrency tăng round-trip khi contention. Stable ID cần migration dữ liệu GUID cũ. Synthetic partition key cải thiện phân bố nhưng làm truy vấn và migration phức tạp; không thay đổi partition key của container hiện tại tại chỗ. Nếu ERP không có version đáng tin cậy, phải thiết kế ordering contract khác.

## Cách kiểm thử

1. Integration concurrency: 50 workers cập nhật một SKU, final version lớn nhất.
2. Out-of-order: gửi version 12 rồi 10 và 11; không rollback.
3. Cross-tenant: cùng SKU nhưng hai tenant độc lập.
4. Failure injection: 409, 412, 429 và timeout sau commit.
5. Load: đo RU, p95, throttling theo tenant và logical partition.

## Quan sát trong production

Theo dõi Cosmos DB RequestCharge, ActivityId, diagnostics, 429/412/409, latency p95/p99, RU consumption theo partition, tỷ lệ stale/updated, conflict retry và queue backlog. Application Insights trace correlation; alert khi 429 kéo dài hoặc conflict rate tăng.

## Câu hỏi phỏng vấn mở rộng

1. Nếu một SKU nhận 5.000 updates/giây, bạn coalesce events thế nào?
2. Bạn cutover container với synthetic partition key ra sao mà không mất write?
3. Khi version bị reset sau ERP migration, xử lý contract thế nào?

var builder = WebApplication.CreateBuilder(args);
builder.Services.AddControllersWithViews();
builder.Services.AddResponseCaching();
var app = builder.Build();
app.UseResponseCaching();
app.UseRouting();
app.MapControllers();
app.Run();

[Route("{culture:regex(vi|en)}/pages")]
public sealed class PagesController : Controller
{
    private readonly IPageService _pages;
    public PagesController(IPageService pages) => _pages = pages;

    [HttpGet("{slug}")]
    public async Task<IActionResult> Detail(
        string culture, string slug)
    {
        var page = await _pages.GetPublishedAsync(slug);
        if (page is null) return NotFound();

        var segment = Request.Cookies["segment"] ?? "general";
        var banner = page.Banners.FirstOrDefault(
            x => x.Segment == segment)
            ?? page.Banners.FirstOrDefault();

        Response.Headers.CacheControl = "public,max-age=3600";
        Response.Headers["Vary"] = "Accept-Encoding";

        var html = $"""
          <html><head>
          <title>{page.Title}</title>
          <link rel="canonical"
                href="https://shop.example/en/pages/{slug}">
          </head><body>
          <h1>{page.Title}</h1>
          <div>{banner?.Html}</div>
          </body></html>
          """;
        return Content(html, "text/html");
    }
}

## Kết quả code review tham khảo

### [Critical] — Personalized HTML bị shared cache

**Vấn đề:** Response phụ thuộc cookie nhưng gắn `public,max-age=3600`.  
**Tại sao xảy ra:** Shared cache có thể tái sử dụng HTML giữa các segment.  
**Ảnh hưởng production:** Sai banner, có thể lộ dữ liệu nếu fragment chứa nội dung riêng.  
**Cách sửa:** Cache public shell; personalized API dùng `private,no-store` hoặc tắt shared caching toàn trang.

### [High] — Stored XSS từ CMS HTML

**Vấn đề:** Chèn `banner.Html` không sanitize.  
**Tại sao xảy ra:** Nội dung từ editor/integration có thể chứa markup độc hại.  
**Ảnh hưởng production:** Script chạy trong trình duyệt.  
**Cách sửa:** Structured content, Razor encoding và HTML allowlist sanitizer khi thực sự cần rich HTML.

### [High] — Không dùng culture khi lookup

**Vấn đề:** `GetPublishedAsync(slug)` không nhận culture.  
**Tại sao xảy ra:** Slug có thể trùng giữa ngôn ngữ.  
**Ảnh hưởng production:** Sai translation và content.  
**Cách sửa:** Lookup theo culture + slug và published status.

### [High] — Canonical hard-code tiếng Anh

**Vấn đề:** Mọi page canonical về `/en/`.  
**Tại sao xảy ra:** Không xây URL từ published localized route.  
**Ảnh hưởng production:** Search engine có thể bỏ qua bản tiếng Việt.  
**Cách sửa:** Generate canonical theo culture, thêm hreflang khi phù hợp.

### [Medium] — Không có purge/invalidation contract

**Vấn đề:** TTL dài mà không liên kết CMS publish với Akamai.  
**Tại sao xảy ra:** Publish không mặc nhiên purge mọi CDN.  
**Ảnh hưởng production:** Nội dung cũ sau publish.  
**Cách sửa:** Publish event → purge đúng URLs → retry/audit, kèm TTL fallback.

### [Medium] — Edge cache configuration chưa được xác minh

**Vấn đề:** Chỉ đặt origin headers.  
**Tại sao xảy ra:** Akamai property có thể override cache policy.  
**Ảnh hưởng production:** Cache key sai hoặc hit ratio thấp.  
**Cách sửa:** Validate edge property, cookie/authorization handling và headers bằng integration test.

### [Medium] — String interpolation không encode

**Vấn đề:** Title/slug đưa trực tiếp vào HTML.  
**Tại sao xảy ra:** Bỏ qua context-sensitive encoding.  
**Ảnh hưởng production:** XSS, malformed metadata.  
**Cách sửa:** Razor view và URL builder.

### [Low] — Thiếu telemetry content version

**Vấn đề:** Không trace publish → purge → edge response.  
**Tại sao xảy ra:** Không có cache observability.  
**Ảnh hưởng production:** Khó xác minh stale content.  
**Cách sửa:** Ghi content version, culture, cache status, purge outcome.

## Phiên bản đề xuất

Giả định `IPageService` và `IUrlService` là abstraction của ứng dụng, không phải API được khẳng định của Optimizely. Public shell không chứa dữ liệu phụ thuộc cookie.

```csharp
[Route("{culture:regex(vi|en)}/pages")]
public sealed class PagesController(
    IPageService pages, IUrlService urls) : Controller
{
    [HttpGet("{slug}")]
    public async Task<IActionResult> Detail(
        string culture, string slug, CancellationToken ct)
    {
        var page = await pages.GetPublishedAsync(
            culture, slug, ct);
        if (page is null) return NotFound();

        Response.Headers.CacheControl =
            "public,max-age=60,s-maxage=300";
        return View("PublicPage", new PublicPageVm(
            page.Title, page.PublicText,
            urls.CanonicalUrl(page, culture),
            culture, page.Id));
    }
}

[Authorize]
[Route("api/banners")]
public sealed class BannersController(IPageService pages)
    : ControllerBase
{
    [HttpGet("{id:guid}")]
    public async Task<IActionResult> Get(
        Guid id, CancellationToken ct)
    {
        Response.Headers.CacheControl = "private,no-store";
        var segment = User.FindFirst("segment")?.Value
            ?? "general";
        var banner = await pages.GetBannerAsync(
            id, segment, ct);
        return banner is null ? NotFound()
            : Ok(new { banner.Text, banner.ImageUrl });
    }
}
```

## Giải thích thiết kế sau khi sửa

CDN chỉ cache public shell. Personalized response không lưu shared cache. Canonical sinh từ localized published URL; Razor encode text. CMS publish cần purge với audit, retry và xác minh edge. Akamai configuration phải được kiểm thử thực tế; origin header không đủ chứng minh edge behavior.

## Trade-offs

Tách banner tăng một network request, có thể gây layout shift: reserve kích thước placeholder và đo Core Web Vitals. TTL thấp tăng origin load; purge phức tạp nhưng cải thiện freshness. Nếu page không personalized, không cần thêm endpoint. `[Authorize]` phụ thuộc trust model của segment.

## Cách kiểm thử

1. Cache isolation: hai segment cùng public URL không dùng chung banner.
2. Playwright E2E: canonical, lang và fallback cho `/vi/`, `/en/`.
3. Security: payload script trong title/banner phải bị encode/sanitize.
4. Publish: purge failure, retry và kiểm tra stale window.
5. Akamai integration: cache key, Age, Cache-Control, cookies, edge hit/miss.

## Quan sát trong production

Theo dõi edge hit ratio, Age, origin latency, content version, publish-to-purge delay, purge failure rate, banner API errors và Core Web Vitals. Correlate CMS publish event → purge request → edge response; Application Insights cho origin và Akamai logs cho CDN.
