# Code Review Challenge 1 — Optimizely CMS publish làm sai cache và lộ nội dung chưa công bố

## Bối cảnh

Website marketing đa ngôn ngữ dùng Optimizely CMS làm nguồn nội dung. API ASP.NET Core phục vụ Vue.js frontend và Akamai CDN. Một số editor có quyền preview bản nháp; khách truy cập chỉ được xem nội dung đã publish. Trong campaign, một editor báo bản mới không xuất hiện trong 20 phút; một khách khác đôi lúc thấy bản nháp. Hệ thống có 4 Azure App Service instances, CDN cache HTML/API. Giả định CMS adapter có phương thức `GetLatestAsync` trả cả bản nháp và published; `GetPublishedAsync` chỉ trả published. Chưa xác nhận CDN có cache response chứa cookie hay không.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/pages")]
public sealed class PagesController : ControllerBase
{
    private readonly ICmsPages _cms;
    private readonly IMemoryCache _cache;
    private readonly ILogger<PagesController> _logger;

    public PagesController(ICmsPages cms, IMemoryCache cache,
        ILogger<PagesController> logger)
    {
        _cms = cms;
        _cache = cache;
        _logger = logger;
    }

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(string slug, string? language,
        bool preview = false)
    {
        var key = $"page:{slug}";
        if (_cache.TryGetValue<PageDto>(key, out var cached))
            return Ok(cached);

        var page = await _cms.GetLatestAsync(slug, language ?? "en");
        if (page == null) return NotFound();

        if (preview && User.Identity?.IsAuthenticated != true)
            return Unauthorized();

        var dto = new PageDto(page.Title, page.Html, page.Version);
        _cache.Set(key, dto, TimeSpan.FromMinutes(30));
        Response.Headers.CacheControl = "public,max-age=1800";
        _logger.LogInformation("Page loaded {Slug} {Html}", slug, page.Html);
        return Ok(dto);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Bản nháp có thể bị trả về public

**Vấn đề:** Endpoint public luôn gọi `GetLatestAsync`, dù `preview=false`.  
**Tại sao xảy ra:** Chọn revision theo trạng thái latest thay vì published; kiểm tra `preview` diễn ra sau khi đọc và không quyết định query.  
**Ảnh hưởng production:** Rò rỉ nội dung embargo, giá campaign, thông tin chưa công bố.  
**Cách sửa:** Public luôn dùng published revision; preview là route riêng có policy authorization theo quyền CMS/content, không chỉ authentication.

### [Critical] — Cache mixing giữa ngôn ngữ, revision và quyền

**Vấn đề:** `page:{slug}` dùng chung cho language và preview, trả cache trước khi kiểm quyền.  
**Tại sao xảy ra:** Cache không biểu diễn identity của representation và security boundary.  
**Ảnh hưởng production:** Nội dung sai locale hoặc bản nháp được tái sử dụng cho anonymous user.  
**Cách sửa:** Không cache shared cho preview; public cache theo canonical slug, locale, published version và site/tenant nếu có. Kiểm quyền trước mọi read của preview.

### [High] — Public Cache-Control cho response nhạy cảm

**Vấn đề:** `public,max-age=1800` không phân biệt preview, có thể đi qua CDN.  
**Tại sao xảy ra:** HTTP cache directives thiếu phân loại response.  
**Ảnh hưởng production:** Cache trung gian giữ nội dung không dành cho public.  
**Cách sửa:** Preview `private, no-store`; public cache có policy rõ ràng và CDN rule kiểm chứng, tránh cache response gắn auth/cookie.

### [High] — Publish không invalidation toàn hệ thống

**Vấn đề:** IMemoryCache của từng instance tồn tại 30 phút; CDN có TTL riêng.  
**Tại sao xảy ra:** Không có event-driven invalidation hoặc versioned URL/key/purge policy.  
**Ảnh hưởng production:** Stale page sau publish/unpublish, không nhất quán giữa instances.  
**Cách sửa:** CMS publish/unpublish event → invalidation/purge theo content ID và locale; kiểm tra acknowledgement, retry, fallback TTL; đảm bảo unpublish xử lý khẩn cấp.

### [High] — Thiếu authorization theo nội dung cho preview

**Vấn đề:** Bất kỳ authenticated user nào cũng qua được điều kiện preview.  
**Tại sao xảy ra:** Authentication bị nhầm thành quyền xem draft.  
**Ảnh hưởng production:** Lộ nội dung nội bộ cho user không thuộc editorial role.  
**Cách sửa:** Policy authorization kiểm content/site/tenant và role, đồng thời audit preview access.

### [Medium] — Log toàn bộ HTML

**Vấn đề:** Structured log chứa nội dung HTML.  
**Tại sao xảy ra:** Logging payload thay vì metadata.  
**Ảnh hưởng production:** Rò rỉ PII/content và tăng ingestion cost.  
**Cách sửa:** Log content ID, locale, revision, cache outcome, trace ID; không log body.

### [Medium] — Thiếu cancellation và xử lý dependency failure

**Vấn đề:** Không chuyển `HttpContext.RequestAborted` tới CMS adapter, thiếu timeout/degraded behavior.  
**Tại sao xảy ra:** Async không đồng nghĩa tự động hủy I/O.  
**Ảnh hưởng production:** Request bị hủy vẫn chiếm tài nguyên, CMS outage lan sang API.  
**Cách sửa:** Truyền CancellationToken, áp timeout hợp lý; chỉ serve stale public content nếu policy nghiệp vụ cho phép.

### [Medium] — Chưa xác định chính sách HTML rendering

**Vấn đề:** `page.Html` đưa trực tiếp vào frontend; nguy cơ XSS phụ thuộc nguồn CMS và renderer.  
**Tại sao xảy ra:** Trust boundary không được định nghĩa.  
**Ảnh hưởng production:** Nếu editor hoặc integration bị compromise, HTML nguy hiểm có thể chạy ở browser.  
**Cách sửa:** Sanitize/allowlist tại trusted boundary, CSP defense-in-depth và test renderer Vue.

## Phiên bản đề xuất

Ví dụ thiết kế ở application boundary; `ICmsPages` và `IPublicPageCache` là abstractions của ứng dụng, không phải Optimizely SDK APIs. Triển khai `GetPublishedAsync` và quyền preview phải được đối chiếu với CMS adapter thực tế.

```csharp
[ApiController]
[Route("api/pages")]
public sealed class PagesController : ControllerBase
{
    private readonly ICmsPages _cms;
    private readonly IPublicPageCache _publicCache;
    private readonly IAuthorizationService _authorization;
    private readonly ILogger<PagesController> _log;

    public PagesController(ICmsPages cms, IPublicPageCache publicCache,
        IAuthorizationService authorization, ILogger<PagesController> log)
        => (_cms, _publicCache, _authorization, _log)
         = (cms, publicCache, authorization, log);

    [HttpGet("{slug}")]
    [AllowAnonymous]
    public async Task<IActionResult> Published(
        string slug, [FromQuery] string language = "en",
        CancellationToken ct = default)
    {
        var locale = NormalizeSupportedLocale(language);
        if (locale is null) return BadRequest();
        var page = await _publicCache.GetOrLoadPublishedAsync(
            slug, locale,
            token => _cms.GetPublishedAsync(slug, locale, token), ct);
        if (page is null) return NotFound();
        Response.Headers.CacheControl = "public,max-age=60";
        _log.LogInformation("Published page {Slug} {Locale} {Version}",
            slug, locale, page.Version);
        return Ok(page);
    }

    [HttpGet("{slug}/preview")]
    [Authorize]
    public async Task<IActionResult> Preview(
        string slug, [FromQuery] string language = "en",
        CancellationToken ct = default)
    {
        Response.Headers.CacheControl = "private,no-store";
        var locale = NormalizeSupportedLocale(language);
        if (locale is null) return BadRequest();
        var allowed = await _authorization.AuthorizeAsync(
            User, new PreviewResource(slug, locale), "CanPreviewContent");
        if (!allowed.Succeeded) return Forbid();
        var page = await _cms.GetLatestAsync(slug, locale, ct);
        return page is null ? NotFound() : Ok(page);
    }

    private static string? NormalizeSupportedLocale(string value) =>
        value.ToLowerInvariant() is "en" or "vi"
            ? value.ToLowerInvariant() : null;
}
```

`IPublicPageCache` phải có cache key gồm site/tenant (nếu multi-site), slug chuẩn hóa, locale và publication identity; invalidate khi publish/unpublish. Public cache tuyệt đối không lấy draft. CDN phải bypass preview path, và khi unpublish cần purge public objects. Nếu yêu cầu bảo mật nghiêm ngặt, public TTL 60 giây vẫn không đủ để thu hồi ngay: cần purge có xác nhận hoặc bypass cache cho loại nội dung đó.

## Giải thích thiết kế sau khi sửa

Security boundary nằm ở endpoint và CMS query; cache chỉ là tối ưu cho dữ liệu đã được phép public. Tách preview khỏi published làm dễ cấu hình CDN, kiểm thử và audit. Một `IPublicPageCache` có thể triển khai bằng in-memory nếu chấp nhận stale theo instance; không bắt buộc Redis. HTML sanitation và CSP cần triển khai tại CMS/frontend boundary thực tế.

## Trade-offs

TTL ngắn giảm stale nhưng tăng origin load; purge nhanh hơn nhưng có failure/retry và chi phí vận hành. Versioned cache key giảm collision nhưng vẫn cần giải quyết CDN URL và unpublish. Cache phân tán cải thiện consistency nhưng thêm dependency; với website nhỏ, purge + TTL và monitoring có thể đủ.

## Cách kiểm thử

1. **Security integration:** Anonymous và user không có `CanPreviewContent` không bao giờ thấy draft, kể cả sau khi editor preview.
2. **Locale/cache test:** Xen kẽ `vi`/`en` cùng slug trên nhiều instance; response không bị cross-locale.
3. **Publish/unpublish E2E:** Sau event, kiểm tra CDN và origin trong SLO được thống nhất; mô phỏng purge thất bại.
4. **Failure-path:** CMS timeout, client disconnect và stale fallback chỉ cho published content.
5. **Frontend security:** HTML độc hại trong CMS không thực thi script trong Vue renderer.

## Quan sát trong production

Application Insights traces: `contentId`, locale, revision, cache layer/hit, publish event ID, correlation ID. Dashboard: stale age, CDN hit/miss, purge latency/failure, CMS dependency p95, 403/404 rate. Alert khi unpublish vẫn trả 200 hoặc preview route được edge-cache. Không log raw HTML.

2. Khi 20 sites dùng cùng content block, thiết kế dependency graph invalidation thế nào?
3. Khi nào nên chọn SSR thay vì client rendering cho SEO của CMS website?

# Code Review Challenge 2 — React search results ghi đè sau khi đổi filter

```tsx
type Audit = { id: string; action: string; status: string };
type Result = { items: Audit[]; total: number };

export function AuditSearch() {
  const { token } = useAuth();
  const [query, setQuery] = useState("");
  const [status, setStatus] = useState("all");
  const [page, setPage] = useState(1);
  const [items, setItems] = useState<Audit[]>([]);
  const [total, setTotal] = useState(0);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  useEffect(() => {
    setLoading(true);
    setError("");
    const url = "/api/audits?q=" + query +
      "&status=" + status + "&page=" + page;
    fetch(url, { headers: { Authorization: "Bearer " + token } })
      .then(r => r.json())
      .then((data: Result) => {
        setItems(data.items);
        setTotal(data.total);
      })
      .catch(() => setError("Không tải được dữ liệu"))
      .finally(() => setLoading(false));
  }, [query, status, page]);

  const exportCsv = () => {
    window.open("/api/audits/export?q=" + query + "&status=" + status);
  };

  return (
    <section>
      <input value={query} onChange={e => setQuery(e.target.value)} />
      <select value={status} onChange={e => setStatus(e.target.value)}>
        <option value="all">All</option>
        <option value="failed">Failed</option>
      </select>
      <button onClick={() => setPage(page + 1)}>Next</button>
      <button onClick={exportCsv}>Export</button>
      {loading && <p>Loading...</p>}
      {error && <p role="alert">{error}</p>}
      <p>{total} results</p>
      {items.map(item => <div key={item.id}>{item.action}</div>)}
    </section>
  );
}
```

## Kết quả code review tham khảo

### [High] — Stale response ghi đè kết quả mới

**Vấn đề:** Request cũ hoàn thành sau request mới vẫn gọi `setItems`.  
**Tại sao xảy ra:** Không cancel hoặc chặn stale completion.  
**Ảnh hưởng production:** User xem audit records sai filter, dễ đưa ra quyết định nhầm.  
**Cách sửa:** `AbortController` mỗi effect và cleanup; nếu client/API không hỗ trợ cancel hoàn chỉnh, thêm request identity guard.

### [High] — Không xử lý HTTP errors

**Vấn đề:** `fetch` resolve cho 401/403/500; code gọi `r.json()` và coi payload là `Result`.  
**Tại sao xảy ra:** Promise rejection không đồng nghĩa HTTP error.  
**Ảnh hưởng production:** UI rỗng/không nhất quán, che lỗi authorization hoặc outage.  
**Cách sửa:** Kiểm `response.ok`, xử lý 401 theo auth flow, 403 riêng, validate shape của JSON.

### [High] — Export bỏ qua auth header và có nguy cơ lệch scope

**Vấn đề:** `window.open` không tự gắn Authorization Bearer header từ fetch; query chưa encode.  
**Tại sao xảy ra:** Browser navigation và authenticated fetch là hai cơ chế khác nhau.  
**Ảnh hưởng production:** Export thất bại 401; nếu server cấu hình sai, có thể tạo lỗ hổng quyền.  
**Cách sửa:** Fetch export bằng authenticated API client, dùng Blob URL; server luôn authorize tenant và filters. Với cookie auth, vẫn cần CSRF policy phù hợp.

### [Medium] — Query string không encode

**Vấn đề:** Từ khóa có `&`, `#`, dấu tiếng Việt hoặc ký tự đặc biệt làm query sai.  
**Tại sao xảy ra:** Nối chuỗi URL trực tiếp.  
**Ảnh hưởng production:** Search sai và lỗi khó tái hiện.  
**Cách sửa:** `URLSearchParams`.

### [Medium] — Page không reset khi filter đổi

**Vấn đề:** User đang page 9 đổi status vẫn query page 9.  
**Tại sao xảy ra:** Filter và pagination state không được cập nhật đồng bộ.  
**Ảnh hưởng production:** Kết quả trống giả dù có dữ liệu.  
**Cách sửa:** Reset page về 1 ngay trong filter handlers.

### [Medium] — Token không nằm trong dependencies

**Vấn đề:** Khi token thay đổi mà filters giữ nguyên, effect không fetch lại.  
**Tại sao xảy ra:** Dependency list thiếu `token`.  
**Ảnh hưởng production:** UI không phục hồi sau refresh token; stale auth state.  
**Cách sửa:** Include token hoặc sử dụng authenticated client ổn định có refresh coordination.

### [Medium] — Loading state có thể sai và request quá dày

**Vấn đề:** Nhiều requests đồng thời, `finally` của request cũ có thể tắt loading của request mới; mỗi ký tự gõ tạo request.  
**Tại sao xảy ra:** Không có request ownership và debounce.  
**Ảnh hưởng production:** UI flicker, API load tăng, khó đọc telemetry.  
**Cách sửa:** Cleanup và debounce keyword, theo dõi request hiện hành.

## Phiên bản đề xuất

Ví dụ sử dụng `useEffect` cùng `AbortController`; auth refresh do `useAuth` hoặc shared API client quản lý. `Result` cần runtime validation đầy đủ hơn trong production (ví dụ schema validation).

```tsx
type Audit = { id: string; action: string; status: string };
type Result = { items: Audit[]; total: number };

function isResult(value: unknown): value is Result {
  if (typeof value !== "object" || value === null) return false;
  const v = value as Partial<Result>;
  return Array.isArray(v.items) &&
    v.items.every(x => x && typeof x.id === "string" &&
      typeof x.action === "string" && typeof x.status === "string") &&
    typeof v.total === "number";
}

export function AuditSearch() {
  const { token } = useAuth();
  const [query, setQuery] = useState("");
  const [debounced, setDebounced] = useState("");
  const [status, setStatus] = useState("all");
  const [page, setPage] = useState(1);
  const [result, setResult] = useState<Result | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  useEffect(() => {
    const timer = setTimeout(() => setDebounced(query), 300);
    return () => clearTimeout(timer);
  }, [query]);

  useEffect(() => {
    const controller = new AbortController();
    setLoading(true);
    setError("");
    setResult(null);
    const params = new URLSearchParams({
      q: debounced, status, page: String(page)
    });
    async function load() {
      try {
        if (!token) throw new Error("AUTH_REQUIRED");
        const response = await fetch("/api/audits?" + params, {
          headers: { Authorization: `Bearer ${token}` },
          signal: controller.signal
        });
        if (!response.ok) throw new Error(`HTTP_${response.status}`);
        const data: unknown = await response.json();
        if (!isResult(data)) throw new Error("INVALID_RESPONSE");
        if (!controller.signal.aborted) setResult(data);
      } catch (e) {
        if (!controller.signal.aborted)
          setError(e instanceof Error ? e.message : "REQUEST_FAILED");
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }
    void load();
    return () => controller.abort();
  }, [debounced, status, page, token]);

  async function exportCsv() {
    if (!token) return setError("AUTH_REQUIRED");
    const params = new URLSearchParams({ q: query, status });
    try {
      const response = await fetch("/api/audits/export?" + params, {
        headers: { Authorization: `Bearer ${token}` }
      });
      if (!response.ok) throw new Error(`HTTP_${response.status}`);
      const blob = await response.blob();
      const url = URL.createObjectURL(blob);
      const link = document.createElement("a");
      link.href = url; link.download = "audits.csv"; link.click();
      setTimeout(() => URL.revokeObjectURL(url), 60_000);
    } catch { setError("EXPORT_FAILED"); }
  }

  return <section>
    <input value={query} onChange={e => {
      setQuery(e.target.value); setPage(1);
    }} />
    <select value={status} onChange={e => {
      setStatus(e.target.value); setPage(1);
    }}>
      <option value="all">All</option>
      <option value="failed">Failed</option>
    </select>
    <button disabled={loading || !result ||
      page * 20 >= result.total} onClick={() => setPage(p => p + 1)}>
      Next
    </button>
    <button onClick={() => void exportCsv()}>Export</button>
    {loading && <p>Loading...</p>}
    {error && <p role="alert">{error}</p>}
    <p>{result?.total ?? 0} results</p>
    {result?.items.map(x => <div key={x.id}>{x.action}</div>)}
  </section>;
}
```

Lưu ý: `page * 20` giả định API page size 20; nếu API cho phép page size động, cần trả `hasNext` hoặc metadata chính thức. Export dùng `blob()` chỉ phù hợp file nhỏ; với export lớn, dùng streaming/download endpoint hoặc short-lived scoped download URL theo policy. `setTimeout` thu hồi Blob URL là biện pháp đơn giản, production nên quản lý lifecycle download rõ hơn.

## Giải thích thiết kế sau khi sửa

Effect cleanup làm request cũ mất quyền cập nhật state. `URLSearchParams` bảo toàn query semantics. Runtime validation chặn việc tin JSON tùy ý. Server vẫn chịu trách nhiệm authorization và tenant isolation; client-side filter không phải security control. Auth refresh/retry phải có giới hạn để không tạo retry storm.

## Trade-offs

Debounce giảm traffic nhưng tăng độ trễ cảm nhận; cache theo query key (TanStack Query chẳng hạn) có thể giảm boilerplate nhưng thêm dependency và cần cấu hình stale policy. Abort không bảo đảm server dừng xử lý ngay; backend cần cancellation và rate limits. Blob export đơn giản nhưng tốn memory cho file lớn.

## Cách kiểm thử

1. **Race E2E (Playwright):** Delay response A lâu hơn B; đổi filter nhanh; chỉ B được render.
2. **HTTP/auth:** Mock 401/403/500 và malformed JSON; UI không hiển thị dữ liệu giả thành công.
3. **Pagination:** Đổi filter từ page cuối; request mới phải dùng page 1.
4. **Export integration:** Xác minh Authorization header và server tenant-scoped access; test 403.
5. **Load/browser:** Gõ nhanh 20 ký tự; số requests được debounce và stale updates không xuất hiện.

## Quan sát trong production

Frontend telemetry: request key hash (không log raw PII query), response status, latency, abort count, stale response suppression, auth refresh failures, export errors. Backend Application Insights: correlation ID, tenant ID được pseudonymize, p95, 401/403, DB query time. Alert khi search 5xx hoặc export 403 bất thường; kiểm tra network waterfall trước khi tối ưu.

## Câu hỏi phỏng vấn mở rộng

1. Nếu backend không hỗ trợ cancellation, UI vẫn đảm bảo last-request-wins bằng cách nào?
2. Khi nào dùng React Query thay vì tự viết `useEffect`?
3. Làm sao xuất CSV hàng GB mà không giữ toàn bộ file trong browser memory?

# Tổng kết hôm nay

## Kiến thức trọng tâm

Cache không chỉ là vấn đề hiệu năng: nó phải tuân thủ authorization boundary, revision và locale. Frontend async cũng cần quản lý request ownership, HTTP status và trạng thái UI nhất quán. Mọi giải pháp cần kiểm thử failure path, không chỉ happy path.

## Mẫu tư duy cần nhớ

1. Xác định trust boundary trước khi cache hoặc chia sẻ dữ liệu.
2. Tách dữ liệu privileged và public ở cả API lẫn CDN.
3. Một response chỉ được cập nhật UI khi còn thuộc request hiện hành.
4. Thiết kế invalidation cùng lúc với caching và publish workflow.
5. Dùng telemetry để phân biệt stale data, lỗi dependency và lỗi client state.
