# Code Review Challenge 1 — Download tài liệu nội bộ qua ASP.NET Core

## Bối cảnh

Một hệ thống tài liệu đa tenant chạy trên Azure App Service (4 instances). Người dùng tải báo cáo PDF từ Azure Blob Storage qua API để giữ quyền truy cập trong backend. Mỗi document thuộc một tenant, có chủ sở hữu và trạng thái `IsDeleted`. Metadata được lưu trong SQL Server; Blob container là private. Mỗi giờ có khoảng 12.000 lượt tải, file từ 100 KB đến 250 MB. Gần đây p95 tăng, một số request gây OutOfMemoryException và QA phát hiện khả năng tải nhầm file tenant khác. Đoạn code được rút gọn; giả định `Document` có `Id`, `TenantId`, `OwnerId`, `BlobName`, `FileName`, `ContentType`, `IsDeleted`.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/documents")]
[Authorize]
public sealed class DocumentsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly BlobContainerClient _container;
    private readonly ILogger<DocumentsController> _logger;

    public DocumentsController(
        AppDbContext db,
        BlobContainerClient container,
        ILogger<DocumentsController> logger)
    {
        _db = db;
        _container = container;
        _logger = logger;
    }

    [HttpGet("{id:guid}/download")]
    public async Task<IActionResult> Download(Guid id)
    {
        var tenantId = Request.Headers["X-Tenant-Id"].ToString();
        var document = await _db.Documents
            .FirstOrDefaultAsync(x => x.Id == id);

        if (document == null)
            return NotFound();

        _logger.LogInformation("Download {Id} {Tenant} {User}",
            id, tenantId, User.Identity?.Name);

        var blob = _container.GetBlobClient(document.BlobName);
        var response = await blob.DownloadStreamingAsync();
        using var stream = response.Value.Content;
        using var memory = new MemoryStream();
        await stream.CopyToAsync(memory);

        Response.Headers.CacheControl = "public, max-age=3600";
        return File(memory.ToArray(),
            document.ContentType,
            document.FileName);
    }
}
```

## Kết quả code review tham khảo

### Critical — IDOR / broken object-level authorization

**Vấn đề:** Chỉ cần authenticated là có thể yêu cầu bất kỳ `id` nào.  
**Tại sao xảy ra:** `[Authorize]` không kiểm tra tenant, owner hoặc quyền chia sẻ.  
**Ảnh hưởng production:** Rò rỉ tài liệu giữa tenant.  
**Cách sửa:** Lấy tenant từ claim được server xác thực hoặc tenant context đáng tin cậy; query lọc tenant, `!IsDeleted`, sau đó áp dụng policy/ACL theo user. Kiểm tra membership và quyền hiện hành, không chỉ claim tenant.

### High — Tin header do client tự khai

**Vấn đề:** `X-Tenant-Id` không phải nguồn authorization đáng tin cậy.  
**Tại sao xảy ra:** Client có thể tự sửa header.  
**Ảnh hưởng production:** Nếu dùng header để lọc ở nơi khác, dễ tạo bypass.  
**Cách sửa:** Tenant context được xác minh bằng authentication và membership; chỉ chấp nhận header như lựa chọn tenant sau khi xác thực quyền.

### High — Buffer toàn bộ file vào RAM nhiều lần

**Vấn đề:** `MemoryStream` và `ToArray()` tạo allocation lớn.  
**Tại sao xảy ra:** File bị copy đầy đủ trước khi trả response; mảng mới tạo thêm bản sao.  
**Ảnh hưởng production:** LOH pressure, GC pauses, OOM khi tải đồng thời.  
**Cách sửa:** Stream trực tiếp từ Blob tới response, giữ stream sống đến khi ASP.NET Core hoàn tất ghi.

### High — Public caching cho tài liệu riêng tư

**Vấn đề:** `public, max-age=3600` cho phép shared cache lưu response.  
**Tại sao xảy ra:** Chính sách cache không phù hợp dữ liệu có authorization.  
**Ảnh hưởng production:** Nội dung nhạy cảm có thể bị lưu và phục vụ không đúng ngữ cảnh.  
**Cách sửa:** `Cache-Control: private, no-store` cho dữ liệu nhạy cảm; kiểm tra cấu hình CDN/reverse proxy.

### Medium — Không truyền cancellation

**Vấn đề:** Query, Blob download và copy không dùng `RequestAborted`.  
**Tại sao xảy ra:** Client disconnect không được truyền xuyên chuỗi I/O.  
**Ảnh hưởng production:** Tốn bandwidth, connections và worker resources.  
**Cách sửa:** Nhận `CancellationToken` từ action và truyền xuống EF Core, Azure SDK và streaming.

### Medium — Không xử lý Blob không tồn tại hoặc storage failure

**Vấn đề:** Metadata có thể còn nhưng Blob đã bị xóa, Blob Storage có thể timeout.  
**Tại sao xảy ra:** Không có mapping lỗi dependency và phân loại retry.  
**Ảnh hưởng production:** 500 khó phân tích; retry không kiểm soát làm tăng tải.  
**Cách sửa:** Mapping `RequestFailedException` 404 thành lỗi phù hợp, 503/timeout theo chính sách; không retry vô hạn trong request.

### Medium — Tracking EF Core không cần thiết

**Vấn đề:** Entity được tracking dù chỉ đọc.  
**Tại sao xảy ra:** Query mặc định tracking.  
**Ảnh hưởng production:** Overhead nhỏ nhưng không cần thiết dưới tải cao.  
**Cách sửa:** `AsNoTracking()` và projection metadata tối thiểu.

### Medium — Thiếu kiểm soát filename/content type

**Vấn đề:** Metadata có thể chứa filename bất thường hoặc MIME không mong muốn.  
**Tại sao xảy ra:** Upload/metadata pipeline chưa được chứng minh là đã validate.  
**Ảnh hưởng production:** Rủi ro content sniffing và download behavior ngoài ý muốn.  
**Cách sửa:** Validate metadata tại ingestion, whitelist MIME phù hợp, đặt `X-Content-Type-Options: nosniff`; ưu tiên attachment.

### Low — Log chưa đủ chẩn đoán và cần giới hạn PII

**Vấn đề:** Chưa có duration, size, storage status; log user name có thể không cần thiết.  
**Tại sao xảy ra:** Log chỉ ghi sự kiện bắt đầu.  
**Ảnh hưởng production:** Khó phân biệt lỗi authorization, DB và Blob.  
**Cách sửa:** Log structured `documentId`, tenant pseudonymous, trace ID, latency và outcome; tránh filename hoặc token nhạy cảm.

## Phiên bản đề xuất

Giả định `IDocumentAccess` là policy service kiểm tra ACL/membership theo user hiện hành và tenant, trả về true chỉ khi được phép; `ITenantContext` được xây từ identity đã xác thực. Không được triển khai hai interface này bằng cách tin header trực tiếp.

```csharp
[Authorize]
[ApiController]
[Route("api/documents")]
public sealed class DocumentsController(
    AppDbContext db,
    BlobContainerClient container,
    ITenantContext tenantContext,
    IDocumentAccess access,
    ILogger<DocumentsController> logger) : ControllerBase
{
    [HttpGet("{id:guid}/download")]
    public async Task<IActionResult> Download(
        Guid id, CancellationToken cancellationToken)
    {
        var tenantId = tenantContext.RequiredTenantId;
        var doc = await db.Documents.AsNoTracking()
            .Where(x => x.Id == id &&
                        x.TenantId == tenantId &&
                        !x.IsDeleted)
            .Select(x => new DocumentDownloadInfo(
                x.Id, x.OwnerId, x.BlobName,
                x.FileName, x.ContentType))
            .SingleOrDefaultAsync(cancellationToken);

        if (doc is null || !await access.CanDownloadAsync(
                User, tenantId, doc, cancellationToken))
            return NotFound();

        Response.Headers.CacheControl = "private, no-store";
        Response.Headers["X-Content-Type-Options"] = "nosniff";

        try
        {
            var blob = container.GetBlobClient(doc.BlobName);
            var result = await blob.DownloadStreamingAsync(
                cancellationToken: cancellationToken);

            logger.LogInformation(
                "Document download authorized {DocumentId} {TraceId}",
                id, HttpContext.TraceIdentifier);

            return File(result.Value.Content,
                "application/octet-stream",
                SanitizeDownloadName(doc.FileName));
        }
        catch (RequestFailedException ex) when (ex.Status == 404)
        {
            logger.LogWarning(ex, "Missing blob for {DocumentId}", id);
            return NotFound();
        }
    }

    private static string SanitizeDownloadName(string name)
    {
        var cleaned = Path.GetFileName(name.Replace('\\', '/'));
        return string.IsNullOrWhiteSpace(cleaned) ? "download" : cleaned;
    }
}
```

`DocumentDownloadInfo`, `ITenantContext`, `IDocumentAccess` là abstractions giả định; cần định nghĩa cụ thể trong ứng dụng. ASP.NET Core `File(Stream,...)` xử lý disposal sau khi response hoàn tất; không dùng `using` quanh stream trả về. Khi streaming đã bắt đầu, lỗi giữa chừng không thể luôn chuyển thành JSON ProblemDetails; cần quan sát aborted responses. Cần bảo đảm `SanitizeDownloadName` và validation lúc upload đáp ứng chính sách tên file của hệ thống.

## Giải thích thiết kế sau khi sửa

Authorization được thực hiện **trước** truy cập Blob, với tenant đã xác minh và ACL riêng. SQL metadata là nguồn để xác định quyền; Blob vẫn private. Stream không cần materialize toàn bộ file. Chính sách cache ưu tiên bảo mật; cancellation truyền qua đường I/O. Một số policy thay đổi trong lúc stream đang chạy không thể thu hồi bytes đã gửi: cần xác định yêu cầu revoke theo business.

## Trade-offs

Proxy streaming giữ kiểm soát audit và không tiết lộ Blob URL, nhưng App Service chịu egress, kết nối và chi phí scale. Với file lớn, có thể cân nhắc user delegation SAS thời hạn ngắn sau authorization, giới hạn quyền Blob, nhưng phải tính rủi ro URL bị chia sẻ, khả năng thu hồi, CORS và audit. `no-store` giảm hiệu quả cache; đây là đánh đổi có chủ đích cho dữ liệu nhạy cảm.

## Cách kiểm thử

1. **Security integration:** user tenant A truy cập `id` tenant B, tài liệu bị xóa, user không thuộc ACL → không đọc Blob và không trả dữ liệu.
2. **Load test:** 100 download song song với file lớn; đo working set, GC, throughput, p95/p99.
3. **Failure-path:** client disconnect giữa stream; xác minh cancellation và cleanup.
4. **Storage integration:** metadata tồn tại nhưng Blob 404; Blob timeout; xác minh status, logs, không rò thông tin.
5. **HTTP security:** xác minh `Cache-Control`, `Content-Disposition`, `nosniff` và tên file bất thường.

## Quan sát trong production

Application Insights: request p95/p99, dependency duration SQL/Blob, failure rate theo status, trace ID. Azure Monitor: memory working set, GC heap/LOH, OOM/restarts, outbound bandwidth, concurrent requests. Audit log quyền truy cập thành công/thất bại theo tenant pseudonymous; alert khi 403/404 tăng bất thường, Blob 5xx hoặc OOM. Đối chiếu request cancellation với aborted streaming.

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from "vue";

type Product = {
  id: string;
  name: string;
  highlightHtml: string;
  price: number;
};

const query = ref("");
const products = ref<Product[]>([]);
const loading = ref(false);
const error = ref("");
const selected = ref<Product | null>(null);

async function search() {
  loading.value = true;
  const response = await fetch(
    "/api/products/search?q=" + query.value
  );
  const data = await response.json();
  products.value = data.items;
  loading.value = false;
}

watch(query, () => {
  search();
});

onMounted(() => {
  search();
});

function choose(product: Product) {
  selected.value = product;
}
</script>

<template>
  <section>
    <label for="product-query">Tìm sản phẩm</label>
    <input id="product-query" v-model="query" />
    <p v-if="loading">Đang tìm...</p>
    <p v-if="error">{{ error }}</p>
    <ul>
      <li v-for="product in products" :key="product.id">
        <div v-html="product.highlightHtml"></div>
        <span>{{ product.price }}</span>
        <button @click="choose(product)">Chọn</button>
      </li>
    </ul>
    <aside v-if="selected">{{ selected.name }}</aside>
  </section>
</template>
```

## Kết quả code review tham khảo

### Critical — XSS qua `v-html`

**Vấn đề:** Render `highlightHtml` chưa được tin cậy.  
**Tại sao xảy ra:** `v-html` chèn HTML; Vue không tự sanitize nội dung này.  
**Ảnh hưởng production:** Nội dung catalog độc hại có thể thực thi script qua các vector HTML/event handler trong browser.  
**Cách sửa:** Ưu tiên API trả plain text và highlight ranges; render text với interpolation, highlight bằng cấu trúc node an toàn. Nếu bắt buộc HTML, sanitize theo allowlist được kiểm thử ở boundary phù hợp và dùng CSP defense-in-depth.

### High — Response cũ ghi đè response mới

**Vấn đề:** Mọi request đều cập nhật `products` khi hoàn tất.  
**Tại sao xảy ra:** Network responses không đảm bảo cùng thứ tự với request.  
**Ảnh hưởng production:** Kết quả sai query, user chọn nhầm sản phẩm.  
**Cách sửa:** Abort request cũ và kiểm tra request sequence trước khi cập nhật state.

### High — Không xử lý lỗi và trạng thái HTTP

**Vấn đề:** `fetch` không throw khi HTTP 429/500; `json()` có thể throw.  
**Tại sao xảy ra:** Không kiểm tra `response.ok`, không `try/catch/finally`.  
**Ảnh hưởng production:** Loading kẹt, lỗi im lặng, dữ liệu cũ bị hiểu nhầm là mới.  
**Cách sửa:** Phân biệt abort, HTTP failure và network failure; đặt error state và cleanup có guard.

### Medium — Không debounce

**Vấn đề:** Gõ mỗi ký tự tạo request.  
**Tại sao xảy ra:** `watch` gọi `search` trực tiếp.  
**Ảnh hưởng production:** Tăng request, rate limit, load API/search cluster.  
**Cách sửa:** Debounce khoảng thời gian UX được đo đạc; server vẫn cần rate limiting.

### Medium — Query chưa URL-encode

**Vấn đề:** Nối trực tiếp query vào URL.  
**Tại sao xảy ra:** Ký tự `&`, `#`, `?` có ý nghĩa đặc biệt.  
**Ảnh hưởng production:** Search sai input, query parameters bị tách.  
**Cách sửa:** Dùng `URLSearchParams`.

### Medium — Loading state có thể sai khi request chồng nhau

**Vấn đề:** Request cũ có thể đặt `loading=false` trong lúc request mới đang chạy.  
**Tại sao xảy ra:** Không ràng buộc state với request hiện hành.  
**Ảnh hưởng production:** UX sai, dễ chọn kết quả cũ.  
**Cách sửa:** Chỉ request mới nhất được cập nhật loading/error/products.

### Medium — Không xác định chính sách query rỗng và giới hạn input

**Vấn đề:** Gửi cả query rỗng, không có min length/max length.  
**Tại sao xảy ra:** Không có contract rõ giữa frontend/backend.  
**Ảnh hưởng production:** Có thể gây expensive wildcard query hoặc trả catalog quá lớn.  
**Cách sửa:** Xác định ngưỡng tìm kiếm, giới hạn độ dài, paging và server validation.

### Low — Selection không đồng bộ với search

**Vấn đề:** `selected` vẫn giữ item từ query cũ.  
**Tại sao xảy ra:** Không reset hoặc kiểm tra selection khi query đổi.  
**Ảnh hưởng production:** User có thể thao tác nhầm sản phẩm.  
**Cách sửa:** Reset selection khi query thay đổi hoặc tách rõ “đã chọn” khỏi search result theo UX contract.

```vue
const query = ref("");
const products = ref<Product[]>([]);
const selected = ref<Product | null>(null);
const loading = ref(false);
const error = ref("");
let timer: ReturnType<typeof setTimeout> | undefined;
let controller: AbortController | undefined;
let version = 0;

watch(query, (value) => {
  const current = ++version;
  if (timer) clearTimeout(timer);
  controller?.abort();
  controller = undefined;
  selected.value = null;
  products.value = [];
  error.value = "";
  loading.value = false;

  const q = value.trim();
  if (q.length < 2 || q.length > 100) return;

  timer = setTimeout(async () => {
    if (current !== version) return;
    const abort = new AbortController();
    controller = abort;
    loading.value = true;
    try {
      const params = new URLSearchParams({ q });
      const response = await fetch(
        "/api/products/search?" + params.toString(),
        { signal: abort.signal }
      );
      if (!response.ok) throw new Error("Search unavailable");
      const data: { items: Product[] } = await response.json();
      if (current === version) products.value = data.items;
    } catch (e) {
      if (current === version && !abort.signal.aborted)
        error.value = "Không thể tìm kiếm. Vui lòng thử lại.";
    } finally {
      if (current === version) loading.value = false;
    }
  }, 250);
});

onBeforeUnmount(() => {
  version++;
  if (timer) clearTimeout(timer);
  controller?.abort();
});
</script>

<template>
  <section>
    <label for="product-query">Tìm sản phẩm</label>
    <input id="product-query" v-model="query" maxlength="100" />
    <p v-if="loading">Đang tìm...</p>
    <p v-if="error" role="alert">{{ error }}</p>
    <ul>
      <li v-for="product in products" :key="product.id">
        <span>{{ product.name }}</span>
        <span>{{ product.price }}</span>
        <button type="button" @click="selected = product">Chọn</button>
      </li>
    </ul>
    <aside v-if="selected">{{ selected.name }}</aside>
  </section>
</template>
```

Bản sửa giữ code tương đối nhỏ; production nên bổ sung schema validation cho response và quy ước retry UX. `AbortController` giảm request còn đang chạy nhưng **không bảo đảm server đã ngừng xử lý**; `version` bảo vệ state ngay cả khi abort đến muộn. Với query ban đầu rỗng, không gửi request theo contract giả định.

## Giải thích thiết kế sau khi sửa

Watcher invalidates request cũ ngay khi query thay đổi; timer chỉ giảm tần suất gọi API. Guard `version` đảm bảo kết quả đúng query hiện tại. Render `{{ product.name }}` dùng text escaping của Vue thay vì HTML không tin cậy. Backend cần áp dụng paging, giới hạn query, rate limit và kiểm soát dữ liệu trả về; frontend không phải security boundary.

## Trade-offs

Debounce 250 ms giảm tải nhưng tăng độ trễ trước request; giá trị tối ưu cần đo theo UX và latency. Abort giúp tiết kiệm tài nguyên mạng nhưng có thể không ngăn công việc backend đã bắt đầu. Plain text bỏ highlight giàu định dạng; có thể khôi phục bằng server trả highlight offsets và render bằng text nodes, đổi lại contract phức tạp hơn. Caching search phải xét personalization, freshness và quyền truy cập.

## Cách kiểm thử

1. **Component concurrency:** giả lập request A chậm hơn B, xác minh UI chỉ hiện kết quả B.
2. **Security:** payload chứa HTML/event handlers được hiển thị như text, không thực thi.
3. **Failure-path:** HTTP 429, 500, network reject và invalid JSON; loading kết thúc, lỗi hiển thị phù hợp.
4. **E2E Playwright:** gõ nhanh, xóa query, chuyển trang/unmount; không có stale results hoặc state update sau unmount.
5. **Load/API test:** đo request per keystroke, p95 search và rate limit trước/sau debounce.

## Quan sát trong production

Browser RUM: search interaction latency, request count/query session, error rate, abort ratio, stale-result prevention metric nếu có. Application Insights: endpoint p95/p99, 429/5xx, search dependency latency, query length buckets (không log raw query nhạy cảm). Dashboard so sánh request volume trước/sau release, cảnh báo tăng đột biến lỗi search. CSP violation reports hỗ trợ phát hiện rủi ro HTML injection nhưng không thay thế escaping.

## Câu hỏi phỏng vấn mở rộng

1. Nếu search hỗ trợ personalized pricing, cache key và privacy thay đổi thế nào?
2. Khi cần highlight chính xác từ khóa, bạn thiết kế API contract an toàn ra sao?
3. Khi backend trả kết quả theo eventual consistency từ Elasticsearch, UI cần truyền đạt freshness thế nào?

# Tổng kết hôm nay

## Kiến thức trọng tâm

Authorization phải kiểm tra quyền trên **resource cụ thể**, không chỉ authentication; streaming file cần xét memory, cancellation, cache và failure giữa response. Frontend asynchronous state cần chống response out-of-order; render HTML không tin cậy là rủi ro security, còn debounce không thay thế rate limiting và server validation.

## Mẫu tư duy cần nhớ

1. Kiểm tra quyền trước khi truy cập dữ liệu; không tin input do client tự khai.
2. Đo allocation, concurrency và dependency latency trước khi tối ưu.
3. Mọi async response cần ràng buộc với phiên bản state mà nó phục vụ.
4. Kiểm thử failure-path và security boundary, không chỉ happy path.
5. Chọn phương án đơn giản có thể quan sát được trước khi thêm caching hoặc hạ tầng phức tạp.
