# Code Review Challenge 1 — Import bảng giá CSV gây sai dữ liệu và nghẽn SQL Server

**Chủ đề:** C#/.NET 8, ASP.NET Core, EF Core, SQL Server  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 45 phút  
**Số vấn đề cần tìm:** khoảng 9

## Bối cảnh

Portal B2B nhập bảng giá tối đa 100.000 dòng/file; 20 imports đồng thời. Mỗi SKU thuộc tenant, SQL Server có unique (TenantId,Sku). Client có thể retry khi HTTP timeout. Production có giá sai tenant, import báo failed nhưng vài dòng vẫn được ghi, p95 tăng. Chưa thống nhất atomic toàn file hay partial success.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/prices")]
[Authorize(Roles = "CatalogEditor")]
public sealed class ImportController : ControllerBase
{
    private readonly CatalogDbContext _db;
    private readonly ILogger<ImportController> _log;
    public ImportController(CatalogDbContext db, ILogger<ImportController> log)
        => (_db, _log) = (db, log);

    [HttpPost("import")]
    public async Task<IActionResult> Import([FromBody] List<PriceRow> rows)
    {
        var tenantId = Request.Headers["X-Tenant-Id"].ToString();
        var result = new List<object>();
        foreach (var row in rows)
        {
            try
            {
                var product = await _db.Products.FirstOrDefaultAsync(
                    p => p.TenantId == tenantId && p.Sku == row.Sku);
                if (product == null)
                {
                    result.Add(new { row.Sku, status = "missing" });
                    continue;
                }
                product.Price = row.Price;
                product.UpdatedAtUtc = DateTime.UtcNow;
                await _db.SaveChangesAsync();
                result.Add(new { row.Sku, status = "updated" });
            }
            catch (Exception ex)
            {
                _log.LogWarning(ex, "Row {Sku} failed", row.Sku);
                result.Add(new { row.Sku, status = "failed" });
            }
        }
        return Ok(new { total = rows.Count, result });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Tenant spoofing

**Vấn đề:** Header tenant do client tự đặt.  
**Tại sao xảy ra:** Role không ràng buộc membership với tenant.  
**Ảnh hưởng production:** Có thể sửa giá của tenant khác.  
**Cách sửa:** Dùng tenant từ identity đã xác thực, kiểm tra membership và policy ở data access.

### [High] — Không validate dữ liệu và kích thước

**Vấn đề:** Giá âm, SKU rỗng, duplicate và payload quá lớn được nhận.  
**Tại sao xảy ra:** Thiếu kiểm tra trước ghi.  
**Ảnh hưởng production:** Sai giá và nguy cơ resource exhaustion.  
**Cách sửa:** Giới hạn request, validate price/SKU, deduplicate hoặc reject theo chính sách.

### [High] — N+1 database operations

**Vấn đề:** Mỗi dòng SELECT rồi SaveChanges.  
**Tại sao xảy ra:** Vòng lặp I/O tuần tự.  
**Ảnh hưởng production:** Latency lớn, tăng DB pressure.  
**Cách sửa:** Staging + set-based update theo batch; đo plan, waits, log throughput.

### [High] — Partial commits không được mô tả

**Vấn đề:** Lỗi giữa file không rollback các dòng trước.  
**Tại sao xảy ra:** Mỗi SaveChanges commit riêng.  
**Ảnh hưởng production:** Client retry có thể ghi đè giá mới.  
**Cách sửa:** Chốt atomic/partial policy, job ID và durable progress.

### [High] — Tracker sau exception

**Vấn đề:** Tiếp tục dùng cùng DbContext sau failed SaveChanges.  
**Tại sao xảy ra:** Entity modified có thể vẫn tracked.  
**Ảnh hưởng production:** Dòng failed có thể được ghi ở lần save sau.  
**Cách sửa:** Rollback và bỏ context sau lỗi; scope theo batch.

### [High] — Lost update khi concurrent imports

**Vấn đề:** Hai writer cùng sửa SKU.  
**Tại sao xảy ra:** Không có version/order check.  
**Ảnh hưởng production:** File cũ ghi đè file mới.  
**Cách sửa:** Rowversion hoặc source revision và conflict policy.

### [Medium] — Timeout và retry không idempotent

**Vấn đề:** Xử lý import dài ngay trong request.  
**Tại sao xảy ra:** Không có durable job identity.  
**Ảnh hưởng production:** Không phân biệt đang chạy với chưa nhận.  
**Cách sửa:** 202 Accepted + durable job, unique idempotency key/payload hash.

### [Medium] — Không truyền cancellation

**Vấn đề:** Queries và SaveChanges thiếu token.  
**Tại sao xảy ra:** Không có cancellation policy.  
**Ảnh hưởng production:** Tốn tài nguyên sau disconnect.  
**Cách sửa:** Dùng CancellationToken cho request; worker dùng shutdown token.

### [Low] — Response/report lớn, telemetry thiếu

**Vấn đề:** Trả tất cả kết quả và chỉ log SKU khi lỗi.  
**Tại sao xảy ra:** Thiếu job correlation và pagination.  
**Ảnh hưởng production:** Khó truy vết, tăng memory.  
**Cách sửa:** Report phân trang, metrics theo job và structured logs.

## Phiên bản đề xuất

```csharp
[ApiController]
[Route("api/price-imports")]
[Authorize(Policy = "CanImportPrices")]
public sealed class PriceImportsController(
    ICurrentTenant tenant, IPriceImportJobs jobs) : ControllerBase
{
    [HttpPost]
    [RequestSizeLimit(20_000_000)]
    public async Task<IActionResult> Submit(
        [FromBody] PriceImportRequest request, CancellationToken ct)
    {
        var tenantId = tenant.RequiredAuthorizedTenantId;
        if (request.Rows is null || request.Rows.Count is < 1 or > 100_000)
            return BadRequest("Invalid row count");
        if (request.Rows.Any(x => string.IsNullOrWhiteSpace(x.Sku)
                                  || x.Price < 0))
            return BadRequest("Invalid SKU or price");
        if (request.Rows.GroupBy(x => x.Sku, StringComparer.OrdinalIgnoreCase)
                        .Any(g => g.Count() > 1))
            return BadRequest("Duplicate SKU");
        var job = await jobs.CreateOrGetAsync(
            tenantId, request.IdempotencyKey, request.Rows, ct);
        return AcceptedAtAction(nameof(Status), new { id = job.Id },
            new { job.Id, job.Status });
    }

    [HttpGet("{id:guid}")]
    public async Task<IActionResult> Status(Guid id, CancellationToken ct)
    {
        var job = await jobs.GetAuthorizedAsync(
            tenant.RequiredAuthorizedTenantId, id, ct);
        return job is null ? NotFound() : Ok(job);
    }
}
```

## Giải thích thiết kế sau khi sửa

Đây là skeleton API, không phải worker hoàn chỉnh. IPriceImportJobs phải lưu payload và job atomically, unique (TenantId,IdempotencyKey), kiểm tra payload hash khi reuse key. Worker claim bằng lease/fencing, staging (JobId,RowNumber), validate và set-based update theo batch. Dùng source revision/expected version chống ghi đè; lưu kết quả batch cùng commit. Atomic toàn file cần transaction lớn; partial success cần durable progress và báo cáo rõ.

## Trade-offs

Staging/job tăng schema, chi phí vận hành và eventual completion; transaction toàn file dễ giải thích nhưng kéo dài locks và tăng transaction log. Với file nhỏ, ít traffic, batch đồng bộ có thể đơn giản hơn. Không tự động chọn Redis hoặc message broker.

## Cách kiểm thử

1. Security: tenant A giả header tenant B không sửa được dữ liệu B.
2. Database: duplicate SKU, giá âm, missing SKU và report chính xác.
3. Concurrency: import cũ không ghi đè source revision mới.
4. Failure: kill worker sau commit trước acknowledgement; retry không lặp effect.
5. Load: 20 imports, đo p95 completion, lock waits, log writes.

## Quan sát trong production

Application Insights: job duration, rows processed/rejected, retries, conflicts, queue age, correlation ID; SQL Server Query Store, deadlocks, lock waits, execution plans, transaction log. Alert backlog và error rate; không log raw CSV.

## Câu hỏi phỏng vấn mở rộng

1. Nếu Product yêu cầu atomic 100.000 dòng, bạn thay đổi gì?
2. Nếu file mới đến trước file cũ, xác định ordering ra sao?
3. Khi nào SqlBulkCopy + staging đáng giá hơn EF Core batching?

## Kết quả code review tham khảo

### [Critical] — Breaking schema compatibility

**Vấn đề:** Drop DisplayName khi old app vẫn đang chạy.  
**Tại sao xảy ra:** Old/new apps chia sẻ database.  
**Ảnh hưởng production:** HTTP 500 trong rollout và rollback.  
**Cách sửa:** Expand bằng thêm FullName, giữ DisplayName tới khi mọi consumer đã migrate.

### [Critical] — Mất dữ liệu tên

**Vấn đề:** Gán FullName chuỗi rỗng sau khi drop nguồn.  
**Tại sao xảy ra:** Không backfill từ DisplayName.  
**Ảnh hưởng production:** Mất dữ liệu không thể phục hồi bằng deploy.  
**Cách sửa:** Backfill trước khi drop; verify counts/hashes, thử backup/restore.

### [High] — Migration chạy nhiều lần

**Vấn đề:** run_once false trên hai nodes.  
**Tại sao xảy ra:** DDL không được phối hợp.  
**Ảnh hưởng production:** Race và schema errors.  
**Cách sửa:** Migration stage một coordinator, version table và idempotent guards.

### [High] — Rollback binary không rollback schema

**Vấn đề:** Previous package vẫn cần DisplayName.  
**Tại sao xảy ra:** Schema phá vỡ tương thích.  
**Ảnh hưởng production:** Kéo dài outage.  
**Cách sửa:** Rollback trên expanded schema, contract ở release khác; roll-forward plan cho destructive change.

### [High] — Artifact không immutable

**Vấn đề:** latest-successful có thể thay đổi.  
**Tại sao xảy ra:** Không pin build ID/digest.  
**Ảnh hưởng production:** Nodes hoặc rollback dùng binary khác.  
**Cách sửa:** Pin artifact version và checksum ngay lúc tạo release.

### [High] — Parallel deployment dừng cả hai App Pools

**Vấn đề:** Không có LB draining hoặc readiness gate.  
**Tại sao xảy ra:** Hai nodes có thể unavailable cùng lúc.  
**Ảnh hưởng production:** Downtime.  
**Cách sửa:** Rolling từng node, drain, warmup, verify, add-back.

### [Medium] — Smoke test quá yếu

**Vấn đề:** Chỉ gọi /health một lần.  
**Tại sao xảy ra:** Không kiểm tra customer flow/schema.  
**Ảnh hưởng production:** False-green release.  
**Cách sửa:** Readiness, synthetic read/write và error-budget gate.

### [Medium] — Secret scope và DDL privileges chưa xác minh

**Vấn đề:** Connection string inject không thể hiện secret masking và quyền.  
**Tại sao xảy ra:** Thiếu kiểm soát privilege và audit.  
**Ảnh hưởng production:** Nguy cơ lộ secret/quyền quá rộng.  
**Cách sửa:** Sensitive variables, separate migration identity, least privilege và audit.

## Phiên bản đề xuất

```text
release:
  artifact:
    source: TeamCity
    version: build-1842
    digest: "sha256:<verified-digest>"
  stages:
    - name: preflight
      checks: [backup-restore-tested, compatibility-tested, error-budget]
    - name: expand-schema
      execution: single-coordinator
      migration: 20261119_add_FullName_and_backfill
      preserve: Customer.DisplayName
    - name: rolling-web
      batch_size: 1
      drain_load_balancer: true
      warmup: true
      readiness: /ready
      smoke: [customer-read, customer-update-and-readback]
      abort_on_regression: true
    - name: verify
      checks: [error-rate, p95, data-consistency]
    - name: contract-in-later-release
      requires: [all-consumers-migrated, rollback-window-expired, approval]

-- SQL Server expand migration, versioned and run once:
IF COL_LENGTH('dbo.Customer', 'FullName') IS NULL
    ALTER TABLE dbo.Customer ADD FullName nvarchar(200) NULL;
UPDATE dbo.Customer
SET FullName = DisplayName
WHERE FullName IS NULL AND DisplayName IS NOT NULL;
```

## Giải thích thiết kế sau khi sửa

Pipeline là pseudocode; SQL ở cuối là script minh họa riêng, không chạy nguyên YAML như executable. Test old-app/expanded-schema và new-app/expanded-schema. Nếu old app vẫn ghi DisplayName, cần compatibility strategy (dual-write qua service, trigger được test, hoặc tạm giữ old writer ownership) trước khi chuyển read sang FullName. Contract chỉ khi xác nhận không còn old consumers và đã hết rollback window.

## Trade-offs

Giữ hai cột tạm thời làm tăng độ phức tạp đồng bộ. Rolling deployment chậm hơn parallel nhưng giới hạn blast radius. Backfill lớn cần batch và theo dõi lock/log; nếu không thể đảm bảo compatibility, cân nhắc maintenance window được phê duyệt.

## Cách kiểm thử

1. Integration: old app và new app đều hoạt động trên expanded schema.
2. Migration: chạy lại script trên snapshot dữ liệu ẩn danh, không mất tên.
3. Deployment: fail readiness node đầu, node còn lại vẫn phục vụ.
4. Rollback: pinned old artifact chạy được với expanded schema.
5. Load: đo p95, SQL lock waits, transaction log khi backfill.

## Quan sát trong production

Theo dõi TeamCity build ID, Octopus release ID, package digest, schema version; Application Insights HTTP 5xx/p95; IIS App Pool recycling, LB healthy nodes; SQL blocking, deadlocks, log growth và tỷ lệ FullName NULL. Có ngưỡng abort rollout.

## Câu hỏi phỏng vấn mở rộng

1. Nếu app cũ không thể sửa để dual-write, chọn phương án nào?
2. Khi nào blue-green tốt hơn rolling với shared DB?
3. Nếu backfill mất sáu giờ, thiết kế cutover ra sao?
