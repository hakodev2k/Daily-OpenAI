# Code Review Challenge 1 — Optimizely CMS preview bị cache ra public

**Chủ đề:** ASP.NET Core, Optimizely CMS, Akamai CDN, authorization, SEO  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35 phút  
**Số vấn đề cần tìm:** khoảng 8

## Bối cảnh

Website thương mại 12 ngôn ngữ dùng Optimizely CMS, ASP.NET Core và Akamai CDN. Editor preview bản nháp, khách chỉ được xem bản published. Sau khi tối ưu cache, người dùng báo cáo thấy nội dung preview, sai ngôn ngữ và sitemap có URL không nên public. Có nhiều origin instances; chưa biết cấu hình cache key thực tế ở edge.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/content")]
public sealed class ContentController : ControllerBase
{
    private readonly IContentLoader _loader;
    private readonly IContentRepository _repository;
    private readonly IMemoryCache _cache;

    public ContentController(IContentLoader loader,
        IContentRepository repository, IMemoryCache cache)
    {
        _loader = loader;
        _repository = repository;
        _cache = cache;
    }

    [HttpGet("{id:int}")]
    public IActionResult Get(int id, string language = "en",
        bool preview = false)
    {
        var key = $"content:{id}";
        var result = _cache.GetOrCreate(key, entry =>
        {
            entry.AbsoluteExpirationRelativeToNow =
                TimeSpan.FromMinutes(30);
            var options = preview
                ? LoaderOptions.Default
                : new LoaderOptions {
                    LanguageLoaderOption =
                        LanguageLoaderOption.Specific(
                            new CultureInfo(language))
                };
            var content = _loader.Get<IContent>(
                new ContentReference(id), options);
            return new {
                Id = id, Name = content.Name,
                Language = language, Preview = preview
            };
        });
        Response.Headers.CacheControl =
            "public, max-age=1800, s-maxage=3600";
        return Ok(result);
    }

    [HttpPost("{id:int}/publish")]
    public IActionResult Publish(int id)
    {
        var content = _repository.Get<IContent>(
            new ContentReference(id));
        _repository.Save(content, SaveAction.Publish,
            AccessLevel.NoAccess);
        return NoContent();
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Preview thiếu authorization

**Vấn đề:** Caller tự chọn `preview=true`.  
**Tại sao xảy ra:** Không có editor policy; `LoaderOptions.Default` không phải bảo đảm lấy đúng draft/version, còn phụ thuộc CMS version.  
**Ảnh hưởng production:** Nguy cơ lộ nội dung chưa publish.  
**Cách sửa:** Tách endpoint preview, kiểm tra editor identity, ACL và version resolution theo API Optimizely đang dùng.

### [Critical] — Shared caching cho nội dung có thể riêng tư

**Vấn đề:** Luôn trả `public, s-maxage`.  
**Tại sao xảy ra:** Edge/browser có thể cache response dù chứa nội dung nhạy cảm.  
**Ảnh hưởng production:** Cross-user data leak.  
**Cách sửa:** Preview `private, no-store`; chỉ published anonymous content mới được cache shared.

### [High] — Cache key không phân biệt biến thể

**Vấn đề:** `content:{id}` bỏ qua language, preview, version và access.  
**Tại sao xảy ra:** Request đầu tiên điền memory cache cho các request sau cùng ID.  
**Ảnh hưởng production:** Sai ngôn ngữ, stale hoặc leaked content.  
**Cách sửa:** Key public gồm ID, locale, revision; không dùng chung preview cache.

### [High] — Không xác nhận published và visible

**Vấn đề:** Content load không có contract rõ về published status và ACL.  
**Tại sao xảy ra:** Loader được coi như authorization boundary.  
**Ảnh hưởng production:** Có thể phục vụ expired/restricted content tùy cấu hình.  
**Cách sửa:** CMS adapter chỉ trả published, visible, authorized content; kiểm tra đúng API phiên bản đang triển khai.

### [High] — Publish thiếu policy

**Vấn đề:** POST không có `[Authorize]`, sử dụng `AccessLevel.NoAccess`.  
**Tại sao xảy ra:** Không kiểm tra quyền và editorial workflow tại HTTP boundary.  
**Ảnh hưởng production:** Unauthorized publication nếu endpoint truy cập được.  
**Cách sửa:** `CmsPublisher` policy, workflow validation, CSRF khi dùng cookie, audit trail.

### [High] — Thiếu invalidation sau publish

**Vấn đề:** Memory cache và Akamai không được purge.  
**Tại sao xảy ra:** TTL không gắn với revision.  
**Ảnh hưởng production:** Stale content trên nhiều tầng.  
**Cách sửa:** Durable publish event, idempotent purge/reconciliation, revisioned cache keys.

### [Medium] — Input validation và error mapping thiếu

**Vấn đề:** Locale tùy ý, missing content có thể thành 500.  
**Tại sao xảy ra:** Chưa allowlist và xử lý NotFound/Forbidden.  
**Ảnh hưởng production:** Tăng 5xx và khó debug.  
**Cách sửa:** Validate locale, phân biệt 400/403/404.

### [Medium] — Thiếu observability

**Vấn đề:** Không có cache tier, revision, purge latency, correlation.  
**Tại sao xảy ra:** Không thiết kế telemetry contract.  
**Ảnh hưởng production:** Không biết stale xuất phát từ origin hay CDN.  
**Cách sửa:** Structured logs, cache hit/miss, Akamai status, trace publish-to-purge; không log preview token.

## Phiên bản đề xuất

Pseudocode tầng application: `ICmsContentGateway` và `IPurgeQueue` là adapter do đội phát triển triển khai theo Optimizely version, không phải API framework có sẵn.

```csharp
[Authorize(Policy = "CmsEditor")]
[HttpGet("preview/{id:int}")]
public async Task<IActionResult> Preview(
    int id, string language, CancellationToken ct)
{
    if (!_locales.IsSupported(language)) return BadRequest();
    var data = await _cms.GetAuthorizedPreviewAsync(
        id, language, User, ct);
    Response.Headers.CacheControl = "private, no-store";
    return data is null ? NotFound() : Ok(data);
}

[AllowAnonymous]
[HttpGet("public/{id:int}")]
public async Task<IActionResult> Public(
    int id, string language, CancellationToken ct)
{
    if (!_locales.IsSupported(language)) return BadRequest();
    var data = await _cms.GetPublishedVisibleAsync(
        id, language, ct);
    if (data is null) return NotFound();
    Response.Headers.CacheControl =
        "public, max-age=60, s-maxage=300";
    return Ok(data);
}

[Authorize(Policy = "CmsPublisher")]
[HttpPost("{id:int}/publish")]
public async Task<IActionResult> Publish(
    int id, CancellationToken ct)
{
    var revision = await _cms.PublishWithAuditAsync(
        id, User, ct);
    await _purgeQueue.EnqueueAsync(
        new ContentPublished(id, revision), ct);
    return Accepted();
}
```

Publish và enqueue cần durable outbox/reconciliation để không mất purge event nếu process crash giữa hai bước. Sitemap chỉ dùng canonical URLs của published content; preview và campaign query không được đưa vào.

## Giải thích thiết kế sau khi sửa

Public và preview là hai trust boundaries. Authorization phải thực hiện ở server, không dựa vào client flags. Public cache key gắn locale và revision; purge là asynchronous workflow có retry, idempotency và audit.

## Trade-offs

TTL ngắn tăng origin load; purge có eventual consistency; preview bypass cache tăng latency editor. Versioned cache keys tăng object count. Không mặc định thêm Redis nếu CDN/origin đáp ứng SLO.

## Cách kiểm thử

1. Security integration: anonymous không preview/publish; editor chỉ đọc nội dung được cấp quyền.
2. Cache isolation: nhiều locale, draft/published, thứ tự request đảo ngược.
3. Multi-instance: publish trên A, đọc trên B và Akamai; kiểm tra freshness bound.
4. Failure-path: purge timeout, outbox retry, duplicate publish events.
5. SEO E2E: sitemap/canonical/hreflang không chứa preview hoặc unpublished URLs.

## Quan sát trong production

Log content ID, locale, revision, cache tier, publish event ID; không log secret. Đo hit/miss, `Age`, CDN cache status, purge lag, p95 origin và 403/404/5xx. Alert nếu public response có preview marker hoặc purge lag vượt SLO.

## Câu hỏi phỏng vấn mở rộng

1. Nếu Akamai không hỗ trợ purge theo content ID, thiết kế surrogate keys thế nào?
2. Preview cho reviewer bên ngoài nên dùng short-lived token ra sao?
3. Khi publish phải visible ngay, thay đổi cache policy thế nào?

## Kết quả code review tham khảo

### [Critical] — Database credential hardcode

**Vấn đề:** Password trong manifest.  
**Tại sao xảy ra:** Secrets nằm trong deployment artifact.  
**Ảnh hưởng production:** Rò rỉ credential và unauthorized access.  
**Cách sửa:** Rotate credential, dùng secret manager/Kubernetes Secret được kiểm soát, RBAC least privilege; tránh log secrets.

### [High] — Migration không tương thích existing rows

**Vấn đề:** Thêm `NOT NULL` không default trước khi backfill.  
**Tại sao xảy ra:** PostgreSQL phải thỏa constraint với existing rows; UPDATE sau có thể không bao giờ chạy.  
**Ảnh hưởng production:** Migration fail.  
**Cách sửa:** Expand nullable, backfill theo batch, validate, contract NOT NULL sau khi writers tương thích.

### [High] — Mixed-version incompatibility

**Vấn đề:** App mới giả định schema mới; app cũ chưa chắc ghi cột mới.  
**Tại sao xảy ra:** Rolling deployment có overlap.  
**Ảnh hưởng production:** 500 hoặc dữ liệu không nhất quán.  
**Cách sửa:** Expand–migrate–contract; backward-compatible reads/writes trước, contract ở release khác.

### [High] — Job không có sequencing gate

**Vấn đề:** Manifest không bảo đảm migration hoàn tất trước app rollout.  
**Tại sao xảy ra:** Resource declaration không định nghĩa release dependency.  
**Ảnh hưởng production:** App mới chạy trước schema.  
**Cách sửa:** Pipeline preflight, migration lock, idempotent execution và success gate.

### [High] — Mutable image tag

**Vấn đề:** `:latest` thay đổi giữa các lần pull.  
**Tại sao xảy ra:** Không pin immutable digest.  
**Ảnh hưởng production:** Version drift, rollback không tái lập.  
**Cách sửa:** Pin digest, lưu provenance và release ID.

### [High] — Probe không tách chức năng

**Vấn đề:** Liveness và readiness cùng `/health`; nếu endpoint phụ thuộc DB, DB outage có thể gây restart cascade.  
**Tại sao xảy ra:** Liveness đo process health, readiness đo khả năng phục vụ.  
**Ảnh hưởng production:** Restarts và thundering herd.  
**Cách sửa:** Lightweight liveness, dependency-aware readiness khi phù hợp, startupProbe và graceful shutdown.

### [Medium] — Capacity budget quá rộng

**Vấn đề:** `maxUnavailable: 3` cho phép mất nửa Pods.  
**Tại sao xảy ra:** Không dựa trên load/headroom.  
**Ảnh hưởng production:** p95 và 5xx tăng.  
**Cách sửa:** Cân nhắc `maxUnavailable: 0`, `maxSurge: 1` nếu đủ capacity.

### [Medium] — Thiếu resource/termination/telemetry

**Vấn đề:** Không có requests/limits, shutdown grace, rollout gates.  
**Tại sao xảy ra:** Thiếu operational design.  
**Ảnh hưởng production:** OOM, dropped requests, delayed rollback.  
**Cách sửa:** Profile resources, SIGTERM drain, alerts và release dashboards.

## Giải thích thiết kế sau khi sửa

Pipeline triển khai schema expand, kiểm tra compatibility, chạy migration có lock và gate, rollout app, backfill, validate rồi contract trong release sau. Artifact immutable giúp rollback app tái lập. Database schema phải vẫn hỗ trợ app cũ khi rollback.

## Trade-offs

Surge cần node headroom; nhiều phase làm release dài hơn; nullable transition thêm complexity tạm thời; dependency-aware readiness có thể giảm capacity khi DB outage. Kubernetes không tự động giải quyết migration sequencing.

## Cách kiểm thử

1. Database integration trên snapshot existing rows, đo migration/locks.
2. Mixed-version test với old/new apps cùng schema.
3. Load/deployment validation: rolling update và SIGTERM drain.
4. Failure injection: DB timeout, migration fail, readiness false, image pull fail.
5. Security audit: credential rotation, RBAC, secret exposure trong logs/manifests.

## Quan sát trong production

Application Insights/OpenTelemetry: p50/p95/p99, 5xx, dependency latency, release ID. Kubernetes: available replicas, readiness, restarts, OOMKilled, CPU throttling. PostgreSQL: schema version, blocking sessions, lock waits, long transactions. Alert theo error budget và migration gate failures.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào có thể drop cột cũ mà không làm hỏng rollback?
2. Migration thành công nhưng rollout thất bại: rollback app và schema thế nào?
3. Nếu không đủ surge capacity, chọn rollout strategy nào?
