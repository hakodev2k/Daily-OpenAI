# Code Review Challenge 1 — ASP.NET Core export báo cáo bị treo khi client ngắt kết nối

**Chủ đề:** ASP.NET Core, HTTP streaming, cancellation, memory và production performance  
**Độ khó:** Senior  
**Thời gian review đề xuất:** 25 phút

## Bối cảnh

Một enterprise portal chạy ASP.NET Core 8 trên Azure App Service Linux, 4 instances. Người dùng xuất báo cáo timesheet CSV theo khoảng ngày. Mỗi lần có thể trả về từ vài trăm đến 2 triệu dòng. Gần đây p99 tăng mạnh, memory tăng khi nhiều người export cùng lúc; có những request vẫn chạy sau khi browser đóng tab. Cần giữ format CSV và không thêm infrastructure mới nếu chưa có bằng chứng cần thiết.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/reports")]
public sealed class ReportsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<ReportsController> _logger;

    public ReportsController(
        AppDbContext db,
        ILogger<ReportsController> logger)
    {
        _db = db;
        _logger = logger;
    }

    [HttpGet("timesheets.csv")]
    public async Task<IActionResult> Export(
        [FromQuery] DateOnly from,
        [FromQuery] DateOnly to)
    {
        var rows = await _db.Timesheets
            .Where(x => x.WorkDate >= from && x.WorkDate <= to)
            .Include(x => x.Employee)
            .OrderBy(x => x.Id)
            .ToListAsync();

        var buffer = new StringBuilder();
        buffer.AppendLine("Employee,Date,Hours,Note");

        foreach (var row in rows)
        {
            buffer.Append(row.Employee.DisplayName).Append(',')
                .Append(row.WorkDate).Append(',')
                .Append(row.Hours).Append(',')
                .Append(row.Note)
                .AppendLine();
        }

        _logger.LogInformation(
            "Export generated: {Csv}", buffer.ToString());

        return File(
            Encoding.UTF8.GetBytes(buffer.ToString()),
            "text/csv",
            "timesheets.csv");
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Ghi toàn bộ dữ liệu nhân sự vào logs

**Vấn đề:** `buffer.ToString()` được log nguyên văn.  
**Tại sao xảy ra:** Logging không giới hạn và không có data minimization.  
**Ảnh hưởng production:** Rò rỉ thông tin cá nhân, chi phí ingestion và retention tăng.  
**Cách sửa:** Log số dòng, duration, kích thước, correlation ID; không log nội dung CSV.

### [High] — Materialize toàn bộ tập dữ liệu và nhân bản trong memory

**Vấn đề:** `ToListAsync`, `StringBuilder`, `ToString`, `GetBytes` cùng tồn tại.  
**Tại sao xảy ra:** Query, build và HTTP response đều được buffer.  
**Ảnh hưởng production:** LOH pressure, GC pauses, OOM khi concurrency tăng.  
**Cách sửa:** Projection và `AsAsyncEnumerable` kết hợp ghi tuần tự ra response stream; giới hạn số export đồng thời nếu đo đạc cho thấy cần.

### [High] — Không truyền cancellation

**Vấn đề:** Query và output không nhận `RequestAborted`.  
**Tại sao xảy ra:** Cancellation không được propagate.  
**Ảnh hưởng production:** Tiếp tục tốn database và CPU sau disconnect.  
**Cách sửa:** Truyền `CancellationToken` tới EF Core và stream writes; xử lý `OperationCanceledException` phù hợp.

### [High] — CSV không được escape và không xử lý formula injection

**Vấn đề:** Giá trị chứa comma, quote, CR/LF phá cấu trúc CSV; giá trị bắt đầu bằng `=`, `+`, `-`, `@` có thể bị spreadsheet diễn giải là công thức.  
**Tại sao xảy ra:** Nối chuỗi thô không phải CSV serialization.  
**Ảnh hưởng production:** File sai cột, dữ liệu sai hoặc rủi ro khi mở bằng spreadsheet.  
**Cách sửa:** Dùng CSV writer đã kiểm chứng, escape chuẩn RFC 4180 và áp dụng policy trung hòa spreadsheet formulas cho trường text untrusted; test trên Excel/LibreOffice.

### [Medium] — Thiếu giới hạn phạm vi và authorization theo dữ liệu

**Vấn đề:** Không thấy giới hạn date range hoặc kiểm tra quyền truy cập timesheet.  
**Tại sao xảy ra:** Endpoint tin rằng mọi caller được đọc toàn bộ.  
**Ảnh hưởng production:** Export dữ liệu ngoài phạm vi quyền và query quá lớn.  
**Cách sửa:** Áp dụng authorization policy và tenant/row-level scope ở query; giới hạn range, validate `from <= to`. Cần kiểm tra middleware hiện hữu trước khi kết luận endpoint đang public.

### [Medium] — Tải entity dư thừa

**Vấn đề:** `Include` cùng entity tracking và nhiều columns không cần thiết.  
**Tại sao xảy ra:** Query lấy full entity thay vì projection.  
**Ảnh hưởng production:** Tăng allocations, network và database cost.  
**Cách sửa:** `AsNoTracking`, select đúng fields; kiểm tra execution plan và index theo filter/order.

### [Medium] — Format không ổn định theo locale

**Vấn đề:** `DateOnly` và numeric values được nối trực tiếp.  
**Tại sao xảy ra:** Implicit formatting phụ thuộc culture.  
**Ảnh hưởng production:** CSV khác nhau giữa deployments; parser đọc sai.  
**Cách sửa:** Chốt ISO date và `InvariantCulture`.

## Phiên bản đề xuất

Giả định hệ thống đã có policy `Timesheet.Export` và scope theo tenant. Ví dụ dưới đây minh họa streaming với CSV encoding; `CsvSafe` là helper dành cho các trường text và phải được test với spreadsheet clients thực tế.

```csharp
[Authorize(Policy = "Timesheet.Export")]
[HttpGet("timesheets.csv")]
public async Task Export(
    [FromQuery] DateOnly from,
    [FromQuery] DateOnly to,
    CancellationToken cancellationToken)
{
    if (from > to || to.DayNumber - from.DayNumber > 31)
    {
        Response.StatusCode = StatusCodes.Status400BadRequest;
        return;
    }

    var tenantId = GetAuthorizedTenantId(User);
    var query = _db.Timesheets.AsNoTracking()
        .Where(x => x.TenantId == tenantId &&
                    x.WorkDate >= from && x.WorkDate <= to)
        .OrderBy(x => x.Id)
        .Select(x => new
        {
            Employee = x.Employee.DisplayName,
            x.WorkDate,
            x.Hours,
            x.Note
        });

    Response.ContentType = "text/csv; charset=utf-8";
    Response.Headers.ContentDisposition =
        "attachment; filename=\"timesheets.csv\"";

    await using var writer = new StreamWriter(
        Response.Body, new UTF8Encoding(false),
        bufferSize: 16 * 1024, leaveOpen: true);

    await writer.WriteLineAsync("Employee,Date,Hours,Note");

    var count = 0;
    await foreach (var row in query
        .AsAsyncEnumerable()
        .WithCancellation(cancellationToken))
    {
        cancellationToken.ThrowIfCancellationRequested();

        var line = string.Join(",",
            CsvSafe(row.Employee),
            row.WorkDate.ToString("yyyy-MM-dd",
                CultureInfo.InvariantCulture),
            row.Hours.ToString(CultureInfo.InvariantCulture),
            CsvSafe(row.Note));

        await writer.WriteLineAsync(
            line.AsMemory(), cancellationToken);
        count++;
    }

    await writer.FlushAsync(cancellationToken);
    _logger.LogInformation(
        "Timesheet export completed. Rows={RowCount}", count);
}

// Neutralize spreadsheet formula-like text, then quote CSV fields.
private static string CsvSafe(string? value)
{
    var text = value ?? "";
    if (text.Length > 0 &&
        (text[0] is '=' or '+' or '-' or '@' ||
         text[0] is '\t' or '\r' or '\n'))
        text = "'" + text;

    return "\"" + text.Replace("\"", "\"\"") + "\"";
}
```

**Giới hạn của ví dụ:** `GetAuthorizedTenantId` là abstraction ứng dụng, không phải ASP.NET Core API; phải triển khai theo identity/authorization thật. Formula mitigation cần xét thêm leading whitespace và cách spreadsheet import diễn giải dữ liệu. Với datasets rất lớn, cân nhắc async export job + Blob Storage sau khi đo memory, timeout, throughput và UX. Khi response đã bắt đầu, không thể chuyển sang HTTP 500 một cách đáng tin cậy; cần metrics cho stream bị ngắt.

## Giải thích thiết kế sau khi sửa

Query projection giảm payload và allocations. Streaming giúp tránh giữ toàn bộ báo cáo trong managed heap; vẫn phải đo buffering ở reverse proxy và downstream. Cancellation giảm wasted work, nhưng mức độ hủy query phụ thuộc database provider. Authorization scope được áp dụng ngay tại database query.

## Trade-offs

Streaming giữ connection lâu hơn và lỗi giữa stream có thể để lại file tải chưa hoàn chỉnh. Async export job giải quyết timeout tốt hơn nhưng tăng storage, lifecycle, access control và cleanup. Giới hạn date range bảo vệ hệ thống nhưng có thể không đáp ứng báo cáo nhiều năm; cần product decision.

## Cách kiểm thử

1. Integration test: tenant A không export được rows của tenant B.
2. CSV round-trip test: comma, quote, newline, Unicode, formula-like values.
3. Cancellation test: đóng connection giữa export, xác minh query/loop ngừng và tài nguyên được giải phóng.
4. Load test: 20 exports lớn, so sánh peak memory, GC, p95/p99 và DB utilization.
5. Failure-path test: database timeout giữa stream; xác minh telemetry và client behavior.

## Quan sát trong production

Theo dõi `export.started/completed/canceled/failed`, row count, bytes sent, duration, active exports, managed heap, GC pauses, database duration và connection pool. Dùng Application Insights traces/dependencies theo correlation ID; tuyệt đối không ghi nội dung CSV.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào chọn export background job và signed Blob download thay vì HTTP streaming?
2. Làm sao đảm bảo snapshot nhất quán nếu dữ liệu thay đổi trong lúc stream?
3. Thiết kế admission control thế nào để một tenant không chiếm hết tài nguyên?

```csharp
public sealed class ProductSearchSync
{
    private readonly CatalogDbContext _db;
    private readonly HttpClient _http;
    private readonly ILogger<ProductSearchSync> _logger;

    public ProductSearchSync(
        CatalogDbContext db,
        HttpClient http,
        ILogger<ProductSearchSync> logger)
    {
        _db = db;
        _http = http;
        _logger = logger;
    }

    public async Task UpdateAsync(
        Guid productId, CancellationToken ct)
    {
        var product = await _db.Products
            .SingleAsync(x => x.Id == productId, ct);

        var document = new
        {
            id = product.Id,
            title = product.Title,
            price = product.Price,
            updatedAt = DateTime.UtcNow
        };

        var payload = JsonSerializer.Serialize(document);
        var response = await _http.PutAsync(
            $"products/_doc/{product.Id}",
            new StringContent(payload, Encoding.UTF8, "application/json"),
            ct);

        _logger.LogInformation(
            "Indexed product {ProductId} with {Status}",
            productId, response.StatusCode);
    }

    public async Task RebuildAsync(CancellationToken ct)
    {
        await _http.DeleteAsync("products", ct);
        await _http.PutAsync("products",
            new StringContent(
                "{\"mappings\":{\"properties\":{\"title\":{\"type\":\"text\"}}}}",
                Encoding.UTF8, "application/json"), ct);

        foreach (var id in await _db.Products
            .Select(x => x.Id).ToListAsync(ct))
        {
            await UpdateAsync(id, ct);
        }
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Xóa live index trước khi rebuild

**Vấn đề:** `DeleteAsync("products")` xóa index đang phục vụ search.  
**Tại sao xảy ra:** Rebuild trực tiếp trên tên index production.  
**Ảnh hưởng production:** Search downtime, partial results và mapping mismatch giữa old/new application versions.  
**Cách sửa:** Tạo `products_vN` riêng, backfill, validate rồi atomically switch read alias; giữ index cũ đủ lâu để rollback.

### [High] — Không có durable change capture sau database commit

**Vấn đề:** Chỉ gọi `UpdateAsync` sau update mà không thấy persisted event/outbox.  
**Tại sao xảy ra:** Search update không cùng transaction với PostgreSQL.  
**Ảnh hưởng production:** Crash hoặc dependency outage làm mất update vĩnh viễn nếu không có retry/reconciliation.  
**Cách sửa:** Transactional outbox trong cùng database transaction với product update; dispatcher retry và reconciliation định kỳ.

### [High] — Không kiểm tra HTTP status

**Vấn đề:** `PutAsync` có thể trả response 4xx/5xx mà không throw.  
**Tại sao xảy ra:** Chỉ log status, không `EnsureSuccessStatusCode` hay classify response.  
**Ảnh hưởng production:** Silent indexing failure.  
**Cách sửa:** Phân loại 429/5xx transient, 400 mapping/validation permanent; bounded retries, DLQ/quarantine và alerts.

### [High] — Stale update ghi đè newer document

**Vấn đề:** Concurrent workers ghi cùng document mà không có version guard.  
**Tại sao xảy ra:** Arrival order được coi là business order; `DateTime.UtcNow` không phản ánh version từ source.  
**Ảnh hưởng production:** Search trả giá hoặc tên cũ.  
**Cách sửa:** Persist monotonically increasing source version, áp dụng external versioning hoặc guarded update với semantics được kiểm thử; xử lý delete/tombstone.

### [Medium] — Không có delete synchronization

**Vấn đề:** Chỉ có đường update; product deleted vẫn còn trong index.  
**Tại sao xảy ra:** Không model hóa lifecycle events.  
**Ảnh hưởng production:** Ghost products trong search.  
**Cách sửa:** Outbox events gồm upsert và delete; reconciliation kiểm tra chênh lệch.

### [Medium] — Rebuild N+1 và không bounded batch

**Vấn đề:** Load toàn bộ IDs rồi query từng product và PUT từng document.  
**Tại sao xảy ra:** Không có pagination, projection hoặc bulk indexing.  
**Ảnh hưởng production:** DB round trips, heap usage và indexing throughput kém.  
**Cách sửa:** Keyset batches, `AsNoTracking` projection, Elasticsearch Bulk API với per-item error inspection và bounded concurrency.

### [Medium] — Không validate index readiness trước switch

**Vấn đề:** Không thấy kiểm tra mappings, counts, failures hoặc representative queries.  
**Tại sao xảy ra:** Deployment không có acceptance gate.  
**Ảnh hưởng production:** Reader chuyển sang index thiếu dữ liệu.  
**Cách sửa:** Validate schema compatibility, sampling, counts, indexing failures, query smoke tests và lag.

### [Medium] — HTTP response disposal thiếu

**Vấn đề:** Response không được dispose.  
**Tại sao xảy ra:** Không dùng `using` cho `HttpResponseMessage`.  
**Ảnh hưởng production:** Resource pressure dưới tải cao.  
**Cách sửa:** Dispose response và quản lý `HttpClient` qua factory hoặc typed client.

## Phiên bản đề xuất

Thiết kế sau là pseudo-code C# cho transaction và dispatcher; các methods `SaveProductAndOutboxAsync`, `ClaimBatchAsync`, `MarkDeliveredAsync` và `IndexWithSourceVersionAsync` là application abstractions cần triển khai. Chúng không phải API có sẵn của EF Core/Elasticsearch.

```csharp
public async Task ChangeProductAsync(
    ProductChange command, CancellationToken ct)
{
    await using var tx = await _db.Database
        .BeginTransactionAsync(ct);

    var product = await LoadAndApplyAsync(command, ct);
    product.SearchVersion++;

    _db.SearchOutbox.Add(new SearchOutboxEvent
    {
        EventId = Guid.NewGuid(),
        ProductId = product.Id,
        SourceVersion = product.SearchVersion,
        Operation = product.IsDeleted ? "delete" : "upsert",
        CreatedAtUtc = DateTimeOffset.UtcNow
    });

    await _db.SaveChangesAsync(ct);
    await tx.CommitAsync(ct);
}

public async Task DispatchAsync(CancellationToken ct)
{
    var events = await ClaimBatchAsync(limit: 100, ct);
    foreach (var item in events)
    {
        try
        {
            await IndexWithSourceVersionAsync(
                item.ProductId, item.SourceVersion,
                item.Operation, ct);
            await MarkDeliveredAsync(item.EventId, ct);
        }
        catch (TransientSearchException ex)
        {
            await ScheduleRetryAsync(item.EventId, ex, ct);
        }
        catch (PermanentSearchException ex)
        {
            await QuarantineAsync(item.EventId, ex, ct);
        }
    }
}
```

**Điều kiện thiết kế quan trọng:** `ClaimBatchAsync` cần lease/locking an toàn khi nhiều worker; event processing là at-least-once nên indexing phải idempotent. Không đánh dấu delivered trước khi search xác nhận thành công. `IndexWithSourceVersionAsync` cần sử dụng source version một cách nhất quán cho upsert/delete, kiểm tra semantics của Elasticsearch versioning và delete tombstones; nếu đọc lại current product thì phải tránh gắn version cũ vào dữ liệu mới. Rebuild dùng immutable versioned physical index, replay changes phát sinh trong lúc backfill, kiểm tra lag rồi mới alias switch. Với writer alias, phải thiết kế dual-write/replay hoặc tạm điều phối writes để tránh mất events trong thời điểm chuyển.

## Giải thích thiết kế sau khi sửa

PostgreSQL tiếp tục là source of truth. Outbox đảm bảo thay đổi dữ liệu và ý định index được commit atomically trong cùng database. Dispatcher cho phép retry độc lập và quan sát lag. Version guard ngăn out-of-order updates. Versioned indices và alias switch tách rollout schema khỏi live readers.

## Trade-offs

Outbox thêm storage, cleanup, operational overhead và eventual consistency. Bulk indexing tăng throughput nhưng cần xử lý lỗi từng item. Alias switch là atomic ở Elasticsearch metadata, nhưng không tự bảo đảm data catch-up; cần cutover protocol. Nếu catalog nhỏ và tần suất cập nhật thấp, periodic full reconciliation có thể là giải pháp đơn giản hơn so với hệ thống event phức tạp, miễn business chấp nhận lag.

## Cách kiểm thử

1. Integration test: database commit thành công, Elasticsearch unavailable, outbox vẫn tồn tại và được replay sau recovery.
2. Concurrency test: version 12 đến trước version 11, index cuối vẫn là version 12.
3. Deployment test: rebuild physical index mới khi readers dùng alias cũ; không có search downtime.
4. Failure injection: Bulk API trả partial failures, chỉ các items thành công được acknowledge.
5. Reconciliation test: update/delete xảy ra giữa backfill và alias switch, index mới vẫn đạt trạng thái đúng sau catch-up.

## Quan sát trong production

Dashboard: outbox pending count, oldest event age, retry attempts, quarantined events, Elasticsearch 429/5xx, bulk item failure ratio, indexing throughput, source-to-index lag, index document counts và representative search correctness. Alert theo lag SLO và sustained failures; log structured `eventId`, `productId`, `sourceVersion`, `indexGeneration` nhưng không log secrets hoặc toàn bộ product payload.

## Câu hỏi phỏng vấn mở rộng

1. Nếu cần read-your-writes cho admin portal nhưng không cần cho public search, bạn thiết kế UX/API thế nào?
2. Khi nào chọn CDC thay transactional outbox, và trade-offs vận hành là gì?
3. Làm sao rollback alias sau schema migration mà không mất writes mới?

# Tổng kết hôm nay

## Kiến thức trọng tâm

HTTP streaming cần đi cùng cancellation, resource bounds, data authorization và định dạng output an toàn. Search indexing là một projection eventually consistent: cần durable change capture, version ordering, retries, reconciliation và rollout không gián đoạn.

## Mẫu tư duy cần nhớ

1. Đo memory, latency, database waits trước khi thêm infrastructure.
2. Mọi dependency bên ngoài đều có thể fail sau khi local transaction thành công.
3. Thiết kế retry đồng thời với idempotency và ordering.
4. Tách data-plane availability khỏi schema migration và rollback.
5. Test cancellation, partial failure và concurrency thay vì chỉ happy path.
