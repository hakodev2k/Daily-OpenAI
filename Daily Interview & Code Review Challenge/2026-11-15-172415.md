## Đoạn code cần review

```csharp
public sealed class SearchService(HttpClient http, CatalogDb db,
    ILogger<SearchService> logger)
{
    public async Task<List<ProductDto>> Search(
        Guid shopId, string term, int page, int size)
    {
        var query = new {
            from = (page - 1) * size,
            size,
            query = new {
                query_string = new {
                    query = term + "*",
                    fields = new[] { "name", "description" }
                }
            }
        };
        var response = await http.PostAsync("/products/_search",
            JsonContent.Create(query));
        var json = await response.Content.ReadAsStringAsync();
        logger.LogInformation("Search {Term} {Body}", term, json);
        using var doc = JsonDocument.Parse(json);
        var results = new List<ProductDto>();
        foreach (var hit in doc.RootElement.GetProperty("hits")
            .GetProperty("hits").EnumerateArray())
        {
            var id = hit.GetProperty("_source").GetProperty("id").GetGuid();
            var product = await db.Products
                .FirstOrDefaultAsync(x => x.Id == id);
            if (product != null)
                results.Add(new ProductDto(
                    product.Id, product.Name, product.Price));
        }
        return results;
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Thiếu shop isolation

**Vấn đề:** `shopId` không dùng. **Tại sao xảy ra:** Không enforce scope tại data access. **Ảnh hưởng production:** Cross-shop data exposure. **Cách sửa:** Enforce authorized shop ở backend; lọc shop tại cả Elasticsearch và PostgreSQL, lấy quyền từ trusted identity.

### [Critical] — Trả sản phẩm đã thu hồi

**Vấn đề:** Không kiểm tra trạng thái. **Tại sao xảy ra:** Tin index eventual-consistent. **Ảnh hưởng production:** Vi phạm yêu cầu bán hàng. **Cách sửa:** Batch recheck `Status == Active` ở PostgreSQL trước response.

### [High] — N+1 queries

**Vấn đề:** Một SQL query mỗi hit. **Tại sao xảy ra:** Query trong loop. **Ảnh hưởng production:** p99 và pool saturation. **Cách sửa:** Batch `Contains`, projection, `AsNoTracking`, preserve ranking bằng dictionary.

### [High] — Unbounded query và parser semantics

**Vấn đề:** `query_string` ghép input, page/size chưa validate. **Tại sao xảy ra:** Input chưa chuẩn hóa và giới hạn. **Ảnh hưởng production:** Query lỗi hoặc quá đắt. **Cách sửa:** `multi_match`, input limits, page cap, mapping đúng.

### [High] — Không xử lý dependency failure

**Vấn đề:** Không cancellation/status check. **Tại sao xảy ra:** Parse response bất kể HTTP status. **Ảnh hưởng production:** 500 khó chẩn đoán, request tồn đọng. **Cách sửa:** Timeout budget, cancellation, status handling, bounded retry cho lỗi phù hợp.

### [Medium] — Logging nhạy cảm

**Vấn đề:** Log raw query và toàn bộ response. **Tại sao xảy ra:** Dùng payload logging thay telemetry. **Ảnh hưởng production:** Privacy, chi phí. **Cách sửa:** Log duration, status, hit count, correlation ID, redaction.

### [Medium] — Pagination thiếu ổn định

**Vấn đề:** Lọc candidates sau khi phân trang làm page ngắn. **Tại sao xảy ra:** Index stale và database recheck. **Ảnh hưởng production:** UX không nhất quán. **Cách sửa:** Cursor contract, bounded over-fetch, `search_after`/PIT khi cần; xác nhận freshness SLA.

### [Medium] — Không có reconciliation index

**Vấn đề:** Không theo dõi event bị mất hoặc đến sai thứ tự. **Tại sao xảy ra:** Thiếu index-lag monitoring. **Ảnh hưởng production:** Stale data kéo dài. **Cách sửa:** Outbox, idempotent consumer, retry và reconciliation.

## Phiên bản đề xuất

Đoạn sau giả định API boundary đã xác thực quyền truy cập shop; Elasticsearch mapping `shopId` là keyword. DTO, enum và DbContext là các type của ứng dụng.

```csharp
public async Task<IReadOnlyList<ProductDto>> SearchAsync(
    Guid authorizedShopId, string term, int page, int size,
    CancellationToken ct)
{
    if (string.IsNullOrWhiteSpace(term) || term.Length > 120)
        throw new ArgumentException("Invalid term");
    if (page < 1 || size is < 1 or > 50)
        throw new ArgumentOutOfRangeException(nameof(size));
    int offset = checked((page - 1) * size);
    if (offset > 1000) throw new ArgumentOutOfRangeException(nameof(page));

    var query = new {
        from = offset, size,
        query = new {
            @bool = new {
                filter = new object[] {
                    new { term = new Dictionary<string, string> {
                        ["shopId"] = authorizedShopId.ToString() } }
                },
                must = new object[] {
                    new { multi_match = new {
                        query = term, fields = new[] { "name", "description" }
                    } }
                }
            }
        }
    };

    using var response = await http.PostAsync(
        "/products/_search", JsonContent.Create(query), ct);
    response.EnsureSuccessStatusCode();
    await using var stream = await response.Content.ReadAsStreamAsync(ct);
    using var doc = await JsonDocument.ParseAsync(
        stream, cancellationToken: ct);
    var ids = doc.RootElement.GetProperty("hits").GetProperty("hits")
        .EnumerateArray()
        .Select(x => x.GetProperty("_source").GetProperty("id").GetGuid())
        .Distinct().ToArray();

    var eligible = await db.Products.AsNoTracking()
        .Where(p => ids.Contains(p.Id) &&
            p.ShopId == authorizedShopId &&
            p.Status == ProductStatus.Active)
        .Select(p => new ProductDto(p.Id, p.Name, p.Price))
        .ToListAsync(ct);
    var byId = eligible.ToDictionary(p => p.Id);
    return ids.Where(byId.ContainsKey).Select(id => byId[id]).ToArray();
}
```

## Giải thích thiết kế sau khi sửa

Index phục vụ candidate retrieval; database enforce trạng thái nghiệp vụ. Batch SQL giảm round trips, giữ thứ tự relevance. Production cần timeout cấu hình trên typed HttpClient, response-size budget và mapping được kiểm chứng. Không được coi filter ở Elasticsearch là authorization boundary.

## Trade-offs

Database recheck tăng tải DB nhưng giữ correctness. Lọc sau search có thể làm page thiếu items; giải pháp cursor và over-fetch có chi phí, cần thỏa thuận API contract. Nếu database unavailable, không được tự động trả stale search result vì business cấm sản phẩm withdrawn.

## Cách kiểm thử

1. Security integration: shop A không thấy sản phẩm shop B.
2. Consistency: withdrawn item vẫn ở index nhưng không có trong API response.
3. Load: đo SQL queries/request và p95/p99 với 50 hits.
4. Failure injection: Elasticsearch 429, 503, timeout, invalid JSON.
5. Pagination: page thiếu item, offset lớn, empty term.

## Quan sát trong production

Application Insights spans cho Elasticsearch/PostgreSQL, SQL round trips, p95/p99, candidate rejection rate, 429/503, connection pool, indexing lag và failed events. Không log raw payload.

## Câu hỏi phỏng vấn mở rộng

1. Thiết kế outbox và reconciliation khi index event đến sai thứ tự?
2. Khi nào cần `search_after` thay vì offset?
3. Nếu database mất kết nối, đáp ứng yêu cầu không trả withdrawn bằng cách nào?

import { ref, watch, onMounted } from 'vue'

type Article = {
  id: string
  title: string
  body: string
  rowVersion: string
}
const props = defineProps<{ articleId: string; token: string }>()
const article = ref<Article | null>(null)
const saving = ref(false)
const error = ref('')

async function loadArticle() {
  const response = await fetch('/api/articles/' + props.articleId, {
    headers: { Authorization: 'Bearer ' + props.token }
  })
  article.value = await response.json()
}

async function saveArticle() {
  if (!article.value) return
  saving.value = true
  const response = await fetch('/api/articles/' + props.articleId, {
    method: 'PUT',
    headers: {
      Authorization: 'Bearer ' + props.token,
      'Content-Type': 'application/json'
    },
    body: JSON.stringify(article.value)
  })
  if (!response.ok) error.value = 'Save failed'
  saving.value = false
}

onMounted(loadArticle)
watch(() => props.articleId, loadArticle)
watch(article, saveArticle, { deep: true })
</script>

<template>
  <section v-if="article">
    <input v-model="article.title" />
    <textarea v-model="article.body" />
    <span v-if="saving">Saving...</span>
    <p v-if="error">{{ error }}</p>
  </section>
</template>

## Kết quả code review tham khảo

### [Critical] — Lost updates

**Vấn đề:** PUT đồng thời không có precondition. **Tại sao xảy ra:** Network reorder, backend có thể last-write-wins. **Ảnh hưởng production:** Mất nội dung. **Cách sửa:** `If-Match`/ETag hoặc rowVersion được enforce atomically tại SQL; trả 412/409 và hiển thị conflict.

### [High] — Stale GET thay state

**Vấn đề:** Không cancel/ignore response cũ. **Tại sao xảy ra:** Props đổi trước request hoàn thành. **Ảnh hưởng production:** Hiển thị bài A khi đang ở B. **Cách sửa:** AbortController và generation guard.

### [High] — Hydration kích hoạt save

**Vấn đề:** Deep watch chạy khi gán article mới. **Tại sao xảy ra:** Không phân biệt user edits và load. **Ảnh hưởng production:** PUT không cần thiết, conflict. **Cách sửa:** Chỉ gọi save từ edit event/dirty state.

### [High] — Thiếu per-resource authorization evidence

**Vấn đề:** Frontend không thể bảo đảm quyền xem/sửa draft. **Tại sao xảy ra:** Nhầm authentication với authorization. **Ảnh hưởng production:** IDOR nếu server thiếu kiểm tra. **Cách sửa:** Backend enforce author/reviewer access cho cả GET và PUT; đây là rủi ro cần xác minh, không thể kết luận từ snippet.

### [Medium] — Không debounce

**Vấn đề:** Một ký tự tạo một request. **Tại sao xảy ra:** Deep watcher. **Ảnh hưởng production:** Tăng tải DB và race. **Cách sửa:** Debounce và serialize writes.

### [Medium] — Không xử lý lỗi fetch

**Vấn đề:** Network rejection bỏ qua cleanup. **Tại sao xảy ra:** Thiếu try/finally. **Ảnh hưởng production:** Saving indicator sai. **Cách sửa:** State machine và error handling.

### [Medium] — Không validate GET response

**Vấn đề:** Parse 401/403/500 như article. **Tại sao xảy ra:** Không check `response.ok`. **Ảnh hưởng production:** UI sai/crash. **Cách sửa:** Handle status, validate shape.

### [Medium] — Navigation làm mất dirty edits

**Vấn đề:** Không có navigation guard. **Tại sao xảy ra:** Pending autosave chưa được quản lý. **Ảnh hưởng production:** Mất nội dung chưa lưu. **Cách sửa:** Guard và recovery policy.

## Phiên bản đề xuất

Ví dụ sau dùng một document-scoped editor. Parent **phải remount editor với `:key="articleId"`**, đồng thời chặn navigation nếu còn dirty/pending save. Backend **phải** hỗ trợ ETag và conditional PUT; code không giả định API hiện tại đã hỗ trợ.

```ts
import { ref, onMounted, onBeforeUnmount } from 'vue'

type Article = { id: string; title: string; body: string }
const props = defineProps<{ articleId: string; token: string }>()
const draft = ref<Article | null>(null)
const status = ref('loading')
let etag = ''
let dirty = false
let saving = false
let timer: ReturnType<typeof setTimeout> | undefined
const abort = new AbortController()

async function load() {
  try {
    const r = await fetch('/api/articles/' + encodeURIComponent(props.articleId), {
      headers: { Authorization: 'Bearer ' + props.token },
      signal: abort.signal
    })
    if (!r.ok) throw new Error('GET ' + r.status)
    const tag = r.headers.get('ETag')
    if (!tag) throw new Error('Missing ETag')
    etag = tag
    draft.value = await r.json() as Article
    status.value = 'ready'
  } catch (e) {
    if (!abort.signal.aborted) status.value = 'error'
  }
}

function edited() {
  dirty = true
  clearTimeout(timer)
  timer = setTimeout(() => void save(), 700)
}

async function save() {
  if (saving || !dirty || !draft.value) return
  saving = true
  dirty = false
  status.value = 'saving'
  const snapshot = { ...draft.value }
  try {
    const r = await fetch('/api/articles/' + encodeURIComponent(snapshot.id), {
      method: 'PUT',
      headers: {
        Authorization: 'Bearer ' + props.token,
        'Content-Type': 'application/json',
        'If-Match': etag
      },
      body: JSON.stringify(snapshot)
    })
    if (r.status === 409 || r.status === 412) {
      dirty = true
      status.value = 'conflict'
      return
    }
    if (!r.ok) throw new Error('PUT ' + r.status)
    const newTag = r.headers.get('ETag')
    if (!newTag) throw new Error('Missing ETag')
    etag = newTag
    status.value = 'saved'
  } catch {
    dirty = true
    status.value = 'error'
  } finally {
    saving = false
    if (dirty && status.value === 'saved') edited()
  }
}
onMounted(() => void load())
onBeforeUnmount(() => { clearTimeout(timer); abort.abort() })
```

Template liên kết `v-model="draft.title"`/`v-model="draft.body"` và `@input="edited"`; render trạng thái `status`. Bản minh họa vẫn cần cải thiện: khi user gõ trong lúc PUT đang chạy, `status='saved'` sau response cho phép schedule tiếp; khi PUT lỗi phải có nút Retry, không tự retry vô hạn; khi conflict phải dừng và cho người dùng merge/reload. Remount và navigation guard cần thực thi ở parent; unmount không được coi là save thành công. Server phải kiểm tra ETag atomically trong transaction.

## Giải thích thiết kế sau khi sửa

Debounce giảm tải, single-flight giảm reordering trong một editor; ETag bảo vệ giữa nhiều editor và nhiều instance. Abort stale load tránh sai UI. Không thể dựa vào client để enforce authorization.

## Trade-offs

Debounce có cửa sổ chưa lưu; navigation guard tăng friction. ETag cần backend contract và conflict UX. Nếu nhiều người cộng tác real-time, CRDT/OT là phương án cân nhắc, không bắt buộc cho CMS bình thường.

## Cách kiểm thử

1. Playwright: gõ nhanh, đảo thứ tự response và kiểm tra nội dung cuối.
2. E2E: chuyển A→B khi GET A chậm; không hiển thị A.
3. Integration: hai editor cùng ETag, PUT thứ hai nhận 412.
4. Security: GET/PUT draft trái quyền bị từ chối.
5. Failure injection: timeout, 500, navigation với unsaved edits.

## Quan sát trong production

Client metrics: autosave latency, conflict rate, dirty duration, aborted GET, save errors. Backend Application Insights: 409/412, 403, PUT p95, SQL concurrency conflicts, correlation IDs. Không log token hoặc nội dung bài.
