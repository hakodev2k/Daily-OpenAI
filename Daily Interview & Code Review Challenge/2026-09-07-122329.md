# Code Review Challenge 1 — Legacy export chạy được trên Windows nhưng lỗi và rò rỉ dữ liệu khi chuyển sang App Service Linux

**Chủ đề:** C#/.NET, ASP.NET Core, .NET modernization, file handling, Linux hosting, path traversal, concurrency, multi-instance hosting, reliability  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35–45 phút  
**Số vấn đề cần tìm:** khoảng 10–13 vấn đề

## Bối cảnh

Một hệ thống nội bộ cũ viết bằng ASP.NET MVC trên .NET Framework 4.5 đang được migrate dần sang .NET 8 và Azure App Service on Linux.

Một endpoint export báo cáo được port gần như nguyên trạng. Trên hệ thống cũ:

- ứng dụng chạy một IIS instance trên Windows Server;
- export tạo file CSV tạm trên local disk;
- file được tải xuống ngay sau khi tạo;
- traffic thấp nên ít khi có hai export đồng thời;
- tên file report lấy từ input người dùng;
- một scheduled cleanup job xóa file cũ mỗi đêm.

Sau khi chuyển sang App Service Linux và scale-out 4 instances, production ghi nhận:

- một số request trả 500 với lỗi file/path;
- đôi khi user A tải được nội dung export của user B;
- khi scale-out hoặc restart, file tạm biến mất bất ngờ;
- disk usage tăng dần trong ngày;
- request export lớn làm memory và latency tăng mạnh;
- client hủy request nhưng server vẫn tiếp tục tạo file;
- support phát hiện input report name có thể chứa chuỗi như `../../`;
- log chỉ ghi tên file, không có user, export ID, duration hoặc instance.

Developer hiện tại dùng đoạn code sau.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/reports")]
[Authorize]
public sealed class ReportsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<ReportsController> _logger;

    public ReportsController(
        AppDbContext db,
        ILogger<ReportsController> logger)
    {
        _db = db;
        _logger = logger;
    }

    [HttpGet("export")]
    public async Task<IActionResult> Export(
        [FromQuery] string reportName,
        [FromQuery] DateTime from,
        [FromQuery] DateTime to)
    {
        var rows = await _db.Transactions
            .Where(x => x.CreatedUtc >= from && x.CreatedUtc <= to)
            .OrderBy(x => x.CreatedUtc)
            .ToListAsync();

        var csv = new StringBuilder();
        csv.AppendLine("Id,CustomerName,Amount,CreatedUtc");

        foreach (var row in rows)
        {
            csv.AppendLine(
                $"{row.Id},{row.CustomerName},{row.Amount},{row.CreatedUtc:o}");
        }

        var exportFolder = Path.Combine(
            Directory.GetCurrentDirectory(),
            "wwwroot\\exports");

        Directory.CreateDirectory(exportFolder);

        var fileName = reportName + ".csv";
        var fullPath = Path.Combine(exportFolder, fileName);

        await System.IO.File.WriteAllTextAsync(
            fullPath,
            csv.ToString());

        _logger.LogInformation(
            "Export created at {Path}",
            fullPath);

        var bytes = await System.IO.File.ReadAllBytesAsync(fullPath);

        return File(
            bytes,
            "text/csv",
            fileName);
    }
}
```

## Kết quả code review tham khảo

### Critical — Path traversal qua `reportName`

**Vấn đề:**  
`reportName` do user kiểm soát được nối trực tiếp thành filename.

**Tại sao xảy ra:**  
`Path.Combine` không phải security boundary. Nó chỉ kết hợp path. Input chứa traversal segment hoặc path separator có thể làm path cuối cùng thoát khỏi thư mục dự kiến, tùy input và platform.

**Ảnh hưởng production:**  
Attacker đã authenticated có thể ghi đè file ngoài thư mục export mà process có quyền ghi, hoặc gây lỗi/DoS bằng path bất thường.

**Cách sửa:**  
Không dùng user input làm physical storage path. Sinh export ID nội bộ, ví dụ `Guid`, làm object identity. Nếu cần giữ report name thì lưu như metadata/display name. Có thể chuẩn hóa display filename bằng `Path.GetFileName` nhưng vẫn không nên dùng nó làm storage identity.

---

### High — Broken data isolation: query không filter theo user/tenant

**Vấn đề:**  
Query lấy toàn bộ `Transactions` trong date range mà không áp dụng tenant/user scope.

**Tại sao xảy ra:**  
`[Authorize]` chỉ xác nhận caller đã authenticated, không giới hạn dữ liệu họ được phép export.

**Ảnh hưởng production:**  
User hợp lệ có thể export dữ liệu của user/tenant khác nếu authorization boundary nằm ở business resource.

**Cách sửa:**  
Áp dụng resource/tenant authorization trước khi query và luôn đưa tenant key vào predicate. Nếu hệ thống có row-level policy, vẫn cần kiểm tra application assumptions và test isolation.

---

### High — Filename collision gây ghi đè giữa các request đồng thời

**Vấn đề:**  
Hai request có cùng `reportName` ghi vào cùng physical path.

**Tại sao xảy ra:**  
Filename đóng vai trò vừa là display name vừa là storage identity.

**Ảnh hưởng production:**  
Hai request đồng thời có thể overwrite file của nhau. Request A có thể ghi xong, request B overwrite, sau đó A đọc lại file và trả nội dung của B. Điều này giải thích hiện tượng cross-user data leak.

**Cách sửa:**  
Dùng unique internal export ID hoặc bỏ local file hoàn toàn và stream response. Nếu cần lưu artifact, dùng unique blob/object key gắn với tenant/user/export ID.

---

### High — Whole-result buffering gây memory pressure

**Vấn đề:**  
Code đồng thời giữ:

1. toàn bộ EF entities trong `List`;
2. toàn bộ CSV trong `StringBuilder`;
3. toàn bộ CSV lần nữa dưới dạng string khi gọi `ToString()`;
4. toàn bộ file lần nữa dưới dạng `byte[]` khi `ReadAllBytesAsync()`.

**Tại sao xảy ra:**  
Pipeline được thiết kế batch-in-memory thay vì streaming.

**Ảnh hưởng production:**  
Export lớn hoặc nhiều export đồng thời có thể tăng LOH/Gen 2 pressure, GC pause, working set và cuối cùng làm instance recycle/OOM.

**Cách sửa:**  
Projection chỉ lấy cột cần thiết, dùng `AsNoTracking()`, đọc theo streaming pattern phù hợp và ghi trực tiếp vào response stream hoặc Blob stream. Không materialize toàn bộ dataset nếu không cần.

---

### High — Local filesystem bị giả định là durable/shared storage

**Vấn đề:**  
Implementation dùng thư mục bên trong application working directory như một artifact store.

**Tại sao xảy ra:**  
Thiết kế cũ dựa trên single-server IIS được giữ nguyên khi chuyển sang horizontally scaled cloud hosting.

**Ảnh hưởng production:**  
Artifact phụ thuộc instance nào xử lý request, có thể biến mất khi restart/redeploy, và cleanup behavior không đồng nhất. Đây không phải nơi phù hợp để làm durable/shared source of truth cho export workflow nhiều instance.

**Cách sửa:**  
Nếu file chỉ tồn tại trong duration của một request, ưu tiên stream và không lưu. Nếu export cần download lại sau đó hoặc chạy background, dùng shared durable object storage như Azure Blob Storage với unique key và lifecycle policy.

---

### High — Windows-specific separator được hard-code

**Vấn đề:**  
`"wwwroot\\exports"` chứa backslash như path separator kiểu Windows.

**Tại sao xảy ra:**  
Code được port từ Windows mà không dùng path segments theo platform abstraction.

**Ảnh hưởng production:**  
Trên Linux, backslash không phải directory separator như trên Windows; path có thể không trỏ đến cấu trúc thư mục developer dự định.

**Cách sửa:**  
Dùng `Path.Combine(basePath, "wwwroot", "exports")` nếu thực sự cần local path. Tốt hơn nữa, tránh đặt export tạm trong `wwwroot`.

---

### Medium — Export artifact được đặt dưới `wwwroot`

**Vấn đề:**  
File nhạy cảm được ghi vào web root.

**Tại sao xảy ra:**  
Thiết kế tái sử dụng thói quen lưu file public/static.

**Ảnh hưởng production:**  
Tùy static file middleware/routing/configuration, file có nguy cơ bị truy cập ngoài intended authorization path hoặc vô tình được publish/cache.

**Cách sửa:**  
Không lưu sensitive export dưới web root. Nếu phải dùng temp disk, dùng thư mục không được web serve và kiểm soát ACL/lifecycle. Với durable download, dùng private Blob Storage và authorization ở download flow.

---

### Medium — CSV injection và escaping không được xử lý

**Vấn đề:**  
`CustomerName` và các field khác được nội suy trực tiếp vào CSV.

**Tại sao xảy ra:**  
CSV có escaping rules riêng; giá trị có comma, quote hoặc newline sẽ phá cấu trúc. Ngoài ra spreadsheet software có thể diễn giải một số cell bắt đầu bằng `=`, `+`, `-`, `@` như formula.

**Ảnh hưởng production:**  
File sai format, dữ liệu bị lệch cột hoặc có rủi ro formula injection khi người dùng mở file bằng spreadsheet client.

**Cách sửa:**  
Dùng CSV writer/library có escaping đúng. Nếu export được mở bằng spreadsheet, áp dụng policy chống formula injection phù hợp với dữ liệu và threat model.

---

### Medium — Không propagate `CancellationToken`

**Vấn đề:**  
Query, file write và file read không nhận request cancellation.

**Tại sao xảy ra:**  
Action không nhận `CancellationToken`.

**Ảnh hưởng production:**  
Client disconnect nhưng server vẫn tiếp tục query, serialize và ghi file, làm lãng phí DB, CPU, memory và disk I/O.

**Cách sửa:**  
Nhận `CancellationToken cancellationToken` và truyền xuyên suốt các operation hỗ trợ cancellation. Với background export, cancellation semantics cần tách khỏi lifetime của HTTP request.

---

### Medium — Query không tối ưu cho read-only export

**Vấn đề:**  
EF Core materialize entity đầy đủ và bật tracking mặc định.

**Tại sao xảy ra:**  
Query chưa projection và chưa `AsNoTracking()`.

**Ảnh hưởng production:**  
Memory và CPU tăng không cần thiết, đặc biệt khi export nhiều row.

**Cách sửa:**  
Projection chỉ các field cần export, `AsNoTracking()`, kiểm tra index cho filter/sort `(TenantId, CreatedUtc, ...)`, và đánh giá streaming/paging tùy volume.

---

### Medium — Không có lifecycle/cleanup đáng tin cậy

**Vấn đề:**  
File được ghi nhưng không được xóa sau response.

**Tại sao xảy ra:**  
Code dựa vào cleanup job lịch sử, nhưng không rõ job có còn phù hợp trong môi trường scale-out hay không.

**Ảnh hưởng production:**  
Disk usage tăng dần, có thể gây failure khi local storage đầy.

**Cách sửa:**  
Nếu stream trực tiếp thì không có artifact cần cleanup. Nếu dùng Blob, cấu hình lifecycle/retention. Nếu dùng temp file, xóa deterministically trong `finally` và vẫn có reconciliation cleanup cho crash cases.

## Phiên bản đề xuất

Ví dụ dưới đây chọn phương án **stream trực tiếp HTTP response** cho export đồng bộ kích thước vừa phải. Nếu export có thể rất lớn hoặc cần download lại sau này, nên chuyển sang background export + Azure Blob Storage.

```csharp
[ApiController]
[Route("api/reports")]
[Authorize]
public sealed class ReportsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ICurrentTenant _currentTenant;
    private readonly ILogger<ReportsController> _logger;

    public ReportsController(
        AppDbContext db,
        ICurrentTenant currentTenant,
        ILogger<ReportsController> logger)
    {
        _db = db;
        _currentTenant = currentTenant;
        _logger = logger;
    }

    [HttpGet("export")]
    public async Task Export(
        [FromQuery] DateTime from,
        [FromQuery] DateTime to,
        CancellationToken cancellationToken)
    {
        if (from > to)
        {
            Response.StatusCode = StatusCodes.Status400BadRequest;
            return;
        }

        var tenantId = _currentTenant.Id;
        var exportId = Guid.NewGuid();

        Response.ContentType = "text/csv; charset=utf-8";
        Response.Headers.ContentDisposition =
            $"attachment; filename=transactions-{from:yyyyMMdd}-{to:yyyyMMdd}.csv";

        await using var writer = new StreamWriter(
            Response.Body,
            new UTF8Encoding(encoderShouldEmitUTF8Identifier: false),
            bufferSize: 64 * 1024,
            leaveOpen: true);

        await writer.WriteLineAsync(
            "Id,CustomerName,Amount,CreatedUtc");

        var query = _db.Transactions
            .AsNoTracking()
            .Where(x =>
                x.TenantId == tenantId &&
                x.CreatedUtc >= from &&
                x.CreatedUtc <= to)
            .OrderBy(x => x.CreatedUtc)
            .Select(x => new
            {
                x.Id,
                x.CustomerName,
                x.Amount,
                x.CreatedUtc
            })
            .AsAsyncEnumerable();

        var count = 0;
        var started = Stopwatch.GetTimestamp();

        await foreach (var row in query
            .WithCancellation(cancellationToken))
        {
            var name = EscapeCsv(row.CustomerName);

            await writer.WriteLineAsync(
                $"{row.Id},{name},{row.Amount.ToString(CultureInfo.InvariantCulture)},{row.CreatedUtc:o}");

            count++;
        }

        await writer.FlushAsync(cancellationToken);

        var elapsed = Stopwatch.GetElapsedTime(started);

        _logger.LogInformation(
            "Export {ExportId} completed for tenant {TenantId}. Rows={RowCount} DurationMs={DurationMs}",
            exportId,
            tenantId,
            count,
            elapsed.TotalMilliseconds);
    }

    private static string EscapeCsv(string? value)
    {
        value ??= string.Empty;

        if (value.StartsWith('=') ||
            value.StartsWith('+') ||
            value.StartsWith('-') ||
            value.StartsWith('@'))
        {
            value = "'" + value;
        }

        if (value.Contains(',') ||
            value.Contains('"') ||
            value.Contains('\n') ||
            value.Contains('\r'))
        {
            value = "\"" + value.Replace("\"", "\"\"") + "\"";
        }

        return value;
    }
}
```

Với export rất lớn hoặc kéo dài hàng phút, có thể dùng flow:

1. API tạo `ExportJob` với `ExportId` và tenant/user ownership;
2. background worker xử lý theo idempotent job semantics;
3. output được stream vào private Azure Blob Storage;
4. record chuyển trạng thái `Pending → Ready / Failed`;
5. client polling hoặc nhận notification;
6. download endpoint kiểm tra authorization rồi cấp short-lived SAS hoặc proxy download;
7. Blob lifecycle policy xóa artifact hết hạn.

## Giải thích thiết kế sau khi sửa

### 1. Loại bỏ physical filename khỏi security boundary

Internal export identity được sinh bởi server. Display filename không còn quyết định nơi dữ liệu được lưu.

### 2. Stream thay vì buffer toàn bộ export

Streaming giảm peak application memory và tránh việc giữ nhiều bản copy của cùng dữ liệu trong RAM.

### 3. Authorization gắn với dữ liệu

Tenant/user scope được đưa vào query, không chỉ dựa vào `[Authorize]`.

### 4. Không phụ thuộc local disk cho artifact dùng chung

Nếu artifact cần sống lâu hơn request, shared durable storage phù hợp hơn local instance storage.

### 5. Modernization là thay đổi operational model, không chỉ target framework

Migration từ single IIS server sang Linux App Service scale-out thay đổi filesystem, instance lifecycle, deployment và concurrency assumptions. Port code mà giữ nguyên assumptions cũ có thể vẫn compile nhưng không còn đúng về mặt hệ thống.

## Trade-offs

- HTTP streaming giữ request mở lâu; nếu export rất lớn, background job + Blob tốt hơn cho reliability và retry.
- Streaming query cần kiểm tra database connection lifetime và concurrency; nhiều export dài đồng thời có thể giữ connection lâu.
- Background export tăng architecture complexity nhưng cho phép retry, status tracking và download lại.
- Azure Blob Storage thêm dependency/cost nhưng phù hợp hơn cho durable shared artifacts.
- CSV formula mitigation phụ thuộc consumer/threat model; không nên tự tạo escaping ad-hoc nếu có library chuẩn đã được kiểm chứng.

## Cách kiểm thử

1. **Security test:** thử `reportName`/filename chứa traversal, separator và ký tự đặc biệt; storage path không được phụ thuộc input này.
2. **Tenant isolation integration test:** user tenant A không bao giờ export được transaction của tenant B.
3. **Load test:** chạy nhiều export lớn đồng thời; đo memory, GC, DB connection count, p95/p99 và throughput.
4. **Cancellation test:** hủy client giữa export; query/serialization phải dừng hợp lý và không để temp artifact rác.
5. **Cross-platform test:** chạy integration test trong Linux container/App Service-like environment để bắt Windows path assumptions.

## Quan sát trong production

Theo dõi:

- export request count, duration, p95/p99;
- exported row count và bytes theo bucket;
- process memory, GC heap và allocation rate;
- DB query duration, rows read, connection pool usage;
- cancellation count;
- 4xx/5xx;
- export failure stage;
- tenant/user/export ID correlation;
- instance/container identifier;
- local disk usage nếu vẫn còn temp-file flow;
- Blob dependency telemetry nếu dùng Azure Blob Storage;
- alert khi duration, memory, disk hoặc failure rate vượt baseline.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào synchronous HTTP streaming vẫn là lựa chọn tốt hơn background export?
2. Nếu report cần hàng chục triệu rows, bạn sẽ giới hạn concurrency và database impact như thế nào?
3. Nếu download artifact được cấp bằng SAS, bạn sẽ thiết kế expiry, authorization và revocation strategy ra sao?

# Code Review Challenge 2 — Vue autocomplete hiển thị kết quả cũ, gửi request trùng và mở đường cho XSS

## Bối cảnh

Một e-commerce storefront dùng Vue 3 + TypeScript có ô search autocomplete.

Yêu cầu:

- bắt đầu search sau khi user gõ ít nhất 2 ký tự;

Component hiện tại:

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue'

interface Suggestion {
  id: string
  highlightedName: string
  url: string
}

const query = ref('')
const suggestions = ref<Suggestion[]>([])
const loading = ref(false)
const error = ref<string | null>(null)

let timer: number | undefined

async function search(value: string) {
  loading.value = true
  error.value = null

  try {
    const response = await fetch(
      `/api/search/suggest?q=${value}`,
      {
        headers: {
          Authorization: `Bearer ${localStorage.getItem('access_token')}`
        }
      }
    )

    const data = await response.json()
    suggestions.value = data.items
  } catch (e) {
    error.value = 'Search failed'
  } finally {
    loading.value = false
  }
}

watch(query, value => {
  if (value.length < 2) {
    suggestions.value = []
    return
  }

  timer = window.setTimeout(() => {
    search(value)
  }, 250)
})

onMounted(() => {
  const input = document.querySelector('#global-search')
  input?.addEventListener('keyup', () => {
    search(query.value)
  })
})
</script>

<template>
  <div class="search-box">
    <input id="global-search" v-model="query" />

    <div v-if="loading">Loading...</div>
    <div v-if="error">{{ error }}</div>

    <ul v-if="suggestions.length">
      <li v-for="item in suggestions" :key="item.id">
        <a :href="item.url" v-html="item.highlightedName"></a>
      </li>
    </ul>
  </div>
</template>
```

Hãy review component như một full-stack Senior Developer.

Bạn cần:

1. xác định async correctness problems;
2. giải thích tại sao response cũ có thể overwrite response mới;
3. xác định nguyên nhân duplicate requests;
4. đánh giá debounce implementation;
5. đánh giá lifecycle cleanup;
6. phân tích XSS risk của `v-html`;

9. giải thích behavior khi API timeout/fail;
10. giải thích test và telemetry cần có.

## Câu hỏi gợi mở

1. `setTimeout` cũ có bị `clearTimeout` trước khi tạo timer mới không?
2. Nếu request cho `iphone` mất 1200 ms còn `ipad` mất 100 ms, response nào update state cuối cùng?
3. `watch(query)` và listener `keyup` có đang kích hoạt cùng một business action không?

## Kết quả code review tham khảo

### Critical — `v-html` render untrusted HTML

**Vấn đề:**  
`item.highlightedName` được render trực tiếp bằng `v-html`.

**Tại sao xảy ra:**  
`v-html` yêu cầu developer tự đảm bảo nội dung là trusted/sanitized. Nếu backend hoặc upstream content chứa HTML/JS payload không được sanitize đúng, Vue sẽ không escape như text interpolation.

**Ảnh hưởng production:**  
Có thể dẫn đến stored/reflected XSS tùy dữ liệu và backend behavior. Với e-commerce/CMS-like content, product name có thể đi qua nhiều hệ thống trước khi tới browser.

**Cách sửa:**  
Tốt nhất backend trả structured highlight ranges/tokens và frontend render bằng text nodes + `<mark>` do chính component tạo. Nếu bắt buộc nhận HTML, phải sanitize bằng một giải pháp được review kỹ và xác định trust boundary rõ ràng.

---

### High — Race condition: stale response overwrite latest query

**Vấn đề:**  
Mọi response thành công đều gán `suggestions.value = data.items`.

**Tại sao xảy ra:**  
Network completion order không nhất thiết giống request start order.

**Ảnh hưởng production:**  
Query cũ trả chậm có thể overwrite kết quả của query mới, khiến UI sai với text hiện tại.

**Cách sửa:**  
Abort request trước bằng `AbortController` và/hoặc dùng monotonically increasing request ID để chỉ latest request được commit state.

---

### High — Debounce không thực sự debounce

**Vấn đề:**  
Timer cũ không bị `clearTimeout`.

**Tại sao xảy ra:**  
Mỗi thay đổi query tạo một timer mới.

**Ảnh hưởng production:**  
Gõ 6 ký tự có thể tạo nhiều request sau 250 ms thay vì chỉ request cho giá trị cuối cùng. Điều này tăng API load và làm race condition dễ xuất hiện hơn.

**Cách sửa:**  
`clearTimeout(timer)` trước khi tạo timer mới hoặc dùng composable debounce đã được kiểm chứng.

---

### High — Duplicate producer: `watch` và raw `keyup` cùng gọi search

**Vấn đề:**  
`watch(query)` đã phản ứng với input, nhưng `keyup` listener lại gọi `search()` trực tiếp.

**Tại sao xảy ra:**  
Component trộn Vue reactivity với imperative DOM event listener cho cùng behavior.

**Ảnh hưởng production:**  
Một lần gõ có thể tạo request trực tiếp và thêm request debounce sau đó. Telemetry/network cho thấy duplicate calls.

**Cách sửa:**  
Chọn một state flow duy nhất, thông thường dựa trên `v-model` + `watch`/computed/composable. Không thêm raw DOM listener cho cùng event nếu không cần.

---

### High — Không cancel in-flight request khi query đổi hoặc component unmount

**Vấn đề:**  
`fetch` không nhận `AbortSignal`.

**Tại sao xảy ra:**  
Không có `AbortController` lifecycle.

**Ảnh hưởng production:**  
Request không còn relevant vẫn consume network/backend capacity và có thể update state sau khi context UI đã thay đổi.

**Cách sửa:**  
Mỗi search tạo controller mới, abort controller cũ khi query đổi, và abort khi component unmount.

---

### Medium — `loading` có thể bị response cũ set sai

**Vấn đề:**  
Mọi request đều set `loading=true` rồi `finally` set `false`.

**Tại sao xảy ra:**  
Nhiều request overlap dùng cùng boolean state.

**Ảnh hưởng production:**  
Request cũ hoàn tất trong khi request mới vẫn đang chạy có thể set `loading=false` quá sớm.

**Cách sửa:**  
Chỉ latest request được phép cập nhật `loading/error/suggestions`, hoặc dùng request counter/state machine.

---

### Medium — HTTP error không được kiểm tra trước khi parse JSON

**Vấn đề:**  
Code không kiểm tra `response.ok`.

**Tại sao xảy ra:**  
`fetch` chỉ reject cho network-level failure; HTTP 4xx/5xx vẫn resolve thành `Response`.

**Ảnh hưởng production:**  
Code có thể parse error body như success schema hoặc hiển thị state không chính xác.

**Cách sửa:**  
Kiểm tra `response.ok`, map status theo policy và phân biệt abort/network/server/auth errors.

---

### Medium — URL query không được encode

**Vấn đề:**  
`value` được nối trực tiếp vào URL.

**Tại sao xảy ra:**  
Không dùng `URLSearchParams` hoặc `encodeURIComponent`.

**Ảnh hưởng production:**  
Các ký tự như `&`, `?`, `#`, unicode hoặc space có thể làm request sai semantics.

**Cách sửa:**  
Dùng `URL`/`URLSearchParams` hoặc encode đúng query parameter.

---

### Medium — Timer và event listener không được cleanup

**Vấn đề:**  
Không có `onUnmounted` cleanup.

**Tại sao xảy ra:**  
Imperative resources được tạo ngoài Vue-managed lifecycle.

**Ảnh hưởng production:**  
Trong SPA navigation, timer/listener cũ có thể sống quá lâu, tạo unexpected behavior hoặc duplicate action khi component mount lại.

**Cách sửa:**  
Tránh raw event listener nếu không cần. Cleanup timer/controller trong `onUnmounted`.

---

### Medium — Token handling cần được đánh giá theo auth architecture

**Vấn đề:**  
Code đọc bearer token trực tiếp từ `localStorage` cho mỗi request.

**Tại sao xảy ra:**  
Frontend tự quản lý token storage và header injection.

**Ảnh hưởng production:**  
Nếu ứng dụng có XSS, token trong JavaScript-readable storage có thể bị đánh cắp. Ngoài ra auth logic bị phân tán giữa component.

**Cách sửa:**  
Không kết luận rằng một storage model luôn đúng cho mọi app. Nên tập trung auth handling trong API client layer và đánh giá architecture: cookie `HttpOnly`/same-site CSRF controls, BFF, hoặc bearer-token SPA flow theo identity provider và threat model hiện tại. Component search không nên tự chịu trách nhiệm đọc token storage.

## Phiên bản đề xuất

Ví dụ dưới đây loại bỏ raw `keyup`, debounce đúng, abort request cũ và dùng latest-request guard. Backend giả định trả `name` dạng plain text cùng các highlight ranges, thay vì HTML tùy ý.

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue'
import { searchApi } from '@/api/searchApi'

interface HighlightRange {
  start: number
  length: number
}

interface Suggestion {
  id: string
  name: string
  highlights: HighlightRange[]
  url: string
}

const query = ref('')
const suggestions = ref<Suggestion[]>([])
const loading = ref(false)
const error = ref<string | null>(null)

let timer: number | undefined
let activeController: AbortController | null = null
let requestVersion = 0

function resetResults() {
  suggestions.value = []
  error.value = null
  loading.value = false
}

async function search(value: string) {
  const version = ++requestVersion

  activeController?.abort()
  activeController = new AbortController()

  loading.value = true
  error.value = null

  try {
    const result = await searchApi.suggest(
      value,
      activeController.signal)

    if (version !== requestVersion)
      return

    suggestions.value = result.items
  } catch (e) {
    if (version !== requestVersion)
      return

    if (e instanceof DOMException && e.name === 'AbortError')
      return

    suggestions.value = []
    error.value = 'Không thể tải gợi ý tìm kiếm.'
  } finally {
    if (version === requestVersion)
      loading.value = false
  }
}

watch(query, value => {
  if (timer !== undefined)
    window.clearTimeout(timer)

  activeController?.abort()

  const normalized = value.trim()

  if (normalized.length < 2) {
    ++requestVersion
    resetResults()
    return
  }

  timer = window.setTimeout(() => {
    void search(normalized)
  }, 250)
})

onUnmounted(() => {
  if (timer !== undefined)
    window.clearTimeout(timer)

  activeController?.abort()
  ++requestVersion
})
</script>

<template>
  <div class="search-box">
    <input
      v-model="query"
      autocomplete="off"
      aria-label="Search products"
    />

    <div v-if="loading">Loading...</div>
    <div v-else-if="error" role="status">{{ error }}</div>

    <ul v-if="suggestions.length">
      <li v-for="item in suggestions" :key="item.id">
        <a :href="item.url">{{ item.name }}</a>
      </li>
    </ul>
  </div>
</template>
```

Một API client tập trung có thể xử lý auth/header/error mapping:

```ts
export const searchApi = {
  async suggest(query: string, signal: AbortSignal) {
    const url = new URL('/api/search/suggest', window.location.origin)
    url.searchParams.set('q', query)

    const response = await fetch(url, {
      signal,
      credentials: 'include'
    })

    if (!response.ok) {
      throw new Error(`Search API failed: ${response.status}`)
    }

    return await response.json()
  }
}
```

`credentials: 'include'` ở ví dụ này chỉ phù hợp nếu hệ thống dùng cookie-based authentication. Nếu architecture dùng bearer token SPA, API client layer phải lấy/refresh token theo auth SDK/policy hiện tại; không nên suy diễn một cơ chế auth khác chỉ từ component search.

## Giải thích thiết kế sau khi sửa

### 1. Một reactive source of truth

`query` là nguồn duy nhất kích hoạt search. Không có `keyup` producer thứ hai.

### 2. Debounce, cancellation và stale guard là ba lớp riêng

- debounce giảm số request trước khi gửi;
- abort dừng request đã mất relevance;
- request version bảo vệ state kể cả khi cancellation không ngăn được mọi completion race.

### 3. Không render HTML do upstream kiểm soát

Plain text + structured highlight model giữ quyền quyết định DOM structure ở frontend.

### 4. Auth tách khỏi UI component

Search component không nên biết token nằm ở đâu hoặc refresh như thế nào. Đó là responsibility của API/auth client layer.

## Trade-offs

- Abort request thường giảm work không cần thiết nhưng backend có thể đã nhận và xử lý một phần request trước khi browser abort.
- Latest-request guard thêm state/versioning nhưng làm correctness rõ ràng hơn.
- Structured highlight ranges làm contract phức tạp hơn so với gửi sẵn HTML, đổi lại giảm XSS surface và coupling với markup.
- Debounce 250 ms chỉ là scenario value; giá trị thực tế nên dựa trên UX và telemetry.
- Cookie-based auth, BFF và bearer-token SPA có trade-offs khác nhau; không thể chọn chỉ từ component này.

## Cách kiểm thử

1. **Race test:** mock `iphone` response chậm hơn `ipad`; UI cuối cùng chỉ hiển thị `ipad`.
2. **Debounce test:** gõ nhanh nhiều ký tự; chỉ query cuối sau debounce window được gửi.
3. **Unmount test:** navigate khỏi component khi request đang chạy; không có state update từ request cũ và request bị abort.
4. **Security test:** product name chứa HTML/script payload; UI phải render text an toàn, không thực thi markup.
5. **Failure-path test:** mô phỏng 401, 500, timeout/network error và abort; UI/telemetry phân biệt đúng trạng thái.

# Tổng kết hôm nay

## Kiến thức trọng tâm

- Modernization từ .NET Framework/IIS sang modern .NET/Linux/cloud hosting phải xem xét **operational assumptions**, không chỉ compile compatibility.
- User-controlled filename không nên trở thành storage identity hoặc filesystem path.
- Export lớn cần thiết kế pipeline dữ liệu để tránh whole-result buffering và memory amplification.
- Local instance disk không nên bị mặc định xem là shared durable storage trong hệ thống scale-out.
- Frontend async correctness phụ thuộc vào request ordering, cancellation và state ownership.
- Debounce không tự giải quyết stale response; cancellation cũng không thay thế latest-response validation.
- `v-html` tạo trust boundary khác với text interpolation và cần được coi là security-sensitive.

## Mẫu tư duy cần nhớ

1. **Migration framework cũng là migration operational model.**
2. **Không dùng untrusted display data làm resource identity.**
3. **Stream large data; đừng buffer mặc định.**
4. **Latest intent phải thắng latest completion trong UI async flows.**
5. **Security boundary phải được xác định ở nơi dữ liệu đi vào DOM, filesystem hoặc business resource.**
