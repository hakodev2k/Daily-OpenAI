# Code Review Challenge 1 — Race Condition trong cập nhật trạng thái đơn hàng

**Chủ đề:** Concurrency và Transaction Handling
**Độ khó:** Senior
**Thời gian review đề xuất:** 25 phút
**Số vấn đề cần tìm:** Khoảng 6 vấn đề

## Bối cảnh

Một API ASP.NET Core xử lý thanh toán. Khi payment provider gọi webhook, hệ thống cập nhật trạng thái Order và phát event gửi email. Production đôi lúc ghi nhận Order vừa Paid vừa Cancelled khi webhook đến gần nhau.

## Đoạn code cần review

```csharp
public async Task HandlePaymentAsync(Guid orderId, string transactionId)
{
    var order = await _db.Orders.FirstAsync(x => x.Id == orderId);

    if (order.Status == OrderStatus.Paid)
        return;

    order.Status = OrderStatus.Paid;
    order.TransactionId = transactionId;

    await _db.SaveChangesAsync();

    await _publisher.PublishAsync(new OrderPaidEvent(orderId));
}
```

## Nhiệm vụ của ứng viên

1. Xác định correctness, concurrency, reliability risks.
2. Giải thích production impact.
3. Đề xuất implementation tốt hơn.
4. Nêu cách test và monitoring.

## Gợi ý

### Gợi ý 1
Xem xét nhiều request chạy đồng thời.

### Gợi ý 2
Tập trung vào database consistency, transaction và idempotency.

---

**Hãy tự review đoạn code trước khi xem phần phân tích bên dưới.**

## Kết quả code review tham khảo

- Race condition khi hai webhook cùng đọc trạng thái cũ. Severity: High. Fix bằng optimistic concurrency hoặc transaction lock.
- Publish event sau SaveChanges có thể thất bại gây mất event. Severity: High. Cân nhắc outbox pattern.
- Thiếu idempotency key cho webhook retry. Severity: High.
- Không kiểm tra transactionId hợp lệ. Severity: Medium.

## Phiên bản code đề xuất

```csharp
await using var tx = await _db.Database.BeginTransactionAsync();
var order = await _db.Orders.SingleAsync(x => x.Id == orderId);
if (order.Status != OrderStatus.Paid)
{
    order.MarkPaid(transactionId);
    await _db.SaveChangesAsync();
    await _outbox.AddAsync(new OrderPaidEvent(orderId));
}
await tx.CommitAsync();
```

## Kiểm thử

- Hai webhook chạy đồng thời.
- Provider retry cùng transactionId.
- Database timeout.
- Event publisher failure.

## Quan sát production

Logs orderId, transactionId, correlationId; metric duplicate webhook; trace payment flow.

# Code Review Challenge 2 — HTTP Client và Cancellation trong Background Worker

**Chủ đề:** Resource Lifetime, async/cancellation, HTTP integration
**Độ khó:** Senior+
**Thời gian review đề xuất:** 25 phút
**Số vấn đề cần tìm:** Khoảng 5 vấn đề

## Bối cảnh

Một BackgroundService đồng bộ dữ liệu Microsoft Graph mỗi phút. Sau vài ngày chạy, service có memory tăng và đôi lúc không dừng graceful khi deploy.

## Đoạn code cần review

```csharp
public class SyncWorker : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (true)
        {
            using var client = new HttpClient();
            var response = await client.GetAsync("https://graph.microsoft.com/data");
            var data = await response.Content.ReadAsStringAsync();
            await SaveAsync(data);
            await Task.Delay(60000);
        }
    }
}
```

## Nhiệm vụ của ứng viên

1. Tìm vấn đề runtime.
2. Phân tích ảnh hưởng production.
3. Đề xuất thiết kế tốt hơn.
4. Nêu test và observability.

## Gợi ý

### Gợi ý 1
Xem xét lifetime của dependency và shutdown behavior.

### Gợi ý 2
Xem xét cancellation propagation và HTTP reliability.

---

**Hãy tự review đoạn code trước khi xem phần phân tích bên dưới.**

## Kết quả code review tham khảo

- Tạo HttpClient liên tục gây socket/resource issue. Severity: High. Dùng IHttpClientFactory.
- Bỏ qua stoppingToken khiến deploy không graceful. Severity: High.
- Delay không hỗ trợ cancellation. Severity: Medium.
- Không timeout, retry, logging. Severity: Medium.

## Phiên bản code đề xuất

```csharp
while (!stoppingToken.IsCancellationRequested)
{
    var response = await _client.GetAsync(url, stoppingToken);
    await SaveAsync(await response.Content.ReadAsStringAsync(stoppingToken));
    await Task.Delay(TimeSpan.FromMinutes(1), stoppingToken);
}
```

## Kiểm thử

- Cancellation khi đang gọi API.
- API timeout.
- Graph trả lỗi 429.
- Worker restart.

## Tổng kết hôm nay

## Kiến thức trọng tâm

Concurrency cần thiết kế cùng consistency, idempotency và transaction. Background service cần quản lý lifetime, cancellation và external failure.

## Mẫu tư duy cần nhớ

- Clarify before designing.
- Measure before optimizing.
- Design retries together with idempotency.
- Treat observability as part of design.
