# Code Review Challenge 1 — BackgroundService xuất báo cáo trùng khi scale-out

**Chủ đề:** C#/.NET 8, EF Core, concurrency, BackgroundService  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35 phút  
**Số vấn đề cần tìm:** Khoảng 8

## Bối cảnh

ASP.NET Core trên Azure App Service vừa scale từ một lên bốn instances. Mỗi instance chạy worker quét SQL Server để xuất báo cáo nhân sự. Sau scale, một số file được xuất hai lần, jobs treo ở Running và SQL connection pool bị quá tải. Báo cáo có thể có 100.000 dòng. `AppDbContext` và exporter là scoped services. Yêu cầu: không publish hai kết quả cho cùng job, có thể retry sau khi instance chết.

## Đoạn code cần review

```csharp
public sealed class ReportWorker : BackgroundService
{
    private readonly IServiceScopeFactory _scopes;
    private readonly ILogger<ReportWorker> _logger;

    public ReportWorker(IServiceScopeFactory scopes,
                        ILogger<ReportWorker> logger)
    {
        _scopes = scopes;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = _scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            var exporter = scope.ServiceProvider.GetRequiredService<IReportExporter>();

            var jobs = await db.ReportJobs
                .Where(x => x.Status == "Pending")
                .OrderBy(x => x.CreatedAt)
                .Take(20)
                .ToListAsync();

            var tasks = jobs.Select(async job =>
            {
                job.Status = "Running";
                await db.SaveChangesAsync();

                var rows = await db.EmployeeRecords
                    .Where(x => x.DepartmentId == job.DepartmentId)
                    .ToListAsync();

                job.OutputPath = await exporter.ExportAsync(job.Id, rows);
                job.Status = "Completed";
                await db.SaveChangesAsync();
            });

            await Task.WhenAll(tasks);
            await Task.Delay(TimeSpan.FromSeconds(10));
        }
    }
}
```

## Kết quả code review tham khảo

### Critical — Không có atomic claim

**Vấn đề:** Nhiều workers cùng lấy Pending job.  
**Tại sao xảy ra:** SELECT và UPDATE tách rời.  
**Ảnh hưởng production:** Duplicate exports, ghi đè kết quả.  
**Cách sửa:** Atomic conditional claim trong SQL, LeaseOwner, LeaseUntil và fencing token; finalize có điều kiện.

### Critical — DbContext bị dùng song song

**Vấn đề:** `Task.WhenAll` chia sẻ cùng DbContext.  
**Tại sao xảy ra:** EF Core DbContext không thread-safe.  
**Ảnh hưởng production:** Exceptions, tracking inconsistency.  
**Cách sửa:** Mỗi job dùng scope/DbContext riêng, bounded concurrency.

### High — Không phục hồi job Running

**Vấn đề:** Process chết khiến job bị treo.  
**Tại sao xảy ra:** Không có lease expiry và reclaim.  
**Ảnh hưởng production:** Backlog và vi phạm SLA.  
**Cách sửa:** TTL, heartbeat, retries có giới hạn, trạng thái Failed/poison.

### High — File storage và DB không atomic

**Vấn đề:** File đã tạo nhưng DB chưa commit.  
**Tại sao xảy ra:** Không có distributed transaction.  
**Ảnh hưởng production:** Orphan files, duplicate output sau retry.  
**Cách sửa:** Deterministic object key, staging, conditional publish, cleanup; không khẳng định exactly-once execution.

### High — Không xử lý cancellation và lỗi theo job

**Vấn đề:** Không truyền stoppingToken; một exception có thể kết thúc worker.  
**Tại sao xảy ra:** I/O và `Task.WhenAll` thiếu boundary xử lý.  
**Ảnh hưởng production:** Shutdown chậm, backlog tăng.  
**Cách sửa:** Propagate token; catch và phân loại retryable/permanent failures theo job và polling loop.

### Medium — Memory/connection pool pressure

**Vấn đề:** `ToListAsync` toàn bộ records; 20 tasks mỗi instance.  
**Tại sao xảy ra:** Không streaming và không có global concurrency cap.  
**Ảnh hưởng production:** OOM, GC, pool exhaustion.  
**Cách sửa:** Projection + AsNoTracking, keyset batches/streaming, bounded workers, benchmark.

### Medium — Thiếu kiểm tra quyền export

**Vấn đề:** Truy xuất theo DepartmentId mà không có tenant/requester policy.  
**Tại sao xảy ra:** Job không thể hiện authorization boundary.  
**Ảnh hưởng production:** Rò rỉ dữ liệu nhân sự.  
**Cách sửa:** Validate tenant/requester/permission lúc enqueue và trước export theo policy; audit không chứa PII.

## Phiên bản đề xuất

Các interface bên dưới là contract ứng dụng cần triển khai, không phải APIs có sẵn của .NET. `TryClaimNextAsync` phải atomic và tăng fencing token; `CompleteIfOwnedAsync` chỉ commit khi token còn hiệu lực. Exporter dùng staging key ổn định, không publish khi mất ownership.

```csharp
public sealed class ReportWorker : BackgroundService
{
    private readonly IServiceScopeFactory _scopes;
    private readonly ILogger<ReportWorker> _log;
    private readonly string _owner = Guid.NewGuid().ToString("N");

    public ReportWorker(IServiceScopeFactory scopes,
        ILogger<ReportWorker> log)
    {
        _scopes = scopes;
        _log = log;
    }

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            try
            {
                await using var scope = _scopes.CreateAsyncScope();
                var store = scope.ServiceProvider
                    .GetRequiredService<IReportJobStore>();
                var claim = await store.TryClaimNextAsync(
                    _owner, TimeSpan.FromMinutes(5), ct);

                if (claim is null)
                {
                    await Task.Delay(TimeSpan.FromSeconds(5), ct);
                    continue;
                }

                await ProcessAsync(claim, ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                break;
            }
            catch (Exception ex)
            {
                _log.LogError(ex, "Report polling failed");
                await Task.Delay(TimeSpan.FromSeconds(10), ct);
            }
        }
    }

    private async Task ProcessAsync(ReportClaim claim, CancellationToken ct)
    {
        await using var scope = _scopes.CreateAsyncScope();
        var store = scope.ServiceProvider.GetRequiredService<IReportJobStore>();
        var exporter = scope.ServiceProvider.GetRequiredService<IReportExporter>();

        try
        {
            await store.ValidateAuthorizationAsync(claim, ct);
            var artifact = await exporter.ExportIdempotentlyAsync(claim, ct);
            if (!await store.CompleteIfOwnedAsync(
                claim.Id, claim.FencingToken, artifact, ct))
                _log.LogWarning("Lease lost for {JobId}", claim.Id);
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            throw;
        }
        catch (Exception ex)
        {
            _log.LogError(ex, "Report {JobId} failed", claim.Id);
            await store.FailIfOwnedAsync(
                claim.Id, claim.FencingToken, ex.GetType().Name, ct);
        }
    }
}
```

**Implementation constraints:** Lease phải được renew nếu export dài hơn TTL. `FailIfOwnedAsync` phân biệt transient/permanent errors, giới hạn attempts. Fencing token phải được kiểm tra ở DB và cơ chế publish artifact; không để worker cũ ghi đè file của worker mới. Dùng scope riêng cho mỗi job. Ví dụ chạy tuần tự mỗi instance để kiểm soát tải; muốn song song cần bounded concurrency và đo lường trước.

## Giải thích thiết kế sau khi sửa

SQL làm coordinator vì source of truth đã có sẵn và lưu lượng giả định vừa phải. Atomic claim tránh tranh chấp; fencing tránh late completion; deterministic artifact key + conditional publish tạo một kết quả hiển thị nhất quán dù execution có thể lặp.

## Trade-offs

SQL polling tăng DB traffic và latency; Azure Service Bus giảm polling nhưng vẫn cần idempotent consumer. Lease ngắn recovery nhanh nhưng tăng false reclaim; lease dài ngược lại. Streaming giảm RAM nhưng cần kiểm soát thời gian giữ DB connection.

## Cách kiểm thử

1. Concurrency: 4 workers tranh 100 jobs, chỉ một owner hợp lệ tại mỗi thời điểm.
2. Failure injection: kill worker sau upload trước DB commit, retry không publish duplicate.
3. Fencing: worker A hết lease, B claim, A finalize muộn phải bị từ chối.
4. Load: 100.000 records, đo GC, memory, SQL pool và completion p95.
5. Security: tenant A không thể export dữ liệu tenant B.

## Quan sát trong production

Application Insights và Azure Monitor: structured logs với JobId, Attempt, LeaseOwner, FencingToken, TraceId; pending age p95, expired leases, retry rate, failure rate, SQL pool usage, memory/GC, storage latency. Alert theo backlog/SLA và jobs Running quá hạn. Không log PII.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào thay SQL polling bằng Azure Service Bus?
2. Upload thành công nhưng mất lease thì xử lý artifact thế nào?
3. Nếu báo cáo cần snapshot nhất quán 30 phút, chọn extraction strategy nào?

```typescript
import { test, expect } from '@playwright/test';

const baseUrl = process.env.BASE_URL || 'https://staging.example.test';
const username = process.env.E2E_USER || 'qa@example.test';
const password = process.env.E2E_PASSWORD || 'password123';

test.describe.configure({ mode: 'parallel' });

test('employee login and leave request', async ({ page }) => {
  await page.goto(baseUrl);
  await page.evaluate(() => localStorage.clear());
  await page.reload();

  await page.getByLabel('Email').fill(username);
  await page.getByLabel('Password').fill(password);
  await page.getByRole('button', { name: 'Sign in' }).click();

  await page.waitForTimeout(3000);
  const dashboard = page.locator('[data-testid="dashboard"]');
  if (await dashboard.isVisible()) console.log('Login passed');

  await page.getByRole('link', { name: 'Leave' }).click();
  await page.getByRole('button', { name: 'New request' }).click();
  await page.getByLabel('Start date').fill('2026-12-01');
  await page.getByLabel('End date').fill('2026-12-02');

  await page.route('**/api/leave/**', async route => {
    if (route.request().method() === 'POST') {
      await route.fulfill({
        status: 200,
        contentType: 'application/json',
        body: JSON.stringify({ id: 1, status: 'Created' })
      });
    } else {
      await route.continue();
    }
  });

  await page.getByRole('button', { name: 'Submit' }).click();
  await page.waitForTimeout(2000);
  expect(await page.getByText('Created').count()).toBeGreaterThanOrEqual(0);
});
```

## Phiên bản đề xuất

Giả định ứng dụng có `Reference` unique và test-only cleanup endpoint được bảo vệ. `POST /api/leave` trả 201 và id. Đây là contracts cần xác minh, không phải Playwright APIs mặc định.

```typescript
import { test, expect } from '@playwright/test';
import { randomUUID } from 'node:crypto';

const baseURL = process.env.BASE_URL;
const user = process.env.E2E_USER;
const password = process.env.E2E_PASSWORD;
const token = process.env.E2E_TEST_TOKEN;
if (!baseURL || !user || !password || !token)
  throw new Error('Missing E2E configuration');

test('employee creates leave request', async ({ page, request }) => {
  const reference = randomUUID();
  let id: string | undefined;

  try {
    await page.goto(baseURL);
    await page.getByLabel('Email').fill(user);
    await page.getByLabel('Password').fill(password);
    await page.getByRole('button', { name: 'Sign in' }).click();

    await expect(page.getByTestId('dashboard')).toBeVisible();
    await expect(page.getByTestId('current-user')).toContainText(user);

    await page.getByRole('link', { name: 'Leave' }).click();
    await page.getByRole('button', { name: 'New request' }).click();
    await page.getByLabel('Start date').fill('2026-12-01');
    await page.getByLabel('End date').fill('2026-12-02');
    await page.getByLabel('Reference').fill(reference);

    const responsePromise = page.waitForResponse(r =>
      r.url().includes('/api/leave') &&
      r.request().method() === 'POST');
    await page.getByRole('button', { name: 'Submit' }).click();
    const response = await responsePromise;
    expect(response.status()).toBe(201);

    const body = await response.json();
    expect(body.id).toBeTruthy();
    id = String(body.id);
    await expect(page.getByText('Created', { exact: true })).toBeVisible();

    const saved = await request.get(
      new URL('/api/leave/' + encodeURIComponent(id), baseURL).toString(),
      { headers: { Authorization: 'Bearer ' + token } });
    expect(saved.ok()).toBeTruthy();
    expect((await saved.json()).reference).toBe(reference);
  } finally {
    if (id) {
      const deleted = await request.delete(
        new URL('/test-support/leave/' +
          encodeURIComponent(id), baseURL).toString(),
        { headers: { Authorization: 'Bearer ' + token } });
      expect(deleted.ok()).toBeTruthy();
    }
  }
});
```

**Giới hạn:** Verification phải dùng quyền tối thiểu, không dùng admin token rộng che authorization bugs. Browser cookie session không tự chia sẻ với `request` fixture độc lập. `finally` không chạy nếu worker bị kill, cần periodic cleanup. Date fixture phải hợp lệ theo business calendar; account phải được tách theo worker trước khi bật parallel. Không expose test-support endpoint trong production.

## Giải thích thiết kế sau khi sửa

Web-first assertions xác nhận state thực, network response chứng minh request đến backend và read-back chứng minh persistence. Unique reference giảm xung đột. E2E thật nên tập trung critical journeys; API integration tests kiểm tra nhiều business cases nhanh hơn.

## Trade-offs

E2E thật chậm và phụ thuộc staging. Per-worker accounts tăng chi phí fixture nhưng giảm flakiness. Test-support API cần kiểm soát quyền, audit và isolation. Không nên dùng số lượng lớn E2E thay unit/API tests.
