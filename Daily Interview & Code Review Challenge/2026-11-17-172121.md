# Code Review Challenge 1 — Multi-tenant CSV export gây cạn bộ nhớ

**Chủ đề:** C#/.NET 8, ASP.NET Core, EF Core, PostgreSQL, security, performance

## Bối cảnh

API export requisitions phục vụ nhiều tenant trên Azure App Service (4 instances). Một tenant có 500.000 records, nội dung title/description do người dùng nhập. Sau khi triển khai export, API khác bị tăng p95, memory và connection pool waits. Người dùng thường đóng tab giữa chừng. Yêu cầu không tiết lộ dữ liệu tenant khác và CSV mở được trong spreadsheet. Chưa rõ yêu cầu snapshot consistency.

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/requisitions")]
public sealed class ExportController : ControllerBase
{
    private readonly HiringDbContext _db;
    private readonly ILogger<ExportController> _logger;

    public ExportController(HiringDbContext db, ILogger<ExportController> logger)
    {
        _db = db;
        _logger = logger;
    }

    [HttpGet("export")]
    public async Task<IActionResult> Export(string? status, CancellationToken ct)
    {
        var query = _db.Requisitions.Include(x => x.Department)
            .OrderBy(x => x.CreatedAt);
        var rows = await query.ToListAsync(CancellationToken.None);
        if (!string.IsNullOrWhiteSpace(status))
            rows = rows.Where(x => x.Status == status).ToList();

        var csv = new StringBuilder("Id,Title,Department,Description\n");
        foreach (var row in rows)
        {
            csv.Append(row.Id).Append(',')
               .Append(row.Title).Append(',')
               .Append(row.Department.Name).Append(',')
               .Append(row.Description).Append('\n');
        }
        _logger.LogInformation("Export {Data}", csv.ToString());
        return File(Encoding.UTF8.GetBytes(csv.ToString()),
            "text/csv", "requisitions.csv");
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Cross-tenant disclosure

**Vấn đề:** Không lọc tenant.  
**Tại sao xảy ra:** `[Authorize]` chỉ xác nhận identity, không giới hạn records.  
**Ảnh hưởng production:** Rò rỉ dữ liệu tuyển dụng giữa tenants.  
**Cách sửa:** Derive tenant từ authenticated context; enforce predicate ở DB và integration test isolation.

### [High] — Memory amplification

**Vấn đề:** ToList, StringBuilder, ToString và GetBytes buffer nhiều bản sao.  
**Tại sao xảy ra:** Materialize toàn bộ dataset trước khi gửi.  
**Ảnh hưởng production:** LOH/GC pressure, OOM, p95 tăng.  
**Cách sửa:** Bounded keyset batches, projection, streaming; cân nhắc async export sang Blob Storage.

### [High] — CSV injection và malformed CSV

**Vấn đề:** Fields không được quote, escape hay neutralize spreadsheet formulas.  
**Tại sao xảy ra:** Ghép chuỗi trực tiếp từ untrusted content.  
**Ảnh hưởng production:** Hỏng cột và spreadsheet formula execution.  
**Cách sửa:** CSV serializer, quote double-quotes, xử lý leading formula characters theo client policy.

### [High] — Sensitive data logging

**Vấn đề:** Log toàn bộ CSV.  
**Tại sao xảy ra:** Log payload thay vì metadata.  
**Ảnh hưởng production:** Data exposure, log cost.  
**Cách sửa:** Chỉ log export ID, row count, duration và outcome.

### [Medium] — Cancellation bị bỏ qua

**Vấn đề:** Query dùng `CancellationToken.None`.  
**Tại sao xảy ra:** Không propagate request token.  
**Ảnh hưởng production:** Query tiếp tục sau disconnect.  
**Cách sửa:** Truyền `ct` vào DB và response writes.

### [Medium] — Filtering sau materialization

**Vấn đề:** Status filter chạy trên List.  
**Tại sao xảy ra:** Query thực thi trước khi filter.  
**Ảnh hưởng production:** DB/network/memory waste.  
**Cách sửa:** Filter trên IQueryable trước ToList.

### [Medium] — Tracking/Include quá mức

**Vấn đề:** Track entity graph dù chỉ đọc vài fields.  
**Tại sao xảy ra:** Không dùng `AsNoTracking` và projection.  
**Ảnh hưởng production:** Allocations lớn.  
**Cách sửa:** Project scalar fields cần export.

### [Medium] — Thứ tự không duy nhất

**Vấn đề:** Chỉ order CreatedAt.  
**Tại sao xảy ra:** Timestamps trùng nhau.  
**Ảnh hưởng production:** Batch pagination có thể bỏ sót/lặp rows.  
**Cách sửa:** Stable tie-breaker Id; xác định consistency contract.

## Phiên bản đề xuất

Thiết kế này giả định tenant ID đã được middleware xác thực và cung cấp qua `ITenantContext`. Sử dụng keyset batches với khóa `(CreatedAt, SequenceId)`, trong đó `SequenceId` là unique bigint tăng dần và được index; không giả định UUID comparison được provider translate. Chỉ lưu một batch trong memory.

```csharp
public sealed class CsvExportService
{
    private readonly HiringDbContext _db;
    private readonly ITenantContext _tenant;

    public CsvExportService(HiringDbContext db, ITenantContext tenant)
    {
        _db = db;
        _tenant = tenant;
    }

    public async Task WriteAsync(Stream output, string? status,
        CancellationToken ct)
    {
        await using var writer = new StreamWriter(output,
            new UTF8Encoding(false), leaveOpen: true);
        await writer.WriteLineAsync("Id,Title,Department,Description");

        DateTime? lastTime = null;
        long lastSequence = 0;
        while (true)
        {
            var query = _db.Requisitions.AsNoTracking()
                .Where(x => x.TenantId == _tenant.RequiredTenantId);
            if (!string.IsNullOrWhiteSpace(status))
                query = query.Where(x => x.Status == status);
            if (lastTime.HasValue)
            {
                var t = lastTime.Value;
                var s = lastSequence;
                query = query.Where(x => x.CreatedAt > t ||
                    (x.CreatedAt == t && x.SequenceId > s));
            }

            var batch = await query.OrderBy(x => x.CreatedAt)
                .ThenBy(x => x.SequenceId)
                .Select(x => new {
                    x.Id, x.CreatedAt, x.SequenceId, x.Title,
                    Department = x.Department.Name, x.Description
                }).Take(500).ToListAsync(ct);
            if (batch.Count == 0) break;

            foreach (var x in batch)
            {
                ct.ThrowIfCancellationRequested();
                await writer.WriteLineAsync(string.Join(",",
                    Cell(x.Id.ToString()), Cell(x.Title),
                    Cell(x.Department), Cell(x.Description)));
            }
            await writer.FlushAsync(ct);
            lastTime = batch[^1].CreatedAt;
            lastSequence = batch[^1].SequenceId;
        }
    }

    private static string Cell(string? value)
    {
        var s = value ?? "";
        var prefix = s.TrimStart(' ', '\t', '\r', '\n');
        if (prefix.Length > 0 && "=+-@".Contains(prefix[0]))
            s = "'" + s;
        return "\"" + s.Replace("\"", "\"\"") + "\"";
    }
}
```

Controller phải set Content-Type và Content-Disposition an toàn, gọi service với `Response.Body` và `HttpContext.RequestAborted`. Middleware phải map invalid tenant claims thành 401/403, không dùng tenant ID từ query. Đoạn trên là phần service cốt lõi; trong production nên dùng CSV library có test với spreadsheet mục tiêu. Nếu yêu cầu snapshot consistency, keyset pagination không tự bảo đảm snapshot khi records bị cập nhật.

## Giải thích thiết kế sau khi sửa

Tenant predicate thực thi ở DB; projection giảm allocations; batches giải phóng DB connection giữa các lần ghi HTTP. Stable ordering giảm lỗi pagination. Escape CSV bảo vệ cấu trúc, còn formula neutralization giải quyết một lớp rủi ro khác.

## Trade-offs

Streaming giữ HTTP connection lâu và có thể bị slow clients. Batching tăng số queries và không bảo đảm snapshot consistency. Background export + Azure Blob Storage tăng complexity và storage cost nhưng phù hợp export lớn, retry và download lại. Cần đo trước khi quyết định.

## Cách kiểm thử

1. **Security integration:** Tenant A không thấy tenant B.
2. **CSV security:** Quotes, commas, CRLF, Unicode và formula-prefixed cells.
3. **Load:** 50 exports đồng thời, đo heap, GC, pool waits, p95 API khác.
4. **Cancellation:** Client disconnect dừng DB work.
5. **Consistency:** Concurrent insert/update trong lúc paging; xác nhận contract.

## Quan sát trong production

Application Insights dependency duration, export duration, row count, active exports, GC pause, memory, DB pool waits, cancellation rate; structured logs không chứa PII; alerts khi p95 API khác bị ảnh hưởng.

## Câu hỏi phỏng vấn mở rộng

1. Nếu yêu cầu point-in-time snapshot, bạn thiết kế thế nào?
2. Khi nào chuyển sang Azure Blob Storage background export?
3. Rate limit export theo user và tenant ra sao?

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'

type Item = { id: string; title: string; status: string }
const query = ref('')
const status = ref('all')
const tenant = ref(localStorage.getItem('tenantId') || '')
const items = ref<Item[]>([])
const loading = ref(false)
const error = ref('')
const cache = new Map<string, Item[]>()

watch([query, status, tenant], async () => {
  loading.value = true
  error.value = ''
  const key = query.value + ':' + status.value
  if (cache.has(key)) {
    items.value = cache.get(key)!
    loading.value = false
    return
  }
  try {
    const url = '/api/requisitions/search?q=' + query.value +
      '&status=' + status.value + '&tenant=' + tenant.value
    const response = await fetch(url, { credentials: 'include' })
    const data = await response.json()
    cache.set(key, data.items)
    items.value = data.items
  } catch {
    error.value = 'Cannot load results'
  } finally {
    loading.value = false
  }
}, { immediate: true })
</script>

<template>
  <section>
    <input v-model="query" placeholder="Search requisitions" />
    <select v-model="status">
      <option value="all">All</option>
      <option value="open">Open</option>
      <option value="closed">Closed</option>
    </select>
    <p v-if="loading">Loading...</p>
    <p v-if="error">{{ error }}</p>
    <ul><li v-for="item in items" :key="item.id">{{ item.title }}</li></ul>
  </section>
</template>
```

## Kết quả code review tham khảo

### [High] — Stale response overwrite

**Vấn đề:** Request cũ ghi đè kết quả mới.  
**Tại sao xảy ra:** Watch callbacks async chạy chồng lấp.  
**Ảnh hưởng production:** UI hiển thị sai filter.  
**Cách sửa:** Abort previous request và generation guard.

### [High] — Cache leak qua account/tenant

**Vấn đề:** Key chỉ có query/status.  
**Tại sao xảy ra:** Cache không scope theo identity.  
**Ảnh hưởng production:** UI có thể hiện dữ liệu account trước.  
**Cách sửa:** Bỏ cache hoặc partition và clear theo session; backend vẫn enforce authorization.

### [High] — Tenant do client kiểm soát

**Vấn đề:** Tenant ID lấy từ localStorage.  
**Tại sao xảy ra:** Frontend state bị coi như identity.  
**Ảnh hưởng production:** Nếu server tin parameter sẽ có cross-tenant disclosure.  
**Cách sửa:** Backend derive tenant từ authenticated context và authorize mọi selection.

### [Medium] — Không kiểm tra HTTP status

**Vấn đề:** 401/403/500 vẫn được parse như success.  
**Tại sao xảy ra:** Fetch chỉ reject network errors.  
**Ảnh hưởng production:** UI sai và auth expiry không được xử lý.  
**Cách sửa:** Check `response.ok`, clear state khi session invalid.

### [Medium] — URL parameters không encode

**Vấn đề:** Nối query trực tiếp.  
**Tại sao xảy ra:** Không dùng URLSearchParams.  
**Ảnh hưởng production:** `&`, `#`, `+` làm sai search.  
**Cách sửa:** Encode parameters.

### [Medium] — Loading race

**Vấn đề:** Request cũ set loading=false khi request mới còn chạy.  
**Tại sao xảy ra:** Shared state trong finally.  
**Ảnh hưởng production:** Loading indicator không đáng tin.  
**Cách sửa:** Generation guard cho finally.

### [Low] — Request amplification và accessibility

**Vấn đề:** Mỗi keystroke gửi request; input thiếu label, status thiếu live region.  
**Tại sao xảy ra:** Không debounce và semantic markup.  
**Ảnh hưởng production:** Tăng API load và giảm accessibility.  
**Cách sửa:** Debounce, label, role=status/alert.

## Phiên bản đề xuất

Giả định auth store cung cấp reactive `sessionVersion` tăng đồng bộ mỗi lần login/logout/account switch. Server không tin tenant từ client. Không cache sensitive results trong component.

```vue
<script setup lang="ts">
import { ref, watch } from 'vue'
import { useAuthStore } from '@/stores/auth'

type Item = { id: string; title: string; status: string }
const auth = useAuthStore()
const query = ref('')
const status = ref('all')
const items = ref<Item[]>([])
const loading = ref(false)
const error = ref('')
let generation = 0

watch(
  () => [query.value, status.value, auth.sessionVersion],
  (_values, _old, onCleanup) => {
    const current = ++generation
    const controller = new AbortController()
    let timer: ReturnType<typeof setTimeout> | undefined
    items.value = []
    loading.value = true
    error.value = ''

    onCleanup(() => {
      controller.abort()
      if (timer) clearTimeout(timer)
    })

    timer = setTimeout(async () => {
      try {
        const params = new URLSearchParams({
          q: query.value, status: status.value
        })
        const response = await fetch(
          '/api/requisitions/search?' + params,
          { credentials: 'include', signal: controller.signal,
            cache: 'no-store' }
        )
        if (!response.ok) throw new Error('HTTP ' + response.status)
        const data: { items: Item[] } = await response.json()
        if (current === generation && !controller.signal.aborted)
          items.value = data.items
      } catch {
        if (current === generation && !controller.signal.aborted)
          error.value = 'Không thể tải dữ liệu.'
      } finally {
        if (current === generation) loading.value = false
      }
    }, 250)
  },
  { immediate: true }
)
</script>

<template>
  <section>
    <label for="search">Search requisitions</label>
    <input id="search" v-model="query" />
    <label for="status">Status</label>
    <select id="status" v-model="status">
      <option value="all">All</option>
      <option value="open">Open</option>
      <option value="closed">Closed</option>
    </select>
    <p v-if="loading" role="status">Loading...</p>
    <p v-if="error" role="alert">{{ error }}</p>
    <ul><li v-for="item in items" :key="item.id">{{ item.title }}</li></ul>
  </section>
</template>
```

Khi logout, auth store phải clear tất cả user-scoped stores ngay lập tức, tăng `sessionVersion` và điều hướng phù hợp. Backend nên trả `Cache-Control: private, no-store` cho dữ liệu nhạy cảm. Cần kiểm tra service worker và shared API cache nếu có. Abort phía browser không bảo đảm backend đã hủy DB work.

## Giải thích thiết kế sau khi sửa

Generation guard đảm bảo chỉ request hiện hành cập nhật state; AbortController giảm work thừa. Debounce giảm load. Session boundary được thể hiện trong reactive dependencies. Backend là nơi thực thi authorization.

## Trade-offs

Không cache tăng request khi quay lại filter cũ. Nếu cần cache, phải partition theo session/tenant, TTL và invalidation rõ ràng. Debounce thêm độ trễ nhỏ; chọn giá trị dựa trên đo UX và API load.

## Cách kiểm thử

1. **Playwright race:** Delay A, trả B trước; UI chỉ hiện B.
2. **Session switch:** Đổi account khi request đang chạy; không hiện dữ liệu cũ.
3. **Failure path:** 401/403/500 và malformed JSON; UI không giữ stale data.
4. **Encoding:** Search `&`, `+`, Unicode, whitespace.
5. **Accessibility/load:** Keyboard, live regions, request count khi gõ nhanh.

## Quan sát trong production

Browser metrics search request count, abort rate, response latency, error status; server traces với correlation ID, authorization denials, p95 và DB dependency duration. Không log query chứa dữ liệu nhạy cảm.

2. Cursor pagination thay đổi race handling ra sao?
3. Nếu service worker cache API, bạn bảo vệ dữ liệu khi logout thế nào?
