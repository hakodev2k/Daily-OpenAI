# Code Review Challenge 1 — Product search index sai giá sau khi cập nhật

**Chủ đề:** .NET 8, EF Core, PostgreSQL, Elasticsearch, distributed consistency  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35 phút  
**Số vấn đề cần tìm:** Khoảng 8

## Bối cảnh

E-commerce API chạy trên ba Azure App Service instances. PostgreSQL là source of truth của Product và giá; Elasticsearch phục vụ tìm kiếm. Khi editor cập nhật sản phẩm, API lưu database và lập tức cập nhật index. Elasticsearch đôi lúc timeout; một số kết quả tìm kiếm có giá cũ dù database đúng. Có nhiều update đồng thời trên cùng product. Search được phép eventual consistency nhưng không được mất thay đổi vĩnh viễn. Checkout luôn xác minh giá tại database.

## Đoạn code cần review

```csharp
public sealed class ProductService(
    CatalogDbContext db,
    HttpClient search,
    ILogger<ProductService> logger)
{
    public async Task<bool> UpdateAsync(
        long id, string name, decimal price, CancellationToken ct)
    {
        var product = await db.Products
            .SingleOrDefaultAsync(x => x.Id == id, ct);
        if (product is null) return false;

        product.Name = name;
        product.Price = price;
        product.UpdatedAt = DateTimeOffset.UtcNow;

        await db.SaveChangesAsync(ct);

        try
        {
            using var response = await search.PutAsJsonAsync(
                $"/products/_doc/{id}",
                new
                {
                    product.Id,
                    product.Name,
                    product.Price,
                    product.UpdatedAt
                }, ct);
            response.EnsureSuccessStatusCode();
        }
        catch (Exception ex)
        {
            logger.LogWarning(ex, "Index update failed: {Id}", id);
        }

        return true;
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Mất durable indexing intent

**Vấn đề:** Database commit rồi HTTP call; failure bị nuốt.  
**Tại sao xảy ra:** Không có atomic transaction xuyên PostgreSQL/Elasticsearch.  
**Ảnh hưởng production:** Index stale vĩnh viễn nếu không có reconciliation.  
**Cách sửa:** Transactional Outbox ghi event cùng transaction với Product; worker xử lý retry và replay.

### [High] — Out-of-order updates

**Vấn đề:** Request cũ có thể index sau request mới.  
**Tại sao xảy ra:** Network scheduling không giữ commit order.  
**Ảnh hưởng production:** Giá cũ ghi đè giá mới.  
**Cách sửa:** Database-assigned monotonically increasing product version; consumer dùng external versioning phù hợp với Elasticsearch version triển khai hoặc kiểm tra version và serialize per key.

### [High] — Lost update trong database

**Vấn đề:** Không có concurrency token.  
**Tại sao xảy ra:** Hai editor cùng đọc một version rồi ghi đè.  
**Ảnh hưởng production:** Một thay đổi bị mất mà không cảnh báo.  
**Cách sửa:** EF Core concurrency token và expectedVersion/ETag, trả conflict khi mismatch.

### [High] — Authorization không thể hiện trong write path

**Vấn đề:** Không thấy kiểm tra editor được sửa product/tenant nào.  
**Tại sao xảy ra:** Có thể được xử lý ở controller, cần xác minh trước khi kết luận vulnerability.  
**Ảnh hưởng production:** Nếu upstream thiếu policy, user sửa giá ngoài quyền.  
**Cách sửa:** Policy-based authorization và tenant scope trong application/query, integration tests.

### [Medium] — Validation thiếu

**Vấn đề:** Giá âm, tên rỗng, độ dài quá mức chưa được chặn trong snippet.  
**Tại sao xảy ra:** Không thấy domain invariants và DB constraints.  
**Ảnh hưởng production:** Dữ liệu bất hợp lệ.  
**Cách sửa:** Domain validation, database constraints và kiểm tra currency/business rules.

### [Medium] — Cancellation và lỗi bị gom chung

**Vấn đề:** Catch(Exception) không phân biệt timeout, cancellation, 4xx và 5xx.  
**Tại sao xảy ra:** Indexing nằm trong request lifetime.  
**Ảnh hưởng production:** Không có retry có kiểm soát; request bị cancel sau commit.  
**Cách sửa:** Worker độc lập, retry transient với backoff/jitter, quarantine permanent failures.

### [Medium] — Kết quả API gây hiểu lầm

**Vấn đề:** true chỉ chứng minh database write thành công, không chứng minh index đã cập nhật.  
**Tại sao xảy ra:** Không định nghĩa consistency contract.  
**Ảnh hưởng production:** Client kỳ vọng read-after-write từ search.  
**Cách sửa:** Document eventual consistency; trả version hoặc trạng thái nếu business cần.

### [Medium] — Thiếu telemetry và reconciliation

**Vấn đề:** Chỉ có warning log, không có backlog age hoặc drift detection.  
**Tại sao xảy ra:** Không có durable queue.  
**Ảnh hưởng production:** Không biết product nào stale.  
**Cách sửa:** Pending age, retry count, dead-letter, last indexed version và periodic reconciliation.

## Phiên bản đề xuất

Giả định `Product.Version` được cấu hình `IsConcurrencyToken()`, `OutboxMessage.EventId` unique và cả hai entities nằm cùng database:

```csharp
public sealed record UpdateProduct(
    long Id, long ExpectedVersion, string Name, decimal Price);

public sealed class UpdateProductHandler(CatalogDbContext db)
{
    public async Task<long?> ExecuteAsync(
        UpdateProduct cmd, CancellationToken ct)
    {
        if (cmd.Price < 0 || string.IsNullOrWhiteSpace(cmd.Name))
            throw new ArgumentException("Invalid product");

        await using var tx = await db.Database.BeginTransactionAsync(ct);
        var p = await db.Products.SingleOrDefaultAsync(x => x.Id == cmd.Id, ct);
        if (p is null) return null;
        if (p.Version != cmd.ExpectedVersion)
            throw new DbUpdateConcurrencyException("Stale version");

        var original = p.Version;
        p.Name = cmd.Name.Trim();
        p.Price = cmd.Price;
        p.Version = original + 1;
        db.Entry(p).Property(x => x.Version).OriginalValue = original;

        db.OutboxMessages.Add(new OutboxMessage
        {
            EventId = Guid.NewGuid(),
            ProductId = p.Id,
            ProductVersion = p.Version,
            Payload = JsonSerializer.Serialize(new
            {
                p.Id, p.Name, p.Price, p.Version
            }),
            CreatedAt = DateTimeOffset.UtcNow
        });

        await db.SaveChangesAsync(ct);
        await tx.CommitAsync(ct);
        return p.Version;
    }
}
```

Worker algorithm:

```text
Claim pending rows atomically (lease or SKIP LOCKED)
 -> deserialize and validate schema
 -> index using product version
 -> ack only on confirmed success / confirmed newer version
 -> transient failure: bounded backoff and retry
 -> permanent failure: quarantine + alert
 -> crash: lease expires, safely replay event
```

Không giữ database transaction khi gọi Elasticsearch. Consumer phải xử lý duplicate events, delete/tombstone và version conflicts. Elasticsearch external versioning có API/semantics phụ thuộc version và client; xác minh official documentation trước triển khai. Dùng source of truth để reconcile khi cần. Outbox không cung cấp exactly-once delivery.

## Giải thích thiết kế sau khi sửa

Transaction đảm bảo Product và indexing intent cùng commit. Worker tách availability của database write khỏi search dependency. Optimistic concurrency ngăn lost update từ editor; monotonic version ngăn index cũ ghi đè bản mới. Không cần microservices chỉ để chạy worker.

## Trade-offs

Outbox cần schema, worker, monitoring, storage và xử lý event schema evolution. Eventual consistency vẫn tồn tại. CDC là phương án khác nếu có infrastructure và operational maturity. Direct indexing đơn giản hơn khi index chỉ best-effort và periodic full rebuild đủ đáp ứng business.

## Cách kiểm thử

1. **Integration:** DB commit, Elasticsearch timeout; outbox vẫn pending và retry thành công.
2. **Concurrency:** Hai update cùng expectedVersion, chỉ một được commit.
3. **Ordering:** Event version 12 đến trước 11, index cuối cùng là 12.
4. **Failure-path:** Worker crash sau index trước ack; replay không làm sai trạng thái.
5. **Load/reconciliation:** Hàng trăm nghìn updates, đo backlog age, index drift và throughput.

## Quan sát trong production

Application Insights dependency traces, structured logs theo eventId/productId/version/traceId, không log PII. Metrics: oldest outbox age, pending count, dead-letter count, retry rate, Elasticsearch latency p95/p99, version drift. Alert khi lag vượt freshness SLA hoặc poison events tăng.

## Câu hỏi phỏng vấn mở rộng

1. Reindex không downtime bằng index alias và schema version như thế nào?
2. Nếu Product yêu cầu search freshness dưới một giây, xác minh SLA và phương án thế nào?
3. Khi nào chọn CDC thay Outbox?

# Code Review Challenge 2 — Akamai cache trộn bản preview và bản public

Marketing website dùng ASP.NET Core 8, Optimizely CMS và Akamai CDN. Editor preview campaign drafts trước khi publish. Khách đôi lúc thấy nội dung cũ sau publish; một số canonical URL sai locale; có báo cáo draft xuất hiện ở browser không đăng nhập. `IContentFacade` là abstraction nội bộ giả định, không phải API chính thức của Optimizely. Traffic tăng mạnh trong campaign.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/campaigns")]
public sealed class CampaignController : ControllerBase
{
    private readonly IContentFacade _content;

    public CampaignController(IContentFacade content)
        => _content = content;

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(
        string slug,
        [FromQuery] bool preview = false,
        [FromQuery] string? lang = null,
        CancellationToken ct = default)
    {
        var locale = lang ?? "en";
        var campaign = await _content.FindBySlugAsync(
            slug, locale, includeDrafts: preview, ct);

        if (campaign is null)
            return NotFound();

        Response.Headers.CacheControl = "public,max-age=3600";
        Response.Headers["Surrogate-Control"] = "max-age=86400";
        Response.Headers["Vary"] = "Accept-Encoding";

        var canonical = $"https://shop.example.com/campaigns/{slug}";
        return Ok(new
        {
            campaign.Title,
            campaign.BodyHtml,
            campaign.LastPublishedAt,
            CanonicalUrl = canonical,
            Locale = locale
        });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Preview không được bảo vệ trong endpoint

**Vấn đề:** Public query parameter điều khiển includeDrafts.  
**Tại sao xảy ra:** Không có authorization check tại endpoint; phải kiểm tra global policies/facade để kết luận exploit.  
**Ảnh hưởng production:** Nếu các tầng khác không chặn, anonymous user đọc draft.  
**Cách sửa:** Preview authorization policy và content-level permissions; không tin client flag.

### [Critical] — Draft bị đánh dấu public cache

**Vấn đề:** Preview cũng nhận public Cache-Control và Surrogate-Control.  
**Tại sao xảy ra:** Không tách public/preview response.  
**Ảnh hưởng production:** CDN có thể cache draft nếu property cho phép.  
**Cách sửa:** Preview private/no-store và CDN bypass cho preview/authenticated traffic; kiểm tra edge behavior thực tế.

### [High] — Cache key không xác minh locale/preview

**Vấn đề:** Vary Accept-Encoding không bảo đảm cache phân biệt lang/preview.  
**Tại sao xảy ra:** Query string inclusion phụ thuộc Akamai property.  
**Ảnh hưởng production:** Cross-locale hoặc draft/public contamination.  
**Cách sửa:** Public locale trong URL path hoặc cấu hình query allowlist rõ ràng; preview bypass hoàn toàn.

### [High] — Publish không invalidate edge

**Vấn đề:** Surrogate TTL tới 24 giờ, không thấy purge.  
**Tại sao xảy ra:** Chỉ dựa TTL; có thể có purge ngoài snippet cần xác minh.  
**Ảnh hưởng production:** Nội dung stale sau publish/unpublish.  
**Cách sửa:** Publish/unpublish event, durable purge job, retry, kiểm tra revision tại edge; TTL fallback theo SLA.

### [High] — Public visibility chưa được chứng minh

**Vấn đề:** Facade contract không rõ published status, publish windows và tenant scope.  
**Tại sao xảy ra:** includeDrafts=false chưa chứng minh mọi filter đúng.  
**Ảnh hưởng production:** Nội dung expired/unpublished có thể được phục vụ.  
**Cách sửa:** Enforce published-only, visibility và authorization trong reader, test unpublish.

### [Medium] — Canonical sai locale/route

**Vấn đề:** Canonical ghép raw slug, không dùng URL resolver và locale.  
**Tại sao xảy ra:** Không có localized routing policy.  
**Ảnh hưởng production:** Duplicate indexing, canonical không đúng, SEO regression.  
**Cách sửa:** Canonical URL resolver, normalized slug, hreflang và redirects.

### [Medium] — Rich HTML có thể gây XSS

**Vấn đề:** BodyHtml được trả nguyên, chưa thấy sanitization/rendering policy.  
**Tại sao xảy ra:** Phụ thuộc editor trust model và frontend.  
**Ảnh hưởng production:** Stored XSS nếu render HTML không an toàn.  
**Cách sửa:** Sanitization allowlist, CSP defense-in-depth và browser tests.

### [Medium] — Không có revision/cache diagnostics

**Vấn đề:** Không thể biết stale do CMS, origin, CDN hay browser.  
**Tại sao xảy ra:** Thiếu revision/age telemetry.  
**Ảnh hưởng production:** Incident kéo dài.  
**Cách sửa:** Safe revision headers, cache status, edge age, correlated tracing.

## Phiên bản đề xuất

Ví dụ dùng application abstractions nội bộ, không giả định API cụ thể của Optimizely:

```csharp
[ApiController]
[Route("api/campaigns")]
public sealed class CampaignController(
    ICampaignReader reader,
    ICampaignUrlResolver urls,
    IHtmlSanitizer sanitizer,
    IAuthorizationService authorization) : ControllerBase
{
    [HttpGet("{locale}/{slug}")]
    public async Task<IActionResult> Get(
        string locale, string slug,
        [FromQuery] bool preview,
        CancellationToken ct)
    {
        if (!SupportedLocales.Contains(locale))
            return BadRequest();

        if (preview)
        {
            var result = await authorization.AuthorizeAsync(
                User, "CampaignPreview");
            if (!result.Succeeded)
                return User.Identity?.IsAuthenticated == true
                    ? Forbid() : Challenge();

            Response.Headers.CacheControl = "private, no-store";
            Response.Headers["Surrogate-Control"] = "no-store";
        }
        else
        {
            Response.Headers.CacheControl = "public, max-age=60";
            Response.Headers["Surrogate-Control"] = "max-age=300";
        }

        var item = await reader.GetAsync(
            slug, locale, includeDrafts: preview, ct);
        if (item is null) return NotFound();

        return Ok(new
        {
            item.Title,
            BodyHtml = sanitizer.Sanitize(item.BodyHtml),
            CanonicalUrl = urls.ResolveCanonical(item, locale),
            Locale = locale
        });
    }

    private static readonly HashSet<string> SupportedLocales =
        new(StringComparer.OrdinalIgnoreCase) { "en", "vi" };
}
```

Reader vẫn phải enforce content-level access, publication window và tenant boundaries. Akamai phải bypass preview/authenticated paths bất kể origin headers; edge configuration có thể override headers. Publish pipeline:

```text
CMS publish/unpublish
 -> durable event and retryable purge job
 -> enumerate affected locale URLs / cache tags
 -> Akamai purge
 -> synthetic edge GET validates published revision
 -> alert if freshness SLA exceeded
```

Canonical/hreflang cần được render đúng ở HTML page cho crawler, không chỉ trả qua JSON API.

## Giải thích thiết kế sau khi sửa

Preview và public có access/cache policy riêng. Content reader chịu trách nhiệm publication state và permission. Canonical được tạo từ routing policy. Publish purge rút ngắn stale interval; TTL fallback giới hạn impact nếu purge hỏng. CDN configuration phải được kiểm thử bằng request thật.

## Trade-offs

TTL ngắn tăng origin load; purge nhiều URLs tăng complexity/rate-limit risk. Preview bypass cache tăng latency nhưng bảo vệ draft. Sanitization có thể làm mất markup hợp lệ; cần editor acceptance tests. Không cần microservices hoặc headless rewrite chỉ để sửa caching.

## Cách kiểm thử

1. **Security:** Anonymous preview bị chặn; editor không có content permission không thấy draft.
2. **CDN E2E:** Preview không được cache dù thay query/cookie/locale.
3. **Publish/unpublish:** Purge failure/retry; edge cuối cùng có đúng revision.
4. **Playwright SEO:** Canonical, hreflang, redirect và 404 theo locale.
5. **XSS:** Rich text chứa event handler/script không thực thi trên browser.

## Quan sát trong production

Structured logs theo contentId, locale, revision, preview, traceId; không log preview tokens. Akamai cache hit/miss, cache key variants, Age, purge status; origin CMS read latency, 403/404, p95. Application Insights trace correlation; alert khi edge revision stale quá SLA hoặc anonymous preview thành công.
