# Code Review Challenge 1 — Optimizely CMS và Akamai trả nhầm nội dung preview

## Bối cảnh

Website thương mại sử dụng Optimizely CMS để biên tập landing page, ASP.NET Core làm origin, Akamai làm CDN. Biên tập viên có thể preview nội dung chưa publish; khách truy cập chỉ được xem phiên bản published. Sau chiến dịch marketing, một số khách thấy banner chưa phát hành, trong khi biên tập viên đôi khi thấy nội dung cũ. Traffic tăng đột biến và cache hit ratio giảm. [ApiController]
```csharp
[Route("api/content")]
public sealed class ContentController : ControllerBase
{
    private static readonly MemoryCache Cache = new(new MemoryCacheOptions());
    private readonly ICmsContentClient _cms;
    private readonly ILogger<ContentController> _logger;

    public ContentController(ICmsContentClient cms, ILogger<ContentController> logger)
    {
        _cms = cms;
        _logger = logger;
    }

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(
        string slug, string locale = "en", bool preview = false)
    {
        var key = $"content:{slug}";
        if (!Cache.TryGetValue(key, out CmsPage? page))
        {
            page = await _cms.GetPageAsync(slug, locale, preview);
            if (page is null) return NotFound();

            Cache.Set(key, page, TimeSpan.FromMinutes(30));
        }

        Response.Headers.CacheControl = "public, max-age=1800";
        Response.Headers.ETag = page!.Revision;
        _logger.LogInformation("Content requested {Slug} {Preview}", slug, preview);
        return Ok(new
        {
            page.Title,
            page.Html,
            page.Revision,
            page.PublishedAt
        });
    }

    [HttpPost("purge")]
    public IActionResult Purge([FromBody] PurgeRequest request)
    {
        Cache.Remove($"content:{request.Slug}");
        return Accepted();
    }
}

public sealed record PurgeRequest(string Slug);
```

## Kết quả code review tham khảo

### Critical — Preview không kiểm tra authorization

**Vấn đề:** Caller tự đặt `preview=true`.  
**Tại sao xảy ra:** Origin tin query parameter thay vì identity và quyền editor.  
**Ảnh hưởng production:** Lộ nội dung chưa publish nếu CMS client chấp nhận preview.  
**Cách sửa:** Bắt buộc authorization policy riêng, server-side editor context, audit truy cập; chặn preview tại edge nếu không có session hợp lệ.

### Critical — Cache key trộn public và preview

**Vấn đề:** Chỉ dùng slug làm key.  
**Tại sao xảy ra:** Locale, publication state và audience không được phân tách.  
**Ảnh hưởng production:** Public nhận nội dung preview, ngôn ngữ sai hoặc nội dung của phân khúc khác.  
**Cách sửa:** Không shared-cache preview; public cache key bao gồm canonical locale, content identity, variation được phép cache.

### High — Response preview có thể được CDN/browser cache công khai

**Vấn đề:** Luôn trả `public, max-age=1800`.  
**Tại sao xảy ra:** Không phân loại response theo quyền truy cập.  
**Ảnh hưởng production:** Lộ dữ liệu kéo dài sau khi origin sửa.  
**Cách sửa:** Preview/personalized dùng `private, no-store`; chỉ public published variant mới có `public` với edge policy phù hợp.

### High — Endpoint purge không có bảo vệ

**Vấn đề:** Bất kỳ caller nào cũng có thể gửi purge.  
**Tại sao xảy ra:** Thiếu xác thực, authorization và chống abuse.  
**Ảnh hưởng production:** Cache churn, origin overload, giảm availability.  
**Cách sửa:** Nội bộ hóa endpoint; dùng service identity, policy và rate limit, audit.

### High — Invalidation không bao phủ nhiều instances và Akamai

**Vấn đề:** `MemoryCache.Remove` chỉ xóa trên một process.  
**Tại sao xảy ra:** Không có cơ chế invalidation đa tầng.  
**Ảnh hưởng production:** Các replicas/CDN tiếp tục trả nội dung cũ.  
**Cách sửa:** Event publish bền vững, versioned keys hoặc distributed invalidation, CDN purge theo key/tag và retry có giám sát.

### Medium — Cache stampede và memory pressure

**Vấn đề:** Cache miss đồng thời gọi CMS nhiều lần, cache không có size bound.  
**Tại sao xảy ra:** Không có single-flight/bounded cache.  
**Ảnh hưởng production:** Origin tăng tải, memory/GC xấu đi.  
**Cách sửa:** Bounded cache hoặc output cache được quản lý, request coalescing theo key; đo trước khi chọn distributed cache.

### Medium — ETag và conditional request chưa hoàn chỉnh

**Vấn đề:** Gán revision tùy ý làm ETag và không xử lý `If-None-Match`.  
**Tại sao xảy ra:** Chưa chuẩn hóa strong/weak validator và representation variants.  
**Ảnh hưởng production:** Revalidation sai hoặc không hiệu quả.  
**Cách sửa:** Dùng validator hợp lệ cho representation cụ thể; middleware/output caching hỗ trợ conditional requests.

### Medium — Cancellation và lỗi CMS chưa được quản lý

**Vấn đề:** Không truyền `RequestAborted`, không định nghĩa timeout/fallback.  
**Tại sao xảy ra:** Dependency call thiếu resilience policy.  
**Ảnh hưởng production:** Tốn tài nguyên khi client ngắt kết nối; lỗi upstream làm tăng latency.  
**Cách sửa:** Propagate cancellation, timeout có giới hạn, circuit breaker khi phù hợp; chỉ stale fallback cho public content được cho phép.

### Medium — HTML chưa có hợp đồng an toàn

**Vấn đề:** `page.Html` trả thẳng mà không xác định trust/sanitization.  
**Tại sao xảy ra:** Ranh giới CMS editor, renderer và browser chưa rõ.  
**Ảnh hưởng production:** Stored XSS nếu nội dung chứa HTML không tin cậy và frontend render trực tiếp.  
**Cách sửa:** Áp dụng sanitization theo content policy, CSP và safe rendering; không giả định JSON serialization tự chống XSS khi client chèn HTML.

## Phiên bản đề xuất

Thiết kế tách riêng public và preview; ví dụ dưới đây minh họa phần origin. `ICmsContentClient` và `IContentCache` là abstraction ứng dụng, không phải API cụ thể của Optimizely.

```csharp
[ApiController]
[Route("api/content")]
public sealed class ContentController(
    ICmsContentClient cms,
    IContentCache cache) : ControllerBase
{
    [HttpGet("published/{slug}")]
    public async Task<IActionResult> Published(
        string slug, [FromQuery] string locale, CancellationToken ct)
    {
        if (!SupportedLocales.Contains(locale))
            return BadRequest();

        var key = $"published:v2:{locale}:{slug}";
        var page = await cache.GetOrCreatePublishedAsync(
            key, token => cms.GetPublishedAsync(slug, locale, token), ct);
        if (page is null) return NotFound();

        Response.Headers.CacheControl = "public, max-age=60, s-maxage=300";
        return Ok(new { page.Title, page.SafeHtml, page.Revision });
    }

    [Authorize(Policy = "CmsEditor")]
    [HttpGet("preview/{slug}")]
    public async Task<IActionResult> Preview(
        string slug, [FromQuery] string locale, CancellationToken ct)
    {
        Response.Headers.CacheControl = "private, no-store";
        var page = await cms.GetPreviewForEditorAsync(
            slug, locale, User, ct);
        return page is null ? NotFound() :
            Ok(new { page.Title, page.SafeHtml, page.Revision });
    }

    private static readonly HashSet<string> SupportedLocales =
        new(StringComparer.OrdinalIgnoreCase) { "en", "vi" };
}
```

`IContentCache` phải thực hiện bounded caching, tránh stampede, chỉ lưu public published pages; publish handler cần xác thực event, cập nhật version/invalidate origin trên mọi replica và yêu cầu Akamai purge theo policy. Nếu personalization dựa trên user identity, không đưa vào shared cache. `SafeHtml` là kết quả của pipeline sanitization đáng tin cậy; không phải đổi tên property là đủ.

## Giải thích thiết kế sau khi sửa

Ranh giới quyền được xác định trước cache. Public cache chỉ lưu representation có thể chia sẻ; preview luôn bypass shared cache. TTL ngắn hạn là safety net, không thay thế invalidation. Nếu cần SEO ổn định, đảm bảo canonical URLs, đúng locale, published-only sitemap và tránh preview được index.

## Trade-offs

TTL ngắn giảm stale window nhưng tăng origin traffic; purge event tăng độ phức tạp và phải xử lý mất event. Bounded in-memory cache có thể đủ cho traffic nhỏ; distributed cache chỉ đáng dùng nếu đo được lợi ích. `no-store` cho preview đánh đổi latency lấy isolation.

## Cách kiểm thử

1. Security test: anonymous và non-editor không đọc được preview kể cả sau khi editor đã truy cập.
2. Integration test: cùng slug khác locale/audience không rò representation.
3. Multi-instance test: publish/purge invalidates origin replicas và CDN, kể cả retry event.
4. Load test: 1.000 concurrent cache misses không tạo 1.000 CMS requests.
5. Browser/E2E test: unpublished page không nằm trong sitemap, preview không bị shared-cache và HTML độc hại không thực thi.

## Quan sát trong production

Theo dõi Akamai cache status/age, cache hit ratio theo variant, CMS dependency latency và error rate, purge event lag/failure, origin CPU/GC, số lần truy cập preview bị từ chối, synthetic probes cho published revision. Dùng correlation ID nối publish event, purge và request; không log nội dung preview nhạy cảm.

## Câu hỏi phỏng vấn mở rộng

1. Khi Akamai purge API lỗi trong 20 phút, bạn chọn stale-while-revalidate hay fail closed cho loại nội dung nào?
2. Nếu traffic 95% là anonymous nhưng 5% personalized, bạn thiết kế cache variation ra sao để tránh cardinality explosion?
3. Làm thế nào chứng minh không có cross-tenant cache leakage?

# Code Review Challenge 2 — Rolling deployment Kubernetes làm mất tác vụ xuất báo cáo

**Chủ đề:** .NET 8 BackgroundService, Kubernetes, graceful shutdown, job ownership  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 45 phút  
**Số vấn đề cần tìm:** khoảng 9

## Bối cảnh

Dịch vụ báo cáo chạy 6 pods trên Kubernetes, đọc hàng đợi công việc trong PostgreSQL và xuất CSV lên Azure Blob Storage. Khi rolling deployment hoặc pod bị OOMKilled, người dùng thấy báo cáo treo ở `Running`, một số báo cáo được xuất hai lần. Mỗi job có thể mất 8 phút; termination grace period hiện là 30 giây. Không giả định Blob upload là atomic đối với toàn bộ workflow.

## Đoạn code cần review

```csharp
public sealed class ExportWorker(
    IServiceScopeFactory scopes,
    IBlobExportClient blobs,
    ILogger<ExportWorker> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            using var scope = scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<ReportDbContext>();

            var jobs = await db.ExportJobs
                .Where(x => x.Status == "Pending")
                .OrderBy(x => x.CreatedAt)
                .Take(10)
                .ToListAsync(stoppingToken);

            foreach (var job in jobs)
            {
                job.Status = "Running";
                await db.SaveChangesAsync(stoppingToken);

                try
                {
                    var bytes = await BuildCsvAsync(db, job.ReportId);
                    await blobs.UploadAsync($"exports/{job.Id}.csv", bytes);
                    job.Status = "Completed";
                    await db.SaveChangesAsync(stoppingToken);
                }
                catch (Exception ex)
                {
                    logger.LogError(ex, "Export failed {JobId}", job.Id);
                    job.Status = "Pending";
                    await db.SaveChangesAsync(CancellationToken.None);
                }
            }

            await Task.Delay(TimeSpan.FromSeconds(5), stoppingToken);
        }
    }

    private static async Task<byte[]> BuildCsvAsync(
        ReportDbContext db, Guid reportId)
    {
        var rows = await db.ReportRows
            .Where(x => x.ReportId == reportId)
            .ToListAsync();
        return Encoding.UTF8.GetBytes(
            string.Join("\n", rows.Select(x => $"{x.Name},{x.Amount}")));
    }
}
```

## Kết quả code review tham khảo

### Critical — Claim job không atomic

**Vấn đề:** Nhiều pods đọc cùng `Pending`, sau đó cùng đặt `Running`.  
**Tại sao xảy ra:** Select rồi update không có compare-and-swap/row lock.  
**Ảnh hưởng production:** Trùng export, ghi đè Blob, tính toán lãng phí.  
**Cách sửa:** Atomic claim bằng PostgreSQL `FOR UPDATE SKIP LOCKED` trong transaction ngắn hoặc conditional update; cấp lease token duy nhất.

### High — Job bị kẹt sau crash

**Vấn đề:** `Running` không có lease expiry/recovery.  
**Tại sao xảy ra:** Worker chết không chạy catch/finally.  
**Ảnh hưởng production:** Báo cáo treo vĩnh viễn.  
**Cách sửa:** LeaseUntil + heartbeat, reclaim khi hết lease, retry budget và terminal failure.

### High — Side effect Blob không idempotent

**Vấn đề:** Upload rồi mới commit completion; crash giữa hai bước tạo duplicate processing.  
**Tại sao xảy ra:** DB và Blob không chung transaction.  
**Ảnh hưởng production:** Blob overwrite và kết quả không nhất quán.  
**Cách sửa:** Upload tới attempt-specific temporary object, kiểm tra lease token trước khi publish canonical pointer; sử dụng conditional writes/version nếu cần.

### High — Shutdown không truyền cancellation

**Vấn đề:** `BuildCsvAsync` và `UploadAsync` không nhận token.  
**Tại sao xảy ra:** Worker không propagate cancellation xuyên I/O.  
**Ảnh hưởng production:** Pod bị kill khi job đang chạy, tăng retry và thời gian phục hồi.  
**Cách sửa:** Truyền token, cấu hình grace period phù hợp và thiết kế restart-safe thay vì dựa vào graceful shutdown.

### High — Retry vô hạn và bắt cả cancellation

**Vấn đề:** Bắt `Exception` rồi đặt `Pending` cho mọi lỗi.  
**Tại sao xảy ra:** Không phân loại transient/permanent, không backoff và không giới hạn attempt.  
**Ảnh hưởng production:** Poison job gây loop, nghẽn queue.  
**Cách sửa:** Phân loại lỗi, `NextAttemptAt`, exponential backoff có jitter, dead-letter/Failed sau ngưỡng; không nuốt cancellation.

### Medium — Memory và throughput không giới hạn theo kích thước báo cáo

**Vấn đề:** `ToListAsync` và `byte[]` giữ toàn bộ CSV trong memory.  
**Tại sao xảy ra:** Buffer toàn bộ dữ liệu.  
**Ảnh hưởng production:** LOH/GC, OOMKilled, chậm ở dataset lớn.  
**Cách sửa:** Stream query theo batch và ghi CSV streaming vào Blob, giới hạn concurrency và memory.

### Medium — CSV escaping và formula injection

**Vấn đề:** Nối chuỗi trực tiếp.  
**Tại sao xảy ra:** Không quote/escape CSV, không có spreadsheet formula policy.  
**Ảnh hưởng production:** File sai cột hoặc công thức không tin cậy chạy khi mở bằng spreadsheet.  
**Cách sửa:** CSV writer chuẩn, escape theo RFC 4180, áp dụng policy neutralize formula khi file dùng trong spreadsheet.

### Medium — Trạng thái lưu không gắn với owner

**Vấn đề:** Worker cũ có thể ghi `Completed` sau khi lease được cấp cho worker mới.  
**Tại sao xảy ra:** Không có fencing token/conditional completion.  
**Ảnh hưởng production:** Old attempt ghi đè kết quả mới.  
**Cách sửa:** `UPDATE ... WHERE id=@id AND lease_token=@token`, kiểm tra affected rows.

### Medium — Telemetry thiếu độ trễ và trạng thái attempt

**Vấn đề:** Chỉ log exception và job ID.  
**Tại sao xảy ra:** Không theo dõi queue lag, lease expiry, attempt, blob bytes.  
**Ảnh hưởng production:** Không phân biệt queue starvation, DB contention, Blob outage.  
**Cách sửa:** Structured logs, metrics, trace spans theo job/attempt; không log nội dung báo cáo.

## Phiên bản đề xuất

Phác thảo thiết kế cải tiến: DB claim phải được triển khai bằng SQL transaction ngắn; code sau cố ý dùng abstraction để thể hiện ranh giới đúng, không ngụ ý `IExportJobStore` là thư viện có sẵn.

```csharp
public sealed class ExportWorker(
    IExportJobStore jobs,
    IStreamingReportExporter exporter,
    ILogger<ExportWorker> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            var lease = await jobs.TryClaimAsync(
                leaseDuration: TimeSpan.FromMinutes(2), ct);
            if (lease is null)
            {
                await Task.Delay(TimeSpan.FromSeconds(3), ct);
                continue;
            }

            try
            {
                await using var heartbeat = await jobs.StartHeartbeatAsync(
                    lease, ct);
                var artifact = await exporter.WriteAttemptArtifactAsync(
                    lease.JobId, lease.Token, ct);
                var published = await jobs.TryCompleteAsync(
                    lease.JobId, lease.Token, artifact, ct);
                if (!published)
                    logger.LogWarning("Lease lost {JobId}", lease.JobId);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                throw;
            }
            catch (Exception ex)
            {
                logger.LogError(ex, "Export failed {JobId}", lease.JobId);
                await jobs.TryScheduleRetryAsync(
                    lease.JobId, lease.Token, ex, ct);
            }
        }
    }
}
```

**Yêu cầu implementation của abstraction:** `TryClaimAsync` dùng transaction và `SKIP LOCKED`/conditional update để claim đúng một owner, gắn `LeaseUntil`, `Token`, `Attempt`. Heartbeat gia hạn có điều kiện theo token; mất lease phải cancel work nếu có thể. `TryCompleteAsync` chỉ cập nhật DB khi token vẫn hợp lệ; artifact được lưu với tên chứa attempt token và không công khai cho đến khi pointer DB được commit. Cần cleanup orphan artifacts theo lifecycle policy. `TryScheduleRetryAsync` cũng conditional theo token và không được che mất lỗi gốc. Khi lỗi recovery DB xảy ra, lease hết hạn sẽ cho phép claim lại. Nếu yêu cầu exactly-once visible result, chỉ publish qua pointer DB tới artifact bất biến, không coi upload đơn lẻ là exactly-once.

## Giải thích thiết kế sau khi sửa

Lease có hạn giải quyết crash recovery; fencing bảo vệ khi worker cũ tiếp tục chạy. Artifact bất biến tách upload khỏi publication. Retry an toàn dựa trên idempotent visibility thay vì giả định task chạy một lần. Với tải nhỏ, PostgreSQL queue có thể đủ; không cần tự động chuyển sang Service Bus hay Kubernetes-native queue.

## Trade-offs

Heartbeat tăng DB writes; lease quá ngắn gây reclaim sớm, quá dài tăng recovery time. Temporary artifacts tốn storage và cần cleanup. Streaming giảm memory nhưng làm test và lỗi giữa stream phức tạp hơn. Tăng termination grace period cải thiện shutdown nhưng không thay thế crash-safe design.

## Cách kiểm thử

1. Concurrency test: 20 workers claim 1.000 jobs, không có hai owner hợp lệ cùng thời điểm cho một job.
2. Failure injection: kill pod sau Blob upload trước DB completion; chỉ một artifact được public qua pointer.
3. Lease test: worker cũ resume sau expiry nhưng không thể complete job của owner mới.
4. Load test: xuất báo cáo lớn với memory bounded, đo LOH/GC, latency và throughput.
5. Security/data test: CSV chứa comma/newline/quotes/formula và kiểm tra kết quả an toàn.

## Quan sát trong production

Metrics: pending/running/failed jobs, queue age p95, lease expired, reclaim count, attempts/job, export duration p95, bytes exported, orphan artifacts, Blob dependency errors, DB lock waits, pod restarts/OOMKilled. Traces nối job ID và attempt token (không log secrets). Alerts khi queue age vượt SLO, failure rate tăng hoặc số job expired tăng bất thường.

## Câu hỏi phỏng vấn mở rộng

1. Khi export mất 30 phút và heartbeat DB outage 5 phút, làm sao tránh split-brain ownership?
2. Nếu người dùng nhấn cancel giữa upload, API và worker phối hợp trạng thái thế nào?
3. Khi nào bạn chuyển từ PostgreSQL queue sang Azure Service Bus và tiêu chí đo lường là gì?

# Tổng kết hôm nay

## Kiến thức trọng tâm

Cache là một ranh giới dữ liệu và authorization, không chỉ là tối ưu hiệu năng. Công việc background trên nhiều replicas cần durable ownership, lease expiry, fencing và idempotent publication; graceful shutdown không đủ bảo vệ trước crash.

## Mẫu tư duy cần nhớ

1. Xác định identity, audience và publication state trước khi thiết kế cache key.
2. Xem xét mọi lớp cache: process, CDN, browser; invalidation phải có kiểm chứng.
3. Tách claim, execution và publish thành các bước có thể recovery.
4. Giả định process có thể chết ở bất kỳ điểm nào giữa hai side effects.
5. Đo queue lag, dependency latency và cache leakage risk trước khi tối ưu.
