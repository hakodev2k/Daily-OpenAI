# Code Review Challenge 1 — Kubernetes health check gây restart storm

**Chủ đề:** .NET 8, ASP.NET Core, EF Core, Kubernetes, PostgreSQL  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 40 phút  
**Số vấn đề cần tìm:** khoảng 8

## Bối cảnh

Order API chạy 6 Pods. Mỗi rolling deployment xuất hiện HTTP 503, Pod restart và database connection spike. PostgreSQL đôi khi gián đoạn 20 giây. Schema migration do CI/CD quản lý. Yêu cầu giữ traffic khỏi Pod chưa ready mà không restart process khỏe chỉ vì DB outage. Chưa xác nhận startup duration.

## Đoạn code cần review

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<OrderDbContext>(o =>
    o.UseNpgsql(builder.Configuration.GetConnectionString("Orders")));
builder.Services.AddHealthChecks().AddDbContextCheck<OrderDbContext>("db");
builder.Services.AddHostedService<WarmupWorker>();
var app = builder.Build();
app.MapGet("/health", async (OrderDbContext db) =>
{
    await db.Database.MigrateAsync();
    return Results.Ok(await db.Orders.CountAsync());
});
app.MapHealthChecks("/ready");
app.MapHealthChecks("/live");
app.MapControllers();
app.Run();

public sealed class WarmupWorker(IServiceProvider services) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (true)
        {
            using var scope = services.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<OrderDbContext>();
            var rows = await db.Orders.OrderByDescending(x => x.Id)
                .Take(10000).ToListAsync();
            await Task.Delay(2000);
        }
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Schema migration trong health endpoint

**Vấn đề:** Mỗi probe có thể chạy `MigrateAsync`.  
**Tại sao xảy ra:** Endpoint kiểm tra lại mutate schema.  
**Ảnh hưởng production:** Migration race, locks, probe timeout, downtime.  
**Cách sửa:** Migration riêng trong deployment step có rollback/compatibility plan.

### [High] — Liveness phụ thuộc database

**Vấn đề:** `/live` và `/ready` chạy cùng DB check.  
**Tại sao xảy ra:** Không lọc checks theo tags.  
**Ảnh hưởng production:** DB outage gây restart storm.  
**Cách sửa:** Liveness không kiểm tra DB; readiness kiểm tra critical dependency với timeout thích hợp.

### [High] — Probe dùng sai endpoint

**Vấn đề:** readiness gọi /health; liveness gọi /ready.  
**Tại sao xảy ra:** Cấu hình lệch semantics.  
**Ảnh hưởng production:** 503 và restart không cần thiết.  
**Cách sửa:** Trỏ đúng /ready và /live.

### [High] — Worker bỏ qua cancellation

**Vấn đề:** while(true), EF query và delay không truyền token.  
**Tại sao xảy ra:** Không tuân thủ graceful shutdown.  
**Ảnh hưởng production:** Request/DB work còn chạy khi Pod bị terminate.  
**Cách sửa:** Kiểm tra ct, truyền ct vào EF và Task.Delay, xử lý shutdown cancellation.

### [Medium] — Warmup tốn tài nguyên

**Vấn đề:** Mỗi 2 giây tải 10.000 tracked entities mà không dùng kết quả.  
**Tại sao xảy ra:** Không có mục tiêu cache rõ ràng.  
**Ảnh hưởng production:** DB QPS, allocation và connection pressure.  
**Cách sửa:** Bỏ worker nếu không cần; nếu cần, projection/AsNoTracking và bounded schedule.

### [Medium] — Health query quá nặng

**Vấn đề:** Count toàn bộ Orders để đo health.  
**Tại sao xảy ra:** Nhầm business query với connectivity check.  
**Ảnh hưởng production:** Tăng database workload.  
**Cách sửa:** Dùng check nhẹ và đo duration.

### [Medium] — Startup/shutdown budget chưa đủ căn cứ

**Vấn đề:** Grace period 5s và liveness threshold thấp.  
**Tại sao xảy ra:** Không đo startup và drain duration.  
**Ảnh hưởng production:** Kill process sớm, cắt in-flight requests.  
**Cách sửa:** Đo trước khi chọn startupProbe và grace period.

## Phiên bản đề xuất

```csharp
var builder = WebApplication.CreateBuilder(args);
builder.Services.AddDbContext<OrderDbContext>(o =>
    o.UseNpgsql(builder.Configuration.GetConnectionString("Orders")));
builder.Services.AddHealthChecks()
    .AddDbContextCheck<OrderDbContext>("db", tags: new[] { "ready" });
var app = builder.Build();
app.MapHealthChecks("/live", new HealthCheckOptions
{
    Predicate = _ => false
});
app.MapHealthChecks("/ready", new HealthCheckOptions
{
    Predicate = c => c.Tags.Contains("ready")
});
app.MapControllers();
app.Run();
```

```yaml
startupProbe:
  httpGet: { path: /live, port: 8080 }
  periodSeconds: 5
  failureThreshold: 24
readinessProbe:
  httpGet: { path: /ready, port: 8080 }
  periodSeconds: 10
  timeoutSeconds: 3
livenessProbe:
  httpGet: { path: /live, port: 8080 }
  periodSeconds: 10
  failureThreshold: 3
terminationGracePeriodSeconds: 30
```

Cần `using Microsoft.AspNetCore.Diagnostics.HealthChecks;`. Probe timings là giả định khởi điểm, phải đo và hiệu chỉnh. Nếu giữ worker, dùng `while (!ct.IsCancellationRequested)`, `ToListAsync(ct)`, `Task.Delay(interval, ct)` và giới hạn workload. Không chạy migration trong API.

## Giải thích thiết kế sau khi sửa

Tách health semantics khỏi deployment side effects. Database outage không đồng nghĩa process đã chết. Readiness giúp tạm ngừng nhận traffic; migration chạy độc lập. Liveness HTTP 200 không phát hiện mọi dạng deadlock nên cần thêm telemetry.

## Trade-offs

Readiness dựa DB có thể làm mọi Pod unready khi outage toàn vùng; nếu có degraded mode, cân nhắc readiness theo capability. StartupProbe tăng thời gian chờ phát hiện lỗi startup thật. Pipeline migration riêng tăng thao tác nhưng giảm rủi ro cạnh tranh.

## Cách kiểm thử

1. Integration test: DB down, /live vẫn 200 còn /ready unhealthy.
2. Failure injection: mất DB 30 giây không tạo restart storm.
3. Rolling deployment 6 Pods: đo 503, readiness transitions.
4. SIGTERM khi đang query: xác minh graceful shutdown.
5. Load test: so sánh DB QPS và p95 trước/sau.

## Quan sát trong production

Kubernetes events, restart count, Pod readiness, HTTP 503, DB connections/locks, query duration, Application Insights dependency traces. Correlate với deployment timestamp; alert trên restart và 503 spikes.

## Câu hỏi phỏng vấn mở rộng

1. Thiết kế expand/contract migration khi hai phiên bản cùng chạy?
2. Khi DB outage toàn vùng, readiness nên fail hay hỗ trợ degraded mode?
3. Phát hiện worker deadlock nếu /live vẫn trả 200 thế nào?

# Code Review Challenge 2 — Vue search hiển thị kết quả tenant cũ

**Chủ đề:** Vue 3, TypeScript, REST API, race condition, XSS  
**Độ khó:** Senior  
**Thời gian review đề xuất:** 35 phút  
**Số vấn đề cần tìm:** khoảng 7

## Bối cảnh

Portal tuyển dụng dùng Vue 3, API ASP.NET Core và Microsoft Entra ID. Người dùng gõ tìm kiếm liên tục, đổi tenant trong một tab. Một số kết quả nhảy về query cũ; notes là user-generated content. API phải enforce tenant authorization. Chưa xác định pagination contract.

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue'
type Result = { id: string; title: string; notes: string }
const props = defineProps<{ tenantId: string; token: string }>()
const query = ref('')
const results = ref<Result[]>([])
const loading = ref(false)
const error = ref('')

async function search() {
  loading.value = true
  error.value = ''
  const response = await fetch(
    `/api/tenants/${props.tenantId}/requisitions?q=${query.value}`,
    { headers: { Authorization: `Bearer ${props.token}` } }
  )
  const data = await response.json()
  results.value = data.items
  loading.value = false
}
watch(query, search)
onMounted(search)
</script>

<template>
  <input v-model="query" />
  <span v-if="loading">Loading...</span>
  <p v-if="error">{{ error }}</p>
  <ul>
    <li v-for="item in results" :key="item.id">
      <strong>{{ item.title }}</strong>
      <div v-html="item.notes"></div>
    </li>
  </ul>
</template>
```

## Kết quả code review tham khảo

### [Critical] — Stored XSS qua v-html

**Vấn đề:** notes từ người dùng được render như HTML.  
**Tại sao xảy ra:** v-html không tự escape nội dung.  
**Ảnh hưởng production:** Script injection và thao tác trái phép trong browser.  
**Cách sửa:** Dùng `{{ item.notes }}`; nếu rich text bắt buộc, sanitize bằng policy và library phù hợp.

### [High] — Race condition giữa các request

**Vấn đề:** Response cũ có thể ghi đè response mới.  
**Tại sao xảy ra:** Không cancellation hoặc request generation guard.  
**Ảnh hưởng production:** Kết quả sai, có thể hiển thị dữ liệu context cũ.  
**Cách sửa:** Abort request trước và guard trước khi cập nhật state.

### [High] — Tenant/token change không trigger search

**Vấn đề:** Watcher chỉ quan sát query.  
**Tại sao xảy ra:** Không theo dõi props.  
**Ảnh hưởng production:** UI hiển thị dữ liệu tenant cũ.  
**Cách sửa:** Watch query, tenantId, token; clear results khi context đổi. Backend phải kiểm tra authorization trên từng request.

### [Medium] — HTTP failure không được xử lý

**Vấn đề:** fetch không throw cho 4xx/5xx.  
**Tại sao xảy ra:** Không kiểm tra response.ok và response schema.  
**Ảnh hưởng production:** UI lỗi hoặc hiển thị sai.  
**Cách sửa:** Kiểm tra status và validate payload.

### [Medium] — Spinner bị kẹt khi network error

**Vấn đề:** Không có try/catch/finally.  
**Tại sao xảy ra:** Promise rejection bỏ qua cleanup.  
**Ảnh hưởng production:** Loading vô hạn.  
**Cách sửa:** try/catch/finally và request identity guard.

### [Medium] — Query không encode

**Vấn đề:** Ký tự &, # có thể làm sai query string.  
**Tại sao xảy ra:** Nối trực tiếp input vào URL.  
**Ảnh hưởng production:** Search sai hoặc mất parameter.  
**Cách sửa:** URLSearchParams.

### [Low] — Request burst

**Vấn đề:** Mỗi ký tự tạo request.  
**Tại sao xảy ra:** Không debounce, pagination hoặc limit.  
**Ảnh hưởng production:** Tăng API load.  
**Cách sửa:** Debounce và enforce page size server-side.

## Phiên bản đề xuất

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue'
type Result = { id: string; title: string; notes: string }
const props = defineProps<{ tenantId: string; token: string }>()
const query = ref('')
const results = ref<Result[]>([])
const loading = ref(false)
const error = ref('')
let abort: AbortController | undefined
let timer: ReturnType<typeof setTimeout> | undefined
let version = 0

watch([query, () => props.tenantId, () => props.token], () => {
  const currentVersion = ++version
  abort?.abort()
  if (timer) clearTimeout(timer)
  results.value = []
  error.value = ''
  loading.value = true
  timer = setTimeout(async () => {
    const controller = new AbortController()
    abort = controller
    try {
      const params = new URLSearchParams({ q: query.value, limit: '30' })
      const tenant = encodeURIComponent(props.tenantId)
      const response = await fetch(
        `/api/tenants/${tenant}/requisitions?${params}`,
        { headers: { Authorization: `Bearer ${props.token}` },
          signal: controller.signal }
      )
      if (!response.ok) throw new Error(`HTTP ${response.status}`)
      const data: unknown = await response.json()
      if (!data || typeof data !== 'object' ||
          !('items' in data) || !Array.isArray(data.items))
        throw new Error('Invalid response')
      if (currentVersion === version)
        results.value = data.items as Result[]
    } catch {
      if (currentVersion === version && !controller.signal.aborted)
        error.value = 'Không thể tải kết quả'
    } finally {
      if (currentVersion === version) loading.value = false
    }
  }, 250)
}, { immediate: true })

onUnmounted(() => {
  version++
  abort?.abort()
  if (timer) clearTimeout(timer)
})
</script>

<template>
  <input v-model="query" />
  <span v-if="loading">Loading...</span>
  <p v-if="error">{{ error }}</p>
  <ul>
    <li v-for="item in results" :key="item.id">
      <strong>{{ item.title }}</strong>
      <div>{{ item.notes }}</div>
    </li>
  </ul>
</template>
```

Đây là skeleton; production cần schema validation cho từng item, token lifecycle và authorization server-side. Không log bearer token.

## Giải thích thiết kế sau khi sửa

Abort giảm network work; version guard ngăn response cũ ghi state ngay cả khi abort không kịp. Reset results ngay khi tenant đổi giảm nguy cơ hiển thị dữ liệu context cũ. Server vẫn chịu trách nhiệm tenant isolation.

## Trade-offs

Debounce giảm load nhưng tăng search latency. Clear results có thể gây nhấp nháy; nếu giữ cache theo tenant cần key gắn principal và invalidation. Abort không bảo đảm backend ngừng xử lý, vì vậy server cần timeout, cancellation và rate limit.

## Cách kiểm thử

1. Component test: request A về sau B, UI phải hiển thị B.
2. Playwright E2E: đổi tenant khi request đang pending.
3. Security test: HTML trong notes chỉ hiển thị plain text.
4. Failure-path test: 403/500, network reject và invalid payload.
5. API load test: gõ nhanh, đo request count và pagination.

## Quan sát trong production

Browser network waterfall, API p95, request count, 401/403/5xx, frontend error categories, aborted requests và correlation ID tới Application Insights. Không ghi token hoặc dữ liệu notes nhạy cảm trong telemetry.

## Câu hỏi phỏng vấn mở rộng

1. Cache client theo tenant/principal cần key và invalidation như thế nào?
2. Refresh token giữa request ảnh hưởng UI ra sao?
3. Khi nào chọn server-side search thay vì client filtering?
