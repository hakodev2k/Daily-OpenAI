# Code Review Challenge 1 — Export timesheet làm cạn memory và lộ dữ liệu

## Bối cảnh

Một hệ thống nhân sự xuất báo cáo timesheet theo department và khoảng ngày. Dữ liệu có thể vượt 2 triệu dòng; 4 Azure App Service instances dùng chung SQL Server. Sau khi triển khai export, memory tăng, p95 các API khác xấu đi và một số file CSV có cột lệch. Người dùng chỉ được xuất dữ liệu của department mình có quyền. Chưa có giới hạn khoảng ngày hoặc hợp đồng về snapshot consistency.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/reports")]
public sealed class ReportsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<ReportsController> _log;

    public ReportsController(AppDbContext db, ILogger<ReportsController> log)
    {
        _db = db;
        _log = log;
    }

    [HttpGet("timesheets.csv")]
    public async Task<IActionResult> Export(
        DateTime from, DateTime to, int departmentId)
    {
        var records = await _db.Timesheets
            .Include(x => x.Employee)
            .Where(x => x.DepartmentId == departmentId
                && x.WorkDate >= from && x.WorkDate <= to)
            .OrderBy(x => x.WorkDate)
            .ToListAsync();

        var output = new StringBuilder("Name,Date,Hours,Note\n");
        foreach (var record in records)
        {
            output.Append(record.Employee.DisplayName).Append(',')
                .Append(record.WorkDate.ToString("yyyy-MM-dd")).Append(',')
                .Append(record.Hours).Append(',')
                .Append(record.Note).Append('\n');
        }

        _log.LogInformation("Export {Count} rows for {Department}",
            records.Count, departmentId);
        return File(Encoding.UTF8.GetBytes(output.ToString()),
            "text/csv", "timesheets.csv");
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Broken object-level authorization

**Vấn đề:** departmentId được client tự chọn, không xác minh quyền.  
**Tại sao xảy ra:** Chỉ lọc theo ID, không có authorization policy và resource authorization.  
**Ảnh hưởng production:** Lộ thông tin chấm công giữa các phòng ban.  
**Cách sửa:** Authenticate và kiểm tra quyền export department trước truy vấn, dùng trusted server-side mapping.

### [High] — Memory tăng theo kích thước toàn bộ export

**Vấn đề:** ToListAsync, StringBuilder, ToString và GetBytes tạo nhiều bộ nhớ đồng thời.  
**Tại sao xảy ra:** Materialization và buffering toàn bộ response.  
**Ảnh hưởng production:** GC pressure, OOM, 502 và ảnh hưởng các request khác.  
**Cách sửa:** Projection + AsNoTracking + streaming; export rất lớn dùng background job + Blob Storage.

### [High] — CSV escaping và formula injection

**Vấn đề:** Dấu phẩy, quote, newline phá cấu trúc CSV; giá trị bắt đầu bằng =,+,-,@ có nguy cơ được spreadsheet diễn giải thành công thức.  
**Tại sao xảy ra:** Ghép chuỗi thô.  
**Ảnh hưởng production:** Báo cáo sai và nguy cơ thao tác không mong muốn khi mở spreadsheet.  
**Cách sửa:** Serializer CSV chuẩn RFC 4180 và policy formula mitigation được kiểm thử theo ứng dụng tiêu thụ.

### [High] — Không hỗ trợ cancellation

**Vấn đề:** SQL query không nhận CancellationToken.  
**Tại sao xảy ra:** Không truyền RequestAborted.  
**Ảnh hưởng production:** Client đã ngắt nhưng SQL vẫn làm việc.  
**Cách sửa:** Truyền token xuyên suốt query và response writer; xử lý cancellation riêng với lỗi server.

### [Medium] — Date boundary không rõ

**Vấn đề:** <= to có thể loại dữ liệu trong ngày cuối nếu to là midnight.  
**Tại sao xảy ra:** Không quy định timezone và inclusive/exclusive.  
**Ảnh hưởng production:** Thiếu giờ công.  
**Cách sửa:** Dùng khoảng [from, toExclusive) với timezone nghiệp vụ rõ ràng.

### [Medium] — Query load thừa và tracking

**Vấn đề:** Include + tracking toàn bộ Employee và Timesheet.  
**Tại sao xảy ra:** Không projection, không AsNoTracking.  
**Ảnh hưởng production:** SQL payload và allocation tăng.  
**Cách sửa:** Select các cột cần thiết; kiểm tra execution plan và index dựa trên filter/order.

### [Medium] — Thiếu quota và admission control

**Vấn đề:** Có thể export nhiều năm hoặc mở nhiều download song song.  
**Tại sao xảy ra:** Thiếu validation, concurrency limit và rate limit.  
**Ảnh hưởng production:** Cạn connection pool, bão hòa SQL.  
**Cách sửa:** Giới hạn ngày, quota theo user, điều phối export lớn qua job queue.

### [Medium] — Culture và consistency chưa định nghĩa

**Vấn đề:** Hours có thể format theo locale; stream dài có thể thấy dữ liệu thay đổi.  
**Tại sao xảy ra:** Không có output contract và snapshot requirement.  
**Ảnh hưởng production:** CSV khó parse, kết quả không nhất quán.  
**Cách sửa:** InvariantCulture và thống nhất snapshot/version watermark nếu nghiệp vụ cần.

## Phiên bản đề xuất

Ví dụ dưới đây giả định đã đăng ký IReportAccess và ICsvFieldEncoder; ICsvFieldEncoder phải implement CSV quoting và chính sách chống formula injection. Streaming trực tiếp chỉ dành cho export nhỏ trong giới hạn đã đo; các lỗi xảy ra sau khi response bắt đầu có thể khiến download bị ngắt, không thể đổi status.

```csharp
[Authorize]
[HttpGet("timesheets.csv")]
public async Task Export(
    DateOnly from, DateOnly to, int departmentId,
    CancellationToken ct)
{
    if (to < from || to.DayNumber - from.DayNumber > 31)
    {
        Response.StatusCode = 400;
        return;
    }
    if (!await _access.CanExportAsync(User, departmentId, ct))
    {
        Response.StatusCode = 403;
        return;
    }

    var start = from.ToDateTime(TimeOnly.MinValue);
    var end = to.AddDays(1).ToDateTime(TimeOnly.MinValue);
    var query = _db.Timesheets.AsNoTracking()
        .Where(x => x.DepartmentId == departmentId &&
            x.WorkDate >= start && x.WorkDate < end)
        .OrderBy(x => x.WorkDate).ThenBy(x => x.Id)
        .Select(x => new {
            x.Employee.DisplayName, x.WorkDate, x.Hours, x.Note
        }).AsAsyncEnumerable();

    Response.ContentType = "text/csv; charset=utf-8";
    Response.Headers.ContentDisposition =
        "attachment; filename=\"timesheets.csv\"";
    await using var writer = new StreamWriter(
        Response.Body, new UTF8Encoding(false), leaveOpen: true);
    await writer.WriteLineAsync("Name,Date,Hours,Note");
    await foreach (var row in query.WithCancellation(ct))
    {
        var fields = new[] {
            _csv.Encode(row.DisplayName),
            _csv.Encode(row.WorkDate.ToString("yyyy-MM-dd",
                CultureInfo.InvariantCulture)),
            _csv.Encode(row.Hours.ToString(CultureInfo.InvariantCulture)),
            _csv.Encode(row.Note ?? "")
        };
        await writer.WriteLineAsync(string.Join(",", fields));
    }
    await writer.FlushAsync(ct);
}
```

## Giải thích thiết kế sau khi sửa

Authorization xảy ra trước truy vấn; projection giảm SQL payload và tracking; streaming giảm peak memory. Giới hạn 31 ngày chỉ là giả định, cần kiểm tra số dòng thực tế. Cần đảm bảo DbContext còn sống trong toàn bộ enumeration và kiểm tra provider thực sự stream. Query vẫn giữ connection trong thời gian client download.

## Trade-offs

Streaming giảm memory nhưng giữ database connection lâu; background export tăng queue/storage complexity nhưng cô lập tải, hỗ trợ retry và download bất đồng bộ. Snapshot consistency có thể tăng chi phí DB. Formula mitigation có thể thay đổi giá trị hiển thị, cần xác nhận downstream contract.

## Cách kiểm thử

1. Security integration: người dùng phòng A yêu cầu department B phải bị 403, không chạy query.
2. CSV test: Unicode, quote, newline, dấu phẩy, formula prefix và round-trip parse.
3. Load test: nhiều export đồng thời, đo RSS/GC/SQL connections và p95 API khác.
4. Failure-path: client disconnect, xác minh cancellation và connection release.
5. Database test: boundary ngày, timezone, query plan và consistency contract.

## Quan sát trong production

Application Insights: duration, bytes, row count, cancellation, error rate, trace ID. Azure Monitor: working set, GC, 5xx, CPU. SQL Server: active connections, logical reads, waits, execution plan. Không log nội dung timesheet. Alert nếu export ảnh hưởng latency API chấm công.

## Kết quả code review tham khảo

### [Critical] — Credential hardcode

**Vấn đề:** Database password trong manifest plaintext.  
**Tại sao xảy ra:** Đặt secret trong env value được commit.  
**Ảnh hưởng production:** Credential có thể bị lộ qua Git và deployment tooling.  
**Cách sửa:** Rotate password; dùng Secret hoặc external secret store với RBAC, encryption at rest và least privilege. Kubernetes Secret không tự đảm bảo encryption at rest.

### [High] — Rolling update làm giảm capacity

**Vấn đề:** maxUnavailable=2 với 3 replicas có thể chỉ còn một Pod available trong rollout.  
**Tại sao xảy ra:** maxSurge=0 không cấp capacity thay thế trước.  
**Ảnh hưởng production:** 503, p99 tăng khi tải cao.  
**Cách sửa:** Nếu có headroom, maxUnavailable=0 và maxSurge=1; validate khả năng scheduling.

### [High] — Probe semantics không được tách

**Vấn đề:** Cùng /health cho liveness/readiness có thể gây restart storm nếu dependency lỗi hoặc gửi traffic vào Pod chưa ready.  
**Tại sao xảy ra:** Không định nghĩa health endpoint theo mục đích.  
**Ảnh hưởng production:** Cascading outage hoặc 500.  
**Cách sửa:** /health/live kiểm tra process viability, /health/ready kiểm tra khả năng phục vụ với dependency policy phù hợp.

### [High] — Startup và graceful shutdown không an toàn

**Vấn đề:** Liveness chạy quá sớm, không có startupProbe, không có termination budget đã kiểm chứng.  
**Tại sao xảy ra:** Timing hardcode, không dựa trên telemetry.  
**Ảnh hưởng production:** Pod bị kill khi warmup hoặc ngắt request đang xử lý.  
**Cách sửa:** StartupProbe, graceful SIGTERM, terminationGracePeriodSeconds, ingress drain; đo duration.

### [Medium] — Mutable latest image

**Vấn đề:** latest không cố định artifact.  
**Tại sao xảy ra:** Không pin digest.  
**Ảnh hưởng production:** Rollback khó tái hiện.  
**Cách sửa:** Pin image SHA256 digest, lưu provenance.

### [Medium] — Resource limits không có evidence

**Vấn đề:** CPU/memory giới hạn tùy ý và thiếu requests.  
**Tại sao xảy ra:** Không đo CPU, RSS, startup.  
**Ảnh hưởng production:** Throttling, OOMKilled, scheduling thiếu ổn định.  
**Cách sửa:** Set requests/limits từ metrics và headroom.

### [Medium] — Thiếu rollout validation

**Vấn đề:** Không có synthetic test, error budget hoặc rollback gate.  
**Tại sao xảy ra:** Coi Running là đủ.  
**Ảnh hưởng production:** Regression lan rộng.  
**Cách sửa:** CI/CD validate rollout status, readiness, traffic và business transaction.

## Phiên bản đề xuất

              path: /health/live
              port: 8080

## Giải thích thiết kế sau khi sửa

MaxUnavailable=0 giữ mục tiêu capacity nhưng yêu cầu thêm một Pod khi rollout. StartupProbe bảo vệ warmup; readiness điều khiển routing; liveness chỉ restart khi process không còn hoạt động đúng. Graceful shutdown cần app xử lý SIGTERM, propagate cancellation và phối hợp endpoint/ingress draining. Immutable digest hỗ trợ audit và rollback.

## Trade-offs

MaxSurge=1 cần cluster headroom; readiness quá phụ thuộc external service có thể làm toàn bộ Pods unready khi dependency outage. Tăng timeout không thay thế đo đạc. Nếu cluster thiếu capacity, cần điều chỉnh kế hoạch release hoặc tăng node trước khi rollout; không mặc định Kubernetes là lựa chọn tốt hơn App Service.

## Cách kiểm thử

1. Deployment validation: rollout dưới traffic liên tục, theo dõi available replicas và 5xx.
2. Failure injection: PostgreSQL/IdP outage; kiểm tra readiness và restart storm.
3. Graceful shutdown: SIGTERM giữa request dài; đo drain và business correctness.
4. Load test: p95/p99, throttling, OOMKilled, startup time.
5. Security: scan manifest/Git và xác minh secret rotation, RBAC.

## Quan sát trong production

Kubernetes: available replicas, Pod readiness, restarts, OOMKilled, CPU throttling, endpoint count và rollout duration. Application Insights/Azure Monitor: ingress 503, request p95/p99, dependency failure, trace ID và image digest. Alert khi available replicas giảm hoặc error budget bị vượt.
