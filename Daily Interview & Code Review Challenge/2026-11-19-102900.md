# Code Review Challenge 1 — Upload CSV đa tenant lên Azure Blob Storage

**Chủ đề:** C#/.NET 8, ASP.NET Core, Azure Blob Storage, authorization, streaming  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 40 phút

## Bối cảnh

API import đơn hàng cho nhiều tenant chạy trên 4 Azure App Service instances. Người dùng chỉ được import vào tenant có quyền `Orders.Import`; file tối đa 25 MiB, CSV UTF-8. Worker xử lý job từ SQL Server sau khi upload. Khi 100 người upload đồng thời, memory tăng và đôi lúc import sai file. Frontend retry khi timeout. Chưa biết chính sách quét file, cấu hình ingress hay tính duy nhất của upload ID.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/tenants/{tenantId}/imports")]
public sealed class ImportsController : ControllerBase
{
    private readonly BlobContainerClient _container;
    private readonly ImportDbContext _db;
    private readonly ILogger<ImportsController> _log;

    public ImportsController(BlobContainerClient container,
        ImportDbContext db, ILogger<ImportsController> log)
    {
        _container = container;
        _db = db;
        _log = log;
    }

    [HttpPost]
    [RequestSizeLimit(200_000_000)]
    public async Task<IActionResult> Upload(
        string tenantId, IFormFile file, string? uploadId)
    {
        if (file.Length == 0) return BadRequest();
        var bytes = new byte[file.Length];
        await using (var stream = file.OpenReadStream())
            await stream.ReadAsync(bytes);

        var blobName = tenantId + "/" + file.FileName;
        var blob = _container.GetBlobClient(blobName);
        await blob.UploadAsync(new MemoryStream(bytes), overwrite: true);

        var job = new ImportJob {
            TenantId = tenantId, BlobName = blobName,
            UploadId = uploadId, Status = "Pending"
        };
        _db.ImportJobs.Add(job);
        await _db.SaveChangesAsync();

        var sas = blob.GenerateSasUri(BlobSasPermissions.Read,
            DateTimeOffset.UtcNow.AddDays(7));
        _log.LogInformation("Uploaded {Tenant} {Sas}", tenantId, sas);
        return Ok(new { job.Id, url = sas.ToString() });
    }
}
```

Giả định `BlobContainerClient` được cấu hình hỗ trợ tạo SAS; đoạn code chỉ là tình huống review, không khẳng định mọi credential đều có thể ký SAS.

## Kết quả code review tham khảo

### Critical — Broken tenant authorization

**Vấn đề:** Không có `[Authorize]` hay kiểm tra permission cho tenant.  
**Tại sao xảy ra:** Client tự cung cấp `tenantId`; model binding không phải authorization.  
**Ảnh hưởng production:** Cross-tenant data contamination và unauthorized upload.  
**Cách sửa:** Authenticate và authorize `Orders.Import` trên tenant trước mọi side effect; worker cũng dùng tenant từ job đã xác minh.

### High — Signed URL lộ trong logs

**Vấn đề:** Trả read SAS 7 ngày, ghi cả URL vào log.  
**Tại sao xảy ra:** SAS là bearer credential trong query string.  
**Ảnh hưởng production:** Người đọc log có thể đọc file nhạy cảm.  
**Cách sửa:** Trả job ID thay vì SAS; nếu cần download, cấp user-delegation SAS ngắn hạn sau authorization, không log URL.

### High — Memory và size limit

**Vấn đề:** Cho request tới 200 MB, tạo mảng bằng toàn bộ file và MemoryStream.  
**Tại sao xảy ra:** Không enforce 25 MiB; `IFormFile` còn có thể đã được buffer.  
**Ảnh hưởng production:** LOH/GC pressure, 500, instance restart.  
**Cách sửa:** Giới hạn tại proxy/action, stream với cancellation; dùng multipart streaming reader nếu cần tránh buffering end-to-end.

### High — Partial stream read

**Vấn đề:** Bỏ qua số byte thực tế trả về bởi `ReadAsync`.  
**Tại sao xảy ra:** Một read không đảm bảo lấp đầy buffer.  
**Ảnh hưởng production:** Blob chứa dữ liệu thiếu hoặc bytes 0.  
**Cách sửa:** Stream trực tiếp; nếu bắt buộc buffer thì dùng read loop hoặc `ReadExactlyAsync`.

### High — Filename collision

**Vấn đề:** Blob key dùng filename do client điều khiển, `overwrite: true`.  
**Tại sao xảy ra:** Không có server-generated unique key.  
**Ảnh hưởng production:** File job trước bị thay thế, mất auditability.  
**Cách sửa:** Key `tenant/Guid.csv` do server cấp, create-only precondition, original filename chỉ là metadata đã sanitize.

### High — Retry tạo duplicate jobs

**Vấn đề:** `uploadId` nullable, không có unique constraint.  
**Tại sao xảy ra:** HTTP retry có thể thực hiện side effect nhiều lần.  
**Ảnh hưởng production:** Import trùng hoặc trạng thái sai.  
**Cách sửa:** Required idempotency key, unique index `(TenantId, UploadId)`, request fingerprint, conflict khi key tái sử dụng với payload khác.

### High — Blob và DB không atomic

**Vấn đề:** Upload thành công rồi SQL lỗi để lại orphan; không có reliable worker dispatch.  
**Tại sao xảy ra:** Hai resource không chung local transaction.  
**Ảnh hưởng production:** Job thất lạc, orphan storage, khó retry.  
**Cách sửa:** State machine `Receiving → Ready → Processing → Completed`, reconciliation, worker idempotent; dùng polling hoặc transactional outbox tùy SLA.

### Medium — Input validation và cancellation thiếu

**Vấn đề:** Không validate CSV schema/encoding/length, không truyền cancellation token.  
**Tại sao xảy ra:** Tin vào metadata client, không có bounded parser.  
**Ảnh hưởng production:** Import lỗi, malicious content, tiếp tục tốn tài nguyên khi client disconnect.  
**Cách sửa:** Validate file content và kích thước, scan/quarantine theo threat model, truyền cancellation, structured logs không chứa PII.

## Phiên bản đề xuất

Đoạn code dùng abstraction `IImportBlobStore` có hợp đồng stream/create-only; `IImportPermission` kiểm tra quyền tenant. Unique index và reconciliation là bắt buộc ở database/worker.

```csharp
[Authorize]
[ApiController]
[Route("api/tenants/{tenantId}/imports")]
public sealed class ImportsController : ControllerBase
{
    private readonly IImportPermission _permission;
    private readonly IImportBlobStore _blobs;
    private readonly ImportDbContext _db;

    public ImportsController(IImportPermission permission,
        IImportBlobStore blobs, ImportDbContext db)
        => (_permission, _blobs, _db) = (permission, blobs, db);

    [HttpPost]
    [RequestSizeLimit(27L * 1024 * 1024)]
    public async Task<IActionResult> Upload(
        string tenantId, IFormFile file,
        [FromHeader(Name = "Idempotency-Key")] string key,
        CancellationToken ct)
    {
        if (!await _permission.CanImportAsync(User, tenantId, ct))
            return Forbid();
        if (string.IsNullOrWhiteSpace(key) || key.Length > 128)
            return BadRequest("Missing idempotency key");
        if (file is null || file.Length <= 0 ||
            file.Length > 25L * 1024 * 1024)
            return BadRequest("Invalid size");
        if (!Path.GetExtension(file.FileName)
            .Equals(".csv", StringComparison.OrdinalIgnoreCase))
            return BadRequest("CSV required");

        var prior = await _db.ImportJobs.AsNoTracking()
            .SingleOrDefaultAsync(x => x.TenantId == tenantId
                && x.UploadId == key, ct);
        if (prior != null)
            return Accepted(new { prior.Id, prior.Status });

        var id = Guid.NewGuid();
        var name = $"imports/{tenantId}/{id:N}.csv";
        var job = new ImportJob {
            Id = id, TenantId = tenantId, UploadId = key,
            BlobName = name, Status = "Receiving"
        };
        _db.ImportJobs.Add(job);
        await _db.SaveChangesAsync(ct);

        await using var input = file.OpenReadStream();
        await _blobs.PutCreateOnlyAsync(name, input, file.Length, ct);
        job.Status = "Ready";
        await _db.SaveChangesAsync(ct);
        return Accepted(new { job.Id, job.Status });
    }
}
```

**Production completion:** Cần xử lý race insert bằng unique-constraint conflict và re-read, so sánh fingerprint payload khi duplicate key, validate CSV thực tế, cleanup/reconcile jobs `Receiving`, xử lý orphan blob, và worker chỉ nhận `Ready`. Code minh họa không phải drop-in hoàn chỉnh; `IFormFile` vẫn có buffering trước action.

## Giải thích thiết kế sau khi sửa

Permission kiểm tra trước side effect; server-generated blob ID tránh collision; streaming giảm cấp phát; unique DB constraint làm arbiter xuyên 4 instances. Trạng thái job và reconciliation thay cho giả định atomic transaction xuyên Blob và SQL.

## Trade-offs

API proxy upload đơn giản về authorization nhưng tốn băng thông App Service. Direct-to-Blob upload với scoped SAS giảm tải nhưng cần finalize/verify/quarantine và cleanup. Polling job table đơn giản ở quy mô nhỏ; outbox/queue tăng vận hành nhưng có thể cần khi throughput và SLA tăng.

## Cách kiểm thử

1. Security integration: tenant A upload tenant B bị chặn, không có side effect.
2. Concurrency: 50 requests cùng key tạo một job; khác payload cùng key trả conflict.
3. Failure injection: Blob timeout, SQL lỗi ở từng transition, client disconnect; reconciliation không import trùng.
4. Load: 100 uploads 25 MiB, đo RSS, GC, latency, 5xx.
5. File validation: UTF-8 lỗi, oversized file, filename trùng, malicious CSV content.

## Quan sát trong production

Application Insights: traces theo job ID và Blob request ID; metrics bytes, in-flight, p95, allocation/GC, jobs `Receiving` quá TTL, orphan count, retries. Alert khi 5xx/backlog tăng. Không log raw file, SAS hoặc token.

## Câu hỏi phỏng vấn mở rộng

1. Nếu file tăng lên 2 GiB, ingestion architecture thay đổi thế nào?
2. Nếu cùng key nhưng payload khác, phát hiện conflict ở đâu?
3. Nếu DB mất kết nối 30 phút sau Blob upload, reconciliation hoạt động thế nào?

## Kết quả code review tham khảo

### Critical — XSS qua v-html

**Vấn đề:** Render HTML vendor trực tiếp.  
**Tại sao xảy ra:** `v-html` không escape HTML như `{{ }}`.  
**Ảnh hưởng production:** Nội dung độc hại có thể thực thi script/event handler tùy payload và CSP.  
**Cách sửa:** Ưu tiên plain text; nếu cần rich text, sanitize theo allowlist ở server, defense-in-depth ở client và CSP.

### High — Race condition stale result

**Vấn đề:** Mọi request đều cập nhật products khi hoàn tất.  
**Tại sao xảy ra:** Completion order khác invocation order.  
**Ảnh hưởng production:** Search B hiển thị kết quả A.  
**Cách sửa:** Abort previous request, sequence guard để chỉ latest request được commit.

### High — Bearer token trong localStorage

**Vấn đề:** JS đọc token trực tiếp từ localStorage.  
**Tại sao xảy ra:** XSS có thể đọc và exfiltrate token.  
**Ảnh hưởng production:** Compromise account trong phạm vi token.  
**Cách sửa:** Threat-model auth; cân nhắc BFF với HttpOnly/Secure/SameSite cookie và CSRF protection; không khẳng định cookie luôn phù hợp.

### High — Không kiểm tra HTTP errors

**Vấn đề:** `fetch` resolve cả 401/429/500; response schema không validate.  
**Tại sao xảy ra:** HTTP error không tự throw.  
**Ảnh hưởng production:** UI gán undefined hoặc hiển thị sai.  
**Cách sửa:** `response.ok`, schema validation, error states rõ ràng.

### Medium — Request storm

**Vấn đề:** Mỗi ký tự gõ gây một request.  
**Tại sao xảy ra:** Không debounce, không abort.  
**Ảnh hưởng production:** QPS tăng, rate limit.  
**Cách sửa:** Debounce theo UX (ví dụ 300ms), cancellation và server-side limits.

### Medium — Pagination không gắn filter

**Vấn đề:** Keyword đổi nhưng page không reset; Next không giới hạn.  
**Tại sao xảy ra:** State độc lập.  
**Ảnh hưởng production:** Empty page hoặc request ngoài phạm vi.  
**Cách sửa:** Reset page 1 khi filter đổi; disable Next khi hết dữ liệu.

### Medium — URL không encode

**Vấn đề:** Ghép keyword trực tiếp.  
**Tại sao xảy ra:** `&/#` có nghĩa đặc biệt trong URL.  
**Ảnh hưởng production:** Search sai hoặc query parameters bị thay đổi.

### Medium — Loading/error ownership sai

**Vấn đề:** Request cũ có thể tắt spinner hoặc ghi lỗi khi request mới đang chạy.  
**Tại sao xảy ra:** Shared state không gắn request ID; không cleanup unmount.

## Phiên bản đề xuất

```vue
<script setup lang="ts">
import { ref, watch, onBeforeUnmount } from "vue";
type Product = { id: string; name: string; description: string };
type Result = { items: Product[]; total: number };
const keyword = ref("");
const page = ref(1);
const products = ref<Product[]>([]);
const total = ref(0);
const loading = ref(false);
const error = ref("");
let active: AbortController | undefined;
let seq = 0;
let timer: ReturnType<typeof setTimeout> | undefined;

async function load() {
  active?.abort();
  const controller = new AbortController();
  active = controller;
  const id = ++seq;
  loading.value = true;
  error.value = "";
  const params = new URLSearchParams({
    q: keyword.value.trim(), page: String(page.value), size: "20"
  });
  try {
    const response = await fetch("/api/products?" + params, {
      signal: controller.signal
    });
    if (!response.ok) throw new Error("HTTP " + response.status);
    const data: Result = await response.json();
    if (!Array.isArray(data.items) ||
        !Number.isInteger(data.total) || data.total < 0)
      throw new Error("Invalid response");
    if (id !== seq) return;
    products.value = data.items;
    total.value = data.total;
  } catch {
    if (id !== seq || controller.signal.aborted) return;
    error.value = "Không thể tải sản phẩm";
    products.value = [];
    total.value = 0;
  } finally {
    if (id === seq) loading.value = false;
  }
}

watch([keyword, page], ([q, p], [oldQ]) => {
  if (q !== oldQ && p !== 1) {
    page.value = 1;
    return;
  }
  ++seq;
  active?.abort();
  loading.value = true;
  if (timer) clearTimeout(timer);
  timer = setTimeout(() => { void load(); }, q !== oldQ ? 300 : 0);
});
onBeforeUnmount(() => {
  ++seq;
  if (timer) clearTimeout(timer);
  active?.abort();
});
void load();
function nextPage() {
  if (!loading.value && page.value * 20 < total.value) page.value++;
}
</script>

<template>
  <input v-model="keyword" aria-label="Tìm sản phẩm" />
  <p v-if="loading" role="status">Đang tải...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <p v-if="!loading && !error && !products.length">Không có kết quả</p>
  <div v-for="product in products" :key="product.id">
    <h3>{{ product.name }}</h3>
    <p>{{ product.description }}</p>
  </div>
  <button :disabled="loading || page * 20 >= total" @click="nextPage">
    Tiếp
  </button>
</template>
```
