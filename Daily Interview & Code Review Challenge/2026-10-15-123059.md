# Code Review Challenge 1 — CSV export làm SQL quá tải và có nguy cơ lộ dữ liệu tenant

**Chủ đề:** ASP.NET Core 8, EF Core, SQL Server, HTTP streaming, CSV security.  
**Độ khó:** Senior.  
**Thời gian review đề xuất:** 30 phút.  
**Số vấn đề cần tìm:** khoảng 10.

## Bối cảnh

SaaS quản lý đơn hàng nhiều tenant chạy trên Azure App Service, SQL Server, Microsoft Entra ID. Mỗi tenant có từ 50.000 đến vài triệu orders. Endpoint export CSV chạy tốt với dữ liệu test, nhưng khi nhiều người dùng đồng thời tải báo cáo thì p95 tăng, SQL Server nhiều query, process memory tăng và CSV mở bằng Excel đôi khi sai cột. Người dùng được đăng nhập không mặc nhiên có quyền xuất dữ liệu mọi tenant. Product cho phép export đồng bộ với báo cáo nhỏ; báo cáo lớn có thể chuyển thành job.

Giả định entity Orders có TenantId, CustomerId, CustomerName, Total, CreatedAt (UTC); Customers có Id, Email. Chưa xác minh middleware/policy ngoài snippet.

## Đoạn code cần review

~~~csharp
app.MapGet("/api/reports/orders.csv", async (
    HttpContext http, AppDbContext db,
    CancellationToken cancellationToken) =>
{
    var tenantId = http.Request.Query["tenantId"].ToString();
    var from = DateTime.Parse(http.Request.Query["from"]!);
    var to = DateTime.Parse(http.Request.Query["to"]!);

    var orders = await db.Orders
        .Where(o => o.TenantId == tenantId &&
                    o.CreatedAt >= from && o.CreatedAt < to)
        .OrderBy(o => o.CreatedAt)
        .ToListAsync();

    http.Response.ContentType = "text/csv";
    http.Response.Headers.ContentDisposition =
        "attachment; filename=orders.csv";

    await using var writer = new StreamWriter(
        http.Response.Body, new UTF8Encoding(false),
        8192, leaveOpen: true);

    await writer.WriteLineAsync(
        "OrderId,Customer,Email,Total,CreatedAt");

    foreach (var order in orders)
    {
        var email = await db.Customers
            .Where(c => c.Id == order.CustomerId)
            .Select(c => c.Email)
            .FirstOrDefaultAsync();

        await writer.WriteLineAsync(
            $"{order.Id},{order.CustomerName},{email}," +
            $"{order.Total},{order.CreatedAt}");
    }

    await writer.FlushAsync();
});
~~~

4. Đề xuất code/design sửa có tính đến performance và failure path.
5. Chọn tests và telemetry để xác minh thay đổi.

## Kết quả code review tham khảo

### [Critical] — Tenant scope do client tự chọn

**Vấn đề:** tenantId lấy từ query string, snippet không có authorization check.  
**Tại sao xảy ra:** Input không đáng tin bị dùng làm ranh giới truy cập dữ liệu. Authentication không đồng nghĩa authorization.  
**Ảnh hưởng production:** Có thể lộ dữ liệu tenant khác nếu không có lớp policy bên ngoài.  
**Cách sửa:** RequireAuthorization, lấy tenant scope từ identity đã xác thực hoặc kiểm tra membership/permission server-side trước query. Kiểm tra cấu hình thực tế trước khi kết luận có lỗ hổng.

### [High] — ToListAsync giữ toàn bộ rows trong RAM

**Vấn đề:** Materialize hết dữ liệu trước khi gửi response.  
**Tại sao xảy ra:** ToListAsync tạo danh sách và objects cho toàn bộ result set.  
**Ảnh hưởng production:** Allocation/GC, peak memory, OOM khi export lớn hoặc concurrent.  
**Cách sửa:** AsNoTracking + projection + streaming với giới hạn rows; export lớn dùng background job và object storage.

### [High] — N+1 queries trong vòng lặp

**Vấn đề:** Mỗi order thực hiện query Customer riêng.  
**Tại sao xảy ra:** Customer lookup chạy sau ToListAsync, bên trong foreach.  
**Ảnh hưởng production:** Khoảng 1 + N round trips, latency và DB pressure tăng theo số orders.  
**Cách sửa:** Project customer email qua navigation/join thành một SQL query; kiểm tra SQL translation, index và execution plan.

### [High] — CSV formula injection

**Vấn đề:** CustomerName/Email có thể chứa chuỗi bắt đầu bằng =, +, -, @ và được spreadsheet diễn giải như formula.  
**Tại sao xảy ra:** CSV quoting không đủ để chống formula interpretation trong một số ứng dụng.  
**Ảnh hưởng production:** Người mở báo cáo có thể gặp hành vi spreadsheet ngoài ý muốn; phụ thuộc consumer.  
**Cách sửa:** Áp dụng spreadsheet-safe encoding theo contract và test với spreadsheet mục tiêu; machine-readable export có thể cần contract khác.

### [High] — Không giới hạn ngày, rows hoặc đồng thời

**Vấn đề:** Không có upper bound cho khoảng ngày và kết quả.  
**Tại sao xảy ra:** Input không được validate; API đồng bộ được dùng như bulk export.  
**Ảnh hưởng production:** SQL connection giữ lâu, timeout, resource exhaustion.  
**Cách sửa:** Validate date range, row cap, quota/rate limiting; chuyển export lớn thành job có status và retention.

### [Medium] — CSV delimiter/quote/newline không được escape

**Vấn đề:** Dấu phẩy, double quote, CR/LF trong customer name làm sai cấu trúc CSV.  
**Tại sao xảy ra:** String interpolation không phải CSV serializer.  
**Ảnh hưởng production:** Import sai cột/dòng, sai báo cáo.  
**Cách sửa:** Quote fields, double embedded quotes, test parser/consumer hoặc dùng CSV library phù hợp.

### [Medium] — Decimal và timestamp phụ thuộc culture

**Vấn đề:** Total và CreatedAt format theo culture mặc định, timezone không rõ trong output.  
**Tại sao xảy ra:** Không có invariant serialization contract.  
**Ảnh hưởng production:** Số tiền có dấu phẩy thập phân; ngày được hiểu khác giữa các hệ thống.  
**Cách sửa:** InvariantCulture và ISO 8601 UTC, document contract.

### [Medium] — CancellationToken không được sử dụng

**Vấn đề:** Query/write không nhận cancellation token.  
**Tại sao xảy ra:** Gọi overload không truyền token.  
**Ảnh hưởng production:** Client disconnect vẫn có thể để lại công việc vô ích.  
**Cách sửa:** Propagate RequestAborted/CancellationToken qua EF Core và stream I/O; phân loại cancellation trong telemetry.

### [Medium] — Date parsing và boundary sai

**Vấn đề:** DateTime.Parse có thể throw; không kiểm tra from < to hoặc UTC.  
**Tại sao xảy ra:** Không validate request trước query.  
**Ảnh hưởng production:** 500 không cần thiết hoặc báo cáo sai biên thời gian.  
**Cách sửa:** TryParse với UTC contract rõ ràng, validate range và trả 400 trước khi response bắt đầu.

### [Medium] — Partial CSV khi stream lỗi

**Vấn đề:** Sau khi gửi headers/bytes, lỗi SQL hoặc network có thể tạo file dở dang.  
**Tại sao xảy ra:** HTTP streaming không tự bảo đảm artifact atomicity.  
**Ảnh hưởng production:** Consumer nhầm partial file là báo cáo đầy đủ.  
**Cách sửa:** Telemetry và contract cho partial response; yêu cầu toàn vẹn mạnh thì tạo file hoàn chỉnh trước rồi mới cho tải.

### [Low] — Thiếu observability

**Vấn đề:** Không ghi số rows, bytes, SQL duration, aborted exports.  
**Tại sao xảy ra:** Không có operational metrics.  
**Ảnh hưởng production:** Khó xác định bottleneck.  
**Cách sửa:** Structured logs, traces, dashboards không chứa PII.

## Phiên bản đề xuất

Mẫu dưới đây dành cho **small bounded export**. Giả định Order.Customer navigation được mapping, claim tenant_id đã được issuer xác thực và policy CanExportOrders thực thi đúng resource authorization. Cần bổ sung membership check nếu user có nhiều tenant. Mã tập trung vào request/streaming contract.

~~~csharp
using System.Globalization;
using System.Text;
using Microsoft.EntityFrameworkCore;

app.MapGet("/api/reports/orders.csv", async (
    HttpContext http, AppDbContext db, CancellationToken ct) =>
{
    var tenantId = http.User.FindFirst("tenant_id")?.Value;
    if (string.IsNullOrWhiteSpace(tenantId))
    {
        http.Response.StatusCode = StatusCodes.Status403Forbidden;
        return;
    }

    var style = DateTimeStyles.AssumeUniversal |
                DateTimeStyles.AdjustToUniversal;
    var culture = CultureInfo.InvariantCulture;
    if (!DateTimeOffset.TryParse(http.Request.Query["from"],
            culture, style, out var from) ||
        !DateTimeOffset.TryParse(http.Request.Query["to"],
            culture, style, out var to) ||
        to <= from || to - from > TimeSpan.FromDays(31))
    {
        http.Response.StatusCode = StatusCodes.Status400BadRequest;
        return;
    }

    var query = db.Orders.AsNoTracking()
        .Where(o => o.TenantId == tenantId &&
                    o.CreatedAt >= from.UtcDateTime &&
                    o.CreatedAt < to.UtcDateTime)
        .OrderBy(o => o.CreatedAt).ThenBy(o => o.Id)
        .Select(o => new {
            o.Id, o.CustomerName, Email = o.Customer.Email,
            o.Total, o.CreatedAt
        });

    const int maxRows = 50000;
    if (await query.Take(maxRows + 1).CountAsync(ct) > maxRows)
    {
        http.Response.StatusCode =
            StatusCodes.Status422UnprocessableEntity;
        return;
    }

    http.Response.ContentType = "text/csv; charset=utf-8";
    http.Response.Headers.ContentDisposition =
        "attachment; filename=\"orders.csv\"";
    await using var writer = new StreamWriter(
        http.Response.Body, new UTF8Encoding(false),
        8192, leaveOpen: true);

    await writer.WriteLineAsync(
        "OrderId,Customer,Email,Total,CreatedAt".AsMemory(), ct);
    await foreach (var row in query.AsAsyncEnumerable()
                                  .WithCancellation(ct))
    {
        var fields = new[] {
            Csv(row.Id.ToString()),
            Csv(row.CustomerName),
            Csv(row.Email),
            Csv(row.Total.ToString(culture)),
            Csv(row.CreatedAt.ToUniversalTime().ToString("O", culture))
        };
        await writer.WriteLineAsync(
            string.Join(",", fields).AsMemory(), ct);
    }
    await writer.FlushAsync(ct);
}).RequireAuthorization("CanExportOrders");

static string Csv(string? value)
{
    var text = value ?? "";
    if (text.TrimStart().FirstOrDefault() is '=' or '+' or '-' or '@')
        text = "'" + text;
    return "\"" + text.Replace("\"", "\"\"") + "\"";
}
~~~

**Cần xác minh trước production:** CountAsync và streaming là hai query, có thể đọc hai snapshot khác nhau khi dữ liệu thay đổi; COUNT có chi phí riêng, cần benchmark. Nếu yêu cầu snapshot consistency, thiết kế snapshot/isolation hoặc background export thích hợp. Streaming giữ database connection đến khi đọc xong; không phải giải pháp cho file không giới hạn. Spreadsheet-safe prefix chỉ là biện pháp giảm thiểu, cần test theo consumer; một số CSV consumer muốn raw data không bị prefix.

## Giải thích thiết kế sau khi sửa

Authorization đặt trước data access. Projection và AsNoTracking giảm materialization; AsAsyncEnumerable giảm peak memory nhưng giữ connection khi đọc. Cancellation giúp giảm công việc thừa khi client ngắt kết nối. CSV escaping bảo vệ cấu trúc file, còn spreadsheet-safe encoding xử lý lớp rủi ro khác. API đặt giới hạn rõ ràng cho export đồng bộ; quy mô lớn chuyển sang asynchronous artifact workflow.

## Trade-offs

- Streaming tiết kiệm RAM nhưng kéo dài database connection nếu client chậm.
- Count trước response cho phép từ chối sớm nhưng thêm round trip và không tạo snapshot nhất quán.
- Background export + Azure Blob Storage tăng complexity: job status, ACL, expiry, cleanup, retry, audit.
- Spreadsheet-safe transformation có thể thay đổi text đối với integration consumer; phải thống nhất contract.

## Cách kiểm thử

1. **Security integration:** User tenant A cố export tenant B, kể cả sửa query; không được nhận data B.
2. **CSV contract:** CustomerName chứa comma, quote, newline, Unicode, =/+/-/@; verify bằng parser và spreadsheet mục tiêu.
3. **Load/SQL:** 100, 10.000, 50.000 rows; đo SQL query count, p95, memory, GC, connection duration, execution plan.
4. **Failure-path:** Client disconnect, SQL timeout, write failure; verify cancellation và partial response được ghi nhận.
5. **Boundary:** Invalid UTC dates, reversed dates, quá 31 ngày, vượt row cap và dữ liệu cập nhật trong khi export.

## Quan sát trong production

Application Insights dependency telemetry: SQL duration và số SQL calls/export; Azure Monitor: process memory, GC, p95/p99, 4xx/5xx và SQL connection pressure. Structured logs gồm reportId, tenant hash, rowCount, bytesWritten, elapsedMs, cancellation/failure stage; không log Email/CustomerName. Alert theo baseline khi export failure rate hoặc DB timeouts tăng.

# Code Review Challenge 2 — Vue Role Management gán nhầm quyền khi đổi app và environment

**Chủ đề:** Vue 3, TypeScript, HTTP API contract, optimistic UI, concurrency, security.  
**Độ khó:** Senior+.  
**Thời gian review đề xuất:** 30 phút.  
**Số vấn đề cần tìm:** khoảng 9.

## Bối cảnh

Một màn Role Management quản lý system roles, với grants áp dụng theo app (Portal/Admin) và environment (dev/staging/prod). Admin chọn nhiều environment để áp dụng cùng một permission. API GET trả grants của scope đang chọn; PUT cập nhật desired state. Sau release, QA thấy grants của app A xuất hiện trên app B khi chuyển tab nhanh; một số thao tác hiển thị thành công dù backend từ chối; khi chọn dev+staging, UI không biểu diễn đúng trạng thái permission chỉ bật ở dev.

Giả định backend có thể trả version và kiểm tra resource authorization nhưng chưa có API contract cho trạng thái mixed/concurrent updates. Snippet là logic Vue setup, không phải bằng chứng rằng backend thiếu authorization.

## Đoạn code cần review

~~~typescript
import { ref, watch } from "vue";

type Grant = {
  permissionId: string;
  enabled: boolean;
};

const roleId = ref("editor");
const appId = ref("portal");
const environments = ref<string[]>(["dev"]);
const grants = ref<Grant[]>([]);
const loading = ref(false);
const error = ref("");

watch([roleId, appId], async () => {
  loading.value = true;
  const query = new URLSearchParams({
    appId: appId.value,
    environments: environments.value.join(",")
  });

  const response = await fetch(
    "/api/roles/" + roleId.value + "/grants?" + query
  );

  grants.value = await response.json();
  loading.value = false;
}, { immediate: true });

async function toggle(grant: Grant) {
  grant.enabled = !grant.enabled;
  const response = await fetch(
    "/api/roles/" + roleId.value +
    "/grants/" + grant.permissionId,
    {
      method: "PUT",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        appId: appId.value,
        environments: environments.value,
        enabled: grant.enabled
      })
    }
  );
  if (!response.ok) {
    error.value = "Save failed";
  }
}
~~~

## Nhiệm vụ của ứng viên

1. Tìm race conditions của GET và PUT khi scope thay đổi.
2. Đánh giá correctness khi chọn nhiều environments và có mixed grants.
3. Phân tích failure, conflict và server-authoritative state.
4. Ưu tiên rủi ro cấp sai quyền trước vấn đề UX.
5. Đề xuất implementation, API contract, tests và production telemetry.

## Câu hỏi gợi mở

1. GET app A trả sau GET app B sẽ tạo UI nào?
2. Chỉ thay đổi environments có kích hoạt watch không?
3. Grant thuộc app A có thể bị PUT vào app B khi selection thay đổi không?
4. Boolean enabled có thể biểu diễn dev=true, staging=false không?
5. Nếu server trả 412 hoặc network disconnect sau khi commit, UI nên xử lý thế nào?

## Kết quả code review tham khảo

### [Critical] — Mutation có thể áp dụng sai scope

**Vấn đề:** Grant được tải cho scope cũ nhưng toggle đọc roleId/appId/environments hiện tại.  
**Tại sao xảy ra:** Dataset không gắn immutable scope identity; reactive state có thể đổi trong lúc GET/PUT pending.  
**Ảnh hưởng production:** Cấp/thu hồi permission trên app hoặc environment khác với ý định; phụ thuộc backend validation.  
**Cách sửa:** Gắn scope snapshot với dataset; disable thao tác nếu scope không khớp; backend bắt buộc xác minh actor, role, app, environment, permission.

### [High] — Stale GET response ghi đè dữ liệu mới

**Vấn đề:** Request cũ có thể hoàn thành sau request mới.  
**Tại sao xảy ra:** Watch tạo requests không có cancellation hoặc sequence check.  
**Ảnh hưởng production:** UI hiển thị grant sai app, làm tăng nguy cơ mutation sai.

### [High] — Thay đổi environments không reload

**Vấn đề:** watch chỉ theo roleId/appId.

**Ảnh hưởng production:** Hiển thị grants của dev nhưng PUT áp dụng dev+staging.

**Ảnh hưởng production:** Bulk assignment gây hiểu nhầm.

### [Medium] — Không bắt network/JSON errors

**Tại sao xảy ra:** Thiếu try/catch/finally.  
**Ảnh hưởng production:** UI treo hoặc unhandled promise rejection.

### [Medium] — Rapid clicks tạo concurrent PUTs

**Tại sao xảy ra:** Không có per-scope pending guard.

**Tại sao xảy ra:** Client không phải security boundary.  
**Ảnh hưởng production:** Nếu backend thiếu policy, user có thể cấp quyền ngoài phạm vi.  
**Cách sửa:** Server-side resource authorization, allowlist app/env, version check và audit actor/scope/before/after; không kết luận backend thiếu từ snippet.

### [Low] — Thiếu observability cho conflict/race

**Vấn đề:** Không có correlation ID, scope identity hay metrics conflict.  
**Tại sao xảy ra:** Không có operational instrumentation.  
**Ảnh hưởng production:** Khó điều tra “quyền nhảy” hoặc silent overwrite.  
**Cách sửa:** Client actionId + backend audit + metrics 409/412/403.

## Phiên bản đề xuất

Contract minh họa: GET trả GrantRow với state = all/none/mixed và version; PUT đặt desired state cho tất cả environments trong snapshot, yêu cầu If-Match. Backend thực thi authorization, optimistic concurrency và atomic/partial semantics đã thống nhất. Code là state-management layer, template cần disable actions khi scope chưa loaded.

~~~typescript
import { ref, watch, onUnmounted } from "vue";

type GrantRow = {
  permissionId: string;
  state: "all" | "none" | "mixed";
  version: string;
};
type Scope = {
  roleId: string;
  appId: string;
  environments: string[];
};

const roleId = ref("editor");
const appId = ref("portal");
const environments = ref<string[]>(["dev"]);
const grants = ref<GrantRow[]>([]);
const loadedScope = ref("");
const loading = ref(false);
const error = ref("");
const pending = ref(new Set<string>());
let controller: AbortController | undefined;
let sequence = 0;

const snapshot = (): Scope => ({
  roleId: roleId.value,
  appId: appId.value,
  environments: [...new Set(environments.value)].sort()
});
const key = (s: Scope) =>
  JSON.stringify([s.roleId, s.appId, s.environments]);

async function reload() {
  controller?.abort();
  const abort = new AbortController();
  controller = abort;
  const seq = ++sequence;
  const scope = snapshot();
  loading.value = true;
  error.value = "";
  loadedScope.value = "";
  try {
    const query = new URLSearchParams({
      appId: scope.appId,
      environments: scope.environments.join(",")
    });
    const url = "/api/roles/" +
      encodeURIComponent(scope.roleId) + "/grants?" + query;
    const res = await fetch(url, { signal: abort.signal });
    if (!res.ok) throw Error("GET HTTP " + res.status);
    const data = await res.json() as GrantRow[];
    if (seq === sequence && key(scope) === key(snapshot())) {
      grants.value = data;
      loadedScope.value = key(scope);
    }
  } catch (e) {
    if (seq === sequence && !abort.signal.aborted)
      error.value = String(e);
  } finally {
    if (seq === sequence) loading.value = false;
  }
}

watch(
  [roleId, appId,
   () => [...new Set(environments.value)].sort().join("|")],
  () => { void reload(); },
  { immediate: true }
);

async function apply(permissionId: string, enabled: boolean) {
  const scope = snapshot();
  const scopeKey = key(scope);
  const row = grants.value.find(g => g.permissionId === permissionId);
  const pendingKey = scopeKey + ":" + permissionId;
  if (!row || loading.value || loadedScope.value !== scopeKey ||
      !scope.environments.length || pending.value.has(pendingKey))
    return;

  pending.value = new Set([...pending.value, pendingKey]);
  try {
    const url = "/api/roles/" +
      encodeURIComponent(scope.roleId) + "/grants/" +
      encodeURIComponent(permissionId);
    const res = await fetch(url, {
      method: "PUT",
      headers: {
        "Content-Type": "application/json",
        "If-Match": row.version
      },
      body: JSON.stringify({
        appId: scope.appId,
        environments: scope.environments,
        enabled
      })
    });
    if (!res.ok) throw Error("PUT HTTP " + res.status);
    if (scopeKey === key(snapshot())) await reload();
  } catch (e) {
    if (scopeKey === key(snapshot())) {
      error.value = String(e);
      await reload();
    }
  } finally {
    const next = new Set(pending.value);
    next.delete(pendingKey);
    pending.value = next;
  }
}

onUnmounted(() => controller?.abort());
~~~

**Triển khai bổ sung:** Template hiển thị mixed state và pending; disable mutation nếu loadedScope khác current scope. If-Match version phải đại diện đúng các records được cập nhật (có thể cần per-environment versions). Khi 412, báo conflict rõ ràng và không auto-retry mutation. Nếu nhiều permission được update song song, cần phối hợp refresh và pending feedback. Backend không được tin client-side permission checks.

## Giải thích thiết kế sau khi sửa

GET gắn với snapshot và sequence; response cũ không ghi đè state mới. PUT mang scope bất biến và desired state thay vì toggle từ reactive data không ổn định. UI chỉ chấp nhận trạng thái authoritative sau reload; pending guard chặn rapid clicks. Version precondition bảo vệ concurrent edits, còn tri-state làm rõ bulk permission semantics.

## Trade-offs

- AbortController không bảo đảm server dừng xử lý, nên sequence guard vẫn cần.
- Reload sau PUT đơn giản nhưng tăng HTTP calls; batch refresh khi API contract ổn định.
- If-Match tạo conflict cần xử lý bằng UX, nhưng tránh silent overwrite.
- Bulk update cần chọn all-or-nothing hay partial success; partial đòi per-environment results và recovery.
- Client guard là UX; server-side authorization và audit mới là security boundary.

## Cách kiểm thử

1. **Playwright race:** GET app A trả sau app B; assert UI luôn hiển thị B và không PUT grant A vào B.
2. **Scope integration:** Chuyển dev sang dev+staging trong lúc GET/PUT pending; payload luôn gắn đúng snapshot.
3. **Concurrency:** Hai admin sửa cùng permission; API trả 409/412, UI refresh và hiển thị conflict.
4. **Failure-path:** HTTP 403/500, invalid JSON, network disconnect, rapid clicks; loading/pending reset và không báo thành công giả.
5. **Security:** User chỉ quản trị dev cố PUT prod trực tiếp; server từ chối và audit actor, scope, outcome.

## Quan sát trong production

Client telemetry ghi actionId, roleId, appId, environmentCount, sequence, latency, error class; không ghi access token hoặc dữ liệu nhạy cảm. Backend structured audit ghi actor, scope, permission, desired state, version, before/after, correlationId. Theo dõi 403/409/412/5xx, update latency, conflict rate và scope mismatch để phân biệt frontend race với backend rejection.

## Câu hỏi phỏng vấn mở rộng

1. Khi role áp dụng cho 100 apps và ba environments, API/UI cần thiết kế “check all” thế nào để tránh cấp quyền ngoài ý muốn?
2. Chọn atomic transaction hay partial success nếu một environment không cho phép permission đó?
3. PUT đã commit nhưng network disconnect trước response: xác minh trạng thái thế nào mà không ghi đè ngoài ý muốn?
