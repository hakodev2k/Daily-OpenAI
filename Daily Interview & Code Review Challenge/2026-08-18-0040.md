# Câu 1 — EF Core query execution trong API báo cáo chậm

**Loại câu hỏi:** Internal mechanism
**Độ khó:** Senior
**Thời gian trả lời đề xuất:** 15 phút
**Kỹ năng được đánh giá:** EF Core internals, performance diagnosis

## Bối cảnh
Một ASP.NET Core API dùng EF Core và PostgreSQL bắt đầu chậm sau khi dữ liệu tăng lên vài triệu bản ghi. API timeout tăng từ dưới 1 giây lên hơn 10 giây.

## Câu hỏi chính
Giải thích bên trong EF Core query được tạo và thực thi như thế nào. Vì sao materialize dữ liệu sớm có thể gây vấn đề? Bạn xác minh giả thuyết bằng cách nào?

## Câu hỏi làm rõ nên cân nhắc
- Query trả về bao nhiêu dữ liệu?
- Có tracking không?
- SQL thực tế là gì?
- Execution plan ra sao?

## Gợi ý tư duy
- LINQ không đồng nghĩa với SQL chạy ngay.
- Xem xét tracking, projection, memory.
- Đo trước khi tối ưu.

## Hướng giải quyết tham khảo
Dùng projection DTO, AsNoTracking cho read-only, pagination, kiểm tra SQL generated và database metrics.

# Câu 2 — Thiết kế nền tảng QA Automation

**Loại câu hỏi:** System Design
**Độ khó:** Senior+
**Thời gian trả lời đề xuất:** 25 phút
**Kỹ năng được đánh giá:** Architecture, scalability, reliability

## Bối cảnh
Xây dựng hệ thống quản lý Playwright test cho nhiều ứng dụng nội bộ. Cần chạy test, lưu artifact, retry, dashboard và tích hợp CI/CD.

## Câu hỏi chính
Thiết kế kiến trúc, database, execution flow, retry và observability như thế nào?

## Câu hỏi làm rõ nên cân nhắc
- Quy mô test run?
- Artifact retention?
- Environment isolation?
- Approval workflow?

## Gợi ý tư duy
- Bắt đầu từ lifecycle của test run.
- Modular monolith phù hợp MVP.
- Retry cần đi cùng idempotency.

## Hướng giải quyết tham khảo
API quản lý test suite, worker chạy Playwright, database lưu trạng thái, blob storage lưu artifact, metrics theo dõi flaky test.

# Câu 3 — AI Code Review Agent cho dự án .NET

**Loại câu hỏi:** AI Engineering
**Độ khó:** Senior+
**Thời gian trả lời đề xuất:** 20 phút
**Kỹ năng được đánh giá:** Context engineering, AI safety, evaluation

## Bối cảnh
Team muốn dùng AI agent review Pull Request dựa trên code, issue và architecture document.

## Câu hỏi chính
Thiết kế agent thế nào để tăng chất lượng review nhưng không phụ thuộc mù quáng vào LLM?

## Câu hỏi làm rõ nên cân nhắc
- Repository có dữ liệu nhạy cảm không?
- Agent có quyền gì?
- Đánh giá chất lượng bằng metric nào?

## Gợi ý tư duy
- AI không thay thế deterministic checks.
- Context và permission quan trọng.
- Cần evaluation loop.

## Hướng giải quyết tham khảo
Dùng retrieval context, structured output, tool permission giới hạn, human approval, rule-based validation và đo false positive/negative.

# Tổng kết hôm nay

## Kiến thức trọng tâm
- Hiểu runtime behavior trước khi tối ưu.
- Thiết kế hệ thống bắt đầu từ requirement và failure mode.
- AI production cần validation và evaluation.

## Mẫu tư duy cần nhớ
- Clarify before designing.
- Measure before optimizing.
- Design retries together with idempotency.
- Validate AI output deterministically.
- Treat observability as architecture.
