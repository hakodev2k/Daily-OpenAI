## Đoạn code cần review

```csharp
public sealed class ProductIndexWorker(
    IServiceScopeFactory scopes,
    HttpClient http,
    ILogger<ProductIndexWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            await RebuildAsync(ct);
            await Task.Delay(TimeSpan.FromMinutes(10), ct);
        }
    }

    private async Task RebuildAsync(CancellationToken ct)
    {
        using var scope = scopes.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
        var products = await db.Products
            .Include(p => p.Category)
            .ToListAsync(ct);

        await http.DeleteAsync("products/_doc", ct);

        foreach (var p in products)
        {
            var document = new
            {
                p.Id,
                p.Name,
                p.Price,
                Category = p.Category.Name,
                p.IsPublished,
                p.UpdatedAt
            };

            var response = await http.PutAsJsonAsync(
                $"products/_doc/{p.Id}", document, ct);

            if (!response.IsSuccessStatusCode)
                log.LogWarning("Index failed for {ProductId}", p.Id);
        }

        log.LogInformation("Indexed {Count} products", products.Count);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Rebuild trực tiếp trên index đang phục vụ

**Vấn đề:** Job thay đổi trực tiếp index `products` mà không có staging và atomic cutover. Lệnh DELETE tới `products/_doc` không phải thao tác xóa toàn bộ index hợp lệ; hành vi thực tế phụ thuộc endpoint và cấu hình, phải kiểm tra HTTP response.  
**Tại sao xảy ra:** Code nhầm API xóa document với quản lý index và không có versioned index.  
**Ảnh hưởng production:** Nếu thao tác xóa được thay đổi thành xóa index thật, hoặc các bản ghi bị thay thế không đồng bộ, người dùng thấy kết quả thiếu, sai hoặc gián đoạn.  
**Cách sửa:** Tạo index mới `products_vNN`, bulk import, kiểm tra count/sample/health, rồi đổi alias `products_read` bằng một alias update request. Giữ index cũ để rollback.

### [High] — Nhiều worker chạy đồng thời

**Vấn đề:** Ba instance đều chạy vòng lặp.  
**Tại sao xảy ra:** `BackgroundService` không cung cấp singleton execution xuyên process.  
**Ảnh hưởng production:** Ghi đè lẫn nhau, tăng tải database/cluster và trạng thái khó dự đoán.  
**Cách sửa:** Dùng orchestrator độc lập với lease có fencing hoặc một job runner duy nhất; dù vậy consumer vẫn phải idempotent và kiểm tra version.

### [High] — Snapshot không nhất quán với thay đổi trong lúc rebuild

**Vấn đề:** Dữ liệu đọc tại một thời điểm rồi được ghi dần; cập nhật mới có thể bị bản cũ ghi đè.  
**Tại sao xảy ra:** Không có change capture, watermark hoặc version guard.  
**Ảnh hưởng production:** Giá, tồn kho, trạng thái publish bị stale.  
**Cách sửa:** Dùng transactional outbox/change feed để replay thay đổi sau snapshot watermark; chỉ áp dụng update nếu source version mới hơn. Với dữ liệu nhạy cảm như giá/tồn kho, xác nhận lại tại checkout từ database nguồn.

### [High] — Lỗi từng item bị bỏ qua

**Vấn đề:** HTTP failure chỉ được log, job vẫn báo hoàn tất.  
**Tại sao xảy ra:** Không phân loại lỗi transient/permanent, không có retry bounded hay DLQ.  
**Ảnh hưởng production:** Thiếu document kéo dài, không có tín hiệu thất bại đáng tin cậy.  
**Cách sửa:** Bulk API, kiểm tra `errors` và từng item status; retry có backoff/jitter với giới hạn; đưa lỗi cố định vào hàng xử lý thủ công, fail validation trước alias swap.

### [High] — Không giới hạn dung lượng query

**Vấn đề:** `ToListAsync` tải toàn catalog và entity tracking vào RAM.  
**Tại sao xảy ra:** Không dùng projection, paging hoặc streaming có kiểm soát.  
**Ảnh hưởng production:** Memory/GC tăng, query dài, có thể OOM khi catalog lớn.  
**Cách sửa:** `AsNoTracking`, select field cần thiết, keyset paging theo ID hoặc snapshot key, bulk theo batch có giới hạn.

### [Medium] — Không kiểm tra HTTP response xóa và không quản lý timeout

**Vấn đề:** Response từ DELETE không được kiểm tra/dispose; request có thể treo lâu.  
**Tại sao xảy ra:** Thiếu response handling và timeout budget.  
**Ảnh hưởng production:** Silent failure và job chồng lên nhau.  
**Cách sửa:** Dùng typed client, `using` response, `EnsureSuccessStatusCode` nơi thích hợp, timeout và cancellation; không retry mù thao tác không idempotent.

### [Medium] — Thiếu kiểm soát dữ liệu công khai

**Vấn đề:** Mọi product kể cả `IsPublished=false` được index vào cùng tập document.  
**Tại sao xảy ra:** Không có explicit search visibility policy.  
**Ảnh hưởng production:** Query sai filter có thể lộ sản phẩm chưa phát hành.  
**Cách sửa:** Index chỉ dữ liệu được phép public hoặc enforce visibility ở mọi query và kiểm thử quyền truy cập.

### [Medium] — Telemetry không phản ánh chất lượng index

**Tại sao xảy ra:** Không đo lag, failure rate, alias version và reconciliation.  
**Ảnh hưởng production:** Incident kéo dài mà dashboard vẫn xanh.  
**Cách sửa:** Đo bulk successes/failures, source-to-search lag, mismatch count, job duration, alias target và alert theo SLO.

## Phiên bản đề xuất

Ví dụ dưới đây minh họa orchestration; các abstraction `IIndexAdmin`, `IProductSnapshotReader`, `IBulkProductWriter`, `IProductChangeReplay` là interface của ứng dụng, không phải API tích hợp sẵn của Elasticsearch.

```csharp
public sealed class ProductReindexJob(
    IIndexLease lease,
    IIndexAdmin indices,
    IProductSnapshotReader source,
    IBulkProductWriter writer,
    IProductChangeReplay replay,
    ILogger<ProductReindexJob> logger)
{
    public async Task RunAsync(CancellationToken ct)
    {
        await using var guard = await lease.TryAcquireAsync(
            "product-reindex", ct);
        if (guard is null) return;

        var snapshot = await source.OpenSnapshotAsync(ct);
        var target = await indices.CreateVersionedIndexAsync(ct);
        var published = false;

        try
        {
            await foreach (var batch in source.ReadBatchesAsync(
                snapshot, 500, ct))
            {
                await guard.AssertOwnershipAsync(ct);
                var result = await writer.UpsertBulkAsync(
                    target, batch, ct);
                if (result.Failures.Count != 0)
                    throw new IndexBatchException(result.Failures);
            }

            await replay.ApplyAfterAsync(
                target, snapshot.Watermark, ct);
            await guard.AssertOwnershipAsync(ct);
            await indices.ValidateAsync(target, ct);
            await indices.SwapReadAliasAsync(
                "products_read", target, ct);
            published = true;
        }
        finally
        {
            if (!published)
                logger.LogWarning(
                    "Index {Index} not published", target);
        }
    }
}
```

**Điều kiện bắt buộc của thiết kế:** `OpenSnapshotAsync` phải cung cấp một snapshot/watermark có ngữ nghĩa xác định; replay phải xử lý concurrent changes đến điểm cutover (hoặc tiếp tục dual-write có version guard). Lease cần fencing chống owner cũ; alias swap không thay thế được kiểm soát thứ tự cập nhật. Không tự động xóa index cũ ngay sau cutover.

## Giải thích thiết kế sau khi sửa

Database là source of truth. Rebuild theo versioned index giúp search luôn trỏ tới phiên bản hoàn chỉnh; alias swap là bước publish. Outbox đảm bảo thay đổi nghiệp vụ có thể replay; idempotent upsert và version guard ngăn event cũ ghi đè event mới. Job tách khỏi web instances giảm duplicate scheduling. Query public vẫn cần filter đúng và checkout vẫn đọc dữ liệu authoritative.

## Trade-offs

Full rebuild đơn giản để khôi phục nhưng tốn IO, storage tạm và thời gian. Incremental indexing giảm tải nhưng tăng phức tạp về outbox, ordering và reconciliation. Alias cutover giảm downtime nhưng phải quản lý disk capacity, index mapping compatibility và rollback. Nếu catalog nhỏ, chỉ một instance và chấp nhận lag, batch incremental đơn giản có thể đủ; không nhất thiết cần Kafka hay microservices.

## Cách kiểm thử

1. **Concurrency test:** hai job cùng acquire lease; chỉ một owner được publish, owner mất lease không thể swap.
2. **Failure-path test:** bulk trả partial failure hoặc timeout; alias vẫn trỏ index cũ và lỗi được ghi nhận.
3. **Consistency test:** update giá/unpublish trong lúc snapshot; replay và version guard cho kết quả đúng.
4. **Load test:** hàng triệu product; đo memory, GC, batch throughput và search p95.
5. **Security/integration test:** draft/unpublished product không xuất hiện qua public search.

## Quan sát trong production

Application Insights: `reindex_duration`, `bulk_failed_items`, `source_to_index_lag_seconds`, `reconciliation_mismatch`, active alias version, lease conflict, retry count. Elasticsearch: indexing pressure, refresh/merge latency, rejected requests, disk usage, shard health. PostgreSQL: query duration, connection pool, outbox backlog. Correlate run ID và index version; alert khi lag hoặc mismatch vượt SLO.

## Đoạn code cần review

```tsx
type Quote = { shipping: number; tax: number };
type Cart = { subtotal: number; items: { sku: string; qty: number }[] };

export function Checkout({ cart }: { cart: Cart }) {
  const [postcode, setPostcode] = React.useState("");
  const [method, setMethod] = React.useState("standard");
  const [quote, setQuote] = React.useState<Quote | null>(null);
  const [error, setError] = React.useState("");
  const [loading, setLoading] = React.useState(false);

  React.useEffect(() => {
    setLoading(true);
    fetch("/api/shipping/quote", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({ postcode, method, items: cart.items })
    })
      .then(r => r.json())
      .then(data => {
        setQuote(data);
        setLoading(false);
      })
      .catch(e => {
        setError(String(e));
        setLoading(false);
      });
  }, [postcode, method, cart.items]);

  const total = cart.subtotal + (quote?.shipping ?? 0)
    + (quote?.tax ?? 0);

  async function submit() {
    await fetch("/api/orders", {
      method: "POST",
      headers: { "Content-Type": "application/json" },
      body: JSON.stringify({
        items: cart.items, postcode, method, total
      })
    });
    window.location.href = "/orders/success";
  }

  return <section>
    <input value={postcode} onChange={e => setPostcode(e.target.value)} />
    <select value={method} onChange={e => setMethod(e.target.value)}>
      <option value="standard">Standard</option>
      <option value="express">Express</option>
    </select>
    <p>{loading ? "Đang tính..." : total}</p>
    {error && <p role="alert">{error}</p>}
    <button onClick={submit}>Đặt hàng</button>
  </section>;
}
```

### [Critical] — Tin tổng tiền do client gửi

**Vấn đề:** Browser gửi `total` do UI tính.  
**Tại sao xảy ra:** Client không phải trust boundary; giá, tax và shipping có thể bị sửa trong DevTools hoặc stale.

### [High] — Race condition ghi đè quote mới

**Vấn đề:** Response cũ có thể gọi `setQuote` sau response mới.  
**Tại sao xảy ra:** Effect không cancel/ignore request cũ.  
**Ảnh hưởng production:** Người dùng thấy tổng sai địa chỉ.

**Vấn đề:** `fetch` resolve với 4xx/5xx và code vẫn redirect.  
**Tại sao xảy ra:** Không kiểm tra `response.ok`.  
**Ảnh hưởng production:** UI báo thành công dù không có order.

**Tại sao xảy ra:** Thiếu runtime validation và status check.

**Cách sửa:** Validate số hữu hạn không âm, currency và quote identity; dùng schema validation ở boundary.

```tsx
          signal: controller.signal
        });
        if (!response.ok) throw new Error(`Quote HTTP ${response.status}`);
        const data: Quote = await response.json();
        if (!data.quoteId ||
            !Number.isFinite(data.shipping) ||
            !Number.isFinite(data.tax) ||
            data.shipping < 0 || data.tax < 0)
          throw new Error("Invalid quote");
        if (!controller.signal.aborted) setQuote(data);
      } catch (e) {
        if (!controller.signal.aborted) setError(String(e));
      } finally {
        if (!controller.signal.aborted) setLoading(false);
      }
    }, 350);

    return () => {
      clearTimeout(timer);
      controller.abort();
    };
  }, [postcode, method, cart.version]);

  async function submit() {
    if (!quote || loading || submitting) return;
    setSubmitting(true);
    setError("");
    try {
      const response = await fetch("/api/orders", {
        method: "POST",
        headers: {
          "Content-Type": "application/json",
          "Idempotency-Key": requestKey
        },
        body: JSON.stringify({
          cartVersion: cart.version, postcode,
          method, quoteId: quote.quoteId
        })
      });
      if (!response.ok) throw new Error(`Order HTTP ${response.status}`);
      const order: { id: string } = await response.json();
      window.location.assign(`/orders/${encodeURIComponent(order.id)}`);
    } catch (e) {
      setError(String(e));
      setSubmitting(false);
    }
  }

  const total = quote
    ? cart.subtotal + quote.shipping + quote.tax : null;
  return <section>
    <input value={postcode} onChange={e => setPostcode(e.target.value)} />
    <select value={method} onChange={e => setMethod(e.target.value)}>
      <option value="standard">Standard</option>
      <option value="express">Express</option>
    </select>
    <p>{loading ? "Đang tính..." :
      total === null ? "Chưa có báo giá" : total}</p>
    {error && <p role="alert">{error}</p>}
    <button disabled={!quote || loading || submitting}
      onClick={submit}>Đặt hàng</button>
  </section>;
}
```

**Giới hạn cần xử lý khi triển khai thực tế:** Khi `postcode`, `method` hoặc cart thay đổi trong lúc submit, nên khóa input hoặc snapshot và gắn quote với đúng input/version; backend bắt buộc đối chiếu quote. Idempotency key phải đại diện cho một ý định đặt hàng, giữ nguyên qua retry nhưng tạo mới khi bắt đầu order intent mới. Cần định nghĩa cách retry sau timeout không tạo trùng. Giá trị tiền nên dùng minor units/decimal ở backend thay vì tin phép cộng floating-point của JavaScript. Cần authentication/CSRF protection phù hợp cơ chế session và không lộ thông tin nội bộ trong lỗi UI.

## Giải thích thiết kế sau khi sửa

`AbortController` cùng cleanup ngăn stale effect cập nhật state; debounce giảm request không cần thiết. Kiểm tra `response.ok` phân biệt lỗi HTTP với network failure. Server có quyền quyết định số tiền, tạo order và xử lý idempotency. Quote ID là tham chiếu tới tính toán được xác thực phía server, không phải bằng chứng thanh toán. Tính đúng đắn không phụ thuộc việc UI disable button.

## Trade-offs

Debounce giảm tải nhưng tăng latency nhỏ; nếu cần UX tức thì có thể hiển thị cached estimate nhưng phải đánh dấu chưa final. Abort request không đảm bảo server ngừng xử lý, nên backend vẫn cần rate limiting. Idempotency storage tăng chi phí nhưng cần thiết với checkout. Server quote có expiry đòi hỏi xử lý stale quote rõ ràng. Không nhất thiết đưa toàn bộ checkout vào global state manager nếu local state và API contract đã đủ.

## Cách kiểm thử

1. **Playwright E2E:** mock response postcode A chậm hơn B; chỉ B được hiển thị.
2. **Failure-path test:** quote 429/500 và order 500; không redirect thành công.
3. **Concurrency/integration test:** double click/retry cùng idempotency key chỉ tạo một order.
4. **Security test:** sửa client total, quote ID, cart version; backend từ chối hoặc tính lại đúng.
5. **Load test:** gõ nhanh và đổi method; đo request rate và cancellation/429.

## Quan sát trong production

Frontend: quote request count/session, abort rate, 429 rate, stale quote guard, submit error rate, latency p95; không log postcode đầy đủ nếu không cần. Backend/Application Insights: correlation ID, quote-to-order mismatch, idempotency replay, order creation failures, pricing recalculation differences. Alert theo tỷ lệ checkout thất bại và số order duplicate, không chỉ theo HTTP 5xx.
