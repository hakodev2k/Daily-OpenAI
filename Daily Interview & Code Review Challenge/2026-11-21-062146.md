## Đoạn code cần review

```csharp
[ApiController]
[Route("api/pages")]
public sealed class PagesController : ControllerBase
{
    private static readonly Dictionary<string, PageDto> Cache = new();
    private readonly IContentLoader _loader;
    private readonly IContentVersionRepository _versions;

    public PagesController(IContentLoader loader,
        IContentVersionRepository versions)
    {
        _loader = loader;
        _versions = versions;
    }

    [HttpGet("{slug}")]
    public IActionResult Get(string slug, [FromQuery] bool preview = false)
    {
        var tenant = Request.Headers["X-Tenant"].ToString();
        var key = slug.ToLowerInvariant();

        if (Cache.TryGetValue(key, out var cached))
        {
            Response.Headers.CacheControl = "public,max-age=900";
            return Ok(cached);
        }

        var page = _loader.GetChildren<LandingPage>(
                ContentReference.StartPage)
            .FirstOrDefault(x => x.URLSegment == slug);

        if (page == null) return NotFound();

        if (preview)
        {
            var latest = _versions.List(page.ContentLink)
                .OrderByDescending(x => x.Saved)
                .FirstOrDefault();
            if (latest != null)
                page = _loader.Get<LandingPage>(latest.ContentLink);
        }

        var dto = new PageDto(
            page.Name, page.MainBody?.ToHtmlString(), tenant);

        Cache[key] = dto;
        Response.Headers.CacheControl = "public,max-age=900";
        return Ok(dto);
    }
}

public record PageDto(string Title, string? Html, string Tenant);
```

## Kết quả code review tham khảo

### Critical — Preview không có authorization

**Vấn đề:** Client tự bật `preview=true`.  
**Tại sao xảy ra:** Không có authentication, policy authorization hoặc kiểm tra quyền content.  
**Ảnh hưởng production:** Bất kỳ người dùng nào cũng có thể yêu cầu draft; có nguy cơ tiết lộ thông tin chưa công bố.  
**Cách sửa:** Tách endpoint preview, bắt buộc xác thực editor, kiểm tra quyền đọc từng content version và trả `no-store`; không cho CDN cache.

### Critical — Draft đi vào public cache

**Vấn đề:** DTO preview được lưu trong cache chung rồi phát qua response `public`.  
**Tại sao xảy ra:** Không phân vùng cache theo publication state và principal; lookup cache chạy trước logic preview.  
**Ảnh hưởng production:** Draft có thể bị phát cho người ẩn danh trên cùng instance và qua CDN.  
**Cách sửa:** Preview tuyệt đối không ghi shared cache; public endpoint chỉ lấy phiên bản published; purge các cache keys có khả năng bị nhiễm.

### High — Không xác minh tenant

**Vấn đề:** `X-Tenant` do client kiểm soát và không giới hạn truy vấn content.  
**Tại sao xảy ra:** Tenant chỉ xuất hiện trong DTO; truy vấn lấy từ StartPage chung.  
**Ảnh hưởng production:** Có thể trả nội dung của site khác và gắn nhãn tenant sai.  
**Cách sửa:** Resolve tenant từ host đã được cấu hình/trusted mapping, giới hạn content root/site và enforce authorization; không tin header tùy ý.

### High — Cache key thiếu site, locale và version

**Vấn đề:** Chỉ dùng slug lower-case.  
**Tại sao xảy ra:** Không tính tới các chiều định danh của content.  
**Ảnh hưởng production:** Cross-site/cross-language collisions, trả sai nội dung.  
**Cách sửa:** Key gồm site ID, culture, canonical content ID, published revision và schema version; URL/edge cache cũng cần phân vùng tương ứng.

### High — Dictionary static không thread-safe

**Vấn đề:** Nhiều request đọc/ghi `Dictionary` đồng thời.  
**Tại sao xảy ra:** Static mutable collection không có synchronization.  
**Ảnh hưởng production:** Race condition và hành vi không xác định dưới tải.  
**Cách sửa:** Dùng `IMemoryCache` hoặc distributed cache thích hợp với chính sách eviction; không tự xây cache dictionary.

### High — Không có cơ chế invalidation và giới hạn bộ nhớ

**Vấn đề:** Cache tồn tại vô hạn trên từng instance, trong khi CDN TTL 15 phút.  
**Tại sao xảy ra:** Không có TTL, eviction, publish event hay purge.  
**Ảnh hưởng production:** Stale content kéo dài, tăng memory, instance bất nhất.  
**Cách sửa:** Cache public theo revision/TTL có giới hạn, invalidation từ publish event và purge CDN; định nghĩa SLA propagation và fallback khi purge lỗi.

### Medium — Truy vấn toàn bộ children và tìm theo slug mỗi request miss

**Vấn đề:** `GetChildren` rồi `FirstOrDefault` thay vì content routing/index có scope.  
**Tại sao xảy ra:** Bỏ qua cơ chế lookup theo site/culture/path.  
**Ảnh hưởng production:** Miss tốn tài nguyên, phân trang/language khó đúng.  
**Cách sửa:** Sử dụng routing/content lookup có hỗ trợ site, language và published state; đo latency và số content loads.

### Medium — Raw HTML đưa thẳng tới frontend

**Vấn đề:** `MainBody` là HTML; trust boundary và sanitization không được xác nhận.  
**Tại sao xảy ra:** Có thể có nội dung editor hoặc integration chưa được kiểm soát.  
**Ảnh hưởng production:** Stored XSS nếu frontend render HTML không an toàn.  
**Cách sửa:** Chính sách editor permissions, allowlist HTML/sanitizer phù hợp, CSP defense-in-depth, review rendering pipeline.

### Medium — Thiếu observability và incident controls

**Vấn đề:** Không log content identity, revision, cache status, publish state hoặc tenant resolution.  
**Tại sao xảy ra:** Delivery path không được instrument.  
**Ảnh hưởng production:** Khó xác định nội dung rò rỉ, edge nào còn stale.  
**Cách sửa:** Structured logs và tracing với ID phi nhạy cảm, metrics cache hit/miss, revision mismatch, purge lag; không log draft HTML hoặc token.

## Phiên bản đề xuất

Thiết kế minh họa dưới đây dùng các abstraction ứng dụng để không phụ thuộc API cụ thể của một phiên bản Optimizely. Adapter CMS phải kiểm tra published state, culture và content permissions thực tế.

```csharp
public interface IPublicPageReader
{
    Task<PublishedPage?> FindAsync(
        string siteId, string culture, string slug,
        CancellationToken ct);
}
public interface IPreviewPageReader
{
    Task<PreviewPage?> FindAuthorizedAsync(
        ClaimsPrincipal editor, string siteId,
        string culture, string slug, CancellationToken ct);
}
public record PublishedPage(
    string Id, string Revision, string Title, string Html);
public record PreviewPage(string Title, string Html);

[ApiController]
[Route("api/pages")]
public sealed class SafePagesController(
    ISiteResolver sites,
    IPublicPageReader publicPages,
    IPreviewPageReader previewPages,
    IMemoryCache cache) : ControllerBase
{
    [HttpGet("{slug}")]
    public async Task<IActionResult> Public(
        string slug, CancellationToken ct)
    {
        var site = sites.Resolve(Request.Host);
        if (site is null) return NotFound();
        var culture = sites.ResolveCulture(Request, site);
        var page = await publicPages.FindAsync(
            site.Id, culture, slug, ct);
        if (page is null) return NotFound();

        var key = $"page:v2:{site.Id}:{culture}:{page.Id}:{page.Revision}";
        var dto = cache.GetOrCreate(key, entry =>
        {
            entry.AbsoluteExpirationRelativeToNow =
                TimeSpan.FromMinutes(2);
            entry.Size = 1;
            return new PageDto(page.Title, page.Html, site.Id);
        });
        Response.Headers.CacheControl = "public,max-age=120";
        return Ok(dto);
    }

    [Authorize(Policy = "CmsEditor")]
    [HttpGet("{slug}/preview")]
    public async Task<IActionResult> Preview(
        string slug, CancellationToken ct)
    {
        Response.Headers.CacheControl = "private,no-store";
        var site = sites.Resolve(Request.Host);
        if (site is null) return NotFound();
        var culture = sites.ResolveCulture(Request, site);
        var page = await previewPages.FindAuthorizedAsync(
            User, site.Id, culture, slug, ct);
        return page is null ? NotFound() :
            Ok(new { page.Title, page.Html });
    }
}
```

`ISiteResolver` phải chỉ chấp nhận configured host; `IPreviewPageReader` phải kiểm tra quyền ở mức content. Cấu hình `IMemoryCache` cần `SizeLimit` tương ứng hoặc bỏ `Size` và dùng cache có chính sách riêng. Cần đảm bảo response preview không bị edge cache bởi CDN rules, kể cả khi origin gửi `no-store`. Published revision phải thay đổi khi nội dung public thay đổi. HTML chỉ được đưa ra sau quy trình validation/sanitization đã chọn.

## Giải thích thiết kế sau khi sửa

Public và preview có trust boundary khác nhau. Public delivery không phụ thuộc quyền editor và chỉ truy cập published content; preview không dùng shared cache. Cache key theo identity và revision giúp tránh tái sử dụng payload cũ giữa site/culture. Host resolution phải được kiểm soát phía server. Publish event có thể purge CDN theo surrogate key; nếu invalidation event bị mất, TTL và reconciliation là lớp bảo vệ bổ sung. Khi phát hiện leak, ưu tiên vô hiệu hóa preview public route, purge edge và app caches, kiểm tra access logs rồi mới tối ưu performance.

## Trade-offs

Revision-key tăng số cache entries và có thể tạo orphan entries cho đến khi eviction; TTL ngắn làm tăng origin load. Purge nhanh phụ thuộc CDN API và propagation, không bảo đảm đồng thời tuyệt đối. Một distributed cache có thể giúp consistency đa instance nhưng thêm dependency và failure mode; không bắt buộc nếu origin lookup rẻ và CDN hit cao. Sanitization cần cân bằng khả năng biên tập và security.

## Cách kiểm thử

1. **Security integration:** Anonymous gọi preview phải bị từ chối; editor không có quyền với site khác không được đọc draft.
2. **Concurrency:** Nhiều request đồng thời cùng slug khác site/culture không trả chéo nội dung.
3. **Publish/rollback:** Publish revision mới, purge thất bại, retry và rollback đều có kết quả theo SLA đã xác định.
4. **Load:** Đo p95 origin, memory, hit ratio và content lookup count ở 3.000 RPS giả định.
5. **XSS/E2E:** Nội dung HTML nguy hiểm từ nguồn ít tin cậy không thực thi script trên website.

## Quan sát trong production

Application Insights: `siteId`, `contentId`, `revision`, `publicationState`, `cacheLayer`, `cacheHit`, `correlationId` (không lưu HTML/token). Theo dõi cache hit ratio theo tenant, p95/p99, memory, origin requests, publish-to-visible latency, CDN `Age` và cache status. Alert khi public response chứa revision không thuộc published manifest; kiểm tra audit logs của CMS và purge history.

## Câu hỏi phỏng vấn mở rộng

1. Nếu CDN purge mất 10 phút, làm sao giữ nội dung chưa publish không bị lộ ngay cả khi origin đã sửa?
2. Khi có 20 ngôn ngữ và 1 triệu page, bạn thay đổi cache strategy thế nào?
3. Có nên dùng Redis thay `IMemoryCache` nếu traffic chủ yếu được CDN phục vụ?

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue';

type Employee = { id: string; name: string; department: string };
const query = ref('');
const department = ref('all');
const page = ref(1);
const employees = ref<Employee[]>([]);
const total = ref(0);
const loading = ref(false);
const selected = ref<Employee | null>(null);

async function load() {
  loading.value = true;
  const url = '/api/employees?q=' + query.value +
    '&department=' + department.value + '&page=' + page.value;
  const response = await fetch(url, { credentials: 'include' });
  const result = await response.json();
  employees.value = result.items;
  total.value = result.total;
  loading.value = false;
}

watch([query, department, page], load);
onMounted(load);

function select(employee: Employee) {
  selected.value = employee;
}
</script>

<template>
```

## Kết quả code review tham khảo

### Critical — Stored XSS qua v-html

**Vấn đề:** Tên nhân viên từ hệ thống ngoài được render bằng `v-html`.  
**Tại sao xảy ra:** Vue không escape HTML trong directive này.  
**Ảnh hưởng production:** Nếu dữ liệu chứa markup nguy hiểm, có thể thực thi script trong origin của portal.  
**Cách sửa:** Dùng text interpolation `{{ selected.name }}`; chỉ dùng HTML khi có nhu cầu thực và sanitization đáng tin cậy.

### High — Request race ghi đè state

**Vấn đề:** Response cũ có thể cập nhật danh sách sau response mới.  
**Tại sao xảy ra:** Không có cancellation hay request sequence guard.  
**Ảnh hưởng production:** Người dùng xem dữ liệu không đúng filter, có thể ra quyết định sai.  
**Cách sửa:** Abort request cũ và dùng sequence ID bảo đảm latest-request-wins.

### High — Không kiểm tra response.ok

**Vấn đề:** HTTP 401/403/500 vẫn được parse và gán như thành công.  
**Tại sao xảy ra:** `fetch` chỉ reject với network-level failure hoặc abort, không tự reject HTTP error status.  
**Ảnh hưởng production:** UI lỗi, dữ liệu sai shape, không phân biệt session expired với backend outage.  
**Cách sửa:** Kiểm tra status, xử lý lỗi có phân loại, schema validation ở boundary.

### High — Không cleanup loading/error khi throw

**Vấn đề:** `loading=false` không chạy nếu request/json throw.  
**Tại sao xảy ra:** Thiếu `try/catch/finally`.  
**Ảnh hưởng production:** Spinner kẹt, lỗi không có thông báo.  
**Cách sửa:** Error state, `finally` có guard, hiển thị retry có kiểm soát.

### Medium — Không reset page khi filter thay đổi

**Vấn đề:** Search mới vẫn ở trang cũ.  
**Tại sao xảy ra:** Watch cùng ba nguồn nhưng không phân biệt filter và pagination.  
**Ảnh hưởng production:** Danh sách trống giả, total không nhất quán.  
**Cách sửa:** Reset page về 1 khi query hoặc department đổi.

### Medium — Request không encode query

**Vấn đề:** Ghép URL trực tiếp với input.  
**Tại sao xảy ra:** Thiếu `URLSearchParams`.  
**Ảnh hưởng production:** Ký tự `&`, `#`, Unicode làm sai query semantics.  
**Cách sửa:** Dùng `URLSearchParams` và validate input ở backend.

### Medium — Không debounce input

**Vấn đề:** Mỗi lần gõ đều gửi request.  
**Tại sao xảy ra:** Watch trực tiếp `query`.  
**Ảnh hưởng production:** Request amplification, tăng API/DB load, giảm UX.  
**Cách sửa:** Debounce 250–400 ms theo nhu cầu UX; vẫn cần cancellation.

### Medium — Không giới hạn pagination và state selection

**Vấn đề:** `page++` không có bound; selected employee giữ từ filter cũ.  
**Tại sao xảy ra:** Không kiểm tra total/pages hoặc reset selection.  
**Ảnh hưởng production:** Request vô ích, detail hiển thị không liên quan.  
**Cách sửa:** Clamp page, disable next khi hết dữ liệu, reset selection khi filter đổi; backend giới hạn page size.

```vue
const error = ref('');
const selected = ref<Employee | null>(null);
let controller: AbortController | undefined;
let generation = 0;
let debounce: ReturnType<typeof setTimeout> | undefined;

async function load() {
  const id = ++generation;
  controller?.abort();
  controller = new AbortController();
  const signal = controller.signal;
  loading.value = true;
  error.value = '';
  try {
    const params = new URLSearchParams({
      q: query.value.trim(),
      department: department.value,
      page: String(page.value)
    });
    const response = await fetch('/api/employees?' + params, {
      credentials: 'include', signal
    });
    if (!response.ok) throw new Error('HTTP ' + response.status);
    const data: Result = await response.json();
    if (!Array.isArray(data.items) ||
        !Number.isFinite(data.total)) throw new Error('Invalid response');
    if (id !== generation) return;
    employees.value = data.items;
    total.value = data.total;
  } catch (e) {
    if (id !== generation || signal.aborted) return;
    error.value = e instanceof Error ? e.message : 'Request failed';
    employees.value = [];
    total.value = 0;
  } finally {
    if (id === generation) loading.value = false;
  }
}

watch([query, department], () => {
  page.value = 1;
  selected.value = null;
  clearTimeout(debounce);
  controller?.abort();
  ++generation;
  loading.value = false;
  debounce = setTimeout(load, 300);
});
watch(page, () => {
  clearTimeout(debounce);
  void load();
});
void load();
onBeforeUnmount(() => {
  clearTimeout(debounce);
  controller?.abort();
  ++generation;
});
function next() {
  if (page.value * 20 < total.value) page.value++;
}
</script>

<template>
  <section>
    <input v-model="query" aria-label="Tìm nhân viên" />
    <select v-model="department">
      <option value="all">Tất cả</option>
      <option value="sales">Sales</option>
      <option value="hr">HR</option>
    </select>
    <button :disabled="loading || page * 20 >= total" @click="next">
      Trang tiếp
    </button>
    <p v-if="loading">Đang tải...</p>
    <p v-if="error" role="alert">{{ error }}</p>
    <p>Tổng: {{ total }}</p>
    <ul>
      <li v-for="e in employees" :key="e.id">
        <button @click="selected = e">{{ e.name }} — {{ e.department }}</button>
      </li>
    </ul>
    <article v-if="selected">{{ selected.name }}</article>
  </section>
</template>
```

*Điều kiện của bản đề xuất:* API dùng page size 20 cố định; nếu contract khác, phải lấy `pageSize`/`hasNext` từ response. Việc kiểm tra `Result` ở đây mới là tối thiểu; production nên validate toàn bộ item schema tại API boundary. Khi đổi filter trong lúc page khác 1, watcher của page có thể phát một request tức thì trước request debounce; guard bảo đảm state không bị ghi đè nhưng còn request thừa. Có thể tinh chỉnh bằng một watcher điều phối duy nhất hoặc composable query state nếu cần giảm tải thêm.

## Giải thích thiết kế sau khi sửa

Sequence guard bảo vệ correctness kể cả khi abort đến muộn hoặc response đã hoàn thành. Abort giúp giảm công việc vô ích nhưng không bảo đảm backend ngừng xử lý. `URLSearchParams` xử lý encoding. Text interpolation escape HTML theo mặc định. Error state tách biệt loading. Backend vẫn phải enforce authorization, filtering, maximum page size và rate limits; frontend chỉ cải thiện trải nghiệm, không phải security boundary.

## Trade-offs

Debounce giảm tải nhưng tăng độ trễ trước khi search; cần chọn dựa trên latency thực. Abort không thay thế deduplication/cache ở server. Sequence guard thêm state và cần test race; thư viện query như TanStack Query có thể giảm code tùy stack, nhưng không bắt buộc cho một màn hình đơn giản. Việc xóa danh sách khi lỗi tránh dữ liệu sai ngữ cảnh nhưng có thể gây flicker; giữ dữ liệu cũ cần nhãn stale rõ ràng.

## Cách kiểm thử

1. **Race E2E:** Playwright intercept A chậm hơn B; chỉ kết quả B được hiển thị.
2. **Failure-path:** 401, 403, 500, JSON sai schema, offline và abort đều không để spinner kẹt.
3. **Security:** Tên chứa `<img onerror=...>` phải hiển thị dạng text, không thực thi.
4. **Pagination:** Đang page 12 đổi filter phải quay page 1; nút Next dừng đúng boundary.
5. **Load/network:** Gõ nhanh 20 ký tự, đo số request, abort, p95 latency và backend query count.

## Quan sát trong production

Frontend telemetry: query generation ID (không log tên người tìm), duration, HTTP status, abort count, stale response suppressed, JS errors, request count per interaction. Backend: trace ID xuyên frontend/API, p95/p99, 401/403/5xx, database query latency, rate-limit metrics. Alert theo tỷ lệ lỗi thực, không coi request chủ động abort là server outage. Theo dõi accessibility errors qua Playwright.

## Câu hỏi phỏng vấn mở rộng

1. Nếu API trả dữ liệu phân trang bằng cursor thay vì page number, bạn thay đổi state model thế nào?
2. Khi có nhiều tab và session hết hạn, frontend nên phối hợp refresh/login ra sao mà không tạo retry storm?
3. Khi nào dùng query library thay vì tự viết cancellation và caching?

# Tổng kết hôm nay

## Kiến thức trọng tâm

Hai bài tập kiểm tra hai trust boundary khác nhau: CMS public/preview với cache nhiều tầng, và Vue async state với dữ liệu không đáng tin cậy.
