## Bối cảnh

Enterprise portal trên 4 Azure App Service instances tải PDF từ provider; 100 request/giây lúc cao điểm, file có thể hàng trăm MB. DocumentLinks chứa Id, OwnerUserId, RemoteUrl, FileName; integration ngoài có thể cập nhật URL. Production ghi nhận memory tăng, timeout và outbound traffic đến private IP. Chưa biết provider có redirect hay không.

## Đoạn code cần review

```csharp
[ApiController]
[Authorize]
[Route("api/documents")]
public sealed class DocumentsController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<DocumentsController> _log;
    public DocumentsController(AppDbContext db, ILogger<DocumentsController> log)
    {
        _db = db;
        _log = log;
    }

    [HttpGet("{id:guid}/download")]
    public async Task<IActionResult> Download(Guid id)
    {
        var doc = await _db.DocumentLinks
            .FirstOrDefaultAsync(x => x.Id == id);
        if (doc == null) return NotFound();

        using var client = new HttpClient();
        var response = await client.GetAsync(doc.RemoteUrl);
        var bytes = await response.Content.ReadAsByteArrayAsync();

        _log.LogInformation("Download {Url} {User} {Size}",
            doc.RemoteUrl, User.Identity?.Name, bytes.Length);

        return File(bytes, "application/pdf", doc.FileName);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — SSRF qua RemoteUrl

**Vấn đề:** SSRF qua RemoteUrl.
**Tại sao xảy ra:** URL do integration điều khiển có thể trỏ tới loopback/private/metadata endpoint; redirect và DNS rebinding làm kiểm tra URL ban đầu không đủ.
**Ảnh hưởng production:** Lộ dữ liệu hoặc truy cập service nội bộ.
**Cách sửa:** Dùng provider registry với origin cố định, HTTPS, disable redirect hoặc xác minh mọi hop; egress policy chặn private/link-local/reserved IP tại kết nối.

### [High] — Broken object-level authorization

**Vấn đề:** Broken object-level authorization.
**Tại sao xảy ra:** Chỉ yêu cầu đăng nhập, không đối chiếu OwnerUserId/tenant.
**Ảnh hưởng production:** Rò rỉ tài liệu giữa người dùng.
**Cách sửa:** Query theo principal/tenant và áp authorization policy; không dùng GUID làm bảo mật.

### [High] — Unbounded response buffering

**Vấn đề:** Unbounded response buffering.
**Tại sao xảy ra:** GetAsync mặc định ResponseContentRead; ReadAsByteArrayAsync giữ toàn bộ file trong memory.
**Ảnh hưởng production:** LOH/GC pressure, OOM và p99 xấu khi concurrent download.
**Cách sửa:** ResponseHeadersRead, bounded stream, giới hạn kích thước thực đọc, giới hạn concurrency; cân nhắc Blob SAS.

### [High] — Trả error body như PDF

**Vấn đề:** Trả error body như PDF.
**Tại sao xảy ra:** Không kiểm tra response.IsSuccessStatusCode và content policy.
**Ảnh hưởng production:** Client nhận HTML lỗi dưới tên PDF.
**Cách sửa:** Map lỗi upstream sang 502/504 hoặc 404 theo contract; không forward raw error.

### [Medium] — HttpClient mỗi request

**Vấn đề:** HttpClient mỗi request.
**Tại sao xảy ra:** Handler/connection pooling không được tái sử dụng.
**Ảnh hưởng production:** Connection churn, socket/port pressure.
**Cách sửa:** IHttpClientFactory với handler lifetime và timeout phù hợp.

### [Medium] — Không có cancellation/deadline

**Vấn đề:** Không có cancellation/deadline.
**Tại sao xảy ra:** Không truyền RequestAborted hoặc deadline cho EF/HTTP.
**Ảnh hưởng production:** Request treo tiếp tục tiêu thụ tài nguyên.
**Cách sửa:** Linked CancellationToken, upstream deadline và cancel khi disconnect.

### [Medium] — Metadata và payload chưa được validate

**Vấn đề:** Metadata và payload chưa được validate.
**Tại sao xảy ra:** Không giới hạn size, filename, loại file; tin metadata từ integration.
**Ảnh hưởng production:** Tải file không mong muốn, tăng chi phí và rủi ro nội dung.
**Cách sửa:** Giới hạn bytes thực tế, filename server-generated, kiểm tra MIME và signature theo policy.

### [Medium] — Log URL có thể chứa credential

**Vấn đề:** Log URL có thể chứa credential.
**Tại sao xảy ra:** Signed URL/query token được ghi nguyên văn.
**Ảnh hưởng production:** Lộ secrets trong log.
**Cách sửa:** Log DocumentId, provider ID, duration, status, correlation ID; redact URL.

### [Low] — Tracking entity đọc-only

**Vấn đề:** Tracking entity đọc-only.
**Tại sao xảy ra:** EF Core tracking cả entity dù chỉ dùng metadata.
**Ảnh hưởng production:** Overhead nhỏ trên hot path.
**Cách sửa:** AsNoTracking và projection các cột cần thiết.

## Phiên bản đề xuất

```csharp
[ApiController]
[Authorize]
[Route("api/documents")]
public sealed class DocumentsController(
    AppDbContext db, IUserDocumentAccess access,
    IProviderRegistry registry, ILimitedDownloadService downloads,
    ILogger<DocumentsController> log) : ControllerBase
{
    [HttpGet("{id:guid}/download")]
    public async Task<IActionResult> Download(Guid id, CancellationToken ct)
    {
        var doc = await db.DocumentLinks.AsNoTracking()
            .Where(x => x.Id == id)
            .Select(x => new {
                x.Id, x.OwnerUserId, x.ProviderId, x.RemoteDocumentId
            }).SingleOrDefaultAsync(ct);
        if (doc is null) return NotFound();
        if (!await access.CanDownloadAsync(User, doc.OwnerUserId, ct))
            return Forbid();
        if (!registry.TryGet(doc.ProviderId, out var provider))
            return StatusCode(502);

        // FetchPdfAsync: fixed trusted origin, no unvalidated redirects,
        // egress policy, deadline, max-byte enforcement, content validation.
        try
        {
            await using var file = await downloads.FetchPdfAsync(
                provider, doc.RemoteDocumentId, 25_000_000, ct);
            Response.ContentType = "application/pdf";
            Response.Headers.ContentDisposition =
                $"attachment; filename=\"document-{id:N}.pdf\"";
            await file.CopyToAsync(Response.Body, ct);
            log.LogInformation("Delivered {DocumentId}", id);
            return new EmptyResult();
        }
        catch (UpstreamUnavailableException ex)
        {
            log.LogWarning(ex, "Provider failed {DocumentId}", id);
            if (Response.HasStarted) { HttpContext.Abort(); return new EmptyResult(); }
            return StatusCode(502);
        }
    }
}
```

## Giải thích thiết kế sau khi sửa

IProviderRegistry, IUserDocumentAccess và ILimitedDownloadService là abstraction cần tự triển khai, không phải API .NET built-in. FetchPdfAsync phải enforce DNS/IP egress và giới hạn byte trong vòng đọc. Nếu response đã bắt đầu, không thể đổi status thành 502; abort và ghi telemetry. Nếu cần kiểm tra toàn file trước khi trả, spool có giới hạn vào storage tạm rồi stream; xử lý cleanup. Cần bổ sung mapping cho timeout, quá size và invalid content trước khi production.

## Trade-offs

- Streaming giảm memory nhưng lỗi giữa response không thể đổi HTTP status.
- Spooling tăng I/O và latency nhưng cho phép validate trước khi gửi.
- Blob SAS giảm tải App Service nhưng cần expiry, permission và audit.
- Egress restrictions cần duy trì allowlist khi provider thay đổi.

## Cách kiểm thử

1. Security: tenant A không tải được document B; private IP, redirect, DNS rebinding bị chặn.
2. Load: 100 concurrent file lớn; đo memory/GC, connections, p95.
3. Failure-path: upstream 404/500/timeout/disconnect; không trả file lỗi giả PDF.
4. Integration: PDF hợp lệ, filename an toàn, size cap, client cancellation.

## Quan sát trong production

Application Insights dependency traces theo provider, status, duration; Azure Monitor memory/GC, CPU, outbound connections, p95/p99; log DocumentId và correlation ID; alert SSRF-block, upstream 5xx, byte-cap violations; không log signed URLs.

## Câu hỏi phỏng vấn mở rộng

1. Nếu provider bắt buộc redirect qua CDN nhiều domain, làm sao giữ trust boundary?
2. Nếu file 2 GB, chọn streaming, background export hay Blob SAS?
3. Làm sao phát hiện partial download khi headers đã gửi?

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue'
type Campaign = { id: string; title: string; html: string }
const props = defineProps<{ campaignId: string }>()
const campaign = ref<Campaign | null>(null)
const saving = ref(false)
const error = ref('')
let timer: ReturnType<typeof setTimeout> | undefined

async function load() {
  const r = await fetch('/api/campaigns/' + props.campaignId)
  campaign.value = await r.json()
}
async function save() {
  if (!campaign.value) return
  saving.value = true
  const r = await fetch('/api/campaigns/' + props.campaignId, {
    method: 'PUT',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(campaign.value)
  })
  if (!r.ok) error.value = 'Save failed'
  saving.value = false
}
watch(() => props.campaignId, load)
watch(campaign, () => {
  clearTimeout(timer)
  timer = setTimeout(save, 400)
}, { deep: true })
onMounted(load)
</script>
<template>
  <section v-if="campaign">
    <input v-model="campaign.title" />
    <textarea v-model="campaign.html" />
    <div v-html="campaign.html"></div>
    <span v-if="saving">Saving...</span>
    <p v-if="error">{{ error }}</p>
  </section>
</template>
```

## Phiên bản đề xuất

```typescript
// Contract đề xuất: GET trả {id,title,html,version}.
// PUT dùng If-Match; server atomic compare-and-update, trả 412.
type Campaign = { id:string; title:string; html:string; version:string }
const draft = ref<Campaign | null>(null)
const status = ref<'idle'|'dirty'|'saving'|'saved'|'conflict'|'error'>('idle')
let seq = 0
let loadAbort: AbortController | undefined
let timer: ReturnType<typeof setTimeout> | undefined
let pending = false
let busy = false

watch(() => props.campaignId, async (id, _, cleanup) => {
  const current = ++seq
  loadAbort?.abort()
  const ctrl = new AbortController()
  loadAbort = ctrl
  clearTimeout(timer)
  draft.value = null
  cleanup(() => ctrl.abort())
  try {
    const r = await fetch('/api/campaigns/' + encodeURIComponent(id),
      { signal: ctrl.signal })
    if (!r.ok) throw new Error('GET failed')
    const data = await r.json() as Campaign
    if (current === seq && data.id === id) draft.value = data
  } catch {
    if (!ctrl.signal.aborted && current === seq) status.value = 'error'
  }
}, { immediate: true })

function edited() {
  if (!draft.value) return
  status.value = 'dirty'
  pending = true
  clearTimeout(timer)
  timer = setTimeout(() => { void flush() }, 400)
}
async function flush() {
  if (busy) return
  busy = true
  try {
    while (pending && draft.value?.id === props.campaignId) {
      pending = false
      const snap = { ...draft.value }
      status.value = 'saving'
      const r = await fetch('/api/campaigns/' + encodeURIComponent(snap.id), {
        method: 'PUT',
        headers: { 'Content-Type':'application/json',
                   'If-Match':snap.version },
        body: JSON.stringify({ title:snap.title, html:snap.html })
      })
      if (r.status === 412) { status.value = 'conflict'; break }
      if (!r.ok) { status.value = 'error'; break }
      const saved = await r.json() as Campaign
      if (draft.value?.id !== snap.id) break
      draft.value.version = saved.version
      if (draft.value.title !== snap.title ||
          draft.value.html !== snap.html) pending = true
      else status.value = 'saved'
    }
  } catch { status.value = 'error' }
  finally { busy = false }
}
onUnmounted(() => { clearTimeout(timer); loadAbort?.abort() })
// Template: bind input events to edited(); render preview as
// <pre>{{ draft?.html }}</pre> or sanitized HTML only.
```

## Giải thích thiết kế sau khi sửa

Đây là lõi minh họa, chưa phải component production hoàn chỉnh: phải import watch/onUnmounted/ref, thêm dirty-navigation guard, per-campaign queue và đảm bảo save cũ không đổi status của campaign mới. Khi conflict, ngừng autosave cho tới khi user resolve. Nếu save lỗi, giữ draft dirty và có retry do user chủ động. Backend bắt buộc enforce authorization, validate schema và update atomically theo version; không chỉ tin client. Với cross-origin API cần expose ETag nếu version lấy từ response header.

## Trade-offs

- Optimistic concurrency tránh khóa dài nhưng đòi hỏi conflict resolution UX.
- Autosave giảm mất dữ liệu nhưng tăng request và state complexity; manual save có thể phù hợp hơn.
- Plain text preview an toàn hơn rich HTML; sanitizer cần policy và regression tests.
- Abort GET không thay server-side authorization/cancellation.

## Cách kiểm thử

1. Race: GET A về sau GET B; UI chỉ hiển thị B.
2. Concurrency: hai editor PUT cùng version, một nhận 412; database giữ bản hợp lệ.
3. Network: PUT reorder/lost response; không ghi đè bản mới.
4. Security: HTML chứa event handler, javascript URL, SVG không thực thi.
5. Playwright E2E: unmount, dirty navigation, retry 500 và conflict UI.

## Quan sát trong production

Client: campaign ID không nhạy cảm, request sequence, version, 412 rate, dirty duration, save latency; backend structured logs với correlation ID, conditional-update failures, p95/p99 và 4xx/5xx; không log HTML hoặc token.

## Câu hỏi phỏng vấn mở rộng

1. Khi nào ETag không đủ cho collaborative editing real-time?
2. Offline 20 phút rồi reconnect, làm sao merge?
3. PUT thành công nhưng response mất: retry và conflict UX thế nào?
