## Bối cảnh

Catalog e-commerce có 2 triệu sản phẩm; PostgreSQL là source of truth và Elasticsearch là search projection. Ba App Service instances chạy worker đồng bộ mỗi 10 giây. Sau deploy, giá tìm kiếm cũ, sản phẩm đã xóa vẫn xuất hiện; log vẫn báo index thành công. Giả định `ISearchIndex.BulkAsync` trả kết quả từng item, nhưng code hiện tại bỏ qua kết quả đó.

## Đoạn code cần review

```csharp
public sealed class CatalogWorker : BackgroundService
{
    private readonly IServiceScopeFactory _factory;
    private readonly ISearchIndex _index;
    private readonly ILogger<CatalogWorker> _logger;
    private static DateTime _cursor = DateTime.UtcNow.AddMinutes(-5);

    public CatalogWorker(IServiceScopeFactory factory,
        ISearchIndex index, ILogger<CatalogWorker> logger)
    {
        _factory = factory;
        _index = index;
        _logger = logger;
    }

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            using var scope = _factory.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<CatalogDbContext>();
            var rows = await db.Products
                .Where(p => p.UpdatedAt > _cursor)
                .OrderBy(p => p.UpdatedAt)
                .Take(500)
                .Select(p => new ProductDocument(p.Id, p.Name,
                    p.Price, p.IsVisible, p.UpdatedAt))
                .ToListAsync();
            if (rows.Count != 0)
            {
                _cursor = rows.Max(p => p.UpdatedAt);
                await _index.BulkAsync(rows);
                _logger.LogInformation("Indexed {Count}", rows.Count);
            }
            await Task.Delay(10000);
        }
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Checkpoint trước acknowledgment

**Vấn đề:** Cursor tiến trước `BulkAsync`. **Tại sao xảy ra:** Exception hoặc partial failure sau cursor update làm batch bị bỏ qua. **Ảnh hưởng production:** Mất cập nhật. **Cách sửa:** Ack sau xác nhận từng item, giữ failed events retryable.

### [Critical] — Timestamp cursor bỏ sót hàng cùng thời điểm

**Vấn đề:** `>` kết hợp `Take(500)`. **Tại sao xảy ra:** Timestamp không unique. **Ảnh hưởng production:** Missing documents. **Cách sửa:** Durable keyset `(UpdatedAt, Id)` hoặc sequence outbox; lưu ý keyset timestamp vẫn có rủi ro late commit.

### [High] — Static state không dùng chung giữa instances

**Vấn đề:** Cursor process-local, reset sau restart. **Tại sao xảy ra:** Mỗi process có memory riêng. **Ảnh hưởng production:** Duplicate work và reorder. **Cách sửa:** Durable consumer ownership, lease có fencing hoặc atomic queue claim; không coi static lock là distributed lock.

### [High] — Không đọc partial bulk errors

**Vấn đề:** Response item-level bị bỏ qua. **Tại sao xảy ra:** Transport success không đồng nghĩa item success. **Ảnh hưởng production:** Silent data loss. **Cách sửa:** Parse từng outcome, retry transient errors, quarantine permanent failures.

### [High] — Stale write có thể ghi đè new write

**Vấn đề:** Không có monotonic product version. **Tại sao xảy ra:** Concurrent requests hoàn tất không theo thứ tự phát sinh. **Ảnh hưởng production:** Giá và visibility bị rollback. **Cách sửa:** External version/conditional update tương thích Elasticsearch client version, hoặc ordered per-key consumer.

### [High] — Hard delete không được truyền sang search

**Vấn đề:** Chỉ query rows đang tồn tại. **Tại sao xảy ra:** Deleted row biến mất khỏi polling. **Ảnh hưởng production:** Ghost product. **Cách sửa:** Transactional outbox chứa delete tombstone.

### [Medium] — Cancellation không propagate

**Vấn đề:** DB/search/delay không nhận `ct`. **Tại sao xảy ra:** Thiếu token forwarding. **Ảnh hưởng production:** Shutdown chậm, I/O thừa. **Cách sửa:** Truyền token xuyên các lớp và không ack khi bị hủy.

### [Medium] — Không có retry/error boundary

**Vấn đề:** Exception thoát `ExecuteAsync`. **Tại sao xảy ra:** Thiếu catch/backoff. **Ảnh hưởng production:** Worker dừng hoặc ảnh hưởng host tùy cấu hình. **Cách sửa:** Retry có phân loại, exponential backoff, alert; lỗi cấu hình permanent phải fail visibly.

### [Medium] — Không chứng minh được completeness

**Vấn đề:** Timestamp có thể được ghi trước commit; commit trễ hơn checkpoint. **Tại sao xảy ra:** Timestamp order khác commit visibility. **Ảnh hưởng production:** Missed updates dù cursor unique. **Cách sửa:** Transactional outbox/CDC, periodic reconciliation và backlog monitoring.

## Phiên bản đề xuất

Đây là application skeleton, phụ thuộc các interface **phải được triển khai** bằng transaction PostgreSQL, atomic claims và version enforcement; không tự cung cấp distributed lock.

```csharp
public record CatalogChange(long Sequence, Guid ProductId,
    long Version, string Operation, ProductDocument? Data);
public enum ApplyResult { Applied, AlreadyApplied, Retry, Reject }
public interface IOutbox
{
    Task<IReadOnlyList<CatalogChange>> ClaimAsync(int count, CancellationToken ct);
    Task AckAsync(long sequence, CancellationToken ct);
    Task RetryAsync(long sequence, string reason, CancellationToken ct);
}
public interface IVersionedIndex
{
    Task<ApplyResult> ApplyAsync(CatalogChange change, CancellationToken ct);
}
public sealed class ProjectionWorker(IServiceScopeFactory factory,
    ILogger<ProjectionWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            try
            {
                using var scope = factory.CreateScope();
                var outbox = scope.ServiceProvider.GetRequiredService<IOutbox>();
                var index = scope.ServiceProvider.GetRequiredService<IVersionedIndex>();
                var batch = await outbox.ClaimAsync(100, ct);
                foreach (var change in batch)
                {
                    var outcome = await index.ApplyAsync(change, ct);
                    if (outcome is ApplyResult.Applied or ApplyResult.AlreadyApplied)
                        await outbox.AckAsync(change.Sequence, ct);
                    else
                        await outbox.RetryAsync(change.Sequence, outcome.ToString(), ct);
                }
                if (batch.Count == 0)
                    await Task.Delay(TimeSpan.FromSeconds(5), ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested) { break; }
            catch (Exception ex)
            {
                log.LogError(ex, "Projection failed");
                await Task.Delay(TimeSpan.FromSeconds(5), ct);
            }
        }
    }
}
```

Trong cùng transaction nghiệp vụ: update product và insert outbox event với version tăng đơn điệu. `ClaimAsync` cần lease expiry/atomic claim; không được để một worker chết giữ message mãi. `RetryAsync` phải lên lịch backoff và quarantine; `ApplyAsync` cần xử lý delete, partial failure, version conflict và idempotency. Nếu out-of-order events cho cùng product không được chấp nhận, partition theo key hoặc enforce version tại index.

## Giải thích thiết kế sau khi sửa

Outbox khép khoảng trống commit → projection. Acknowledgment chỉ sau khi index xác nhận; retry được thiết kế cùng idempotency. Reconciliation định kỳ phát hiện drift. Search là read model eventual consistent; giá thanh toán phải kiểm tra ở source of truth.

## Trade-offs

Outbox tăng storage và operations; per-item API đơn giản nhưng throughput thấp, có thể bulk và ack từng item. Atomic claim cho nhiều worker tăng throughput nhưng phức tạp hơn single owner. Nếu tải nhỏ, polling với durable cursor và overlap/reconciliation có thể phù hợp, nhưng cần chứng minh không mất late commits.

## Cách kiểm thử

1. Integration: product transaction rollback không sinh event; commit sinh event.
2. Failure-path: 1/100 bulk item lỗi, chỉ 99 được ack.
3. Concurrency: hai workers claim đồng thời, retry và version không rollback.
4. Database: 800 updates cùng timestamp, hard delete, late commit.
5. Load: burst 100k events, đo p95 lag, backlog và index drift.

## Quan sát trong production

Structured logs `sequence/productId/version/attempt/traceId`; metrics oldest pending age, retry/quarantine count, bulk partial failures, index lag, reconciliation mismatch, PostgreSQL lock waits; Application Insights dependency tracing và alert theo backlog age.

function ProductSearch() {
  const [keyword, setKeyword] = useState("");
  const [category, setCategory] = useState("all");
  const [page, setPage] = useState(1);
  const [products, setProducts] = useState<Product[]>([]);
  const [total, setTotal] = useState(0);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  useEffect(() => {
    setLoading(true);
    fetch(`/api/products?q=${keyword}&category=${category}&page=${page}`)
      .then(response => response.json())
      .then((data: ProductResponse) => {
        setProducts(data.items);
        setTotal(data.total);
        setError("");

        setProducts([]);
        setError("No products found");

      onChange={e => setKeyword(e.target.value)} />
    <select value={category}

      <option value="all">All</option>
      <option value="books">Books</option>

    {error && <p role="alert">{error}</p>}
    <ul>{products.map(p => <li key={p.id}>{p.name}</li>)}</ul>
    <p>Total: {total}</p>
    <button disabled={page === 1} onClick={() => setPage(page - 1)}>Prev</button>
    <button onClick={() => setPage(page + 1)}>Next</button>
  </section>;
}

## Kết quả code review tham khảo

### [High] — Out-of-order response overwrite

**Vấn đề:** Response cũ ghi state sau response mới. **Tại sao xảy ra:** Promise completion không theo request order. **Ảnh hưởng production:** UI hiển thị sai kết quả. **Cách sửa:** AbortController cleanup + active guard.

### [High] — HTTP errors không được kiểm tra

**Vấn đề:** Parse JSON cho cả HTTP 500. **Tại sao xảy ra:** `fetch` không tự reject theo HTTP status. **Ảnh hưởng production:** Error payload bị coi là success. **Cách sửa:** `response.ok`, runtime payload validation.

### [Medium] — Query string không encode

**Vấn đề:** Raw keyword ghép URL. **Tại sao xảy ra:** Reserved characters thay đổi semantics. **Ảnh hưởng production:** Search sai hoặc query bị cắt. **Cách sửa:** `URLSearchParams`.

### [Medium] — Mỗi keystroke tạo request

**Vấn đề:** Không debounce. **Tại sao xảy ra:** Effect theo keyword trực tiếp. **Ảnh hưởng production:** Request amplification. **Cách sửa:** Debounce theo UX, abort obsolete requests; server-side rate limiting nếu cần.

### [Medium] — Filter không reset page

**Vấn đề:** Page cũ giữ nguyên. **Tại sao xảy ra:** State độc lập. **Ảnh hưởng production:** False empty search. **Cách sửa:** Update query/filter và page=1 cùng event.

### [Medium] — Loading state race

**Vấn đề:** `finally` của request cũ tắt spinner mới. **Tại sao xảy ra:** Không xác minh request owner. **Ảnh hưởng production:** Trạng thái sai. **Cách sửa:** Chỉ effect active thay đổi loading.

### [Medium] — Error bị trình bày thành no results

**Vấn đề:** Catch xóa danh sách và báo không tìm thấy. **Tại sao xảy ra:** Trộn error với empty. **Ảnh hưởng production:** Che backend outage. **Cách sửa:** Separate error/empty/loading states.

### [Low] — Pagination không giới hạn cuối

**Vấn đề:** Next vượt `total`, updater dùng captured page. **Tại sao xảy ra:** Thiếu last-page guard. **Ảnh hưởng production:** Request vô ích. **Cách sửa:** Functional update và disable Next theo total.

## Phiên bản đề xuất

Giả định API pageSize=20, total là count sau filter. `isProductResponse` là validator tại network boundary; ví dụ kiểm tra tối thiểu, production nên kiểm tra schema đầy đủ.

```tsx
const SIZE = 20;
function ProductSearch() {
  const [input, setInput] = useState("");
  const [query, setQuery] = useState({ keyword: "", category: "all", page: 1 });
  const [result, setResult] = useState<ProductResponse | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState<string | null>(null);
  const [retry, setRetry] = useState(0);

  useEffect(() => {
    const timer = window.setTimeout(() => setQuery(q =>
      q.keyword === input ? q : { ...q, keyword: input, page: 1 }), 300);
    return () => clearTimeout(timer);
  }, [input]);

  useEffect(() => {
    const controller = new AbortController();
    let active = true;
    const params = new URLSearchParams({
      q: query.keyword, category: query.category,
      page: String(query.page), pageSize: String(SIZE)
    });
    setLoading(true);
    setError(null);
    setResult(null);
    async function load() {
      try {
        const response = await fetch(`/api/products?${params}`, {
          signal: controller.signal
        });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const body: unknown = await response.json();
        if (!isProductResponse(body)) throw new Error("Invalid payload");
        if (active) setResult(body);
      } catch {
        if (active && !controller.signal.aborted)
          setError("Không thể tải sản phẩm");
      } finally {
        if (active) setLoading(false);
      }
    }
    void load();
    return () => { active = false; controller.abort(); };
  }, [query, retry]);

  const last = Math.max(1, Math.ceil((result?.total ?? 0) / SIZE));
  return <section>
    <input aria-label="Search" value={input}
      onChange={e => setInput(e.target.value)} />
    <select aria-label="Category" value={query.category}
      onChange={e => setQuery(q => ({ ...q, category: e.target.value, page: 1 }))}>
      <option value="all">All</option><option value="books">Books</option>
    </select>
    <div role="status" aria-live="polite">
      {loading ? "Đang tải" : error ?? (result ? `${result.total} kết quả` : "")}
    </div>
    {error && <button onClick={() => setRetry(n => n + 1)}>Retry</button>}
    {!loading && !error && result?.items.length === 0 && <p>Không có kết quả</p>}
    <ul>{result?.items.map(p => <li key={p.id}>{p.name}</li>)}</ul>
    <button disabled={loading || query.page === 1}
      onClick={() => setQuery(q => ({ ...q, page: Math.max(1, q.page - 1) }))}>Prev</button>
    <span>Page {query.page} / {last}</span>
    <button disabled={loading || !result || query.page >= last}
      onClick={() => setQuery(q => ({ ...q, page: q.page + 1 }))}>Next</button>
  </section>;
}
function isProductResponse(v: unknown): v is ProductResponse {
  if (typeof v !== "object" || v === null) return false;
  const d = v as Record<string, unknown>;
  return Array.isArray(d.items) && d.items.every(p =>
    typeof p === "object" && p !== null &&
    typeof (p as Record<string, unknown>).name === "string" &&
    (typeof (p as Record<string, unknown>).id === "string" ||
     typeof (p as Record<string, unknown>).id === "number")) &&
    Number.isSafeInteger(d.total) && (d.total as number) >= 0;
}
```

Browser abort không bảo đảm backend lập tức dừng xử lý; server vẫn cần timeout, cancellation và rate limiting.

## Giải thích thiết kế sau khi sửa

1. Playwright: response A chậm hơn B, UI chỉ hiển thị B.
2. API: 500, malformed payload và empty 200 hiển thị đúng ba trạng thái.
3. Interaction: đổi filter từ page 20 về page 1.
4. Load: gõ 20 ký tự nhanh, đo request count.
5. Accessibility: keyboard navigation và live status.

Không log raw keyword có thể chứa PII. Development React StrictMode có thể chạy thêm effect setup/cleanup; không suy từ dev request count sang production.
