# Code Review Challenge 1 — IIS reverse proxy và tenant authorization trong API xuất hóa đơn

**Chủ đề:** ASP.NET Core, JWT, multi-tenancy, IIS, file streaming, security  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35–45 phút  
**Số vấn đề cần tìm:** khoảng 7

## Bối cảnh

Một ứng dụng ASP.NET Core chạy sau IIS/ARR trên Windows Server, xác thực JWT từ Microsoft Entra ID. API cho phép kế toán tải hóa đơn PDF theo tenant. SQL Server lưu metadata và đường dẫn blob nội bộ; một số hóa đơn lớn (80–200 MB). Khi hai tenant cùng sử dụng, đội support nhận báo cáo tải nhầm tài liệu; sau triển khai scale-out, memory tăng mạnh và đôi lúc API trả 500. API chỉ được phép xuất hóa đơn mà principal hiện tại có quyền đọc. Mã bên dưới là phần liên quan; giả định `IInvoiceStore` trả về metadata hợp lệ từ DB, `IFileStore` đọc byte từ storage nội bộ, và authentication middleware đã được đăng ký.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/invoices")]
public sealed class InvoicesController : ControllerBase
{
    private readonly IInvoiceStore _invoices;
    private readonly IFileStore _files;
    private readonly ILogger<InvoicesController> _logger;

    public InvoicesController(
        IInvoiceStore invoices,
        IFileStore files,
        ILogger<InvoicesController> logger)
    {
        _invoices = invoices;
        _files = files;
        _logger = logger;
    }

    [HttpGet("{invoiceId:guid}/pdf")]
    public async Task<IActionResult> Download(Guid invoiceId)
    {
        var tenant = Request.Headers["X-Tenant-Id"].ToString();
        var invoice = await _invoices.FindAsync(invoiceId);

        if (invoice == null)
            return NotFound();

        if (invoice.TenantId != tenant)
            _logger.LogWarning(
                "Tenant mismatch: {Tenant} invoice={InvoiceId} owner={Owner}",
                tenant, invoiceId, invoice.TenantId);

        var path = Path.Combine("D:\\InvoiceFiles", invoice.RelativePath);
        var bytes = await _files.ReadAllBytesAsync(path);
        Response.Headers["Cache-Control"] = "public, max-age=3600";
        Response.Headers["Content-Disposition"] =
            $"attachment; filename={invoice.FileName}";

        _logger.LogInformation(
            "Download {InvoiceId} for {User}, path={Path}",
            invoiceId, User.Identity?.Name, path);

        return File(bytes, "application/pdf");
    }
}
```

3. Mô tả tác động production, ưu tiên xử lý theo mức độ nghiêm trọng.

6. Nêu telemetry để chứng minh bản sửa an toàn.

## Kết quả code review tham khảo

### [Critical] — Tenant mismatch vẫn trả file

**Vấn đề:** Điều kiện mismatch chỉ ghi log, không từ chối request.  
**Tại sao xảy ra:** Authorization được xử lý như telemetry thay vì gate bắt buộc.  
**Ảnh hưởng production:** Cross-tenant data exposure trực tiếp, đặc biệt khi ID bị lộ.  
**Cách sửa:** Kiểm tra principal đã xác thực, tenant membership/permission ở server; query metadata theo tenant được phép và invoiceId; từ chối trước khi truy cập storage.

### [Critical] — Tenant identity lấy từ header không đáng tin

**Vấn đề:** `X-Tenant-Id` là input do client kiểm soát.  
**Tại sao xảy ra:** Nhầm routing hint với authorization claim.  
**Ảnh hưởng production:** Tenant spoofing; nếu chỉ sửa `return Forbid()` mà vẫn tin header thì vẫn có bypass.  
**Cách sửa:** Lấy tenant đã được cấp quyền từ claims/authorization service đã kiểm chứng; nếu hỗ trợ chọn tenant, validate membership với authoritative store.

### [High] — Public caching tài liệu riêng tư

**Vấn đề:** `public, max-age=3600` cho hóa đơn có thông tin nhạy cảm.  
**Tại sao xảy ra:** Response cache được cấu hình như static asset.  
**Ảnh hưởng production:** Shared proxy/CDN có thể lưu và phân phối tài liệu ngoài intended audience tùy cache key và cấu hình.  
**Cách sửa:** `Cache-Control: private, no-store` và kiểm tra chính sách cache của IIS/ARR/CDN; không phụ thuộc cache header để thay thế authorization.

### [High] — Buffer toàn bộ file vào managed memory

**Vấn đề:** `ReadAllBytesAsync` tạo buffer lớn cho mỗi request.  
**Tại sao xảy ra:** API trả `byte[]` thay vì stream.  
**Ảnh hưởng production:** LOH pressure, GC pauses, OOM dưới concurrent downloads.  
**Cách sửa:** Stream từ storage đến response với cancellation và ownership/disposal rõ ràng; giới hạn concurrency nếu storage cần bảo vệ.

### [High] — Relative path chưa được giới hạn vào root

**Vấn đề:** `Path.Combine` không chứng minh đường dẫn vẫn thuộc root; path rooted hoặc `..` có thể thoát root.  
**Tại sao xảy ra:** DB field được tin như đường dẫn an toàn.  
**Ảnh hưởng production:** Truy cập file ngoài vùng hóa đơn khi metadata bị sai/poisoned; lộ dữ liệu nếu storage API cho phép.  
**Cách sửa:** Ưu tiên opaque storage key; nếu bắt buộc dùng filesystem, canonicalize và kiểm tra containment, chống symlink/reparse-point theo threat model.

### [Medium] — Content-Disposition ghép chuỗi không kiểm soát

**Vấn đề:** Filename được đưa trực tiếp vào HTTP header.  
**Tại sao xảy ra:** Không sử dụng framework encoder cho Content-Disposition.  
**Ảnh hưởng production:** Filename không hợp lệ, lỗi response hoặc header manipulation tùy runtime/validation.  
**Cách sửa:** Dùng `File(stream, "application/pdf", safeFileName)` để framework tạo header phù hợp; sanitize tên file cho UX.

### [Medium] — Không truyền cancellation và log lộ đường dẫn nội bộ

**Vấn đề:** I/O tiếp tục sau client disconnect; log ghi absolute path và user identifier.  
**Tại sao xảy ra:** Thiếu `HttpContext.RequestAborted` và log minimization.  
**Ảnh hưởng production:** I/O lãng phí, telemetry chứa thông tin không cần thiết.  
**Cách sửa:** Truyền cancellation xuyên suốt; log invoice ID, tenant hash/correlation ID và outcome, không log path hay PII nếu không có yêu cầu kiểm toán.

## Phiên bản đề xuất

Ví dụ dưới đây giả định `IAuthorizedTenantResolver` xác thực tenant membership từ principal, `IInvoiceStore.FindForTenantAsync` lọc bằng tenantId và invoiceId tại DB, và `IInvoiceBlobStore.OpenReadAsync` nhận opaque storage key (không phải filesystem path). Cả ba interface phải được hiện thực và kiểm thử theo hợp đồng này.

```csharp
[Authorize]
[ApiController]
[Route("api/invoices")]
public sealed class InvoicesController : ControllerBase
{
    private readonly IAuthorizedTenantResolver _tenants;
    private readonly IInvoiceStore _invoices;
    private readonly IInvoiceBlobStore _blobs;
    private readonly ILogger<InvoicesController> _logger;

    public InvoicesController(
        IAuthorizedTenantResolver tenants,
        IInvoiceStore invoices,
        IInvoiceBlobStore blobs,
        ILogger<InvoicesController> logger)
    {
        _tenants = tenants;
        _invoices = invoices;
        _blobs = blobs;
        _logger = logger;
    }

    [HttpGet("{invoiceId:guid}/pdf")]
    public async Task<IActionResult> Download(
        Guid invoiceId, CancellationToken cancellationToken)
    {
        Response.Headers.CacheControl = "private, no-store";

        var tenantId = await _tenants.ResolveAuthorizedTenantAsync(
            User, cancellationToken);
        if (tenantId is null)
            return Forbid();

        var invoice = await _invoices.FindForTenantAsync(
            tenantId, invoiceId, cancellationToken);
        if (invoice is null)
            return NotFound();

        var stream = await _blobs.OpenReadAsync(
            invoice.StorageKey, cancellationToken);
        if (stream is null)
            return NotFound();

        _logger.LogInformation(
            "Invoice download started: {InvoiceId} {TraceId}",
            invoiceId, HttpContext.TraceIdentifier);

        var safeName = Path.GetFileName(invoice.FileName);
        if (string.IsNullOrWhiteSpace(safeName))
            safeName = "invoice.pdf";

        return File(stream, "application/pdf", safeName);
    }
}
```

Framework `FileStreamResult` chịu trách nhiệm dispose stream sau khi execute; storage implementation cần mở stream đúng quyền, giới hạn key và hỗ trợ cancellation. Nếu có role/action-level permission, `FindForTenantAsync` vẫn chưa đủ: thêm authorization check theo invoice và quyền nghiệp vụ. Kiểm tra policy proxy để không cache response dù origin gửi `no-store`.

## Giải thích thiết kế sau khi sửa

Authorization diễn ra trước storage I/O; tenant được chứng thực server-side. DB query theo scope ngăn object leak; storage key tách khỏi filesystem path. Streaming giảm peak managed allocations; `RequestAborted` được model binding vào `CancellationToken`. Không cần microservices hay distributed cache cho use case này.

## Trade-offs

Streaming giữ connection và storage handle lâu hơn; cần kiểm soát timeouts, concurrent streams và slow clients. Direct download bằng short-lived scoped SAS có thể giảm tải API nhưng đòi hỏi bảo vệ URL, expiry, audit và chính sách truy cập của storage. Trả 404 thay vì 403 cho invoice ngoài scope có thể giảm enumeration nhưng phải nhất quán với policy.

## Cách kiểm thử

1. **Security integration:** Tenant A gọi invoice của B, kể cả tự sửa header, phải không nhận bytes; thử user không có permission.
2. **Load test:** 100 concurrent streams lớn; đo allocated bytes, LOH/GC, p95 và memory peak so với bản cũ.
3. **Failure-path:** Client cancel giữa chừng; xác nhận stream được dispose và storage I/O ngừng hợp lý.
4. **Storage security:** Metadata có path traversal/absolute path và filename kỳ lạ không dẫn đến đọc ngoài scope.
5. **Proxy deployment validation:** Qua IIS/ARR và CDN thật, response không được shared-cache; download hoạt động sau recycle.

## Quan sát trong production

Structured logs theo `TraceId`, `InvoiceId`, outcome và sanitized tenant identifier; Application Insights dependency latency, download duration, bytes streamed, 403/404/5xx, cancellation rate, working set, GC heap/LOH và IIS queue length. Alert khi cross-tenant authorization denials tăng đột biến, memory spike hoặc p99 vượt SLO. Không ghi raw JWT, file path, nội dung PDF.

## Câu hỏi phỏng vấn mở rộng

1. Nếu kế toán có quyền nhiều tenant, cách xác định active tenant mà không tin header ra sao?
2. Khi file ở Azure Blob Storage, lúc nào nên dùng backend streaming và lúc nào dùng scoped SAS?
3. Làm sao triển khai authorization change không làm gián đoạn các client cũ?

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/pages")]
public sealed class PagesController : ControllerBase
{
    private static readonly Dictionary<string, PageDto> Cache = new();
    private readonly IContentRepository _content;

    public PagesController(IContentRepository content)
    {
        _content = content;
    }

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(
        string slug,
        [FromQuery] string locale = "en-US",
        [FromQuery] bool preview = false)
    {
        if (Cache.TryGetValue(slug, out var cached))
            return Ok(cached);

        var audience = Request.Headers["X-Audience"].ToString();
        var page = await _content.FindAsync(
            slug, locale, preview, audience);

        if (page is null)
            return NotFound();

        Cache[slug] = page;
        Response.Headers["Cache-Control"] = "public, max-age=1200";
        Response.Headers["Surrogate-Key"] = $"page-{slug}";
        return Ok(page);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Preview content có thể bị public-cache

**Vấn đề:** `preview=true` không được authorize và response đặt `public`.  
**Tại sao xảy ra:** Preview được coi là query parameter bình thường.  
**Ảnh hưởng production:** Draft/unpublished content có thể bị truy cập hoặc lưu tại edge nếu cấu hình cache key không đúng.  
**Cách sửa:** Preview endpoint/policy riêng, bắt buộc editor authorization, `private, no-store`, bypass origin và CDN cache; audit access.

### [High] — Cache key chỉ gồm slug

**Vấn đề:** Locale và audience dùng chung `PageDto`; preview cũng có thể trộn với public.  
**Tại sao xảy ra:** Representation identity không được đưa vào cache key.  
**Ảnh hưởng production:** Cross-locale/audience leak, sai nội dung và SEO metadata.  
**Cách sửa:** Chỉ cache public non-personalized variants với key canonical gồm site, slug, locale, version và audience bucket đã được server xác thực; nếu audience cá nhân hóa thì bypass shared cache.

### [High] — Shared mutable Dictionary không thread-safe

**Vấn đề:** Static `Dictionary` bị đọc/ghi đồng thời.  
**Tại sao xảy ra:** Không dùng concurrency-safe cache abstraction.  
**Ảnh hưởng production:** Race, trạng thái sai, và mỗi instance có cache khác nhau.  
**Cách sửa:** Dùng `IMemoryCache` cho bounded local caching hoặc `IDistributedCache` nếu thật sự cần; xử lý thundering herd và instance consistency theo yêu cầu.

### [High] — Không có publish invalidation

**Vấn đề:** Cache nội bộ không TTL/purge, CDN TTL 20 phút; `Surrogate-Key` chỉ là metadata nếu purge workflow chưa được tích hợp.  
**Tại sao xảy ra:** Publish event chưa nối tới cache lifecycle.  
**Ảnh hưởng production:** Nội dung stale vô thời hạn tại origin; purge edge đơn thuần vẫn có thể lấy lại dữ liệu cũ.  
**Cách sửa:** Content versioned keys hoặc invalidate origin trước edge purge; publish workflow có retry/telemetry, eventual-consistency SLO và fallback TTL.

### [Medium] — Audience header do client tự chọn

**Vấn đề:** `X-Audience` được tin trực tiếp.  
**Tại sao xảy ra:** Client hint bị dùng như entitlement/segmentation authority.  
**Ảnh hưởng production:** User có thể yêu cầu variant không dành cho mình; cache làm tăng phạm vi lộ.  
**Cách sửa:** Chỉ dùng public segment được phép hoặc derive từ server-side authenticated context; nội dung restricted cần authorization và no-store.

### [Medium] — Vue request race và thiếu kiểm tra HTTP status

**Vấn đề:** Request cũ có thể ghi đè page mới; 404/500 JSON bị coi như `PageDto`.  
**Tại sao xảy ra:** Watcher không cancel request trước, không check `response.ok`.  
**Ảnh hưởng production:** UI hiển thị trang sai, lỗi âm thầm, SEO/client navigation inconsistency.  
**Cách sửa:** `AbortController` với cleanup, check status và error state; watch cả locale/preview nếu chúng thay đổi.

### [Medium] — Response headers không nhất quán

**Vấn đề:** Cache hit trả ngay trước khi set header; CDN behavior có thể khác giữa miss và hit.  
**Tại sao xảy ra:** Header được set ở cuối miss path.  
**Ảnh hưởng production:** Khó dự đoán cache semantics, khó debug.  
**Cách sửa:** Set policy trước mọi return; tách public và preview endpoint hoặc middleware policy.

## Phiên bản đề xuất

Thiết kế sau ưu tiên correctness trước tối ưu: không giữ static cache trong controller. `FindPublishedAsync` phải chỉ trả published, public, non-personalized content. `FindPreviewAsync` kiểm tra editor permission và content scope. `IContentRepository` là abstraction minh họa, cần map với API Optimizely đang sử dụng.

```csharp
[ApiController]
[Route("api/pages")]
public sealed class PagesController : ControllerBase
{
    private readonly IContentRepository _content;
    public PagesController(IContentRepository content) => _content = content;

    [HttpGet("{slug}")]
    public async Task<IActionResult> PublicPage(
        string slug, [FromQuery] string locale = "en-US",
        CancellationToken ct = default)
    {
        if (!SupportedLocales.Contains(locale))
            return BadRequest();

        Response.Headers.CacheControl = "public, max-age=60";
        var page = await _content.FindPublishedAsync(slug, locale, ct);
        if (page is null) return NotFound();

        Response.Headers["Surrogate-Key"] = $"page-{page.Id}";
        Response.Headers.ETag = $"\"{page.Version}\"";
        return Ok(page);
    }

    [Authorize(Policy = "CmsEditor")]
    [HttpGet("{slug}/preview")]
    public async Task<IActionResult> Preview(
        string slug, [FromQuery] string locale = "en-US",
        CancellationToken ct = default)
    {
        Response.Headers.CacheControl = "private, no-store";
        if (!SupportedLocales.Contains(locale))
            return BadRequest();

        var page = await _content.FindPreviewAsync(
            slug, locale, User, ct);
        return page is null ? NotFound() : Ok(page);
    }

    private static readonly HashSet<string> SupportedLocales =
        new(StringComparer.OrdinalIgnoreCase) { "en-US", "vi-VN" };
}
```

```typescript
    try {
      const slug = encodeURIComponent(String(route.params.slug));
      const query = new URLSearchParams({ locale: locale.value });
      const response = await fetch(
        `/api/pages/${slug}?${query}`,
        { signal: controller.signal }
      );
      if (!response.ok) throw new Error(`HTTP ${response.status}`);
      const data: PageDto = await response.json();
      if (!controller.signal.aborted) page.value = data;
    } catch (e) {
      if (!controller.signal.aborted) error.value = String(e);
    }
  },
  { immediate: true }
);
```

Preview UI phải gọi endpoint preview riêng bằng credential hợp lệ, không dựa vào query flag của public route. Với production CDN, cấu hình Akamai cache key phải bao gồm canonical locale và site, đồng thời bypass preview/authenticated responses; validate bằng actual edge config. Sau publish: invalidate/version origin first, sau đó purge edge theo content ID và các dependent pages; có retry, audit và monitoring. `ETag` chỉ dùng khi version thực sự đại diện chính xác cho representation; nếu khác locale cần version riêng.

## Giải thích thiết kế sau khi sửa

Tách public và preview để policy có thể kiểm chứng độc lập. Public endpoint chỉ xuất bản variant không cá nhân hóa; cache key cần tương ứng đầy đủ với URL/host và các yếu tố representation. Không cache tùy tiện ở memory trước khi có bằng chứng origin overload. Vue watcher cancel request cũ để tránh stale UI. Publish invalidation là workflow có trạng thái, không chỉ là header.

## Trade-offs

TTL 60 giây tăng origin load; có thể nâng TTL với reliable purge và stale-while-revalidate phù hợp business SLA. Cache key quá nhiều chiều gây fragmentation; giảm cardinality bằng public buckets được phép. Purge không tức thời tuyệt đối; cần versioning, propagation metrics và UX expectation. SSR/prerender có thể cần cho SEO thay vì chỉ client-side Vue rendering; quyết định dựa trên crawl/render evidence và Lighthouse.

## Cách kiểm thử

1. **Security integration:** Anonymous không truy cập preview, kể cả sửa query/header; response preview có no-store.
2. **Variant matrix:** Hai locale, nhiều site/segment; kiểm tra cả origin và Akamai HIT/MISS không cross-serve.
3. **Concurrency/load:** Peak 4.000 req/s, cache miss burst và publish đồng thời; đo origin QPS, p95, error rate.
4. **Publish E2E:** Draft → publish → origin invalidation → edge purge; kiểm tra dependent pages và bounded staleness.
5. **Playwright E2E:** Chuyển route nhanh và đổi locale; page cuối phải khớp route cuối, 404/500 hiển thị error state.

## Quan sát trong production

Log `contentId`, locale, public/preview flag, content version, publish event ID và correlation ID (không log draft body). Akamai cache status, age, key dimensions, purge result và propagation latency; origin cache hit ratio, DB/CMS dependency latency, p95/p99, 4xx/5xx, request burst. Dashboard đối chiếu `publishedVersion` với `servedVersion`; alert khi preview xuất hiện ở public path hoặc stale age vượt SLO.

## Câu hỏi phỏng vấn mở rộng

1. Nếu một content block được reuse bởi 500 pages, thiết kế dependency-aware invalidation thế nào?
2. Với multi-site và localized canonical URLs, đảm bảo SEO không index nhầm language variant ra sao?
3. Khi Akamai purge API thất bại nhưng publish đã commit, bạn phục hồi thế nào mà không rollback content không cần thiết?
