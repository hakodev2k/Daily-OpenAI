```csharp
[ApiController]
[Route("api/inventory/webhook")]
public class InventoryWebhookController : ControllerBase
{
    private readonly InventoryDbContext _db;
    private readonly HttpClient _http;
    public InventoryWebhookController(InventoryDbContext db, HttpClient http)
    {
        _db = db;
        _http = http;
    }

    [HttpPost]
    public async Task<IActionResult> Receive(StockChanged request)
    {
        var product = await _db.Products
            .SingleAsync(x => x.Sku == request.Sku);
        if (request.Delta != 0)
            product.Stock += request.Delta;

        await _db.SaveChangesAsync();
        var response = await _http.PostAsJsonAsync(
            "https://partner.example/api/stock", new {
                request.Sku, product.Stock
            });
        response.EnsureSuccessStatusCode();
        return Ok(new { product.Stock });
    }
}
public record StockChanged(string Sku, int Delta, string EventId);
```

**Tại sao xảy ra:** EventId không được lưu/kiểm tra.
**Ảnh hưởng production:** Retry làm sai số tồn.

### [High] — Lost update dưới concurrent requests

**Vấn đề:** Lost update dưới concurrent requests.
**Tại sao xảy ra:** Read-modify-write không có optimistic concurrency.
**Ảnh hưởng production:** Hai delta có thể ghi đè nhau.
**Cách sửa:** Atomic SQL UPDATE Stock=Stock+delta hoặc rowversion và retry có giới hạn.

### [High] — Dual-write sang partner không nguyên tử

**Vấn đề:** Dual-write sang partner không nguyên tử.
**Tại sao xảy ra:** SQL commit trước HTTP call.
**Ảnh hưởng production:** API lỗi nhưng DB đã thay đổi, retry gây sai dữ liệu.

### [Medium] — HTTP response không mô tả eventual state

**Vấn đề:** HTTP response không mô tả eventual state.
**Tại sao xảy ra:** Caller hiểu partner đã đồng bộ hoặc toàn bộ thất bại.
**Ảnh hưởng production:** Retry không an toàn.
**Cách sửa:** Contract 202/200 với trạng thái accepted và reconciliation.

## Phiên bản đề xuất

Đoạn sau là skeleton có chủ đích: các dependency/helper như signature verifier, inbox/outbox repository và atomic SQL update phải được triển khai và kiểm thử theo contract thực tế.

```csharp
// DB unique index: Inbox(EventId)
// Outbox được xử lý bởi worker độc lập, không gọi HTTP trong request.
[HttpPost]
public async Task<IActionResult> Receive(
    StockChanged request, CancellationToken ct)
{
    if (!await _signature.VerifyAsync(Request, ct)) return Unauthorized();
    if (string.IsNullOrWhiteSpace(request.EventId) || request.Delta == 0)
        return BadRequest();

    await using var tx = await _db.Database.BeginTransactionAsync(ct);
    // Idempotency phải dựa trên unique constraint, không chỉ check-then-insert.
    var inserted = await _inbox.TryInsertAsync(request.EventId, ct);
    if (!inserted) return Ok(new { Duplicate = true });
    var changed = await _inventory.ApplyAtomicDeltaAsync(
        request.Sku, request.Delta, ct);
    if (!changed) return Conflict();
    _db.Outbox.Add(StockSyncEvent.Create(request.EventId, request.Sku));
    await _db.SaveChangesAsync(ct);
    await tx.CommitAsync(ct);
    return Accepted(new { request.EventId });
}
// Worker claim outbox bằng lease, đọc state mới, gửi partner với
// idempotency key và version; retry/backoff, DLQ/reconciliation.
```

## Giải thích thiết kế sau khi sửa

SQL transaction ghi inbox và outbox cùng với delta để xử lý at-least-once delivery. Unique constraint, không phải check-then-insert, bảo đảm cạnh tranh an toàn. Worker có thể replay, cần idempotency key, retry bounded và reconciliation. HTTP request không đợi partner.

## Trade-offs

Outbox thêm worker, storage, cleanup và lag; không cần message broker nếu polling SQL đủ tải. Stock update phải có invariant rõ ràng; nếu partner không hỗ trợ idempotency, cần reconcile trạng thái trước khi retry side effect.

## Cách kiểm thử

1. Webhook thiếu/sai signature, timestamp quá cũ bị từ chối.
2. Gửi cùng EventId 100 lần concurrent: tồn kho chỉ đổi một lần.
3. Hai EventId đồng thời: không lost update, stock invariant được giữ.
4. Partner timeout sau khi nhận request: retry không gây side effect trùng.
5. IIS recycle giữa commit và send: outbox còn và được replay.

## Quan sát trong production

Application Insights dependency duration, SQL conflicts, inbox duplicate rate, outbox oldest age, partner failure rate, stock reconciliation drift, correlation EventId.

## Câu hỏi phỏng vấn mở rộng

2. Khi nào dùng Service Bus thay vì SQL outbox polling?

## Phiên bản đề xuất

Đoạn sau là skeleton có chủ đích: các dependency/helper như runtime response validator và BFF authentication phải được triển khai và kiểm thử theo contract thực tế.

```vue
<script setup lang="ts">
import { ref, watch, onBeforeUnmount } from 'vue'
type Item = { id: string; title: string; description: string }
const term = ref(''), category = ref('all'), page = ref(1)
const items = ref<Item[]>([]), loading = ref(false)
const error = ref(''), hasNext = ref(false)
let active: AbortController | undefined
let generation = 0
let timer: ReturnType<typeof setTimeout> | undefined
async function search() {
  active?.abort()
  const controller = new AbortController()
  active = controller
  const mine = ++generation
  loading.value = true
  error.value = ''
  try {
    const params = new URLSearchParams({
      q: term.value, category: category.value, page: String(page.value)
    })
    const response = await fetch('/api/search?' + params, {
      credentials: 'same-origin', signal: controller.signal
    })
    if (!response.ok) throw new Error(String(response.status))
    const data: unknown = await response.json()
    if (!isResult(data)) throw new Error('Invalid response')
    if (mine !== generation) return
    items.value = data.items
    hasNext.value = data.hasNext
  } catch {
    if (mine !== generation || controller.signal.aborted) return
    items.value = []
    error.value = 'Không tải được'
  } finally {
    if (mine === generation) loading.value = false
  }
}
function isResult(x: unknown): x is { items: Item[]; hasNext: boolean } {
  if (typeof x !== 'object' || x === null) return false
  const v = x as { items?: unknown; hasNext?: unknown }
  return Array.isArray(v.items) && typeof v.hasNext === 'boolean'
}
watch([term, category], () => {
  page.value = 1
  clearTimeout(timer)
  active?.abort()
  generation++
  loading.value = true
  timer = setTimeout(search, 250)
})
watch(page, search)
search()
onBeforeUnmount(() => {
  clearTimeout(timer)
  active?.abort()
  generation++
})
</script>
<template>
  <input v-model="term" aria-label="Tìm kiếm" />
  <select v-model="category" aria-label="Danh mục">
    <option value="all">Tất cả</option>
    <option value="books">Sách</option>
  </select>
  <p v-if="loading">Đang tải...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <article v-for="item in items" :key="item.id">
    <h3>{{ item.title }}</h3>
    <p>{{ item.description }}</p>
  </article>
  <button :disabled="loading || !hasNext" @click="page++">Tiếp</button>
</template>
```

## Giải thích thiết kế sau khi sửa

Generation guard ngăn stale response kể cả khi abort đến muộn. URLSearchParams encode query; response.ok phân biệt lỗi HTTP. Plain text giảm XSS; cookie-based BFF chỉ phù hợp nếu đã thiết kế CSRF protection. API vẫn enforce authorization và query limits.

## Trade-offs

Debounce tăng độ trễ nhỏ; cancellation không bảo đảm server ngừng xử lý. BFF/cookie tăng yêu cầu CSRF/session; sanitize rich text cần allowlist và policy. Router URL sync và schema validation tăng code nhưng cải thiện correctness.

## Cách kiểm thử

1. Playwright trả response A chậm hơn B: chỉ hiển thị B.
2. HTML payload từ CMS không tạo executable DOM.
3. HTTP 401/500 và malformed JSON: UI báo lỗi.
4. Search chứa & và # tạo đúng query parameters.
5. Slow network và gõ nhanh: đo request count, state và loading.

## Quan sát trong production

Browser search latency, aborted requests, HTTP 4xx/5xx, API p95, request rate per interaction, CSP violations, correlation ID; không log token.
