# Câu 1 — EF Core Query Execution và vấn đề hiệu năng bất thường

**Loại câu hỏi:** Internal mechanism trong production scenario  
**Độ khó:** Senior  
**Kỹ năng được đánh giá:** EF Core, SQL, debugging, performance analysis

## Bối cảnh
Một API ASP.NET Core dùng EF Core lấy danh sách đơn hàng. Sau một lần release, thời gian phản hồi tăng từ 200ms lên 5 giây dù dữ liệu không tăng đáng kể.

## Câu hỏi chính
Hãy giải thích điều gì xảy ra bên trong khi EF Core xây dựng và thực thi query, vì sao có thể xảy ra hiện tượng này, cách xác minh nguyên nhân và rủi ro production.

## Gợi ý tư duy
- Kiểm tra query thực sự được gửi xuống database.
- Phân tích tracking, projection, execution plan.
- Đo lường trước khi tối ưu.

# Câu 2 — Thiết kế hệ thống xử lý background job đáng tin cậy

**Loại câu hỏi:** System Design  
**Độ khó:** Senior+  
**Kỹ năng được đánh giá:** Architecture, reliability, Hangfire, concurrency

## Bối cảnh
Công ty cần xây dựng hệ thống xử lý email notification, import dữ liệu và đồng bộ Microsoft Graph. Job có thể chạy lâu, lỗi do external API và có khả năng bị trigger nhiều lần.

## Câu hỏi chính
Thiết kế giải pháp MVP dạng modular monolith, đảm bảo retry, idempotency, monitoring và recovery.

## Gợi ý tư duy
- Xác định trạng thái xử lý.
- Thiết kế retry cùng idempotency.
- Observability là một phần của thiết kế.

# Câu 3 — Thiết kế AI Coding Agent an toàn

**Loại câu hỏi:** AI Engineering Decision  
**Độ khó:** Senior+  
**Kỹ năng được đánh giá:** Agent engineering, context engineering, security

## Bối cảnh
Team muốn tạo AI agent hỗ trợ review code .NET, tạo test và phân tích bug.

## Câu hỏi chính
Thiết kế workflow cho agent: context, tools, permissions, validation, evaluation và fallback.

## Gợi ý tư duy
- Không giao toàn quyền cho model.
- Output cần deterministic validation.
- Đo chất lượng bằng evaluation dataset.

# Tổng kết hôm nay

## Kiến thức trọng tâm
- Hiểu runtime behavior trước khi sửa lỗi.
- Thiết kế hệ thống dựa trên failure mode.
- AI cần guardrails, validation và observability.

## Mẫu tư duy cần nhớ
- Clarify before designing.
- Measure before optimizing.
- Design retries together with idempotency.
- Treat observability as part of the design.
