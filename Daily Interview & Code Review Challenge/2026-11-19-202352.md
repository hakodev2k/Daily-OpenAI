## Bối cảnh

Website marketing chạy trên 4 Azure App Service instances, dùng CMS cho published content và editor preview. Akamai cache public pages. Sau deploy, người dùng anonymous đôi khi thấy draft, bản tiếng Pháp hiển thị tiếng Anh, và unpublish mất hơn 30 phút mới biến mất. Yêu cầu bảo vệ draft tuyệt đối và giảm origin load. `IContentReader` là abstraction giả định, không phải API chính thức của Optimizely.

## Đoạn code cần review

```csharp
[ApiController]
[Route("content")]
public sealed class ContentController : ControllerBase
{
    private readonly IContentReader _reader;
    private readonly IMemoryCache _cache;
    public ContentController(IContentReader reader, IMemoryCache cache)
        => (_reader, _cache) = (reader, cache);

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(
        string slug, [FromQuery] string? lang,
        [FromQuery] bool preview = false)
    {
        var culture = lang ?? "en";
        var key = $"page:{slug}";
        if (!_cache.TryGetValue(key, out PageDto? page))
        {
            page = await _reader.ReadAsync(slug, culture, preview);
            if (page == null) return NotFound();
            _cache.Set(key, page, TimeSpan.FromMinutes(30));
        }

        Response.Headers.CacheControl = "public, max-age=1800";
        Response.Headers.ETag = $"\"{page!.Revision}\"";
        return Ok(page);
    }
}

public interface IContentReader
{
    Task<PageDto?> ReadAsync(string slug, string language, bool preview);
}
public record PageDto(string Slug, string Language,
    string Revision, bool Published, string Html);
```

## Kết quả code review tham khảo

### [Critical] — Preview không được authorization

**Vấn đề:** Anonymous có thể bật `preview=true`.  
**Tại sao xảy ra:** Query parameter không xác minh identity/quyền theo content item.  
**Ảnh hưởng production:** Draft hoặc thông tin chưa công bố bị lộ.  
**Cách sửa:** Editor authentication và per-content authorization tại preview reader; không dựa vào UI.

### [Critical] — Draft được đánh dấu public cacheable

**Vấn đề:** Mọi response đều `public, max-age=1800`.  
**Tại sao xảy ra:** Không tách preview với published.  
**Ảnh hưởng production:** CDN/shared caches có thể phục vụ draft cho anonymous.  
**Cách sửa:** Preview `private, no-store`, cấu hình Akamai bypass preview; kiểm chứng ở edge.

### [High] — Cache key thiếu culture và publication state

**Vấn đề:** Chỉ có slug.  
**Tại sao xảy ra:** Key không bao gồm mọi dimension ảnh hưởng response.  
**Ảnh hưởng production:** Cross-language contamination, draft/public mixing.  
**Cách sửa:** Public cache key gồm site/tenant, culture, normalized slug; không cache preview trong public cache.

### [High] — Public path không enforce Published

**Vấn đề:** Không kiểm tra `page.Published`.  
**Tại sao xảy ra:** Tin hoàn toàn vào reader/cache.  
**Ảnh hưởng production:** Unpublished content xuất hiện ở public route.  
**Cách sửa:** Public reader chỉ trả published, thêm guard defense-in-depth.

### [High] — Không có purge khi unpublish

**Vấn đề:** TTL 30 phút nhưng không có invalidation.  
**Tại sao xảy ra:** Publication lifecycle không nối với cache lifecycle.  
**Ảnh hưởng production:** Nội dung bị gỡ vẫn hiển thị.  
**Cách sửa:** Publication events kích hoạt purge theo URL/surrogate key, retry và alert nếu purge thất bại.

### [Medium] — Memory cache khác nhau giữa instances

**Vấn đề:** `IMemoryCache` per process.  
**Tại sao xảy ra:** Không có cross-instance invalidation.  
**Ảnh hưởng production:** Revision không đồng nhất.  
**Cách sửa:** Fan-out invalidation hoặc TTL ngắn có đo lường; distributed cache chỉ khi cần.

### [Medium] — ETag chưa đủ định danh representation

**Vấn đề:** Revision có thể trùng giữa cultures/variants.  
**Tại sao xảy ra:** Validator không chứa dimension liên quan.  
**Ảnh hưởng production:** Conditional caching sai khi triển khai 304.  
**Cách sửa:** ETag theo representation, xác minh semantics `If-None-Match`.

### [Medium] — Thiếu cancellation và normalization

**Vấn đề:** Không truyền `RequestAborted`, không chuẩn hóa slug/culture.  
**Tại sao xảy ra:** Contract thiếu input validation.  
**Ảnh hưởng production:** I/O thừa và key fragmentation.  
**Cách sửa:** Validate, normalize và truyền `CancellationToken`.

## Phiên bản đề xuất

Các interface dưới đây là thiết kế minh họa cần triển khai, không phải API Optimizely.

```csharp
[ApiController]
[Route("content")]
public sealed class ContentController : ControllerBase
{
    private readonly IPublishedReader _publicReader;
    private readonly IAuthorizedPreviewReader _previewReader;
    private readonly IPublicPageCache _cache;

    public ContentController(IPublishedReader publicReader,
        IAuthorizedPreviewReader previewReader, IPublicPageCache cache)
        => (_publicReader, _previewReader, _cache)
            = (publicReader, previewReader, cache);

    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(string slug, string? lang,
        bool preview = false, CancellationToken ct = default)
    {
        if (!ContentInput.TryNormalize(slug, lang,
            out var normalizedSlug, out var culture))
            return BadRequest();

        if (preview)
        {
            Response.Headers.CacheControl = "private, no-store";
            if (User.Identity?.IsAuthenticated != true) return Challenge();
            var draft = await _previewReader.ReadAuthorizedAsync(
                User, normalizedSlug, culture, ct);
            return draft is null ? NotFound() : Ok(draft);
        }

        var key = $"public:{culture}:{normalizedSlug}";
        var page = await _cache.GetOrLoadAsync(key,
            token => _publicReader.ReadPublishedAsync(
                normalizedSlug, culture, token), ct);
        if (page is null || !page.Published)
        {
            Response.Headers.CacheControl = "no-store";
            return NotFound();
        }
        Response.Headers.CacheControl = "public, max-age=60";
        Response.Headers.ETag = $"\"{culture}-{page.Revision}\"";
        return Ok(page);
    }
}
```

`ContentInput` cần validate site/culture/slug; `IPublicPageCache` không cache draft. Akamai phải bypass preview và purge khi publish/unpublish. Cấu hình edge là một phần của solution, không thể chỉ sửa controller.

## Giải thích thiết kế sau khi sửa

Tách trust boundaries: preview được authorize tại service và không dùng shared cache; public reader trả published representation. TTL chỉ giảm stale window, không thay thế purge. Kiểm tra behavior tại origin và edge.

## Trade-offs

TTL ngắn tăng origin traffic; purge event-driven tăng complexity và cần retry. Không cache preview giảm editor performance nhưng bảo vệ confidentiality. Distributed cache cải thiện consistency nhưng tạo dependency mới.

## Cách kiểm thử

1. Security: anonymous preview bị chặn cả khi editor vừa preview.
2. Integration: xen kẽ cultures và public/preview cùng slug không lẫn dữ liệu.
3. CDN validation: cache headers/key/bypass đúng ở edge.
4. Failure injection: unpublish khi purge API lỗi, đo stale duration.
5. Load test: p95, hit ratio, revision skew trên 4 instances.

## Quan sát trong production

Structured logs: content ID, culture, revision, cache layer, publication state, purge correlation ID (không log draft body). Metrics: CDN/origin hit ratio, purge latency/failures, preview denial, stale revisions. Alert nếu preview response bị shared-cache hoặc public route trả unpublished.

## Câu hỏi phỏng vấn mở rộng

1. Nếu purge API mất kết nối 20 phút, giảm rủi ro disclosure thế nào?
2. Multi-site cùng slug nhưng khác tenant cần cache key ra sao?
3. Khi chuyển headless CMS, invariant nào phải giữ?

# Code Review Challenge 2 — Vue catalog search hiển thị kết quả cũ

## Bối cảnh

Khi gõ nhanh trên mạng di động, kết quả keyword cũ ghi đè keyword mới, pagination sai và API nhận nhiều requests. Component có thể unmount khi đổi tab; backend rate-limit 50 requests/giây/user.

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue';
type Product = { id: string; name: string };
type Result = { items: Product[]; total: number };
const keyword = ref('');
const category = ref('all');
const page = ref(1);
const items = ref<Product[]>([]);
const total = ref(0);
const loading = ref(false);
const error = ref('');

async function loadProducts() {
  loading.value = true;
  error.value = '';
  const url = '/api/products?keyword=' + keyword.value
    + '&category=' + category.value + '&page=' + page.value;
  try {
    const response = await fetch(url);
    const data: Result = await response.json();
    items.value = data.items;
    total.value = data.total;
  } catch (e) {
    error.value = String(e);
  } finally {
    loading.value = false;
  }
}
watch(keyword, loadProducts);
watch(category, loadProducts);
watch(page, loadProducts);
onMounted(loadProducts);
</script>
<template>
  <input v-model="keyword" aria-label="Search" />
  <select v-model="category">
    <option value="all">All</option>
    <option value="books">Books</option>
  </select>
  <p v-if="loading">Loading...</p>
  <p v-if="error">{{ error }}</p>
  <p>{{ total }} products</p>
  <ul><li v-for="p in items" :key="p.id">{{ p.name }}</li></ul>
  <button @click="page++">Next</button>
</template>
```

## Kết quả code review tham khảo

### [High] — Response cũ ghi đè state mới

**Vấn đề:** Bất kỳ response nào cũng cập nhật items/total.  
**Tại sao xảy ra:** Promise completion không theo thứ tự gọi.  
**Ảnh hưởng production:** Kết quả không khớp filter.  
**Cách sửa:** AbortController kết hợp request generation guard.

### [High] — HTTP errors bị coi là success

**Vấn đề:** Không kiểm tra `response.ok`.  
**Tại sao xảy ra:** `fetch` resolve với HTTP 4xx/5xx.  
**Ảnh hưởng production:** Error payload ghi vào state hoặc gây exception.  
**Cách sửa:** Check status, validate response shape.

### [Medium] — Pagination không reset

**Vấn đề:** Keyword/category thay đổi nhưng page vẫn giữ nguyên.  
**Tại sao xảy ra:** State phụ thuộc không được đồng bộ.  
**Ảnh hưởng production:** Trang rỗng sai ngữ cảnh.  
**Cách sửa:** Reset page=1 khi đổi filter, gom transition để tránh duplicate fetch.

### [Medium] — Request storm

**Vấn đề:** Mỗi ký tự gây request.  
**Tại sao xảy ra:** Watch không debounce.  
**Ảnh hưởng production:** Rate limit, network contention.  
**Cách sửa:** Debounce, abort; backend vẫn rate-limit.

### [Medium] — Loading/error race

**Vấn đề:** `finally` request cũ tắt loading mới.  
**Tại sao xảy ra:** State không gắn request identity.  
**Ảnh hưởng production:** UI hiển thị trạng thái sai.  
**Cách sửa:** Chỉ request hiện hành được commit mọi state.

### [Medium] — URL không encode

**Vấn đề:** Nối trực tiếp query values.  
**Tại sao xảy ra:** Không dùng `URLSearchParams`.  
**Ảnh hưởng production:** Ký tự đặc biệt phá filter.  
**Cách sửa:** Encode và backend validate.

### [Low] — Thiếu cleanup/next boundary

**Vấn đề:** Request vẫn chạy sau unmount, Next không giới hạn.  
**Tại sao xảy ra:** Thiếu cleanup và kiểm tra total.  
**Ảnh hưởng production:** Work dư và trang không tồn tại.  
**Cách sửa:** Cleanup, disable Next khi tới cuối.

## Phiên bản đề xuất

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue';
type Product = { id: string; name: string };
type Result = { items: Product[]; total: number };
const keyword = ref('');
const category = ref('all');
const page = ref(1);
const items = ref<Product[]>([]);
const total = ref(0);
const loading = ref(false);
const error = ref('');
let generation = 0;
let controller: AbortController | undefined;
let timer: ReturnType<typeof setTimeout> | undefined;

watch([keyword, category], () => { page.value = 1; });
watch([keyword, category, page], ([term, group, current], _, cleanup) => {
  const id = ++generation;
  controller?.abort();
  if (timer) clearTimeout(timer);
  const request = new AbortController();
  controller = request;
  cleanup(() => {
    request.abort();
    if (timer) clearTimeout(timer);
  });
  loading.value = true;
  error.value = '';
  items.value = [];
  total.value = 0;
  timer = setTimeout(async () => {
    const query = new URLSearchParams({
      keyword: term.trim(), category: group, page: String(current)
    });
    try {
      const response = await fetch('/api/products?' + query, {
        signal: request.signal
      });
      if (!response.ok) throw new Error('HTTP ' + response.status);
      const data = await response.json() as Result;
      if (!Array.isArray(data.items) || !Number.isFinite(data.total))
        throw new Error('Invalid API response');
      if (id !== generation || request.signal.aborted) return;
      items.value = data.items;
      total.value = data.total;
    } catch (e) {
      if (id === generation && !request.signal.aborted)
        error.value = e instanceof Error ? e.message : 'Request failed';
    } finally {
      if (id === generation) loading.value = false;
    }
  }, term ? 250 : 0);
}, { immediate: true });
onUnmounted(() => {
  generation++;
  controller?.abort();
  if (timer) clearTimeout(timer);
});
</script>
<template>
  <input v-model="keyword" aria-label="Search" />
  <select v-model="category" aria-label="Category">
    <option value="all">All</option>
    <option value="books">Books</option>
  </select>
  <p v-if="loading" role="status">Loading...</p>
  <p v-else-if="error" role="alert">{{ error }}</p>
  <p v-else-if="!items.length">No products found</p>
  <p v-if="!loading && !error">{{ total }} products</p>
  <ul><li v-for="p in items" :key="p.id">{{ p.name }}</li></ul>
  <button :disabled="loading || !!error || page * 20 >= total"
          @click="page++">Next</button>
</template>
```

## Giải thích thiết kế sau khi sửa

Generation guard bảo đảm chỉ response hiện hành được commit, kể cả khi abort đến quá muộn. Debounce và abort giảm request load; correctness không dựa riêng vào cancellation. Filter/page watchers có thể phát sinh request trung gian tùy scheduling; nếu cần chính xác một request mỗi transition, gộp filter và page vào một state machine/reducer.

## Trade-offs

Clear stale results tránh hiểu nhầm nhưng có thể gây flicker; giữ kết quả cũ cần nhãn stale rõ ràng. Debounce tăng latency nhỏ. Query library hỗ trợ caching/deduplication nhưng thêm dependency và cần cache key đúng.

## Cách kiểm thử

1. Race: A chậm, B nhanh, A hoàn thành sau; UI chỉ hiển thị B.
2. API: 429/500, invalid JSON và network failure.
3. Playwright: đổi filter ở trang cao, reset về trang 1.
4. Lifecycle: unmount trong request, không update state.
5. Throttled network: đo request count và UI consistency.

## Quan sát trong production

Browser waterfall, HTTP 429/5xx, search requests/session, aborted requests, p95 time-to-results. Correlate frontend request ID với ASP.NET Core trace/Application Insights. Không log raw sensitive search terms.

1. Cursor pagination thay đổi state model thế nào?
2. Cache key của search API cần các dimension nào?
3. Backend trả partial results thì UI thể hiện degraded state ra sao?
