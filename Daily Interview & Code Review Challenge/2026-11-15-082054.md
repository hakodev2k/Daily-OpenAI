```csharp
public sealed class ImportController : ControllerBase
{
    private static readonly Dictionary<Guid, string> Jobs = new();
    private readonly IWebHostEnvironment _env;
    private readonly IServiceProvider _services;

    public ImportController(IWebHostEnvironment env, IServiceProvider services)
    {
        _env = env;
        _services = services;
    }

    [HttpPost("/api/imports")]
    public async Task<IActionResult> Upload(IFormFile file)
    {
        var tenantId = Request.Headers["X-Tenant"].ToString();
        var jobId = Guid.NewGuid();
        var path = Path.Combine(_env.WebRootPath, "imports", file.FileName);
        Directory.CreateDirectory(Path.GetDirectoryName(path)!);

        await using (var output = System.IO.File.Create(path))
            await file.CopyToAsync(output);

        Jobs[jobId] = "Running";
        _ = Task.Run(async () =>
        {
            using var scope = _services.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            try
            {
                foreach (var line in System.IO.File.ReadLines(path).Skip(1))
                {
                    var fields = line.Split(',');
                    db.Products.Add(new Product
                    {
                        TenantId = tenantId,
                        Sku = fields[0],
                        Price = decimal.Parse(fields[1])
                    });
                }
                await db.SaveChangesAsync();
                Jobs[jobId] = "Completed";
            }
            catch (Exception ex)
            {
                Jobs[jobId] = ex.Message;
            }
        });
        return Accepted(new { jobId });
    }

    [HttpGet("/api/imports/{id:guid}")]
    public IActionResult Status(Guid id) =>
        Jobs.TryGetValue(id, out var status) ? Ok(new { status }) : NotFound();
}
```

## Kết quả code review tham khảo

### [Critical] — Tenant ID lấy từ header không đáng tin

**Vấn đề:** Client tự chọn `X-Tenant`.  
**Tại sao xảy ra:** Không có authorization mapping tenant với identity.  
**Ảnh hưởng production:** Ghi dữ liệu vào tenant khác; vi phạm isolation.  
**Cách sửa:** Lấy tenant từ authenticated claims và kiểm tra quyền truy cập, không tin header đơn thuần.

### [High] — Fire-and-forget task không được quản lý

**Vấn đề:** `Task.Run` thoát khỏi lifecycle của request, không được host theo dõi.  
**Tại sao xảy ra:** IIS recycle/shutdown có thể dừng process trước khi xử lý xong.  
**Ảnh hưởng production:** Job mất, trạng thái giả, import một phần.  
**Cách sửa:** Ghi job bền vững trước khi trả 202; worker được host quản lý hoặc durable queue; recovery sau restart.

### [High] — Tên file client điều khiển đường dẫn

**Vấn đề:** Dùng trực tiếp `file.FileName` trong path web root.  
**Tại sao xảy ra:** Tên có thể chứa path components; web root có thể phục vụ file công khai; collision giữa request.  
**Ảnh hưởng production:** Ghi đè, lộ dữ liệu, upload nội dung nguy hiểm.  
**Cách sửa:** Tạo storage key server-side ngẫu nhiên, lưu ngoài web root, validate size/type/content và giới hạn quyền filesystem.

### [High] — Không có idempotency và uniqueness

**Vấn đề:** Retry tạo job và product trùng.  
**Tại sao xảy ra:** Mỗi request sinh ID mới; không có khóa nghiệp vụ hay unique constraint.  
**Ảnh hưởng production:** Dữ liệu sai và billing/reporting lệch.  
**Cách sửa:** Idempotency key scoped theo tenant, unique constraint phù hợp `(TenantId, Sku)`, chính sách upsert rõ ràng.

### [High] — State static dictionary không thread-safe và không durable

**Vấn đề:** Nhiều thread đọc/ghi `Dictionary`; state chỉ nằm trong process.  
**Tại sao xảy ra:** Không có synchronization; nhiều IIS workers/instances không chia sẻ memory.  
**Ảnh hưởng production:** Race, lỗi truy cập, status mất sau restart.  
**Cách sửa:** Job table trong SQL Server; status endpoint đọc từ DB theo tenant.

### [Medium] — CSV parser và culture không đúng

**Vấn đề:** `Split(',')`, `decimal.Parse` không xử lý quoted CSV và culture.  
**Tại sao xảy ra:** Format phức tạp hơn split string; lỗi một dòng làm hỏng cả batch.  
**Ảnh hưởng production:** Giá sai, import thất bại bất ngờ.  
**Cách sửa:** CSV parser chuẩn, schema validation, `InvariantCulture` nếu hợp đồng dữ liệu quy định.

### [Medium] — Memory/transaction lớn

**Vấn đề:** Add toàn bộ rows vào một `DbContext`, rồi `SaveChangesAsync` một lần.  
**Tại sao xảy ra:** Change tracker tăng theo kích thước file; transaction lớn, lock dài.  
**Ảnh hưởng production:** GC pressure, timeout, blocking.  
**Cách sửa:** Batches có checkpoint và semantics partial failure được xác định; cân nhắc bulk ingestion sau đo đạc.

### [Medium] — Không có cancellation, retry classification và DLQ

**Vấn đề:** Worker không phân biệt lỗi transient/permanent, không có lease/retry budget.  
**Tại sao xảy ra:** Exception chỉ ghi vào dictionary.  
**Ảnh hưởng production:** Job treo hoặc không thể xử lý lại an toàn.  
**Cách sửa:** State machine Pending/Running/Completed/Failed, attempt count, lease expiry, retry backoff và dead-letter/manual repair.

### [Medium] — Trả exception message cho client

**Vấn đề:** Exception text trở thành job status.  
**Tại sao xảy ra:** Không tách thông tin vận hành với thông tin public.  
**Ảnh hưởng production:** Rò rỉ đường dẫn, SQL details hoặc dữ liệu nhạy cảm.  
**Cách sửa:** Public error code an toàn, log structured details nội bộ.

## Phiên bản đề xuất

Thiết kế dưới đây là phần cốt lõi, giả định `IImportStore` cung cấp atomic SQL operations, `IImportProcessor` xử lý CSV theo batch, `ITenantContext` lấy tenant từ identity đã xác thực. Không coi các interface này là implementation đã có sẵn.

```csharp
[Authorize]
[ApiController]
[Route("api/imports")]
public sealed class ImportsController : ControllerBase
{
    private readonly IImportStore _store;
    private readonly IImportFileStore _files;
    private readonly ITenantContext _tenant;

    public ImportsController(IImportStore store, IImportFileStore files,
        ITenantContext tenant)
        => (_store, _files, _tenant) = (store, files, tenant);

    [HttpPost]
    [RequestSizeLimit(104_857_600)]
    public async Task<IActionResult> Create(
        IFormFile file,
        [FromHeader(Name = "Idempotency-Key")] string key,
        CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(key) || file.Length == 0 ||
            file.Length > 104_857_600)
            return BadRequest();

        var tenantId = _tenant.RequiredTenantId;
        var objectKey = Guid.NewGuid().ToString("N");
        await using (var input = file.OpenReadStream())
            await _files.SavePrivateAsync(objectKey, input, ct);

        var job = await _store.CreateOrGetPendingAsync(
            tenantId, key, objectKey, ct);
        if (job.ObjectKey != objectKey)
            await _files.DeleteIfExistsAsync(objectKey, ct);

        return AcceptedAtAction(nameof(Status), new { id = job.Id },
            new { job.Id, job.Status });
    }

    [HttpGet("{id:guid}")]
    public async Task<IActionResult> Status(Guid id, CancellationToken ct)
    {
        var job = await _store.FindAsync(_tenant.RequiredTenantId, id, ct);
        return job is null ? NotFound() :
            Ok(new { job.Id, job.Status, job.ErrorCode });
    }
}

public sealed class ImportWorker : BackgroundService
{
    private readonly IImportStore _store;
    private readonly IImportProcessor _processor;
    private readonly ILogger<ImportWorker> _log;

    public ImportWorker(IImportStore store, IImportProcessor processor,
        ILogger<ImportWorker> log)
        => (_store, _processor, _log) = (store, processor, log);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            var job = await _store.TryLeaseNextAsync(stoppingToken);
            if (job is null)
            {
                await Task.Delay(TimeSpan.FromSeconds(2), stoppingToken);
                continue;
            }

            try
            {
                await _processor.ProcessIdempotentlyAsync(job, stoppingToken);
                await _store.CompleteIfLeaseOwnerAsync(job, stoppingToken);
            }
            catch (OperationCanceledException) when (stoppingToken.IsCancellationRequested)
            {
                throw;
            }
            catch (Exception ex)
            {
                _log.LogError(ex, "Import failed for {JobId}", job.Id);
                await _store.FailOrRetryAsync(job, ex, stoppingToken);
            }
        }
    }
}
```

**Contract bắt buộc của các abstraction:** `CreateOrGetPendingAsync` phải có unique constraint `(TenantId, IdempotencyKey)` và atomic insert/read; `TryLeaseNextAsync` phải claim atomically kèm lease token/expiry; `CompleteIfLeaseOwnerAsync` dùng fencing để worker cũ không ghi đè; processor checkpoint/upsert transactionally và kiểm tra lease. Nếu file lưu thành công nhưng DB commit thất bại, cleanup bằng orphan sweeper. Nếu file là input không thể lặp lại, không xóa trước khi job kết thúc và retention hết hạn. Worker nên chạy trong process/host riêng nếu cần tránh recycle của IIS; `BackgroundService` trong cùng IIS process vẫn bị ảnh hưởng khi recycle, chỉ bền vững khi có durable state và restart/recovery.

## Giải thích thiết kế sau khi sửa

API chỉ xác nhận sau khi lưu input và durable job. SQL giữ nguồn sự thật về job; private storage không expose nội dung qua HTTP. Worker lease hỗ trợ nhiều instances; DB uniqueness bảo vệ correctness khi retry. Checkpoint giúp recovery nhưng yêu cầu xác định semantics upsert và partial import. Authentication/authorization thực hiện ở cả create và status.

## Trade-offs

SQL-backed polling đơn giản hơn Service Bus cho lưu lượng vừa phải nhưng tạo DB polling và cần lease/recovery logic. Service Bus thích hợp khi throughput lớn, song vẫn phải có idempotent consumer. Batch import tăng throughput nhưng khó bảo đảm all-or-nothing; nếu nghiệp vụ yêu cầu atomic toàn file, cân nhắc staging table rồi transaction publish với chi phí locking và storage. Virus scanning và content validation làm tăng latency/cost.

## Cách kiểm thử

1. **Security test:** User tenant A không tạo hoặc đọc job tenant B, kể cả giả mạo header.
2. **Concurrency test:** 50 uploads cùng idempotency key chỉ tạo một job; nhiều worker không cùng claim lease.
3. **Failure-path test:** Kill worker sau một batch rồi restart; không duplicate sản phẩm và job hoàn tất.
4. **Integration test:** CSV quoted commas, invalid price, file quá lớn và malformed rows trả lỗi theo policy.
5. **Load/deployment test:** Import 100 MB, recycle IIS giữa chừng; kiểm tra p95, memory, retry và eventual completion.

## Quan sát trong production

Structured logs có `JobId`, `TenantId` (không log dữ liệu file), attempt và correlation ID. Metrics: pending/running/failed, lease expirations, retries, throughput rows/s, processing duration p95, DB locks, GC heap, IIS recycle events. Alert khi backlog tăng hoặc job quá SLA. Dùng Application Insights traces cho API và worker; dashboard SQL cho checkpoint và uniqueness conflicts.

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue'

type Item = { id: number; title: string; description: string }
const query = ref('')
const status = ref('All')
const page = ref(1)
const items = ref<Item[]>([])
const total = ref(0)
const loading = ref(false)
const error = ref('')
const cache = new Map<string, Item[]>()

async function load() {
  loading.value = true
  error.value = ''
  const key = query.value
  if (cache.has(key)) {
    items.value = cache.get(key)!
    loading.value = false
    return
  }
  const url = '/api/requests?q=' + query.value +
    '&status=' + status.value + '&page=' + page.value
  const response = await fetch(url, { credentials: 'include' })
  const data = await response.json()
  items.value = data.items
  total.value = data.total
  cache.set(key, data.items)
  loading.value = false
}

watch([query, status, page], load)
onMounted(load)
</script>

<template>
  <section>
    <input v-model="query" placeholder="Search requests" />
    <select v-model="status">
      <option>All</option>
      <option>Pending</option>
      <option>Approved</option>
    </select>
    <button @click="page++">Next</button>
    <p v-if="loading">Loading...</p>
    <p v-if="error">{{ error }}</p>
    <p>Total: {{ total }}</p>
    <article v-for="item in items" :key="item.id">
      <h3>{{ item.title }}</h3>
      <div v-html="item.description"></div>
    </article>
  </section>
</template>
```

## Kết quả code review tham khảo

### [High] — XSS qua v-html

**Vấn đề:** `description` từ API được render như HTML không qua sanitize.  
**Tại sao xảy ra:** `v-html` bỏ qua text escaping.  
**Ảnh hưởng production:** Stored/reflected XSS nếu attacker kiểm soát nội dung.  
**Cách sửa:** Render bằng interpolation `{{ }}` nếu chỉ cần text; nếu HTML thực sự bắt buộc, sanitize theo allowlist ở trust boundary, thêm CSP như defense-in-depth.

### [High] — Out-of-order responses ghi đè state mới

**Vấn đề:** Request cũ có thể hoàn thành sau request mới.  
**Tại sao xảy ra:** `watch` gọi `load` song song không có cancellation/version guard.  
**Ảnh hưởng production:** UI hiển thị sai filter, người dùng quyết định dựa trên dữ liệu không đúng.  
**Cách sửa:** Abort request cũ và kiểm tra sequence ID trước khi cập nhật state.

### [High] — Cache key không đủ và total không được cache

**Vấn đề:** Cache chỉ theo query, bỏ status/page; cache hit không cập nhật total.  
**Tại sao xảy ra:** Key không biểu diễn toàn bộ tham số request.  
**Ảnh hưởng production:** Kết quả và số trang sai, có thể làm lộ kết quả cũ sau thay đổi quyền/phiên nếu cache được chia sẻ hoặc không reset.  
**Cách sửa:** Cache đầy đủ key và response; xác định invalidation/TTL và clear khi session thay đổi; với dữ liệu nhạy cảm có thể bỏ cache.

### [Medium] — Không xử lý HTTP error và rejected Promise

**Vấn đề:** `response.ok` không kiểm tra, exception không được catch/finally.  
**Tại sao xảy ra:** `fetch` không reject với HTTP 4xx/5xx.  
**Ảnh hưởng production:** Spinner treo, lỗi bị che, trạng thái stale.  
**Cách sửa:** Kiểm tra status; try/catch/finally, hiển thị lỗi an toàn, phân biệt abort.

### [Medium] — URL không encode query

**Vấn đề:** Ghép chuỗi raw từ input.  
**Tại sao xảy ra:** Ký tự `&`, `#`, `?` làm biến đổi query string.  
**Ảnh hưởng production:** Search sai, filter bị ảnh hưởng.  
**Cách sửa:** `URLSearchParams`.

### [Medium] — Request quá nhiều khi gõ nhanh

**Vấn đề:** Mỗi keystroke tạo network call.  
**Tại sao xảy ra:** Không debounce.  
**Ảnh hưởng production:** Tăng tải API, rate-limit, UI chậm.  
**Cách sửa:** Debounce search input; không trì hoãn vô lý các thay đổi filter/page.

### [Medium] — Pagination không reset và thiếu bounds

**Vấn đề:** Giữ page cũ sau thay filter; Next luôn tăng.  
**Tại sao xảy ra:** Không gắn page với bộ lọc và total.  
**Ảnh hưởng production:** Trang rỗng, trải nghiệm sai.  
**Cách sửa:** Reset page=1 khi filter thay đổi; disable Next khi hết dữ liệu.

### [Low] — Accessibility thiếu label và status announcement

**Vấn đề:** Input không có accessible label; loading/error không được announce rõ.  
**Tại sao xảy ra:** Chỉ có placeholder.  
**Ảnh hưởng production:** Khó dùng với screen reader.  
**Cách sửa:** Label, `role="status"`, `role="alert"` và disabled state.

## Phiên bản đề xuất

Đoạn sau cố ý không dùng client cache: với dashboard có quyền truy cập thay đổi, correctness và tính đơn giản quan trọng hơn cache chưa được chứng minh là cần thiết. `watch` cleanup hủy request trước; sequence guard bảo vệ cả trường hợp response đã hoàn tất ngay trước abort.

```vue
<script setup lang="ts">
import { computed, ref, watch } from 'vue'

type Item = { id: number; title: string; description: string }
type Result = { items: Item[]; total: number }
const query = ref('')
const debouncedQuery = ref('')
const status = ref('All')
const page = ref(1)
const items = ref<Item[]>([])
const total = ref(0)
const loading = ref(false)
const error = ref('')
const pageSize = 20
let sequence = 0

watch(query, (value, _, onCleanup) => {
  const timer = setTimeout(() => { debouncedQuery.value = value }, 300)
  onCleanup(() => clearTimeout(timer))
})
watch([query, status], () => { page.value = 1 })
const canNext = computed(() => page.value * pageSize < total.value)

watch([debouncedQuery, status, page], async (_, __, onCleanup) => {
  const current = ++sequence
  const controller = new AbortController()
  onCleanup(() => controller.abort())
  loading.value = true
  error.value = ''
  items.value = []
  total.value = 0
  try {
    const params = new URLSearchParams({
      q: debouncedQuery.value,
      status: status.value,
      page: String(page.value),
      pageSize: String(pageSize)
    })
    const response = await fetch('/api/requests?' + params, {
      credentials: 'include',
      signal: controller.signal
    })
    if (!response.ok) throw new Error('Request failed')
    const data = await response.json() as Result
    if (current !== sequence || controller.signal.aborted) return
    items.value = data.items
    total.value = data.total
  } catch (e) {
    if (current === sequence && !controller.signal.aborted)
      error.value = 'Không thể tải dữ liệu. Vui lòng thử lại.'
  } finally {
    if (current === sequence) loading.value = false
  }
}, { immediate: true })
</script>

<template>
  <section>
    <label for="search">Search requests</label>
    <input id="search" v-model="query" />
    <label for="status">Status</label>
    <select id="status" v-model="status">
      <option>All</option><option>Pending</option><option>Approved</option>
    </select>
    <button :disabled="loading || !canNext" @click="page++">Next</button>
    <p role="status" v-if="loading">Loading...</p>
    <p role="alert" v-if="error">{{ error }}</p>
    <p>Total: {{ total }}</p>
    <article v-for="item in items" :key="item.id">
      <h3>{{ item.title }}</h3>
      <div>{{ item.description }}</div>
    </article>
  </section>
</template>
```

**Giới hạn cần xác minh:** API phải thống nhất semantics `pageSize`, total và sort ổn định. Nếu cần phản ánh search text ngay khi người dùng gõ mà không chờ debounce, có thể clear stale items ngay khi query thay đổi. `AbortController` tiết kiệm client work nhưng không bảo đảm backend đã hủy query; server vẫn phải có timeout, cancellation và rate limits.

## Giải thích thiết kế sau khi sửa

State cập nhật chỉ từ request còn hiệu lực. Abort giúp giảm công việc thừa, sequence bảo vệ correctness. Không render HTML không đáng tin. URLSearchParams đảm bảo encoding. UI thông báo lỗi và có accessible labels. Authorization vẫn bắt buộc ở API, không phụ thuộc filter ở frontend.

## Trade-offs

Debounce giảm request nhưng thêm 300 ms độ trễ search; không cache làm tăng request khi quay lại filter nhưng tránh invalidation phức tạp. Nếu thêm cache, key phải bao gồm query/status/page/pageSize, scope user/tenant, TTL và invalidate khi mutation/logout. Server-side pagination cần sort ổn định; dữ liệu cập nhật liên tục có thể cần cursor pagination thay offset.

## Cách kiểm thử

1. **Component concurrency test:** Mock response A chậm hơn B, chỉ B được render.
2. **Failure-path test:** HTTP 500, malformed JSON, network reject và abort không làm spinner treo.
3. **Security test:** API trả `<img onerror=...>` trong description, DOM hiển thị text và không thực thi.
4. **Playwright E2E:** Gõ nhanh, đổi filter, đổi route; xác nhận đúng query và không hiển thị stale state.
5. **Load/API test:** Đo số request khi gõ 20 ký tự và p95 của endpoint, xác nhận rate-limit và pagination contract.

## Quan sát trong production

Frontend telemetry: request count/search session, abort count, response latency p95, HTTP status, filter/page transitions, stale-response suppression, user-visible errors. Backend Application Insights: dependency latency, rate limits, query plans và request correlation. Không log search terms chứa PII; dùng aggregation/redaction. Theo dõi CSP reports nếu có chính sách CSP.

## Câu hỏi phỏng vấn mở rộng

1. Nếu dùng TanStack Query hoặc cache layer, key và invalidation cần thiết kế ra sao?
2. Khi API không hỗ trợ cancellation, client sequence guard còn giá trị gì?
3. Nếu description bắt buộc chứa rich HTML từ CMS, bạn thiết kế sanitize và CSP như thế nào?

# Tổng kết hôm nay

## Kiến thức trọng tâm

IIS recycle là lifecycle của process, không phải durable job scheduler. HTTP 202 chỉ có ý nghĩa đáng tin khi công việc đã được chấp nhận và lưu bền vững. Multi-tenant authorization, idempotency, lease và transaction boundary phải được xác định rõ. Trong Vue, request hoàn thành không theo thứ tự khởi tạo; state cần guard, cancellation và error handling. Dữ liệu API không mặc nhiên an toàn để render HTML.

## Mẫu tư duy cần nhớ

1. Xác định trust boundary trước khi xử lý input và dữ liệu hiển thị.
2. Phân biệt accepted, persisted, processed và completed.
3. Thiết kế retry cùng idempotency, lease expiry và recovery.
4. Kiểm thử thứ tự bất lợi, crash và dependency failure thay vì chỉ happy path.
5. Đo telemetry trước khi thêm cache hoặc kiến trúc phức tạp.
