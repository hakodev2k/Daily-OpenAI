Sau deployment và App Pool recycle, CRM nhận đơn trùng; khi website ít traffic backlog tăng. CRM có trường externalReference nhưng chưa xác nhận tính năng deduplication. public class MvcApplication : HttpApplication
```csharp
{
    static Timer _timer;
    static bool _running;

    protected void Application_Start()
    {
        AreaRegistration.RegisterAllAreas();
        _timer = new Timer(_ => Sync(), null,
            TimeSpan.Zero, TimeSpan.FromMinutes(5));
    }

    static void Sync()
    {
        if (_running) return;
        _running = true;
        try
        {
            using (var db = new CommerceDbContext())
            using (var client = new HttpClient())
            {
                var orders = db.Orders.Where(x => !x.SentToCrm)
                    .OrderBy(x => x.CreatedAt).Take(100).ToList();
                foreach (var order in orders)
                {
                    var json = JsonConvert.SerializeObject(new {
                        order.Id, order.Total, order.CustomerId
                    });
                    var response = client.PostAsync(
                        "https://crm.example/api/orders",
                        new StringContent(json, Encoding.UTF8,
                            "application/json")).Result;
                    if (response.IsSuccessStatusCode)
                    {
                        order.SentToCrm = true;
                        db.SaveChanges();
                    }
                }
            }
        }
        catch (Exception ex)
        {
            File.AppendAllText(@"C:\logs\sync.txt", ex.ToString());
        }
        finally { _running = false; }
    }

    protected void Application_End() => _timer?.Dispose();
}
```

## Kết quả code review tham khảo

### [Critical] — Concurrent workers gửi trùng

**Vấn đề:** Static bool không bảo vệ nhiều processes, đồng thời check/set không atomic.
**Tại sao xảy ra:** Hai IIS instances đọc cùng hàng chưa gửi.
**Ảnh hưởng production:** Duplicate orders.
**Cách sửa:** Atomic SQL claim/lease với owner và expiry, unique work identity; xác minh CRM idempotency.

### [Critical] — Khoảng trống HTTP thành công và SQL commit

**Vấn đề:** CRM xử lý thành công rồi process chết trước SaveChanges.
**Tại sao xảy ra:** Không có distributed transaction.
**Ảnh hưởng production:** Retry tạo duplicate.
**Cách sửa:** Stable externalReference, CRM deduplication nếu contract hỗ trợ; reconciliation khi outcome không rõ. Không hứa exactly-once.

### [High] — Job phụ thuộc IIS lifecycle

**Vấn đề:** Timer dừng khi recycle/idle và chạy nhiều bản khi scale.
**Tại sao xảy ra:** Web process không phải durable scheduler.
**Ảnh hưởng production:** Backlog hoặc duplicate.
**Cách sửa:** Worker Service/Windows Service hoặc Azure Functions riêng; có health và deployment ownership.

### [High] — Thiếu durable retry state

**Vấn đề:** Boolean không mô tả Pending/InProgress/Retry/Completed.
**Tại sao xảy ra:** Không có attempts, lease, nextAttempt.
**Ảnh hưởng production:** Retry không kiểm soát, khó reconcile.
**Cách sửa:** Dispatch table với lease, attempts, exponential backoff, terminal failure.

### [High] — Blocking HTTP và thiếu cancellation

**Vấn đề:** .Result chiếm thread và không có shutdown coordination.
**Tại sao xảy ra:** Sync-over-async.
**Ảnh hưởng production:** Thread exhaustion, xử lý bị ngắt.
**Cách sửa:** Async end-to-end, timeout, cancellation, reuse HttpClient.

### [Medium] — Một exception bỏ cả batch

**Vấn đề:** Catch ngoài vòng lặp.
**Tại sao xảy ra:** Không isolate từng item.
**Ảnh hưởng production:** Head-of-line blocking.
**Cách sửa:** Catch per item, ghi retry state, tiếp tục các item khác.

### [Medium] — Local file logging thiếu observability

**Vấn đề:** File local có thể không ghi được và không tổng hợp.
**Tại sao xảy ra:** Không có structured logs/metrics.
**Ảnh hưởng production:** Backlog tăng âm thầm.
**Cách sửa:** Application Insights hoặc Kibana, correlation ID, backlog age, attempts, alerts.

### [Medium] — Throughput chưa kiểm soát

**Vấn đề:** Tạo HttpClient mỗi batch, SaveChanges mỗi item, không xử lý 429.
**Tại sao xảy ra:** Không có resource reuse/rate limiting.
**Ảnh hưởng production:** Connection churn và throttling.
**Cách sửa:** IHttpClientFactory, bounded concurrency, Retry-After, batch SQL updates nếu phù hợp.

## Phiên bản đề xuất

Các interface dưới đây là contract ứng dụng tự triển khai, không phải API framework. Claim phải atomic trong SQL transaction và Complete phải kiểm tra owner/lease.

```csharp
public record ClaimedOrder(long Id, decimal Total, Guid ExternalReference);
public interface IDispatchStore
{
    Task<IReadOnlyList<ClaimedOrder>> ClaimAsync(
        string owner, DateTimeOffset until, CancellationToken ct);
    Task CompleteAsync(long id, string owner, CancellationToken ct);
    Task RetryAsync(long id, string owner, string reason,
        DateTimeOffset next, CancellationToken ct);
}

public sealed class DispatchWorker(
    IDispatchStore store, IHttpClientFactory clients,
    ILogger<DispatchWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        var owner = Guid.NewGuid().ToString("N");
        while (!ct.IsCancellationRequested)
        {
            var batch = await store.ClaimAsync(
                owner, DateTimeOffset.UtcNow.AddMinutes(2), ct);
            foreach (var item in batch)
            {
                try
                {
                    using var response = await clients.CreateClient("crm")
                        .PostAsJsonAsync("/api/orders", new {
                            item.Id, item.Total,
                            externalReference = item.ExternalReference
                        }, ct);
                    if (response.IsSuccessStatusCode)
                        await store.CompleteAsync(item.Id, owner, ct);
                    else
                        await store.RetryAsync(item.Id, owner,
                            $"http_{(int)response.StatusCode}",
                            DateTimeOffset.UtcNow.AddMinutes(5), ct);
                }
                catch (OperationCanceledException) when (ct.IsCancellationRequested)
                {
                    throw;
                }
                catch (Exception ex)
                {
                    log.LogWarning(ex, "Dispatch {Id} failed", item.Id);
                    await store.RetryAsync(item.Id, owner, "transport",
                        DateTimeOffset.UtcNow.AddMinutes(5), ct);
                }
            }
            await Task.Delay(TimeSpan.FromSeconds(15), ct);
        }
    }
}
```

Store phải có lease expiry, bounded attempts và fencing/owner check; timeout CRM phải ngắn hơn lease hoặc renew lease. Nếu CRM không bảo đảm deduplication, cần tra cứu/reconcile trước khi retry unknown outcomes. Cấu hình named HttpClient BaseAddress và DI registration trước khi deploy.

## Giải thích thiết kế sau khi sửa

Worker tách khỏi web lifecycle; atomic claim giới hạn concurrent ownership nhưng không loại bỏ duplicate do lease expiry. External reference và reconciliation xử lý failure window qua HTTP. Rollout bằng dispatch table, backfill, shadow mode, chuyển ownership có kiểm soát; tuyệt đối không chạy song song scheduler cũ và mới.

## Trade-offs

Thêm dispatch table và worker tăng chi phí vận hành. Lease, retry và reconciliation cần tuning. Không cần microservices; một worker trong cùng solution là đủ nếu đáp ứng SLO.

## Cách kiểm thử

1. Concurrency: hai workers claim 1.000 orders, không đồng thời sở hữu cùng lease.
2. Failure-path: CRM thành công, crash trước SQL Complete; kiểm chứng dedup/reconciliation.
3. Deployment: IIS recycle và worker restart không mất work.
4. Load: CRM 429/5xx, đo backlog và bounded retries.
5. Database: expired lease, stale worker không được Complete.

## Quan sát trong production

Structured logs theo OrderId, externalReference, workerId; metrics pending count, oldest pending age, attempts, unknown outcome, CRM latency/status, lease expiry, heartbeat. Alert backlog age vượt SLO dù website HTTP 200.

## Câu hỏi phỏng vấn mở rộng

1. Nếu CRM không hỗ trợ tra cứu externalReference, bạn xử lý unknown outcome ra sao?
2. Vì sao SQL claim không cung cấp exactly-once?
3. Khi nào giữ Windows Service thay vì Azure Functions?

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/audit")]
public sealed class AuditController : ControllerBase
{
    private readonly Container _container;
    public AuditController(CosmosClient cosmos)
    {
        _container = cosmos.GetContainer("app", "audit");
    }

    [HttpGet]
    public async Task<IActionResult> Get(
        [FromQuery] string tenantId,
        [FromQuery] int page = 1,
        [FromQuery] int size = 50)
    {
        var query = new QueryDefinition(
            "SELECT * FROM c WHERE c.tenantId = @tenant " +
            "ORDER BY c.createdAt DESC")
            .WithParameter("@tenant", tenantId);

        using var iterator = _container.GetItemQueryIterator<AuditEvent>(
            query, requestOptions: new QueryRequestOptions {
                MaxItemCount = 1000
            });
        var all = new List<AuditEvent>();
        while (iterator.HasMoreResults)
        {
            var response = await iterator.ReadNextAsync();
            all.AddRange(response);
        }

        var items = all.Skip((page - 1) * size).Take(size)
            .Select(x => new {
                x.Id, x.CreatedAt, x.ActorEmail, x.Action, x.Payload
            });
        return Ok(new { total = all.Count, items });
    }
}
```

## Phiên bản đề xuất

Các interface tenant/token bên dưới là application contracts cần triển khai. Token phải được bảo vệ và ràng buộc với tenant, query shape và page size.

```csharp
public record AuditListItem(string Id, string CreatedAt, string Action);
public record AuditPage(
    IReadOnlyList<AuditListItem> Items, string? NextToken);

[Authorize]
[ApiController]
[Route("api/audit")]
public sealed class AuditController(
    Container container, ITenantAccess access,
    ICursorProtector cursors, ILogger<AuditController> log)
    : ControllerBase
{
    [HttpGet]
    public async Task<ActionResult<AuditPage>> Get(
        [FromQuery] int size = 50,
        [FromQuery] string? cursor = null)
    {
        if (size is < 1 or > 100) return BadRequest();
        var ct = HttpContext.RequestAborted;
        var tenant = await access.RequireTenantAsync(User, ct);
        string? continuation;
        try
        {
            continuation = cursor is null ? null
                : cursors.Unprotect(cursor, tenant, "audit-v1", size);
        }
        catch (InvalidCursorException) { return BadRequest("Invalid cursor"); }

        var query = new QueryDefinition(
            "SELECT c.id, c.createdAt, c.action FROM c " +
            "WHERE c.tenantId = @tenant ORDER BY c.createdAt DESC")
            .WithParameter("@tenant", tenant);

        using var iterator = container.GetItemQueryIterator<AuditListItem>(
            query, continuation, new QueryRequestOptions {
                PartitionKey = new PartitionKey(tenant),
                MaxItemCount = size
            });

        var items = new List<AuditListItem>();
        string? next;
        double ru = 0;
        do
        {
            var response = await iterator.ReadNextAsync(ct);
            items.AddRange(response);
            ru += response.RequestCharge;
            next = response.ContinuationToken;
        } while (items.Count == 0 && next is not null);

        log.LogInformation("Audit page RU={RU} Count={Count}", ru, items.Count);
        return Ok(new AuditPage(items,
            next is null ? null :
                cursors.Protect(next, tenant, "audit-v1", size)));
    }
}
```

MaxItemCount không bảo đảm một page đủ size; cursor không cung cấp snapshot isolation qua nhiều requests. Nếu cần sort ổn định khi createdAt trùng nhau, thiết kế tie-breaker/index phù hợp và xác minh Cosmos query support. Cần register DI và bảo vệ cursor bằng authenticated encryption/signing phù hợp.

## Giải thích thiết kế sau khi sửa

Tenant được authorize trước khi query. Explicit partition key thu hẹp query scope. Projection giảm dữ liệu; cursor tránh đọc toàn bộ history. Vue.js cần reset cursor khi filter thay đổi, bỏ response stale và không tái sử dụng cursor của tenant khác.

## Trade-offs

Cursor không hỗ trợ random page jump thuận tiện; total chính xác có chi phí. Tenant lớn có thể thành hot partition: chỉ cân nhắc synthetic partition key khi metrics chứng minh cần thiết, vì migration tốn kém. Cursor protection tăng complexity nhưng giữ isolation.

## Cách kiểm thử

1. Security: tenant A không thể dùng tenant B hoặc cursor B.
2. Load: hàng triệu events, đo RU/p95/memory/429.
3. Pagination: empty page có continuation, insert giữa requests, timestamp trùng.
4. Failure-path: cancellation và throttling.
5. Playwright E2E: Vue filter thay đổi nhanh không hiển thị stale results.

## Quan sát trong production

Application Insights dependency telemetry, Cosmos RequestCharge, ActivityId, diagnostics duration, 429, retries, page size, p95/p99 và hot-partition metrics. Không log JWT, raw cursor hay payload; dùng tenant hash nếu cần phân nhóm.
