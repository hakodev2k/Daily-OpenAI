# Code Review Challenge 1 — ASP.NET Core multi-tenant export và broken object authorization

**Chủ đề:** C#/.NET 8, ASP.NET Core, EF Core, Azure Blob Storage  
**Độ khó:** Senior+

## Bối cảnh

SaaS quản lý nhân sự có nhiều tenant trên PostgreSQL. Mỗi tenant có hàng chục nghìn nhân viên; API export CSV chạy trên 4 App Service instances. Một user đã tải được file tenant khác bằng cách đổi URL. Yêu cầu bảo vệ PII, hạn chế memory và audit mọi download.

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/tenants/{tenantId:guid}/exports")]
public sealed class ExportController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly BlobContainerClient _blobs;
    public ExportController(AppDbContext db, BlobContainerClient blobs)
        => (_db, _blobs) = (db, blobs);

    [HttpPost]
    public async Task<IActionResult> Create(Guid tenantId)
    {
        var employees = await _db.Employees
            .Where(e => e.TenantId == tenantId).ToListAsync();
        var csv = new StringBuilder("Name,Email\n");
        foreach (var e in employees)
            csv.AppendLine($"{e.Name},{e.Email}");
        var key = $"exports/{tenantId}/{Guid.NewGuid()}.csv";
        await _blobs.GetBlobClient(key)
            .UploadAsync(BinaryData.FromString(csv.ToString()));
        return Ok(new { key });
    }

    [HttpGet("download")]
    public async Task<IActionResult> Download(Guid tenantId, string key)
    {
        var stream = await _blobs.GetBlobClient(key).OpenReadAsync();
        return File(stream, "text/csv", "employees.csv");
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Cross-tenant export

**Vấn đề:** Route tenantId được tin trực tiếp.  
**Tại sao xảy ra:** Authentication không chứng minh tenant membership.  
**Ảnh hưởng production:** User có thể xuất PII tenant khác.  
**Cách sửa:** Kiểm tra quyền export theo actor/tenant từ DB hoặc policy resource trước query.

### [Critical] — Arbitrary blob download

**Vấn đề:** Client truyền blob key tùy ý.  
**Tại sao xảy ra:** Không đối chiếu key với tenant và owner.  
**Ảnh hưởng production:** Có thể tải file của tenant khác.  
**Cách sửa:** Nhận opaque exportId; lookup metadata rồi authorize trước khi mở blob.

### [High] — CSV formula injection

**Vấn đề:** Cell untrusted được ghi thẳng.  
**Tại sao xảy ra:** Spreadsheet có thể diễn giải prefix công thức.  
**Ảnh hưởng production:** Rủi ro thực thi công thức khi mở file.  
**Cách sửa:** CSV quoting đúng chuẩn và neutralize spreadsheet formula prefixes.

### [High] — Unbounded memory

**Vấn đề:** ToListAsync, StringBuilder và BinaryData cùng giữ dữ liệu.  
**Tại sao xảy ra:** Toàn bộ export được materialize.  
**Ảnh hưởng production:** GC/LOH, OOM, timeout.  
**Cách sửa:** Bounded batches, streaming upload hoặc durable background job.

### [High] — Không có retention

**Vấn đề:** File không có expiration/cleanup.  
**Tại sao xảy ra:** Blob tồn tại sau khi người dùng mất quyền.  
**Ảnh hưởng production:** PII exposure kéo dài.  
**Cách sửa:** Private storage, retention policy, cleanup và kiểm tra quyền lại khi tải.

### [Medium] — CSV encoding sai

**Vấn đề:** Comma, quote và newline không được escape.  
**Tại sao xảy ra:** Không dùng CSV writer.  
**Ảnh hưởng production:** Sai cột hoặc hỏng dữ liệu.  
**Cách sửa:** Dùng CSV library và kiểm thử edge cases.

### [Medium] — Thiếu cancellation và quota

**Vấn đề:** Không truyền token, không giới hạn export.  
**Tại sao xảy ra:** Request không có admission control.  
**Ảnh hưởng production:** DB/Blob overload khi abuse.  
**Cách sửa:** CancellationToken, per-tenant quota, bounded concurrency.

### [Medium] — Thiếu audit

**Vấn đề:** Không lưu actor, tenant, exportId và outcome.  
**Tại sao xảy ra:** Không có metadata/audit events.  
**Ảnh hưởng production:** Khó điều tra phạm vi leak.  
**Cách sửa:** Structured audit với stable actor ID, correlation và access outcome.

## Phiên bản đề xuất

```csharp
[Authorize]
[ApiController]
[Route("api/tenants/{tenantId:guid}/exports")]
public sealed class ExportController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ITenantAccess _access;
    private readonly IExportStorage _storage;
    public ExportController(AppDbContext db, ITenantAccess access,
        IExportStorage storage)
        => (_db, _access, _storage) = (db, access, storage);

    [HttpPost]
    public async Task<IActionResult> Create(Guid tenantId, CancellationToken ct)
    {
        var actor = User.FindFirst("sub")?.Value;
        if (actor is null) return Unauthorized();
        if (!await _access.CanExportAsync(actor, tenantId, ct))
            return Forbid();

        var job = new ExportJob {
            Id = Guid.NewGuid(), TenantId = tenantId,
            RequestedBy = actor, Status = "Pending"
        };
        _db.ExportJobs.Add(job);
        await _db.SaveChangesAsync(ct);
        return Accepted(new { exportId = job.Id, status = job.Status });
    }

    [HttpGet("{exportId:guid}/download")]
    public async Task<IActionResult> Download(
        Guid tenantId, Guid exportId, CancellationToken ct)
    {
        var actor = User.FindFirst("sub")?.Value;
        if (actor is null) return Unauthorized();
        if (!await _access.CanDownloadAsync(actor, tenantId, ct))
            return Forbid();
        var job = await _db.ExportJobs.AsNoTracking()
            .SingleOrDefaultAsync(x => x.Id == exportId
                && x.TenantId == tenantId && x.RequestedBy == actor, ct);
        if (job is null) return NotFound();
        if (job.Status != "Completed") return Conflict();
        var stream = await _storage.OpenReadAsync(job.StorageKey!, ct);
        return File(stream, "text/csv", "employees.csv");
    }
}
// Worker: claim jobs atomically, stream bounded DB batches,
// CSV-escape and neutralize formula cells, upload privately,
// persist completion, expire and clean up blobs.
```

## Giải thích thiết kế sau khi sửa

Opaque exportId chỉ là locator, không phải authorization. Worker cần durable queue/polling, atomic claim, streaming, retry, cleanup. Actor identifier phải được xác thực trong issuer/tenant context; không giả định claim sub đơn lẻ là globally unique.

## Trade-offs

Background jobs tăng latency và state management. Với export nhỏ có thể stream trực tiếp nếu vẫn có authorization, quota, CSV safety và cancellation. Owner-only download là policy giả định; nếu chia sẻ file, phải thiết kế policy riêng.

## Cách kiểm thử

1. Security: user A thử export/download tenant B và exportId của user khác.
2. CSV: comma, quote, newline và formula prefix mở bằng spreadsheet thực tế.
3. Load: 1 triệu rows, peak memory và DB impact.
4. Failure: worker crash giữa upload, retry và cleanup partial blob.
5. Revocation: quyền bị thu hồi trước download.

## Quan sát trong production

Audit actor/tenant/exportId, authorization outcomes, byte count và correlation ID; metrics queue age, failure, memory/GC, DB query duration, storage errors. Alert khi forbidden attempts hoặc export volume tăng bất thường.

## Câu hỏi phỏng vấn mở rộng

1. Nếu cần chia sẻ export trong tenant, policy thay đổi thế nào?
2. Khi nào short-lived SAS download phù hợp và có rủi ro gì?
3. Nếu dữ liệu thay đổi giữa các batches, consistency contract nào cần xác nhận?

## Kết quả code review tham khảo

### [Critical] — Hardcoded database password

**Vấn đề:** Credential nằm trực tiếp trong manifest.  
**Tại sao xảy ra:** Secret được đưa vào artifact/repo.  
**Ảnh hưởng production:** Lộ quyền truy cập DB.  
**Cách sửa:** Rotate credential; dùng Secret/secret manager với RBAC và encryption at rest.

### [High] — Rollout làm mất capacity

**Vấn đề:** maxUnavailable: 2 và maxSurge: 0.  
**Tại sao xảy ra:** Hai trong ba replicas có thể unavailable.  
**Ảnh hưởng production:** 503 và latency dưới tải.  
**Cách sửa:** maxUnavailable: 0, maxSurge: 1 nếu cluster có capacity; đo trước.

### [High] — Probe gây restart storm

**Vấn đề:** Liveness chạy sớm và trùng readiness.  
**Tại sao xảy ra:** Startup chậm hoặc DB outage có thể làm probe fail.  
**Ảnh hưởng production:** Pod restart lặp và giảm capacity.  
**Cách sửa:** startupProbe; liveness độc lập transient dependency, readiness phản ánh khả năng phục vụ.

### [High] — Shutdown quá ngắn

**Vấn đề:** terminationGracePeriodSeconds: 5.  
**Tại sao xảy ra:** Không đủ drain in-flight writes.  
**Ảnh hưởng production:** Connection reset, ambiguous writes.  
**Cách sửa:** Graceful shutdown, ingress draining, đo p99 request và idempotent write APIs.

### [Medium] — Mutable image tag

**Vấn đề:** Dùng latest.  
**Tại sao xảy ra:** Không pin artifact cụ thể.  
**Ảnh hưởng production:** Rollback/audit không đáng tin.  
**Cách sửa:** Pin immutable digest và ghi build SHA.

### [Medium] — Resource limit không có baseline

**Vấn đề:** CPU/memory thấp chưa được kiểm chứng.  
**Tại sao xảy ra:** Throttling hoặc OOM làm startup kéo dài.  
**Ảnh hưởng production:** Lỗi không ổn định.  
**Cách sửa:** Đo CPU throttling, OOM và memory trước khi tune.

### [Medium] — Thiếu rollout gates

**Vấn đề:** Không có stable readiness window và smoke validation.  
**Tại sao xảy ra:** Deployment có thể tiếp tục dù app chưa ổn định.  
**Ảnh hưởng production:** Sự cố lan rộng.  
**Cách sửa:** minReadySeconds, progress deadline, rollout status và synthetic tests.

## Giải thích thiết kế sau khi sửa

Giả định /health/live không phụ thuộc DB và /health/ready chỉ trả ready sau warm-up. Ứng dụng phải drain SIGTERM và bảo vệ idempotency. Secret phải provision trước, digest placeholder phải thay bằng digest thật. Các số resource/grace là starting assumptions, không phải benchmark.

## Trade-offs

maxSurge cần thêm capacity; nếu không đủ, rollout có thể đứng thay vì giảm availability. Readiness phụ thuộc DB có thể làm tất cả pods unready khi DB outage. Grace period dài làm deployment chậm; quyết định dựa trên p99 và SLO.

## Cách kiểm thử

1. Load/deployment: rolling update khi có traffic, đo 5xx.
2. Failure: inject DB outage, xác minh không restart storm.
3. Shutdown: SIGTERM khi write in-flight và retry an toàn.
4. Capacity: node thiếu tài nguyên, rollout deadline/rollback.
5. Security: scan manifest và kiểm tra rotation/RBAC secrets.

## Quan sát trong production

Theo dõi available replicas, readiness transitions, pod restarts/OOMKilled, CPU throttling, ingress 502/503/504, ASP.NET Core p95/p99, DB pool và rollout events theo image digest. Alert khi rollout deadline vượt ngưỡng.

## Câu hỏi phỏng vấn mở rộng

1. Nếu không đủ surge capacity, chọn rollout nào?
2. DB migration không backward-compatible cần expand/contract thế nào?
3. Có nên cho readiness kiểm tra mọi downstream dependency không?
