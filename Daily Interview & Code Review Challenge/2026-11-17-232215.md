## Đoạn code cần review

```csharp
[ApiController]
[Route("api/pages")]
public class PagesController(
    IPageReader reader, IMemoryCache cache) : ControllerBase
{
    [HttpGet("{slug}")]
    public async Task<IActionResult> Get(
        string slug, string lang = "en", bool preview = false)
    {
        var key = "page:" + slug;
        if (cache.TryGetValue(key, out PageDto? hit))
        {
            Response.Headers.CacheControl = "public,max-age=3600";
            return Ok(hit);
        }
        var page = await reader.ReadAsync(slug, lang, preview);
        if (page == null) return NotFound();
        var result = new PageDto(
            page.Title, page.Html, lang, preview);
        cache.Set(key, result, TimeSpan.FromHours(1));
        Response.Headers.CacheControl = "public,max-age=3600";
        return Ok(result);
    }
}
public record PageDto(
    string Title, string Html, string Language, bool Preview);
```

## Phiên bản đề xuất

Ví dụ dùng application abstractions IPublishedReader/IPreviewReader, không phải API Optimizely có sẵn. Reader phải đảm bảo version, language và content-level permission; cấu hình Akamai phải bypass preview.

```csharp
[ApiController]
[Route("api/content")]
public class ContentController(
    IPublishedReader published, IPreviewReader preview) : ControllerBase
{
    [AllowAnonymous]
    [HttpGet("published/{site}/{lang}/{slug}")]
    public async Task<IActionResult> GetPublished(
        string site, string lang, string slug, CancellationToken ct)
    {
        var result = await published.ReadAsync(site, lang, slug, ct);
        if (result == null) return NotFound();
        Response.Headers.CacheControl = "public,max-age=60,s-maxage=300";
        Response.Headers.ETag = $"\"{result.VersionHash}\"";
        return Ok(result.Page);
    }

    [Authorize(Policy = "CmsEditor")]
    [HttpGet("preview/{id:guid}")]
    public async Task<IActionResult> GetPreview(
        Guid id, CancellationToken ct)
    {
        Response.Headers.CacheControl = "private,no-store";
        var result = await preview.ReadAuthorizedAsync(id, User, ct);
        return result == null ? NotFound() : Ok(result);
    }
}
```

## Giải thích thiết kế sau khi sửa

Tách published/preview ở endpoint và quyền, thay vì chỉ thêm preview vào cache key. Published reader trả version đã publish; preview reader kiểm tra quyền với nội dung cụ thể. Event publish kích hoạt invalidation/purge, có retry và alert khi purge lỗi.

## Trade-offs

Purge tăng độ mới nhưng phụ thuộc API CDN; TTL ngắn tăng origin load. Versioned key dễ audit nhưng thêm quản lý lifecycle. Không cần Redis nếu edge hit ratio và origin capacity đã đạt mục tiêu.

## Cách kiểm thử

1. **Security/integration:** Anonymous và editor không đủ quyền không thể xem draft.
2. **Concurrency/integration:** Cùng slug khác language/site không dùng chung cache.
3. **Failure-path:** Akamai không cache preview kể cả query/cookie khác nhau.
4. **Load/lifecycle:** Publish mới hiển thị đúng trên 4 instances sau purge hoặc TTL.
5. **E2E:** Rich text XSS payload không thực thi trong browser.

## Quan sát trong production

CDN Age/cache status, origin cache hit ratio, content version, publish-to-visible latency, purge failure, preview 401/403 và trace request→CMS.

## Câu hỏi phỏng vấn mở rộng

1. Khi CDN purge outage 30 phút, phương án giảm stale?
2. Khi nào headless CMS phù hợp hơn server-side rendering?

import { ref, watch, onMounted } from 'vue';
type Employee = { id: string; name: string };
const query = ref('');
const department = ref('all');
const page = ref(1);
const employees = ref<Employee[]>([]);
const total = ref(0);
const loading = ref(false);
const error = ref('');
async function load() {

  error.value = '';

## Phiên bản đề xuất

Ví dụ giả định API trả {items,total} với pageSize=20; kiểm tra watcher batching bằng integration test. Client cancellation không thay thế backend cancellation.

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted, computed } from 'vue';
type Employee = { id: string; name: string };
const query = ref(''), search = ref('');
const department = ref('all'), page = ref(1);
const employees = ref<Employee[]>([]);
const total = ref(0), loading = ref(false), error = ref('');
let timer: ReturnType<typeof setTimeout> | undefined;
let controller: AbortController | undefined;
let sequence = 0;
watch(query, value => {
  clearTimeout(timer);
  timer = setTimeout(() => { search.value = value; }, 300);
});
watch([search, department], () => { page.value = 1; });
async function load() {
  const id = ++sequence;
  controller?.abort();
  const active = new AbortController();
  controller = active;
  loading.value = true;
  error.value = '';
  const params = new URLSearchParams({
    q: search.value, department: department.value,
    page: String(page.value)
  });
  try {
    const response = await fetch('/api/employees?' + params, {
      signal: active.signal
    });
    if (!response.ok) throw new Error('HTTP ' + response.status);
    const data = await response.json();
    if (id !== sequence || active.signal.aborted) return;
    employees.value = data.items;
    total.value = data.total;
  } catch (e) {
    if (id !== sequence || active.signal.aborted) return;
    error.value = e instanceof Error ? e.message : 'Request failed';
    employees.value = [];
    total.value = 0;
  } finally {
    if (id === sequence) loading.value = false;
  }
}
watch([search, department, page], load, { immediate: true });
const canNext = computed(() => !loading.value && page.value * 20 < total.value);
onUnmounted(() => {
  sequence++;
  controller?.abort();
  clearTimeout(timer);
});
</script>
<template>
  <label for="q">Search employees</label>
  <input id="q" v-model="query" />
  <label for="dept">Department</label>
  <select id="dept" v-model="department">
    <option value="all">All</option>
    <option value="hr">HR</option>
  </select>
  <p v-if="loading" role="status">Loading...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <button v-if="error" @click="load">Retry</button>
  <ul><li v-for="x in employees" :key="x.id">{{ x.name }}</li></ul>
  <button @click="page--" :disabled="page <= 1 || loading">Previous</button>
  <button @click="page++" :disabled="!canNext">Next</button>
  <p>Total: {{ total }}</p>
</template>
```

## Giải thích thiết kế sau khi sửa

Một watcher quản lý fetch theo snapshot; request sequence bảo vệ correctness ngay cả khi abort đến muộn. try/catch/finally chỉ cập nhật state của active request; debounce giảm request burst.

## Trade-offs

Debounce giảm load nhưng tăng latency 300ms. Abort không đảm bảo server dừng; sequence guard bảo đảm client state. Khi query đang debounce, có thể tạm giữ kết quả cũ với nhãn stale hoặc clear ngay để bảo đảm strict filter correspondence. Không cần thư viện state mới nếu scope nhỏ.

## Cách kiểm thử

1. **Security/integration:** Response A chậm hơn B: chỉ B được render.
2. **Concurrency/integration:** 429/500/network failure không làm loading kẹt.
3. **Failure-path:** Đang page 4 đổi filter: page reset 1, không duplicate request.
4. **Load/lifecycle:** Unmount giữa fetch: abort và không update state.
5. **E2E:** Playwright test gõ nhanh, pagination, label và live region.

## Quan sát trong production

Client request count/session, aborted count, stale discarded count, 429/5xx, frontend latency p95, API dependency trace và browser network waterfall.

## Câu hỏi phỏng vấn mở rộng

1. Cursor pagination sẽ đổi state ra sao?
2. Làm thế nào tránh cache stale sau khi sửa nhân viên?
