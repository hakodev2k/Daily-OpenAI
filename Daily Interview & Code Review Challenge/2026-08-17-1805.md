# Code Review Challenge 1 — Hangfire Job xử lý thanh toán không an toàn khi retry

**Chủ đề:** Background jobs, idempotency, concurrency, EF Core transaction
**Độ khó:** Senior+

## Bối cảnh

Hệ thống ASP.NET Core sử dụng Hangfire để xử lý thanh toán. Khi worker restart hoặc dependency lỗi, job được retry. Production ghi nhận duplicate email và trạng thái xử lý không nhất quán.

## Đoạn code cần review

```csharp
public async Task ProcessPayment(Guid id)
{
    var payment = await _db.Payments.FirstAsync(x => x.Id == id);

    if (payment.Status == "Completed")
        return;

    payment.Status = "Completed";
    await _db.SaveChangesAsync();

    await _email.SendAsync(payment.Email, "Completed");
}
```

## Nhiệm vụ của ứng viên

- Xác định lỗi correctness, concurrency, reliability.
- Giải thích impact production.
- Đề xuất thiết kế retry an toàn.
- Nêu cách test race condition.

## Gợi ý

### Gợi ý 1
Retry không đồng nghĩa với xử lý an toàn.

### Gợi ý 2
Cần idempotency, concurrency control và tách database state với external side effect.

---

**Hãy tự review đoạn code trước khi xem phần phân tích bên dưới.**

---

## Kết quả code review tham khảo

- Hai worker có thể xử lý cùng payment.
- Email có thể gửi nhiều lần.
- Không có transaction boundary phù hợp.
- Không có idempotency key.
- Thiếu audit và observability.

## Code đề xuất

Sử dụng state transition có optimistic concurrency, lưu event/outbox trong transaction, sau đó worker riêng xử lý email với retry và deduplication.

## Kiểm thử

- Concurrent execution.
- Worker crash sau commit.
- Email timeout.
- Retry nhiều lần.

# Code Review Challenge 2 — EF Core query load toàn bộ dữ liệu vào memory

**Chủ đề:** EF Core query execution, performance
**Độ khó:** Senior

## Bối cảnh

API báo cáo đơn hàng timeout khi dữ liệu tăng lên vài triệu bản ghi.

## Đoạn code cần review

```csharp
public async Task<List<OrderDto>> GetOrders(DateTime from, DateTime to)
{
    var orders = await _db.Orders.ToListAsync();

    return orders.Where(x => x.CreatedAt >= from && x.CreatedAt <= to)
        .Select(x => new OrderDto
        {
            Id = x.Id,
            Amount = x.Total
        })
        .ToList();
}
```

## Nhiệm vụ của ứng viên

- Tìm vấn đề performance.
- Giải thích query execution.
- Đề xuất cải tiến.
- Nêu cách benchmark.

## Gợi ý

### Gợi ý 1
Xác định đoạn code chạy ở database hay application.

### Gợi ý 2
Projection, AsNoTracking, pagination và index cần được xem xét.

---

**Hãy tự review đoạn code trước khi xem phần phân tích bên dưới.**

---

## Kết quả code review tham khảo

- ToListAsync tải toàn bộ bảng.
- Filter chạy trong memory.
- Tracking không cần thiết cho read-only.
- Thiếu pagination và index strategy.

## Code đề xuất

```csharp
return await _db.Orders
    .AsNoTracking()
    .Where(x => x.CreatedAt >= from && x.CreatedAt <= to)
    .Select(x => new OrderDto { Id = x.Id, Amount = x.Total })
    .Take(1000)
    .ToListAsync();
```
