# Code Review Challenge 1 — EF Core transaction và external side effects

**Chủ đề:** EF Core transaction, concurrency, consistency
**Độ khó:** Senior+
**Thời gian review đề xuất:** 35 phút
**Số vấn đề cần tìm:** Khoảng 8 vấn đề

## Bối cảnh

Một API xử lý offboarding nhân viên. Hệ thống cần cập nhật SQL Server, cập nhật calendar qua Microsoft Graph và gửi notification. API chạy nhiều instance trên Azure. Production xuất hiện lock timeout, notification gửi sai trạng thái và dữ liệu giữa DB với external service không đồng nhất.

## Đoạn code cần review

```csharp
public async Task OffboardAsync(Guid employeeId, CancellationToken ct)
{
    await using var tx = await _db.Database.BeginTransactionAsync(ct);

    var employee = await _db.Employees
        .SingleAsync(x => x.Id == employeeId, ct);

    employee.Status = EmployeeStatus.Inactive;

    await _db.SaveChangesAsync(ct);

    await _graph.Me.Events[employee.CalendarId]
        .PatchAsync(new Event { Subject = "Inactive" }, cancellationToken: ct);

    await _notification.SendAsync(employee.Email, ct);

    await tx.CommitAsync(ct);
}
```

## Nhiệm vụ của ứng viên

1. Tìm correctness, concurrency và reliability issue.
2. Giải thích production impact.
3. Đề xuất thiết kế sửa lỗi.
4. Mô tả cách test và monitor.

## Gợi ý

### Gợi ý 1
Không phải mọi side effect đều thuộc cùng transaction với database.

### Gợi ý 2
Xem xét outbox pattern, idempotency, retry và optimistic concurrency.

## Kết quả code review tham khảo

- Giữ SQL transaction trong lúc gọi Graph/notification làm tăng lock duration. Severity: Critical.
- External API không rollback cùng SQL transaction. Severity: Critical.
- Không có idempotency khi retry. Severity: High.
- Không có concurrency control cho employee state transition. Severity: High.
- Thiếu structured logging cho workflow nhiều bước. Severity: Medium.

## Phiên bản code đề xuất

Commit thay đổi business state trong transaction ngắn, tạo outbox messages cùng transaction, xử lý Graph và notification bằng worker có retry, idempotency key và trạng thái xử lý.

## Cách kiểm thử

- Hai request offboard cùng employee.
- Graph timeout sau khi DB commit.
- Notification retry nhiều lần.
- Worker crash giữa các bước.

## Quan sát production

Theo dõi transaction duration, lock wait, outbox backlog, dependency latency, retry count và correlation id.

# Code Review Challenge 2 — Background worker mất cancellation và uncontrolled concurrency

**Chủ đề:** async/await, BackgroundService, resource lifetime
**Độ khó:** Senior
**Thời gian review đề xuất:** 30 phút
**Số vấn đề cần tìm:** Khoảng 7 vấn đề

## Bối cảnh

Worker đọc message RabbitMQ để gửi email. Khi traffic tăng, memory tăng và shutdown kéo dài.

## Đoạn code cần review

```csharp
public class EmailWorker : BackgroundService
{
    private readonly RabbitClient _client;

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (true)
        {
            var message = await _client.ReceiveAsync();

            _ = Task.Run(async () =>
            {
                await SendEmailAsync(message);
                await _client.AckAsync(message.Id);
            });
        }
    }
}
```

## Nhiệm vụ của ứng viên

1. Xác định vấn đề async, cancellation và reliability.
2. Đánh giá khi chạy dưới load.
3. Đề xuất implementation tốt hơn.

## Gợi ý

### Gợi ý 1
Fire-and-forget trong background processing thường có rủi ro.

### Gợi ý 2
Cần bounded queue, controlled concurrency và graceful shutdown.

---

**Hãy tự review đoạn code trước khi xem phần phân tích bên dưới.**

---

## Kết quả code review tham khảo

- Không dùng cancellation token. Severity: High.
- Fire-and-forget task không được quản lý. Severity: Critical.
- Không giới hạn số task chạy đồng thời. Severity: High.
- Exception có thể bị mất. Severity: Medium.

## Phiên bản code đề xuất

Dùng Channel<T> bounded, worker pool có giới hạn concurrency, await processing task khi shutdown và propagate cancellation.

## Cách kiểm thử

- Shutdown khi đang xử lý message.
- RabbitMQ timeout.
- Email provider lỗi liên tục.
- Load test nhiều message.

## Quan sát production

Theo dõi queue depth, processing latency, failure rate, retry count và worker health.

# Tổng kết hôm nay

## Kiến thức trọng tâm

- Transaction boundary phải phù hợp với hệ thống thực tế.
- External side effects cần idempotency và recovery strategy.
- Background processing cần lifecycle management.
- Observability là một phần của thiết kế.

## Mẫu tư duy cần nhớ

- Clarify before designing.
- Measure before optimizing.
- Design retries together with idempotency.
- Stabilize before investigating.
- Treat observability as part of the design.
