# Code Review Challenge 1 — ASP.NET Core upload file lên Azure Blob Storage

**Chủ đề:** .NET 8, ASP.NET Core, Azure Blob Storage, EF Core, security, consistency  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 35 phút  
**Số vấn đề cần tìm:** khoảng 9–10

## Bối cảnh

Ứng dụng quản lý tài liệu trên Azure App Service Linux có nhiều instances. User được upload PDF/ảnh vào dự án mà họ có quyền ghi, tối đa 50 MiB/file. Blob lưu trên Azure Storage, metadata lưu SQL Server. Frontend có thể retry khi timeout. Sau đợt tăng tải, memory tăng và xuất hiện blob không có metadata; QA nghi ngờ user có thể ghi vào dự án khác. Chưa xác định root cause. Giả định authentication middleware đã chạy và các dependencies được đăng ký hợp lệ.

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/projects/{projectId:guid}/documents")]
public sealed class DocumentsController : ControllerBase
{
    private readonly DocumentDbContext _db;
    private readonly BlobContainerClient _container;
    private readonly ILogger<DocumentsController> _log;

    public DocumentsController(DocumentDbContext db,
        BlobContainerClient container, ILogger<DocumentsController> log)
    {
        _db = db;
        _container = container;
        _log = log;
    }

    [HttpPost]
    public async Task<IActionResult> Upload(Guid projectId, IFormFile file)
    {
        if (file == null || file.Length == 0)
            return BadRequest("Missing file");

        var key = $"{projectId}/{file.FileName}";
        var blob = _container.GetBlobClient(key);
        using var buffer = new MemoryStream();
        await file.CopyToAsync(buffer);
        buffer.Position = 0;
        await blob.UploadAsync(buffer, overwrite: true);

        var document = new Document
        {
            Id = Guid.NewGuid(),
            ProjectId = projectId,
            BlobName = key,
            OriginalName = file.FileName,
            ContentType = file.ContentType,
            UploadedBy = User.Identity!.Name!,
            UploadedAtUtc = DateTime.UtcNow
        };
        _db.Documents.Add(document);
        await _db.SaveChangesAsync();
        _log.LogInformation("Uploaded {File} for {User}",
            file.FileName, User.Identity.Name);
        return Ok(new { document.Id, key });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Broken project-level authorization

**Vấn đề:** `[Authorize]` không kiểm tra quyền trên `projectId`.  
**Tại sao xảy ra:** ID từ route được sử dụng trực tiếp.  
**Ảnh hưởng production:** User đăng nhập có thể upload vào dự án không thuộc quyền của họ.  
**Cách sửa:** Kiểm tra permission từ database/authorization service trước side effect; trả 403 hoặc 404 theo policy.

### [High] — Blob overwrite và filename không đáng tin

**Vấn đề:** `overwrite: true` với blob key từ filename.  
**Tại sao xảy ra:** Nhiều upload trùng tên dùng chung key.  
**Ảnh hưởng production:** Nội dung bị thay thế, metadata cũ trỏ sang bytes mới.  
**Cách sửa:** Opaque server-generated blob ID, conditional create; lưu filename chỉ như display metadata.

### [High] — Không giới hạn kích thước file

**Vấn đề:** Chỉ kiểm tra file rỗng, không kiểm tra 50 MiB.  
**Tại sao xảy ra:** Thiếu validation và request/form limit.  
**Ảnh hưởng production:** Resource exhaustion, storage cost, DoS.  
**Cách sửa:** Áp giới hạn ở proxy/server và endpoint; tính multipart overhead.

### [High] — Buffer toàn bộ file trong MemoryStream

**Vấn đề:** Sao chép toàn bộ payload vào managed memory.  
**Tại sao xảy ra:** `CopyToAsync` trước upload, trong khi `IFormFile` có thể đã được buffer.  
**Ảnh hưởng production:** LOH allocations, GC pressure, memory spike khi tải tăng.  
**Cách sửa:** Stream từ `OpenReadStream` hoặc direct-to-Blob upload; đo allocation trước/sau.

### [High] — Không có transaction xuyên Blob và SQL

**Vấn đề:** Blob có thể được tạo dù DB save thất bại; timeout sau commit là ambiguous outcome.  
**Tại sao xảy ra:** Hai storage systems không có local atomic transaction chung.  
**Ảnh hưởng production:** Orphan blob, metadata trỏ tới missing blob, duplicate khi retry.  
**Cách sửa:** Pending/Ready state machine, idempotency key, reconciliation và cleanup an toàn; không xóa blob mù quáng khi SQL timeout.

### [High] — Thiếu file-content validation

**Vấn đề:** Tin `ContentType` và không kiểm tra bytes/scan.  
**Tại sao xảy ra:** Metadata client tự khai báo.  
**Ảnh hưởng production:** Lưu và phát tán nội dung nguy hiểm.  
**Cách sửa:** Allowlist, signature/parser validation, malware scanning theo threat model; download với attachment/nosniff khi phù hợp.

### [Medium] — Thiếu cancellation propagation

**Vấn đề:** Không truyền `CancellationToken` cho Blob và SQL.  
**Tại sao xảy ra:** Không gắn I/O với request lifecycle.  
**Ảnh hưởng production:** Request bị hủy vẫn dùng tài nguyên; partial side effect không được theo dõi.  
**Cách sửa:** Truyền token và quản lý operation state; cancellation không có nghĩa rollback.

### [Medium] — Không có idempotency contract

**Vấn đề:** Client retry có thể tạo nhiều document records.  
**Tại sao xảy ra:** Không có unique operation key.  
**Ảnh hưởng production:** Duplicate, khó reconcile.  
**Cách sửa:** Unique idempotency key scoped theo user/project và payload fingerprint; replay kết quả cũ khi cùng request.

### [Medium] — Identity, metadata và logs chưa an toàn

**Vấn đề:** `Identity.Name!` có thể null, filename có thể chứa ký tự bất thường, response lộ storage key.  
**Tại sao xảy ra:** Giả định claims và client input luôn hợp lệ.  
**Ảnh hưởng production:** 500, log injection/unsafe rendering downstream, lộ storage layout.  
**Cách sửa:** Dùng stable subject claim, normalize display name, không trả raw blob key.

### [Medium] — Thiếu telemetry theo giai đoạn

**Vấn đề:** Chỉ log happy path.  
**Tại sao xảy ra:** Không ghi operation ID, failure stage và orphan state.  
**Ảnh hưởng production:** Khó điều tra incident.  
**Cách sửa:** Structured logging, dependency tracing, pending-age metrics và reconciliation alerts.

## Phiên bản đề xuất

Đây là service-layer skeleton cho production: `IProjectAccess`, `IFileInspection` và `IUploadRepository` là contracts cần implement; repository phải bảo đảm unique idempotency key và trạng thái bền vững. Không giả định các abstraction này là built-in APIs.

```csharp
public sealed class UploadService
{
    private readonly IProjectAccess _access;
    private readonly IFileInspection _inspection;
    private readonly IUploadRepository _uploads;
    private readonly BlobContainerClient _container;

    public UploadService(IProjectAccess access, IFileInspection inspection,
        IUploadRepository uploads, BlobContainerClient container)
        => (_access, _inspection, _uploads, _container) =
            (access, inspection, uploads, container);

    public async Task<Guid> UploadAsync(
        string subject, Guid projectId, string operationKey,
        IFormFile file, CancellationToken ct)
    {
        if (!await _access.CanWriteAsync(subject, projectId, ct))
            throw new UnauthorizedAccessException();
        if (file is null || file.Length is <= 0 or > 52_428_800)
            throw new ArgumentException("Invalid file size");

        var operation = await _uploads.GetOrCreatePendingAsync(
            subject, projectId, operationKey, file.Length, ct);
        if (operation.IsReady) return operation.DocumentId;

        await using var stream = file.OpenReadStream();
        await _inspection.ValidateAsync(stream, file.FileName, ct);
        if (!stream.CanSeek)
            throw new InvalidOperationException("Rewindable stream required");
        stream.Position = 0;

        var blob = _container.GetBlobClient(
            $"{projectId:D}/{operation.DocumentId:N}");
        await blob.UploadAsync(stream,
            new Azure.Storage.Blobs.Models.BlobUploadOptions
            {
                Conditions = new Azure.Storage.Blobs.Models.BlobRequestConditions
                {
                    IfNoneMatch = Azure.ETag.All
                }
            }, ct);

        await _uploads.MarkReadyAsync(operation.DocumentId, ct);
        return operation.DocumentId;
    }
}
```

**Điều kiện để triển khai:** `GetOrCreatePendingAsync` phải có unique constraint, kiểm tra payload fingerprint và concurrency ownership; chỉ một worker được phép upload cùng operation. Khi conditional upload gặp existing blob, phải kiểm tra ownership/hash/state, không mặc nhiên báo lỗi vĩnh viễn. `MarkReadyAsync` thất bại thì giữ Pending để reconciliation xác minh blob rồi hoàn tất; không xóa ngay. Inspector phải đọc stream an toàn, có giới hạn và đưa file vào quarantine nếu cần scan async. Controller chuyển exceptions thành ProblemDetails đúng status, không lộ internal details. Cần cấu hình request/form limits riêng; sample không tự giải quyết multipart buffering.

## Giải thích thiết kế sau khi sửa

Authorization trước side effect, server-generated key tránh overwrite, Pending/Ready giúp recover sau ambiguous failure, conditional Blob write tránh thay thế dữ liệu. Streaming giảm memory copies nhưng không loại bỏ buffering upstream. Unique operation key bảo vệ retry; reconciliation giải quyết trạng thái không chắc chắn.

## Trade-offs

State machine và reconciliation tăng complexity nhưng cần khi consistency quan trọng. Direct upload bằng scoped SAS giảm tải App Service nhưng cần validation/quarantine sau upload. Nếu file nhỏ và concurrency thấp, streaming proxy đơn giản hơn. Malware scanning tăng latency và cost; chính sách phụ thuộc loại tài liệu và risk profile.

## Cách kiểm thử

1. **Security integration:** user không có project permission bị chặn trước khi tạo blob.
2. **Concurrency:** 20 requests cùng filename không overwrite; cùng idempotency key chỉ có một logical document.
3. **Failure injection:** SQL timeout trước/sau commit, Blob timeout sau upload; reconciliation không mất file.
4. **Load:** 50 MiB concurrent uploads; đo memory, GC, p95, throttling.
5. **Validation:** MIME giả, file vượt limit, filename độc hại, client disconnect.

## Quan sát trong production

Application Insights tracing theo `operationId` và `traceId`, dependency latency Blob/SQL, upload bytes, failure stage, p95/p99, memory/GC. Azure Monitor alert cho Pending quá SLA, orphan count và Blob throttling. Không log file content, secrets hoặc SAS tokens. Đối chiếu logs và DB trước khi kết luận root cause.

## Câu hỏi phỏng vấn mở rộng

1. Nếu SQL timeout sau commit, làm sao tránh cleanup xóa blob đang được DB tham chiếu?
2. Khi chuyển sang direct-to-Blob SAS, làm sao ngăn user đánh dấu file chưa scan là Ready?
3. Khi nào upload qua API vẫn phù hợp hơn direct upload?

import { ref, watch, onMounted } from 'vue'
type Product = { id: string; name: string; description: string }
const keyword = ref('')
const category = ref('all')
const products = ref<Product[]>([])
const selected = ref<Product | null>(null)
const loading = ref(false)
const error = ref('')
const token = ref(localStorage.getItem('access_token') ?? '')

async function search() {
  loading.value = true
  error.value = ''
  const url = '/api/products/search?q=' + keyword.value +
    '&category=' + category.value
  try {
    const response = await fetch(url, {

watch(category, search)

}

## Kết quả code review tham khảo

### [High] — XSS từ v-html

**Vấn đề:** Description được render như raw HTML.  
**Tại sao xảy ra:** `v-html` bỏ qua escaping của interpolation.  
**Ảnh hưởng production:** Nếu description không tin cậy, có nguy cơ script/markup injection.  
**Cách sửa:** Render `{{ p.description }}` nếu plain text; nếu rich text bắt buộc, sanitize theo allowlist và CSP defense-in-depth.

### [High] — Out-of-order response ghi đè kết quả mới

**Vấn đề:** Các request chạy đồng thời, request cũ có thể trả về sau.  
**Tại sao xảy ra:** Watch không hủy request cũ hay kiểm tra generation.  
**Ảnh hưởng production:** UI hiển thị dữ liệu sai filter.  
**Cách sửa:** AbortController + monotonically increasing generation; chỉ request hiện tại được cập nhật state.

### [High] — Token/session lifecycle không an toàn

**Vấn đề:** Token đọc một lần từ localStorage, không invalidate khi logout.  
**Tại sao xảy ra:** Component tự quản auth state.  
**Ảnh hưởng production:** Gửi token cũ sau logout, stale data và tăng ảnh hưởng nếu XSS xảy ra.  
**Cách sửa:** Central auth layer, session change invalidation, clear state, abort requests; cân nhắc BFF HttpOnly cookie với CSRF protection theo threat model.

### [Medium] — Không xử lý HTTP error

**Vấn đề:** `fetch` không throw cho HTTP 4xx/5xx.  
**Tại sao xảy ra:** Parse JSON và gán `body.items` không kiểm tra `response.ok`.  
**Ảnh hưởng production:** Lỗi 401 bị hiểu là thành công; UI sai.  
**Cách sửa:** Check status, validate response shape, xử lý 401 qua auth layer.

### [Medium] — URL encoding sai

**Vấn đề:** Nối trực tiếp query parameters.  
**Tại sao xảy ra:** Không dùng `URLSearchParams`.  
**Ảnh hưởng production:** Search sai với Unicode và reserved characters.  
**Cách sửa:** Encode bằng `URLSearchParams`.

### [Medium] — Quá nhiều request

**Vấn đề:** Mỗi keystroke gọi API.  
**Tại sao xảy ra:** Watch trực tiếp không debounce.  
**Ảnh hưởng production:** Backend load tăng, browser/network lãng phí.  
**Cách sửa:** Debounce và server rate limiting; abort không bảo đảm server ngừng xử lý.

### [Medium] — Loading và error state bị race

**Vấn đề:** `finally` của request cũ đặt loading false khi request mới đang chạy.  
**Tại sao xảy ra:** State chung không gắn request generation.  
**Ảnh hưởng production:** UX sai, error cũ che kết quả mới.  
**Cách sửa:** Chỉ active request được ghi loading/error.

### [Medium] — Không cleanup và selected stale

**Vấn đề:** Không abort khi unmount; selected giữ item từ filter cũ.  
**Tại sao xảy ra:** Thiếu lifecycle cleanup và reset selection.  
**Ảnh hưởng production:** Request thừa và hiển thị chi tiết không khớp.

## Phiên bản đề xuất

Giả định auth layer truyền `token` và `sessionKey` reactive, thay sessionKey khi logout/login. Backend vẫn phải enforce authorization; frontend không phải security boundary.

```vue
<script setup lang="ts">
import { ref, watch, onBeforeUnmount } from 'vue'
type Product = { id: string; name: string; description: string }
const props = defineProps<{ token: string; sessionKey: string }>()
const keyword = ref('')
const category = ref('all')
const products = ref<Product[]>([])
const selected = ref<Product | null>(null)
const loading = ref(false)
const error = ref('')
let timer: ReturnType<typeof setTimeout> | undefined
let controller: AbortController | undefined
let generation = 0

function invalidate() {
  generation++
  if (timer) clearTimeout(timer)
  controller?.abort()
  controller = undefined
}
watch(
  () => [keyword.value, category.value, props.token, props.sessionKey],
  () => {
    invalidate()
    products.value = []
    selected.value = null
    loading.value = false
    error.value = ''
    if (!props.token) return
    const current = generation
    timer = setTimeout(() => void search(current), 300)
  },
  { immediate: true }
)

async function search(current: number) {
  if (current !== generation || !props.token) return
  const abort = new AbortController()
  controller = abort
  loading.value = true
  const query = new URLSearchParams({
    q: keyword.value.trim(), category: category.value
  })
  try {
    const response = await fetch('/api/products/search?' + query, {
      headers: { Authorization: 'Bearer ' + props.token },
      signal: abort.signal
    })
    if (!response.ok) throw new Error('HTTP ' + response.status)
    const body: unknown = await response.json()
    if (!body || typeof body !== 'object' ||
        !('items' in body) || !Array.isArray(body.items))
      throw new Error('Invalid response')
    if (current === generation)
      products.value = body.items as Product[]
  } catch (e) {
    if (current === generation && !abort.signal.aborted)
      error.value = e instanceof Error ? e.message : 'Search failed'
  } finally {
    if (current === generation) {
      loading.value = false
      controller = undefined
    }
  }
}
onBeforeUnmount(invalidate)
</script>
<template>
  <input v-model="keyword" />
  <select v-model="category">
    <option value="all">All</option>
    <option value="books">Books</option>
    <option value="games">Games</option>
  </select>
  <p v-if="loading">Loading...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <ul>
    <li v-for="p in products" :key="p.id">
      <button @click="selected = p">{{ p.name }}</button>
      <div>{{ p.description }}</div>
    </li>
  </ul>
  <aside v-if="selected">{{ selected.name }}</aside>
</template>
```

**Giới hạn:** `as Product[]` chỉ kiểm tra array, chưa validate từng item; production nên dùng runtime schema validation nếu API không đáng tin. Token qua prop chỉ minh họa, không phải khuyến nghị kiến trúc auth chung. Auth layer phải đổi sessionKey ngay khi logout; lỗi 401 phải được xử lý tập trung, không retry vô hạn.

## Giải thích thiết kế sau khi sửa

Generation guard đảm bảo chỉ kết quả mới nhất được hiển thị kể cả khi abort không kịp. Debounce giảm số request, URLSearchParams giữ query đúng, interpolation escape HTML. Session change hủy request và xóa dữ liệu cũ. Backend tiếp tục kiểm tra quyền truy cập độc lập.

## Trade-offs

Debounce tăng latency nhỏ; AbortController không thay thế correctness guard. Dùng TanStack Query/Vue Query có thể giảm boilerplate nhưng vẫn cần auth-scoped cache key và clear cache khi logout. Sanitization rich HTML phức tạp hơn plain text và phải có chính sách rõ ràng.

## Cách kiểm thử

1. **Component concurrency:** hai response đảo thứ tự; UI chỉ hiển thị query mới.
2. **Security:** description chứa HTML nguy hiểm được render thành text.
3. **Auth:** logout trong khi request đang chạy; abort, clear state, không gửi token cũ.
4. **API failure:** 401, 500, malformed response, network failure; loading/error đúng.
5. **Playwright E2E:** gõ nhanh Unicode/`&`, đổi category; verify encoded URL, debounce và selection.

## Quan sát trong production

Browser network waterfall, frontend request generation/abort/stale-ignored metrics, HTTP status và request latency. Correlation ID liên kết Application Insights frontend/backend; backend đo p95/p99, query duration, authorization failures. Không log token hoặc search text nhạy cảm. Phân biệt frontend stale response với Elasticsearch indexing lag bằng timestamp/version của index và trace request.

## Câu hỏi phỏng vấn mở rộng

1. Khi dùng Vue Query, cache key và cache invalidation cần thay đổi thế nào sau logout?
2. Làm sao phân biệt Elasticsearch eventual consistency với out-of-order frontend responses?
3. Nếu CMS bắt buộc cung cấp rich HTML, bạn sẽ thiết kế sanitization và CSP ra sao?

## Kiến thức trọng tâm

1. Xác định trust boundary trước khi tạo side effect.
2. Thiết kế retry cùng idempotency và reconciliation.
3. Đo memory, GC, dependency latency trước khi tối ưu.
4. Cancellation không thay thế correctness guard.
5. Kiểm thử failure paths và telemetry cùng happy path.
