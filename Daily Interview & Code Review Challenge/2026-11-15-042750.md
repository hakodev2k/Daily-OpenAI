## Đoạn code cần review

```csharp
public sealed class ProductSyncWorker(
    IServiceScopeFactory scopes,
    HttpClient http,
    ILogger<ProductSyncWorker> log) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            using var scope = scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<CatalogDbContext>();
            var changed = await db.Products
                .Where(x => x.UpdatedAt > DateTime.UtcNow.AddMinutes(-2))
                .OrderBy(x => x.UpdatedAt)
                .Take(500)
                .ToListAsync(ct);

            foreach (var p in changed)
            {
                var json = JsonSerializer.Serialize(new
                {
                    id = p.Id, name = p.Name,
                    price = p.Price, active = p.IsActive
                });
                var response = await http.PutAsync(
                    $"products/_doc/{p.Id}",
                    new StringContent(json, Encoding.UTF8, "application/json"),
                    ct);
                if (!response.IsSuccessStatusCode)
                    log.LogWarning("Index failed {Id}", p.Id);
            }

            await Task.Delay(TimeSpan.FromSeconds(30), ct);
        }
    }
}
```

Giả định HttpClient đã được cấu hình BaseAddress và index mapping hợp lệ.

## Kết quả code review tham khảo

### [Critical] — Polling window bỏ sót thay đổi vĩnh viễn

**Vấn đề:** Lấy tối đa 500 bản ghi trong 2 phút gần nhất.  
**Tại sao xảy ra:** Backlog và downtime làm record cũ rơi khỏi window.  
**Ảnh hưởng production:** Search sai không tự hồi phục.  
**Cách sửa:** Ghi transactional outbox trong cùng transaction cập nhật Product, xử lý theo trạng thái chưa hoàn thành.

### [High] — Out-of-order updates

**Vấn đề:** Replica A có thể ghi version cũ sau replica B.  
**Tại sao xảy ra:** HTTP requests hoàn tất không theo thứ tự.  
**Ảnh hưởng production:** Giá bị rollback trong index.  
**Cách sửa:** Monotonic product version + Elasticsearch conditional/external version strategy phù hợp API version đang chạy.

### [High] — Retry không bền vững

**Vấn đề:** Non-2xx chỉ log; exception timeout thoát worker.  
**Tại sao xảy ra:** Không có retry state hoặc dead-letter handling.  
**Ảnh hưởng production:** Mất update và worker ngừng.  
**Cách sửa:** Durable retry có exponential backoff, jitter, bounded attempts và quarantine.

### [High] — Delete không được đồng bộ

**Vấn đề:** Hard-deleted product không còn trong query.  
**Tại sao xảy ra:** Không có tombstone/event xóa.  
**Ảnh hưởng production:** Ghost products trong search.  
**Cách sửa:** Outbox ProductDeleted, delete index theo version; định nghĩa chính sách soft-delete.

### [High] — Không bảo đảm atomicity của intent

**Vấn đề:** Product commit và tín hiệu index không cùng transaction.  
**Tại sao xảy ra:** Polling dựa trên UpdatedAt không phải durable event.  
**Ảnh hưởng production:** Commit thành công nhưng index không nhận thay đổi.  
**Cách sửa:** Product + Outbox commit cùng PostgreSQL transaction.

### [Medium] — Multiple replicas duplicate work

**Vấn đề:** Cả 4 workers scan cùng tập records.  
**Tại sao xảy ra:** Không claim/lease.  
**Ảnh hưởng production:** Traffic Elasticsearch bị nhân lên.  
**Cách sửa:** Claim outbox với transaction, lease expiry, PostgreSQL SKIP LOCKED và ownership check.

### [Medium] — Sequential indexing

**Vấn đề:** 500 HTTP calls nối tiếp.  
**Tại sao xảy ra:** Không batch.  
**Ảnh hưởng production:** Lag vượt 60 giây.  
**Cách sửa:** Bulk API, kiểm tra item-level failures, giới hạn batch/concurrency.

### [Medium] — Thiếu telemetry lag và drift

**Vấn đề:** Chỉ log product ID khi HTTP non-2xx.  
**Tại sao xảy ra:** Không theo dõi backlog, oldest event, retry, index version.  
**Ảnh hưởng production:** Không chứng minh được SLA.  
**Cách sửa:** Metrics, tracing, alerts và reconciliation job.

### [Low] — EF tracking không cần thiết

**Vấn đề:** Load tracked entities chỉ để đọc.  
**Tại sao xảy ra:** Không dùng AsNoTracking/projection.  
**Ảnh hưởng production:** Tăng allocations.  
**Cách sửa:** Projection DTO hoặc đọc outbox trực tiếp.

## Phiên bản đề xuất

Mẫu thiết kế C# dưới đây minh họa orchestration; các interface cần implementation và integration tests, không giả định đây là code chạy độc lập.

```csharp
// Trong transaction cập nhật Product:
await using var tx = await db.Database.BeginTransactionAsync(ct);
product.Price = newPrice;
product.Version++;
db.Outbox.Add(new OutboxEvent {
    Id = Guid.NewGuid(),
    ProductId = product.Id,
    Version = product.Version,
    Type = "ProductUpsert",
    Payload = JsonSerializer.Serialize(new {
        product.Id, product.Name, product.Price, product.IsActive
    })
});
await db.SaveChangesAsync(ct);
await tx.CommitAsync(ct);

// Worker: claim bền vững với lease expiry, xử lý at-least-once.
var batch = await outbox.ClaimAsync(100, ct);
foreach (var evt in batch)
{
    try
    {
        await indexer.ApplyWithVersionGuardAsync(evt, ct);
        await outbox.CompleteIfLeaseOwnedAsync(evt.Id, ct);
    }
    catch (Exception ex) when (!ct.IsCancellationRequested)
    {
        await outbox.ScheduleRetryAsync(evt.Id, ex, ct);
    }
}
```

`ClaimAsync` phải dùng transaction và tránh double-claim; lease hết hạn phải được reclaim. `ApplyWithVersionGuardAsync` phải ngăn event version cũ ghi đè version mới; timeout có thể đã apply nên retry phải idempotent. Cần event xóa, bounded retry, poison handling và periodic full reconciliation.

## Giải thích thiết kế sau khi sửa

Outbox lưu intent cùng transaction, consumer xử lý at-least-once, version guard bảo vệ ordering. Search vẫn eventual consistency. Với tải nhỏ, một worker và PostgreSQL outbox là đủ; không tự động cần microservices hay Kafka.

## Trade-offs

Outbox tăng DB writes, cleanup và operational complexity. Bulk indexing nhanh nhưng khó xử lý lỗi từng item. Versioning cần tương thích Elasticsearch API. Reconciliation tốn tài nguyên nhưng khắc phục drift lâu dài.

## Cách kiểm thử

1. Integration: rollback Product transaction cũng rollback outbox.
2. Concurrency: 2 workers claim cùng event, không double-apply sai.
3. Failure-path: timeout sau khi index đã ghi; retry không rollback version.
4. Load: burst 10.000 updates, đo p95 lag và drain time.
5. Recovery: Elasticsearch outage 10 phút, restart và verify toàn bộ updates/deletes.

## Quan sát trong production

Application Insights/Kibana: outbox pending, oldest pending age, index lag p95/p99, bulk item failures, Elasticsearch 429/5xx, retry count, PostgreSQL locks, lease expiries, index drift. Alert khi oldest age vượt 60 giây theo SLO và khi backlog tăng liên tục. Correlate Product update với event ID.

## Câu hỏi phỏng vấn mở rộng

1. Rebuild index toàn phần khi writes vẫn tiếp diễn như thế nào?
2. Khi nào có thể coalesce nhiều ProductUpdated events?
3. Khi nào polling UpdatedAt vẫn đủ an toàn và rẻ hơn outbox?

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch } from "vue";

type Hit = { id: string; title: string; snippetHtml: string; url: string };
const query = ref("");
const hits = ref<Hit[]>([]);
const loading = ref(false);
const error = ref("");

watch(query, async value => {
  if (!value.trim()) {
    hits.value = [];
    return;
  }
  loading.value = true;
  error.value = "";
  try {
    const response = await fetch("/api/search?q=" + value, {
      credentials: "include"
    });
    const payload = await response.json();
    hits.value = payload.items;
  } catch (e) {
    error.value = String(e);
  } finally {
    loading.value = false;
  }
});
</script>

<template>
  <section>
    <label for="search">Search</label>
    <input id="search" v-model="query" />
    <p v-if="loading">Loading...</p>
    <p v-if="error">{{ error }}</p>
    <ul>
      <li v-for="hit in hits" :key="hit.id">
        <a :href="hit.url">{{ hit.title }}</a>
        <div v-html="hit.snippetHtml"></div>
      </li>
    </ul>
  </section>
</template>
```

## Kết quả code review tham khảo

### [Critical] — XSS qua v-html

**Tại sao xảy ra:** `v-html` không escape như interpolation.

### [High] — URL không được kiểm soát

**Vấn đề:** Bind href trực tiếp từ API.  
**Tại sao xảy ra:** Không validate protocol/origin.  
**Ảnh hưởng production:** Phishing hoặc URL nguy hiểm.  
**Cách sửa:** Parse URL, allowlist http/https và origin phù hợp business.

### [High] — Async race

**Vấn đề:** Request cũ overwrite kết quả mới.  
**Tại sao xảy ra:** Watch callbacks chạy async độc lập.  
**Ảnh hưởng production:** Search trả sai query.

**Tại sao xảy ra:** Nối URL thô.

## Phiên bản đề xuất

Hotfix dùng text-only snippet để tránh unsafe HTML; nếu cần highlight, thiết kế safe tokens hoặc dùng sanitizer được bảo trì. Code dưới đây dành cho client-rendered Vue 3.

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from "vue";
type Hit = { id: string; title: string; snippetHtml: string; url: string };
const query = ref("");
const hits = ref<Hit[]>([]);
const loading = ref(false);
const error = ref("");
let generation = 0;
let controller: AbortController | undefined;
let timer: ReturnType<typeof setTimeout> | undefined;

function safeUrl(raw: string): string | null {
  try {
    const u = new URL(raw, window.location.origin);
    return u.origin === window.location.origin &&
      ["http:", "https:"].includes(u.protocol) ? u.href : null;
  } catch { return null; }
}
function plainText(html: string): string {
  return new DOMParser().parseFromString(html, "text/html")
    .body.textContent ?? "";
}
watch(query, value => {
  const id = ++generation;
  controller?.abort();
  clearTimeout(timer);
  hits.value = [];
  loading.value = false;
  error.value = "";
  if (!value.trim()) return;

  timer = setTimeout(async () => {
    const current = new AbortController();
    controller = current;
    loading.value = true;
    try {
      const qs = new URLSearchParams({ q: value.trim() });
      const res = await fetch("/api/search?" + qs, {
        credentials: "include", signal: current.signal
      });
      if (!res.ok) throw new Error("HTTP failure");
      const data: unknown = await res.json();
      if (!data || typeof data !== "object" ||
          !("items" in data) || !Array.isArray(data.items))
        throw new Error("Invalid response");
      if (id !== generation) return;
      hits.value = data.items.filter((x: unknown): x is Hit =>
        !!x && typeof x === "object" &&
        ["id", "title", "snippetHtml", "url"].every(k =>
          typeof (x as Record<string, unknown>)[k] === "string"));
    } catch {
      if (id === generation && !current.signal.aborted)
        error.value = "Không thể tải kết quả. Vui lòng thử lại.";
    } finally {
      if (id === generation) loading.value = false;
    }
  }, 250);
});
onUnmounted(() => {
  generation++;
  controller?.abort();
  clearTimeout(timer);
});
</script>
<template>
  <section>
    <label for="search">Search</label>
    <input id="search" v-model="query" />
    <p v-if="loading">Loading...</p>
    <p v-if="error" role="alert">{{ error }}</p>
    <ul>
      <li v-for="hit in hits" :key="hit.id">
        <a v-if="safeUrl(hit.url)" :href="safeUrl(hit.url)!">{{ hit.title }}</a>
        <span v-else>{{ hit.title }}</span>
        <div>{{ plainText(hit.snippetHtml) }}</div>
      </li>
    </ul>
  </section>
</template>
```

DOMParser ở đây chỉ trích xuất text để interpolation escape, **không phải sanitizer**. Nếu SSR, chuyển sang server-side text extraction. Client validation không thay thế server authorization.

## Giải thích thiết kế sau khi sửa

Generation ID ngăn stale state ngay cả khi abort không kịp. Debounce giảm tải; response.ok và schema check tránh success giả. URL allowlist giới hạn navigation. Render text an toàn hơn v-html.

## Trade-offs

Bỏ HTML highlight làm mất format. Debounce tăng latency cảm nhận. Same-origin allowlist có thể chặn external links hợp lệ; cần xác nhận requirement. Abort không đảm bảo server đã ngừng xử lý.

## Cách kiểm thử

1. Playwright E2E: response `a` chậm hơn `abc`, cuối cùng chỉ có `abc`.
2. Security: malicious HTML và javascript URL không thực thi/không clickable.
3. Failure-path: 500, malformed JSON, abort, empty query; spinner chính xác.
4. Load/browser: gõ 20 ký tự, kiểm tra request count và cleanup.
5. Integration: `&`, `#`, Unicode được encode đúng.

## Quan sát trong production

Theo dõi API p95/p99, 4xx/5xx, requests per session, frontend errors, stale response drops, search-to-result latency và browser network waterfall. Correlate browser request ID với Application Insights; không log raw query nhạy cảm.
