# Code Review Challenge 1 — Import CSV chạy lại sau timeout làm sai số tồn kho

**Chủ đề:** C#/.NET 8, ASP.NET Core, SQL Server, Azure Blob Storage, idempotency, batch processing  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 30–40 phút  
**Số vấn đề cần tìm:** khoảng 7–9

## Bối cảnh

Hệ thống quản lý kho nhận file CSV từ đối tác qua Blob Storage. Mỗi dòng chứa SKU và số lượng tồn kho tuyệt đối (không phải delta). API được gọi sau khi upload; phía đối tác có thể retry khi timeout. Ứng dụng chạy ba instance trên Azure App Service; mỗi file 200.000 dòng. Yêu cầu: cùng một file không được áp dụng nhiều lần, dữ liệu cuối cùng phải nhất quán, lỗi một dòng phải được báo rõ. Production có hiện tượng tồn kho cũ ghi đè tồn kho mới, SQL CPU tăng đột biến và request timeout. Chưa biết liệu các file cùng SKU có thứ tự phiên bản hay không.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/imports")]
public sealed class StockImportController(
    WarehouseDbContext db,
    BlobServiceClient blobs,
    ILogger<StockImportController> logger) : ControllerBase
{
    [HttpPost("{blobName}")]
    public async Task<IActionResult> Import(string blobName)
    {
        var blob = blobs.GetBlobContainerClient("imports")
                        .GetBlobClient(blobName);
        var response = await blob.DownloadStreamingAsync();
        using var reader = new StreamReader(response.Value.Content);
        var changed = 0;

        while (!reader.EndOfStream)
        {
            var line = await reader.ReadLineAsync();
            if (string.IsNullOrWhiteSpace(line)) continue;

            var columns = line.Split(',');
            var sku = columns[0].Trim();
            var quantity = int.Parse(columns[1]);

            var item = await db.StockItems
                .FirstOrDefaultAsync(x => x.Sku == sku);

            if (item == null)
            {
                db.StockItems.Add(new StockItem
                {
                    Sku = sku,
                    Quantity = quantity
                });
            }
            else
            {
                item.Quantity = quantity;
            }

            await db.SaveChangesAsync();
            changed++;
        }

        logger.LogInformation("Imported {Count} rows from {Blob}",
            changed, blobName);
        return Ok(new { changed });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — File cũ có thể ghi đè phiên bản mới

**Vấn đề:** Mỗi dòng cập nhật quantity không kiểm tra revision hoặc event time.

**Tại sao xảy ra:** Hai file cùng SKU được xử lý không theo thứ tự nghiệp vụ; last writer wins theo thời điểm SQL commit.

**Ảnh hưởng production:** Tồn kho cuối cùng sai dù mọi request đều trả 200.

**Cách sửa:** Thỏa thuận với đối tác về monotonically increasing source version hoặc sequence per SKU; cập nhật có điều kiện `WHERE SourceVersion < @version`. Nếu không có thứ tự đáng tin cậy, phải làm rõ business rule trước khi cam kết tính đúng.

### [High] — Retry không có idempotency và job checkpoint

**Vấn đề:** Không có import identity, trạng thái processing/completed hoặc unique key.

**Tại sao xảy ra:** HTTP timeout không chứng minh xử lý thất bại; retry có thể chạy đồng thời với request gốc.

**Ảnh hưởng production:** Tăng tải, chạy trùng, số lượng xử lý báo sai và khó truy vết.

**Cách sửa:** Dùng `ImportId` do đối tác cung cấp hoặc identity gắn với immutable blob version/ETag và source; unique constraint, trạng thái job, lease có thời hạn và resumable worker. Cùng identity nhưng nội dung khác phải reject.

### [High] — Không có atomicity hay checkpoint cho từng batch

**Vấn đề:** `SaveChangesAsync` từng dòng; lỗi giữa file để lại prefix đã commit.

**Tại sao xảy ra:** Mỗi lần SaveChanges là một transaction riêng khi không có transaction bao ngoài.

**Ảnh hưởng production:** Import partial không được phân biệt với completed; rollback khó.

**Cách sửa:** Parse và validate toàn bộ trước khi publish, staging table theo ImportId; transaction ngắn cho bước merge/publish hoặc chunk có checkpoint với business semantics được thống nhất.

### [High] — Race condition khi insert SKU mới

**Vấn đề:** `FirstOrDefaultAsync` rồi `Add` không atomic.

**Tại sao xảy ra:** Hai request có thể cùng quan sát row chưa tồn tại.

**Ảnh hưởng production:** Duplicate SKU nếu thiếu unique constraint, hoặc một request thất bại với unique violation.

**Cách sửa:** Unique index trên SKU; upsert có điều kiện và transaction/locking phù hợp SQL Server, xử lý conflict rõ ràng.

### [Medium] — Round trip và tracking tăng theo số dòng

**Vấn đề:** SELECT + SaveChanges cho từng dòng; DbContext theo request tích lũy tracked entities.

**Tại sao xảy ra:** N+1 database round trips, change tracker lớn, request dài.

**Ảnh hưởng production:** CPU SQL tăng, memory pressure, p95/p99 timeout.

**Cách sửa:** Streaming parse vào staging, bulk copy/batch writes; giới hạn kích thước batch, đo execution plan và wait stats.

### [Medium] — Parsing CSV không đúng định dạng thực tế

**Vấn đề:** `Split(',')`, `int.Parse` không hỗ trợ quoted field, header, duplicate SKU, invalid quantity.

**Tại sao xảy ra:** Giả định input sạch và cấu trúc đơn giản.

**Ảnh hưởng production:** Import dừng giữa chừng hoặc đọc sai cột.

**Cách sửa:** CSV parser chuẩn, schema validation, invariant culture, row-level errors, giới hạn kích thước, quy tắc duplicate rõ ràng.

### [Medium] — Không truyền CancellationToken, không kiểm soát timeout

**Vấn đề:** I/O và EF calls không nhận `RequestAborted`; xử lý gắn chặt request.

**Tại sao xảy ra:** Import lớn được thực hiện trực tiếp trong HTTP pipeline.

**Ảnh hưởng production:** Request timeout, instance recycle gây dừng giữa chừng.

**Cách sửa:** API chỉ đăng ký job và trả 202 Accepted; worker xử lý durable queue, checkpoint và cancellation khi shutdown.

### [Medium] — Blob identity và quyền truy cập chưa được ràng buộc

**Vấn đề:** `blobName` lấy trực tiếp từ route, không chứng minh file thuộc đối tác đang gọi.

**Tại sao xảy ra:** Chưa thấy authorization theo tenant/import và immutable blob reference.

**Ảnh hưởng production:** Có nguy cơ import nhầm hoặc đọc dữ liệu của tenant khác nếu endpoint thiếu policy.

**Cách sửa:** Authenticate/authorize caller; resolve blob qua record sở hữu tenant, validate ETag/version và giới hạn file.

## Phiên bản đề xuất

API chỉ tạo job bền vững; worker parse vào staging rồi publish theo version. Đoạn dưới là **skeleton kiến trúc**, không phải triển khai đầy đủ SQL bulk/transaction. Database phải có unique index `(TenantId, ImportId)`, `(TenantId, Sku)` và version check ở câu lệnh SQL atomic.

```csharp
public sealed record StartImport(
    Guid ImportId, string BlobKey, string ExpectedETag);

[Authorize(Policy = "WarehouseImporter")]
[ApiController]
[Route("api/stock-imports")]
public sealed class ImportsController(IImportJobs jobs) : ControllerBase
{
    [HttpPost]
    public async Task<IActionResult> Start(
        StartImport request, CancellationToken ct)
    {
        var tenantId = User.FindFirst("tenant_id")?.Value;
        if (string.IsNullOrWhiteSpace(tenantId))
            return Forbid();

        var result = await jobs.CreateOrGetAsync(
            tenantId, request.ImportId,
            request.BlobKey, request.ExpectedETag, ct);

        if (result.IdentityConflict)
            return Conflict("ImportId already belongs to different content");

        return AcceptedAtAction(nameof(Get), new { id = request.ImportId },
            new { id = request.ImportId, status = result.Status });
    }

    [HttpGet("{id:guid}")]
    public async Task<IActionResult> Get(Guid id, CancellationToken ct)
    {
        var tenantId = User.FindFirst("tenant_id")?.Value;
        if (string.IsNullOrWhiteSpace(tenantId))
            return Forbid();

        var job = await jobs.GetAsync(tenantId, id, ct);
        return job is null ? NotFound() : Ok(job);
    }
}

public sealed class ImportWorker(
    IImportJobs jobs, IStockStaging staging,
    IStockPublisher publisher)
{
    public async Task ProcessAsync(Guid importId, CancellationToken ct)
    {
        // Acquire lease atomically; reject concurrent ownership.
        var lease = await jobs.TryAcquireLeaseAsync(importId, ct);
        if (lease is null) return;

        await using (lease)
        {
            // Validate immutable blob ETag and parse into bounded batches.
            await staging.LoadAndValidateAsync(lease, ct);

            // Atomic publish: unique SKU and conditional source version.
            await publisher.PublishStagedAsync(lease, ct);

            // Completion must be recorded consistently with publish,
            // or recoverable by a deterministic reconciliation step.
            await jobs.MarkCompletedAsync(lease, ct);
        }
    }
}
```

**Ràng buộc triển khai:** `CreateOrGetAsync` cần ghi job và outbox trong cùng database transaction nếu dispatch qua queue; dispatcher gửi at-least-once, worker xử lý idempotently. `PublishStagedAsync` cần transaction bảo đảm staging merge và trạng thái published không bị lệch; nếu `MarkCompletedAsync` tách transaction, phải hỗ trợ reconciliation. Lease hết hạn phải có fencing token để worker cũ không tiếp tục publish. Nếu dữ liệu không cho phép atomic publish toàn file, phải công bố rõ semantics partial progress.

## Giải thích thiết kế sau khi sửa

HTTP trở thành control plane; worker là data plane. Import identity và blob ETag bảo vệ replay/TOCTOU. Staging tách validation khỏi cập nhật live data. SQL constraint và conditional update mới là điểm thực thi correctness; distributed lock chỉ hỗ trợ điều phối, không thay thế constraint.

## Trade-offs

Staging và durable job tăng storage, schema và vận hành; đổi lại retry/recovery quan sát được. Transaction toàn bộ merge bảo đảm atomic visibility nhưng có thể tạo lock contention; cân nhắc partition/chunk với semantics được business chấp thuận. Không thể tự suy ra thứ tự file nếu upstream không cung cấp revision đáng tin cậy.

## Cách kiểm thử

1. **Concurrency:** Hai job cùng ImportId chạy trên hai worker; chỉ một owner hợp lệ, không double publish.
2. **Ordering:** File version 12 hoàn thành trước version 11; version 11 không được ghi đè.
3. **Failure-path:** Kill worker sau staging, giữa merge và trước completion; retry cho kết quả duy nhất.
4. **Database/load:** 200.000 dòng với 10% duplicate SKU; đo duration, locks, log growth, CPU, memory.
5. **Security/input:** Tenant khác tham chiếu BlobKey; ETag mismatch, CSV malformed, quantity âm hoặc overflow đều bị từ chối đúng.

## Quan sát trong production

Structured logs theo `ImportId`, `TenantId`, blob ETag, worker lease/fencing token; không log nội dung file. Metrics: queued/running/failed/completed jobs, age of oldest job, rows validated/rejected, SQL batch duration, deadlocks, CPU, log growth, retry count, version-conflict count. Trace từ API → outbox → worker → SQL; alert khi job stuck hoặc duplicate claim tăng.

## Câu hỏi phỏng vấn mở rộng

1. Nếu upstream chỉ cung cấp timestamp với clock skew, bạn xác định thứ tự cập nhật ra sao?
2. Nếu một file cần thay đổi 5 triệu SKU và không thể khóa bảng lâu, bạn chọn consistency contract nào?
3. Làm sao reconcile khi database commit thành công nhưng worker chết trước khi ack queue?

## Đoạn code cần review

```csharp
[ApiController]
[Route("content")]
public sealed class ContentController(
    IContentRepository repository,
    IContentLoader loader) : ControllerBase
{
    [HttpGet("{id:int}")]
    public IActionResult Get(int id, [FromQuery] bool preview = false)
    {
        var reference = new ContentReference(id);
        var content = loader.Get<IContent>(reference);

        if (preview)
        {
            var draft = repository.GetLanguageBranches<IContent>(
                reference).FirstOrDefault();
            if (draft != null) content = draft;
        }

        Response.Headers.CacheControl = "public,max-age=3600";
        Response.Headers.ETag = $"\"content-{id}\"";

        return Ok(new
        {
            id,
            title = content.Name,
            html = (content as ArticlePage)?.MainBody?.ToHtmlString(),
            updated = content.Saved
        });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Preview không được authorization

**Vấn đề:** Bất kỳ caller nào đặt `preview=true` đều có thể kích hoạt đường lấy branch khác.

**Tại sao xảy ra:** Boolean query parameter được dùng như quyền truy cập.

**Ảnh hưởng production:** Có thể lộ nội dung chưa public, tùy version/branch thực tế được repository trả về.

**Cách sửa:** Tách preview route với policy editor; kiểm tra quyền content cụ thể bằng CMS authorization service; không dựa vào query flag.

### [Critical] — Shared cache có thể lưu response preview

**Vấn đề:** Mọi response đều có `public,max-age=3600`.

**Tại sao xảy ra:** Shared caches được phép lưu public response; cấu hình Akamai chưa được kiểm chứng.

**Ảnh hưởng production:** Draft có thể được phục vụ cho anonymous users nếu cache key/caching rules gộp biến thể.

**Cách sửa:** Preview trả `Cache-Control: private, no-store`, chặn edge caching theo route; public endpoint chỉ phục vụ published content. Kiểm tra Akamai property rules thực tế.

### [High] — ETag không đổi khi content đổi

**Vấn đề:** ETag chỉ phụ thuộc ID.

**Tại sao xảy ra:** Không đưa published version, locale hoặc representation vào validator.

**Ảnh hưởng production:** Cache revalidation có thể sai nếu origin/CDN dùng validator này để quyết định 304.

**Cách sửa:** Sinh ETag từ published revision + language + representation, hoặc bỏ ETag nếu chưa có cơ chế conditional request đúng.

### [High] — Không xác định language và published version

**Vấn đề:** `GetLanguageBranches().FirstOrDefault()` không chọn theo culture và publish state.

**Tại sao xảy ra:** Thứ tự enumeration không phải business contract.

**Ảnh hưởng production:** Trả sai ngôn ngữ hoặc version; SEO metadata và canonical mismatch.

**Cách sửa:** Resolve locale từ route; dùng CMS APIs phù hợp để lấy published content, preview context được authorization riêng.

### [Medium] — Cache invalidation sau publish thiếu thiết kế

**Vấn đề:** TTL cố định 3600 giây, không có publish-triggered purge.

**Tại sao xảy ra:** Cache lifecycle không gắn CMS events.

**Ảnh hưởng production:** Nội dung đã publish chậm hiển thị, crawler thấy bản cũ.

**Cách sửa:** Purge theo content URL/surrogate key khi publish, có retry và reconciliation; TTL ngắn hơn nếu SLA cần.

### [Medium] — HTML body được xuất trực tiếp không có trust contract

**Vấn đề:** `ToHtmlString()` được trả cho frontend mà không xác định rendering/sanitization policy.

**Tại sao xảy ra:** CMS rich text có thể chứa HTML, frontend có thể render bằng `innerHTML`.

**Ảnh hưởng production:** XSS nếu editor/input hoặc integration không đáng tin và pipeline thiếu sanitization/CSP.

**Cách sửa:** Xác định trusted editor/content policy, sanitize theo allowlist khi cần, tránh arbitrary HTML injection, bổ sung CSP defense-in-depth.

### [Medium] — Không xử lý content missing/unauthorized

**Vấn đề:** `loader.Get` có thể throw khi content không tồn tại hoặc không truy cập được.

**Tại sao xảy ra:** Không phân biệt not found, unpublished và forbidden.

**Ảnh hưởng production:** 500 không cần thiết, error logs nhiễu, SEO crawl errors.

**Cách sửa:** Dùng TryGet hoặc exception mapping phù hợp, trả 404/403 theo policy tránh information disclosure.

## Phiên bản đề xuất

Ví dụ sau là **application-level design sketch**: `IPublishedContentReader` và `IPreviewContentReader` là abstractions tự định nghĩa, không phải tên API chính thức của Optimizely. Implementations phải áp dụng CMS version/language/permission APIs tương ứng phiên bản đang dùng.

```csharp
public sealed record ArticleDto(
    int Id, string Locale, string Title,
    string Html, string Revision);

[ApiController]
[Route("content")]
public sealed class SafeContentController(
    IPublishedContentReader published,
    IPreviewContentReader previews) : ControllerBase
{
    [HttpGet("{locale}/{id:int}")]
    [AllowAnonymous]
    public async Task<IActionResult> Public(
        string locale, int id, CancellationToken ct)
    {
        var article = await published.TryGetAsync(locale, id, ct);
        if (article is null) return NotFound();

        Response.Headers.CacheControl = "public,max-age=60,s-maxage=300";
        Response.Headers.ETag =
            $"\"{article.Id}-{article.Locale}-{article.Revision}\"";
        return Ok(article);
    }

    [HttpGet("preview/{locale}/{id:int}")]
    [Authorize(Policy = "CmsEditor")]
    public async Task<IActionResult> Preview(
        string locale, int id, CancellationToken ct)
    {
        Response.Headers.CacheControl = "private,no-store";
        Response.Headers.Pragma = "no-cache";

        var article = await previews.TryGetAuthorizedAsync(
            User, locale, id, ct);
        if (article is null) return NotFound();

        return Ok(article);
    }
}
```

**Bắt buộc ở hạ tầng:** Akamai phải bypass caching hoàn toàn cho `/content/preview/*` và không phục vụ stale preview; origin auth vẫn bắt buộc. Public cache key cần bao gồm locale và các representation dimensions thực sự ảnh hưởng output. Nếu implement conditional requests, chỉ trả 304 sau khi kiểm tra `If-None-Match` đúng. Publish hook enqueue purge có durable retry và ghi nhận kết quả; cần purge cả canonical/alternate URLs bị ảnh hưởng.

## Giải thích thiết kế sau khi sửa

Public và preview là hai trust zones khác nhau. Published reader trả đúng phiên bản public; preview reader kiểm tra quyền theo content. Edge cache là tối ưu hóa trên dữ liệu public, không phải lớp authorization. ETag và purge được gắn với revision để cache không trở thành nguồn sự thật sai.

## Trade-offs

TTL thấp tăng origin load; TTL cao cần purge đáng tin. Purge toàn site dễ triển khai nhưng gây cache miss storm; surrogate keys chính xác hơn nhưng cần quản lý mapping. Preview bypass cache làm tăng latency cho editor nhưng giảm rủi ro lộ draft. CSP/sanitization có thể ảnh hưởng các embedded components hợp lệ, cần kiểm thử editorial workflows.

## Cách kiểm thử

1. **Security:** Anonymous gọi preview với mọi query/cookie; không nhận draft, CDN không lưu response.
2. **Integration:** Editor được phép và không được phép xem content theo từng locale/branch.
3. **CDN:** Publish revision mới, verify cache purge và ETag thay đổi; test origin và edge độc lập.
4. **E2E/SEO:** Playwright kiểm tra canonical, locale, content và không lộ preview trong anonymous session.
5. **Failure-path:** Purge API thất bại; job retry và reconciliation khôi phục freshness trong SLA.

## Quan sát trong production

Log `contentId`, locale, revision, route class (public/preview), correlation ID; không log draft body hoặc token. Theo dõi Akamai cache status, Age, cache hit ratio, purge latency/failures, origin p95, 404/403/500, publish-to-visible latency. Dashboard so sánh revision tại CMS, origin và edge; alert khi preview response có public cache headers hoặc purge backlog tăng.

## Câu hỏi phỏng vấn mở rộng

1. Nếu public page cá nhân hóa theo region nhưng CDN chỉ cache theo URL, bạn thiết kế cache variation ra sao?
2. Khi purge service ngừng 30 phút, giải pháp giảm stale content mà không làm sập origin là gì?
3. Bạn sẽ chọn headless CMS hay server-rendered CMS theo tiêu chí nào nếu SEO và editor preview là yêu cầu trọng tâm?

- Durable import cần identity, ordering, SQL constraints, checkpoint và reconciliation; HTTP retry không phải transaction rollback.
