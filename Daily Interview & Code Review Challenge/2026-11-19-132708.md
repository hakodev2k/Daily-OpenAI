## Đoạn code cần review

```csharp
public sealed class ProductIndexer(
    IServiceScopeFactory scopes,
    ISearchClient search,
    ILogger<ProductIndexer> logger) : BackgroundService
{
    private static DateTime _lastRun = DateTime.UtcNow.AddMinutes(-5);

    protected override async Task ExecuteAsync(CancellationToken stoppingToken)
    {
        while (!stoppingToken.IsCancellationRequested)
        {
            try { await RunAsync(stoppingToken); }
            catch (Exception ex) { logger.LogError(ex, "Index failed"); }
            await Task.Delay(TimeSpan.FromMinutes(5), stoppingToken);
        }
    }

    private async Task RunAsync(CancellationToken ct)
    {
        using var scope = scopes.CreateScope();
        var db = scope.ServiceProvider.GetRequiredService<CatalogDbContext>();
        var to = DateTime.UtcNow;
        var products = await db.Products
            .Where(p => p.UpdatedAtUtc > _lastRun &&
                        p.UpdatedAtUtc <= to)
            .OrderBy(p => p.UpdatedAtUtc)
            .Take(10000).ToListAsync(ct);

        var docs = products.Select(p => new SearchProduct
        {
            Id = p.Id.ToString(),
            Name = p.Name,
            Price = p.Price,
            IsPublished = p.IsPublished
        }).ToArray();

        await search.IndexManyAsync(docs, ct);
        _lastRun = to;
        logger.LogInformation("Indexed {Count}", docs.Length);
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Checkpoint nhảy qua dữ liệu chưa xử lý

**Vấn đề:** `Take(10000)` rồi cập nhật `_lastRun = to`.  
**Tại sao xảy ra:** Các rows vượt giới hạn không bao giờ được đọc lại nếu không có thay đổi mới.  
**Ảnh hưởng production:** Search mất hàng nghìn cập nhật âm thầm.  
**Cách sửa:** Durable outbox/CDC offset, hoặc keyset pagination với watermark và snapshot semantics được chứng minh; chỉ acknowledge khi đã xử lý thành công.

### [Critical] — Ghi đè phiên bản mới bằng dữ liệu cũ

**Vấn đề:** Multi-replica index cùng document không có version/ordering.  
**Tại sao xảy ra:** Thứ tự hoàn tất network khác thứ tự thay đổi nguồn.  
**Ảnh hưởng production:** Giá hoặc publication status bị đảo ngược.  
**Cách sửa:** Monotonic source version và version-aware writes; hoặc ordered consumer theo product key. Kiểm tra semantics của Elasticsearch external versioning và delete tombstones.

### [High] — Checkpoint static theo process

**Vấn đề:** Cursor không bền vững và không chia sẻ giữa replicas.  
**Tại sao xảy ra:** Static chỉ tồn tại trong process.  
**Ảnh hưởng production:** Restart/redeploy gây duplicate và mất thay đổi ngoài cửa sổ.  
**Cách sửa:** Durable checkpoint, claim/lease atomic, idempotent processing.

### [High] — Bulk partial failure bị coi là thành công

**Vấn đề:** Chỉ xét wrapper success.  
**Tại sao xảy ra:** Bulk response có status từng item.  
**Ảnh hưởng production:** Một số document không được index nhưng checkpoint vẫn tiến.  
**Cách sửa:** Kiểm tra từng item, retry transient với backoff, quarantine permanent failures, không acknowledge sớm.

### [High] — Timestamp không phải commit sequence

**Vấn đề:** `UpdatedAtUtc` do ứng dụng gán không bảo đảm commit order.  
**Tại sao xảy ra:** Transaction commit trễ, clock skew hoặc timestamp trùng.  
**Ảnh hưởng production:** Bỏ sót rows ngay cả khi batch nhỏ.  
**Cách sửa:** Transactional outbox trong cùng SQL transaction, hoặc CDC/change tracking có retention phù hợp.

### [High] — Không xử lý hard-delete

**Vấn đề:** Record đã xóa không còn trong query.  
**Tại sao xảy ra:** Polling chỉ đọc rows tồn tại.  
**Ảnh hưởng production:** Sản phẩm đã xóa vẫn hiện trong search.  
**Cách sửa:** Tombstone/delete event, filter publication và xác minh trạng thái tại checkout.

### [Medium] — Tracking và materialization không cần thiết

**Vấn đề:** EF Core tracking toàn bộ entities, tạo thêm document array.  
**Tại sao xảy ra:** Query mặc định tracking.  
**Ảnh hưởng production:** Memory, GC, DB load tăng.  
**Cách sửa:** `AsNoTracking`, projection, batch theo payload và đo allocations.

### [Medium] — Polling và observability không đáp ứng SLA

**Vấn đề:** Delay 5 phút dù SLA 60 giây; log chỉ count.  
**Tại sao xảy ra:** Không đo end-to-end lag hoặc per-item failure.  
**Ảnh hưởng production:** Incident bị phát hiện muộn.  
**Cách sửa:** Event-driven/short polling được kiểm soát; alert lag, backlog và reconciliation mismatch.

## Phiên bản đề xuất

Thiết kế minh họa: transaction cập nhật Product cũng ghi `OutboxEvent(EventId, ProductId, Version, Operation, Payload)`. Version tăng đơn điệu theo từng product tại nguồn. Worker nhận batch **đã claim atomically**; claim/lease, retry budget và dead-letter do `IOutboxStore` triển khai, không giả định API có sẵn.

```csharp
public sealed class SearchOutboxProcessor(
    IOutboxStore store, ISearchClient search,
    ILogger<SearchOutboxProcessor> logger)
{
    public async Task ProcessAsync(
        IReadOnlyList<SearchOutboxEvent> claimed,
        CancellationToken ct)
    {
        foreach (var group in claimed.GroupBy(x => x.ProductId))
        {
            foreach (var evt in group.OrderBy(x => x.Version))
            {
                try
                {
                    var result = evt.Operation == "Delete"
                        ? await search.DeleteVersionedAsync(
                            evt.ProductId, evt.Version, ct)
                        : await search.UpsertVersionedAsync(
                            evt.ProductId, evt.Payload!,
                            evt.Version, ct);

                    if (result is SearchWriteResult.Success
                        or SearchWriteResult.AlreadySuperseded)
                    {
                        await store.MarkCompletedAsync(evt.EventId, ct);
                        continue;
                    }

                    await store.ReleaseForRetryAsync(evt.EventId, ct);
                    break;
                }
                catch (OperationCanceledException) when (ct.IsCancellationRequested)
                {
                    throw;
                }
                catch (Exception ex)
                {
                    logger.LogWarning(ex, "Failed {EventId}", evt.EventId);
                    await store.RecordFailureAsync(evt.EventId, ct);
                    break;
                }
            }
        }
    }
}
```

**Điều kiện correctness:** `UpsertVersionedAsync`/`DeleteVersionedAsync` phải bảo vệ khỏi out-of-order writes, phân biệt transient/permanent error; `MarkCompletedAsync` idempotent; store phải quản lý lease expiry, poison events và retry. Nếu delete tombstone hết hạn, cần reconciliation để không resurrect document. Thứ tự trong batch không đủ nếu hai workers xử lý cùng product; cần ordering hoặc version guard toàn cục.

## Giải thích thiết kế sau khi sửa

Transactional outbox bảo đảm business update và intent-to-index cùng commit; at-least-once processing cộng idempotency giải quyết retry. Reconciliation định kỳ phát hiện mismatch. Search là derived read model, không phải nguồn xác thực giá hoặc quyền bán.

## Trade-offs

Outbox tăng SQL writes và chi phí vận hành. Version-aware indexing cần kiểm chứng theo phiên bản Elasticsearch; per-key ordering có thể giới hạn throughput. CDC giảm thay đổi ứng dụng nhưng phụ thuộc retention và permission. Nếu SLA cho phép vài phút, single-worker với durable cursor có thể đơn giản hơn.

## Cách kiểm thử

1. Integration: 20.000 changes, restart sau 10.000, không mất events.
2. Concurrency: version 21 đến trước version 20, cuối cùng vẫn là 21.
3. Failure injection: bulk partial failure, timeout sau write, retry idempotent.
4. Database: transaction rollback không tạo outbox; commit xong worker chết vẫn replay được.
5. Reindex: delete/unpublish, alias swap và reconciliation không làm resurrect data.

## Quan sát trong production

Đo oldest outbox event age, backlog, index lag p95/p99, item failure rate, version conflicts, SQL waits, memory/GC, retry counts và reconciliation mismatches. Structured logs chứa EventId, ProductId, Version, trace ID nhưng không ghi payload nhạy cảm. Dùng Application Insights/Azure Monitor và Kibana để đối chiếu dependency failures, alert khi lag vượt 60 giây.

## Câu hỏi phỏng vấn mở rộng

1. Elasticsearch outage 6 giờ thì bảo vệ SQL và xử lý backlog ra sao?
2. Rebuild index bằng alias swap thế nào để không mất writes phát sinh giữa snapshot và cutover?
3. Khi một product có hot-key updates, chọn coalescing hay strict ordering theo tiêu chí nào?

<script setup lang="ts">
import { ref, watch, onMounted } from 'vue';

type Contact = {
  id: string;
  name: string;
  email: string;
  noteHtml: string;
};
const props = defineProps<{ tenantId: string }>();
const query = ref('');
const contacts = ref<Contact[]>([]);
const loading = ref(false);
const error = ref('');
const selected = ref<Contact | null>(null);

async function search() {
  loading.value = true;
  error.value = '';
  try {
    const url = '/api/contacts?tenant=' + props.tenantId
      + '&q=' + query.value;
    const response = await fetch(url, {

    contacts.value = await response.json();

    error.value = String(e);
  } finally {
    loading.value = false;
  }
}

watch(query, search);
onMounted(search);

function choose(contact: Contact) {
  selected.value = contact;
}
</script>

<template>
  <input v-model="query" placeholder="Tìm contact" />
  <p v-if="loading">Đang tìm...</p>
  <p v-if="error">{{ error }}</p>
  <ul>
    <li v-for="contact in contacts" :key="contact.id"
        @click="choose(contact)">
      <strong>{{ contact.name }}</strong>
      <span>{{ contact.email }}</span>
    </li>
  </ul>
  <article v-if="selected">
    <h3>{{ selected.name }}</h3>
    <div v-html="selected.noteHtml"></div>
  </article>
</template>

## Kết quả code review tham khảo

### [Critical] — XSS qua v-html

**Vấn đề:** Render untrusted `noteHtml` như HTML.  
**Tại sao xảy ra:** `v-html` không escape như `{{ text }}`.  
**Ảnh hưởng production:** Script injection trong origin CRM nếu attacker kiểm soát notes; CSP có thể giảm một số tác động.  
**Cách sửa:** Render plain text, hoặc sanitize theo allowlist nếu bắt buộc rich text; CSP là defense-in-depth.

### [High] — Stale response ghi đè query mới

**Vấn đề:** Request nào xong cũng cập nhật `contacts`.  
**Tại sao xảy ra:** Network completion không theo request order.  
**Ảnh hưởng production:** User chọn contact sai.  
**Cách sửa:** Abort + generation counter; debounce chỉ giảm request count.

### [High] — Đổi tenant không reset state

**Vấn đề:** Chỉ watch query; selected contact còn nguyên.  
**Tại sao xảy ra:** Tenant không phải watcher dependency.  
**Ảnh hưởng production:** UI lộ dữ liệu đã tải của tenant trước trong phiên hiện tại.  
**Cách sửa:** Watch tenant và query, invalidate requests, xóa selection/results ngay khi tenant đổi; backend phải enforce tenant membership.

### [High] — HTTP errors được xử lý như success

**Vấn đề:** Không kiểm tra `response.ok`.  
**Tại sao xảy ra:** `fetch` không reject chỉ vì HTTP 4xx/5xx.  
**Ảnh hưởng production:** ProblemDetails bị gán thành contacts; UI lỗi.  
**Cách sửa:** Check status và validate JSON shape.

### [Medium] — Loading sai dưới concurrency

**Vấn đề:** Request cũ `finally` tắt spinner request mới.  
**Tại sao xảy ra:** Boolean không gắn request identity.  
**Ảnh hưởng production:** UX báo hoàn thành sai.  
**Cách sửa:** Chỉ generation hiện hành được cập nhật state.

### [Medium] — URL chưa encode và request flood

**Vấn đề:** Query nối trực tiếp, mỗi ký tự phát request.  
**Tại sao xảy ra:** `&`, `#` thay đổi URL semantics; không debounce.  
**Ảnh hưởng production:** Sai query, QPS tăng.

**Tại sao xảy ra:** localStorage có thể truy cập từ JavaScript.  
**Ảnh hưởng production:** Credential exfiltration nếu XSS xảy ra.

## Phiên bản đề xuất

Giả định nghiệp vụ cho phép notes dạng plain text và ứng dụng có same-origin BFF session. Backend vẫn phải xác thực tenant theo identity, không tin query parameter.

```vue
<script setup lang="ts">
import { ref, watch, onBeforeUnmount } from 'vue';

type Contact = {
  id: string; name: string; email: string; noteHtml: string
};
const props = defineProps<{ tenantId: string }>();
const query = ref('');
const contacts = ref<Contact[]>([]);
const selected = ref<Contact | null>(null);
const loading = ref(false);
const error = ref('');
let generation = 0;
let controller: AbortController | undefined;
let debounce: ReturnType<typeof setTimeout> | undefined;

watch(
  () => [props.tenantId, query.value] as const,
  ([tenant, term], previous) => {
    const tenantChanged = !previous || previous[0] !== tenant;
    const current = ++generation;
    controller?.abort();
    if (debounce) clearTimeout(debounce);
    contacts.value = [];
    if (tenantChanged) selected.value = null;
    error.value = '';
    loading.value = false;
    if (!tenant) return;

    debounce = setTimeout(async () => {
      if (current !== generation) return;
      const request = new AbortController();
      controller = request;
      loading.value = true;
      try {
        const params = new URLSearchParams({
          tenant, q: term.trim()
        });
        const response = await fetch(
          `/api/contacts?${params.toString()}`,
          { signal: request.signal, credentials: 'same-origin' }
        );
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const body: unknown = await response.json();
        if (!Array.isArray(body) || !body.every(x =>
          x && typeof x.id === 'string' &&
          typeof x.name === 'string' &&
          typeof x.email === 'string' &&
          typeof x.noteHtml === 'string'))
          throw new Error('Invalid response');
        if (current === generation) contacts.value = body as Contact[];
      } catch {
        if (current === generation && !request.signal.aborted)
          error.value = 'Không thể tải contact.';
      } finally {
        if (current === generation) loading.value = false;
      }
    }, 250);
  },
  { immediate: true }
);

function choose(contact: Contact) {
  if (contacts.value.some(c => c.id === contact.id))
    selected.value = contact;
}
onBeforeUnmount(() => {
  generation++;
  controller?.abort();
  if (debounce) clearTimeout(debounce);
});
</script>

<template>
  <input v-model="query" aria-label="Tìm contact" />
  <p v-if="loading" role="status">Đang tìm...</p>
  <p v-if="error" role="alert">{{ error }}</p>
  <ul>
    <li v-for="contact in contacts" :key="contact.id">
      <button type="button" @click="choose(contact)">
        {{ contact.name }} — {{ contact.email }}
      </button>
    </li>
  </ul>
  <article v-if="selected">
    <h3>{{ selected.name }}</h3>
    <div class="note">{{ selected.noteHtml }}</div>
  </article>
</template>

<style scoped>
.note { white-space: pre-wrap; }
</style>
```

## Giải thích thiết kế sau khi sửa

Watcher theo tenant/query và `immediate` xử lý cả initial load. Generation counter bảo vệ state khi abort tới muộn. Reset state tránh hiển thị tenant cũ. `URLSearchParams` encode query, `response.ok` phân biệt HTTP failure, runtime validation tránh gán ProblemDetails. Interpolation render notes dưới dạng text. Same-origin BFF là lựa chọn kiến trúc, không phải tính năng Vue mặc định.

## Trade-offs

Reset ngay có thể gây flicker; có thể dùng skeleton hoặc cached results phân vùng tenant nhưng không hiển thị stale results như current. Debounce 250 ms cần điều chỉnh theo telemetry. BFF đòi hỏi CSRF/session management; rich text nếu cần sẽ đòi hỏi sanitizer và allowlist. Schema validator chuyên dụng có thể thay validation thủ công.

## Cách kiểm thử

1. Playwright E2E: query A chậm, AB nhanh, UI cuối chỉ có AB.
2. Tenant isolation: switch tenant trong lúc pending request; không còn contact/selection cũ.
3. Security: notes chứa event handlers/script; không thực thi HTML.
4. Failure path: 401/403/500, invalid JSON và offline; UI không crash.
5. Load: gõ 20 ký tự liên tục; request count giảm, không update sau unmount.

## Quan sát trong production

Browser Network waterfall, aborted request count, search latency p95, API 4xx/5xx, client errors, CSP reports và backend Application Insights traces theo correlation ID. Không log email/contact notes hoặc raw search query chứa PII. Alert khi 403 bất thường và search latency vượt SLO.

## Kiến thức trọng tâm

Elasticsearch và Vue UI đều là derived state: response đến muộn không có nghĩa còn hợp lệ. Source-of-truth, ordering, idempotency, tenant isolation và output encoding quyết định correctness và security. Test failure path và observability quan trọng hơn happy-path coverage.

## Mẫu tư duy cần nhớ

1. Không advance checkpoint khi chưa chứng minh xử lý thành công.
2. Retry phải đi kèm idempotency và ordering.
3. Derived read models không thay thế authorization hay nguồn dữ liệu chuẩn.
4. Đo lag, failures và race bằng telemetry trước khi tối ưu.
5. Giữ trust boundaries: validate identity, escape untrusted content.
