# Code Review Challenge 1 — Timesheet approval và payroll bị nhân đôi

**Chủ đề:** C#/.NET 8, EF Core, SQL Server, concurrency, transactional outbox  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 45 phút  
**Số vấn đề cần tìm:** khoảng 9

## Bối cảnh

Hệ thống nhân sự chạy 6 Azure App Service instances, cuối tháng có 300 approval requests/giây. Manager duyệt timesheet, tạo đúng một `PayrollAdjustment` và gửi kết quả tới payroll gateway qua HTTP. Mobile retry sau timeout; gateway đôi khi unavailable. Production xuất hiện duplicate adjustments và timesheet Approved nhưng payroll chưa nhận. Giả định `Timesheet` có `Id`, `EmployeeId`, `Status`, `Hours`, `ApprovedBy`; gateway không tham gia SQL transaction.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/timesheets")]
[Authorize(Roles = "Manager")]
public sealed class TimesheetsController : ControllerBase
{
    private readonly HrDbContext _db;
    private readonly IPayrollGateway _gateway;
    private readonly ILogger<TimesheetsController> _logger;

    public TimesheetsController(HrDbContext db, IPayrollGateway gateway,
        ILogger<TimesheetsController> logger)
        => (_db, _gateway, _logger) = (db, gateway, logger);

    [HttpPost("{id:guid}/approve")]
    public async Task<IActionResult> Approve(Guid id)
    {
        var sheet = await _db.Timesheets
            .FirstOrDefaultAsync(x => x.Id == id);

        if (sheet == null) return NotFound();
        if (sheet.Status == "Approved") return Ok();

        sheet.Status = "Approved";
        sheet.ApprovedBy = User.Identity?.Name;
        sheet.ApprovedAtUtc = DateTime.UtcNow;

        _db.PayrollAdjustments.Add(new PayrollAdjustment
        {
            TimesheetId = id,
            Hours = sheet.Hours
        });

        await _db.SaveChangesAsync();
        await _gateway.SendAsync(sheet.EmployeeId, sheet.Hours);
        _logger.LogInformation("Approved {Id}", id);
        return Ok();
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Thiếu resource-level authorization

**Vấn đề:** Chỉ check role, không check quan hệ manager–employee/tenant.  
**Tại sao xảy ra:** Truy vấn timesheet theo ID bất kỳ.  
**Ảnh hưởng production:** Manager có thể phê duyệt dữ liệu ngoài phạm vi.  
**Cách sửa:** Enforce scope bằng mapping đáng tin cậy ở backend; không dựa vào client-provided employee/tenant.

### [Critical] — Race condition và duplicate adjustment

**Vấn đề:** Check-then-write không nguyên tử.  
**Tại sao xảy ra:** Hai DbContext có thể cùng đọc trạng thái cũ.  
**Ảnh hưởng production:** Duplicate payroll adjustments, sai số tiền.  
**Cách sửa:** Conditional `UPDATE WHERE Status='Submitted'` kiểm tra affected rows, SQL transaction và unique index `PayrollAdjustments(TimesheetId)`.

### [High] — External side effect bị mất sau DB commit

**Vấn đề:** DB commit rồi HTTP fail; lần retry thấy Approved và bỏ qua.  
**Tại sao xảy ra:** HTTP không thuộc SQL transaction.  
**Ảnh hưởng production:** Payroll không nhận thay đổi.  
**Cách sửa:** Transactional outbox ghi event cùng transaction; worker gửi và reconciliation.

### [High] — Duplicate delivery tại gateway

**Vấn đề:** Không có idempotency key.  
**Tại sao xảy ra:** Timeout không chứng minh downstream chưa xử lý.  
**Ảnh hưởng production:** Tính lương trùng khi retry.  
**Cách sửa:** Stable event key, downstream deduplication và lookup/reconciliation; không hứa exactly-once nếu gateway không hỗ trợ.

### [High] — Transition thiếu business invariant

**Vấn đề:** Rejected/Cancelled cũng được Approved.  
**Tại sao xảy ra:** Chỉ kiểm tra khác Approved.  
**Ảnh hưởng production:** Duyệt timesheet không hợp lệ.  
**Cách sửa:** Chỉ cho phép Submitted → Approved, kiểm soát việc thay đổi Hours sau submit.

### [Medium] — Không có cancellation và bounded timeout

**Vấn đề:** Không truyền `CancellationToken`, không quy định timeout/retry budget.  
**Tại sao xảy ra:** Dependency calls dùng default behavior.  
**Ảnh hưởng production:** Request treo và tăng resource consumption.  
**Cách sửa:** Truyền token tới SQL; worker dùng timeout, backoff+jitter, dead-letter/reconciliation.

### [Medium] — Audit identity không ổn định

**Vấn đề:** `User.Identity?.Name` có thể null hoặc thay đổi.  
**Tại sao xảy ra:** Không lưu stable subject ID.  
**Ảnh hưởng production:** Khó audit và điều tra.  
**Cách sửa:** Lưu authenticated user ID và correlation ID, tránh log PII không cần thiết.

### [Medium] — Duplicate request bị hiểu sai

**Vấn đề:** Trả Ok khi Approved mà không phân biệt identical retry với conflicting transition.  
**Tại sao xảy ra:** Thiếu operation identity và response contract.  
**Ảnh hưởng production:** Client hiểu nhầm kết quả.  
**Cách sửa:** Trả current state và operation ID; 409 cho conflict theo contract.

### [Low] — Thiếu delivery telemetry

**Vấn đề:** Chỉ log success sau gateway call.  
**Tại sao xảy ra:** Không theo dõi event lifecycle.  
**Ảnh hưởng production:** Không thấy backlog hoặc approved-but-not-delivered.  
**Cách sửa:** Metrics outbox pending age, retries, duplicate suppression, reconciliation mismatches.

## Phiên bản đề xuất

Mẫu application service bên dưới giả định controller đã xác thực `managerId` từ claims đáng tin cậy; bảng `ManagerEmployees` xác định phạm vi quyền; `Hours` bất biến sau Submitted. `ApprovalResult`, `OutboxMessage` là kiểu domain của ứng dụng. Migration bắt buộc tạo unique indexes cho `PayrollAdjustments(TimesheetId)` và `OutboxMessages(EventKey)`.

```csharp
public async Task<ApprovalResult> ApproveAsync(
    Guid id, Guid managerId, CancellationToken ct)
{
    await using var tx = await _db.Database.BeginTransactionAsync(ct);

    var sheet = await _db.Timesheets.AsNoTracking()
        .Where(t => t.Id == id &&
            _db.ManagerEmployees.Any(m =>
                m.ManagerId == managerId && m.EmployeeId == t.EmployeeId))
        .Select(t => new { t.Id, t.EmployeeId, t.Hours, t.Status })
        .SingleOrDefaultAsync(ct);

    if (sheet is null) return ApprovalResult.NotFound;
    if (sheet.Status == "Approved") return ApprovalResult.AlreadyApproved;
    if (sheet.Status != "Submitted") return ApprovalResult.InvalidTransition;

    var changed = await _db.Database.ExecuteSqlInterpolatedAsync(
        $@"UPDATE Timesheets SET Status = 'Approved',
              ApprovedById = {managerId}, ApprovedAtUtc = SYSUTCDATETIME()
           WHERE Id = {id} AND Status = 'Submitted'", ct);

    if (changed != 1) return ApprovalResult.ConcurrencyConflict;

    _db.PayrollAdjustments.Add(new PayrollAdjustment
    {
        TimesheetId = id, Hours = sheet.Hours
    });
    _db.OutboxMessages.Add(new OutboxMessage
    {
        EventKey = $"timesheet-approved:{id}",
        Type = "TimesheetApproved",
        Payload = JsonSerializer.Serialize(new
        {
            TimesheetId = id, sheet.EmployeeId, sheet.Hours
        }),
        CreatedAtUtc = DateTime.UtcNow
    });
    await _db.SaveChangesAsync(ct);
    await tx.CommitAsync(ct);
    return ApprovalResult.Approved;
}
```

Trong hệ thống cho phép sửa `Hours` đồng thời, phải bổ sung `rowversion`/locking phù hợp và kiểm tra version ở conditional update; nếu không, projection trước UPDATE có thể lấy Hours cũ. Worker claim outbox an toàn trên nhiều instances, gửi `EventKey` làm idempotency key, chỉ mark Delivered sau acknowledgment. Nếu crash sau HTTP success nhưng trước mark Delivered, downstream vẫn phải deduplicate. Khi SQL unique/concurrency conflict, rollback và đọc lại trạng thái để trả kết quả phù hợp.

## Giải thích thiết kế sau khi sửa

SQL transaction bảo vệ transition, adjustment và outbox cùng lúc. Unique constraint là defense-in-depth. Outbox chuyển external HTTP khỏi request transaction, giảm khả năng mất sự kiện. Scope authorization phải dựa trên quan hệ manager–employee đáng tin cậy.

## Trade-offs

Outbox tăng storage, worker, operational complexity và eventual consistency. Với payroll chạy batch hàng ngày, batch export kèm reconciliation có thể đơn giản hơn. Serializable isolation có thể tăng blocking, không thay thế downstream idempotency. Không có guarantee exactly-once end-to-end khi gateway không hỗ trợ.

## Cách kiểm thử

1. **Concurrency integration:** 100 approvals đồng thời, chỉ một adjustment/outbox event.
2. **Authorization:** manager ngoài scope không thay đổi dữ liệu.
3. **Failure injection:** kill process ngay sau SQL commit, worker vẫn gửi event sau restart.
4. **Gateway timeout:** downstream đã xử lý nhưng client timeout, retry không tạo payroll entry trùng.
5. **Database test:** thay đổi Hours/status đồng thời, deadlock/unique violation, verify rollback và conflict handling.

## Quan sát trong production

Application Insights traces theo operation ID; SQL deadlocks và transaction duration; outbox backlog/oldest age; gateway p95, timeout, retry, duplicate suppression; alert khi Approved quá SLA mà chưa delivered/reconciled. Đối soát SQL và payroll định kỳ.

## Câu hỏi phỏng vấn mở rộng

1. Nếu gateway không hỗ trợ idempotency key hoặc lookup, bạn có thể cam kết điều gì?
2. Nếu quyền manager bị thu hồi giữa transaction, authorization consistency nên ra sao?
3. Khi outbox tăng lên hàng triệu rows, thiết kế claim, retention và ordering thế nào?

# Code Review Challenge 2 — Vue CMS preview hiển thị nhầm nội dung và rủi ro XSS

## Bối cảnh

Trang marketing dùng CMS để editor xem bản nháp. API `GET /api/preview?slug=...` trả `{title,html,updatedAt}` sau khi xác thực quyền preview. Editor chuyển slug liên tục trên mạng latency cao; đôi lúc preview của trang A hiện trên trang B. HTML có thể chứa markup không đáng tin cậy. CDN có thể cache GET nếu cấu hình sai; draft không được lộ ra public. Component hiện tại:

## Đoạn code cần review

```vue
<script setup lang="ts">
import { ref, watch, onMounted } from 'vue';

type Preview = { title: string; html: string; updatedAt: string };
const props = defineProps<{ slug: string; token: string }>();

const preview = ref<Preview | null>(null);
const loading = ref(false);
const error = ref('');
const cache = new Map<string, Preview>();

async function load() {
  loading.value = true;
  error.value = '';
  if (cache.has(props.slug)) {
    preview.value = cache.get(props.slug)!;
    loading.value = false;
    return;
  }
  try {
    const url = '/api/preview?slug=' + props.slug;
    const response = await fetch(url, {
      headers: { Authorization: 'Bearer ' + props.token }
    });
    const data = await response.json() as Preview;
    cache.set(props.slug, data);
    preview.value = data;
  } catch (e) {
    error.value = String(e);
  } finally {
    loading.value = false;
  }
}
watch(() => props.slug, load);
onMounted(load);
</script>

<template>
  <section>
    <p v-if="loading">Đang tải...</p>
    <p v-if="error">{{ error }}</p>
    <article v-if="preview">
      <h1>{{ preview.title }}</h1>
      <div v-html="preview.html"></div>
      <small>{{ preview.updatedAt }}</small>
    </article>
  </section>
</template>
```

## Kết quả code review tham khảo

### [Critical] — Raw HTML injection

**Vấn đề:** `v-html` render HTML không tự sanitize.  
**Tại sao xảy ra:** CMS content được coi là trusted.  
**Ảnh hưởng production:** Stored XSS nếu attacker đưa được payload vào content.  
**Cách sửa:** Backend sanitize theo allowlist đáng tin cậy, chặn unsafe attributes/URL schemes; defense-in-depth CSP và client sanitization khi cần.

### [Critical] — Draft có nguy cơ lộ qua shared cache

**Vấn đề:** Preview API thiếu cache policy rõ ràng.  
**Tại sao xảy ra:** CDN/proxy có thể bị cấu hình cache nhầm authenticated GET.  
**Ảnh hưởng production:** Draft lộ cho user khác.  
**Cách sửa:** Enforce authorization cho mỗi request; `Cache-Control: private, no-store`, bypass shared CDN; test hai identities. Không mặc định cho rằng mọi CDN cache request có Authorization.

### [High] — Out-of-order response

**Vấn đề:** Response cũ ghi đè `preview` mới.  
**Tại sao xảy ra:** Promise không hoàn thành theo thứ tự gửi.  
**Ảnh hưởng production:** Editor sửa sai trang.  
**Cách sửa:** Abort previous request và sequence guard ở success/error/finally.

### [High] — Cache không scoped và không invalidation

**Vấn đề:** Key chỉ có slug.  
**Tại sao xảy ra:** Draft phụ thuộc identity, locale, revision.  
**Ảnh hưởng production:** Stale/cross-session preview.  
**Cách sửa:** Bỏ cache draft mặc định; nếu bắt buộc cache, scope và invalidation rõ ràng.

### [High] — Không kiểm tra HTTP status/schema

**Vấn đề:** `fetch` resolve cả 4xx/5xx; TypeScript cast không validate runtime JSON.  
**Tại sao xảy ra:** Giả định JSON luôn là Preview.  
**Ảnh hưởng production:** UI sai, che lỗi auth.  
**Cách sửa:** `response.ok`, runtime schema validation và error handling theo status.

### [Medium] — Loading/error bị request cũ ghi đè

**Vấn đề:** `finally` và `catch` không kiểm tra request hiện hành.  
**Tại sao xảy ra:** State dùng chung cho nhiều calls.  
**Ảnh hưởng production:** Spinner/error sai thời điểm.  
**Cách sửa:** Sequence guard cho mọi state update.

### [Medium] — Slug chưa URL-encode

**Vấn đề:** Nối trực tiếp query string.  
**Tại sao xảy ra:** Không dùng `URLSearchParams`.  
**Ảnh hưởng production:** Slug chứa reserved characters gây request sai.  
**Cách sửa:** Encode query parameters.

### [Medium] — Token ownership chưa rõ

**Vấn đề:** Bearer token truyền qua presentation prop, error có thể hiển thị thông tin backend.  
**Tại sao xảy ra:** Auth client chưa được đóng gói.  
**Ảnh hưởng production:** Tăng rủi ro token exposure và refresh lỗi.  
**Cách sửa:** Centralized authenticated API client, không log token, hiển thị safe error.

## Phiên bản đề xuất

Backend phải enforce authz theo content/tenant và sanitize HTML trước khi trả, đặt `Cache-Control: private, no-store`. `usePreviewApi` dưới đây là adapter ứng dụng quản lý auth, URL encoding, `response.ok`, schema validation; `v-html` chỉ nhận HTML đã sanitize. Nếu chưa bảo đảm điều đó, không render raw HTML.

```vue
<script setup lang="ts">
import { ref, watch } from 'vue';
import { usePreviewApi } from '@/api/preview';

type Preview = { title: string; html: string; updatedAt: string };
const props = defineProps<{ slug: string; sessionKey: string }>();
const api = usePreviewApi();
const preview = ref<Preview | null>(null);
const loading = ref(false);
const error = ref('');
let sequence = 0;

watch(
  () => [props.slug, props.sessionKey] as const,
  ([slug], _previous, onCleanup) => {
    const controller = new AbortController();
    const current = ++sequence;
    onCleanup(() => controller.abort());

    preview.value = null;
    loading.value = true;
    error.value = '';

    void (async () => {
      try {
        const data = await api.getPreview(slug, controller.signal);
        if (current === sequence && !controller.signal.aborted)
          preview.value = data;
      } catch {
        if (current === sequence && !controller.signal.aborted)
          error.value = 'Không tải được bản xem trước.';
      } finally {
        if (current === sequence)
          loading.value = false;
      }
    })();
  },
  { immediate: true }
);
</script>

<template>
  <section aria-live="polite">
    <p v-if="loading">Đang tải...</p>
    <p v-else-if="error" role="alert">{{ error }}</p>
    <article v-else-if="preview">
      <h1>{{ preview.title }}</h1>
      <div v-html="preview.html"></div>
      <small>{{ preview.updatedAt }}</small>
    </article>
  </section>
</template>
```

API adapter phải dùng `URLSearchParams({ slug })`, check HTTP status và validate JSON; sessionKey thay đổi khi login/logout/token context đổi. Sequence guard ngăn stale update ngay cả khi abort không kịp. Với interactive third-party widgets, cân nhắc sandboxed iframe ở origin riêng.

## Giải thích thiết kế sau khi sửa

Latest request mới được phép commit UI state. Không cache draft giảm cross-session leakage; backend vẫn là trust boundary quyết định authz và safe HTML. Client cancellation chỉ là tối ưu tài nguyên, không phải security control.

## Trade-offs

Không cache draft tăng request; nếu cần offline preview phải có encrypted/session-scoped storage và invalidation. Sanitization có thể bỏ markup hợp lệ, cần phối hợp editor và QA. Sandboxed iframe tăng isolation nhưng phức tạp styling và communication. Debounce giảm traffic nhưng không giải quyết race một mình.

## Cách kiểm thử

1. **Playwright race:** A delay 800ms, B 50ms; UI cuối chỉ hiển thị B.
2. **Security:** HTML event handler, unsafe URL và SVG payload không thực thi.
3. **Identity isolation:** logout A/login B cùng slug không thấy draft A; CDN không trả cache HIT.
4. **Failure path:** 401/403/500, invalid JSON, abort, offline; UI không hiển thị content cũ.
5. **CMS lifecycle:** sửa revision/locale rồi publish; preview đúng bản, public route không lộ draft.

## Quan sát trong production

Frontend metrics: preview latency p95, cancellation, stale-response suppression, error status; backend Application Insights: authorization denials, correlation ID, revision; CDN logs: cache status cho preview phải bypass, alert shared-cache HIT; CSP reports được lọc thông tin nhạy cảm. Không log bearer token hoặc raw draft HTML.
