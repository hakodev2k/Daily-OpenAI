# Code Review Challenge 1 — Azure Blob upload làm lộ dữ liệu giữa các tenant

**Chủ đề:** ASP.NET Core, Azure Blob Storage, multi-tenant authorization, file upload security

## Bối cảnh

Một CMS multi-tenant cho phép biên tập viên tải tài liệu PDF và ảnh lên Azure Blob Storage. ASP.NET Core API chạy trên Azure App Service; frontend React gọi API để nhận URL upload rồi hiển thị nội dung. Hệ thống có khoảng 600 tenant và hàng nghìn lượt upload mỗi giờ. Người dùng phản ánh đôi khi tài liệu của tenant khác xuất hiện khi biết URL; một số file upload thành công nhưng metadata trong SQL Server không được tạo. Backend xác thực JWT và có claim `tenant_id`; quyền editor được kiểm tra bằng policy riêng. Container Blob được giả định cấu hình private. Review code sau mà không mặc định rằng client đáng tin.

## Đoạn code cần review

```csharp
[Authorize]
[ApiController]
[Route("api/media")]
public sealed class MediaController : ControllerBase
{
    private readonly BlobContainerClient _container;
    private readonly CmsDbContext _db;
    private readonly IConfiguration _config;

    public MediaController(BlobServiceClient blobs,
        CmsDbContext db, IConfiguration config)
    {
        _container = blobs.GetBlobContainerClient("cms-assets");
        _db = db;
        _config = config;
    }

    [HttpPost("upload-url")]
    public async Task<IActionResult> CreateUploadUrl(
        [FromBody] UploadRequest request)
    {
        var path = $"{request.TenantId}/{request.FileName}";
        var blob = _container.GetBlobClient(path);
        var sas = blob.GenerateSasUri(
            BlobSasPermissions.Write | BlobSasPermissions.Read,
            DateTimeOffset.UtcNow.AddDays(7));

        _db.Media.Add(new MediaEntity {
            TenantId = request.TenantId,
            Path = path,
            ContentType = request.ContentType,
            Status = "Published"
        });
        await _db.SaveChangesAsync();
        return Ok(new { uploadUrl = sas.ToString(), path });
    }

    [HttpGet("{tenantId}/{*path}")]
    public async Task<IActionResult> Download(
        string tenantId, string path)
    {
        var blob = _container.GetBlobClient($"{tenantId}/{path}");
        var stream = await blob.OpenReadAsync();
        return File(stream, "application/octet-stream");
    }
}

public sealed record UploadRequest(
    string TenantId, string FileName, string ContentType);
```

## Kết quả code review tham khảo

### Critical — Cross-tenant access (IDOR)

**Vấn đề:** `request.TenantId` và route `tenantId` đều do client quyết định; chỉ có `[Authorize]` chung.  
**Tại sao xảy ra:** Authentication không thay thế resource-level authorization.  
**Ảnh hưởng production:** Đọc, ghi đè tài liệu tenant khác.  
**Cách sửa:** Lấy tenant scope từ identity và membership đã xác minh, kiểm tra quyền editor/read trên từng resource, không tin tenant do request tự khai báo.

### Critical — Quyền SAS quá rộng và thời hạn quá dài

**Vấn đề:** URL có cả Read và Write trong bảy ngày.  
**Tại sao xảy ra:** Upload credential bị dùng như download credential.  
**Ảnh hưởng production:** URL rò rỉ có thể tiếp tục truy cập hoặc ghi dữ liệu.  
**Cách sửa:** SAS ngắn hạn, chỉ Create/Write phù hợp luồng, scope tới blob ID mới; cân nhắc user delegation SAS với Managed Identity. Không log URL chứa token.

### High — Published trước khi upload hoàn thành

**Vấn đề:** Database ghi Published trước khi có bytes.  
**Tại sao xảy ra:** SQL transaction không bao trùm Blob upload từ browser.  
**Ảnh hưởng production:** Broken link, file chưa kiểm duyệt được phục vụ.  
**Cách sửa:** Pending → Uploaded → Validated → Published; endpoint finalize xác minh Blob properties, owner và policy; cleanup các Pending hết hạn.

### High — Blob name có thể đụng nhau hoặc chứa path không mong muốn

**Vấn đề:** Ghép `FileName` trực tiếp vào Blob path.  
**Tại sao xảy ra:** Không tạo object ID độc lập với tên hiển thị.  
**Ảnh hưởng production:** Overwrite tài liệu, đường dẫn khó audit và xử lý ký tự đặc biệt.  
**Cách sửa:** Tạo server-side opaque ID, dùng display name riêng; giới hạn độ dài, canonicalize và validate tên.

### High — Thiếu kiểm tra nội dung file và giới hạn upload

**Vấn đề:** Tin `ContentType` từ client, không kiểm tra kích thước và loại nội dung sau upload.  
**Tại sao xảy ra:** Direct upload bỏ qua validation ở API.  
**Ảnh hưởng production:** File độc hại, chi phí lưu trữ tăng, tài liệu không phù hợp bị phát hành.  
**Cách sửa:** Giới hạn kích thước ở luồng upload và kiểm tra lại Blob properties; kiểm tra signature/file type, malware scanning khi phù hợp, quarantine trước publish.

### High — Download không kiểm tra metadata và trạng thái

**Vấn đề:** Chỉ cần biết blob path là có thể tải.  
**Tại sao xảy ra:** Không truy vấn ownership, publish status hay access policy.  
**Ảnh hưởng production:** Đọc bản nháp, tài liệu đã thu hồi hoặc dữ liệu tenant khác.  
**Cách sửa:** Query media theo ID và tenant scope, kiểm tra Published và quyền đọc rồi stream hoặc cấp read SAS ngắn hạn.

### Medium — Không hỗ trợ CancellationToken và xử lý lỗi rõ ràng

**Vấn đề:** Không truyền `HttpContext.RequestAborted`; exception có thể tạo response không nhất quán.  
**Tại sao xảy ra:** Thiếu cancellation, ProblemDetails và logging có cấu trúc.  
**Ảnh hưởng production:** Request treo, khó điều tra.  
**Cách sửa:** Truyền cancellation; mapping 404/403/409 phù hợp, không tiết lộ tài nguyên ngoài quyền.

### Medium — Thiếu idempotency và orphan cleanup

**Vấn đề:** Retry tạo nhiều metadata hoặc để blob mồ côi.  
**Tại sao xảy ra:** Không có operation ID, unique constraint và reconciliation.  
**Ảnh hưởng production:** Storage leak, sai số liệu CMS.  
**Cách sửa:** Idempotency key scoped theo tenant/user, unique constraint, background reconciliation.

## Phiên bản đề xuất

Thiết kế rút gọn dưới đây giả định `IMediaPolicy` kiểm tra membership/role từ identity đã xác thực, `IMediaRepository` áp dụng tenant filter và concurrency token, `IBlobUploadIssuer` phát user-delegation SAS có giới hạn thời gian. Các abstraction là contract minh họa, không phải API sẵn có của Azure SDK.

```csharp
[Authorize]
[ApiController]
[Route("api/media")]
public sealed class SecureMediaController : ControllerBase
{
    private readonly IMediaPolicy _policy;
    private readonly IMediaRepository _media;
    private readonly IBlobUploadIssuer _uploads;

    public SecureMediaController(IMediaPolicy policy,
        IMediaRepository media, IBlobUploadIssuer uploads)
    {
        _policy = policy;
        _media = media;
        _uploads = uploads;
    }

    [HttpPost("uploads")]
    public async Task<IActionResult> Start(
        StartUploadRequest request, CancellationToken ct)
    {
        var tenant = await _policy.RequireEditorTenantAsync(
            User, request.TenantId, ct);
        var mediaId = Guid.NewGuid();
        var blobName = $"{tenant}/{mediaId:N}";
        var item = MediaRecord.Pending(mediaId, tenant, blobName,
            request.DisplayName, request.ExpectedBytes);
        await _media.InsertAsync(item, ct);
        var url = await _uploads.CreateWriteOnlyUrlAsync(
            blobName, TimeSpan.FromMinutes(10), ct);
        return Ok(new { mediaId, uploadUrl = url });
    }

    [HttpPost("{id:guid}/finalize")]
    public async Task<IActionResult> FinalizeUpload(
        Guid id, CancellationToken ct)
    {
        var item = await _media.GetAuthorizedForEditAsync(
            id, User, ct);
        if (item is null) return NotFound();
        var validation = await _uploads.ValidateUploadedBlobAsync(
            item.BlobName, item.ExpectedBytes, ct);
        if (!validation.IsAcceptable) return Conflict(
            new ProblemDetails { Title = "Upload not validated" });
        await _media.MarkValidatedAsync(item, ct);
        return Accepted(new { item.Id, status = "Validated" });
    }
}
public sealed record StartUploadRequest(
    string TenantId, string DisplayName, long ExpectedBytes);
```

Publishing là thao tác riêng sau bước malware/content validation và authorization; download phải truy vấn record đã Published rồi mới phát read SAS ngắn hạn hoặc stream. `MarkValidatedAsync` cần optimistic concurrency; finalize lặp lại phải idempotent. Hệ thống phải kiểm tra upload size thực tế, MIME/signature và xử lý lỗi giữa các trạng thái. Blob không nên public.

## Giải thích thiết kế sau khi sửa

Identity quyết định tenant scope; object ID do server sinh giúp tránh overwrite; state machine tránh phát hành file chưa có bytes. Managed Identity giảm phụ thuộc account key. Authorization phải chạy cả khi download, không chỉ lúc upload.

## Trade-offs

Direct-to-Blob giảm bandwidth và CPU của API nhưng cần lifecycle, SAS governance và reconciliation. Proxy upload dễ kiểm soát luồng bytes nhưng tăng chi phí tài nguyên. Malware scanning bất đồng bộ tăng latency publish; cần UI thể hiện Pending rõ ràng. Không thể có atomic transaction xuyên SQL Server và Blob Storage chỉ bằng EF Core transaction.

## Cách kiểm thử

1. **Security integration:** User tenant A không thể start/finalize/download media của tenant B; kiểm tra 403/404 theo policy.
2. **Failure-path:** SAS hết hạn, upload thiếu bytes hoặc Blob bị xóa trước finalize không được Published.
3. **Concurrency:** Hai finalize đồng thời và retry cùng operation không tạo nhiều phiên bản trạng thái.
4. **Security:** File có MIME giả, vượt size, nội dung bị quarantine không thể download.
5. **E2E:** React upload → finalize → validation → publish → download; kiểm tra revoke và expiry.

## Quan sát trong production

Structured logs với `tenantId` đã được kiểm soát, `mediaId`, `operationId`, state transition và correlation ID; tuyệt đối không log SAS. Application Insights dependency telemetry cho Blob/SQL, metrics Pending age, validation failures, orphan count, 403/404 theo endpoint, upload-to-publish p95 và alert cho bất thường cross-tenant access. Audit ai publish/revoke.

3. Khi nào chọn backend proxy thay vì direct upload?

type Row = { orderId: string; amount: number };
type Report = { rows: Row[]; total: number };
type Props = { tenantId: string };

export function RevenueReport({ tenantId }: Props) {
  const [from, setFrom] = useState("2026-11-01");
  const [to, setTo] = useState("2026-11-21");
  const [page, setPage] = useState(1);
  const [report, setReport] = useState<Report | null>(null);
  const [loading, setLoading] = useState(false);
  const [error, setError] = useState("");

  async function loadReport() {
    setLoading(true);
    setError("");
    try {
      const key = `report:${from}:${to}:${page}`;
      const cached = sessionStorage.getItem(key);
      if (cached) {
        setReport(JSON.parse(cached));
        return;
      }
      const url = `/api/reports/revenue?tenantId=${tenantId}` +
        `&from=${from}&to=${to}&page=${page}`;
      const response = await fetch(url, { credentials: "include" });
      const data = await response.json() as Report;
      setReport(data);
      sessionStorage.setItem(key, JSON.stringify(data));
    } catch {
      setError("Không thể tải báo cáo");
    } finally {
      setLoading(false);
    }
  }

  useEffect(() => {
    loadReport();
  }, [tenantId, from, to, page]);

  return <section>
    <input type="date" value={from}
      onChange={e => setFrom(e.target.value)} />
    <input type="date" value={to}
      onChange={e => setTo(e.target.value)} />
    <button onClick={() => setPage(page + 1)}>Next</button>
    {loading && <p>Loading...</p>}
    {error && <p role="alert">{error}</p>}
    <strong>Total: {report?.total ?? 0}</strong>
    <ul>{report?.rows.map(x =>
      <li key={x.orderId}>{x.orderId}: {x.amount}</li>)}</ul>
  </section>;
}
```

## Phiên bản đề xuất

type Row = { orderId: string; amount: number };
type Report = { rows: Row[]; total: number };
type Query = { tenantId: string; from: string; to: string; page: number };

function isReport(value: unknown): value is Report {
  if (!value || typeof value !== "object") return false;
  const x = value as Partial<Report>;
  return typeof x.total === "number" && Array.isArray(x.rows) &&
    x.rows.every(r => typeof r.orderId === "string" &&
      typeof r.amount === "number");
}

    let active = true;
    setState({ key, report: null, loading: true, error: "" });
    const params = new URLSearchParams({
      tenantId, from, to, page: String(page)
    });
    async function run() {
      try {
        if (from > to) throw new Error("Khoảng ngày không hợp lệ");
        const response = await fetch(
          `/api/reports/revenue?${params}`,
          { credentials: "include", signal: controller.signal });
        if (!response.ok) throw new Error(`HTTP ${response.status}`);
        const data: unknown = await response.json();
        if (!isReport(data)) throw new Error("Invalid response");
        if (active) setState({ key, report: data, loading: false, error: "" });
      } catch (e) {
        if (active) setState({
          key, report: null, loading: false,
          error: e instanceof Error ? e.message : "Request failed"
        });
      }
    }
    void run();
    return () => { active = false; controller.abort(); };
  }, [key, tenantId, from, to, page]);

  const visible = state.key === key ? state : null;
  return <section>
    <input type="date" value={from}
      onChange={e => { setFrom(e.target.value); setPage(1); }} />
    <input type="date" value={to}
      onChange={e => { setTo(e.target.value); setPage(1); }} />
    <button onClick={() => setPage(p => p + 1)}>Next</button>
    {(!visible || visible.loading) && <p>Loading...</p>}
    {visible?.error && <p role="alert">{visible.error}</p>}
    {visible?.report && <>
      <strong>Total: {visible.report.total}</strong>
      <ul>{visible.report.rows.map(r =>
        <li key={r.orderId}>{r.orderId}: {r.amount}</li>)}</ul>
    </>}
  </section>;
}
```

## Giải thích thiết kế sau khi sửa

State được gắn với query key, nên render không dùng dữ liệu của query khác kể cả trong một render trước khi effect chạy. Cleanup ngăn request cũ ghi state; abort giảm request không cần thiết. `response.ok` và schema guard tránh coi error payload là báo cáo. Date change reset pagination. Nếu cần UX tốt hơn, có thể dùng TanStack Query với key đầy đủ, cancellation và cache policy riêng.

## Trade-offs

Không cache giúp giảm nguy cơ stale/cross-tenant nhưng tăng API calls; cần đo trước khi bật cache. Abort ở browser không đảm bảo SQL Server query đã dừng: backend phải truyền `CancellationToken` đến database và giới hạn query. Guard/schema validation có thêm code; dùng query library giảm boilerplate nhưng thêm dependency. Với yêu cầu không flash dữ liệu cũ, placeholder có thể làm UX ít mượt hơn.

## Cách kiểm thử

1. **Race test:** Mock response A chậm hơn B; chỉ kết quả B được hiển thị.
2. **Tenant switch:** Chuyển A → B khi A đang tải; không render A trong context B.
3. **Failure-path:** HTTP 403, 500, JSON sai schema và network abort không hiển thị dữ liệu cũ.
4. **Playwright E2E:** Đổi date nhanh, Next rồi đổi filter; kiểm tra page reset và loading.
5. **Load/API test:** Nhiều request bị hủy; đo request duration và SQL cancellation/timeout.

## Quan sát trong production

Frontend đo query key đã hash/không chứa dữ liệu nhạy cảm, request duration, cancellation count, stale-response suppression và UI error rate. Backend Application Insights ghi correlation ID, tenant scope đã authorize, SQL dependency p95/p99, 403 rate, request cancellation và query timeout. Không gửi cookie hoặc response chứa dữ liệu doanh thu vào telemetry.

1. Nếu chuyển sang TanStack Query, query key và staleTime nên thiết kế ra sao?

3. Khi báo cáo cần streaming hoặc export CSV lớn, UI và API nên thay đổi thế nào?

# Tổng kết hôm nay

## Kiến thức trọng tâm

Multi-tenant authorization phải được kiểm tra ở resource boundary; direct Blob upload cần lifecycle rõ ràng và SAS quyền tối thiểu. Frontend asynchronous state phải gắn với query identity, không được cho response cũ ghi đè context mới. Cache và telemetry đều phải tuân thủ isolation và confidentiality.

## Mẫu tư duy cần nhớ

1. **Authenticate rồi vẫn phải authorize từng resource.**
2. **Thiết kế trạng thái và failure path trước khi publish dữ liệu.**
3. **Mỗi asynchronous result cần có owner/context rõ ràng.**
4. **Cache key phải phản ánh đầy đủ security và freshness boundary.**
5. **Dùng test đảo thứ tự, retry và dependency failure để chứng minh correctness.**
