# Code Review Challenge 1 — CRM webhook ghi đè dữ liệu mới bằng event cũ

## Bối cảnh

Portal nhân sự nhận webhook ContactChanged từ CRM. CRM gửi at-least-once, có thể đảo thứ tự, mỗi contact có Revision tăng dần. ASP.NET Core chạy 4 instances, PostgreSQL là source of truth. Sau scale-out, email đôi khi quay về bản cũ, webhook nhận 200 nhưng database không thay đổi. Chưa biết CRM có replay API hoặc signed webhook không. Không được thay đổi hợp đồng CRM khi chưa xác minh.

## Đoạn code cần review

```csharp
public record ContactChanged(
    string TenantId, string ContactId, long Revision, string Email);

[ApiController]
[Route("api/crm/webhooks")]
public class ContactWebhookController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly ILogger<ContactWebhookController> _log;

    public ContactWebhookController(
        AppDbContext db, ILogger<ContactWebhookController> log)
        => (_db, _log) = (db, log);

    [HttpPost("contact")]
    public async Task<IActionResult> Receive(ContactChanged evt)
    {
        var contact = await _db.Contacts
            .FirstOrDefaultAsync(x => x.ContactId == evt.ContactId);

        if (contact == null)
        {
            contact = new Contact {
                Id = Guid.NewGuid(),
                TenantId = evt.TenantId,
                ContactId = evt.ContactId
            };
            _db.Contacts.Add(contact);
        }

        contact.Email = evt.Email;
        contact.Revision = evt.Revision;

        try
        {
            await _db.SaveChangesAsync();
        }
        catch (Exception ex)
        {
            _log.LogWarning(ex, "Failed contact update {@Event}", evt);
        }

        return Ok(new { received = true });
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Thiếu authentication của webhook

**Vấn đề:** Không thấy xác thực nguồn gọi.  
**Tại sao xảy ra:** Endpoint nhận payload mà không có signature/token verification trong code.  
**Ảnh hưởng production:** Người ngoài có thể giả mạo update hoặc tenant.  
**Cách sửa:** Xác minh HMAC signature trên raw body, timestamp và replay window nếu CRM hỗ trợ; hoặc OAuth/mTLS theo hợp đồng thực tế. Secret trong Key Vault, so sánh constant-time. Không tự giả định một cơ chế sẵn có.

### [Critical] — Cross-tenant update

**Vấn đề:** Query chỉ theo ContactId.  
**Tại sao xảy ra:** Identity tenant không tham gia lookup.  
**Ảnh hưởng production:** Contact của tenant khác bị sửa.  
**Cách sửa:** Unique key (TenantId, ContactId), mọi read/write tenant-scoped; authorize tenant mapping từ verified sender.

### [High] — Stale revision overwrite

**Vấn đề:** Không so sánh Revision.  
**Tại sao xảy ra:** Delivery order không đảm bảo business order.  
**Ảnh hưởng production:** Data regression.  
**Cách sửa:** Atomic upsert chỉ update khi stored revision nhỏ hơn incoming revision.

### [High] — Check-then-insert race

**Vấn đề:** Hai request đồng thời có thể cùng insert.  
**Tại sao xảy ra:** Read và insert không atomic.  
**Ảnh hưởng production:** Duplicate rows hoặc unique violations.  
**Cách sửa:** Unique index và INSERT ON CONFLICT có điều kiện.

### [High] — Acknowledge lỗi như thành công

**Vấn đề:** Exception bị nuốt và luôn trả 200.  
**Tại sao xảy ra:** Không phân biệt received với durable commit.  
**Ảnh hưởng production:** CRM không retry và mất update.  
**Cách sửa:** Chỉ trả 2xx sau commit hoặc durable enqueue; trả 5xx khi transient failure, theo retry contract.

### [High] — Thiếu validation và replay control

**Vấn đề:** Không kiểm tra Revision, length, body size, event ID/timestamp.  
**Tại sao xảy ra:** Model binding không enforce business invariant.  
**Ảnh hưởng production:** Data pollution, flood và replay.  
**Cách sửa:** Validate input và giới hạn request, replay window/dedup nếu provider hỗ trợ.

### [Medium] — Không propagate cancellation

**Vấn đề:** DB calls không nhận RequestAborted.  
**Tại sao xảy ra:** Bỏ qua CancellationToken.  
**Ảnh hưởng production:** Tăng resource consumption khi client disconnect.  
**Cách sửa:** Truyền token; xác định commit boundary phù hợp.

### [Medium] — Sensitive logging và thiếu outcome metrics

**Vấn đề:** Log cả email nhưng không phân biệt applied/stale/failed.  
**Tại sao xảy ra:** Log nguyên payload và chỉ quan sát HTTP 200.  
**Ảnh hưởng production:** Rò PII, không phát hiện data drift.  
**Cách sửa:** Redact PII, structured outcome metrics, correlation ID.

## Phiên bản đề xuất

Trước rollout, xử lý duplicate hiện có; schema giả định bảng contacts có tenant_id, contact_id, revision, email và các cột khác có default hợp lệ.

```sql
CREATE UNIQUE INDEX ux_contacts_tenant_contact
ON contacts (tenant_id, contact_id);
```

```csharp
public sealed class ContactIngestor(NpgsqlDataSource source)
{
    public async Task<bool> ApplyAsync(ContactChanged e, CancellationToken ct)
    {
        const string sql = """
            INSERT INTO contacts (tenant_id, contact_id, revision, email)
            VALUES (@tenant, @contact, @revision, @email)
            ON CONFLICT (tenant_id, contact_id)
            DO UPDATE SET
                revision = EXCLUDED.revision,
                email = EXCLUDED.email
            WHERE contacts.revision < EXCLUDED.revision
            RETURNING revision;
            """;
        await using var cmd = source.CreateCommand(sql);
        cmd.Parameters.AddWithValue("tenant", e.TenantId);
        cmd.Parameters.AddWithValue("contact", e.ContactId);
        cmd.Parameters.AddWithValue("revision", e.Revision);
        cmd.Parameters.AddWithValue("email", e.Email);
        return await cmd.ExecuteScalarAsync(ct) is not null;
    }
}

[ApiController]
[Route("api/crm/webhooks")]
[VerifiedCrmWebhook]
public class ContactWebhookController(ContactIngestor ingestor)
    : ControllerBase
{
    [HttpPost("contact")]
    [RequestSizeLimit(65536)]
    public async Task<IActionResult> Receive(
        [FromBody] ContactChanged e, CancellationToken ct)
    {
        if (string.IsNullOrWhiteSpace(e.TenantId) ||
            string.IsNullOrWhiteSpace(e.ContactId) ||
            string.IsNullOrWhiteSpace(e.Email) ||
            e.Email.Length > 320 || e.Revision <= 0)
            return BadRequest();

        var applied = await ingestor.ApplyAsync(e, ct);
        return Ok(new { received = true, applied });
    }
}
```

`VerifiedCrmWebhook` là **custom filter cần implement**, không phải ASP.NET Core built-in. Nó phải verify raw body trước khi model binding, xác minh tenant mapping, timestamp/replay theo hợp đồng CRM. Exception middleware phải trả 5xx khi database unavailable, không 200. Conditional `RETURNING` không có row khi stale revision. Nếu cần downstream side effects, dùng transactional outbox và event ID thay vì giả định upsert đủ để deduplicate toàn bộ workflow.

## Giải thích thiết kế sau khi sửa

Unique constraint xác định business identity. Atomic upsert kết hợp compare revision và write, không có cửa sổ race giữa query và update. Sử dụng Npgsql riêng cho critical statement không bắt buộc loại bỏ EF Core ở nơi khác. Stale/duplicate event được acknowledge vì state không cần thay đổi; failed write không được acknowledge.

## Trade-offs

- PostgreSQL-specific SQL giảm portability nhưng tăng correctness.
- Revision chỉ đáng tin nếu monotonic theo từng contact; phải xác minh upstream.
- Retry khi database outage có thể tạo burst; cần backoff và reconciliation.
- Queue không mặc định cần thiết: chỉ bổ sung khi latency/burst hoặc durability yêu cầu.
- Signature verification đòi hỏi secret rotation và clock-skew policy.

## Cách kiểm thử

1. Concurrency integration: 100 events đảo thứ tự, 4 instances; cuối cùng một row với max revision.
2. Tenant isolation: cùng ContactId ở hai tenant; không cross-write.
3. Failure injection: PostgreSQL unavailable; không 200, retry sau phục hồi.
4. Security: sai signature, replay, oversized payload bị từ chối.
5. Load: đo p95, lock waits, connection pool và tỷ lệ applied/stale.

## Quan sát trong production

Application Insights: request p95, 5xx, dependency latency, trace ID; metrics `crm_ingest_total` theo applied/stale/failed. PostgreSQL: unique violations, lock waits, connection saturation. Alert khi failed tăng hoặc applied giảm bất thường. Không log email, signature, token hay raw body.

## Câu hỏi phỏng vấn mở rộng

1. Nếu CRM không cung cấp revision mà chỉ có updatedAt, cần kiểm chứng gì?
2. Nếu update còn publish sang Elasticsearch, bạn bảo đảm eventual consistency bằng cách nào?
3. Nếu retry bị gửi trong lúc deploy, chiến lược reconciliation và rollback là gì?

```vue
type Product = {
```

## Kết quả code review tham khảo

### [Critical] — Untrusted HTML trong v-html

**Vấn đề:** Render HTML chưa sanitize.  
**Tại sao xảy ra:** v-html bỏ qua escaping mặc định của Vue.  
**Ảnh hưởng production:** Stored XSS, session abuse và nguy cơ token theft.  
**Cách sửa:** Render text bằng interpolation; nếu bắt buộc rich text, sanitize allowlist ở trust boundary và áp dụng CSP.

### [High] — Token trong localStorage

**Vấn đề:** JavaScript cùng origin có thể đọc bearer token.  
**Tại sao xảy ra:** localStorage không có HttpOnly; token đọc một lần sẽ stale khi refresh.  
**Ảnh hưởng production:** XSS có thể lấy token; session hết hạn gây 401.  
**Cách sửa:** Cân nhắc BFF với Secure HttpOnly SameSite cookie + CSRF protection, hoặc quản lý memory token/refresh flow theo kiến trúc auth thực tế.

### [High] — Stale response overwrite

**Vấn đề:** Response cũ cập nhật products sau response mới.  
**Tại sao xảy ra:** Không cancel/guard request.  
**Ảnh hưởng production:** Hiển thị sai keyword hoặc tenant.  
**Cách sửa:** Abort request cũ và dùng generation ID để chỉ request mới nhất được cập nhật state.

### [High] — Tenant chỉ được kiểm soát bởi UI

**Vấn đề:** Nếu backend tin tenant query, có thể cross-tenant access.  
**Tại sao xảy ra:** Client có thể tự thay đổi query parameter.  
**Ảnh hưởng production:** Rò dữ liệu tenant.  
**Cách sửa:** API authorize tenant membership theo principal trên mỗi request; Elasticsearch query phải tenant-scoped.

### [Medium] — HTTP failure bị xử lý như thành công

**Vấn đề:** fetch không throw khi 4xx/5xx; data.items không được validate.  
**Tại sao xảy ra:** Chỉ catch network error.  
**Ảnh hưởng production:** UI lỗi hoặc silently empty.  
**Cách sửa:** Kiểm tra response.ok, parse và validate DTO, hiển thị lỗi an toàn.

### [Medium] — Request burst

**Vấn đề:** Mỗi keystroke tạo request.  
**Tại sao xảy ra:** Watch không debounce.  
**Ảnh hưởng production:** Elasticsearch load tăng, 429 và p95 cao.  
**Cách sửa:** Debounce theo UX, server pagination/rate limit; đo trước khi chọn threshold.

### [Medium] — Loading state không thuộc request

**Vấn đề:** Request A kết thúc có thể set loading=false khi B còn chạy.  
**Tại sao xảy ra:** Shared boolean.  
**Ảnh hưởng production:** UX báo hoàn tất sai.  
**Cách sửa:** Generation guard và finally.

### [Medium] — URL không encode và thiếu cleanup

**Vấn đề:** Query chứa &/# gây sai tham số, request chạy sau unmount.  
**Tại sao xảy ra:** Nối chuỗi thủ công, không cancel lifecycle.  
**Ảnh hưởng production:** Search sai và resource waste.  
**Cách sửa:** URLSearchParams, onUnmounted cleanup.

## Phiên bản đề xuất

Giả định same-origin BFF session cookie đã có Secure/HttpOnly/SameSite và server CSRF protection; nếu dùng bearer auth, thay bằng auth client tập trung, không đọc localStorage trực tiếp.

```vue
<script setup lang="ts">
import { ref, watch, onUnmounted } from 'vue'
type Product = { id: string; name: string; summary: string; price: number }
const query = ref('')
const tenantId = ref('tenant-a')
const status = ref('active')
const products = ref<Product[]>([])
const loading = ref(false)
const error = ref('')
let timer: ReturnType<typeof setTimeout> | undefined
let controller: AbortController | undefined
let generation = 0

watch([query, tenantId, status], () => {
  const id = ++generation
  if (timer) clearTimeout(timer)
  controller?.abort()
  products.value = []
  error.value = ''
  loading.value = true
  timer = setTimeout(async () => {
    const current = new AbortController()
    controller = current
    const params = new URLSearchParams({
      tenant: tenantId.value,
      q: query.value.trim(),
      status: status.value
    })
    try {
      const response = await fetch('/api/products/search?' + params, {
        signal: current.signal,
        credentials: 'same-origin'
      })
      if (!response.ok) throw new Error('HTTP ' + response.status)
      const data: unknown = await response.json()
      if (!data || typeof data !== 'object' ||
          !('items' in data) || !Array.isArray(data.items))
        throw new Error('Invalid response')
      if (id === generation) products.value = data.items as Product[]
    } catch {
      if (id === generation && !current.signal.aborted)
        error.value = 'Không thể tải sản phẩm.'
    } finally {
      if (id === generation) loading.value = false
    }
  }, 300)
}, { immediate: true })

onUnmounted(() => {
  generation++
  if (timer) clearTimeout(timer)
  controller?.abort()
})
</script>

<template>
  <section>
    <input v-model="query" aria-label="Search products" />
    <select v-model="tenantId" aria-label="Tenant">
      <option value="tenant-a">Tenant A</option>
      <option value="tenant-b">Tenant B</option>
    </select>
    <select v-model="status" aria-label="Status">
      <option value="active">Active</option>
      <option value="archived">Archived</option>
    </select>
    <p v-if="loading" role="status">Loading...</p>
    <p v-else-if="error" role="alert">{{ error }}</p>
    <p v-else-if="products.length === 0">Không có kết quả.</p>
    <ul v-else>
      <li v-for="p in products" :key="p.id">
        <strong>{{ p.name }}</strong>
        <span>{{ p.summary }}</span>
        <small>{{ p.price }}</small>
      </li>
    </ul>
  </section>
</template>
```

Lưu ý: `as Product[]` chỉ là TypeScript assertion, không validate phần tử runtime. Production cần DTO/schema validation, giới hạn số items ở API. 300ms chỉ là giả định để đo UX. Abort không đảm bảo server đã dừng xử lý; cần propagate cancellation phía ASP.NET Core.

## Giải thích thiết kế sau khi sửa

Generation ID ngăn stale response cập nhật state ngay cả khi abort không kịp. Debounce giảm burst. URLSearchParams bảo toàn query. Vue interpolation escape HTML. Server vẫn chịu trách nhiệm authorize tenant, enforce pagination, rate limiting và search bounds. Không cần thêm state library cho một component độc lập.

## Trade-offs

- Debounce giảm tải nhưng tăng độ trễ cảm nhận; cần đo.
- Clear kết quả khi filter đổi tránh hiển thị tenant cũ nhưng có thể gây flicker.
- BFF cookie giảm exposure của token với JS nhưng phải giải quyết CSRF và session lifecycle.
- Runtime DTO validation tăng độ tin cậy nhưng thêm code/dependency.
- Abort request không đảm bảo backend rollback hoặc ngừng query ngay.

## Cách kiểm thử

1. Playwright: delay A, trả B trước; chỉ hiển thị kết quả B.
2. Security: summary chứa HTML nguy hiểm hiển thị như text; API từ chối tenant không được phép.
3. Failure-path: 401/429/500, malformed JSON và invalid response shape.
4. Load: gõ nhanh 15 ký tự, đo request count, p95 và abort.
5. Lifecycle: unmount giữa debounce/request, không còn update hoặc request mới.

## Quan sát trong production

Frontend RUM: search duration, abort count, error rate, requests/session. Application Insights: request p95/p99, 429/5xx, authorization failures, Elasticsearch dependency latency, trace correlation. Redact search keywords nếu chứa PII; alert khi p95 và error rate vượt baseline.

# Tổng kết hôm nay
