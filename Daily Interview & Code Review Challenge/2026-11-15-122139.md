# Code Review Challenge 1 — Import CSV bị chạy trùng sau horizontal scaling

**Chủ đề:** C#/.NET 8, BackgroundService, PostgreSQL, Azure Blob Storage, multi-tenancy  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 45 phút

## Bối cảnh

Một nền tảng nhân sự import CSV từ Blob Storage, ghi employee vào PostgreSQL. Sau khi Azure App Service scale lên bốn instance, cùng file đôi khi chạy hai lần; có file bị bỏ qua sau lỗi transient. File tối đa 200.000 dòng. Hai tenant có thể sử dụng cùng employee external ID. Cần xử lý restart an toàn và tránh duplicate effect. Các interface Blob là abstraction nội bộ.

## Đoạn code cần review

```csharp
public sealed class ImportWorker(
    IServiceScopeFactory scopes,
    IBlobCatalog blobs,
    ILogger<ImportWorker> log) : BackgroundService
{
    private static readonly HashSet<string> Seen = new();

    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            using var scope = scopes.CreateScope();
            var db = scope.ServiceProvider.GetRequiredService<AppDbContext>();
            var files = await blobs.ListPendingAsync();
            foreach (var file in files)
            {
                if (Seen.Contains(file.Name)) continue;
                Seen.Add(file.Name);
                try
                {
                    var rows = await blobs.ReadCsvAsync(file.Name);
                    await using var tx = await db.Database.BeginTransactionAsync();
                    foreach (var row in rows)
                    {
                        var employee = await db.Employees.FirstOrDefaultAsync(
                            x => x.ExternalId == row.ExternalId);
                        if (employee is null)
                            db.Employees.Add(new Employee {
                                TenantId = file.TenantId,
                                ExternalId = row.ExternalId,
                                Name = row.Name
                            });
                        else employee.Name = row.Name;
                    }
                    await db.SaveChangesAsync();
                    await tx.CommitAsync();
                    await blobs.MarkCompleteAsync(file.Name);
                }
                catch (Exception ex)
                {
                    log.LogError(ex, "Import failed {File}", file.Name);
                }
            }
            await Task.Delay(TimeSpan.FromSeconds(15));
        }
    }
}
```

## Kết quả code review tham khảo

### [Critical] — Không có atomic distributed claim

**Vấn đề:** Mỗi process có `Seen` riêng; HashSet không thread-safe.  
**Tại sao xảy ra:** Nhiều replica đọc cùng danh sách pending.  
**Ảnh hưởng production:** Import trùng và race.  
**Cách sửa:** Database-backed atomic claim với lease, fencing token, unique key theo tenant/blob/version.

### [Critical] — Cross-tenant data modification

**Vấn đề:** Lookup chỉ theo `ExternalId`.  
**Tại sao xảy ra:** ID có thể trùng giữa tenant.  
**Ảnh hưởng production:** Ghi đè dữ liệu tenant khác.  
**Cách sửa:** Query scoped `TenantId`, unique constraint `(TenantId, ExternalId)` và trusted tenant context.

### [High] — Commit và Blob acknowledgement không atomic

**Vấn đề:** Commit DB thành công, `MarkCompleteAsync` có thể fail.  
**Tại sao xảy ra:** Không có shared transaction giữa PostgreSQL và Blob.  
**Ảnh hưởng production:** Retry duplicate.  
**Cách sửa:** Durable import ledger và idempotent upsert; checkpoint transactionally cùng business data.

### [High] — Seen đánh dấu trước success

**Vấn đề:** Transient failure làm file bị skip đến khi process restart.  
**Tại sao xảy ra:** In-memory state không có retry state machine.  
**Ảnh hưởng production:** Backlog im lặng.  
**Cách sửa:** Pending/Processing/Completed/Failed, retry/backoff, lease expiry, quarantine.

### [High] — Tenant-independent blob identity

**Vấn đề:** Chỉ dùng filename, không có version.  
**Tại sao xảy ra:** Blob có thể overwrite, nhiều tenant có cùng name.  
**Ảnh hưởng production:** Bỏ qua file mới.  
**Cách sửa:** Pin Blob version/ETag và include tenant in key.

### [High] — Transaction và tracking quá lớn

**Vấn đề:** N+1 lookup, 200.000 tracked entities, long transaction.  
**Tại sao xảy ra:** Query từng dòng và SaveChanges cuối.  
**Ảnh hưởng production:** Memory/GC, locks, DB latency.  
**Cách sửa:** Streaming, staging/bulk upsert, bounded batches, benchmark.

### [Medium] — Cancellation không propagated

**Vấn đề:** I/O và Delay không nhận `ct`.  
**Tại sao xảy ra:** Token chỉ được kiểm tra đầu vòng lặp.  
**Ảnh hưởng production:** Shutdown chậm, work bị cắt.  
**Cách sửa:** Truyền token mọi async operation, checkpoint sau batch.

### [Medium] — Không phân loại lỗi

**Vấn đề:** Catch-all log không phân biệt invalid CSV và network error.  
**Tại sao xảy ra:** Không có retry policy.  
**Ảnh hưởng production:** Poison file và mất tiến độ.  
**Cách sửa:** Retry bounded, permanent-failure quarantine, error code.

### [Low] — Telemetry thiếu context

**Vấn đề:** Log chỉ chứa file name.  
**Tại sao xảy ra:** Thiếu tenant, version, attempt, duration.  
**Ảnh hưởng production:** Khó điều tra duplicate.  
**Cách sửa:** Structured logging và tracing không chứa PII.

## Phiên bản đề xuất

Code minh họa orchestration; các interface là contract nội bộ, phải triển khai atomic trong database. `ProcessAsync` cần idempotent batch upsert, conditional checkpoint và fencing-token validation trong cùng transaction. Lease renewal phải chạy cho tác vụ vượt TTL.

```csharp
public record ImportKey(string Tenant, string Blob, string Version);
public record ImportLease(ImportKey Key, Guid Fence);

public interface IImportStore
{
    Task<ImportLease?> ClaimAsync(CancellationToken ct);
    Task CompleteAsync(ImportLease lease, CancellationToken ct);
    Task FailAsync(ImportLease lease, CancellationToken ct);
}
public interface IImportProcessor
{
    Task ProcessAsync(ImportLease lease, CancellationToken ct);
}

public sealed class SafeImportWorker(
    IServiceScopeFactory scopes,
    ILogger<SafeImportWorker> logger) : BackgroundService
{
    protected override async Task ExecuteAsync(CancellationToken ct)
    {
        while (!ct.IsCancellationRequested)
        {
            await using var scope = scopes.CreateAsyncScope();
            var store = scope.ServiceProvider.GetRequiredService<IImportStore>();
            var processor = scope.ServiceProvider
                .GetRequiredService<IImportProcessor>();
            var lease = await store.ClaimAsync(ct);
            if (lease is null)
            {
                await Task.Delay(TimeSpan.FromSeconds(5), ct);
                continue;
            }
            try
            {
                await processor.ProcessAsync(lease, ct);
                await store.CompleteAsync(lease, ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                throw;
            }
            catch (Exception ex)
            {
                logger.LogError(ex,
                    "Import failed {Tenant} {Blob} {Version}",
                    lease.Key.Tenant, lease.Key.Blob, lease.Key.Version);
                await store.FailAsync(lease, ct);
            }
        }
    }
}
```

**Implementation invariant:** `ClaimAsync` phải dùng conditional DB update/row lock, không dùng in-memory lock. `CompleteAsync` chỉ thành công với fencing token hiện hành. Crash sau batch commit phải retry an toàn; nếu shutdown khiến `FailAsync` bị cancel, lease expiry phải cho phép recovery. Đừng tuyên bố exactly-once chỉ vì có distributed lock.

## Giải thích thiết kế sau khi sửa

Ledger lưu durable progress, unique constraints bảo vệ data integrity, và fencing ngăn stale worker ghi sau lease expiry. Batch processing giảm lock time và memory.

## Trade-offs

Lease/heartbeat tăng độ phức tạp và cần monitoring; batch nhỏ tăng overhead; queue giảm polling nhưng không thay thế idempotency. Với traffic thấp có thể chọn single worker và database uniqueness thay vì hạ tầng mới.

## Cách kiểm thử

1. Concurrency integration: bốn replica claim cùng một file.
2. Failure injection: crash giữa DB commit và Blob acknowledgement.
3. Security: hai tenant trùng ExternalId.
4. Load: 200.000 dòng, đo allocations, locks và throughput.
5. Lease expiry: stale worker không được commit.

## Quan sát trong production

Theo dõi backlog age, retries, lease expiry, duplicate claim rejection, batch p95, DB waits, memory/GC; trace theo import ID, tenant, blob version, attempt và correlation ID.

## Câu hỏi phỏng vấn mở rộng

1. Nếu external API không hỗ trợ idempotency, bạn xử lý thế nào?
2. Nếu yêu cầu atomic toàn file, staging/commit cần thay đổi gì?
3. Khi nào Azure Functions Blob trigger hợp lý hơn polling?

## Kết quả code review tham khảo

### [Critical] — Hard-coded database credential

**Vấn đề:** Password nằm trong manifest.  
**Tại sao xảy ra:** Secret bị lưu trong deployment artifact.  
**Ảnh hưởng production:** Lộ credential qua repository hoặc log.  
**Cách sửa:** Secret reference/secret manager, RBAC, rotation.

### [High] — Liveness kiểm tra dependency readiness

**Vấn đề:** DB outage khiến liveness fail.  
**Tại sao xảy ra:** Probe dùng sai endpoint.  
**Ảnh hưởng production:** Restart storm.  
**Cách sửa:** Liveness chỉ kiểm tra process-local health.

### [High] — Readiness không kiểm tra khả năng phục vụ

**Vấn đề:** Pod nhận traffic trước warmup hoặc khi DB chưa sẵn sàng.  
**Tại sao xảy ra:** Readiness dùng `/health/live`.  
**Ảnh hưởng production:** 5xx.  
**Cách sửa:** Readiness dùng `/health/ready` với timeout phù hợp.

### [High] — Không có startupProbe

**Vấn đề:** Cold start 25 giây có thể bị kill sớm.  
**Tại sao xảy ra:** Liveness bắt đầu sau ba giây.  
**Ảnh hưởng production:** CrashLoopBackOff.  
**Cách sửa:** Startup budget lớn hơn measured warmup p99.

### [High] — Rollout giảm capacity

**Vấn đề:** maxUnavailable 2 trên ba Pod.  
**Tại sao xảy ra:** Controller được phép giảm available replicas.  
**Ảnh hưởng production:** Overload và 5xx.  
**Cách sửa:** maxUnavailable 0, maxSurge 1 nếu cluster có headroom.

### [High] — Graceful shutdown quá ngắn

**Vấn đề:** terminationGracePeriodSeconds 5.  
**Tại sao xảy ra:** Request đang chạy có thể bị kill.  
**Ảnh hưởng production:** Booking trạng thái không rõ.  
**Cách sửa:** Đo request duration, drain, SIGTERM và endpoint propagation.

### [Medium] — Mutable image tag

**Vấn đề:** `:latest` không pin artifact.  
**Tại sao xảy ra:** Tag có thể đổi.  
**Ảnh hưởng production:** Rollback khó tái lập.  
**Cách sửa:** Pin immutable image digest.

### [Medium] — Resource sizing không có đo đạc

**Vấn đề:** CPU/memory giới hạn tùy ý.  
**Tại sao xảy ra:** Thiếu profiling.  
**Ảnh hưởng production:** Throttling/OOMKill.  
**Cách sửa:** Load test và theo dõi RSS, GC, CPU throttling.

## Giải thích thiết kế sau khi sửa

3. Graceful shutdown: request dài đang chạy khi Pod terminate.
4. Load test: peak traffic trong rollout, đo p95/p99.
5. Security: audit manifest, Secret access và credential rotation.

## Quan sát trong production
