# Code Review Challenge 1 — Cache-aside gây stampede, stale data và trộn dữ liệu tenant dưới tải cao

**Chủ đề:** Caching, concurrency, race condition, multi-tenancy, error handling, observability  
**Độ khó:** Senior+  
**Thời gian review đề xuất:** 30–40 phút  
**Số vấn đề cần tìm:** Khoảng 8–10 vấn đề

## Bối cảnh

Một ASP.NET Core API phục vụ dashboard cho nhiều công ty. Mỗi tenant có bộ cấu hình pricing riêng. Endpoint `/api/pricing/{productId}` được gọi rất nhiều từ web/mobile và một số background jobs.

Team dùng Redis theo mô hình cache-aside để giảm tải PostgreSQL. Bình thường endpoint chạy nhanh, nhưng sau deploy hoặc khi Redis key đồng loạt hết hạn, database CPU tăng đột biến và latency p99 tăng mạnh. Một số khách hàng từng báo nhìn thấy giá của tenant khác trong vài giây. Khi Redis gặp timeout, API đôi lúc trả 500 dù database vẫn hoạt động.

Hệ thống chạy nhiều instance sau load balancer. Mỗi tenant có thể có hàng nghìn request/phút. Pricing được cập nhật bởi admin portal và thay đổi cần phản ánh tương đối nhanh, nhưng không bắt buộc strong consistency tuyệt đối cho mọi read.

## Đoạn code cần review

```csharp
public sealed class PricingService
{
    private readonly AppDbContext _db;
    private readonly IDistributedCache _cache;
    private readonly ILogger<PricingService> _logger;

    public PricingService(AppDbContext db, IDistributedCache cache, ILogger<PricingService> logger)
    {
        _db = db;
        _cache = cache;
        _logger = logger;
    }

    public async Task<PricingDto?> GetPricingAsync(Guid tenantId, Guid productId, CancellationToken cancellationToken)
    {
        var cacheKey = $"pricing:{productId}";

        var cached = await _cache.GetStringAsync(cacheKey, cancellationToken);
        if (cached is not null)
            return JsonSerializer.Deserialize<PricingDto>(cached);

        var pricing = await _db.Pricings
            .Where(x => x.TenantId == tenantId && x.ProductId == productId)
            .Select(x => new PricingDto
            {
                ProductId = x.ProductId,
                Amount = x.Amount,
                Currency = x.Currency,
                UpdatedAt = x.UpdatedAt
            })
            .SingleOrDefaultAsync(cancellationToken);

        if (pricing is null)
            return null;

        await _cache.SetStringAsync(
            cacheKey,
            JsonSerializer.Serialize(pricing),
            new DistributedCacheEntryOptions
            {
                AbsoluteExpirationRelativeToNow = TimeSpan.FromMinutes(10)
            },
            cancellationToken);

        _logger.LogInformation("Pricing cache miss for product {ProductId}", productId);
        return pricing;
    }

    public async Task UpdatePricingAsync(Guid tenantId, Guid productId, decimal amount, CancellationToken cancellationToken)
    {
        var pricing = await _db.Pricings.SingleAsync(
            x => x.TenantId == tenantId && x.ProductId == productId,
            cancellationToken);

        pricing.Amount = amount;
        pricing.UpdatedAt = DateTimeOffset.UtcNow;
        await _db.SaveChangesAsync(cancellationToken);
        await _cache.RemoveAsync($"pricing:{productId}", cancellationToken);
    }
}
```

## Kết quả code review tham khảo

### 1. Cache key không chứa tenantId, gây cross-tenant data leakage

**Problem:** `cacheKey = $"pricing:{productId}"` chỉ dùng `productId`.

**Why it happens:** Database query lọc theo tenant, nhưng cache layer không giữ cùng boundary dữ liệu.

**Production impact:** Nếu hai tenant có cùng `productId`, tenant B có thể nhận dữ liệu tenant A.

**Severity:** Critical

**Recommended fix:** Dùng key như `pricing:{tenantId}:{productId}` và chuẩn hoá cache key convention dùng chung.

### 2. Cache stampede khi key hết hạn

**Problem:** Mọi request miss đều query DB độc lập.

**Why it happens:** Không có single-flight, lock theo key hoặc stale-while-revalidate.

**Production impact:** DB CPU, connection pool và latency có thể spike mạnh sau deploy/expiry.

**Severity:** High

**Recommended fix:** Dùng per-key single-flight trong process; nếu scale-out lớn vẫn chưa đủ, cân nhắc distributed coordination hoặc stale-while-revalidate.

### 3. Redis timeout làm fail read path

**Problem:** Cache exception propagate như lỗi business chính.

**Why it happens:** Cache bị coi như dependency bắt buộc.

**Production impact:** Redis degraded kéo API xuống dù database còn tốt.

**Severity:** High

**Recommended fix:** Với read path, fallback DB khi cache lỗi phù hợp; vẫn propagate cancellation. Set cache lỗi không nên làm fail một read đã lấy được dữ liệu đúng.

### 4. Invalidation sau database commit có thể thất bại

**Problem:** DB commit và Redis remove không cùng transaction.

**Why it happens:** Hai storage độc lập.

**Production impact:** Stale price tồn tại đến TTL nếu remove fail.

**Severity:** High

**Recommended fix:** Thiết kế eventual consistency có chủ đích: TTL phù hợp, retry bounded/outbox nếu business yêu cầu, hoặc versioned keys.

### 5. TTL cố định dễ tạo synchronized expiry

**Problem:** Tất cả key dùng đúng 10 phút.

**Why it happens:** Không có jitter.

**Production impact:** Có thể tạo load spike định kỳ.

**Severity:** Medium

**Recommended fix:** Thêm random jitter vào TTL.

### 6. Không negative-cache dữ liệu không tồn tại

**Problem:** Miss DB không được cache.

**Production impact:** Request lặp lại cho ID không tồn tại tiếp tục đánh DB.

**Severity:** Medium

**Recommended fix:** Cân nhắc negative cache TTL ngắn nếu semantics cho phép.

### 7. Logging mọi miss ở Information tạo noise

**Problem:** Mỗi miss tạo log riêng.

**Production impact:** Khi cache lạnh, log volume tăng đúng lúc hệ thống chịu tải.

**Severity:** Medium

**Recommended fix:** Dùng metrics hit/miss, sampled logs hoặc warning theo threshold.

### 8. Thiếu observability cho cache latency/fallback

**Problem:** Không đo Redis duration, DB fallback, lock wait.

**Production impact:** Khó phân biệt bottleneck.

**Severity:** Medium

**Recommended fix:** Thêm metrics/traces với cardinality kiểm soát.

## Phiên bản code đề xuất

```csharp
public sealed class PricingService
{
    private static readonly ConcurrentDictionary<string, SemaphoreSlim> Locks = new();

    private readonly AppDbContext _db;
    private readonly IDistributedCache _cache;
    private readonly ILogger<PricingService> _logger;

    public PricingService(AppDbContext db, IDistributedCache cache, ILogger<PricingService> logger)
    {
        _db = db;
        _cache = cache;
        _logger = logger;
    }

    public async Task<PricingDto?> GetPricingAsync(Guid tenantId, Guid productId, CancellationToken ct)
    {
        var key = $"pricing:{tenantId:N}:{productId:N}";

        var cached = await TryGetAsync(key, ct);
        if (cached is not null)
            return cached;

        var gate = Locks.GetOrAdd(key, _ => new SemaphoreSlim(1, 1));
        await gate.WaitAsync(ct);

        try
        {
            cached = await TryGetAsync(key, ct);
            if (cached is not null)
                return cached;

            var pricing = await _db.Pricings
                .AsNoTracking()
                .Where(x => x.TenantId == tenantId && x.ProductId == productId)
                .Select(x => new PricingDto
                {
                    ProductId = x.ProductId,
                    Amount = x.Amount,
                    Currency = x.Currency,
                    UpdatedAt = x.UpdatedAt
                })
                .SingleOrDefaultAsync(ct);

            if (pricing is null)
                return null;

            try
            {
                await _cache.SetStringAsync(
                    key,
                    JsonSerializer.Serialize(pricing),
                    new DistributedCacheEntryOptions
                    {
                        AbsoluteExpirationRelativeToNow =
                            TimeSpan.FromMinutes(9) + TimeSpan.FromSeconds(Random.Shared.Next(0, 90))
                    },
                    ct);
            }
            catch (OperationCanceledException) when (ct.IsCancellationRequested)
            {
                throw;
            }
            catch (Exception ex)
            {
                _logger.LogWarning(ex, "Pricing cache populate failed");
            }

            return pricing;
        }
        finally
        {
            gate.Release();
        }
    }

    private async Task<PricingDto?> TryGetAsync(string key, CancellationToken ct)
    {
        try
        {
            var json = await _cache.GetStringAsync(key, ct);
            return json is null ? null : JsonSerializer.Deserialize<PricingDto>(json);
        }
        catch (OperationCanceledException) when (ct.IsCancellationRequested)
        {
            throw;
        }
        catch (Exception ex)
        {
            _logger.LogWarning(ex, "Pricing cache read failed");
            return null;
        }
    }
}
```

Lưu ý: dictionary chứa semaphore cần cleanup nếu key space lớn; production có thể dùng keyed-lock abstraction có eviction.

## Trade-offs

- Local single-flight đơn giản và rẻ nhưng không đồng bộ giữa nhiều instance.
- Distributed lock giảm stampede xuyên instance nhưng thêm network/failure mode.
- Stale-while-revalidate tăng availability nhưng chấp nhận stale data có kiểm soát.
- TTL dài giảm DB load nhưng tăng stale window.
- Nếu pricing phải chính xác tuyệt đối ngay sau update, cache policy cần nghiêm ngặt hơn.

## Cách kiểm thử

1. 200–500 request đồng thời cùng miss một key; đo số query DB.
2. Hai tenant dùng cùng `productId`; xác minh không bao giờ nhận chéo dữ liệu.
3. Redis timeout; read vẫn fallback DB và không trả 500 chỉ vì cache fail.
4. DB update thành công nhưng invalidation fail; xác minh behavior nằm trong stale policy.
5. Load test expiry burst; theo dõi DB CPU, connection pool, p95/p99.

## Quan sát trong production

- Metrics: hit/miss ratio, Redis latency, fallback count, populate/invalidation failures, lock wait.
- Logs: warning khi cache degraded; không log identifiers nhạy cảm không cần thiết.
- Traces: Redis GET/SET, DB query, lock wait trong cùng trace.
- Alerts: miss/error rate tăng, DB CPU/connection spike, p99 tăng cùng Redis errors.

## Bối cảnh

Một ASP.NET Core API có endpoint cho manager tải ZIP chứa hồ sơ và tài liệu của nhân viên. Dữ liệu metadata nằm trong database, file nằm trong storage thông qua `IFileStore`.

Endpoint chỉ dành cho manager có quyền trên đúng tenant/phòng ban. File có thể từ vài MB đến vài trăm MB. Security team phát hiện manager tenant A có thể đoán `employeeId` tenant B và tải được ZIP. Production cũng từng memory spike khi nhiều export chạy đồng thời; một số request đã bị client huỷ nhưng server vẫn tiếp tục tải/nén.

## Đoạn code cần review

```csharp
[ApiController]
[Route("api/employees")]
public sealed class EmployeeExportController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly IFileStore _fileStore;
    private readonly ILogger<EmployeeExportController> _logger;

    public EmployeeExportController(
        AppDbContext db,
        IFileStore fileStore,
        ILogger<EmployeeExportController> logger)
    {
        _db = db;
        _fileStore = fileStore;
        _logger = logger;
    }

    [HttpGet("{employeeId:guid}/export")]
    [Authorize(Roles = "Manager")]
    public async Task<IActionResult> Export(Guid employeeId)
    {
        var employee = await _db.Employees
            .Include(x => x.Documents)
            .SingleOrDefaultAsync(x => x.Id == employeeId);

        if (employee is null)
            return NotFound();

        await using var zipBuffer = new MemoryStream();

        using (var archive = new ZipArchive(zipBuffer, ZipArchiveMode.Create, leaveOpen: true))
        {
            foreach (var document in employee.Documents)
            {
                var bytes = await _fileStore.DownloadAsync(document.StoragePath);
                var entry = archive.CreateEntry(document.FileName);
                await using var entryStream = entry.Open();
                await entryStream.WriteAsync(bytes);
            }
        }

        _logger.LogInformation(
            "Manager {User} exported employee {EmployeeId} with {DocumentCount} documents",
            User.Identity!.Name,
            employee.Id,
            employee.Documents.Count);

        return File(zipBuffer.ToArray(), "application/zip", $"{employee.FullName}-documents.zip");
    }
}
```

## Kết quả code review tham khảo

### 1. Chỉ kiểm tra role, không kiểm tra quyền trên employee cụ thể

**Problem:** Role `Manager` không chứng minh user được quyền với resource này.

**Why it happens:** Authorization coarse-grained.

**Production impact:** IDOR/BOLA-style cross-tenant data exposure.

**Severity:** Critical

**Recommended fix:** Scope query bằng tenant server-side và dùng resource-based authorization/policy.

### 2. Load toàn bộ document vào `byte[]`

**Problem:** Mỗi file được materialize hoàn toàn.

**Production impact:** LOH/GC pressure và OOM dưới concurrency.

**Severity:** High

**Recommended fix:** Storage API trả stream và copy theo buffer giới hạn.

### 3. Build toàn bộ ZIP trong `MemoryStream`

**Problem:** ZIP hoàn chỉnh tồn tại trong RAM.

**Production impact:** Memory amplification với file lớn.

**Severity:** High

**Recommended fix:** Stream trực tiếp hoặc background-generate artifact cho export lớn.

### 4. `ToArray()` tạo thêm bản sao toàn bộ ZIP

**Problem:** Allocate byte array mới bằng kích thước ZIP.

**Production impact:** Peak memory tăng thêm đáng kể.

**Severity:** High

**Recommended fix:** Tránh `File(byte[])`; dùng streaming result.

### 5. Không propagate cancellation

**Problem:** DB/storage/copy không dùng `RequestAborted`.

**Production impact:** Client disconnect nhưng server vẫn tải/nén.

**Severity:** High

**Recommended fix:** Nhận `CancellationToken` và truyền xuyên xuống dependency.

### 6. `document.FileName` không được sanitize

**Problem:** Có thể chứa path separators, `../`, control chars hoặc tên trùng.

**Production impact:** Archive entries không an toàn/khó kiểm soát; downstream extraction tool không an toàn có thể gặp zip-slip risk.

**Severity:** High

**Recommended fix:** Dùng basename, loại separators/control chars, giới hạn length và xử lý duplicates.

### 7. Entity graph tracking không cần thiết

**Problem:** `Include` materialize/tracking toàn bộ graph.

**Production impact:** Thêm memory/CPU.

**Severity:** Medium

**Recommended fix:** `AsNoTracking()` + projection đúng field cần.

### 8. Audit log chưa có policy rõ ràng

**Problem:** Log raw identity và employee id nhưng thiếu normalized actor/tenant/outcome/trace semantics.

**Production impact:** Có thể vừa lộ PII vừa khó audit incident.

**Severity:** Medium

**Recommended fix:** Structured security audit theo policy, hạn chế PII và retention/access control phù hợp.

### 9. Không giới hạn tổng kích thước/số file export

**Problem:** Request hợp lệ vẫn có thể cực lớn.

**Production impact:** Internal resource exhaustion.

**Severity:** Medium

**Recommended fix:** Guardrail và chuyển job lớn sang async processing.

## Phiên bản code đề xuất

```csharp
[ApiController]
[Route("api/employees")]
public sealed class EmployeeExportController : ControllerBase
{
    private readonly AppDbContext _db;
    private readonly IFileStore _fileStore;
    private readonly IAuthorizationService _authorization;
    private readonly ICurrentTenant _currentTenant;

    public EmployeeExportController(
        AppDbContext db,
        IFileStore fileStore,
        IAuthorizationService authorization,
        ICurrentTenant currentTenant)
    {
        _db = db;
        _fileStore = fileStore;
        _authorization = authorization;
        _currentTenant = currentTenant;
    }

    [HttpGet("{employeeId:guid}/export")]
    [Authorize(Roles = "Manager")]
    public async Task Export(Guid employeeId, CancellationToken ct)
    {
        var employee = await _db.Employees
            .AsNoTracking()
            .Where(x => x.Id == employeeId && x.TenantId == _currentTenant.Id)
            .Select(x => new
            {
                x.Id,
                Documents = x.Documents.Select(d => new
                {
                    d.Id,
                    d.FileName,
                    d.StoragePath
                }).ToList()
            })
            .SingleOrDefaultAsync(ct);

        if (employee is null)
        {
            Response.StatusCode = StatusCodes.Status404NotFound;
            return;
        }

        var allowed = await _authorization.AuthorizeAsync(
            User,
            employee.Id,
            "CanExportEmployeeDocuments");

        if (!allowed.Succeeded)
        {
            Response.StatusCode = StatusCodes.Status403Forbidden;
            return;
        }

        Response.StatusCode = StatusCodes.Status200OK;
        Response.ContentType = "application/zip";
        Response.Headers.ContentDisposition =
            $"attachment; filename=\"employee-{employee.Id:N}-documents.zip\"";

        await using var archive = new ZipArchive(Response.Body, ZipArchiveMode.Create, leaveOpen: true);

        foreach (var document in employee.Documents)
        {
            ct.ThrowIfCancellationRequested();

            var safeName = Path.GetFileName(document.FileName);
            if (string.IsNullOrWhiteSpace(safeName))
                safeName = $"document-{document.Id:N}";

            var entry = archive.CreateEntry(safeName, CompressionLevel.Fastest);
            await using var source = await _fileStore.OpenReadAsync(document.StoragePath, ct);
            await using var destination = entry.Open();
            await source.CopyToAsync(destination, 64 * 1024, ct);
        }
    }
}
```

Nếu export lớn/mất nhiều phút, background export job + blob artifact + short-lived authorized download flow phù hợp hơn synchronous streaming.

## Trade-offs

- Streaming trực tiếp ít memory nhưng giữ request lâu và lỗi giữa chừng có thể tạo partial ZIP.
- Background export tốt cho artifact lớn/retry/progress nhưng cần state machine, cleanup và authorization khi download.
- Pre-generated artifact giảm compute lặp lại nhưng tăng storage/staleness risk.
- Resource-based authorization tăng complexity nhưng cần thiết với dữ liệu multi-tenant nhạy cảm.
- Compression mạnh giảm bandwidth nhưng tăng CPU.

## Cách kiểm thử

1. Manager tenant A export employee tenant B phải bị từ chối.
2. Load test nhiều export file lớn; working set/GC phải bounded.
3. Client disconnect giữa chừng; storage/copy phải cancel.
4. Filename chứa `../`, separator, control chars, duplicate names; ZIP phải được normalize theo policy.
5. Storage timeout giữa chừng; resources phải dispose và không retry vô hạn.

## Quan sát trong production

- Logs/Audit: actor id, tenant id, resource id, outcome, document count, trace id; tránh PII không cần thiết.
- Metrics: active exports, duration, bytes streamed, cancellations, storage failures, authorization denials.
- Traces: DB/resource auth, policy decision, storage reads, streaming duration.
- Alerts: export failure rate, active export count, memory/GC, storage latency.

## Câu hỏi phỏng vấn mở rộng

1. Nếu export lên tới 5–10 GB, bạn thiết kế kiến trúc khác thế nào?
2. Bạn chọn 403 hay 404 cho resource ngoài tenant và trade-off là gì?
3. Nếu export chạy background và lưu Blob, bạn bảo vệ link download và cleanup artifact ra sao?

# Tổng kết hôm nay

## Kiến thức trọng tâm

- Cache key phải giữ nguyên security/data boundary của nguồn dữ liệu.
- Cache-aside cần được thiết kế cùng failure behavior, stampede control, TTL và invalidation semantics.
- Role-based authorization không thay thế resource-based authorization.
- Với file lớn, tránh materialize nhiều bản sao trong RAM; streaming và cancellation là phần của correctness.
- Observability phải giúp phân biệt dependency latency, contention, fallback và authorization failures.

## Mẫu tư duy cần nhớ

- Security boundary phải nhất quán ở database, cache, API và background processing.
- Cache là optimization; cache outage không nên mặc định trở thành application outage.
- Khi thấy memory spike, vẽ data flow và đếm số bản sao dữ liệu tồn tại đồng thời.
- Authorization phải trả lời “user này có quyền trên resource này không?”, không chỉ “user có role gì?”.
- Thiết kế cancellation và observability ngay từ đầu cho I/O dài.
