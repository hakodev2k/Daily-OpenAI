# Daily Developer Tips & Design — 2026-08-17

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `ValueTask` đúng trường hợp trong C#

**Mẹo:**
Sử dụng `ValueTask` cho các API async có khả năng trả kết quả đồng bộ thường xuyên.

**Tại sao hữu ích:**
Giảm allocation của `Task` trong các hot path như cache lookup hoặc high-throughput service.

**Ví dụ:**
```csharp
public ValueTask<User?> GetUserAsync(string id)
{
    if (_cache.TryGetValue(id, out User user))
        return ValueTask.FromResult<User?>(user);
    return LoadFromDatabaseAsync(id);
}
```

**Lưu ý:**
Không thay toàn bộ `Task` bằng `ValueTask` vì complexity cao hơn.

### Tip 2 — Sử dụng `AsNoTracking()` khi đọc dữ liệu EF Core

**Mẹo:**
Dùng `AsNoTracking()` cho query chỉ đọc.

**Tại sao hữu ích:**
Giảm memory usage và tăng performance vì EF Core không cần tracking entity.

**Ví dụ:**
```csharp
var users = await db.Users.AsNoTracking().ToListAsync();
```

**Lưu ý:**
Không dùng khi cần update entity sau query.

### Tip 3 — Debug production bằng Correlation ID

**Mẹo:**
Gắn `CorrelationId` xuyên suốt request, log và external call.

**Tại sao hữu ích:**
Dễ trace một workflow qua nhiều service.

**Ví dụ:**
```csharp
using (_logger.BeginScope(new Dictionary<string, object>{{"CorrelationId", id}}))
{
    await HandleAsync();
}
```

**Lưu ý:**
Không log dữ liệu nhạy cảm chỉ để phục vụ tracing.

### Tip 4 — Dùng `git reflog` để khôi phục thay đổi

**Mẹo:**
Kiểm tra `git reflog` trước khi cho rằng commit đã mất.

**Tại sao hữu ích:**
Khôi phục được sau reset, rebase hoặc checkout nhầm.

**Ví dụ:**
```bash
git reflog
git checkout <commit-sha>
```

**Lưu ý:**
Không thay thế backup dài hạn.

### Tip 5 — Dùng Health Check cho dependency

**Mẹo:**
Expose health endpoint cho database, cache và external service.

**Tại sao hữu ích:**
Monitoring và orchestrator biết service có thực sự sẵn sàng.

**Ví dụ:**
```csharp
builder.Services.AddHealthChecks().AddSqlServer(connectionString);
```

**Lưu ý:**
Không đưa dependency nặng vào liveness check.

## 🧠 Software Design

### Design 1 — Anti-Corruption Layer trong Domain Design

**Khái niệm:**
Tạo lớp chuyển đổi giữa domain model nội bộ và external model.

**Vấn đề nó giải quyết:**
Ngăn dependency bên ngoài làm nhiễm business logic.

**Ví dụ thực tế:**
CRM integration dùng adapter để chuyển Customer DTO thành domain entity.

**Trade-off:**
Tăng code mapping nhưng bảo vệ domain boundary.

**Middle → Senior insight:**
Middle cần biết tách integration code. Senior cần quyết định boundary nào cần bảo vệ.

### Design 2 — Eventual Consistency trong Distributed System

**Khái niệm:**
Cho phép dữ liệu đồng bộ sau một khoảng thời gian thay vì nhất quán ngay lập tức.

**Vấn đề nó giải quyết:**
Giảm coupling và tăng khả năng scale giữa các service.

**Ví dụ thực tế:**
Order service publish event để Inventory service cập nhật tồn kho.

**Trade-off:**
Tăng availability nhưng cần retry, compensation và xử lý trạng thái tạm thời.

**Middle → Senior insight:**
Senior cần đánh giá business requirement trước khi chọn consistency model.

### Design 3 — API Versioning Strategy

**Khái niệm:**
Quản lý thay đổi API mà không phá vỡ client hiện tại.

**Vấn đề nó giải quyết:**
Cho phép phát triển API trong môi trường có nhiều consumer.

**Ví dụ thực tế:**
Tạo `/api/v2/orders` khi thay đổi response contract lớn.

**Trade-off:**
Backward compatibility tốt hơn nhưng tăng chi phí maintain nhiều version.

**Middle → Senior insight:**
Senior cần phân biệt breaking change và migration strategy thay vì version mọi thay đổi nhỏ.
