# Daily Developer Tips & Design — 2026-08-18

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `required` keyword trong C# để bảo vệ object initialization

**Mẹo:**
Sử dụng `required` property khi object bắt buộc phải có dữ liệu hợp lệ ngay khi khởi tạo.

**Tại sao hữu ích:**
Giảm bug do thiếu field quan trọng và làm rõ contract của class.

**Ví dụ:**
```csharp
public class UserRequest
{
    public required string Email { get; init; }
}
```

**Lưu ý:**
Không thay thế hoàn toàn validation runtime vì dữ liệu bên ngoài vẫn cần kiểm tra.

### Tip 2 — Dùng `QueryTagging` trong EF Core để trace SQL

**Mẹo:**
Thêm tag vào query để dễ liên kết LINQ code với SQL trong database monitoring.

**Tại sao hữu ích:**
Hữu ích khi điều tra query chậm trong production.

**Ví dụ:**
```csharp
var orders = await db.Orders
    .TagWith("Get pending orders report")
    .ToListAsync();
```

**Lưu ý:**
Không thêm tag quá dài hoặc chứa thông tin nhạy cảm.

### Tip 3 — Dùng `git bisect` để tìm commit gây lỗi

**Mẹo:**
Dùng binary search của Git để nhanh chóng xác định commit làm phát sinh bug.

**Tại sao hữu ích:**
Tiết kiệm thời gian khi regression xuất hiện sau nhiều thay đổi.

**Ví dụ:**
```bash
git bisect start
git bisect bad
git bisect good v1.0
```

**Lưu ý:**
Cần có cách kiểm tra pass/fail rõ ràng cho từng commit.

### Tip 4 — Dùng Health Check để kiểm tra dependency của service

**Mẹo:**
Expose health endpoint cho database, cache, message broker hoặc external service.

**Tại sao hữu ích:**
Giúp Kubernetes, load balancer và monitoring phát hiện trạng thái service.

**Ví dụ:**
```csharp
builder.Services.AddHealthChecks()
    .AddSqlServer(connectionString);
```

**Lưu ý:**
Không để health check phụ thuộc quá nhiều khiến endpoint trở thành bottleneck.

### Tip 5 — Dùng `ConfigureAwait(false)` đúng ngữ cảnh trong library code

**Mẹo:**
Trong reusable library, có thể dùng `ConfigureAwait(false)` để tránh capture synchronization context.

**Tại sao hữu ích:**
Giảm nguy cơ deadlock trong một số môi trường đặc biệt.

**Ví dụ:**
```csharp
await stream.ReadAsync(buffer).ConfigureAwait(false);
```

**Lưu ý:**
ASP.NET Core thường không có SynchronizationContext nên không cần lạm dụng.

## 🧠 Software Design

### Design 1 — Separation of Concerns trong Layer Design

**Khái niệm:**
Mỗi component nên chịu trách nhiệm cho một nhóm vấn đề rõ ràng thay vì trộn business logic, persistence và presentation.

**Vấn đề nó giải quyết:**
Giảm coupling và giúp thay đổi một phần hệ thống mà không ảnh hưởng toàn bộ.

**Ví dụ thực tế:**
Controller xử lý HTTP concern, Application Service xử lý use case, Repository xử lý data access.

**Trade-off:**
Boundary rõ ràng tăng maintainability nhưng có thể tạo thêm abstraction nếu áp dụng quá mức.

**Middle → Senior insight:**
Middle cần biết tách trách nhiệm. Senior cần quyết định boundary dựa trên thay đổi thực tế của hệ thống.

### Design 2 — Event-Driven Architecture và Eventual Consistency

**Khái niệm:**
Các component giao tiếp thông qua event thay vì gọi trực tiếp, cho phép xử lý bất đồng bộ.

**Vấn đề nó giải quyết:**
Giảm coupling giữa các service và tăng khả năng mở rộng.

**Ví dụ thực tế:**
OrderCreated event kích hoạt Payment, Notification và Analytics service.

**Trade-off:**
Scale tốt hơn nhưng debugging và consistency trở nên phức tạp hơn.

**Middle → Senior insight:**
Senior cần biết khi nào eventual consistency chấp nhận được và khi nào business yêu cầu strong consistency.

### Design 3 — API Versioning Strategy

**Khái niệm:**
API versioning giúp hệ thống thay đổi contract mà không phá vỡ client hiện tại.

**Vấn đề nó giải quyết:**
Quản lý backward compatibility trong hệ thống có nhiều consumer.

**Ví dụ thực tế:**
`/api/v1/orders` tiếp tục hỗ trợ client cũ trong khi `/api/v2/orders` có response mới.

**Trade-off:**
Versioning tăng khả năng tương thích nhưng làm tăng chi phí maintenance.

**Middle → Senior insight:**
Senior không chỉ thêm version mà cần xác định khi nào breaking change đáng để tạo version mới.
