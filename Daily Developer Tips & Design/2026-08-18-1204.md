# Daily Developer Tips & Design — 2026-08-18

## 🛠 Developer Tips & Tricks

### Tip 1 — Dùng `CancellationToken` xuyên suốt async workflow

**Mẹo:**
Truyền `CancellationToken` từ API endpoint xuống service, database call và background task.

**Tại sao hữu ích:**
Giúp hủy request không còn cần thiết, giảm resource usage và tránh xử lý dư thừa.

**Ví dụ:**
```csharp
public async Task ProcessAsync(CancellationToken cancellationToken)
{
    await db.Users.ToListAsync(cancellationToken);
}
```

**Lưu ý:**
Không nên bỏ qua cancellation ở các operation dài như file processing, HTTP call hoặc batch job.

### Tip 2 — Dùng `ConfigureAwait(false)` trong library code

**Mẹo:**
Trong reusable library hoặc code không phụ thuộc UI context, dùng `ConfigureAwait(false)` để tránh capture synchronization context.

**Tại sao hữu ích:**
Giảm overhead và tránh một số deadlock scenario trong môi trường cũ.

**Ví dụ:**
```csharp
await service.CallAsync().ConfigureAwait(false);
```

**Lưu ý:**
ASP.NET Core không có SynchronizationContext mặc định, nên không cần lạm dụng trong application code.

### Tip 3 — Kiểm tra HTTP response headers khi debug API

**Mẹo:**
Đừng chỉ nhìn response body; kiểm tra headers như `Cache-Control`, `ETag`, `Retry-After`, `Correlation-Id`.

**Tại sao hữu ích:**
Nhiều lỗi production liên quan cache, retry hoặc tracing nằm ở HTTP metadata.

**Ví dụ:**
```bash
curl -I https://api.example.com/orders
```

**Lưu ý:**
Không expose thông tin nhạy cảm như internal server headers.

### Tip 4 — Dùng Docker multi-stage build để giảm image size

**Mẹo:**
Tách build environment và runtime environment trong Dockerfile.

**Tại sao hữu ích:**
Image nhỏ hơn, deploy nhanh hơn và giảm attack surface.

**Ví dụ:**
```dockerfile
FROM mcr.microsoft.com/dotnet/sdk:8.0 AS build
FROM mcr.microsoft.com/dotnet/aspnet:8.0 AS runtime
```

**Lưu ý:**
Không copy toàn bộ source code hoặc SDK vào production image nếu không cần thiết.

### Tip 5 — Dùng structured logging thay vì string interpolation

**Mẹo:**
Ghi log theo template để hệ thống observability có thể query field.

**Tại sao hữu ích:**
Dễ tìm kiếm, filter và phân tích lỗi production.

**Ví dụ:**
```csharp
logger.LogInformation("Order {OrderId} created by {UserId}", order.Id, user.Id);
```

**Lưu ý:**
Không log password, token hoặc dữ liệu cá nhân nhạy cảm.

## 🧠 Software Design

### Design 1 — Anti-Corruption Layer trong Domain-Driven Design

**Khái niệm:**
Anti-Corruption Layer tạo lớp chuyển đổi giữa hệ thống hiện tại và hệ thống bên ngoài để bảo vệ domain model.

**Vấn đề nó giải quyết:**
Ngăn external model, API contract hoặc legacy system làm ô nhiễm business logic.

**Ví dụ thực tế:**
Hệ thống ERP tích hợp payment gateway có model transaction khác với domain Payment nội bộ.

**Trade-off:**
Tăng code mapping nhưng giữ domain sạch và dễ thay đổi.

**Middle → Senior insight:**
Middle cần biết mapping không phải code thừa. Senior cần xác định boundary nào cần bảo vệ.

### Design 2 — Eventual Consistency trong Distributed System

**Khái niệm:**
Eventual Consistency cho phép các hệ thống đạt trạng thái đồng nhất sau một khoảng thời gian thay vì đồng bộ tức thời.

**Vấn đề nó giải quyết:**
Giúp hệ thống scale tốt khi nhiều service cần giao tiếp độc lập.

**Ví dụ thực tế:**
Order Service tạo đơn hàng, sau đó publish event để Inventory Service cập nhật tồn kho.

**Trade-off:**
Tăng availability nhưng business flow phải xử lý trạng thái pending và retry.

**Middle → Senior insight:**
Senior cần biết khi nào chấp nhận delay consistency và khi nào bắt buộc strong consistency.

### Design 3 — API Versioning Strategy

**Khái niệm:**
API Versioning giúp phát triển API mới mà không phá vỡ client hiện tại.

**Vấn đề nó giải quyết:**
Quản lý thay đổi contract trong hệ thống có nhiều consumer.

**Ví dụ thực tế:**
Thay đổi response Order từ `customerName` sang object `customer` có thể tạo `/api/v2/orders`.

**Trade-off:**
Versioning tăng khả năng tương thích nhưng làm tăng chi phí maintenance.

**Middle → Senior insight:**
Middle cần biết breaking change. Senior cần thiết kế API evolution strategy trước khi contract được sử dụng rộng rãi.
