# Câu 1 — EF Core Tracking và query execution trong production

**Loại câu hỏi:** Internal mechanism
**Độ khó:** Senior
**Kỹ năng được đánh giá:** EF Core internals, performance diagnosis

## Bối cảnh
Một ASP.NET Core API phục vụ dashboard quản trị. Khi dữ liệu tăng lên vài triệu bản ghi, latency và memory tăng. Developer đã thêm Include và xử lý LINQ trong service nhưng chưa rõ nguyên nhân.

## Câu hỏi chính
Giải thích EF Core thực hiện query, tracking, deferred execution và materialization như thế nào. Vì sao có thể gây vấn đề production? Bạn xác minh bằng cách nào?

## Gợi ý tư duy
- Phân biệt database execution và application execution.
- Kiểm tra SQL generated, execution plan, memory.
- Tối ưu theo workload thay vì áp dụng mặc định.

## Hướng giải quyết tham khảo
Xác định read/write requirement, dùng projection DTO khi phù hợp, AsNoTracking cho read-only, kiểm tra query plan, index và metrics trước khi thay đổi.

# Câu 2 — Production incident: API latency tăng sau deployment

**Loại câu hỏi:** Production incident
**Độ khó:** Senior+

## Bối cảnh
API .NET sau deployment có p95 latency tăng từ 300ms lên 4s. CPU tăng nhẹ, database chưa quá tải, một số request timeout.

## Câu hỏi chính
Bạn xử lý incident từ mitigation đến root cause, fix và prevention như thế nào?

## Gợi ý tư duy
- Stabilize trước khi investigate.
- Thu thập logs, metrics, traces.
- Xem xét code, database, dependency và infrastructure.

## Hướng giải quyết tham khảo
Rollback nếu cần, phân tích telemetry, so sánh release diff, kiểm tra dependency, thread pool, connection pool, SQL và bổ sung regression test cùng monitoring.

# Câu 3 — AI Code Review Agent

**Loại câu hỏi:** AI engineering
**Độ khó:** Senior+

## Bối cảnh
Team muốn xây dựng agent review Pull Request cho repository .NET. Agent có thể đọc code, chạy tool và đề xuất comment.

## Câu hỏi chính
Thiết kế agent như thế nào để tránh hallucination, bảo vệ source code và đo chất lượng output?

## Gợi ý tư duy
- AI không thay thế deterministic validation.
- Context, tools, permissions cần giới hạn.
- Cần evaluation loop.

## Hướng giải quyết tham khảo
Dùng context selection, rules, analyzers, tests, structured output, human approval, audit log và đo false positive/false negative, cost, latency.

# Tổng kết hôm nay

## Kiến thức trọng tâm
- Hiểu runtime behavior trước khi tối ưu.
- Incident response dựa trên evidence.
- AI production cần validation và evaluation.

## Mẫu tư duy cần nhớ
- Clarify before designing.
- Measure before optimizing.
- Design retries together with idempotency.
- Treat observability as part of architecture.
- Validate AI output deterministically.
