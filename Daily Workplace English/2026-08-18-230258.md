# Daily Workplace English — Ngày 4

- **Date in Vietnam time:** 18/08/2026
- **Workplace situation:** Requesting code review for a database migration with a potential production risk
- **Main communication skill:** Yêu cầu code review rõ ràng, nêu risk và hướng người reviewer tập trung đúng chỗ
- **Estimated study time:** 15–25 phút
- **Difficulty:** Elementary

## 1. Tình huống hôm nay

Bạn vừa hoàn thành một pull request cho một thay đổi trong ASP.NET Core service. PR này thêm một Entity Framework Core migration để tạo index mới trên bảng lớn trong SQL Server. Thay đổi nhìn qua khá đơn giản, nhưng bạn biết rằng database migration có thể ảnh hưởng đến thời gian deploy hoặc gây lock nếu chạy trên dữ liệu production lớn.

Bạn cần nhờ một Senior Developer review PR. Tuy nhiên, thay vì chỉ viết “Please review my PR”, bạn muốn giải thích ngắn gọn thay đổi chính, chỉ ra phần có risk, nói bạn đã kiểm tra gì, và nhờ reviewer tập trung vào migration strategy.

Rủi ro giao tiếp là gửi một request quá chung chung khiến reviewer không biết đâu là phần quan trọng, hoặc ngược lại viết quá dài khiến message khó đọc.

## 2. Bạn cần nói gì?

Mục tiêu giao tiếp hôm nay gồm năm điểm:

- Nói rõ bạn cần code review.
- Tóm tắt thay đổi chính trong 1–2 câu.
- Chỉ ra phần bạn muốn reviewer chú ý.
- Nói ngắn gọn bạn đã kiểm tra những gì.
- Nêu risk hoặc câu hỏi còn chưa chắc chắn.

Một cấu trúc hữu ích:

**Request → Summary → Risk → What I checked → Specific review focus**

## 3. Đoạn hội thoại hoặc mẫu trình bày

**Developer:** Could you take a look at my PR when you have a moment?

Bạn có thể xem giúp PR của tôi khi bạn có thời gian không?

**Reviewer:** Sure. What does it change?

Được. PR thay đổi gì vậy?

**Developer:** It adds an index to the `EmployeeEvents` table to improve a slow query used by the reporting API.

Nó thêm một index vào bảng `EmployeeEvents` để cải thiện một query chậm được reporting API sử dụng.

**Developer:** The code change is small, but I’d like a second pair of eyes on the migration because the table is quite large in production.

Phần code thay đổi không nhiều, nhưng tôi muốn có thêm một người kiểm tra migration vì bảng này khá lớn trên production.

**Reviewer:** Have you tested the migration locally?

Bạn đã test migration ở local chưa?

**Developer:** Yes. I tested it against a copy of the schema and checked the generated SQL. I haven’t tested it with production-scale data yet.

Rồi. Tôi đã test với một bản copy của schema và kiểm tra SQL được generate. Tôi chưa test với lượng dữ liệu tương đương production.

**Developer:** Could you focus on whether we should create the index in the normal deployment or handle it separately?

Bạn có thể tập trung review xem chúng ta nên tạo index trong deployment thông thường hay xử lý nó riêng không?

**Reviewer:** Yes, I’ll check that part carefully.

Được, tôi sẽ xem kỹ phần đó.

## 4. Các cụm từ quan trọng

### 1. “Could you take a look at my PR?”

- **Nghĩa:** Bạn có thể xem giúp PR của tôi không?
- **Khi dùng:** Cách tự nhiên để request code review.
- **Ví dụ:** “Could you take a look at my PR before the release branch is cut?”

### 2. “I’d like a second pair of eyes on …”

- **Nghĩa:** Tôi muốn có thêm một người kiểm tra kỹ …
- **Khi dùng:** Khi một phần thay đổi có risk hoặc bạn muốn validation thêm.
- **Ví dụ:** “I’d like a second pair of eyes on the retry logic.”

### 3. “The main thing I’d like you to check is …”

- **Nghĩa:** Điều chính tôi muốn bạn kiểm tra là …
- **Khi dùng:** Khi muốn hướng reviewer đến phần quan trọng nhất.
- **Ví dụ:** “The main thing I’d like you to check is the authorization flow.”

### 4. “I tested it against …”

- **Nghĩa:** Tôi đã test nó với …
- **Khi dùng:** Khi báo phạm vi verification bạn đã thực hiện.
- **Ví dụ:** “I tested it against our staging API.”

### 5. “I haven’t tested it with … yet.”

- **Nghĩa:** Tôi vẫn chưa test nó với …
- **Khi dùng:** Khi muốn minh bạch về giới hạn của việc kiểm tra hiện tại.
- **Ví dụ:** “I haven’t tested it with a large file yet.”

### 6. “Could you focus on whether …?”

- **Nghĩa:** Bạn có thể tập trung kiểm tra xem liệu … không?
- **Khi dùng:** Khi cần reviewer đưa ý kiến về một trade-off hoặc quyết định cụ thể.
- **Ví dụ:** “Could you focus on whether this retry policy is too aggressive?”

## 5. Từ vựng trong tình huống

### migration
- **Loại:** noun
- **IPA:** /maɪˈɡreɪʃən/
- **Nghĩa:** migration, thay đổi cấu trúc database
- **Ví dụ:** “The migration creates a new index.”
- **Collocation:** database migration, run a migration

### index
- **Loại:** noun
- **IPA:** /ˈɪndeks/
- **Nghĩa:** chỉ mục trong database
- **Ví dụ:** “The new index improves this query.”
- **Collocation:** create an index, database index

### lock
- **Loại:** noun / verb
- **IPA:** /lɒk/
- **Nghĩa:** khóa; khóa tài nguyên
- **Ví dụ:** “The migration may hold a lock on the table.”
- **Collocation:** table lock, acquire a lock

### production-scale
- **Loại:** adjective
- **IPA:** /prəˈdʌkʃən skeɪl/
- **Nghĩa:** ở quy mô tương đương production
- **Ví dụ:** “I haven’t tested it with production-scale data.”
- **Collocation:** production-scale traffic, production-scale data

### reviewer
- **Loại:** noun
- **IPA:** /rɪˈvjuːər/
- **Nghĩa:** người review
- **Ví dụ:** “The reviewer checked the migration strategy.”
- **Collocation:** code reviewer, assigned reviewer

### risk
- **Loại:** noun
- **IPA:** /rɪsk/
- **Nghĩa:** rủi ro
- **Ví dụ:** “The main risk is the migration time.”
- **Collocation:** production risk, reduce risk

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Present perfect để nói việc đã làm và chưa làm đến hiện tại

Cấu trúc:

**have/has + past participle**

Trong code review, present perfect rất hữu ích để nói những gì bạn đã kiểm tra trước khi gửi PR.

Ví dụ:

- “I have tested the migration locally.”
- “I have checked the generated SQL.”
- “I haven’t tested it with production-scale data yet.”

Điểm quan trọng là những hành động này liên quan trực tiếp đến trạng thái hiện tại của PR.

So sánh:

- “I tested it yesterday.” → past simple vì có thời điểm cụ thể.
- “I have tested it locally.” → tập trung vào kết quả hiện tại: việc test local đã xong.

**Lỗi thường gặp:**

Không nói:

“I haven’t tested it yesterday.”

Nếu có `yesterday`, hãy dùng:

“I didn’t test it yesterday.”

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“Review my PR.”

### Tự nhiên và chuyên nghiệp hơn

“Could you take a look at my PR when you have a moment?”

### Giải thích

Câu đầu nghe giống mệnh lệnh. Câu sau vẫn rõ ràng nhưng phù hợp hơn khi nhờ đồng nghiệp hỗ trợ. Trong tình huống incident khẩn cấp, bạn có thể nói trực tiếp hơn, ví dụ: “Could you review this now? It’s blocking the hotfix.”

### Chưa tự nhiên hoặc quá trực tiếp

“Check the migration carefully.”

### Tự nhiên và chuyên nghiệp hơn

“The main thing I’d like you to check is the migration strategy.”

### Giải thích

Phiên bản thứ hai nói rõ mục tiêu review thay vì chỉ bảo người khác “check carefully”.

### Chưa tự nhiên hoặc quá trực tiếp

“It should be fine.”

### Tự nhiên và chuyên nghiệp hơn

“I’ve tested it locally, but I haven’t validated it with production-scale data yet.”

### Giải thích

“It should be fine” quá mơ hồ. Câu tốt hơn cho reviewer biết bạn đã verify gì và còn giới hạn nào.

## 8. Phát âm và luyện nói

### “Could you take a look at my PR?”

- Nhấn chính: **take**, **look**, **PR**.
- `Could you` thường được nói nhẹ và nối nhanh hơn phần nội dung chính.
- Ngắt nhẹ sau `PR` nếu tiếp tục giải thích.
- Không cần đọc từng từ với lực ngang nhau.

### “I’d like a second pair of eyes on the migration.”

- Nhấn: **second pair of eyes**, **migration**.
- `I’d like` là dạng rút gọn của `I would like`.
- Có thể ngắt: “I’d like a second pair of eyes / on the migration.”

### “I haven’t tested it with production-scale data yet.”

- Nhấn: **haven’t**, **production-scale data**, **yet**.
- `tested it` thường được nối nhẹ trong lời nói tự nhiên.
- Đừng bỏ âm cuối của `tested` và `yet`.

### Shadowing script

> Could you take a look at my PR when you have a moment?  
> The code change is small, but I’d like a second pair of eyes on the migration.  
> I’ve checked the generated SQL, but I haven’t tested it with production-scale data yet.  
> Could you focus on whether we should run this migration during the normal deployment?

Luyện theo thứ tự:

1. Đọc chậm.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp lại từng câu.
4. Ghi âm giọng của bạn.
5. Nói toàn bộ đoạn không nhìn text.

## 10. Bài tập thực hành chủ động

### Scenario

Bạn vừa tạo PR thay đổi một background job trong .NET. Job hiện retry tối đa 5 lần thay vì 3 lần. Bạn đã test unit test và local environment, nhưng chưa test khi external API thật trả về `429 Too Many Requests` trong thời gian dài.

### Yêu cầu

Hãy viết hoặc nói một message 5–7 câu để nhờ Senior Developer review PR.

Message phải có:

- Một câu request review.
- Một câu tóm tắt thay đổi.
- Một câu nói risk chính.
- Một câu nói bạn đã test gì.
- Một câu nói bạn chưa test gì.
- Một câu chỉ rõ reviewer nên tập trung vào đâu.

### Cấu trúc gợi ý

- “Could you take a look at …?”
- “This PR changes …”
- “The main risk is …”
- “I’ve tested …”
- “I haven’t tested … yet.”
- “Could you focus on whether …?”

### Completion criteria

Bài hoàn thành khi người reviewer đọc message có thể trả lời được ba câu:

1. PR thay đổi gì?
2. Risk nằm ở đâu?
3. Tôi cần tập trung review phần nào?

**Đáp án: A — have checked**

### Bài 4

Một đáp án phù hợp:

“I’ve tested the migration locally, but I haven’t tested it with production-scale data yet.”

Một lựa chọn khác:

“I’ve checked the generated SQL, but I still need to validate the migration time on a larger dataset.”

Cả hai đều tốt hơn “It should be fine” vì chúng cho thấy bằng chứng và giới hạn hiện tại.

### Bài 5

**Đáp án: B → D → C → E → A**

Flow tự nhiên:

**Request → Summary → Risk → Verification → Review focus**

Bạn không nhất thiết phải dùng đúng thứ tự này mọi lúc, nhưng đây là cấu trúc rất dễ hiểu trong chat hoặc PR description.

## 12. Mẫu trả lời tham khảo

**“Could you take a look at my PR when you have a moment? This PR increases the retry limit for the background job from three attempts to five. The main risk is that we may keep retrying too aggressively when the external API returns 429 for a long period. I’ve tested the unit tests and the local retry flow, but I haven’t tested it against a long rate-limit window yet. Could you focus on whether the retry count and delay strategy look reasonable?”**

Các pattern có thể tái sử dụng:

- **“Could you take a look at …?”**
- **“The main risk is …”**
- **“I’ve tested …, but I haven’t tested … yet.”**
- **“Could you focus on whether …?”**

## 13. Thử nói lại theo cách của bạn

Chọn một PR thật hoặc một thay đổi kỹ thuật gần đây của bạn và điền template:

- **Context:** I’ve opened a PR for …
- **What changed:** This PR changes …
- **Main risk:** The main risk is …
- **What I tested:** I’ve tested …
- **What I haven’t tested:** I haven’t tested … yet.
- **Review focus:** Could you focus on …?
- **Expected next action:** After the review, I’ll …

Sau đó nói lại thành một đoạn khoảng 45–60 giây mà không đọc từng dòng.

## 14. Tóm tắt cần ghi nhớ

### 3 câu nên nhớ

1. **“Could you take a look at my PR when you have a moment?”**
2. **“The main thing I’d like you to check is the migration strategy.”**
3. **“I’ve tested it locally, but I haven’t tested it with production-scale data yet.”**

### Lỗi cần tránh

- Không chỉ viết “Please review” nếu PR có risk quan trọng mà reviewer cần biết.
- Không dùng “It should be fine” thay cho thông tin verification cụ thể.
- Không giấu phần chưa test; nói rõ giới hạn hiện tại giúp review tốt hơn.

### Thử thách hôm nay

Lấy một PR thật bạn đã tạo gần đây và viết lại review request theo cấu trúc **Request → Summary → Risk → What I tested → Review focus**. Nếu có thể, dùng ít nhất hai câu trong phần “3 câu nên nhớ”.
