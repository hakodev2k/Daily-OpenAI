# Daily Workplace English — Ngày 38

- **Ngày:** 17/08/2026 (UTC+7)
- **Tình huống công việc:** Mô tả rõ expected behavior và actual behavior khi báo một bug liên quan đến calendar synchronization
- **Kỹ năng giao tiếp chính:** Trình bày bug theo cấu trúc context → expected → actual → impact → next action để người khác hiểu nhanh và tránh diễn đạt mơ hồ
- **Thời gian học:** 20–25 phút
- **Độ khó:** Lower-intermediate

## 1. Tình huống hôm nay

Bạn đang làm backend cho một tính năng đồng bộ lịch. Khi admin thay đổi thời gian của một event, backend cập nhật dữ liệu nội bộ thành công, nhưng trong một số trường hợp lịch của user vẫn hiển thị thời gian cũ.

Những người liên quan gồm bạn, QA engineer và Technical Lead. Bạn cần báo lại vấn đề trong team chat để mọi người hiểu chính xác behavior nào được mong đợi, behavior thực tế đang xảy ra và ảnh hưởng tới user.

Khó khăn giao tiếp là nhiều developer mô tả bug quá ngắn, ví dụ:

> “Calendar update is not working.”

Câu này không cho biết phần nào không hoạt động, điều gì đã thành công, điều gì chưa đúng và người khác phải kiểm tra ở đâu.

Cách rõ ràng hơn là dùng cấu trúc:

**Context → Expected behavior → Actual behavior → Scope/impact → Investigation status → Next action**

## 2. Bạn cần nói gì?

Trong tình huống này, bạn nên:

- Nêu ngắn gọn thao tác dẫn đến vấn đề.
- Phân biệt rõ **expected behavior** và **actual behavior**.
- Nói rõ phần nào của flow vẫn hoạt động bình thường.
- Mô tả impact mà không phóng đại.
- Tránh kết luận root cause khi chưa đủ evidence.
- Nêu việc bạn sẽ kiểm tra tiếp theo.

Một cấu trúc dễ nhớ:

**When X happens, Y should happen. However, Z is happening instead.**

## 3. Đoạn hội thoại hoặc mẫu trình bày

**You:** “I found an issue with the calendar update flow.”  
*Mình phát hiện một vấn đề trong flow cập nhật lịch.*

**QA:** “What exactly is happening?”  
*Cụ thể đang xảy ra chuyện gì?*

**You:** “When the admin changes the event time, the new time should be reflected in the user’s calendar.”  
*Khi admin thay đổi thời gian event, thời gian mới đáng lẽ phải được cập nhật trên lịch của user.*

**You:** “The backend record is updated correctly, but the user’s calendar still shows the previous time in some cases.”  
*Record ở backend được cập nhật đúng, nhưng trong một số trường hợp lịch của user vẫn hiển thị thời gian cũ.*

**QA:** “Do we know whether the sync request is failing?”  
*Chúng ta có biết request đồng bộ có đang bị fail không?*

**You:** “Not yet. I can see that our database update succeeds, but I still need to verify what happens during the calendar synchronization step.”  
*Chưa. Mình thấy database update thành công, nhưng vẫn cần kiểm tra điều gì xảy ra ở bước đồng bộ lịch.*

**You:** “I’ll check the relevant logs and trace one affected request end to end.”  
*Mình sẽ kiểm tra các log liên quan và trace một request bị ảnh hưởng từ đầu đến cuối.*

**You:** “I’ll share an update once I know whether the problem is in our sync logic or the external calendar call.”  
*Mình sẽ cập nhật khi xác định được vấn đề nằm ở logic đồng bộ của mình hay ở lời gọi tới hệ thống lịch bên ngoài.*

## 4. Các cụm từ quan trọng

### 1. “The expected behavior is…”

- **Nghĩa:** Behavior mong đợi là…
- **Khi dùng:** Khi cần mô tả requirement hoặc kết quả đúng của hệ thống.
- **Ví dụ thêm:** “The expected behavior is that the API returns `404` when the record does not exist.”

### 2. “What actually happens is…”

- **Nghĩa:** Điều thực tế xảy ra là…
- **Khi dùng:** Khi đối chiếu behavior hiện tại với expectation.
- **Ví dụ thêm:** “What actually happens is that the request returns `200` with an empty result.”

### 3. “The backend record is updated correctly, but…”

- **Nghĩa:** Record ở backend được cập nhật đúng, nhưng…
- **Khi dùng:** Khi một phần của flow thành công nhưng phần sau bị lỗi.
- **Ví dụ thêm:** “The payment record is created correctly, but the confirmation email is not sent.”

### 4. “I still need to verify…”

- **Nghĩa:** Tôi vẫn cần kiểm tra/xác minh…
- **Khi dùng:** Khi chưa đủ evidence để kết luận.
- **Ví dụ thêm:** “I still need to verify whether the retry policy is being applied.”

### 5. “I’ll trace one affected request end to end.”

- **Nghĩa:** Tôi sẽ trace một request bị ảnh hưởng xuyên suốt toàn bộ flow.
- **Khi dùng:** Khi cần điều tra một request qua nhiều service hoặc bước xử lý.
- **Ví dụ thêm:** “I’ll trace one failed request end to end using the correlation ID.”

### 6. “I’ll share an update once I know…”

- **Nghĩa:** Tôi sẽ cập nhật khi tôi biết/xác định được…
- **Khi dùng:** Khi muốn đưa ra next update rõ ràng nhưng chưa hứa một kết luận chưa chắc chắn.
- **Ví dụ thêm:** “I’ll share an update once I know whether this is caused by the API or the database.”

## 5. Từ vựng trong tình huống

### 1. expected behavior

- **Loại:** noun phrase
- **IPA:** /ɪkˈspektɪd bɪˈheɪvjər/
- **Nghĩa:** hành vi/kết quả được mong đợi
- **Ví dụ:** “The expected behavior is that the new event time appears in the user’s calendar.”
- **Collocation:** expected behavior, define expected behavior

### 2. actual behavior

- **Loại:** noun phrase
- **IPA:** /ˈæktʃuəl bɪˈheɪvjər/
- **Nghĩa:** hành vi thực tế
- **Ví dụ:** “The actual behavior is that the old time is still displayed.”
- **Collocation:** actual behavior, observe actual behavior

### 3. synchronization

- **Loại:** noun
- **IPA:** /ˌsɪŋkrənaɪˈzeɪʃən/
- **Nghĩa:** sự đồng bộ
- **Ví dụ:** “I need to verify the calendar synchronization step.”
- **Collocation:** data synchronization, calendar synchronization

### 4. affected

- **Loại:** adjective
- **IPA:** /əˈfektɪd/
- **Nghĩa:** bị ảnh hưởng
- **Ví dụ:** “I’ll trace one affected request.”
- **Collocation:** affected user, affected request, affected environment

### 5. trace

- **Loại:** verb
- **IPA:** /treɪs/
- **Nghĩa:** theo dõi luồng xử lý để tìm vấn đề
- **Ví dụ:** “I’ll trace the request from the API to the calendar service.”
- **Collocation:** trace a request, trace the flow

### 6. reflect

- **Loại:** verb
- **IPA:** /rɪˈflekt/
- **Nghĩa:** phản ánh/hiển thị đúng một thay đổi
- **Ví dụ:** “The new time should be reflected in the user’s calendar.”
- **Collocation:** reflect a change, reflect the latest status

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Mẫu: “X should happen, but Y is happening instead.”

Đây là mẫu rất hữu ích khi mô tả **expected behavior vs actual behavior**.

**Cấu trúc:**

`Subject + should + base verb, but + subject + is/are + V-ing + instead.`

Hoặc:

`X should happen, but Y happens instead.`

**Ý nghĩa:**

- `should` mô tả behavior được mong đợi theo requirement hoặc thiết kế.
- Mệnh đề sau `but` mô tả behavior thực tế đang xảy ra.

**Ví dụ trong bài:**

“The new time should be reflected in the user’s calendar, but the old time is still being displayed in some cases.”

**Ví dụ khác:**

“The API should return `404`, but it returns `200` instead.”

“The background job should run once, but it is being triggered twice.”

**Lỗi thường gặp:**

Sai: “The API should returns `404`.”  
Đúng: “The API should return `404`.”

Sau modal verb `should`, luôn dùng **động từ nguyên mẫu không `to`**.

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“The calendar is wrong.”

### Tự nhiên và chuyên nghiệp hơn

“The calendar is still showing the previous event time.”

### Giải thích

“Wrong” quá chung chung. Câu thứ hai mô tả được chính xác điều đang sai nên người nghe dễ điều tra hơn.

### Chưa tự nhiên hoặc quá trực tiếp

“The sync API has a bug.”

### Tự nhiên và chuyên nghiệp hơn

“I haven’t confirmed the root cause yet, but the issue appears during the synchronization step.”

### Giải thích

Nếu chưa có evidence, không nên gắn nguyên nhân chắc chắn cho một component. Câu thứ hai tách observation khỏi conclusion.

### Chưa tự nhiên hoặc quá trực tiếp

“I will check it.”

### Tự nhiên và chuyên nghiệp hơn

“I’ll check the synchronization logs and trace one affected request end to end.”

### Giải thích

“I will check it” đúng ngữ pháp nhưng quá mơ hồ trong môi trường kỹ thuật. Câu mới nói rõ **check cái gì** và **check như thế nào**. Trong incident khẩn cấp, câu trực tiếp vẫn phù hợp nếu action đã rõ với cả team.

## 8. Phát âm và luyện nói

### “The expected behavior is…”

- Nhấn chính: **EXPECTED**, **BEHAVIOR**.
- `expected` có âm cuối `/ɪd/`, đừng bỏ mất âm cuối.
- Có thể ngắt nhẹ sau `behavior` nếu câu dài.
- Gợi ý gần âm tiếng Việt chỉ để dễ bắt đầu, không phải phiên âm chuẩn: “ịch-SPEK-tịt bi-HÂY-vyờ”.

### “What actually happens is…”

- Nhấn: **ACTUALLY**, **HAPPENS**.
- `what actually` khi nói tự nhiên sẽ nối khá liền.
- Không cần nhấn mạnh từ `is`.

### “I still need to verify…”

- Nhấn: **STILL**, **VERIFY**.
- `need to` thường được nói nhanh, gần như nối thành một cụm.
- Ngắt sau phần bạn cần verify nếu câu còn giải thích dài.

### “I’ll trace one affected request end to end.”

- Nhấn: **TRACE**, **AFFECTED REQUEST**, **END TO END**.
- `end to end` nói thành một cụm nhịp đều.
- Không đọc quá tách từng từ nhỏ.

### Shadowing script

“The expected behavior is that the new time appears in the user’s calendar.”  
“The backend record is updated correctly, but the old time is still displayed.”  
“I haven’t confirmed the root cause yet.”  
“I’ll trace one affected request end to end and check the synchronization logs.”

Cách luyện:

1. Đọc chậm từng câu.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp lại từng câu một.
4. Ghi âm giọng của bạn.
5. Nói lại toàn bộ đoạn mà không nhìn văn bản.

## 10. Bài tập thực hành chủ động

### Nhiệm vụ

Viết hoặc nói một update 60–90 giây cho QA và Technical Lead về bug giả định sau:

- User updates a setting through an ASP.NET Core API.
- Database value is updated successfully.
- UI still shows the old value after refresh.
- Bạn chưa biết lỗi nằm ở caching, API response hay frontend state.

### Bạn cần đề cập

- Context ngắn gọn.
- Expected behavior.
- Actual behavior.
- Phần nào đã xác nhận hoạt động đúng.
- Điều gì vẫn chưa biết.
- Next investigation action.

### Cấu trúc gợi ý

1. “I found an issue with…”
2. “The expected behavior is…”
3. “What actually happens is…”
4. “I can confirm that…”
5. “I still need to verify…”
6. “I’ll…”

### Cụm từ có thể dùng

- “The expected behavior is…”
- “What actually happens is…”
- “I can confirm that…”
- “I still need to verify…”
- “I’ll trace…”
- “I’ll share an update once…”

### Tiêu chí hoàn thành

- 6–8 câu tiếng Anh.
- Có expected và actual behavior rõ ràng.
- Không đoán root cause.
- Có ít nhất một investigation action cụ thể.
- Nói được mà không cần dịch từng từ từ tiếng Việt.

## 12. Mẫu trả lời tham khảo

“I found an issue with the settings update flow. **The expected behavior is that the new value appears after the user refreshes the page.** What actually happens is that the UI still shows the previous value. **I can confirm that the database value is updated correctly.** I haven’t confirmed the root cause yet, so I still need to verify the API response, cache behavior, and frontend state. **I’ll trace one affected request end to end and share an update once I know where the value becomes stale.**”

Các mẫu nên tái sử dụng:

- **The expected behavior is that…**
- **I can confirm that…**
- **I still need to verify…**
- **I’ll share an update once…**

## 13. Thử nói lại theo cách của bạn

Chọn một bug thật hoặc gần với công việc hiện tại của bạn và điền template sau bằng tiếng Anh:

- **Context:** The issue happens when…
- **What happened:** I noticed that…
- **My current understanding:** I can confirm that…
- **Expected behavior:** The system should…
- **Actual behavior:** What actually happens is…
- **Missing information:** I still need to verify…
- **My proposed action:** I’ll…
- **Expected next update:** I’ll share an update once…

Hãy cố gắng dùng bug thật từ API, background job, SQL, Azure, Microsoft Graph, Playwright hoặc một task hiện tại để bài luyện có giá trị thực tế hơn.

## 14. Tóm tắt cần ghi nhớ

### 3 câu nên nhớ

1. “The expected behavior is that the new value is reflected immediately.”
2. “What actually happens is that the old value is still displayed.”
3. “I still need to verify where the flow is failing.”

### Lỗi cần tránh

- Nói “It is not working” mà không chỉ rõ expected và actual behavior.
- Kết luận root cause trước khi có đủ evidence.
- Dùng sai sau `should`: `should returns` thay vì `should return`.

### Thử thách hôm nay

Chọn một bug hoặc issue thật trong công việc và nói một đoạn 60 giây theo đúng cấu trúc:

**Context → Expected → Actual → Confirmed fact → Unknown → Next action**
