# Daily Workplace English — Ngày 3

- **Ngày:** 17/08/2026 (giờ Việt Nam, UTC+7)
- **Workplace situation:** Request code review cho một API change có database migration
- **Main communication skill:** Nhờ review rõ ràng, nêu phạm vi thay đổi, rủi ro và điểm cần reviewer tập trung
- **Estimated study time:** 20 phút
- **Difficulty:** Elementary

## 1. Tình huống hôm nay

Bạn vừa hoàn thành một pull request cho tính năng cập nhật trạng thái đơn hàng. PR có ba phần chính:

- Thêm endpoint mới trong ASP.NET Core.
- Thay đổi logic trong service layer.
- Thêm một Entity Framework Core migration để tạo index mới trên bảng `Orders`.

Bạn muốn nhờ một senior developer review trước khi merge. Nếu chỉ nhắn “Please review my PR” thì reviewer sẽ thiếu context và có thể mất thời gian tự tìm phần quan trọng.

Bạn cần giao tiếp rõ:

- PR thay đổi cái gì.
- Vì sao thay đổi đó cần thiết.
- Phần nào có rủi ro cao hơn.
- Reviewer nên tập trung vào đâu.
- Bạn đã test những gì.
- Khi nào bạn cần feedback.

Rủi ro giao tiếp là gửi yêu cầu quá ngắn, quá thúc ép, hoặc khẳng định thay đổi “safe” khi chưa có đủ bằng chứng.

## 2. Bạn cần nói gì?

Một code-review request tốt có thể theo cấu trúc:

**Context → Main changes → Risk → Testing → Review request**

Bạn nên:

1. Nói ngắn gọn mục tiêu của PR.
2. Chỉ ra 2–3 thay đổi chính.
3. Nêu phần bạn muốn reviewer chú ý nhất.
4. Nói rõ test đã chạy.
5. Đề cập rủi ro nếu có, đặc biệt với database migration.
6. Nhờ feedback một cách lịch sự và cụ thể.

## 3. Đoạn hội thoại hoặc mẫu trình bày

**Developer:** “Hi Alex, could you review my PR when you have some time today?”  
Developer: Chào Alex, khi nào hôm nay bạn có thời gian thì bạn review PR của mình giúp nhé.

**Developer:** “It adds a new endpoint for updating order status and includes a small database migration.”  
Developer: PR này thêm endpoint mới để cập nhật trạng thái đơn hàng và có một database migration nhỏ.

**Reviewer:** “Sure. Is there anything specific you want me to focus on?”  
Reviewer: Được. Có phần nào cụ thể bạn muốn tôi tập trung review không?

**Developer:** “Yes. Could you pay special attention to the transaction handling and the new index on the `Orders` table?”  
Developer: Có. Bạn có thể chú ý kỹ phần transaction handling và index mới trên bảng `Orders` giúp mình không?

**Developer:** “I’ve added unit tests for the service logic and tested the migration on my local database.”  
Developer: Mình đã thêm unit test cho service logic và test migration trên database local.

**Reviewer:** “Does the migration lock the table for a long time?”  
Reviewer: Migration có lock bảng lâu không?

**Developer:** “I don’t expect it to, but I’d like a second opinion before we deploy it to QA.”  
Developer: Mình không nghĩ là như vậy, nhưng mình muốn có thêm một ý kiến review trước khi deploy lên QA.

**Developer:** “There’s no urgent deadline, but feedback before this afternoon would help me keep the QA testing on track.”  
Developer: Không có deadline khẩn, nhưng nếu có feedback trước chiều nay thì sẽ giúp mình giữ QA testing đúng kế hoạch.

## 4. Các cụm từ quan trọng

### 1. “Could you review my PR when you have some time?”

- **Nghĩa:** Bạn có thể review PR của tôi khi có thời gian không?
- **Khi dùng:** Yêu cầu review một cách lịch sự, không tạo cảm giác ép buộc.
- **Ví dụ thêm:** “Could you review my API changes when you have some time?”

### 2. “It adds…”

- **Nghĩa:** Nó thêm…
- **Khi dùng:** Tóm tắt nhanh thay đổi chính trong PR.
- **Ví dụ thêm:** “It adds validation for duplicate email addresses.”

### 3. “Could you pay special attention to…?”

- **Nghĩa:** Bạn có thể chú ý kỹ phần… không?
- **Khi dùng:** Hướng reviewer vào khu vực quan trọng hoặc rủi ro cao.
- **Ví dụ thêm:** “Could you pay special attention to the retry logic?”

### 4. “I’ve added tests for…”

- **Nghĩa:** Tôi đã thêm test cho…
- **Khi dùng:** Cho reviewer biết phạm vi kiểm thử đã có.
- **Ví dụ thêm:** “I’ve added tests for the authorization rules.”

### 5. “I’ve tested it on…”

- **Nghĩa:** Tôi đã test nó trên…
- **Khi dùng:** Báo rõ môi trường hoặc phạm vi test.
- **Ví dụ thêm:** “I’ve tested it on the QA database with sample data.”

### 6. “I’d like a second opinion.”

- **Nghĩa:** Tôi muốn có thêm một ý kiến đánh giá khác.
- **Khi dùng:** Khi bạn chưa hoàn toàn chắc chắn về một quyết định kỹ thuật.
- **Ví dụ thêm:** “I’d like a second opinion on the caching approach.”

### 7. “Feedback before this afternoon would help…”

- **Nghĩa:** Nếu có feedback trước chiều nay thì sẽ giúp…
- **Khi dùng:** Nêu thời điểm mong muốn mà không ra lệnh.
- **Ví dụ thêm:** “Feedback before the deployment window would help us avoid delays.”

## 5. Từ vựng trong tình huống

### 1. review

- **Part of speech:** verb / noun
- **IPA:** /rɪˈvjuː/
- **Nghĩa:** xem xét, đánh giá
- **Ví dụ:** “Could you review my PR?”
- **Collocation:** code review, review a pull request

### 2. migration

- **Part of speech:** noun
- **IPA:** /maɪˈɡreɪʃən/
- **Nghĩa:** thay đổi cấu trúc database có quản lý theo version
- **Ví dụ:** “The PR includes a database migration.”
- **Collocation:** database migration, run a migration

### 3. transaction

- **Part of speech:** noun
- **IPA:** /trænˈzækʃən/
- **Nghĩa:** giao dịch database
- **Ví dụ:** “Please check the transaction handling.”
- **Collocation:** database transaction, transaction handling

### 4. index

- **Part of speech:** noun
- **IPA:** /ˈɪndeks/
- **Nghĩa:** chỉ mục database
- **Ví dụ:** “The migration creates a new index.”
- **Collocation:** create an index, database index

### 5. feedback

- **Part of speech:** noun
- **IPA:** /ˈfiːdbæk/
- **Nghĩa:** phản hồi, nhận xét
- **Ví dụ:** “Feedback before this afternoon would help.”
- **Collocation:** give feedback, review feedback

### 6. deploy

- **Part of speech:** verb
- **IPA:** /dɪˈplɔɪ/
- **Nghĩa:** triển khai
- **Ví dụ:** “We’ll deploy the change to QA after review.”
- **Collocation:** deploy to QA, deploy a release

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Modal verb `could` cho yêu cầu lịch sự

Trong bài hôm nay có hai mẫu rất hữu ích:

- **“Could you review my PR?”**
- **“Could you pay special attention to the transaction handling?”**

### Cấu trúc

**Could you + base verb + ...?**

Ví dụ:

- “Could you check this query?”
- “Could you review the migration?”
- “Could you confirm the expected behavior?”

### Ý nghĩa

`Could you…?` là cách yêu cầu tự nhiên và lịch sự trong môi trường làm việc. Nó mềm hơn câu mệnh lệnh nhưng vẫn rất rõ ràng.

### Khi dùng

Dùng khi:

- Nhờ teammate review.
- Hỏi QA cung cấp thông tin.
- Nhờ DevOps kiểm tra cấu hình.
- Nhờ PM xác nhận requirement.

### Lỗi thường gặp

Không nói:

**“Could you to review my PR?”**

Sau `could`, dùng động từ nguyên mẫu không có `to`:

**“Could you review my PR?”**

## 7. Cách nói tự nhiên hơn

### 1

#### Chưa tự nhiên hoặc quá trực tiếp

“Review my PR.”

#### Tự nhiên và chuyên nghiệp hơn

“Could you review my PR when you have some time today?”

#### Giải thích

Câu đầu nghe giống mệnh lệnh. Câu sau giữ yêu cầu rõ ràng nhưng cho reviewer không gian sắp xếp công việc.

### 2

#### Chưa tự nhiên hoặc quá trực tiếp

“Check all code carefully.”

#### Tự nhiên và chuyên nghiệp hơn

“Could you pay special attention to the transaction handling and the migration?”

#### Giải thích

Một review request tốt nên chỉ rõ phần quan trọng thay vì yêu cầu chung chung “check carefully”. Điều này giúp reviewer tập trung và tiết kiệm thời gian.

### 3

#### Chưa tự nhiên hoặc quá trực tiếp

“This migration is safe.”

#### Tự nhiên và chuyên nghiệp hơn

“I don’t expect the migration to cause a long lock, but I’d like a second opinion.”

#### Giải thích

Khi chưa có bằng chứng tuyệt đối, cách thứ hai thể hiện mức độ chắc chắn hợp lý. Bạn nêu assumption nhưng vẫn mở cửa cho review.

## 8. Phát âm và luyện nói

### “Could you review my PR?”

- **Stress:** nhấn **review** và **PR**.
- **Connected speech:** “Could you” thường nối nhanh khi nói tự nhiên.
- **Gợi ý:** không cần đọc quá mạnh từng âm trong “Could you”; ưu tiên nhịp câu.
- **Pause:** có thể dừng nhẹ sau “PR” trước khi thêm context.
- **Emphasis:** **review**, **PR**.

### “Could you pay special attention to the transaction handling?”

- **Stress:** **special attention**, **transaction handling**.
- **Connected speech:** “attention to” thường được nối tự nhiên.
- **Gợi ý:** `transaction` có trọng âm ở âm tiết thứ hai: tran-**SAC**-tion.
- **Pause:** có thể ngắt nhẹ trước phần cần focus nếu câu dài.
- **Emphasis:** **transaction handling**.

### “I’d like a second opinion.”

- **Stress:** **second opinion**.
- **Connected speech:** “I’d like a” nên đọc thành một cụm liên tục.
- **Gợi ý:** `opinion` có trọng âm ở âm tiết thứ hai: o-**PIN**-ion.
- **Emphasis:** **second opinion**.

### Shadowing script

“Could you review my PR when you have some time today? It adds a new API endpoint and includes a database migration. Could you pay special attention to the transaction handling and the new index? I’ve added tests, but I’d like a second opinion before we deploy it to QA.”

Luyện theo 5 bước:

1. Đọc chậm từng câu.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp lại từng câu một.
4. Ghi âm giọng của bạn.
5. Nói lại toàn bộ đoạn mà không nhìn văn bản.

## 10. Bài tập thực hành chủ động

### Scenario

Bạn vừa mở một PR thay đổi caching logic cho một API ASP.NET Core. PR sử dụng Redis và thay đổi cache expiration từ 5 phút thành 30 phút. Bạn lo rằng dữ liệu có thể stale lâu hơn trong một số trường hợp.

### Required points

Viết một message tiếng Anh dài khoảng 5–7 câu để nhờ teammate review. Message cần có:

- Nêu mục tiêu của PR.
- Tóm tắt thay đổi chính.
- Nói phần bạn muốn reviewer chú ý.
- Nêu test bạn đã chạy.
- Nêu rủi ro về stale data.
- Nhờ feedback trước khi merge.

### Suggested structure

1. Ask for review.
2. Give context.
3. Describe the key change.
4. Highlight the risk.
5. Mention testing.
6. Ask for feedback.

### Useful phrases

- “Could you review my PR when you have some time?”
- “It changes…”
- “Could you pay special attention to…?”
- “I’ve tested it with…”
- “I’d like a second opinion.”

### Completion criteria

Bài làm đạt yêu cầu nếu:

- Có ít nhất 5 câu rõ ràng.
- Có context, risk và testing.
- Dùng ít nhất 2 cụm từ trong bài hôm nay.
- Không viết theo kiểu mệnh lệnh.
- Reviewer hiểu ngay phần nào cần tập trung.

## 11. Đáp án và giải thích

### Bài 1

**Đáp án: A. review**

Sau `could` dùng động từ nguyên mẫu:

**Could you + review + ...?**

Không dùng `to review` sau `could`.

### Bài 2

**Đáp án: B. “Could you pay special attention to the transaction handling?”**

Câu này vừa lịch sự vừa chỉ rõ focus area. A quá chung chung, còn C mang tính ép buộc.

### Bài 3

Một đáp án tốt:

**“Could you review this sometime today if you have availability?”**

Hoặc đơn giản hơn:

**“Could you review this when you have some time today?”**

Nếu thật sự khẩn cấp, có thể nói trực tiếp nhưng nên giải thích lý do:

**“Could you review this before 2 PM? We need the approval for today’s deployment.”**

### Bài 4

**Đáp án: B. added**

Câu đúng:

**“I’ve added unit tests for the service logic.”**

`I’ve` = `I have`, sau đó dùng past participle `added`.

### Bài 5

**Đáp án: B → C → D → A**

Một flow tự nhiên là:

1. Nhờ review.
2. Nêu thay đổi chính.
3. Chỉ ra phần rủi ro.
4. Cho biết đã test gì.

### Bài 6

Ví dụ:

**“I don’t expect the migration to cause a problem, but I’d like a second opinion.”**

Câu này thể hiện bạn có assessment riêng nhưng vẫn chủ động tìm thêm review.

## 12. Mẫu trả lời tham khảo

“Hi Alex, **could you review my PR when you have some time today?** It changes the Redis cache expiration from 5 minutes to 30 minutes for the product API. **Could you pay special attention to the stale-data risk?** I’ve tested the main read and update flows locally. The longer cache duration should reduce repeated database calls, but I’d like a second opinion before we merge it. Please let me know if you see any cases where we should invalidate the cache earlier.”

Các mẫu câu tái sử dụng:

- **Could you + verb + ...?**
- **Could you pay special attention to + noun?**
- **I’ve tested + scope/environment.**
- **I’d like a second opinion on + topic.**

## 13. Thử nói lại theo cách của bạn

Hãy chọn một PR thật hoặc một thay đổi gần đây trong công việc của bạn và tạo phiên bản riêng.

Template:

- **Context:** What does the PR change?
- **Main change:** What are the 1–2 most important code changes?
- **Risk:** What part are you least certain about?
- **Testing:** What have you tested?
- **Review focus:** What should the reviewer look at carefully?
- **Expected next update:** When do you hope to get feedback?

Bạn có thể áp dụng với API change, EF Core migration, Hangfire job, Azure Function, Redis caching hoặc Microsoft Graph integration.

## 14. Tóm tắt cần ghi nhớ

### 3 câu nên nhớ

1. **“Could you review my PR when you have some time?”**
2. **“Could you pay special attention to the transaction handling?”**
3. **“I’d like a second opinion before we deploy it.”**

### Lỗi cần tránh

- Không dùng `Could you to review…`; đúng là `Could you review…`.
- Không chỉ viết “Please review” mà không đưa context khi PR có thay đổi quan trọng.
- Không khẳng định tuyệt đối “This is safe” khi bạn vẫn còn uncertainty; hãy nói rõ assessment và nhờ second opinion.

### Thử thách hôm nay

Mở một PR cũ hoặc PR hiện tại của bạn. Viết lại code-review request bằng tiếng Anh theo cấu trúc:

**Context → Main change → Risk → Testing → Review focus**

Cố gắng dùng ít nhất hai trong ba câu nên nhớ ở trên.
