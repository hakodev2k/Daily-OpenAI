# Daily Workplace English — Ngày 9

- **Ngày:** 17/08/2026 (UTC+7)
- **Workplace situation:** Requesting code review for a backend change
- **Main communication skill:** Nhờ teammate review code rõ ràng, cung cấp đủ context và chỉ ra phần cần chú ý
- **Estimated study time:** 20 phút
- **Difficulty:** Elementary

## 1. Tình huống hôm nay

Bạn vừa hoàn thành một pull request cho một ASP.NET Core API. Thay đổi gồm validation mới, một query Entity Framework Core, và cập nhật một background job. Bạn cần nhờ một Senior Developer review code trước khi merge.

Người tham gia gồm bạn và một reviewer trong team. Bạn cần nói rõ PR này thay đổi gì, phần nào có rủi ro, reviewer nên tập trung vào đâu, và bạn mong muốn review trước thời điểm nào.

Khó khăn thường gặp là chỉ gửi một câu rất ngắn như “Please review my PR” mà không có context, khiến reviewer phải tự tìm hiểu toàn bộ. Ngược lại, nếu viết quá dài, reviewer cũng khó biết phần nào cần chú ý nhất.

## 2. Bạn cần nói gì?

Một code-review request tốt nên có bốn phần:

1. Nói ngắn gọn PR thay đổi gì.
2. Chỉ ra phần quan trọng hoặc có rủi ro.
3. Nói rõ reviewer nên tập trung kiểm tra điều gì.
4. Đưa ra timing hợp lý nếu có deadline.

Cấu trúc đơn giản:

**Context → What changed → What to focus on → Timing**

## 3. Đoạn hội thoại hoặc mẫu trình bày

**Developer:** “Hi Alex, I’ve opened a pull request for the employee sync changes.”  
*Mình vừa mở một pull request cho phần thay đổi employee sync.*

**Reviewer:** “Sure. What does it include?”  
*Được. PR này gồm những gì?*

**Developer:** “It adds validation for inactive employees and updates the background job to skip invalid records.”  
*Nó bổ sung validation cho employee inactive và cập nhật background job để bỏ qua các record không hợp lệ.*

**Developer:** “I also changed the EF Core query to reduce the number of database calls.”  
*Mình cũng thay đổi EF Core query để giảm số lần gọi database.*

**Reviewer:** “Is there anything specific you want me to check?”  
*Có phần nào cụ thể bạn muốn mình kiểm tra không?*

**Developer:** “Could you pay particular attention to the query and the transaction handling?”  
*Bạn có thể chú ý đặc biệt tới query và phần transaction handling không?*

**Developer:** “I’ve added tests for the main scenarios, but I’d like a second pair of eyes on the edge cases.”  
*Mình đã thêm test cho các scenario chính, nhưng muốn có thêm một người kiểm tra các edge case.*

**Reviewer:** “No problem. I’ll review it this afternoon.”  
*Không vấn đề gì. Chiều nay mình sẽ review.*

**Developer:** “Thanks. If possible, I’d like to merge it before the QA deployment at 4 p.m.”  
*Cảm ơn. Nếu có thể, mình muốn merge trước đợt deploy QA lúc 4 giờ chiều.*

## 4. Các cụm từ quan trọng

### 1. “I’ve opened a pull request for…”

- **Nghĩa:** Tôi đã mở một pull request cho…
- **Khi dùng:** Mở đầu một code-review request.
- **Ví dụ:** “I’ve opened a pull request for the API pagination changes.”

### 2. “It adds…”

- **Nghĩa:** Nó bổ sung…
- **Khi dùng:** Tóm tắt chức năng mới trong PR.
- **Ví dụ:** “It adds validation for duplicate email addresses.”

### 3. “I also changed…”

- **Nghĩa:** Tôi cũng đã thay đổi…
- **Khi dùng:** Nêu thêm một thay đổi quan trọng.
- **Ví dụ:** “I also changed the retry logic for the background job.”

### 4. “Could you pay particular attention to…?”

- **Nghĩa:** Bạn có thể chú ý đặc biệt tới… không?
- **Khi dùng:** Hướng reviewer tới phần có rủi ro hoặc cần kiểm tra kỹ.
- **Ví dụ:** “Could you pay particular attention to the authorization logic?”

### 5. “I’d like a second pair of eyes on…”

- **Nghĩa:** Tôi muốn có thêm một người kiểm tra kỹ phần…
- **Khi dùng:** Cách tự nhiên để nói bạn muốn reviewer kiểm tra thêm một phần mà bạn chưa hoàn toàn tự tin.
- **Ví dụ:** “I’d like a second pair of eyes on the database migration.”

### 6. “If possible, I’d like to merge it before…”

- **Nghĩa:** Nếu có thể, tôi muốn merge trước…
- **Khi dùng:** Nêu deadline mà không gây áp lực quá mạnh.
- **Ví dụ:** “If possible, I’d like to merge it before tomorrow’s release.”

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Modal verb “Could you…?” để đưa ra yêu cầu lịch sự

**Cấu trúc:**

`Could you + động từ nguyên mẫu + ... ?`

Ví dụ trong bài:

> “Could you pay particular attention to the query and the transaction handling?”

Cấu trúc này rất hữu ích khi nhờ teammate làm một việc như review code, gửi log hoặc kiểm tra một scenario.

Ví dụ khác:

- “Could you review this PR when you have time?”
- “Could you check the error handling?”
- “Could you confirm whether this behavior is expected?”

### So sánh

**“Review my PR.”** — đúng ngữ pháp nhưng mang tính mệnh lệnh.  
**“Could you review my PR?”** — tự nhiên hơn trong hầu hết tình huống cộng tác.

### Lỗi thường gặp

Không nói:

> “Could you to review this PR?”

Sau `could` dùng động từ nguyên mẫu không có `to`:

> “Could you review this PR?”

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“Review my PR.”

### Tự nhiên và chuyên nghiệp hơn

“Could you review this PR when you have a chance?”

### Giải thích

Câu thứ hai phù hợp hơn trong giao tiếp thông thường vì thể hiện đây là một request, không phải mệnh lệnh.

### Chưa tự nhiên hoặc quá trực tiếp

“Check carefully the query.”

### Tự nhiên và chuyên nghiệp hơn

“Could you pay particular attention to the query?”

### Giải thích

`pay attention to` là cụm rất tự nhiên khi muốn reviewer tập trung vào một khu vực cụ thể.

### Chưa tự nhiên hoặc quá trực tiếp

“I need your review before 4 p.m.”

### Tự nhiên và chuyên nghiệp hơn

“If possible, I’d like to merge it before the QA deployment at 4 p.m.”

### Giải thích

Câu thứ hai giải thích lý do của deadline và tránh tạo cảm giác ép buộc. Tuy nhiên, nếu đang xử lý incident hoặc deadline thực sự cứng, bạn có thể trực tiếp hơn, ví dụ: “We need approval before 4 p.m. to make today’s deployment.”

## 8. Phát âm và luyện nói

### “I’ve opened a pull request for the employee sync changes.”

- **Stress:** **OPENED**, **PULL REQUEST**, **EMPLOYEE SYNC**.
- `I’ve opened` nên nói liền thành một cụm.
- Có thể ngắt nhẹ sau `pull request`.
- Nhấn mạnh tên feature để reviewer biết ngay context.

### “Could you pay particular attention to the query?”

- **Stress:** **PARTICULAR ATTENTION**, **QUERY**.
- `Could you` thường được nói nhẹ và nhanh hơn các từ nội dung.
- Ngắt nhẹ trước `to the query` nếu cần.

### “I’d like a second pair of eyes on the edge cases.”

- **Stress:** **SECOND PAIR OF EYES**, **EDGE CASES**.
- `I’d like` nên nói liền, không tách `I would` từng từ.
- `second pair of eyes` là một cụm, nên giữ nhịp liền nhau.

### Shadowing script

> “I’ve opened a pull request for the employee sync changes. It adds validation for inactive employees and updates the background job. Could you pay particular attention to the EF Core query and the transaction handling? I’d also like a second pair of eyes on the edge cases. If possible, I’d like to merge it before the QA deployment at 4 p.m.”

Cách luyện:

1. Đọc chậm từng câu.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp từng câu, tập trung vào từ được nhấn.
4. Ghi âm lại giọng của bạn.
5. Nói toàn bộ đoạn không nhìn văn bản.

## 10. Bài tập thực hành chủ động

### Scenario

Bạn vừa tạo PR cho một thay đổi trong ASP.NET Core API. PR gồm:

- Thay đổi validation của request.
- Cập nhật EF Core query.
- Thêm retry logic cho một background job.
- Có một edge case liên quan đến duplicate processing mà bạn muốn reviewer kiểm tra kỹ.

Bạn muốn merge trước đợt deploy QA chiều nay.

### Required points

Viết một message 5–7 câu bằng tiếng Anh gồm:

- Nói bạn đã mở PR.
- Tóm tắt 2–3 thay đổi chính.
- Nói phần bạn muốn reviewer chú ý.
- Nhắc tới edge case.
- Nêu timing một cách lịch sự.

### Suggested structure

`PR opened → Summary → Focus area → Risk/edge case → Timing`

### Useful phrases

- “I’ve opened a pull request for…”
- “It adds…”
- “I also changed…”
- “Could you pay particular attention to…?”
- “I’d like a second pair of eyes on…”
- “If possible, I’d like to merge it before…”

### Completion criteria

Bài làm đạt yêu cầu nếu người đọc có thể hiểu ngay:

- PR để làm gì.
- Những phần quan trọng đã thay đổi.
- Họ nên review kỹ phần nào.
- Bạn cần review trước thời điểm nào và vì sao.

## 12. Mẫu trả lời tham khảo

> “Hi Alex, **I’ve opened a pull request for the API validation changes**. It updates the request validation, changes the EF Core query, and adds retry logic to the background job. **Could you pay particular attention to the query and the duplicate-processing edge case?** I’ve added tests for the main scenarios, but **I’d like a second pair of eyes on the edge case**. If possible, I’d like to merge it before the QA deployment this afternoon. Thanks.”

Các mẫu câu có thể tái sử dụng:

- **I’ve opened a pull request for…**
- **Could you pay particular attention to…?**
- **I’d like a second pair of eyes on…**
- **If possible, I’d like to…**

## 13. Thử nói lại theo cách của bạn

Hãy chọn một PR thật hoặc một thay đổi code bạn đã từng làm và điền template sau:

- **Context:** I’ve opened a pull request for…
- **What changed:** It adds/updates…
- **Important area:** Could you pay particular attention to…?
- **Risk/edge case:** I’d like a second pair of eyes on…
- **Timing:** If possible, I’d like to merge it before…

Ưu tiên nói ngắn và cụ thể. Reviewer không cần toàn bộ lịch sử của task; họ cần đủ context để review hiệu quả.

## 14. Tóm tắt cần ghi nhớ

### 3 câu nên nhớ

1. **“I’ve opened a pull request for the employee sync changes.”**
2. **“Could you pay particular attention to the query and the transaction handling?”**
3. **“I’d like a second pair of eyes on the edge cases.”**

### Lỗi cần tránh

- Không chỉ gửi **“Please review my PR”** nếu PR có thay đổi phức tạp; hãy thêm context ngắn gọn.
- Sau `could`, không dùng `to`: đúng là **“Could you review…?”**.
- Khi có deadline, nên nói lý do thay vì chỉ đưa ra yêu cầu cứng.

### Thử thách hôm nay

Chọn một PR thật bạn đã tạo gần đây và viết lại code-review request của bạn bằng 4–6 câu theo cấu trúc:

**Context → Changes → Focus area → Timing.**
