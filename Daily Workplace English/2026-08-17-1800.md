# Daily Workplace English — Ngày 19

- **Ngày:** 17/08/2026 (UTC+7)
- **Tình huống công việc:** Giải thích một database migration có rủi ro và thống nhất cách triển khai an toàn
- **Kỹ năng giao tiếp chính:** Trình bày thay đổi database, nêu risk, đề xuất mitigation và xác nhận rollout plan
- **Thời gian học:** 20–25 phút
- **Độ khó:** Lower-intermediate

## 1. Tình huống hôm nay

Team của bạn chuẩn bị triển khai một thay đổi ASP.NET Core có kèm database migration trên SQL Server. Migration sẽ thêm một cột mới bắt buộc và backfill dữ liệu cho các record hiện có. Trên môi trường nhỏ, migration chạy nhanh, nhưng production có bảng lớn hơn nhiều.

Những người liên quan gồm bạn, Technical Lead và DevOps engineer. Bạn cần giải thích rằng code change thì khá đơn giản, nhưng migration có thể giữ lock lâu hơn dự kiến và ảnh hưởng request đang chạy.

Khó khăn giao tiếp là không nên nói quá chắc chắn như “The migration will be fine” khi chưa test với dữ liệu gần production. Ngược lại, chỉ nói “This is risky” cũng không giúp team ra quyết định. Bạn cần trình bày rõ:

**Change → Risk → Evidence → Mitigation → Rollout plan → Confirmation**

## 2. Bạn cần nói gì?

Trong cuộc trao đổi này, bạn nên:

- Nói ngắn gọn migration sẽ thay đổi gì.
- Chỉ ra risk cụ thể thay vì dùng từ chung chung như “dangerous”.
- Phân biệt điều đã test với điều chưa chắc chắn.
- Đề xuất cách giảm rủi ro, ví dụ chia migration thành nhiều bước.
- Xác nhận cách rollout trước khi deploy production.
- Nêu rõ điều kiện để rollback hoặc dừng deployment nếu cần.

## 3. Đoạn hội thoại hoặc mẫu trình bày

**You:** “The application change is small, but the database migration needs a bit more attention.”  
*Phần thay đổi trong ứng dụng khá nhỏ, nhưng database migration cần được xem xét kỹ hơn một chút.*

**Technical Lead:** “What’s the main risk?”  
*Rủi ro chính là gì?*

**You:** “The migration adds a required column and backfills existing rows. On a large table, that could hold locks longer than we expect.”  
*Migration thêm một cột bắt buộc và backfill dữ liệu hiện có. Với bảng lớn, việc này có thể giữ lock lâu hơn chúng ta dự kiến.*

**DevOps:** “Have we tested it with production-like data?”  
*Chúng ta đã test với dữ liệu gần giống production chưa?*

**You:** “Not yet. We tested it on QA, but the dataset there is much smaller.”  
*Chưa. Chúng ta đã test trên QA, nhưng dataset ở đó nhỏ hơn nhiều.*

**You:** “I’d suggest splitting the migration into two steps: add the column as nullable first, backfill the data separately, and make it required afterward.”  
*Tôi đề xuất chia migration thành hai bước: trước tiên thêm cột dưới dạng nullable, backfill dữ liệu riêng, rồi sau đó mới chuyển thành required.*

**Technical Lead:** “That sounds safer, although it takes longer.”  
*Nghe có vẻ an toàn hơn, dù sẽ mất nhiều thời gian hơn.*

**You:** “Yes. The main trade-off is a longer rollout, but it reduces the chance of blocking production traffic.”  
*Đúng. Trade-off chính là rollout lâu hơn, nhưng giảm khả năng làm block traffic production.*

**You:** “If we agree on that approach, I’ll prepare the migration steps and a rollback check before deployment.”  
*Nếu chúng ta thống nhất cách đó, tôi sẽ chuẩn bị các bước migration và kiểm tra rollback trước khi deploy.*

## 4. Các cụm từ quan trọng

### 1. “needs a bit more attention”

- **Nghĩa:** cần được chú ý/xem xét kỹ hơn một chút.
- **Khi dùng:** Khi muốn nói một phần công việc có rủi ro hoặc độ phức tạp cao hơn phần còn lại mà không làm câu quá nặng nề.
- **Ví dụ thêm:** “The API change is straightforward, but the authentication flow needs a bit more attention.”

### 2. “The main risk is…”

- **Nghĩa:** Rủi ro chính là…
- **Khi dùng:** Khi cần đưa cuộc trao đổi vào đúng trọng tâm.
- **Ví dụ thêm:** “The main risk is that retries may create duplicate records.”

### 3. “That could…”

- **Nghĩa:** Điều đó có thể…
- **Khi dùng:** Khi nói về một khả năng/rủi ro chưa chắc chắn 100%.
- **Ví dụ thêm:** “That could increase response time during peak hours.”

### 4. “We tested it on…, but…”

- **Nghĩa:** Chúng ta đã test trên…, nhưng…
- **Khi dùng:** Khi cần nói rõ evidence hiện tại có giới hạn.
- **Ví dụ thêm:** “We tested it locally, but we haven’t tested it under load yet.”

### 5. “I’d suggest…”

- **Nghĩa:** Tôi đề xuất…
- **Khi dùng:** Khi đưa ra hướng xử lý một cách chuyên nghiệp nhưng vẫn rõ ràng.
- **Ví dụ thêm:** “I’d suggest adding a feature flag before enabling this for all users.”

### 6. “The main trade-off is…”

- **Nghĩa:** Sự đánh đổi chính là…
- **Khi dùng:** Khi so sánh lợi ích với chi phí/rủi ro của giải pháp.
- **Ví dụ thêm:** “The main trade-off is higher memory usage for faster reads.”

### 7. “If we agree on that approach, I’ll…”

- **Nghĩa:** Nếu chúng ta thống nhất cách đó, tôi sẽ…
- **Khi dùng:** Khi chốt next action sau khi team ra quyết định.
- **Ví dụ thêm:** “If we agree on that approach, I’ll update the API contract today.”

## 5. Từ vựng trong tình huống

### 1. migration

- **Từ loại:** noun
- **IPA:** /maɪˈɡreɪʃən/
- **Nghĩa:** thay đổi cấu trúc hoặc dữ liệu database theo một phiên bản mới.
- **Ví dụ:** “The migration adds a new column.”
- **Collocation:** database migration, run a migration, migration script

### 2. backfill

- **Từ loại:** verb / noun
- **IPA:** /ˈbæk.fɪl/
- **Nghĩa:** điền dữ liệu còn thiếu cho các record đã tồn tại.
- **Ví dụ:** “We need to backfill existing rows.”
- **Collocation:** backfill data, backfill existing records

### 3. lock

- **Từ loại:** noun / verb
- **IPA:** /lɒk/
- **Nghĩa:** cơ chế khóa dữ liệu/tài nguyên để kiểm soát truy cập đồng thời.
- **Ví dụ:** “The migration could hold locks for too long.”
- **Collocation:** database lock, hold a lock, lock contention

### 4. nullable

- **Từ loại:** adjective
- **IPA:** /ˈnʌl.ə.bəl/
- **Nghĩa:** cho phép giá trị `null`.
- **Ví dụ:** “Add the column as nullable first.”
- **Collocation:** nullable column, nullable property

### 5. rollout

- **Từ loại:** noun
- **IPA:** /ˈrəʊl.aʊt/
- **Nghĩa:** quá trình đưa thay đổi ra môi trường thực tế theo kế hoạch.
- **Ví dụ:** “The rollout will take a bit longer.”
- **Collocation:** gradual rollout, rollout plan, production rollout

### 6. rollback

- **Từ loại:** noun / verb
- **IPA:** /ˈrəʊl.bæk/
- **Nghĩa:** quay lại trạng thái trước khi triển khai thay đổi.
- **Ví dụ:** “We should prepare a rollback check before deployment.”
- **Collocation:** rollback plan, rollback strategy, roll back a deployment

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Hedging với `could` để nói về rủi ro chưa chắc chắn

**Cấu trúc:**

`Subject + could + verb ...`

Dùng `could` khi bạn muốn nói rằng một điều **có khả năng xảy ra**, nhưng chưa có đủ bằng chứng để khẳng định chắc chắn.

Ví dụ trong bài:

- “That could hold locks longer than we expect.”
- “That could affect production traffic.”

So sánh:

- “The migration will block production.” → quá chắc chắn nếu chưa có evidence.
- “The migration could block production traffic.” → thể hiện đây là risk cần xem xét.

**Lỗi thường gặp:**

Sai: “It could blocks the table.”  
Đúng: “It could block the table.”

Sau modal verb như `could`, động từ luôn ở dạng nguyên mẫu.

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“This migration is dangerous.”

### Tự nhiên và chuyên nghiệp hơn

“The main risk is that the migration could hold locks for longer than expected.”

### Giải thích

“Dangerous” quá chung chung và cảm tính. Phiên bản tốt hơn mô tả đúng technical risk nên team có thể đánh giá và xử lý.

### Chưa tự nhiên hoặc quá trực tiếp

“We cannot deploy this.”

### Tự nhiên và chuyên nghiệp hơn

“I don’t think we should deploy this version until we’ve tested the migration with a larger dataset.”

### Giải thích

Câu thứ hai vẫn rõ ràng nhưng có lý do và điều kiện cụ thể. Trong incident khẩn cấp, câu trực tiếp đôi khi cần thiết, nhưng trong design/deployment discussion thì nên giải thích basis của quyết định.

### Chưa tự nhiên hoặc quá trực tiếp

“Make the migration two steps.”

### Tự nhiên và chuyên nghiệp hơn

“I’d suggest splitting the migration into two steps.”

### Giải thích

Câu đầu nghe giống mệnh lệnh. “I’d suggest…” phù hợp hơn khi bạn đang đưa proposal trong technical discussion.

## 8. Phát âm và luyện nói

### 1. “The main risk is that…”

- **Nhấn:** `MAIN`, `RISK`.
- **Connected speech:** `risk is` thường nối nhẹ với nhau.
- **Gợi ý cho người Việt:** Không cần đọc từng từ tách rời; nói thành một cụm ý.
- **Ngắt:** “The main risk / is that…”

### 2. “I’d suggest splitting the migration into two steps.”

- **Nhấn:** `SUGGEST`, `SPLITTING`, `TWO STEPS`.
- `I’d` thường rất ngắn, gần như nối trực tiếp vào `suggest`.
- **Ngắt:** “I’d suggest / splitting the migration / into two steps.”

### 3. “The main trade-off is…”

- **Nhấn:** `MAIN`, `TRADE-OFF`.
- Không cần nhấn mạnh `the` hoặc `is`.
- **Ngắt:** “The main trade-off / is a longer rollout…”

### Shadowing script

“The application change is small, but the migration needs more attention.”  
“The main risk is that it could hold locks longer than expected.”  
“I’d suggest splitting the migration into two steps.”  
“The main trade-off is a longer rollout, but it reduces production risk.”

Cách luyện:

1. Đọc chậm từng câu.
2. Nghe bằng Text-to-Speech nếu có.
3. Lặp lại từng câu một.
4. Ghi âm giọng của bạn.
5. Nói lại toàn bộ đoạn mà không nhìn văn bản.

## 10. Bài tập thực hành chủ động

### Scenario

Bạn chuẩn bị deploy một EF Core migration cho một bảng lớn. Migration thêm index mới và thay đổi một cột. Bạn chưa test với production-size data.

### Nhiệm vụ

Nói hoặc viết một update 6–8 câu cho Technical Lead.

Bạn cần đề cập:

- Migration thay đổi gì.
- Risk chính là gì.
- Bạn đã test ở đâu.
- Điều gì vẫn chưa được verify.
- Mitigation bạn đề xuất.
- Next action nếu team đồng ý.

### Cấu trúc gợi ý

1. “The application change is…”
2. “The main risk is…”
3. “We tested it on…, but…”
4. “I’d suggest…”
5. “The main trade-off is…”
6. “If we agree on that approach, I’ll…”

### Tiêu chí hoàn thành

- 6–8 câu.
- Không khẳng định risk như một fact nếu chưa verify.
- Có ít nhất một mitigation cụ thể.
- Có next action rõ ràng.

## 12. Mẫu trả lời tham khảo

“The application change itself is small, but the EF Core migration needs more attention. **The main risk is that** creating the index on a large table **could** take longer than expected and affect database performance. We tested the migration on QA, but the dataset there is much smaller than production. **I’d suggest** testing it with a larger dataset first and running the production migration during a low-traffic window. **The main trade-off is** a slightly longer rollout, but it gives us more confidence before deployment. **If we agree on that approach, I’ll** prepare the test and rollout steps today.”

Các mẫu đáng tái sử dụng:

- **The main risk is that…**
- **I’d suggest…**
- **The main trade-off is…**
- **If we agree on that approach, I’ll…**
