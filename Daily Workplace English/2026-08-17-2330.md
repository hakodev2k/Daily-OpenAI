# Daily Workplace English — Ngày 23

- **Ngày:** 17/08/2026 (UTC+7)
- **Tình huống công việc:** Giải thích root cause của một bug production
- **Kỹ năng giao tiếp chính:** Explain technical issues clearly without blaming others
- **Thời gian học:** 15–20 phút
- **Độ khó:** Lower-intermediate

## 1. Tình huống hôm nay

Một API trong hệ thống .NET bị lỗi ở production. Người dùng báo rằng một số request trả về lỗi 500. Bạn đã kiểm tra log, tìm thấy nguyên nhân liên quan đến việc xử lý null data trong một background job.

Người liên quan gồm bạn, QA, Technical Lead và Product Owner. Bạn cần giải thích:

- Bug xảy ra như thế nào.
- Root cause là gì.
- Vì sao test trước đó chưa phát hiện lỗi.
- Bạn sẽ fix và phòng tránh lỗi tương tự ra sao.

Khó khăn là giải thích nguyên nhân kỹ thuật mà không nói kiểu “QA missed this” hoặc “Requirement was wrong”.

## 2. Bạn cần nói gì?

Mục tiêu giao tiếp:

- Xác nhận vấn đề đang xảy ra.
- Mô tả nguyên nhân dựa trên dữ liệu.
- Phân biệt symptom và root cause.
- Nói rõ hành động sửa lỗi.
- Đề xuất cách phòng tránh trong tương lai.

## 3. Đoạn hội thoại

**Team Lead:** “Can you explain what caused the production issue?”

Bạn có thể giải thích nguyên nhân của lỗi production không?

**You:** “The issue was caused by a null value that was not handled correctly in the background job.”

Lỗi xảy ra do một giá trị null chưa được xử lý đúng trong background job.

**Team Lead:** “Why did we not catch this during testing?”

Tại sao chúng ta không phát hiện lỗi này khi test?

**You:** “The current test cases did not cover this specific data scenario. We need to add more edge-case tests.”

Các test hiện tại chưa bao phủ trường hợp dữ liệu đặc biệt này. Chúng ta cần thêm test cho edge case.

**You:** “I have prepared a fix and I’m also adding validation to prevent this issue from happening again.”

Tôi đã chuẩn bị bản sửa lỗi và cũng thêm validation để ngăn lỗi xảy ra lại.

## 4. Các cụm từ quan trọng

### “The issue was caused by...”

- Nghĩa: Vấn đề xảy ra do...
- Dùng khi giải thích nguyên nhân.
- Ví dụ: “The issue was caused by an incorrect configuration.”

### “The root cause was...”

- Nghĩa: Nguyên nhân gốc là...
- Dùng trong incident review.
- Ví dụ: “The root cause was a missing database index.”

### “We did not cover this scenario...”

- Nghĩa: Chúng ta chưa bao phủ trường hợp này.
- Dùng để nói về thiếu sót trong test mà không đổ lỗi.
- Ví dụ: “We did not cover this scenario in the integration tests.”

### “To prevent this from happening again...”

- Nghĩa: Để tránh việc này xảy ra lần nữa...
- Dùng khi nói preventive action.
- Ví dụ: “To prevent this from happening again, we added monitoring.”

### “Based on the logs, it looks like...”

- Nghĩa: Dựa trên log, có vẻ như...
- Dùng khi kết luận chưa hoàn toàn chắc chắn.
- Ví dụ: “Based on the logs, it looks like the timeout came from the external API.”

## 5. Từ vựng trong tình huống

### root cause (noun)
- IPA: /ruːt kɔːz/
- Nghĩa: nguyên nhân gốc
- Example: “We identified the root cause of the issue.”
- Collocation: root cause analysis

### reproduce (verb)
- IPA: /ˌriːprəˈduːs/
- Nghĩa: tái hiện lỗi
- Example: “We can reproduce the issue in the test environment.”
- Collocation: reproduce a bug

### validation (noun)
- IPA: /ˌvælɪˈdeɪʃən/
- Nghĩa: kiểm tra tính hợp lệ
- Example: “We added validation for missing data.”
- Collocation: input validation

### edge case (noun)
- IPA: /edʒ keɪs/
- Nghĩa: trường hợp biên
- Example: “This edge case was not covered by our tests.”
- Collocation: handle edge cases

## 6. Mẫu câu hoặc ngữ pháp cần nhớ

### Passive voice để mô tả sự cố kỹ thuật

Cấu trúc:

**The issue was caused by + noun**

Dùng khi muốn tập trung vào sự việc thay vì người gây ra lỗi.

Ví dụ:

- “The deployment was delayed by a configuration issue.”
- “The bug was introduced by a recent change.”

Lỗi thường gặp:

Sai: “The issue caused by null data.”

Đúng: “The issue was caused by null data.”

## 7. Cách nói tự nhiên hơn

### Chưa tự nhiên hoặc quá trực tiếp

“QA missed this bug.”

### Tự nhiên và chuyên nghiệp hơn

“This scenario was not covered by the current test cases.”

### Giải thích

Tập trung vào quy trình thay vì đổ lỗi cho cá nhân.

### Chưa tự nhiên

“The code is wrong.”

### Tự nhiên hơn

“The current implementation does not handle this case correctly.”

### Giải thích

Cách nói này phù hợp hơn khi thảo luận kỹ thuật.

## 8. Phát âm và luyện nói

Cụm quan trọng:

**The root cause was...**

- Nhấn: ROOT, CAUSE.
- Pause: “The root cause was / ...”

**To prevent this from happening again...**

- Nhấn: PREVENT, AGAIN.
- Nối âm “this from”.

Shadowing:

“The issue was caused by invalid data handling.”
“The root cause was a missing validation step.”
“To prevent this from happening again, we added more test coverage.”

## 9. Bài tập nhanh

1. Điền từ: “The ______ cause was a missing validation step.”

2. Chọn câu chuyên nghiệp hơn:
A. “The developer made a mistake.”
B. “The implementation did not handle this scenario correctly.”

3. Viết lại: “Why did QA not find this?”

4. Hoàn thành: “To prevent this from happening again, we will ______.”

## 10. Bài tập thực hành chủ động

Viết một đoạn giải thích bug production trong 60 giây.

Cấu trúc:

- Problem
- Root cause
- Investigation result
- Fix
- Prevention action

Dùng các câu:

- “The issue was caused by...”
- “Based on the logs, it looks like...”
- “To prevent this from happening again...”

### Lỗi cần tránh

- Đổ lỗi trực tiếp cho một người hoặc team.
- Kết luận root cause khi chưa có dữ liệu.
- Chỉ nói cách fix mà không nói cách phòng tránh.

### Thử thách hôm nay

Chọn một bug cũ và thử giải thích lại bằng cấu trúc:

Problem → Root cause → Fix → Prevention.
